## Step 1: Load the data and standardize BMI

Use the unscaled diabetes data so BMI has its real values. Then standardize it, because gradient descent takes far more steps when a feature's numbers are large (you'll see why in the practice).

```python run
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.datasets import load_diabetes

diabetes = load_diabetes(as_frame=True, scaled=False)
bmi = diabetes.data["bmi"].to_numpy()
y = diabetes.target.to_numpy()

bmi_mean, bmi_std = bmi.mean(), bmi.std()
x = (bmi - bmi_mean) / bmi_std
print(f"BMI mean {bmi_mean:.2f}, std {bmi_std:.2f}")
print("first 3 raw BMIs:   ", bmi[:3])
print("first 3 standardized:", x[:3].round(2))
```

Keep `bmi_mean` and `bmi_std`. You'll need them in Step 5 to turn your answer back into real BMI units.

## Step 2: Write the line and its loss

Two small functions: one makes predictions for a slope `w` and intercept `b`, the other scores them with mean squared error. Try three guesses by hand:

```python run
def predict(w, b, x):
    return w * x + b

def mse(w, b, x, y):
    return ((predict(w, b, x) - y) ** 2).mean()

for w, b in [(0, 0), (0, 150), (40, 150)]:
    print(f"w = {w:3d}, b = {b:3d}  ->  MSE {mse(w, b, x, y):8.0f}")
```

Each guess is better than the last: putting the line at the right height (`b = 150`) cuts the loss by more than half, and tilting it upward (`w = 40`) cuts it again. Guess-and-check works, but it's slow, and you'd never know when to stop. Gradient descent tells you which way to adjust, and by how much.

## Step 3: Compute the gradients

The gradient says how fast the loss changes as you nudge each number. For mean squared error on a line, calculus gives two short formulas. Let `error = prediction - y`:

- gradient for `w`: the average of `2 * error * x`
- gradient for `b`: the average of `2 * error`

You don't need the calculus to use them. Read them as: "if the line is too high where `x` is large, lower the slope; if it's too high on average, lower the intercept."

```python run
def gradients(w, b, x, y):
    error = predict(w, b, x) - y
    dw = 2 * (error * x).mean()
    db = 2 * error.mean()
    return dw, db

w, b = 0.0, 0.0
dw, db = gradients(w, b, x, y)
print(f"gradients at (0, 0): dw = {dw:.1f}, db = {db:.1f}")

learning_rate = 0.1
w, b = w - learning_rate * dw, b - learning_rate * db
print(f"after one step: w = {w:.2f}, b = {b:.2f}, MSE {mse(w, b, x, y):.0f}")
```

Both gradients are negative, meaning "the loss goes down if you increase these", so the step increases both. One step took the loss from about 29,000 to about 20,000.

## Step 4: Loop it

Repeat that step and record the loss each time:

```python run alt="Line chart of mean squared error against step number for 60 steps of gradient descent. The loss falls from about 29,000 to about 4,000 within the first 12 steps, then flattens just under 3,900." caption="Your own gradient descent at work: big improvements first, then a slow settle."
def fit_line(x, y, learning_rate=0.1, steps=60):
    w, b = 0.0, 0.0
    history = []
    for _ in range(steps):
        history.append(mse(w, b, x, y))
        dw, db = gradients(w, b, x, y)
        w -= learning_rate * dw
        b -= learning_rate * db
    return w, b, history

w, b, history = fit_line(x, y)
print(f"w = {w:.2f}, b = {b:.2f}, final MSE {history[-1]:.1f}")

plt.figure(figsize=(6, 3.6))
plt.plot(history)
plt.xlabel("step")
plt.ylabel("mean squared error")
plt.title("Gradient descent on the BMI line")
```

Each step reduces the error between prediction and truth a little, and the gradients shrink as the line gets closer, so the curve flattens out on its own. After 60 steps the changes are too small to matter.

## Step 5: Check your answer against scikit-learn

If your code is right, `LinearRegression` should find the same line. Fit it on the same standardized `x`:

```python run
from sklearn.linear_model import LinearRegression

sk_line = LinearRegression().fit(x.reshape(-1, 1), y)
print(f"yours:        w = {w:.3f}, b = {b:.3f}")
print(f"scikit-learn: w = {sk_line.coef_[0]:.3f}, b = {sk_line.intercept_:.3f}")
```

They agree to three decimal places. `x.reshape(-1, 1)` turns the flat array into a one-column table, the shape `fit` needs (the same fix as the Series bug in Module 2).

Your slope is in "progression points per standard deviation of BMI", which nobody thinks in. Convert it back to real BMI units. Since `x = (bmi - mean) / std`, the line `w * x + b` equals `(w / std) * bmi + (b - w * mean / std)`:

```python run
slope_per_bmi = w / bmi_std
intercept_raw = b - w * bmi_mean / bmi_std
print(f"progression = {slope_per_bmi:.2f} * bmi {intercept_raw:+.2f}")

raw_line = LinearRegression().fit(diabetes.data[["bmi"]], diabetes.target)
print(f"scikit-learn on raw BMI: {raw_line.coef_[0]:.2f} * bmi {raw_line.intercept_:+.2f}")
```

The same line as the Notes lesson: about 10.2 progression points per BMI point. You've reproduced scikit-learn's answer with an algorithm you wrote yourself.

## Step 6: Race the line against k-NN on BMI alone

k-NN regression predicts a patient's score by averaging the scores of the k patients with the closest BMI. Draw each model's predictions across a range of BMIs, including some beyond the data (the dashed lines mark the smallest and largest BMI in the dataset):

```python run alt="Scatter of BMI against disease progression with three prediction curves from BMI 12 to 50. The linear regression line rises steadily across the whole range. The k-NN curve with k equals 5 is jagged and steppy inside the data. The k-NN curve with k equals 40 is smoother. Both k-NN curves go flat outside the dashed lines that mark the data's minimum and maximum BMI." caption="Inside the data, both kinds of model follow the trend. Outside it, k-NN goes flat and the line keeps going."
from sklearn.neighbors import KNeighborsRegressor

X_bmi = diabetes.data[["bmi"]]
grid = pd.DataFrame({"bmi": np.linspace(12, 50, 300)})

plt.figure(figsize=(7, 4.3))
plt.scatter(X_bmi["bmi"], y, s=8, alpha=0.3, color="gray")
plt.plot(grid["bmi"], raw_line.predict(grid), linewidth=2, label="linear regression")
for k in [5, 40]:
    knn = KNeighborsRegressor(n_neighbors=k).fit(X_bmi, y)
    plt.plot(grid["bmi"], knn.predict(grid), linewidth=1.5, label=f"k-NN, k = {k}")
plt.axvline(X_bmi["bmi"].min(), linestyle="--", color="black", linewidth=0.8)
plt.axvline(X_bmi["bmi"].max(), linestyle="--", color="black", linewidth=0.8)
plt.xlabel("body mass index")
plt.ylabel("disease progression")
plt.legend()
```

With k = 5, k-NN chases small clusters of patients and wobbles. With k = 40 it's smoother and looks a lot like the line, with a slight curve. Past the dashed lines, k-NN can only repeat the average of the most extreme patients it knows, so it goes flat, while the line keeps rising. The k = 40 curve flattens even before the right-hand line, because above a BMI of about 37 the same 40 patients are always the nearest. Whether that's good depends on whether the trend really continues.

## Step 7: Race them on all ten features

One feature only tells part of the story. Use all ten, split off a test set, and compare test MAE. k-NN gets a scaler in a pipeline, as Module 3 taught; the line doesn't need one:

```python run
from sklearn.metrics import mean_absolute_error
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X_all = diabetes.data
X_train, X_test, y_train, y_test = train_test_split(X_all, diabetes.target, test_size=0.25, random_state=1)

contenders = {
    "linear regression": LinearRegression(),
    "k-NN, k = 5 (scaled)": make_pipeline(StandardScaler(), KNeighborsRegressor(n_neighbors=5)),
    "k-NN, k = 20 (scaled)": make_pipeline(StandardScaler(), KNeighborsRegressor(n_neighbors=20)),
}
print(f"{'always guess the average':28s}  MAE {mean_absolute_error(y_test, [y_train.mean()] * len(y_test)):.1f}")
for name, model in contenders.items():
    model.fit(X_train, y_train)
    print(f"{name:28s}  MAE {mean_absolute_error(y_test, model.predict(X_test)):.1f}")
```

Every model beats the baseline by a wide margin, and the line wins narrowly. With 442 patients and a mostly steady relationship between the measurements and the outcome, a straight-line rule is hard to beat. k-NN would shine on a pattern with bends that a line can't follow, like the crescents in the Notes lesson. Neither model is "better" in general; the data decides.

## The finished line-fitter

Your from-scratch gradient descent, in one cell, with a check against scikit-learn built in:

```python run
import numpy as np
from sklearn.datasets import load_diabetes
from sklearn.linear_model import LinearRegression

def fit_line_gd(feature, target, learning_rate=0.1, steps=60):
    """Fit target ≈ slope * feature + intercept by gradient descent on MSE."""
    mean, std = feature.mean(), feature.std()
    x = (feature - mean) / std
    w = b = 0.0
    for _ in range(steps):
        error = (w * x + b) - target
        w -= learning_rate * 2 * (error * x).mean()
        b -= learning_rate * 2 * error.mean()
    return w / std, b - w * mean / std

data = load_diabetes(as_frame=True, scaled=False)
slope, intercept = fit_line_gd(data.data["bmi"].to_numpy(), data.target.to_numpy())
check = LinearRegression().fit(data.data[["bmi"]], data.target)
print(f"gradient descent: {slope:.3f} * bmi {intercept:+.3f}")
print(f"scikit-learn:     {check.coef_[0]:.3f} * bmi {check.intercept_:+.3f}")
```

:::quiz
Q: In Step 3, both gradients at `(0, 0)` were negative. Why did the update *increase* `w` and `b`?
- [ ] Because the learning rate was negative
  The learning rate was 0.1, a positive number.
- [x] Because the update subtracts learning rate × gradient, and subtracting a negative number adds
  A negative gradient means the loss falls as the value rises, so the downhill step raises it.
- [ ] Because gradient descent always increases the numbers on the first step
  The direction depends entirely on the gradient's sign. Start above the best line and the first steps go down.

Q: Why did the build standardize BMI before running gradient descent?
- [x] Gradient descent converges far faster when the feature isn't on a large scale, and the result can be converted back afterwards
  Standardizing changes the units, not the line. Step 5's conversion recovered the same slope as scikit-learn on raw BMI.
- [ ] `LinearRegression` refuses unscaled features
  It accepts any scale. That's why the raw-BMI check in Step 5 worked.
- [ ] Standardizing makes the MSE smaller
  The best possible line makes the same predictions in either unit, so its MSE is the same.

Q: For a patient with BMI 48, above everyone in the data, what does the k = 40 k-NN model predict?
- [ ] A higher score than for any patient in the data, following the trend
  That's what the line does. k-NN can only average scores it has already seen.
- [x] The average score of the 40 patients with the highest BMIs, no matter how far above them 48 is
  Every BMI above the maximum has the same 40 nearest neighbors, so the prediction stays flat.
- [ ] An error, because 48 is outside the training range
  k-NN will predict for any input; it just can't extrapolate.
:::

:::takeaways
- Gradient descent needs three pieces: a prediction function, a loss, and the loss's gradients. The loop repeatedly steps each parameter against its gradient.
- A from-scratch model is worth checking against a trusted library. Matching answers mean both your math and your code are right.
- Standardizing a feature changes the units of the slope, not the line itself; you can convert back.
- k-NN regression follows local wiggles and goes flat outside the data; a line follows one steady trend and extends it.
- On the full diabetes data, a line narrowly beats k-NN on test error. On curved data, it often goes the other way.
:::
