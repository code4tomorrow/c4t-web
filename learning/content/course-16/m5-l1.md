You kept a log of 150 basketball shots: how far you stood from the hoop, whether a defender was close, and whether the ball went in. A teammate asks about a 15-foot jumper. Will it go in? Answering "yes" or "no" hides how unsure you are. Answering "about a one-in-three chance" is something you can act on: take it late in the shot clock, pass if a teammate is open under the basket.

This module gives you two models for yes-or-no questions. **Logistic regression** turns features into a probability. A **decision tree** turns them into a short list of questions you can read out loud. Run each cell below in order in one Colab notebook.

```python run
import numpy as np
import pandas as pd

rng = np.random.default_rng(3)
n = 150
distance = rng.uniform(1, 30, n).round(1)        # feet from the hoop
defender_close = rng.integers(0, 2, n)            # 1 = a defender was close
score = 3.6 - 0.24 * distance - 1.6 * defender_close
made = (rng.random(n) < 1 / (1 + np.exp(-score))).astype(int)

shots = pd.DataFrame({"distance": distance, "defender_close": defender_close, "made": made})
print(shots.head())
print("Shots made:", shots["made"].sum(), "of", len(shots))
```

The shots are simulated so the notebook runs anywhere, but they follow a sensible hidden rule: longer shots and close defenders both make a miss more likely. The models never see that rule. They only see the 150 rows.

## Why a straight line makes a bad probability

You already know linear regression from Module 4. What happens if you point it at a column of 0s and 1s?

```python run
from sklearn.linear_model import LinearRegression

line = LinearRegression().fit(shots[["distance"]], shots["made"])
new_shots = pd.DataFrame({"distance": [1, 15, 40]})
print(line.predict(new_shots).round(2))
```

At 40 feet (roughly a half-court heave) the line predicts a negative number. A shot can't go in −0.5 times. The line has no idea its answers are supposed to stay between 0 and 1, and it keeps sloping forever.

```python run alt="Shots plotted as dots at 0 (missed) and 1 (made) against distance, with a straight regression line that slopes down and crosses below zero after about 25 feet" caption="A straight line through 0/1 data drifts outside the range a probability can take."
import matplotlib.pyplot as plt

xs = pd.DataFrame({"distance": np.linspace(0, 40, 100)})
plt.figure(figsize=(7, 3.5))
plt.scatter(shots["distance"], shots["made"], alpha=0.4, label="shots (1 = made)")
plt.plot(xs["distance"], line.predict(xs), color="crimson", label="linear regression")
plt.axhline(0, color="gray", linewidth=0.8)
plt.axhline(1, color="gray", linewidth=0.8)
plt.xlabel("Distance from hoop (feet)")
plt.ylabel("Prediction")
plt.legend()
plt.show()
```

## The sigmoid squashes any score into 0 to 1

The fix is to keep the straight-line score but pass it through a function that can never leave 0 to 1. That function is the **sigmoid**:

`sigmoid(z) = 1 / (1 + e^(-z))`

Feed it a big positive number and you get something close to 1. A big negative number gives something close to 0. A score of exactly 0 gives 0.5, a perfect toss-up.

```python run alt="An S-shaped curve rising from near 0 on the left to near 1 on the right, passing through 0.5 where the score is 0" caption="The sigmoid: every score, however large or small, lands between 0 and 1."
def sigmoid(z):
    return 1 / (1 + np.exp(-z))

for z in [-4, -2, 0, 2, 4]:
    print(f"score {z:>2} -> probability {sigmoid(z):.3f}")

zs = np.linspace(-8, 8, 200)
plt.figure(figsize=(6, 3))
plt.plot(zs, sigmoid(zs))
plt.axhline(0.5, color="gray", linestyle="--", linewidth=0.8)
plt.axvline(0, color="gray", linestyle="--", linewidth=0.8)
plt.xlabel("score z")
plt.ylabel("sigmoid(z)")
plt.show()
```

Logistic regression does two things in a row. First it computes a straight-line score, `z = w * distance + b`, exactly like linear regression. Then it runs that score through the sigmoid. Training picks `w` and `b` so the probabilities match what really happened as closely as possible. Despite the name, logistic regression is a **classification** model: it answers "which class?", not "how much?".

## Fit LogisticRegression and ask for probabilities

```python run
from sklearn.linear_model import LogisticRegression

logit = LogisticRegression()
logit.fit(shots[["distance"]], shots["made"])

w = logit.coef_[0][0]
b = logit.intercept_[0]
print(f"w = {w:.3f}, b = {b:.3f}")
print(f"The model's 50/50 distance: {-b / w:.1f} feet")

probs = logit.predict_proba(new_shots)
print("classes_:", logit.classes_)
print(pd.DataFrame(probs, columns=["P(missed)", "P(made)"], index=[1, 15, 40]).round(3))
```

`w` is negative, which means every extra foot pushes the score down and the probability with it. The 50/50 distance comes from solving `w * distance + b = 0`, the point where the sigmoid gives exactly 0.5.

`predict_proba` returns one column per class, in the order listed in `classes_`. Here that's `[0, 1]`, so column 0 is the chance of a miss and column 1 is the chance of a make. Each row adds up to 1. Now look at 40 feet: instead of a negative number, you get a small but sensible probability.

```python run alt="The same shot dots with an S-shaped curve that starts near 0.9 at short range and slides toward 0 at long range, staying between 0 and 1" caption="Logistic regression bends to stay between 0 and 1."
plt.figure(figsize=(7, 3.5))
plt.scatter(shots["distance"], shots["made"], alpha=0.4, label="shots (1 = made)")
plt.plot(xs["distance"], logit.predict_proba(xs)[:, 1], color="seagreen", label="P(made)")
plt.axhline(0.5, color="gray", linestyle="--", linewidth=0.8)
plt.xlabel("Distance from hoop (feet)")
plt.ylabel("Probability of a make")
plt.legend()
plt.show()
```

## Thresholds turn probabilities into decisions

A probability isn't a decision yet. `logit.predict()` makes the decision for you by saying "made" whenever `P(made)` is at least 0.5. That 0.5 is the **threshold**, and you're allowed to choose a different one.

Before you run the next cell, predict: if the threshold rises from 0.5 to 0.7, will more shots or fewer get a "take it" decision?

```python run
p_made = logit.predict_proba(shots[["distance"]])[:, 1]

for threshold in [0.3, 0.5, 0.7]:
    take_it = p_made >= threshold
    print(f"threshold {threshold}: take {take_it.sum():>3} of {len(shots)} shots")
```

A higher threshold means the model needs more confidence before it says yes, so fewer shots qualify. A coach who hates wasted possessions might pick 0.7. A team that's down by ten with a minute left might drop to 0.3 and shoot more. The model's probabilities stay the same, and only the rule for acting on them changes. Module 6 shows how to choose a threshold using the mistakes it causes.

## Decision trees: a flowchart learned from data

A decision tree predicts by asking yes-or-no questions about the features, one after another, until it reaches an answer. Here's one trained on both columns, limited to two levels of questions with `max_depth=2`:

```python run alt="A decision tree diagram: the top box asks whether distance is at most about 16 feet; the left branch then asks whether a defender is close; each bottom box shows the number of samples, the split of missed and made shots, and the predicted class" caption="Each box shows its question, its Gini impurity, how many shots reached it, and the [missed, made] counts."
from sklearn.tree import DecisionTreeClassifier, plot_tree

X = shots[["distance", "defender_close"]]
y = shots["made"]
tree = DecisionTreeClassifier(max_depth=2, random_state=0)
tree.fit(X, y)

plt.figure(figsize=(10, 5))
plot_tree(tree, feature_names=X.columns, class_names=["missed", "made"], filled=True, rounded=True)
plt.show()
```

Read it from the top. Every shot starts at the root box and answers its question: true goes left, false goes right. In each box, `samples` is how many training shots reached it and `value` is how many of them were [missed, made]. The bottom boxes are **leaves**, and a leaf predicts whichever class is in the majority there.

Follow a 10-foot shot with a defender close: distance is under the root's cutoff, so go left; `defender_close` is 1, which fails `<= 0.5`, so go right. Check that the tree agrees:

```python run
shot = pd.DataFrame({"distance": [10], "defender_close": [1]})
print("Prediction:", tree.predict(shot)[0])
print("P(missed), P(made):", tree.predict_proba(shot)[0].round(2))
```

The shot lands in a leaf holding 22 misses and 17 makes, so the tree says "missed", but only just: 22 out of 39 is 0.56. A tree's probability is simply the share of each class in the leaf an example lands in, which makes it easy to explain to anyone.

Look at the right half of the tree, too. Its two leaves both say "missed". The split still happened because it made one group purer (47 misses and 2 makes), even though the prediction didn't change.

## How the tree picks a question: Gini impurity

Why did the tree ask about distance first, and why at that cutoff? A good question sorts the shots into groups that are each mostly made or mostly missed. The tree measures how mixed a group is with **Gini impurity**:

`Gini = 1 − (share made)² − (share missed)²`

A group that's all makes scores 0. A 50/50 group scores 0.5, the worst a two-class group can do. To score a whole split, the tree averages the two groups' Gini, weighting each by how many shots it holds. Lower is better.

Step through the search on seven shots. Watch `score` for each cutoff and see which one wins:

:::trace Try four cutoffs and keep the purest split
```python
distances = [2, 4, 7, 10, 13, 18, 24]
made      = [1, 1, 1, 0, 1, 0, 0]

def gini(labels):
    p = sum(labels) / len(labels)
    return 1 - p**2 - (1 - p)**2

best_cut, best_score = None, 1.0
for cut in [5.5, 8.5, 11.5, 15.5]:
    left = [m for d, m in zip(distances, made) if d <= cut]
    right = [m for d, m in zip(distances, made) if d > cut]
    score = (len(left) * gini(left) + len(right) * gini(right)) / len(made)
    print(cut, round(score, 3))
    if score < best_score:
        best_cut, best_score = cut, score
print("Best cut:", best_cut)
```
:::

The cut at 8.5 feet wins because its left group is perfectly pure (three makes) and its right group is mostly misses. scikit-learn does the same thing at full scale: for every feature, it tries the midpoint between each pair of neighboring values, keeps the split with the lowest weighted Gini, and then repeats the search inside each new group until it hits `max_depth` or runs out of mixed groups.

:::quiz
Q: A shot gets `predict_proba` of `[0.3, 0.7]` and `classes_` is `[0, 1]`. Your coach only wants shots with at least an 80% chance. What's the call?
- [ ] Shoot, because 0.7 is more than 0.5
  0.5 is the default threshold, but the coach set it at 0.8.
- [x] Pass, because 0.7 is below the 0.8 threshold
  `P(made)` is the second column, 0.7, and it doesn't reach 0.8.
- [ ] Shoot, because 0.3 is below 0.8
  0.3 is the chance of a miss. Comparing it to the threshold mixes up the columns.

Q: You raise the threshold from 0.5 to 0.7. What happens to the number of shots predicted "made"?
- [ ] It goes up
  A higher bar is harder to clear, so it can't add any yes answers.
- [x] It goes down or stays the same
  Every shot that clears 0.7 also cleared 0.5, but some that cleared 0.5 fall short of 0.7.
- [ ] The probabilities change, so it's impossible to say
  The threshold changes the decision rule only. `predict_proba` gives the same numbers either way.

Q: Which split would a tree choose? Split A makes groups of [9 made, 1 missed] and [2 made, 8 missed]. Split B makes [5 made, 5 missed] and [6 made, 4 missed].
- [x] Split A
  Both of its groups are mostly one class, so their Gini scores (0.18 and 0.32) are low.
- [ ] Split B
  Its groups are close to 50/50, so their Gini scores are near the worst value of 0.5.
- [ ] Either, because both splits use all 20 shots
  Every split uses all the shots; what matters is how pure the groups come out.

Q: After fitting, `coef_` for `distance` is negative. What does that tell you?
- [ ] The model is broken, because probabilities can't be negative
  The coefficient is part of the score, not a probability; the sigmoid keeps the output between 0 and 1.
- [x] The chance of a make falls as distance grows
  A negative weight lowers the score for every extra foot, and a lower score means a lower probability.
- [ ] Long shots are always predicted as made
  It's the opposite: a negative weight pulls long shots toward "missed".
:::

:::takeaways
- Linear regression on 0/1 targets can predict values below 0 or above 1. Logistic regression passes a straight-line score through the sigmoid so every output is a probability.
- `predict_proba` gives one column per class in the order of `classes_`; `predict` applies a 0.5 threshold that you can replace with your own.
- Raising the threshold gives fewer, more confident "yes" answers.
- A decision tree is a learned flowchart. Each leaf predicts its majority class, and its probability is the share of each class in that leaf.
- Trees choose each question by trying cutoffs and keeping the one with the lowest weighted Gini impurity; `max_depth` limits how many questions in a row they can ask.
:::
