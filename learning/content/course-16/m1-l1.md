In the next lesson, a program you write will read four measurements of a flower it has never seen and tell you its species. The whole thing is five lines of Python. Those five lines need a place to run, with the right libraries installed, and that's all this lesson sets up.

You'll use **Google Colab**, a free notebook that runs in your browser. Google's computers do the work, so it runs the same on a school Chromebook as on a gaming PC, and the machine-learning libraries this course uses are already installed. Expect the whole setup to take about ten minutes.

## What you need

- A computer with an up-to-date web browser. Chrome works best with Colab, but Edge, Firefox, and Safari work too.
- A Google account. A personal Gmail account is the safest choice, because some schools switch Colab off for student accounts.
- An internet connection while you work.

You don't need a graphics card, a paid plan, or any software installs. Every lesson in this course runs on Colab's free CPU machines in seconds.

## What happens when you press Run

A Colab notebook is a page made of **cells**. A code cell holds Python; a text cell holds notes. When you run a code cell, your browser sends the code to a computer in a Google data center (Colab calls it the **runtime**), Python runs it there, and the result comes back and appears under the cell.

```mermaid caption="Your notebook lives in Drive; your code runs on a Google machine"
flowchart LR
    A["Code cell in your browser"] -->|"Shift + Enter"| B["Colab runtime runs Python"]
    B -->|"printed text, tables, charts"| A
    A -->|"saves automatically"| C[("Google Drive: Colab Notebooks folder")]
```

Two things follow from that picture. Your notebook file is safe in Drive even if you close the tab. But the runtime's memory (every variable you made) is temporary, and it's wiped when the runtime shuts down.

## Step 1: Create your first notebook

These steps are the same on every computer.

1. Go to **colab.research.google.com** and sign in with your Google account (the **Sign in** button is at the top right).
2. A window called **Open notebook** appears. Click **New notebook**. If the window doesn't appear, use the menu: **File → New notebook in Drive**. (Typing **colab.new** in the address bar is a shortcut that does the same thing.)
3. At the top left, click the name `Untitled0.ipynb` and change it to `m1-setup.ipynb`.
4. Click inside the gray code cell, type the line below, and press **Shift + Enter**.

```python run
print("Colab is working")
```

The first run takes a few seconds because Colab has to start a runtime for you. Once it's connected, the top right shows small **RAM** and **Disk** meters, a number like `[1]` appears beside the cell, and the text prints underneath.

## Step 2: Learn the run keys

You'll press these hundreds of times. The menu equivalents live under **Runtime**, but the keys are faster.

:::tabs

- **Ctrl + Enter**: run the cell and stay on it.
- **Ctrl + M**, then **B**: add a new code cell below.

- **Cmd + Return**: run the cell and stay on it.

- **Ctrl + M**, then **B**: add a new code cell below.

## Step 3: Check that the ML libraries are there

This course uses four libraries. **scikit-learn** has the models. **pandas** holds tables. **NumPy** does fast math on arrays of numbers. **matplotlib** draws charts. Paste this into a new code cell and run it:

```python run title="check_libraries.py"
import sklearn
import pandas as pd
import numpy as np
import matplotlib
import matplotlib.pyplot as plt

print("scikit-learn", sklearn.__version__)
print("pandas      ", pd.__version__)
print("NumPy       ", np.__version__)
print("matplotlib  ", matplotlib.__version__)
```

The versions above are from the machine that built this page. Yours will be a little different because Google updates Colab regularly, and that's fine. Everything in this course works with scikit-learn 1.4 or newer.

Look at the first line. The library is called **scikit-learn** when people talk about it or install it, but the Python name you import is `sklearn`. The `as pd`, `as np`, and `as plt` parts give the other libraries short nicknames, and nearly every tutorial on the internet uses those same three.

Now prove that charts work. This cell makes 300 random points in three clumps and colors them by clump:

```python run alt="Scatter plot of 300 points in three colored clusters" caption="If you can see three colored clumps, matplotlib works."
from sklearn.datasets import make_blobs

points, group = make_blobs(n_samples=300, centers=3, random_state=4)
plt.figure(figsize=(5, 4))
plt.scatter(points[:, 0], points[:, 1], c=group, cmap="viridis", s=15)
plt.title("300 points in three groups")
plt.xlabel("feature 1")
plt.ylabel("feature 2")
```

That kind of picture, points with a color for each group, is what most of this course is about: teaching a program to work out the color of a new point from its position.

:::try
Change `centers=3` to `centers=5` and run the cell again with **Ctrl + Enter** (or **Cmd + Return**). Then change `random_state=4` to another number and see the clumps move.
:::

## Fixes for the problems beginners actually hit

**A page saying you need access, or that your organization or administrator doesn't allow this app.** Your school's Google account has Colab turned off. Switch to a personal Google account with the profile picture at the top right, or ask your teacher which account to use.

**`SyntaxError: invalid syntax` on an import line.** You probably wrote the install name instead of the import name. Python reads the dash in `scikit-learn` as a minus sign:

```python run raises
import scikit-learn
```

Change it to `import sklearn`.

**`NameError: name 'pd' is not defined`.** The runtime restarted (or you opened the notebook fresh) and you ran a cell that uses `pd` before the cell that imports it. Variables don't survive a restart, but your code does, so run the import cell again, or use **Runtime → Run all** to run every cell from the top.

**"Cannot connect to GPU backend" or a message about usage limits.** Someone switched the notebook to a GPU. This course never needs one. Open **Runtime → Change runtime type**, pick **CPU**, and click **Save**.

**"Runtime disconnected" after a break.** Colab shuts down runtimes that sit idle for a while, and free sessions also have a maximum length. Click **Reconnect**, then **Runtime → Run all**. Your notebook is untouched; only the variables need rebuilding.

:::warning
Don't type `pip install sklearn` to fix an import problem. That old package name now fails on purpose with a message telling you to use `scikit-learn`. In Colab you almost never need to install anything for this course, because the libraries come preinstalled.
:::

:::quiz
Q: You open yesterday's notebook and run only the last cell, which uses `pd.DataFrame`. What happens?
- [ ] It works, because the notebook remembers yesterday's imports
  The notebook file keeps your code, but variables and imports live in the runtime's memory, which was wiped.
- [x] `NameError: name 'pd' is not defined`
  A fresh runtime hasn't run `import pandas as pd` yet. Run the import cell first, or use Runtime → Run all.
- [ ] `ModuleNotFoundError: No module named 'pandas'`
  pandas is installed in Colab. The problem is that this runtime hasn't imported it yet.

Q: Which line correctly imports scikit-learn?
- [ ] `import scikit-learn`
  The dash makes this a syntax error. That spelling is only for talking about or installing the library.
- [x] `import sklearn`
  The installed package is called scikit-learn, but its Python name is `sklearn`.
- [ ] `import scikit_learn`
  Close, but there's no module by that name, so Python raises `ModuleNotFoundError`.

Q: Where does Colab keep your notebook file?
- [x] In a folder called Colab Notebooks in your Google Drive
  New notebooks save there automatically, so you can find them from Drive or from File → Open notebook.
- [ ] On the runtime, until you download it
  The runtime is temporary. Your notebook file is saved to Drive, separately from the runtime.
- [ ] Nowhere, until you press Ctrl + S
  Colab autosaves to Drive. Ctrl + S saves right away, but you don't depend on it.
:::

:::takeaways
- Colab is a free notebook in your browser; code runs on a Google runtime and the notebook saves to your Drive.
- **Shift + Enter** runs a cell and moves on; **Ctrl + Enter** (Cmd + Return on a Mac) runs it and stays put.
- You install **scikit-learn** but import **sklearn**.
- After a restart or disconnect, rerun your cells from the top: the code survives, the variables don't.
:::
