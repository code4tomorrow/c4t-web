## Warm-up: one distance

How far apart are the points (2, 7) and (5, 3)? Work it out on paper with Pythagoras first, then check with NumPy.

```python run
import numpy as np

a = np.array([2, 7])
b = np.array([5, 3])
print("by formula:", np.sqrt(((a - b) ** 2).sum()))
print("np.linalg.norm:", np.linalg.norm(a - b))
```

The differences are 3 and 4, so the distance is √(9 + 16) = 5. `np.linalg.norm` computes the same straight-line distance in one call.

### Exercise 1: Vote by hand

Each movie below is described by two scores from 0 to 10: how much action and how much comedy it has. Using k = 3, classify a new movie with action 6 and comedy 5. Print the three nearest movies and the vote, then confirm with `KNeighborsClassifier` and its `kneighbors` method.

```python run
movies = np.array([[9, 2], [8, 3], [7, 1], [2, 8], [3, 9], [1, 7], [6, 7]])
genres = np.array(["action", "action", "action", "comedy", "comedy", "comedy", "comedy"])
new_movie = np.array([6, 5])
```

```text
nearest: [[6, 7], [8, 3], [7, 1]] ['comedy', 'action', 'action']
vote: action
```

:::hint
Subtract `new_movie` from every row, square, sum along `axis=1`, and take the square root. `np.argsort(distances)[:3]` gives the positions of the three smallest. `Counter(...).most_common(1)` from the `collections` module counts the vote.
:::

:::solution
```python run
from collections import Counter
from sklearn.neighbors import KNeighborsClassifier

distances = np.sqrt(((movies - new_movie) ** 2).sum(axis=1))
nearest = np.argsort(distances)[:3]
print("distances:", distances.round(2))
print("nearest:", movies[nearest].tolist(), genres[nearest].tolist())
print("vote:", Counter(genres[nearest]).most_common(1)[0][0])

knn = KNeighborsClassifier(n_neighbors=3).fit(movies, genres)
print("scikit-learn:", knn.predict([new_movie]), knn.kneighbors([new_movie])[1])
```

The single closest movie is a comedy, so k = 1 would say comedy. The next two are both action, so with k = 3 action wins 2 to 1. Same data, different k, different answer.
:::

### Exercise 2: Choose k without peeking at the test set

Module 3 said not to tune on the test set. So split three ways: hold out a test set first, then split the rest into a **fitting** set and a **validation** set. Try every odd k from 1 to 79 on the moons data below, fitting on the fitting set and scoring on the validation set. Plot both accuracies against k, pick the best k, then refit on fitting + validation rows and score the test set **once**.

```python run
from sklearn.datasets import make_moons
from sklearn.model_selection import train_test_split

X_m, y_m = make_moons(n_samples=600, noise=0.35, random_state=2)
X_rest, X_test, y_rest, y_test = train_test_split(X_m, y_m, test_size=0.2, random_state=0, stratify=y_m)
X_fit, X_val, y_fit, y_val = train_test_split(X_rest, y_rest, test_size=0.25, random_state=0, stratify=y_rest)
print(len(X_fit), "fitting rows,", len(X_val), "validation rows,", len(X_test), "test rows")
```

:::hint
Loop over `range(1, 80, 2)`. Store each k's fitting and validation accuracy in two lists, then plot both with `plt.plot(ks, ...)`. `ks[np.argmax(val_scores)]` finds the k with the best validation accuracy.
:::

:::solution
```python run alt="Line chart of accuracy against k from 1 to 79. Fitting accuracy starts at 1.0 for k equals 1, drops quickly, then drifts down to about 0.86. Validation accuracy starts near 0.85, rises to about 0.9 by k equals 15, peaks at k equals 29, stays near 0.89 to 0.90 until about k equals 65, then dips slightly." caption="Fitting accuracy always favors k = 1; validation accuracy shows where the real sweet spot is."
import matplotlib.pyplot as plt

ks = list(range(1, 80, 2))
fit_scores, val_scores = [], []
for k in ks:
    model = KNeighborsClassifier(n_neighbors=k).fit(X_fit, y_fit)
    fit_scores.append(model.score(X_fit, y_fit))
    val_scores.append(model.score(X_val, y_val))

best_k = ks[int(np.argmax(val_scores))]
plt.figure(figsize=(7, 3.8))
plt.plot(ks, fit_scores, label="fitting rows")
plt.plot(ks, val_scores, label="validation rows")
plt.axvline(best_k, linestyle="--", color="gray")
plt.xlabel("k (number of neighbors)")
plt.ylabel("accuracy")
plt.legend()

final = KNeighborsClassifier(n_neighbors=best_k).fit(X_rest, y_rest)
print("best k on validation:", best_k)
print("test accuracy, measured once:", round(final.score(X_test, y_test), 3))
```

The fitting-set curve always prefers k = 1, because each point is its own neighbor. The validation curve climbs as k smooths out noise, levels off, then drops a little when k gets too blunt. The test score at the end is honest, because nothing was chosen using it. A technique called cross-validation goes further, repeating this with several different validation sets so one lucky split doesn't decide k.
:::

### Exercise 3: What if k is everyone?

Split the breast cancer data with `random_state=0` and `stratify=y`. Train k-NN with `n_neighbors` equal to the **number of training rows**. Predict first: what will it predict for every test sample, and what accuracy will it get? Then check.

:::hint
If every training row is a neighbor, every new sample gets exactly the same set of neighbors. Which class wins that vote? Compare the accuracy with `(y_test == 1).mean()`.
:::

:::solution
```python run
from sklearn.datasets import load_breast_cancer

X_c, y_c = load_breast_cancer(return_X_y=True)
Xc_train, Xc_test, yc_train, yc_test = train_test_split(X_c, y_c, random_state=0, stratify=y_c)

everyone = KNeighborsClassifier(n_neighbors=len(Xc_train)).fit(Xc_train, yc_train)
print("distinct predictions:", np.unique(everyone.predict(Xc_test)))
print("accuracy:", round(everyone.score(Xc_test, yc_test), 3))
print("share of benign in test:", round((yc_test == 1).mean(), 3))
```

Every sample gets the whole training set as neighbors, so every vote is the same: benign, the majority class. The accuracy equals the share of benign samples. That's the do-nothing baseline from Module 3 in disguise: the far end of the "large k" scale.
:::

### Exercise 4: Residuals and MSE by hand

Five points: `x = [1, 2, 3, 4, 5]`, `y = [5, 6, 10, 13, 15]`. Someone proposes the line `y = 3x + 1`. Compute its predictions, residuals, and MSE by hand (paper first, then code). Then fit `LinearRegression` and compare its MSE.

```text
residuals: [ 1 -1  0  0 -1]
MSE of y = 3x + 1: 0.6
best line: y = 2.70x + 1.70, MSE 0.38
```

:::hint
Residual = actual − predicted. The predictions of `3x + 1` are 4, 7, 10, 13, 16. For scikit-learn, `x.reshape(-1, 1)` makes the one-column table `fit` needs, and `mean_squared_error(y, predictions)` scores it.
:::

:::solution
```python run
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_squared_error

x = np.array([1, 2, 3, 4, 5])
y = np.array([5, 6, 10, 13, 15])

guess = 3 * x + 1
residuals = y - guess
print("residuals:", residuals)
print("MSE of y = 3x + 1:", (residuals ** 2).mean())

best = LinearRegression().fit(x.reshape(-1, 1), y)
best_mse = mean_squared_error(y, best.predict(x.reshape(-1, 1)))
print(f"best line: y = {best.coef_[0]:.2f}x + {best.intercept_:.2f}, MSE {best_mse:.2f}")
```

The guessed line is close (three of its residuals are ±1), but the fitted line trades a slightly smaller slope for a bigger intercept and gets the MSE down from 0.6 to 0.38. No line through these points can do better than 0.38; that's what "best fit" means.
:::

### Exercise 5: Learning rates that crawl, zigzag, and explode

Using gradient descent on the standardized BMI (as in the build-along), run 30 steps with each learning rate in `[0.01, 0.1, 0.95, 1.05]` and plot the four loss curves on one chart with a log-scale y-axis. Then, part (b): try `learning_rate=0.01` on **raw**, unstandardized BMI and print the loss after 30 steps.

:::hint
Write a function `loss_history(x, y, rate, steps=30)` that runs the build-along's loop and returns the list of losses. `plt.yscale("log")` keeps the exploding curve from flattening the others. For part (b), pass the raw BMI array instead of the standardized one.
:::

:::solution
```python run alt="Line chart of loss on a log scale over 30 steps for four learning rates. Rate 0.01 falls slowly. Rate 0.1 falls fast and flattens. Rate 0.95 falls more slowly than 0.1. Rate 1.05 rises steadily, ending far above where it started." caption="Too small crawls, a bit under the limit zigzags, over the limit diverges."
from sklearn.datasets import load_diabetes

diabetes = load_diabetes(as_frame=True, scaled=False)
bmi = diabetes.data["bmi"].to_numpy()
target = diabetes.target.to_numpy()
z = (bmi - bmi.mean()) / bmi.std()

def loss_history(x, y, rate, steps=30):
    w = b = 0.0
    losses = []
    for _ in range(steps):
        error = (w * x + b) - y
        losses.append((error ** 2).mean())
        w -= rate * 2 * (error * x).mean()
        b -= rate * 2 * error.mean()
    return losses

plt.figure(figsize=(7, 4))
for rate in [0.01, 0.1, 0.95, 1.05]:
    plt.plot(loss_history(z, target, rate), label=f"learning rate {rate}")
plt.yscale("log")
plt.xlabel("step")
plt.ylabel("MSE (log scale)")
plt.legend()

print(f"(b) raw BMI, rate 0.01: loss after 30 steps = {loss_history(bmi, target, 0.01)[-1]:.2e}")
```

At **0.01** the steps are so small that 30 aren't nearly enough. **0.1** gets there quickly. At **0.95** each step overshoots the bottom and lands on the far side, slightly lower each time: a zigzag that converges slowly. At **1.05** each overshoot lands *higher* than before, and the loss grows without limit.

Part (b) explains the build-along's standardizing step. Raw BMIs are around 26 instead of within a couple of units of 0, so the gradient for `w` is many times bigger, and a learning rate that's fine for standardized data now overshoots wildly (the loss reaches a number with about 70 digits). On raw data you'd need a rate around 0.0001 and many more steps. Standardizing lets one sensible learning rate work for every feature.
:::

### Exercise 6: Neighbors or a line?

Make two datasets and, for each, compare the test MAE of `LinearRegression` and `KNeighborsRegressor(n_neighbors=5)`:

- **(a) A curve:** 120 points with `x` from 0 to 6 and `y = 10 * sin(x)` plus noise. Use a random `train_test_split`.
- **(b) A trend you must extend:** 120 points with `x` from 0 to 7 and `y = 4x + 3` plus noise. Train on points with `x < 5` and test on the rest.

Predict the winner of each before running it.

:::hint
Generate the data with `rng = np.random.default_rng(0)`, `rng.uniform(...)` for `x`, and `rng.normal(0, 1.5, 120)` for the noise. For (b), a Boolean mask like `x2 < 5` picks the training rows and `~mask` picks the test rows. Remember `reshape(-1, 1)` for one-feature `X`.
:::

:::solution
```python run
from sklearn.metrics import mean_absolute_error
from sklearn.neighbors import KNeighborsRegressor

rng = np.random.default_rng(0)

x1 = rng.uniform(0, 6, 120)
y1 = 10 * np.sin(x1) + rng.normal(0, 1.5, 120)
x1_tr, x1_te, y1_tr, y1_te = train_test_split(x1.reshape(-1, 1), y1, random_state=0)

x2 = rng.uniform(0, 7, 120)
y2 = 4 * x2 + 3 + rng.normal(0, 1.5, 120)
seen = x2 < 5
x2_tr, x2_te = x2[seen].reshape(-1, 1), x2[~seen].reshape(-1, 1)
y2_tr, y2_te = y2[seen], y2[~seen]

for name, (Xtr, Xte, ytr, yte) in {"(a) curve": (x1_tr, x1_te, y1_tr, y1_te),
                                    "(b) extend trend": (x2_tr, x2_te, y2_tr, y2_te)}.items():
    line_mae = mean_absolute_error(yte, LinearRegression().fit(Xtr, ytr).predict(Xte))
    knn_mae = mean_absolute_error(yte, KNeighborsRegressor(n_neighbors=5).fit(Xtr, ytr).predict(Xte))
    print(f"{name:18s} line MAE {line_mae:.2f}   k-NN MAE {knn_mae:.2f}")
```

On the curve, a straight line can't bend, so k-NN wins easily by following the wave locally. On the trend, every test point lies beyond the training range: the line simply continues and stays accurate, while k-NN keeps predicting the average of the last few training points it knows. Pick the model whose assumptions match the data and the questions you'll ask it.
:::

### Challenge: k-NN from scratch

Write `knn_predict(X_train, y_train, X_new, k=5)` using only NumPy and `Counter`, returning one prediction per row of `X_new`. Test it on an iris split (`random_state=0`, `stratify`) and check that it agrees with scikit-learn's `KNeighborsClassifier()` on every test flower.

```text
agreement with scikit-learn: 1.0
accuracy: 1.0
```

:::hint
Loop over the rows of `X_new`. For each, reuse your code from Exercise 1: distances to all training rows, `argsort`, keep the first `k`, and vote. Collect the answers in a list and return `np.array(answers)`. Agreement is `(mine == theirs).mean()`.
:::

:::solution
```python run
from sklearn.datasets import load_iris

def knn_predict(X_train, y_train, X_new, k=5):
    answers = []
    for row in X_new:
        distances = np.sqrt(((X_train - row) ** 2).sum(axis=1))
        nearest = np.argsort(distances)[:k]
        answers.append(Counter(y_train[nearest]).most_common(1)[0][0])
    return np.array(answers)

iris = load_iris()
Xi_tr, Xi_te, yi_tr, yi_te = train_test_split(iris.data, iris.target, random_state=0, stratify=iris.target)

mine = knn_predict(Xi_tr, yi_tr, Xi_te)
theirs = KNeighborsClassifier().fit(Xi_tr, yi_tr).predict(Xi_te)
print("agreement with scikit-learn:", (mine == theirs).mean())
print("accuracy:", (mine == yi_te).mean())
```

Eight lines reproduce the model you've been using since Module 1. scikit-learn's version is faster on big data (it organizes the training points so it doesn't have to measure every distance) and handles ties and weighting options, but the idea is identical. If your agreement is below 1.0, print the rows where they differ; a tie in the vote or in distance is usually the reason.
:::
