## Warm-up: an 80/20 split

Split the iris data so 20% is held out for testing, with `random_state=7`, and print the shapes of all four pieces.

```python run
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split

X_iris, y_iris = load_iris(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(X_iris, y_iris, test_size=0.2, random_state=7)
print(X_train.shape, X_test.shape, y_train.shape, y_test.shape)
```

120 rows to learn from, 30 to test on, and the first numbers of `X` and `y` agree within each part.

### Exercise 1: The sorted-data trap

Someone made a test set by taking the **last 30 rows** of iris. Count how many flowers of each species end up in their training and test sets. Then do the same for a stratified `train_test_split` with `test_size=30` and `random_state=7`.

```text
sliced     train: [50 50 20]  test: [ 0  0 30]
stratified train: [40 40 40]  test: [10 10 10]
```

:::hint
`np.bincount(labels)` counts how many 0s, 1s, and 2s are in an array. Slicing with `y_iris[:120]` and `y_iris[120:]` gives the sliced version.
:::

:::solution
```python run
import numpy as np

print("sliced     train:", np.bincount(y_iris[:120], minlength=3), " test:", np.bincount(y_iris[120:], minlength=3))

_, _, y_tr, y_te = train_test_split(X_iris, y_iris, test_size=30, random_state=7, stratify=y_iris)
print("stratified train:", np.bincount(y_tr), " test:", np.bincount(y_te))
```

The sliced test set contains only virginica, so its score would say nothing about setosa or versicolor, and the model trained on just 20 virginica. The stratified split puts exactly a fifth of each species in the test set. `minlength=3` makes `bincount` print a 0 for missing species instead of a shorter array.
:::

### Exercise 2: How much does stratify matter?

Using the breast cancer data, split with `test_size=0.2` and `random_state=3`, once without `stratify` and once with `stratify=y`. For each, print the share of malignant samples (target `0`) in the full data, the training set, and the test set.

:::hint
`(y == 0).mean()` gives the fraction of rows where the target is 0, because `True` counts as 1 and `False` as 0. Loop over `[None, y]` as the value of `stratify` to avoid writing the split twice.
:::

:::solution
```python run
from sklearn.datasets import load_breast_cancer

X, y = load_breast_cancer(return_X_y=True)
for strat, label in [(None, "plain     "), (y, "stratified")]:
    X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, random_state=3, stratify=strat)
    print(f"{label} full {(y == 0).mean():.3f}  train {(y_tr == 0).mean():.3f}  test {(y_te == 0).mean():.3f}")
```

Without stratifying, this split happens to put fewer malignant samples in the test set (35.1% versus 37.3% overall). That looks small, but with 114 test rows it's about two fewer of the cases you most need to catch. Stratified, the test share is as close to the true share as whole rows allow.
:::

### Exercise 3: StandardScaler by hand

Split the breast cancer data with `random_state=0` and `stratify=y`. Compute each feature's mean and standard deviation from the **training rows** with NumPy, standardize the **test rows** by hand, and check that your result matches `StandardScaler().fit(X_train).transform(X_test)`.

```text
match: True
first test row, first 3 features: [-0.12 -0.67 -0.17]
```

:::hint
`X_train.mean(axis=0)` gives one mean per column (`axis=0` means "down the rows"). Use `X_train.std(axis=0)` for the spread. Watch out if you try pandas: its `.std()` divides by n − 1 by default, while `StandardScaler` divides by n, so they differ slightly. `np.allclose(a, b)` checks whether two arrays match up to rounding.
:::

:::solution
```python run
from sklearn.preprocessing import StandardScaler

X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=0, stratify=y)

means = X_train.mean(axis=0)
stds = X_train.std(axis=0)
by_hand = (X_test - means) / stds

by_sklearn = StandardScaler().fit(X_train).transform(X_test)
print("match:", np.allclose(by_hand, by_sklearn))
print("first test row, first 3 features:", by_hand[0, :3].round(2))
```

`StandardScaler` is these three lines with some safety checks. It remembers `means` and `stds` (as `mean_` and `scale_`) from training, and every later `transform` uses those same numbers. The test rows are measured against the *training* average, which is what keeps them honest.
:::

### Exercise 4: Fix the leaky code

This code runs and prints a good score, but it breaks two rules from the Notes lesson. Find both, then rewrite it as a pipeline that's fitted on training rows only.

```python run
from sklearn.neighbors import KNeighborsClassifier

X_all = StandardScaler().fit_transform(X)
X_tr, X_te, y_tr, y_te = train_test_split(X_all, y, test_size=0.2, random_state=3, stratify=y)
X_te = StandardScaler().fit_transform(X_te)
leaky = KNeighborsClassifier().fit(X_tr, y_tr)
print("leaky score:", round(leaky.score(X_te, y_te), 3))
```

:::hint
Look for every call to `fit` or `fit_transform` and ask which rows it learned from. One happens before the split. Another learns a second, different set of means from the test rows.
:::

:::solution
**Bug 1:** the scaler is fitted on all of `X` before splitting, so test rows shape the training data's scaling. **Bug 2:** the test set is scaled again with `fit_transform`, using its own mean and standard deviation, so it's measured with a different ruler from the training set.

```python run
from sklearn.pipeline import make_pipeline

X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, random_state=3, stratify=y)
honest = make_pipeline(StandardScaler(), KNeighborsClassifier()).fit(X_tr, y_tr)
print("honest score:", round(honest.score(X_te, y_te), 3))
```

The honest score is exactly the same as the leaky one here, and that's what makes this bug so easy to ship: nothing looks wrong. With 569 rows, the means and standard deviations hardly change whichever rows they're learned from, so the damage is invisible. With a small dataset, or steps that learn more (like picking features), it can be large. The pipeline makes both bugs impossible to write.
:::

### Exercise 5: A category the encoder never saw

An encoder is trained on players from Android and iOS. Then a web player shows up. Run this, read the error, and fix the encoder so the web player gets all-zero device columns.

```python run raises
import pandas as pd
from sklearn.preprocessing import OneHotEncoder

old_players = pd.DataFrame({"device": ["android", "ios", "ios", "android"]})
new_player = pd.DataFrame({"device": ["web"]})

encoder = OneHotEncoder(sparse_output=False).fit(old_players)
print(encoder.transform(new_player))
```

```text
['device_android' 'device_ios']
[[0. 0.]]
```

:::hint
The last line of the error names the unknown category. `OneHotEncoder` has a setting that decides what to do in that situation; its default is to raise an error.
:::

:::solution
```python run
encoder = OneHotEncoder(handle_unknown="ignore", sparse_output=False).fit(old_players)
print(encoder.get_feature_names_out())
print(encoder.transform(new_player))
```

With `handle_unknown="ignore"`, a new category becomes a row of zeros: "none of the devices I know". For a model running in an app, that's usually better than crashing. If a new category turns up often, it's a sign to retrain with data that includes it.
:::

### Exercise 6: Does scaling always help?

The digits dataset has 64 pixel features, each already measured on the same 0 to 16 brightness scale. **Predict first**: will `StandardScaler` help k-NN here? Then measure it with a stratified split (`random_state=0`), comparing k-NN with and without the scaler.

:::hint
Build two models: `KNeighborsClassifier()` and `make_pipeline(StandardScaler(), KNeighborsClassifier())`. Fit both on the same training rows and compare `score` on the same test rows.
:::

:::solution
```python run
from sklearn.datasets import load_digits

X_d, y_d = load_digits(return_X_y=True)
Xd_tr, Xd_te, yd_tr, yd_te = train_test_split(X_d, y_d, random_state=0, stratify=y_d)

plain = KNeighborsClassifier().fit(Xd_tr, yd_tr)
scaled = make_pipeline(StandardScaler(), KNeighborsClassifier()).fit(Xd_tr, yd_tr)
print("raw pixels:   ", round(plain.score(Xd_te, yd_te), 3))
print("scaled pixels:", round(scaled.score(Xd_te, yd_te), 3))
```

Scaling made it slightly *worse*. The pixels already share one unit, so there's no imbalance to fix. Worse, pixels near the edge of the image are almost always 0 and only occasionally faint. Standardizing divides by their tiny standard deviation, which blows that occasional faint smudge up into a big number, so noise at the edges starts to matter as much as the strokes in the middle. Scaling fixes *mismatched units*; it isn't a free upgrade.
:::

### Challenge: A pipeline for used-bike listings

A resale website wants to flag listings likely to sell within a week. Each listing has a price, the bike's age, its kind (`road`, `mountain`, `kids`), and the city. Build the data with the cell below, then:

1. Split with `test_size=0.25`, `stratify`, and `random_state=0`.
2. Print the majority-guess baseline.
3. Score k-NN on the two numeric columns only, scaled.
4. Build a pipeline that scales the numbers **and** one-hot encodes both text columns, and score it.

```python run
rng = np.random.default_rng(13)
n = 300
kind = rng.choice(["road", "mountain", "kids"], n, p=[0.4, 0.4, 0.2])
city = rng.choice(["Austin", "Denver", "Portland"], n)
age = rng.integers(0, 15, n)
price = rng.integers(5, 120, n) * 10
appeal = (-0.004 * price - 0.12 * age + 2.2 * (kind == "kids")
          + 2.0 * ((city == "Denver") & (kind == "mountain")) + 1.6 + rng.normal(0, 0.6, n))
bikes = pd.DataFrame({"price": price, "age_years": age, "kind": kind, "city": city,
                      "sold_in_week": (appeal > 0).astype(int)})
print(bikes.head())
```

```text
baseline: 0.693
numbers only: 0.747
numbers + kind + city: 0.84
```

:::hint
`make_column_transformer` takes pairs of (step, list of columns). Put both text columns in one list for a single `OneHotEncoder`. The numbers-only version is just `make_pipeline(StandardScaler(), KNeighborsClassifier())` fitted on `X_train[numeric]`.
:::

:::solution
```python run
from sklearn.compose import make_column_transformer

numeric = ["price", "age_years"]
categorical = ["kind", "city"]
X_b = bikes[numeric + categorical]
y_b = bikes["sold_in_week"]
Xb_tr, Xb_te, yb_tr, yb_te = train_test_split(X_b, y_b, test_size=0.25, stratify=y_b, random_state=0)

print("baseline:", round(max(yb_te.mean(), 1 - yb_te.mean()), 3))

numbers_only = make_pipeline(StandardScaler(), KNeighborsClassifier()).fit(Xb_tr[numeric], yb_tr)
print("numbers only:", round(numbers_only.score(Xb_te[numeric], yb_te), 3))

bike_model = make_pipeline(
    make_column_transformer(
        (StandardScaler(), numeric),
        (OneHotEncoder(handle_unknown="ignore"), categorical),
    ),
    KNeighborsClassifier(),
)
bike_model.fit(Xb_tr, yb_tr)
print("numbers + kind + city:", round(bike_model.score(Xb_te, yb_te), 3))
```

Kids' bikes sell fast, and so do mountain bikes in Denver. Neither fact is visible in price and age alone, so the numbers-only model is only a little better than the baseline. With `kind` and `city` encoded, listings of the same kind in the same city become each other's neighbors, and the model can pick up both patterns.
:::
