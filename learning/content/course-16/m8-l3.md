The night before a presentation is the worst time to discover that your notebook only worked because of a cell you deleted on Tuesday. This lesson is about catching problems while they're cheap: with code that checks your process, a clean rerun, and a self-review against the rubric your work will be graded on.

## Write checks, not hopes

A model comparison can be wrong in ways no error message will ever reveal. A test row sneaks into training; a scaler sits outside its pipeline; a rerun gives different numbers. Each of those can be turned into a line of code that prints PASS or FAIL. Here's a checks cell, shown on a small iris comparison so it runs quickly. Copy the `check` lines into your own notebook, after Milestone 3, and change the names to match yours.

```python run
import numpy as np
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split, StratifiedKFold, cross_val_score
from sklearn.pipeline import Pipeline, make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.dummy import DummyClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.neighbors import KNeighborsClassifier
from sklearn.tree import DecisionTreeClassifier

X, y = load_iris(return_X_y=True)
rows = np.arange(len(y))
X_train, X_test, y_train, y_test, rows_train, rows_test = train_test_split(
    X, y, rows, test_size=0.2, stratify=y, random_state=0)
folds = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
models = {
    "logistic regression (scaled)": make_pipeline(StandardScaler(), LogisticRegression()),
    "k-NN (scaled)": make_pipeline(StandardScaler(), KNeighborsClassifier()),
    "tree": DecisionTreeClassifier(max_depth=3, random_state=0),
}
cv_means = {name: cross_val_score(m, X_train, y_train, cv=folds).mean() for name, m in models.items()}
baseline = cross_val_score(DummyClassifier(), X_train, y_train, cv=folds).mean()

passed = []
def check(description, condition):
    passed.append(bool(condition))
    print("PASS" if condition else "FAIL", "-", description)

check("no row is in both train and test", not set(rows_train) & set(rows_test))
check("class shares in train and test differ by under 5 points",
      np.all(np.abs(np.bincount(y_train) / len(y_train) - np.bincount(y_test) / len(y_test)) < 0.05))
check("every scaled model is a pipeline",
      all(isinstance(m, Pipeline) for name, m in models.items() if "scaled" in name))
again = cross_val_score(models["tree"], X_train, y_train, cv=folds).mean()
check("cross-validation gives the same score twice", again == cv_means["tree"])
check("every model beats the baseline", all(score > baseline for score in cv_means.values()))
check("all scores are between 0 and 1", all(0 <= s <= 1 for s in [baseline, *cv_means.values()]))
print(f"{sum(passed)} of {len(passed)} checks passed")
```

Each check matches a rule from the brief. The row-number trick deserves a note: passing `rows` as an extra array to `train_test_split` splits it exactly like `X` and `y`, so you can prove which original rows ended up where. The reproducibility check only passes if every random step has a `random_state`; remove the one in `StratifiedKFold` and it will fail on most runs.

:::try
Break something on purpose to see a check catch it. Replace `make_pipeline(StandardScaler(), KNeighborsClassifier())` with plain `KNeighborsClassifier()` but keep the name `"k-NN (scaled)"`, as if you'd forgotten the scaler. Rerun and watch the pipeline check fail. Then put the pipeline back.
:::

## Rerun from a fresh session

Checks only help if the notebook runs at all. Choose **Runtime → Restart session and run all**. Colab wipes every variable and runs each cell once, top to bottom. If it reaches the end with no errors and the same numbers as before, the notebook is reproducible. If a cell fails, it depended on something you ran by hand and later changed or deleted; fix it now.

Then check the numbers themselves. Do the CV scores in your write-up match what's printed? Every number in your recommendation should be copied from output, not remembered.

## Polish the notebook

Someone reading your notebook should be able to follow it without you in the room. Before you hand it in:

- The data card and plan are text cells at the very top.
- Each milestone starts with a short text cell saying what it does and what you found.
- Every chart has a title, labeled axes, and units where they apply.
- Printed numbers are rounded to 3 decimal places, not 16.
- Dead experiments are deleted, not commented out. (Keep them in a separate scratch notebook if you like them.)
- Every `random_state` is set, so your numbers are the reader's numbers.

The single biggest upgrade is a results chart whose title is the conclusion, not the topic. "Model accuracy" makes the reader work it out; "k-NN on raw pixels reads digits best" tells them. Here's the digits comparison from Lesson 2, polished:

```python run alt="Horizontal bar chart of cross-validated accuracy with error bars: k-NN on raw pixels is the longest bar at 0.985 and highlighted, logistic regression and scaled k-NN are at 0.970, the tree is at 0.842, and the gray baseline bar is at 0.102; each bar has its value printed at the end" caption="A title that states the finding, values on the bars, and the baseline in gray."
import pandas as pd
import matplotlib.pyplot as plt

summary = pd.DataFrame({
    "model": ["baseline", "tree, depth 10", "k-NN, scaled", "logistic regression", "k-NN (k=3), raw pixels"],
    "accuracy": [0.102, 0.842, 0.970, 0.970, 0.985],
    "std": [0.001, 0.012, 0.006, 0.011, 0.003],
})
colors = ["#b8b8b8", "#9fb0e8", "#9fb0e8", "#9fb0e8", "#2f55d4"]

fig, ax = plt.subplots(figsize=(7.5, 3.4))
ax.barh(summary["model"], summary["accuracy"], xerr=summary["std"], color=colors, capsize=4)
for i, acc in enumerate(summary["accuracy"]):
    ax.text(acc + 0.02, i, f"{acc:.3f}", va="center")
ax.set_xlim(0, 1.12)
ax.set_xlabel("5-fold cross-validated accuracy (training set)")
ax.set_title("k-NN on raw pixels reads digits best")
plt.show()
```

Sorted bars, one highlight color for the recommendation, gray for the baseline, and numbers printed on the bars so nobody has to squint at the axis. The error bars stay, because they show which gaps are real.

## Present it in three minutes

You won't have time to show the whole notebook, and you shouldn't. Lead with the answer, then earn it:

1. **The question and the answer** (20 seconds). "We wanted a model to read handwritten digits. We recommend k-NN with k=3, which read 98.6% of test digits correctly."
2. **The data** (20 seconds). One sentence from your data card and one picture of the data.
3. **The contest** (40 seconds). The polished chart. Say how the comparison was kept fair: same folds, pipelines, a locked test set.
4. **The diagnosis** (30 seconds). One fit curve and what it showed, such as the tree memorizing at every depth past 10.
5. **The mistakes** (40 seconds). The error gallery and the pattern you found.
6. **Limits and next step** (30 seconds). What the model can't be trusted with, and one experiment you'd run next.

Say the limits yourself, before someone in the audience does. "It might struggle with handwriting styles it hasn't seen" sounds like expertise. Being asked about it and having no answer sounds like you didn't look.

## The rubric

Grade yourself honestly before you submit. Each row is scored 1 to 4.

| Criterion | 4: Excellent | 3: Solid | 2: Developing | 1: Missing |
| --- | --- | --- | --- | --- |
| **Data and plan** | Complete data card and plan, written before modeling, with a tie-break rule | Data card and plan present, a field or two thin | Partial data card or plan written after results | Neither |
| **Leak-free process** | Test set split first and used once; all preprocessing in pipelines; checks cell passes | Test set used once; one small preprocessing slip | Test set used more than once, or scaler outside pipeline | No held-out test set |
| **Fair comparison** | Baseline plus 3+ models, same folds, 2+ metrics with mean ± std | Baseline plus 3 models, same folds, one metric | Fewer than 3 models, or different splits per model | Single model |
| **Fit diagnosis** | Training-vs-validation curve with a clear explanation of under- or overfitting | Curve present, explanation brief | Train and validation numbers mentioned, no curve | Not addressed |
| **Error analysis** | Specific mistakes examined, a pattern named, and a likely reason given | Mistakes listed with some pattern | Confusion matrix shown without comment | Not addressed |
| **Recommendation** | One model chosen with evidence, honest limits, and a concrete next step | Clear choice with evidence; limits thin | Choice stated with little evidence | No recommendation |
| **Notebook quality** | Restart-and-run-all works; text cells guide the reader; charts titled with findings | Runs cleanly; some sections unexplained | Runs only with manual fixes | Doesn't run |

A 4 in every row doesn't require a high accuracy. An iris project with a careful tie-break argument can outscore a digits project with a leaky pipeline.
