## The starter notebook

Get this running first, with your own dataset swapped in if you're not doing digits. A tiny notebook that runs end to end beats a fancy one that crashes halfway.

```python run title="starter.py"
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split, StratifiedKFold, cross_val_score
from sklearn.dummy import DummyClassifier
from sklearn.neighbors import KNeighborsClassifier

# 1. Data (swap in your own loader here)
X, y = load_digits(return_X_y=True)

# 2. Lock away the test set before anything else
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, stratify=y, random_state=0)

# 3. One set of folds for every model
folds = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)

# 4. Baseline and one real model
for name, model in [("baseline", DummyClassifier()), ("k-NN", KNeighborsClassifier())]:
    scores = cross_val_score(model, X_train, y_train, cv=folds)
    print(f"{name:<9} accuracy {scores.mean():.3f} ± {scores.std():.3f}")
```

Two lines of output, and the skeleton of the whole project is already there: a locked test set, shared folds, a baseline, and a model that beats it. Every milestone below grows one part of this.

## Milestone 1: Data card and a look at the data

Fill in the data card from Lesson 1 in a text cell. For digits it reads:

```text
Name and source:     scikit-learn load_digits (UCI optical recognition of handwritten digits)
One row is:          one handwritten digit, scanned and reduced to an 8x8 grid
Rows and columns:    1,797 rows, 64 pixel columns, each 0 (blank) to 16 (full ink)

Known issues:        very low resolution; written by a few dozen people, so styles are limited
Who is affected:     a misread digit changes a recorded score; 1/7 and 3/8 mix-ups are the likely risks
```

Then look at real examples, because a data card written without looking at the data is a guess:

```python run alt="A row of ten tiny 8-by-8 grayscale images of handwritten digits 0 through 9, each labeled with its digit" caption="What the model sees: 64 numbers per digit."
import numpy as np
import matplotlib.pyplot as plt

print("Training rows:", len(X_train), "| test rows:", len(X_test))

fig, axes = plt.subplots(1, 10, figsize=(10, 1.6))
for digit, ax in enumerate(axes):
    first = np.where(y_train == digit)[0][0]
    ax.imshow(X_train[first].reshape(8, 8), cmap="gray_r")
    ax.set_title(str(digit))
    ax.axis("off")
plt.show()
```

At 8×8 pixels, some digits are hard even for people. That's worth one sentence in your write-up, because it sets expectations for the error analysis.

## Milestone 2: An evaluation helper and the baseline

Your plan named two metrics. For ten balanced classes, accuracy is reasonable, and **macro F1** (F1 computed for each digit, then averaged so every digit counts equally) catches a model that's great at most digits but bad at one. Write one helper so every model is measured identically:

```python run
import pandas as pd
from sklearn.model_selection import cross_validate

def evaluate(name, model):
    r = cross_validate(model, X_train, y_train, cv=folds,
                       scoring=["accuracy", "f1_macro"], return_train_score=True)
    return {
        "model": name,
        "CV accuracy": r["test_accuracy"].mean(),
        "± std": r["test_accuracy"].std(),
        "CV macro F1": r["test_f1_macro"].mean(),
        "train accuracy": r["train_accuracy"].mean(),
    }

print(pd.DataFrame([evaluate("baseline", DummyClassifier())]).round(3))
```

The baseline guesses the most common digit every time and is right about 10% of the time, which is chance with ten classes. Its macro F1 is near 0 because it never predicts nine of the ten digits.

## Milestone 3: Four models on the same folds

```python run
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier

pd.set_option("display.width", 120)
candidates = {
    "baseline": DummyClassifier(),
    "logistic regression": make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000)),
    "k-NN, scaled": make_pipeline(StandardScaler(), KNeighborsClassifier()),
    "k-NN, raw pixels": KNeighborsClassifier(),
    "tree, depth 10": DecisionTreeClassifier(max_depth=10, random_state=0),
}
results = pd.DataFrame([evaluate(name, model) for name, model in candidates.items()]).round(3)
print(results)
```

`max_iter=1000` gives logistic regression enough steps to finish fitting 64 features; with the default, Colab may show a `ConvergenceWarning`.

Two findings here are worth writing up. First, the tree's training accuracy is far above its CV accuracy, a gap you'll investigate next. Second, **scaling made k-NN worse**. That's the opposite of what you might expect from Module 3. All 64 pixels already share one unit (ink, 0 to 16). `StandardScaler` stretches every pixel to the same spread, so a corner pixel that's almost always blank gets as much say in the distance as a pixel in the middle of the digit. Scaling fixes features measured in *different* units; here it amplifies noise. That's the kind of observation that makes a capstone more than a table of numbers.

## Milestone 4: Diagnose fit

Draw a cross-validated curve for the model with the biggest train/CV gap, the tree:

```python run alt="Line chart of tree accuracy against max_depth: training accuracy climbs from about 0.3 at depth 2 to 1.0 by depth 15, while cross-validated accuracy rises to about 0.85 around depth 10 and then flattens" caption="The tree reaches its ceiling near 0.85 while training accuracy keeps climbing to 1.0."
depths = [2, 4, 6, 8, 10, 12, 15, None]
train_acc, cv_acc = [], []
for depth in depths:
    r = cross_validate(DecisionTreeClassifier(max_depth=depth, random_state=0), X_train, y_train,
                       cv=folds, return_train_score=True)
    train_acc.append(r["train_score"].mean())
    cv_acc.append(r["test_score"].mean())

labels = [str(d) for d in depths]
plt.figure(figsize=(7, 3.5))
plt.plot(labels, train_acc, marker="o", label="training")
plt.plot(labels, cv_acc, marker="o", label="cross-validated")
plt.xlabel("max_depth")
plt.ylabel("accuracy")
plt.legend()
plt.show()
```

Past depth 10, the tree memorizes the training digits (training accuracy reaches 1.0) while its CV accuracy stalls around 0.85. No depth makes it competitive: asking about one pixel at a time is a poor way to read handwriting. That's a model limitation, not a tuning problem, and saying so is a legitimate finding.

Now tune k for the winning family, raw-pixel k-NN:

```python run
for k in [1, 3, 5, 7, 10, 15, 25]:
    r = cross_validate(KNeighborsClassifier(n_neighbors=k), X_train, y_train, cv=folds, return_train_score=True)
    print(f"k={k:<3} train {r['train_score'].mean():.3f}  CV {r['test_score'].mean():.3f} ± {r['test_score'].std():.3f}")
```

`k=1` has the best CV mean, but `k=3` is within its standard deviation and is steadier from fold to fold. The plan said near-ties go to the less extreme setting, and `k=1` is the most extreme a k-NN can be (one mislabeled training digit fools it every time). So the choice is `k=3`, decided by a rule written before the results came in.

## Milestone 5: Choose, then test once

```python run alt="A 10-by-10 confusion matrix for the test set with large counts on the diagonal for every digit and only five scattered off-diagonal ones" caption="Nearly everything on the diagonal. The five exceptions are the error analysis."
from sklearn.metrics import accuracy_score, f1_score, ConfusionMatrixDisplay

final = KNeighborsClassifier(n_neighbors=3).fit(X_train, y_train)
pred = final.predict(X_test)
print(f"Test accuracy: {accuracy_score(y_test, pred):.3f}")
print(f"Test macro F1: {f1_score(y_test, pred, average='macro'):.3f}")
print("Wrong:", (pred != y_test).sum(), "of", len(y_test))

ConfusionMatrixDisplay.from_predictions(y_test, pred, cmap="Blues", colorbar=False)
plt.show()
```

The test accuracy lands right next to the cross-validated estimate, so the process held up. This is the only time the test set is used.

## Milestone 6: Look at every mistake

With five errors, you can look at each one. (With fifty, you'd look at the most common confusions from the matrix instead.)

```python run alt="Five tiny handwritten digit images, each titled with its true label and the model's wrong guess" caption="The test digits k-NN misread. Would you have read them correctly?"
wrong = np.where(pred != y_test)[0]
fig, axes = plt.subplots(1, len(wrong), figsize=(2 * len(wrong), 2.2))
for ax, i in zip(axes, wrong):
    ax.imshow(X_test[i].reshape(8, 8), cmap="gray_r")
    ax.set_title(f"true {y_test[i]}, said {pred[i]}")
    ax.axis("off")
plt.show()

for i in wrong:
    print(f"true {y_test[i]} -> predicted {pred[i]}")
```

Look for a pattern before writing anything. Here, four of the five mistakes involve an 8 or a 9, and three involve a 3 (either as the truth or the guess). In an 8×8 grid, the loops of an 8 or 9 and the curves of a 3 differ by only a few pixels. Your write-up should say which mistakes happen and suggest why; "the model is 98.6% accurate" says neither.

## Milestone 7: Write the recommendation

Use this shape in a text cell, and fill in every bracket with a number from your notebook:

```text
RECOMMENDATION
Use [model + setting]. In 5-fold cross-validation on [n] training rows it scored [metric ± std],
ahead of [runner-up] at [score] and the baseline at [score]. On the untouched test set it scored
[score], close to the cross-validated estimate.
Why not the others: [one sentence each, with the evidence].
Limits: [what it gets wrong, from the error analysis; what the data can't tell us].
Next step: [one concrete experiment].
```

For the digits example:

> Use k-NN with k=3 on raw pixels. In 5-fold cross-validation on 1,437 training digits it scored 0.985 ± 0.003 accuracy, ahead of logistic regression and scaled k-NN at about 0.97, and far ahead of the 0.10 baseline. On the untouched test set it scored 0.986. A decision tree topped out near 0.85 at any depth while memorizing its training data. k=1 scored about the same as k=3 but is more fragile, so we chose k=3 by a rule set before testing. Limits: most of its five test errors involve 3, 8, and 9, and with only 8×8 images and a few dozen writers, it may do worse on new handwriting styles. Next step: collect a few digits from new writers and check whether accuracy holds.

## Adapting the milestones to your project

| If your project is... | Change this |
| --- | --- |
| Regression (`make_friedman1` or a numeric CSV) | `KFold` instead of `StratifiedKFold`; `DummyRegressor`; regressors instead of classifiers; scoring `["neg_mean_absolute_error", "r2"]` (flip the sign of MAE); error analysis looks at the largest misses. |
| Rare events | Scoring `["recall", "precision"]` or `"f1"`; choose a threshold on a validation split as in Module 6; error analysis looks at the missed positives. |
| Iris | Everything ties, so Milestone 7's "why not the others" needs care: use the std and your plan's tie-break rule. |
| Your own CSV | Add encoding for text columns inside the pipeline (Module 3), and check for columns that leak the answer before Milestone 1. |

:::takeaways
- A minimal end-to-end notebook comes first; each milestone grows it without breaking it.
- One `evaluate` helper and one `folds` object make every comparison identical.
- Fit diagnosis can show that a model is limited, not just badly tuned; both are findings.
- Near-ties are settled by a rule written in the plan, not by which number you like.
- Error analysis means looking at the actual mistakes and naming a pattern.
:::
