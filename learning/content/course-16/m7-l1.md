A decision tree with no depth limit scores a perfect 100% on the 420 rows it trained on. On 180 rows it hasn't seen, it drops to 79%. A tree that is only allowed four levels of questions scores lower in training and *higher* on the new rows. The model that looked best was the one that had memorized the most.

```python run
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

X, y = make_classification(n_samples=600, n_features=6, n_informative=4, n_redundant=0,
                           flip_y=0.15, random_state=0)
X_train, X_val, y_train, y_val = train_test_split(X, y, test_size=0.3, stratify=y, random_state=0)

for depth in [None, 4]:
    tree = DecisionTreeClassifier(max_depth=depth, random_state=0).fit(X_train, y_train)
    print(f"max_depth={depth}: train {tree.score(X_train, y_train):.3f}, validation {tree.score(X_val, y_val):.3f}")
```

`flip_y=0.15` flips 15% of the labels at random, the way real data contains typos, mislabeled photos, and people who answer surveys carelessly. No model should predict those flipped rows, because there's no pattern in them. The unlimited tree learns them anyway.

## What the gap between two scores tells you

Every diagnosis starts by putting two numbers side by side: the score on the training data and the score on validation data the model didn't train on.

| Training score | Validation score | Diagnosis | What to try |
| --- | --- | --- | --- |
| Low | Low, about the same | **Underfitting**: too simple to catch the pattern | A more flexible model, more useful features |
| High | Much lower | **Overfitting**: memorized the training rows, noise included | A simpler model, limits like `max_depth`, more data |
| Fairly high | Close to it | **A good fit** | Keep it, and confirm with cross-validation |

Logistic regression shows the first row on this data. Its boundary is a straight line and the real pattern isn't, so it scores poorly everywhere:

```python run
from sklearn.linear_model import LogisticRegression

line_model = LogisticRegression().fit(X_train, y_train)
print(f"logistic regression: train {line_model.score(X_train, y_train):.3f}, validation {line_model.score(X_val, y_val):.3f}")
```

Two scores near 0.66 with almost no gap: classic underfitting. Making it "try harder" won't help, because a straight line is the most it can draw. Compare that with the unlimited tree: 1.000 against 0.794 is a gap of more than 20 points, the signature of overfitting.

## See it: three trees fit the same noisy curve

Overfitting is easiest to see when there's one feature and a numeric target. Here are 60 noisy points along a wave, and three regression trees of different depths:

```python run alt="Three side-by-side plots of the same noisy wave-shaped points: a depth-1 tree draws a single step that captures only high-then-low; a depth-3 tree draws a staircase that follows the wave; a depth-12 tree draws a jagged line that jumps to hit almost every point" caption="Too simple, about right, and memorizing the noise."
import numpy as np
import matplotlib.pyplot as plt
from sklearn.tree import DecisionTreeRegressor

rng = np.random.default_rng(0)
x = np.sort(rng.uniform(0, 6, 60))
wave = np.sin(x) + rng.normal(0, 0.3, 60)
grid = np.linspace(0, 6, 400)

fig, axes = plt.subplots(1, 3, figsize=(12, 3.5), sharey=True)
for ax, depth, label in zip(axes, [1, 3, 12], ["underfit", "good fit", "overfit"]):
    reg = DecisionTreeRegressor(max_depth=depth, random_state=0).fit(x.reshape(-1, 1), wave)
    ax.scatter(x, wave, s=14, alpha=0.6)
    ax.plot(grid, reg.predict(grid.reshape(-1, 1)), color="crimson")
    ax.set_title(f"max_depth={depth} ({label})")
plt.show()
```

The depth-1 tree can only ask one question, so it draws a single step: high on the left, low on the right, and none of the wave's curve. The depth-3 tree follows the wave's shape with a staircase. The depth-12 tree chases every point, including the noise, so its line spikes up and down between neighbors. Those spikes are confident predictions that are wrong for any new point.

:::video EuBBz3bI-aA start=0:29
StatQuest explains the same idea with the names statisticians use: bias (too simple to bend with the data) and variance (so flexible that it changes wildly with each new sample). Watch for the squiggly line that nails the training points and misses the test points.
:::

## A validation curve finds the sweet spot

Rather than guessing a depth, try them all and plot both scores. Before you run it, predict: which line keeps rising as depth grows, and which one rises and then falls?

```python run alt="Line chart of accuracy against max_depth from 1 to 15: the training line climbs steadily to 1.0, while the validation line rises to a peak of about 0.84 at depth 4 and then drifts down to around 0.79 to 0.81" caption="The widening gap to the right of the peak is overfitting."
depths = range(1, 16)
train_scores, val_scores = [], []
for depth in depths:
    tree = DecisionTreeClassifier(max_depth=depth, random_state=0).fit(X_train, y_train)
    train_scores.append(tree.score(X_train, y_train))
    val_scores.append(tree.score(X_val, y_val))

best_depth = depths[int(np.argmax(val_scores))]
print("Best validation depth:", best_depth)

plt.figure(figsize=(7, 3.5))
plt.plot(depths, train_scores, marker="o", label="training")
plt.plot(depths, val_scores, marker="o", label="validation")
plt.axvline(best_depth, color="gray", linestyle="--")
plt.xlabel("max_depth")
plt.ylabel("accuracy")
plt.legend()
plt.show()
```

Left of the peak, both scores are low: underfitting. Right of it, training accuracy keeps climbing toward 1.0 while validation accuracy slides: overfitting. The peak is where the tree has learned the pattern and not yet the noise.

## One split can be lucky: cross-validation

That validation score came from one particular random split. Change only `random_state` and the same depth-4 tree gets a different grade:

```python run
for seed in range(5):
    a, b, c, d = train_test_split(X, y, test_size=0.3, stratify=y, random_state=seed)
    score = DecisionTreeClassifier(max_depth=4, random_state=0).fit(a, c).score(b, d)
    print(f"split {seed}: validation {score:.3f}")
```

The scores spread across nearly seven percentage points just from which rows landed where. If two models differ by less than that, one split can't tell you which is better.

**Cross-validation** fixes this by using every row for validation exactly once. Cut the data into 5 equal **folds**. Train on 4, score on the fifth, and repeat until each fold has had a turn:

```mermaid caption="5-fold cross-validation: every row is used for validation exactly once"
flowchart LR
    R1["Round 1: validate on fold 1, train on 2-5"] --> S1[score 1]
    R2["Round 2: validate on fold 2, train on the rest"] --> S2[score 2]
    R3["Rounds 3-5: same pattern"] --> S3[scores 3-5]
    S1 --> M["Report mean ± std"]
    S2 --> M
    S3 --> M
```

`cross_val_score` does all five rounds in one call:

```python run
from sklearn.model_selection import cross_val_score, StratifiedKFold

folds = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
scores = cross_val_score(DecisionTreeClassifier(max_depth=4, random_state=0), X, y, cv=folds)
print("fold scores:", scores.round(3))
print(f"mean {scores.mean():.3f}, std {scores.std():.3f}")
```

The mean is a steadier estimate than any single split, and the standard deviation (std) tells you how much the score wobbles from fold to fold. `StratifiedKFold` keeps the class balance the same in every fold, and `shuffle=True` mixes the rows first, in case the data arrived sorted.

## Compare models under the same rules

A fair comparison gives every model the same chances:

1. **The same folds.** Create one `folds` object and pass it to every `cross_val_score` call.
2. **The same preprocessing, inside a pipeline.** Scaling lives in `make_pipeline`, so each fold's scaler learns only from that fold's training rows.
3. **The same metric**, chosen before you look at any results.

```python run
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.neighbors import KNeighborsClassifier
from sklearn.dummy import DummyClassifier

candidates = {
    "always majority": DummyClassifier(strategy="most_frequent"),
    "logistic regression": make_pipeline(StandardScaler(), LogisticRegression()),
    "k-NN (k=15)": make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=15)),
    "tree (depth 4)": DecisionTreeClassifier(max_depth=4, random_state=0),
    "tree (no limit)": DecisionTreeClassifier(random_state=0),
}
for name, model in candidates.items():
    s = cross_val_score(model, X, y, cv=folds)
    print(f"{name:<20} {s.mean():.3f} ± {s.std():.3f}")
```

Read it top to bottom. Everything beats the do-nothing baseline. Logistic regression underfits. The unlimited tree loses to its depth-4 cousin. k-NN has the best mean, about 0.035 ahead of the depth-4 tree, which is roughly one standard deviation, a lead worth noticing but not a landslide.

So which do you pick? If you need the best predictions, k-NN. If people need to see and question every decision, the depth-4 tree gives up a few points for rules anyone can read. Either is defensible, as long as you state the reason. What isn't defensible is picking the unlimited tree because its training score was perfect.

:::warning
**Choosing on the test set.** If you try ten depths and keep the one with the best *test* score, the test set has become a validation set, and its score is now optimistic. Choose depths, thresholds, and models with validation data or cross-validation, and score the test set once, at the very end.
:::

:::warning
**Scaling before cross-validation.** Calling `StandardScaler().fit_transform(X)` on all rows and *then* running `cross_val_score` lets every validation fold leak into the scaler's averages. The numbers come out slightly too rosy. Put the scaler in a pipeline and pass the pipeline to `cross_val_score`.
:::

:::quiz
Q: A model scores 0.99 on training data and 0.71 on validation data. What's the diagnosis, and a reasonable next step?
- [ ] Underfitting; use a more flexible model
  Underfitting shows up as low scores on both sets. Here training is nearly perfect.
- [x] Overfitting; simplify it, for example with a smaller `max_depth`
  A big gap between a near-perfect training score and a much lower validation score means it memorized the training rows.
- [ ] A good fit; ship it
  A 28-point gap means the training score badly overstates how it will do on new data.

Q: On a validation curve, both the training and validation scores are low at `max_depth=1` and close together. What's going on?
- [x] The tree is too simple to capture the pattern
  One question can't describe the data, so even the training rows are predicted poorly.
- [ ] The tree has memorized the noise
  Memorizing would make the training score high, not low.
- [ ] The validation set is too small
  A small set makes scores wobble, but it doesn't push the training score down.

Q: Model A scores 0.842 ± 0.030 in 5-fold cross-validation, and model B scores 0.836 ± 0.028. What's the most honest conclusion?
- [ ] A is clearly better
  A 0.006 gap is far smaller than how much the scores wobble from fold to fold.
- [x] They perform about the same, so decide on something else, such as simplicity or explainability
  When the difference is well inside the fold-to-fold spread, the data can't separate them.
- [ ] B is better because its std is smaller
  A slightly steadier score is nice, but it doesn't make B more accurate.

Q: Why should every model in a comparison use the same `folds` object?
- [ ] It makes cross-validation run faster
  Speed has nothing to do with it.
- [x] Each model is then tested on exactly the same rows, so score differences come from the models, not from luck in the splits
  Different splits can move scores by several points on their own, as the five-seed experiment showed.
:::

:::takeaways
- Training score low and validation score low: underfitting. Training high and validation much lower: overfitting.
- A validation curve over a setting such as `max_depth` shows where learning the pattern turns into memorizing noise.
- One split's score can swing by several points; 5-fold cross-validation gives a mean and a std you can trust more.
- Compare models with the same folds, preprocessing inside pipelines, and a metric chosen in advance.
- When scores are within about one std, the data can't separate the models; choose on simplicity, speed, or explainability.
:::
