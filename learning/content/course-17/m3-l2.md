:::objectives
- Add a servo to a Wokwi circuit and power it correctly.
- Test conversion functions in regular Python before they go on the board.
- Drive LED brightness and servo angle from analog readings with PWM.
- Switch modes on a debounced button press without missing presses.
- Run a heartbeat, an alarm blink, and a status report on separate `ticks_ms` timers.
:::

A greenhouse monitor needs to show its state at a glance, even to someone who never opens a dashboard. Here you'll build a panel that does that from the circuit you checked and wired in Module 2, plus one servo.

When it's finished:

-   Turning the **knob** dims or brightens the green status LED.
-   A **servo needle** acts as a gauge, showing either the knob position or the light level.
-   The blue **button** switches the gauge between those two modes.
-   The red **alarm LED** flashes quickly whenever the light falls below 20%.
-   The onboard LED blinks once a second as a heartbeat, so you can see the loop is alive, and the Serial Monitor prints a status line every second:

```text
mode knob | knob 62 % | light 76 %
mode knob | knob 62 % | light 76 %
mode -> light
mode light | knob 62 % | light 17 %
```

Your numbers will differ with the knob position and the simulated light level.

```mermaid caption="Every pass of the loop reads, decides, and updates without waiting"
flowchart LR
    A["Read knob and light (ADC)"] --> B[Convert to percent]
    B --> C["Status LED brightness (PWM)"]
    B --> D["Servo gauge angle (PWM)"]
    B --> E{"Light below 20%?"}
    E -->|yes| F[Blink alarm on its timer]
    E -->|no| G[Alarm off]
    H[Debounced button] --> I[Switch gauge mode]
    I --> D
```

The servo sits on GP16 for a reason you met in the Module 2 challenge: GP16 is on PWM slice 0, while the status LED on GP15 is on slice 7. The servo needs 50 Hz and the LED runs at 1000 Hz, and two pins on one slice can't have different frequencies.

## Step 2: Write the math first, and test it off the board

Testing on a microcontroller is slow: edit, run, squint at the terminal. So put every conversion in a small function and test it in regular Python first. These are the exact functions that go into `main.py`:

```python run title="panel_math.py"
import sys
import unittest

FULL = 65535
MIN_US, MAX_US, PERIOD_US = 500, 2400, 20_000

def percent(raw):
    return max(0.0, min(100.0, raw * 100 / FULL))

def light_percent(raw):
    # this light module reads LOWER when it's brighter, so flip the scale
    return 100.0 - percent(raw)

def angle_to_duty(angle):
    angle = max(0, min(180, angle))
    pulse_us = MIN_US + (MAX_US - MIN_US) * angle / 180
    return int(pulse_us / PERIOD_US * FULL)

class PanelMath(unittest.TestCase):
    def test_percent_covers_the_range(self):
        self.assertEqual(percent(0), 0.0)
        self.assertEqual(percent(FULL), 100.0)

    def test_light_scale_is_flipped(self):
        self.assertEqual(light_percent(0), 100.0)
        self.assertLess(light_percent(60000), 10)

    def test_servo_stays_inside_its_range(self):
        self.assertEqual(angle_to_duty(-30), angle_to_duty(0))
        self.assertEqual(angle_to_duty(500), angle_to_duty(180))

    def test_servo_middle(self):
        self.assertTrue(4700 < angle_to_duty(90) < 4800)

suite = unittest.defaultTestLoader.loadTestsFromTestCase(PanelMath)
unittest.TextTestRunner(stream=sys.stdout, verbosity=2).run(suite)
```

The clamping in `angle_to_duty` matters more than it looks. A bug that asks for 500° would otherwise send a pulse far outside the servo's range, and a real servo would grind against its end stop.

## Step 3: The knob dims the status LED

On the board, the LED becomes a `PWM` object, and each pass of the loop copies the knob's percentage into its duty cycle:

```python
from machine import Pin, PWM, ADC

status_led = PWM(Pin(15), freq=1000, duty_u16=0)
knob = ADC(Pin(26))

knob_pct = percent(knob.read_u16())
status_led.duty_u16(int(knob_pct * FULL / 100))
```

At 1000 Hz the flicker is far too fast to see. Wokwi's LEDs also mimic how eyes respond to light, so the bottom quarter of the knob's travel changes the brightness more visibly than the top quarter, just as a real LED does.

## Step 4: The servo becomes a gauge needle

```python
from machine import Pin, PWM

servo = PWM(Pin(16), freq=50)

gauge = knob_pct if mode == "knob" else light_pct
servo.duty_u16(angle_to_duty(gauge * 180 / 100))
```

0% points the needle to 0° and 100% to 180°. Setting the same duty again on every pass is harmless: the PWM hardware keeps producing the pulse on its own, and writing a new number only changes the next pulse.

## Step 5: A button that changes mode once per press

The button should flip the mode on the press, once, no matter how long it's held and no matter how much the contacts bounce. This function returns `True` only when the button has *just* settled into the pressed state:

```python
from machine import Pin
import time

button = Pin(13, Pin.IN, Pin.PULL_UP)
DEBOUNCE_MS = 30
last_level = 1
stable_level = 1
last_change = time.ticks_ms()

def new_press(now):
    global last_level, stable_level, last_change
    level = button.value()
    if level != last_level:
        last_level = level
        last_change = now
    elif level != stable_level and time.ticks_diff(now, last_change) >= DEBOUNCE_MS:
        stable_level = level
        return level == 0
    return False
```

It's the same idea as the trace in the notes, but measured in milliseconds instead of readings: any change restarts the clock, and the new level only counts once it has held for 30 ms. Releasing the button also updates `stable_level`, but returns `False`, so only presses switch the mode.

## Step 6: Timers for the alarm, the heartbeat, and the report

Each periodic job gets its own "last ran" time. The alarm flashes every 125 ms while it's dark and switches off the moment it isn't; the heartbeat and the status line run once a second. Here is the whole program. Paste it into `main.py` and press play:

```python title="main.py"
from machine import Pin, PWM, ADC
import time

time.sleep(0.1)  # let the USB terminal connect

# Pins: the approved Module 2 plan, plus the servo
status_led = PWM(Pin(15), freq=1000, duty_u16=0)
alarm_led = Pin(14, Pin.OUT)
button = Pin(13, Pin.IN, Pin.PULL_UP)
knob = ADC(Pin(26))
light = ADC(Pin(27))
servo = PWM(Pin(16), freq=50)
heartbeat = Pin("LED", Pin.OUT)

# Conversions, tested in regular Python first
FULL = 65535
MIN_US, MAX_US, PERIOD_US = 500, 2400, 20_000
DARK_PERCENT = 20

def percent(raw):
    return max(0.0, min(100.0, raw * 100 / FULL))

def light_percent(raw):
    return 100.0 - percent(raw)

def angle_to_duty(angle):
    angle = max(0, min(180, angle))
    pulse_us = MIN_US + (MAX_US - MIN_US) * angle / 180
    return int(pulse_us / PERIOD_US * FULL)

# Button debouncing
DEBOUNCE_MS = 30
last_level = 1
stable_level = 1
last_change = time.ticks_ms()

def new_press(now):
    global last_level, stable_level, last_change
    level = button.value()
    if level != last_level:
        last_level = level
        last_change = now
    elif level != stable_level and time.ticks_diff(now, last_change) >= DEBOUNCE_MS:
        stable_level = level
        return level == 0
    return False

mode = "knob"
last_beat = last_blink = last_report = time.ticks_ms()

while True:
    now = time.ticks_ms()
    knob_pct = percent(knob.read_u16())
    light_pct = light_percent(light.read_u16())

    status_led.duty_u16(int(knob_pct * FULL / 100))

    if new_press(now):
        mode = "light" if mode == "knob" else "knob"
        print("mode ->", mode)

    gauge = knob_pct if mode == "knob" else light_pct
    servo.duty_u16(angle_to_duty(gauge * 180 / 100))

    if light_pct < DARK_PERCENT:
        if time.ticks_diff(now, last_blink) >= 125:
            alarm_led.toggle()
            last_blink = now
    else:
        alarm_led.value(0)

    if time.ticks_diff(now, last_beat) >= 1000:
        heartbeat.toggle()
        last_beat = now

    if time.ticks_diff(now, last_report) >= 1000:
        print("mode", mode, "| knob", round(knob_pct), "% | light", round(light_pct), "%")
        last_report = now

    time.sleep_ms(5)
```

Now test it like a user would. Click the knob and use the arrow keys or **Home** and **End**; the green LED and the needle follow. Hold **B** for a moment: `mode -> light` prints once, not five times. Click the light sensor and drag its lux slider down to about 10 lux: the light reading drops below 20%, the red LED flashes, and the needle (in light mode) swings low. Throughout, the heartbeat keeps its steady one-second rhythm, which proves nothing in the loop is blocking.

:::try
Add `time.sleep(1)` just before `time.sleep_ms(5)` and run it again. The needle lags, the alarm flashes slowly, and quick button taps are missed. Take it out again.
:::

## Step 7 (optional): The same panel on a Raspberry Pi

A Raspberry Pi has no analog inputs, so the knob and the light sensor connect through an **MCP3008** ADC chip on the SPI pins (turn on SPI in `sudo raspi-config` under *Interface Options*). gpiozero handles the debouncing and the button callback for you. These pin choices avoid GPIO14 and GPIO15, which the Pi uses for its serial port:

```python title="panel_pi.py"
from gpiozero import AngularServo, Button, LED, MCP3008, PWMLED
import time

status_led = PWMLED(18)                 # physical pin 12
alarm_led = LED(23)                     # physical pin 16
button = Button(24, bounce_time=0.03)   # physical pin 18, pull-up on by default
knob = MCP3008(channel=0)
light = MCP3008(channel=1)
servo = AngularServo(12, min_angle=0, max_angle=180,
                     min_pulse_width=0.0005, max_pulse_width=0.0024)

mode = "knob"

def switch_mode():
    global mode
    mode = "light" if mode == "knob" else "knob"
    print("mode ->", mode)

button.when_pressed = switch_mode
alarm_on = False

while True:
    knob_pct = knob.value * 100       # MCP3008 values run from 0.0 to 1.0
    light_pct = 100 - light.value * 100
    status_led.value = knob.value
    servo.angle = (knob_pct if mode == "knob" else light_pct) * 1.8
    dark = light_pct < 20
    if dark and not alarm_on:
        alarm_led.blink(on_time=0.125, off_time=0.125)
    elif not dark and alarm_on:
        alarm_led.off()
    alarm_on = dark
    time.sleep(0.05)
```

Notice `alarm_on`: gpiozero's `blink()` starts a background blinker, so calling it on every pass would restart it 20 times a second. The variable makes sure it starts once when it gets dark and stops once when it gets light.

:::quiz
Q: Why does the servo use GP16 rather than GP17, the pin right next to it?
- [ ] GP17 can't produce PWM
  Every GPIO pin can produce PWM on the RP2040.
- [x] GP17 shares PWM slice 0 with GP16, and the servo needs 50 Hz while LEDs run faster
  Two pins on one slice share a frequency. Using GP16 alone on its slice (with the LEDs on GP14 and GP15) avoids the clash.
- [ ] GP16 is the only pin connected to VBUS
  VBUS is a separate power pin; the servo's signal can use any free GPIO.

Q: Why does the program read the knob on every pass but print only once a second?
- [x] Reading is fast and keeps the outputs responsive; printing is slow and would flood the terminal
  The LED and needle need fresh values every few milliseconds, but a person can only read about one line a second.
- [ ] The ADC can only be read once a second
  The ADC can take hundreds of thousands of readings a second.
- [ ] Printing resets the ADC
  Printing and the ADC are unrelated.

Q: What would happen if `new_press` returned `True` whenever `button.value() == 0`?
- [ ] Nothing different
  The mode would be checked on every pass of the loop, about 200 times a second.
- [x] Holding the button would flip the mode back and forth on every pass of the loop
  The function must detect the moment of pressing, not the state of being pressed.
- [ ] The button would stop working entirely
  It would still work, just uncontrollably.
:::

:::takeaways
- Keep conversions in small functions and test them in regular Python before they reach the board.
- PWM duty sets LED brightness at 1000 Hz and servo angle at 50 Hz; keep pins that need different frequencies on different slices.
- Clamp anything that drives hardware, so a bug can't command an impossible position.
- A debounced edge detector turns a bouncy, held-down button into exactly one event per press.
- One fast loop with a `ticks_ms` timer per job keeps every output responsive; a heartbeat LED proves the loop is alive.
:::
