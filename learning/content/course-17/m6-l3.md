## Warm-up: which check stops it?

Match each attack to the check in Lesson 2's `check_command` that rejects it: **types**, **signature**, **device**, **allowlist**, or **seq**.

1.  Publishing the word `on`.
2.  Resending yesterday's genuine `fan_on` exactly as it was.
3.  Taking a genuine command and changing `"seq": 4` to `"seq": 40`.
4.  A genuine command you signed for `station-02`, delivered to `station-01`.
5.  `{"dev": "station-01", "cmd": "fan_on", "seq": "5", "sig": "..."}`

:::solution
1.  **Types**, or really one step earlier: `"on"` isn't JSON at all.
2.  **Seq**. The signature is genuine, so only freshness can catch it.
3.  **Signature**. `seq` is part of the signed text, so changing it breaks the tag.
4.  **Device**. The tag is valid, because both boards share the demo key, but the name doesn't match.
5.  **Types**. `"5"` is a string, not an integer, so it is refused before any HMAC is computed.
:::

### Exercise 1: Fix a handler that "works"

This handler passes its one happy-path test. Run it against the attacks below and list every problem you see in the output. Then rewrite `handle()` so that a replay, a forgery, and a command for another board are all rejected, and the fan only changes after every check passes.

```python run title="buggy_handler.py"
import hashlib, hmac, json

KEY = b"practice-key-1234567890abcdef"
fan_on = False
last_seq = 0

def sign(text):
    return hmac.new(KEY, text.encode(), hashlib.sha256).hexdigest()

def handle(payload):
    global fan_on, last_seq
    msg = json.loads(payload)
    fan_on = msg["cmd"] == "fan_on"
    if sign(msg["cmd"]) == msg["sig"]:
        last_seq = msg["seq"]
        return "accepted"
    return "rejected"

# The controller's real command (signed the buggy way, over cmd only)
good = json.dumps({"dev": "station-01", "cmd": "fan_on", "seq": 1, "sig": sign("fan_on")})
print("genuine:          ", handle(good), "| fan on:", fan_on)
print("replayed:         ", handle(good), "| fan on:", fan_on)
forged = json.dumps({"dev": "station-01", "cmd": "fan_off", "seq": 2, "sig": "0" * 64})
print("forged fan_off:   ", handle(forged), "| fan on:", fan_on)
other = json.dumps({"dev": "station-99", "cmd": "fan_on", "seq": 0, "sig": sign("fan_on")})
print("for another board:", handle(other), "| fan on:", fan_on)
```

:::hint
Read the "fan on" column, not just accepted or rejected. The forgery was rejected, and yet the fan changed. Then ask: which fields does the tag cover? Is `seq` ever compared with anything? Is `==` the right way to compare tags?
:::

:::solution
Five problems: the fan changes **before** any check; the tag covers only `cmd`, so `dev` and `seq` can be anything; `seq` is stored but never compared, so replays pass; there's no device check; and `==` leaks timing. The fix signs all three fields, checks shape and types, compares with `compare_digest`, enforces `seq`, and acts last:

```python run title="fixed_handler.py"
import hashlib, hmac, json

KEY = b"practice-key-1234567890abcdef"
fan_on = False
last_seq = 0

def sign(text):
    return hmac.new(KEY, text.encode(), hashlib.sha256).hexdigest()

def handle(payload):
    global fan_on, last_seq
    try:
        msg = json.loads(payload)
    except ValueError:
        return "rejected: not JSON"
    if not isinstance(msg, dict) or msg.get("dev") != "station-01":
        return "rejected: wrong device or shape"
    if not isinstance(msg.get("seq"), int) or not isinstance(msg.get("sig"), str) \
            or msg.get("cmd") not in ("fan_on", "fan_off"):
        return "rejected: bad fields"
    signed = f'{msg["dev"]}|{msg["cmd"]}|{msg["seq"]}'
    if not hmac.compare_digest(sign(signed), msg["sig"]):
        return "rejected: bad signature"
    if msg["seq"] <= last_seq:
        return "rejected: old seq"
    last_seq = msg["seq"]
    fan_on = msg["cmd"] == "fan_on"          # act only after every check
    return f"accepted {msg['cmd']} #{last_seq}"

def make(cmd, seq, dev="station-01"):
    return json.dumps({"dev": dev, "cmd": cmd, "seq": seq, "sig": sign(f"{dev}|{cmd}|{seq}")})

good = make("fan_on", 1)
print(handle(good), "| fan on:", fan_on)
print(handle(good), "| fan on:", fan_on)
print(handle(good.replace("fan_on", "fan_off")), "| fan on:", fan_on)
print(handle(json.dumps({"dev": "station-01", "cmd": "fan_off", "seq": 2, "sig": "0" * 64})), "| fan on:", fan_on)
print(handle(make("fan_off", 2)), "| fan on:", fan_on)
```

Here the device check runs before the signature check. That's fine because it doesn't change anything; what matters is that nothing *acts* until the signature has been verified.
:::

### Exercise 2: Two messages, one signature

A student signs a command by gluing its fields together with no separator: `cmd + minutes + seq`. Show that a signed `("fan_on", 5, 12)` also verifies `("fan_on", 51, 2)`. Then write `tag_fixed(*fields)` that joins with `|` and refuses any field that contains a `|`.

```text
no separator: same tag? True
with '|':     same tag? False
refused: field contains the separator: 'fan_on|5'
```

:::hint
Both tuples turn into the same string, `fan_on512`, and HMAC only ever sees the string. A separator restores the boundaries, but only if no field can contain the separator itself.
:::

:::solution
```python run title="separators.py"
import hashlib, hmac
KEY = b"practice-key-1234567890abcdef"

def tag(*fields):
    return hmac.new(KEY, "".join(str(f) for f in fields).encode(), hashlib.sha256).hexdigest()

def tag_fixed(*fields):
    for f in fields:
        if "|" in str(f):
            raise ValueError("field contains the separator: " + repr(f))
    return hmac.new(KEY, "|".join(str(f) for f in fields).encode(), hashlib.sha256).hexdigest()

a = tag("fan_on", 5, 12)    # cmd, minutes, seq
b = tag("fan_on", 51, 2)
print("no separator: same tag?", a == b)
print("with '|':     same tag?", tag_fixed("fan_on", 5, 12) == tag_fixed("fan_on", 51, 2))
try:
    tag_fixed("fan_on|5", 12)
except ValueError as err:
    print("refused:", err)
```

The forged version runs the fan for 51 minutes instead of 5. The counter check might happen to catch this one (2 is lower than 12), but you shouldn't rely on luck: the signed text must have exactly one meaning.
:::

### Exercise 3: A nonce cache that can't be flooded

The timestamp-plus-nonce guard from the notes keeps every nonce from the last 30 seconds. An attacker can't forge nonces, but a buggy controller (or your own script stuck in a loop) could send thousands per second, and a Pico W has only a few hundred kilobytes of RAM in total. Write `NonceGuard(window_s=30, max_size=100)` whose memory never exceeds `max_size`, without ever accepting a replay.

```text
flood at t=1000: {'ok': 100, 'busy': 50} | largest memory: 100
replay of n5 at t=1010: replay
new nonce at t=1031:    ok | memory: 1
n5 again at t=1031:     too old
```

:::hint
When the cache is full, the tempting move is to throw away the oldest nonce. Don't: that nonce is still inside the window, so its message could be replayed straight away. Refuse the new message instead ("fail closed"), and let time empty the cache.
:::

:::solution
```python run title="nonce_guard.py"
class NonceGuard:
    def __init__(self, window_s=30, max_size=100):
        self.window_s = window_s
        self.max_size = max_size
        self.seen = {}                      # nonce -> ts

    def check(self, nonce, ts, now):
        if abs(now - ts) > self.window_s:
            return "too old"
        self.seen = {n: t for n, t in self.seen.items() if now - t <= self.window_s}
        if nonce in self.seen:
            return "replay"
        if len(self.seen) >= self.max_size:
            return "busy"                   # fail closed: never forget a live nonce
        self.seen[nonce] = ts
        return "ok"

guard = NonceGuard()
results = {}
biggest = 0
for i in range(150):                        # a flood: 150 commands in the same second
    r = guard.check(f"n{i}", ts=1000, now=1000)
    results[r] = results.get(r, 0) + 1
    biggest = max(biggest, len(guard.seen))
print("flood at t=1000:", results, "| largest memory:", biggest)
print("replay of n5 at t=1010:", guard.check("n5", ts=1000, now=1010))
print("new nonce at t=1031:   ", guard.check("fresh", ts=1031, now=1031), "| memory:", len(guard.seen))
print("n5 again at t=1031:    ", guard.check("n5", ts=1000, now=1031))
```

At t=1031 every stored nonce has aged out, so memory drops back to one entry. A nonce that has aged out can't be replayed anyway, because the time check rejects it first.
:::

### Exercise 4: Survive a reboot without reopening replays

In Wokwi, `fan_seq.txt` resets on every start, so `last_seq` goes back to 0 and your old `seq` 1 command works again. One fix uses the broker's memory: the station already publishes a retained `fan/state` with the last `seq`. On boot, it can read that back.

But anyone can publish a retained message to that topic. So the station must **sign its own state message**, and verify it on boot. Write `state_message(state, seq)` and `recover_seq(file_seq, retained)`, which returns the larger of the file's number and a *verified* retained number.

```mermaid caption="The station uses the broker as a backup memory, and only trusts what it signed itself"
sequenceDiagram
    participant S as Station
    participant B as Broker
    S->>B: fan/state = on, seq 7, signed (retained)
    Note over S: Restart: file says seq 0
    S->>B: SUBSCRIBE fan/state
    B->>S: on, seq 7, signed (retained copy)
    Note over S: Signature valid, so last_seq = max(0, 7)
```

```text
Wokwi restart, genuine state:   7
real Pico, file ahead of broker: 9
forged state with seq 0:        7
retained message erased:        0
```

:::hint
Put a word like `state` into the signed text, so it reads `station-01|state|on|7`. Without it, the station's state message for seq 7 could be signed over the very same text as a command, and an attacker could replay your station's own state message *as* a command.
:::

:::solution
```python run title="recover_seq.py"
import hashlib, hmac, json

KEY = b"practice-key-1234567890abcdef"
DEVICE = "station-01"

def tag(text):
    return hmac.new(KEY, text.encode(), hashlib.sha256).hexdigest()

def state_message(state, seq):
    # "state" in the signed text keeps this from ever looking like a command
    text = f"{DEVICE}|state|{state}|{seq}"
    return json.dumps({"state": state, "seq": seq, "sig": tag(text)})

def recover_seq(file_seq, retained):
    try:
        msg = json.loads(retained)
        text = f"{DEVICE}|state|{msg['state']}|{msg['seq']}"
        if isinstance(msg["seq"], int) and hmac.compare_digest(tag(text), msg["sig"]):
            return max(file_seq, msg["seq"])
    except (ValueError, KeyError, TypeError):
        pass
    return file_seq

genuine = state_message("on", 7)
print("Wokwi restart, genuine state:  ", recover_seq(0, genuine))
print("real Pico, file ahead of broker:", recover_seq(9, genuine))
print("forged state with seq 0:       ", recover_seq(7, json.dumps({"state": "off", "seq": 0, "sig": "f" * 64})))
print("retained message erased:       ", recover_seq(0, ""))
```

`max()` means a forgery can never move the counter *down*. The last line shows the limit of this fix: on a public broker anyone can erase a retained message by publishing an empty one, and then a Wokwi station falls back to 0. A real Pico's flash file, or a private broker whose ACL stops strangers writing to `fan/state`, closes that gap.
:::

What to watch for: an attacker capturing traffic and sending it again without ever needing to read or crack it. Your recorded `fan_on` command is the same attack aimed at a device, and the counter you are protecting here is what stops it.
:::

### Exercise 5: Access rules a broker could enforce

On a private broker, the cleanest protection is to stop strangers publishing at all. Write the rules as data and an `allowed(user, action, topic)` function that denies anything not listed. The station may publish its own readings and status, may read its fan topic, and must **not** be able to publish to its own `fan/set`.

```text
ok  station-01 write greenhouse/bed1/temperature            -> True
ok  station-01 write greenhouse/bed1/fan/set                -> False
ok  station-01 write greenhouse/devices/station-02/status   -> False
ok  station-01 read  greenhouse/bed1/fan/set                -> True
ok  controller write greenhouse/bed2/fan/set                -> True
ok  controller write greenhouse/bed1/temperature            -> False
ok  dashboard  write greenhouse/bed1/fan/set                -> False
ok  stranger   read  greenhouse/bed1/temperature            -> False
```

:::hint
`greenhouse/bed1/+` matches `bed1/temperature` but not `bed1/fan/set`, which has two levels after `bed1`. Picking `+` instead of `#` is the whole trick for the second line. An unknown user gets an empty rule list, so the default `return False` covers strangers.
:::

:::solution
```python run title="acl_check.py"
def matches(pattern, topic):
    p, t = pattern.split("/"), topic.split("/")
    for i in range(len(p)):
        if p[i] == "#":
            return True
        if i >= len(t) or (p[i] != "+" and p[i] != t[i]):
            return False
    return len(p) == len(t)

ACL = {
    "station-01": [("write", "greenhouse/bed1/+"),
                   ("write", "greenhouse/devices/station-01/#"),
                   ("read", "greenhouse/bed1/fan/set")],
    "controller": [("write", "greenhouse/+/fan/set"),
                   ("read", "greenhouse/#")],
    "dashboard": [("read", "greenhouse/#")],
}

def allowed(user, action, topic):
    for rule_action, pattern in ACL.get(user, []):
        if rule_action in (action, "readwrite") and matches(pattern, topic):
            return True
    return False                            # anything not listed is denied

checks = [
    ("station-01", "write", "greenhouse/bed1/temperature", True),
    ("station-01", "write", "greenhouse/bed1/fan/set", False),
    ("station-01", "write", "greenhouse/devices/station-02/status", False),
    ("station-01", "read", "greenhouse/bed1/fan/set", True),
    ("controller", "write", "greenhouse/bed2/fan/set", True),
    ("controller", "write", "greenhouse/bed1/temperature", False),
    ("dashboard", "write", "greenhouse/bed1/fan/set", False),
    ("stranger", "read", "greenhouse/bed1/temperature", False),
]
for user, action, topic, expected in checks:
    got = allowed(user, action, topic)
    print(f"{'ok ' if got == expected else 'BAD'} {user:10} {action:5} {topic:38} -> {got}")
```

In Mosquitto the same rules go in the ACL file as `user station-01` followed by `topic write greenhouse/bed1/+`, and so on. Deny-by-default is what makes it safe: forgetting a rule breaks a feature, which you'll notice, instead of opening a hole, which you won't.
:::

### Exercise 6: Read the audit log

Here is a station's audit log as `(seconds, result, detail)`. Count the rejections by reason, most common first, and print an alert for the first time five bad signatures land within 60 seconds.

```text
 6  bad signature
 3  replayed or old seq
 2  not JSON
ALERT: 5 bad signatures between t=2000 and t=2049
```

:::hint
For the alert, collect the times of bad signatures in order. If the 1st and 5th of any run of five are at most 60 seconds apart, that's your window: compare `times[i]` with `times[i + 4]`.
:::

:::solution
```python run title="audit_report.py"
audit = [
    (12, "accepted", "fan_on"), (300, "rejected", "not JSON"), (301, "rejected", "not JSON"),
    (900, "rejected", "replayed or old seq"), (1500, "accepted", "fan_off"),
    (2000, "rejected", "bad signature"), (2010, "rejected", "bad signature"),
    (2025, "rejected", "bad signature"), (2031, "rejected", "bad signature"),
    (2049, "rejected", "bad signature"), (2050, "rejected", "bad signature"),
    (2400, "rejected", "replayed or old seq"), (2401, "rejected", "replayed or old seq"),
]

counts = {}
for t, result, detail in audit:
    if result == "rejected":
        counts[detail] = counts.get(detail, 0) + 1
for reason, n in sorted(counts.items(), key=lambda item: -item[1]):
    print(f"{n:2}  {reason}")

bad_times = [t for t, result, detail in audit if detail == "bad signature"]
for i in range(len(bad_times) - 4):
    if bad_times[i + 4] - bad_times[i] <= 60:
        print(f"ALERT: 5 bad signatures between t={bad_times[i]} and t={bad_times[i + 4]}")
        break
```

The two `not JSON` entries a second apart look like a person typing in the web client. Six bad signatures in 50 seconds look like a script. Two replays right after each other at t=2400 suggest someone resending a message they recorded.
:::

### Challenge: Should the station lock itself?

A common instinct is to lock out all commands for two minutes after five bad signatures in a minute. Build that `Lockout` class, then play the attacker: send five junk messages, then try your own genuine command at t=30, and again at t=150 after the attacker repeats the trick. Decide whether the lockout helps, and what you'd do instead.

```text
t=  0  attacker junk  -> rejected
t=  1  attacker junk  -> rejected
t=  2  attacker junk  -> rejected
t=  3  attacker junk  -> rejected
t=  4  attacker junk  -> rejected, now LOCKED
t= 30  YOUR fan_on   -> ignored (locked)
t=150  YOUR fan_on   -> ignored (locked)
```

:::hint
Think about what the lockout protects against. Guessing a 256-bit key one message at a time would take longer than the age of the universe, even with no lockout at all. Now think about what it hands the attacker: five junk messages, which anyone on a public broker can send, switch off your control for two minutes, and they can repeat it forever.
:::

:::solution
```python run title="lockout.py"
class Lockout:
    def __init__(self, limit=5, within_s=60, lock_s=120):
        self.limit, self.within_s, self.lock_s = limit, within_s, lock_s
        self.failures = []
        self.locked_until = -1

    def handle(self, signature_ok, now):
        if now < self.locked_until:
            return "ignored (locked)"
        if signature_ok:
            return "accepted"
        self.failures = [t for t in self.failures if now - t <= self.within_s] + [now]
        if len(self.failures) >= self.limit:
            self.locked_until = now + self.lock_s
            self.failures = []
            return "rejected, now LOCKED"
        return "rejected"

guard = Lockout()
for t in [0, 1, 2, 3, 4]:
    print(f"t={t:3}  attacker junk  -> {guard.handle(False, t)}")
print(f"t= 30  YOUR fan_on   -> {guard.handle(True, 30)}")
for t in [124, 125, 126, 127, 128]:
    guard.handle(False, t)
print(f"t=150  YOUR fan_on   -> {guard.handle(True, 150)}")
```

The lockout turns a harmless nuisance into a working **denial-of-service** attack: the attacker never needs the key to stop you controlling your own fan. Lockouts make sense for short secrets such as a 4-digit PIN, where guessing is realistic. With a long random key, a better design keeps accepting genuine commands, publishes an alert like Exercise 6's, and leaves blocking strangers to a broker with accounts and ACLs, where the attacker can't publish in the first place.
:::
