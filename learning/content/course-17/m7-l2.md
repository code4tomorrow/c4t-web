Right now, if Wi-Fi drops for a minute, the station from Module 6 crashes on its next `publish` with an `OSError` and stays dead until someone presses reset. By the end of this lesson the same outage is a non-event: readings pile up in an outbox, the station retries with growing, randomized waits, and when the network returns it reconnects, resubscribes to its fan topic, and delivers the backlog in order.

Module 4's logger already queued readings through an outage. An MQTT station has more to put back together afterward: a broker connection, a subscription that silently disappears, a retained status, and a fan that must stay in a safe state the whole time.

Here is a run you'll be able to reproduce, with the button pressed once to cut the Wi-Fi (your numbers will differ, because the waits are random):

```text
Online. Queued messages: 1
Button: cutting Wi-Fi to test recovery
Wi-Fi lost. Retrying in 612 ms. Queued messages: 0
Online. Queued messages: 2
```

## Step 2: An outbox that is bounded and loses nothing it hasn't sent

During an outage, readings keep coming every five seconds. Storing them all eventually fills the Pico's RAM. The outbox therefore has a **capacity**, and a policy for when it's full: drop the **oldest** reading, because a recent reading is worth more than an old one, and count how many were dropped so the dashboard can be told.

The other rule is in `flush`: a message is removed only **after** `send` succeeds. If the link dies in the middle of a flush, the unsent messages stay put.

`random.getrandbits` is used for jitter because it exists on both MicroPython and regular Python. Here are both classes, followed by a 90-second simulated run with the link down from t = 20 s to t = 60 s and a deliberately small outbox of 6:

```python run title="resilience.py"
import random

class Outbox:
    """Holds unsent messages. When full, drops the oldest and counts it."""

    def __init__(self, capacity):
        self.capacity = capacity
        self.items = []
        self.dropped = 0

    def add(self, topic, payload):
        if len(self.items) >= self.capacity:
            self.items.pop(0)
            self.dropped += 1
        self.items.append((topic, payload))

    def flush(self, send):
        """Send oldest first; on the first failure, stop and keep the rest."""
        sent = 0
        while self.items:
            topic, payload = self.items[0]
            send(topic, payload)          # raises OSError if the link is down
            self.items.pop(0)             # only forget it once it's sent
            sent += 1
        return sent


class Backoff:
    """Exponential backoff with full jitter."""

    def __init__(self, base_ms=1000, cap_ms=60000):
        self.base_ms = base_ms
        self.cap_ms = cap_ms
        self.failures = 0

    def next_delay_ms(self):
        ceiling = min(self.cap_ms, self.base_ms * 2 ** self.failures)
        self.failures = min(self.failures + 1, 16)
        return max(250, ceiling * random.getrandbits(16) // 65536)

    def reset(self):
        self.failures = 0

# ---- test on your computer: a fake link that goes down for 40 seconds ----
random.seed(5)

class FakeLink:
    def __init__(self):
        self.up = True
        self.delivered = []

    def publish(self, topic, payload):
        if not self.up:
            raise OSError("link down")
        self.delivered.append(payload["seq"])

link = FakeLink()
box = Outbox(capacity=6)
backoff = Backoff(base_ms=1000, cap_ms=16000)
online, retry_at = True, 0.0

for t in range(91):                         # one pass per simulated second
    link.up = not (20 <= t < 60)            # the outage
    if t % 5 == 0:
        box.add("bed1/temperature", {"v": 24.0, "seq": t // 5 + 1})
    if not online and t >= retry_at:
        if link.up:
            online = True
            backoff.reset()
            print(f"t={t:2}  reconnected")
        else:
            wait = backoff.next_delay_ms() / 1000
            retry_at = t + wait
            print(f"t={t:2}  still down, next try in {wait:4.1f} s")
    if online:
        try:
            n = box.flush(link.publish)
            if n > 1:
                print(f"t={t:2}  flushed {n} readings, oldest first")
        except OSError:
            online, retry_at = False, t
            print(f"t={t:2}  link lost, {len(box.items)} reading waiting")

print("delivered seq:", link.delivered)
print("dropped:", box.dropped)
```

Read the result carefully, because it shows both the design working and its price:

-   **Nothing crashed**, and every reading from before and after the outage arrived, in order.
-   Seq 5 to 9 were **dropped**, because 11 readings piled up and the outbox holds 6. The gap is visible in `delivered`, which is exactly what Module 5's `seq` gap detector is for. On the Pico, a capacity of 120 holds about five minutes.
-   The link came back at t = 60, but the station only noticed at t = 70, because its last wait was 15 seconds. That is the trade-off the **cap** controls: a lower cap reconnects sooner and hits the broker harder.

## Step 3: Fail closed on a damaged counter

Move Module 6's command code into `commands.py`, with one change. The old `load_seq` got one case wrong: it returned 0 for a damaged file, which would quietly re-accept old commands. The new one tells "no file yet" apart from "file exists but is unreadable", and returns `None` for the second:

```python title="commands.py"
import json

from hmac_lite import hmac_sha256_hex, same

SEQ_FILE = "fan_seq.txt"
COMMANDS = {"fan_on": 1, "fan_off": 0}


def load_seq():
    try:
        f = open(SEQ_FILE)
    except OSError:
        return 0                 # no file yet: first boot
    with f:
        try:
            return int(f.read())
        except ValueError:
            return None          # damaged: refuse commands until a person fixes it


def save_seq(seq):
    with open(SEQ_FILE, "w") as f:
        f.write(str(seq))


def check_command(text, last_seq, key, device):
    if last_seq is None:
        return False, "counter unreadable", None
    try:
        msg = json.loads(text)
    except ValueError:
        return False, "not JSON", None
    if not isinstance(msg, dict):
        return False, "not a JSON object", None
    dev, cmd, seq, sig = msg.get("dev"), msg.get("cmd"), msg.get("seq"), msg.get("sig")
    if not (isinstance(dev, str) and isinstance(cmd, str) and isinstance(seq, int) and isinstance(sig, str)):
        return False, "missing or wrong-type field", None
    signed = (dev + "|" + cmd + "|" + str(seq)).encode()
    if not same(hmac_sha256_hex(key, signed), sig):
        return False, "bad signature", None
    if dev != device:
        return False, "meant for another device", None
    if cmd not in COMMANDS:
        return False, "unknown command", None
    if seq <= last_seq:
        return False, "replayed or old seq", None
    return True, "accepted", msg
```

Readings keep flowing when the counter is damaged. Only the security-sensitive part stops, and every refused command says why on the audit topic.

## Step 5: The connection state machine

The old station had one blocking connect at startup. The new one has a `state` variable and a `network_step()` function that does a little bit of work and returns at once, so the sampling loop is never stuck waiting. The states match the diagram from the notes: `join_wifi`, `wait_wifi`, `connect_broker`, `online`, and `backoff`.

Three details make it robust:

-   Every wait has a **deadline**: Wi-Fi gets 15 seconds before the station backs off, and `client.connect(timeout=5)` gives up on an unreachable broker after 5 seconds. (The `timeout` argument exists in current copies of `umqtt.simple`; an old copy will reject it.)
-   `connect_broker` **subscribes again** every time. `umqtt.simple` connects with a clean session, so the broker forgets subscriptions when a connection drops.
-   Every reading goes **through the outbox**, even while online. There is one path for data, so the "online" and "recovering" cases can't behave differently by accident.

```python title="main.py"
# Greenhouse station that keeps working through Wi-Fi and broker outages
import json
import time

import dht
import network
from machine import Pin
from umqttsimple import MQTTClient, MQTTException

from commands import COMMANDS, check_command, load_seq, save_seq
from resilience import Backoff, Outbox

try:
    from secrets import WIFI_SSID, WIFI_PASSWORD, FAN_KEY
except ImportError:
    print("No secrets.py on this board. Copy secrets.example.py to secrets.py and fill it in.")
    raise

CODE = "a7f3c9"                          # your own random code
DEVICE = "station-01"
BROKER = "broker.hivemq.com"
BASE = "c4t-lab/" + CODE + "/greenhouse"
STATUS = BASE + "/devices/" + DEVICE + "/status"
HEALTH = BASE + "/devices/" + DEVICE + "/health"
AUDIT = BASE + "/devices/" + DEVICE + "/audit"
FAN_SET = BASE + "/bed1/fan/set"
FAN_STATE = BASE + "/bed1/fan/state"
EVERY_MS = 5000
WIFI_TIMEOUT_MS = 15000

sensor = dht.DHT22(Pin(15))
fan = Pin(16, Pin.OUT, value=0)          # fail safe: the fan starts off
cut_button = Pin(14, Pin.IN, Pin.PULL_UP)
wlan = network.WLAN(network.STA_IF)
wlan.active(True)

box = Outbox(capacity=120)               # about five minutes of readings
backoff = Backoff(base_ms=1000, cap_ms=30000)
last_seq = load_seq()                    # None means the counter file is damaged
reading_seq = 0
state = "join_wifi"
retry_at = time.ticks_ms()
wifi_deadline = time.ticks_ms()
was_pressed = False
BOOT = time.ticks_ms()


def on_message(topic, payload):
    global last_seq
    try:
        text = payload.decode()
    except ValueError:
        text = ""
    ok, reason, msg = check_command(text, last_seq, FAN_KEY, DEVICE)
    if ok:
        last_seq = msg["seq"]
        save_seq(last_seq)
        fan.value(COMMANDS[msg["cmd"]])
        state_text = "on" if fan.value() else "off"
        client.publish(FAN_STATE, json.dumps({"state": state_text, "seq": last_seq}), retain=True)
        entry = {"result": "accepted", "cmd": msg["cmd"], "seq": last_seq}
    else:
        entry = {"result": "rejected", "reason": reason}
    client.publish(AUDIT, json.dumps(entry))
    print("fan command:", entry)


client = MQTTClient(DEVICE + "-" + CODE, BROKER, keepalive=30)
client.set_callback(on_message)
client.set_last_will(STATUS, "offline", retain=True, qos=1)


def sample():
    """Read the sensor and queue the result. Runs whether or not we're online."""
    global reading_seq
    reading_seq += 1
    up = time.ticks_diff(time.ticks_ms(), BOOT) // 1000      # seconds since boot
    try:
        sensor.measure()
        temp, hum = sensor.temperature(), sensor.humidity()
    except OSError:
        box.add(HEALTH, json.dumps({"ok": False, "error": "sensor read failed", "seq": reading_seq}))
        return
    if not (-40 <= temp <= 80 and 0 <= hum <= 100):
        box.add(HEALTH, json.dumps({"ok": False, "error": "reading out of range", "seq": reading_seq}))
        return
    for what, value, unit in (("temperature", temp, "C"), ("humidity", hum, "%")):
        payload = {"v": round(value, 1), "unit": unit, "dev": DEVICE, "seq": reading_seq, "up": up}
        box.add(BASE + "/bed1/" + what, json.dumps(payload))


def send(topic, payload):
    client.publish(topic, payload)


def go_offline(why):
    global state, retry_at
    wait = backoff.next_delay_ms()
    retry_at = time.ticks_add(time.ticks_ms(), wait)
    state = "backoff"
    print(why + ". Retrying in", wait, "ms. Queued messages:", len(box.items))


def network_step():
    """Do one small piece of connection work, then return."""
    global state, wifi_deadline
    now = time.ticks_ms()
    if state == "backoff":
        if time.ticks_diff(now, retry_at) >= 0:
            state = "join_wifi"
    elif state == "join_wifi":
        if wlan.isconnected():
            state = "connect_broker"
        else:
            wlan.connect(WIFI_SSID, WIFI_PASSWORD)
            wifi_deadline = time.ticks_add(now, WIFI_TIMEOUT_MS)
            state = "wait_wifi"
    elif state == "wait_wifi":
        if wlan.isconnected():
            state = "connect_broker"
        elif time.ticks_diff(now, wifi_deadline) >= 0:
            go_offline("Wi-Fi timed out")
    elif state == "connect_broker":
        try:
            client.connect(timeout=5)            # don't wait forever on a dead broker
            client.publish(STATUS, "online", retain=True, qos=1)
            client.subscribe(FAN_SET, qos=1)     # new connection, no old subscriptions
            if box.dropped:
                client.publish(HEALTH, json.dumps({"ok": True, "dropped": box.dropped}))
                box.dropped = 0
            backoff.reset()
            state = "online"
            print("Online. Queued messages:", len(box.items))
        except (OSError, MQTTException) as err:
            go_offline("Broker connect failed: " + repr(err))
    elif state == "online":
        if not wlan.isconnected():
            go_offline("Wi-Fi lost")
            return
        try:
            client.check_msg()
            box.flush(send)
        except OSError as err:
            go_offline("Connection lost: " + repr(err))


def check_button():
    global was_pressed
    pressed = cut_button.value() == 0
    if pressed and not was_pressed:
        print("Button: cutting Wi-Fi to test recovery")
        wlan.disconnect()
    was_pressed = pressed


if last_seq is None:
    print("Counter file is damaged: fan commands will be refused until it is fixed")
next_sample = time.ticks_ms()
while True:
    check_button()
    if time.ticks_diff(time.ticks_ms(), next_sample) >= 0:
        next_sample = time.ticks_add(next_sample, EVERY_MS)
        sample()
    network_step()
    time.sleep_ms(50)
```

## Step 6: Break it on purpose

Run the simulation with the HiveMQ web client subscribed to `c4t-lab/a7f3c9/#`, and try each failure:

1.  **Wi-Fi drop.** Press the button. The terminal prints `Wi-Fi lost`, readings keep queuing, and after a short random wait the station reconnects and flushes. In the web client, a short burst of readings arrives at once, with `seq` values in order.
2.  **Repeat drops.** Press the button several times quickly. Each failure before a successful reconnect makes the next wait longer; one success resets it.
3.  **Commands after recovery.** After a reconnect, publish a freshly signed fan command. It works, which proves the resubscribe happened.
4.  **Sensor fault.** Stop the simulation, delete the wire to the DHT22's SDA pin, and start again. Instead of readings, the `health` topic reports `sensor read failed` every five seconds, and the dashboard's temperature tile goes stale on schedule.
5.  **Damaged counter.** Add a file named `fan_seq.txt` to the project containing the word `oops`, and start the simulation. The station prints its warning, readings flow normally, and every fan command is refused with `counter unreadable`.

:::quiz
Q: Why does `flush` call `self.items.pop(0)` only after `send` returns?
- [x] If `send` raises, the message is still in the outbox and goes out on the next flush
  Removing it first would lose exactly the message that was being sent when the link died.
- [ ] Because `pop(0)` is faster after a send
  Speed is the same either way; the order is about not losing data.
- [ ] So that the outbox can grow past its capacity during a flush
  Capacity is enforced in `add`, and `flush` only ever shrinks the list.

Q: When the outbox is full, it drops the oldest reading. When would dropping the newest be better?
- [ ] Never; newest data is always worth more
  Usually, but not for every kind of data.
- [x] When the start of an event matters most, such as the first reading after a frost alarm began
  A policy is a choice about which data matters. For a live dashboard, keep the newest; for a record of what went wrong, the oldest can be the valuable part.
- [ ] When the outbox is small
  Capacity changes how much you keep, not which end you should sacrifice.

Q: After a Wi-Fi drop, the station reconnects and readings arrive, but fan commands are ignored. Which line was most likely forgotten?
- [ ] `backoff.reset()`
  That only affects how long the *next* outage's waits are.
- [x] `client.subscribe(FAN_SET, qos=1)` in the `connect_broker` state
  Each new connection starts with no subscriptions, so the broker has nowhere to send your commands.
- [ ] `client.set_last_will(...)`
  The will is stored in the client object and sent with each `connect()`, and it doesn't affect receiving commands.
:::

:::takeaways
- Put every secret in one file that never leaves your machine or the board, and share a `secrets.example.py` instead.
- An outbox needs a capacity, a drop policy, and a dropped counter, and it removes a message only after it is sent.
- Backoff with jitter protects the broker; its cap decides how long recovery can lag behind the network coming back.
- A non-blocking state machine with deadlines keeps sampling running in every state.
- After every reconnect: publish `online`, resubscribe, report drops, then flush oldest first.
- Fail closed on damaged security state, and keep the harmless parts of the system working.
:::

## Ideas to extend it

-   Save the counter crash-safely: write to `fan_seq.tmp`, then `os.rename` it over `fan_seq.txt`, so a power cut leaves either the old file or the new one, never half of each.
-   Show the `health` topic on the dashboard as a warning banner, including how many readings were dropped.
-   Add `ntptime.settime()` after the first successful connection and send a real timestamp with each reading, so a logger can place buffered readings at the moment they were measured.
-   Keep a small outbox in flash as well as RAM, so readings taken during an outage survive a reboot too.
