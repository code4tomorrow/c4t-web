The station from Module 5 gets a fan (an LED on GP16 stands in for it). By the end, the fan obeys exactly one kind of message: a command signed with your key, addressed to `station-01`, naming a known command, with a sequence number it hasn't seen. Everything else is refused and written to an audit topic, so you can see who tried what.

We use a **counter** for replay protection rather than a timestamp, because the simulated board's clock can drift away from your computer's. Each command's `seq` must be higher than the last one the station accepted.

## Step 1: Make a key and a signing tool

On your own computer, make a random key:

```bash
python3 -c "import secrets; print(secrets.token_hex(32))"
```

That prints 64 hex characters, which is 256 bits of randomness. You'll use those 64 characters as the key bytes on both sides. This key protects a simulated LED, so treat it as a throwaway; Module 7 is about handling keys that protect something real.

The signing tool runs on your computer with nothing but the standard library. It builds the signed string `device|command|seq` in a fixed order and prints a JSON command ready to paste:

```python run title="sign_command.py" input="fan_on|1"
import hashlib
import hmac
import json

KEY = b"0d4f6a8c1e3b5d7f9a2c4e6b8d0f1a3c5e7b9d2f4a6c8e0b1d3f5a7c9e2b4d6f"  # replace with yours
DEVICE = "station-01"

cmd = input("Command (fan_on or fan_off): ").strip()
seq = int(input("Sequence number (one more than the last): "))
text = f"{DEVICE}|{cmd}|{seq}"
sig = hmac.new(KEY, text.encode(), hashlib.sha256).hexdigest()
print(json.dumps({"dev": DEVICE, "cmd": cmd, "seq": seq, "sig": sig}))
```

Copy the last line of your own output; that is the whole command. The signature is the only part that needs the key, so the JSON itself can be read by anyone without harm.

## Step 2: HMAC for a board without an `hmac` module

MicroPython on the Pico has `hashlib.sha256` but no `hmac`. Fortunately HMAC is short enough to write yourself, straight from its definition (RFC 2104):

1.  Pad the key with zero bytes to SHA-256's block size, 64 bytes. (A longer key is hashed first.)
2.  Make two keys from it: every byte XOR `0x36` (the inner key) and every byte XOR `0x5C` (the outer key).
3.  `tag = SHA256(outer_key + SHA256(inner_key + message))`.

Never trust a hand-written crypto function until it matches a known-good one, so this cell checks it against Python's `hmac` on keys that are exactly 64 bytes, short, long, and empty:

```python run title="hmac_lite.py"
import binascii
import hashlib
import hmac

BLOCK = 64   # SHA-256 works on 64-byte blocks

def hmac_sha256(key, message):
    if len(key) > BLOCK:
        key = hashlib.sha256(key).digest()
    key = key + b"\x00" * (BLOCK - len(key))
    inner_key = bytes([b ^ 0x36 for b in key])
    outer_key = bytes([b ^ 0x5C for b in key])
    inner = hashlib.sha256(inner_key + message).digest()
    return hashlib.sha256(outer_key + inner).digest()

def hmac_sha256_hex(key, message):
    return binascii.hexlify(hmac_sha256(key, message)).decode()

def same(a, b):
    """Compare two strings in a time that doesn't depend on where they differ."""
    a, b = a.encode(), b.encode()
    if len(a) != len(b):
        return False
    diff = 0
    for x, y in zip(a, b):
        diff |= x ^ y
    return diff == 0

cases = [(KEY, b"station-01|fan_on|1"), (b"short", b""),
         (b"k" * 100, b"a long key gets hashed first"), (b"", b"no key at all")]
for key, message in cases:
    ours = hmac_sha256_hex(key, message)
    theirs = hmac.new(key, message, hashlib.sha256).hexdigest()
    print(f"key {len(key):3} bytes: {ours[:20]}...  matches hmac module: {ours == theirs}")
print(same("abc123", "abc123"), same("abc123", "abc124"), same("abc", "abcd"))
```

All four match, and the first tag starts with the same characters as the signature from Step 1. `binascii.hexlify` replaces `.hexdigest()`, which MicroPython's `hashlib` doesn't have. And `same()` is MicroPython's stand-in for `hmac.compare_digest`: it always walks the whole string, folding every difference into `diff`, so it takes the same time wherever the first mismatch is.

## Step 3: One function that decides

All the rules live in `check_command`. It runs unchanged on your computer and on the Pico, so you can attack it here, with ten messages, before it ever touches hardware. The order matters: parse, check types, verify the signature, and only then look at what the message asks for.

```python run title="command_check.py"
COMMANDS = {"fan_on": 1, "fan_off": 0}

def check_command(text, last_seq, key, device):
    try:
        msg = json.loads(text)
    except ValueError:
        return False, "not JSON", None
    if not isinstance(msg, dict):
        return False, "not a JSON object", None
    dev, cmd, seq, sig = msg.get("dev"), msg.get("cmd"), msg.get("seq"), msg.get("sig")
    if not (isinstance(dev, str) and isinstance(cmd, str) and isinstance(seq, int) and isinstance(sig, str)):
        return False, "missing or wrong-type field", None
    signed = (dev + "|" + cmd + "|" + str(seq)).encode()
    if not same(hmac_sha256_hex(key, signed), sig):
        return False, "bad signature", None
    if dev != device:
        return False, "meant for another device", None
    if cmd not in COMMANDS:
        return False, "unknown command", None
    if seq <= last_seq:
        return False, "replayed or old seq", None
    return True, "accepted", msg

# Build test messages the way sign_command.py does
def make(cmd, seq, key=KEY, dev=DEVICE):
    sig = hmac.new(key, f"{dev}|{cmd}|{seq}".encode(), hashlib.sha256).hexdigest()
    return json.dumps({"dev": dev, "cmd": cmd, "seq": seq, "sig": sig})

first = make("fan_on", 1)
attempts = [
    ("genuine fan_on #1", first),
    ("same message again", first),
    ("cmd edited, old sig", first.replace("fan_on", "fan_off")),
    ("genuine fan_off #2", make("fan_off", 2)),
    ("signed with a guessed key", make("fan_on", 3, key=b"letmein")),
    ("genuine, other device", make("fan_on", 3, dev="station-02")),
    ("genuine, unknown cmd", make("unlock_door", 3)),
    ("old seq, freshly signed", make("fan_on", 1)),
    ("plain text", "on"),
    ("JSON without sig", '{"dev": "station-01", "cmd": "fan_on", "seq": 9}'),
]
last_seq = 0
for label, text in attempts:
    ok, reason, msg = check_command(text, last_seq, KEY, DEVICE)
    if ok:
        last_seq = msg["seq"]
    print(f"{label:27} -> {reason:28} last_seq={last_seq}")
```

Only the two genuine, fresh commands get through. The "unknown cmd" row is worth a second look: it was signed with the real key, so it came from you, and the station still refuses it. An allowlist protects you from your own controller's bugs, too.

## Step 4: Wire the fan and save the counter

Add an LED to the Wokwi diagram with the **+** button, plus a resistor (set it to 220 Ω):

| From | To |
| --- | --- |
| GP16 | resistor, one end |
| resistor, other end | LED anode (**A**, the bent leg) |
| LED cathode (**C**) | GND |

Then add two files to the project next to `umqttsimple.py`:

-   `hmac_lite.py`: the three functions from Step 2 (`hmac_sha256`, `hmac_sha256_hex`, `same`) plus `import binascii` and `import hashlib` at the top.
-   `secrets.py`: one line holding the same key as your signing tool:

```python title="secrets.py (on the station)"
FAN_KEY = b"0d4f6a8c1e3b5d7f9a2c4e6b8d0f1a3c5e7b9d2f4a6c8e0b1d3f5a7c9e2b4d6f"
```

The station must remember `last_seq` across reboots, or a restart would accept every old command again. It saves the number to a small file each time it accepts a command:

```python title="saving the counter (part of main.py)"
SEQ_FILE = "fan_seq.txt"

def load_seq():
    try:
        with open(SEQ_FILE) as f:
            return int(f.read())
    except (OSError, ValueError):
        return 0

def save_seq(seq):
    with open(SEQ_FILE, "w") as f:
        f.write(str(seq))
```

On a real Pico W that file lives in flash and survives power cuts. **In Wokwi, files your program writes don't survive a restart**: each run starts from a fresh copy of the project files, so the counter goes back to 0 when you press Stop and Play. Keep that in mind when testing; the practice lesson has you fix it.

## Step 5: Subscribe, check, act, and log

Here is the complete station. Compared with Module 5 it adds the fan pin, a callback that runs `check_command`, a `subscribe` call, and `client.check_msg()` in the loop, which handles any waiting message and returns at once if there is none.

```python title="main.py"
# Greenhouse station: readings out, signed fan commands in
import json
import time

import dht
import network
from machine import Pin
from umqttsimple import MQTTClient

from hmac_lite import hmac_sha256_hex, same
from secrets import FAN_KEY

CODE = "a7f3c9"                      # your own random code
DEVICE = "station-01"
BROKER = "broker.hivemq.com"
BASE = "c4t-lab/" + CODE + "/greenhouse"
STATUS = BASE + "/devices/" + DEVICE + "/status"
AUDIT = BASE + "/devices/" + DEVICE + "/audit"
FAN_SET = BASE + "/bed1/fan/set"
FAN_STATE = BASE + "/bed1/fan/state"
SEQ_FILE = "fan_seq.txt"
COMMANDS = {"fan_on": 1, "fan_off": 0}
EVERY_MS = 5000

sensor = dht.DHT22(Pin(15))
fan = Pin(16, Pin.OUT, value=0)
heartbeat = Pin("LED", Pin.OUT)


def load_seq():
    try:
        with open(SEQ_FILE) as f:
            return int(f.read())
    except (OSError, ValueError):
        return 0


def save_seq(seq):
    with open(SEQ_FILE, "w") as f:
        f.write(str(seq))


def check_command(text, last_seq, key, device):
    try:
        msg = json.loads(text)
    except ValueError:
        return False, "not JSON", None
    if not isinstance(msg, dict):
        return False, "not a JSON object", None
    dev, cmd, seq, sig = msg.get("dev"), msg.get("cmd"), msg.get("seq"), msg.get("sig")
    if not (isinstance(dev, str) and isinstance(cmd, str) and isinstance(seq, int) and isinstance(sig, str)):
        return False, "missing or wrong-type field", None
    signed = (dev + "|" + cmd + "|" + str(seq)).encode()
    if not same(hmac_sha256_hex(key, signed), sig):
        return False, "bad signature", None
    if dev != device:
        return False, "meant for another device", None
    if cmd not in COMMANDS:
        return False, "unknown command", None
    if seq <= last_seq:
        return False, "replayed or old seq", None
    return True, "accepted", msg


def on_message(topic, payload):
    global last_seq
    try:
        text = payload.decode()
    except ValueError:
        text = ""
    ok, reason, msg = check_command(text, last_seq, FAN_KEY, DEVICE)
    if ok:
        last_seq = msg["seq"]
        save_seq(last_seq)
        fan.value(COMMANDS[msg["cmd"]])
        state = "on" if fan.value() else "off"
        client.publish(FAN_STATE, json.dumps({"state": state, "seq": last_seq}), retain=True)
        entry = {"result": "accepted", "cmd": msg["cmd"], "seq": last_seq}
    else:
        entry = {"result": "rejected", "reason": reason}
    client.publish(AUDIT, json.dumps(entry))
    print("fan command:", entry)


def connect_wifi():
    wlan = network.WLAN(network.STA_IF)
    wlan.active(True)
    wlan.connect("Wokwi-GUEST", "")
    print("Joining Wi-Fi", end="")
    while not wlan.isconnected():
        print(".", end="")
        time.sleep(0.25)
    print(" ok")


def connect_broker():
    global client                    # on_message needs it, even during subscribe()
    client = MQTTClient(DEVICE + "-" + CODE, BROKER, keepalive=30)
    client.set_callback(on_message)
    client.set_last_will(STATUS, "offline", retain=True, qos=1)
    client.connect()
    client.publish(STATUS, "online", retain=True, qos=1)
    client.subscribe(FAN_SET, qos=1)
    print("Broker ok; listening on", FAN_SET, "with last seq", last_seq)


def publish_reading(where, what, value, unit, seq):
    topic = BASE + "/" + where + "/" + what
    client.publish(topic, json.dumps({"v": value, "unit": unit, "dev": DEVICE, "seq": seq}))


last_seq = load_seq()
connect_wifi()
connect_broker()
reading_seq = 0
next_due = time.ticks_ms()

while True:
    client.check_msg()               # runs on_message if a command is waiting
    if time.ticks_diff(time.ticks_ms(), next_due) >= 0:
        next_due = time.ticks_add(next_due, EVERY_MS)
        try:
            sensor.measure()
        except OSError as err:
            print("Sensor read failed:", err)
            continue
        reading_seq += 1
        publish_reading("bed1", "temperature", round(sensor.temperature(), 1), "C", reading_seq)
        publish_reading("bed1", "humidity", round(sensor.humidity(), 1), "%", reading_seq)
        heartbeat.toggle()
    time.sleep_ms(50)
```

A few lines deserve a closer look:

-   `set_callback` must come before `subscribe`; `umqtt.simple` refuses to subscribe without one. And `client` is made global inside `connect_broker` because a message can arrive while `subscribe()` is still waiting for the broker's reply, and `on_message` publishes through `client`.
-   The audit entry for a rejection records the **reason only**. It never echoes the payload, so a stranger can't use your audit topic to bounce their own text around, and it never contains the key.
-   The fan state is published **retained** with its `seq`, so a dashboard sees whether the fan is on, and you can see which number to sign next.

## Step 6: Attack your own fan

Run the simulation, open the HiveMQ web client, connect, and subscribe to `c4t-lab/a7f3c9/#` so you see the audit topic. Then use its **Publish** box with the topic `c4t-lab/a7f3c9/greenhouse/bed1/fan/set`, and leave **Retain** unchecked:

1.  Paste the signed `fan_on` command with `seq` 1 and click **Publish**. The LED lights, and the audit topic shows `accepted`.
2.  Click **Publish** again without changing anything. That's a replay. The audit shows `replayed or old seq` and nothing changes.
3.  Change `fan_on` to `fan_off` in the message box but keep the old `sig`. Result: `bad signature`.
4.  Publish the word `on`. Result: `not JSON`.
5.  Run `sign_command.py` again for `fan_off` with `seq` 2 and publish it. The LED goes dark.

```text
Joining Wi-Fi....... ok
Broker ok; listening on c4t-lab/a7f3c9/greenhouse/bed1/fan/set with last seq 0
fan command: {'result': 'accepted', 'cmd': 'fan_on', 'seq': 1}
fan command: {'result': 'rejected', 'reason': 'replayed or old seq'}
fan command: {'result': 'rejected', 'reason': 'bad signature'}
fan command: {'result': 'rejected', 'reason': 'not JSON'}
fan command: {'result': 'accepted', 'cmd': 'fan_off', 'seq': 2}
```

(The dictionary keys may print in another order on the Pico.)

What to watch for: the sender and receiver both computing the MAC from the message and the shared key, and the receiver comparing results. That is exactly what `sign_command.py` and `check_command` do on opposite ends of the broker.

:::quiz
Q: Why does `check_command` verify the signature before checking `seq <= last_seq`?
- [x] So that nothing about an unsigned message affects the station, and the checks that read its contents only ever run on authentic data
  A message is untrusted until its tag checks out. Checking the signature first means every later decision is about a message you actually sent.
- [ ] Because checking the sequence number is slower
  Comparing two integers is far cheaper than an HMAC; speed isn't the reason.
- [ ] Because a bad signature is the most common problem
  Maybe, but the order is about trust, not frequency.

Q: The station accepts `seq` 5. You then sign `fan_on` with `seq` 4 by mistake. What happens, and why is that the right behavior?
- [ ] It is accepted, because the signature is valid
  A valid signature proves you sent it, not that it's new. An old genuine message is exactly what a replay looks like.
- [x] It is rejected as an old seq; the station can't tell your mistake apart from a replay of an earlier message
  Any number at or below the last accepted one is refused, whoever sent it. Sign with 6 instead.
- [ ] The station resets its counter to 4
  The counter only moves up, and only after a fully valid command.

Q: Why does the station save `last_seq` to a file?
- [ ] To make the program faster
  Writing to flash is slower than keeping a variable; the file is about memory across restarts.
- [x] So a reboot doesn't reset the counter and reopen the door to every command ever sent
  If `last_seq` restarted at 0, an attacker could replay your `seq` 1 command after any power cut. In Wokwi the file resets on every start, which is a simulator limit to remember.
:::

:::takeaways
- Sign a fixed-order string of every field the device acts on: here `device|command|seq`.
- HMAC-SHA256 is two SHA-256 calls with padded, XOR-ed keys; test any hand-written version against a trusted library.
- Check in this order: parse, types, signature, then device, allowlist, and freshness. Act only after every check passes.
- A counter needs no clock, but the device must store it somewhere that survives a reboot.
- Log every decision to an audit topic, with reasons, never the key or the raw rejected payload.
:::

## Ideas to extend it

-   Give each device its own key, so a key pulled out of one stolen board can't command the others.
-   Replace the counter with a timestamp and nonce: call `ntptime.settime()` after Wi-Fi connects and allow a generous window to absorb simulator drift.
-   Lock out commands for a minute after five bad signatures in a row, and publish a `locked` audit entry.
-   Write a desktop controller that publishes the signed command itself with the `paho-mqtt` package, and reads the retained `fan/state` to pick the next `seq` automatically.
