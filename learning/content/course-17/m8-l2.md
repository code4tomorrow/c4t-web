The examples here use the **weather station** from the planning lesson, with a DHT22, a photoresistor, a pushbutton as a rain gauge, and a signed `set_interval` command. If you picked another project, the structure stays the same; only `sensors.py`, `RANGES`, `COMMANDS`, and `apply_command` change.

## The starter logic, with commands that take an argument

Module 6's commands were just names. Real projects need values: an interval, an angle, a duration. The argument goes **inside the signed text** (`device|command|argument|seq`, with an empty argument for commands that take none), and after the signature is verified, the station checks it against an allowed range. A signed `set_interval 1` is still refused, because one second would flood the broker.

On your computer, the standard library stands in for `hmac_lite.py`, so this cell runs here unchanged:

```python run title="logic.py"
import hashlib
import hmac
import json

# On your computer the standard library stands in for hmac_lite.py
def hmac_sha256_hex(key, message):
    return hmac.new(key, message, hashlib.sha256).hexdigest()

same = hmac.compare_digest

# ---------------- logic.py: copy everything below onto the Pico ----------------
RANGES = {"temperature": (-40, 80), "humidity": (0, 100), "light": (0, 100), "rain": (0, 100000)}
COMMANDS = {"set_interval": (5, 300), "reset_rain": None}   # name -> argument range, or None


def validate_reading(what, value):
    if what not in RANGES:
        return False, "unknown measurement " + what
    if isinstance(value, bool) or not isinstance(value, (int, float)):
        return False, "not a number"
    low, high = RANGES[what]
    if not low <= value <= high:
        return False, "out of range"
    return True, "ok"


def signed_text(dev, cmd, arg, seq):
    return dev + "|" + cmd + "|" + ("" if arg is None else str(arg)) + "|" + str(seq)


def check_command(text, last_seq, key, device):
    if last_seq is None:
        return False, "counter unreadable", None
    try:
        msg = json.loads(text)
    except ValueError:
        return False, "not JSON", None
    if not isinstance(msg, dict):
        return False, "not a JSON object", None
    dev, cmd, arg, seq, sig = [msg.get(k) for k in ("dev", "cmd", "arg", "seq", "sig")]
    if not (isinstance(dev, str) and isinstance(cmd, str) and isinstance(seq, int) and isinstance(sig, str)):
        return False, "missing or wrong-type field", None
    if arg is not None and (isinstance(arg, bool) or not isinstance(arg, int)):
        return False, "argument must be a whole number", None
    if not same(hmac_sha256_hex(key, signed_text(dev, cmd, arg, seq).encode()), sig):
        return False, "bad signature", None
    if dev != device:
        return False, "meant for another device", None
    if cmd not in COMMANDS:
        return False, "unknown command", None
    allowed = COMMANDS[cmd]
    if (allowed is None) != (arg is None):
        return False, "argument missing or not expected", None
    if allowed is not None and not allowed[0] <= arg <= allowed[1]:
        return False, "argument out of range", None
    if seq <= last_seq:
        return False, "replayed or old seq", None
    return True, "accepted", msg
```

On the Pico, `logic.py` starts with `import json` and `from hmac_lite import hmac_sha256_hex, same` instead of the stand-ins above the dashed line.

Now the tests. They are the part of the starter worth the most: every time you change `logic.py`, run them again. Add a test for each rule your own project adds.

```python run title="test_logic.py"
import sys
import unittest

KEY = b"capstone-test-key-not-a-real-one-0123456789abcdef0123456789abcd"
DEV = "ws-01"

def make(cmd, arg, seq, key=KEY, dev=DEV):
    sig = hmac_sha256_hex(key, signed_text(dev, cmd, arg, seq).encode())
    return json.dumps({"dev": dev, "cmd": cmd, "arg": arg, "seq": seq, "sig": sig})

class Readings(unittest.TestCase):
    def test_normal_value_passes(self):
        self.assertEqual(validate_reading("temperature", 21.5), (True, "ok"))

    def test_impossible_value_is_caught(self):
        self.assertEqual(validate_reading("humidity", 140)[1], "out of range")

    def test_true_is_not_a_number(self):
        self.assertFalse(validate_reading("light", True)[0])

class Commands(unittest.TestCase):
    def test_genuine_command_with_argument(self):
        ok, reason, msg = check_command(make("set_interval", 30, 1), 0, KEY, DEV)
        self.assertTrue(ok)
        self.assertEqual(msg["arg"], 30)

    def test_command_without_argument(self):
        self.assertTrue(check_command(make("reset_rain", None, 1), 0, KEY, DEV)[0])

    def test_replay_is_refused(self):
        self.assertEqual(check_command(make("set_interval", 30, 4), 4, KEY, DEV)[1], "replayed or old seq")

    def test_edited_argument_breaks_signature(self):
        edited = make("set_interval", 30, 1).replace('"arg": 30', '"arg": 3000')
        self.assertEqual(check_command(edited, 0, KEY, DEV)[1], "bad signature")

    def test_signed_but_out_of_range(self):
        self.assertEqual(check_command(make("set_interval", 1, 1), 0, KEY, DEV)[1], "argument out of range")

    def test_missing_argument(self):
        self.assertEqual(check_command(make("set_interval", None, 1), 0, KEY, DEV)[1], "argument missing or not expected")

    def test_damaged_counter_fails_closed(self):
        self.assertEqual(check_command(make("reset_rain", None, 9), None, KEY, DEV)[1], "counter unreadable")

suite = unittest.TestSuite()
for case in (Readings, Commands):
    suite.addTests(unittest.defaultTestLoader.loadTestsFromTestCase(case))
unittest.TextTestRunner(stream=sys.stdout, verbosity=2).run(suite)
```

The test names read like the requirements, which is deliberate: in the last lesson this output becomes evidence in your README.

## M1: Sensors that report honestly

Wire your parts and write `sensors.py`. Its only job is to read hardware and return tuples; it doesn't know about MQTT. Here is the weather station's version, including a rain gauge that counts button presses with an interrupt:

```python title="sensors.py"
import time

import dht
from machine import ADC, Pin

_dht = dht.DHT22(Pin(15))
_light = ADC(26)                          # photoresistor module's AO pin
_bucket = Pin(13, Pin.IN, Pin.PULL_UP)    # pushbutton to GND stands in for the bucket
_tips = 0
_last_tip = time.ticks_ms()


def _on_tip(pin):
    global _tips, _last_tip
    now = time.ticks_ms()
    if time.ticks_diff(now, _last_tip) > 200:     # ignore switch bounce
        _tips += 1
        _last_tip = now


_bucket.irq(trigger=Pin.IRQ_FALLING, handler=_on_tip)


def read_all():
    """Returns (where, what, value, unit) tuples. Raises OSError if the DHT22 fails."""
    _dht.measure()
    light = round(_light.read_u16() * 100 / 65535, 1)
    return [
        ("roof", "temperature", round(_dht.temperature(), 1), "C"),
        ("roof", "humidity", round(_dht.humidity(), 1), "%"),
        ("roof", "light", light, "%"),
        ("roof", "rain", _tips, "tips"),
    ]


def reset_rain():
    global _tips
    _tips = 0
```

**Done when:** a loop that calls `read_all()` and `validate_reading()` every few seconds prints every value with its unit; dragging the DHT22's sliders changes the numbers; and pressing the button raises `rain`. Check which way your light value moves when you cover the photoresistor, and write it in your plan.

## M2: Publishing that matches the plan

Start from Module 7's `main.py`. Import `config`, `logic`, and `sensors`, and replace its `sample()` with one that validates every reading and reports problems on the health topic instead of publishing them:

```python title="main.py: the parts that change"
import json
import time

import network
import config
import sensors
from logic import COMMANDS, check_command, validate_reading

every_ms = config.EVERY_MS               # a command can change this


def sample():
    global reading_seq
    reading_seq += 1
    try:
        readings = sensors.read_all()
    except OSError:
        box.add(config.HEALTH, json.dumps({"ok": False, "error": "sensor read failed", "seq": reading_seq}))
        return
    for where, what, value, unit in readings:
        ok, reason = validate_reading(what, value)
        if not ok:
            box.add(config.HEALTH, json.dumps({"ok": False, "error": what + " " + reason, "seq": reading_seq}))
            continue
        payload = {"v": value, "unit": unit, "dev": config.DEVICE, "seq": reading_seq}
        box.add(config.BASE + "/" + where + "/" + what, json.dumps(payload))
```

In the main loop, use `every_ms` instead of the fixed `EVERY_MS` when you schedule the next sample, so M4's command can change it.

**Done when:** the HiveMQ web client, subscribed to your prefix with `#`, shows every topic from your plan with the right payloads, the retained status arrives first, and stopping the simulation produces `offline` within about 45 seconds.

## M3: A dashboard that tells the truth

Reuse the dashboard from Module 5 with three changes:

1.  Add your units to `UNITS`, or the dashboard will rightly ignore your readings: for the weather station, `tips: "tips"`.
2.  Show the health topic. A simple version: in `show()`, if `parts[2] === "health"`, write the error text into a banner element with `textContent`.
3.  Make `offline` impossible to miss. When a status badge says `offline`, add the `stale` class to every tile from that device.

**Done when:** tiles go stale after three missed intervals; stopping the simulation shows `offline`; disconnecting the DHT22's data wire shows a health banner; and publishing `{"v": "<b>hi</b>", "unit": "C"}` to a reading topic changes nothing on screen.

## M4: A remote action only you can trigger

Point the station's subscription at `config.COMMAND_TOPIC`, and route accepted commands through one function that holds every project-specific effect:

```python title="main.py: commands"
def apply_command(cmd, arg):
    """Every branch must leave the device in a safe state."""
    global every_ms
    if cmd == "set_interval":
        every_ms = arg * 1000
    elif cmd == "reset_rain":
        sensors.reset_rain()


def on_message(topic, payload):
    global last_seq
    try:
        text = payload.decode()
    except ValueError:
        text = ""
    ok, reason, msg = check_command(text, last_seq, FAN_KEY, config.DEVICE)
    if ok:
        last_seq = msg["seq"]
        save_seq(last_seq)
        apply_command(msg["cmd"], msg.get("arg"))
        entry = {"result": "accepted", "cmd": msg["cmd"], "arg": msg.get("arg"), "seq": last_seq}
    else:
        entry = {"result": "rejected", "reason": reason}
    client.publish(config.AUDIT, json.dumps(entry))
```

The signing tool learns about arguments too:

```python run title="sign_command.py" input="set_interval|30|1"
import hmac
import json

cmd = input("Command: ").strip()
arg_text = input("Argument (blank for none): ").strip()
seq = int(input("Sequence number: "))

text = DEVICE + "|" + cmd + "|" + ("" if arg is None else str(arg)) + "|" + str(seq)

```

**Done when:** a genuine command takes effect and is audited as accepted, and each of these is refused with the right reason: the same message again, the argument edited, a signed but out-of-range argument, a command for another device, and plain text. The last lesson gives you a script that generates all of these at once.

:::warning
If your project has an actuator (a pump, a fan, a heater), it needs a **safe default** that doesn't depend on any command arriving: off at boot (`Pin(..., value=0)`), and for anything that runs, a timer that switches it off by itself. "The off command got lost" must never mean "the pump runs all night."
:::

## M5: Survive outages and reboots

Module 7's state machine, outbox, and backoff carry over as they are. What's new is testing them against *your* project:

-   Cut Wi-Fi with the button for 10 seconds, then for 2 minutes. Readings from the short outage all arrive; the long one reports a `dropped` count on the health topic if the outbox filled.
-   Send a command, cut the Wi-Fi, restore it, and send another command with the next `seq`. It must work, proving the resubscribe.
-   Restart the simulation and replay your last command. On a real Pico it is refused; in Wokwi the counter file resets, so write down in your README what you'd do about it (Module 6's practice lesson has one answer).

**Done when:** every failure row in your plan's failure table has been triggered at least once, and the response matched the table, or you've updated the table to match what you decided is right.
