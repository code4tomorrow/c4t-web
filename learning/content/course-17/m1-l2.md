:::objectives
- Run a MicroPython program in Wokwi and read its output in the Serial Monitor.
- Blink the onboard LED with `Pin("LED")` and an external LED on GP15.
- Paste a circuit into `diagram.json` and check the LED is wired the right way round.
- Stop a running program with Ctrl+C and control pins by hand from the REPL.
- (Optional) Log in to a Raspberry Pi with SSH and blink an LED with gpiozero.
:::

Blinking an LED is the "hello, world" of hardware, and it earns that place. If the light flashes, you have proved that your editor, the firmware, your code, and your wiring all work together. When something breaks later, a quick blink test tells you which of those four is at fault.

By the end of this lesson, two LEDs take turns: the tiny one on the board and a green one you wired yourself. The Serial Monitor counts the blinks.

```mermaid caption="The circuit you'll build: one pin, one resistor, one LED"
flowchart LR
    A["GP15 (physical pin 20)"] --> B["330 Ω resistor"]
    B --> C["LED anode (+)"]
    C --> D["LED cathode (−)"]
    D --> E["GND (physical pin 18)"]
```

## Step 1: Run the template

Open a new **Micropython Pico W** project (`wokwi.com/projects/new/micropython-pi-pico-w`) and press play. `Hello, Pi Pico W!` appears in the Serial Monitor.

Now press stop. Every run starts the board fresh, like unplugging a real one and plugging it back in. Variables don't survive between runs, which matters once you start logging data in Module 4.

## Step 2: Blink the onboard LED

Replace everything in `main.py` with this and press play:

```python title="main.py"
from machine import Pin
import time

time.sleep(0.1)  # give the USB terminal a moment to connect

led = Pin("LED", Pin.OUT)

while True:
    led.toggle()
    time.sleep(0.25)
```

The small LED near the USB connector flashes twice a second. Three lines do the work:

-   `Pin("LED", Pin.OUT)` creates an object for the onboard LED and makes it an **output**, a pin your code drives on or off. On the Pico W the LED is wired to the Wi-Fi chip rather than an ordinary GP pin, which is why it's named instead of numbered.
-   `led.toggle()` flips it: on becomes off, off becomes on.
-   `time.sleep(0.25)` pauses for a quarter second. On, wait, off, wait: one full blink every half second.

The `while True:` loop never ends, and that's normal for a microcontroller. There's no operating system to return to, so the program's job is to run until the power goes.

:::try
Change `0.25` to `0.05` and run it again. Then try `2`. Notice that while the board is sleeping it does nothing else at all; Module 3 shows how to blink without freezing the rest of the program.
:::

## Step 3: Add an LED and a resistor

An LED on its own would pull as much current as the pin can push, which overheats both. A resistor in series limits the current. With 3.3 V from the pin, about 2 V dropped across a green LED, and 330 Ω, the current is (3.3 − 2.0) / 330 ≈ 4 mA: bright enough to see and gentle on the pin. Module 2 works through this math properly.

You can wire it with the mouse (blue **+** button, then click pin to pin), but pasting is faster and exact. Open the `diagram.json` tab, select everything, and replace it with:

```json title="diagram.json"
{
  "version": 1,
  "author": "C4T Hardware Lab",
  "editor": "wokwi",
  "parts": [
    {
      "type": "board-pi-pico-w",
      "id": "pico",
      "top": 0,
      "left": 0,
      "attrs": { "env": "micropython-20260406-v1.28.0" }
    },
    { "type": "wokwi-resistor", "id": "r1", "top": 140, "left": -110, "attrs": { "value": "330" } },
    { "type": "wokwi-led", "id": "led1", "top": 40, "left": -130, "attrs": { "color": "green" } }
  ],
  "connections": [
    [ "pico:GP15", "r1:2", "green", [] ],
    [ "r1:1", "led1:A", "green", [] ],
    [ "led1:C", "pico:GND.4", "black", [] ]
  ],
  "dependencies": {}
}
```

Each connection lists two pins as `part:pin`. `pico:GND.4` is the fourth ground pin, physical pin 18, just above GP14 and GP15. `led1:A` is the LED's **anode**, its positive leg, and `led1:C` is the **cathode**. Current only flows from anode to cathode, so an LED wired backwards stays dark without any error message. The `env` line tells Wokwi which MicroPython firmware to load; it's the same value the template uses.

Drag the parts anywhere you like. The wires follow.

## Step 4: Make the two LEDs take turns

Replace `main.py` with the finished program:

```python title="main.py"
from machine import Pin
import time

time.sleep(0.1)  # give the USB terminal a moment to connect

onboard = Pin("LED", Pin.OUT)
external = Pin(15, Pin.OUT)

blinks = 0
while True:
    onboard.value(1)
    external.value(0)
    time.sleep(0.25)
    onboard.value(0)
    external.value(1)
    time.sleep(0.25)
    blinks += 1
    if blinks % 10 == 0:
        print("Blinks so far:", blinks)
```

The two LEDs alternate, and every five seconds the Serial Monitor gets a new line:

```text
Blinks so far: 10
Blinks so far: 20
Blinks so far: 30
```

`value(1)` and `value(0)` set a pin high (3.3 V) or low (0 V) directly, which is clearer than `toggle()` when two pins must stay opposite. The `blinks % 10 == 0` check prints only every tenth blink, so the terminal doesn't scroll by too fast to read.

:::warning
**The external LED never lights.** Check three things in this order: the pin number in code matches the wire (`Pin(15)` needs `pico:GP15`), the LED's anode faces the resistor and its cathode faces GND, and the wire really ends on a pin. In Wokwi, hovering over a wire end shows which pin it reached.
:::

## Step 5: Take over from the REPL

Click inside the Serial Monitor and press **Ctrl+C**. The program stops with a `KeyboardInterrupt` message and you land at the MicroPython prompt, `>>>`, called the **REPL** (read, evaluate, print, loop). The variables from `main.py` are still there, so you can drive the pins by hand:

```text
>>> external.value(1)
>>> external.value()
1
>>> onboard.toggle()
>>> import sys
>>> sys.platform
'rp2'
```

The first line lights the green LED and leaves it on. `sys.platform` reports `'rp2'`, the name of MicroPython's port for Raspberry Pi's microcontroller chips. The REPL is the fastest way to test one line of code or check how a sensor responds before writing a whole program around it.

## Step 6 (optional): Blink an LED on a real Raspberry Pi over SSH

If you prepared a Raspberry Pi with Imager in lesson 1 (hostname `iotpi`, SSH turned on), you can control its GPIO pins from your own computer's terminal. With the Pi **powered off**, wire GPIO17 (physical pin 11) through a 330 Ω resistor to the LED's long leg, and the short leg to GND (physical pin 9). Then power it up, wait a minute for the first boot, and connect, replacing `student` with the username you chose:

```bash
ssh student@iotpi.local
```

The first time, SSH asks you to trust the Pi:

```text
The authenticity of host 'iotpi.local (192.168.1.57)' can't be established.
ED25519 key fingerprint is SHA256:...
Are you sure you want to continue connecting (yes/no/[fingerprint])? yes
student@iotpi.local's password:
```

Type `yes`, then your password (nothing appears while you type it; that's deliberate). The prompt changes to `student@iotpi:~ $`, and every command you type now runs on the Pi. Make a folder and a file:

```bash
mkdir -p ~/iot-lab
cd ~/iot-lab
nano blink.py
```

In the nano editor, type this program, then save with **Ctrl+O** and **Enter** and exit with **Ctrl+X**:

```python title="blink.py"
from gpiozero import LED
from signal import pause

led = LED(17)  # GPIO17, which is physical pin 11
led.blink(on_time=0.25, off_time=0.25)
pause()  # keep the program alive while gpiozero blinks the LED
```

Run it with `python3 blink.py` and stop it with **Ctrl+C**. Notice the difference from MicroPython: gpiozero's `blink()` runs in the background, so the program needs `pause()` to stay alive. Type `exit` to end the SSH session.

-   **`Could not resolve hostname iotpi.local`**: the Pi may still be booting, or your network doesn't pass `.local` names. Find the Pi's IP address in your router's device list and use `ssh student@192.168.1.57` (with its real address) instead.
-   **`Permission denied, please try again.`**: the username or password doesn't match what you set in Imager. Usernames are lowercase.

:::quiz
Q: Why does the Pico W code use `Pin("LED")` instead of `Pin(25)`?
- [ ] `Pin(25)` is too slow for blinking
  Speed has nothing to do with it; both would switch in microseconds.
- [x] The Pico W's onboard LED is wired to the Wi-Fi chip, not to a regular GP pin
  On the original Pico it was GP25, but on the Pico W MicroPython reaches it through the wireless chip by name.
- [ ] Names are required for every pin in MicroPython
  Regular pins use numbers, like `Pin(15)`. Only special pins such as the LED have names.

Q: You swap the LED's two legs in `diagram.json`. What happens when you run the program?
- [ ] MicroPython raises an error about the LED's direction
  The code has no idea how the LED is wired; it only sets the pin high or low.
- [ ] The LED lights, just more dimly
  An LED is a diode: current flows only from anode to cathode, so a reversed LED doesn't light at all.
- [x] The LED stays dark and nothing reports a problem
  That silence is why "check the LED's direction" is on every hardware debugging checklist.

Q: Your program runs a `while True:` loop. How do you get to the `>>>` prompt without restarting the simulation?
- [x] Click in the Serial Monitor and press Ctrl+C
  That raises `KeyboardInterrupt`, stops `main.py`, and leaves its variables available at the prompt.
- [ ] Press the stop button
  Stop ends the whole simulation, so there's no board left to type to.
- [ ] Wait for the loop to finish
  `while True:` never finishes on its own.
:::

:::takeaways
- `Pin(id, Pin.OUT)` makes an output; `value(1)` sets it to 3.3 V, `value(0)` to 0 V, and `toggle()` flips it.
- The Pico W's onboard LED is `Pin("LED")`; external LEDs use GP numbers and need a series resistor.
- Wokwi circuits live in `diagram.json` as parts plus `part:pin` connections. A reversed LED fails silently.
- Ctrl+C in the Serial Monitor stops `main.py` and opens the REPL, where you can test single lines.
- On a Raspberry Pi, `ssh user@host.local` gives you its terminal, and gpiozero's `LED(17)` drives GPIO17.
:::
