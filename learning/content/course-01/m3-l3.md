---
title: "Practice: robot routes, scrambled steps, and drawing blind"
summary: Order scrambled steps, trace and write grid-robot routes, name inputs and outputs, fix a Scratch script that fails on its second run, and write drawing instructions a partner can follow without peeking.
---

:::objectives
- Put steps in an order that works, and spot which steps are allowed to swap.
- Trace a grid robot's state by hand, and write a route around obstacles.
- Name the inputs and outputs of everyday algorithms.
- Find a missing starting state in a Scratch script.
- Use events to control a sprite, and write instructions precise enough to draw from.
:::

Grid exercises use the same robot as the Notes lesson: **F** moves forward one square, **L** turns left 90 degrees, and **R** turns right 90 degrees. Turning never moves the robot off its square. Columns are numbered left to right, and rows bottom to top.

## Warm-up: find the gaps

"Put a little sugar in the tea and stir it for a while."

Circle every word that two people might carry out differently.

:::solution
*A little* (how much?) and *for a while* (how long?). A precise version: "Put 1 teaspoon of sugar in the tea and stir it 10 times." *It* is fine here, because there's only one thing it could mean.
:::

### Exercise 1: Breakfast, scrambled

These steps are out of order:

```text
A. Pour milk into the bowl.
B. Take a bowl out of the cupboard.
C. Eat the cereal with the spoon.
D. Pour cereal into the bowl.
E. Take a spoon out of the drawer.
```

Write them in an order that works. Then answer: which steps could swap places without breaking anything, and which steps have to stay where they are?

:::hint
For each step, ask: "What has to have happened already for this step to be possible?" You can't pour into a bowl you haven't taken out.
:::

:::solution
One order that works: **B, D, A, E, C**.

-   **B must come first**, because A and D need a bowl.
-   **C must come last**, because it needs the cereal, the milk, and the spoon.
-   **E can go anywhere before C.** Getting the spoon doesn't depend on the bowl at all.
-   **A and D can swap**, if you don't mind milk-first cereal.

Some steps *depend* on others, and those can't be swapped. Steps that don't depend on each other can go in either order. Algorithms often have more than one correct order for exactly this reason.
:::

### Exercise 2: Be the robot

On an empty grid, the robot starts at column 1, row 1, **facing north** (up the page). It runs:

```text
F F R F F L F
```

Where does it end up, and which way is it facing? Fill in a state table as you go.

:::hint
Facing north, F adds 1 to the row. After R, the robot faces east, so F adds 1 to the column instead. L and R never change the column or row.
:::

:::solution
| After | Command | Column | Row | Facing |
| --- | --- | --- | --- | --- |
| start | | 1 | 1 | north |
| 1 | F | 1 | 2 | north |
| 2 | F | 1 | 3 | north |
| 3 | R | 1 | 3 | east |
| 4 | F | 2 | 3 | east |
| 5 | F | 3 | 3 | east |
| 6 | L | 3 | 3 | north |
| 7 | F | 3 | 4 | north |

It ends at **column 3, row 4, facing north**.
:::

### Exercise 3: Write the route

The robot starts at column 1, row 1, facing north (`^`). Write the commands that get it to the desk `D` without driving through a table `#`.

```text
       1     2     3     4     5
    +-----+-----+-----+-----+-----+
  5 |     |     |     |     |  D  |
    +-----+-----+-----+-----+-----+
  4 |     |  #  |  #  |  #  |     |
    +-----+-----+-----+-----+-----+
  3 |     |     |     |  #  |     |
    +-----+-----+-----+-----+-----+
  2 |  #  |  #  |     |     |     |
    +-----+-----+-----+-----+-----+
  1 |  ^  |     |     |     |     |
    +-----+-----+-----+-----+-----+
```

:::hint
The robot can't go straight up: column 1, row 2 is a table. Look for a clear column that runs all the way from row 1 to row 5.
:::

:::solution
```text
R F F F F L F F F F
```

Turn right to face east, drive 4 squares along row 1 to column 5, turn left to face north, and drive 4 squares up column 5 to the desk. Check it by tracing: every square the robot enters, (2,1) through (5,1) and then (5,2) through (5,5), is free.

Other routes work too, such as turning north at column 3, going east along row 2, and then north up column 5 (R F F L F R F F L F F F). That one takes 12 commands instead of 10. Module 7 is about comparing different correct answers like these.
:::

### Exercise 4: Inputs and outputs

For each algorithm, name its inputs and its output:

1.  A vending machine selling a snack.
2.  A map app giving walking directions.
3.  A pancake recipe.
4.  A calculator adding two numbers.

:::hint
Inputs are what goes in before the algorithm can start (things you give it, or facts it needs). The output is what you get at the end.
:::

:::solution
| Algorithm | Inputs | Output |
| --- | --- | --- |
| Vending machine | Money, the button you press | A snack, and maybe change |
| Map app | Where you are, where you want to go, the map | A list of turns to follow |
| Pancake recipe | Flour, eggs, milk, a hot pan | Pancakes |
| Calculator | Two numbers | Their sum |

Notice that the map app needs the map itself as an input, even though you never type it in. Like the robot's starting state, some inputs are easy to forget because nobody hands them over.
:::

### Exercise 5: It works once

This script is supposed to move the cat right, then up, then say "Here!". It works the first time you click the flag. The second time, the cat ends up somewhere else.

```scratch
when green flag clicked
go to x: (-100) y: (-100)
move (100) steps
turn left (90) degrees
move (100) steps
say [Here!] for (2) seconds
```

Explain what goes wrong on the second run, using a state table. Then fix it.

:::hint
A brand-new cat starts facing right (direction 90). Which way is it facing at the *end* of the first run? That's how it starts the second run.
:::

:::solution
The first run starts facing right and ends facing **up**, because of the left turn. The second run begins from that state:

| Second run | x | y | Direction |
| --- | --- | --- | --- |
| go to | -100 | -100 | 0 (up, left over from run 1) |
| move 100 | -100 | 0 | 0 |
| turn left 90 | -100 | 0 | -90 (left) |
| move 100 | -200 | 0 | -90 |

The cat goes up and then left, ending at (-200, 0) instead of (0, 0). The script sets the starting *position* but not the starting *direction*. The fix is one block:

```scratch
when green flag clicked
go to x: (-100) y: (-100)
point in direction (90)
move (100) steps
turn left (90) degrees
move (100) steps
say [Here!] for (2) seconds
```
:::

### Exercise 6: Remote-control robot

Save your delivery robot as `m3-delivery-robot-v2.sb3`, then add four scripts so the arrow keys drive the robot one step at a time. Here's the first:

```scratch
when [right arrow v] key pressed
point in direction (90)
move (40) steps
```

Build the other three, then drive the robot to the laptop with the keys. Write down the keys you pressed, in order. Last question: in this version, who is following the algorithm?

:::hint
Each arrow needs its own `when [ v] key pressed` script with a different direction: up is 0, left is -90, and down is 180.
:::

:::solution
```scratch
when [up arrow v] key pressed
point in direction (0)
move (40) steps
```

```scratch
when [left arrow v] key pressed
point in direction (-90)
move (40) steps
```

```scratch
when [down arrow v] key pressed
point in direction (180)
move (40) steps
```

The program no longer contains a route. Each event script is one tiny, exact command, and **you** are choosing the order. The list of keys you wrote down is the algorithm, and you were the one following it. Games work like this: the program handles events, and the player supplies the sequence.
:::

### Challenge: Draw it blind

Sit back to back with a helper, each with grid paper and a pencil. Picture a simple house: a square for the walls, a triangle for the roof, and a door. Write instructions for drawing it without using the words "house", "roof", or "door". Your helper follows your instructions exactly, without looking at your paper and without asking questions. Then compare drawings, find each place they differ, and fix the instruction that caused it.

If you don't have a helper, write the instructions today and follow them yourself tomorrow, doing only what the words say.

:::hint
Give your helper a starting point they can find, like "the point where two grid lines cross, 3 squares up from the bottom edge and 3 in from the left edge." After that, describe every line with a direction and a length in squares.
:::

:::solution
```text
Start: the point where two grid lines cross, 3 squares up from the bottom edge
       of the paper and 3 squares in from the left edge.
1. Draw a line along the grid, 4 squares to the right.
2. From the end of that line, draw 4 squares straight up.
3. From there, draw 4 squares to the left.
4. From there, draw 4 squares straight down. You're back at the start.
5. Put your pencil on the top-left corner of the shape you drew. Draw a straight
   line to the point 2 squares to the right and 2 squares up from it.
6. From there, draw a straight line to the top-right corner of the shape.
7. Put your pencil on the bottom line, 1 square right of the start.
   Draw 2 squares up, 2 squares to the right, then 2 squares down.
```

Steps 5 and 7 are where most first drafts go wrong. "Draw a triangle on top" leaves the size, the height, and which way it points up to the reader. Every line needs a starting point, a direction, and a length.
:::
