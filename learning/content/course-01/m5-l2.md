:::objectives
- Save typed replies in variables with `ask` and `set`.
- Turn each library rule into its own check with a clear message.
- Use `or` to accept more than one spelling, and `not` to say "5 or more."
- Write a test table before testing, then use it to find and fix a real bug.
:::

## What we're building

The Maple Street library wants its kiosk rebuilt, and this time it has to explain itself. Here is a full conversation with the finished version:

```text
Kiosk: Welcome to Maple Street Library!
Kiosk: Is your library card active? (yes/no)
You:   y
Kiosk: Is this book marked REFERENCE? (yes/no)
You:   no
Kiosk: How many books do you have out right now?
You:   4
Kiosk: How much do you owe in fines? (dollars)
You:   2.50
Kiosk: Enjoy your book! It's due back in 3 weeks.
```

These are the head librarian's rules:

1. Your card must be active.
2. Reference books, like encyclopedias, never leave the building.
3. You may have at most 5 books out, so you can borrow only if you have 4 or fewer right now.
4. If you owe $5 or more in fines, pay them before borrowing.

The script checks them in that order. Each check either lets the person through to the next one or explains the problem and stops:

```mermaid caption="Four checks in a row; any failed check explains itself and stops"
flowchart LR
    A[Card] -->|ok| B[Reference]
    B -->|ok| C[Books out]
    C -->|ok| D[Fines]
    D -->|ok| E["Enjoy your book!"]
    A -.->|no| X["Explain and stop"]
    B -.->|no| X
    C -.->|no| X
    D -.->|no| X
```

You'll build one rule at a time and test each one as you go. At the end, a test table will catch a bug that none of the four rules mention.

## Step 1: Set up the project and ask the first question

1.  Go to [scratch.mit.edu](https://scratch.mit.edu) and click **Create**.
2.  The cat can be the kiosk, or hover over the **Choose a Sprite** button (bottom right of the sprite list) and pick something else.
3.  Click the orange **Variables** category, then **Make a Variable**. Make four variables, each **For all sprites**: `card`, `reference`, `books out`, and `fines`.

Now build this first script on the kiosk sprite:

```scratch
when green flag clicked
say [Welcome to Maple Street Library!] for (2) seconds
ask [Is your library card active? (yes/no)] and wait
set [card v] to (answer)
```

Click the green flag and type `yes`. The `card` monitor on the stage now shows `yes`.

Why copy `answer` into `card`? The light-blue `answer` block only remembers the most recent reply. By the end of this script you'll have asked four questions, and the first reply would be long gone. Copying each reply into its own variable keeps all four.

## Step 2: The card rule, with an early exit

Snap this under the `set` block:

```scratch
if <(card) = [yes]> then
  say [Card OK.] for (1) seconds
else
  say [Your card isn't active. Please see the front desk.] for (3) seconds
  stop [this script v]
end
```

`stop [this script v]` (in **Control**) ends the script on the spot. So a person with an inactive card never gets asked about fines, just like the decision tree in the Notes. Explain the problem, then stop.

Test it three ways. `yes` gives "Card OK." `no` sends you to the front desk. `YES` also works, because Scratch's `=` ignores capitals.

Now type `y`. The kiosk sends you to the front desk! Lots of people type `y` for yes, and the rule as written refuses them. Drag the `=` block out of the `if`, drop in an `or` block, and put one `=` block on each side:

```scratch
if <<(card) = [yes]> or <(card) = [y]>> then
  say [Card OK.] for (1) seconds
else
  say [Your card isn't active. Please see the front desk.] for (3) seconds
  stop [this script v]
end
```

Run it with `y` again. Card OK.

## Step 3: Reference books stay in the building

Add the second question and its check:

```scratch
ask [Is this book marked REFERENCE? (yes/no)] and wait
set [reference v] to (answer)
if <<(reference) = [yes]> or <(reference) = [y]>> then
  say [Reference books stay in the library, but you can read it here!] for (3) seconds
  stop [this script v]
end
```

There's no `else` this time. If the book isn't a reference book, there's nothing to say yet, so the script simply moves on to the next question. A plain `if` is the right block whenever one of the two paths is "do nothing."

## Step 4: The books-out limit

```scratch
ask [How many books do you have out right now?] and wait
set [books out v] to (answer)
if <(books out) > (4)> then
  say [You have the most books allowed (5). Please return one first.] for (3) seconds
  stop [this script v]
end
```

Why `> 4` and not `> 5`? The rule means "5 at most *after* borrowing," so someone who already has 5 must be refused. `> 4` refuses 5, 6, 7, and up, and lets 0 through 4 pass. That's Jada's bug from the Notes, fixed before it ever ships.

Test with 4 (you move on to the next question) and 5 (refused).

## Step 5: Fines, and saying "5 or more" without a ≥ block

The rule says $5 or more blocks borrowing. Scratch has `<`, `>`, and `=`, but no "greater than or equal to" block. You could write `<<(fines) > (5)> or <(fines) = (5)>>`, but there's a neater way: "5 or more" means the same as "not less than 5."

```scratch
ask [How much do you owe in fines? (dollars)] and wait
set [fines v] to (answer)
if <not <(fines) < (5)>> then
  say [You owe $5 or more. Please pay at the front desk first.] for (3) seconds
  stop [this script v]
end
say [Enjoy your book! It's due back in 3 weeks.] for (3) seconds
```

Read the condition out loud: "if not fines-less-than-5." With $4.99, `fines < 5` is true, `not` flips it to false, and the person passes. With exactly $5, `fines < 5` is false, `not` makes it true, and the kiosk refuses.

Why not reuse the `> 4` trick from Step 4? Because money has cents. A person owing $4.50 is under the limit, but 4.50 > 4 is true, so they'd be wrongly refused. The `> 4` trick only works for things you can't have half of, like books.

## Step 6: Write the test table, then run it

Before clicking anything else, write down what *should* happen. A test table has one row per test, and the Expected column gets filled in **before** you run a single test, so the program can't talk you into its answer.

| # | Card | Reference | Books out | Fines | Expected |
| --- | --- | --- | --- | --- | --- |
| 1 | yes | no | 0 | 0 | Enjoy your book |
| 2 | Y | no | 4 | 4.99 | Enjoy your book |
| 3 | yes | no | 5 | 0 | Return one first |
| 4 | yes | no | 2 | 5 | Pay fines first |
| 5 | no | | | | See the front desk |
| 6 | yes | yes | | | Stays in the library |
| 7 | yes | no | -3 | 0 | That number can't be right |
| 8 | yes | no | 2 | -10 | That number can't be right |

Tests 7 and 8 come from a question you took back to the librarian: "what should happen with a negative number?" Her answer: someone typing -3 has made a typo, so tell them and let them try again.

Now run all 8 in Scratch and write down what actually happens. Clicking the green flag eight times and typing four answers each time gets tedious, so here is the same kiosk in Python, a text language, running all 8 tests in a row. You don't need to read every line. `.lower()` turns text into lowercase first, which copies what Scratch's `=` does for free. Look at the output.

```python run title="kiosk_tests.py"
def kiosk(card, reference, books_out, fines):
    if card.lower() not in ("yes", "y"):
        return "See the front desk"
    if reference.lower() in ("yes", "y"):
        return "Stays in the library"
    if books_out > 4:
        return "Return one first"
    if not fines < 5:
        return "Pay fines first"
    return "Enjoy your book"

tests = [
    ("yes", "no", 0, 0, "Enjoy your book"),
    ("Y", "no", 4, 4.99, "Enjoy your book"),
    ("yes", "no", 5, 0, "Return one first"),
    ("yes", "no", 2, 5, "Pay fines first"),
    ("no", "no", 0, 0, "See the front desk"),
    ("yes", "yes", 0, 0, "Stays in the library"),
    ("yes", "no", -3, 0, "That number can't be right"),
    ("yes", "no", 2, -10, "That number can't be right"),
]

def run_tests():
    for number, (card, ref, books, fines, expected) in enumerate(tests, start=1):
        actual = kiosk(card, ref, books, fines)
        verdict = "PASS" if actual == expected else "FAIL"
        print(f"Test {number}: {verdict}   expected: {expected}   got: {actual}")

run_tests()
```

Tests 1 to 6 pass. Tests 7 and 8 fail: the kiosk happily lends a book to someone with -3 books out, because nothing in the script ever asked whether the number made sense. Your Scratch kiosk does exactly the same thing.

## Step 7: Fix the bug, then re-run every test

Add a sanity check right after each number comes in. This one goes straight after `set [books out v] to (answer)`:

```scratch
if <(books out) < (0)> then
  say [That number can't be right. Click the green flag to try again.] for (3) seconds
  stop [this script v]
end
```

Put a matching check after `set [fines v] to (answer)`, using `(fines)` instead. Then run **all eight** tests again, not just 7 and 8. A fix in one place can break something that used to work, and the only way to know it didn't is to check.

Here is the Python kiosk with the same two checks added, re-running the whole table:

```python run title="kiosk_tests.py (fixed)"
def kiosk(card, reference, books_out, fines):
    if card.lower() not in ("yes", "y"):
        return "See the front desk"
    if reference.lower() in ("yes", "y"):
        return "Stays in the library"
    if books_out < 0:
        return "That number can't be right"
    if books_out > 4:
        return "Return one first"
    if fines < 0:
        return "That number can't be right"
    if not fines < 5:
        return "Pay fines first"
    return "Enjoy your book"

run_tests()
```

All eight pass.

## The finished kiosk

```scratch title="Kiosk sprite"
when green flag clicked
say [Welcome to Maple Street Library!] for (2) seconds
ask [Is your library card active? (yes/no)] and wait
set [card v] to (answer)
if <<(card) = [yes]> or <(card) = [y]>> then
  say [Card OK.] for (1) seconds
else
  say [Your card isn't active. Please see the front desk.] for (3) seconds
  stop [this script v]
end
ask [Is this book marked REFERENCE? (yes/no)] and wait
set [reference v] to (answer)
if <<(reference) = [yes]> or <(reference) = [y]>> then
  say [Reference books stay in the library, but you can read it here!] for (3) seconds
  stop [this script v]
end
ask [How many books do you have out right now?] and wait
set [books out v] to (answer)
if <(books out) < (0)> then
  say [That number can't be right. Click the green flag to try again.] for (3) seconds
  stop [this script v]
end
if <(books out) > (4)> then
  say [You have the most books allowed (5). Please return one first.] for (3) seconds
  stop [this script v]
end
ask [How much do you owe in fines? (dollars)] and wait
set [fines v] to (answer)
if <(fines) < (0)> then
  say [That number can't be right. Click the green flag to try again.] for (3) seconds
  stop [this script v]
end
if <not <(fines) < (5)>> then
  say [You owe $5 or more. Please pay at the front desk first.] for (3) seconds
  stop [this script v]
end
say [Enjoy your book! It's due back in 3 weeks.] for (3) seconds
```

:::quiz
Q: Why does the kiosk copy `answer` into `books out` instead of just using `answer` in the later checks?
- [ ] `answer` can only hold words, not numbers
  `answer` holds whatever was typed, numbers included.
- [x] `answer` is replaced every time an `ask` block runs
  After the fines question, `answer` holds the fines, so the books-out reply would be lost. A variable keeps each reply safe.
- [ ] Variables make the script run faster
  Speed isn't the issue here; keeping each reply is.

Q: The books rule uses `<(books out) > (4)>`, but the fines rule uses `<not <(fines) < (5)>>`. Why not use `> 4` for fines too?
- [ ] `not` only works with money
  `not` works with any condition at all.
- [x] Fines can include cents, so someone owing $4.50 would be wrongly refused
  4.50 > 4 is true. The `> 4` shortcut only works for whole numbers, like a count of books.
- [ ] `> 4` would let someone owing exactly $5 borrow
  5 > 4 is true, so they'd be refused, which is correct. The problem is with amounts between 4 and 5.

Q: A friend suggests replacing the four checks with one big `and` block that only says "yes" or "no." What would the kiosk lose?
- [ ] Nothing, because the yes/no answers would be the same
  The yes/no answers could match, but something people need would disappear.
- [x] It could no longer tell people which rule stopped them
  With one combined condition there's only one "no" message, so nobody would know whether to renew a card, return a book, or pay a fine.
- [ ] It would let more people borrow
  Not if the combined condition is correct. The loss is the explanation, not the decision.
:::

:::takeaways
- Copy `answer` into a variable right away whenever a script asks more than one question.
- A run of separate checks that each explain the problem and `stop` keeps a decision tree flat and easy to read.
- `or` lets one rule accept several spellings; `not <() < (5)>` is how Scratch says "5 or more."
- Fill in the Expected column before you test, and re-run every test after every fix.
:::

## Ideas to extend it

- **Kids' cards:** readers under 13 may have only 3 books out. Ask for an age, `set` a `limit` variable to 3 or 5 with if/else, then compare `books out` to `(limit) - (1)`.
- **Accept more replies:** let `n` and `nope` count as no, and make the kiosk say "Please answer yes or no" for anything else.
- **Count checkouts:** add a `checkouts today` variable that goes up by 1 after each successful loan. Think about where to reset it (hint: not under the green flag).
