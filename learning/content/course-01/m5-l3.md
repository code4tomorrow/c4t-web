:::objectives
- Turn a written rule into the right mix of if/else, and, or, and not.
- Choose test values that sit on and around every boundary.
- Spot and fix overlapping conditions and rules that use the wrong operator.
- Order nested decisions so the most specific rule is checked first.
:::

Each exercise gives you a rule and asks you to build or fix a decision in Scratch. Write the plain-English steps on paper first, then build the script, then test it with values on both sides of every boundary. Try each one properly before you open the solution.

## Warm-up: true or false?

Say `x` is 7 and `y` is 10. Is each condition true or false?

```scratch
<(x) > (y)>
<(x) = (7)>
<<(x) < (y)> and <(y) < (10)>>
<<(x) > (8)> or <(y) = (10)>>
<not <(x) < (y)>>
```

:::solution
1. **false**: 7 is not more than 10.
2. **true**.
3. **false**: the left side is true, but 10 < 10 is false, and `and` needs both.
4. **true**: the left side is false, but `y = 10` is true, and `or` needs only one.
5. **false**: 7 < 10 is true, and `not` flips it.
:::

### Exercise 1: Movie ticket prices

A cinema charges $6 for kids under 12, $7 for people 65 and older, and $10 for everyone else. Build a script that asks for an age and says the price. Then test it with 11, 12, 30, 64, and 65.

```text
How old are you? 12
Your ticket is $10.
```

:::hint
Three possible prices means two decisions. Put the second if/else inside the `else` of the first one. And since ages are whole numbers, "65 and older" can be written as `> 64`.
:::

:::solution
```scratch
when green flag clicked
ask [How old are you?] and wait
if <(answer) < (12)> then
  say [Your ticket is $6.]
else
  if <(answer) > (64)> then
    say [Your ticket is $7.]
  else
    say [Your ticket is $10.]
  end
end
```

The tests: 11 → $6, 12 → $10, 30 → $10, 64 → $10, 65 → $7. Ages 12 and 65 are the edges, and they're exactly the ones a wrong `<` or `>` would get wrong. Each age lands on exactly one `say`, because every path through nested if/else blocks ends in exactly one place.
:::

### Exercise 2: Fix the roller coaster

The sign says: **riders must be at least 120 cm tall and at least 8 years old.** Someone built this:

```scratch
if <<(height) > (120)> or <(age) > (8)>> then
  say [Enjoy the ride!]
else
  say [Sorry, not this time.]
end
```

There are two different bugs. For each one, find a rider (a height and an age) who gets the wrong answer, then fix the script.

:::hint
Picture a rider who is tall but young, and run them through the condition. Then picture a rider who is *exactly* 120 cm and *exactly* 8.
:::

:::solution
**Bug 1: `or` should be `and`.** A rider who is 150 cm tall but only 5 years old gets "Enjoy the ride!", because one true side is enough for `or`. The sign says both must be true.

**Bug 2: `>` leaves out the limit.** A rider who is exactly 120 cm and exactly 8 is refused, because 120 > 120 is false. "At least" includes the limit.

The fix uses "not less than" for both checks, which is how Scratch says "at least" and also works for heights like 119.5 cm:

```scratch
if <<not <(height) < (120)>> and <not <(age) < (8)>>> then
  say [Enjoy the ride!]
else
  say [Sorry, not this time.]
end
```
:::

### Exercise 3: Why does everyone get a C?

This script is supposed to turn a test score into a letter grade: 90 and up is an A, 80 to 89 is a B, 70 to 79 is a C.

```scratch
when green flag clicked
ask [Score?] and wait
if <(answer) > (89)> then
  say [A]
end
if <(answer) > (79)> then
  say [B]
end
if <(answer) > (69)> then
  say [C]
end
```

Before you run it, predict what the sprite ends up saying for a score of 95. Then explain why, and fix it.

:::hint
Walk through the script with 95, one block at a time. How many of the three conditions are true? A `say` block with no time replaces whatever the sprite was saying a moment ago.
:::

:::solution
It ends up saying **C**. For 95, all three conditions are true, so all three `say` blocks run, one right after the other. Each one replaces the last, and C comes last. The conditions *overlap*: every score above 89 is also above 79 and above 69.

The fix is a chain of if/else blocks, so that once one grade matches, the rest are skipped:

```scratch
when green flag clicked
ask [Score?] and wait
if <(answer) > (89)> then
  say [A]
else
  if <(answer) > (79)> then
    say [B]
  else
    if <(answer) > (69)> then
      say [C]
    else
      say [Below C]
    end
  end
end
```

Test 90, 89, 80, 79, 70, and 69: each pair sits on either side of a boundary.
:::

### Exercise 4: A rock-paper-scissors judge

Two players type their moves into variables `you` and `friend` (each one is `rock`, `paper`, or `scissors`). Build a script that says who wins or that it's a tie. Before you build it, work out how many different games are possible and draw the decision on paper.

```text
you: paper   friend: rock   →   You win!
```

:::hint
There are 3 × 3 = 9 possible games. Handle the 3 ties with a single check first: `<(you) = (friend)>`. Of the 6 games left, exactly 3 are wins for you. What does "everything else" mean after that?
:::

:::solution
One clear way is to start with a default answer, then let each winning combination overwrite it:

```scratch
set [result v] to [Your friend wins!]
if <(you) = (friend)> then
  set [result v] to [It's a tie!]
end
if <<(you) = [rock]> and <(friend) = [scissors]>> then
  set [result v] to [You win!]
end
if <<(you) = [paper]> and <(friend) = [rock]>> then
  set [result v] to [You win!]
end
if <<(you) = [scissors]> and <(friend) = [paper]>> then
  set [result v] to [You win!]
end
say (result)
```

This is safe *only* because the four conditions never overlap: no single game is both a tie and a win. (Exercise 3 showed what happens when they do.)

With just 9 possible games, you can test every one of them. Here are the same rules in a text language, checked against all 9:

```python run title="judge.py"
def judge(you, friend):
    if you == friend:
        return "tie"
    if (you, friend) in [("rock", "scissors"), ("paper", "rock"), ("scissors", "paper")]:
        return "you win"
    return "friend wins"

moves = ["rock", "paper", "scissors"]
for you in moves:
    for friend in moves:
        print(f"{you:>8} vs {friend:<8} -> {judge(you, friend)}")
```

Across the 9 games there are 3 ties, 3 wins for you, and 3 wins for your friend, which is what a fair game should have.
:::

### Exercise 5: Password length edge cases

A website says: **passwords must be 8 to 12 characters long.** The `(length of (answer))` block in **Operators** reports how many characters were typed.

1. Write the condition that is true for a valid length.
2. List at least six test passwords with the result you expect, aimed at the edges.

:::hint
"8 to 12" includes both 8 and 12. A range check is two comparisons joined with `and`. For the tests, think: just below, on, and just above each end, plus one strange input.
:::

:::solution
```scratch
if <<(length of (answer)) > (7)> and <(length of (answer)) < (13)>> then
  say [Password accepted.]
else
  say [Passwords must be 8 to 12 characters.]
end
```

| Test password | Length | Expected | Why |
| --- | --- | --- | --- |
| `sunfish` | 7 | rejected | one below the bottom edge |
| `sunfish1` | 8 | accepted | exactly on the bottom edge |
| `sunfish1234` | 11 | accepted | comfortably inside |
| `sunfish12345` | 12 | accepted | exactly on the top edge |
| `sunfish123456` | 13 | rejected | one above the top edge |
| (blank) | 0 | rejected | nothing typed at all |
| eight spaces | 8 | accepted?! | follows the rule, but is it a good password? |

The last row is the kind of edge case that reveals a missing rule. The script does what the sign says, and the sign is probably wrong. That's a question for whoever owns the website.
:::

### Exercise 6: Leap years

Here are the real rules for leap years:

- A year divisible by 4 is a leap year,
- except a year divisible by 100 is **not**,
- except a year divisible by 400 **is**.

In Scratch, `<((year) mod (4)) = (0)>` is true when `year` divides evenly by 4. (`mod` gives the remainder after dividing, and a remainder of 0 means it divides evenly.) Build a script that asks for a year and says whether it's a leap year. Test 2024, 2023, 1900, 2000, and 2100.

:::hint
The rules are written from general to specific, but the script works best the other way round. Check the 400 rule first, then the 100 rule, then the 4 rule. Once a rule matches, you have your answer, so the rest belong in the `else`.
:::

:::solution
```scratch
when green flag clicked
ask [Which year?] and wait
if <((answer) mod (400)) = (0)> then
  say [Leap year!]
else
  if <((answer) mod (100)) = (0)> then
    say [Not a leap year.]
  else
    if <((answer) mod (4)) = (0)> then
      say [Leap year!]
    else
      say [Not a leap year.]
    end
  end
end
```

If you checked the 4 rule first, 1900 would be called a leap year, because 1900 divides evenly by 4 and the script would never reach the exceptions. Here is the same decision in a text language, run on all five test years (`%` is Python's way of writing `mod`):

```python run title="leap.py"
def is_leap(year):
    if year % 400 == 0:
        return True
    elif year % 100 == 0:
        return False
    elif year % 4 == 0:
        return True
    else:
        return False

for year in [2024, 2023, 1900, 2000, 2100]:
    print(year, "leap" if is_leap(year) else "not leap")
```

1900 and 2100 are the edge cases that trip most people up: divisible by 4 but not leap years.
:::

### Challenge: Kiosk 2.0

Add two new rules to the library kiosk you built:

1. Readers under 13 may have at most 3 books out. Everyone else may have 5.
2. During July (the summer reading program), fines don't stop anyone from borrowing.

`(current [month v])` in **Sensing** reports the month as a number from 1 to 12. Write your test table **first**: at least 10 rows, covering the edges of both new rules (ages 12 and 13, 2 and 3 books, June, July, and August).

:::hint
You can't wait until July to test the July rule. Make a `month` variable, `set` it from `(current [month v])`, and temporarily replace that with an `ask` while you're testing. Next module calls this a *test mode*.
:::

:::solution
One way: ask for the age first and `set [limit v]` to 3 or 5 with an if/else. Change the books check to `<(books out) > ((limit) - (1))>`. Then wrap the fines check in `if <not <(month) = (7)>> then … end`, so it only runs outside July. Your table should include a 12-year-old with 3 books (refused), a 13-year-old with 3 books (allowed), and someone owing $20 in July (allowed) and in August (refused).
:::

## A picture of "most specific first"

When rules have exceptions, and the exceptions have exceptions, draw them as a tree before you build. The leap-year rules look like this, with the most specific rule at the top:

```mermaid caption="Leap years: check the rarest rule first, so the exceptions are never skipped"
flowchart TD
    A{"Divisible by 400?"} -->|yes| L1["Leap year"]
    A -->|no| B{"Divisible by 100?"}
    B -->|yes| N1["Not a leap year"]
    B -->|no| C{"Divisible by 4?"}
    C -->|yes| L2["Leap year"]
    C -->|no| N2["Not a leap year"]
```

The same shape works for the kiosk challenge, ticket prices with discounts, or any rule that comes with an "except when…".
