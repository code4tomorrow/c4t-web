The school office has to make 300 name labels for the science fair. Taped to the label printer is this:

```text
Type "Aaliyah Brooks". Press Print. Peel off the label. Stick it on a badge.
Type "Ben Castillo". Press Print. Peel off the label. Stick it on a badge.
Type "Chloe Dang". Press Print. Peel off the label. Stick it on a badge.
...
```

Written out in full, that's 300 lines and 1,200 steps. Nobody reads 1,200 steps, and somebody would definitely skip line 147 by accident. Yet anyone can follow this one sentence: **"For each name on the list: type it, print, peel, and stick."** Spotting that pattern, and then writing it once, is what this module is about.

## Find the pattern first

Before you can shorten a list of steps, you need to see what's repeating. Look for two things:

1.  **The repeating unit**: the chunk of steps that happens again and again. For the labels, it's *type, print, peel, stick*.
2.  **The part that changes**: what's different each time through. For the labels, it's the name.

Sometimes nothing changes. Here are the moves that make a sprite trace a square:

```text
move 100, turn right 90, move 100, turn right 90,
move 100, turn right 90, move 100, turn right 90
```

The repeating unit is *move 100, turn right 90*, it happens 4 times, and nothing about it changes from one time to the next.

## A loop says "do this part again"

A **loop** is an instruction to run a group of steps more than once. Here's the square written the long way in Scratch, with eight blocks under the hat:

```scratch
when green flag clicked
move (100) steps
turn right (90) degrees
move (100) steps
turn right (90) degrees
move (100) steps
turn right (90) degrees
move (100) steps
turn right (90) degrees
```

And here it is with the orange `repeat` block from **Control**. The blocks inside the `repeat` are the repeating unit:

```scratch
when green flag clicked
repeat (4)
move (100) steps
turn right (90) degrees
end
```

Both scripts make the cat do exactly the same moves. The second one is shorter, but that's not the main reason to use it. Say you want each side to be 50 steps instead of 100. In the long version, you have to change four numbers and not miss one. In the loop version, you change one. Fewer copies means fewer places for a mistake to hide.

The blocks inside a loop are called its **body**. Each time the body runs is called a **pass** (or an *iteration*).

## Watch the part that changes

In the label job, the body is the same every pass, but the name it uses is different. Here's that loop in a text language. Step through it and watch `name` take a new value on every pass:

:::trace Three passes through the label loop
```python
names = ["Ava", "Ben", "Cai"]
for name in names:
    print("HELLO, my name is", name)
print("All labels printed.")
```
:::

The body (the `print` line, indented under the loop) is written once and runs three times. The last line isn't indented, so it isn't part of the body: it runs once, after the loop has finished. Scratch shows the same thing by which blocks sit inside the `repeat` jaws and which sit below it.

## Counting loops and condition-controlled loops

There are two kinds of "do it again", and real life uses both:

-   **Counting loops** run a set number of times. You know the number *before you start*: 4 sides of a square, 300 labels, 20 jumping jacks. In Scratch, that's `repeat (10)`.
-   **Condition-controlled loops** keep going until something becomes true. You *don't* know how many passes it will take: stir until the sugar dissolves, keep knocking until someone answers, print labels until the roll runs out. In Scratch, that's `repeat until < >`.

Here's a condition-controlled loop for the label printer:

```mermaid caption="A condition-controlled loop checks its question before every pass"
flowchart TD
    A[Load a new label roll] --> B{Is the roll empty?}
    B -->|no| C[Print one label]
    C --> B
    B -->|yes| D[Say 'Roll finished']
```

Nobody counts the labels on a roll first. The loop checks the question, does one pass, then checks again, and it stops the moment the answer is yes.

And here's one in Scratch. The cat walks until it reaches the edge of the stage:

```scratch
when green flag clicked
go to x: (0) y: (0)
point in direction (90)
repeat until <touching (edge v)?>
move (5) steps
end
say [Wall!] for (2) seconds
```

How many passes does that take? It depends on where the cat starts and how big it is, and the loop doesn't need to know. That's the giveaway: **if you'd have to guess the number, use a condition.**

Scratch also has `forever`, a loop that never stops on its own. Games use it to keep checking the keyboard for as long as the game runs. You'll stop a `forever` loop with the red stop sign.

## Inside the loop or outside it?

Every step in a looped task belongs in one of three places, and the rule is simple:

-   **Before the loop:** steps that happen once, to get ready. *Turn on the printer.*
-   **Inside the loop:** steps that happen once per pass. *Type, print, peel, stick.*
-   **After the loop:** steps that happen once, at the end. *Turn off the printer.*

Put a step in the wrong place and the program still runs; it just does the wrong thing. This script means to say "Done!" when the square is finished:

```scratch
when green flag clicked
repeat (4)
move (100) steps
turn right (90) degrees
say [Done!] for (1) seconds
end
```

The cat says "Done!" four times, once after every side, because the `say` block is inside the jaws of the `repeat`. Drag it out and snap it *under* the loop, and it runs once, after the fourth pass.

## Mistakes to watch for

:::warning
**A condition that can never become true.** This loop is meant to count down the labels left on a roll:

```scratch
repeat until <(labels left) = (0)>
change [labels left v] by (1)
end
```

It adds 1 instead of taking 1 away, so `labels left` grows forever and never reaches 0. The loop never ends, and nothing after it ever runs. If a script seems frozen, look at the loop's condition and ask: does anything inside the body move it closer to being true? Click the red stop sign to end it, then change `1` to `-1`.
:::

:::warning
**Off by one.** A loop that draws a triangle needs `repeat (3)`. A loop for 300 labels needs `repeat (300)`. It's easy to type one more or one fewer, especially when counting fence posts versus the gaps between them. Check the count against a small example you can do by hand: does a 3-label version print 3?
:::

The first and last quiz questions are about these two scripts.

Script A:

```scratch
when green flag clicked
repeat (3)
say [Hip!] for (1) seconds
end
say [Hooray!] for (1) seconds
```

Script B:

```scratch
when green flag clicked
repeat until <touching (edge v)?>
move (0) steps
end
say [Made it!] for (2) seconds
```

:::quiz
Q: In Script A, what does the cat say, and how many times?
- [ ] "Hip!" 3 times and "Hooray!" 3 times
  "Hooray!" is below the loop, not inside it, so it isn't part of the body.
- [x] "Hip!" 3 times, then "Hooray!" once
  The body is just the "Hip!" block, so it runs 3 times. The block after the loop runs once, when the loop is done.
- [ ] "Hip!" once, then "Hooray!" once
  That would be true without the loop. `repeat (3)` runs its body three times.

Q: Which of these jobs needs a **condition-controlled** loop?
- [ ] Do 20 jumping jacks
  You know the count before you start, so a counting loop fits.
- [ ] Print a label for each of 300 students
  The number of students is known, so this is a counting loop (one pass per name).
- [x] Keep knocking until someone opens the door
  You can't know in advance how many knocks it'll take. The loop stops when a condition becomes true.

Q: In the label-printing loop, where does "Turn on the printer" belong?
- [x] Before the loop
  It only needs to happen once, before any labels are printed.
- [ ] Inside the loop
  Then the printer would get switched on 300 times, once for every label.
- [ ] After the loop
  Then it would happen after all the printing, which is too late.

Q: Script B freezes, and the cat never says "Made it!". Why?
- [ ] `repeat until` loops always run forever
  They stop as soon as their condition becomes true. The trouble is this one's condition can't.
- [x] The cat never moves, so it never touches the edge
  Moving 0 steps changes nothing, so every pass checks the same condition with the same answer. Nothing in the body moves it toward being true.
- [ ] Scratch can't check for the edge inside a loop
  It can; the cat-walks-to-the-wall example in this lesson does exactly that.
:::

:::takeaways
- To shorten repeated steps, find the repeating unit and the part that changes.
- A loop writes the body once and runs it many times. Fewer copies means fewer places for mistakes.
- Use a counting loop when you know the number of passes, and a condition-controlled loop when you don't.
- Steps that happen once go before or after the loop; steps that happen every pass go inside.
- A condition-controlled loop needs something in its body that moves it toward stopping.
:::
