Clicking through your app proves it works today. Later you'll change the ratings query, or rename a field for the page, and something that worked will quietly break. A test suite is how you find out in two seconds instead of in front of your audience. It's also the strongest evidence on the rubric: "here are 13 rules, and here they are passing" is more convincing than any demo.

## From route table to test plan

Your planning lesson ended with a route table. Every row becomes at least one test for the success case and one for each failure listed. Here is the book club's, condensed:

| Rule | Test | Expect |
| --- | --- | --- |
| Usernames are unique and well-formed | sign up as `ana` again; sign up as `Ana!` | 409, 422 |
| Wrong password is refused | log in with the wrong password | 401 |
| Logout ends the token | log out, then use the old token | 204, then 401 |
| Adding a book needs a token | `POST /api/books` with no header | 401 |
| A new book has no ratings | add a book, read `avg_rating` | `null`, 0 reviews |
| No duplicate books | add the same title and author twice | 409 |
| Only the adder can delete; reviews go too | Ben deletes Ana's book, then Ana does | 403, then 204, then 404 and 0 reviews left |
| Reviews change the average | ratings 5 and 4 | 4.5 |
| One review per person per book | review the same book twice | 409 |
| Ratings are 1 to 5 | ratings 0 and 6 | 422 each |
| Can't review a missing book | review book 999 | 404 |
| Only the author edits or deletes a review | Ben edits, Ben deletes, Ana edits | 403, 403, 200 with rating kept |
| Errors explain themselves | `GET /api/books/999` | `{"detail": "No book with that id"}` |

```python run title="bookclub/main.py"
import hashlib
import hmac
import secrets
import sqlite3
from pathlib import Path

from fastapi import Depends, FastAPI, Header, HTTPException, Response, status
from fastapi.staticfiles import StaticFiles
from pydantic import BaseModel, ConfigDict, Field

DB_PATH = "bookclub.db"

SCHEMA = """
CREATE TABLE IF NOT EXISTS users (
    id            INTEGER PRIMARY KEY,
    username      TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL
);
CREATE TABLE IF NOT EXISTS tokens (
    token_hash TEXT PRIMARY KEY,
    user_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE TABLE IF NOT EXISTS books (
    id       INTEGER PRIMARY KEY,
    title    TEXT NOT NULL CHECK (length(title) BETWEEN 1 AND 200),
    author   TEXT NOT NULL CHECK (length(author) BETWEEN 1 AND 100),
    added_by INTEGER NOT NULL REFERENCES users(id),
    UNIQUE (title, author)
);
CREATE TABLE IF NOT EXISTS reviews (
    id         INTEGER PRIMARY KEY,
    book_id    INTEGER NOT NULL REFERENCES books(id) ON DELETE CASCADE,
    user_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    rating     INTEGER NOT NULL CHECK (rating BETWEEN 1 AND 5),
    comment    TEXT NOT NULL DEFAULT '',
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    UNIQUE (book_id, user_id)
);
CREATE INDEX IF NOT EXISTS reviews_by_book ON reviews (book_id);
"""


def init_db(path=DB_PATH):
    with sqlite3.connect(path) as conn:
        conn.executescript(SCHEMA)


def get_db():
    conn = sqlite3.connect(DB_PATH, check_same_thread=False)
    conn.row_factory = sqlite3.Row
    conn.execute("PRAGMA foreign_keys = ON")
    try:
        yield conn
    finally:
        conn.close()


# ---------- passwords and tokens ----------
SCRYPT = dict(n=2**14, r=8, p=1)


def hash_password(password: str) -> str:
    salt = secrets.token_bytes(16)
    digest = hashlib.scrypt(password.encode(), salt=salt, **SCRYPT)
    return f"scrypt${salt.hex()}${digest.hex()}"


def verify_password(password: str, stored: str) -> bool:
    _, salt_hex, digest_hex = stored.split("$")
    digest = hashlib.scrypt(password.encode(), salt=bytes.fromhex(salt_hex), **SCRYPT)
    return hmac.compare_digest(digest.hex(), digest_hex)


def token_hash(token: str) -> str:
    return hashlib.sha256(token.encode()).hexdigest()


def current_user(
    authorization: str = Header(default=""), db: sqlite3.Connection = Depends(get_db)
) -> dict:
    scheme, _, token = authorization.partition(" ")
    row = None
    if scheme.lower() == "bearer" and token:
        row = db.execute(
            """SELECT users.id, users.username FROM tokens
               JOIN users ON users.id = tokens.user_id
               WHERE tokens.token_hash = ?""",
            (token_hash(token),),
        ).fetchone()
    if row is None:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "Missing or invalid token",
                            headers={"WWW-Authenticate": "Bearer"})
    return dict(row)


# ---------- models ----------
class Credentials(BaseModel):
    model_config = ConfigDict(extra="forbid")
    username: str = Field(min_length=3, max_length=20, pattern=r"^[a-z0-9_]+$")
    password: str = Field(min_length=8, max_length=128)


class BookIn(BaseModel):
    model_config = ConfigDict(extra="forbid", str_strip_whitespace=True)
    title: str = Field(min_length=1, max_length=200)
    author: str = Field(min_length=1, max_length=100)


class BookSummary(BaseModel):
    id: int
    title: str
    author: str
    added_by: str
    review_count: int
    avg_rating: float | None


init_db()
app = FastAPI(title="Book Club API")


# ---------- accounts ----------
@app.post("/api/signup", status_code=status.HTTP_201_CREATED)
def signup(creds: Credentials, db: sqlite3.Connection = Depends(get_db)):
    try:
        with db:
            db.execute("INSERT INTO users (username, password_hash) VALUES (?, ?)",
                       (creds.username, hash_password(creds.password)))
    except sqlite3.IntegrityError:
        raise HTTPException(status.HTTP_409_CONFLICT, "That username is taken")
    return {"username": creds.username}


@app.post("/api/login")
def login(creds: Credentials, db: sqlite3.Connection = Depends(get_db)):
    user = db.execute("SELECT id, password_hash FROM users WHERE username = ?",
                      (creds.username,)).fetchone()
    if user is None or not verify_password(creds.password, user["password_hash"]):
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "Wrong username or password")
    token = secrets.token_urlsafe(32)
    with db:
        db.execute("INSERT INTO tokens (token_hash, user_id) VALUES (?, ?)",
                   (token_hash(token), user["id"]))
    return {"token": token, "token_type": "bearer"}


# ---------- books ----------
BOOK_SUMMARY_SQL = """
    SELECT books.id, books.title, books.author, users.username AS added_by,
           COUNT(reviews.id) AS review_count,
           ROUND(AVG(reviews.rating), 1) AS avg_rating
    FROM books
    JOIN users ON users.id = books.added_by
    LEFT JOIN reviews ON reviews.book_id = books.id
"""


def find_book(db, book_id):
    row = db.execute(BOOK_SUMMARY_SQL + " WHERE books.id = ? GROUP BY books.id", (book_id,)).fetchone()
    if row is None:
        raise HTTPException(status.HTTP_404_NOT_FOUND, "No book with that id")
    return dict(row)


@app.get("/api/books", response_model=list[BookSummary])
def list_books(db: sqlite3.Connection = Depends(get_db)):
    rows = db.execute(BOOK_SUMMARY_SQL + " GROUP BY books.id ORDER BY books.title")
    return [dict(row) for row in rows]


@app.post("/api/books", status_code=status.HTTP_201_CREATED, response_model=BookSummary)
def add_book(book: BookIn, user: dict = Depends(current_user),
             db: sqlite3.Connection = Depends(get_db)):
    try:
        with db:
            cur = db.execute("INSERT INTO books (title, author, added_by) VALUES (?, ?, ?)",
                             (book.title, book.author, user["id"]))
    except sqlite3.IntegrityError:
        raise HTTPException(status.HTTP_409_CONFLICT, "That book is already on the list")
    return find_book(db, cur.lastrowid)


class ReviewIn(BaseModel):
    model_config = ConfigDict(extra="forbid")
    rating: int = Field(ge=1, le=5)
    comment: str = Field(default="", max_length=1000)


class ReviewOut(BaseModel):
    id: int
    book_id: int
    username: str
    rating: int
    comment: str
    created_at: str


class BookDetail(BookSummary):
    reviews: list[ReviewOut]


def find_review(db, review_id):
    row = db.execute(
        """SELECT reviews.id, reviews.book_id, reviews.user_id, users.username,
                  reviews.rating, reviews.comment, reviews.created_at
           FROM reviews JOIN users ON users.id = reviews.user_id
           WHERE reviews.id = ?""",
        (review_id,),
    ).fetchone()
    if row is None:
        raise HTTPException(status.HTTP_404_NOT_FOUND, "No review with that id")
    return dict(row)


@app.get("/api/books/{book_id}", response_model=BookDetail)
def book_detail(book_id: int, db: sqlite3.Connection = Depends(get_db)):
    book = find_book(db, book_id)
    rows = db.execute(
        """SELECT reviews.id, reviews.book_id, users.username, reviews.rating,
                  reviews.comment, reviews.created_at
           FROM reviews JOIN users ON users.id = reviews.user_id
           WHERE reviews.book_id = ?
           ORDER BY reviews.created_at DESC, reviews.id DESC""",
        (book_id,),
    )
    return {**book, "reviews": [dict(r) for r in rows]}


@app.post("/api/books/{book_id}/reviews", status_code=status.HTTP_201_CREATED,
          response_model=ReviewOut)
def add_review(book_id: int, review: ReviewIn, user: dict = Depends(current_user),
               db: sqlite3.Connection = Depends(get_db)):
    find_book(db, book_id)
    try:
        with db:
            cur = db.execute(
                "INSERT INTO reviews (book_id, user_id, rating, comment) VALUES (?, ?, ?, ?)",
                (book_id, user["id"], review.rating, review.comment),
            )
    except sqlite3.IntegrityError:
        raise HTTPException(status.HTTP_409_CONFLICT,
                            "You already reviewed this book. Edit that review instead.")
    return find_review(db, cur.lastrowid)


class ReviewPatch(BaseModel):
    model_config = ConfigDict(extra="forbid")
    rating: int | None = Field(default=None, ge=1, le=5)
    comment: str | None = Field(default=None, max_length=1000)


def own_review(db, review_id, user):
    review = find_review(db, review_id)
    if review["user_id"] != user["id"]:
        raise HTTPException(status.HTTP_403_FORBIDDEN, "You can only change your own reviews")
    return review


@app.patch("/api/reviews/{review_id}", response_model=ReviewOut)
def edit_review(review_id: int, patch: ReviewPatch, user: dict = Depends(current_user),
                db: sqlite3.Connection = Depends(get_db)):
    own_review(db, review_id, user)
    with db:
        db.execute(
            "UPDATE reviews SET rating = COALESCE(?, rating), comment = COALESCE(?, comment) "
            "WHERE id = ?",
            (patch.rating, patch.comment, review_id),
        )
    return find_review(db, review_id)


@app.delete("/api/reviews/{review_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_review(review_id: int, user: dict = Depends(current_user),
                  db: sqlite3.Connection = Depends(get_db)):
    own_review(db, review_id, user)
    with db:
        db.execute("DELETE FROM reviews WHERE id = ?", (review_id,))
    return Response(status_code=status.HTTP_204_NO_CONTENT)


@app.delete("/api/books/{book_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_book(book_id: int, user: dict = Depends(current_user),
                db: sqlite3.Connection = Depends(get_db)):
    row = db.execute("SELECT added_by FROM books WHERE id = ?", (book_id,)).fetchone()
    if row is None:
        raise HTTPException(status.HTTP_404_NOT_FOUND, "No book with that id")
    if row["added_by"] != user["id"]:
        raise HTTPException(status.HTTP_403_FORBIDDEN, "Only the person who added a book can remove it")
    with db:
        db.execute("DELETE FROM books WHERE id = ?", (book_id,))
    return Response(status_code=status.HTTP_204_NO_CONTENT)


@app.post("/api/logout", status_code=status.HTTP_204_NO_CONTENT)
def logout(authorization: str = Header(default=""), user: dict = Depends(current_user),
           db: sqlite3.Connection = Depends(get_db)):
    token = authorization.partition(" ")[2]
    with db:
        db.execute("DELETE FROM tokens WHERE token_hash = ?", (token_hash(token),))
    return Response(status_code=status.HTTP_204_NO_CONTENT)


Path("static").mkdir(exist_ok=True)
app.mount("/", StaticFiles(directory="static", html=True), name="static")
```

## The test file

Three choices keep this suite fast and trustworthy:

1. **A separate database.** `app.dependency_overrides[get_db]` points every route at `test_bookclub.db`. The override turns on foreign keys exactly like the real `get_db`; if it didn't, the cascade test would fail for a reason that has nothing to do with your app.
2. **Accounts once, data every time.** Hashing passwords is slow on purpose, so `setUpClass` creates Ana and Ben once. `setUp` empties books and reviews before every test, so no test depends on another's leftovers or on running in a particular order.
3. **A helper that explains failures.** `expect(response, status)` passes `response.text` as the assertion message, so a failure prints the server's `detail` instead of just `500 != 201`.

```python run title="bookclub/test_main.py"
# In your project this file starts with:
# from main import app, get_db, init_db
import os
import sqlite3
import sys
import unittest
from fastapi.testclient import TestClient

TEST_DB = "test_bookclub.db"


def get_test_db():
    conn = sqlite3.connect(TEST_DB, check_same_thread=False)
    conn.row_factory = sqlite3.Row
    conn.execute("PRAGMA foreign_keys = ON")  # same setup as the real get_db
    try:
        yield conn
    finally:
        conn.close()


client = TestClient(app)


def log_in(name, password):
    r = client.post("/api/login", json={"username": name, "password": password})
    return {"Authorization": f"Bearer {r.json()['token']}"}


class BookClubTests(unittest.TestCase):
    @classmethod
    def setUpClass(cls):
        if os.path.exists(TEST_DB):
            os.remove(TEST_DB)
        init_db(TEST_DB)
        app.dependency_overrides[get_db] = get_test_db
        for name in ["ana", "ben"]:
            client.post("/api/signup", json={"username": name, "password": "correct horse"})
        cls.ana = log_in("ana", "correct horse")
        cls.ben = log_in("ben", "correct horse")

    @classmethod
    def tearDownClass(cls):
        app.dependency_overrides.clear()

    def setUp(self):
        with sqlite3.connect(TEST_DB) as conn:
            conn.execute("DELETE FROM reviews")
            conn.execute("DELETE FROM books")

    # ---------- helpers ----------
    def expect(self, response, status):
        self.assertEqual(response.status_code, status, response.text)
        return response.json() if response.content else None

    def add_book(self, who, title="Piranesi", author="Susanna Clarke"):
        r = client.post("/api/books", json={"title": title, "author": author}, headers=who)
        return self.expect(r, 201)

    def review(self, who, book_id, rating, comment=""):
        return client.post(f"/api/books/{book_id}/reviews",
                           json={"rating": rating, "comment": comment}, headers=who)

    # ---------- accounts ----------
    def test_signup_rejects_taken_and_badly_formed_names(self):
        self.expect(client.post("/api/signup", json={"username": "ana", "password": "another pass"}), 409)
        self.expect(client.post("/api/signup", json={"username": "Ana!", "password": "another pass"}), 422)

    def test_wrong_password_is_401(self):
        self.expect(client.post("/api/login", json={"username": "ana", "password": "not the one"}), 401)

    def test_logout_makes_the_token_useless(self):
        temp = log_in("ana", "correct horse")
        self.expect(client.post("/api/logout", headers=temp), 204)
        r = client.post("/api/books", json={"title": "Dune", "author": "Frank Herbert"}, headers=temp)
        self.expect(r, 401)

    # ---------- books ----------
    def test_adding_a_book_needs_a_token(self):
        self.expect(client.post("/api/books", json={"title": "Dune", "author": "Frank Herbert"}), 401)

    def test_new_book_has_no_ratings_yet(self):
        book = self.add_book(self.ana)
        self.assertEqual((book["review_count"], book["avg_rating"], book["added_by"]), (0, None, "ana"))

    def test_same_book_twice_is_409(self):
        self.add_book(self.ana)
        r = client.post("/api/books", json={"title": "Piranesi", "author": "Susanna Clarke"}, headers=self.ben)
        self.expect(r, 409)

    def test_only_the_adder_can_delete_and_reviews_go_too(self):
        book = self.add_book(self.ana)
        self.review(self.ben, book["id"], 4)
        self.expect(client.delete(f"/api/books/{book['id']}", headers=self.ben), 403)
        self.expect(client.delete(f"/api/books/{book['id']}", headers=self.ana), 204)
        self.expect(client.get(f"/api/books/{book['id']}"), 404)
        with sqlite3.connect(TEST_DB) as conn:
            self.assertEqual(conn.execute("SELECT COUNT(*) FROM reviews").fetchone()[0], 0)

    # ---------- reviews ----------
    def test_reviews_update_the_average(self):
        book = self.add_book(self.ana)
        self.expect(self.review(self.ana, book["id"], 5), 201)
        self.expect(self.review(self.ben, book["id"], 4), 201)
        detail = self.expect(client.get(f"/api/books/{book['id']}"), 200)
        self.assertEqual((detail["review_count"], detail["avg_rating"]), (2, 4.5))

    def test_second_review_by_same_person_is_409(self):
        book = self.add_book(self.ana)
        self.review(self.ana, book["id"], 5)
        self.expect(self.review(self.ana, book["id"], 2), 409)

    def test_rating_must_be_1_to_5(self):
        book = self.add_book(self.ana)
        for bad in [0, 6]:
            with self.subTest(rating=bad):
                self.expect(self.review(self.ana, book["id"], bad), 422)

    def test_review_of_missing_book_is_404(self):
        self.expect(self.review(self.ana, 999, 3), 404)

    def test_only_the_author_can_edit_or_delete_a_review(self):
        book = self.add_book(self.ana)
        review = self.expect(self.review(self.ana, book["id"], 5, "Loved it"), 201)
        url = f"/api/reviews/{review['id']}"
        self.expect(client.patch(url, json={"rating": 1}, headers=self.ben), 403)
        self.expect(client.delete(url, headers=self.ben), 403)
        edited = self.expect(client.patch(url, json={"comment": "Loved it twice"}, headers=self.ana), 200)
        self.assertEqual((edited["rating"], edited["comment"]), (5, "Loved it twice"))

    def test_errors_explain_themselves(self):
        body = self.expect(client.get("/api/books/999"), 404)
        self.assertEqual(body, {"detail": "No book with that id"})


suite = unittest.defaultTestLoader.loadTestsFromTestCase(BookClubTests)
unittest.TextTestRunner(stream=sys.stdout, verbosity=2).run(suite)
```

## Polish: the last 20 percent people notice

Work through this list after the tests pass. Re-run the tests after each change.

- **Empty states.** A brand-new club has no books. The page should say "No books yet. Add the first one." rather than showing nothing.
- **Error messages a person can act on.** Read every `detail` your API can send. "That book is already on the list" helps; "IntegrityError" doesn't.
- **Disable buttons while waiting.** Set `button.disabled = true` before a `fetch` and back to `false` in a `finally`, so a double-click doesn't post a review twice. (The `UNIQUE` rule would catch it anyway, but the user would see a confusing 409.)
- **`/docs` that explains itself.** Give the app a description and each route a summary; FastAPI puts both on the `/docs` page.
- **A clean repository.** Add `bookclub.db` and `test_bookclub.db` to `.gitignore`. A database file in Git is a privacy leak waiting to happen, and every teammate's copy will conflict.

## Present it in three minutes

A good demo tells a short story. Rehearse it once with a timer, on a fresh database, so nothing surprising is left over from testing.

1. **The problem** (20 seconds): who would use this, and what's annoying without it.
2. **The happy path** (60 seconds): sign up, add a book, review it, show the average change.
3. **A rule holding** (40 seconds): log in as a second user and try to edit the first user's review. Show the 403 message on the page, then the same request in the Network tab.
4. **The tests** (30 seconds): run `python -m unittest -v` and let the list of passing rules scroll by.
5. **One decision and one regret** (30 seconds): a design choice you'd defend, and something you'd do differently with more time.

## The rubric

Score yourself honestly before anyone else does. "Solid" in every row is a strong project.

| Area | Excellent (4) | Solid (3) | Developing (2) |
| --- | --- | --- | --- |
| Data model | 3+ normalized tables; keys, `UNIQUE`, `CHECK`, and cascades enforce the rules | Related tables with foreign keys; some rules only in code | Repeated data or missing keys |
| API design | Consistent REST paths, correct status for every case, `response_model` on outputs | Correct CRUD with mostly right statuses | Wrong methods or 200 for errors |
| Validation and errors | Every input has limits; every failure has a clear `detail`; no tracebacks reach the client | Most inputs validated; most errors explained | Some routes crash with 500 on bad input |
| Security | Hashed passwords, hashed tokens, logout, ownership checked on every write, parameterized SQL everywhere | Hashed passwords, tokens, ownership on edits | Ownership missing somewhere, or any SQL built from strings |
| Front end | Every action works; errors and empty states shown; `textContent` for user data | Main actions work and errors show | Errors hidden or the page breaks on failure |
| Tests | A test for every row of the route table, on a separate database, all passing | Success and main failure cases tested | A few happy-path tests only |
| Docs and demo | README a stranger could follow; demo shows a rule holding and the tests | README and working demo | Missing README or demo depends on luck |


The natural next step is FastAPI's own SQL tutorial, which rebuilds what you did with `sqlite3` using SQLModel, and its security tutorial, which replaces hand-made tokens with the OAuth2 password flow. You'll recognize every idea, because you've already built each one by hand.

:::takeaways
- Each row of the route table becomes tests: one for success, one for every failure code.
- Point tests at their own database with `dependency_overrides`, set up slow things once, and reset data before every test.
- Make assertion messages show the server's response, so failures explain themselves.
- Polish means empty states, actionable messages, `/docs` descriptions, a README, and a `.gitignore` for database files.
- A demo should show a rule holding and the tests passing, not only the happy path.
:::
