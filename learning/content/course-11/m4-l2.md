## Step 1: Models and storage

The contract has three shapes, so the code has three models. **NoteIn** is what a client sends to create a note. **NoteUpdate** is what it sends to change one: every field is optional. **Note** is what the API sends back, and it's the only one with an `id`, because the server assigns ids.

```python run title="main.py (step 1)"
from itertools import count
from typing import Annotated

from fastapi import FastAPI, HTTPException, Query, status
from fastapi.testclient import TestClient
from pydantic import BaseModel, Field

app = FastAPI(title="Notes API")


class NoteIn(BaseModel):
    title: str = Field(min_length=1, max_length=100)
    body: str = Field(default="", max_length=2000)


class NoteUpdate(BaseModel):
    title: str | None = Field(default=None, min_length=1, max_length=100)
    body: str | None = Field(default=None, max_length=2000)


class Note(BaseModel):
    id: int
    title: str
    body: str


notes: list[Note] = []
ids = count(1)


def find_note(note_id: int) -> Note:
    for note in notes:
        if note.id == note_id:
            return note
    raise HTTPException(status.HTTP_404_NOT_FOUND, f"Note {note_id} not found")


demo = count(1)
print(next(demo), next(demo), next(demo))
print(NoteUpdate(body="new text"))
```

`notes` is a plain list, so every note disappears when the server stops. That's fine for now; Module 5 replaces it with a database. `ids = count(1)` is a counter from `itertools`: each `next(ids)` hands out the next number, and nothing ever hands one back, which is exactly the "never reuse ids" rule.

`find_note` **raises** instead of returning `None`. Every route that needs a note calls it, so a missing note gives the same 404 with the same message everywhere, and no route can forget the check.

## Step 2: Create and list

```python run title="main.py (step 2)"
@app.post("/notes", status_code=status.HTTP_201_CREATED)
def create_note(note_in: NoteIn) -> Note:
    note = Note(id=next(ids), **note_in.model_dump())
    notes.append(note)
    return note


@app.get("/notes")
def list_notes(
    q: str = "",
    limit: Annotated[int, Query(ge=1, le=100)] = 20,
    offset: Annotated[int, Query(ge=0)] = 0,
) -> list[Note]:
    text = q.lower()
    matches = [n for n in notes if text in n.title.lower() or text in n.body.lower()]
    return matches[offset : offset + limit]


client = TestClient(app)
print(client.post("/notes", json={"title": "Buy milk", "body": "2 cartons"}).json())
print(client.post("/notes", json={"title": "Essay outline"}).json())
print(client.get("/notes?q=milk").json())
print(client.get("/notes?limit=0").status_code)
```

`Note(id=next(ids), **note_in.model_dump())` builds the stored note from validated fields plus a server-made id, the same habit as the mock. `[offset : offset + limit]` does the paging, and the `Query` rules handle the 422 for `limit=0` without a line of your own code.

```python run title="main.py (step 3)"
for url in ["/notes/1", "/notes/99", "/notes/abc"]:

```

One line of function body, three behaviors: 200 from the helper, 404 raised by the helper, and 422 from the `int` hint before the function runs.

## Step 4: Update part of a note

PATCH should change only what the client sends. Fields the client leaves out arrive in `NoteUpdate` as `None`, so `model_dump(exclude_none=True)` gives just the fields that were sent:

```python run title="main.py (step 4)"
@app.patch("/notes/{note_id}")
def update_note(note_id: int, changes: NoteUpdate) -> Note:
    note = find_note(note_id)
    for field, value in changes.model_dump(exclude_none=True).items():
        setattr(note, field, value)
    return note


print(NoteUpdate(body="3 cartons").model_dump(exclude_none=True))
print(client.patch("/notes/1", json={"body": "3 cartons"}).json())
print(client.patch("/notes/1", json={"title": ""}).status_code)
print(client.patch("/notes/42", json={"body": "x"}).json())
```

The first line shows the trick: only `body` survives. `setattr(note, field, value)` then changes that one attribute on the stored note. Since `notes` holds that same object, the change is saved. An empty title still gets a 422, because `NoteUpdate` keeps the same rules for any field that **is** sent.

:::note
With this design, `{"title": null}` is treated as "leave the title alone." That's a reasonable rule for this API, since a note can't have no title. An API where `null` means "clear this field" would use `exclude_unset=True` instead, which keeps fields the client sent even when they're `null`.
:::

## Step 5: Delete

```python run title="main.py (step 5)"
@app.delete("/notes/{note_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_note(note_id: int) -> None:
    notes.remove(find_note(note_id))


first = client.delete("/notes/1")
print(first.status_code, repr(first.text))
print(client.delete("/notes/1").status_code)
print([note["id"] for note in client.get("/notes").json()])
```

`204` means "done, no body", so the function returns nothing and the response text is empty. The second delete gets a 404 from the helper. DELETE is still idempotent: note 1 is gone either way.

## Step 6: Run it for real

Put Steps 1 to 5 together in `notes-api/main.py` (the full file is below), leaving out the `client` and `print` lines, which are only for this page. Then, in your server terminal:

```bash
cd notes-api
fastapi dev main.py
```

Now send requests from your second terminal. A JSON body is easiest to send from a file, because then the quoting is the same on every system. Save `{"title": "Buy milk", "body": "2 cartons"}` as `notes-api/note.json`, then:

:::tabs
@tab Windows
```powershell
cd notes-api
curl.exe -i -X POST http://127.0.0.1:8000/notes -H "Content-Type: application/json" --data "@note.json"
curl.exe http://127.0.0.1:8000/notes
curl.exe -i http://127.0.0.1:8000/notes/2
```
@tab macOS
```bash
cd notes-api
curl -i -X POST http://127.0.0.1:8000/notes -H "Content-Type: application/json" --data "@note.json"
curl http://127.0.0.1:8000/notes
curl -i http://127.0.0.1:8000/notes/2
```
@tab Chromebook / Linux
```bash
cd notes-api
curl -i -X POST http://127.0.0.1:8000/notes -H "Content-Type: application/json" --data "@note.json"
curl http://127.0.0.1:8000/notes
curl -i http://127.0.0.1:8000/notes/2
```
:::

`-X POST` sets the method, `-H` adds a header, and `--data "@note.json"` sends the file's contents as the body. The first command prints the `201 Created` response at the top of this page. The list prints `[{"id":1,"title":"Buy milk","body":"2 cartons"}]`, and note 2 doesn't exist yet:

```text
HTTP/1.1 404 Not Found
date: Mon, 16 Nov 2026 06:25:52 GMT
server: uvicorn
content-length: 29
content-type: application/json

{"detail":"Note 2 not found"}
```

Then open `http://127.0.0.1:8000/docs`. All five routes are there, with the request body shape for POST and PATCH filled in as an example. Use **Try it out** to send a PATCH, and watch each request appear in the server terminal with its status code.

:::warning Forgetting `-H "Content-Type: application/json"`
Without that header, curl labels the body as form data, and FastAPI answers `422` with `loc: ["body"]` and "Input should be a valid dictionary or object to extract fields from". The JSON was fine; the label was wrong.
:::

## Step 7: Tests that start clean

Clicking around proves it works today. Tests prove it still works after your next round of changes. Each test sends requests with TestClient and checks the answers with `assertEqual`.

The important part is `setUp`, which unittest runs before **every** test. It empties the list, so no test depends on notes another test left behind. The ids keep counting up across tests, which is why the tests use the id that came back from `create` instead of assuming it's 1.

On your computer, `test_main.py` starts with `from main import app, notes`. This page already has both from the cells above, so the cell leaves that line out.

```python run title="notes-api/test_main.py"
import sys
import unittest

from fastapi.testclient import TestClient

client = TestClient(app)


class NotesApiTests(unittest.TestCase):
    def setUp(self):
        notes.clear()

    def create(self, **fields):
        response = client.post("/notes", json=fields)
        self.assertEqual(response.status_code, 201)
        return response.json()

    def test_create_fills_in_id_and_default_body(self):
        note = self.create(title="Buy milk")
        self.assertIsInstance(note["id"], int)
        self.assertEqual(note["body"], "")

    def test_list_filters_with_q_ignoring_case(self):
        self.create(title="Buy milk")
        self.create(title="Essay outline", body="Mention milk prices")
        self.create(title="Call Sam")
        titles = [n["title"] for n in client.get("/notes?q=MILK").json()]
        self.assertEqual(titles, ["Buy milk", "Essay outline"])

    def test_missing_note_is_404_with_detail(self):
        response = client.get("/notes/999")
        self.assertEqual(response.status_code, 404)
        self.assertEqual(response.json(), {"detail": "Note 999 not found"})

    def test_empty_title_is_422_on_title(self):
        response = client.post("/notes", json={"title": ""})
        self.assertEqual(response.status_code, 422)
        self.assertEqual(response.json()["detail"][0]["loc"], ["body", "title"])

    def test_patch_changes_only_sent_fields(self):
        note = self.create(title="Buy milk", body="2 cartons")
        response = client.patch(f"/notes/{note['id']}", json={"body": "3 cartons"})
        self.assertEqual(response.json(), {**note, "body": "3 cartons"})

    def test_delete_then_get_is_404(self):
        note = self.create(title="Temporary")
        self.assertEqual(client.delete(f"/notes/{note['id']}").status_code, 204)
        self.assertEqual(client.get(f"/notes/{note['id']}").status_code, 404)


if __name__ == "__main__":
    suite = unittest.defaultTestLoader.loadTestsFromTestCase(NotesApiTests)
    unittest.TextTestRunner(stream=sys.stdout, verbosity=2).run(suite)
```

Tests don't need the server, so it doesn't matter whether it's running. From the client terminal, inside `notes-api`, run `python -m unittest -v`. unittest finds `test_main.py` by its name and runs every method that starts with `test`.

## The finished main.py

```python run title="notes-api/main.py"
from itertools import count
from typing import Annotated

from fastapi import FastAPI, HTTPException, Query, status
from pydantic import BaseModel, Field

app = FastAPI(title="Notes API")


class NoteIn(BaseModel):
    title: str = Field(min_length=1, max_length=100)
    body: str = Field(default="", max_length=2000)


class NoteUpdate(BaseModel):
    title: str | None = Field(default=None, min_length=1, max_length=100)
    body: str | None = Field(default=None, max_length=2000)


class Note(BaseModel):
    id: int
    title: str
    body: str


notes: list[Note] = []
ids = count(1)


def find_note(note_id: int) -> Note:
    for note in notes:
        if note.id == note_id:
            return note
    raise HTTPException(status.HTTP_404_NOT_FOUND, f"Note {note_id} not found")


@app.get("/notes")
def list_notes(
    q: str = "",
    limit: Annotated[int, Query(ge=1, le=100)] = 20,
    offset: Annotated[int, Query(ge=0)] = 0,
) -> list[Note]:
    text = q.lower()
    matches = [n for n in notes if text in n.title.lower() or text in n.body.lower()]
    return matches[offset : offset + limit]


@app.post("/notes", status_code=status.HTTP_201_CREATED)
def create_note(note_in: NoteIn) -> Note:
    note = Note(id=next(ids), **note_in.model_dump())
    notes.append(note)
    return note


@app.get("/notes/{note_id}")
def get_note(note_id: int) -> Note:
    return find_note(note_id)


@app.patch("/notes/{note_id}")
def update_note(note_id: int, changes: NoteUpdate) -> Note:
    note = find_note(note_id)
    for field, value in changes.model_dump(exclude_none=True).items():
        setattr(note, field, value)
    return note


@app.delete("/notes/{note_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_note(note_id: int) -> None:
    notes.remove(find_note(note_id))
```

About 70 lines for five endpoints, validation, paging, search, consistent errors, and interactive docs. Stop the server and start it again, then list the notes: the list is empty. Keeping notes across restarts is the job of the next module.

Corey Schafer adds Pydantic schemas to his FastAPI app: separate models for what comes in and what goes out, length limits on fields, and a POST endpoint. Compare his create and response schemas with `NoteIn` and `Note`, and notice where he puts the id.

:::quiz
Q: Why does `NoteUpdate` make every field optional, while `NoteIn` requires `title`?
- [x] A PATCH may send only the fields that change, but a new note must have a title
  Required fields on an update model would force clients to resend everything, which is what PUT is for.
- [ ] Pydantic doesn't allow two models with the same required fields
  It does. The difference is a design choice about what each request must contain.
- [ ] So PATCH can skip validation
  Fields that are sent are still validated: an empty title still gets a 422.

Q: Why does `find_note` raise an `HTTPException` instead of returning `None`?
- [ ] Returning `None` would crash Python
  It wouldn't crash at that line; the routes would just have to check for it.
- [x] So every route gets the same 404 without each one having to remember an `if note is None` check
  One helper, one rule. A route can't forget the check because the helper does it.
- [ ] Because FastAPI can't send 404s any other way
  You could also raise the exception inside each route. The helper avoids repeating it.

Q: Why does `setUp` call `notes.clear()`?
- [ ] To make the tests run faster
  Speed is the same. It's about each test starting from a known state.
- [x] So each test starts with an empty list and can't pass or fail because of another test's notes
  Without it, the filter test would also find notes created by other tests, and results would depend on the order tests run in.
:::

:::takeaways
- Use separate models for input (`NoteIn`), partial updates (`NoteUpdate`), and output (`Note`). Only the server sets `id`.
- One lookup helper that raises `HTTPException(404)` keeps every route's "not found" identical.
- `model_dump(exclude_none=True)` plus `setattr` updates only the fields the client sent.
- Set `status_code` for 201 and 204. A 204 route returns nothing.
- Send JSON with curl using `-H "Content-Type: application/json" --data "@file.json"`.
- Tests with TestClient need no server. Reset shared state in `setUp`, and use ids from responses.
:::
