function messageFrom(body, status) {

## Step 1: The schema and the connection dependency

`init_db` takes a path so tests can make their own database. `get_db` is the per-request connection from the Notes lesson.

```python run title="main.py (step 1)"
import sqlite3
from fastapi import Depends, FastAPI, HTTPException, Response, status
from pydantic import BaseModel, ConfigDict, Field

DB_PATH = "notes.db"

SCHEMA = """
CREATE TABLE IF NOT EXISTS notes (
    id         INTEGER PRIMARY KEY,
    title      TEXT NOT NULL CHECK (length(title) BETWEEN 1 AND 100),
    body       TEXT NOT NULL DEFAULT '',
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
"""

def init_db(path=DB_PATH):
    with sqlite3.connect(path) as conn:
        conn.executescript(SCHEMA)

def get_db():
    conn = sqlite3.connect(DB_PATH, check_same_thread=False)
    conn.row_factory = sqlite3.Row
    conn.execute("PRAGMA foreign_keys = ON")
    try:
        yield conn
    finally:
        conn.close()

init_db()
tables = sqlite3.connect(DB_PATH).execute("SELECT name FROM sqlite_master WHERE type = 'table'").fetchall()
print("Tables in notes.db:", [t[0] for t in tables])
```

SQLite's `datetime('now')` is in UTC, written as `YYYY-MM-DD HH:MM:SS`. Text in that format sorts correctly, which the list route relies on.

## Step 2: Routes backed by SQL

The paths move under `/api` (`/api/notes` instead of the earlier `/notes`), so they can never collide with page files once FastAPI serves the page too. Each route asks for `db` and runs one or two parameterized statements. `find_note` raises the 404 in one place. The `PATCH` route updates only the fields the client sent: a missing field arrives as `None`, and `COALESCE(?, title)` means "use the new value, or keep the old one if the new one is `NULL`". That keeps the SQL fixed, with no string-building.

```python run title="main.py (step 2)"
class NoteIn(BaseModel):
    model_config = ConfigDict(extra="forbid")
    title: str = Field(min_length=1, max_length=100)
    body: str = Field(default="", max_length=2000)

class NotePatch(BaseModel):
    model_config = ConfigDict(extra="forbid")
    title: str | None = Field(default=None, min_length=1, max_length=100)
    body: str | None = Field(default=None, max_length=2000)

class NoteOut(BaseModel):
    id: int
    title: str
    body: str
    created_at: str

app = FastAPI(title="Notes")

def find_note(db, note_id):
    row = db.execute("SELECT id, title, body, created_at FROM notes WHERE id = ?", (note_id,)).fetchone()
    if row is None:
        raise HTTPException(status.HTTP_404_NOT_FOUND, "Note not found")
    return dict(row)

@app.get("/api/notes", response_model=list[NoteOut])
def list_notes(db: sqlite3.Connection = Depends(get_db)):
    rows = db.execute("SELECT id, title, body, created_at FROM notes ORDER BY created_at DESC, id DESC")
    return [dict(row) for row in rows]

@app.post("/api/notes", status_code=status.HTTP_201_CREATED, response_model=NoteOut)
def create_note(note: NoteIn, db: sqlite3.Connection = Depends(get_db)):
    with db:
        cur = db.execute("INSERT INTO notes (title, body) VALUES (?, ?)", (note.title, note.body))
    return find_note(db, cur.lastrowid)

@app.patch("/api/notes/{note_id}", response_model=NoteOut)
def update_note(note_id: int, patch: NotePatch, db: sqlite3.Connection = Depends(get_db)):
    find_note(db, note_id)
    with db:
        db.execute(
            "UPDATE notes SET title = COALESCE(?, title), body = COALESCE(?, body) WHERE id = ?",
            (patch.title, patch.body, note_id),
        )
    return find_note(db, note_id)

@app.delete("/api/notes/{note_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_note(note_id: int, db: sqlite3.Connection = Depends(get_db)):
    find_note(db, note_id)
    with db:
        db.execute("DELETE FROM notes WHERE id = ?", (note_id,))
    return Response(status_code=status.HTTP_204_NO_CONTENT)

from fastapi.testclient import TestClient
client = TestClient(app)
first = client.post("/api/notes", json={"title": "Chem lab checklist", "body": "goggles"}).json()
second = client.post("/api/notes", json={"title": "Scratch note"}).json()
updated = client.patch(f"/api/notes/{first['id']}", json={"body": "goggles, gloves"}).json()
print("PATCH kept the title:", updated["title"], "| new body:", updated["body"])
print("DELETE 999:", client.delete("/api/notes/999").status_code)
print("DELETE scratch:", client.delete(f"/api/notes/{second['id']}").status_code)
print([note["title"] for note in client.get("/api/notes").json()])
```

`create_note` reads the row back with `find_note` instead of echoing the input, so the response includes the `id` and `created_at` that only the database knows. The `with db:` blocks commit each write, which matters now: forget the commit and the next request, on a fresh connection, wouldn't see the note.

## Step 3: Tests on their own database

Tests that create and delete notes shouldn't touch `notes.db`, where your real notes live. `app.dependency_overrides` tells FastAPI "whenever a route asks for `get_db`, call this instead", so every route gets a connection to `test_notes.db` without changing a line of them. `setUp` rebuilds that file before each test.

```python run title="test_main.py"
# In your project this file starts with:
# from main import app, get_db, init_db
import os
import sqlite3
import sys
import unittest
from fastapi.testclient import TestClient

TEST_DB = "test_notes.db"

def get_test_db():
    conn = sqlite3.connect(TEST_DB, check_same_thread=False)
    conn.row_factory = sqlite3.Row
    try:
        yield conn
    finally:
        conn.close()

app.dependency_overrides[get_db] = get_test_db
client = TestClient(app)

class NotesApiTests(unittest.TestCase):
    def setUp(self):
        if os.path.exists(TEST_DB):
            os.remove(TEST_DB)
        init_db(TEST_DB)

    def add(self, title, body=""):
        r = client.post("/api/notes", json={"title": title, "body": body})
        self.assertEqual(r.status_code, 201)
        return r.json()

    def test_create_then_list_newest_first(self):
        self.add("First")
        self.add("Second")
        titles = [n["title"] for n in client.get("/api/notes").json()]
        self.assertEqual(titles, ["Second", "First"])

    def test_empty_title_is_422_and_saves_nothing(self):
        r = client.post("/api/notes", json={"title": ""})
        self.assertEqual(r.status_code, 422)
        self.assertEqual(client.get("/api/notes").json(), [])

    def test_patch_changes_only_what_was_sent(self):
        note = self.add("Essay", "intro")
        r = client.patch(f"/api/notes/{note['id']}", json={"body": "intro, 3 points"})
        self.assertEqual((r.json()["title"], r.json()["body"]), ("Essay", "intro, 3 points"))

    def test_missing_note_is_404(self):
        self.assertEqual(client.patch("/api/notes/42", json={"title": "x"}).status_code, 404)
        self.assertEqual(client.delete("/api/notes/42").status_code, 404)

    def test_delete_removes_the_row(self):
        note = self.add("Temporary")
        self.assertEqual(client.delete(f"/api/notes/{note['id']}").status_code, 204)
        self.assertEqual(client.get("/api/notes").json(), [])

suite = unittest.defaultTestLoader.loadTestsFromTestCase(NotesApiTests)
unittest.TextTestRunner(stream=sys.stdout, verbosity=2).run(suite)
print("notes.db still holds", sqlite3.connect("notes.db").execute("SELECT COUNT(*) FROM notes").fetchone()[0], "note")
```

The last line is the proof: the note from step 2 is still the only row in the real file. "First" and "Second" both get `created_at` in the same second, which is why the list route also sorts by `id DESC` as a tie-breaker; without it, `test_create_then_list_newest_first` could pass or fail depending on timing.

## Step 4: The page

Save the page from the top of this lesson as `static/index.html`, without the preview-only `<script>` block. Three choices in it are worth copying into every front end you write:

1. **One `api()` function** does every request, so the `response.ok` check, the JSON check, and the error message format happen in one place.
2. **Paths, not full URLs.** `fetch("/api/notes")` goes to whatever origin served the page, so the same file works on your laptop and on a host.
3. **`textContent`, never `innerHTML`, for user data.** A note titled `<img src=x onerror=alert(1)>` would run that script if inserted as HTML. With `textContent` it's just odd text.

The title box has `maxlength` but not `required`. Normally you'd add `required` for a friendlier form; it's left off so you can watch the server's 422 arrive. Browser checks are a convenience for honest users; the server's checks are the ones that count, because anyone can send a request without your page.

## Step 5: Serve the page and run everything

Here is the finished `main.py`. Compared with the steps, it adds the `StaticFiles` mount at the bottom and finds `notes.db` and `static/` next to the file, so it works from any folder you start it in.

## Step 6: Putting it online for free

Hosting changes often, so check each provider's current docs before you rely on these details. The big question for this app is **where `notes.db` lives**, because many free plans throw away files.

- **Render** (free web service): connect a GitHub repository, set the build command to `pip install -r requirements.txt` and the start command to `uvicorn main:app --host 0.0.0.0 --port $PORT`. A free service sleeps after 15 minutes without traffic and takes about a minute to wake. Its filesystem is temporary, so `notes.db` is wiped on every redeploy, restart, or spin-down. That's fine for showing the app off; for data you want to keep, you'd use a hosted database instead (Render's free Postgres databases expire after 30 days).
- **PythonAnywhere**: your files stay put, so a SQLite file survives. Its support for FastAPI (an ASGI app) is a beta feature that you set up with their `pa` command-line tool, following their "ASGI" help pages; check there for what a free account currently includes.

For either one, make a `requirements.txt` next to `main.py` containing the line `fastapi[standard]`, which pulls in Uvicorn too. And never deploy with secrets in your code; read them from environment variables, which every host lets you set.

:::quiz
Q: Why does the `StaticFiles` mount come after all the `@app` routes?
- [ ] Mounts must always be the last line of a Python file
  Python doesn't care. FastAPI checks routes and mounts in the order they were added.
- [x] A mount at `/` matches every path, so anything added after it would never be reached
  Registering the API routes first means `/api/notes` and `/docs` win, and everything else falls through to the files.
- [ ] `StaticFiles` needs the database to exist first
  It only reads files from the `static` folder.

Q: Why do the tests use `app.dependency_overrides[get_db]` instead of changing `DB_PATH`?
- [x] It swaps the database for every route at once, without editing the app or risking the real `notes.db`
  Routes ask for `get_db`; the override answers with a test connection instead.
- [ ] `DB_PATH` can't be changed after import
  It could be reassigned, but every function would then depend on the order things were imported and set, which is easy to get wrong.
- [ ] Overrides make the tests run in parallel
  They don't affect how tests are scheduled.

Q: A note's title is `<b>hi</b>`. What does the page show?
- [ ] **hi** in bold
  That would only happen with `innerHTML`, which this page never uses for note data.
- [x] The literal text `<b>hi</b>`
  `textContent` puts characters on screen as text, so markup in user data can't run.
- [ ] Nothing; the API rejects titles with `<`
  The model allows any characters. Safety comes from how the page displays them.
:::

:::takeaways
- Every route gets its connection from `get_db`, runs parameterized SQL, and commits with `with db:`.
- `COALESCE(?, column)` gives you a partial update with fixed SQL.
- `app.dependency_overrides` points tests at their own database file, rebuilt before each test.
- The page's single `api()` helper checks `response.ok`, parses only real JSON, and shows `detail`.
- Mount `StaticFiles` last so the page and the API share one origin, with no CORS needed.
- On free hosts with temporary disks, a SQLite file resets on every restart. Pick hosting knowing where your data lives.
:::
