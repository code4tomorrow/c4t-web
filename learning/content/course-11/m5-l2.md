The notes API from earlier modules keeps its notes in a Python list. Restart the server and every note is gone. In this build you'll make the database that replaces that list: a file called `notes.db` that survives restarts, knows which user owns each note, and lets notes carry tags like `school` or `health`.

Here is the finished design. Every cell in this lesson shares one Python session, like a notebook, so each step builds on the one before. On your computer, put the cells one after another in a single file and run it.

## Step 1: Create the tables

A schema is a contract the database enforces for you. The interesting parts here are the rules on the columns. `CHECK (length(title) BETWEEN 1 AND 100)` refuses blank or huge titles even if a bug in your Python lets one through. `DEFAULT (datetime('now'))` stamps new notes with the current UTC time. `ON DELETE CASCADE` says "when the parent row is deleted, delete the rows that point at it", so deleting a note also deletes its tag links.

```python run title="notes_db.py (step 1)"
import sqlite3

SCHEMA = """
CREATE TABLE IF NOT EXISTS users (
    id       INTEGER PRIMARY KEY,
    username TEXT NOT NULL UNIQUE
);
CREATE TABLE IF NOT EXISTS notes (
    id         INTEGER PRIMARY KEY,
    user_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title      TEXT NOT NULL CHECK (length(title) BETWEEN 1 AND 100),
    body       TEXT NOT NULL DEFAULT '',
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE TABLE IF NOT EXISTS tags (
    id   INTEGER PRIMARY KEY,
    name TEXT NOT NULL UNIQUE CHECK (length(name) <= 20)
);
CREATE TABLE IF NOT EXISTS note_tags (
    note_id INTEGER NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
    tag_id  INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
    PRIMARY KEY (note_id, tag_id)
);
"""

conn = sqlite3.connect("notes.db")
conn.execute("PRAGMA foreign_keys = ON")
conn.executescript(SCHEMA)
print([row[0] for row in conn.execute("SELECT name FROM sqlite_master WHERE type = 'table'")])
```

`sqlite_master` is SQLite's own table of contents, so querying it confirms all four tables exist. `IF NOT EXISTS` makes the script safe to run twice.

## Step 2: Add seed data, and see what commit does

Seed data is a small, realistic set of rows to develop against. `executemany` runs one `INSERT` once per tuple. The timestamps are typed out so that "newest first" has a predictable answer.

```python run title="notes_db.py (step 2)"
conn.executemany("INSERT INTO users (username) VALUES (?)", [("ana",), ("ben",)])
conn.executemany(
    "INSERT INTO notes (user_id, title, body, created_at) VALUES (?, ?, ?, ?)",
    [
        (1, "Chem lab checklist", "goggles, gloves, notebook", "2026-11-02 08:15:00"),
        (1, "Essay outline", "intro, 3 points, conclusion", "2026-11-04 19:40:00"),
        (2, "Gym schedule", "Mon/Wed/Fri 7am", "2026-11-03 06:55:00"),
        (1, "Gift ideas", "headphones, book", "2026-11-05 21:10:00"),
    ],
)
conn.executemany("INSERT INTO tags (name) VALUES (?)", [("school",), ("health",), ("personal",)])
conn.executemany("INSERT INTO note_tags VALUES (?, ?)", [(1, 1), (2, 1), (3, 2), (4, 3), (3, 3)])

other = sqlite3.connect("notes.db")
print("Before commit, another connection sees", other.execute("SELECT COUNT(*) FROM notes").fetchone()[0], "notes")
conn.commit()
print("After commit, it sees", other.execute("SELECT COUNT(*) FROM notes").fetchone()[0], "notes")
other.close()
```

Python's `sqlite3` starts a transaction before the first `INSERT`, and nothing is permanent until `commit()`. The second connection plays the part of a second request to your API: until the commit, it sees zero notes. Forget `commit()` in a route and the API will report success while saving nothing.

## Step 3: Write the reads the API will need

Each API route will need one query. Writing them as functions now means the routes in a later module stay short. Setting `conn.row_factory = sqlite3.Row` makes each row behave like a dictionary, so `dict(row)` turns it into exactly the JSON-ready shape a FastAPI route can return.

```python run title="notes_db.py (step 3)"
conn.row_factory = sqlite3.Row

def notes_for(conn, username, limit=10):
    rows = conn.execute(
        """
        SELECT notes.id, notes.title, notes.created_at
        FROM notes JOIN users ON users.id = notes.user_id
        WHERE users.username = ?
        ORDER BY notes.created_at DESC
        LIMIT ?
        """,
        (username, limit),
    ).fetchall()
    return [dict(row) for row in rows]

def notes_tagged(conn, tag):
    rows = conn.execute(
        """
        SELECT notes.title, users.username
        FROM notes
        JOIN note_tags ON note_tags.note_id = notes.id
        JOIN tags      ON tags.id = note_tags.tag_id
        JOIN users     ON users.id = notes.user_id
        WHERE tags.name = ?
        ORDER BY notes.title
        """,
        (tag,),
    ).fetchall()
    return [dict(row) for row in rows]

def tag_counts(conn):
    rows = conn.execute(
        """
        SELECT tags.name, COUNT(note_tags.note_id) AS uses
        FROM tags LEFT JOIN note_tags ON note_tags.tag_id = tags.id
        GROUP BY tags.id
        ORDER BY uses DESC, tags.name
        """
    ).fetchall()
    return {row["name"]: row["uses"] for row in rows}

for note in notes_for(conn, "ana", limit=2):
    print(note)
print(notes_tagged(conn, "school"))
print(tag_counts(conn))
```

`LIMIT ?` caps the result, which is how an API pages through long lists. Every value from outside the function goes in through a `?` placeholder, never pasted into the SQL string. Module 6 shows exactly what goes wrong if you paste.

## Step 4: Update and delete only what the user owns

The ownership check can live inside the SQL. `WHERE id = ? AND user_id = ?` matches nothing if the note belongs to someone else, and `cursor.rowcount` tells you how many rows changed. Zero means "not found, or not yours", which the API will turn into an error response.

```python run title="notes_db.py (step 4)"
def rename_note(conn, note_id, user_id, title):
    cur = conn.execute(
        "UPDATE notes SET title = ? WHERE id = ? AND user_id = ?",
        (title, note_id, user_id),
    )
    conn.commit()
    return cur.rowcount == 1

def delete_note(conn, note_id, user_id):
    cur = conn.execute("DELETE FROM notes WHERE id = ? AND user_id = ?", (note_id, user_id))
    conn.commit()
    return cur.rowcount == 1

print("Ben renames Ana's note:", rename_note(conn, 2, user_id=2, title="Hacked"))
print("Ana renames her note:  ", rename_note(conn, 2, user_id=1, title="Essay outline v2"))
print("Tag links before delete:", conn.execute("SELECT COUNT(*) FROM note_tags").fetchone()[0])
print("Ben deletes note 3:", delete_note(conn, 3, user_id=2))
print("Tag links after delete: ", conn.execute("SELECT COUNT(*) FROM note_tags").fetchone()[0])
```

Note 3 had two tags, and both links vanished with it. That's the cascade doing its job, and it only works because step 1 turned on `PRAGMA foreign_keys`.

## Step 5: Add an index for the most common query

Every time Ana opens the app, the API runs "Ana's notes, newest first". Without help, SQLite reads every row in `notes` to find hers, then sorts them. An **index** is a sorted copy of some columns with pointers back to the rows, like the index at the back of a textbook. `EXPLAIN QUERY PLAN` shows which strategy SQLite picked.

```python run title="notes_db.py (step 5)"
QUERY = "SELECT id, title FROM notes WHERE user_id = ? ORDER BY created_at DESC"

def plan(sql, params):
    for row in conn.execute("EXPLAIN QUERY PLAN " + sql, params):
        print("  ", row["detail"])

print("Without an index:")
plan(QUERY, (1,))
conn.execute("CREATE INDEX IF NOT EXISTS notes_by_user ON notes (user_id, created_at)")
conn.commit()
print("With an index:")
plan(QUERY, (1,))
```

`SCAN notes` means "read the whole table", and `USE TEMP B-TREE FOR ORDER BY` means "then sort". With the index it becomes `SEARCH ... USING INDEX`: jump straight to Ana's entries, already in date order. With four notes you won't feel the difference; with a million, it's the difference between milliseconds and seconds. Indexes cost disk space and slow down writes a little, so add them for queries you run constantly, not for every column.

## Step 6: Save a note and its tags in one transaction

Creating a tagged note takes several statements: insert the note, make sure each tag exists, link them. If the third statement fails, you'd be left with a note missing its tags. A **transaction** makes the whole group all-or-nothing. Used as `with conn:`, a connection commits when the block finishes and rolls everything back if an exception escapes it.

```python run title="notes_db.py (step 6)"
def add_note_with_tags(conn, user_id, title, tag_names):
    with conn:
        cur = conn.execute("INSERT INTO notes (user_id, title) VALUES (?, ?)", (user_id, title))
        note_id = cur.lastrowid
        for name in tag_names:
            conn.execute("INSERT INTO tags (name) VALUES (?) ON CONFLICT (name) DO NOTHING", (name,))
            tag_id = conn.execute("SELECT id FROM tags WHERE name = ?", (name,)).fetchone()["id"]
            conn.execute("INSERT INTO note_tags VALUES (?, ?)", (note_id, tag_id))
    return note_id

count = lambda: conn.execute("SELECT COUNT(*) FROM notes").fetchone()[0]
print("Notes:", count())
print("New note id:", add_note_with_tags(conn, 2, "Track meet", ["health", "sports"]))
print("Notes:", count())
try:
    add_note_with_tags(conn, 2, "Packing list", ["travel", "a tag name that is far too long"])
except sqlite3.IntegrityError as error:
    print("Failed:", error)
print("Notes:", count())
print(tag_counts(conn))
conn.close()
```

The second call inserted "Packing list" and the `travel` tag before the long tag broke the `CHECK` rule. The rollback erased both: the note count stayed at 4 and `travel` never appears in the tag counts. `ON CONFLICT (name) DO NOTHING` reuses a tag that already exists, such as `health`.

:::warning
`INSERT OR IGNORE` looks like a shortcut for "skip it if the tag exists", but it also skips rows that break `NOT NULL` and `CHECK` rules, silently. Here the long tag would vanish without an error and the next line would crash on `None`. `ON CONFLICT (name) DO NOTHING` only ignores the duplicate-name case.
:::

## The finished program

Here is everything in one file. It rebuilds `notes.db` from the seed data each run, which is what you want while developing.

```python run title="notes_db.py"
import os
import sqlite3

DB_PATH = "notes.db"

SCHEMA = """
CREATE TABLE IF NOT EXISTS users (
    id       INTEGER PRIMARY KEY,
    username TEXT NOT NULL UNIQUE
);
CREATE TABLE IF NOT EXISTS notes (
    id         INTEGER PRIMARY KEY,
    user_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title      TEXT NOT NULL CHECK (length(title) BETWEEN 1 AND 100),
    body       TEXT NOT NULL DEFAULT '',
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE TABLE IF NOT EXISTS tags (
    id   INTEGER PRIMARY KEY,
    name TEXT NOT NULL UNIQUE CHECK (length(name) <= 20)
);
CREATE TABLE IF NOT EXISTS note_tags (
    note_id INTEGER NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
    tag_id  INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
    PRIMARY KEY (note_id, tag_id)
);
CREATE INDEX IF NOT EXISTS notes_by_user ON notes (user_id, created_at);
"""


def connect(path=DB_PATH):
    conn = sqlite3.connect(path)
    conn.row_factory = sqlite3.Row
    conn.execute("PRAGMA foreign_keys = ON")
    return conn


def seed(conn):
    with conn:
        conn.executemany("INSERT INTO users (username) VALUES (?)", [("ana",), ("ben",)])
        conn.executemany(
            "INSERT INTO notes (user_id, title, created_at) VALUES (?, ?, ?)",
            [(1, "Chem lab checklist", "2026-11-02 08:15:00"),
             (1, "Essay outline", "2026-11-04 19:40:00"),
             (2, "Gym schedule", "2026-11-03 06:55:00")],
        )


def notes_for(conn, username, limit=10):
    rows = conn.execute(
        """SELECT notes.id, notes.title, notes.created_at
           FROM notes JOIN users ON users.id = notes.user_id
           WHERE users.username = ?
           ORDER BY notes.created_at DESC LIMIT ?""",
        (username, limit),
    ).fetchall()
    return [dict(row) for row in rows]


def tag_counts(conn):
    rows = conn.execute(
        """SELECT tags.name, COUNT(note_tags.note_id) AS uses
           FROM tags LEFT JOIN note_tags ON note_tags.tag_id = tags.id
           GROUP BY tags.id ORDER BY uses DESC, tags.name"""
    ).fetchall()
    return {row["name"]: row["uses"] for row in rows}


def rename_note(conn, note_id, user_id, title):
    with conn:
        cur = conn.execute(
            "UPDATE notes SET title = ? WHERE id = ? AND user_id = ?", (title, note_id, user_id)
        )
    return cur.rowcount == 1


def delete_note(conn, note_id, user_id):
    with conn:
        cur = conn.execute("DELETE FROM notes WHERE id = ? AND user_id = ?", (note_id, user_id))
    return cur.rowcount == 1


def add_note_with_tags(conn, user_id, title, tag_names):
    with conn:
        note_id = conn.execute(
            "INSERT INTO notes (user_id, title) VALUES (?, ?)", (user_id, title)
        ).lastrowid
        for name in tag_names:
            conn.execute("INSERT INTO tags (name) VALUES (?) ON CONFLICT (name) DO NOTHING", (name,))
            tag_id = conn.execute("SELECT id FROM tags WHERE name = ?", (name,)).fetchone()["id"]
            conn.execute("INSERT INTO note_tags VALUES (?, ?)", (note_id, tag_id))
    return note_id


if __name__ == "__main__":
    if os.path.exists(DB_PATH):
        os.remove(DB_PATH)  # start from the same seed data on every run
    conn = connect()
    conn.executescript(SCHEMA)
    seed(conn)
    add_note_with_tags(conn, 1, "Bio flashcards", ["school", "exam"])
    print("Rename someone else's note:", rename_note(conn, 3, user_id=1, title="Mine now"))
    for note in notes_for(conn, "ana"):
        print(note["id"], note["title"])
    print(tag_counts(conn))
    conn.close()
```

The "Bio flashcards" note has no typed-out timestamp, so its `created_at` comes from the clock and it sorts to the top as the newest note.

:::quiz
Q: Why does `note_tags` use `PRIMARY KEY (note_id, tag_id)` instead of its own `id` column?
- [ ] SQLite requires every linking table to have exactly two columns
  It doesn't; you could add more columns, such as when the tag was added.
- [x] The pair must be unique, so the same tag can't be attached to the same note twice
  A composite primary key makes the combination the identity of the row and blocks duplicates.
- [ ] It makes `ON DELETE CASCADE` work
  Cascades come from the `REFERENCES ... ON DELETE CASCADE` clauses, not from the primary key.

Q: `rename_note(conn, 2, user_id=2, title="Hacked")` returned `False`. What did the database actually do?
- [ ] Raised an error that Python caught
  No exception happened. The `UPDATE` ran successfully and matched no rows.
- [x] Ran the `UPDATE`, which matched zero rows because note 2's `user_id` is 1
  `rowcount` was 0, so the function reported that nothing changed.
- [ ] Changed the title, then rolled it back
  The `WHERE` clause excluded the row before anything changed.

Q: Why is the index on `(user_id, created_at)` rather than only `(user_id)`?
- [ ] An index must always include a date column
  Indexes can be on any columns.
- [ ] Two-column indexes use less disk space
  They use more, if anything.
- [x] It finds one user's notes and already has them in date order, so SQLite can skip the sort
  The second column keeps each user's entries sorted by time, which removed the temp B-tree step.
:::

:::takeaways
- Write the schema's rules (`NOT NULL`, `UNIQUE`, `CHECK`, foreign keys) into the database so they hold even when application code slips.
- Nothing is saved until `commit()`. `with conn:` commits for you, or rolls back on an exception.
- Put ownership into the `WHERE` clause and check `rowcount` to see whether anything matched.
- `ON DELETE CASCADE` removes dependent rows, but only with `PRAGMA foreign_keys = ON`.
- Index the columns your most frequent query filters and sorts by, and confirm with `EXPLAIN QUERY PLAN`.
:::
