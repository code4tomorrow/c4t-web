:::objectives
- Validate sign-up and note data with strict Pydantic models.
- Store passwords as salted scrypt hashes and issue random bearer tokens at login.
- Write a `current_user` dependency that turns a missing or bad token into a 401.
- Return 403 when someone touches a note they don't own, and test that it happens.
:::

Right now anyone who can reach the notes API can read and rewrite every note. By the end of this build, each note has an owner, and the API enforces the rules in this table. Every row with "yes" in the token column goes through the same dependency, so the rule can't be forgotten on one route.

| Method and path | Token needed? | Success | Failures |
| --- | --- | --- | --- |
| `POST /signup` | no | 201 | 409 name taken, 422 bad input |
| `POST /login` | no | 200 with a token | 401 wrong name or password |
| `GET /me` | yes | 200 | 401 |
| `POST /notes` | yes | 201 | 401, 422 |
| `GET /notes` | yes | 200, only your notes | 401 |
| `PATCH /notes/{id}` | yes | 200 | 401, 403 not yours, 404, 422 |
| `DELETE /notes/{id}` | yes | 204 | 401, 403, 404 |

```mermaid caption="FastAPI runs current_user before the route. If it raises, the route body never runs."
flowchart LR
    R["PATCH /notes/1"] --> V["Validate body (NoteIn)"]
    V --> D["current_user(Authorization header)"]
    D -->|"no or bad token"| E1["401"]
    D -->|"username"| O["owned_note(id, username)"]
    O -->|"missing"| E2["404"]
    O -->|"someone else's"| E3["403"]
    O -->|"yours"| OK["update, 200"]
```

The cells below share one Python session, so each step uses what the earlier ones defined. In your project, steps 1 to 5 all go in `notes-api/main.py`, and step 6 goes in `notes-api/test_main.py`. Data stays in dictionaries for now; the next module moves it into SQLite.

## Step 1: Models that say exactly what's allowed

Usernames become part of URLs and log lines, so keep them boring: 3 to 20 lowercase letters, digits, or underscores. Passwords get a minimum length and nothing else, because rules like "must contain a symbol" mostly produce `Password1!`. `NoteIn` has no `owner` field at all: the owner comes from the token, never from the request body.

```python run title="main.py (step 1)"
from pydantic import BaseModel, ConfigDict, Field, ValidationError

class Credentials(BaseModel):
    model_config = ConfigDict(extra="forbid")
    username: str = Field(min_length=3, max_length=20, pattern=r"^[a-z0-9_]+$")
    password: str = Field(min_length=8, max_length=128)

class NoteIn(BaseModel):
    model_config = ConfigDict(extra="forbid")
    title: str = Field(min_length=1, max_length=100)
    body: str = Field(default="", max_length=2000)

class NoteOut(BaseModel):
    id: int
    owner: str
    title: str
    body: str

for data in [{"username": "ana", "password": "correct horse"},
             {"username": "Ana!", "password": "short"}]:
    try:
        print("OK:", Credentials(**data))
    except ValidationError as error:
        for problem in error.errors():
            print("Rejected", problem["loc"][0], "->", problem["msg"])
```

Calling a model directly, without FastAPI, is a quick way to try its rules. Both problems with the second sign-up are reported at once, which is what the API's 422 response will do too.

## Step 2: Hash passwords before they touch storage

The stored string starts with `scrypt$` so that a future version of your app can tell which algorithm made it, and switch to a stronger one without breaking old accounts. The salt and the hash travel together, separated by `$`.

```python run title="main.py (step 2)"
import hashlib
import hmac
import secrets

SCRYPT = dict(n=2**14, r=8, p=1)  # raise n for production; see the Notes lesson

def hash_password(password: str) -> str:
    salt = secrets.token_bytes(16)
    digest = hashlib.scrypt(password.encode(), salt=salt, **SCRYPT)
    return f"scrypt${salt.hex()}${digest.hex()}"

def verify_password(password: str, stored: str) -> bool:
    _, salt_hex, digest_hex = stored.split("$")
    digest = hashlib.scrypt(password.encode(), salt=bytes.fromhex(salt_hex), **SCRYPT)
    return hmac.compare_digest(digest.hex(), digest_hex)

stored = hash_password("correct horse")
print(stored[:7], "...", len(stored), "characters")
print(verify_password("correct horse", stored), verify_password("Correct horse", stored))
```

One capital letter is enough to fail, as it should be. Nothing in the stored string can be turned back into the password; the only way to check a guess is to hash it again.

What to watch for: why plain hashing isn't enough and what salting adds. That reasoning is exactly why this step uses a random salt and a deliberately slow hash.

## Step 3: Sign up and log in

Sign-up hashes and stores. Login looks the user up, verifies, and hands out a fresh random token. The server keeps a `tokens` dictionary mapping each token to its username, which is how a later request proves who it's from.

```python run title="main.py (step 3)"
from fastapi import Depends, FastAPI, Header, HTTPException, status
from fastapi.testclient import TestClient

users: dict[str, str] = {}    # username -> stored password hash
tokens: dict[str, str] = {}   # token -> username
notes: dict[int, dict] = {}   # note id -> note
next_id = 1

app = FastAPI()

@app.post("/signup", status_code=status.HTTP_201_CREATED)
def signup(creds: Credentials):
    if creds.username in users:
        raise HTTPException(status.HTTP_409_CONFLICT, "That username is taken")
    users[creds.username] = hash_password(creds.password)
    return {"username": creds.username}

@app.post("/login")
def login(creds: Credentials):
    stored = users.get(creds.username)
    if stored is None or not verify_password(creds.password, stored):
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "Wrong username or password")
    token = secrets.token_urlsafe(32)
    tokens[token] = creds.username
    return {"token": token, "token_type": "bearer"}

client = TestClient(app)
print(client.post("/signup", json={"username": "ana", "password": "correct horse"}).status_code)
print(client.post("/signup", json={"username": "ana", "password": "another one"}).json())
print(client.post("/login", json={"username": "ana", "password": "wrong guess"}).json())
response = client.post("/login", json={"username": "ana", "password": "correct horse"})
print(response.status_code, list(response.json()), len(response.json()["token"]), "character token")
```

The failed login says "wrong username or password" without saying which. Telling an attacker "no such user" would let them test a list of names first. `token_urlsafe(32)` uses 32 random bytes, far too many to guess, encoded as 43 URL-safe characters.

## Step 4: A dependency that answers "who is this?"

A FastAPI **dependency** is a function the framework calls before your route, passing its return value in as a parameter. `current_user` reads the `Authorization` header, splits `Bearer <token>`, and either returns a username or stops the request with a 401.

```python run title="main.py (step 4)"
def current_user(authorization: str = Header(default="")) -> str:
    scheme, _, token = authorization.partition(" ")
    username = tokens.get(token) if scheme.lower() == "bearer" else None
    if username is None:
        raise HTTPException(
            status.HTTP_401_UNAUTHORIZED,
            "Missing or invalid token",
            headers={"WWW-Authenticate": "Bearer"},
        )
    return username

@app.get("/me")
def me(user: str = Depends(current_user)):
    return {"username": user}

ana_token = response.json()["token"]
no_token = client.get("/me")
print(no_token.status_code, "WWW-Authenticate:", no_token.headers["www-authenticate"])
print(client.get("/me", headers={"Authorization": "Bearer made-up"}).status_code)
print(client.get("/me", headers={"Authorization": f"Bearer {ana_token}"}).json())
```

The parameter is named `authorization` and FastAPI maps it to the `Authorization` header for you. The `WWW-Authenticate: Bearer` header on a 401 is the HTTP standard's way of saying which kind of credentials to send.

## Step 5: Notes that belong to someone

Every note route takes `user: str = Depends(current_user)`. The helper `owned_note` does the 404 and 403 checks in one place, so edit and delete can't drift apart. `response_model=NoteOut` makes FastAPI filter the output to exactly those fields.

```python run title="main.py (step 5)"
def owned_note(note_id: int, user: str) -> dict:
    note = notes.get(note_id)
    if note is None:
        raise HTTPException(status.HTTP_404_NOT_FOUND, "Note not found")
    if note["owner"] != user:
        raise HTTPException(status.HTTP_403_FORBIDDEN, "You can only change your own notes")
    return note

@app.post("/notes", status_code=status.HTTP_201_CREATED, response_model=NoteOut)
def create_note(note: NoteIn, user: str = Depends(current_user)):
    global next_id
    saved = {"id": next_id, "owner": user, **note.model_dump()}
    notes[next_id] = saved
    next_id += 1
    return saved

@app.get("/notes", response_model=list[NoteOut])
def list_notes(user: str = Depends(current_user)):
    return [n for n in notes.values() if n["owner"] == user]

@app.patch("/notes/{note_id}", response_model=NoteOut)
def edit_note(note_id: int, note: NoteIn, user: str = Depends(current_user)):
    saved = owned_note(note_id, user)
    saved.update(note.model_dump())
    return saved

@app.delete("/notes/{note_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_note(note_id: int, user: str = Depends(current_user)):
    owned_note(note_id, user)
    del notes[note_id]

def log_in(name, password):
    client.post("/signup", json={"username": name, "password": password})
    token = client.post("/login", json={"username": name, "password": password}).json()["token"]
    return {"Authorization": f"Bearer {token}"}

ana = log_in("ana", "correct horse")
ben = log_in("ben", "battery staple")
created = client.post("/notes", json={"title": "Diary: Nov 3"}, headers=ana)
print(created.status_code, created.json())
print(client.patch("/notes/1", json={"title": "lol"}, headers=ben).json())
print(client.delete("/notes/1", headers=ben).status_code)
print("Ben's list:", client.get("/notes", headers=ben).json())
print("Ana's list:", client.get("/notes", headers=ana).json())
```

Ben's edit and delete both bounced with 403, and Ana's note is untouched. `GET /notes` filters by owner too: a list route that returned everyone's notes would leak just as badly as an unchecked edit.

## Step 6: Tests that lock the rules in

Security rules are easy to break later by accident, so each one gets a test. `setUpClass` creates the two accounts once (hashing is slow on purpose, so you don't want to repeat it), and `setUp` empties the notes before every test so tests can't leak state into each other.

```python run title="test_main.py"
# In your project, this file also starts with:
# from main import app, users, tokens, notes
import sys
import unittest
from fastapi.testclient import TestClient

client = TestClient(app)

def log_in(name, password):
    client.post("/signup", json={"username": name, "password": password})
    token = client.post("/login", json={"username": name, "password": password}).json()["token"]
    return {"Authorization": f"Bearer {token}"}

class NotesAuthTests(unittest.TestCase):
    @classmethod
    def setUpClass(cls):
        users.clear(); tokens.clear()
        cls.ana = log_in("ana", "correct horse")
        cls.ben = log_in("ben", "battery staple")

    def setUp(self):
        notes.clear()
        self.note_id = client.post("/notes", json={"title": "Diary"}, headers=self.ana).json()["id"]

    def test_no_token_is_401(self):
        self.assertEqual(client.get("/notes").status_code, 401)

    def test_owner_can_edit(self):
        r = client.patch(f"/notes/{self.note_id}", json={"title": "Diary v2"}, headers=self.ana)
        self.assertEqual(r.status_code, 200)
        self.assertEqual(r.json()["title"], "Diary v2")

    def test_other_user_cannot_edit_or_delete(self):
        url = f"/notes/{self.note_id}"
        self.assertEqual(client.patch(url, json={"title": "x"}, headers=self.ben).status_code, 403)
        self.assertEqual(client.delete(url, headers=self.ben).status_code, 403)
        self.assertEqual(client.get("/notes", headers=self.ana).json()[0]["title"], "Diary")

    def test_list_shows_only_my_notes(self):
        self.assertEqual(client.get("/notes", headers=self.ben).json(), [])

    def test_password_is_not_stored(self):
        self.assertNotIn("correct horse", users["ana"])

    def test_client_cannot_choose_owner(self):
        r = client.post("/notes", json={"title": "Sneaky", "owner": "ben"}, headers=self.ana)
        self.assertEqual(r.status_code, 422)

suite = unittest.defaultTestLoader.loadTestsFromTestCase(NotesAuthTests)
unittest.TextTestRunner(stream=sys.stdout, verbosity=2).run(suite)
```

Run the tests from the `notes-api` folder with `python -m unittest`. (Leave out the last two lines in your file; they're how this page runs the tests.) The test that matters most is `test_other_user_cannot_edit_or_delete`: it's the bug from the start of this module, written down so it can never come back unnoticed.

## The finished main.py

```python title="notes-api/main.py"
import hashlib
import hmac
import secrets

from fastapi import Depends, FastAPI, Header, HTTPException, status
from pydantic import BaseModel, ConfigDict, Field

SCRYPT = dict(n=2**14, r=8, p=1)

class Credentials(BaseModel):
    model_config = ConfigDict(extra="forbid")
    username: str = Field(min_length=3, max_length=20, pattern=r"^[a-z0-9_]+$")
    password: str = Field(min_length=8, max_length=128)

class NoteIn(BaseModel):
    model_config = ConfigDict(extra="forbid")
    title: str = Field(min_length=1, max_length=100)
    body: str = Field(default="", max_length=2000)

class NoteOut(BaseModel):
    id: int
    owner: str
    title: str
    body: str

users: dict[str, str] = {}
tokens: dict[str, str] = {}
notes: dict[int, dict] = {}
next_id = 1

app = FastAPI(title="Notes API")


def hash_password(password: str) -> str:
    salt = secrets.token_bytes(16)
    digest = hashlib.scrypt(password.encode(), salt=salt, **SCRYPT)
    return f"scrypt${salt.hex()}${digest.hex()}"


def verify_password(password: str, stored: str) -> bool:
    _, salt_hex, digest_hex = stored.split("$")
    digest = hashlib.scrypt(password.encode(), salt=bytes.fromhex(salt_hex), **SCRYPT)
    return hmac.compare_digest(digest.hex(), digest_hex)


def current_user(authorization: str = Header(default="")) -> str:
    scheme, _, token = authorization.partition(" ")
    username = tokens.get(token) if scheme.lower() == "bearer" else None
    if username is None:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "Missing or invalid token",
                            headers={"WWW-Authenticate": "Bearer"})
    return username


def owned_note(note_id: int, user: str) -> dict:
    note = notes.get(note_id)
    if note is None:
        raise HTTPException(status.HTTP_404_NOT_FOUND, "Note not found")
    if note["owner"] != user:
        raise HTTPException(status.HTTP_403_FORBIDDEN, "You can only change your own notes")
    return note


@app.post("/signup", status_code=status.HTTP_201_CREATED)
def signup(creds: Credentials):
    if creds.username in users:
        raise HTTPException(status.HTTP_409_CONFLICT, "That username is taken")
    users[creds.username] = hash_password(creds.password)
    return {"username": creds.username}


@app.post("/login")
def login(creds: Credentials):
    stored = users.get(creds.username)
    if stored is None or not verify_password(creds.password, stored):
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "Wrong username or password")
    token = secrets.token_urlsafe(32)
    tokens[token] = creds.username
    return {"token": token, "token_type": "bearer"}


@app.get("/me")
def me(user: str = Depends(current_user)):
    return {"username": user}


@app.post("/notes", status_code=status.HTTP_201_CREATED, response_model=NoteOut)
def create_note(note: NoteIn, user: str = Depends(current_user)):
    global next_id
    saved = {"id": next_id, "owner": user, **note.model_dump()}
    notes[next_id] = saved
    next_id += 1
    return saved


@app.get("/notes", response_model=list[NoteOut])
def list_notes(user: str = Depends(current_user)):
    return [n for n in notes.values() if n["owner"] == user]


@app.patch("/notes/{note_id}", response_model=NoteOut)
def edit_note(note_id: int, note: NoteIn, user: str = Depends(current_user)):
    saved = owned_note(note_id, user)
    saved.update(note.model_dump())
    return saved


@app.delete("/notes/{note_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_note(note_id: int, user: str = Depends(current_user)):
    owned_note(note_id, user)
    del notes[note_id]
```

Start it with `fastapi dev main.py`, then try the flow by hand from your client terminal. Log in, copy the token from the response, and send it back:

```bash
curl -i -X POST http://127.0.0.1:8000/signup -H "Content-Type: application/json" -d '{"username": "ana", "password": "correct horse"}'
curl -i -X POST http://127.0.0.1:8000/login -H "Content-Type: application/json" -d '{"username": "ana", "password": "correct horse"}'

```

The tokens live in a dictionary, so restarting the server (which `fastapi dev` does every time you save) logs everyone out. Storing users and tokens in SQLite, next module, fixes that.

:::quiz
Q: Why does `NoteIn` have no `owner` field, when every saved note has one?
- [ ] Pydantic can't validate usernames
  It can, as `Credentials` shows. The issue is who gets to decide the value.
- [x] The owner must come from the verified token, never from data the client chose
  If the body could set `owner`, anyone could create or move notes into someone else's account.
- [ ] To make the JSON smaller
  Size has nothing to do with it; this is about trust.

Q: Why is the ownership check in a helper, `owned_note`, instead of written inline in each route?
- [ ] FastAPI requires checks to be in separate functions
  It doesn't; inline checks work, they're just easy to get inconsistent.
- [x] So edit and delete apply the exact same 404 and 403 rules, and a new route can reuse them
  One function, one rule. Copies of a security check tend to drift apart.
- [ ] Helpers run faster than inline code
  The speed is the same. This is about keeping the rule in one place.

Q: Login fails. Why does the API say "Wrong username or password" instead of "No user named ana"?
- [ ] Because the server doesn't know which part was wrong
  It does know. It chooses not to say.
- [x] So an attacker can't use the login form to find out which usernames exist
  A vague message gives away less. (Sign-up still reveals taken names, a trade-off most apps accept.)
- [ ] HTTP requires that exact wording for 401
  The status code is standard; the message text is up to you.
:::

:::takeaways
- The owner of a record comes from the token, never from the request body. `extra="forbid"` rejects attempts to sneak it in.
- Store `scrypt$salt$hash`, verify with `hmac.compare_digest`, and give the same error for unknown users and wrong passwords.
- `secrets.token_urlsafe(32)` makes an unguessable bearer token; a `current_user` dependency turns it back into a username or a 401.
- Put the 404 and 403 checks in one helper and call it from every route that touches a single record.
- Write a test for each security rule, especially "another user can't edit or delete my record".
:::

## Ideas to extend it

- Add `POST /logout` that deletes the caller's token from `tokens`, and a test that the old token then gets 401.
- Give tokens an expiry: store `(username, expires_at)` and reject tokens older than an hour.
- Store `hashlib.sha256(token.encode()).hexdigest()` as the dictionary key instead of the raw token, so a leaked token table can't be used directly.
