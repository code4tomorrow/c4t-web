:::objectives
- Write a FastAPI app with two routes and start it with `fastapi dev main.py`.
- Read the startup output and the one-line log each request leaves behind.
- Call the same route four ways: browser, `curl -i`, the `/docs` page, and `TestClient`.
- Fix "address already in use", a wrong file name, and a server that didn't reload.
:::

Here's the finish line for this lesson. You type a URL into a second terminal, and your own code answers:

```text
HTTP/1.1 200 OK
date: Mon, 16 Nov 2026 04:34:02 GMT
server: uvicorn
content-length: 32
content-type: application/json

{"message":"Hello from FastAPI"}
```

That is a complete HTTP response: a status line, some headers, a blank line, and a body. You'll take it apart properly in Module 2. For now, the goal is to make one.

## Step 1: Write the app

Inside `backend-course`, make a folder called `hello` and a file inside it called `main.py`:

```python title="hello/main.py"
from fastapi import FastAPI

app = FastAPI()


@app.get("/")
def read_root():
    return {"message": "Hello from FastAPI"}


@app.get("/hello/{name}")
def hello(name: str):
    return {"greeting": f"Hello, {name}"}
```

Three things are going on. `app = FastAPI()` creates the application object the server will look for. `@app.get("/")` registers the function below it as the handler for **GET requests to the path `/`**. And whatever you return (here a dict) is converted to JSON for you.

The second route has `{name}` in its path. That's a **path parameter**: whatever the client puts in that spot arrives as the `name` argument. Running this file with the play button prints nothing, because it only defines things. A server has to load it.

## Step 2: Start the server

In the VS Code terminal, with `(.venv)` showing:

```bash
cd hello
fastapi dev main.py
```

FastAPI prints a block like this (trimmed here):

```text
   FastAPI   Starting development server

      code   Importing the FastAPI app object from the module with the following
             code:

             from main import app

    server   Server started at http://127.0.0.1:8000
    server   Documentation at http://127.0.0.1:8000/docs

      INFO   Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
      INFO   Started reloader process [65421] using WatchFiles
      INFO   Application startup complete.
```

Read it top to bottom. FastAPI found `app` inside `main.py`, Uvicorn is listening at `127.0.0.1` (your own computer, also called `localhost`) on port `8000`, and a **reloader** is watching your files. The terminal is now busy serving, so it won't take new commands until you press **Ctrl+C**.

## Step 3: Visit it in a browser

Open [http://127.0.0.1:8000](http://127.0.0.1:8000). The page shows `{"message":"Hello from FastAPI"}`. Now try `http://127.0.0.1:8000/hello/Ada`, and then a path that doesn't exist, such as `/nope`.

Look back at the server terminal. Each visit left a line:

```text
      INFO   127.0.0.1:52426 - "GET / HTTP/1.1" 200
      INFO   127.0.0.1:52428 - "GET /hello/Ada HTTP/1.1" 200
      INFO   127.0.0.1:52430 - "GET /nope HTTP/1.1" 404
```

That line is the server's view of the conversation: who asked, the method, the path, and the status code it sent back. `/nope` got `404` and the body `{"detail":"Not Found"}`, because no route matches that path. When something goes wrong later in the course, this log is the first place to look.

## Step 4: Ask with curl

The first terminal is running the server, so open a second one with the **+** button in the terminal panel. curl doesn't need the virtual environment, so it works straight away:

:::tabs
@tab Windows
```powershell
curl.exe -i http://127.0.0.1:8000/hello/Ada
```
@tab macOS
```bash
curl -i http://127.0.0.1:8000/hello/Ada
```
@tab Chromebook / Linux
```bash
curl -i http://127.0.0.1:8000/hello/Ada
```
:::

```text
HTTP/1.1 200 OK
date: Mon, 16 Nov 2026 04:37:12 GMT
server: uvicorn
content-length: 25
content-type: application/json

{"greeting":"Hello, Ada"}
```

The `-i` flag means "include the headers". Without it, curl prints only the body. With it, you can see that the server said `200 OK`, that it was Uvicorn, and that the body is `application/json`, 25 bytes long. The browser received the same headers; it just didn't show them.

## Step 5: Change the code while it runs

Edit the greeting to `f"Hi there, {name}"` and **save**. Among a few other lines, the server terminal prints:

```text
   WARNING   WatchFiles detected changes in 'main.py'. Reloading...
      INFO   Application startup complete.
```

Run the curl command again and you get the new text. That reload is what the `dev` in `fastapi dev` buys you. No save, no reload: if your change isn't showing up, check the file tab in VS Code for the dot that means "unsaved".

## Step 6: Use the /docs page

Open [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs). FastAPI built this page from your code: both routes are listed, with their methods and parameters. Click **GET /hello/{name}**, then **Try it out**, type a name, and click **Execute**.

The page sends a real request to your server and shows the curl command it used, the request URL, the status code, the response body, and the response headers. It's the fastest way to test a route that needs a request body, which you'll do in Module 4. There's a second docs style at `/redoc`, and the raw description both are built from lives at `/openapi.json`.

## Step 7: Call the app from Python with TestClient

The last way to talk to your app skips the server entirely. `TestClient` hands a request straight to the `app` object and gives you back the response, so it works even when nothing is running. This course uses it for every runnable example and for your tests.

```python run title="hello/check_hello.py"
from fastapi import FastAPI
from fastapi.testclient import TestClient

app = FastAPI()


@app.get("/")
def read_root():
    return {"message": "Hello from FastAPI"}


@app.get("/hello/{name}")
def hello(name: str):
    return {"greeting": f"Hello, {name}"}


client = TestClient(app)
for path in ["/", "/hello/Ada", "/hello/Grace%20Hopper", "/nope"]:
    response = client.get(path)
    print(response.status_code, path, "->", response.json())
```

`client.get(path)` returns a response object with `.status_code`, `.headers`, and `.json()`. Notice `%20` in the third path: URLs can't contain spaces, so a space travels as `%20`, and FastAPI decodes it before your function sees it. In your own project you'd write `from main import app` instead of copying the routes, which is exactly how the tests in Module 4 start.

## When it doesn't work

:::warning `[Errno 48] Address already in use` (or `Errno 98`, or `WinError 10048`)
Another server already holds port 8000, usually one you started earlier in another terminal. Find that terminal and press Ctrl+C, or start this one on a different port with `fastapi dev main.py --port 8001`.
:::

:::warning `Path does not exist mian.py`
The CLI couldn't find the file you named. Check the spelling, and check that the terminal is in the folder that holds `main.py`: run `cd hello` first, or start it from the course folder with `fastapi dev hello/main.py`.
:::

:::warning The browser says "This site can't be reached"
Nothing is listening at that address. The server isn't running (look for `Application startup complete.`), or you typed `https://` instead of `http://`. The development server doesn't do HTTPS.
:::

:::quiz
Q: You change the greeting, refresh the browser, and still see the old text. The server terminal shows no "Reloading" message. What happened?
- [ ] The browser cached the page
  Possible in general, but the missing reload message points at the file, not the browser.
- [x] The file wasn't saved, so the reloader never noticed a change
  WatchFiles reacts to saved files. Save, and the reload message appears.
- [ ] `fastapi dev` only reloads once
  It reloads on every saved change until you stop it.

Q: You visit `http://127.0.0.1:8000/hello` with no name. What comes back?
- [ ] `{"greeting": "Hello, "}`
  The route needs something in the `{name}` slot; an empty slot doesn't match.
- [x] `404` with `{"detail":"Not Found"}`
  `/hello` and `/hello/{name}` are different paths, and no route was registered for `/hello` alone.
- [ ] `500 Internal Server Error`
  Nothing crashed. The server just had no route for that path.

Q: Your server is stopped. Does `client.get("/")` from TestClient still work?
- [x] Yes, because TestClient passes the request straight to the `app` object in the same Python process
  No network and no Uvicorn are involved, which is why it's handy for tests.
- [ ] No, it needs Uvicorn running on port 8000
  That's true for curl and the browser, which go over the network. TestClient doesn't.
:::

:::takeaways
- `@app.get("/path")` connects a method and a path to a function, and a returned dict becomes JSON.
- `fastapi dev main.py` starts Uvicorn on `http://127.0.0.1:8000` and reloads every time you save.
- The server terminal logs every request with its method, path, and status code.
- Browser, `curl -i`, `/docs`, and TestClient are four ways to send the same request. curl shows headers; TestClient needs no server.
:::
