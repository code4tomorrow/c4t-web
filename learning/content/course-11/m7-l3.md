summary: Prove a connection dependency always cleans up, turn constraint failures into clear 409s, page through results, format 422 errors and token failures in JavaScript, nest related rows in JSON, and give every error one shape.
---

:::objectives
- Show that a `yield` dependency cleans up after success, an `HTTPException`, and a crash.
- Translate `sqlite3.IntegrityError` messages into specific 409 responses with one handler.
- Paginate a list with validated `limit` and `offset` query parameters.
- Turn FastAPI's 422 `detail` list into per-field messages, and handle 401 and network failures in a front end.
- Assemble nested JSON from two tables, and give every error response the same shape.
:::

## Warm-up: which layer caught it?

For each failure, name the layer that notices first (page, FastAPI/Pydantic, your route code, or SQLite) and the status the page ends up seeing.

1. `GET /api/notes/abc` when the route expects `note_id: int`.
2. Signing up a second member with an email that's already in a `UNIQUE` column, with no `try`/`except` and no handler.
3. The same thing, with the route catching `sqlite3.IntegrityError`.
4. The laptop's Wi-Fi is off when the user clicks **Save**.
5. `GET /api/notes/42` and the `SELECT` returns no row.

:::solution
1. **FastAPI/Pydantic**, 422: path parameters are validated before your function runs.
2. **SQLite** raises `IntegrityError`; nobody translates it, so it becomes a **500**.
3. **SQLite** notices, **your route** translates it into a **409** with a message.
4. **The page**: `fetch` itself rejects, so no status at all. Your `catch` should say the server can't be reached.
5. **Your route**: SQLite happily returns zero rows; it's your code that decides that means **404**.
:::

### Exercise 1: Prove the connection always closes

Write a `get_db` dependency that records every connection it opens and closes, and three routes that use it: one that succeeds, one that raises `HTTPException(404)`, and one with a bug in its SQL. Call all three with `TestClient(app, raise_server_exceptions=False)` and show that opens and closes always match.

```text
/ok       200  opened=1 closed=1
/missing  404  opened=2 closed=2
/bug      500  opened=3 closed=3
```

:::hint
Append to two lists, one before `yield` and one in the `finally` block. `raise_server_exceptions=False` makes `TestClient` return the 500 response the way a real server would, instead of re-raising the error in your test.
:::

:::solution
```python run title="ex1_cleanup.py"
import sqlite3
from fastapi import Depends, FastAPI, HTTPException
from fastapi.testclient import TestClient

opened, closed = [], []

def get_db():
    conn = sqlite3.connect(":memory:", check_same_thread=False)
    opened.append(1)
    try:
        yield conn
    finally:
        conn.close()
        closed.append(1)

app = FastAPI()

@app.get("/ok")
def ok(db: sqlite3.Connection = Depends(get_db)):
    return {"answer": db.execute("SELECT 6 * 7").fetchone()[0]}

@app.get("/missing")
def missing(db: sqlite3.Connection = Depends(get_db)):
    raise HTTPException(404, "Nothing here")

@app.get("/bug")
def bug(db: sqlite3.Connection = Depends(get_db)):
    return db.execute("SELECT * FROM no_such_table").fetchall()

client = TestClient(app, raise_server_exceptions=False)
for path in ["/ok", "/missing", "/bug"]:
    r = client.get(path)
    print(f"{path:9} {r.status_code}  opened={len(opened)} closed={len(closed)}")
```

The `finally` block runs however the request ends. Without `try`/`finally`, the crash in `/bug` would skip the cleanup line, and a busy server would slowly pile up open connections and file handles.
:::

### Exercise 2: One handler for every constraint failure

Instead of wrapping each insert in `try`/`except`, register one exception handler for `sqlite3.IntegrityError` that returns 409 with a message based on which rule failed: a single-column `UNIQUE`, a multi-column `UNIQUE`, or a `FOREIGN KEY`.

```text
{'id': 1}
409 {'detail': 'That email is already taken'}
201 {'member_id': 1, 'event_id': 1}
409 {'detail': 'That member_id + event_id combination already exists'}
409 {'detail': "That refers to something that doesn't exist"}
```

:::hint
`str(exc)` holds SQLite's message, such as `UNIQUE constraint failed: members.email` or `FOREIGN KEY constraint failed`. Strip the prefix, split on `", "`, and take the part after each dot. A handler is a function decorated with `@app.exception_handler(sqlite3.IntegrityError)` that returns a `JSONResponse`.
:::

:::solution
```python run title="ex2_conflicts.py"
import sqlite3
from fastapi import Depends, FastAPI, Request
from fastapi.responses import JSONResponse
from fastapi.testclient import TestClient
from pydantic import BaseModel

DB = "club.db"
with sqlite3.connect(DB) as conn:
    conn.executescript("""
        CREATE TABLE IF NOT EXISTS members (id INTEGER PRIMARY KEY, email TEXT NOT NULL UNIQUE);
        CREATE TABLE IF NOT EXISTS events (id INTEGER PRIMARY KEY, name TEXT NOT NULL);
        CREATE TABLE IF NOT EXISTS signups (
            member_id INTEGER NOT NULL REFERENCES members(id),
            event_id  INTEGER NOT NULL REFERENCES events(id),
            PRIMARY KEY (member_id, event_id));
        INSERT INTO events (name) VALUES ('Hackathon');
    """)

def get_db():
    conn = sqlite3.connect(DB, check_same_thread=False)
    conn.execute("PRAGMA foreign_keys = ON")
    try:
        yield conn
    finally:
        conn.close()

app = FastAPI()

@app.exception_handler(sqlite3.IntegrityError)
def integrity_error(request: Request, exc: sqlite3.IntegrityError):
    message = str(exc)
    if message.startswith("UNIQUE constraint failed: "):
        columns = message.removeprefix("UNIQUE constraint failed: ").split(", ")
        fields = [column.split(".")[1] for column in columns]
        if len(fields) == 1:
            detail = f"That {fields[0]} is already taken"
        else:
            detail = f"That {' + '.join(fields)} combination already exists"
    elif message.startswith("FOREIGN KEY"):
        detail = "That refers to something that doesn't exist"
    else:
        detail = "That conflicts with data already saved"
    return JSONResponse(status_code=409, content={"detail": detail})

class MemberIn(BaseModel):
    email: str

@app.post("/api/members", status_code=201)
def add_member(member: MemberIn, db: sqlite3.Connection = Depends(get_db)):
    with db:
        cur = db.execute("INSERT INTO members (email) VALUES (?)", (member.email,))
    return {"id": cur.lastrowid}

@app.post("/api/events/{event_id}/signups/{member_id}", status_code=201)
def sign_up(event_id: int, member_id: int, db: sqlite3.Connection = Depends(get_db)):
    with db:
        db.execute("INSERT INTO signups VALUES (?, ?)", (member_id, event_id))
    return {"member_id": member_id, "event_id": event_id}

client = TestClient(app)
print(client.post("/api/members", json={"email": "maya@club.org"}).json())
for r in [
    client.post("/api/members", json={"email": "maya@club.org"}),
    client.post("/api/events/1/signups/1"),
    client.post("/api/events/1/signups/1"),
    client.post("/api/events/1/signups/99"),
]:
    print(r.status_code, r.json())
```

Routes stay short because none of them mention errors. The `with db:` block rolls the failed insert back before the exception reaches the handler, so nothing half-written is left behind. Messages built from column names are fine for a club app; a public product would map each constraint to hand-written wording.
:::

### Exercise 3: Page through a long list

`GET /api/books?limit=2&offset=0` should return one page of books in title order, plus `total` and `next_offset` (or `null` on the last page). Reject `limit` above 50 with a 422. Then walk every page from Python until `next_offset` is `None`.

```text
['Dune', 'Hatchet'] next_offset: 2
['Holes', 'Matilda'] next_offset: 4
['Wonder'] next_offset: None
422 Input should be less than or equal to 50
```

:::hint
`limit: int = Query(default=2, ge=1, le=50)` validates the query parameter. SQL's `LIMIT ? OFFSET ?` takes both as placeholders. Sort by something unique at the end (`ORDER BY title, id`), or rows with equal titles could swap places between pages.
:::

:::solution
```python run title="ex3_pages.py"
import sqlite3
from fastapi import Depends, FastAPI, Query
from fastapi.testclient import TestClient
from pydantic import BaseModel

DB = "books.db"
with sqlite3.connect(DB) as conn:
    conn.execute("CREATE TABLE IF NOT EXISTS books (id INTEGER PRIMARY KEY, title TEXT NOT NULL)")
    conn.executemany("INSERT INTO books (title) VALUES (?)",
                     [(t,) for t in ["Dune", "Hatchet", "Holes", "Matilda", "Wonder"]])

def get_db():
    conn = sqlite3.connect(DB, check_same_thread=False)
    conn.row_factory = sqlite3.Row
    try:
        yield conn
    finally:
        conn.close()

class Book(BaseModel):
    id: int
    title: str

class BookPage(BaseModel):
    items: list[Book]
    total: int
    next_offset: int | None

app = FastAPI()

@app.get("/api/books", response_model=BookPage)
def list_books(
    limit: int = Query(default=2, ge=1, le=50),
    offset: int = Query(default=0, ge=0),
    db: sqlite3.Connection = Depends(get_db),
):
    total = db.execute("SELECT COUNT(*) FROM books").fetchone()[0]
    rows = db.execute(
        "SELECT id, title FROM books ORDER BY title, id LIMIT ? OFFSET ?", (limit, offset)
    ).fetchall()
    next_offset = offset + limit if offset + limit < total else None
    return {"items": [dict(r) for r in rows], "total": total, "next_offset": next_offset}

client = TestClient(app)
offset = 0
while offset is not None:
    page = client.get("/api/books", params={"limit": 2, "offset": offset}).json()
    print([b["title"] for b in page["items"]], "next_offset:", page["next_offset"])
    offset = page["next_offset"]
r = client.get("/api/books", params={"limit": 500})
print(r.status_code, r.json()["detail"][0]["msg"])
```

The upper limit on `limit` is a protection, not a nicety: without it, one request for `limit=100000000` makes the server load the whole table into memory.
:::

### Exercise 4: Put each 422 message next to its field

A form needs a message under each input, not one long sentence. Write `fieldErrors(detail)` that turns FastAPI's 422 list into an object keyed by field name. Nested locations like `["body", "tags", 2]` (the third tag) should read as `item 3`, and a missing body (`["body"]`) should land under `request`.

```text
{
  title: 'String should have at least 1 character',
  priority: 'Input should be less than or equal to 3',
  tags: 'item 3: Input should be a valid string; item 4: String should have at most 20 characters'
}
{ request: 'Field required' }
```

:::hint
Drop the first element of `loc` (it's always `"body"`, `"query"`, or `"path"`). The next element is the field; anything after it describes where inside the field. Numbers in `loc` are zero-based list positions.
:::

:::solution
```javascript run title="field_errors.js"
function fieldErrors(detail) {
  const errors = {};
  for (const error of detail) {
    const path = error.loc.slice(1); // drop "body", "query", or "path"
    const field = String(path[0] ?? "request");
    const where = path.slice(1).map((part) => (typeof part === "number" ? `item ${part + 1}` : part));
    const text = where.length ? `${where.join(" ")}: ${error.msg}` : error.msg;
    errors[field] = errors[field] ? `${errors[field]}; ${text}` : text;
  }
  return errors;
}

// 422 bodies in the shape FastAPI sends, for a model with title, priority, and tags
const detail = [
  { type: "string_too_short", loc: ["body", "title"], msg: "String should have at least 1 character" },
  { type: "less_than_equal", loc: ["body", "priority"], msg: "Input should be less than or equal to 3" },
  { type: "string_type", loc: ["body", "tags", 2], msg: "Input should be a valid string" },
  { type: "string_too_long", loc: ["body", "tags", 3], msg: "String should have at most 20 characters" },
];
console.log(fieldErrors(detail));
console.log(fieldErrors([{ type: "missing", loc: ["body"], msg: "Field required" }]));
```

In the page, loop over the result and set the `textContent` of an element like `<small id="title-error">` under each input. Fields with no entry get their message cleared, so old errors disappear when they're fixed.
:::

### Exercise 5: A front end that knows about tokens

Extend the page's `api()` helper for an API with logins. It should send `Authorization: Bearer <token>` when a token is saved in `sessionStorage`, forget the token and ask the user to log in again on a 401, and give a clear message when the server can't be reached at all. Throw an error that carries the status, so the page can decide whether to show the login form.

```text
no token -> 401 Please log in again. | token kept: null
logged in -> [{"id":1,"title":"Diary"}]
old token -> 401 Please log in again. | token kept: null
server down -> 0 Can't reach the server. Check your connection and try again. | token kept: abc123
```

:::hint
Make a small `class ApiError extends Error` with a `status` property. Wrap only the `fetch` call in `try`/`catch` (that's the network failure); check `response.status` after it. Be careful with `/api/login` itself: there, a 401 means "wrong password", not "your session ended".
:::

:::solution
```javascript run title="api_with_token.js"
// Stand-ins so this runs in Node: a pretend server and a pretend sessionStorage.
const storage = new Map();
const sessionStorage = {
  getItem: (k) => (storage.has(k) ? storage.get(k) : null),
  setItem: (k, v) => storage.set(k, String(v)),
  removeItem: (k) => storage.delete(k),
};
let serverDown = false;
async function fetch(path, options = {}) {
  if (serverDown) throw new TypeError("Failed to fetch");
  if (path === "/api/login") return Response.json({ token: "abc123" });
  if (options.headers?.Authorization !== "Bearer abc123") {
    return Response.json({ detail: "Missing or invalid token" }, { status: 401 });
  }
  return Response.json([{ id: 1, title: "Diary" }]);
}

class ApiError extends Error {
  constructor(message, status) {
    super(message);
    this.status = status;
  }
}

async function api(method, path, data) {
  const headers = {};
  const token = sessionStorage.getItem("token");
  if (token) headers.Authorization = `Bearer ${token}`;
  if (data !== undefined) headers["Content-Type"] = "application/json";

  let response;
  try {
    response = await fetch(path, {
      method, headers, body: data === undefined ? undefined : JSON.stringify(data),
    });
  } catch {
    throw new ApiError("Can't reach the server. Check your connection and try again.", 0);
  }
  const isJson = (response.headers.get("Content-Type") || "").includes("application/json");
  const body = isJson ? await response.json() : null;
  if (response.status === 401 && path !== "/api/login") {
    sessionStorage.removeItem("token");
    throw new ApiError("Please log in again.", 401);
  }
  if (!response.ok) {
    const message = typeof body?.detail === "string" ? body.detail : `Request failed (${response.status})`;
    throw new ApiError(message, response.status);
  }
  return body;
}

async function attempt(label) {
  try {
    console.log(label, "->", JSON.stringify(await api("GET", "/api/notes")));
  } catch (error) {
    console.log(label, "->", error.status, error.message, "| token kept:", sessionStorage.getItem("token"));
  }
}

async function main() {
  await attempt("no token");
  const { token } = await api("POST", "/api/login", { username: "ana", password: "correct horse" });
  sessionStorage.setItem("token", token);
  await attempt("logged in");
  sessionStorage.setItem("token", "expired-token");
  await attempt("old token");
  sessionStorage.setItem("token", token);
  serverDown = true;
  await attempt("server down");
}
main();
```

When the server is down the token is kept, because nothing proved it was bad; the user just needs to retry. `sessionStorage` is cleared when the tab closes, which is a reasonable default for a school project. Any script running on your page can read it, which is one more reason to never insert user data with `innerHTML`.
:::

### Exercise 6: Return an event with its attendees nested inside

`GET /api/events/1` should return the event's fields plus `going` (a count) and `attendees` (a list of `{id, name}`, sorted by name). An event nobody has joined returns an empty list, and an unknown id returns 404.

```text
{'id': 1, 'name': 'Hackathon', 'day': '2026-10-03', 'going': 3, 'attendees': [{'id': 2, 'name': 'Leo'}, {'id': 1, 'name': 'Maya'}, {'id': 3, 'name': 'Priya'}]}
{'id': 2, 'name': 'Field trip', 'day': '2026-11-07', 'going': 0, 'attendees': []}
404
```

:::hint
Two queries are clearer than one here: one `SELECT` for the event (404 if it's missing), then a `JOIN` of `signups` and `members` for the attendees. Describe the nested shape with two Pydantic models, one inside the other, and use the outer one as `response_model`.
:::

:::solution
```python run title="ex6_nested.py"
import sqlite3
from fastapi import Depends, FastAPI, HTTPException
from fastapi.testclient import TestClient
from pydantic import BaseModel

DB = "events.db"
with sqlite3.connect(DB) as conn:
    conn.executescript("""
        CREATE TABLE members (id INTEGER PRIMARY KEY, name TEXT NOT NULL);
        CREATE TABLE events  (id INTEGER PRIMARY KEY, name TEXT NOT NULL, day TEXT NOT NULL);
        CREATE TABLE signups (
            member_id INTEGER NOT NULL REFERENCES members(id),
            event_id  INTEGER NOT NULL REFERENCES events(id),
            PRIMARY KEY (member_id, event_id));
        INSERT INTO members (name) VALUES ('Maya'), ('Leo'), ('Priya');
        INSERT INTO events (name, day) VALUES ('Hackathon', '2026-10-03'), ('Field trip', '2026-11-07');
        INSERT INTO signups VALUES (1, 1), (3, 1), (2, 1);
    """)

def get_db():
    conn = sqlite3.connect(DB, check_same_thread=False)
    conn.row_factory = sqlite3.Row
    try:
        yield conn
    finally:
        conn.close()

class Attendee(BaseModel):
    id: int
    name: str

class EventDetail(BaseModel):
    id: int
    name: str
    day: str
    going: int
    attendees: list[Attendee]

app = FastAPI()

@app.get("/api/events/{event_id}", response_model=EventDetail)
def event_detail(event_id: int, db: sqlite3.Connection = Depends(get_db)):
    event = db.execute("SELECT id, name, day FROM events WHERE id = ?", (event_id,)).fetchone()
    if event is None:
        raise HTTPException(404, "No event with that id")
    people = db.execute(
        """SELECT members.id, members.name
           FROM signups JOIN members ON members.id = signups.member_id
           WHERE signups.event_id = ?
           ORDER BY members.name""",
        (event_id,),
    ).fetchall()
    attendees = [dict(p) for p in people]
    return {**dict(event), "going": len(attendees), "attendees": attendees}

client = TestClient(app)
print(client.get("/api/events/1").json())
print(client.get("/api/events/2").json())
print(client.get("/api/events/9").status_code)
```

Tables are flat and JSON is nested, and the route is where one turns into the other. A single `LEFT JOIN` could fetch everything at once, but it repeats the event's columns on every attendee row and needs Python to regroup them. For one event, two small queries are simpler and just as fast.
:::

### Challenge: Give every error the same shape

The page has to handle `detail` as a string sometimes and a list other times, and a 500 isn't JSON at all. Make every error, from any source, look like `{"error": {"status": ..., "message": ..., "fields": {...}}}`, with `fields` only on validation errors. Cover `HTTPException`, unknown URLs, validation errors in the body and in the path, and an unexpected crash. The crash must still be logged on the server, with only a polite message sent to the client.

```mermaid caption="Three handlers, one shape. Every failure leaves the API as the same kind of JSON."
flowchart LR
    A["HTTPException, unknown URL"] --> H1["http_error"]
    B["RequestValidationError"] --> H2["validation_error"]
    C["any other Exception"] --> H3["unexpected_error"]
    H1 --> J["{error: {status, message}}"]
    H2 --> J2["{error: {status, message, fields}}"]
    H3 --> L["server log"]
    H3 --> J
```

:::hint
Register the `HTTPException` handler for `starlette.exceptions.HTTPException`, not FastAPI's subclass, so it also catches the 404 for URLs that match no route. `RequestValidationError` comes from `fastapi.exceptions`, and `exc.errors()` gives the same list you saw in 422 responses. A handler for `Exception` covers the rest.
:::

:::solution
```python run title="one_error_shape.py"
from fastapi import FastAPI, HTTPException, Request
from fastapi.exceptions import RequestValidationError
from fastapi.responses import JSONResponse
from fastapi.testclient import TestClient
from pydantic import BaseModel, Field
from starlette.exceptions import HTTPException as StarletteHTTPException

app = FastAPI()

def error_body(status, message, fields=None):
    error = {"status": status, "message": message}
    if fields:
        error["fields"] = fields
    return JSONResponse(status_code=status, content={"error": error})

@app.exception_handler(StarletteHTTPException)
def http_error(request: Request, exc: StarletteHTTPException):
    return error_body(exc.status_code, str(exc.detail))

@app.exception_handler(RequestValidationError)
def validation_error(request: Request, exc: RequestValidationError):
    fields = {}
    for e in exc.errors():
        name = ".".join(str(part) for part in e["loc"][1:]) or "request"
        fields[name] = e["msg"]
    return error_body(422, "Some fields need fixing", fields)

@app.exception_handler(Exception)
def unexpected_error(request: Request, exc: Exception):
    print(f"  [server log] {type(exc).__name__}: {exc}")
    return error_body(500, "Something went wrong on our side. Please try again.")

class NoteIn(BaseModel):
    title: str = Field(min_length=1)

@app.post("/api/notes", status_code=201)
def create(note: NoteIn):
    return note

@app.get("/api/notes/{note_id}")
def read(note_id: int):
    raise HTTPException(404, "Note not found")

@app.get("/api/bug")
def bug():
    return {"ratio": 1 / 0}

client = TestClient(app, raise_server_exceptions=False)
for method, path, body in [
    ("GET", "/api/notes/5", None),
    ("GET", "/api/notes/abc", None),
    ("POST", "/api/notes", {"title": ""}),
    ("GET", "/api/nowhere", None),
    ("GET", "/api/bug", None),
]:
    r = client.request(method, path, json=body)
    print(method, path, r.status_code, r.json())
```

Now the page's `messageFrom` shrinks to `body.error.message`, and a form can read `body.error.fields` directly. The `[server log]` line stands in for real logging: in a project, use Python's `logging` module so the traceback lands in the server's output while the client sees only the polite sentence. If you change the error shape, write it down in your API's documentation, since every client depends on it.
:::
