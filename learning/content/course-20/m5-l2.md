The last lesson ended on a weak spot: the fully connected network fell apart when the test digits moved one pixel. Here you build the fix and measure how much it helps. This is the network:

## Step 1: Split the data and make shifted test sets

Three splits this time. Training data fits the weights, validation data is for choices like the number of epochs, and the test set is looked at once, at the end.

```python run
import torch
import torch.nn as nn
import torch.nn.functional as F
import matplotlib.pyplot as plt
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split

digits = load_digits()
X = torch.tensor(digits.images, dtype=torch.float32).unsqueeze(1) / 16
y = torch.tensor(digits.target)
X_train, X_rest, y_train, y_rest = train_test_split(X, y, test_size=0.4, random_state=0, stratify=y)
X_val, X_test, y_val, y_test = train_test_split(X_rest, y_rest, test_size=0.5, random_state=0, stratify=y_rest)
print("train", tuple(X_train.shape), " val", tuple(X_val.shape), " test", tuple(X_test.shape))

def shift(images, dx=0, dy=0):
    """Move image content dx pixels right and dy pixels down, filling with zeros."""
    out = torch.zeros_like(images)
    h, w = images.shape[-2:]
    out[..., max(dy, 0):h + min(dy, 0), max(dx, 0):w + min(dx, 0)] = \
        images[..., max(-dy, 0):h - max(dy, 0), max(-dx, 0):w - max(dx, 0)]
    return out

test_sets = {
    "original": X_test,
    "right 1": shift(X_test, dx=1),
    "right 2": shift(X_test, dx=2),
    "down 1": shift(X_test, dy=1),
}
```

Always look at a transformed image before trusting it. A sign error in `shift` would quietly move the digits the wrong way:

```python run alt="Four copies of the same handwritten digit side by side, titled original, right 1, right 2, and down 1. Each copy sits one or two pixels further right or lower than the original." caption="The same test digit in all four test sets"
fig, axes = plt.subplots(1, 4, figsize=(6, 1.8))
for ax, (name, images) in zip(axes, test_sets.items()):
    ax.imshow(images[3, 0], cmap="gray_r", vmin=0, vmax=1)
    ax.set_title(name, fontsize=9)
    ax.set_xticks([])
    ax.set_yticks([])
plt.show()
```

## Step 2: A Dataset that augments one image at a time

A `Dataset` needs two methods: `__len__` and `__getitem__`. Putting the transform inside `__getitem__` means every image gets its own random change each time the `DataLoader` asks for it, which avoids the whole-batch trap from the last lesson.

```python run
from torch.utils.data import Dataset, DataLoader
from torchvision.transforms import v2

class Digits(Dataset):
    def __init__(self, images, labels, transform=None):
        self.images, self.labels, self.transform = images, labels, transform

    def __len__(self):
        return len(self.labels)

    def __getitem__(self, i):
        image = self.images[i]
        if self.transform is not None:
            image = self.transform(image)
        return image, self.labels[i]

image, label = Digits(X_train, y_train)[0]
print(tuple(image.shape), label.item())
```

## Step 3: Define both models and check the shapes

Two builder functions, so we can make fresh copies with a fixed seed later:

```python run
def make_mlp():
    return nn.Sequential(nn.Flatten(), nn.Linear(64, 128), nn.ReLU(), nn.Linear(128, 10))

def make_cnn():
    return nn.Sequential(
        nn.Conv2d(1, 16, kernel_size=3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
        nn.Conv2d(16, 32, kernel_size=3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
        nn.Flatten(),
        nn.Linear(32 * 2 * 2, 10),
    )

x = torch.zeros(5, 1, 8, 8)            # a fake batch of 5 digits
for layer in make_cnn():
    x = layer(x)
    print(f"{layer.__class__.__name__:<10} -> {tuple(x.shape)}")

count = lambda model: sum(p.numel() for p in model.parameters())
print("parameters: MLP", count(make_mlp()), " CNN", count(make_cnn()))
```

Walking a fake batch through the layers one at a time is the fastest way to get `nn.Linear(32 * 2 * 2, 10)` right. Padding 1 keeps each conv's output the same size, and each pool halves it: 8 → 4 → 2. The CNN also has fewer parameters than the MLP, thanks to weight sharing.

## Step 4: One training function for every model

`fit` seeds the random generator **before** building the model, so the same seed gives the same starting weights and the same batch order. It records the average training loss and the validation accuracy after every epoch.

```python run
def accuracy(model, images, labels):
    model.eval()
    with torch.no_grad():
        return (model(images).argmax(1) == labels).float().mean().item()

def fit(make_model, transform=None, epochs=20, lr=1e-3, seed=0):
    torch.manual_seed(seed)
    model = make_model()
    loader = DataLoader(Digits(X_train, y_train, transform), batch_size=64, shuffle=True)
    opt = torch.optim.Adam(model.parameters(), lr=lr)
    history = {"loss": [], "val_acc": []}
    for epoch in range(epochs):
        model.train()
        total, seen = 0.0, 0
        for xb, yb in loader:
            loss = F.cross_entropy(model(xb), yb)
            opt.zero_grad()
            loss.backward()
            opt.step()
            total += loss.item() * len(yb)
            seen += len(yb)
        history["loss"].append(total / seen)
        history["val_acc"].append(accuracy(model, X_val, y_val))
    return model, history

mlp, mlp_hist = fit(make_mlp)
cnn, cnn_hist = fit(make_cnn)
print(f"final val accuracy: MLP {mlp_hist['val_acc'][-1]:.1%}, CNN {cnn_hist['val_acc'][-1]:.1%}")
```

```python run alt="Two line charts. Left: training loss per epoch for the MLP and the CNN, both falling steeply, then flattening. Right: validation accuracy per epoch, both rising quickly and leveling off in the 90s." caption="Training loss and validation accuracy for both models"
fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(8, 3))
for name, hist, color in [("MLP", mlp_hist, "#7892ee"), ("CNN", cnn_hist, "#d9534f")]:
    ax1.plot(hist["loss"], label=name, color=color)
    ax2.plot(hist["val_acc"], label=name, color=color)
ax1.set(title="training loss", xlabel="epoch")
ax2.set(title="validation accuracy", xlabel="epoch", ylim=(0.5, 1.0))
ax1.legend()
for ax in (ax1, ax2):
    ax.spines[["top", "right"]].set_visible(False)
plt.tight_layout()
plt.show()
```

On the original digits the two models are close. If you stopped here, you'd conclude the CNN isn't worth the extra code.

## Step 5: Score both models on the moved digits

```python run
def report(models):
    print(f"{'model':<12}" + "".join(f"{name:>10}" for name in test_sets))
    for label, model in models.items():
        scores = [accuracy(model, images, y_test) for images in test_sets.values()]
        print(f"{label:<12}" + "".join(f"{s:>10.1%}" for s in scores))

report({"MLP": mlp, "CNN": cnn})
```

Now the CNN pulls ahead, but it still loses a lot on shifted digits. Shared kernels make the feature maps move with the digit, yet the final `Linear` layer reads the flattened 2×2 map position by position, and a one-pixel move on an 8-pixel image often crosses a pooling block boundary. The architecture gives tolerance to shifts; it doesn't give immunity.

## Step 6: Add augmentation and train again

If shifted digits are what the model will face, train it on shifted digits. `translate=(0.25, 0.25)` moves each training image by up to a quarter of its width (2 pixels) in each direction, chosen fresh every time it's loaded. First, look at what the model will actually see:

```python run alt="A 3 by 8 grid of 24 augmented training digits, each nudged by up to two pixels in some direction, with its label above it." caption="One batch from the augmented loader"
augment = v2.RandomAffine(degrees=0, translate=(0.25, 0.25))
torch.manual_seed(1)
xb, yb = next(iter(DataLoader(Digits(X_train, y_train, augment), batch_size=24, shuffle=True)))

fig, axes = plt.subplots(3, 8, figsize=(8, 3.6))
for ax, image, label in zip(axes.flat, xb, yb):
    ax.imshow(image[0], cmap="gray_r", vmin=0, vmax=1)
    ax.set_title(str(label.item()), fontsize=8)
    ax.set_xticks([])
    ax.set_yticks([])
plt.tight_layout()
plt.show()
```

Every digit is still readable, and a few are pushed right up against the edge. Now train the same CNN architecture on these, with more epochs because the task got harder:

```python run
cnn_aug, aug_hist = fit(make_cnn, transform=augment, epochs=30)
report({"MLP": mlp, "CNN": cnn, "CNN + aug": cnn_aug})
```

The augmented CNN holds up on every shifted set. It gives up a few points on the original images: it spent some of its capacity learning to handle positions the original test set never uses. That trade-off is normal, and validation accuracy is how you'd tune it (more epochs, a gentler `translate`, or a wider network).

## Step 7: Look at what the CNN learned

The first conv layer's weights have shape (16, 1, 3, 3): sixteen 3×3 kernels. Plot them, and the sixteen feature maps they produce for one test digit:

```python run alt="Top row of 16 tiny 3 by 3 kernels in red and blue, several with one side positive and the other negative like edge detectors. Bottom row of 16 8 by 8 feature maps for a digit, each highlighting different strokes or edges of the digit." caption="First-layer kernels (top) and the feature maps they make for one digit (bottom)"
kernels = cnn_aug[0].weight.detach()[:, 0]                   # (16, 3, 3)
with torch.no_grad():
    maps = F.relu(cnn_aug[0](X_test[3:4]))[0]                # (16, 8, 8)

fig, axes = plt.subplots(2, 16, figsize=(10, 1.6))
for i in range(16):
    limit = kernels[i].abs().max()
    axes[0, i].imshow(kernels[i], cmap="RdBu_r", vmin=-limit, vmax=limit)
    axes[1, i].imshow(maps[i], cmap="magma")
for ax in axes.flat:
    ax.set_xticks([])
    ax.set_yticks([])
axes[0, 0].set_ylabel("kernel", fontsize=8)
axes[1, 0].set_ylabel("map", fontsize=8)
plt.show()
```

Several kernels have a positive side and a negative side, the same shape as the edge filters you built by hand. Each feature map lights up a different part of the digit: some respond to the left edges of strokes, some to the top, some to the inside of loops. Nobody wrote these; gradient descent found them because they help separate the ten classes.

## The finished program

Everything above as one script you can paste into a Colab cell. It picks the GPU when there is one.

```python title="digits_cnn.py"
import torch
import torch.nn as nn
import torch.nn.functional as F
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
from torch.utils.data import Dataset, DataLoader
from torchvision.transforms import v2

device = "cuda" if torch.cuda.is_available() else "cpu"
digits = load_digits()
X = torch.tensor(digits.images, dtype=torch.float32).unsqueeze(1) / 16
y = torch.tensor(digits.target)
X_train, X_rest, y_train, y_rest = train_test_split(X, y, test_size=0.4, random_state=0, stratify=y)
X_val, X_test, y_val, y_test = train_test_split(X_rest, y_rest, test_size=0.5, random_state=0, stratify=y_rest)


def shift(images, dx=0, dy=0):
    out = torch.zeros_like(images)
    h, w = images.shape[-2:]
    out[..., max(dy, 0):h + min(dy, 0), max(dx, 0):w + min(dx, 0)] = \
        images[..., max(-dy, 0):h - max(dy, 0), max(-dx, 0):w - max(dx, 0)]
    return out


class Digits(Dataset):
    def __init__(self, images, labels, transform=None):
        self.images, self.labels, self.transform = images, labels, transform

    def __len__(self):
        return len(self.labels)

    def __getitem__(self, i):
        image = self.images[i]
        if self.transform is not None:
            image = self.transform(image)
        return image, self.labels[i]


def make_cnn():
    return nn.Sequential(
        nn.Conv2d(1, 16, kernel_size=3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
        nn.Conv2d(16, 32, kernel_size=3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
        nn.Flatten(), nn.Linear(32 * 2 * 2, 10),
    )


def accuracy(model, images, labels):
    model.eval()
    with torch.no_grad():
        preds = model(images.to(device)).argmax(1).cpu()
    return (preds == labels).float().mean().item()


def fit(transform=None, epochs=30, lr=1e-3, seed=0):
    torch.manual_seed(seed)
    model = make_cnn().to(device)
    loader = DataLoader(Digits(X_train, y_train, transform), batch_size=64, shuffle=True)
    opt = torch.optim.Adam(model.parameters(), lr=lr)
    for epoch in range(epochs):
        model.train()
        for xb, yb in loader:
            xb, yb = xb.to(device), yb.to(device)
            loss = F.cross_entropy(model(xb), yb)
            opt.zero_grad()
            loss.backward()
            opt.step()
    print(f"val accuracy {accuracy(model, X_val, y_val):.1%}")
    return model


model = fit(transform=v2.RandomAffine(degrees=0, translate=(0.25, 0.25)))
for name, images in [("original", X_test), ("right 1", shift(X_test, dx=1)), ("right 2", shift(X_test, dx=2))]:
    print(f"{name:<9} {accuracy(model, images, y_test):.1%}")
```

:::quiz
Q: Why does the augmentation live inside `Digits.__getitem__` instead of being called on `xb` in the training loop?
- [ ] `__getitem__` runs faster than the training loop
  Speed isn't the reason; calling the transform on a batch would be fewer calls, not more.
- [x] A v2 transform called on a batch applies one random change to every image in it
  Calling it per image gives each digit its own random shift, so the model sees far more variety.
- [ ] `DataLoader` refuses tensors that were transformed outside a `Dataset`
  `DataLoader` doesn't check where tensors came from.

Q: You want to choose between `translate=(0.15, 0.15)` and `translate=(0.25, 0.25)`. Which numbers should decide?
- [x] Validation accuracy, on original and on shifted validation copies
  Choices are made on validation data, so the test set stays an unbiased final check.
- [ ] Test accuracy on the shifted test sets
  Picking settings by test score turns the test set into a second validation set, and the final number becomes optimistic.
- [ ] The lowest final training loss
  Stronger augmentation makes training harder, so training loss will favor the weaker setting regardless of how well it generalizes.

Q: Without augmentation, which part of the CNN makes it sensitive to where the digit sits?
- [ ] The first conv layer
  A conv layer's output shifts along with its input, so it doesn't care where a stroke is.
- [ ] The ReLU activations
  ReLU works on each value separately and doesn't involve position at all.
- [x] The final `Linear` layer reading the flattened 2×2 map
  It has a separate weight for each position in that map, so the same feature in a different block gives a different score.
:::

:::takeaways
- Put random transforms in `Dataset.__getitem__` so each image gets its own random change every epoch.
- Push a fake batch through the layers and print shapes before you train; it's how you size the final `Linear`.
- Seed before building the model so runs you compare start from the same weights and see the same batch order.
- A CNN tolerates small shifts better than an MLP, and augmentation that matches the expected shift closes most of the remaining gap.
- Augmentation can cost a little accuracy on the unchanged data; tune its strength on validation, not test.
:::

## Ideas to extend it

- Add `v2.ColorJitter(contrast=0.5)` to the augmentation and test on a low-contrast copy of the test set (`X_test * 0.6 + 0.3`).
- Replace `nn.Flatten()` and the final `Linear` with `nn.AdaptiveAvgPool2d(1)`, `nn.Flatten()`, and `nn.Linear(32, 10)`, which averages each map over all positions. Does it help with shifts by itself?
- Train on real photos with your Colab GPU. CIFAR-10 has 60,000 color images, 32×32, in 10 classes. Use `nn.Conv2d(3, 16, ...)` for the three color channels, and `nn.Linear(32 * 8 * 8, 10)` because two pools take 32 down to 8. The first run downloads about 170 MB; if Colab shows a download error, run the cell again.

```python
import torch
from torch.utils.data import DataLoader
from torchvision import datasets
from torchvision.transforms import v2

train_tf = v2.Compose([
    v2.ToImage(),
    v2.RandomCrop(32, padding=4),
    v2.RandomHorizontalFlip(),          # a mirrored ship is still a ship
    v2.ToDtype(torch.float32, scale=True),
])
test_tf = v2.Compose([v2.ToImage(), v2.ToDtype(torch.float32, scale=True)])

train_set = datasets.CIFAR10("data", train=True, download=True, transform=train_tf)
test_set = datasets.CIFAR10("data", train=False, download=True, transform=test_tf)
train_loader = DataLoader(train_set, batch_size=128, shuffle=True, num_workers=2)
test_loader = DataLoader(test_set, batch_size=256, num_workers=2)
print(len(train_set), len(test_set), train_set.classes)
```

Unlike digits, a horizontal flip is safe here, which is why it appears in `train_tf`.
