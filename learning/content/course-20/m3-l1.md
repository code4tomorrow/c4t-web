A model has one weight, `w`, and predicts `y = w · x`. The data is four points that lie exactly on `y = 2x`, so the best weight is 2. Start at `w = 0`, compute which way is downhill, step that way, and repeat. Step through it and watch the loss column:

:::trace Gradient descent with a learning rate of 0.2
```python
xs = [1, 2, 3, 4]
ys = [2, 4, 6, 8]
w = 0.0
lr = 0.2
for step in range(3):
    loss = sum((w * x - y) ** 2 for x, y in zip(xs, ys)) / 4
    grad = sum(2 * (w * x - y) * x for x, y in zip(xs, ys)) / 4
    w = w - lr * grad
    print("step", step, "loss", loss, "grad", grad, "new w", w)
```
:::

Every step moves `w` in the downhill direction, exactly as designed, and the loss goes 30, 120, 480. The direction is right and the **scale** is wrong: each step jumps clear over the valley and lands higher up the far side. By the end of this lesson you'll be able to calculate the learning rate where that starts. First, the pieces: what the loss measures, what the gradient is, and how PyTorch computes it.

## A loss turns "how wrong" into one number

Training needs a single number to push down. A **loss function** compares predictions with the truth and returns it.

For predicting quantities (a price, an angle, a box coordinate), the standard choice is **mean squared error**: the average of `(prediction − truth)²`. Squaring makes every miss positive and punishes big misses much more than small ones.

For classification, the model outputs a probability for each class, and **cross-entropy** looks only at the probability given to the right one: the loss is `−log(p_true)`. A confident correct answer (`p_true` near 1) costs almost nothing; a confident wrong one (`p_true` near 0) costs a lot. In PyTorch you hand `F.cross_entropy` the raw **logits**; it applies softmax itself.

```python run
import torch
import torch.nn.functional as F

logits = torch.tensor([[2.0, 0.5, -1.0]])   # one image, three classes
target = torch.tensor([0])                 # the true class is 0

probs = torch.softmax(logits, dim=1)
print("probabilities:", [round(p, 4) for p in probs[0].tolist()])
print("by hand:      ", round(-torch.log(probs[0, 0]).item(), 4))
print("F.cross_entropy:", round(F.cross_entropy(logits, target).item(), 4))
```

The model gives class 0 a probability of 0.7856, so the loss is `−log(0.7856) = 0.2413`, and PyTorch agrees. Plot the loss against `p_true` for both choices and the difference is obvious:

```python run alt="Line chart of loss against the probability given to the true class, from 0.01 to 1. Squared error (1 - p) squared falls gently from just under 1 to 0. Cross-entropy, -log p, starts at about 4.6 when p is 0.01, drops steeply, and reaches 0 at p equal to 1." caption="Cross-entropy charges heavily for confident mistakes; squared error never charges more than 1."
import matplotlib.pyplot as plt

p = torch.linspace(0.01, 1, 200)
fig, ax = plt.subplots(figsize=(6.4, 3.2))
ax.plot(p, -torch.log(p), color="#2a78d6", linewidth=2, label="cross-entropy: −log p")
ax.plot(p, (1 - p) ** 2, color="#eb6834", linewidth=2, label="squared error: (1 − p)²")
ax.set_xlabel("probability the model gives the true class")
ax.set_ylabel("loss")
ax.spines[["top", "right"]].set_visible(False)
ax.legend(frameon=False)
plt.show()
```

Squared error caps out at 1, so a model that's 99% sure of the wrong class is charged about the same as one that's 60% sure. Cross-entropy keeps climbing. There's a second, bigger reason to prefer it for classifiers, and it shows up in the gradients below.

## The gradient of one neuron, by hand

Take one neuron with no activation: `ŷ = w·x + b`, with squared error `L = (ŷ − y)²`. Use concrete numbers: `x = 2`, `y = 7`, `w = 1`, `b = 0.5`. The forward pass gives `ŷ = 2.5`, an error of `e = ŷ − y = −4.5`, and a loss of `20.25`.

The **gradient** answers: if I nudge `w` up by a tiny amount, how much does `L` change, and in which direction? The loss depends on `w` only through a chain of steps, `w → ŷ → e → L`, and the **chain rule** says to multiply the local rate of change at each link:

```mermaid caption="The forward pass builds the chain; the backward pass multiplies local slopes along it, from the loss back to each weight"
flowchart LR
    W["w = 1"] --> M["w·x = 2"]
    X["x = 2"] --> M
    M --> Y["ŷ = w·x + b = 2.5"]
    B["b = 0.5"] --> Y
    Y --> E["e = ŷ − y = −4.5"]
    E --> L["L = e² = 20.25"]
```

- `dL/de = 2e = −9`
- `de/dŷ = 1`
- `dŷ/dw = x = 2`, and `dŷ/db = 1`

So `dL/dw = 2e · 1 · x = −18` and `dL/db = 2e · 1 · 1 = −9`. The negative sign says increasing `w` would **lower** the loss; the size says the loss is about 18 times as sensitive as the change in `w`, for small changes. Notice that `dL/de = −9` was computed once and reused for both weights. That reuse is **backpropagation**: one pass backward from the loss, handing each link the gradient from the link after it, gives the gradient for every parameter at the cost of roughly one extra forward pass.

## Autograd checks your calculus

PyTorch does that backward pass for you. Mark the tensors you want gradients for with `requires_grad=True`, compute the loss, call `.backward()`, and read `.grad`:

```python run
w = torch.tensor(1.0, requires_grad=True)
b = torch.tensor(0.5, requires_grad=True)
x, y = torch.tensor(2.0), torch.tensor(7.0)

loss = (w * x + b - y) ** 2
loss.backward()
print("loss:", loss.item(), "| dL/dw:", w.grad.item(), "| dL/db:", b.grad.item())
```

`−18` and `−9`, matching the hand calculation. As PyTorch runs the forward pass it records every operation in a graph like the diagram above, and `.backward()` walks it in reverse.

Now the promised reason for cross-entropy. Take a sigmoid neuron whose logit is `z = −6` for an example whose true label is 1. It outputs `p = 0.0025`: confidently wrong. Compare the gradient each loss sends back to `z`:

```python run
z = torch.tensor(-6.0, requires_grad=True)
mse = (torch.sigmoid(z) - 1) ** 2
mse.backward()
print("squared error: loss", round(mse.item(), 4), "| gradient at z:", round(z.grad.item(), 4))

z = torch.tensor(-6.0, requires_grad=True)
ce = F.binary_cross_entropy_with_logits(z, torch.tensor(1.0))
ce.backward()
print("cross-entropy: loss", round(ce.item(), 4), "| gradient at z:", round(z.grad.item(), 4))
```

With squared error, the chain passes through the sigmoid's slope, which at `z = −6` is about 0.0025, so the neuron that most needs correcting gets a gradient near zero: the saturation problem from Module 2. With cross-entropy, the sigmoid's slope cancels out of the algebra and the gradient is simply `p − y = −0.9975`. Being confidently wrong produces the **largest** possible push, not the smallest.

:::warning
**Gradients add up.** `.backward()` adds into `.grad`; it doesn't overwrite. Run the forward pass and `backward()` a second time without clearing, and `w.grad` becomes `−36`. Every training loop clears gradients before each backward pass, with `optimizer.zero_grad()`, as you'll see in the next lesson.
:::

## Gradient descent: walking down a loss surface

With two parameters, the loss is a surface over the `(w, b)` plane, and the gradient points uphill. **Gradient descent** repeats one update, `w ← w − lr · dL/dw` (and the same for `b`), where the **learning rate** `lr` sets the step size. Here it is on 20 noisy points around the line `y = 3x − 1`, starting from `(w, b) = (−1, 2)` with three learning rates:

```python run alt="Contour plot of mean squared error over weight w (horizontal, -1.5 to 4) and bias b (vertical, -4 to 2.5). The contours are stretched ellipses, longer along w, centered near w = 3, b = -1. Three paths start at w = -1, b = 2. With learning rate 0.05 the path creeps about a third of the way toward the center. With 0.3 it curves smoothly to the minimum. With 0.85 it zigzags up and down in b, from 2 down to -4 and back with shrinking swings, while moving toward the minimum in w." caption="The same surface, the same start, three step sizes. Too small crawls; too large bounces across the narrow direction of the valley."
torch.manual_seed(0)
xs = torch.rand(20) * 2 - 1
ys = 3 * xs - 1 + 0.3 * torch.randn(20)


def descend(lr, steps):
    w, b = -1.0, 2.0
    path, losses = [(w, b)], []
    for _ in range(steps):
        err = w * xs + b - ys
        losses.append((err**2).mean().item())
        grad_w, grad_b = (2 * err * xs).mean().item(), (2 * err).mean().item()
        w, b = w - lr * grad_w, b - lr * grad_b
        path.append((w, b))
    return path, losses


W, B = torch.meshgrid(torch.linspace(-1.5, 4, 120), torch.linspace(-4, 2.5, 120), indexing="xy")
surface = ((W[..., None] * xs + B[..., None] - ys) ** 2).mean(dim=-1)

fig, ax = plt.subplots(figsize=(6.4, 4.4))
ax.contour(W, B, surface, levels=torch.logspace(-1.2, 1.5, 12).tolist(), colors="#b8b7b1", linewidths=0.8)
for lr, color in [(0.05, "#1baf7a"), (0.3, "#2a78d6"), (0.85, "#eb6834")]:
    path, _ = descend(lr, 25)
    ax.plot(*zip(*path), marker="o", markersize=3, linewidth=1.5, color=color, label=f"lr = {lr}")
ax.set_xlabel("weight w")
ax.set_ylabel("bias b")
ax.spines[["top", "right"]].set_visible(False)
ax.legend(frameon=False, loc="lower left")
plt.show()
```

The valley is a stretched bowl: the loss is far more sensitive to `b` than to `w` here, because the `x` values are small. A learning rate of 0.05 heads in the right direction but needs hundreds of steps. At 0.3 the path curves smoothly toward the bottom. At 0.85 each step overshoots in the steep `b` direction, so the path bounces from wall to wall, with each bounce a little smaller, while it moves along `w`.

## How large is too large?

Go back to the opening trace. For that loss, each update multiplies the distance from the best weight, `w − 2`, by the same factor, `1 − lr · 15`, where 15 is the loss's **curvature** (its second derivative, `2 · mean(x²)`). With `lr = 0.2` the factor is `−2`: every step flips to the other side and doubles the distance, so the loss, which grows with the distance squared, quadruples. The rule that falls out: descent converges only when `lr` is below `2 / curvature`, here `2/15 ≈ 0.133`. In the steepest direction of the surface above, the curvature is about 2, so the limit is just under 1.0. A learning rate of 0.85 bounces but survives; 1.05 does not:

```python run alt="Line chart of loss over 40 steps on a log scale. Learning rate 0.05 declines slowly. 0.3 and 0.85 both drop below 0.1 within about 15 steps. 1.05 rises in a straight line on the log scale, to nearly a million by step 40." caption="Loss per step. Just past the limit, the loss climbs exponentially instead of falling."
fig, ax = plt.subplots(figsize=(6.4, 3.2))
for lr, color in [(0.05, "#1baf7a"), (0.3, "#2a78d6"), (0.85, "#eb6834"), (1.05, "#52514e")]:
    _, losses = descend(lr, 40)
    ax.plot(losses, color=color, linewidth=2, label=f"lr = {lr}")
    print(f"lr {lr:<5} first loss {losses[0]:7.3f}  last loss {losses[-1]:10.3f}")
ax.set_yscale("log")
ax.set_xlabel("step")
ax.set_ylabel("mean squared error (log scale)")
ax.spines[["top", "right"]].set_visible(False)
ax.legend(frameon=False)
plt.show()
```

Look closely at 0.85: despite all that bouncing, it reaches the bottom sooner than 0.3. Big steps overshoot in the steep direction but make fast progress along the shallow one, so the quickest learning rates usually sit just below the edge, and one step past it the loss explodes.

Real networks have millions of directions with different curvatures, so you can't compute the limit by hand. But the symptoms are the same, and you'll learn to read them from loss curves in Module 4: too small crawls, too large bounces or blows up to `inf` and then `nan`.

## Mistakes worth recognizing

- **Applying softmax before `F.cross_entropy`.** It expects logits and applies its own log-softmax, so you'd squash the probabilities twice. The loss still decreases, slowly, and never gets near zero.
- **Float labels for classification.** `F.cross_entropy` wants class indices as `int64` with shape `(N,)`, not floats.
- **Reading a single gradient as the whole story.** A gradient is a local slope. It tells you the best direction for a tiny step, not how far to go. That's the learning rate's job.

:::quiz
Q: A model gives the true class a probability of 0.05. What is its cross-entropy loss for that example?
- [ ] 0.05
  That's the probability itself. The loss is the negative log of it.
- [x] About 3.0
  `−log(0.05) ≈ 3.0`. A confident mistake costs far more than the `0.9` squared error would charge.
- [ ] 0.95
  That's `1 − p`. Cross-entropy is `−log p`, which grows without limit as `p` approaches 0.

Q: For `ŷ = w·x + b` and `L = (ŷ − y)²`, with `x = 3`, `y = 1`, `w = 1`, and `b = 0`, what is `dL/dw`?
- [ ] 4
  That's `2e`, which is `dL/db`. For `w` you multiply by one more link, `dŷ/dw = x = 3`.
- [x] 12
  `ŷ = 3`, `e = 2`, so `dL/dw = 2e · x = 2 · 2 · 3 = 12`.
- [ ] 6
  Close, but the derivative of `e²` is `2e`, so the factor of 2 belongs in front.

Q: You call `loss.backward()` in a loop without ever clearing `.grad`. What goes wrong?
- [ ] Nothing: each call replaces the old gradient
  `.backward()` adds into `.grad`, so old gradients stay in the total.
- [x] Each step uses the sum of all gradients so far, so the steps grow and point in stale directions
  The accumulated sum mixes every past gradient. Clear with `optimizer.zero_grad()` before each backward pass.
- [ ] PyTorch raises an error on the second call
  It raises an error only if you reuse the same graph twice. A fresh forward pass followed by `backward()` runs fine and silently accumulates.

Q: For a loss whose curvature in its steepest direction is 50, which learning rate makes gradient descent diverge?
- [ ] 0.01
  `0.01 × 50 = 0.5`, so the factor is `1 − 0.5 = 0.5`: safely shrinking.
- [ ] 0.03
  `1 − 0.03 × 50 = −0.5`: it overshoots each time but the distance still halves, so it converges.
- [x] 0.05
  The limit is `2 / 50 = 0.04`. At 0.05 the factor is `1 − 2.5 = −1.5`, so each step lands farther away than the last.
:::

:::takeaways
- Use mean squared error for quantities and cross-entropy (on logits) for classes; cross-entropy keeps a strong gradient when the model is confidently wrong.
- The chain rule multiplies local slopes from the loss back to each weight; backpropagation reuses the shared links so every gradient costs one backward pass.
- `loss.backward()` fills `.grad` for every tensor with `requires_grad=True`, and it adds, so gradients must be cleared each step.
- Gradient descent steps against the gradient. Too small a learning rate crawls; above `2 / curvature` the loss grows every step.
:::
