## Warm-up: shapes in your head

Predict the shape of each result, then check with the cell below.

1. `torch.zeros(8, 3, 32, 32).flatten(1)`
2. `torch.zeros(5, 4) @ torch.zeros(4, 7)`
3. `torch.zeros(6, 1, 5) + torch.zeros(4, 1)`
4. `torch.zeros(10, 64).mean(dim=0, keepdim=True)`
5. `torch.zeros(10, 64).sum(dim=1)`

```python run
import torch

print(tuple(torch.zeros(8, 3, 32, 32).flatten(1).shape))
print(tuple((torch.zeros(5, 4) @ torch.zeros(4, 7)).shape))
print(tuple((torch.zeros(6, 1, 5) + torch.zeros(4, 1)).shape))
print(tuple(torch.zeros(10, 64).mean(dim=0, keepdim=True).shape))
print(tuple(torch.zeros(10, 64).sum(dim=1).shape))
```

The third is the one people miss. Aligned from the right, `(6, 1, 5)` and `(4, 1)` compare 5 with 1, then 1 with 4, then 6 with nothing, giving `(6, 4, 5)`. Both tensors were stretched along a different dimension.

### Exercise 1: the batch that crashes on the last step

A classmate's scoring function works on every test batch of 64 digits, then crashes on the final batch of the epoch, which has only 37 images (1,797 isn't a multiple of 64). Find the bug and fix it so any batch size works.

```python
import torch
import torch.nn as nn

layer = nn.Linear(64, 10)


def scores(images):            # images: (N, 8, 8)
    flat = images.reshape(64, -1)
    return layer(flat)


print(tuple(scores(torch.rand(64, 8, 8)).shape))
print(tuple(scores(torch.rand(37, 8, 8)).shape))
```

Sample output after the fix:

```text
(64, 10)
(37, 10)
```

:::hint
With 64 images, `reshape(64, -1)` happens to produce the right shape. Work out what it produces for 37 images: 37 × 64 numbers split into 64 rows.
:::

:::solution
The code hard-codes the batch size in the wrong position. With 37 images, `reshape(64, -1)` makes 64 rows of 37 numbers, which can't meet a 64-input layer. Keep dimension 0 as the batch and flatten the rest:

```python run
import torch
import torch.nn as nn

layer = nn.Linear(64, 10)


def scores(images):
    flat = images.flatten(start_dim=1)     # or images.reshape(len(images), -1)
    return layer(flat)


print(tuple(scores(torch.rand(64, 8, 8)).shape))
print(tuple(scores(torch.rand(37, 8, 8)).shape))
```

A bug that depends on batch size hides until the last, smaller batch of an epoch. Test shape-sensitive code with an odd batch size like 37 on purpose.
:::

### Exercise 2: count before you build

Count, by hand, the parameters in a network with layers 64 → 128 → 64 → 10 (ReLU between the `Linear` layers). Then build it and confirm, printing the size of each parameter tensor and the total.

```text
[8192, 128, 8192, 64, 640, 10]
total: 17226
```

:::hint
Each `nn.Linear(a, b)` has `a × b` weights and `b` biases. ReLU has none.
:::

:::solution
By hand: (64 × 128 + 128) + (128 × 64 + 64) + (64 × 10 + 10) = 8,320 + 8,256 + 650 = 17,226.

```python run
import torch.nn as nn

model = nn.Sequential(
    nn.Linear(64, 128), nn.ReLU(),
    nn.Linear(128, 64), nn.ReLU(),
    nn.Linear(64, 10),
)
sizes = [p.numel() for p in model.parameters()]
print(sizes)
print("total:", sum(sizes))
```

`model.parameters()` yields weights and biases in layer order, so the list alternates weight, bias. Notice where the parameters live: the first two layers hold 96% of them. Widening an early layer is far more expensive than widening the last one.
:::

### Exercise 3: `nn.Linear` by hand, for any number of leading dimensions

Write `my_linear(x, W, b)` using `@` so that it matches `nn.Linear` for inputs of shape `(2, 5, 64)`, not just `(N, 64)`. Print the output shape and whether it matches.

```text
(2, 5, 3) True
```

:::hint
`@` broadcasts every dimension except the last two, just like `+` broadcasts. Try the simplest formula first.
:::

:::solution
The two-dimensional formula already works:

```python run
import torch
import torch.nn as nn

torch.manual_seed(0)


def my_linear(x, W, b):
    return x @ W.T + b


layer = nn.Linear(64, 3)
x = torch.randn(2, 5, 64)
out = my_linear(x, layer.weight, layer.bias)
print(tuple(out.shape), torch.allclose(out, layer(x)))
```

`(2, 5, 64) @ (64, 3)` treats the leading `(2, 5)` as a batch of batches and gives `(2, 5, 3)`. The bias `(3,)` broadcasts across both leading dimensions. That's why `nn.Linear` accepts any shape ending in its input size, which is also how the opening bug in the Notes (256 rows of 8) came about.
:::

### Exercise 4: standardize without NaNs

Standardize every pixel column of the full digits data, `X = torch.tensor(load_digits().data, dtype=torch.float32)`, to mean 0 and standard deviation 1. The obvious one-liner fills the result with `nan`. Find out how many NaNs it makes and which columns cause them, then fix it so there are none.

```text
NaNs from the one-liner: 5391
columns with std 0: [0, 32, 39]
NaNs after the fix: False
```

:::hint
Some pixels sit at the very edge of the 8 × 8 grid. What is the standard deviation of a column that's 0 for every image, and what is 0 / 0?
:::

:::solution
Three border pixels are blank in all 1,797 images, so their standard deviation is 0 and `(0 - 0) / 0` is `nan`. Clamp the denominator:

```python run
import torch
from sklearn.datasets import load_digits

X = torch.tensor(load_digits().data, dtype=torch.float32)
mean, std = X.mean(dim=0), X.std(dim=0)

naive = (X - mean) / std
print("NaNs from the one-liner:", torch.isnan(naive).sum().item())
print("columns with std 0:", (std == 0).nonzero().flatten().tolist())

Z = (X - mean) / std.clamp_min(1e-6)
print("NaNs after the fix:", torch.isnan(Z).any().item())
print("largest column mean:", round(Z.mean(dim=0).abs().max().item(), 6))
```

`dim=0` reduces down the rows, giving one mean and one standard deviation per pixel column, shape `(64,)`, which broadcasts back across the `(1797, 64)` data. A single NaN in an input spreads through every layer it touches and turns the loss into `nan`, so this check belongs in every data pipeline.
:::

### Exercise 5: channels-last to channels-first

Images loaded with NumPy or PIL usually arrive as `(N, H, W, C)`, but PyTorch's image layers expect `(N, C, H, W)`. Build a fake batch where every red value is 1, every green is 2, and every blue is 3, convert it, and prove that channel 0 now contains only red values. Also show what `reshape` does instead.

```text
permute: (4, 3, 8, 8) channel 0 holds [1.0]
reshape: (4, 3, 8, 8) channel 0 holds [1.0, 2.0, 3.0]
```

:::hint
Name the target position of each old dimension. Old order: N=0, H=1, W=2, C=3. New order: N, C, H, W.
:::

:::solution
```python run
import numpy as np
import torch

rgb = np.zeros((4, 8, 8, 3), dtype=np.float32)
rgb[..., 0], rgb[..., 1], rgb[..., 2] = 1, 2, 3
t = torch.from_numpy(rgb)

right = t.permute(0, 3, 1, 2)
wrong = t.reshape(4, 3, 8, 8)
print("permute:", tuple(right.shape), "channel 0 holds", right[:, 0].unique().tolist())
print("reshape:", tuple(wrong.shape), "channel 0 holds", wrong[:, 0].unique().tolist())
```

`permute(0, 3, 1, 2)` reads as "new dim 0 is old 0, new dim 1 is old 3 (C), then old 1 (H) and old 2 (W)". `reshape` produces the same shape but keeps the memory order, where red, green, and blue alternate pixel by pixel, so each "channel" ends up a mixture of all three colors. A model trained on that still runs, and quietly learns from scrambled pixels.
:::

### Exercise 6: count the dead units

Write `dead_units(linear, x)`, which applies a `Linear` layer and then ReLU to the inputs `x` and returns how many of the layer's units output zero for **every** row. Test it on `nn.Linear(64, 32)` with the full scaled digits (`load_digits().data / 16`), first as initialized, then after simulating a bad update that lowered every bias by 0.5.

```text
dead units at init: 0
dead units after the bias drop: 20
```

:::hint
After ReLU, `h` has shape `(1797, 32)`. A unit is a column. `(h == 0)` is a boolean grid; which reduction asks "true in every row of this column"?
:::

:::solution
```python run
import torch
import torch.nn as nn
from sklearn.datasets import load_digits

X = torch.tensor(load_digits().data, dtype=torch.float32) / 16
torch.manual_seed(0)
layer = nn.Linear(64, 32)


def dead_units(linear, x):
    with torch.no_grad():
        h = torch.relu(linear(x))
    return int((h == 0).all(dim=0).sum())


print("dead units at init:", dead_units(layer, X))
with torch.no_grad():
    layer.bias -= 0.5
print("dead units after the bias drop:", dead_units(layer, X))
```

`.all(dim=0)` collapses the rows and leaves one True or False per unit. Lowering the biases by just 0.5 pushes 20 of 32 units below zero for every digit. A dead unit's slope is 0 for every input, so no training signal ever reaches its weights, and it can't recover by itself. Large learning rates cause exactly this kind of jump, which is one reason Module 4 watches them closely.
:::

### Challenge: a network that passes the spec

Your network will receive color images of shape `(N, 3, 8, 8)` with **raw** pixel values from 0 to 255, exactly as a camera produces them, and must output 5 class scores. The spec:

- output shape `(N, 5)`;
- at most 10,000 parameters, with at least two hidden layers using `nn.Tanh`;
- on `torch.rand(512, 3, 8, 8) * 255`, no tanh layer may have more than 5% of its outputs flat (slope below 0.01);
- scaling must happen **inside** the model, because the people calling it will send raw pixels.

Write a check that prints the output shape, the parameter count, and each tanh layer's flat share.

:::hint
`nn.Sequential` has no layer that divides by a constant, so write one: a class that subclasses `nn.Module`, calls `super().__init__()`, and returns `x * self.factor` from `forward`. Run the check without it first to see why the spec demands it.
:::

:::solution
```python run
import torch
import torch.nn as nn


class Scale(nn.Module):
    def __init__(self, factor):
        super().__init__()
        self.factor = factor

    def forward(self, x):
        return x * self.factor


def check(net, x):
    flat = []

    def hook(module, inputs, output):
        flat.append(round(((1 - output**2) < 0.01).float().mean().item(), 3))

    handles = [layer.register_forward_hook(hook) for layer in net if isinstance(layer, nn.Tanh)]
    with torch.no_grad():
        out = net(x)
    for handle in handles:
        handle.remove()
    params = sum(p.numel() for p in net.parameters())
    print(f"out {tuple(out.shape)}  params {params}  flat share per tanh layer {flat}")


x = torch.rand(512, 3, 8, 8) * 255
torch.manual_seed(0)
unscaled = nn.Sequential(nn.Flatten(), nn.Linear(192, 40), nn.Tanh(), nn.Linear(40, 24), nn.Tanh(), nn.Linear(24, 5))
check(unscaled, x)

torch.manual_seed(0)
scaled = nn.Sequential(Scale(1 / 255), nn.Flatten(), nn.Linear(192, 40), nn.Tanh(), nn.Linear(40, 24), nn.Tanh(), nn.Linear(24, 5))
check(scaled, x)
```

Parameters: (192 × 40 + 40) + (40 × 24 + 24) + (24 × 5 + 5) = 7,720 + 984 + 125 = 8,829. `Scale` has no parameters, so it's free. Without it, about 97% of the first tanh layer's outputs are pinned at ±1. The second layer looks healthy only because its inputs are already squashed into −1 to 1, so a per-layer check matters: an average over the whole network would have hidden the problem. With scaling built in, both layers are 0% flat, and callers can't forget it.
:::
