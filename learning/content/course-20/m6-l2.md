:::objectives
- Write train and evaluation transforms that match ImageNet-pretrained weights.
- Freeze ResNet-18, attach a 102-class head, and keep BatchNorm statistics fixed.
- Smoke-test a training loop on fake data by overfitting one small batch.
- Unfreeze the last stage with a smaller learning rate and a cosine schedule.
- Assemble the full two-phase script and run it on a Colab GPU.
:::

Oxford Flowers-102 is a classic transfer-learning test: 102 species of flowers, but only **10 training images per species**. That's 1,020 photos to learn 102 classes, some of which look almost identical. Trained from scratch, a network has far too little to go on. Starting from ImageNet weights, it doesn't need much.

Here's the plan:

```mermaid caption="Two phases: train only the head, then also the last stage of the backbone"
flowchart LR
    A["photo"] --> B["train_tf / eval_tf"]
    B --> C["ResNet-18: stem, layer1 to layer3 (frozen)"]
    C --> D["layer4 (frozen in phase 1, trained in phase 2)"]
    D --> E["new head: 512 to 102"]
    E --> F["val accuracy each epoch, test once"]
```

Downloading the dataset and the weights needs Colab, but almost everything that can go wrong (a transform that produces the wrong shape, a loop that never updates the head, a learning rate set on the wrong layers) can be caught on any CPU in seconds. So you'll build each piece here, check it, and then run the finished script on a GPU.

## Step 1: Transforms that match the pretrained weights

ResNet-18's ImageNet weights expect 224×224 crops, scaled to 0–1, then normalized with ImageNet's per-channel mean and standard deviation. Training adds randomness on top; evaluation must be the same every time.

```python run
import torch
import torch.nn as nn
import torch.nn.functional as F
import matplotlib.pyplot as plt
from sklearn.datasets import load_sample_image
from torchvision import models, datasets
from torchvision.transforms import v2
from torch.utils.data import DataLoader

MEAN, STD = [0.485, 0.456, 0.406], [0.229, 0.224, 0.225]

train_tf = v2.Compose([
    v2.ToImage(),
    v2.RandomResizedCrop(224, scale=(0.5, 1.0)),
    v2.RandomHorizontalFlip(),
    v2.ColorJitter(brightness=0.2, contrast=0.2),     # no hue change: color is a clue to the species
    v2.ToDtype(torch.float32, scale=True),
    v2.Normalize(MEAN, STD),
])
eval_tf = v2.Compose([
    v2.ToImage(),
    v2.Resize(256),
    v2.CenterCrop(224),
    v2.ToDtype(torch.float32, scale=True),
    v2.Normalize(MEAN, STD),
])

photo = load_sample_image("flower.jpg")        # a (427, 640, 3) photo that ships with scikit-learn
x = eval_tf(photo)
print(tuple(x.shape), x.dtype)
print("per-channel means after normalizing:", [round(v, 2) for v in x.mean(dim=(1, 2)).tolist()])
```

`ToImage` turns the NumPy array (height, width, channels) into a tensor image (channels, height, width). After normalizing, an average ImageNet pixel maps to 0 in every channel; this photo has a dark background, so its means come out below zero. Those are the units the first conv layer worked in during ImageNet training. Now look at what the model will receive. To display a normalized image you have to undo the normalization:

```python run alt="Six versions of the same flower photo. The first is the full original. The next four are random training crops, some zoomed in on the petals, one mirrored, with slightly different brightness. The last is the centered evaluation crop." caption="The original photo, four random training views, and the fixed evaluation crop"
def show(t):
    return (t * torch.tensor(STD)[:, None, None] + torch.tensor(MEAN)[:, None, None]).clamp(0, 1).permute(1, 2, 0)

torch.manual_seed(0)
views = [train_tf(photo) for _ in range(4)] + [eval_tf(photo)]
fig, axes = plt.subplots(1, 6, figsize=(10, 2))
axes[0].imshow(photo)
axes[0].set_title("original", fontsize=9)
for i, view in enumerate(views, start=1):
    axes[i].imshow(show(view))
    axes[i].set_title("eval crop" if i == 5 else f"train view {i}", fontsize=9)
for ax in axes:
    ax.axis("off")
plt.tight_layout()
plt.show()
```

Every training view is still clearly the same flower, which is the test for any augmentation.

## Step 2: A fake dataset with the real interface

In Colab, the data comes from `datasets.Flowers102("data", split="train", download=True, transform=train_tf)`, with matching `"val"` and `"test"` splits (1,020, 1,020, and 6,149 images). Each item is a `(PIL image, label)` pair.

`datasets.FakeData` returns random images in exactly that format, with no download. It's the perfect stand-in for checking the plumbing:

```python run
fake_train = datasets.FakeData(size=32, image_size=(3, 256, 320), num_classes=102, transform=train_tf)
xb, yb = next(iter(DataLoader(fake_train, batch_size=16, shuffle=True)))
print(tuple(xb.shape), xb.dtype, yb[:8].tolist())
```

A batch of 16 normalized 224×224 images and integer labels: the same shapes the real loader will produce.

## Step 3: Freeze the backbone and attach the new head

Locally there are no pretrained weights, so `WEIGHTS` is `None` and the backbone is random. The structure, the shapes, and the parameter counts are identical, which is all these checks need.

```python run
WEIGHTS = None          # in Colab: models.ResNet18_Weights.DEFAULT

def build_model(num_classes=102, weights=WEIGHTS):
    model = models.resnet18(weights=weights)
    for p in model.parameters():
        p.requires_grad = False
    model.fc = nn.Linear(model.fc.in_features, num_classes)   # new layers start trainable
    return model

def trainable(model):
    return sum(p.numel() for p in model.parameters() if p.requires_grad)

model = build_model()
print(f"trainable: {trainable(model):,}   output: {tuple(model(xb[:2]).shape)}")
```

52,326 trainable numbers (512 × 102 + 102), and two images in give two rows of 102 scores out.

## Step 4: A training loop that leaves BatchNorm alone

Recall the warning from the notes: in `train()` mode, BatchNorm layers keep updating their running statistics even when their weights are frozen. With 1,020 images and a small batch, those statistics would drift away from the ImageNet values the frozen layers depend on. `train_epoch` switches every BatchNorm layer back to eval mode after `model.train()`:

```python run
device = "cuda" if torch.cuda.is_available() else "cpu"

def train_epoch(model, loader, optimizer):
    model.train()
    for module in model.modules():
        if isinstance(module, nn.BatchNorm2d):
            module.eval()                       # keep ImageNet's running mean and variance
    total, seen = 0.0, 0
    for xb, yb in loader:
        xb, yb = xb.to(device), yb.to(device)
        loss = F.cross_entropy(model(xb), yb)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        total += loss.item() * len(yb)
        seen += len(yb)
    return total / seen

@torch.no_grad()
def evaluate(model, loader):
    model.eval()
    correct = seen = 0
    for xb, yb in loader:
        correct += (model(xb.to(device)).argmax(1).cpu() == yb).sum().item()
        seen += len(yb)
    return correct / seen
```

Accuracy on random images means nothing, so how do you test a loop on fake data? Ask it to do the one thing any working loop can do: **memorize a single small batch**. If the loss doesn't fall toward zero, something is broken (the optimizer holds the wrong parameters, the labels are misaligned, or gradients aren't flowing). Small 64×64 images keep this fast:

```python run
tiny_tf = v2.Compose([v2.ToImage(), v2.ToDtype(torch.float32, scale=True), v2.Normalize(MEAN, STD)])
tiny = datasets.FakeData(size=16, image_size=(3, 64, 64), num_classes=102, transform=tiny_tf)
tiny_loader = DataLoader(tiny, batch_size=16)

torch.manual_seed(0)
model = build_model().to(device)
head_optimizer = torch.optim.Adam(model.fc.parameters(), lr=1e-2)
for epoch in range(1, 31):
    loss = train_epoch(model, tiny_loader, head_optimizer)
    if epoch in (1, 10, 20, 30):
        print(f"epoch {epoch:>2}: loss {loss:.3f}   accuracy on the same 16 images: {evaluate(model, tiny_loader):.0%}")
```

The loss starts near ln(102) ≈ 4.6, which is what a model guessing uniformly over 102 classes scores, and falls fast as the head memorizes the batch. That's the behavior you want to see before moving on.

## Step 5: Phase two unfreezes `layer4` with smaller steps

After the head has trained for a few epochs, its gradients are sensible, and it's safe to let the last stage adapt too. The pretrained layers get a learning rate ten times smaller than the head, and a cosine schedule lowers both smoothly to zero over the phase:

```python run alt="Line chart of learning rate against epoch for two parameter groups. The head starts at 0.001 and the layer4 group at 0.0001; both curve smoothly down to nearly zero by the last epoch." caption="Cosine annealing scales every group's learning rate by the same curve"
def start_phase_two(model, epochs, head_lr=1e-3, body_lr=1e-4):
    for p in model.layer4.parameters():
        p.requires_grad = True
    optimizer = torch.optim.AdamW([
        {"params": model.layer4.parameters(), "lr": body_lr},
        {"params": model.fc.parameters(), "lr": head_lr},
    ], weight_decay=1e-4)
    scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=epochs)
    return optimizer, scheduler

optimizer, scheduler = start_phase_two(model, epochs=10)
print(f"trainable in phase two: {trainable(model):,}")

lrs = []
for epoch in range(10):
    lrs.append([group["lr"] for group in optimizer.param_groups])
    optimizer.step()          # in the real loop, train_epoch does the steps
    scheduler.step()

lrs = torch.tensor(lrs)
plt.figure(figsize=(5, 2.8))
plt.plot(lrs[:, 1], label="head", color="#d9534f")
plt.plot(lrs[:, 0], label="layer4", color="#7892ee")
plt.xlabel("epoch of phase two")
plt.ylabel("learning rate")
plt.legend()
plt.gca().spines[["top", "right"]].set_visible(False)
plt.tight_layout()
plt.show()
```

Phase two trains about 8.4 million parameters instead of 52 thousand, so it's slower and easier to overfit. That's why it comes second, runs at small learning rates, and stops at the epoch with the best validation accuracy.

## Step 6: The full script for Colab

Switch the runtime to a T4 GPU, paste this into one cell, and run it. The first run downloads the flower images (a few hundred MB) and the ResNet-18 weights (about 45 MB). If a download stops with a network error, run the cell again; finished files are reused. Loading Flowers-102 needs SciPy, which Colab already has.

```python title="flowers_transfer.py"
import copy
import torch
import torch.nn as nn
import torch.nn.functional as F
from torch.utils.data import DataLoader
from torchvision import datasets, models
from torchvision.transforms import v2

device = "cuda" if torch.cuda.is_available() else "cpu"
torch.manual_seed(0)
MEAN, STD = [0.485, 0.456, 0.406], [0.229, 0.224, 0.225]
train_tf = v2.Compose([
    v2.ToImage(), v2.RandomResizedCrop(224, scale=(0.5, 1.0)), v2.RandomHorizontalFlip(),
    v2.ColorJitter(brightness=0.2, contrast=0.2),
    v2.ToDtype(torch.float32, scale=True), v2.Normalize(MEAN, STD),
])
eval_tf = v2.Compose([
    v2.ToImage(), v2.Resize(256), v2.CenterCrop(224),
    v2.ToDtype(torch.float32, scale=True), v2.Normalize(MEAN, STD),
])
loaders = {
    split: DataLoader(
        datasets.Flowers102("data", split=split, download=True,
                            transform=train_tf if split == "train" else eval_tf),
        batch_size=32, shuffle=(split == "train"), num_workers=2,
    )
    for split in ["train", "val", "test"]
}

model = models.resnet18(weights=models.ResNet18_Weights.DEFAULT)
for p in model.parameters():
    p.requires_grad = False
model.fc = nn.Linear(model.fc.in_features, 102)
model = model.to(device)


def train_epoch(model, loader, optimizer):
    model.train()
    for module in model.modules():
        if isinstance(module, nn.BatchNorm2d):
            module.eval()
    for xb, yb in loader:
        xb, yb = xb.to(device), yb.to(device)
        loss = F.cross_entropy(model(xb), yb)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()


@torch.no_grad()
def evaluate(model, loader):
    model.eval()
    correct = seen = 0
    for xb, yb in loader:
        correct += (model(xb.to(device)).argmax(1).cpu() == yb).sum().item()
        seen += len(yb)
    return correct / seen


best_acc, best_state = 0.0, None

def run_phase(name, optimizer, epochs, scheduler=None):
    global best_acc, best_state
    for epoch in range(1, epochs + 1):
        train_epoch(model, loaders["train"], optimizer)
        if scheduler:
            scheduler.step()
        acc = evaluate(model, loaders["val"])
        print(f"{name} epoch {epoch}: val accuracy {acc:.1%}")
        if acc > best_acc:
            best_acc, best_state = acc, copy.deepcopy(model.state_dict())

run_phase("head", torch.optim.Adam(model.fc.parameters(), lr=1e-3), epochs=5)

for p in model.layer4.parameters():
    p.requires_grad = True
optimizer = torch.optim.AdamW([
    {"params": model.layer4.parameters(), "lr": 1e-4},
    {"params": model.fc.parameters(), "lr": 1e-3},
], weight_decay=1e-4)
run_phase("fine-tune", optimizer, epochs=10,
          scheduler=torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=10))

model.load_state_dict(best_state)
print(f"best val accuracy {best_acc:.1%}, test accuracy {evaluate(model, loaders['test']):.1%}")
torch.save(best_state, "flowers_resnet18.pt")
```

Chance is 1 in 102, under 1%. Watch the head-only phase climb far above that within its first epochs, using features nobody trained on flowers, and note how much phase two adds on top. Write both numbers down; the practice set asks you to compare them with a from-scratch run.

:::quiz
Q: Why does `train_epoch` call `.eval()` on every BatchNorm layer right after `model.train()`?
- [ ] To turn off dropout in the head
  The new head is a single `Linear` layer; it has no dropout.
- [x] So the running mean and variance stay at their ImageNet values instead of drifting with small flower batches
  In train mode BatchNorm updates those statistics on every batch, even when its weights are frozen.
- [ ] Because frozen layers can't run in train mode
  They can; that's exactly why the statistics would drift.

Q: Why does `eval_tf` use `Resize(256)` and `CenterCrop(224)` instead of `RandomResizedCrop`?
- [x] Evaluation must be deterministic, and resize-then-center-crop is the preprocessing these weights were evaluated with
  Random crops at test time would make accuracy change from run to run and would shift the inputs away from what the model expects.
- [ ] Center crops are faster to compute
  The speed difference is negligible; consistency is the point.
- [ ] `RandomResizedCrop` only works on training datasets
  Any transform works on any dataset; the choice is about what each split should measure.

Q: The memorize-one-batch check ends with the loss near zero. What does that prove?
- [ ] The model will reach high accuracy on Flowers-102
  It says nothing about generalization; the images were random noise.
- [x] Data, model, loss, optimizer, and loop are wired together correctly
  A loop that can't memorize 16 images has a bug; one that can is ready for real data.
- [ ] The pretrained weights loaded correctly
  This check ran with random weights on purpose.
:::

:::takeaways
- Match the preprocessing the weights were trained with: 224×224 crops, values scaled to 0–1, ImageNet mean and standard deviation.
- Augment only what keeps the label true; for flowers, crops and flips are safe and hue shifts are not.
- Test the whole pipeline on `FakeData` by memorizing one batch before spending GPU time on real data.
- Keep BatchNorm in eval mode when fine-tuning on small data.
- Train the head first, then unfreeze the last stage with a learning rate about ten times smaller, and keep the epoch with the best validation accuracy.
:::
