Training a neural network is mostly matrix multiplication. Multiplying two 4096 × 4096 matrices takes 2 × 4096³, about 137 billion, multiply-and-add operations. NVIDIA rates the T4, the GPU that Google Colab lends to free users, at roughly 8 trillion 32-bit floating-point operations per second at peak. Even at half that speed, the whole multiplication finishes in a few hundredths of a second. The two-core CPU that Colab gives you without a GPU is many times slower.

The networks in Modules 2 to 4 are small enough that a CPU handles them in seconds. From Module 5 on, you'll train convolutional networks on real image datasets, and that's where the GPU turns a long wait into a short one. Setting it up now, while nothing depends on it, means you'll already know how it behaves when it matters.

## What you need

- **A Google account.** Some schools switch Colab off for student accounts. If Colab says you don't have access, use a personal account instead.
- **A recent browser:** Chrome, Firefox, Safari, or Edge.
- **Nothing to install.** Colab's machines come with PyTorch, torchvision, NumPy, scikit-learn, and matplotlib already installed.

The free tier costs nothing, and it makes no promises. Which GPU you get, and for how long, depends on demand and on how much you've used recently. Google doesn't publish the exact limits. Every exercise in this course is sized to fit comfortably inside them.

## Step 1: make a notebook and run a cell

1. Go to [colab.research.google.com](https://colab.research.google.com) and sign in.
2. In the window that opens, click **New notebook**. If no window appears, use **File › New notebook in Drive**.
3. Click the name `Untitled0.ipynb` at the top left and rename it `dlcv-setup.ipynb`.
4. Click in the empty code cell, type `print("hello from Colab")`, and press **Shift + Enter**.

The first run takes several seconds because Colab is starting a machine for you. When it's ready, the **Connect** button at the top right turns into small RAM and Disk meters, and your text prints under the cell. The notebook file itself is saved in a folder called **Colab Notebooks** in your Google Drive.

Your code doesn't run in the browser. It runs on a virtual machine in a Google data center, and the browser only shows you the results. Hold on to that picture; it explains nearly every surprise in this lesson.

## Step 2: switch the runtime to a GPU

1. Open **Runtime › Change runtime type**.
2. Under **Hardware accelerator**, choose **T4 GPU**.
3. Click **Save**.

Saving gives you a brand-new machine with a GPU attached. Anything the old machine had in memory is gone, so change the runtime type before you run real work, not halfway through it.

## Step 3: prove the GPU is there

Two checks, one asking NVIDIA's driver and one asking PyTorch. In a new cell, run the driver's status tool. In Colab you type a shell command with an exclamation mark in front, so the cell reads `!nvidia-smi`:

```bash
nvidia-smi
```

It prints a table. The version numbers and temperature will differ, but the important part looks like this:

```text
|   0  Tesla T4                       Off |   00000000:00:04.0 Off |                    0 |
| N/A   38C    P8              9W /   70W |      0MiB /  15360MiB  |      0%      Default |
```

That says one GPU (number `0`), a Tesla T4, using 0 of its roughly 15 GB of memory. Now ask PyTorch:

```python run
import torch

print("PyTorch version:", torch.__version__)
print("CUDA available: ", torch.cuda.is_available())
if torch.cuda.is_available():
    print("GPU:            ", torch.cuda.get_device_name(0))
```

The output above was made by the machine that builds this page, which has no NVIDIA GPU, so it says `False` and skips the last line. That's also exactly what you'll see in Colab if you forgot Step 2. With the T4 attached, you should see:

```text
PyTorch version: 2.x.x+cu12x
CUDA available:  True
GPU:             Tesla T4
```

The `x`s stand for whatever versions Colab has installed this term. The `+cu` part means this copy of PyTorch was built for **CUDA**, NVIDIA's platform for running general code on its GPUs. `torch.cuda.is_available()` is the line you'll lean on for the rest of the course.

## Your keyboard and the local-install question

Colab works the same in every browser. The differences are the shortcut keys and whether installing PyTorch on your own computer makes sense.

:::tabs
@tab Windows
- **Ctrl + Enter** runs the current cell; **Shift + Enter** runs it and moves to the next one.
- **Ctrl + M**, then **B**, adds a code cell below. **Tools › Keyboard shortcuts** lists the rest.
- A local install only gets you a GPU if your PC has an NVIDIA graphics card. If it does, the selector at pytorch.org/get-started/locally builds the right `pip` command for your CUDA version. Stick with Colab for this course unless you already know you want this.
@tab macOS
- **Cmd + Enter** runs the current cell; **Shift + Enter** runs it and moves to the next one.
- **Cmd + M**, then **B**, adds a code cell below. **Tools › Keyboard shortcuts** lists the rest.
- Macs don't have NVIDIA GPUs, so `torch.cuda.is_available()` is always `False` on a Mac. Apple silicon Macs have their own GPU backend called `mps`, which this course doesn't rely on. Use Colab for the GPU modules.
@tab Chromebook
- **Ctrl + Enter** runs the current cell; **Shift + Enter** runs it and moves to the next one.
- **Ctrl + M**, then **B**, adds a code cell below. **Tools › Keyboard shortcuts** lists the rest.
- Chromebooks have no CUDA GPU, and school-managed ones usually can't install software. Colab in Chrome is the whole setup, and it's all this course needs.
:::

## Fixes for the four problems people actually hit

**"Cannot connect to GPU backend."** Colab shows this when you've used up your recent GPU allowance or none are free. Switch to **CPU** in **Runtime › Change runtime type** and keep going: every lesson through Module 4 runs comfortably on a CPU. Try the GPU again later, often the next day.

**`torch.cuda.is_available()` still prints `False`.** The runtime is still a CPU one, or you changed it and are looking at the old output. Check **Runtime › Change runtime type**, then run the cell again; output never updates on its own.

**`NameError` on a variable you definitely made.** The machine was recycled. Colab disconnects notebooks that sit idle, and every runtime has a maximum lifetime (up to 12 hours on the free tier, often less). The notebook is safe in Drive, but its variables are not. **Runtime › Run all** rebuilds everything from the top. The next two lessons show how to save trained weights so they survive this.

**A notice that you're connected to a GPU but not using it.** Colab watches for GPUs sitting idle. If you're doing a small CPU-sized lesson, accept the offer to switch, or use **Runtime › Disconnect and delete runtime** when you finish. Either one stops spending your allowance on nothing.

:::tip
A good habit from day one: put `import torch` and the CUDA check at the top of every notebook. If the GPU silently disappears, you'll see it in the first cell instead of finding out from a slow training run.
:::

:::quiz
Q: You switch the runtime to T4 GPU and rerun `torch.cuda.is_available()`, which now prints `True`. The next cell uses a list called `images` that you built earlier and fails with `NameError`. Why?
- [ ] The GPU can't store Python lists
  Lists live in ordinary CPU memory on the machine, GPU or not. The problem is which machine you're on.
- [x] Changing the runtime type gave you a new machine, and the old one's variables went with it
  Saving the runtime type starts a fresh virtual machine. Rerun the cell that builds `images`, or use Runtime › Run all.
- [ ] `torch.cuda.is_available()` deletes variables when it returns `True`
  Checking for a GPU changes nothing; it only reports what the machine has.

Q: A friend's laptop is a MacBook with an M-series chip. They install PyTorch and `torch.cuda.is_available()` prints `False`. What's going on?
- [ ] Their install is broken and needs to be redone
  The install is fine. A `False` here is the correct answer for that hardware.
- [x] CUDA is NVIDIA's platform, and Macs don't have NVIDIA GPUs
  Apple silicon uses a different backend (`mps`). For this course, Colab's T4 is the simpler path.
- [ ] They need to choose T4 GPU in the Mac's settings
  T4 GPU is a Colab runtime option. It isn't hardware inside the laptop.
:::
