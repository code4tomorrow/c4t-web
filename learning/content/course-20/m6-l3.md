## Warm-up: which strategy?

For each project, choose between training only a new head, fine-tuning the last stage, and fine-tuning everything, starting from ImageNet weights.

1. 500 photos of four bird species from a backyard feeder camera.
2. 20,000 labeled satellite tiles of farmland, 8 crop types.
3. 150 microscope images of three kinds of cell, all grayscale.

:::solution
1. **Head only.** Birds look like ImageNet photos (which include many bird species), and 500 images is small.
2. **Everything**, with a small learning rate for the backbone. Satellite tiles look nothing like everyday photos, and 20,000 labels is enough to move every layer safely.
3. **Head first, then the last stage**, with strong augmentation, and compare the two on validation. The images are unusual and the dataset is tiny, so it's a judgment call you settle by measuring. Grayscale images need three channels for an ImageNet model: repeat the single channel (`v2.Grayscale(num_output_channels=3)` does it).
:::

### Exercise 1: Count what each strategy trains

Write `prepare(num_classes, unfreeze)` that builds `models.resnet18(weights=None)`, freezes everything, unfreezes the stages named in the list `unfreeze` (for example `["layer4"]`), and replaces the head. Print the trainable count for a 5-class problem with `[]`, `["layer4"]`, `["layer3", "layer4"]`, and every stage unfrozen.

```text
[]                            2,565
['layer4']                    8,396,293
['layer3', 'layer4']          10,496,005
all                           11,179,077
```

:::hint
`getattr(model, "layer4")` returns the stage by name. The head must be replaced **after** freezing, or it gets frozen too.
:::

:::solution
```python run
def prepare(num_classes, unfreeze):
    model = models.resnet18(weights=None)
    for p in model.parameters():
        p.requires_grad = False
    for name in unfreeze:
        for p in getattr(model, name).parameters():
            p.requires_grad = True
    model.fc = nn.Linear(model.fc.in_features, num_classes)
    return model

every_stage = ["conv1", "bn1", "layer1", "layer2", "layer3", "layer4"]
for label, stages in [("[]", []), ("['layer4']", ["layer4"]),
                      ("['layer3', 'layer4']", ["layer3", "layer4"]), ("all", every_stage)]:
    print(f"{label:<30}{count(prepare(5, stages)):,}")
```

Unfreezing `layer4` multiplies the trainable count by more than 3,000. The last stage holds most of ResNet-18's weights because it has the most channels (512), which is one more reason to unfreeze it last and gently.
:::

### Exercise 2: Prove BatchNorm stays put

Show that `model.bn1.running_mean` **changes** after one forward pass in `train()` mode even though every parameter is frozen. Then write `freeze_bn(model)`, which puts every `BatchNorm2d` layer in eval mode, and a `unittest` that passes only when the running mean is unchanged after a training-mode forward pass.

:::hint
Clone the buffer before the forward pass (`model.bn1.running_mean.clone()`), otherwise you'll compare the tensor with itself. Use random input such as `torch.randn(4, 3, 64, 64)`.
:::

:::solution
```python run
model = prepare(5, [])
before = model.bn1.running_mean.clone()
model.train()
model(torch.randn(4, 3, 64, 64))
print("changed in train mode:", not torch.equal(before, model.bn1.running_mean))

def freeze_bn(model):
    for module in model.modules():
        if isinstance(module, nn.BatchNorm2d):
            module.eval()

class TestFreezeBN(unittest.TestCase):
    def test_running_stats_fixed(self):
        model = prepare(5, ["layer4"])
        before = [m.running_mean.clone() for m in model.modules() if isinstance(m, nn.BatchNorm2d)]
        model.train()
        freeze_bn(model)
        model(torch.randn(4, 3, 64, 64))
        after = [m.running_mean for m in model.modules() if isinstance(m, nn.BatchNorm2d)]
        self.assertTrue(all(torch.equal(a, b) for a, b in zip(before, after)))

suite = unittest.defaultTestLoader.loadTestsFromTestCase(TestFreezeBN)
unittest.TextTestRunner(stream=sys.stdout, verbosity=2).run(suite)
```

`requires_grad` controls gradients; `train()` and `eval()` control behavior. They're separate switches, and frozen fine-tuning needs both set correctly.
:::

### Exercise 3: IoU from scratch

Write `iou(a, b)` for two boxes in `(x1, y1, x2, y2)` form using plain Python arithmetic. Boxes that don't overlap must give exactly 0, not a negative number. Test it against `torchvision.ops.box_iou` on 200 random pairs.

:::hint
The overlap's left edge is the larger of the two left edges, and its right edge is the smaller of the two right edges. If right < left, the width is 0: use `max(0, right - left)`.
:::

:::solution
```python run
def iou(a, b):
    w = max(0.0, min(a[2], b[2]) - max(a[0], b[0]))
    h = max(0.0, min(a[3], b[3]) - max(a[1], b[1]))
    inter = w * h
    area = lambda box: (box[2] - box[0]) * (box[3] - box[1])
    return inter / (area(a) + area(b) - inter)

def random_box(rng):
    x, y = rng.uniform(0, 80), rng.uniform(0, 80)
    return [x, y, x + rng.uniform(5, 40), y + rng.uniform(5, 40)]

class TestIoU(unittest.TestCase):
    def test_matches_torchvision(self):
        rng = random.Random(0)
        for _ in range(200):
            a, b = random_box(rng), random_box(rng)
            expected = box_iou(torch.tensor([a]), torch.tensor([b])).item()
            self.assertAlmostEqual(iou(a, b), expected, places=5)

    def test_no_overlap_is_zero(self):
        self.assertEqual(iou([0, 0, 10, 10], [20, 20, 30, 30]), 0.0)

suite = unittest.defaultTestLoader.loadTestsFromTestCase(TestIoU)
unittest.TextTestRunner(stream=sys.stdout, verbosity=2).run(suite)
```

Without the `max(0.0, ...)`, two boxes far apart in both directions give a negative width times a negative height, a *positive* "overlap", and a nonsense IoU.
:::

### Exercise 4: Non-maximum suppression from scratch

Implement greedy NMS: sort boxes by score, highest first; keep the top box; drop every remaining box whose IoU with it is above the threshold; repeat on what's left. Return the kept indices in the order kept. Compare with `torchvision.ops.nms` on 40 random boxes for thresholds 0.3, 0.5, and 0.7.

```text
threshold 0.3: kept 24, matches torchvision: True
threshold 0.5: kept 35, matches torchvision: True
threshold 0.7: kept 39, matches torchvision: True
```

:::hint
Keep a list `remaining` of indices sorted by score. Each round, pop the first one into `kept`, then rebuild `remaining` with only the boxes whose `iou` with it is at or below the threshold. Your counts will differ from the sample if your random boxes differ.
:::

:::solution
```python run
def my_nms(boxes, scores, threshold):
    remaining = sorted(range(len(boxes)), key=lambda i: scores[i], reverse=True)
    kept = []
    while remaining:
        best = remaining.pop(0)
        kept.append(best)
        remaining = [i for i in remaining if iou(boxes[best], boxes[i]) <= threshold]
    return kept

rng = random.Random(1)
boxes = [random_box(rng) for _ in range(40)]
scores = [rng.random() for _ in range(40)]
for threshold in [0.3, 0.5, 0.7]:
    mine = my_nms(boxes, scores, threshold)
    theirs = nms(torch.tensor(boxes), torch.tensor(scores), threshold).tolist()
    print(f"threshold {threshold}: kept {len(mine)}, matches torchvision: {mine == theirs}")
```

A lower threshold suppresses more aggressively. That's a real trade-off: in a crowd, two people can overlap by more than 0.3, and a strict threshold would delete one of them.
:::

### Exercise 5: A metric that hides the pedestrian

Here's a 12×12 street scene mask: 0 is background, 1 is road, 2 is a small pedestrian. The prediction gets the road nearly right but labels the pedestrian as road. Compute **pixel accuracy** (fraction of pixels correct) and **IoU for each class**, then the mean IoU over the three classes. Plot the two masks side by side.

```python
import torch

truth = torch.zeros(12, 12, dtype=torch.long)
truth[6:, :] = 1               # road across the bottom half
truth[4:8, 5:7] = 2            # a pedestrian, 4 pixels tall, 2 wide
pred = truth.clone()
pred[pred == 2] = 1            # pedestrian predicted as road...
pred[4:6, 5:7] = 0             # ...and its top half as background
pred[6, 0:3] = 0               # a small error at the road's edge
```

:::hint
For class `c`, IoU is `((pred == c) & (truth == c)).sum() / ((pred == c) | (truth == c)).sum()`. Pixel accuracy is `(pred == truth).float().mean()`.
:::

:::solution
```python run alt="Two 12 by 12 masks side by side. The true mask has a dark background top half, a road band across the bottom half, and a small bright pedestrian block in the middle. The predicted mask has the same road and background but no pedestrian at all." caption="The prediction is 92% correct pixel by pixel and completely misses the pedestrian"
truth = torch.zeros(12, 12, dtype=torch.long)
truth[6:, :] = 1
truth[4:8, 5:7] = 2
pred = truth.clone()
pred[pred == 2] = 1
pred[4:6, 5:7] = 0
pred[6, 0:3] = 0

pixel_acc = (pred == truth).float().mean().item()
ious = []
for c, name in enumerate(["background", "road", "pedestrian"]):
    inter = ((pred == c) & (truth == c)).sum().item()
    union = ((pred == c) | (truth == c)).sum().item()
    ious.append(inter / union)
    print(f"IoU {name:<11} {ious[-1]:.2f}")
print(f"pixel accuracy {pixel_acc:.1%}   mean IoU {sum(ious) / 3:.2f}")

fig, axes = plt.subplots(1, 2, figsize=(5.5, 2.8))
for ax, mask, title in [(axes[0], truth, "truth"), (axes[1], pred, "prediction")]:
    ax.imshow(mask, cmap="viridis", vmin=0, vmax=2)
    ax.set_title(title)
    ax.axis("off")
plt.show()
```

Pixel accuracy rewards getting the big classes right, and the pedestrian is only 8 of 144 pixels. Per-class IoU puts every class on an equal footing, so the miss shows up as a 0 that drags the mean down. For anything safety-related, report the per-class numbers, not only the average.
:::

### Exercise 6: When transfer learning loses

Test the transfer bet on the digits. Pretrain the small CNN from Module 5 on digits **0–4**, then use its conv layers as a backbone for digits **5–9**, with only `k` labeled images per class (try k = 3 and k = 10). Compare three strategies on a held-out set of 5–9: training from scratch, frozen backbone with a new head, and fine-tuning everything (backbone at 1e-4, head at 1e-3). Average two random draws of the labeled images. Does transfer help? Why or why not?

:::hint
Relabel 5–9 as 0–4 with `y - 5` so a 5-output head works. Pick `k` images per class with a seeded `torch.Generator`. Train each target model for about 100 epochs on its handful of images, and copy the pretrained backbone with `copy.deepcopy` so runs don't share weights.
:::

:::solution
```python run
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split

digits = load_digits()
X = torch.tensor(digits.images, dtype=torch.float32).unsqueeze(1) / 16
y = torch.tensor(digits.target)
X_src, y_src = X[y < 5], y[y < 5]
X_pool, X_hold, y_pool, y_hold = train_test_split(
    X[y >= 5], y[y >= 5] - 5, test_size=0.5, random_state=0, stratify=y[y >= 5])

def backbone():
    return nn.Sequential(
        nn.Conv2d(1, 16, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
        nn.Conv2d(16, 32, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2), nn.Flatten())

def fit(model, X, y, groups, epochs):
    opt = torch.optim.Adam(groups)
    for _ in range(epochs):
        for idx in torch.randperm(len(y)).split(64):
            loss = F.cross_entropy(model(X[idx]), y[idx])
            opt.zero_grad()
            loss.backward()
            opt.step()
    return model

def acc(model):
    with torch.no_grad():
        return (model(X_hold).argmax(1) == y_hold).float().mean().item()

torch.manual_seed(0)
source = nn.Sequential(backbone(), nn.Linear(128, 5))
fit(source, X_src, y_src, [{"params": source.parameters(), "lr": 1e-3}], epochs=20)

def target_model(strategy):
    body = backbone() if strategy == "scratch" else copy.deepcopy(source[0])
    model = nn.Sequential(body, nn.Linear(128, 5))
    if strategy == "frozen":
        for p in body.parameters():
            p.requires_grad = False
        return model, [{"params": model[1].parameters(), "lr": 1e-3}]
    body_lr = 1e-4 if strategy == "fine-tune" else 1e-3
    return model, [{"params": body.parameters(), "lr": body_lr}, {"params": model[1].parameters(), "lr": 1e-3}]

for k in [3, 10]:
    results = {"scratch": [], "frozen": [], "fine-tune": []}
    for seed in range(2):
        g = torch.Generator().manual_seed(seed)
        picks = torch.cat([torch.nonzero(y_pool == c).flatten()[torch.randperm(int((y_pool == c).sum()), generator=g)[:k]]
                           for c in range(5)])
        for strategy in results:
            torch.manual_seed(seed)
            model, groups = target_model(strategy)
            results[strategy].append(acc(fit(model, X_pool[picks], y_pool[picks], groups, epochs=100)))
    print(f"k={k:>2}: " + "   ".join(f"{s} {sum(v) / len(v):.1%}" for s, v in results.items()))
```

Here transfer loses: training from scratch beats both transfer strategies at both label counts. That's not a bug. Transfer pays off when three things hold, and this setup breaks all of them:

- **The source is much bigger and more varied than the target.** Here it's 900 small images of five digits; ImageNet is 1.28 million photos of 1,000 kinds of things.
- **The model is big enough to overfit a small target from scratch.** This CNN has about 6,000 parameters, so 15 images don't let it memorize much. ResNet-18 has 11.7 million.
- **The target is hard.** Telling 5–9 apart at 8×8 is easy enough that a few examples go a long way.

So measure, don't assume: a from-scratch baseline is the control every transfer-learning result needs.
:::

### Challenge: precision and recall for one image

A detector returned these boxes for an image with three true objects:

```python
truth = [[10, 10, 50, 50], [60, 10, 100, 50], [10, 60, 50, 100]]
preds = [[12, 11, 49, 52], [58, 12, 101, 49], [61, 9, 98, 51], [70, 70, 95, 95], [8, 58, 36, 86]]
scores = [0.95, 0.90, 0.85, 0.60, 0.55]
```

Match predictions to true boxes greedily by score: each prediction, highest score first, claims the unmatched true box it overlaps most, if that IoU is at least 0.5. A matched prediction is a true positive; an unmatched one is a false positive (including a second box on an already-claimed object); an unclaimed true box is a false negative. Report precision, recall, and which mistake each false positive represents. Then repeat at IoU 0.3, and explain why the answer changes.

:::hint
Track `claimed = set()` of true-box indices. For each prediction, compute its IoU with every true box not in `claimed` and take the best. At IoU 0.5 you should find three different kinds of false positive: a duplicate, a box on empty background, and a box in roughly the right place that isn't tight enough. Your `iou` from Exercise 3 does all the geometry.
:::
