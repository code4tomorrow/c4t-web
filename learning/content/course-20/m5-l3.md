## Warm-up: shapes in your head

A 1×28×28 image goes through `Conv2d(1, 8, 5)`, `MaxPool2d(2)`, `Conv2d(8, 16, 3, padding=1)`, and `MaxPool2d(2)`. Write down the shape after each layer.

:::solution
`(8, 24, 24)` because 28 − 5 + 1 = 24. Then `(8, 12, 12)` after pooling. The padded 3×3 conv keeps the size and changes the channels: `(16, 12, 12)`. The last pool gives `(16, 6, 6)`, so a following `Linear` would need `16 * 6 * 6 = 576` inputs.
:::

The exercises below share this setup cell. It loads the digits and trains the baseline CNN from the build-along, which Exercises 5 and 6 test.

```python run
import sys
import unittest
import torch
import torch.nn as nn
import torch.nn.functional as F
import matplotlib.pyplot as plt
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
from torch.utils.data import Dataset, DataLoader
from torchvision.transforms import v2

digits = load_digits()
X = torch.tensor(digits.images, dtype=torch.float32).unsqueeze(1) / 16
y = torch.tensor(digits.target)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)

class Digits(Dataset):
    def __init__(self, images, labels, transform=None):
        self.images, self.labels, self.transform = images, labels, transform
    def __len__(self):
        return len(self.labels)
    def __getitem__(self, i):
        image = self.images[i]
        return (self.transform(image) if self.transform else image), self.labels[i]

def make_cnn():
    return nn.Sequential(
        nn.Conv2d(1, 16, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
        nn.Conv2d(16, 32, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
        nn.Flatten(), nn.Linear(32 * 2 * 2, 10),
    )

def train(transform=None, epochs=20, seed=0):
    torch.manual_seed(seed)
    model = make_cnn()
    loader = DataLoader(Digits(X_train, y_train, transform), batch_size=64, shuffle=True)
    opt = torch.optim.Adam(model.parameters(), lr=1e-3)
    for _ in range(epochs):
        model.train()
        for xb, yb in loader:
            loss = F.cross_entropy(model(xb), yb)
            opt.zero_grad()
            loss.backward()
            opt.step()
    return model.eval()

def accuracy(model, images):
    with torch.no_grad():
        return (model(images).argmax(1) == y_test).float().mean().item()

baseline = train()
print(f"baseline test accuracy: {accuracy(baseline, X_test):.1%}")
```

### Exercise 1: Output sizes, including dilation

A **dilated** convolution spreads its kernel out, leaving gaps of `d − 1` pixels between taps, so a 3×3 kernel with `dilation=2` covers a 5×5 area. The full output-size rule is:

```text
out = floor((n + 2p - d*(k - 1) - 1) / s) + 1
```

Write `conv_out(n, k, s=1, p=0, d=1)` and a `unittest` test that compares it with the real height of `nn.Conv2d` outputs for at least 50 random combinations of input size, kernel, stride, padding, and dilation. Skip combinations where the kernel doesn't fit.

```text
test_matches_pytorch (__main__.TestConvOut.test_matches_pytorch) ... ok
----------------------------------------------------------------------
Ran 1 test in 0.140s

OK
```

:::hint
With `d = 1` the formula reduces to the one from the notes. Use `random.randint` for each setting, and `self.subTest(...)` so a failure tells you which combination broke. A combination is invalid when `n + 2p < d*(k - 1) + 1`.
:::

:::solution
```python run
import random

def conv_out(n, k, s=1, p=0, d=1):
    return (n + 2 * p - d * (k - 1) - 1) // s + 1

class TestConvOut(unittest.TestCase):
    def test_matches_pytorch(self):
        random.seed(0)
        checked = 0
        while checked < 50:
            n, k = random.randint(4, 20), random.choice([1, 3, 5])
            s, p, d = random.randint(1, 3), random.randint(0, 2), random.randint(1, 3)
            if n + 2 * p < d * (k - 1) + 1:
                continue
            layer = nn.Conv2d(1, 1, k, stride=s, padding=p, dilation=d)
            real = layer(torch.zeros(1, 1, n, n)).shape[-1]
            with self.subTest(n=n, k=k, s=s, p=p, d=d):
                self.assertEqual(conv_out(n, k, s, p, d), real)
            checked += 1

suite = unittest.defaultTestLoader.loadTestsFromTestCase(TestConvOut)
unittest.TextTestRunner(stream=sys.stdout, verbosity=2).run(suite)
```

The `- d*(k - 1) - 1` part is the effective kernel size `d*(k - 1) + 1` written out; with `d = 1` it's just `k`.
:::

### Exercise 2: Where do the parameters live?

This CNN is for 3×32×32 color images (CIFAR-10 size):

```python
import torch.nn as nn

cifar_cnn = nn.Sequential(
    nn.Conv2d(3, 32, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
    nn.Conv2d(32, 64, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
    nn.Flatten(), nn.Linear(64 * 8 * 8, 10),
)
```

By hand, count the parameters in each layer that has any, and the total. Which layer holds the most? Then count again after replacing `Flatten` + `Linear` with `nn.AdaptiveAvgPool2d(1)`, `nn.Flatten()`, `nn.Linear(64, 10)`. Check both totals in code.

:::hint
Use C_out × C_in × k × k + C_out for each conv and in × out + out for each linear. Pooling, ReLU, and Flatten have none.
:::

:::solution
Conv 1: 32 × 3 × 9 + 32 = 896. Conv 2: 64 × 32 × 9 + 64 = 18,496. Linear: 4,096 × 10 + 10 = 40,970. Total 60,362, and the final linear layer holds about two thirds of it. With global average pooling the linear layer shrinks to 64 × 10 + 10 = 650, for a total of 20,042.

```python run
count = lambda model: sum(p.numel() for p in model.parameters())
cifar_cnn = nn.Sequential(
    nn.Conv2d(3, 32, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
    nn.Conv2d(32, 64, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
    nn.Flatten(), nn.Linear(64 * 8 * 8, 10),
)
gap_cnn = nn.Sequential(*list(cifar_cnn)[:6], nn.AdaptiveAvgPool2d(1), nn.Flatten(), nn.Linear(64, 10))
print("per layer:", [count(layer) for layer in cifar_cnn if count(layer)])
print("flatten head:", count(cifar_cnn), " global-average head:", count(gap_cnn))
print(tuple(gap_cnn(torch.zeros(2, 3, 32, 32)).shape))
```

This is why most modern CNNs, ResNet included, end with global average pooling: the conv layers are cheap, and a big flattened map feeding a dense layer is where parameters pile up.
:::

### Exercise 3: Design a line detector

Build a 24×24 test image with a bright horizontal line, a bright vertical line, and a bright diagonal on a dark background. Design a 3×3 kernel that responds strongly to **horizontal lines** (a bright row with dark rows above and below), and weakly to the other two lines. Also make a 3×3 box blur. Apply both with `F.conv2d` and plot the input and the two outputs. Print the strongest response along each line.

```text
strongest response  horizontal: 6.0  vertical: 0.0  diagonal: 1.0
```

:::hint
A kernel gives zero on flat areas when its numbers sum to zero. Put positive weights where the line should be (the middle row) and negative weights above and below. A box blur is all ninths.
:::

:::solution
```python run alt="Three panels: the input with a horizontal, a vertical, and a diagonal white line on black; the line-detector output, bright along the horizontal line, faint along the diagonal, and blank along the vertical line; the blurred image with all three lines softened." caption="A horizontal-line kernel ignores the vertical line entirely and barely responds to the diagonal"
img = torch.zeros(24, 24)
img[5, 2:22] = 1.0                      # horizontal line
img[8:22, 4] = 1.0                      # vertical line
for i in range(10):
    img[11 + i, 9 + i] = 1.0            # diagonal

line = torch.tensor([[-1., -1., -1.], [2., 2., 2.], [-1., -1., -1.]])
blur = torch.full((3, 3), 1 / 9)
out = F.conv2d(img.reshape(1, 1, 24, 24), torch.stack([line, blur]).unsqueeze(1), padding=1)[0]

print(f"strongest response  horizontal: {out[0, 5, 6:18].max():.1f}"
      f"  vertical: {out[0, 12:18, 4].max():.1f}  diagonal: {out[0, 13:18, 11:16].max():.1f}")

fig, axes = plt.subplots(1, 3, figsize=(8, 2.9))
for ax, image, title in zip(axes, [img, out[0].clamp(min=0), out[1]], ["input", "line detector (ReLU)", "box blur"]):
    ax.imshow(image, cmap="gray")
    ax.set_title(title)
    ax.axis("off")
plt.tight_layout()
plt.show()
```

On the horizontal line the middle row contributes 2 + 2 + 2 and the dark rows contribute nothing: 6. On the vertical line each row of the window holds one bright pixel, so the sum is −1 + 2 − 1 = 0. Centered on the diagonal, the window also holds one bright pixel per row and sums to 0; one pixel to the side it catches the middle-row pixel and only one outer pixel, which leaves 1. A tilted line is a weak, partial match.
:::

### Exercise 4: Fix the crash

This network is meant for the digits, but it crashes on the first batch:

```python run raises
broken = nn.Sequential(
    nn.Conv2d(1, 16, 3), nn.ReLU(), nn.MaxPool2d(2),
    nn.Conv2d(16, 32, 3), nn.ReLU(),
    nn.Flatten(), nn.Linear(32 * 2 * 2, 10),
)
broken(X_train[:4])
```

Explain both numbers in `(4x32 and 128x10)`, then fix it two ways: once by correcting `in_features`, and once without computing it at all.

:::hint
Trace the height: no padding means each 3×3 conv shrinks the size by 2. For the second fix, look up `nn.LazyLinear` in the PyTorch docs.
:::

:::solution
`4x32` is the input to the linear layer: 4 images, each flattened to 32 numbers, because 8 → 6 (conv) → 3 (pool) → 1 (conv) leaves a 32×1×1 map. `128x10` is the layer's weight as PyTorch multiplies it: it expects 128 inputs. Fix 1 is `nn.Linear(32, 10)`. Fix 2 is `nn.LazyLinear(10)`, which reads its input size from the first batch:

```python run
fixed = nn.Sequential(
    nn.Conv2d(1, 16, 3), nn.ReLU(), nn.MaxPool2d(2),
    nn.Conv2d(16, 32, 3), nn.ReLU(),
    nn.Flatten(), nn.LazyLinear(10),
)
print(tuple(fixed(X_train[:4]).shape), fixed[-1].weight.shape)
```

Run one dummy batch through a lazy model **before** creating the optimizer; until then its weights don't exist yet.
:::

### Exercise 5: Stress-test the baseline

Real inputs vary in ways your test split doesn't. Build six altered copies of `X_test`: shifted right one pixel, rotated 15°, faded (`X_test * 0.5 + 0.25`, a washed-out scan), Gaussian noise with standard deviation 0.15 (clamped to 0 to 1), slightly blurred, and flipped left to right. Print the baseline's accuracy on each. Which drop would you fix with augmentation, and which would you leave alone?

:::hint
`torchvision.transforms.v2.functional` has `rotate`, `gaussian_blur`, and `horizontal_flip`, and each one works on a whole batch tensor (here, applying the same change to every image is exactly what you want). Seed before adding noise so your numbers are repeatable.
:::

:::solution
```python run
import torchvision.transforms.v2.functional as TF

def shift_right(images, pixels=1):
    moved = torch.zeros_like(images)
    moved[..., pixels:] = images[..., :-pixels]
    return moved

torch.manual_seed(0)
stress = {
    "original": X_test,
    "shift 1": shift_right(X_test),
    "rotate 15": TF.rotate(X_test, 15),
    "faded": X_test * 0.5 + 0.25,
    "noise": (X_test + 0.15 * torch.randn_like(X_test)).clamp(0, 1),
    "blur": TF.gaussian_blur(X_test, kernel_size=3, sigma=0.8),
    "flipped": TF.horizontal_flip(X_test),
}
for name, images in stress.items():
    print(f"{name:<10} {accuracy(baseline, images):.1%}")
```

Read the table as a list of risks. The one-pixel shift is the disaster: about half the digits come out wrong. Rotation, fading, and blur each cost several points, and all three are realistic for scanned forms (a crooked page, a faint photocopy, a cheap scanner), so they're worth augmenting. Noise at this level barely matters. The flipped score should stay low: a mirrored digit isn't a valid input, so a model that "handles" flips has learned to read nonsense. (It isn't near 10% because 0, 1, and 8 look much the same mirrored.)
:::

### Exercise 6: Write your own augmentation for faded scans

`v2` doesn't have a transform for "washed out toward gray". It doesn't need one: any callable that takes an image and returns an image can go in `v2.Compose`. Write a class `RandomFade(max_lift)` that picks a random `lift` between 0 and `max_lift` and returns `image * (1 - lift) + lift / 2`. Train a CNN with `v2.Compose([RandomFade(0.6), v2.RandomAffine(degrees=0, translate=(0.15, 0.15))])` and compare it with the baseline on the original, shifted, and faded sets.

:::hint
Draw the random number with `torch.rand(1).item()` rather than Python's `random` module, so `torch.manual_seed` controls it. Give the augmented model 30 epochs.
:::

:::solution
```python run
class RandomFade:
    """Blend the image toward mid-gray by a random amount up to max_lift."""
    def __init__(self, max_lift=0.6):
        self.max_lift = max_lift

    def __call__(self, image):
        lift = torch.rand(1).item() * self.max_lift
        return image * (1 - lift) + lift / 2

augment = v2.Compose([RandomFade(0.6), v2.RandomAffine(degrees=0, translate=(0.15, 0.15))])
robust = train(augment, epochs=30)
for name in ["original", "shift 1", "faded"]:
    print(f"{name:<10} baseline {accuracy(baseline, stress[name]):.1%}   augmented {accuracy(robust, stress[name]):.1%}")
```

Both weak spots improve sharply, at the cost of a few points on the original images. The faded test set (`0.5x + 0.25`) is exactly what `RandomFade` produces with `lift = 0.5`, inside the range the model trained on. In a real project you'd set `max_lift` from the faintest scans you've actually seen, not from the test set; otherwise you're tuning to the answer.
:::
