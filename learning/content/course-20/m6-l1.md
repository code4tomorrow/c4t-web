A school garden club wants an app that tells three tomato-leaf diseases apart, and they've photographed 40 leaves of each. ResNet-18, one of the smaller standard vision networks, has 11.7 million parameters. Train it from scratch on 120 photos and it will memorize every leaf, including the shadows and the table it was photographed on, and learn almost nothing that carries over to a new leaf.

But somebody has already trained ResNet-18 on ImageNet: 1.28 million photos in 1,000 categories. Most of what that network learned isn't about those 1,000 categories at all. It's about edges, textures, and shapes, and leaves have all three. **Transfer learning** keeps that knowledge and retrains only the part that's specific to the new task.

## What a pretrained network already knows

You saw the first step of this in the last module: the first conv layer of your digit CNN learned edge detectors. A deep network trained on millions of photos stacks many such layers, and each one builds on the one before:

- **Early layers** respond to edges, color contrasts, and simple blobs. They're useful for almost any photo.
- **Middle layers** combine those into textures and parts: fur, mesh, wheels, veins on a leaf.
- **The last layer** maps the final 512 features to ImageNet's 1,000 class scores. That's the only part that is truly about ImageNet.

So the recipe is: keep everything up to the last layer (the **backbone**), throw away the last layer (the **head**), and attach a new head with one output per class in your task.

## Look inside ResNet-18

`torchvision.models` builds the architecture. With `weights=None` you get random weights and nothing is downloaded, which is enough to look at its structure:

```python run
import torch
import torch.nn as nn
from torchvision import models

model = models.resnet18(weights=None)
print([name for name, _ in model.named_children()])
print(model.fc)
print(f"{sum(p.numel() for p in model.parameters()):,} parameters")
```

The ten top-level parts are a stem (`conv1`, `bn1`, `relu`, `maxpool`), four stages of residual blocks (`layer1` to `layer4`), global average pooling (`avgpool`), and the head (`fc`): a `Linear` from 512 features to 1,000 classes.

In Colab you load the real ImageNet weights by passing a weights enum. The weights object also carries the exact preprocessing the network was trained with, so you don't have to remember the resize size or the normalization numbers. The first call downloads about 45 MB; if it stops with a network error, check the runtime is connected and run the cell again.

```python
from torchvision import models

weights = models.ResNet18_Weights.DEFAULT      # currently IMAGENET1K_V1
model = models.resnet18(weights=weights)
preprocess = weights.transforms()              # resize to 256, center-crop 224, normalize
print(weights.meta["categories"][:5])          # the 1,000 ImageNet class names
```

## Freeze the backbone, replace the head

Freezing means telling autograd not to compute gradients for a parameter, by setting `requires_grad = False`. Then the head is replaced with a fresh `Linear` whose output size is your number of classes. New layers are created with `requires_grad=True`, so only the head will learn:

```python run
for p in model.parameters():
    p.requires_grad = False
model.fc = nn.Linear(model.fc.in_features, 3)          # 512 -> 3 leaf classes

trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)
total = sum(p.numel() for p in model.parameters())
print(f"trainable {trainable:,} of {total:,}")

optimizer = torch.optim.Adam(model.fc.parameters(), lr=1e-3)
print(tuple(model(torch.zeros(2, 3, 224, 224)).shape))
```

From 11 million trainable numbers down to 1,539 (512 × 3 weights plus 3 biases). A linear classifier with 1,539 parameters is something 120 photos can train without memorizing. This setting is often called **feature extraction**: the frozen backbone turns each photo into 512 good features, and you fit a small classifier on top.

## When to fine-tune more than the head

Sometimes the frozen features aren't quite right for your images. **Fine-tuning** unfreezes some or all of the backbone and keeps training it, gently. The question is how much to unfreeze, and it depends on two things: how much labeled data you have, and how much your images look like ImageNet's everyday photos.

| Your data | Similar to everyday photos | Very different (X-rays, satellite, microscope) |
| --- | --- | --- |
| Small (tens to a few hundred per class) | Freeze the backbone, train the head | Fine-tune the last stage too, with a small learning rate |
| Large (thousands per class) | Fine-tune everything with a small learning rate | Fine-tune everything; training from scratch becomes an option |

When you do unfreeze, give the pretrained layers a smaller learning rate than the new head. Their weights are already good, and big steps would wreck them before the head has learned anything useful. PyTorch optimizers take a list of **parameter groups**, each with its own settings:

```python run
for p in model.layer4.parameters():
    p.requires_grad = True

optimizer = torch.optim.AdamW([
    {"params": model.layer4.parameters(), "lr": 1e-4},   # pretrained: small steps
    {"params": model.fc.parameters(), "lr": 1e-3},       # new head: larger steps
])
trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)
print(f"trainable now {trainable:,}")
print([group["lr"] for group in optimizer.param_groups])
```

A common schedule is to train the head alone for a few epochs first, then unfreeze `layer4` and continue. Starting fine-tuning with a random head sends large, random gradients into the pretrained layers.

## Beyond one label per image

Classification answers "what is in this photo?" with one label. Many products need more than that: a self-checkout camera needs to know *where* each item is, and a medical tool may need the exact outline of a lesion. Three tasks, three kinds of output:

| Task | Answers | Output for one image |
| --- | --- | --- |
| Classification | What is it? | One score per class |
| Object detection | What, and where? | A list of boxes `(x1, y1, x2, y2)`, each with a label and a confidence score |
| Semantic segmentation | Which class is each pixel? | A class score map per class, the same size as the image |
| Instance segmentation | Which pixels belong to each separate object? | One mask per object, plus a box, label, and score |

Detectors and segmenters are built the same way as your leaf classifier: a pretrained backbone with a task-specific head on top. torchvision ships pretrained versions trained on the COCO dataset. Both downloads are over 150 MB, so if Colab stops with a timeout error, run the cell again:

```python
import torch
from torchvision.io import decode_image, ImageReadMode
from torchvision.models.detection import fasterrcnn_resnet50_fpn_v2, FasterRCNN_ResNet50_FPN_V2_Weights
from torchvision.models.segmentation import deeplabv3_resnet50, DeepLabV3_ResNet50_Weights

img = decode_image("street.jpg", mode=ImageReadMode.RGB)     # uint8 tensor (3, H, W)

det_weights = FasterRCNN_ResNet50_FPN_V2_Weights.DEFAULT
detector = fasterrcnn_resnet50_fpn_v2(weights=det_weights, box_score_thresh=0.5).eval()
with torch.no_grad():
    found = detector([det_weights.transforms()(img)])[0]     # a list in, a list of dicts out
print(found["boxes"].shape, found["scores"])
print([det_weights.meta["categories"][i] for i in found["labels"]])

seg_weights = DeepLabV3_ResNet50_Weights.DEFAULT
segmenter = deeplabv3_resnet50(weights=seg_weights).eval()
with torch.no_grad():
    scores = segmenter(seg_weights.transforms()(img).unsqueeze(0))["out"]   # (1, 21, H', W')
pixel_classes = scores.argmax(1)                              # a class index for every pixel
```

`found["boxes"]` has shape (N, 4), one row per detected object, in pixel coordinates. The segmenter returns 21 score maps (20 object classes plus background), and taking `argmax` over that dimension gives one class per pixel.

## Scoring a box: intersection over union

A predicted box is never exactly the true box, so detection needs a measure of "close enough". **Intersection over union** divides the area where the two boxes overlap by the area they cover together. Identical boxes score 1; boxes that don't touch score 0. A common convention counts a detection as correct when IoU ≥ 0.5 with a true box of the same class.

Detectors also produce many overlapping boxes for the same object. **Non-maximum suppression** (NMS) cleans that up: keep the highest-scoring box, delete every other box that overlaps it by more than a threshold, and repeat with what's left. Both are one call in `torchvision.ops`:

```python run alt="Two panels showing the same scene with a green true box around one object and a second green box around another. Left, before NMS: four red predicted boxes, three crowded around the first object and one on the second, each labeled with its score and IoU. Right, after NMS: only two red boxes remain, the best one on each object." caption="Before and after non-maximum suppression at an IoU threshold of 0.5"
import matplotlib.pyplot as plt
import matplotlib.patches as patches
from torchvision.ops import box_iou, nms

truth = torch.tensor([[20., 30., 120., 130.], [150., 60., 230., 140.]])
preds = torch.tensor([[25., 35., 125., 128.], [10., 20., 110., 120.],
                      [40., 50., 130., 150.], [155., 55., 225., 150.]])
scores = torch.tensor([0.92, 0.81, 0.64, 0.88])

best_iou = box_iou(preds, truth).max(dim=1).values
keep = nms(preds, scores, iou_threshold=0.5)
print("IoU of each prediction with its nearest true box:", [round(v, 2) for v in best_iou.tolist()])
print("kept after NMS:", keep.tolist())

fig, axes = plt.subplots(1, 2, figsize=(8, 3.4))
for ax, shown, title in [(axes[0], range(4), "before NMS"), (axes[1], keep.tolist(), "after NMS")]:
    for x1, y1, x2, y2 in truth.tolist():
        ax.add_patch(patches.Rectangle((x1, y1), x2 - x1, y2 - y1, fill=False, ec="#2e9d5b", lw=2.5))
    for i in shown:
        x1, y1, x2, y2 = preds[i].tolist()
        ax.add_patch(patches.Rectangle((x1, y1), x2 - x1, y2 - y1, fill=False, ec="#d9534f", lw=1.3))
        ax.text(x1 + 3, y1 + 10, f"{scores[i]:.2f} / IoU {best_iou[i]:.2f}", fontsize=7, color="#d9534f",
                bbox=dict(fc="white", ec="none", pad=1))
    ax.set(xlim=(0, 250), ylim=(170, 0), title=title, aspect="equal")
    ax.set_xticks([])
    ax.set_yticks([])
plt.tight_layout()
plt.show()
```

NMS kept box 0 (score 0.92) and box 3 (0.88). Boxes 1 and 2 overlapped box 0 by more than 0.5, so they were dropped even though each of them, alone, would have been a fine detection. The same IoU idea scores segmentation: count the pixels in both masks, divide by the pixels in either.

:::warning
**A frozen backbone isn't completely frozen in training mode.** ResNet's BatchNorm layers update their running mean and variance on every forward pass in `model.train()`, whether or not `requires_grad` is set. With a small dataset, those statistics drift away from what the pretrained weights expect, and accuracy at test time drops for no obvious reason. When you train only the head, keep the backbone in eval mode (`model.eval()`, since the new head has no dropout or BatchNorm of its own).
:::

:::warning
**Preprocessing must match the pretrained weights.** The ImageNet weights expect 224×224 crops normalized with ImageNet's mean and standard deviation. Feed raw 0–255 pixels, or skip the normalization, and the "pretrained" features are nonsense. Use `weights.transforms()`, or copy its settings into your own `v2.Compose`.
:::

:::quiz
Q: You have 300 photos of five dog breeds and an ImageNet-trained ResNet-18. What's the best first experiment?
- [x] Freeze the backbone and train a new 5-class head
  Dog photos look like ImageNet (which has many dog breeds), and 300 photos is small, so the frozen features are a strong, cheap start.
- [ ] Train ResNet-18 from scratch so it learns dog-specific features
  With 300 photos, 11.7 million parameters will memorize the training set.
- [ ] Fine-tune every layer with the same learning rate as the new head
  Large steps on the pretrained layers, driven by a random head, can erase what made them useful.

Q: After freezing every parameter of ResNet-18 and replacing `fc` with `nn.Linear(512, 5)`, how many parameters are trainable?
- [ ] 512
  That's the number of input features, not the number of weights.
- [x] 2,565
  512 × 5 weights plus 5 biases.
- [ ] About 11.2 million
  That's the total; the frozen ones don't count as trainable.

Q: A true box is `(0, 0, 4, 4)` and a predicted box is `(2, 0, 6, 4)`. What is their IoU?
- [ ] 0.5
  Half of each box overlaps, but the union is bigger than either box.
- [x] About 0.33
  Overlap is 2 × 4 = 8. Union is 16 + 16 − 8 = 24. 8 / 24 = 1/3.
- [ ] 0.25
  That's 8 / 32, the overlap divided by both areas added together. The union counts the shared area once, so it's 24.

Q: A biology lab wants to count the cells in each microscope image and measure each one's area. Which output fits?
- [ ] Classification
  One label per image can't count or measure.
- [ ] Semantic segmentation
  It labels every pixel "cell" or "background", so two touching cells merge into one blob.
- [x] Instance segmentation
  Each cell gets its own mask, so you can count them and measure each one's area.
:::

:::takeaways
- A pretrained backbone has learned general visual features; replacing only the head lets a few hundred labels train a good classifier.
- Freeze with `requires_grad = False`, replace `model.fc`, and pass only trainable parameters to the optimizer.
- Unfreeze more as you get more data or as your images move away from everyday photos, with smaller learning rates for pretrained layers.
- Detection returns boxes, labels, and scores; segmentation returns a class per pixel (semantic) or a mask per object (instance).
- IoU measures overlap; NMS uses it to remove duplicate boxes for the same object.
:::
