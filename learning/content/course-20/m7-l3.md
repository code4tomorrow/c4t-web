## Warm-up: memory in your head

A model has 60 million parameters and trains in float32. How much memory do the weights, gradients, and optimizer state need with Adam? With plain SGD and no momentum?

:::solution
Adam: 4 (weights) + 4 (gradients) + 8 (two running averages) = 16 bytes per parameter, so 60M × 16 = 960 MB. Plain SGD keeps no extra state: 8 bytes per parameter, 480 MB. SGD with momentum keeps one running average: 12 bytes, 720 MB. Activations come on top of all three.
:::

Run the setup cell first:

```python run
import sys
import random
import unittest
import numpy as np
import torch
import torch.nn as nn
import torch.nn.functional as F
import matplotlib.pyplot as plt
from torchvision import models
from sklearn.datasets import load_digits

digits = load_digits()
X = torch.tensor(digits.images, dtype=torch.float32).unsqueeze(1) / 16
y = torch.tensor(digits.target)
print("ready:", tuple(X.shape))
```

### Exercise 1: A memory estimator

Write `training_memory_mb(model, optimizer)` that returns the megabytes (10⁶ bytes) needed for weights, gradients, and optimizer state in float32, for `"sgd"`, `"momentum"`, and `"adam"`. Count only parameters with `requires_grad=True` for gradients and optimizer state, since frozen layers need neither. Print a table for ResNet-18 and ResNet-50 (with `weights=None`), plus ResNet-50 with everything frozen except a new 10-class head.

```text
model                    sgd  momentum      adam
resnet18                93.5     140.3     187.0
resnet50               204.5     306.7     408.9
resnet50, head only     94.2      94.3      94.4
```

:::hint
Weights always cost 4 bytes per parameter. Gradients cost 4 per trainable parameter. Momentum adds 4 per trainable parameter and Adam adds 8.
:::

:::solution
```python run
def training_memory_mb(model, optimizer):
    total = sum(p.numel() for p in model.parameters())
    trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)
    state = {"sgd": 0, "momentum": 4, "adam": 8}[optimizer]
    return (4 * total + (4 + state) * trainable) / 1e6

frozen50 = models.resnet50(weights=None)
for p in frozen50.parameters():
    p.requires_grad = False
frozen50.fc = nn.Linear(frozen50.fc.in_features, 10)

print(f"{'model':<20}{'sgd':>8}{'momentum':>10}{'adam':>10}")
for name, net in [("resnet18", models.resnet18(weights=None)), ("resnet50", models.resnet50(weights=None)),
                  ("resnet50, head only", frozen50)]:
    print(f"{name:<20}" + "".join(f"{training_memory_mb(net, opt):>{w}.1f}"
                                    for opt, w in [("sgd", 8), ("momentum", 10), ("adam", 10)]))
```

With only the head trainable, the optimizer barely matters: almost all of the memory is the frozen weights themselves. That's one more reason feature extraction is cheap.
:::

### Exercise 2: The largest batch that fits

For ResNet-18 trained with Adam, estimate the per-image activation memory at 224×224 and at 128×128 (sum every leaf layer's output size, as in the notes). With a 15 GB GPU and 20% kept free as headroom, what is the largest power-of-two batch size at each resolution?

:::hint
Usable memory is 15 × 0.8 = 12 GB. Subtract the fixed cost from Exercise 1, divide by the per-image cost, and round down to a power of two with `2 ** int(np.log2(n))`. Use a fresh model for each measurement so old hooks don't add up.
:::

:::solution
```python run
def activation_gb_per_image(size):
    net, outputs = models.resnet18(weights=None), []
    for module in net.modules():
        if not list(module.children()):
            module.register_forward_hook(lambda m, i, out: outputs.append(out.numel()))
    with torch.no_grad():
        net(torch.zeros(1, 3, size, size))
    return sum(outputs) * 4 / 1e9

fixed_gb = training_memory_mb(models.resnet18(weights=None), "adam") / 1000
usable_gb = 15 * 0.8
for size in [224, 128]:
    per_image = activation_gb_per_image(size)
    fits = int((usable_gb - fixed_gb) / per_image)
    print(f"{size}x{size}: {per_image * 1000:.1f} MB per image, fits {fits}, use batch {2 ** int(np.log2(fits))}")
```

Shrinking images from 224 to 128 cuts the pixels per feature map by about two thirds, so about three times as many images fit. This is only an estimate; confirm with `torch.cuda.max_memory_allocated()` on the real GPU before a long run.
:::

### Exercise 3: Gradient accumulation really matches the big batch

Take `nn.Linear(64, 10)` and 64 digit images. Compute the gradient of the mean cross-entropy loss on all 64 at once. Then zero the gradients and accumulate over four micro-batches of 16, calling `backward()` on each micro-batch's loss **divided by 4**. Write a `unittest` that checks the two gradients match with `torch.allclose`, and a second test showing that forgetting the division gives gradients four times too large.

:::hint
`backward()` adds into `.grad`; it doesn't overwrite. The mean over 64 equals the average of the four means over 16, which is why each micro-batch loss is divided by the number of micro-batches.
:::

:::solution
```python run
def big_and_accumulated(divide):
    torch.manual_seed(0)
    layer = nn.Linear(64, 10)
    xb, yb = X[:64].flatten(1), y[:64]
    F.cross_entropy(layer(xb), yb).backward()
    big = layer.weight.grad.clone()
    layer.weight.grad = None
    for chunk_x, chunk_y in zip(xb.split(16), yb.split(16)):
        loss = F.cross_entropy(layer(chunk_x), chunk_y)
        (loss / 4 if divide else loss).backward()
    return big, layer.weight.grad

class TestAccumulation(unittest.TestCase):
    def test_matches_big_batch(self):
        big, accumulated = big_and_accumulated(divide=True)
        self.assertTrue(torch.allclose(big, accumulated, atol=1e-6))

    def test_forgetting_to_divide_scales_by_four(self):
        big, accumulated = big_and_accumulated(divide=False)
        self.assertTrue(torch.allclose(4 * big, accumulated, atol=1e-5))

suite = unittest.defaultTestLoader.loadTestsFromTestCase(TestAccumulation)
unittest.TextTestRunner(stream=sys.stdout, verbosity=2).run(suite)
```

The bug in the second test doesn't crash anything; it just behaves like a learning rate four times too high. One caveat: accumulation matches a big batch exactly only for models without BatchNorm, whose statistics are computed per micro-batch.
:::

### Exercise 4: The seed that didn't seed

This augmentation uses Python's `random` module to decide whether to add noise. Write a test that trains twice with `torch.manual_seed(0)` and checks the final weights are identical. Run it, explain why it fails, and fix `noisy` so the test passes.

```python
def noisy(images):
    if random.random() < 0.5:                       # Python's generator, not PyTorch's
        images = images + 0.1 * torch.randn_like(images)
    return images

def train(seed):
    torch.manual_seed(seed)
    model = nn.Linear(64, 10)
    opt = torch.optim.SGD(model.parameters(), lr=0.1)
    for idx in torch.randperm(256).split(32):
        loss = F.cross_entropy(model(noisy(X[idx]).flatten(1)), y[idx])
        opt.zero_grad()
        loss.backward()
        opt.step()
    return model.weight.detach()
```

:::hint
`torch.manual_seed` seeds PyTorch's generators only. Python's `random` and NumPy each have their own. Either seed them too, or draw the coin flip with `torch.rand(1).item()`.
:::

:::solution
```python run
def noisy(images):
    if random.random() < 0.5:
        images = images + 0.1 * torch.randn_like(images)
    return images

def train(seed):
    torch.manual_seed(seed)
    model = nn.Linear(64, 10)
    opt = torch.optim.SGD(model.parameters(), lr=0.1)
    for idx in torch.randperm(256).split(32):
        loss = F.cross_entropy(model(noisy(X[idx]).flatten(1)), y[idx])
        opt.zero_grad()
        loss.backward()
        opt.step()
    return model.weight.detach()

class TestReproducible(unittest.TestCase):
    def test_same_seed_same_weights(self):
        self.assertTrue(torch.equal(train(0), train(0)))

random.seed(1)
print("before the fix:")
unittest.TextTestRunner(stream=sys.stdout, verbosity=1).run(
    unittest.defaultTestLoader.loadTestsFromTestCase(TestReproducible))

def noisy(images):
    if torch.rand(1).item() < 0.5:                  # now controlled by torch.manual_seed
        images = images + 0.1 * torch.randn_like(images)
    return images

print("after the fix:")
unittest.TextTestRunner(stream=sys.stdout, verbosity=1).run(
    unittest.defaultTestLoader.loadTestsFromTestCase(TestReproducible))
```

Python's `random` kept advancing between the two training runs, so the coin flips differed and so did the noise. Libraries you call can hide the same problem, which is why a "same seed, same weights" test belongs in every project.

### Exercise 5: Read a confusion matrix

A wildlife-camera classifier for four animals produced this confusion matrix on its test set (rows are the true class, columns the prediction):

```python
import numpy as np

classes = ["deer", "fox", "coyote", "wolf"]
cm = np.array([
    [190,   4,   3,   3],
    [  2, 141,  52,   5],
    [  1,  20, 166,  13],
    [  0,   2,  24,  74],
])
```

Compute overall accuracy, then precision and recall for every class. Which pair of classes gets confused most, and in which direction? Which class would you collect more data for first?

:::hint
Recall for class `i` is `cm[i, i] / cm[i].sum()` (the row). Precision is `cm[i, i] / cm[:, i].sum()` (the column). For the most confused pair, zero the diagonal and find the largest remaining cell with `np.unravel_index(off.argmax(), off.shape)`.
:::

:::solution
```python run
classes = ["deer", "fox", "coyote", "wolf"]
cm = np.array([[190, 4, 3, 3], [2, 141, 52, 5], [1, 20, 166, 13], [0, 2, 24, 74]])

print(f"accuracy {np.trace(cm) / cm.sum():.1%}")
for i, name in enumerate(classes):
    print(f"{name:<7} precision {cm[i, i] / cm[:, i].sum():.1%}   recall {cm[i, i] / cm[i].sum():.1%}")
off = cm.copy()
np.fill_diagonal(off, 0)
t, p = np.unravel_index(off.argmax(), off.shape)
print(f"most common mistake: true {classes[t]} predicted as {classes[p]} ({off[t, p]} times)")
```

Foxes are called coyotes 52 times, while coyotes are called foxes only 20 times, so the confusion is lopsided, and fox has the lowest recall. Wolf is close behind: a quarter of the wolves are missed, again mostly as coyotes, and wolf is the rarest class with only 100 test images. Coyote's low precision is the other side of the same coin, since it soaks up foxes and wolves. More fox and coyote photos in similar poses and lighting, and more wolves overall, are the first data to collect.
:::

### Exercise 6: How many images does a subgroup need?

A street-sign detector scores 95.1% on 900 daytime test images and 85.0% on 60 nighttime ones. Compute 95% Wilson intervals for both. Then find the smallest number of night images for which the night interval would be at most ±3 points wide, assuming accuracy stays at 85%.

:::hint
Reuse the `wilson` function from the build-along. Loop `n` upward from 60 until `(high - low) / 2 <= 0.03`. The number of correct images is `round(0.85 * n)`.
:::

:::solution
```python run
def wilson(correct, n, z=1.96):
    p = correct / n
    centre = (p + z * z / (2 * n)) / (1 + z * z / n)
    half = z * np.sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / (1 + z * z / n)
    return centre - half, centre + half

for name, n, acc in [("day", 900, 0.951), ("night", 60, 0.85)]:
    low, high = wilson(round(acc * n), n)
    print(f"{name:<6} n={n:<4} {acc:.1%}  interval {low:.1%} to {high:.1%}")

n = 60
while True:
    low, high = wilson(round(0.85 * n), n)
    if (high - low) / 2 <= 0.03:
        break
    n += 1
print(f"night images needed for +/-3 points: {n}")
```

Here the intervals don't overlap, so the night gap is real even with 60 images. But "somewhere between 74% and 92%" is too vague to set a safety threshold with; you need several hundred night images to pin it down to a few points. Plan subgroup test sets by the precision you need, not by their share of the data.
:::

### Challenge: is the model's confidence honest?

Train a small classifier on the digits (any model from this course), and for every test prediction record the top probability and whether it was right. Split predictions into 10 bins by confidence (0.0–0.1, …, 0.9–1.0). In each bin, compare the average confidence with the actual accuracy, plot the two against each other (a **reliability diagram**), and compute the **expected calibration error**: the average gap between confidence and accuracy across bins, weighted by how many predictions fall in each bin. Is your model overconfident or underconfident?

:::hint
`np.digitize(conf, np.linspace(0, 1, 11)[1:-1])` assigns each prediction a bin from 0 to 9. Skip empty bins. A perfectly calibrated model's points lie on the diagonal line from (0, 0) to (1, 1); points below it mean the model is more confident than it is accurate.
:::
