:::objectives
- Write a sigmoid neuron's forward pass and binary cross-entropy loss with plain tensor operations.
- Derive its gradient, `Xᵀ(p − y) / N`, and verify it two independent ways.
- Train it with a hand-written update loop and draw the path it takes across the loss surface.
- Run a learning-rate sweep and read the crawl, the sweet spot, and the cliff.
- Replace the hand-written update with `torch.optim.SGD` and get identical weights.
:::

In the Notes you computed one gradient for one example. Now you'll do it for a whole dataset, the way a real training loop does, and you won't trust your own math until two independent checks agree with it. The model is the smallest real classifier there is: one neuron with a sigmoid, separating two clouds of points. It has only two weights, so you can draw its entire loss surface and watch training walk across it.

## Step 1: two clouds of points

`make_blobs` draws points around two centers. They overlap a little, so no straight line can separate them perfectly, which keeps the best possible loss above zero.

```python run
import matplotlib.pyplot as plt
import torch
import torch.nn.functional as F
from sklearn.datasets import make_blobs

X_np, y_np = make_blobs(n_samples=200, centers=[[-1, -1], [1, 1]], cluster_std=1.3, random_state=0)
X = torch.tensor(X_np, dtype=torch.float32)
y = torch.tensor(y_np, dtype=torch.float32)
print("X:", tuple(X.shape), "| y:", tuple(y.shape), "| share of class 1:", y.mean().item())
```

Labels are `float32` this time, because binary cross-entropy compares them directly with probabilities.

## Step 2: forward pass and loss, by hand

The neuron computes a score `z = w₁x₁ + w₂x₂` for each point (no bias, to keep exactly two weights), turns it into a probability `p = sigmoid(z)`, and is charged the **binary cross-entropy**: `−log p` when the label is 1 and `−log(1 − p)` when it's 0, averaged over all points. We start from a deliberately bad guess, `w = (−2, 2.5)`.

```python run
w = torch.tensor([-2.0, 2.5])

z = X @ w                                  # (200, 2) @ (2,) -> (200,)
p = torch.sigmoid(z)
loss = -(y * torch.log(p) + (1 - y) * torch.log(1 - p)).mean()

print("by hand:  ", round(loss.item(), 4))
print("PyTorch:  ", round(F.binary_cross_entropy_with_logits(z, y).item(), 4))
```

Both say 1.6713. In real code, prefer `binary_cross_entropy_with_logits`: it takes the score `z` and combines the sigmoid and the log in a way that can't produce `log(0)` when `p` rounds to exactly 0 or 1.

## Step 3: derive the gradient

Follow one point `i` back from the loss to the weights, the same chain as in the Notes:

- From loss to score: `dLᵢ/dzᵢ = pᵢ − yᵢ`. The sigmoid's slope `p(1 − p)` appears in the algebra and cancels against the cross-entropy's `1/p` terms, which is the cancellation that kept the gradient alive for confidently wrong neurons.
- From score to weights: `dzᵢ/dw = xᵢ`, the point's own coordinates.

Average over all N points and stack the results, and the whole gradient is one line of linear algebra: **`grad = Xᵀ(p − y) / N`**. Each point pushes the weights along its own coordinates, by how wrong its probability is.

```python run
grad_by_hand = X.T @ (p - y) / len(y)      # (2, 200) @ (200,) -> (2,)
print("gradient by hand:", grad_by_hand)
```

## Step 4: verify it twice

A hand-derived gradient is a hypothesis. First check: autograd.

```python run
w_check = w.clone().requires_grad_(True)
F.binary_cross_entropy_with_logits(X @ w_check, y).backward()
print("autograd:        ", w_check.grad)
print("match:", torch.allclose(grad_by_hand, w_check.grad))
```

Autograd could, in principle, share a mistake with you, for example if you both differentiated the wrong formula. The second check uses no calculus at all: nudge each weight up and down by a tiny `ε` and measure how much the loss changes, `(L(w + ε) − L(w − ε)) / 2ε`. This is called a **gradient check**, and it's done in `float64`, because with `float32` the rounding error swamps a change of size `ε`.

```python run
X64, y64, w64 = X.double(), y.double(), w.double()
eps = 1e-6


def loss64(weights):
    return F.binary_cross_entropy_with_logits(X64 @ weights, y64)


numeric = torch.stack([(loss64(w64 + eps * e) - loss64(w64 - eps * e)) / (2 * eps)
                       for e in torch.eye(2, dtype=torch.float64)])
analytic = X64.T @ (torch.sigmoid(X64 @ w64) - y64) / len(y64)
relative_error = ((numeric - analytic).norm() / (numeric.norm() + analytic.norm())).item()
print("finite differences:", numeric)
print(f"relative error: {relative_error:.1e}")
```

A relative error around `1e-10` means the formula is right. Errors near `1e-7` are borderline, and anything around `1e-2` means a bug. `torch.eye(2)` supplies the two directions to nudge in, one per weight.

## Step 5: gradient descent by hand

Now the training loop, with nothing hidden: forward, gradient, update, repeat. We'll record every weight vector so we can draw the path.

```python run
def train_by_hand(lr, steps, start=(-2.0, 2.5)):
    w = torch.tensor(start)
    path, losses = [w.tolist()], []
    for _ in range(steps):
        z = X @ w
        losses.append(F.binary_cross_entropy_with_logits(z, y).item())
        w = w - lr * X.T @ (torch.sigmoid(z) - y) / len(y)
        path.append(w.tolist())
    return w, path, losses


w_final, path, losses = train_by_hand(lr=2.0, steps=40)
for step in [0, 1, 2, 5, 10, 39]:
    print(f"step {step:2d}  loss {losses[step]:.4f}  w {[round(v, 3) for v in path[step]]}")
accuracy = ((torch.sigmoid(X @ w_final) > 0.5).float() == y).float().mean().item()
print("training accuracy:", round(accuracy, 3))
```

The loss falls quickly from 1.67 and then levels off at 0.3673, the lowest this model can reach on this data. The weights settle near `(1.08, 1.07)`, almost equal, which makes sense: the two centers sit on the diagonal, so both coordinates matter equally. 84.5% accuracy is about what overlapping clouds allow.

## Step 6: see the path

Two panels: on the left, the loss surface over every possible `(w₁, w₂)` with the paths for two learning rates; on the right, the data with the boundary the trained neuron draws, where `z = 0` and `p = 0.5`.

```python run alt="Left: contour plot of the loss over w1 from -3 to 4 and w2 from -1.5 to 4, a bowl with its minimum near w1 = 1.1, w2 = 1.1. Two paths start at w1 = -2, w2 = 2.5. With learning rate 0.3 the path curves slowly toward the minimum and has not reached it after 40 steps. With 2.0 it reaches the minimum in about 10 steps. Right: scatter plot of 200 points in two overlapping clouds, class 0 at lower left and class 1 at upper right, with a straight dashed boundary running diagonally between them from upper left to lower right." caption="Training is a walk downhill on the left; its result is the line on the right."
_, slow_path, _ = train_by_hand(lr=0.3, steps=40)

W1, W2 = torch.meshgrid(torch.linspace(-3, 4, 150), torch.linspace(-1.5, 4, 150), indexing="xy")
grid = torch.stack([W1.flatten(), W2.flatten()], dim=1)               # every (w1, w2) pair
scores = X @ grid.T                                                   # (200, 22500)
surface = F.binary_cross_entropy_with_logits(scores, y[:, None].expand_as(scores), reduction="none").mean(dim=0)

fig, (left, right) = plt.subplots(1, 2, figsize=(10, 4))
left.contour(W1, W2, surface.reshape(W1.shape), levels=torch.logspace(-0.42, 0.9, 14).tolist(), colors="#b8b7b1", linewidths=0.8)
left.plot(*zip(*slow_path), marker="o", markersize=3, linewidth=1.5, color="#1baf7a", label="lr = 0.3")
left.plot(*zip(*path), marker="o", markersize=3, linewidth=1.5, color="#2a78d6", label="lr = 2.0")
left.set_xlabel("w₁")
left.set_ylabel("w₂")
left.legend(frameon=False, loc="lower left")

for label, color in [(0, "#eb6834"), (1, "#2a78d6")]:
    pts = X[y == label]
    right.scatter(pts[:, 0], pts[:, 1], s=14, color=color, alpha=0.7, label=f"class {label}")
xs_line = torch.linspace(-4, 4, 2)
right.plot(xs_line, -w_final[0] / w_final[1] * xs_line, color="#52514e", linestyle="--", linewidth=1.5)
right.set_xlim(-4.5, 4.5)
right.set_ylim(-4.5, 4.5)
right.set_xlabel("x₁")
right.set_ylabel("x₂")
right.legend(frameon=False, loc="upper left")
for ax in (left, right):
    ax.spines[["top", "right"]].set_visible(False)
plt.tight_layout()
plt.show()
```

The surface is computed in one shot: `grid` holds 22,500 candidate weight pairs as rows, and `X @ grid.T` scores every point under every pair at once, a `(200, 22500)` tensor. That's broadcasting and matrix multiplication from Module 2 doing real work. The boundary on the right is the line where `w₁x₁ + w₂x₂ = 0`, so `x₂ = −(w₁/w₂)·x₁`.

## Step 7: sweep the learning rate

One run tells you little about the learning rate. A **sweep** trains the same model from the same start with many learning rates for a fixed budget of steps and plots where each one ends up. Spacing the rates evenly on a log scale covers several orders of magnitude with a dozen runs.

```python run alt="Line chart with markers: final loss after 30 steps against learning rate on a log scale from 0.01 to about 40. The loss starts near 1.5 at 0.01, falls steadily to 0.367 by a learning rate near 1, stays flat at 0.367 up to 10, then jumps up to about 0.9 at 20 and 40." caption="Too small crawls, a wide middle works, and past the cliff training fails."
rates = torch.logspace(-2, 1.6, 13).tolist()
finals = []
for lr in rates:
    w_end, _, _ = train_by_hand(lr, steps=30)
    finals.append(F.binary_cross_entropy_with_logits(X @ w_end, y).item())
    print(f"lr {lr:7.3f}  final loss {finals[-1]:.4f}")

fig, ax = plt.subplots(figsize=(6.4, 3))
ax.plot(rates, finals, marker="o", markersize=5, linewidth=2, color="#2a78d6")
ax.set_xscale("log")
ax.set_xlabel("learning rate (log scale)")
ax.set_ylabel("loss after 30 steps")
ax.spines[["top", "right"]].set_visible(False)
plt.show()
```

Read it from left to right. Below about 0.3 the loss is still falling when the budget runs out: those rates are safe but slow. From roughly 0.6 to 10, every run reaches the minimum. Past that, the steps overshoot the bowl, just like the opening trace in the Notes, and the loss ends far higher. In practice you pick a rate comfortably inside the flat region, not right at its edge, because a real network's curvature changes during training.

## Step 8: hand the loop to `torch.optim`

PyTorch packages this loop. `nn.Linear(2, 1, bias=False)` holds the two weights, autograd computes the gradient, and `torch.optim.SGD` applies `w ← w − lr · grad`. We copy in the same starting weights so the two versions can be compared number for number.

```python run
import torch.nn as nn

neuron = nn.Linear(2, 1, bias=False)
with torch.no_grad():
    neuron.weight.copy_(torch.tensor([[-2.0, 2.5]]))
optimizer = torch.optim.SGD(neuron.parameters(), lr=2.0)

for step in range(40):
    optimizer.zero_grad()                                   # 1. clear old gradients
    scores = neuron(X).squeeze(1)                           # 2. forward: (200, 1) -> (200,)
    loss = F.binary_cross_entropy_with_logits(scores, y)    # 3. loss
    loss.backward()                                         # 4. gradients into .grad
    optimizer.step()                                        # 5. update the weights

print("torch.optim:", [round(v, 5) for v in neuron.weight.flatten().tolist()])
print("by hand:    ", [round(v, 5) for v in w_final.tolist()])
```

Same weights to five decimal places. Those five numbered lines are the core of every training loop in this course, and in Module 4 they get wrapped in batches and epochs. The order matters, and the first line is the one people drop. Watch what the loss does without it:

```python run
neuron = nn.Linear(2, 1, bias=False)
with torch.no_grad():
    neuron.weight.copy_(torch.tensor([[-2.0, 2.5]]))
optimizer = torch.optim.SGD(neuron.parameters(), lr=2.0)

history = []
for step in range(40):
    loss = F.binary_cross_entropy_with_logits(neuron(X).squeeze(1), y)
    loss.backward()                  # no zero_grad: gradients pile up
    optimizer.step()
    history.append(round(loss.item(), 3))
print(history[::4])
```

Instead of settling at 0.367, the loss swings up and down. Each step uses the **sum** of every gradient so far, which acts like momentum with no friction: the weights keep sliding past the minimum. Nothing crashes, and nothing warns you.

## The finished program

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
from sklearn.datasets import make_blobs

X_np, y_np = make_blobs(n_samples=200, centers=[[-1, -1], [1, 1]], cluster_std=1.3, random_state=0)
X = torch.tensor(X_np, dtype=torch.float32)
y = torch.tensor(y_np, dtype=torch.float32)

# 1. Gradient by hand, checked against autograd.
w = torch.tensor([-2.0, 2.5])
grad_by_hand = X.T @ (torch.sigmoid(X @ w) - y) / len(y)
w_check = w.clone().requires_grad_(True)
F.binary_cross_entropy_with_logits(X @ w_check, y).backward()
assert torch.allclose(grad_by_hand, w_check.grad)

# 2. Gradient descent by hand.
for _ in range(40):
    w = w - 2.0 * X.T @ (torch.sigmoid(X @ w) - y) / len(y)

# 3. The same thing with torch.optim.
neuron = nn.Linear(2, 1, bias=False)
with torch.no_grad():
    neuron.weight.copy_(torch.tensor([[-2.0, 2.5]]))
optimizer = torch.optim.SGD(neuron.parameters(), lr=2.0)
for _ in range(40):
    optimizer.zero_grad()
    loss = F.binary_cross_entropy_with_logits(neuron(X).squeeze(1), y)
    loss.backward()
    optimizer.step()

print("by hand:    ", w.tolist())
print("torch.optim:", neuron.weight.flatten().tolist())
print("accuracy:   ", ((torch.sigmoid(X @ w) > 0.5).float() == y).float().mean().item())
```

:::quiz
Q: Why does the gradient check in Step 4 use `float64`?
- [ ] Autograd only works in `float64`
  Autograd works in any floating dtype; Step 4's first check ran it in `float32`.
- [x] The loss changes by only about `ε × gradient`, and `float32` rounding error is larger than a change that small
  With `ε = 1e-6`, `float32` keeps about 7 significant digits, so the difference between the two losses would be mostly noise.
- [ ] `torch.eye` requires `float64`
  `torch.eye` takes any dtype. We asked for `float64` to match the data.

Q: In the sweep, a learning rate of 0.04 ended at a loss of about 1.15 after 30 steps. What does that tell you?
- [ ] 0.04 is too large and the loss diverged
  The loss went down from 1.67, just not far. Divergence would push it up.
- [x] 0.04 is safe but slow: more steps would reach the minimum, and a larger rate would get there sooner
  It's on the crawl side of the curve. The descent is working, only slowly.
- [ ] The model can't do better than 1.15 on this data
  Other rates reached 0.367 with the same model, so the model isn't the limit.

Q: You forget `optimizer.zero_grad()`. Why doesn't PyTorch raise an error?
- [x] Accumulating gradients is a legitimate feature, used to combine several small batches into one update, so PyTorch can't tell it's a mistake
  `.backward()` always adds into `.grad`. Whether that's a bug depends on your intent, which only you know.
- [ ] Because `optimizer.step()` clears the gradients automatically
  It doesn't, which is exactly why the loss in Step 8 swung up and down.
- [ ] Because the loss is still a valid number
  PyTorch doesn't check whether training is going well; it only runs what you wrote.
:::

:::takeaways
- For a sigmoid neuron with cross-entropy, the gradient is `Xᵀ(p − y) / N`: each point pushes along its own coordinates, by how wrong its probability is.
- Verify a hand-derived gradient against autograd and against finite differences in `float64`; a relative error near `1e-10` means it's right.
- A learning-rate sweep on a log scale shows the crawl, the working range, and the cliff. Pick a rate well inside the working range.
- The five-line loop is `zero_grad`, forward, loss, `backward`, `step`, and a missing `zero_grad` fails silently.
:::
