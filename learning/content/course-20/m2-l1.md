Here are 32 handwritten digits from scikit-learn, each an 8 × 8 grid of pixel brightnesses. A dense layer that takes 64 inputs should be a perfect fit, since 8 × 8 = 64. Let's load them and find out.

```python run
import torch
import torch.nn as nn
from sklearn.datasets import load_digits

digits = load_digits()
images = torch.tensor(digits.images[:32], dtype=torch.float32).unsqueeze(1)
labels = torch.tensor(digits.target[:32])
layer = nn.Linear(64, 10)

print("images:", tuple(images.shape))
print("labels:", tuple(labels.shape), labels[:10].tolist())
```

Now hand the batch to the layer:

```python run raises
layer(images)
```

The numbers in the message are the whole story. `nn.Linear` only looks at the **last** dimension of its input and treats every dimension before it as a pile of separate rows. Our batch has shape `(32, 1, 8, 8)`, so the layer saw 32 × 1 × 8 = 256 rows of 8 numbers each, and an 8-number row can't meet a layer that wants 64. The digits were never wrong; the shape was. Most bugs in this course look like this one, so this lesson is about reading shapes fluently.

## Shape, dtype, device: three facts about every tensor

A **tensor** is an n-dimensional grid of numbers that all share one type. Three attributes tell you nearly everything about it:

```python run
print("shape: ", images.shape, "| dims:", images.ndim)
print("dtype: ", images.dtype, "| labels:", labels.dtype)
print("device:", images.device)
print("straight from NumPy:", torch.tensor(digits.images[:2]).dtype)
```

Image batches in PyTorch follow the **`(N, C, H, W)`** convention: batch size, channels, height, width. The digits are grayscale, so `C` is 1; a color photo batch would be `(N, 3, H, W)`. That's why we called `.unsqueeze(1)`, which inserts a new dimension of size 1 at position 1, turning `(32, 8, 8)` into `(32, 1, 8, 8)`.

The last line shows a trap. NumPy defaults to `float64`, and so does a tensor built from a NumPy array unless you say otherwise. PyTorch layers are `float32`, and as you saw last module, mixing the two raises an error. Labels are the opposite case: they should be `int64` whole numbers, and they are.

## Reshaping: legal is not the same as correct

`flatten(start_dim=1)` squashes everything after the batch dimension into one, giving each image a row of 64 pixels. That fixes the opening bug:

```python run
flat = images.flatten(start_dim=1)
print("flattened:", tuple(flat.shape))
print("layer out:", tuple(layer(flat).shape))
print("legal but wrong:", tuple(images.reshape(64, -1).shape))
```

The `-1` in `reshape` means "work this dimension out for me." `reshape(64, -1)` is perfectly legal (2,048 numbers fit into 64 rows of 32) and a disaster: each new row mixes pixels from different images. Reshaping keeps the numbers in their memory order and only redraws the row boundaries. Reordering dimensions is a different operation, `permute` (or `.T` for a 2-D tensor). The difference shows up clearly on a tiny example:

```python run
t = torch.arange(6).reshape(2, 3)
print(t)
print("t.T, a true transpose:\n", t.T)
print("t.reshape(3, 2), same order, new rows:\n", t.reshape(3, 2))
```

Both results have shape `(3, 2)`, but only the transpose moves `3` under `0`. You'll need `permute` in Module 5, when images loaded as `(H, W, C)` must become `(C, H, W)`.

## Broadcasting: how shapes that differ still combine

You often combine tensors of different shapes: adding a bias of shape `(10,)` to outputs of shape `(32, 10)`, or subtracting a per-pixel mean. PyTorch **broadcasts**: it lines the shapes up from the **right** and compares one dimension at a time. Two sizes are compatible if they're equal or if one of them is 1 (a missing dimension counts as 1). A size-1 dimension is stretched to match, without copying any data. Step through the rule written out in plain Python:

:::trace Watch the broadcast rule walk from the last dimension to the first
```python
def broadcast_shape(a, b):
    result = []
    for i in range(1, max(len(a), len(b)) + 1):
        size_a = a[-i] if i <= len(a) else 1
        size_b = b[-i] if i <= len(b) else 1
        if size_a != size_b and 1 not in (size_a, size_b):
            return "error: " + str(size_a) + " vs " + str(size_b)
        result.insert(0, max(size_a, size_b))
    return result

print(broadcast_shape([32, 64], [64]))
print(broadcast_shape([32, 64], [32]))
print(broadcast_shape([32, 1], [10]))
```
:::

The second call is the classic bug. Say you want to center each **image** by subtracting its own average brightness. `flat.mean(dim=1)` gives one number per image, shape `(32,)`, and broadcasting lines that 32 up against the 64 pixel columns:

```python run raises
image_means = flat.mean(dim=1)
flat - image_means
```

`keepdim=True` keeps the averaged dimension as size 1, giving shape `(32, 1)`, which broadcasts across the columns the way you meant:

```python run
centered = flat - flat.mean(dim=1, keepdim=True)
print(tuple(centered.shape), "| row means now:", centered.mean(dim=1)[:3])
```

The row means print as zero, or as tiny numbers like `1e-8` from rounding. The dangerous case is a mistake that broadcasts without an error, such as `(32, 1)` meeting `(32,)`, which silently produces a `(32, 32)` grid. When a result has a shape you didn't expect, check the broadcast first.

## `nn.Linear` is a matrix multiply plus a bias

Matrix multiplication with `@` follows one shape rule: `(N, k) @ (k, M)` gives `(N, M)`, and the inner sizes must match. A **dense** (fully connected) layer is exactly that. `nn.Linear(64, 10)` stores a weight matrix `W` of shape `(10, 64)`, one row per output, and a bias `b` of shape `(10,)`, and computes `y = x @ W.T + b`:

```python run
print("W:", tuple(layer.weight.shape), " b:", tuple(layer.bias.shape))
by_hand = flat @ layer.weight.T + layer.bias
print("matches nn.Linear:", torch.allclose(layer(flat), by_hand))
print("parameters:", sum(p.numel() for p in layer.parameters()))
```

Each of the 10 outputs is a weighted sum of all 64 pixels plus its own bias, so the layer has 64 × 10 + 10 = 650 parameters. The bias add is a broadcast: `(32, 10) + (10,)`.

Now the reason layers need anything else. Stack two linear layers with nothing between them, and the pair collapses into a single linear layer: `W2(W1 x + b1) + b2 = (W2 W1) x + (W2 b1 + b2)`. Here's that algebra checked numerically:

```python run
first, second = nn.Linear(64, 32), nn.Linear(32, 10)
W = second.weight @ first.weight
b = second.weight @ first.bias + second.bias
print("two layers == one layer:", torch.allclose(second(first(flat)), flat @ W.T + b, atol=1e-4))
```

A hundred stacked linear layers can only draw straight boundaries, the same as one. Depth only buys you something if a **nonlinear** function sits between the layers.

## Activations bend the line, and sometimes flatten it

An **activation function** is applied to every number a layer outputs. The three classics:

- **ReLU**: `max(0, z)`. Passes positive values through and zeroes out the rest. The default choice for hidden layers.
- **Sigmoid**: `1 / (1 + e^(-z))`. Squeezes any number into `(0, 1)`. Used for probabilities in yes/no outputs.
- **tanh**: squeezes into `(-1, 1)`, centered on zero.

The right half of this chart shows each function's **slope**. In Module 3 you'll see that learning sends its signal backward through these slopes, so a slope near zero means almost no learning signal gets through.

```python run alt="Two side-by-side line charts for inputs from -6 to 6. Left: ReLU is flat at zero then rises as a straight line; sigmoid is an S-curve from 0 to 1; tanh is an S-curve from -1 to 1. Right: their slopes. ReLU's slope is 0 for negative inputs and 1 for positive. Sigmoid's slope peaks at only 0.25 at zero and is near zero beyond about 5 in either direction. Tanh's slope peaks at 1 and also falls to near zero beyond about 3." caption="Sigmoid and tanh flatten out at both ends, so their slopes vanish for large inputs; ReLU's slope is 0 or 1."
import matplotlib.pyplot as plt

z = torch.linspace(-6, 6, 241)
sig, th = torch.sigmoid(z), torch.tanh(z)
curves = {"ReLU": torch.relu(z), "sigmoid": sig, "tanh": th}
slopes = {"ReLU": (z > 0).float(), "sigmoid": sig * (1 - sig), "tanh": 1 - th**2}
colors = {"ReLU": "#2a78d6", "sigmoid": "#eb6834", "tanh": "#1baf7a"}

fig, (left, right) = plt.subplots(1, 2, figsize=(9, 3.4))
for name in curves:
    left.plot(z, curves[name], color=colors[name], linewidth=2, label=name)
    right.plot(z, slopes[name], color=colors[name], linewidth=2, label=name)
left.set_title("activation(z)", fontsize=10)
right.set_title("slope of the activation", fontsize=10)
left.set_ylim(-1.2, 3)
for ax in (left, right):
    ax.set_xlabel("z, the layer's output before activation")
    ax.axhline(0, color="#b8b7b1", linewidth=0.8)
    ax.spines[["top", "right"]].set_visible(False)
left.legend(frameon=False, loc="upper left")
plt.tight_layout()
plt.show()
```

Here are the exact numbers for a few inputs. Predict the sigmoid slope at `z = 10` before you look:

```python run
z = torch.tensor([-10.0, -2.0, 0.0, 2.0, 10.0])
s = torch.sigmoid(z)
print("sigmoid:      ", [round(v, 5) for v in s.tolist()])
print("sigmoid slope:", [round(v, 5) for v in (s * (1 - s)).tolist()])
print("relu slope:   ", (z > 0).float().tolist())
```

At `z = 10` the sigmoid outputs 0.99995 and its slope is about 0.00005, roughly 5,000 times smaller than at zero. A unit sitting out there is **saturated**: nudging its weights barely changes its output, so it learns almost nothing. That happens easily when inputs are large, which is one reason you'll scale pixels from 0–16 down to 0–1 in the next lesson. ReLU never saturates for positive inputs, but a unit whose input is negative for **every** example outputs zero with zero slope, a **dead** unit.

## Mistakes that cost an afternoon

:::warning
**Flattening away the batch.** `x.reshape(-1)` or `x.view(-1)` turns a `(32, 1, 8, 8)` batch into one row of 2,048 numbers. Use `x.flatten(start_dim=1)` or `nn.Flatten()`, which both keep dimension 0, so every image stays its own row.
:::

- **`float64` from NumPy.** `torch.tensor(array)` copies NumPy's dtype. Add `dtype=torch.float32` or call `.float()`.
- **Forgetting `keepdim=True`.** A reduction such as `mean(dim=1)` deletes that dimension, and the broadcast that follows either fails or, worse, quietly builds a grid.
- **`reshape` where you meant `permute`.** If you're reordering axes, the result must move data, and `reshape` never does.

:::quiz
Q: A batch has shape `(16, 64)` and goes through `nn.Linear(64, 32)`. What's the output shape, and how many parameters does the layer have?
- [ ] `(16, 64)` and 2,048 parameters
  The layer maps 64 features to 32, so the last dimension changes. And the bias adds parameters on top of the 64 × 32 weights.
- [x] `(16, 32)` and 2,080 parameters
  The batch size passes through untouched. Weights are 32 × 64 = 2,048, plus 32 biases.
- [ ] `(32, 64)` and 2,080 parameters
  Linear never changes the batch dimension; it only transforms the last one.

Q: What shape does `torch.zeros(32, 1) + torch.zeros(10)` produce?
- [ ] An error, because 1 and 10 don't match
  A size of 1 is always compatible: it stretches to match the other size.
- [ ] `(32, 1)`
  Broadcasting stretches the size-1 dimension rather than shrinking the other tensor.
- [x] `(32, 10)`
  Aligned from the right: 1 against 10 gives 10, then 32 against a missing dimension gives 32.

Q: Two `nn.Linear` layers are stacked with no activation between them. Compared with a single `nn.Linear`, what can the pair represent?
- [x] Nothing more: the composition is still one linear function
  The weights multiply into one matrix and the biases into one vector, as the `allclose` check showed. Only a nonlinearity between them adds power.
- [ ] Curved decision boundaries, because there are more parameters
  Parameter count isn't what matters. The function is still linear, so boundaries stay straight.
- [ ] Twice as many classes
  The output size is set by the last layer, not by how many layers there are.

Q: A hidden layer uses sigmoid, and most of its pre-activation values are around 8 or larger. What will you observe during training?
- [ ] Fast learning, because the outputs are all close to 1
  Outputs near 1 mean the curve is flat there, which is the opposite of fast learning.
- [x] Very slow learning for that layer, because the sigmoid's slope there is nearly zero
  The slope at `z = 8` is about 0.0003, so the learning signal flowing back through those units almost vanishes.
- [ ] An error, because sigmoid only accepts inputs between -1 and 1
  Sigmoid accepts any real number. That's exactly why it can be pushed into its flat regions.
:::

:::takeaways
- Every tensor has a shape, a dtype, and a device; print all three before you guess at a bug.
- `nn.Linear` acts on the last dimension only: `(..., in)` becomes `(..., out)`, computed as `x @ W.T + b`.
- Keep the batch dimension when flattening: `flatten(start_dim=1)`, never `reshape(-1)`.
- Broadcasting aligns shapes from the right; sizes must match or be 1. Use `keepdim=True` after reductions.
- Without activations, stacked linear layers collapse into one. Sigmoid and tanh saturate for large inputs; ReLU units can die.
:::
