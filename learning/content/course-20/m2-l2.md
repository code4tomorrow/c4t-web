:::objectives
- Turn NumPy images into a correctly shaped, scaled `float32` batch.
- Build a multilayer perceptron with `nn.Sequential` and count its parameters.
- Follow a batch through every layer and explain each shape change, from pixels to class probabilities.
- Write `shape_report`, a tracer built on forward hooks that prints shapes, parameters, and activation health for any `nn.Sequential`.
- Use the tracer to find a saturated sigmoid layer caused by unscaled inputs, and fix it.
:::

By the end of this build you'll have two things: a small network that turns an 8 × 8 handwritten digit into ten class probabilities, and a tool called `shape_report` that X-rays any `nn.Sequential` model. The tool prints every layer's output shape and parameter count and flags layers whose activations have gone flat. You'll use it to catch a bug that raises no error at all.

Here's the network we're building, with the shape of a 16-image batch at every stage:

```mermaid caption="The digit network, with the batch's shape after each layer"
flowchart LR
    A["images (16, 1, 8, 8)"] --> B["Flatten (16, 64)"]
    B --> C["Linear 64→32 (16, 32)"]
    C --> D["ReLU (16, 32)"]
    D --> E["Linear 32→10 (16, 10)"]
    E --> F["softmax: probabilities (16, 10)"]
```

## Step 1: look at the data

scikit-learn ships 1,797 handwritten digits, each scanned at 8 × 8 pixels with brightness from 0 to 16. They come with the library, so nothing downloads.

```python run alt="Two rows of eight small grayscale images of handwritten digits. The titles read 0 through 9 across the first ten images, then 0 through 5. The digits are blocky at 8 by 8 pixels but readable." caption="The first 16 digits, labeled with their true class"
import matplotlib.pyplot as plt
import torch
import torch.nn as nn
from sklearn.datasets import load_digits

torch.manual_seed(0)
digits = load_digits()
print("images:", digits.images.shape, "| pixel range:", digits.images.min(), "to", digits.images.max())

fig, axes = plt.subplots(2, 8, figsize=(8, 2.4))
for ax, image, label in zip(axes.flat, digits.images, digits.target):
    ax.imshow(image, cmap="gray_r")
    ax.set_title(str(label), fontsize=10)
    ax.axis("off")
plt.show()
```

The shape `(1797, 8, 8)` means 1,797 images of 8 rows by 8 columns. The images are tiny, which is exactly why they're good for tracing: every number we print is something you can reason about.

## Step 2: make a batch PyTorch can use

A batch needs three things fixed: dtype (`float32`), shape (`(N, C, H, W)`), and scale. Pixels from 0 to 16 become 0 to 1 by dividing by 16.

```python run
x = torch.tensor(digits.images[:16], dtype=torch.float32).unsqueeze(1) / 16.0
y = torch.tensor(digits.target[:16])

print("x:", tuple(x.shape), x.dtype, "| range", x.min().item(), "to", x.max().item())
print("y:", tuple(y.shape), y.dtype, y.tolist())
```

`unsqueeze(1)` adds the channel dimension, and `y` holds `int64` class labels, the type classification losses expect. Why bother scaling? Hold that question; Step 6 answers it with evidence.

## Step 3: build the network and count its weights

`nn.Sequential` runs its layers in order, feeding each one's output to the next. `nn.Flatten()` comes first, so the model accepts image-shaped batches directly.

```python run
model = nn.Sequential(
    nn.Flatten(),          # (N, 1, 8, 8) -> (N, 64)
    nn.Linear(64, 32),     # 64*32 weights + 32 biases
    nn.ReLU(),
    nn.Linear(32, 10),     # 32*10 weights + 10 biases: one score per digit class
)
print(model)
print("parameters:", sum(p.numel() for p in model.parameters()))
```

Check the count by hand: (64 × 32 + 32) + (32 × 10 + 10) = 2,080 + 330 = 2,410. The `(0)` to `(3)` on the left are the layer indexes, which become the names in the model's state dict.

## Step 4: walk the batch through, one layer at a time

`nn.Sequential` is iterable, so you can run its layers yourself and print what comes out of each:

```python run
h = x
print(f"{'input':8s} {tuple(h.shape)}")
for index, layer in enumerate(model):
    h = layer(h)
    print(f"{index}: {type(layer).__name__:8s} {tuple(h.shape)}")

logits = h
probs = torch.softmax(logits, dim=1)
print("row sums:", probs.sum(dim=1)[:4].tolist())
print("predicted:", probs.argmax(dim=1).tolist())
print("true:     ", y.tolist())
```

The final layer's outputs are **logits**: ten raw scores per image, any real number. `softmax` turns each row into probabilities by exponentiating and dividing by the row's total, so every row sums to 1 (up to rounding). `argmax(dim=1)` picks the highest-probability class per image.

The predictions are nonsense, and they should be: the weights are random. Training (Module 4) is the process that makes these match the true labels.

:::warning
`torch.softmax(logits, dim=0)` runs without complaint and gives the wrong answer: it normalizes each **column** across the 16 images instead of each image across its 10 classes. Rows then don't sum to 1. For `(N, classes)` tensors, the class dimension is `dim=1`.
:::

## Step 5: automate the trace with forward hooks

Printing inside a loop works for `nn.Sequential`, but real models have custom `forward` methods you don't want to edit. PyTorch lets you attach a **forward hook** to any module: a function that runs every time that module produces an output, receiving `(module, inputs, output)`. A hook can look without changing anything.

The tracer also measures activation health. For each activation layer it computes the slope of the activation at every output (you derived these slopes in the Notes) and reports the share that are **flat**, with slope below 0.01. It also counts **dead units**: hidden units that are flat for every example in the batch.

```python run
def activation_slope(layer, out):
    """Slope of the activation at each output, computed from the output itself."""
    if isinstance(layer, nn.ReLU):
        return (out > 0).float()
    if isinstance(layer, nn.Sigmoid):
        return out * (1 - out)
    if isinstance(layer, nn.Tanh):
        return 1 - out**2
    return None  # not an activation layer


def shape_report(model, x):
    rows = []

    def hook(module, inputs, output):
        params = sum(p.numel() for p in module.parameters())
        line = f"{type(module).__name__:9s} {str(tuple(output.shape)):15s} {params:6d} {output.mean().item():8.3f} {output.std().item():7.3f}"
        slope = activation_slope(module, output)
        if slope is not None:
            flat = slope < 0.01
            line += f" {flat.float().mean().item():6.0%} {int(flat.all(dim=0).sum()):5d}"
        rows.append(line)

    handles = [layer.register_forward_hook(hook) for layer in model]
    with torch.no_grad():
        model(x)
    for handle in handles:
        handle.remove()  # leave the model exactly as we found it

    print(f"{'layer':9s} {'output shape':15s} {'params':>6s} {'mean':>8s} {'std':>7s} {'flat':>6s} {'dead':>5s}")
    print(f"{'input':9s} {str(tuple(x.shape)):15s}")
    print("\n".join(rows))


shape_report(model, x)
```

Three details matter. `torch.no_grad()` skips the bookkeeping PyTorch normally does for training, since we're only looking. `handle.remove()` detaches the hooks, so calling the model later doesn't keep printing. And the report works for any `nn.Sequential`, whatever its layers.

Read the ReLU row: about half its outputs are flat. That's healthy. ReLU zeroes every negative input by design, and with random weights roughly half the inputs are negative. The number to worry about is the **dead** column, units that are zero for every single image, and it says 4.

Before you panic, ask how much evidence 16 images is. A unit that happens to stay silent for these 16 digits might fire for a different 3 or 7. Run the same report on all 1,797 images:

```python run
everything = torch.tensor(digits.images, dtype=torch.float32).unsqueeze(1) / 16.0
shape_report(model, everything)
```

No dead units. The four were an artifact of a small batch, which is the general lesson for every activation statistic: measure on enough data to mean something, a few hundred examples at least.

## Step 6: catch a saturated layer

Now the bug. A teammate swaps ReLU for sigmoid and, to "keep the data raw," skips the divide-by-16. Nothing crashes. Predict what the sigmoid row will show, then run the tracer on 256 raw images and on the same images scaled:

```python run
torch.manual_seed(0)
sigmoid_model = nn.Sequential(nn.Flatten(), nn.Linear(64, 32), nn.Sigmoid(), nn.Linear(32, 10))
raw = torch.tensor(digits.images[:256], dtype=torch.float32).unsqueeze(1)

print("RAW PIXELS (0 to 16)")
shape_report(sigmoid_model, raw)
print("\nSCALED PIXELS (0 to 1)")
shape_report(sigmoid_model, raw / 16)
```

With raw pixels, the first `Linear` layer's outputs have a standard deviation of about 4.6, so a large share of them land where the sigmoid is flat. About a third of all sigmoid outputs carry almost no learning signal. Scaling the input shrinks that spread about sixteenfold, and the flat share drops to zero. The histograms show why:

```python run alt="Two overlapping histograms of the first layer's outputs before the sigmoid. Raw pixels spread widely from about -12 to 12, with large parts of the distribution beyond the dashed lines at -4.6 and 4.6 that mark where the sigmoid's slope drops below 0.01. Scaled pixels form a narrow spike between about -1 and 1, well inside the lines." caption="Unscaled pixels push many pre-activations into the sigmoid's flat zones beyond ±4.6."
with torch.no_grad():
    z_raw = sigmoid_model[1](sigmoid_model[0](raw)).flatten()
    z_scaled = sigmoid_model[1](sigmoid_model[0](raw / 16)).flatten()

fig, ax = plt.subplots(figsize=(7, 3))
bins = torch.linspace(-16, 16, 81).tolist()
ax.hist(z_raw.tolist(), bins=bins, color="#eb6834", alpha=0.75, label="raw pixels (0 to 16)")
ax.hist(z_scaled.tolist(), bins=bins, color="#2a78d6", alpha=0.75, label="scaled pixels (0 to 1)")
for edge in (-4.6, 4.6):
    ax.axvline(edge, color="#52514e", linestyle="--", linewidth=1)
ax.set_xlabel("first-layer output z, the sigmoid's input")
ax.set_ylabel("count")
ax.spines[["top", "right"]].set_visible(False)
ax.legend(frameon=False)
plt.show()
```

The dashed lines sit at ±4.6, where the sigmoid's slope falls below 0.01. Everything outside them is a value that training can barely move. This is the "saturated activation stops useful change" failure, and you caught it before spending a minute on training.

## The finished program

Here is the whole build as one script you can paste into a fresh Colab cell:

```python
import torch
import torch.nn as nn
from sklearn.datasets import load_digits


def activation_slope(layer, out):
    if isinstance(layer, nn.ReLU):
        return (out > 0).float()
    if isinstance(layer, nn.Sigmoid):
        return out * (1 - out)
    if isinstance(layer, nn.Tanh):
        return 1 - out**2
    return None


def shape_report(model, x):
    rows = []

    def hook(module, inputs, output):
        params = sum(p.numel() for p in module.parameters())
        line = f"{type(module).__name__:9s} {str(tuple(output.shape)):15s} {params:6d} {output.mean().item():8.3f} {output.std().item():7.3f}"
        slope = activation_slope(module, output)
        if slope is not None:
            flat = slope < 0.01
            line += f" {flat.float().mean().item():6.0%} {int(flat.all(dim=0).sum()):5d}"
        rows.append(line)

    handles = [layer.register_forward_hook(hook) for layer in model]
    with torch.no_grad():
        model(x)
    for handle in handles:
        handle.remove()
    print(f"{'layer':9s} {'output shape':15s} {'params':>6s} {'mean':>8s} {'std':>7s} {'flat':>6s} {'dead':>5s}")
    print(f"{'input':9s} {str(tuple(x.shape)):15s}")
    print("\n".join(rows))


torch.manual_seed(0)
digits = load_digits()
x = torch.tensor(digits.images[:256], dtype=torch.float32).unsqueeze(1) / 16.0

model = nn.Sequential(nn.Flatten(), nn.Linear(64, 32), nn.ReLU(), nn.Linear(32, 10))
shape_report(model, x)
probs = torch.softmax(model(x), dim=1)
print("first prediction:", probs[0].argmax().item(), "| true:", digits.target[0])
```

:::quiz
Q: Why does the tracer attach hooks instead of adding `print` calls inside the model?
- [ ] Hooks make the forward pass run faster
  Hooks add a little work; they never speed anything up.
- [x] Hooks can observe any module's output without editing the model's code, and can be removed afterward
  That's what lets one `shape_report` work on any `nn.Sequential`, and later on models you didn't write.
- [ ] `print` doesn't work inside PyTorch models
  It works fine. It just means editing the model and remembering to delete the prints later.

Q: The ReLU row reports about 50% flat outputs. Is the layer broken?
- [x] No: ReLU zeroes negative inputs by design, and about half are negative with random weights. The dead-unit count is the warning sign.
  A unit that's zero for some images still learns from the rest. One that's zero for every image never does.
- [ ] Yes: half the network is dead and should be reinitialized
  Flat for some inputs is normal for ReLU. Only units flat for all inputs are dead, and on the full dataset the report shows none.
- [ ] Yes: it means the inputs weren't scaled
  The ReLU model was given scaled inputs. ReLU's flat half comes from its shape, not from scale.

Q: The raw-pixel batch makes about a third of the sigmoid outputs flat. Which fix addresses the cause?
- [ ] Switch the final layer's softmax to `dim=0`
  That would break the probabilities and does nothing for the hidden layer.
- [ ] Add more hidden units so the flat ones matter less
  More units get pushed into the same flat zones, because the inputs are still too large.
- [x] Scale the inputs to 0 to 1, which shrinks the first layer's outputs into the sigmoid's sloped region
  The report showed the flat share dropping to zero with the same weights once the inputs were divided by 16.
:::

:::takeaways
- Fix a batch's dtype, shape, and scale before it meets the model: `float32`, `(N, C, H, W)`, roughly 0 to 1.
- `nn.Sequential` is iterable, and forward hooks let you watch any module's output without editing the model.
- Logits are raw scores; `softmax(dim=1)` turns each row into probabilities, and `argmax(dim=1)` picks the class.
- A health check on activations (flat share, dead units) catches saturation from unscaled inputs before training starts.
:::

## Ideas to extend it

- Add a column for the fraction of exact zeros in each layer's output, and compare ReLU with `nn.LeakyReLU()`.
- Make `shape_report` walk nested models with `model.named_modules()`, printing names like `features.0` instead of class names.
- Stack four `Linear` + `Tanh` pairs and watch the `std` column shrink or grow with depth as you multiply the first layer's weights by 0.5 or 2.
