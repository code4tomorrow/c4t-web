Every exercise here ends with a check, usually `torch.allclose` against autograd or a number you predicted. Get in the habit: in deep learning, a wrong gradient doesn't crash anything, it just trains badly, so a check is the only way you'll know.

## Warm-up: two losses on paper

Without code: (a) predictions `[2, 4]` against targets `[3, 1]` under mean squared error; (b) cross-entropy when the model gives probabilities `[0.7, 0.2, 0.1]` and the true class is 1. Then check:

```python run
import math

import torch
import torch.nn.functional as F

print("MSE:", F.mse_loss(torch.tensor([2.0, 4.0]), torch.tensor([3.0, 1.0])).item())
print("CE: ", round(-math.log(0.2), 4))
```

(a) is `((−1)² + 3²) / 2 = 5`. (b) looks only at the true class's probability, 0.2, so it's `−ln 0.2 ≈ 1.609`. The 0.7 given to the wrong class matters only because it took probability away from the right one.

### Exercise 1: cross-entropy that can't overflow

Write `my_cross_entropy(logits, targets)` for a batch of logits `(N, C)` and integer targets `(N,)`. First write it the obvious way (exp, divide by the sum, take −log), then test it on `[[1000.0, 0.0, -1000.0]]` with target 0. Fix it so it matches `F.cross_entropy` on both ordinary logits and that extreme one.

```text
ordinary: mine 0.1755 | PyTorch 0.1755
extreme:  mine 0.0 | PyTorch 0.0
```

:::hint
`exp(1000)` is `inf` in `float32`. Softmax gives the same answer if you subtract any constant from every logit in a row. Which constant makes the largest exponent `exp(0) = 1`? Then use `−log softmax = log(sum of exps) − (true logit)`.
:::

:::solution
The naive version computes `exp(1000) = inf`, then `inf / inf = nan`. Subtracting each row's maximum keeps every exponent at most `exp(0) = 1`:

```python run
import torch
import torch.nn.functional as F


def my_cross_entropy(logits, targets):
    shifted = logits - logits.max(dim=1, keepdim=True).values      # largest entry becomes 0
    log_sum_exp = torch.log(torch.exp(shifted).sum(dim=1))
    true_logit = shifted[torch.arange(len(targets)), targets]
    return (log_sum_exp - true_logit).mean()


ordinary = torch.tensor([[2.0, 0.5, -1.0], [0.1, 0.2, 3.0]])
targets = torch.tensor([0, 2])
print(f"ordinary: mine {my_cross_entropy(ordinary, targets).item():.4f} | PyTorch {F.cross_entropy(ordinary, targets).item():.4f}")

extreme = torch.tensor([[1000.0, 0.0, -1000.0]])
target = torch.tensor([0])
print(f"extreme:  mine {my_cross_entropy(extreme, target).item()} | PyTorch {F.cross_entropy(extreme, target).item()}")
```

`shifted[torch.arange(N), targets]` picks one entry per row: row `i`, column `targets[i]`. This "subtract the max" trick (the **log-sum-exp trick**) is what `F.cross_entropy` does internally, and it's why you should pass it logits instead of computing probabilities yourself.
:::

### Exercise 2: the softmax-before-the-loss bug

A classmate's network ends in `nn.Softmax(dim=1)`, and they pass its output to `F.cross_entropy`. Their loss never drops below about 0.55, even when every prediction is right. For the confident, correct logits `[[10.0, 0.0, 0.0]]` (target 0), print the loss with and without the extra softmax, then calculate the lowest loss the buggy version could ever reach with 3 classes.

```text
correct:          0.0001
softmax first:    0.5515
lowest possible:  0.5514
```

:::hint
After the extra softmax, the "logits" handed to `F.cross_entropy` are probabilities, so each is between 0 and 1. The best case is `[1, 0, 0]`. What is the cross-entropy of those logits for class 0?
:::

:::solution
```python run
import math

import torch
import torch.nn.functional as F

logits = torch.tensor([[10.0, 0.0, 0.0]])
target = torch.tensor([0])
print(f"correct:          {F.cross_entropy(logits, target).item():.4f}")
print(f"softmax first:    {F.cross_entropy(torch.softmax(logits, dim=1), target).item():.4f}")
print(f"lowest possible:  {math.log(1 + 2 / math.e):.4f}")
```

With the extra softmax, the best possible input is `[1, 0, 0]`, and its cross-entropy is `−log(e / (e + 2)) = log(1 + 2/e) ≈ 0.5514`. The loss has a floor it can never get under, and the gradients reaching the network shrink because they pass through a second softmax. Remove the softmax layer and let `F.cross_entropy` handle it. When you need probabilities for display, apply softmax to the logits **outside** the loss.
:::

### Exercise 3: a tanh neuron by hand

For `ŷ = tanh(w·x + b)` and `L = (ŷ − y)²`, with `x = 0.5`, `y = 0.8`, `w = 1.5`, `b = −0.2`: derive `dL/dw` and `dL/db`, compute them with plain Python `math`, and confirm with autograd.

```text
by hand:  dL/dw = -0.2245  dL/db = -0.4489
autograd: dL/dw = -0.2245  dL/db = -0.4489
```

:::hint
Three links: `dL/dŷ = 2(ŷ − y)`, then the tanh's slope `1 − ŷ²` (from Module 2), then `x` for `w` or `1` for `b`.
:::

:::solution
`dL/dw = 2(ŷ − y)(1 − ŷ²)·x` and `dL/db = 2(ŷ − y)(1 − ŷ²)`.

```python run
import math

import torch

x, y, w0, b0 = 0.5, 0.8, 1.5, -0.2
y_hat = math.tanh(w0 * x + b0)
upstream = 2 * (y_hat - y) * (1 - y_hat**2)
print(f"by hand:  dL/dw = {upstream * x:.4f}  dL/db = {upstream:.4f}")

w = torch.tensor(w0, requires_grad=True)
b = torch.tensor(b0, requires_grad=True)
loss = (torch.tanh(w * x + b) - y) ** 2
loss.backward()
print(f"autograd: dL/dw = {w.grad.item():.4f}  dL/db = {b.grad.item():.4f}")
```

`upstream` is the gradient that has flowed back to the weighted sum. Both weights reuse it, which is backpropagation's saving in miniature. The prediction (0.50) is too low, so both gradients are negative: raise `w` and `b` to raise `ŷ`.
:::

### Exercise 4: an update autograd refuses

This hand-written gradient descent step crashes. Read the error, then fix the loop so it runs 50 steps and drives `w` to the value that makes `2w = 4`.

```python run raises
import torch

w = torch.tensor([0.0], requires_grad=True)
loss = ((w * 2 - 4) ** 2).sum()
loss.backward()
w -= 0.1 * w.grad
```

Sample output after the fix:

```text
w after 50 steps: 2.0
```

:::hint
Autograd tracks every operation on `w` so it can differentiate later. The update itself must not be tracked. Which context manager turns tracking off? And something else has to happen to `w.grad` after each step.
:::

:::solution
```python run
import torch

w = torch.tensor([0.0], requires_grad=True)
for step in range(50):
    loss = ((w * 2 - 4) ** 2).sum()
    loss.backward()
    with torch.no_grad():        # the update is not part of the model
        w -= 0.1 * w.grad
    w.grad.zero_()               # clear before the next backward()
print("w after 50 steps:", round(w.item(), 4))
```

`w` is a **leaf**: a tensor you created, rather than one computed from others. Changing a tracked leaf in place would corrupt the record autograd needs, so PyTorch refuses unless the change happens inside `torch.no_grad()`. This is exactly what `optimizer.step()` does for you, and `w.grad.zero_()` is what `optimizer.zero_grad()` does.
:::

### Exercise 5: predict the largest stable learning rate

For the model `ŷ = w·x` with squared error on `x = [0.5, 1.0, 1.5, 2.0, 2.5]` and `y = 1.2x`, the curvature of the loss is `2 · mean(x²)`. Predict the largest learning rate that converges, then run 50 steps of gradient descent from `w = 0` at 0.9× and 1.1× your prediction.

```text
curvature 5.5 -> predicted limit 0.3636
lr 0.3273: loss after 50 steps 7.97e-10
lr 0.4000: loss after 50 steps 3.28e+08
```

:::hint
`mean(x²) = (0.25 + 1 + 2.25 + 4 + 6.25) / 5`. Convergence needs `lr < 2 / curvature`.
:::

:::solution
```python run
import torch

xs = torch.tensor([0.5, 1.0, 1.5, 2.0, 2.5])
ys = 1.2 * xs
curvature = 2 * (xs**2).mean().item()
limit = 2 / curvature
print(f"curvature {curvature} -> predicted limit {limit:.4f}")

for lr in [0.9 * limit, 1.1 * limit]:
    w = 0.0
    for step in range(50):
        grad = (2 * (w * xs - ys) * xs).mean().item()
        w -= lr * grad
    loss = ((w * xs - ys) ** 2).mean().item()
    print(f"lr {lr:.4f}: loss after 50 steps {loss:.3g}")
```

Each step multiplies the distance from `w = 1.2` by `1 − lr · 5.5`. At 0.9× the limit that factor is −0.8, so the distance shrinks by a fifth each step; at 1.1× it's −1.2, and after 50 steps the error has grown by a factor of about 9,000, so the loss (its square) explodes. A 20% change in learning rate flips training from perfect to useless, which is why the cliff in a learning-rate sweep is so sharp.
:::

### Exercise 6: why classifiers don't use squared error

Train the sigmoid neuron from the Build-along on the same blobs data, starting from the confidently wrong weights `w = (−3, −3)`, for 100 steps at `lr = 0.5`. Do it once with `F.mse_loss(torch.sigmoid(z), y)` and once with `F.binary_cross_entropy_with_logits(z, y)`, record accuracy every step, and plot both.

:::hint
Use the Exercise 4 pattern: `loss.backward()`, then update inside `torch.no_grad()`, then `w.grad.zero_()`. Accuracy is the share of points where `(z > 0)` matches the label.
:::

:::solution
```python run alt="Line chart of training accuracy over 100 steps. Cross-entropy stays near 0.16 for about six steps, then jumps to about 0.84 by step 9 and stays there. Squared error stays flat at about 0.16 for all 100 steps." caption="From a confidently wrong start, squared error barely moves; cross-entropy recovers in under ten steps."
import matplotlib.pyplot as plt
import torch
import torch.nn.functional as F
from sklearn.datasets import make_blobs

X_np, y_np = make_blobs(n_samples=200, centers=[[-1, -1], [1, 1]], cluster_std=1.3, random_state=0)
X = torch.tensor(X_np, dtype=torch.float32)
y = torch.tensor(y_np, dtype=torch.float32)


def train(use_mse, lr=0.5, steps=100):
    w = torch.tensor([-3.0, -3.0], requires_grad=True)
    history = []
    for _ in range(steps):
        z = X @ w
        if use_mse:
            loss = F.mse_loss(torch.sigmoid(z), y)
        else:
            loss = F.binary_cross_entropy_with_logits(z, y)
        loss.backward()
        with torch.no_grad():
            w -= lr * w.grad
        w.grad.zero_()
        history.append(((z > 0).float() == y).float().mean().item())
    return history


mse_acc, ce_acc = train(use_mse=True), train(use_mse=False)
print("squared error, final accuracy:", round(mse_acc[-1], 3))
print("cross-entropy, final accuracy:", round(ce_acc[-1], 3))

fig, ax = plt.subplots(figsize=(6.4, 3))
ax.plot(ce_acc, color="#2a78d6", linewidth=2, label="cross-entropy")
ax.plot(mse_acc, color="#eb6834", linewidth=2, label="squared error")
ax.set_xlabel("step")
ax.set_ylabel("training accuracy")
ax.set_ylim(0, 1)
ax.spines[["top", "right"]].set_visible(False)
ax.legend(frameon=False)
plt.show()
```

At `w = (−3, −3)` most points have scores far from zero on the wrong side, where the sigmoid is flat. Squared error's gradient passes through that flat slope and nearly vanishes, so after 100 steps the neuron is still almost entirely wrong. Cross-entropy's gradient is `p − y`, which is largest exactly when the model is most wrong. Same model, same data, same learning rate; only the loss changed.
:::

### Challenge: backpropagate through two layers by hand

A tiny network: `h = X W₁ᵀ + b₁`, `a = ReLU(h)`, `out = a W₂ᵀ + b₂`, with loss `L = mean((out − y)²)`. Use `X` of shape `(8, 3)`, `W₁` `(4, 3)`, `b₁` `(4,)`, `W₂` `(1, 4)`, `b₂` `(1,)`, all from `torch.manual_seed(0)`. Compute the gradients of all four parameter tensors using only matrix operations (no `.backward()` in your formulas), then compare each with autograd.

```text
W1 (4, 3) True
b1 (4,) True
W2 (1, 4) True
b2 (1,) True
```

:::hint
Work backward and keep every gradient the same shape as the thing it's the gradient of. Start with `d_out = 2(out − y) / N`, shape `(8, 1)`. For a layer `out = a Wᵀ + b`: `dW = d_outᵀ a`, `db = d_out.sum(0)`, and the gradient passed back is `d_a = d_out W`. ReLU passes gradient only where `h > 0`.
:::

:::solution
```python run
import torch

torch.manual_seed(0)
X, y = torch.randn(8, 3), torch.randn(8, 1)
W1 = torch.randn(4, 3, requires_grad=True)
b1 = torch.zeros(4, requires_grad=True)
W2 = torch.randn(1, 4, requires_grad=True)
b2 = torch.zeros(1, requires_grad=True)

h = X @ W1.T + b1
a = torch.relu(h)
out = a @ W2.T + b2
loss = ((out - y) ** 2).mean()
loss.backward()

with torch.no_grad():
    d_out = 2 * (out - y) / len(X)       # (8, 1)
    dW2 = d_out.T @ a                    # (1, 8) @ (8, 4) -> (1, 4)
    db2 = d_out.sum(dim=0)               # (1,)
    d_a = d_out @ W2                     # (8, 1) @ (1, 4) -> (8, 4)
    d_h = d_a * (h > 0).float()          # ReLU: gradient flows only where h > 0
    dW1 = d_h.T @ X                      # (4, 8) @ (8, 3) -> (4, 3)
    db1 = d_h.sum(dim=0)                 # (4,)

for name, mine, auto in [("W1", dW1, W1.grad), ("b1", db1, b1.grad), ("W2", dW2, W2.grad), ("b2", db2, b2.grad)]:
    print(name, tuple(mine.shape), torch.allclose(mine, auto, atol=1e-6))
```

The shape rule does most of the work: there's usually only one way to multiply the available tensors that produces the right shape. Biases sum over the batch because every example adds the same bias. And `d_h = d_a * (h > 0)` is the dead-unit story from Module 2 in one line: where `h ≤ 0`, no gradient reaches `W₁`.
:::
