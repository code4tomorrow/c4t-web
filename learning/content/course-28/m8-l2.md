---
title: Build your game in milestones
summary: Build your capstone one working piece at a time, using a Meteor Dodge example that shows a skeleton, a player, clones, levels, and endings.
---

Big games are built the same way you'd build a LEGO castle: one section at a time, checking each part is solid before adding the next. In coding, those sections are called **milestones**. After each one, your game should run without errors, even if it isn't finished.

Below, each milestone is shown with an example game called **Meteor Dodge**: steer a ship, dodge falling meteors, survive 20 seconds on each of two levels. Your game will be different, but the pattern for each milestone is the same. Use these scripts as a starting point and change them to fit your idea.

:::tip
After each milestone, use **File > Save to your computer** and add the milestone number to the file name, like `meteor-dodge-m2.sb3`. If you break something later, you can go back.
:::

## Milestone 1: The skeleton

Set up everything **before** writing game code:

-   **Backdrops:** a painted `Title` (game name plus how to play), `Level 1`, `Level 2`, `You Win`, and `Game Over`. For Meteor Dodge, add **Stars** and one more space backdrop from the library and rename them `Level 1` and `Level 2`.
-   **Sprites:** add them all now, even if they don't do anything yet. Meteor Dodge has `Ship` and `Meteor`.
-   **Variables:** `lives`, `level`, and `time left`, all **For all sprites**.

Then put the game's "boss" script on the **Stage**. It shows the title, resets variables, and runs each level's clock:

```scratch
when green flag clicked
switch backdrop to (Title v)
set [lives v] to (3)
set [level v] to (1)
wait until <key (space v) pressed?>
repeat until <(level) > (2)>
  set [time left v] to (20)
  broadcast (start level v)
  repeat until <(time left) = (0)>
    wait (1) seconds
    change [time left v] by (-1)
  end
  change [level v] by (1)
end
broadcast (you win v)

when I receive [start level v]
if <(level) = (1)> then
  switch backdrop to (Level 1 v)
else
  switch backdrop to (Level 2 v)
end
```

Notice `set [time left v] to (20)` comes **before** `broadcast (start level v)`. Sprites that hear the message can trust the clock is already full.

**Done when:** the title shows, space starts Level 1, the clock counts down, Level 2 appears at 0, and after Level 2 the backdrop stops changing.

## Milestone 2: The player

Make the player move and give it a My Block for getting back to the start. On **Ship**:

```scratch
define reset ship
go to x: (0) y: (-140)
show

when green flag clicked
set size to (50) %
hide

when I receive [start level v]
reset ship
forever
  if <key (left arrow v) pressed?> then
    change x by (-7)
  end
  if <key (right arrow v) pressed?> then
    change x by (7)
  end
end
```

The ship hides on the title screen and appears when a level starts.

**Done when:** the ship shows up on Level 1 and moves left and right.

## Milestone 3: Clones and collisions

Now the danger. On **Meteor**, make a My Block that drops one meteor:

```scratch
define spawn meteor
go to x: (pick random (-220) to (220)) y: (180)
create clone of (myself v)

when green flag clicked
set size to (40) %
hide

when I receive [start level v]
delete this clone
forever
  spawn meteor
  wait ((1) / (level)) seconds
end

when I start as a clone
show
repeat until <(y position) < (-170)>
  change y by ((-3) * (level))
end
delete this clone
```

:::warning
Why does the `start level` script begin with `delete this clone`? Clones hear messages too. Without that block, every meteor still on screen when Level 2 starts would run the `forever` loop and start making its own meteors. The first block deletes the leftover clones. The original isn't a clone, so it ignores `delete this clone` and keeps spawning. Bonus: Level 2 starts with an empty sky.
:::

Next, add the collision to the Ship. Put this `if` inside the Ship's `forever` loop, under the two arrow-key checks. Add the **Zoop** sound to Ship first.

```scratch
if <touching (Meteor v)?> then
  change [lives v] by (-1)
  start sound (Zoop v)
  if <(lives) = (0)> then
    broadcast (game over v)
  else
    reset ship
    wait (1) seconds
  end
end
```

The `wait (1) seconds` gives the player a moment to recover so one meteor can't take two lives.

**Done when:** meteors fall faster on Level 2, and getting hit lowers `lives` by exactly 1.

## Milestone 4: Win and lose endings

Every sprite needs to react to both endings.

On the **Stage**:

```scratch
when I receive [game over v]
stop [other scripts in stage v]
switch backdrop to (Game Over v)

when I receive [you win v]
switch backdrop to (You Win v)
```

On **Meteor** (one script for each message):

```scratch
when I receive [game over v]
stop [other scripts in sprite v]
delete this clone

when I receive [you win v]
stop [other scripts in sprite v]
delete this clone
```

On **Ship**:

```scratch
when I receive [game over v]
stop [other scripts in sprite v]
hide

when I receive [you win v]
stop [other scripts in sprite v]
say [I made it!] for (2) seconds
```

The Stage's `stop [other scripts in stage v]` matters: it stops the level clock, so a game you already lost can't jump to Level 2.

**Done when:** losing all lives shows Game Over with no meteors still falling, and surviving both levels shows You Win.

## Milestone 5: Instructions and juice

"Juice" is game-designer slang for the little touches that make a game feel alive. Add a few:

-   A sound when the level changes.
-   A `say [Level 2!] for (1) seconds` on the Ship at the start of Level 2.
-   A costume change or `change [color v] effect by (25)` when the player gets hit.
-   Background music. On the Stage's **Sounds** tab, add a sound from the **Loops** category, then put `play sound () until done` inside a `forever` loop in a `when I receive [start level v]` script.

Make sure your **Title** backdrop says exactly how to play: which keys, the goal, and how to win.

**Done when:** a brand-new player can read the title screen and start playing without asking you anything.

## Checking your requirements

Meteor Dodge now covers every row of the brief:

```text
Instructions:  Title backdrop explains keys and goal
Timer:         time left counts down 20 seconds per level
Collisions:    Ship touching Meteor costs a life
Clone:         Meteor clones fall from the sky
My Blocks:     reset ship, spawn meteor
Two levels:    Level 2 has faster, more frequent meteors
Win / lose:    You Win after Level 2, Game Over at 0 lives
```

Make the same list for your own game. Anything missing goes into your next milestone.

## If you get stuck

-   Go back to your last saved milestone and add one piece at a time.
-   Check the usual suspects from Week 6: missing resets, hidden sprites, mismatched message names.
-   Turn on variable monitors and watch them while you play.
-   Ask your instructor. Show them the exact steps that cause the problem.
