Every morning you make decisions: *if* it's raining, take an umbrella, *else* wear sunglasses. Games make decisions like that thousands of times a minute. *If* the player touches the coin, collect it. *If* the ball hits the wall, bounce. This week your sprites learn to look around, ask questions, and choose what to do.

## Yes-or-no questions

Some blocks are shaped like a stretched hexagon with pointy ends. These are **boolean** blocks, also called conditions. They don't *do* anything. They answer a yes-or-no question with `true` or `false`.

Here are some from **Sensing**:

-   `<touching (mouse-pointer v)?>` is the sprite touching the mouse, another sprite, or the edge?
-   `<touching color [#ff0000]?>` is the sprite touching that color?
-   `<key (space v) pressed?>` is that key being held down right now?
-   `<mouse down?>` is the mouse button pressed?

And some from **Operators** that compare numbers:

-   `<(x position) > (200)>` is x bigger than 200?
-   `<(x position) < (-200)>` is x smaller than -200?
-   `<(answer) = [yes]>` is the answer exactly "yes"?

Click any boolean block in the palette and Scratch shows you whether it's true or false right now. Try it with `touching (mouse-pointer v)?` while your mouse is over the cat.

## if/then: do it only sometimes

The `if <> then` block in **Control** has a hexagon-shaped hole. Drop a condition in it. The blocks inside only run when the condition is true.

```scratch
when green flag clicked
forever
    if <touching (mouse-pointer v)?> then
        say [Hi there!]
    end
end
```

What happens:

```text
Move the mouse over the cat: it says "Hi there!"
Move the mouse away: the bubble stays.
```

That's not quite right. We need a way to say something *else* when the mouse is away.

## if/else: pick one of two

`if <> then` with an `else` part has two mouths. Exactly one of them runs each time: the top one if the condition is true, the bottom one if it's false.

```scratch
when green flag clicked
forever
    if <touching (mouse-pointer v)?> then
        say [Hi there!]
        set [color v] effect to (50)
    else
        say []
        clear graphic effects
    end
end
```

What happens:

```text
Mouse over the cat: "Hi there!" and the cat changes color.
Mouse away: the bubble disappears and the color goes back to normal.
```

An empty `say []` block removes the speech bubble.

### Why forever + if?

An `if` only checks **once**, at the moment it runs. Put it inside a `forever` loop and it checks over and over, many times a second. This "forever-if" pattern is how almost every game watches for things to happen.

## Smooth movement with key pressed?

Last week, `when [right arrow v] key pressed` moved the cat. It works, but there's a pause before the key starts repeating, and you can only press one key at a time. Games use a forever loop with `key pressed?` instead:

```scratch
when green flag clicked
go to x: (0) y: (0)
forever
    if <key (right arrow v) pressed?> then
        change x by (5)
    end
    if <key (left arrow v) pressed?> then
        change x by (-5)
    end
    if <key (up arrow v) pressed?> then
        change y by (5)
    end
    if <key (down arrow v) pressed?> then
        change y by (-5)
    end
end
```

Now the cat glides smoothly while you hold a key, and holding up and right together moves it diagonally.

## Asking questions

`ask [What's your name?] and wait` shows a question with a text box. Whatever the player types is saved in the `answer` block, which you can use like any value.

```scratch
when green flag clicked
ask [Do you like pizza? (yes or no)] and wait
if <(answer) = [yes]> then
    say [Me too!] for (2) seconds
else
    say [More for me, then!] for (2) seconds
end
```

What happens if you type `yes`:

```text
Me too!
```

What happens if you type `no` (or anything else):

```text
More for me, then!
```

The `=` block doesn't care about capital letters, so `YES` and `Yes` count too.

## Collisions: when things touch

A **collision** is when two things on the stage overlap. Scratch has three main ways to check.

### Touching another sprite

Pick the sprite's name in the `touching` dropdown. Here the cat is chasing a sprite called Apple:

```scratch
when green flag clicked
forever
    point towards (mouse-pointer v)
    move (3) steps
    if <touching (Apple v)?> then
        say [Yum!] for (1) seconds
        go to (random position v)
    end
end
```

The cat follows your mouse. Lead it to the apple, and the cat says "Yum!" and jumps somewhere random.

### Touching a color

`touching color` is perfect for walls, lava, and finish lines that are part of the backdrop. To pick the color, click the color circle in the block, then click the eyedropper at the bottom and click that color on the stage.

```scratch
if <touching color [#ff0000]?> then
    go to x: (-200) y: (0)
end
```

If the sprite touches red, it goes back to the start. This block needs to be inside a `forever` loop to keep checking.

### Touching the edge

`<touching (edge v)?>` is true when any part of the sprite reaches the side of the stage. You can also check the position yourself. This stops the cat at an invisible wall:

```scratch
when green flag clicked
forever
    if <key (right arrow v) pressed?> then
        change x by (5)
    end
    if <(x position) > (200)> then
        set x to (200)
    end
end
```

The cat moves right but never past x = 200, as if it bumped into glass.

:::tip
`if on edge, bounce` is an easy shortcut for bouncing, but it only works for the stage edges. To bounce off a paddle or wall sprite, use something like `if <touching (Paddle v)?> then` and turn the sprite yourself.
:::

## What usually goes wrong

-   **The `if` only works once.** You forgot the `forever` loop around it.
-   **`touching color` never turns true.** The color isn't an exact match. Use the eyedropper instead of guessing.
-   **The sprite gets "stuck" on a wall.** After a collision, move it back out (for example, `change x by (-5)`) so it's not still touching next time around.
-   **Both if/else parts seem to run.** You probably used two separate `if` blocks. In `if/else`, only one part can ever run.
-   **The sprite you want isn't in the `touching` dropdown.** A sprite can't check if it's touching itself, so its own name never shows up there. Make sure you're editing the right sprite.
