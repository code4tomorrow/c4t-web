---
title: Build a responsive, accessible landing page
summary: Build a one-page site for a stargazing club that starts as a phone layout, grows into two columns on wider screens, and works with a keyboard from the first Tab.
---

:::objectives
- Start a page with the viewport tag and write its base CSS for phones first.
- Size the page with `min()`, `clamp()`, and `rem`, and make the hero image scale.
- Add one `min-width` media query that turns the hero into two columns.
- Add a skip link, visible focus styles, checked contrast, and a reduced-motion rule, then test at phone, tablet, and laptop widths.
:::

Three details matter for later steps. The `id="main"` on `<main>` is where the skip link jumps. The `width` and `height` on the `<img>` let the browser reserve space for it. And every section's content sits inside a `.wrap`, which will control the page width in one place.

## Step 2: Base styles for the smallest screen

Open `styles.css`. Everything you write before any media query is the phone layout.

```css title="styles.css"
*, *::before, *::after { box-sizing: border-box; }

body {
  margin: 0;
  font-family: system-ui, sans-serif;
  line-height: 1.6;
  color: #1e293b;
}

img { max-width: 100%; height: auto; display: block; }

.wrap {
  width: min(100% - 2rem, 64rem);
  margin: 0 auto;
}
```

Read the `.wrap` rule out loud: "be the smaller of *full width minus 2rem* or *64rem*." On a phone, the first value wins, leaving 1rem of breathing room on each side. On a laptop, 64rem (1024px) wins, and `margin: 0 auto` centers it. One line replaces a fixed width, a max-width, and side padding.

The header is the toolbar pattern from the last module: `space-between` with `flex-wrap`, so on a very narrow phone the links drop under the club name instead of overlapping it. `gap: 0.5rem 1.5rem` sets a smaller gap between rows than between columns.

`.hero-row` is a grid with no columns declared, which means one column: text, then image. We'll add the second column in Step 5. The heading uses `clamp()` so it's 2rem on a small phone and grows to 3.5rem at most.

The "Save a spot" link is styled as a button, but it's still an `<a>`, because it takes you somewhere. Use `<a>` for going places and `<button>` for doing things, and keyboards and screen readers will treat each one correctly.

## Step 5: One media query for wider screens

Here is the only media query on the page:

```css
@media (min-width: 40rem) {
  .hero { padding: 4rem 0; }
  .hero-row {
    grid-template-columns: 1fr 1fr;
    align-items: center;
  }
}
```

At 40rem (640px) and up, the hero gets more breathing room and splits into text on the left and image on the right. Everything else already adapts by itself, thanks to `min()`, `clamp()`, `auto-fit`, and `flex-wrap`. That's the goal of a good responsive page: let flexible units do most of the work and save media queries for the few changes they can't make.

**The skip link** is the first thing in the page. It's parked off-screen until it gets focus, then slides into view. A keyboard user can press Enter to jump past the header straight to `<main>`, instead of tabbing through every nav link on every page.

**Focus styles** use two colors: dark blue on the white parts of the page, and yellow on the dark header and hero, so the ring always stands out.

**Contrast** was checked for every text color. White heading text on `#0f172a` is about 18 to 1, the dark text on the yellow button is 10.7 to 1, and the grey `#475569` card text on its light background is 6.9 to 1. All pass the 4.5 to 1 minimum with room to spare.

**Motion** is opt-in. Smooth scrolling and the button's small lift only switch on inside `prefers-reduced-motion: no-preference`, so anyone who has asked their device to reduce motion never gets them.

## Step 7: Test it like a visitor

1.  **Phone, tablet, laptop.** Open DevTools, toggle the device toolbar (**Ctrl+Shift+M**, or **Cmd+Shift+M** on a Mac), and try the *Mobile M*, *Tablet*, and *Laptop* width presets. Look for sideways scrolling, text that's too small, and things that overlap.
2.  **Keyboard only.** Put the mouse away. Press Tab from the top: the skip link should appear first, then the club name, the nav links, the "Save a spot" button, the email field, and the "Join the list" button, in that order, each with a visible ring.
3.  **Zoom to 200%.** Press **Ctrl** and **+** (or **Cmd** and **+**) until the zoom reads 200%. Nothing should be cut off, and you shouldn't need to scroll sideways.

:::quiz
Q: Why does the page use `width: min(100% - 2rem, 64rem)` on `.wrap` instead of `width: 64rem`?
- [ ] `min()` makes the page load faster on phones
  It's a sizing rule only; loading speed doesn't change.
- [x] On small screens the first value wins and keeps the content inside the screen; on big screens 64rem caps the line length
  `min()` picks the smaller value at every width, so the box shrinks on phones and stops growing on laptops.
- [ ] It centers the content
  `margin: 0 auto` does the centering. `min()` only chooses the width.

Q: The smooth scrolling and hover lift sit inside `@media (prefers-reduced-motion: no-preference)`. What does that achieve?
- [ ] It turns animation off for everyone
  People who haven't changed the setting still get the motion.
- [x] Motion only switches on for people who haven't asked their device to reduce it
  The default is no motion, and the effects are added only when the visitor has no preference against them.
- [ ] It makes animations run faster on phones
  The query reads an accessibility setting, not the screen size.

Q: "Save a spot" looks like a button. Why is it written as an `<a>` instead of a `<button>`?
- [x] It takes the visitor to another place (the `#join` section), and links are for going places
  Screen readers announce it as a link, and it supports opening in a new tab and other link behavior.
- [ ] Buttons can't have rounded corners
  Buttons can be styled just like links.
- [ ] Links are the only elements Tab can reach
  Buttons and form fields are focusable too.
:::

- Base CSS is the phone layout. Here, one `min-width` media query was the only one the page needed.
- `width: min(100% - 2rem, 64rem); margin: 0 auto;` is a reusable page container that fits every screen.
- Flexible pieces such as `clamp()` headings, `auto-fit` grids, and wrapping flex rows adapt without breakpoints.
- A skip link, focus styles that contrast with every background, checked text contrast, and opt-in motion make the page usable for keyboard users and people sensitive to animation.
- Test at three widths, with the keyboard alone, and at 200% zoom before you call a page done.
:::
