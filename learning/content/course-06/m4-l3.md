:::objectives
- Write selectors that match exactly the elements you mean, and nothing else.
- Score and rank selectors by specificity without guessing.
- Calculate a box's real width under `content-box` and `border-box`.
- Find the usual reasons a CSS rule "does nothing".
- Control the spacing between stacked boxes, and build a component to an exact size.
:::

Do these in a `practice-m4` folder with Live Server running, and keep DevTools open. For every exercise, check your answer in the **Styles** pane (which rule won, which lines are crossed out) and the **Computed** box diagram (the real sizes) before opening the solution.

## Warm-up: who wins?

Three rules want to color the same link. Cover the result and predict first.

```html preview height="80"
<ul class="menu">
  <li><a href="#" class="active">Home</a></li>
</ul>

<style>
  .menu a  { color: teal; }
  a.active { color: orange; }
  ul li a  { color: purple; }
</style>
```

Orange. `.menu a` and `a.active` both score 0-1-1, a tie, so the later one wins. `ul li a` is last, but it scores only 0-0-3: three type selectors never add up to one class.

### Exercise 1: Write precise selectors

Using this HTML, write one selector for each target. Then give each a different style and check that *only* its target changes.

```html
<header>
  <nav>
    <a href="#">Home</a>
    <a href="#" class="current">Shop</a>
  </nav>
</header>
<main>
  <h1>Shop</h1>
  <p class="lead">Fresh stickers every week.</p>
  <p>Free shipping on orders over $10.</p>
  <ul class="products">
    <li>Laptop stickers</li>
    <li class="sale">Water bottle stickers</li>
  </ul>
</main>
```

1.  Every link in the navigation
2.  Only the current page's link
3.  Only the lead paragraph
4.  The `<h1>` and the lead paragraph, in one rule
5.  Only the item on sale
6.  Every item in the products list

:::hint
Most targets have a class you can use directly. For "every link in the navigation", use a descendant selector that starts from `nav`. For two targets in one rule, separate the selectors with a comma.
:::

:::solution
```html preview height="270"
<header>
  <nav>
    <a href="#">Home</a>
    <a href="#" class="current">Shop</a>
  </nav>
</header>
<main>
  <h1>Shop</h1>
  <p class="lead">Fresh stickers every week.</p>
  <p>Free shipping on orders over $10.</p>
  <ul class="products">
    <li>Laptop stickers</li>
    <li class="sale">Water bottle stickers</li>
  </ul>
</main>

<style>
  nav a { padding: 2px 8px; }                 /* 1 */
  .current { background: #fde68a; }          /* 2 */
  .lead { font-size: 20px; }                  /* 3 */
  h1, .lead { color: #4338ca; }               /* 4 */
  .sale { color: #dc2626; font-weight: bold; } /* 5 */
  .products li { list-style: square; }        /* 6 */
</style>
```

For 2, `.current` is enough on its own; `nav .current` also works and only matters if the class could appear elsewhere. For 6, `.products li` reaches every item; plain `li` would also hit list items anywhere else on a bigger page.
:::

### Exercise 2: Rank by specificity

Score each selector, then sort them from strongest to weakest.

```css
.card p
#main .card
article p
.card .title:hover
p
main article .card p
```

:::hint
Count three columns: IDs, then classes and pseudo-classes, then element names. Compare the left column first and only look right when it's tied.
:::

:::solution
| Rank | Selector | Score |
| --- | --- | --- |
| 1 | `#main .card` | 1-1-0 |
| 2 | `.card .title:hover` | 0-3-0 |
| 3 | `main article .card p` | 0-1-3 |
| 4 | `.card p` | 0-1-1 |
| 5 | `article p` | 0-0-2 |
| 6 | `p` | 0-0-1 |

The one ID puts `#main .card` on top, even though `.card .title:hover` has three things in the middle column. `main article .card p` looks long, but its single class ties with `.card p`, and then its extra element names push it ahead. Check your counting with the [Specificity Calculator](https://specificity.keegan.st/).
:::

### Exercise 3: Measure the boxes

Work out each box's visible width (border edge to border edge), and how much horizontal space it takes up including margins.

1.  `width: 250px; padding: 15px; border: 5px solid; margin: 20px;` with the default `content-box`
2.  The same values with `box-sizing: border-box`. Also: how wide is the content area?
3.  `width: 100px; padding: 10px 20px; border: 3px solid;` with `content-box`

:::hint
Under `content-box`, add padding and border on *both* sides to the width. Under `border-box`, the width already includes them, so subtract to find the content. Margin sits outside either way. In box 3, which of the two padding values applies to the left and right?
:::

:::solution
1.  Visible: 5 + 15 + 250 + 15 + 5 = **290px**. With margins: 20 + 290 + 20 = **330px**.
2.  Visible: **250px**. Content: 250 − 5 − 15 − 15 − 5 = **210px**. With margins: **290px**.
3.  `padding: 10px 20px` means 10 top and bottom, 20 left and right. Visible: 3 + 20 + 100 + 20 + 3 = **146px**.

Here are boxes 1 and 2 against a 250px ruler. Select each one in DevTools and compare the Computed diagram with your numbers.

```html preview height="240"
<div class="ruler">250px</div>
<div class="box one">1: content-box</div>
<div class="box two">2: border-box</div>

<style>
  .ruler { width: 250px; margin-left: 20px; background: #e5e7eb; text-align: center; font: 12px monospace; }
  .box { width: 250px; padding: 15px; border: 5px solid #334155; margin: 20px; background: #ecfccb; font: 14px monospace; }
  .one { box-sizing: content-box; }
  .two { box-sizing: border-box; }
</style>
```
:::

### Exercise 4: Why won't my styles apply?

The goal is a teal-bordered card with a **dark orange** heading, a **crimson** note, and **bold, 20px** paragraph text. None of it works. Find four separate bugs.

```html preview height="140"
<div class="Card">
  <h2 id="title">Weekly challenge</h2>
  <p class="note">Due Friday</p>
</div>

<style>
  .card { border: 2px solid teal; padding: 16px; }
  note { color: crimson; }
  #title { color: navy; }
  h2 { color: darkorange; }
  p { font-size: 20px font-weight: bold; }
</style>
```

:::hint
Check four things, one per rule: does the class name match the HTML exactly, including capitals? Is there a dot where a class is meant? Does an earlier rule have a higher score? Does every declaration end with a semicolon?
:::

:::solution
1.  **Case.** The HTML says `class="Card"`, the CSS says `.card`. Class names are case-sensitive. Use lowercase in both places.
2.  **Missing dot.** `note` looks for a `<note>` element, which doesn't exist. It should be `.note`.
3.  **An ID wins.** `#title` (1-0-0) beats `h2` (0-0-1), so the heading stays navy no matter where the `h2` rule goes. Delete the `#title` rule, or better, don't style with IDs at all.
4.  **Missing semicolon.** Without the `;` after `20px`, the browser reads one declaration, `font-size: 20px font-weight: bold`, which isn't a valid size, and throws the whole thing away. Neither the size nor the bold applies.

```html preview height="150"
<div class="card">
  <h2 class="title">Weekly challenge</h2>
  <p class="note">Due Friday</p>
</div>

<style>
  .card { border: 2px solid teal; padding: 16px; }
  .note { color: crimson; }
  .title { color: darkorange; }
  p { font-size: 20px; font-weight: bold; }
</style>
```

In DevTools, an invalid declaration like bug 4 shows up crossed out with a small warning icon, which makes it easy to spot.
:::

### Exercise 5: Fix the spacing

Three notes are stacked inside a bordered panel, each with `margin: 24px 0`. Predict the gap *between* two notes, then change the CSS so that:

-   the gap between notes is exactly 16px, and
-   there's no extra space above the first note or below the last one (the panel's own 16px padding is enough).

```html preview height="290"
<div class="panel">
  <p class="note">Bring your laptop charger.</p>
  <p class="note">The room changes to 214 next week.</p>
  <p class="note">Pizza order closes Thursday.</p>
</div>

<style>
  .panel { border: 2px solid #94a3b8; padding: 16px; max-width: 360px; }
  .note { margin: 24px 0; padding: 12px; background: #e0f2fe; }
</style>
```

:::hint
The gap between notes is 24px, not 48px: vertical margins collapse. For the fix, give each note margin on one side only, and then remove it from the last note. The pseudo-class `:last-child` matches an element that's the last child of its parent.
:::

:::solution
```html preview height="230"
<div class="panel">
  <p class="note">Bring your laptop charger.</p>
  <p class="note">The room changes to 214 next week.</p>
  <p class="note">Pizza order closes Thursday.</p>
</div>

<style>
  .panel { border: 2px solid #94a3b8; padding: 16px; max-width: 360px; }
  .note { margin: 0 0 16px; padding: 12px; background: #e0f2fe; }
  .note:last-child { margin-bottom: 0; }
</style>
```

Margins only on the bottom means there's nothing to collapse and nothing hanging off the top. `.note:last-child` scores 0-2-0, so it beats `.note` (0-1-0) and removes the final margin.
:::

### Exercise 6: A profile card, built to spec

Style this HTML into a card that matches the spec exactly. Use class selectors only.

```html
<article class="profile">
  <h2 class="profile-name">Ada Lovelace</h2>
  <p class="profile-role">First published computer program, 1843</p>
  <a class="profile-link" href="https://en.wikipedia.org/wiki/Ada_Lovelace">Read more</a>
</article>
```

-   Exactly **300px** wide from border edge to border edge, with a 2px border, 12px rounded corners, and 20px of padding.
-   The name has no top margin and 4px of bottom margin; the role is gray with 16px below it.
-   The link looks like a button: white text on a dark background, 8px by 16px of padding, rounded corners, no underline.
-   The link gets darker on hover and shows a clear outline when focused with the keyboard.

:::hint
`box-sizing: border-box` makes "exactly 300px" mean `width: 300px`. A link is inline, so give it `display: inline-block` before padding behaves like a button's. You'll need `:hover` and `:focus-visible`.
:::

:::solution
```html preview height="240"
<article class="profile">
  <h2 class="profile-name">Ada Lovelace</h2>
  <p class="profile-role">First published computer program, 1843</p>
  <a class="profile-link" href="https://en.wikipedia.org/wiki/Ada_Lovelace">Read more</a>
</article>

<style>
  .profile {
    box-sizing: border-box;
    width: 300px;
    padding: 20px;
    border: 2px solid #cbd5e1;
    border-radius: 12px;
    font-family: system-ui, sans-serif;
  }
  .profile-name { margin: 0 0 4px; }
  .profile-role { margin: 0 0 16px; color: #64748b; }
  .profile-link {
    display: inline-block;
    padding: 8px 16px;
    border-radius: 8px;
    background: #1e293b;
    color: white;
    text-decoration: none;
  }
  .profile-link:hover { background: #0f172a; }
  .profile-link:focus-visible { outline: 3px solid #f59e0b; outline-offset: 2px; }
</style>
```

The Computed diagram for `.profile` should read 2 (border) + 20 (padding) + 256 (content) + 20 + 2 = 300. Every selector is a single class, or a class plus a pseudo-class, so nothing scores higher than 0-2-0 and nothing fights.
:::

### Challenge: Put a stylesheet on a specificity diet

Someone styled this alert box with IDs and `!important`, and now nobody can change it. Rewrite the CSS so it looks the same but uses **no IDs and no `!important`**, with no selector scoring above 0-2-0. Then add a second alert with a green "success" look by adding one extra class in the HTML, without touching the original rules.

```html preview height="150"
<div id="alert" class="alert">
  <p id="alert-text">Your session ends in 5 minutes.</p>
</div>

<style>
  #alert { padding: 12px 16px; border: 2px solid #f59e0b !important; background: #fef3c7; border-radius: 8px; }
  #alert #alert-text { margin: 0; color: #92400e !important; font-family: system-ui, sans-serif; }
  div.alert p { color: black; }
</style>
```

:::hint
Start with a base class (`.alert`) and a class for its text. For the success version, a "modifier" class like `.alert-success` that comes later in the file can override colors at equal specificity. The leftover `div.alert p` rule is dead code: it scores 0-1-2, so the two-ID rule always beat it. Decide whether your version needs it at all.
:::

:::solution
```html preview height="190"
<div class="alert">
  <p class="alert-text">Your session ends in 5 minutes.</p>
</div>
<div class="alert alert-success">
  <p class="alert-text">Your project was saved.</p>
</div>

<style>
  .alert { margin-bottom: 12px; padding: 12px 16px; border: 2px solid #f59e0b; background: #fef3c7; border-radius: 8px; }
  .alert-text { margin: 0; color: #92400e; font-family: system-ui, sans-serif; }

  .alert-success { border-color: #16a34a; background: #dcfce7; }
  .alert-success .alert-text { color: #166534; }
</style>
```

`.alert-success` ties with `.alert` at 0-1-0 and comes later, so its border and background win. `.alert-success .alert-text` (0-2-0) beats `.alert-text` (0-1-0) for the text color. The old `div.alert p` rule is gone, because nothing needed it. The `margin-bottom` is new, only so the two alerts don't touch.
:::
