---
title: "Practice: tokens, hierarchy, and paths between pages"
summary: Six exercises on custom properties, visual hierarchy, spacing, relative paths, and themes, plus a challenge to build a style guide page from your own design tokens.
---

:::objectives
- Replace repeated values with custom properties, and create variations by overriding them.
- Fix flat hierarchy and messy spacing using size, weight, color, and proximity.
- Write correct relative paths between files in nested folders.
:::

These exercises use the skills from the club site, but on new pages with new problems. For the CSS ones, paste the starter into a file, open it with Live Server, and make the change yourself before opening the solution. For the path ones, a pencil is all you need.

## Warm-up: climb the folders

Use this folder tree for the warm-up and for Exercise 3.

```text
portfolio/
├── index.html
├── about.html
├── css/
│   └── styles.css
├── images/
│   └── me.jpg
└── projects/
    ├── index.html
    └── comic/
        └── page.html
```

:::quiz
Q: What `href` links `projects/comic/page.html` to the stylesheet?
- [ ] `../css/styles.css`
  One `../` only climbs out of `comic/` into `projects/`, and there's no `css` folder there.
- [x] `../../css/styles.css`
  The first `../` leaves `comic/`, the second leaves `projects/`, and then `css/styles.css` is right there.
- [ ] `css/styles.css`
  From inside `comic/`, that would look for `projects/comic/css/styles.css`.

Q: `projects/index.html` has a link with `href="comic/page.html"`. Where does it go?
- [x] `projects/comic/page.html`
  A path with no `../` starts in the current file's folder, which is `projects/`.
- [ ] `portfolio/comic/page.html`
  That folder doesn't exist. Relative paths start from where the linking file is, not from the top.
:::

### Exercise 1: Turn repeated values into tokens

This stylesheet repeats the same pink four times and uses three slightly different grays. Rewrite it with custom properties on `:root` so that each color and size appears exactly once. Merge the three grays into one.

```css
.title   { color: #be123c; font-size: 2.4rem; margin-bottom: 0.5rem; }
.tagline { color: #4b5563; font-size: 1.25rem; margin-bottom: 1.5rem; }
.button  { background: #be123c; color: white; padding: 0.5rem 1.5rem; }
.card    { border-top: 4px solid #be123c; padding: 1.5rem; color: #475569; }
.footer  { color: #52525b; padding: 1.5rem; }
a        { color: #be123c; }
```

:::hint
Name tokens by their job, not their color: `--color-brand` instead of `--pink`. That way the name still makes sense if the brand turns orange next year.
:::

:::solution
```css
:root {
  --color-brand: #be123c;
  --color-on-brand: #ffffff;
  --color-muted: #4b5563;
  --step-1: 1.25rem;
  --step-4: 2.4rem;
  --space-xs: 0.5rem;
  --space-m: 1.5rem;
}
.title   { color: var(--color-brand); font-size: var(--step-4); margin-bottom: var(--space-xs); }
.tagline { color: var(--color-muted); font-size: var(--step-1); margin-bottom: var(--space-m); }
.button  { background: var(--color-brand); color: var(--color-on-brand); padding: var(--space-xs) var(--space-m); }
.card    { border-top: 4px solid var(--color-brand); padding: var(--space-m); color: var(--color-muted); }
.footer  { color: var(--color-muted); padding: var(--space-m); }
a        { color: var(--color-brand); }
```

The three grays were almost identical, and nobody would notice the difference, but they made the site harder to maintain. One `--color-muted` (7.6:1 on white) replaces all of them. The border width stays a plain `4px`: tokens are for decisions you'll reuse, not every number.
:::

### Exercise 2: Rescue a page with no hierarchy

Every line on this event page shouts equally. Without changing the HTML, restyle it so a visitor can find, in this order: what the event is, when it is, and how to get a ticket.

```html preview height="250"
<p class="kicker">Riverside Library presents</p>
<h1>Comic Jam Saturday</h1>
<p class="when">Saturday, June 6, 1 to 4 p.m., Main Hall</p>
<p class="about">Draw a four-panel comic with local artists. Paper, pens, and snacks are provided. All ages are welcome, and you don't need to be good at drawing.</p>
<a class="ticket" href="#">Get a free ticket</a>
<style>
  body { font: bold 18px/1.3 system-ui, sans-serif; margin: 12px; color: #1e293b; }
  h1 { font-size: 18px; margin: 0; }
  p, a { margin: 0; color: #1e293b; }
</style>
```

:::hint
Use the four tools from the notes. One element should be clearly the biggest. Body text should be regular weight. The ticket link is the one action on the page, so give it the strongest color. And put the small label right against the title it introduces.
:::

:::solution
```html preview height="330"
<p class="kicker">Riverside Library presents</p>
<h1>Comic Jam Saturday</h1>
<p class="when">Saturday, June 6, 1 to 4 p.m., Main Hall</p>
<p class="about">Draw a four-panel comic with local artists. Paper, pens, and snacks are provided. All ages are welcome, and you don't need to be good at drawing.</p>
<a class="ticket" href="#">Get a free ticket</a>
<style>
  body { font: 16px/1.6 system-ui, sans-serif; margin: 12px; color: #1e293b; }
  .kicker { margin: 0; font-size: 0.8rem; font-weight: 700; letter-spacing: 0.08em; text-transform: uppercase; color: #9d174d; }
  h1 { font-size: 2.4rem; line-height: 1.1; margin: 0.15rem 0 0.5rem; }
  .when { margin: 0 0 1rem; font-size: 1.25rem; font-weight: 600; }
  .about { margin: 0 0 1.5rem; max-width: 60ch; color: #475569; }
  .ticket { display: inline-block; padding: 0.6rem 1.2rem; border-radius: 999px; background: #9d174d; color: white; font-weight: 700; text-decoration: none; }
</style>
```

Squint at it: the title, then the date, then the pink button. The paragraph is still there for anyone who wants details, but it's lighter and quieter, so it doesn't compete. The pink is 7.9:1 against white in both directions, so the label and the button text both pass.
:::

### Exercise 3: Write the paths

Using the warm-up folder tree, write the `href` (or `src`) for each link.

1. In `index.html`, the photo `images/me.jpg`.
2. In `about.html`, a link to the projects list.
3. In `projects/index.html`, a link back to the home page.
4. In `projects/index.html`, the photo `images/me.jpg`.
5. In `projects/comic/page.html`, a link back to the projects list.

:::hint
For each one, start at the folder that holds the file you're writing in. Count how many folders you need to climb out of (`../` each), then walk down into the target.
:::

:::solution
| # | From | `href` or `src` |
| - | ---- | --------------- |
| 1 | `index.html` | `images/me.jpg` |
| 2 | `about.html` | `projects/index.html` |
| 3 | `projects/index.html` | `../index.html` |
| 4 | `projects/index.html` | `../images/me.jpg` |
| 5 | `projects/comic/page.html` | `../index.html` |

Number 5 is the trick question. From `comic/`, one `../` lands in `projects/`, and the projects list is `index.html` right there. It is not the home page, which would be `../../index.html`.
:::

### Exercise 4: Fix the spacing with proximity

On this page every gap is the same 24px, so each heading floats halfway between two sections and it's hard to tell what it belongs to. Change only the margins so each heading clearly belongs to the text *below* it, using the spacing scale 0.25, 0.5, 1, 1.5, 2, and 3rem.

```html preview height="330"
<h2>Hours</h2>
<p>Tuesday to Saturday, 9 a.m. to 5 p.m.</p>
<h2>Parking</h2>
<p>Free lot behind the building. The street spots have a two-hour limit.</p>
<h2>Accessibility</h2>
<p>Step-free entrance on Mill Street, and an elevator to every floor.</p>
<style>
  body { font: 16px/1.6 system-ui, sans-serif; margin: 12px; color: #1e293b; }
  h2, p { margin: 24px 0; }
  h2 { font-size: 1.25rem; }
</style>
```

:::hint
A heading needs a big gap *above* it (that's where the previous topic ends) and a small gap *below* it. Margins collapse between neighbors, so the larger of two touching margins wins.
:::

:::solution
```html preview height="300"
<h2>Hours</h2>
<p>Tuesday to Saturday, 9 a.m. to 5 p.m.</p>
<h2>Parking</h2>
<p>Free lot behind the building. The street spots have a two-hour limit.</p>
<h2>Accessibility</h2>
<p>Step-free entrance on Mill Street, and an elevator to every floor.</p>
<style>
  body { font: 16px/1.6 system-ui, sans-serif; margin: 12px; color: #1e293b; }
  h2 { font-size: 1.25rem; margin: 2rem 0 0.25rem; }
  h2:first-child { margin-top: 0; }
  p { margin: 0; }
</style>
```

Now each heading sits 0.25rem from its paragraph and 2rem from the previous one, so the page reads as three clear groups. Nothing else changed: same fonts, same sizes. Spacing alone did the grouping.
:::

### Exercise 5: A dark theme from the same tokens

This card is built entirely from tokens. Add a dark theme in two ways: automatically, when the visitor's device is set to dark mode, and with a toggle button that sets `data-theme="dark"` on the `<html>` element. Every color pair must pass 4.5:1.

```html
<button type="button" onclick="document.documentElement.toggleAttribute('data-theme')">Toggle theme</button>
<article class="card">
  <h2>Comic Jam</h2>
  <p>Saturday, 1 to 4 p.m. Bring a friend.</p>
  <a href="#">Get a ticket</a>
</article>
<style>
  :root { --color-bg: #ffffff; --color-surface: #f1f5f9; --color-text: #1e293b; --color-brand: #1d4ed8; }
  body { background: var(--color-bg); color: var(--color-text); font: 16px/1.6 system-ui, sans-serif; margin: 12px; }
  .card { background: var(--color-surface); padding: 1rem; border-radius: 12px; max-width: 20rem; margin-top: 1rem; }
  .card h2 { margin: 0; }
  a { color: var(--color-brand); }
</style>
```

:::hint
Redefine the four color tokens in two places: inside `@media (prefers-color-scheme: dark) { :root { … } }` and in a `[data-theme]` rule. Nothing else in the CSS should change. (`toggleAttribute` adds an empty `data-theme` attribute or removes it, so match `[data-theme]` rather than a specific value.)
:::

:::solution
```html preview height="220"
<button type="button" onclick="document.documentElement.toggleAttribute('data-theme')">Toggle theme</button>
<article class="card">
  <h2>Comic Jam</h2>
  <p>Saturday, 1 to 4 p.m. Bring a friend.</p>
  <a href="#">Get a ticket</a>
</article>
<style>
  :root { --color-bg: #ffffff; --color-surface: #f1f5f9; --color-text: #1e293b; --color-brand: #1d4ed8; }

  @media (prefers-color-scheme: dark) {
    :root { --color-bg: #0f172a; --color-surface: #1e293b; --color-text: #e2e8f0; --color-brand: #93c5fd; }
  }
  :root[data-theme] { --color-bg: #0f172a; --color-surface: #1e293b; --color-text: #e2e8f0; --color-brand: #93c5fd; }

  body { background: var(--color-bg); color: var(--color-text); font: 16px/1.6 system-ui, sans-serif; margin: 12px; }
  .card { background: var(--color-surface); padding: 1rem; border-radius: 12px; max-width: 20rem; margin-top: 1rem; }
  .card h2 { margin: 0; }
  a { color: var(--color-brand); }
</style>
```

In the dark theme, text is 11.9:1 on the card and the link is 8.1:1, so both pass easily. To test the automatic version without changing your computer's settings, open DevTools, run **Show Rendering** from the Command Menu, and set the `prefers-color-scheme` emulation to `dark`.

This simple toggle has a limit you'll notice if your device is already in dark mode: the button can't switch to light, because it only ever adds the dark theme. Handling both directions properly takes a few more lines of JavaScript, which is a good first project for the next course.
:::

### Exercise 6: A featured card without new rules

The `.card` below reads its colors from tokens. Make a `.card--featured` variant with a dark brand-colored background and white text, by writing **only custom property values** in the new rule. Don't repeat any `background` or `color` declarations.

```html
<div class="row">
  <article class="card"><h3>Basic</h3><p>One workshop a month.</p><a class="button" href="#">Choose</a></article>
  <article class="card card--featured"><h3>Member</h3><p>Every workshop, plus studio time.</p><a class="button" href="#">Choose</a></article>
</div>
<style>
  :root { --card-bg: #f1f5f9; --card-text: #1e293b; --button-bg: #0f766e; --button-text: #ffffff; }
  body { font: 16px/1.5 system-ui, sans-serif; margin: 12px; }
  .row { display: flex; flex-wrap: wrap; gap: 1rem; }
  .card { flex: 1 1 12rem; background: var(--card-bg); color: var(--card-text); padding: 1rem; border-radius: 12px; }
  .card h3 { margin: 0; }
  .button { display: inline-block; background: var(--button-bg); color: var(--button-text); padding: 0.4rem 1rem; border-radius: 999px; text-decoration: none; font-weight: 700; }
</style>
```

:::hint
Custom properties inherit. If `.card--featured` sets `--card-bg`, everything inside that card (including its button) sees the new value. Which four tokens need new values so that the button still stands out on a dark card?
:::

:::solution
```html preview height="200"
<div class="row">
  <article class="card"><h3>Basic</h3><p>One workshop a month.</p><a class="button" href="#">Choose</a></article>
  <article class="card card--featured"><h3>Member</h3><p>Every workshop, plus studio time.</p><a class="button" href="#">Choose</a></article>
</div>
<style>
  :root { --card-bg: #f1f5f9; --card-text: #1e293b; --button-bg: #0f766e; --button-text: #ffffff; }
  .card--featured { --card-bg: #0f766e; --card-text: #ffffff; --button-bg: #ffffff; --button-text: #0f766e; }
  body { font: 16px/1.5 system-ui, sans-serif; margin: 12px; }
  .row { display: flex; flex-wrap: wrap; gap: 1rem; }
  .card { flex: 1 1 12rem; background: var(--card-bg); color: var(--card-text); padding: 1rem; border-radius: 12px; }
  .card h3 { margin: 0; }
  .button { display: inline-block; background: var(--button-bg); color: var(--button-text); padding: 0.4rem 1rem; border-radius: 999px; text-decoration: none; font-weight: 700; }
</style>
```

The featured card flips the colors: teal background with white text (5.5:1), and a white button with teal text (also 5.5:1). The `.card` and `.button` rules never changed. This is how design systems build dozens of variants from a handful of rules.
:::

### Challenge: A style guide page

Professional teams keep a page that shows every design token so nobody has to guess. Add a `styleguide.html` to the Riverside Robotics site that uses the same stylesheet and shows:

1. A swatch for each color token, with its name and value printed underneath.
2. One line of text at each step of the type scale, labeled with the token name.
3. A bar for each spacing token, whose width *is* that token.
4. One example of each component: the button, a card, and the eyebrow label.

The page should update itself when you change a token in `styles.css`, with no edits to `styleguide.html`.

:::hint
Use the tokens directly in small inline styles or in a few new classes: a swatch is a box with `background: var(--color-brand)`, and a spacing bar is a box with `width: var(--space-l)`. Because the values come from `var()`, the page follows the stylesheet automatically. Typing the hex values in the labels is fine; only the visuals need to update.
:::

:::solution
Here is the start of one, using a few of the club's tokens. Extend it to every token in your stylesheet.

```html preview height="520"
<main class="wrap">
  <h1>Style guide</h1>
  <h2>Colors</h2>
  <div class="swatches">
    <figure><div class="chip" style="background: var(--color-brand)"></div><figcaption>--color-brand<br>#0f766e</figcaption></figure>
    <figure><div class="chip" style="background: var(--color-text)"></div><figcaption>--color-text<br>#1e293b</figcaption></figure>
    <figure><div class="chip" style="background: var(--color-muted)"></div><figcaption>--color-muted<br>#475569</figcaption></figure>
    <figure><div class="chip" style="background: var(--color-surface)"></div><figcaption>--color-surface<br>#f1f5f9</figcaption></figure>
  </div>
  <h2>Type scale</h2>
  <p style="font-size: var(--step-4); margin: 0">--step-4 headline</p>
  <p style="font-size: var(--step-2); margin: 0">--step-2 section heading</p>
  <p style="font-size: var(--step-0)">--step-0 body text</p>
  <h2>Spacing</h2>
  <div class="bar" style="width: var(--space-s)"></div><p class="label">--space-s</p>
  <div class="bar" style="width: var(--space-l)"></div><p class="label">--space-l</p>
  <div class="bar" style="width: var(--space-xl)"></div><p class="label">--space-xl</p>
  <h2>Components</h2>
  <p class="eyebrow">Eyebrow label</p>
  <a class="button" href="#">Button</a>
</main>
<style>
  :root { --color-text: #1e293b; --color-muted: #475569; --color-surface: #f1f5f9; --color-brand: #0f766e; --color-on-brand: #ffffff; --step-0: 1rem; --step-2: 1.563rem; --step-4: 2.441rem; --space-2xs: 0.25rem; --space-xs: 0.5rem; --space-s: 1rem; --space-m: 1.5rem; --space-l: 2rem; --space-xl: 3rem; }
  body { margin: 0; font: var(--step-0)/1.5 system-ui, sans-serif; color: var(--color-text); }
  .wrap { width: min(100% - 2rem, 64rem); margin: 0 auto; }
  h2 { margin: var(--space-l) 0 var(--space-xs); }
  .swatches { display: grid; grid-template-columns: repeat(auto-fit, minmax(8rem, 1fr)); gap: var(--space-s); }
  figure { margin: 0; font: 0.8rem/1.4 monospace; }
  .chip { height: 3rem; border-radius: 0.5rem; border: 1px solid #cbd5e1; margin-bottom: var(--space-2xs); }
  .bar { height: 0.75rem; background: var(--color-brand); border-radius: 4px; }
  .label { margin: 0 0 var(--space-xs); font: 0.8rem monospace; }
  .eyebrow { margin: 0 0 var(--space-xs); font-size: 0.8rem; font-weight: 700; letter-spacing: 0.08em; text-transform: uppercase; color: var(--color-brand); }
  .button { display: inline-block; padding: var(--space-xs) var(--space-m); border-radius: 999px; background: var(--color-brand); color: var(--color-on-brand); font-weight: 700; text-decoration: none; }
</style>
```

In your real `styleguide.html`, leave out the `<style>` block and link `css/styles.css` like every other page, keeping only the few new classes (`.swatches`, `.chip`, `.bar`, `.label`) in the shared stylesheet. Then change `--color-brand` and reload: every swatch, bar, and button follows.
:::
