## Warm-up: name that element

For each piece of content, which element fits best? Answer before opening the solution.

1.  The copyright line at the bottom of every page
2.  Five links to the site's main pages
3.  A blog post shown on the home page that could be shared on its own
4.  A "Did you know?" box next to an article
5.  A wrapper you need only so CSS can add a background color

:::solution
1. `<footer>` 2. `<nav>` with a `<ul>` inside 3. `<article>` 4. `<aside>` 5. `<div>`: no semantic element fits, so use the generic one.
:::

### Exercise 1: Rewrite the div soup

This page uses `<div>` for everything. Rewrite it with landmark and sectioning elements, without changing the text. Keep a `<div>` only if nothing else fits.

```html
<div class="top">
  <div class="logo">Pixel Club</div>
  <div class="menu">
    <a href="index.html">Home</a>
    <a href="events.html">Events</a>
  </div>
</div>
<div class="content">
  <div class="post">
    <div class="title">Our first game jam</div>
    <div class="text">Twelve of us made six games in one weekend.</div>
  </div>
</div>
<div class="bottom">Pixel Club meets every Friday.</div>
```

:::hint
Work from the outside in: the top strip, the menu, the main area, the one self-contained post, the bottom strip. Then fix the insides: the post's title should be a heading, the menu's links a list, and the text a paragraph.
:::

:::solution
```html preview height="270"
<header>
  <p>Pixel Club</p>
  <nav>
    <ul>
      <li><a href="index.html">Home</a></li>
      <li><a href="events.html">Events</a></li>
    </ul>
  </nav>
</header>
<main>
  <article>
    <h1>Our first game jam</h1>
    <p>Twelve of us made six games in one weekend.</p>
  </article>
</main>
<footer>
  <p>Pixel Club meets every Friday.</p>
</footer>
```

No `<div>` survived: every region had a meaningful element. The post title became the page's `<h1>` because the post is what this page is about. (Don't click the menu links in the frame; those pages don't exist here.)
:::

### Exercise 2: Choose and nest lists

Mark up both lists:

-   **My top three movies**, best first: *Spider-Man: Into the Spider-Verse*, *Coco*, *WALL-E*.
-   **Beach day bag:** sunscreen, water bottle, and snacks. Under snacks, list grapes, crackers, and granola bars.

Sample result: the movies numbered 1 to 3, the beach list bulleted, and the three snacks indented under "Snacks".

:::hint
A ranking has an order; a bag doesn't. For the snacks, the inner list goes *inside* the "Snacks" `<li>`, before its closing tag.
:::

:::solution
```html preview height="300"
<h2>My top three movies</h2>
<ol>
  <li><cite>Spider-Man: Into the Spider-Verse</cite></li>
  <li><cite>Coco</cite></li>
  <li><cite>WALL-E</cite></li>
</ol>

<h2>Beach day bag</h2>
<ul>
  <li>Sunscreen</li>
  <li>Water bottle</li>
  <li>Snacks
    <ul>
      <li>Grapes</li>
      <li>Crackers</li>
      <li>Granola bars</li>
    </ul>
  </li>
</ul>
```

`<cite>` marks the title of a creative work, and browsers italicize it. Plain text in the `<li>`s would also be correct.
:::

### Exercise 3: A schedule table with row headers

Build this as a table, with the caption "Art club rotation", the days as column headers, and the weeks as row headers:

```text
         Monday    Wednesday
Week 1   Clay      Painting
Week 2   Drawing   Clay
Week 3   Painting  Drawing
```

:::hint
The top-left cell has no heading of its own; use an empty `<td></td>` there. Each body row starts with a `<th scope="row">` for the week, then `<td>`s for the activities.
:::

:::solution
```html preview height="200"
<table>
  <caption>Art club rotation</caption>
  <thead>
    <tr><td></td><th scope="col">Monday</th><th scope="col">Wednesday</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">Week 1</th><td>Clay</td><td>Painting</td></tr>
    <tr><th scope="row">Week 2</th><td>Drawing</td><td>Clay</td></tr>
    <tr><th scope="row">Week 3</th><td>Painting</td><td>Drawing</td></tr>
  </tbody>
</table>
<style>
  table { border-collapse: collapse; }
  th, td { border: 1px solid #94a3b8; padding: 4px 10px; }
</style>
```

Now a screen reader user who moves to "Clay" in the second row can hear which week and which day it belongs to, not just the word "Clay".
:::

### Exercise 4: Fix the broken form

Try clicking each label in this form. Some do nothing, and the radio buttons misbehave. Find **five** bugs.

```html preview height="290"
<form>
  <p>Username <input type="text" id="user" name="user"></p>
  <p><label for="mail">Email</label> <input type="text" id="email" name="email"></p>
  <p><input type="password" id="pw" placeholder="Password"></p>
  <p>Grade:
    <input type="radio" id="g9" name="grade9"> <label for="g9">9</label>
    <input type="radio" id="g10" name="grade10"> <label for="g10">10</label>
    <input type="radio" id="g11" name="grade11"> <label for="g11">11</label>
  </p>
  <button>Join</button>
</form>
```

:::hint
Check each field for four things: does it have a `<label>`, does `for` match `id`, does it have a `name`, and is its `type` the most specific one? Then look at how the radio buttons are named and grouped.
:::

:::solution
1.  "Username" is plain text, not a `<label>`, so the field has no name for screen readers and clicking the word does nothing.
2.  The email label says `for="mail"` but the input's `id` is `email`.
3.  The email field is `type="text"`; `type="email"` gives the `@` keyboard and checks the address.
4.  The password uses `placeholder` instead of a label, and it has no `name`, so it would never be sent.
5.  Every radio button has a different `name`, so all three can be selected. They also need a `<fieldset>` and `<legend>` so "Grade" is announced as the question, plus a `value` each.

```html preview height="330"
<form>
  <p><label for="user">Username</label> <input type="text" id="user" name="user" required></p>
  <p><label for="email">Email</label> <input type="email" id="email" name="email" required></p>
  <p><label for="pw">Password</label> <input type="password" id="pw" name="password" required></p>
  <fieldset>
    <legend>Grade</legend>
    <input type="radio" id="g9" name="grade" value="9"> <label for="g9">9</label>
    <input type="radio" id="g10" name="grade" value="10"> <label for="g10">10</label>
    <input type="radio" id="g11" name="grade" value="11"> <label for="g11">11</label>
  </fieldset>
  <button>Join</button>
</form>
```

Click the labels again: every one now focuses or selects its control, and only one grade can be chosen.
:::

### Exercise 5: Pick the input types

You're building a form for a summer coding camp. Choose the best element and `type` for each field, and say what it gives the visitor.

1.  Parent's phone number
2.  Camper's date of birth
3.  Number of T-shirts (1 to 3)
4.  Camper's personal website, if any
5.  Allergies or medical notes
6.  Which week: June, July, or August (exactly one)

:::hint
Think about what keyboard or picker would appear on a phone, and whether the visitor picks one option, several, or types freely.
:::

:::solution
| Field | Markup | Why |
| --- | --- | --- |
| Phone | `<input type="tel">` | Phone keypad on mobile; phone formats vary, so no checking |
| Date of birth | `<input type="date">` | A date picker, and no confusion about day/month order |
| T-shirts | `<input type="number" min="1" max="3">` | Number keypad, and 0 or 4 are rejected |
| Website | `<input type="url">` | Checks for a full address like `https://…` |
| Medical notes | `<textarea>` | Room for several lines |
| Week | Three `<input type="radio" name="week">` in a `<fieldset>` | Exactly one choice, with the legend as the question |
:::

### Exercise 6: An event registration form

Build a registration form for a community "Code and Pizza Night". It needs:

-   Full name and email, both required.
-   Age, a number from 10 to 18, required.
-   A choice of one workshop: "Build a web page", "Make a game", or "Program a robot".
-   A T-shirt size drop-down: S, M, L, XL.
-   A text area for dietary needs.
-   A required checkbox: "A parent or guardian knows I'm attending".
-   A submit button.

:::hint
Copy the label-and-input pattern from the Notes for each field. A drop-down is `<select>` with an `<option>` for each size, and it takes a `<label>` just like an input. Test it in Live Server: submitting with blanks should be blocked, and a full submission should put every `name` in the address bar.
:::

:::solution
```html preview height="560"
<form>
  <h2>Code and Pizza Night: register</h2>
  <p><label for="full-name">Full name</label> <input type="text" id="full-name" name="full_name" required></p>
  <p><label for="email">Email</label> <input type="email" id="email" name="email" required></p>
  <p><label for="age">Age (10 to 18)</label> <input type="number" id="age" name="age" min="10" max="18" required></p>
  <fieldset>
    <legend>Pick one workshop</legend>
    <p><input type="radio" id="ws-web" name="workshop" value="web" required> <label for="ws-web">Build a web page</label></p>
    <p><input type="radio" id="ws-game" name="workshop" value="game"> <label for="ws-game">Make a game</label></p>
    <p><input type="radio" id="ws-robot" name="workshop" value="robot"> <label for="ws-robot">Program a robot</label></p>
  </fieldset>
  <p>
    <label for="size">T-shirt size</label>
    <select id="size" name="size">
      <option value="s">S</option>
      <option value="m">M</option>
      <option value="l">L</option>
      <option value="xl">XL</option>
    </select>
  </p>
  <p><label for="diet">Dietary needs</label><br><textarea id="diet" name="diet" rows="3" cols="30"></textarea></p>
  <p><input type="checkbox" id="guardian" name="guardian" required> <label for="guardian">A parent or guardian knows I'm attending</label></p>
  <button>Register</button>
</form>
```

Putting `required` on one radio button makes the whole group required: the visitor has to pick one of the three. The `<br>` before the text area puts the box on its own line until you learn CSS for layout.
:::

### Challenge: A full community event page

Combine the module into one page for Code and Pizza Night:

-   A site `<header>` with the event series name and a `<nav>` of jump links to the sections below.
-   A `<main>` with an `<article>` describing the event (what, when, where), including a `<figure>` with a captioned image whose license you've checked.
-   A schedule `<table>` (6:00 Doors open, 6:15 Workshops, 7:30 Pizza and demos, 8:15 Wrap-up) with a caption and header cells.
-   Your Exercise 6 form in its own `<section>` with an `id` the menu can link to.
-   A `<footer>` with the organizer's contact link.

Check it three ways: the validator reports no errors; Chrome's **Accessibility** tab (or Firefox's **Accessibility** panel) shows the right roles for your landmarks; and every label in the form, when clicked, focuses its field.
