:::objectives
- Install Visual Studio Code (VS Code), the editor you'll write every page in.
- Add the Live Server extension so the browser reloads each time you save.
- Get Chrome or Firefox up to date, since their DevTools are your X-ray glasses for pages.
- Know the no-install fallback (CodePen) and the fixes for the setup problems beginners hit most.
:::

Right-click on almost any web page and choose **View page source**. The wall of angle brackets you see is HTML: plain text that a browser turns into headings, pictures, and buttons. By the end of Module 2 you'll be writing that text yourself, and none of it costs money. You need three free things: an editor to type the files, a browser to show them, and a small helper that refreshes the browser for you.

Plan for about 20 minutes. If you're on a school computer that blocks installs, skip to [the CodePen section](#no-installs-allowed-use-codepen) and come back later.

## How the three tools work together

| Tool | Its job | Cost |
| --- | --- | --- |
| **VS Code** | The editor where you write `.html` and `.css` files | Free, from Microsoft |
| **Live Server** | An add-on for VS Code that runs a tiny web server on your computer and reloads the page when you save | Free |
| **Chrome or Firefox** | Shows the page, and its **DevTools** let you inspect every element | Free |

```mermaid caption="The edit, save, look loop you'll repeat hundreds of times"
flowchart LR
    A["Type in VS Code"] --> B["Save (Ctrl+S)"]
    B --> C["Live Server notices"]
    C --> D["Browser reloads"]
    D --> E["Look and decide"]
    E --> A
```

You *could* double-click an `.html` file and it would open in your browser with an address starting `file://`. Two things go wrong with that. You have to press refresh after every change, and links that start with `/` point at the root of your hard drive instead of your project, so they break. Live Server gives your page a real `http://` address, the same way a hosted website works.

## Step 1: Update Chrome or Firefox

You almost certainly have a browser already. This course shows Chrome and Firefox because both have excellent developer tools. Edge works like Chrome, since it's built on the same engine. Safari works too, but its menus differ from what you'll see in the lessons.

Make sure yours is current:

-   **Chrome:** click the three-dot menu at the top right, then **Help › About Google Chrome**. It checks for updates and asks you to relaunch.
-   **Firefox:** click the menu button (three lines), then **Help › About Firefox**.

## Step 2: Install VS Code

Always download VS Code from the official site, [code.visualstudio.com](https://code.visualstudio.com/). Search ads sometimes point to look-alike sites.

:::tabs
@tab Windows
1. Go to [code.visualstudio.com](https://code.visualstudio.com/) and click the **Download for Windows** button. This gives you the **User Installer**, which doesn't need an administrator password.
2. Open `VSCodeUserSetup-….exe` from your Downloads folder and accept the license.
3. On the **Select Additional Tasks** screen, leave **Add to PATH** ticked. If you see the two **Add "Open with Code" action** boxes, tick them too: they let you right-click any folder and open it straight in VS Code.
4. Click **Install**, then **Finish** with **Launch Visual Studio Code** ticked.
@tab macOS
1. Go to [code.visualstudio.com](https://code.visualstudio.com/) and click the download button for macOS.
2. Open the file from your Downloads folder. If it's a `.zip`, double-click it to unzip; if it's a `.dmg`, double-click it to open a window with the app inside.
3. Drag **Visual Studio Code** into your **Applications** folder. Launch it from Applications, not from Downloads, so updates install properly.
4. The first time, macOS warns that the app was downloaded from the internet and asks if you want to open it. Click **Open**.
5. Optional: right-click (Control-click) its Dock icon and choose **Options › Keep in Dock**.
@tab Chromebook
VS Code runs on a Chromebook through the built-in Linux environment.

1. Select the time at the bottom right, then the **Settings** gear. Go to **About ChromeOS › Developers**, and next to **Linux development environment** select **Set up**. Accept the defaults. This can take 10 minutes or more, and a Terminal window opens when it's done.
2. In that Terminal, type `dpkg --print-architecture` and press Enter. It prints `amd64` (Intel or AMD chip) or `arm64` (ARM chip).
3. On [code.visualstudio.com/download](https://code.visualstudio.com/download), download the **.deb** file: the **x64** one for `amd64`, or **ARM64** for `arm64`.
4. Open the **Files** app, find the `.deb` in Downloads, double-click it, and choose **Install**.
5. Open your app launcher. VS Code is in the **Linux apps** folder.

If **Linux development environment** is missing from Settings, your school has turned it off. Use CodePen (below) and ask your school's IT team whether Linux can be enabled.
:::

**Success looks like this:** VS Code opens to a **Welcome** tab, with a narrow bar of icons down the left side (Explorer, Search, Source Control, Run and Debug, Extensions).

## Step 3: Add the Live Server extension

Extensions are add-ons that give VS Code new abilities. You need exactly one for now.

1.  Open the Extensions view: press **Ctrl+Shift+X** (**Cmd+Shift+X** on a Mac), or click the icon made of four squares in the bar down the left edge.
2.  Type `Live Server` in the search box.
3.  Pick the one published by **Ritwick Dey**. It has more than 80 million installs, so it's usually the first result.
4.  Click **Install**.

Nothing visible happens yet. In the next lesson you'll open a folder with an HTML file in it, and a **Go Live** button will appear in the status bar along the bottom right of VS Code.

:::note
You may also see **Live Preview** (by Microsoft) or **Five Server** in the search results. They do a similar job, but these lessons describe Live Server's buttons and menus, so stick with it for now.
:::

## No installs allowed? Use CodePen

[CodePen](https://codepen.io/) is a free website where you type HTML and CSS into panels and see the result update as you type. It works on any computer with a browser, including locked-down school Chromebooks.

-   Go to [codepen.io](https://codepen.io/) and start a new **Pen**.
-   Type HTML in the **HTML** panel and CSS in the **CSS** panel. The result appears beside them.
-   Make a free account if you want to save your Pens.

The limit: a basic Pen is a single page. When a lesson builds a project from several files and folders, read along, try the parts you can in a Pen, and build the full version when you have a computer that allows installs.

## When setup goes wrong

:::warning
**There's no Go Live button.** Live Server only shows it when you've opened a *folder* (File › Open Folder…) that contains an `.html` file. If you just installed the extension, open the Command Palette (**Ctrl+Shift+P**, or **Cmd+Shift+P** on a Mac), run **Developer: Reload Window**, and look again.
:::

**The page opens in the wrong browser.** Live Server uses your computer's default browser. Either change the default in your system settings, or in VS Code open **Settings**, search for `live server custom browser`, and choose Chrome or Firefox from the list.

**The address shows a port other than 5500.** Live Server normally uses port 5500. If another program is already using it, Live Server picks a different number. That's fine; the page works the same.

**On a Chromebook, the browser can't reach the page.** Pages served from the Linux environment are usually forwarded to Chrome automatically. If `http://127.0.0.1:5500` doesn't load, try `http://localhost:5500`, and if that fails, `http://penguin.linux.test:5500`.

**"Windows protected your PC" or a similar warning.** Check that the file came from code.visualstudio.com. If it did, it's safe to continue. If you aren't allowed to install software at all, use CodePen.
