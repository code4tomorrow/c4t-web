:::objectives
- Organize a multi-page site into folders and link every page to one stylesheet.
- Write design tokens for color, type, and spacing as custom properties, and build every rule from them.
- Reuse one header on every page and mark the current page with `aria-current`.
- Prove the site is consistent by changing one token and watching all three pages update.
:::

Riverside Robotics, the club whose navbar you built in the layout practice, wants a real website: a home page, an events page, and a sign-up page. The rule for this build is that no page gets its own styles. Every color, size, and gap comes from one file, so the three pages can't drift apart the way Lena's did.

## Step 1: Make the folders and files

In VS Code, open an empty folder called `riverside-robotics` (**File > Open Folder**). Use the **New File** and **New Folder** buttons at the top of the Explorer to make this structure:

```text
riverside-robotics/
├── index.html
├── events.html
├── join.html
└── css/
    └── styles.css
```

All names are lowercase with no spaces, so they'll work the same once the site is online. The stylesheet lives in its own folder, which keeps the main folder tidy as the site grows.

## Step 2: Write the design tokens

Open `css/styles.css`. Before writing a single selector, write down every design decision as a custom property on `:root`:

```css title="css/styles.css"
/* 1. Design tokens: every decision lives here */
:root {
  --color-text: #1e293b;
  --color-muted: #475569;
  --color-bg: #ffffff;
  --color-surface: #f1f5f9;
  --color-brand: #0f766e;
  --color-on-brand: #ffffff;

  --step-0: 1rem;
  --step-1: 1.25rem;
  --step-2: 1.563rem;
  --step-3: 1.953rem;
  --step-4: 2.441rem;

  --space-2xs: 0.25rem;
  --space-xs: 0.5rem;
  --space-s: 1rem;
  --space-m: 1.5rem;
  --space-l: 2rem;
  --space-xl: 3rem;

  --radius: 0.75rem;
  --page-width: 64rem;
}
```

The type sizes are the 1.25 scale from the notes. The spacing names (`2xs` up to `xl`) are like t-shirt sizes, so you can tell at a glance that `--space-m` is bigger than `--space-s`. From here on, the rule is simple: if you're about to type a color, a font size, or a margin, use a token instead.

The colors were checked before they went in. `--color-brand` (`#0f766e`) on white is 5.5:1, and on the grey `--color-surface` it's 5.0:1, so it's safe for links, labels, and button backgrounds. `--color-muted` text is 7.6:1 on white.

## Step 7: Test the links, then change one token

1.  Open `index.html` with Live Server. Click every link in the nav on every page. Each one should load, and the underline should move to the page you're on.
2.  If a page shows up as plain black text on white, its `<link>` path is wrong. Open DevTools and look at the **Console**: you'll see a red `404 (Not Found)` error naming the file it couldn't find.
3.  Now the payoff. In `styles.css`, change `--color-brand` from `#0f766e` to `#6d28d9` and save. Click through all three pages: links, labels, buttons, focus rings, and the current-page underline all turned purple at once. (That purple is 7.1:1 on white, so it passes too.)

That one-line change is the whole reason for tokens. A site with a hundred pages works exactly the same way.

:::quiz
Q: Why does every nav link have `border-bottom: 3px solid transparent`, even though you can't see it?
- [ ] Transparent borders improve contrast
  An invisible border has no effect on contrast.
- [x] So the current link only changes the border's color, and the text doesn't shift down when the border appears
  If only the current link had a border, it would be 3px taller than the others, and the nav would jump between pages.
- [ ] Links need a border to be focusable
  Links with an `href` are focusable on their own.

Q: You add a page at `projects/robot-arm.html`, inside a new folder. What has to change in its copy of the header and `<head>`?
- [ ] Nothing, because the header is identical on every page
  The header is identical in what it shows, but paths are relative to the file's location.
- [x] Every link and the stylesheet path need `../` in front, like `../index.html` and `../css/styles.css`
  The page is one folder deeper, so each relative path has to climb up one level first.
- [ ] Only the stylesheet path changes
  The nav links would break too: `index.html` would point to `projects/index.html`.

Q: The button's text color uses `var(--color-on-brand)` instead of writing `white`. What does that buy you?
- [ ] Nothing; `white` and a variable set to `#ffffff` always behave differently
  They give the same color today. The difference shows up when you change the design.
- [x] If the brand color ever changes to a light color, you can switch the text to dark in one place
  Every button, badge, or banner that sits on the brand color reads the same token, so they all stay readable together.
- [ ] Variables make the button load faster
  Custom properties don't change loading speed.
:::

:::takeaways
- Plan the folders first, with lowercase names and a separate `css/` folder.
- Write tokens on `:root` before any selectors, check their contrast once, and never type a raw color or size again.
- Base styles on plain elements (`body`, `h1`, `p`, `a`, `:focus-visible`) give every page the same typography for free.
- Copy one header onto every page and move only `aria-current="page"`. Style the current link with an attribute selector so what you see matches what screen readers say.
- Changing one token and clicking through every page is the fastest consistency test there is.
:::

## Ideas to extend it

- Add a fourth page in a `projects/` folder and get every path right with `../`.
- Add a "night" theme by redefining the color tokens inside `@media (prefers-color-scheme: dark)`, then check every pair for contrast.
- Add a small `.badge` component for "Free" or "New" that uses `--color-brand` and `--color-on-brand`, and put it on two event cards.
- Make a 404 page called `404.html` with the same header, for when someone types a wrong address. GitHub Pages uses it automatically.
