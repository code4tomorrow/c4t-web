:::objectives
- Open a project folder in VS Code and create `index.html`.
- Generate a page skeleton with Emmet and add your own heading and paragraph.
- Start Live Server and prove that saving reloads the browser.
- Open DevTools, find your heading in the Elements panel, and change it live.
:::

Ten minutes from now you'll have a page running at an address like `http://127.0.0.1:5500/index.html`, and you'll have changed it in two different ways: once in your file, which lasts, and once inside the browser, which vanishes the moment you refresh. Knowing the difference between those two is half of web development.

## Step 1: Make a project folder and open it

Web projects are folders, not single files. A real site is a page plus its images, stylesheets, and other pages, and they all need to sit together.

1.  Create a folder for the whole course somewhere easy to find, such as `Documents/web-course`.
2.  Inside it, create a folder called `first-page`.
3.  In VS Code, choose **File › Open Folder…** and pick `first-page`.
4.  VS Code asks whether you trust the authors of the files in this folder. It's your own folder, so choose **Yes, I trust the authors**.

The **Explorer** on the left now shows `FIRST-PAGE` in capitals with nothing under it. Hover over that name and click the **New File** icon (a page with a plus sign). Type `index.html` and press Enter.

:::tip
Why `index.html`? When a browser asks a web server for a folder instead of a specific file, the server sends back the file named `index.html` inside it. Name your home page that way from day one and every server you ever use will find it.
:::

## Step 2: Let Emmet type the skeleton

Every HTML page starts with the same dozen lines. You don't have to type them. In the empty `index.html`, type a single exclamation mark `!`. A suggestion box appears with **Emmet Abbreviation** in it. Press **Enter** (or **Tab**) and VS Code fills in a whole page skeleton.

Now change the title to `My first page` and type two lines between `<body>` and `</body>`:

```html title="index.html"
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>My first page</title>
</head>
<body>
    <h1>Hello from my first web page</h1>
    <p>I made this with VS Code, and Live Server is showing it to me.</p>
</body>
</html>
```

You'll take this skeleton apart line by line in Module 2. For today, two lines matter. `<h1>` makes the main heading, and `<p>` makes a paragraph. Each has an opening tag and a closing tag with a slash, and the text between them is what shows up.

Save with **Ctrl+S** (**Cmd+S** on a Mac). Look at the file's tab: a white dot means unsaved changes, and it turns back into an **×** when the file is saved.

Here's what the browser will draw:

```html preview height="150"
<h1>Hello from my first web page</h1>
<p>I made this with VS Code, and Live Server is showing it to me.</p>
```

## Step 3: Go Live and prove it reloads

Click **Go Live** in the status bar at the bottom right of VS Code. (Or right-click `index.html` in the Explorer and choose **Open with Live Server**.) Your browser opens a tab with an address like this:

```text
http://127.0.0.1:5500/index.html
```

`127.0.0.1` is a special address that always means "this computer". `5500` is the *port*, a numbered door that Live Server listens at. The status bar button now shows the port number instead of Go Live, and clicking it stops the server.

Now the proof. Put VS Code and the browser side by side. Change the heading text, press **Ctrl+S**, and watch the browser. It updates on its own within a second. That loop of edit, save, look is how you'll work for the rest of the course.

:::try
Add a second paragraph under the first one: `<p>My favorite food is ...</p>`. Save and check the browser. Then delete the closing `</p>` from it, save again, and see whether anything looks different. (It probably won't. The next section explains why.)
:::

## Step 4: Open DevTools and find your heading

Every desktop browser has developer tools built in. They show you what the browser *actually built* from your file, and they let you poke at it.

| To do this | Windows, Linux, ChromeOS | macOS |
| --- | --- | --- |
| Open DevTools | **F12** or **Ctrl+Shift+I** | **Cmd+Option+I** |
| Open DevTools and pick an element on the page | **Ctrl+Shift+C** | **Cmd+Option+C** |

The quickest way: right-click your heading on the page and choose **Inspect**. DevTools opens with the heading's line highlighted. In Chrome this panel is called **Elements**; in Firefox it's called **Inspector**. They work the same way.

Spend two minutes looking around:

-   The main area is a **tree**. Click the small triangles to open and close `<head>` and `<body>`. Elements inside other elements are indented under them.
-   **Hover** over any line in the tree and the matching part of the page lights up with colored boxes.
-   The **Styles** pane beside the tree shows the CSS rules affecting the selected element. You haven't written any CSS, yet your `<h1>` is big and bold. In Chrome those rules are labeled **user agent stylesheet**: the browser's own default styles.

## Step 5: Edit the page live, then refresh

In the Elements panel, double-click the text of your heading, type something new, and press Enter. The page changes instantly.

Now refresh the browser. Your edit is gone.

DevTools edits the browser's copy of the page in memory. It never touches `index.html` on your disk. That makes it a safe playground: try an idea in DevTools, and once you like it, make the same change in VS Code so it sticks.

:::try
Select the `<h1>` in the tree. In the Styles pane, click inside the box labeled `element.style { }` at the top, type `color: tomato;` and press Enter. Watch the heading change color. Refresh, and it's back to black.
:::

## The browser quietly fixes your mistakes

Here's a page that forgets to close any of its paragraphs:

```html preview height="200"
<h1>Shopping list</h1>
<p>Eggs
<p>Flour
<p>Milk
```

It still shows three neat paragraphs. Right-click "Flour" in the result and choose **Inspect**: in the tree, every `<p>` has a matching `</p>`. The browser knows a paragraph can't contain another paragraph, so it closed each one for you.

This is the most important idea in this lesson. **View page source** (**Ctrl+U**, or **Cmd+Option+U** on a Mac) shows the text you wrote. The **Elements** panel shows the structure the browser *built* from that text. When a page looks wrong, the Elements panel tells you what the browser understood, and that's usually where the bug is hiding.

:::quiz
Q: You change the heading in `index.html`, but the browser still shows the old text a minute later. What's the most likely cause?
- [x] The file isn't saved yet
  Live Server reloads when the file is saved. Look for the white dot on the tab and press Ctrl+S (Cmd+S).
- [ ] Live Server needs to be reinstalled after every change
  Once installed, it keeps working. Reinstalling won't help if the file was never saved.
- [ ] Browsers only update once an hour
  A browser shows whatever the server sends; with Live Server that happens within a second of saving.

Q: You change a heading's text in the Elements panel, then refresh the page. What do you see?
- [ ] The new text, because DevTools saved it to your file
  DevTools never writes to your files. It edits the copy of the page held in the browser's memory.
- [x] The original text from `index.html`
  Refreshing asks Live Server for the file again, and the file was never changed.
- [ ] A blank page
  Nothing was deleted from the file, so the page loads normally.

Q: Your address bar says `http://127.0.0.1:5500/index.html`. Where is the page coming from?
- [ ] A Google server that hosts test pages
  `127.0.0.1` never leaves your machine; nobody else can visit this address and see your page.
- [x] Live Server, running on your own computer
  `127.0.0.1` always means "this computer", and 5500 is the port Live Server listens on.
- [ ] The CodePen website
  CodePen pages have a `codepen.io` address.
:::

:::takeaways
- Open a folder in VS Code, not a single file, and name the home page `index.html`.
- Typing `!` and pressing Enter makes Emmet write the page skeleton.
- Save, then look: Live Server reloads the browser each time the file is saved.
- DevTools' Elements (Chrome) or Inspector (Firefox) panel shows what the browser built. Edits there are temporary.
:::
