:::objectives
- Start the capstone from a skeleton that already has the viewport tag, a skip link, focus styles, tokens, and a shared header.
- Build in six milestones, checking each one before moving on.
- Publish the site with GitHub Pages and fix the problems that usually appear on the first upload.
:::

The fastest way to get stuck on a website is to write all the HTML, all the CSS, and all the responsive rules at once, then try to figure out which part is broken. Instead, build in milestones. Each one ends with something that works and a quick check that proves it.

## The starter skeleton

Make a project folder with this structure. Use your own page names from your plan.

```text
my-site/
├── index.html
├── about.html
├── contact.html
├── planning.md
├── css/
│   └── styles.css
└── images/
```

Every page starts as a copy of this file. Change the `<title>`, move `aria-current="page"` to the right link, and fill in `<main>`.

```html title="index.html"
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Home | Your Site Name</title>
  <link rel="stylesheet" href="css/styles.css">
</head>
<body>
  <a class="skip" href="#main">Skip to main content</a>

  <header class="site-header">
    <div class="wrap header-row">
      <a class="brand" href="index.html">Your Site Name</a>
      <nav aria-label="Main">
        <ul class="nav-list">
          <li><a href="index.html" aria-current="page">Home</a></li>
          <li><a href="about.html">About</a></li>
          <li><a href="contact.html">Contact</a></li>
        </ul>
      </nav>
    </div>
  </header>

  <main id="main" class="wrap">
    <h1>Page title</h1>
    <p>Replace this with the real content from your plan.</p>
  </main>

  <footer class="site-footer">
    <div class="wrap"><p>Made by you, 2026.</p></div>
  </footer>
</body>
</html>
```

And the stylesheet. Replace the token values with the ones from your plan; everything else already reads from them.

```css title="css/styles.css"
.nav-list { display: flex; flex-wrap: wrap; gap: var(--space-xs) var(--space-m); list-style: none; margin: 0; padding: 0; }
.nav-list a { color: var(--color-muted); text-decoration: none; border-bottom: 3px solid transparent; }
.nav-list a[aria-current="page"] { color: var(--color-text); font-weight: 700; border-bottom-color: var(--color-brand); }
.site-footer { border-top: 2px solid var(--color-surface); padding: var(--space-m) 0; color: var(--color-muted); }

/* 5. Accessibility */
.skip { position: absolute; left: -999px; top: var(--space-xs); z-index: 10; padding: var(--space-xs) var(--space-s); background: var(--color-brand); color: var(--color-on-brand); }
.skip:focus { left: var(--space-xs); }
:focus-visible { outline: 3px solid var(--color-brand); outline-offset: 3px; }
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation: none !important; transition: none !important; scroll-behavior: auto !important; }
}

/* 6. Your components go here */

/* 7. Wider screens */
@media (min-width: 48rem) {
  h1 { font-size: var(--step-4); }
}
```

## The six milestones

| # | Milestone | You're done when |
| - | --------- | ---------------- |
| 1 | **Structure.** Every page's real content in semantic HTML, no new CSS. | Every page has one `<h1>`, headings go in order, every nav link opens the right page, and every image has `alt`. |
| 2 | **Tokens and base.** Your colors, type scale, and spacing in `:root`. | You squint at each page and can tell headings from body text, and every color pair in your plan passes 4.5:1. |
| 3 | **Layout.** Components and layouts with Flexbox and Grid. | At a laptop width, the page matches your desktop wireframe. |
| 4 | **Responsive.** Mobile-first rules and media queries where needed. | In the device toolbar at 320, 375, 768, 1024, and 1440px, nothing scrolls sideways or overlaps. |
| 5 | **Accessibility pass.** Skip link, focus, contrast, labels, motion. | You can use every page with only the keyboard, and the focus ring is visible on every stop. |
| 6 | **Publish.** The site online with GitHub Pages. | The live URL works on your own phone, styles and images included. |

### Milestone 1: Structure

Write each page's HTML with its real text from your plan. Resist the urge to style. A good test: with only the skeleton CSS, the page should still read well from top to bottom, because the order of the HTML *is* the order a screen reader and a phone will use.

Paste each page into the [W3C Markup Validator](https://validator.w3.org/) (the **Validate by Direct Input** tab) and fix whatever it reports, such as unclosed tags or duplicate `id`s.

### Milestone 2: Tokens and base

Fill in your token values. Look at each page and adjust: if headings feel too close in size to the body text, try a bigger scale ratio. Change values only in `:root`.

### Milestone 3: Layout

Build your components in section 6 of the stylesheet: cards, a card grid, a hero, a form layout. Most capstone sites need just three patterns: a flex row for the header (already in the skeleton), an `auto-fit` grid for repeated items, and maybe a two-column section. Build at a laptop width first, and don't worry about phones yet.

### Milestone 4: Responsive

Now shrink the window. Turn on the device toolbar and start at 320px. Fix the first thing that breaks, then widen until the next thing breaks. That point is where a media query belongs, whatever device it matches. Common fixes: swap a fixed width for `min()`, add `flex-wrap: wrap`, or move a two-column rule into a `min-width` query.

### Milestone 5: Accessibility pass

Unplug your mouse, or just don't touch it. Starting from the address bar, press Tab through every page. Check that the skip link appears first, every interactive thing is reachable, the order makes sense, and you can always see where focus is. Then re-check the contrast of anything you added after Milestone 2, and confirm every form field has a `<label>`.

### Milestone 6: Publish

The next section walks through it. Publishing earlier is fine too, so you can check the site on a real phone while you work. Each upload replaces the old files.

## Publishing on GitHub Pages

GitHub Pages hosts plain HTML and CSS sites for free. You need a GitHub account, and GitHub's terms require you to be **13 or older** to have one. If you're younger, ask a teacher or parent to publish it from their account, or present your site from your own computer with Live Server.

1.  Sign in at [github.com](https://github.com). In the upper-right corner, click **+** and choose **New repository**.
2.  Name it in lowercase with dashes, like `my-site`. Leave it **Public** (free accounts need a public repository for Pages). Turn on the option to add a README so the repository isn't empty, then click **Create repository**.
3.  On the repository's main page, open the **Add file** menu and choose **Upload files**. Open your project folder on your computer, select everything *inside* it (your HTML files and the `css` and `images` folders), and drag it onto the page. Don't drag the outer `my-site` folder itself, or your `index.html` will end up one level too deep.
4.  Type a short message like `First upload` in the commit message box. Leave the option to commit directly to the `main` branch selected, and click the green commit button.
5.  Click **Settings** at the top of the repository, then **Pages** in the left sidebar. Under **Build and deployment**, set **Source** to **Deploy from a branch**. In the branch menu choose `main`, leave the folder as `/ (root)`, and click **Save**.
6.  Wait a minute or two, then refresh the Pages settings page. When the site is ready, the page shows its address and a **Visit site** button. It can take up to 10 minutes the first time.

Your address will be `https://your-username.github.io/my-site/`. Open it on your phone. To update the site later, upload the changed files the same way; files with the same name replace the old ones.

## When the live site doesn't look right

| What you see | Likely cause | Fix |
| ------------ | ------------ | --- |
| A GitHub 404 page at your address | `index.html` isn't at the top level, or it's named `Index.html` | Make sure `index.html` (all lowercase) sits next to the `css` folder in the repository, not inside another folder |
| The page loads as plain black text | The stylesheet path is wrong online | Check the capitalization of `css/styles.css` exactly, and remove any leading `/` from the `href` |
| Some images are broken | A capitalization mismatch, often `.JPG` versus `.jpg` | Rename the file or fix the `src` so they match letter for letter |
| A page works locally but 404s online | The link uses different capitals than the file name, or the file wasn't uploaded | Compare the link and the file name in the repository |
| Your changes don't show up | Pages hasn't rebuilt yet, or the browser cached the old file | Wait a few minutes, then reload with **Ctrl+Shift+R** (**Cmd+Shift+R** on a Mac) |

:::warning
**Live Server hides path mistakes.** On Windows and macOS, Live Server will happily load `Styles.css` when you asked for `styles.css`. GitHub Pages won't. If something works on your laptop and breaks online, capitalization is the first suspect.
:::
