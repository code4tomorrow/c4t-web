title: Build a two-page personal profile site
summary: Build a profile page with a photo, a heading outline, jump links, outside links, and a second page in a subfolder that links back.
---

:::objectives
- Set up a project with `images/` and `pages/` folders and name files safely.
- Write a full page: skeleton, one `<h1>`, sections with `<h2>` and `<h3>`, and paragraphs.
- Add an image with useful `alt` text, and decide when `alt` should be empty.
- Link to another site, to a spot on the same page, and to a second page using `../`.
- Check every path with Live Server and the Network panel.
:::

Two notes about these result frames. They can't see your computer, so the photo uses a full web address instead of `images/red-panda.jpg`. And clicking links inside them won't go anywhere useful. Test your links in your own copy with Live Server.

This is your page, so swap in your own details as you go. You don't need your full name, school, or a photo of yourself: a nickname and a picture of something you like are perfect.

## Step 1: Set up the folders and the photo

Inside your `web-course` folder, make this structure. Create the folders in your file manager or with the **New Folder** icon in VS Code's Explorer.

```text
profile/
├── index.html
├── images/
│   └── red-panda.jpg
└── pages/
    └── favorites.html
```

For the photo, use a picture you took or drew, or download the red panda from [its Wikimedia Commons page](https://commons.wikimedia.org/wiki/File:Red_Panda_%2824986761703%29.jpg) (Mathias Appel, CC0, free to use). Save it into `images/` and rename it to `red-panda.jpg`: lowercase, hyphen, real extension.

Then open the `profile` folder in VS Code (**File › Open Folder…**). Leave `favorites.html` for Step 7.

## Step 2: Skeleton and title

In `index.html`, type `!` and press Enter. Change the title, because it's what shows on the browser tab and in bookmarks:

```html title="index.html"
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Jordan's profile</title>
</head>
<body>

</body>
</html>
```

Click **Go Live**. You'll see a blank page with "Jordan's profile" on the tab. Blank is correct: nothing is in `<body>` yet.

## Step 3: The main heading and an introduction

Everything from here goes between `<body>` and `</body>`.

```html
<h1>Hi, I'm Jordan</h1>
<p>I'm in ninth grade, I draw comics, and I'm learning to build websites from scratch. <strong>This is the first page I've written by hand.</strong></p>
```

`<strong>` marks text as important, and browsers show it in bold. Later you'll meet `<em>`, which marks stress (the way your voice leans on a word), shown in italics. Pick them for meaning, not for looks: if you only want bold for decoration, that's a CSS job.

## Step 4: Add the photo

```html
<img src="images/red-panda.jpg" alt="A red panda sitting on a mossy branch, looking straight at the camera" width="330" height="219">
<p>My favorite animal, and the mascot I'd pick for this site.</p>
```

Save and look. If you see a broken-image icon with your alt text next to it, the path or file name is off. Compare them letter by letter: `Red-Panda.JPG` is not `red-panda.jpg`.

The `width` and `height` match the photo's shape (330 by 219 pixels). If your own picture has a different shape, open it in your computer's photo viewer to read its size, then scale both numbers by the same amount so it isn't squashed.

## Step 5: Give the page an outline

Sections make a long page easy to skim. Each `<h2>` gets an `id`, a name that's unique on this page, so that links can jump to it in the next step.

```html
<h2 id="learning">What I'm learning</h2>
<p>HTML first, then CSS. My goal is a site for my comics by the end of the year.</p>

<h2 id="likes">Things I like</h2>
<h3>Books</h3>
<p><em>Hatchet</em> by Gary Paulsen. I read it twice in one week.</p>
<h3>Games</h3>
<p>Anything with a level editor, because building the levels is the fun part.</p>
```

Here's the outline that code produces. Notice that "Books" and "Games" are `<h3>` because they live *inside* "Things I like":

```text
h1  Hi, I'm Jordan
    h2  What I'm learning
    h2  Things I like
        h3  Books
        h3  Games
    h2  Sites I learn from
```

## Step 6: Three kinds of links

**Jump links** to sections on the same page. Put this line right after the photo's caption:

```html
<p>Jump to: <a href="#learning">What I'm learning</a> | <a href="#likes">Things I like</a> | <a href="#sites">Sites I learn from</a></p>
```

The `#` means "an `id` on this page". Click one in your browser and the page scrolls to that heading.

**Links to other websites** need the full address, including `https://`:

```html
<h2 id="sites">Sites I learn from</h2>
<p><a href="https://developer.mozilla.org/en-US/">MDN Web Docs</a>, for looking up any tag.</p>
<p><a href="https://www.youtube.com/@KevinPowell">Kevin Powell on YouTube</a>, for CSS videos.</p>
```

**A link to your second page** uses a relative path. Add this at the end of the "Things I like" section:

```html
<p>There's more on my <a href="pages/favorites.html">favorites page</a>.</p>
```

Click it now and you'll get a 404 page from Live Server, because `favorites.html` doesn't exist yet. That's the next step.

:::tip
Write link text that makes sense on its own, like "favorites page" or "MDN Web Docs". Avoid "click here": screen reader users often pull up a list of every link on a page, and a list of ten "click here"s tells them nothing.
:::

## Step 7: A second page inside `pages/`

In the Explorer, right-click the `pages` folder, choose **New File…**, and name it `favorites.html`. Give it the skeleton, then this body:

```html title="pages/favorites.html"
<p><a href="../index.html">← Back to my profile</a></p>
<h1>My favorite things</h1>
<img src="../images/red-panda.jpg" alt="" width="99" height="66">

<h2>Snack</h2>
<p>Apple slices with peanut butter.</p>
<h2>Place</h2>
<p>The library's back corner, next to the graphic novels.</p>
<h2>Song to code to</h2>
<p>Anything without lyrics, so I can think.</p>
```

Both paths start with `../` because this file sits inside `pages/`. To reach `index.html` or the `images` folder, the browser first has to climb up one level to `profile/`.

The small panda here has `alt=""`. It's the same picture as on the home page, but on this page it's only decoration: it adds nothing a visitor would miss. Empty alt tells screen readers to skip it. Leaving `alt` out entirely is different, and worse, because some screen readers then read out the file name.

The `←` arrow is a normal character you can paste in. It displays correctly because of `<meta charset="UTF-8">`.

## Step 8: Test it the way a visitor would

1.  In the browser, click every link on both pages, including **Back to my profile**.
2.  Open DevTools, go to the **Network** tab, and refresh each page. Every page and image should show status `200`. A red `404` row names the file the browser couldn't find. (Live Server adds one row of its own for auto-reload; ignore it.)
3.  Paste each file into the [W3C validator](https://validator.w3.org/#validate_by_input) and fix anything it reports.

:::quiz
Q: Why does `favorites.html` use `../images/red-panda.jpg` while `index.html` uses `images/red-panda.jpg`?
- [ ] Because the second page should load a different copy of the photo
  It's the same file. Only the starting point of the path is different.
- [x] Because `favorites.html` sits inside `pages/`, so the path must climb up one folder first
  Relative paths start from the current file's folder. From `pages/`, `../` reaches `profile/`, where `images/` lives.
- [ ] Because `../` makes images load faster
  `../` only changes which folder the browser looks in.

Q: Why are "Books" and "Games" `<h3>` instead of `<h2>`?
- [ ] Because `<h3>` text is the right size for them
  Size is never the reason to pick a level. CSS can make any heading any size.
- [x] Because they're subsections inside "Things I like"
  Heading levels describe the outline. Subsections of an `<h2>` section get `<h3>`.
- [ ] Because a page can only have two `<h2>` headings
  A page can have as many `<h2>`s as it has main sections.

Q: The panda on the favorites page has `alt=""`. When is that the right choice?
- [ ] Always, because alt text is optional
  Images that carry information need real alt text, or screen reader users miss it.
- [x] When the image is decoration and a visitor loses nothing by skipping it
  Empty alt tells screen readers to skip the image. Here the same photo was already described on the home page.
- [ ] When you don't know what the image shows
  Then find out. Every image you publish is your responsibility to describe or mark as decoration.
:::

:::takeaways
- Build the folders first (`images/`, `pages/`), with lowercase, hyphenated file names.
- One `<h1>`, then `<h2>` for sections and `<h3>` for subsections, chosen by outline, not size.
- `href="#id"` jumps within a page, a full `https://` address leaves your site, and a relative path reaches your own files.
- Inside a subfolder, paths to the top-level files start with `../`.
- Test every link, and use the Network panel to catch 404s.
:::

## Ideas to extend it

-   Add a third page, `pages/projects.html`, and link all three pages to each other. Check every path from every page.
-   Add an `<h3>` under "What I'm learning" for each topic you've finished, with a sentence about what was hardest.
-   Add a second image to the favorites page that *does* carry information (a drawing you made, say) and write its alt text.
