Hand `LogisticRegression` a single blank cell and it crashes. Hand it the word `"north"` and it crashes again. Real data arrives with both, plus columns measured in units that differ by a factor of a thousand. This week you fix all three problems, and you learn the one rule that keeps the fixes honest:

**Every preparation step learns from the training set only.**

That rule sounds fussy. By the end of this page you'll see it turn a model that "scores 73%" on pure noise back into the coin flip it really is.

## A messy dataset to practice on

The bundled datasets are clean, so we'll dirty one on purpose: blank out some measurements and add a text column naming the clinic each scan came from. Run the cells on this page in order in one notebook.

```python run
import numpy as np
import pandas as pd
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split

df = load_breast_cancer(as_frame=True).frame
df = df[["mean radius", "mean texture", "mean smoothness", "target"]].copy()

rng = np.random.default_rng(0)
df.loc[rng.choice(len(df), 40, replace=False), "mean texture"] = np.nan
df.loc[rng.choice(len(df), 15, replace=False), "mean smoothness"] = np.nan
df["clinic"] = rng.choice(["north", "south", "east"], size=len(df))
df.loc[rng.choice(len(df), 10, replace=False), "clinic"] = np.nan

print(df.isna().sum())
print("Rows with no blanks:", len(df.dropna()), "of", len(df))

num_cols = ["mean radius", "mean texture", "mean smoothness"]
X = df.drop(columns="target")
y = df["target"]
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=0
)
```

`df.isna().sum()` counts blanks per column; make it the first thing you run on any new dataset. Notice the order: we **split before fixing anything**. That ordering is the whole point of this week.

Here's what happens if you skip preparation:

```python run raises
from sklearn.linear_model import LogisticRegression

LogisticRegression().fit(X_train[num_cols], y_train)
```

The error message even names the two standard fixes: impute, or drop the rows. Let's weigh them.

## Drop the rows, or fill the blanks?

`df.dropna()` would delete 63 of 569 rows, about 11% of the data, to fix blanks in three columns. Dropping is fine when very few rows are affected *and* the blanks happen at random. It's risky when they don't. If one clinic's scanner often fails to record texture, dropping those rows quietly removes that clinic's patients, and the model learns less about exactly the people it'll later see.

Filling, called **imputing**, keeps every row. Here's the intuition: replace each blank with a typical value for that column. Now the precise version, and the most important pattern in scikit-learn:

- **`fit`** learns something from data (here, each column's median) and stores it in an attribute ending in `_`.
- **`transform`** applies what was learned to any data, including rows it has never seen.

```python run
from sklearn.impute import SimpleImputer

num_imputer = SimpleImputer(strategy="median")
num_imputer.fit(X_train[num_cols])                 # learn medians from TRAIN only
print("Medians learned from train:", num_imputer.statistics_.round(3))

test_filled = num_imputer.transform(X_test[num_cols])
print("Blanks left in test:", int(np.isnan(test_filled).sum()))

cat_imputer = SimpleImputer(strategy="most_frequent").fit(X_train[["clinic"]])
print("Most common clinic in train:", cat_imputer.statistics_)
```

Test blanks get the **training** median. That mirrors real life: when a new patient arrives tomorrow, all you have is what you learned from past patients.

Pick the strategy by the column: `"median"` for numbers (safer than `"mean"` when outliers pull the average), `"most_frequent"` for categories, and `"constant"` with `fill_value=` for a fixed placeholder like `"unknown"`.

## Turning categories into numbers

Models need numbers. Replacing `north / south / east` with `0 / 1 / 2` invents an order that doesn't exist: is east "twice" south? **One-hot encoding** gives each category its own 0/1 column instead:

```python run
from sklearn.preprocessing import OneHotEncoder

encoder = OneHotEncoder(handle_unknown="ignore", sparse_output=False)
encoder.fit(pd.DataFrame({"clinic": ["north", "east", "south", "east"]}))
print(encoder.get_feature_names_out())
print(encoder.transform(pd.DataFrame({"clinic": ["south", "west"]})))
```

`south` becomes `[0, 0, 1]`. `west` never appeared during `fit`, so with `handle_unknown="ignore"` it becomes all zeros instead of crashing. Always set this: sooner or later, a category will turn up at prediction time that training never saw. (`sparse_output=False` only makes the output printable; inside a pipeline you can leave it out.)

## Scaling: putting features on the same ruler

`mean radius` is around 14, `mean texture` around 19, and `mean smoothness` around 0.1. To a model that measures distances, a change of 1 in radius looks a hundred times bigger than the whole range of smoothness. `StandardScaler` fixes that by subtracting each column's training mean and dividing by its training standard deviation, so every feature ends up centered on 0 with a spread of 1:

```python run alt="Two box plots side by side. Before scaling, mean radius and mean texture sit between about 7 and 40 while mean smoothness is a flat line near 0.1. After scaling, all three features are centered on 0 with similar spreads." caption="Before scaling, smoothness is invisible next to the other two. After scaling, all three count equally."
import matplotlib.pyplot as plt
from sklearn.preprocessing import StandardScaler

filled = pd.DataFrame(num_imputer.transform(X_train[num_cols]), columns=num_cols)
scaled = StandardScaler().fit_transform(filled)

fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(7.5, 3.2))
box_style = dict(patch_artist=True, boxprops=dict(facecolor="#a9c9f0", color="#2a78d6"),
                 medianprops=dict(color="#0b0b0b"), flierprops=dict(markersize=3))
ax1.boxplot(filled.to_numpy(), **box_style)
ax1.set_title("before: raw units")
ax2.boxplot(scaled, **box_style)
ax2.set_title("after StandardScaler")
for ax in (ax1, ax2):
    ax.set_xticks([1, 2, 3], ["radius", "texture", "smoothness"])
    ax.spines[["top", "right"]].set_visible(False)
plt.tight_layout()
plt.show()
print("scaled means:", scaled.mean(axis=0).round(2), " scaled stds:", scaled.std(axis=0).round(2))
```

Scaling matters for models that compare distances or weigh features against each other: k-NN, logistic regression, support vector machines, neural networks. Decision trees and random forests split on one feature at a time, so scale doesn't change them. (A printed `-0.0` is just a rounding artifact.)

## One object for the whole recipe: ColumnTransformer + Pipeline

Different columns need different steps. `ColumnTransformer` routes each group of columns to its own steps, and `Pipeline` chains the preparation with the model:

```mermaid caption="The pipeline: one fit call learns every step from training rows"
flowchart LR
    R["Raw rows"] --> CT{"ColumnTransformer"}
    CT -->|"3 numeric columns"| N1["Impute median"] --> N2["Scale"]
    CT -->|"clinic"| C1["Impute most frequent"] --> C2["One-hot"]
    N2 --> J["6 clean columns"]
    C2 --> J
    J --> M["LogisticRegression"]
```

```python run
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline

numeric = Pipeline([
    ("impute", SimpleImputer(strategy="median")),
    ("scale", StandardScaler()),
])
categorical = Pipeline([
    ("impute", SimpleImputer(strategy="most_frequent")),
    ("onehot", OneHotEncoder(handle_unknown="ignore")),
])
preprocess = ColumnTransformer([
    ("num", numeric, num_cols),
    ("cat", categorical, ["clinic"]),
])
model = Pipeline([("prep", preprocess), ("clf", LogisticRegression())])

model.fit(X_train, y_train)
print("Test accuracy:", round(model.score(X_test, y_test), 3))
print(model.named_steps["prep"].get_feature_names_out())
```

One `model.fit(X_train, y_train)` call fits every imputer, scaler, and encoder on training rows, then trains the classifier on the result. One `model.score(X_test, y_test)` call *transforms* the test rows with what was learned and predicts. You can't accidentally fit on test data, because there's no place in this code where that could happen.

## Leakage: when the test set sneaks into training

**Data leakage** means information from the test rows influences training, so your test score beats what real life will give you. Here's the most dramatic version. The data below is pure noise: random features, random labels. The honest accuracy of *any* model is a coin flip.

```python run alt="Bar chart comparing two test accuracies on pure-noise data. The leaky workflow reports 0.733. The correct pipeline reports 0.55, close to the dashed 0.5 line marking a coin flip." caption="Same noise, same model. Selecting features before the split invents 23 points of fake accuracy."
from sklearn.feature_selection import SelectKBest, f_classif
from sklearn.pipeline import make_pipeline

rng = np.random.default_rng(1)
X_noise = rng.normal(size=(200, 5000))   # 5,000 random features
y_noise = rng.integers(0, 2, size=200)   # random labels

# LEAKY: pick the 20 "best" features using ALL rows, then split
X_sel = SelectKBest(f_classif, k=20).fit_transform(X_noise, y_noise)
Xa, Xb, ya, yb = train_test_split(X_sel, y_noise, test_size=0.3, random_state=0)
leaky = LogisticRegression().fit(Xa, ya).score(Xb, yb)

# CORRECT: split first, and let a pipeline select features on train only
Xa, Xb, ya, yb = train_test_split(X_noise, y_noise, test_size=0.3, random_state=0)
honest = make_pipeline(SelectKBest(f_classif, k=20), LogisticRegression()).fit(Xa, ya).score(Xb, yb)
print(f"Leaky: {leaky:.3f}   Correct: {honest:.3f}")

fig, ax = plt.subplots(figsize=(5, 2.6))
bars = ax.bar(["select, then split\n(leaky)", "split, then pipeline\n(correct)"], [leaky, honest],
              color=["#eb6834", "#2a78d6"], width=0.5)
ax.bar_label(bars, fmt="%.3f", fontsize=9)
ax.axhline(0.5, color="#52514e", linestyle="--", linewidth=1)
ax.text(1.32, 0.51, "coin flip", fontsize=8, color="#52514e")
ax.set_ylim(0, 1)
ax.set_ylabel("test accuracy")
ax.spines[["top", "right"]].set_visible(False)
plt.show()
```

Nothing real can be learned here, yet the leaky version reports 73%. Out of 5,000 noise columns, a few line up with the labels by pure chance, **including on the test rows**, and selecting on all 200 rows finds exactly those. The pipeline selects using training rows only and lands near 50%, the truth. (`make_pipeline` is a shortcut that names the steps for you.)

Fitting a scaler or imputer on all rows leaks the same way, just less dramatically. The fix never changes: **split first, and put every fitted step inside the pipeline.**

:::warning
`StandardScaler().fit_transform(X)` on your full dataset, before `train_test_split`, is the most common leak in student projects. Whenever you see `fit` or `fit_transform` called on anything other than training data, stop and move that step into the pipeline.
:::

:::quiz
Q: A teammate runs `X = StandardScaler().fit_transform(X)` and then `train_test_split`. Their test score looks fine. What's the problem?
- [ ] None: scaling doesn't change labels, so it can't leak
  Leakage isn't about labels. The test rows helped set the mean and standard deviation the model trains with.
- [x] The test rows influenced the scaler, so the test score isn't fully honest
  Any `fit` that sees test rows leaks. Put the scaler in a pipeline and fit it after the split.
- [ ] Scaling must always come after the model
  Scaling prepares the features, so it always comes before the model.

Q: Which of these models gives the same predictions whether or not you scale the features?
- [ ] k-nearest neighbors
  k-NN measures distances, so a feature with big numbers dominates unless you scale.
- [ ] Logistic regression
  Its regularization treats feature weights together, so scaling can change the fitted model.
- [x] A decision tree
  A tree splits one feature at a time on a threshold. Rescaling moves the threshold but not which rows go where.

Q: An `income` column has a few huge values and 5% blanks. Which imputer strategy fits best?
- [ ] `"mean"`
  A few huge incomes drag the mean far above what a typical person earns.
- [x] `"median"`
  The median ignores how extreme the outliers are, so it fills blanks with a typical value.
- [ ] `"most_frequent"`
  For a continuous number nearly every value is unique, so "most frequent" is close to arbitrary.

Q: A new scan arrives from a clinic called `"west"`, which never appeared in training. With `OneHotEncoder(handle_unknown="ignore")`, what happens?
- [ ] `predict` raises a `ValueError`
  That's what happens with the default `handle_unknown="error"`.
- [x] All three clinic columns are 0 for that row, and prediction continues
  The row simply doesn't match any known clinic, and the model relies on the other features.
- [ ] The encoder adds a new `clinic_west` column
  An encoder's columns are fixed at `fit` time. Adding one would break the trained model.
:::

:::takeaways
- Split first. Every preprocessor `fit`s on training rows only and `transform`s everything else.
- `SimpleImputer` fills blanks: median for skewed numbers, most frequent for categories.
- `OneHotEncoder(handle_unknown="ignore")` turns categories into 0/1 columns without crashing on new ones.
- `StandardScaler` matters for distance- and weight-based models, not for trees.
- A `ColumnTransformer` inside a `Pipeline` makes leakage impossible by construction, and leakage can turn pure noise into a convincing score.
:::
