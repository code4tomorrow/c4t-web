title: Comparing and tuning models
summary: Compare decision trees, random forests, and logistic regression on identical folds, then tune their hyperparameters with GridSearchCV and RandomizedSearchCV without spending your test set.

"My random forest got 97% and my logistic regression got 96%, so the forest wins." Before you believe a claim like that, ask three questions. Were both models scored on the same rows? Was the preprocessing fit separately inside each fold? Is a one-point gap bigger than the noise? This week is about making comparisons that hold up when someone asks those questions.

## The three model families

-   **Decision tree:** a flowchart of yes/no questions on features. Easy to explain, needs no scaling, and overfits readily (you saw this last week).
-   **Random forest:** hundreds of trees, each trained on a random resample of the rows and considering a random subset of features at each split. Averaging their votes cancels much of the individual trees' variance. It needs no scaling and is usually strong right out of the box.
-   **Logistic regression:** a weighted sum of features pushed through a sigmoid. It's fast, gives well-behaved probabilities, and its coefficients are interpretable. It *does* need scaled features, and it can only draw straight-line (linear) boundaries unless you engineer features.

None of these is always best. You find out by testing them on your data.

## Rules for a fair comparison

1.  **Same folds.** Create one `StratifiedKFold` object with a fixed `random_state` and pass it to every model.
2.  **Everything inside a pipeline.** Scaling, imputing, and encoding are refit in each fold for every model.
3.  **Same metric**, chosen before you look at results.
4.  **Include the baseline**, so you know what "good" means on this dataset.

```python
from sklearn.datasets import load_breast_cancer
from sklearn.dummy import DummyClassifier
from sklearn.ensemble import RandomForestClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import StratifiedKFold, cross_val_score
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.tree import DecisionTreeClassifier

X, y = load_breast_cancer(return_X_y=True)
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=7)

models = {
    "baseline": DummyClassifier(strategy="most_frequent"),
    "logistic": Pipeline([("scale", StandardScaler()),
                          ("model", LogisticRegression(max_iter=1000))]),
    "tree":     Pipeline([("model", DecisionTreeClassifier(random_state=0))]),
    "forest":   Pipeline([("model", RandomForestClassifier(random_state=0))]),
}

fold_scores = {}
for name, model in models.items():
    s = cross_val_score(model, X, y, cv=cv, scoring="roc_auc")
    fold_scores[name] = s
    print(f"{name:>8}: {s.mean():.3f} ± {s.std():.3f}   folds {s.round(3)}")

wins = (fold_scores["logistic"] > fold_scores["forest"]).sum()
print(f"Logistic beats forest on {wins} of 5 folds")
```

```text
baseline: 0.500 ± 0.000   folds [0.5 0.5 0.5 0.5 0.5]
logistic: 0.995 ± 0.005   folds [0.998 1.    0.99  0.987 1.   ]
    tree: 0.914 ± 0.028   folds [0.928 0.946 0.885 0.877 0.936]
  forest: 0.987 ± 0.010   folds [0.981 0.999 0.981 0.976 1.   ]
Logistic beats forest on 4 of 5 folds
```

ROC AUC measures how well a model *ranks* positives above negatives across every possible threshold. 0.5 is random guessing and 1.0 is perfect ranking. It's a good metric for comparing models, and you'll choose a specific threshold separately.

Because every model saw identical folds, you can compare them **fold by fold**. Logistic regression beats the forest on 4 of 5 folds, which is stronger evidence than comparing two means. The tree is clearly behind. Every model is wrapped in a `Pipeline` with a step named `"model"`, even the ones with no preprocessing. That consistent naming pays off when you tune.

## Hyperparameters vs. parameters

**Parameters** are learned from data: a tree's split points, logistic regression's coefficients. **Hyperparameters** are settings you choose before training: `max_depth`, `n_estimators`, `C`. Tuning means searching for hyperparameters that give the best *cross-validated* score.

## Grid search

`GridSearchCV` tries every combination in a grid and cross-validates each one. Inside a pipeline, you name a hyperparameter as `step name` + two underscores + `parameter name`, so `model__C` means "the `C` of the step called `model`."

```python
from sklearn.datasets import load_breast_cancer
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import GridSearchCV, StratifiedKFold, train_test_split
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_breast_cancer(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=0)
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=7)

pipe = Pipeline([("scale", StandardScaler()),
                 ("model", LogisticRegression(max_iter=5000))])
param_grid = {"model__C": [0.01, 0.1, 1, 10, 100]}

search = GridSearchCV(pipe, param_grid, cv=cv, scoring="roc_auc")
search.fit(X_train, y_train)

for c, m, s in zip(param_grid["model__C"],
                   search.cv_results_["mean_test_score"],
                   search.cv_results_["std_test_score"]):
    print(f"C={c:<6} AUC {m:.4f} ± {s:.4f}")
print("Best params:", search.best_params_)
print(f"Best CV AUC: {search.best_score_:.4f}")
print(f"Test AUC (once): {search.score(X_test, y_test):.4f}")
```

```text
C=0.01   AUC 0.9931 ± 0.0055
C=0.1    AUC 0.9963 ± 0.0036
C=1      AUC 0.9963 ± 0.0036
C=10     AUC 0.9903 ± 0.0086
C=100    AUC 0.9856 ± 0.0093
Best params: {'model__C': 0.1}
Best CV AUC: 0.9963
Test AUC (once): 0.9940
```

After the search, `refit=True` (the default) retrains the best pipeline on all of `X_train`, so `search` itself becomes your final model. `cv_results_` holds the full results table. Load it into a pandas DataFrame to sort and inspect it. Notice that C = 0.1 and C = 1 tie. The search picks the first one listed, and the differences between most of these settings are well inside one standard deviation.

:::warning
Writing `{"C": [...]}` for a pipeline raises `ValueError: Invalid parameter 'C' for estimator Pipeline(...)`. The pipeline doesn't have a `C`; its `model` step does. Run `pipe.get_params().keys()` to list every valid name.
:::

## Random search

A grid grows quickly. Four hyperparameters with five values each is 625 combinations, and at 5 folds each that's 3,125 fits. `RandomizedSearchCV` samples a fixed number of combinations (`n_iter`) from lists or distributions. Random search usually finds a near-best setting in a fraction of the fits, because typically only one or two hyperparameters really matter, and random sampling tries many distinct values of each one.

```python
from scipy.stats import randint
from sklearn.datasets import load_breast_cancer
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import RandomizedSearchCV, StratifiedKFold, train_test_split

X, y = load_breast_cancer(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=0)
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=7)

param_dist = {
    "n_estimators": randint(50, 200),
    "max_depth": [None, 4, 6, 8, 12],
    "min_samples_leaf": randint(1, 10),
    "max_features": ["sqrt", 0.5, 1.0],
}
search = RandomizedSearchCV(RandomForestClassifier(random_state=0), param_dist,
                            n_iter=10, cv=cv, scoring="roc_auc",
                            random_state=0, n_jobs=-1)
search.fit(X_train, y_train)
print("Best params:", search.best_params_)
print(f"Best CV AUC: {search.best_score_:.4f}")
print("Fits run:", 10 * 5, "+ 1 refit")
```

```text
Best params: {'max_depth': 8, 'max_features': 'sqrt', 'min_samples_leaf': 2, 'n_estimators': 79}
Best CV AUC: 0.9944
Fits run: 50 + 1 refit
```

`randint(50, 200)` samples whole numbers from 50 to 199. For a hyperparameter like `C` that spans orders of magnitude, use `scipy.stats.loguniform(1e-3, 1e2)` so that 0.001–0.01 gets as many samples as 10–100. `n_jobs=-1` uses every CPU core. Expect this search to take 10–30 seconds in Colab.

## Why `best_score_` is a little optimistic

Every search reports the highest cross-validated score it found. If you try 10 settings, one of them will look good partly by luck. Picking the maximum of several noisy numbers biases the result upward. Two defenses:

-   **The test set, used once.** It played no part in the search, so it gives an unbiased check on the final choice. The 0.9940 above is the number to report.
-   **Nested cross-validation.** Put the whole search inside an outer CV loop. The inner loop tunes, and the outer folds score the tuned model on data the search never saw:

```python
from sklearn.datasets import load_breast_cancer
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import GridSearchCV, StratifiedKFold, cross_val_score
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_breast_cancer(return_X_y=True)
inner = StratifiedKFold(n_splits=3, shuffle=True, random_state=1)
outer = StratifiedKFold(n_splits=5, shuffle=True, random_state=2)

pipe = Pipeline([("scale", StandardScaler()),
                 ("model", LogisticRegression(max_iter=5000))])
search = GridSearchCV(pipe, {"model__C": [0.01, 0.1, 1, 10, 100]},
                      cv=inner, scoring="roc_auc")

nested = cross_val_score(search, X, y, cv=outer, scoring="roc_auc")
print(f"Nested CV AUC: {nested.mean():.4f} ± {nested.std():.4f}")
```

```text
Nested CV AUC: 0.9961 ± 0.0052
```

Nested CV estimates how well *the whole procedure* (search plus refit) works. It doesn't produce one final model. On small datasets where a test set would be tiny, it's the most honest number you can give.
