A classmate tells you their tumor classifier is 63% accurate. Is that good? On the breast cancer dataset that ships with scikit-learn, a "model" that ignores every measurement and always answers *benign* also scores about 63%. Their model might have learned nothing at all.

That's the question this week trains you to ask about every number: **compared to what?** A score means something only when it was measured on data the model never saw, and only next to the score you'd get with no learning at all.

## Five steps you'll repeat all term

You trained a model before this class. Here's that process written as five steps, each with one job:

```mermaid caption="The supervised learning workflow. The test set touches nothing until step 4."
flowchart LR
    A["1. Load X and y"] --> B["2. Split"]
    B -->|"train rows"| C["3. Fit"]
    B -->|"test rows, sealed"| D["4. Predict"]
    C --> D
    D --> E["5. Evaluate vs a baseline"]
```

Here are the five steps on the breast cancer data: 569 tumors, 30 measurements each, labeled `0` (malignant) or `1` (benign).

```python run
from sklearn.datasets import load_breast_cancer
from sklearn.metrics import accuracy_score
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

# 1. Load: X holds the features, y holds the answers
X, y = load_breast_cancer(return_X_y=True, as_frame=True)
print("Rows, features:", X.shape)

# 2. Split: hold back 25% of rows as the test set
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=42
)

# 3. Fit on the training rows only
model = DecisionTreeClassifier(max_depth=3, random_state=42)
model.fit(X_train, y_train)

# 4. Predict on rows the model has never seen
y_pred = model.predict(X_test)
print("First 10 predictions:", y_pred[:10])
print("First 10 true labels:", y_test.to_numpy()[:10])

# 5. Evaluate
print("Train accuracy:", round(model.score(X_train, y_train), 3))
print("Test accuracy: ", round(accuracy_score(y_test, y_pred), 3))
```

Compare the two rows of ten labels: the tree gets two of them wrong. Training accuracy comes out higher than test accuracy, which is normal, because the model has already seen the training rows. Only the test number estimates how the model will do on the next patient.

`model.score(X, y)` is a shortcut: for a classifier it computes exactly `accuracy_score(y, model.predict(X))`.

## The test set is a sealed exam

Here's the intuition. Scoring a model on its own training rows is like grading a student with the exact questions they studied: a perfect memorizer gets 100% and learns nothing about new questions. A decision tree with no depth limit is a perfect memorizer. Watch:

```python run
deep = DecisionTreeClassifier(random_state=42).fit(X_train, y_train)
print("Depth reached:", deep.get_depth(), "| leaves:", deep.get_n_leaves())
print("Train accuracy:", round(deep.score(X_train, y_train), 3))
print("Test accuracy: ", round(deep.score(X_test, y_test), 3))
```

The unlimited tree grows until every training row sits in a leaf with its own label, so training accuracy is a flawless 1.0. On the test rows it does *worse* than the depth-3 tree. If you had only looked at training accuracy, you'd have picked the wrong model.

Now the precise version. The test set is a stand-in for the future, and it stays honest only if nothing about it influences the model:

- **Fit nothing on it.** Not the model, and (from Week 2) not the scaler or imputer either.
- **Don't tune against it.** If you keep adjusting the model until the test score looks good, the test set has quietly become training data. Week 4's cross-validation lets you compare choices without spending it.

The three `train_test_split` arguments you'll use every time:

- `test_size=0.25` holds out 25% of rows. Between 0.2 and 0.3 is typical for small datasets.
- `random_state=42` fixes the shuffle so the split is identical on every run and every computer. The number itself means nothing.
- `stratify=y` keeps the class proportions the same in both halves. It deserves its own section.

## Stratify: a fair split, every time

`train_test_split` shuffles rows randomly. With a small test set, luck can hand it noticeably more or fewer of one class than the full dataset has. Let's measure how much, using 20 different seeds and a 10% test set (57 tumors):

```python run alt="Strip chart of the share of benign tumors in 20 test sets. Plain random splits scatter from about 0.53 to 0.79. All 20 stratified splits land on the same point, 0.632, beside the dashed line marking the full dataset's rate of 0.627." caption="Plain splits drift by luck; stratified splits match the full dataset every time."
import matplotlib.pyplot as plt

plain, strat = [], []
for seed in range(20):
    *_, y_te = train_test_split(X, y, test_size=0.1, random_state=seed)
    *_, y_te_s = train_test_split(X, y, test_size=0.1, random_state=seed, stratify=y)
    plain.append(y_te.mean())
    strat.append(y_te_s.mean())

print(f"plain:      {min(plain):.3f} to {max(plain):.3f}")
print(f"stratified: {min(strat):.3f} to {max(strat):.3f}")

fig, ax = plt.subplots(figsize=(6.4, 2.6))
ax.scatter(plain, [1] * 20, s=40, color="#eb6834", alpha=0.75)
ax.scatter(strat, [0] * 20, s=40, color="#2a78d6", alpha=0.75)
ax.axvline(y.mean(), color="#52514e", linestyle="--", linewidth=1)
ax.set_yticks([0, 1], ["stratify=y", "plain"])
ax.set_ylim(-0.6, 1.6)
ax.set_xlabel("share of benign tumors in the test set")
ax.spines[["top", "right", "left"]].set_visible(False)
plt.show()
```

Because the labels are 0s and 1s, `y_te.mean()` is the share of 1s (benign). The plain splits wander across a range more than 25 points wide, so one unlucky seed gives a test set where a model looks better or worse purely because of which tumors landed in it. All 20 stratified splits land on one single point, as close to the dashed line (the full dataset's rate) as 57 rows allow. (`*_, y_te = ...` keeps only the last of the four returned pieces.)

Use `stratify=y` for every classification split unless you have a reason not to. You can't stratify a regression target directly, since nearly every value is unique.

## Baselines: the score to beat

A **baseline** is the score you get with no real learning. If your model can't clearly beat it, the model isn't useful, however impressive the number looks.

scikit-learn's `DummyClassifier` builds baselines that `fit`, `predict`, and `score` exactly like real models, so they slot into any comparison:

```python run alt="Horizontal bar chart of test accuracy. A random-guess baseline scores 0.545, always predicting benign scores 0.629, and the depth-3 tree scores 0.944." caption="The tree's real achievement is the gap above the best baseline, not its raw 94%."
from sklearn.dummy import DummyClassifier

candidates = {
    "random guess (stratified)": DummyClassifier(strategy="stratified", random_state=0),
    "always benign (most_frequent)": DummyClassifier(strategy="most_frequent"),
    "decision tree, depth 3": DecisionTreeClassifier(max_depth=3, random_state=42),
}
scores = {}
for name, clf in candidates.items():
    clf.fit(X_train, y_train)
    scores[name] = clf.score(X_test, y_test)
    print(f"{name:30s} {scores[name]:.3f}")

fig, ax = plt.subplots(figsize=(6.4, 2.4))
bar_colors = ["#b8b7b1", "#b8b7b1", "#2a78d6"]
ax.barh(list(scores), list(scores.values()), color=bar_colors, height=0.55)
for i, value in enumerate(scores.values()):
    ax.text(value + 0.01, i, f"{value:.3f}", va="center", fontsize=9)
ax.set_xlim(0, 1.08)
ax.set_xlabel("test accuracy")
ax.spines[["top", "right"]].set_visible(False)
plt.show()
```

`most_frequent` looks only at `y_train`, finds the most common class (benign), and predicts it for every row, ignoring `X` entirely. That alone earns 0.629. Against that, the tree's 0.944 is a real improvement: it cuts the error rate from about 37% to about 6%. That's how to describe a model: not "94% accurate," but "cuts errors by five-sixths compared with always guessing benign."

The strategies you'll use:

- `"most_frequent"`: always the most common training class. The usual minimum to beat.
- `"stratified"`: random guesses in proportion to the training classes.
- `"uniform"`: every class equally likely.
- `"constant"` with `constant=0`: always the class you name.

## Regression gets a baseline too

For a numeric target, the do-nothing model predicts the training average for every row. `DummyRegressor` does exactly that. The diabetes dataset's target is a disease-progression score measured one year later:

```python run
from sklearn.datasets import load_diabetes
from sklearn.dummy import DummyRegressor
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_absolute_error

Xd, yd = load_diabetes(return_X_y=True)
Xd_train, Xd_test, yd_train, yd_test = train_test_split(Xd, yd, random_state=42)

for name, reg in [("mean baseline", DummyRegressor(strategy="mean")),
                  ("linear model ", LinearRegression())]:
    reg.fit(Xd_train, yd_train)
    mae = mean_absolute_error(yd_test, reg.predict(Xd_test))
    print(f"{name}: MAE = {mae:.1f}")
```

**Mean absolute error** (MAE) is the average size of a miss, in the target's own units. Lower is better. The linear model's typical miss is about 24 points smaller than just guessing the average, and that difference is the number worth reporting.

## Mistakes that inflate your score

:::warning
**Accuracy without a baseline.** When 95% of emails aren't spam, a filter that never flags anything is 95% accurate and useless. Print the baseline next to every score; it costs three lines.
:::

- **Fitting on everything, then splitting.** The test rows have already shaped the model, so the score is too optimistic.
- **Forgetting `random_state`.** Your score changes on every run, so you can't tell whether an edit helped or the split just got luckier.
- **Comparing models on different splits.** Two models scored on different test sets aren't in the same race. Split once, then reuse `X_train` and `X_test` for every candidate.
- **Shopping for a seed.** Trying 20 seeds and reporting the best one is tuning on the test set, just with extra steps.

:::quiz
Q: A spam filter scores 95% accuracy on a test set where 95% of emails aren't spam. What does that tell you about the filter?
- [ ] It's excellent: 95% is a high score
  95% is exactly what "never flag anything" scores here, so the number alone proves nothing.
- [x] Almost nothing until you compare it with a `most_frequent` baseline
  The baseline also scores 95%. The filter might be no better than doing nothing.
- [ ] It catches 95% of spam
  Accuracy counts all emails together; it doesn't say how much of the spam was caught.

Q: An unlimited decision tree scores 1.000 on training data and 0.923 on test data. A depth-3 tree scores 0.977 and 0.944. Which do you report as better, and why?
- [ ] The unlimited tree, because 1.000 is the top training score
  Training accuracy rewards memorizing. A tree that memorizes every row always scores 1.0 there.
- [x] The depth-3 tree, because it scores higher on rows neither model saw
  Only the test score estimates performance on new data, and there the shallower tree wins.
- [ ] They're tied, because their average scores are about equal
  Averaging train and test mixes an honest number with a dishonest one.

Q: When does `stratify=y` change your results the most?
- [ ] Large datasets with balanced classes
  With many rows and even classes, random splits already land close to the true proportions.
- [x] Small test sets, especially when one class is rare
  With few rows, luck can easily over- or under-fill the rare class in the test set.
- [ ] Regression problems
  You can't stratify a continuous target directly; it's a classification tool.

Q: You train your model on split seed 0 and your teammate's on seed 1. Yours scores 0.95, theirs 0.93. What can you conclude?
- [ ] Your model is 2 points better
  The test sets contain different rows, so part of the gap (or all of it) is luck of the split.
- [x] Nothing yet; score both on the same split first
  A fair comparison holds the data fixed and changes only the model.
- [ ] Their model is overfitting
  Nothing here compares training and test scores, so there's no evidence about overfitting.
:::

:::takeaways
- Fit on training rows only, and treat the test set as a sealed exam you open once.
- Training accuracy rewards memorizing; the test score is the honest one.
- `stratify=y` keeps class proportions identical across the split, which matters most for small or imbalanced data.
- Always report a baseline. `DummyClassifier(strategy="most_frequent")` and `DummyRegressor(strategy="mean")` are the usual minimums.
- Describe a model by its gap over the best baseline, on the same split, with a fixed `random_state`.
:::
