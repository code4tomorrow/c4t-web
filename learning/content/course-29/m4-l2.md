- Build a threshold table that reports results in counts a business understands.

- Confirm the choice once on the test set, and report an honest result when it falls short.

:::

A bank's fraud team gives you a rule: "We can review a few dozen flagged transactions a day. Catch at least 80% of fraud." That's a real requirement, and `model.predict()` with its built-in 0.5 cutoff knows nothing about it. Today you build the tool that turns a requirement like that into a threshold, and you see why the test set has to stay sealed while you choose it.

Here's the plan. The data gets split three ways, and each part has exactly one job:

```mermaid caption="Three sets, three jobs. The test set is opened once, at the very end."
flowchart LR
    D["3,000 transactions"] --> T["Train 60%: fit the model"]
    D --> V["Validation 20%: choose the threshold"]
    D --> S["Test 20%: confirm once"]
    T --> M["Model"]
    M --> V
    V --> C["Chosen threshold"]
    C --> S
```

The finished notebook ends with a function, `flag_fraud`, that applies your chosen threshold to new transactions, plus a test-set confusion matrix showing exactly how many frauds it catches and how many false alarms it costs. Create `w3-codealong-threshold.ipynb` and run the cells in order.

## Step 1: Three sets, not two

Choosing a threshold is a decision made from data, just like fitting a model. Make it on the test set and the test score stops being honest. So we carve out a **validation set** for decisions and keep the test set for the final check.

```python run
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split

# 3,000 made-up card transactions; about 10% are fraud (label 1)
X, y = make_classification(n_samples=3000, n_features=8, n_informative=4,
                           weights=[0.9, 0.1], class_sep=0.8, random_state=4)

# 60% train, 20% validation, 20% test
X_temp, X_test, y_temp, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=0
)
X_train, X_val, y_train, y_val = train_test_split(
    X_temp, y_temp, test_size=0.25, stratify=y_temp, random_state=0
)
print("train", len(y_train), "| val", len(y_val), "| test", len(y_test))
print("fraud cases: train", y_train.sum(), "| val", y_val.sum(), "| test", y_test.sum())
```

The second split takes 25% of the remaining 80%, which is 20% of the whole. Stratifying both times keeps fraud at about 10% in every part. `make_classification` builds a synthetic dataset: `weights=[0.9, 0.1]` sets the class balance, and `class_sep=0.8` makes the classes overlap enough that the problem is genuinely hard.

## Step 2: Train, and check the default threshold

```python run
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

model = make_pipeline(StandardScaler(), LogisticRegression())
model.fit(X_train, y_train)
print(classification_report(y_val, model.predict(X_val), digits=3))
```

96% accuracy, and the fraud team would reject it. Class 1's recall is 0.645, so about one fraud in three gets through. Precision is excellent, meaning the model flags only when it's very confident. The default threshold puts this model on the wrong side of the trade-off for this job.

## Step 3: Build a threshold table

Instead of trying thresholds one at a time, write a function that scores a whole range at once:

```python run
import numpy as np
import pandas as pd
from sklearn.metrics import confusion_matrix, f1_score, precision_score, recall_score

def threshold_table(y_true, proba, thresholds):
    rows = []
    for t in thresholds:
        pred = (proba >= t).astype(int)
        tn, fp, fn, tp = confusion_matrix(y_true, pred).ravel()
        rows.append({
            "threshold": round(t, 2),
            "precision": precision_score(y_true, pred, zero_division=0),
            "recall": recall_score(y_true, pred),
            "f1": f1_score(y_true, pred),
            "caught": tp, "missed": fn, "false_alarms": fp,
        })
    return pd.DataFrame(rows).round(3)

val_proba = model.predict_proba(X_val)[:, 1]
table = threshold_table(y_val, val_proba, np.arange(0.05, 0.96, 0.05))
print(table.to_string(index=False))
```

Read down the table and you can watch the trade-off happen. As the threshold rises, `false_alarms` falls toward 0 while `missed` climbs. The `caught`, `missed`, and `false_alarms` columns are what you'd actually show the fraud team: they care about "33 extra reviews," not "precision 0.612."

`zero_division=0` tells `precision_score` what to return when a threshold flags nothing at all and precision would be 0/0.

Nineteen rows of numbers are easier to read as a picture. The dashed line is the fraud team's requirement:

## Step 4: Turn the requirement into a threshold

The rule was "catch at least 80%." Among the thresholds that meet it, take the **highest**, because a higher threshold means fewer false alarms for the team to wade through:

```python run
good_enough = table[table["recall"] >= 0.80]
chosen = good_enough["threshold"].max()
best_f1 = table.loc[table["f1"].idxmax(), "threshold"]
print("Highest threshold with recall >= 0.80:", chosen)
print("Threshold with the best F1:", best_f1)
print(table[table["threshold"].isin([chosen, best_f1])].to_string(index=False))
```

On validation, 0.20 catches 52 of 62 frauds at the price of 33 false alarms. The F1-best threshold, 0.35, would be the pick if there were no business rule, but it misses 15 frauds, which breaks the requirement. **The requirement decides the threshold; F1 is a fallback for when there isn't one.**

## Step 5: Confirm once on the test set

Now, and only now, open the test set. Compare the default with the chosen threshold, as numbers and as two confusion matrices:

```python run alt="Two confusion matrices for the test set. At threshold 0.5: 533 legitimate cleared, 5 false alarms, 27 frauds missed, 35 caught. At threshold 0.2: 497 cleared, 41 false alarms, 17 missed, 45 caught." caption="The chosen threshold catches 10 more frauds and costs 36 more reviews."
from sklearn.metrics import ConfusionMatrixDisplay

test_proba = model.predict_proba(X_test)[:, 1]
print(threshold_table(y_test, test_proba, [0.5, chosen]).to_string(index=False))

fig, axes = plt.subplots(1, 2, figsize=(7.6, 3.4))
for ax, t in zip(axes, [0.5, chosen]):
    ConfusionMatrixDisplay.from_predictions(
        y_test, (test_proba >= t).astype(int), display_labels=["legit", "fraud"],
        cmap="Blues", colorbar=False, ax=ax
    )
    ax.set_title(f"threshold {t}")
plt.tight_layout()
plt.show()
```

The chosen threshold catches 10 more frauds than the default. But test recall is 0.726, **below** the 0.80 we saw on validation. That isn't a bug. With only 62 frauds in each set, a handful of borderline transactions moves recall by several points, and the validation set happened to be a little kind.

What you must **not** do is lower the threshold again until the test set says 0.80. That turns the test set into a second validation set, and you'd have no honest number left. Report what happened instead: "At threshold 0.2 the model caught 73% of fraud on held-out data and 84% on validation, so expect recall somewhere in that range." Then shrink the uncertainty with more data, or with Week 4's cross-validation, which averages over many validation splits instead of trusting one.

## Step 6: Package it

```python run
def flag_fraud(transactions, threshold=chosen):
    """Return 1 for transactions to send for review, 0 otherwise."""
    return (model.predict_proba(transactions)[:, 1] >= threshold).astype(int)

flags = flag_fraud(X_test)
print("Sent for review:", flags.sum(), "of", len(flags))
print("Share of reviews that are real fraud:", round(y_test[flags == 1].mean(), 3))
```

The last number is precision, in words the team understands: about half the reviews will turn out to be real fraud. The threshold now lives in one place, so changing it later means editing one value.

:::warning
A threshold belongs to one specific trained model. Retrain it, even on the same data with different settings, and the probabilities shift. Choose the threshold again on validation data every time.
:::

:::quiz
Q: Why does the threshold get chosen on the validation set rather than the test set?
- [ ] The validation set is bigger
  Here they're the same size. The difference is what each set is allowed to influence.
- [x] Choosing a threshold is fitting a setting to data; doing it on the test set would leave no honest score
  The test set stays untouched until the decision is final, so its score is a fair preview of real use.
- [ ] The model can't predict on the test set until the threshold is chosen
  `predict_proba` works on any rows; the issue is which rows influence your decisions.

Q: Thresholds 0.10, 0.15, and 0.20 all meet the 80% recall target on validation. Why pick 0.20?
- [ ] It has the best F1 of all thresholds
  The best F1 was at 0.35, which fails the target. The rule here is about false alarms.
- [x] It's the highest that meets the target, so it brings the fewest false alarms
  Each step down adds reviews without being required by the rule.
- [ ] Lower thresholds always lower recall
  Lower thresholds flag more transactions, so recall goes up or stays the same.

Q: Test recall comes out at 0.726, below the 0.80 target. What's the honest next step?
- [ ] Lower the threshold until test recall reaches 0.80
  That tunes on the test set, and then the 0.80 is no longer an honest estimate.
- [x] Report both numbers, then get more validation evidence (more data or cross-validation) before changing anything
  A small validation set gave an optimistic estimate; the fix is better validation, not test-set tuning.
- [ ] Retrain the model on the test set
  Then the test set is training data, and you have nothing left to evaluate with.
:::

:::takeaways
- Train fits the model, validation chooses settings like the threshold, and test confirms once.
- A threshold table in counts (caught, missed, false alarms) speaks the language of the people who use the model.
- When there's a requirement, pick the highest threshold that meets it; use F1 only when there's no rule.
- When the test result disappoints, report it. Tuning on the test set destroys your only honest number.
- A threshold belongs to one trained model; retrain, and you choose again.
:::
