title: "Code-along: Pick a fraud-alert threshold the honest way"
summary: Split data into train, validation, and test sets, build a threshold table on validation data, choose a cutoff that meets a recall target, and confirm it once on the test set.
---

A bank's fraud team tells you: "We can review a few dozen flagged transactions a day. Catch at least 80% of fraud." That's a real requirement, and `model.predict()` with its built-in 0.5 cutoff knows nothing about it. Today you build the tool that turns a requirement like that into a threshold, and you learn why the test set has to stay sealed while you choose it.

Create `w3-codealong-threshold.ipynb` and run the cells in order.

## Step 1: Three sets, not two

Choosing a threshold is a decision made from data, just like fitting a model. If you make it on the test set, the test score stops being honest. So we carve out a **validation set** for decisions and keep the test set for the final check.

```python
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split

# 3,000 made-up card transactions; about 10% are fraud (label 1)
X, y = make_classification(n_samples=3000, n_features=8, n_informative=4,
                           weights=[0.9, 0.1], class_sep=0.8, random_state=4)

# 60% train, 20% validation, 20% test
X_temp, X_test, y_temp, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=0
)
X_train, X_val, y_train, y_val = train_test_split(
    X_temp, y_temp, test_size=0.25, stratify=y_temp, random_state=0
)
print("train", len(y_train), "| val", len(y_val), "| test", len(y_test))
print("fraud cases: train", y_train.sum(), "| val", y_val.sum(), "| test", y_test.sum())
```

```text
train 1800 | val 600 | test 600
fraud cases: train 185 | val 62 | test 62
```

The second split takes 25% of the remaining 80%, which is 20% of the whole. Stratifying both times keeps fraud at about 10% everywhere. `make_classification` builds a synthetic dataset; `weights=[0.9, 0.1]` sets the class balance and `class_sep=0.8` makes the classes overlap enough that the problem is hard.

## Step 2: Train and check the default

```python
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

model = make_pipeline(StandardScaler(), LogisticRegression())
model.fit(X_train, y_train)
print(classification_report(y_val, model.predict(X_val), digits=3))
```

```text
              precision    recall  f1-score   support

           0      0.961     0.996     0.978       538
           1      0.952     0.645     0.769        62

    accuracy                          0.960       600
   macro avg      0.956     0.821     0.874       600
weighted avg      0.960     0.960     0.957       600
```

96% accuracy, and the fraud team would reject it. Recall for class 1 is 0.645, so about one fraud in three gets through. Precision is excellent, meaning the model only flags when it's very confident. The default threshold puts the model on the wrong side of the trade-off for this job.

## Step 3: Build a threshold table

Instead of trying thresholds one at a time, write a function that scores a whole range:

```python
import numpy as np
import pandas as pd
from sklearn.metrics import confusion_matrix, f1_score, precision_score, recall_score

def threshold_table(y_true, proba, thresholds):
    rows = []
    for t in thresholds:
        pred = (proba >= t).astype(int)
        tn, fp, fn, tp = confusion_matrix(y_true, pred).ravel()
        rows.append({
            "threshold": round(t, 2),
            "precision": precision_score(y_true, pred, zero_division=0),
            "recall": recall_score(y_true, pred),
            "f1": f1_score(y_true, pred),
            "caught": tp, "missed": fn, "false_alarms": fp,
        })
    return pd.DataFrame(rows).round(3)

val_proba = model.predict_proba(X_val)[:, 1]
table = threshold_table(y_val, val_proba, np.arange(0.05, 0.96, 0.05))
print(table.to_string(index=False))
```

Read down the table and you can watch the trade-off happen. As the threshold rises, `false_alarms` falls toward 0 while `missed` climbs. The `caught`, `missed`, and `false_alarms` columns are what you'd actually show the fraud team; they care about "33 extra reviews," not "precision 0.612."

`zero_division=0` tells `precision_score` what to return if a threshold flags nothing at all (precision would be 0/0). Without it you'd get a warning at very high thresholds.

:::tip
If you plot `recall` and `precision` against `threshold` with `plt.plot`, you get two curves that cross: precision rises from about 0.27 to 1.0 while recall falls from about 0.97 to 0.13. The crossing point, near 0.3 here, is where they're balanced.
:::

## Step 4: Turn the requirement into a threshold

The rule was "catch at least 80%." Among thresholds that meet it, take the **highest**, because a higher threshold means fewer false alarms:

```python
good_enough = table[table["recall"] >= 0.80]
chosen = good_enough["threshold"].max()
best_f1 = table.loc[table["f1"].idxmax(), "threshold"]
print("Highest threshold with recall >= 0.80:", chosen)
print("Threshold with the best F1:", best_f1)
```

```text
Highest threshold with recall >= 0.80: 0.2
Threshold with the best F1: 0.35
```

On validation, 0.2 catches 52 of 62 frauds with 33 false alarms. The F1-best threshold (0.35) would be the pick if you had no business rule, but it misses 15 frauds, which breaks the requirement. **The requirement decides the threshold; F1 is only a fallback when there's no requirement.**

## Step 5: Confirm once on the test set

Now, and only now, open the test set. Compare the default with the chosen threshold:

```python
test_proba = model.predict_proba(X_test)[:, 1]
print(threshold_table(y_test, test_proba, [0.5, chosen]).to_string(index=False))
```

```text
 threshold  precision  recall    f1  caught  missed  false_alarms
       0.5      0.875   0.565 0.686      35      27             5
       0.2      0.523   0.726 0.608      45      17            41
```

The new threshold catches 10 more frauds than the default (45 versus 35). But test recall is 0.726, **below** the 0.80 we saw on validation. That isn't a bug. With only 62 fraud cases in each set, a handful of borderline transactions changes recall by several points. The validation set was a little lucky.

What you must **not** do is lower the threshold again until the test set says 0.80. That turns the test set into a second validation set, and you'd have no honest number left. Instead, report what happened: "At threshold 0.2 the model caught 73% of fraud on held-out data, and 84% on validation, so expect a recall somewhere around there." Then fix the uncertainty with more data, or with cross-validation in week 4, which averages over many validation splits instead of trusting one.

## Step 6: Package it

```python
def flag_fraud(transactions, threshold=chosen):
    """Return 1 for transactions to send for review, 0 otherwise."""
    return (model.predict_proba(transactions)[:, 1] >= threshold).astype(int)

flags = flag_fraud(X_test)
print("Sent for review:", flags.sum(), "of", len(flags))
print("Share of reviews that are real fraud:", round(y_test[flags == 1].mean(), 3))
```

```text
Sent for review: 86 of 600
Share of reviews that are real fraud: 0.523
```

The last number is precision, in words the team understands: about half of the reviews will be real fraud. The threshold now lives in one place, so changing it later means changing one value.

:::warning
A threshold belongs to one specific trained model. If you retrain, even on the same data with different settings, the probabilities shift and you must pick the threshold again on validation data.
:::
