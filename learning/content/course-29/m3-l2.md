Last week k-NN came in well behind the decision tree on wine, at about 71%. We blamed feature scales. Today we test that idea on a messier version of the data, the kind you'd really get from a winery: some chemical readings missing, and one measurement recorded as words. You'll build a single pipeline that handles all of it and then use it to predict on brand-new rows, blanks and all.

Create `w2-codealong-pipeline.ipynb`. Run the cells in order; each one builds on the last.

## Step 1: Make the data realistic

```python
import numpy as np
import pandas as pd
from sklearn.datasets import load_wine
from sklearn.model_selection import train_test_split

wine = load_wine(as_frame=True)
df = wine.frame.copy()

# A taster wrote color down as words instead of a number
df["color"] = pd.cut(df["color_intensity"], bins=[0, 3.5, 7, 20],
                     labels=["pale", "medium", "deep"]).astype(str)
df = df.drop(columns="color_intensity")

# Some chemical readings went missing
rng = np.random.default_rng(42)
for col in ["alcohol", "magnesium", "proline"]:
    df.loc[rng.choice(len(df), 12, replace=False), col] = np.nan

print(df["color"].value_counts())
print("Blank cells:", int(df.isna().sum().sum()))
print(df[["proline", "hue", "magnesium"]].describe().loc[["min", "max"]])

X = df.drop(columns="target")
y = df["target"]
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=7
)
num_cols = X.columns.drop("color").tolist()
print(len(num_cols), "numeric columns, 1 text column")
```

```text
color
medium    87
pale      55
deep      36
Name: count, dtype: int64
Blank cells: 36
     proline   hue  magnesium
min    278.0  0.48       70.0
max   1680.0  1.71      162.0
12 numeric columns, 1 text column
```

`pd.cut` sorts each number into a labelled bin, giving us a text column to encode. The min/max table shows the scale problem directly: `proline` covers a range more than a thousand times wider than `hue`. k-NN measures straight-line distance between wines, so a 100-point difference in proline swamps every other feature.

We use the same `random_state=7` split as last week so the numbers are comparable.

## Step 2: Build the pipeline, with and without scaling

Writing a small function that builds the pipeline lets you flip one setting and compare fairly:

```python
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

def build(scale):
    num_steps = [("impute", SimpleImputer(strategy="median"))]
    if scale:
        num_steps.append(("scale", StandardScaler()))
    prep = ColumnTransformer([
        ("num", Pipeline(num_steps), num_cols),
        ("cat", OneHotEncoder(handle_unknown="ignore"), ["color"]),
    ])
    return Pipeline([("prep", prep), ("knn", KNeighborsClassifier(n_neighbors=5))])

unscaled = build(scale=False).fit(X_train, y_train)
scaled = build(scale=True).fit(X_train, y_train)
print("k-NN, no scaling:  ", round(unscaled.score(X_test, y_test), 3))
print("k-NN, with scaling:", round(scaled.score(X_test, y_test), 3))
```

```text
k-NN, no scaling:   0.644
k-NN, with scaling: 0.978
```

Same model, same data, same split. The only change is one `StandardScaler`, and accuracy jumps by 33 points. Without scaling, k-NN was mostly asking "which wines have similar proline?" With scaling, all 12 chemical measurements count equally.

Look at how the pieces fit together:

- The numeric columns go through **impute, then scale**. The order matters: `StandardScaler` can't compute a mean on a column that contains `NaN`.
- The `color` column has no blanks here, so it goes straight to `OneHotEncoder`. If it could have blanks, you'd wrap it in a pipeline with a `most_frequent` imputer first, as in the notes.
- `fit` returns the pipeline, so `build(...).fit(...)` gives you a trained pipeline in one line.

:::tip
To see what the model actually receives, run `scaled.named_steps["prep"].transform(X_test)[:2].round(2)`. You'll see 12 scaled numbers near 0 followed by three 0/1 color columns.
:::

## Step 3: Predict on brand-new, messy rows

A pipeline earns its keep when new data shows up. Here we take two test wines, blank out one's proline, and give the other a color word the training data never contained:

```python
new_wines = pd.DataFrame([X_test.iloc[0], X_test.iloc[1]])
new_wines.iloc[0, new_wines.columns.get_loc("proline")] = np.nan
new_wines.iloc[1, new_wines.columns.get_loc("color")] = "purple"
print(new_wines[["alcohol", "proline", "color"]])
print("Predicted:", scaled.predict(new_wines))
print("Actual:   ", y_test.iloc[:2].tolist())
```

```text
     alcohol  proline   color
167    12.82      NaN    deep
125    12.07    378.0  purple
Predicted: [2 1]
Actual:    [2, 1]
```

Neither row crashes the model, and both predictions are right. The blank proline gets the **training** median. The unknown `"purple"` becomes all zeros in the color columns because of `handle_unknown="ignore"`. You pass raw data in, and the pipeline repeats every preparation step exactly as it learned them during `fit`.

## Step 4: Swap in other models

The preparation half of the pipeline doesn't depend on which model comes after it. `clone` makes a fresh, unfitted copy of the preprocessing, so each model gets its own:

```python
from sklearn.base import clone
from sklearn.dummy import DummyClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier

prep = scaled.named_steps["prep"]
for name, clf in [("baseline", DummyClassifier()),
                  ("tree", DecisionTreeClassifier(max_depth=3, random_state=0)),
                  ("logistic", LogisticRegression(max_iter=1000)),
                  ("k-NN", KNeighborsClassifier())]:
    pipe = Pipeline([("prep", clone(prep)), ("clf", clf)])
    pipe.fit(X_train, y_train)
    print(f"{name:9s} {pipe.score(X_test, y_test):.3f}")
```

```text
baseline  0.400
tree      0.978
logistic  1.000
k-NN      0.978
```

With proper preparation, three very different models all land near the top, and k-NN went from the worst real model to a tie with the tree. Logistic regression scored a perfect 1.000, but that's 45 out of 45 test wines. One different split could easily drop it to 0.956 (43 of 45). Don't declare a winner from a single small test set; week 4's cross-validation is the tool for that.

`max_iter=1000` gives logistic regression more steps to converge. If you ever see a `ConvergenceWarning`, raise it or check that your features are scaled.

:::warning
Without `clone`, every pipeline in the loop would share **one** `ColumnTransformer` object, and each `fit` would overwrite the previous one's learned medians and scales. Here they'd all learn the same values, so nothing breaks, but sharing fitted objects causes confusing bugs. Clone, or build a fresh one each time.
:::

## What you built

A pipeline that takes raw rows, blanks and text included, and gives predictions. Every learned number (medians, means, standard deviations, category lists) comes from `X_train` alone, so the test score is honest. You also proved last week's hypothesis: k-NN's problem was scaling, not the model.
