- Build a `ColumnTransformer` pipeline that imputes, scales, and one-hot encodes in one object.
- Compare a pipeline with and without scaling while changing nothing else.
- Predict on brand-new rows that contain blanks and an unseen category.
- Reuse the same preprocessing with several models using `clone`.

Last week k-NN finished far behind the decision tree on wine, about 71% against 93%, and we blamed feature scales. Today you test that hypothesis properly, on a messier copy of the data, the kind a real winery would send you: a few chemical readings missing, and one measurement written down as words. By the end, a single pipeline object will take raw rows, blanks and all, and return predictions, and k-NN will be tied for first place.

## Step 1: Make the data realistic

```python run
import numpy as np
import pandas as pd
from sklearn.datasets import load_wine
from sklearn.model_selection import train_test_split

df = load_wine(as_frame=True).frame.copy()

# A taster wrote color down as words instead of a number
df["color"] = pd.cut(df["color_intensity"], bins=[0, 3.5, 7, 20],
                     labels=["pale", "medium", "deep"]).astype(str)
df = df.drop(columns="color_intensity")

# Some chemical readings went missing
rng = np.random.default_rng(42)
for col in ["alcohol", "magnesium", "proline"]:
    df.loc[rng.choice(len(df), 12, replace=False), col] = np.nan

print(df["color"].value_counts())
print("Blank cells:", int(df.isna().sum().sum()))

X = df.drop(columns="target")
y = df["target"]
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=7
)
num_cols = X.columns.drop("color").tolist()
print(len(num_cols), "numeric columns, 1 text column")
```

`pd.cut` sorts each number into a labeled bin, which gives us a text column to encode. We reuse last week's `random_state=7` split so today's numbers compare directly with last week's leaderboard.

Before fixing anything, let's measure the problem. k-NN classifies a wine by finding the training wines closest to it, using straight-line distance across all features. For two random wines, each feature adds to that squared distance in proportion to its **variance**. So the share of total variance is the share of k-NN's attention each feature gets:

```python run alt="Horizontal bar chart of each wine feature's share of k-NN's distance before scaling. Proline takes over 99 percent; magnesium takes most of the rest; the other ten features are each near zero. A dashed line at one twelfth marks the equal share every feature gets after scaling." caption="Before scaling, k-NN is really a proline-only classifier."
import matplotlib.pyplot as plt

share = (X_train[num_cols].var() / X_train[num_cols].var().sum()).sort_values()
print(share.tail(3).round(4))

fig, ax = plt.subplots(figsize=(6.4, 3.6))
ax.barh(share.index, share.values, color="#2a78d6", height=0.6)
ax.axvline(1 / 12, color="#eb6834", linestyle="--", linewidth=1.5)
ax.text(1 / 12 + 0.015, 0.2, "after scaling: 1/12 each", fontsize=8, color="#52514e")
ax.set_xlabel("share of squared distance, unscaled")
ax.set_xlim(0, 1.05)
ax.spines[["top", "right"]].set_visible(False)
plt.show()
```

`proline` alone accounts for almost all of the distance. Twelve chemical measurements went in, and k-NN listens to one. After `StandardScaler`, every numeric column has variance 1, so each gets an equal 1/12 share. That's the hypothesis to test.

## Step 2: Build the pipeline, with and without scaling

A small function that builds the pipeline lets you flip one setting and compare fairly:

```python run
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

def build(scale):
    num_steps = [("impute", SimpleImputer(strategy="median"))]
    if scale:
        num_steps.append(("scale", StandardScaler()))
    prep = ColumnTransformer([
        ("num", Pipeline(num_steps), num_cols),
        ("cat", OneHotEncoder(handle_unknown="ignore"), ["color"]),
    ])
    return Pipeline([("prep", prep), ("knn", KNeighborsClassifier(n_neighbors=5))])

unscaled = build(scale=False).fit(X_train, y_train)
scaled = build(scale=True).fit(X_train, y_train)
print("k-NN, no scaling:  ", round(unscaled.score(X_test, y_test), 3))
print("k-NN, with scaling:", round(scaled.score(X_test, y_test), 3))
```

Same model, same data, same split. The only change is one `StandardScaler`, and accuracy jumps by more than 30 points. The hypothesis holds: k-NN was never a bad model for wine, it was asking the wrong question ("which wines have similar proline?").

Look at how the pieces fit:

- Numeric columns go through **impute, then scale**, in that order. `StandardScaler` can't compute a mean over a column that still has `NaN` in it.
- `color` has no blanks here, so it goes straight to `OneHotEncoder`. If it could have blanks, you'd put a `most_frequent` imputer in front of it, as in the Notes.
- `fit` returns the pipeline itself, so `build(...).fit(...)` gives a trained pipeline in one line.

:::try
Peek at what the model actually receives: run `scaled.named_steps["prep"].transform(X_test)[:2].round(2)`. You'll see 12 scaled numbers near 0, then three 0/1 color columns.
:::

## Step 3: Predict on brand-new, messy rows

A pipeline earns its keep when new data arrives. Take two test wines, blank out one's proline, and give the other a color word training never saw:

```python run
new_wines = X_test.iloc[:2].copy()
new_wines.iloc[0, new_wines.columns.get_loc("proline")] = np.nan
new_wines.iloc[1, new_wines.columns.get_loc("color")] = "purple"
print(new_wines[["alcohol", "proline", "color"]])
print("Predicted:", scaled.predict(new_wines))
print("Actual:   ", y_test.iloc[:2].tolist())
```

Neither row crashes the model, and both predictions are correct. The blank proline is filled with the **training** median. The unknown `"purple"` becomes all zeros in the color columns, thanks to `handle_unknown="ignore"`. You hand the pipeline raw data, and it repeats every preparation step exactly as it learned them during `fit`.

## Step 4: Swap in other models

The preparation half of the pipeline doesn't care which model comes after it. `clone` makes a fresh, unfitted copy of it, so each model gets its own:

```python run alt="Bar chart of test accuracy for four models on the same pipeline. The baseline scores 0.400; the decision tree 0.978; logistic regression 1.000; k-NN 0.978." caption="With proper preparation, three very different models all land near the top."
from sklearn.base import clone
from sklearn.dummy import DummyClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier

prep = scaled.named_steps["prep"]
results = {}
for name, clf in [("baseline", DummyClassifier()),
                  ("tree", DecisionTreeClassifier(max_depth=3, random_state=0)),
                  ("logistic", LogisticRegression(max_iter=1000)),
                  ("k-NN", KNeighborsClassifier())]:
    pipe = Pipeline([("prep", clone(prep)), ("clf", clf)])
    results[name] = pipe.fit(X_train, y_train).score(X_test, y_test)
    print(f"{name:9s} {results[name]:.3f}")

fig, ax = plt.subplots(figsize=(6, 2.8))
bars = ax.bar(list(results), list(results.values()), width=0.55,
              color=["#b8b7b1", "#2a78d6", "#2a78d6", "#eb6834"])
ax.bar_label(bars, fmt="%.3f", fontsize=9)
ax.set_ylim(0, 1.12)
ax.set_ylabel("test accuracy (45 wines)")
ax.spines[["top", "right"]].set_visible(False)
plt.show()
```

k-NN (orange) went from the weakest real model last week to a tie with the tree. Logistic regression scored a perfect 1.000, but that's 45 out of 45 wines: one different split could easily make it 43 of 45. Don't crown a winner from one small test set; Week 4's cross-validation is the tool for that.

`max_iter=1000` gives logistic regression more steps to settle on its answer. If you ever see a `ConvergenceWarning`, raise it, or check that your features are scaled.

:::warning
Without `clone`, every pipeline in the loop would share **one** `ColumnTransformer`, and each `fit` would overwrite the medians and scales the previous one learned. Here they'd all learn the same numbers, so nothing visibly breaks, but shared fitted objects cause baffling bugs later. Clone, or build a fresh one each time.
:::

## The finished pipeline

Everything that matters, in one cell you can reuse on any table with numeric and text columns:

```python
import numpy as np
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.datasets import load_wine
from sklearn.impute import SimpleImputer
from sklearn.model_selection import train_test_split
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

df = load_wine(as_frame=True).frame.copy()
df["color"] = pd.cut(df["color_intensity"], bins=[0, 3.5, 7, 20],
                     labels=["pale", "medium", "deep"]).astype(str)
df = df.drop(columns="color_intensity")
rng = np.random.default_rng(42)
for col in ["alcohol", "magnesium", "proline"]:
    df.loc[rng.choice(len(df), 12, replace=False), col] = np.nan

X, y = df.drop(columns="target"), df["target"]
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=7
)
num_cols = X.columns.drop("color").tolist()

model = Pipeline([
    ("prep", ColumnTransformer([
        ("num", Pipeline([("impute", SimpleImputer(strategy="median")),
                          ("scale", StandardScaler())]), num_cols),
        ("cat", OneHotEncoder(handle_unknown="ignore"), ["color"]),
    ])),
    ("knn", KNeighborsClassifier(n_neighbors=5)),
])
model.fit(X_train, y_train)
print("Test accuracy:", round(model.score(X_test, y_test), 3))
```

:::quiz
Q: In the numeric branch, why must `SimpleImputer` come **before** `StandardScaler`?
- [ ] Imputers are always listed first by convention
  It isn't a style rule; reversing the order breaks the math.
- [x] The scaler needs a mean and standard deviation, and it can't compute them through blanks
  Fill the blanks first, then every column has real numbers to average.
- [ ] Scaling first would leak the test set
  Order inside the pipeline doesn't affect leakage; both steps fit on training rows either way.

Q: Last week k-NN scored 0.711 on wine and the tree 0.933. Based on today, which conclusion was wrong?
- [ ] "Trees are better than k-NN for wine"
  That's the wrong conclusion, but the question is which *step* misled us. Look at what changed today.
- [x] Judging k-NN before its features were scaled
  k-NN was measuring distance almost entirely by proline. With fair scales, it ties the tree.
- [ ] Using a stratified split
  The split was fine and identical both weeks; only the preprocessing changed.

Q: Why does the Step 4 loop wrap the preprocessing in `clone(prep)`?
- [ ] `clone` makes the pipeline train faster
  It copies settings, not speed. Each copy still has to be fitted.
- [x] So each model gets its own unfitted copy instead of sharing one object
  Shared fitted objects get overwritten by the next `fit`, a source of confusing bugs.
- [ ] Without `clone`, the test set would leak into training
  Every `fit` here uses `X_train` only, cloned or not; `clone` is about independence, not leakage.
:::

:::takeaways
- Measure before you fix: each feature's share of variance shows what k-NN is really paying attention to.
- Order matters inside a branch: impute, then scale.
- One pipeline object handles blanks and unseen categories at prediction time, using only what it learned from `X_train`.
- Change one thing at a time. The `build(scale)` function made the scaling experiment fair.
- A perfect score on 45 rows is one draw, not proof. Save the verdict for cross-validation.
:::
