:::objectives
- Set up one train/test split and one `cv` object that every search shares.
- Write a grid or random search for each model family, sized to a time budget.
- Build a leaderboard from `cv_results_` that shows mean ± std, and judge whether the gap between the top two is real.
- Read a two-hyperparameter search as a heatmap.
- Score only the winner on the test set, then inspect its confusion matrix and its mistakes.
:::

Today's arena is `load_digits`: 1,797 handwritten digits, each an 8 × 8 grid of gray levels from 0 to 16, flattened into 64 numbers. Ten nearly balanced classes and enough rows to make tuning matter. Here's what the models will see:

```python run alt="Two rows of five small grayscale images showing handwritten digits 0 through 9, each a blocky 8 by 8 pixel grid labeled with its true digit." caption="Ten of the 1,797 digits, at their real 8 × 8 resolution"
import matplotlib.pyplot as plt
import numpy as np
import pandas as pd
from sklearn.datasets import load_digits

digits = load_digits()
X, y = digits.data, digits.target
print("rows, pixels:", X.shape, "| digits per class:", np.bincount(y))

fig, axes = plt.subplots(2, 5, figsize=(7, 3))
for ax, image, label in zip(axes.ravel(), digits.images, digits.target):
    ax.imshow(image, cmap="gray_r")
    ax.set_title(str(label))
    ax.axis("off")
```

You'll build a **shootout**: three model families, each tuned by its own search, all scored on identical folds, ranked on a leaderboard, and then one, only one, checked against the test set.

```mermaid caption="The shootout: three searches share one set of folds; only the winner meets the test set"

    F --> T[Tree grid search]

## Step 1: Split once, fold once

```python run
from sklearn.model_selection import StratifiedKFold, train_test_split

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42)
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
print("train:", X_train.shape, "| test:", X_test.shape)
```

The 360 test digits now go in the vault. Every search below gets the same `cv`, so every setting of every model is scored on exactly the same five sets of validation digits.

## Step 2: One search per model family

Each model sits in a `Pipeline` whose estimator step is named `"model"`, so all three search spaces use the same `model__...` naming.

```python run
from scipy.stats import randint
from sklearn.ensemble import RandomForestClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import GridSearchCV, RandomizedSearchCV
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.tree import DecisionTreeClassifier

searches = {
    "tree": GridSearchCV(
        Pipeline([("model", DecisionTreeClassifier(random_state=0))]),
        {"model__max_depth": [5, 10, 15, None],
         "model__min_samples_leaf": [1, 3, 5]},
        cv=cv, scoring="accuracy"),
    "logistic": GridSearchCV(
        Pipeline([("scale", StandardScaler()),
                  ("model", LogisticRegression(max_iter=5000))]),
        {"model__C": [0.001, 0.01, 0.1, 1, 10]},
        cv=cv, scoring="accuracy"),
    "forest": RandomizedSearchCV(
        Pipeline([("model", RandomForestClassifier(random_state=0))]),
        {"model__n_estimators": randint(30, 90),
         "model__max_features": ["sqrt", "log2"],
         "model__min_samples_leaf": randint(1, 4)},
        n_iter=4, cv=cv, scoring="accuracy", random_state=0),
}
from sklearn.model_selection import ParameterGrid

for name, search in searches.items():
    if isinstance(search, GridSearchCV):
        n = len(ParameterGrid(search.param_grid))
    else:
        n = search.n_iter
    print(f"{name:>8}: {n} settings x 5 folds = {n * 5} fits")
```

Each search is shaped by what it costs:

-   **Tree:** two short lists make 4 × 3 = 12 settings. Trees train in milliseconds, so a full grid is fine.
-   **Logistic:** only `C` matters much, so it gets one log-spaced list. The scaler lives *inside* the pipeline, so each fold refits it on that fold's training digits.
-   **Forest:** three hyperparameters, one a range of integers. A full grid would be hundreds of settings, and each forest is slow, so four random draws keep this cell short enough to run in class. In a real project, raise `n_iter`.

Accuracy is a fair metric here because the ten classes are almost perfectly balanced. Next week's data won't be, and you'll pick something else.

## Step 3: Run the searches and build a leaderboard

```python run alt="Horizontal bar chart of mean cross-validated accuracy with error bars. Forest and logistic regression are both near 0.97 with overlapping error bars. The tree is far behind at about 0.85." caption="The top two overlap; the tree doesn't"
rows = []
for name, search in searches.items():
    search.fit(X_train, y_train)
    i = search.best_index_
    rows.append({"model": name,
                 "cv_mean": search.cv_results_["mean_test_score"][i],
                 "cv_std": search.cv_results_["std_test_score"][i],
                 "best_params": search.best_params_})
board = pd.DataFrame(rows).sort_values("cv_mean", ascending=False).reset_index(drop=True)
for r in board.itertuples():
    print(f"{r.model:>8}: {r.cv_mean:.4f} ± {r.cv_std:.4f}   {r.best_params}")

plt.figure(figsize=(7, 2.4))
plt.barh(board["model"], board["cv_mean"], xerr=board["cv_std"], capsize=4, color="#7f9cc9")
plt.xlim(0.8, 1.0)
plt.gca().invert_yaxis()
plt.xlabel("mean CV accuracy (± 1 std)")
```

`best_index_` points at the winning row of `cv_results_`, which lets you pull out the winner's **std** as well as its mean. `best_score_` alone gives you only the mean, and a leaderboard without spreads invites overconfident conclusions.

What the board says:

-   The single tree is far behind, more than ten points below the others. Even tuned, one tree on raw pixels is too jumpy.
-   The top two are separated by less than one standard deviation. That's a near tie, not a clear win, and the error bars in the chart overlap to say so.
-   Logistic regression is that close while being simpler and much faster to train. In a real project you could reasonably choose it, as long as you say why. Here we follow the leaderboard so you can see the whole procedure.

:::video J4Wdy0Wc_xQ
What to watch for: bootstrapping and the random feature subsets. Those two tricks are exactly what `n_estimators` and `max_features` control in your search.
:::

## Step 4: Look inside one search

The leaderboard shows each family's best setting. `cv_results_` holds every setting, and with two hyperparameters it reads best as a heatmap:

```python run alt="Heatmap of tree accuracy with max_depth on the rows (5, 10, 15, None) and min_samples_leaf on the columns (1, 3, 5). Depth 5 is clearly worst at about 0.68. Depths 10, 15, and None sit between 0.83 and 0.85, and the rows for 15 and None are identical." caption="Depth 5 is too shallow; beyond 10, depth stops mattering"
tree_results = pd.DataFrame(searches["tree"].cv_results_)
tree_results["depth"] = tree_results["param_model__max_depth"].astype(str)
table = tree_results.pivot(index="depth", columns="param_model__min_samples_leaf",
                           values="mean_test_score").loc[["5", "10", "15", "None"]]
print(table.round(3))

plt.figure(figsize=(5, 3.2))
plt.imshow(table.values, cmap="viridis", aspect="auto")
plt.colorbar(label="mean CV accuracy")
plt.xticks(range(3), table.columns)
plt.yticks(range(4), table.index)
plt.xlabel("min_samples_leaf")
plt.ylabel("max_depth")
for i in range(4):
    for j in range(3):
        plt.text(j, i, f"{table.values[i, j]:.3f}", ha="center", va="center", color="white")
```

Every searched hyperparameter gets a column named `param_<name>`, and `pivot` turns the long results table into a depth-by-leaf grid. Two findings jump out. Depth 5 is clearly too shallow. And the rows for 15 and `None` are identical: these trees stop growing before 15 levels, so the two settings build exactly the same trees. When neighboring cells differ only in the third decimal, choose the simpler setting rather than chasing noise.

## Step 5: Open the vault once

```python run alt="Ten by ten confusion matrix for the winning model on 360 test digits. The diagonal holds 30 to 37 correct predictions per digit. The row for true 8 has the most misses: three predicted as 1 and two as 7. Six other cells hold a single mistake each." caption="Almost everything lands on the diagonal; the few misses are worth a look"
from sklearn.metrics import ConfusionMatrixDisplay, accuracy_score

winner_name = board.loc[0, "model"]
winner = searches[winner_name].best_estimator_
test_pred = winner.predict(X_test)
wrong = test_pred != y_test
print(f"winner: {winner_name}")
print(f"CV accuracy:   {board.loc[0, 'cv_mean']:.3f} ± {board.loc[0, 'cv_std']:.3f}")
print(f"test accuracy: {accuracy_score(y_test, test_pred):.3f}  ({wrong.sum()} of {len(y_test)} wrong)")

ConfusionMatrixDisplay.from_predictions(y_test, test_pred, colorbar=False, cmap="Blues")
plt.gcf().set_size_inches(5.5, 5.5)
```

`best_estimator_` is the winning pipeline, already refit on all 1,437 training digits. Its test accuracy lands close to its cross-validated estimate, and remember that the CV number carries a little optimism because it's the best of several tries. Each test digit is worth about 0.28 points, so differences of a point or so are within ordinary noise.

Now read the matrix row by row. Rows are the true digit and columns are the prediction, so everything off the diagonal is a mistake. The row for 8 holds five of the eleven: three 8s called 1 and two called 7. That's a concrete lead, much more useful than "96.9% accurate."

:::warning
Don't score the runner-up on the test set too and switch if it does better. Once you choose between models using test scores, the test set is part of your selection process and its score is no longer unbiased. If you want a second opinion, use nested cross-validation on the training set.
:::

## Step 6: Look at what it gets wrong

A confusion matrix tells you *which* digits get confused. Looking at the actual images tells you *why*, and it's the first move of next week's error analysis.

```python run alt="Eight small grayscale images of misclassified test digits, each titled with its true and predicted label: a 6 read as 8, an 8 read as 1, a 2 read as 0, an 8 read as 7, a 9 read as 7, an 8 read as 1, a 0 read as 4, and a 9 read as 3. Several are thin or smudged." caption="The model's mistakes, as images"
miss_idx = np.where(wrong)[0][:8]
fig, axes = plt.subplots(1, len(miss_idx), figsize=(1.2 * len(miss_idx), 1.8))
for ax, i in zip(np.atleast_1d(axes), miss_idx):
    ax.imshow(X_test[i].reshape(8, 8), cmap="gray_r")
    ax.set_title(f"true {y_test[i]}\nsaid {test_pred[i]}", fontsize=8)
    ax.axis("off")
```

Some of these are digits a person would hesitate over too, and some are honest model errors. Sorting mistakes into "ambiguous even to humans" and "the model should have got this" tells you how much better the model could realistically get.

:::quiz
Q: The forest leads logistic regression by less than one standard deviation. What's the best way to describe the result?
- [ ] The forest is the better model
  A lead smaller than the fold-to-fold wobble isn't enough to call a winner.
- [x] A near tie; logistic regression is simpler and faster, which is a fair reason to prefer it
  When performance ties, cost and simplicity are legitimate tie-breakers, as long as the report says so.
- [ ] Rerun the forest search with different seeds until it wins clearly
  Re-rolling until you like the answer is a form of tuning on noise.

Q: Why does the forest get a 4-setting random search while the tree gets a full 12-setting grid?
- [ ] Random search is more accurate for forests
  Neither search is more accurate in general; the choice is about budget.
- [x] Each forest takes far longer to train, so a fixed, small `n_iter` keeps the cost under control
  Settings × folds × cost per fit is the real budget. Cheap trees can afford a grid; slow forests get a sample.
- [ ] Grid search doesn't work with integer ranges
  A grid can list integers. `randint` is a distribution, which only random search can sample.

Q: After Step 5, the logistic model would have scored 0.4 points higher on the test set. What should you do?
- [ ] Switch the final model to logistic regression
  That choice would be made with the test set, so its score would no longer be honest.
- [x] Keep the decision made on cross-validation, and report the test score as it is
  The test set is for confirming a decision, not for making one. A 0.4-point difference is about one digit anyway.
- [ ] Average the two models' test scores
  Averaging doesn't undo the problem; you'd still be choosing with test data.
:::

:::takeaways
- One split and one `cv` object make every search in a notebook directly comparable.
- Size each search to its cost: grids for cheap models, `RandomizedSearchCV` with a small `n_iter` for slow ones.
- Build leaderboards from `cv_results_` at `best_index_` so you can show mean ± std, not just the mean.
- A two-hyperparameter search is easiest to read as a heatmap from `pivot`.
- Only the winner meets the test set, once. Then look at its mistakes, not just its score.
:::
