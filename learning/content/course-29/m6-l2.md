---
title: "Code-along: a tuned model shootout on handwritten digits"
summary: Tune a decision tree, a logistic regression, and a random forest on the same folds, rank them on a leaderboard, and check only the winner against the test set.
---

`load_digits` contains 1,797 tiny 8×8 grayscale images of handwritten digits. Each image is flattened into 64 pixel values from 0 to 16. Ten balanced classes and a fair amount of data make it a good arena: different model families really do perform differently here, and tuning moves the numbers.

You'll build a notebook that runs a **shootout**: three model families, each tuned with a search, all scored on identical folds, ranked on a leaderboard, with one final test-set check of the winner. Run each step as its own cell. The forest search takes 10–30 seconds.

## Step 1: Split once, fold once

```python
import pandas as pd
from scipy.stats import randint
from sklearn.datasets import load_digits
from sklearn.ensemble import RandomForestClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score
from sklearn.model_selection import (GridSearchCV, RandomizedSearchCV,
                                     StratifiedKFold, train_test_split)
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.tree import DecisionTreeClassifier

X, y = load_digits(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42)
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
print(X.shape, "->", X_train.shape, X_test.shape)
```

```text
(1797, 64) -> (1437, 64) (360, 64)
```

The 360 test images go into a metaphorical vault. Every search below gets the same `cv` object, so each candidate setting of every model is scored on exactly the same five sets of validation images.

## Step 2: Define one search per model family

Each model sits in a `Pipeline` whose estimator step is named `"model"`. That way every grid uses the same `model__...` naming.

```python
searches = {
    "tree": GridSearchCV(
        Pipeline([("model", DecisionTreeClassifier(random_state=0))]),
        {"model__max_depth": [5, 10, 15, None],
         "model__min_samples_leaf": [1, 3, 5]},
        cv=cv, scoring="accuracy"),
    "logistic": GridSearchCV(
        Pipeline([("scale", StandardScaler()),
                  ("model", LogisticRegression(max_iter=5000))]),
        {"model__C": [0.001, 0.01, 0.1, 1, 10]},
        cv=cv, scoring="accuracy"),
    "forest": RandomizedSearchCV(
        Pipeline([("model", RandomForestClassifier(random_state=0, n_jobs=-1))]),
        {"model__n_estimators": randint(50, 150),
         "model__max_features": ["sqrt", "log2", 0.3],
         "model__min_samples_leaf": randint(1, 5)},
        n_iter=6, cv=cv, scoring="accuracy", random_state=0),
}
```

Why each search looks the way it does:

-   **Tree:** two small lists give 4 × 3 = 12 combinations, which is cheap enough for a full grid.
-   **Logistic:** only `C` matters much here, so it gets one log-spaced list. The scaler lives *inside* the pipeline, so it's refit on each fold's training images.
-   **Forest:** three hyperparameters, one of them a range of integers. A full grid would be hundreds of combinations. Six random samples keeps the run short while you learn. Raise it in a real project.

Accuracy is a fine metric here because the ten classes are almost exactly balanced. On imbalanced data you would pick something else (next week).

## Step 3: Run the searches and build a leaderboard

```python
rows = []
for name, search in searches.items():
    search.fit(X_train, y_train)
    i = search.best_index_
    rows.append({
        "model": name,
        "cv_mean": search.cv_results_["mean_test_score"][i],
        "cv_std": search.cv_results_["std_test_score"][i],
        "n_settings": len(search.cv_results_["params"]),
        "best_params": search.best_params_,
    })
board = pd.DataFrame(rows).sort_values("cv_mean", ascending=False)
for r in board.itertuples():
    print(f"{r.model:>8}: {r.cv_mean:.4f} ± {r.cv_std:.4f}  ({r.n_settings} settings tried)")
    print(f"          best: {r.best_params}")
```

```text
  forest: 0.9736 ± 0.0114  (6 settings tried)
          best: {'model__max_features': 0.3, 'model__min_samples_leaf': 1, 'model__n_estimators': 138}
logistic: 0.9680 ± 0.0074  (5 settings tried)
          best: {'model__C': 1}
    tree: 0.8525 ± 0.0192  (12 settings tried)
          best: {'model__max_depth': 15, 'model__min_samples_leaf': 1}
```

`best_index_` points at the winning row of `cv_results_`, so you can pull out the **std** of the best setting too. `best_score_` gives you only the mean.

What the leaderboard says:

-   The single tree is far behind, about 12 points below the others. Even tuned, one tree on raw pixels is too unstable.
-   The forest leads logistic regression by about half a point, which is smaller than the forest's own standard deviation (1.1 points). That's a near tie, not a clear win.
-   Logistic regression is that close while being much faster and simpler. In a real project you might reasonably pick it instead, and the trade-off is worth stating out loud. Here we follow the leaderboard so you can see the whole procedure.

## Step 4: Look inside one search

The leaderboard shows only each family's best setting. `cv_results_` shows every setting, and it often teaches you more.

```python
tree_results = pd.DataFrame(searches["tree"].cv_results_)
cols = ["param_model__max_depth", "param_model__min_samples_leaf",
        "mean_test_score", "std_test_score", "rank_test_score"]
print(tree_results[cols].sort_values("rank_test_score").head(4).round(4).to_string(index=False))
```

```text
param_model__max_depth  param_model__min_samples_leaf  mean_test_score  std_test_score  rank_test_score
                    15                              1           0.8525          0.0192                1
                  None                              1           0.8525          0.0192                1
                    10                              1           0.8462          0.0276                3
                    10                              3           0.8462          0.0179                4
```

Depth 15 and unlimited depth tie exactly: the trees stop growing before they reach 15 levels, so the two settings build the same trees. The two depth-10 rows both show 0.8462 after rounding, but their unrounded scores differ slightly, which is why their ranks differ. When rows are this close, choose the simpler or more stable one (the smaller std) rather than chasing the fourth decimal.

:::tip
Every searched hyperparameter gets a column named `param_<name>`. Sorting by `rank_test_score` is the quickest way to see the top settings.
:::

## Step 5: Open the vault once

```python
winner_name = board.iloc[0]["model"]
winner = searches[winner_name].best_estimator_
test_acc = accuracy_score(y_test, winner.predict(X_test))
print(f"Winner: {winner_name}")
print(f"CV accuracy:   {board.iloc[0]['cv_mean']:.3f} ± {board.iloc[0]['cv_std']:.3f}")
print(f"Test accuracy: {test_acc:.3f}  ({(winner.predict(X_test) != y_test).sum()} of {len(y_test)} wrong)")
```

```text
Winner: forest
CV accuracy:   0.974 ± 0.011
Test accuracy: 0.958  (15 of 360 wrong)
```

`best_estimator_` is the winning pipeline, already refit on all 1,437 training images. The test accuracy is about 1.6 points under the CV estimate. Part of that is the optimism you read about in the Notes: the forest's score is the best of six tries, and the best of several noisy scores tends to run high. Part is ordinary test-set noise, since each image is worth 0.28 points.

:::warning
Don't score the logistic model on the test set too and switch if it does better. The moment you pick between models using test scores, the test set is part of your selection process and its score is no longer unbiased. If you need another opinion, use nested CV on the training set.
:::
