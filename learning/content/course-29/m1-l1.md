In Week 1 you'll watch a model score 94% and then find out a do-nothing guess scores 63%. That moment only lands if it happens on your own screen, in your own notebook. So before the first class you need one thing working: a notebook that runs Python with four libraries installed, **scikit-learn**, **pandas**, **numpy**, and **matplotlib**.

The class uses **Google Colab**. It's free, it runs in a browser, and all four libraries come preinstalled, so most people are done in five minutes. If you'd rather work offline on your own Windows, Mac, or Linux computer, JupyterLab is a fine alternative, and the code is identical in both.

## Where your code actually runs

Colab looks like a document, but every time you run a cell, the code travels to a computer in a Google data center, runs there, and sends the output back. Your notebook file lives in your Google Drive. Knowing this split explains most Colab surprises later: the notebook survives when you close the tab, but the running machine (and anything stored only in its memory) does not.

```mermaid caption="Colab: the notebook lives in Drive, the code runs on a Google machine"
flowchart LR
    A["Your browser (the notebook page)"] -->|"run a cell"| B["Google VM (Python + libraries)"]
    B -->|"output, charts"| A
    A <-->|"autosave"| C[("Google Drive: .ipynb file")]
```

## Option A: Google Colab (the class default)

Colab works the same on Windows, macOS, and Chromebooks, because everything happens in the browser.

1. Sign in to a Google account in Chrome, Edge, Firefox, or Safari. A personal Gmail account is the safest choice; some school accounts have Colab switched off by an administrator.
2. Go to `colab.research.google.com`.
3. In the **Open notebook** window that appears, click **New notebook**. If no window appears, use **File → New notebook in Drive**.
4. Click the name at the top left (it starts as `Untitled0.ipynb`) and rename it `c4t-setup.ipynb`.
5. Click into the gray code cell, type `print("hello")`, and press **Shift + Enter**.

The first run takes a few seconds while Colab connects you to a machine. When it's ready, the top right shows a green check with **RAM** and **Disk** bars, and `hello` appears under the cell.

:::tip

## Option B: JupyterLab on your own computer

JupyterLab is the same kind of notebook, running on your own machine. Pick it if you have a Windows, Mac, or Linux computer you're allowed to install software on and you'd like to work without internet. It takes about 15 minutes, and you'll type a few commands in a terminal.

scikit-learn's current release needs **Python 3.11 or newer**, so check that first.

:::tabs
@tab Windows
1. Open **PowerShell** (press the Windows key and type PowerShell) and run `py --version`. If it prints `Python 3.11` or higher, skip to step 3.
2. Otherwise install Python from `python.org/downloads`. If the installer shows a checkbox called **Add python.exe to PATH**, tick it. Close and reopen PowerShell afterwards.
3. Make a course folder and install everything:

```powershell
mkdir c4t-ml
cd c4t-ml
py -m pip install jupyterlab scikit-learn pandas matplotlib
```

4. Start JupyterLab with `py -m jupyter lab`. Your browser opens at an address like `http://localhost:8888/lab`.
@tab macOS
1. Open **Terminal** (press Cmd + Space and type Terminal) and run `python3 --version`. If it prints `Python 3.11` or higher, skip to step 3.
2. Otherwise install the macOS package from `python.org/downloads`, then open a new Terminal window.
3. Make a course folder and install everything:

```bash
mkdir c4t-ml
cd c4t-ml
python3 -m pip install jupyterlab scikit-learn pandas matplotlib
```

4. Start JupyterLab with `python3 -m jupyter lab`. Your browser opens at an address like `http://localhost:8888/lab`.
@tab Linux
1. Run `python3 --version` in a terminal and check for 3.11 or newer.
2. Many Linux systems block installing into the system Python (you'd see `externally-managed-environment`), so make a virtual environment for the course:

```bash
mkdir c4t-ml && cd c4t-ml
python3 -m venv .venv
source .venv/bin/activate
python -m pip install jupyterlab scikit-learn pandas matplotlib
```

3. Start JupyterLab with `jupyter lab`. Next time, run `source .venv/bin/activate` inside `c4t-ml` first.
@tab Chromebook
Use Colab (Option A). ChromeOS can run Linux apps, but school-managed Chromebooks usually block that, and Colab gives you the same notebook with nothing to install.
:::

numpy installs on its own, because pandas and scikit-learn depend on it. Once JupyterLab opens, click the **Python 3 (ipykernel)** tile under **Notebook** in the Launcher tab, then right-click the new `Untitled.ipynb` in the file panel and rename it `c4t-setup.ipynb`.

:::warning
Leave the terminal window open while you work, because closing it shuts JupyterLab down. And always start JupyterLab from inside your `c4t-ml` folder: it can only see files in the folder where it started and the folders below it, so starting it elsewhere makes your notebooks seem to vanish.
:::

## Prove the toolkit is ready

In either tool, paste this into a code cell and press **Shift + Enter**:

```python run title="version_check.py"
import sys
import sklearn, pandas, numpy, matplotlib

print("Python      ", sys.version.split()[0])
for lib in [sklearn, pandas, numpy, matplotlib]:
    print(f"{lib.__name__:12s}", lib.__version__)

major, minor = (int(part) for part in sklearn.__version__.split(".")[:2])
print("Ready for Week 1" if (major, minor) >= (1, 2) else "Update scikit-learn first")
```

That output came from the computer that built this page. Your version numbers will almost certainly differ, and that's fine. What matters is the last line. Everything in this class works on scikit-learn 1.2 or newer, and Colab ships a recent release.

Notice that the package is called `scikit-learn` when you install it but `sklearn` when you import it. That mismatch causes the second problem in the next section.

## The four problems you're most likely to hit

**1. `ModuleNotFoundError: No module named 'sklearn'`.** The library isn't installed in the Python your notebook uses. Run `%pip install scikit-learn pandas matplotlib` in a notebook cell, then restart: in Colab use **Runtime → Restart session**; in JupyterLab use **Kernel → Restart Kernel**. The `%pip` form (with a percent sign) installs into the exact Python the notebook is running, which avoids the classic "I installed it but it still says missing" loop.

**2. `The 'sklearn' PyPI package is deprecated, use 'scikit-learn' rather than 'sklearn' for pip commands.`** You typed `pip install sklearn`. That old name now fails on purpose. Install `scikit-learn` and keep importing `sklearn`.

**3. Colab says your organization doesn't allow it, or the page won't load.** A school Google account with Colab turned off is the usual cause. Sign in with a personal Google account instead (Colab's profile icon, top right, lets you switch accounts), or ask your teacher before the first class.

**4. `'py' is not recognized` or `python3: command not found`.** Python isn't installed, or the terminal was opened before the install finished. Close the terminal, open a new one, and try again. On Windows, if `py` still fails, try `python --version`, then rerun the installer and tick the PATH box.

## Colab or JupyterLab?

When in doubt, use Colab. Both tools read and write the same `.ipynb` format, so a notebook made in one opens in the other, and you can switch at any point in the term.

| | Google Colab | JupyterLab |
|---|---|---|
| Install needed | No | Yes (Python + pip) |
| Works offline | No | Yes, once installed |
| Where notebooks live | Google Drive | Folders on your computer |
| Works on a Chromebook | Yes | Usually not |
| Session ends when idle | Yes | No |

Once the version check prints its last line without an error, you're set. The next lesson loads a real dataset, draws a chart, and trains a model to prove the whole chain works together.
