Run `train_test_split` with `random_state=1`, then again with `random_state=2`, and your "92% accurate" model might come back as 89% or 95%. Nothing about the model changed. You just got a luckier or unluckier set of test rows. One split gives you one noisy number. Cross-validation gives you several, so you can see both the score and how much it wobbles.

## How k-fold cross-validation works

Cut the data into *k* equal parts, called **folds**. Train on k − 1 folds and score on the one left out. Repeat k times so every fold gets a turn as the validation set. You end up with k scores.

With k = 5:

-   Round 1: train on folds 2–5, score on fold 1
-   Round 2: train on folds 1, 3, 4, 5, score on fold 2
-   ...and so on through round 5

Every row is used for validation exactly once and for training four times. Report the **mean** as your estimate and the **standard deviation** as your uncertainty.

## Stratified folds

For classification, use `StratifiedKFold`. It keeps the class proportions about the same in every fold, which is the same reason you used `stratify=y` in `train_test_split`. Turn on `shuffle=True` too. Some datasets are sorted by class, and unshuffled folds of sorted data can leave a whole class out of training.

```python
from sklearn.datasets import load_breast_cancer
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import StratifiedKFold, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_breast_cancer(return_X_y=True)

pipe = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)

scores = cross_val_score(pipe, X, y, cv=cv, scoring="f1")
print("Fold F1 scores:", scores.round(3))
print(f"F1 = {scores.mean():.3f} ± {scores.std():.3f}")
```

```text
Fold F1 scores: [0.979 0.959 0.973 0.993 0.993]
F1 = 0.979 ± 0.013
```

The five scores run from 0.959 to 0.993. If you had made one split and gotten fold 2, you would have reported 0.959. If you had gotten fold 4, you would have reported 0.993. The honest summary is "about 0.98, give or take 0.01."

Passing the **pipeline** to `cross_val_score` matters. The scaler is refit inside every fold, on that fold's training rows only, so no information leaks from the validation fold. If you scaled `X` first and cross-validated afterward, every fold's scaler would have already seen the validation rows.

:::tip
Make the `cv` object once and reuse it. When every model you try is scored on the same five folds, the comparisons are fair, which is exactly what next week is about.
:::

## Where the test set fits

Cross-validation doesn't replace your test set. A typical workflow:

1.  Split off a test set and don't touch it.
2.  Use cross-validation on the training set to compare models and settings.
3.  Score the final choice on the test set once.

On a small dataset, people sometimes cross-validate on all the data and skip the test set. That's fine for learning, but in a real project, keep the test set.

## Overfitting and underfitting

A model **underfits** when it is too simple to capture the pattern. Training and validation scores are both low. A model **overfits** when it memorizes the training rows, noise included. The training score is high, the validation score is noticeably lower, and that gap is the warning sign.

A decision tree makes this easy to see, because `max_depth` sets how complex it can get. `validation_curve` cross-validates the model once for each value of one hyperparameter and returns training and validation scores:

```python
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import StratifiedKFold, validation_curve
from sklearn.tree import DecisionTreeClassifier

X, y = load_breast_cancer(return_X_y=True)
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
depths = [1, 2, 3, 4, 6, 8, 12]

train_scores, val_scores = validation_curve(
    DecisionTreeClassifier(random_state=0), X, y,
    param_name="max_depth", param_range=depths,
    cv=cv, scoring="accuracy",
)

print("depth  train  valid  gap")
for d, tr, va in zip(depths, train_scores.mean(axis=1), val_scores.mean(axis=1)):
    print(f"{d:>5}  {tr:.3f}  {va:.3f}  {tr - va:.3f}")
```

```text
depth  train  valid  gap
    1  0.925  0.888  0.037
    2  0.956  0.905  0.050
    3  0.972  0.917  0.054
    4  0.987  0.928  0.059
    6  0.996  0.923  0.073
    8  1.000  0.916  0.084
   12  1.000  0.916  0.084
```

Both arrays have shape `(n_values, n_folds)`, so `.mean(axis=1)` averages over the folds. If you plotted depth on the x-axis, you would see the training line climb steadily to 1.0. The validation line rises to a peak at depth 4 and then sags a little. To the left of the peak the tree underfits. To the right, it is memorizing: perfect on the rows it trained on, and no better (actually slightly worse) on new ones. The best setting is around the peak, where validation is highest. Training is not the score to maximize.

## Learning curves: would more data help?

A **learning curve** fixes the model and changes how much training data it gets. It answers a practical question: should you go collect more data, or change the model?

```python
import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import StratifiedKFold, learning_curve
from sklearn.tree import DecisionTreeClassifier

X, y = load_breast_cancer(return_X_y=True)
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)

sizes, train_scores, val_scores = learning_curve(
    DecisionTreeClassifier(random_state=0), X, y,
    train_sizes=np.linspace(0.1, 1.0, 5), cv=cv, scoring="accuracy",
)

print("n_train  train  valid")
for n, tr, va in zip(sizes, train_scores.mean(axis=1), val_scores.mean(axis=1)):
    print(f"{n:>7}  {tr:.3f}  {va:.3f}")
```

```text
n_train  train  valid
     45  1.000  0.802
    147  1.000  0.868
    250  1.000  0.903
    352  1.000  0.909
    455  1.000  0.916
```

The unlimited-depth tree scores a perfect 1.000 on its training data at every size. That's overfitting in its purest form. Validation keeps climbing as data grows, but it flattens out after about 250 rows. On a plot, the two lines would still be far apart at the right edge.

How to read the shapes:

-   **Big gap that keeps shrinking:** high variance. More data helps, and so does a simpler or regularized model.
-   **Both lines low and close together:** high bias, so the model is underfitting. More data won't fix it. Use a more flexible model or better features.
-   **Both lines high and close together:** you're in good shape.

:::warning
A tiny standard deviation doesn't make a score trustworthy if the folds leak. Make sure every preprocessing step lives inside the pipeline you pass to `cross_val_score`, `validation_curve`, or `learning_curve`.
:::

## Common mistakes

-   Reporting the best fold instead of the mean.
-   Leaving out the ± std, so nobody can tell whether a 0.005 difference between two models means anything.
-   Using plain `KFold` without shuffling on data sorted by class.
-   Tuning `max_depth` by looking at test-set scores. Use the validation curve for that.
