Here is a decision tree trained on the breast cancer data 30 times. The model, its settings, and the data never change. The only thing that changes is `random_state` in `train_test_split`, which decides which 25% of tumors land in the test set. Before you run it, guess how far apart the best and worst test accuracy will be.

```python run alt="Histogram of test accuracy for one decision tree over 30 random splits, spread from about 0.86 to 0.97" caption="Same model, same data, 30 different answers"
import matplotlib.pyplot as plt
import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

X, y = load_breast_cancer(return_X_y=True)
tree = DecisionTreeClassifier(max_depth=4, random_state=0)

scores = []
for seed in range(30):
    X_tr, X_te, y_tr, y_te = train_test_split(
        X, y, test_size=0.25, stratify=y, random_state=seed)
    scores.append(tree.fit(X_tr, y_tr).score(X_te, y_te))
scores = np.array(scores)
print(f"worst split {scores.min():.3f}, best split {scores.max():.3f}")

plt.figure(figsize=(7, 2.6))
plt.hist(scores, bins=12, color="#4c72b0", edgecolor="white")
plt.xlabel("test accuracy")
plt.ylabel("number of splits")
plt.title("One tree, 30 random train/test splits")
```

Eleven points separate the luckiest split from the unluckiest one. If you had run this once and written "my tree is 86% accurate," you'd be reporting the split, not the model. A single test score is one draw from that histogram. This week is about drawing several on purpose and reporting what they say together.

## Let every row take a turn as the test

Here's the intuition. Instead of one exam, give the model five, and make sure no question is ever on two of them. Each exam is graded by a model that never studied those questions. The average tells you how good the model is; the spread tells you how much to trust the average.

Now precisely. **k-fold cross-validation** cuts the rows into *k* equal parts called **folds**. In round 1 the model trains on folds 2 to k and is scored on fold 1. In round 2 it trains on everything except fold 2 and is scored on fold 2, and so on. After k rounds, every row has been used for validation exactly once and for training k − 1 times, and you have k scores.

For classifiers, use `StratifiedKFold`, which keeps the class mix roughly the same in every fold, and turn on `shuffle=True`. Let's look at what it actually hands back:

```python run alt="Five horizontal bands, one per round. In each band a different scattered fifth of the 569 rows is shaded dark, and no row is dark in two bands." caption="Each round holds out a different fifth of the rows"
from sklearn.model_selection import StratifiedKFold

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
held_out = np.zeros((5, len(y)))
for round_no, (train_idx, val_idx) in enumerate(cv.split(X, y)):
    held_out[round_no, val_idx] = 1
    print(f"round {round_no + 1}: train on {len(train_idx)}, validate on {len(val_idx)}, "
          f"{y[val_idx].mean():.1%} benign in the validation fold")

plt.figure(figsize=(8, 2.2))
plt.imshow(held_out, aspect="auto", cmap="Blues", interpolation="nearest")
plt.yticks(range(5), [f"round {i + 1}" for i in range(5)])
plt.xlabel("row number in the dataset")
```

`cv.split` yields pairs of index arrays, one pair per round. Notice the last number on each line: every validation fold is 62% to 63% benign, matching the full dataset's 62.7%, because the splitter is stratified. Shuffling is why the dark rows are scattered rather than five solid blocks.

You'll rarely loop over `cv.split` yourself. `cross_val_score` does the fitting and scoring for you:

```python run
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

pipe = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
fold_scores = cross_val_score(pipe, X, y, cv=cv, scoring="accuracy")
print("fold scores:", fold_scores.round(3))
print(f"accuracy = {fold_scores.mean():.3f} ± {fold_scores.std():.3f}")
```

Report the **mean** as your estimate and the **standard deviation** as its wobble: "about 0.97, give or take 0.02." The fold scores run from 0.947 to 0.991, so a single unlucky split could have reported either end.

Two details in that cell matter more than they look:

-   **The pipeline goes in, not a pre-scaled `X`.** `cross_val_score` refits the whole pipeline in each round, so the scaler learns its means only from that round's training rows. Scale `X` first and every validation fold has already shaped the scaler.
-   **`cv` is an object you keep.** Pass the same `cv` to every model you try and they're all graded on identical folds. That's what makes next week's comparisons fair.

```mermaid caption="Cross-validation happens inside the training set; the test set waits for the end"
flowchart LR
    A[All rows] --> B[Training set]
    A --> T[("Test set, locked")]
    B --> C["5-fold CV: compare models, choose settings"]
    C --> D[Refit the winner on all training rows]
    D --> E[Score on the test set once]
    T --> E
```

Cross-validation doesn't replace the test set. You use CV to make choices, and because you made choices with it, its scores end up slightly flattering. The untouched test set is the final, unbiased check.

## Overfitting and underfitting on a validation curve

A model **underfits** when it's too simple for the pattern: think of a student who learned one rule and applies it to everything. Training and validation scores are both low. A model **overfits** when it memorizes the training rows, quirks included, like a student who memorized last year's answer key. Training is high, validation is noticeably lower, and that **gap** is the warning sign.

A tree's `max_depth` is a dial from "one rule" to "memorize everything." `validation_curve` cross-validates the model once per dial setting and returns train and validation scores, each shaped `(settings, folds)`:

```python run alt="Line chart of mean accuracy against tree depth. Training accuracy climbs steadily to 1.0. Validation accuracy rises to a peak of about 0.93 at depths 4 and 5, then sags to about 0.92 while the gap grows." caption="Training keeps improving; validation stops"
from sklearn.model_selection import validation_curve

depths = [1, 2, 3, 4, 5, 6, 8, 12]
train_sc, val_sc = validation_curve(
    DecisionTreeClassifier(random_state=0), X, y,
    param_name="max_depth", param_range=depths, cv=cv, scoring="accuracy")

tr_mean, va_mean, va_std = train_sc.mean(axis=1), val_sc.mean(axis=1), val_sc.std(axis=1)
for d, tr, va in zip(depths, tr_mean, va_mean):
    print(f"depth {d:>2}: train {tr:.3f}  valid {va:.3f}  gap {tr - va:.3f}")

plt.figure(figsize=(7, 3.4))
plt.plot(depths, tr_mean, "o-", label="training")
plt.plot(depths, va_mean, "o-", label="validation")
plt.fill_between(depths, va_mean - va_std, va_mean + va_std, alpha=0.2, color="C1")
plt.xlabel("max_depth")
plt.ylabel("mean accuracy over 5 folds")
plt.legend()
```

`.mean(axis=1)` averages across the five folds for each depth, and the shaded band is ±1 std of the validation scores. Read it left to right. At depth 1 both lines are lowest: underfitting. The validation line peaks at depths 4 and 5 (0.928) and then sags, while training keeps climbing to a perfect 1.000. Every extra level after the peak is spent memorizing. Pick the setting at the validation peak, and if a few settings are within the shaded band of each other, prefer the simplest.

## Learning curves: would more data help?

A validation curve changes the model. A **learning curve** keeps the model fixed and changes how many training rows it gets. It answers a question that can save you weeks: should you collect more data, or change the model?

```python run alt="Two learning-curve panels. Left, a deep tree: training accuracy is flat at 1.0 while validation rises from about 0.80 to 0.92, leaving a wide gap. Right, a one-split stump: after about 150 rows, training sits near 0.93 and validation near 0.89 to 0.90, and neither moves." caption="Two models, two very different diagnoses"
from sklearn.model_selection import learning_curve

fig, axes = plt.subplots(1, 2, figsize=(9, 3.2), sharey=True)
for ax, depth, title in [(axes[0], None, "deep tree (no depth limit)"),
                         (axes[1], 1, "stump (max_depth=1)")]:
    sizes, tr, va = learning_curve(
        DecisionTreeClassifier(max_depth=depth, random_state=0), X, y,
        train_sizes=np.linspace(0.1, 1.0, 5), cv=cv, scoring="accuracy")
    ax.plot(sizes, tr.mean(axis=1), "o-", label="training")
    ax.plot(sizes, va.mean(axis=1), "o-", label="validation")
    ax.set_title(title)
    ax.set_xlabel("training rows")
    print(f"{title:<26} at {sizes[-1]} rows: train {tr.mean(axis=1)[-1]:.3f}, valid {va.mean(axis=1)[-1]:.3f}")
axes[0].set_ylabel("accuracy")
axes[0].legend()
```

The two panels are the two classic shapes:

-   **Left, high variance.** The deep tree scores 1.000 on its own rows at every size. Validation climbs as rows are added, but a wide gap remains. More data would help a bit; a simpler or averaged model (a random forest, next week) would help more.
-   **Right, high bias.** The stump's two lines settle a few points apart after about 150 rows and stop moving, and even its training score is stuck near 0.93. Doubling the data won't help, because one split can't express a better rule. The fix is a more flexible model or better features.

The good shape is the third one: both lines high and close together.

:::warning
**Three mistakes that make cross-validation lie.**
1. Preprocessing outside the pipeline. `StandardScaler().fit_transform(X)` before `cross_val_score` lets every validation fold leak into the scaler. Put every step in the pipeline you pass in.
2. Reporting the best fold. The best of five is luck; report the mean and the std.
3. Choosing a setting by training score. The training line on a validation curve always rewards the most complex model. Choose by validation.
:::

:::quiz
Q: On the same five folds, model A scores 0.951 ± 0.020 and model B scores 0.957 ± 0.025. What's the most defensible conclusion?
- [ ] B is better, because its mean is higher
  A 0.006 gap is far smaller than either model's fold-to-fold wobble, so the means alone can't separate them.
- [x] They're effectively tied; look at the per-fold scores before claiming a winner
  Because the folds are shared, you can check how many folds each model wins. If it's 3 to 2, nobody is ahead.
- [ ] A is better, because its std is smaller
  A slightly smaller std means slightly steadier scores, not better ones. With a lower mean, that's not a win.

Q: A learning curve shows training accuracy fixed at 1.00 while validation climbs from 0.80 to 0.90 and is still rising at the largest size. What's the most promising next step?
- [ ] Switch to a more flexible model
  The model is already memorizing its training rows. More flexibility would widen the gap.
- [x] Get more data, or constrain the model
  A big gap with validation still rising is high variance. More rows or a simpler, regularized model both attack it.
- [ ] Nothing; a rising curve means the model is finished
  Rising at the right edge means it hasn't finished improving, and the gap says it's overfitting.

Q: Your notebook runs `X_scaled = StandardScaler().fit_transform(X)` and then `cross_val_score(LogisticRegression(), X_scaled, y, cv=cv)`. What's wrong?
- [ ] Nothing, because scaling doesn't look at the labels
  It doesn't use labels, but it does use every row's feature values, including the rows that will be validation folds.
- [x] Each validation fold helped compute the scaling, so the folds aren't truly unseen
  Put the scaler in a pipeline and pass the pipeline, so each round fits the scaler on its training rows only.
- [ ] It crashes, because `cross_val_score` needs unscaled data
  It runs without complaint, which is exactly why this leak is easy to miss.

Q: The validation curve above gives depth 3 → 0.917, depth 4 → 0.928, depth 5 → 0.928, depth 8 → 0.916, with validation std around 0.02. Which depth would you choose?
- [ ] 8, because deeper trees fit the training data best
  Training fit is not the goal. Depth 8 is more complex and scores lower on validation.
- [x] 4, or even 3: the simplest settings near the peak
  Depths 3 to 5 are within one std of each other, so take the simplest tree near the peak. It's easier to explain and usually steadier on new data.
- [ ] Whichever depth gives the best test-set score
  Choosing with the test set turns it into a second validation set, and then no unbiased score is left.
:::

:::takeaways
- One train/test split is one draw from a wide distribution. Cross-validation takes k draws and reports mean ± std.
- Use `StratifiedKFold(shuffle=True, random_state=...)` for classifiers, make it once, and reuse it everywhere.
- Pass the whole pipeline to `cross_val_score`, `validation_curve`, and `learning_curve` so preprocessing is refit inside every fold.
- On a validation curve, choose by the validation line and prefer the simplest setting near its peak.
- A learning curve with a big, shrinking gap says variance (more data or a simpler model); two low lines that meet say bias (a more flexible model).
- Cross-validation is for choosing. The test set is still scored once, at the end.
:::
