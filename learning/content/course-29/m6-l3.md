:::objectives
- Name hyperparameters correctly inside a pipeline and find valid names with `get_params()`.
- Count the fits a search will run before you start it.
- Show why models must share folds, using paired fold differences.
- Tune preprocessing steps and model settings in the same search.
- Sample scale-type hyperparameters with `loguniform`, and extend a range when the best value lands on its edge.
- Compare two tuned procedures fairly with nested cross-validation.
:::

Most hyperparameter-search bugs aren't math bugs. They're a misspelled parameter name, a grid that would take three hours, or an "improvement" that turns out to be fold-shuffling noise. Each exercise below goes after one of those. Every solution runs on a bundled dataset.

## Warm-up: learned or chosen?

Sort these into **parameters** (learned by `fit`) and **hyperparameters** (chosen before `fit`): a logistic regression's `coef_`, its `C`, a tree's `max_depth`, the threshold at a tree's first split, and a forest's `n_estimators`. Then run this to check two of them:

```python run
from sklearn.datasets import load_breast_cancer
from sklearn.linear_model import LogisticRegression

X, y = load_breast_cancer(return_X_y=True)
model = LogisticRegression(C=0.5, max_iter=10000)
print("chosen before fit:", model.get_params()["C"])
print("has coef_ before fit?", hasattr(model, "coef_"))
model.fit(X, y)
print("learned by fit: coef_ with shape", model.coef_.shape)
```

`C`, `max_depth`, and `n_estimators` are hyperparameters. `coef_` and the split threshold are parameters. scikit-learn marks the difference in the names: anything that ends in an underscore exists only after `fit`.

### Exercise 1: Fix the parameter name

This search crashes:

```python run raises
from sklearn.datasets import load_wine
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import GridSearchCV
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_wine(return_X_y=True)
pipe = Pipeline([("scale", StandardScaler()),
                 ("clf", LogisticRegression(max_iter=5000))])
GridSearchCV(pipe, {"C": [0.1, 1, 10]}, cv=5).fit(X, y)
```

Use `pipe.get_params()` to find the right name for `C`, fix the grid, and print the best parameters and score.

:::hint
The prefix is whatever *you* named the step, followed by two underscores. Filter the keys of `pipe.get_params()` for ones that end in `C`.
:::

:::solution
```python run
from sklearn.datasets import load_wine
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import GridSearchCV
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_wine(return_X_y=True)
pipe = Pipeline([("scale", StandardScaler()),
                 ("clf", LogisticRegression(max_iter=5000))])
print("names ending in C:", [k for k in pipe.get_params() if k.endswith("__C")])

search = GridSearchCV(pipe, {"clf__C": [0.1, 1, 10]}, cv=5).fit(X, y)
print("best:", search.best_params_, round(search.best_score_, 3))
```

The step is called `clf`, so the name is `clf__C`, not `model__C`. With `make_pipeline` it would be `logisticregression__C`. Naming every estimator step `"model"` in your own projects means you never have to look it up.
:::

### Exercise 2: Budget a grid before you run it

A teammate proposes this grid for a random forest with 5-fold CV:

```python
grid = {
    "model__n_estimators": [100, 300, 500],
    "model__max_depth": [3, 5, 8, None],
    "model__min_samples_leaf": [1, 5, 10],
    "model__max_features": ["sqrt", 0.5],
}
```

Without fitting anything, compute the number of settings, the number of fits, and the total number of trees grown. Check your arithmetic with `sklearn.model_selection.ParameterGrid`.

:::hint
Settings are the product of the list lengths. Fits are settings × folds, plus 1 for the final refit. For trees, add up `n_estimators` over every setting rather than multiplying by one number.
:::

:::solution
```python run
from sklearn.model_selection import ParameterGrid

grid = {
    "model__n_estimators": [100, 300, 500],
    "model__max_depth": [3, 5, 8, None],
    "model__min_samples_leaf": [1, 5, 10],
    "model__max_features": ["sqrt", 0.5],
}
settings = list(ParameterGrid(grid))
k = 5
trees = sum(s["model__n_estimators"] for s in settings) * k
print("settings:", len(settings))
print("fits:", len(settings) * k, "+ 1 refit")
print(f"trees grown during the search: {trees:,}")
```

3 × 4 × 3 × 2 = 72 settings and 360 fits, which grows more than a hundred thousand trees. That's a long wait on a free Colab machine. Replace it with `RandomizedSearchCV(..., n_iter=15)` and you pay for 75 fits instead, while still trying 15 different combinations.
:::

### Exercise 3: Paired folds versus mismatched folds

On breast cancer, compare `DecisionTreeClassifier(max_depth=4, random_state=0)` with `RandomForestClassifier(n_estimators=100, random_state=0)` using one shared `StratifiedKFold(5, shuffle=True, random_state=3)`. Print the per-fold difference (forest − tree) and how many folds the forest wins. Then cross-validate the *tree* again with `random_state=99` folds and compare its two means. What does that second comparison tell you?

:::hint
`cross_val_score` returns arrays in fold order, so `f - t` subtracts fold 1 from fold 1, fold 2 from fold 2, and so on. For the second part, the model is identical; only the folds change.
:::

:::solution
```python run
from sklearn.datasets import load_breast_cancer
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import StratifiedKFold, cross_val_score
from sklearn.tree import DecisionTreeClassifier

X, y = load_breast_cancer(return_X_y=True)
tree = DecisionTreeClassifier(max_depth=4, random_state=0)
forest = RandomForestClassifier(n_estimators=100, random_state=0)

shared = StratifiedKFold(n_splits=5, shuffle=True, random_state=3)
t = cross_val_score(tree, X, y, cv=shared)
f = cross_val_score(forest, X, y, cv=shared)
print("same folds")
print("  forest - tree per fold:", (f - t).round(3))
print(f"  forest wins {(f > t).sum()} of 5, mean gain {(f - t).mean():.3f}")

t_other = cross_val_score(tree, X, y, cv=StratifiedKFold(5, shuffle=True, random_state=99))
print("different folds, same tree")
print(f"  tree mean: {t.mean():.3f} (seed 3) vs {t_other.mean():.3f} (seed 99)")
```

Re-shuffling the folds moves the *same tree* by about as much as the forest's whole advantage. Score two models on different folds and you can't tell skill from luck. On shared folds, the forest's consistent fold-by-fold wins are the real evidence.
:::

### Exercise 4: Tune a preprocessing step

Copy the breast cancer features and blank out about 10% of values at random (`np.random.default_rng(0)`, `rng.random(X.shape) < 0.10`). Build `Pipeline([("impute", SimpleImputer()), ("scale", StandardScaler()), ("model", LogisticRegression(max_iter=5000))])` and grid-search **both** `impute__strategy` (`"mean"`, `"median"`) and `model__C` (0.1, 1, 10) using F1. Print all six results.

:::hint
A pipeline step's settings are tunable the same way as the model's: `impute__strategy`. Loop over `zip(search.cv_results_["params"], search.cv_results_["mean_test_score"])` to print each setting with its score.
:::

:::solution
```python run
import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import GridSearchCV, StratifiedKFold
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_breast_cancer(return_X_y=True)
rng = np.random.default_rng(0)
X = X.copy()
X[rng.random(X.shape) < 0.10] = np.nan
print(f"missing values: {np.isnan(X).mean():.1%}")

pipe = Pipeline([("impute", SimpleImputer()),
                 ("scale", StandardScaler()),
                 ("model", LogisticRegression(max_iter=5000))])
grid = {"impute__strategy": ["mean", "median"], "model__C": [0.1, 1, 10]}
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
search = GridSearchCV(pipe, grid, cv=cv, scoring="f1").fit(X, y)

for p, m in zip(search.cv_results_["params"], search.cv_results_["mean_test_score"]):
    print(f"{p['impute__strategy']:>6}  C={p['model__C']:<4}  F1 {m:.4f}")
print("best:", search.best_params_)
```

Because the imputer sits inside the pipeline, each fold computes its means or medians from its own training rows. All six scores land within about one point of each other, so the imputation choice barely matters here. "This choice didn't matter" is a finding worth writing down; it tells the next person not to waste time on it.
:::

### Exercise 5: Sample C on a log scale

Draw 200 values from `loguniform(1e-3, 1e2)` and 200 from `uniform(1e-3, 100)` (note that scipy's `uniform` takes `loc` and `scale`, so this means `uniform(loc=0.001, scale=100)`). Use `random_state=0` for both. For each, print how many draws fall below 1, and plot histograms of `np.log10` of the draws. Which one would you hand to `RandomizedSearchCV` for `C`, and why?

:::hint
Call `.rvs(size=200, random_state=0)` on each distribution. On a log10 axis, the range 0.001 to 100 spans five equal-width decades, from −3 to 2.
:::

:::solution
```python run alt="Two histograms of log10 of sampled C values. The loguniform draws spread evenly from minus 3 to 2. The uniform draws pile up between 1 and 2, with a single draw below 0 and none below minus 1." caption="uniform wastes nearly every draw on large C"
import matplotlib.pyplot as plt
import numpy as np
from scipy.stats import loguniform, uniform

log_draws = loguniform(1e-3, 1e2).rvs(size=200, random_state=0)
lin_draws = uniform(loc=1e-3, scale=100).rvs(size=200, random_state=0)
print("loguniform:", (log_draws < 1).sum(), "of 200 draws below C = 1")
print("uniform:   ", (lin_draws < 1).sum(), "of 200 draws below C = 1")

fig, axes = plt.subplots(1, 2, figsize=(8, 2.8), sharey=True)
for ax, draws, title in [(axes[0], log_draws, "loguniform(1e-3, 1e2)"),
                         (axes[1], lin_draws, "uniform(0.001, 100)")]:
    ax.hist(np.log10(draws), bins=20, range=(-3, 2), color="#7f9cc9", edgecolor="white")
    ax.set_title(title)
    ax.set_xlabel("log10(C)")
axes[0].set_ylabel("draws")
```

`loguniform` gives each decade the same share of draws, so 0.001 to 0.01 is explored as thoroughly as 10 to 100. Plain `uniform` put just one of its 200 draws below 1, so it would almost never test the small, strongly regularized values that often win. Use `loguniform` for anything that acts like a scale: `C`, learning rates, regularization strengths.
:::

### Exercise 6: The best value is on the edge

On `load_wine`, grid-search a scaled logistic regression over `model__C` in `[0.0001, 0.001, 0.01]` with five shuffled, stratified folds (`random_state=0`). Write a check that prints a warning when the best value is the smallest or largest in the grid. Then extend the grid in the direction the warning points and search again.

:::hint
Compare `search.best_params_["model__C"]` with `min(values)` and `max(values)`. If the best is at the top, add larger values (0.1, 1, 10, 100) and keep the old top value in the new grid so you can see the curve turn.
:::

:::solution
```python run
from sklearn.datasets import load_wine
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import GridSearchCV, StratifiedKFold
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_wine(return_X_y=True)
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
pipe = Pipeline([("scale", StandardScaler()),
                 ("model", LogisticRegression(max_iter=5000))])


def search_c(values):
    search = GridSearchCV(pipe, {"model__C": values}, cv=cv).fit(X, y)
    best = search.best_params_["model__C"]
    scores = search.cv_results_["mean_test_score"].round(3)
    print(f"C values {values}\n  scores {scores}  best C = {best}")
    if best in (min(values), max(values)):
        print("  WARNING: best value is on the edge of the range; extend it")
    return best


search_c([0.0001, 0.001, 0.01])
search_c([0.01, 0.1, 1, 10, 100])
```

The first grid rises at every step and stops at its last value, so "best C = 0.01" really means "at least 0.01." The extended grid shows the curve climbing to a peak at C = 0.1 and easing off after it, with the best value now safely inside the range. Run this edge check after every search in your capstone; it costs one line.
:::

### Challenge: nested CV for two tuned models

Wrap a tuned logistic regression (`model__C` in `[0.01, 0.1, 1, 10]`, with scaling) and a tuned random forest (`n_estimators=60`; `model__max_depth` in `[4, None]`, `model__min_samples_leaf` in `[1, 3]`) each in a `GridSearchCV` with three inner folds. Score both with the **same** five outer folds using `cross_val_score` and ROC AUC on breast cancer. Print each nested AUC and the per-outer-fold difference. Use the diagram below to keep the two loops straight.

:::hint
A `GridSearchCV` object is itself an estimator, so you can pass it straight to `cross_val_score(search, X, y, cv=outer)`. Each outer round runs the whole inner search on that round's training rows.
:::

:::solution
```python run
from sklearn.datasets import load_breast_cancer
from sklearn.ensemble import RandomForestClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import GridSearchCV, StratifiedKFold, cross_val_score
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_breast_cancer(return_X_y=True)
inner = StratifiedKFold(n_splits=3, shuffle=True, random_state=0)
outer = StratifiedKFold(n_splits=5, shuffle=True, random_state=1)

candidates = {
    "logistic": GridSearchCV(
        Pipeline([("scale", StandardScaler()),
                  ("model", LogisticRegression(max_iter=5000))]),
        {"model__C": [0.01, 0.1, 1, 10]}, cv=inner, scoring="roc_auc"),
    "forest": GridSearchCV(
        Pipeline([("model", RandomForestClassifier(n_estimators=60, random_state=0))]),
        {"model__max_depth": [4, None], "model__min_samples_leaf": [1, 3]},
        cv=inner, scoring="roc_auc"),
}
outer_scores = {}
for name, search in candidates.items():
    outer_scores[name] = cross_val_score(search, X, y, cv=outer, scoring="roc_auc")
    s = outer_scores[name]
    print(f"{name:>8}: nested AUC {s.mean():.4f} ± {s.std():.4f}")

diff = outer_scores["logistic"] - outer_scores["forest"]
print("logistic - forest per outer fold:", diff.round(4))
```

Logistic regression wins every outer fold, so as a whole *procedure*, tuning included, it's the better choice on this data. Count the cost: 5 outer rounds × (4 + 4 settings) × 3 inner folds is 120 fits, plus refits. That's why nested CV is usually saved for final, high-stakes comparisons.
:::

```mermaid caption="Nested cross-validation: the inner loop chooses, the outer loop grades"

    B --> C[Outer training rows]

    D --> E[Refit that setting on the outer training rows]
    E --> F[Score on the held-out outer fold]

    G -->|no| H["Report mean ± std of the 5 outer scores"]
```
