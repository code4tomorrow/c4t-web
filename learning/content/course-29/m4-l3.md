Metrics are easy to compute and easy to misread. Most of these exercises hide a trap, the kind that turns up in real projects and in other people's reports. Do Exercise 1 on paper before touching code: if you can do it by hand, you'll never mix up precision and recall again. Use one notebook and run the cells in order.

## Warm-up: the order of `ravel()`

Predict the four numbers before you run this. Remember that rows are the true class, columns are the predicted class, and positive is 1:

```python run
from sklearn.metrics import confusion_matrix

actual    = [0, 1, 1, 0, 1, 1]
predicted = [0, 1, 0, 1, 0, 1]
tn, fp, fn, tp = confusion_matrix(actual, predicted).ravel()
print("TN", tn, "FP", fp, "FN", fn, "TP", tp)
```

Pair them up: (0,0) is a true negative, (1,1) twice is two true positives, (1,0) twice is two misses, and (0,1) once is one false alarm. `ravel()` reads the grid row by row, which is why the order is always TN, FP, FN, TP.

### Exercise 1: By hand first

A model's confusion matrix (rows = true class, columns = predicted, positive class = 1) is:

```text
[[50 10]
 [ 5 35]]
```

On paper, compute accuracy, precision, recall, and F1. Then check your answers by building label arrays that produce this matrix and calling scikit-learn's functions.

:::hint
First name the four cells: top-left is TN, top-right FP, bottom-left FN, bottom-right TP. To rebuild labels, you need 60 true 0s (50 predicted 0, 10 predicted 1) and 40 true 1s (5 predicted 0, 35 predicted 1).
:::

:::solution
TN = 50, FP = 10, FN = 5, TP = 35, for 100 rows in total.

- Accuracy = (35 + 50) / 100 = 0.85
- Precision = 35 / (35 + 10) = 0.778
- Recall = 35 / (35 + 5) = 0.875
- F1 = 2 × 0.778 × 0.875 / (0.778 + 0.875) = 0.824

```python run
import numpy as np
from sklearn.metrics import accuracy_score, f1_score, precision_score, recall_score

y_true = np.array([0] * 60 + [1] * 40)
y_hat = np.array([0] * 50 + [1] * 10 + [0] * 5 + [1] * 35)

print(confusion_matrix(y_true, y_hat))
print("accuracy ", accuracy_score(y_true, y_hat))
print("precision", round(precision_score(y_true, y_hat), 3))
print("recall   ", round(recall_score(y_true, y_hat), 3))
print("F1       ", round(f1_score(y_true, y_hat), 3))
```

Precision and recall share the numerator, TP. The only difference is the denominator: everything the model *flagged* (precision) versus everything that was *really* positive (recall).
:::

### Exercise 2: Which class is positive?

In the original breast cancer labels, `0` is malignant and `1` is benign. Train `DecisionTreeClassifier(max_depth=1, random_state=0)` on all 30 features (`test_size=0.25`, `stratify=y`, `random_state=1`). Print recall with the default settings, then with `pos_label=0`. Which number should a doctor care about?

:::hint
`recall_score(y_test, pred)` measures recall for whichever class is labeled 1. Adding `pos_label=0` measures it for class 0 instead. Same predictions, different question.
:::

:::solution
```python run
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

X, y = load_breast_cancer(return_X_y=True)   # 0 = malignant, 1 = benign
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=1
)
pred = DecisionTreeClassifier(max_depth=1, random_state=0).fit(X_train, y_train).predict(X_test)
print("recall, default pos_label=1 (benign):", round(recall_score(y_test, pred), 3))
print("recall, pos_label=0 (malignant):     ", round(recall_score(y_test, pred, pos_label=0), 3))
```

The default reports how many **healthy** patients were correctly cleared, which sounds great. The number a doctor needs is malignant recall: this one-question tree misses about one cancer in five. Same predictions, very different story, all from which class counts as positive. Pass `pos_label`, or flip the labels as the Notes did.
:::

### Exercise 3: The accuracy paradox

Make a dataset where only about 3% of rows are positive:

```python run
from sklearn.datasets import make_classification

X_rare, y_rare = make_classification(n_samples=2000, n_features=6, weights=[0.97, 0.03],
                                     random_state=2)
print("Positive share:", y_rare.mean())
```

Split it (`test_size=0.3`, `stratify=y_rare`, `random_state=0`). For a default `DummyClassifier` and a default `LogisticRegression`, print accuracy, recall, and F1 (pass `zero_division=0` to F1). Which model does accuracy say is better? Which is actually more useful?

:::hint
Loop over the two models, fit each on the training rows, predict the test rows, and print all three metrics on one line so the comparison is side by side.
:::

:::solution
```python run
from sklearn.dummy import DummyClassifier
from sklearn.linear_model import LogisticRegression

Xr_train, Xr_test, yr_train, yr_test = train_test_split(
    X_rare, y_rare, test_size=0.3, stratify=y_rare, random_state=0
)
for name, clf in [("dummy", DummyClassifier()), ("logistic", LogisticRegression())]:
    pred = clf.fit(Xr_train, yr_train).predict(Xr_test)
    print(f"{name:8s} accuracy {accuracy_score(yr_test, pred):.3f}  "
          f"recall {recall_score(yr_test, pred):.3f}  "
          f"F1 {f1_score(yr_test, pred, zero_division=0):.3f}")
```

Accuracy calls the dummy the winner, by a hair. But the dummy never predicts positive, so its recall and F1 are 0: it has never found a single positive case. Logistic regression at least finds some. With rare classes, accuracy mostly measures how rare the class is. The logistic model's low recall also suggests lowering its threshold, which is the next exercise. Week 6 brings more tools for imbalance.
:::

### Exercise 4: Write your own predict

Rebuild the two-feature screening model from the Notes (`mean radius` and `mean texture`, labels flipped so 1 = malignant, `test_size=0.25`, `stratify=y`, `random_state=0`, `StandardScaler` plus `LogisticRegression`). Write `predict_with_threshold(model, X, threshold)`. Check that it matches `model.predict` at 0.5, then print confusion matrices at 0.5 and 0.25. How many extra cancers does 0.25 catch, and at what price?

:::hint
Your function needs one line: compare column 1 of `model.predict_proba(X)` with the threshold, and turn the True/False result into 1/0 with `.astype(int)`.
:::

:::solution
```python run
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

data = load_breast_cancer(as_frame=True)
X2 = data.data[["mean radius", "mean texture"]]
y2 = 1 - data.target
X2_train, X2_test, y2_train, y2_test = train_test_split(
    X2, y2, test_size=0.25, stratify=y2, random_state=0
)
screen = make_pipeline(StandardScaler(), LogisticRegression()).fit(X2_train, y2_train)

def predict_with_threshold(model, X, threshold):
    return (model.predict_proba(X)[:, 1] >= threshold).astype(int)

same = (predict_with_threshold(screen, X2_test, 0.5) == screen.predict(X2_test)).all()
print("Matches predict() at 0.5:", same)
for t in [0.5, 0.25]:
    print(f"threshold {t}:")
    print(confusion_matrix(y2_test, predict_with_threshold(screen, X2_test, t)))
```

Lowering the threshold to 0.25 shrinks the bottom-left cell (missed cancers) by 3 and grows the top-right cell (false alarms) by 11. Whether 3 caught cancers are worth 11 extra scans is a judgment about costs, not a math question. The final exercise makes that judgment with numbers.
:::

### Exercise 5: Three classes

Train `KNeighborsClassifier()` on only the first two wine features, alcohol and malic acid (`test_size=0.3`, `stratify=y`, `random_state=0`). Draw the 3×3 confusion matrix with `ConfusionMatrixDisplay` and print a classification report. Which class is hardest, and which pair of classes gets mixed up most?

:::hint
In a multi-class matrix, each class gets its own precision and recall, treating that class as positive and the other two together as negative. Look for the largest number **off** the diagonal.
:::

:::solution
```python run alt="Three-by-three confusion matrix for k-NN on two wine features. Class 0 row: 13 correct, 1 predicted as class 1, 4 predicted as class 2. Class 1 row: 20 correct, 1 predicted as class 2. Class 2 row: 2 predicted as class 0, 2 as class 1, 11 correct." caption="The 4 in the top-right corner is the biggest confusion: class-0 wines predicted as class 2."
import matplotlib.pyplot as plt
from sklearn.datasets import load_wine
from sklearn.metrics import ConfusionMatrixDisplay, classification_report
from sklearn.neighbors import KNeighborsClassifier

Xw, yw = load_wine(return_X_y=True)
Xw = Xw[:, [0, 1]]   # only alcohol and malic_acid, so the model makes mistakes
Xw_train, Xw_test, yw_train, yw_test = train_test_split(
    Xw, yw, test_size=0.3, stratify=yw, random_state=0
)
wine_pred = KNeighborsClassifier().fit(Xw_train, yw_train).predict(Xw_test)

fig, ax = plt.subplots(figsize=(4.2, 3.6))
ConfusionMatrixDisplay.from_predictions(yw_test, wine_pred, cmap="Blues", colorbar=False, ax=ax)
plt.show()
print(classification_report(yw_test, wine_pred, digits=3))
```

Class 2 is hardest, with the lowest F1. The biggest single confusion is 4 class-0 wines predicted as class 2, top right of the matrix: both classes are high in alcohol, so with only these two features they overlap. Class 1 (low alcohol) is easy. Macro avg comes out a little below weighted avg, because the weakest class is also the smallest.
:::

### Exercise 6: Compare models before choosing a threshold

On the screening split from Exercise 4 (labels flipped, same `random_state=0`), compare the two-feature model with a logistic regression that uses **all 30 features**. Don't pick a threshold: plot both models' precision-recall curves on one chart, and print each model's average precision and ROC AUC. Which model would you deploy, and does the answer depend on which threshold you later choose?

:::hint
Split `data.data` and `y2` with the same arguments to get the 30-feature version. `PrecisionRecallDisplay.from_estimator(model, X_test, y_test, ax=ax, name="...")` draws one curve; call it twice with the same `ax`. `average_precision_score` and `roc_auc_score` both take the true labels and `predict_proba(X)[:, 1]`.
:::

:::solution
```python run alt="Precision-recall curves for two models on the same axes. The 30-feature model's curve stays near precision 1.0 until recall is above 0.9. The two-feature model's curve drops earlier and sits below it everywhere past recall 0.7." caption="The 30-feature curve sits above the two-feature curve at almost every recall, so it wins whatever threshold you later pick."
from sklearn.metrics import PrecisionRecallDisplay, average_precision_score, roc_auc_score

X30_train, X30_test, _, _ = train_test_split(
    data.data, y2, test_size=0.25, stratify=y2, random_state=0
)
full = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000)).fit(X30_train, y2_train)

fig, ax = plt.subplots(figsize=(5.6, 3.8))
for name, model, X_eval, color in [("2 features", screen, X2_test, "#eb6834"),
                                   ("30 features", full, X30_test, "#2a78d6")]:
    proba = model.predict_proba(X_eval)[:, 1]
    print(f"{name:11s} AP {average_precision_score(y2_test, proba):.3f}   "
          f"ROC AUC {roc_auc_score(y2_test, proba):.3f}")
    PrecisionRecallDisplay.from_estimator(model, X_eval, y2_test, ax=ax, name=name, color=color)
ax.spines[["top", "right"]].set_visible(False)
plt.show()
```

Splitting `data.data` with the same `test_size`, `stratify`, and `random_state` puts exactly the same tumors in the test set, so both curves are scored on identical rows. The 30-feature curve sits above the other almost everywhere, and both summary numbers agree. When one curve dominates like that, the choice doesn't depend on the threshold: whatever recall you need, the bigger model gets it with fewer false alarms. If the curves **crossed**, the better model would depend on where you plan to operate, and you'd decide after fixing the requirement.
:::

### Challenge: put a price on mistakes

Use the fraud data and the three-way split from the code-along. A missed fraud costs the bank $500; reviewing a false alarm costs $20 of staff time. Write `total_cost(y_true, proba, threshold)`. Search thresholds from 0.02 to 0.98 in steps of 0.02 **on the validation set**, plot cost against threshold, pick the cheapest, and then report the test-set cost for the default 0.5 and for your threshold.

:::hint
Cost is `fn * 500 + fp * 20`, using the counts from `confusion_matrix(...).ravel()`. `np.argmin(costs)` gives the position of the cheapest threshold in your list. Don't touch `X_test` until the threshold is chosen.
:::

:::solution
```python run alt="Line chart of total validation cost in dollars against threshold. Cost is lowest, about 3,600 dollars, near a threshold of 0.10, and rises steadily to about 30,000 dollars as the threshold approaches 1. A dotted line marks the chosen threshold." caption="Missed fraud is 25 times more expensive than a review, so the cheapest threshold is low."
X, y = make_classification(n_samples=3000, n_features=8, n_informative=4,
                           weights=[0.9, 0.1], class_sep=0.8, random_state=4)
X_temp, X_test, y_temp, y_test = train_test_split(X, y, test_size=0.2, stratify=y, random_state=0)
X_train, X_val, y_train, y_val = train_test_split(
    X_temp, y_temp, test_size=0.25, stratify=y_temp, random_state=0
)
fraud_model = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_train, y_train)

COST_MISSED = 500   # dollars lost when fraud gets through
COST_REVIEW = 20    # dollars of staff time per false alarm

def total_cost(y_true, proba, threshold):
    pred = (proba >= threshold).astype(int)
    tn, fp, fn, tp = confusion_matrix(y_true, pred).ravel()
    return fn * COST_MISSED + fp * COST_REVIEW

thresholds = np.arange(0.02, 0.99, 0.02)
val_proba = fraud_model.predict_proba(X_val)[:, 1]
val_costs = [total_cost(y_val, val_proba, t) for t in thresholds]
best = thresholds[int(np.argmin(val_costs))]
print(f"Cheapest threshold on validation: {best:.2f} (cost ${min(val_costs):,})")

test_proba = fraud_model.predict_proba(X_test)[:, 1]
for t in [0.5, best]:
    print(f"test cost at {t:.2f}: ${total_cost(y_test, test_proba, t):,}")

fig, ax = plt.subplots(figsize=(6.4, 3))
ax.plot(thresholds, val_costs, color="#2a78d6", linewidth=2)
ax.axvline(best, color="#52514e", linestyle=":", linewidth=1)
ax.set_xlabel("threshold (validation set)")
ax.set_ylabel("total cost ($)")
ax.spines[["top", "right"]].set_visible(False)
plt.show()
```

A missed fraud costs 25 times more than a review, so the cheapest threshold is low, accepting many false alarms to catch more fraud. On the untouched test set it cuts the cost roughly in half compared with 0.5. There's a neat rule of thumb behind this: if the model's probabilities were perfectly trustworthy, you'd flag whenever P(fraud) × $500 exceeds (1 − P(fraud)) × $20, which works out to a threshold of 20 / 520 ≈ 0.04. The search landed higher because real probabilities are never perfectly trustworthy, and that's exactly why you search on validation data instead of trusting the formula.
