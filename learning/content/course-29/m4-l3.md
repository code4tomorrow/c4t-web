Metrics are easy to compute and easy to misread. Most of these exercises have a trap built in, the kind that shows up in real projects and in other people's reports. Do the hand calculation in Exercise 1 on paper before touching code; if you can do it by hand, you'll never confuse precision and recall again.

### Exercise 1: By hand first

A model's confusion matrix (rows = true class, columns = predicted, positive class = 1) is:

```text
[[50 10]
 [ 5 35]]
```

On paper, compute accuracy, precision, recall, and F1. Then check your answers by rebuilding label arrays that give this matrix and calling scikit-learn's functions.

:::solution
TN = 50, FP = 10, FN = 5, TP = 35, for 100 rows in total.

- Accuracy = (35 + 50) / 100 = 0.85
- Precision = 35 / (35 + 10) = 0.778
- Recall = 35 / (35 + 5) = 0.875
- F1 = 2 × 0.778 × 0.875 / (0.778 + 0.875) = 0.824

```python
import numpy as np
from sklearn.metrics import accuracy_score, confusion_matrix, f1_score, precision_score, recall_score

# Rebuild labels that produce the matrix [[50, 10], [5, 35]]
y_true = np.array([0] * 60 + [1] * 40)
y_pred = np.array([0] * 50 + [1] * 10 + [0] * 5 + [1] * 35)

print(confusion_matrix(y_true, y_pred))
print("accuracy ", accuracy_score(y_true, y_pred))
print("precision", round(precision_score(y_true, y_pred), 3))
print("recall   ", round(recall_score(y_true, y_pred), 3))
print("F1       ", round(f1_score(y_true, y_pred), 3))
```

```text
[[50 10]
 [ 5 35]]
accuracy  0.85
precision 0.778
recall    0.875
F1        0.824
```
:::

### Exercise 2: Which class is positive?

In the original breast cancer labels, `0` is malignant and `1` is benign. Train `DecisionTreeClassifier(max_depth=1, random_state=0)` on the full feature set (`test_size=0.25`, `stratify=y`, `random_state=1`). Print recall with the default settings, then with `pos_label=0`. Which number should a doctor care about?

:::solution
```python
from sklearn.datasets import load_breast_cancer
from sklearn.metrics import recall_score
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

X, y = load_breast_cancer(return_X_y=True)   # 0 = malignant, 1 = benign
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=1
)
pred = DecisionTreeClassifier(max_depth=1, random_state=0).fit(X_train, y_train).predict(X_test)
print("recall, default pos_label=1 (benign):", round(recall_score(y_test, pred), 3))
print("recall, pos_label=0 (malignant):     ", round(recall_score(y_test, pred, pos_label=0), 3))
```

```text
recall, default pos_label=1 (benign): 0.967
recall, pos_label=0 (malignant):      0.792
```

The default reports how many **healthy** patients were correctly cleared (96.7%), which sounds great. The number a doctor needs is malignant recall: this one-question model misses about 1 in 5 cancers. Same predictions, very different story, all from which class counts as "positive." Either pass `pos_label`, or flip the labels as in the notes.
:::

### Exercise 3: The accuracy paradox

Make a dataset where only 3% of rows are positive:

```python
from sklearn.datasets import make_classification
X, y = make_classification(n_samples=2000, n_features=6, weights=[0.97, 0.03],
                           random_state=2)
```

Split (`test_size=0.3`, `stratify=y`, `random_state=0`). For a default `DummyClassifier` and a default `LogisticRegression`, print accuracy, recall, and F1 (use `zero_division=0` for F1). Which model does accuracy say is better? Which is actually more useful?

:::solution
```python
from sklearn.datasets import make_classification
from sklearn.dummy import DummyClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score, f1_score, recall_score
from sklearn.model_selection import train_test_split

X, y = make_classification(n_samples=2000, n_features=6, weights=[0.97, 0.03],
                           random_state=2)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, stratify=y, random_state=0
)
for name, clf in [("dummy", DummyClassifier()), ("logistic", LogisticRegression())]:
    pred = clf.fit(X_train, y_train).predict(X_test)
    print(f"{name:8s} accuracy {accuracy_score(y_test, pred):.3f}  "
          f"recall {recall_score(y_test, pred):.3f}  "
          f"F1 {f1_score(y_test, pred, zero_division=0):.3f}")
```

```text
dummy    accuracy 0.963  recall 0.000  F1 0.000
logistic accuracy 0.962  recall 0.136  F1 0.207
```

Accuracy says the dummy wins, by a hair. The dummy never predicts positive, so its recall and F1 are 0, and it has never found a single positive case. Logistic regression at least finds some (13.6%). With rare classes, accuracy mostly measures how rare the class is. The logistic model's low recall also suggests lowering its threshold, which is the next exercise. Week 6 covers more tools for imbalance.
:::

### Exercise 4: Write your own predict

Using the two-feature screening model from the notes (`mean radius` and `mean texture`, labels flipped so 1 = malignant, `test_size=0.25`, `stratify=y`, `random_state=0`, `StandardScaler` plus `LogisticRegression`), write `predict_with_threshold(model, X, threshold)`. Check that it matches `model.predict` at 0.5, then print confusion matrices at thresholds 0.5 and 0.25. How many extra cancers does 0.25 catch, and at what price?

:::solution
```python
from sklearn.datasets import load_breast_cancer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import confusion_matrix
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

data = load_breast_cancer(as_frame=True)
X = data.data[["mean radius", "mean texture"]]
y = 1 - data.target
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=0
)
model = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_train, y_train)

def predict_with_threshold(model, X, threshold):
    return (model.predict_proba(X)[:, 1] >= threshold).astype(int)

same = (predict_with_threshold(model, X_test, 0.5) == model.predict(X_test)).all()
print("Matches predict() at 0.5:", same)
for t in [0.5, 0.25]:
    print(f"threshold {t}:")
    print(confusion_matrix(y_test, predict_with_threshold(model, X_test, t)))
```

```text
Matches predict() at 0.5: True
threshold 0.5:
[[87  3]
 [ 8 45]]
threshold 0.25:
[[76 14]
 [ 5 48]]
```

Lowering to 0.25 catches 3 more cancers (missed drops from 8 to 5) and costs 11 more false alarms (3 up to 14). Whether that's worth it is a judgment about costs, not a math question. (Exact ties at 0.5 are extremely rare, which is why the match is `True`.)
:::

### Exercise 5: Three classes

Train `KNeighborsClassifier()` on only the first two wine features (alcohol and malic acid) with `test_size=0.3`, `stratify=y`, `random_state=0`. Print the 3x3 confusion matrix and a classification report. Which class is hardest, and which pair of classes gets mixed up most?

:::solution
```python
from sklearn.datasets import load_wine
from sklearn.metrics import classification_report, confusion_matrix
from sklearn.model_selection import train_test_split
from sklearn.neighbors import KNeighborsClassifier

X, y = load_wine(return_X_y=True)
X = X[:, [0, 1]]   # only alcohol and malic_acid, so the model makes mistakes
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, stratify=y, random_state=0
)
pred = KNeighborsClassifier().fit(X_train, y_train).predict(X_test)
print(confusion_matrix(y_test, pred))
print(classification_report(y_test, pred, digits=3))
```

```text
[[13  1  4]
 [ 0 20  1]
 [ 2  2 11]]
              precision    recall  f1-score   support

           0      0.867     0.722     0.788        18
           1      0.870     0.952     0.909        21
           2      0.688     0.733     0.710        15

    accuracy                          0.815        54
   macro avg      0.808     0.803     0.802        54
weighted avg      0.818     0.815     0.813        54
```

Each class gets its own precision and recall, treating that class as "positive" and the other two as "negative." Class 2 is hardest (F1 0.710). The biggest single confusion is 4 class-0 wines predicted as class 2, top right of the matrix. Classes 0 and 2 both have high alcohol, so with only these two features they overlap. Class 1 (low alcohol) is easy. Macro avg (0.802) is a bit lower than weighted avg (0.813) because the weakest class is also the smallest.
:::

### Stretch challenge: Put a price on mistakes

Use the fraud data and the three-way split from the code-along. Suppose a missed fraud costs the bank $500 and reviewing a false alarm costs $20 of staff time. Write `total_cost(y_true, proba, threshold)`. Search thresholds from 0.02 to 0.98 in steps of 0.02 **on the validation set**, pick the cheapest, then report test-set cost for the default 0.5 and for your threshold.

:::solution
```python
import numpy as np
from sklearn.datasets import make_classification
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import confusion_matrix
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X, y = make_classification(n_samples=3000, n_features=8, n_informative=4,
                           weights=[0.9, 0.1], class_sep=0.8, random_state=4)
X_temp, X_test, y_temp, y_test = train_test_split(X, y, test_size=0.2, stratify=y, random_state=0)
X_train, X_val, y_train, y_val = train_test_split(
    X_temp, y_temp, test_size=0.25, stratify=y_temp, random_state=0
)
model = make_pipeline(StandardScaler(), LogisticRegression()).fit(X_train, y_train)

COST_MISSED = 500   # dollars lost when fraud gets through
COST_REVIEW = 20    # dollars of staff time per false alarm

def total_cost(y_true, proba, threshold):
    pred = (proba >= threshold).astype(int)
    tn, fp, fn, tp = confusion_matrix(y_true, pred).ravel()
    return fn * COST_MISSED + fp * COST_REVIEW

thresholds = np.arange(0.02, 0.99, 0.02)
val_proba = model.predict_proba(X_val)[:, 1]
val_costs = [total_cost(y_val, val_proba, t) for t in thresholds]
best = thresholds[int(np.argmin(val_costs))]
print(f"Cheapest threshold on validation: {best:.2f} (cost ${min(val_costs):,})")

test_proba = model.predict_proba(X_test)[:, 1]
for t in [0.5, best]:
    print(f"test cost at {t:.2f}: ${total_cost(y_test, test_proba, t):,}")
```

```text
Cheapest threshold on validation: 0.10 (cost $3,620)
test cost at 0.50: $13,600
test cost at 0.10: $7,360
```

A missed fraud costs 25 times more than a review, so the cheapest threshold is low (0.10), accepting many false alarms to catch more fraud. On the untouched test set it cuts the cost from $13,600 to $7,360, about 46% less. There's a neat rule of thumb behind this: if the model's probabilities are trustworthy, flag whenever P(fraud) × $500 is more than (1 − P(fraud)) × $20, which works out to a threshold of 20 / 520 ≈ 0.04. The search landed a bit higher because real probabilities are never perfectly trustworthy, which is exactly why you search on validation data instead of trusting the formula.
:::
