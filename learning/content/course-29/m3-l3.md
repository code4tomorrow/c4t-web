## Warm-up: fit learns, transform applies

Predict the two printed values before running this. The imputer is fit on one list and then used on another:

```python run
import numpy as np
from sklearn.impute import SimpleImputer

train = np.array([[1.0], [2.0], [3.0], [100.0]])
new = np.array([[np.nan], [5.0]])

for strategy in ["mean", "median"]:
    imputer = SimpleImputer(strategy=strategy).fit(train)
    print(strategy, "fills the blank with", imputer.transform(new)[0, 0])
```

The mean of 1, 2, 3, and 100 is 26.5; the median is 2.5. Neither looks at `new` at all: `transform` only applies what `fit` learned. One outlier dragged the mean far above every typical value, which is the whole story of Exercise 1.

### Exercise 1: Mean or median?

Run this setup, which blanks out 10% of the `mean area` column in the breast cancer data:

```python run
import pandas as pd
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split

X, y = load_breast_cancer(return_X_y=True, as_frame=True)
X_area = X[["mean area"]].copy()
X_area.loc[X_area.sample(frac=0.1, random_state=5).index, "mean area"] = np.nan
X_area_train, X_area_test = train_test_split(X_area, test_size=0.25, random_state=0)
```

Print how many blanks are in `X_area_train`. Fit one `SimpleImputer` with `strategy="mean"` and one with `strategy="median"` on the training set, and print the fill value each learned. Then plot a histogram of the column with both values marked. Which would you choose, and why?

:::hint
The learned value lives in `imputer.statistics_[0]`. For the chart, `plt.hist(column.dropna(), bins=40)` draws the shape, and `plt.axvline(value)` marks a vertical line.
:::

:::solution
```python run alt="Histogram of mean tumor area in the training set, piled up between about 300 and 800 with a long tail stretching past 2,000. A dashed line marks the median near 553 inside the main pile; a second line marks the mean near 653, pulled right by the tail." caption="A long right tail drags the mean away from the typical tumor; the median stays in the pile."
import matplotlib.pyplot as plt

print("Blanks in train:", int(X_area_train["mean area"].isna().sum()))
fills = {}
for strategy in ["mean", "median"]:
    fills[strategy] = SimpleImputer(strategy=strategy).fit(X_area_train).statistics_[0]
    print(f"{strategy:6s} fill value: {fills[strategy]:.1f}")

fig, ax = plt.subplots(figsize=(6.4, 3))
ax.hist(X_area_train["mean area"].dropna(), bins=40, color="#a9c9f0", edgecolor="white")
ax.axvline(fills["median"], color="#2a78d6", linestyle="--", linewidth=2, label="median")
ax.axvline(fills["mean"], color="#eb6834", linewidth=2, label="mean")
ax.set_xlabel("mean area")
ax.set_ylabel("tumors")
ax.legend(frameon=False)
ax.spines[["top", "right"]].set_visible(False)
plt.show()
```

The mean is 100 higher because a few very large tumors (areas over 2,000) pull it right. The median, the middle value, doesn't care how extreme those outliers are. For a skewed column like this, the median is the more typical value and the safer fill. Both imputers were fit on training rows only.
:::

### Exercise 2: Predict the one-hot output

Without running it, write down the column names and the two output rows this prints:

```python
import pandas as pd
from sklearn.preprocessing import OneHotEncoder

train = pd.DataFrame({"grape": ["red", "white", "rose", "white", "red"],
                      "size": ["small", "large", "large", "small", "small"]})
enc = OneHotEncoder(handle_unknown="ignore", sparse_output=False).fit(train)
print(enc.get_feature_names_out())
print(enc.transform(pd.DataFrame({"grape": ["rose", "orange"], "size": ["large", "small"]})))
```

:::hint
Each input column produces one output column per category it saw during `fit`, sorted alphabetically within that column. A category never seen during `fit` gets zeros in all of its column's slots.
:::

:::solution
```python run
from sklearn.preprocessing import OneHotEncoder

train = pd.DataFrame({"grape": ["red", "white", "rose", "white", "red"],
                      "size": ["small", "large", "large", "small", "small"]})
enc = OneHotEncoder(handle_unknown="ignore", sparse_output=False).fit(train)
print(enc.get_feature_names_out())
print(enc.transform(pd.DataFrame({"grape": ["rose", "orange"], "size": ["large", "small"]})))
```

Three grapes plus two sizes make 5 columns. Row one is `rose` and `large`. Row two's `orange` was never seen, so all three grape slots are 0, while `small` is still encoded normally. Without `handle_unknown="ignore"`, that second row would raise a `ValueError`.
:::

### Exercise 3: Fix the leak

This script has a leak. Find it, explain it in one sentence, and rewrite it with `make_pipeline`. Print both scores.

```python
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.neighbors import KNeighborsClassifier
from sklearn.preprocessing import StandardScaler

X, y = load_breast_cancer(return_X_y=True)
X_scaled = StandardScaler().fit_transform(X)
X_tr, X_te, y_tr, y_te = train_test_split(X_scaled, y, stratify=y, random_state=0)
print("Leaky:", round(KNeighborsClassifier().fit(X_tr, y_tr).score(X_te, y_te), 3))
```

:::hint
Look for a `fit` or `fit_transform` that runs before `train_test_split`. Whatever it learns, it learned partly from rows that end up in the test set.
:::

:::solution
The scaler is fit on **all** of `X` before the split, so the test rows help set the means and standard deviations.

```python run
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X_all, y_all = load_breast_cancer(return_X_y=True)

X_scaled = StandardScaler().fit_transform(X_all)
X_tr, X_te, y_tr, y_te = train_test_split(X_scaled, y_all, stratify=y_all, random_state=0)
print("Leaky:  ", round(KNeighborsClassifier().fit(X_tr, y_tr).score(X_te, y_te), 3))

X_tr, X_te, y_tr, y_te = train_test_split(X_all, y_all, stratify=y_all, random_state=0)
pipe = make_pipeline(StandardScaler(), KNeighborsClassifier())
print("Correct:", round(pipe.fit(X_tr, y_tr).score(X_te, y_te), 3))
```

Same score this time. A scaling leak is usually tiny, because a column's mean barely moves when you add 25% more rows. The fixed version is still the one to use: its number is honest by construction, and the same habit protects you from leaks like feature selection, where the damage is huge.
:::

### Exercise 4: A full mixed-type pipeline

Run this setup. It replaces wine's `alcohol` column with a text label and adds blanks to two columns:

```python run
from sklearn.datasets import load_wine

wine_df = load_wine(as_frame=True).frame
wine_df["alcohol_level"] = pd.cut(wine_df["alcohol"], bins=[0, 12.5, 13.5, 20],
                                  labels=["low", "mid", "high"]).astype(object)
wine_df = wine_df.drop(columns="alcohol")
rng = np.random.default_rng(3)
wine_df.loc[rng.choice(len(wine_df), 20, replace=False), "alcohol_level"] = np.nan
wine_df.loc[rng.choice(len(wine_df), 20, replace=False), "flavanoids"] = np.nan
Xw, yw = wine_df.drop(columns="target"), wine_df["target"]
Xw_train, Xw_test, yw_train, yw_test = train_test_split(
    Xw, yw, test_size=0.25, stratify=yw, random_state=0
)
```

Build a `ColumnTransformer` that imputes (median) and scales every numeric column, and imputes (most frequent) and one-hot encodes `alcohol_level`. Put it in a `Pipeline` with `LogisticRegression(max_iter=1000)`. Print the test accuracy and the number of features the model receives after preprocessing.

:::hint
The numeric columns are `Xw.columns.drop("alcohol_level").tolist()`. Each branch can be a `make_pipeline(...)` of two steps. After fitting, `model.named_steps["prep"].get_feature_names_out()` lists every output column.
:::

:::solution
```python run
from sklearn.compose import ColumnTransformer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline

wine_num = Xw.columns.drop("alcohol_level").tolist()
prep = ColumnTransformer([
    ("num", make_pipeline(SimpleImputer(strategy="median"), StandardScaler()), wine_num),
    ("cat", make_pipeline(SimpleImputer(strategy="most_frequent"),
                          OneHotEncoder(handle_unknown="ignore")), ["alcohol_level"]),
])
model = Pipeline([("prep", prep), ("clf", LogisticRegression(max_iter=1000))])
model.fit(Xw_train, yw_train)
print("Test accuracy:", round(model.score(Xw_test, yw_test), 3))
print("Features after prep:", len(model.named_steps["prep"].get_feature_names_out()))
```

12 numeric columns plus 3 one-hot columns (low, mid, high) make 15. A perfect score on 45 test wines is great to see, but on a test set this small it's a single draw, not proof of a perfect model.
:::

### Exercise 5: Is "missing" a clue?

Sometimes **whether** a value is blank tells you something. In this setup, texture readings go missing only for malignant tumors (label 0):

```python run
X, y = load_breast_cancer(return_X_y=True, as_frame=True)
X_tex = X[["mean texture", "mean smoothness"]].copy()
rng = np.random.default_rng(0)
blank = (y == 0) & (rng.random(len(y)) < 0.4)
X_tex.loc[blank, "mean texture"] = np.nan
print("Blank texture: malignant", int(blank[y == 0].sum()), " benign", int(blank[y == 1].sum()))
```

Split with `test_size=0.25`, `stratify=y`, `random_state=0`. Compare two pipelines of `SimpleImputer(strategy="median", add_indicator=flag)`, then `StandardScaler()`, then `LogisticRegression()`, with `flag` set to `False` and then `True`.

:::hint
Loop over `[False, True]` and build a fresh pipeline inside the loop. `add_indicator=True` appends one extra 0/1 column per feature that had blanks during `fit`.
:::

:::solution
```python run
Xt_train, Xt_test, yt_train, yt_test = train_test_split(
    X_tex, y, test_size=0.25, stratify=y, random_state=0
)
for flag in [False, True]:
    pipe = make_pipeline(SimpleImputer(strategy="median", add_indicator=flag),
                         StandardScaler(), LogisticRegression())
    pipe.fit(Xt_train, yt_train)
    print(f"add_indicator={flag}: {pipe.score(Xt_test, yt_test):.3f}")
```

`add_indicator=True` adds a column meaning "this texture was blank." The model learns that a blank texture strongly suggests malignant, and accuracy climbs by several points. Real data does this all the time (a lab test gets ordered only for patients who already look sick). The catch: if the reason values go missing changes later, the clue quietly stops working.
:::

### Exercise 6: The feature that knows the answer

A hospital export includes a column `followup_visits`: the number of oncology appointments booked for each patient. Run the setup, then train a scaled `LogisticRegression` on all four columns and print test accuracy. Next, score a model on **each column alone**. Which column is suspicious, and why must it be removed even though no `fit` ever touched the test set?

```python run
X, y = load_breast_cancer(return_X_y=True, as_frame=True)
X_hosp = X[["mean radius", "mean texture", "mean smoothness"]].copy()
rng = np.random.default_rng(7)
X_hosp["followup_visits"] = np.where(y == 0, rng.poisson(4, len(y)), rng.poisson(0.3, len(y)))
Xh_train, Xh_test, yh_train, yh_test = train_test_split(
    X_hosp, y, test_size=0.25, stratify=y, random_state=0
)
```

:::hint
For each column, ask one question: would I know this value at the moment I need the prediction? Follow-up appointments get booked *after* a diagnosis.
:::

:::solution
```python run
def score_on(columns):
    pipe = make_pipeline(StandardScaler(), LogisticRegression())
    return pipe.fit(Xh_train[columns], yh_train).score(Xh_test[columns], yh_test)

print("all four columns:", round(score_on(list(X_hosp.columns)), 3))
for col in X_hosp.columns:
    print(f"  {col:16s} alone: {score_on([col]):.3f}")
print("without followup_visits:", round(score_on(["mean radius", "mean texture", "mean smoothness"]), 3))
```

`followup_visits` alone predicts almost as well as everything together. That's the red flag: one column that's nearly as good as the answer key. It *is* a consequence of the answer, recorded after doctors already knew the diagnosis, so at prediction time (a new scan, no diagnosis yet) it doesn't exist. This is **target leakage**, and a pipeline can't catch it, because nothing was fit on test rows; the leak is in what the column means. The honest model is the one without it.
:::

### Challenge: How bad can leakage get?

Write `leak_test(n_features, seed)`. It builds a pure-noise dataset (200 rows, `n_features` random columns, random 0/1 labels) and returns two test accuracies:

- **leaky:** `SelectKBest(f_classif, k=10)` fit on all rows, then split (`test_size=0.3`, `random_state=0`), then `LogisticRegression`.
- **honest:** split first, then a pipeline of the same two steps.

Average each over seeds 0 to 4 for `n_features` of 10, 100, 1,000, and 10,000, and plot both lines. What pattern do you see, and why does the 10-feature case show no leak?

```mermaid caption="The only difference between the two versions is where the split happens"
flowchart TB
    subgraph Leaky
    A1["All 200 rows"] --> B1["SelectKBest picks 10"] --> C1["Split"] --> D1["Fit and score"]
    end
    subgraph Honest
    A2["All 200 rows"] --> C2["Split"] --> B2["Pipeline: SelectKBest + model, fit on train"] --> D2["Score on test"]
    end
```

:::hint
`np.mean([leak_test(n, s) for s in range(5)], axis=0)` averages pairs of numbers column by column. With `k=10` and only 10 features, ask yourself what `SelectKBest` actually selects.
:::

:::solution
```python run alt="Line chart of test accuracy against number of noise features on a log scale from 10 to 10,000. The honest line stays near 0.5 throughout. The leaky line starts equal to it at 10 features and climbs steadily to about 0.78 at 10,000 features." caption="The more noise there is to search, the more fake signal leaky selection finds."
from sklearn.feature_selection import SelectKBest, f_classif

def leak_test(n_features, seed=0):
    rng = np.random.default_rng(seed)
    Xn = rng.normal(size=(200, n_features))
    yn = rng.integers(0, 2, size=200)

    X_sel = SelectKBest(f_classif, k=10).fit_transform(Xn, yn)
    a, b, c, d = train_test_split(X_sel, yn, test_size=0.3, random_state=0)
    leaky = LogisticRegression().fit(a, c).score(b, d)

    a, b, c, d = train_test_split(Xn, yn, test_size=0.3, random_state=0)
    pipe = make_pipeline(SelectKBest(f_classif, k=10), LogisticRegression())
    honest = pipe.fit(a, c).score(b, d)
    return leaky, honest

sizes = [10, 100, 1000, 10000]
results = []
for n in sizes:
    leaky, honest = np.mean([leak_test(n, seed) for seed in range(5)], axis=0)
    results.append((leaky, honest))
    print(f"{n:6d} noise features: leaky {leaky:.3f}  honest {honest:.3f}")

leaky_line, honest_line = zip(*results)
fig, ax = plt.subplots(figsize=(6.4, 3))
ax.plot(sizes, leaky_line, marker="o", linewidth=2, color="#eb6834", label="select, then split")
ax.plot(sizes, honest_line, marker="o", linewidth=2, color="#2a78d6", label="split, then pipeline")
ax.axhline(0.5, color="#52514e", linestyle="--", linewidth=1)
ax.set_xscale("log")
ax.set_ylim(0.3, 0.9)
ax.set_xlabel("number of pure-noise features")
ax.set_ylabel("test accuracy")
ax.legend(frameon=False)
ax.spines[["top", "right"]].set_visible(False)
plt.show()
```

The honest score hovers near 50%, which is right for random labels. The leaky score climbs as features grow: the more noise columns there are to search, the more of them line up with the labels by chance, test rows included, and leaky selection finds exactly those. With only 10 features and `k=10`, selection keeps every column, so it chooses nothing and there's nothing to leak. Datasets with thousands of columns (genes, words, pixels) are where this mistake does the most damage.
:::
