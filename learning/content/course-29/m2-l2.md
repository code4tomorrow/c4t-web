:::objectives
- Split once and score every candidate, baselines included, on the identical test set.
- Write one `evaluate` function and turn its results into a pandas leaderboard.
- Measure each model by how far it beats the strongest baseline, and chart it.
- Rerun the comparison over ten splits to see which conclusions are luck and which are solid.
:::

"I got 93%" is a weak claim. "The tree beats the best do-nothing baseline by 53 points, and it still wins on every one of ten different splits" is a strong one. Today you build the notebook that lets you say the second sentence. It's a tool you'll keep reusing, because every comparison in this course starts the same way.

Here's the plan. Everything flows from a single split, so every model faces exactly the same exam:

```mermaid caption="What we're building: one split, one scoring function, one leaderboard, then a stability check"

The data is the wine dataset from setup week: 178 wines, 13 chemical measurements, 3 growers labeled 0, 1, and 2. Make a new notebook called `w1-codealong-baseline.ipynb` and put each step in its own cell.

## Step 1: Load, look at the target, and split once

```python run
from sklearn.datasets import load_wine
from sklearn.model_selection import train_test_split

wine = load_wine(as_frame=True)
X, y = wine.data, wine.target
print(X.shape)
print(y.value_counts(normalize=True).sort_index().round(3))

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=7
)
print("train:", len(X_train), " test:", len(X_test))
```

`normalize=True` turns counts into shares. Class 1 is the largest at about 40%. So before running anything, predict this: "always guess class 1" should score close to 0.40. Predicting your baseline before you compute it is a great habit, because if the real number surprises you, something upstream is wrong.

The split happens **once**, before any model exists. Every candidate below uses these same four variables.

## Step 2: Write one evaluation function

Repeating `fit` and `score` by hand for five models invites copy-paste bugs, like scoring model B on model A's test set. A function makes every candidate go through identical steps:

```python run
def evaluate(name, model):
    model.fit(X_train, y_train)
    return {
        "model": name,
        "train": round(model.score(X_train, y_train), 3),
        "test": round(model.score(X_test, y_test), 3),
    }
```

It returns a dictionary instead of printing, because a list of dictionaries turns straight into a pandas table. Training accuracy comes along too: a big gap between train and test is an early warning of overfitting, which Week 4 studies properly.

## Step 3: Score five candidates

Three baselines and two real models:

```python run
import pandas as pd
from sklearn.dummy import DummyClassifier
from sklearn.neighbors import KNeighborsClassifier
from sklearn.tree import DecisionTreeClassifier

candidates = {
    "dummy: most_frequent": DummyClassifier(strategy="most_frequent"),
    "dummy: stratified": DummyClassifier(strategy="stratified", random_state=0),
    "dummy: uniform": DummyClassifier(strategy="uniform", random_state=0),
    "k-NN (k=5)": KNeighborsClassifier(n_neighbors=5),
    "tree (depth 3)": DecisionTreeClassifier(max_depth=3, random_state=0),
}

results = pd.DataFrame([evaluate(name, model) for name, model in candidates.items()])
print(results.to_string(index=False))
```

Read it row by row:

- **most_frequent** lands at 0.400, exactly as predicted in Step 1.
- **stratified** and **uniform** guess at random, so they hover near one in three. They need a `random_state` too, or their scores change on every run.
- **k-NN** clearly beats the baselines but trails the tree by a lot. k-NN decides by measuring distance between wines, and wine's features live on very different scales: `proline` runs into the hundreds and beyond, while `hue` stays near 1. One feature drowns out the rest. Hold that thought until Week 2.
- **The tree** fits its training data almost perfectly and still does well on test.

`to_string(index=False)` prints the table without row numbers. In a notebook you could end the cell with `results` to get a formatted table instead.

## Step 4: Rank by the gap over the best baseline

The question that matters is "how much better than doing nothing?" Add a column that answers it directly:

```python run
is_dummy = results["model"].str.startswith("dummy")
best_baseline = results.loc[is_dummy, "test"].max()
results["beats_baseline_by"] = (results["test"] - best_baseline).round(3)
leaderboard = results.sort_values("test", ascending=False)
print(leaderboard.to_string(index=False))
```

We compare against the **strongest** baseline, not the weakest. Beating random guessing is easy; beating "always say the common class" is the real minimum. A model that only beats `uniform` hasn't shown anything.

A chart makes the gap impossible to miss. Baselines are gray, real models are blue, and the dashed line marks the bar every real model must clear:

```python run alt="Horizontal bar chart of test accuracy for five models. The three gray dummy baselines score between 0.31 and 0.40. k-NN scores 0.711 and the depth-3 tree scores 0.933. A dashed line at 0.40 marks the best baseline." caption="The leaderboard: anything left of the dashed line has learned nothing useful."
import matplotlib.pyplot as plt

board = leaderboard.iloc[::-1]   # reverse so the best model is on top
colors = ["#b8b7b1" if name.startswith("dummy") else "#2a78d6" for name in board["model"]]

fig, ax = plt.subplots(figsize=(6.4, 3))
ax.barh(board["model"], board["test"], color=colors, height=0.6)
ax.axvline(best_baseline, color="#52514e", linestyle="--", linewidth=1)
ax.text(best_baseline, 4.55, "best baseline", ha="center", fontsize=8, color="#52514e")
ax.set_ylim(-0.5, 4.9)
for i, value in enumerate(board["test"]):
    ax.text(value + 0.01, i, f"{value:.3f}", va="center", fontsize=9)

ax.spines[["top", "right"]].set_visible(False)

```

## Step 5: Does the ranking survive a different split?

Here's the uncomfortable fact about Step 3: the test set has only 45 wines, so each wine is worth 2.2 points of accuracy. One or two lucky rows can flip a close race. The way to find out is to rerun everything on ten different splits and look at the spread:

```python run
import numpy as np

X_all, y_all = load_wine(return_X_y=True)
models = {
    "baseline": lambda: DummyClassifier(),
    "k-NN": lambda: KNeighborsClassifier(),
    "tree": lambda: DecisionTreeClassifier(max_depth=3, random_state=0),
}
scores = {name: [] for name in models}
for seed in range(10):
    X_tr, X_te, y_tr, y_te = train_test_split(
        X_all, y_all, test_size=0.25, stratify=y_all, random_state=seed
    )
    for name, make in models.items():
        scores[name].append(make().fit(X_tr, y_tr).score(X_te, y_te))

for name, s in scores.items():
    s = np.array(s)
    print(f"{name:9s} mean {s.mean():.3f}  min {s.min():.3f}  max {s.max():.3f}")
```

Each entry in `models` is a small function that builds a **fresh** model, so no model carries anything over from the previous split. `fit()` returns the model itself, which is why `make().fit(X_tr, y_tr).score(X_te, y_te)` works on one line. `DummyClassifier()` with no arguments uses `most_frequent`.

Now plot every split's score as a dot:

```python run alt="Dot plot of test accuracy across ten random splits. The baseline is fixed at 0.40. k-NN ranges from about 0.64 to 0.76. The tree ranges from about 0.78 to 0.98, entirely above k-NN." caption="Ten splits, ten scores per model. The ranges never overlap, so the ranking is real."
fig, ax = plt.subplots(figsize=(6.4, 2.8))
palette = {"baseline": "#b8b7b1", "k-NN": "#eb6834", "tree": "#2a78d6"}
for row, (name, s) in enumerate(scores.items()):
    ax.scatter(s, [row] * len(s), s=40, color=palette[name], alpha=0.7)
    ax.plot([np.mean(s)] * 2, [row - 0.25, row + 0.25], color="#0b0b0b", linewidth=2)
ax.set_yticks(range(3), list(scores))
ax.set_xlim(0.3, 1.02)
ax.set_xlabel("test accuracy on each of 10 splits (black bar = mean)")
ax.spines[["top", "right", "left"]].set_visible(False)
plt.show()
```

Three things to notice:

- The tree's accuracy swings by about 20 points just from changing which wines are in the test set. The 0.933 from Step 3 was one draw from that range, a bit above its average.
- The **ranking** never changes. The tree's worst split still beats k-NN's best. That's a conclusion you can trust.
- The baseline never moves, because stratification puts the same number of class-1 wines in every test set.

:::warning
Never pick the seed that gives your favorite model its best score and report that. It's the most tempting way to fool yourself. Report the mean and the spread, or use Week 4's cross-validation, which runs this loop more carefully for you.
:::

## The finished notebook

Here's every step in one cell, the version to keep and reuse:

```python
import pandas as pd
from sklearn.datasets import load_wine
from sklearn.dummy import DummyClassifier
from sklearn.model_selection import train_test_split
from sklearn.neighbors import KNeighborsClassifier
from sklearn.tree import DecisionTreeClassifier

X, y = load_wine(return_X_y=True, as_frame=True)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=7
)

def evaluate(name, model):
    model.fit(X_train, y_train)
    return {"model": name,
            "train": round(model.score(X_train, y_train), 3),
            "test": round(model.score(X_test, y_test), 3)}

candidates = {
    "dummy: most_frequent": DummyClassifier(strategy="most_frequent"),
    "dummy: stratified": DummyClassifier(strategy="stratified", random_state=0),
    "dummy: uniform": DummyClassifier(strategy="uniform", random_state=0),
    "k-NN (k=5)": KNeighborsClassifier(n_neighbors=5),
    "tree (depth 3)": DecisionTreeClassifier(max_depth=3, random_state=0),
}
results = pd.DataFrame([evaluate(n, m) for n, m in candidates.items()])
best = results.loc[results["model"].str.startswith("dummy"), "test"].max()
results["beats_baseline_by"] = (results["test"] - best).round(3)
print(results.sort_values("test", ascending=False).to_string(index=False))
```

:::quiz
Q: Why does the leaderboard measure every model against the **best** baseline instead of the uniform one?
- [ ] The uniform baseline has a bug
  It works as intended: it guesses each class equally often.
- [x] Beating random guessing is easy, so it proves little; the strongest do-nothing score is the real minimum
  Any model that has learned anything beats `uniform`. Beating `most_frequent` shows the features carry information.
- [ ] The best baseline is always 0.5
  Here it's 0.400, the share of the biggest class. It depends on the data.

Q: In Step 5, why does each entry in `models` build a fresh model with a `lambda` instead of reusing one model object?
- [ ] Reusing a model object raises an error
  Calling `fit` again on the same object works; it just starts from scratch.
- [x] It guarantees each split gets a brand-new, untouched model
  A fresh model per split rules out any leftover state, so the ten scores are independent.
- [ ] Lambdas make the models train faster
  Speed is the same; this is about keeping each run independent.

Q: On one split the tree scores 0.933. Across ten splits it ranges from 0.778 to 0.978. What should you report?
- [ ] 0.978, the best result
  That's seed shopping: it reports luck as skill.
- [x] The mean and the range, plus the fact that it beat k-NN on every split
  The spread tells readers how much a single score can move, and the ranking is the trustworthy part.
- [ ] 0.933, because it came first
  It's one draw from a wide range, and slightly above average.
:::

:::takeaways
- Split once and push every candidate, baselines included, through the same `evaluate` function.
- Rank models by their gap over the **strongest** baseline, not by raw accuracy.
- With a small test set, each row is worth a couple of points, so one split can mislead.
- Repeating the comparison over several splits separates solid conclusions (the ranking) from luck (the exact score).
:::
