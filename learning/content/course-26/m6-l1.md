Say you're tracking quiz scores for a class of 25. With what you know so far, that's 25 variables: `score1`, `score2`, all the way to `score25`. The average is one enormous line adding all 25 names together. Then a new student joins, and every line that mentions the scores has to change.

A **list** solves this. It's one variable that holds many values, in order. Add a 26th score and the list just gets longer; the code that averages it doesn't change at all.

## Making a list

Put the items inside square brackets, with commas between them:

```python run title="snacks.py"
snacks = ["chips", "apples", "popcorn", "pretzels"]
print(snacks)
print(snacks[0])
print(snacks[2])
print(snacks[-1])
print("We have", len(snacks), "snacks.")
```

Printing the whole list shows the brackets and quotes, which is handy for checking what's inside. `snacks[0]` reaches in and pulls out one item. `len(snacks)` counts the items: 4.

A list can hold strings, numbers, Booleans, or a mix, like `[16, "Maya", True]`. Most of the time, though, every item is the same kind of thing. `[]` is an **empty list**, a container with nothing in it yet.

## Why the first index is 0

Every item has a position number called its **index**, and Python starts counting at 0. That looks strange until you think of the index as **how many steps from the front** an item is. The first item is zero steps from the front. The second is one step away.

| Index | 0 | 1 | 2 | 3 |
| --- | --- | --- | --- | --- |
| Item | `"chips"` | `"apples"` | `"popcorn"` | `"pretzels"` |
| Negative index | -4 | -3 | -2 | -1 |

-   `snacks[0]` is the **first** item.
-   `snacks[-1]` is the **last** item, however long the list is. `snacks[-2]` is second to last.
-   The last index is always `len(snacks) - 1`, here 3. There are 4 items, but the numbering started at 0.

### What happens when you go too far

Before you look: this list has three items. What will `snacks[3]` give you?

```python run raises title="snacks.py"
snacks = ["chips", "apples", "popcorn"]
print(snacks[3])
```

Three snacks means indexes 0, 1, and 2. Index 3 would be a fourth item, and there isn't one. When you see `IndexError: list index out of range`, your first suspect should be counting from 1 instead of 0. The `~~~^^^` marks under the code point at the part of the line that went wrong: the index. (On your computer the traceback shows the full path to your file instead of `main.py`.)

## Changing a list

Strings can't be changed once they're made, but lists can. You can swap, add, and remove items whenever you like. These are the moves you'll use most:

| Code | What it does |
| --- | --- |
| `snacks[1] = "grapes"` | replace the item at index 1 |
| `snacks.append("cookies")` | add to the end |
| `snacks.insert(0, "carrots")` | add at index 0, and shift everything else along |
| `snacks.remove("chips")` | remove the first `"chips"` it finds |
| `snacks.pop()` | remove the last item and hand it back to you |
| `snacks.pop(1)` | remove the item at index 1 and hand it back |
| `"popcorn" in snacks` | `True` if that item is in the list |

The dot in `snacks.append(...)` means "this list, do this". The action belongs to the list, so you write the list's name first. Step through these changes and watch the list on the right after each line:

:::trace Watch the list change with each method
```python
snacks = ["chips", "apples", "popcorn"]
snacks[1] = "grapes"
snacks.append("cookies")
snacks.insert(0, "carrots")
snacks.remove("chips")
last = snacks.pop()
print("Removed", last)
print(snacks)
print("popcorn" in snacks)
```
:::

Two things to notice. After `insert(0, ...)`, every item moved one place to the right, so `"chips"` went from index 0 to index 1. And `pop()` didn't just delete `"cookies"`, it handed it back so we could store it in `last`.

`remove` has a catch: it crashes if the item isn't in the list.

```python run raises title="snacks.py"
snacks = ["chips", "apples"]
snacks.remove("pizza")
```

:::warning
`ValueError: list.remove(x): x not in list` means you asked to remove something that isn't there. Guard it with `in` on the line before: `if "pizza" in snacks:`, then indent the `remove` under it.
:::

## Looping over a list

Here's where lists pay off. A `for` loop hands you each item in turn, so you never need to know how many there are:

```python run title="scores.py"
scores = [88, 92, 75, 100, 64]

for score in scores:
    print("Score:", score)

total = 0
for score in scores:
    total = total + score
print("Average:", total / len(scores))
print("Highest:", max(scores), "Lowest:", min(scores), "Sum:", sum(scores))
```

The average divides by `len(scores)`, not by the number 5. Add a sixth score to the first line and every result is still correct, with nothing else to edit. That's the payoff from the opening example.

Python also has built-in `sum()`, `max()`, and `min()` for lists of numbers. They do the same job as the total loop. It's still worth writing the loop yourself at least once, because next time you need something those three don't do (like counting scores above 90), you'll know how to build it.

### Looping with indexes

Sometimes you want the position as well as the item, for example to print a numbered list. `range(len(chores))` produces every valid index, from 0 up to the last one:

```python run title="chores.py"
chores = ["dishes", "laundry", "walk the dog"]
for i in range(len(chores)):
    print(f"{i + 1}. {chores[i]}")
```

People count from 1, so we print `i + 1`. Behind the scenes Python is still using 0, 1, 2.

## Changing every item: the copy trap

This one catches almost everyone. Both loops below are supposed to double every price. Predict what `prices` holds after each loop, then step through and check.

:::trace One loop changes the list and one doesn't. Which is which?
```python
prices = [2.0, 3.5, 1.25]
for price in prices:
    price = price * 2
print(prices)
for i in range(len(prices)):
    prices[i] = prices[i] * 2
print(prices)
```
:::

In the first loop, `price` gets a **copy** of each value. Doubling the copy changes `price`, and the list never hears about it. You can see `price` change in the trace while `prices` stays the same. To change the list itself, you have to assign to a spot in the list, `prices[i] = ...`, and that means looping over the indexes.

## Building a list as you go

Lists often start empty and fill up while the program runs. This one keeps asking for names until the user presses Enter without typing anything, which gives `input()` an empty string, `""`. In this run the user typed three names and then pressed Enter on a blank line:

```python run title="invites.py" input="Maya|Luis|Priya|"
friends = []
name = input("Friend's name (blank to finish): ")
while name != "":
    friends.append(name)
    name = input("Friend's name (blank to finish): ")

print("You invited", len(friends), "friends:")
for friend in friends:
    print("-", friend)
```

It's the "ask again" `while` loop from Week 4 with one new line, `friends.append(name)`, that saves each answer before asking for the next.

## Mistakes to watch for

:::warning
**Off by one at the end.** The last item is `my_list[len(my_list) - 1]` or simply `my_list[-1]`. `my_list[len(my_list)]` is always one past the end and gives `IndexError`.

**Round brackets instead of square.** `snacks(0)` gives `TypeError: 'list' object is not callable`, because round brackets mean "call this like a function". Use `snacks[0]`.

**Forgetting the dot.** It's `snacks.append("x")`, not `append(snacks, "x")`, which gives a `NameError`.

**Changing the loop variable and expecting the list to change.** Use `my_list[i] = ...` inside a `for i in range(len(my_list))` loop.
:::

:::quiz
Q: `colors = ["red", "green", "blue", "gold"]`. What is `colors[-2]`?
- [ ] `"green"`
  That's `colors[1]`. Negative indexes count from the end, starting at -1.
- [x] `"blue"`
  -1 is the last item (`"gold"`), so -2 is the one just before it.
- [ ] `"gold"`
  That's `colors[-1]`, the very last item.
- [ ] An `IndexError`
  Negative indexes are allowed, as long as you don't go past the front. -2 is fine for a 4-item list.

Q: `nums = [5, 10, 15]`, then `nums.append(20)` and `nums.pop(0)`. What's in `nums` now?
- [ ] `[5, 10, 15]`
  `append` added 20 and `pop(0)` removed the first item, so the list did change.
- [ ] `[5, 10, 15, 20]`
  That's after the `append`. `pop(0)` then removes the item at index 0.
- [x] `[10, 15, 20]`
  20 goes on the end, then the item at index 0, which is 5, is removed.
- [ ] `[5, 10, 15]` with 20 printed
  `pop` hands back the removed item, but nothing here prints it. And the removed item was 5, not 20.

Q: You want to add 1 point to every score in `scores`. Which loop actually changes the list?
- [ ] `for s in scores:` with `s = s + 1` inside
  `s` is a copy of each item. Changing it leaves the list exactly as it was.
- [x] `for i in range(len(scores)):` with `scores[i] = scores[i] + 1` inside
  Assigning to `scores[i]` writes the new value back into the list itself.
- [ ] `for i in scores:` with `scores[i] = scores[i] + 1` inside
  Here `i` is each *score*, not each index, so `scores[88]` would crash with `IndexError`.

Q: A list has 6 items. What is its last valid index?
- [ ] 6
  The indexes start at 0, so 6 would be a seventh item.
- [x] 5
  Six items are numbered 0 through 5. The last index is always `len - 1`.
- [ ] 7
  That's two past the end. Python would answer with `IndexError`.
:::

:::takeaways
- A list is one variable holding many values in order: `scores = [88, 92, 75]`.
- Indexes start at 0 (steps from the front). `[-1]` is the last item, and the last index is `len(list) - 1`.
- `append` adds to the end, `insert` adds anywhere, `remove` deletes by value, and `pop` deletes by position and hands the item back.
- `for item in my_list:` visits every item. Use `len()` instead of typing the count, so the code still works when the list grows.
- To change items in place, loop over indexes and assign to `my_list[i]`.
:::
