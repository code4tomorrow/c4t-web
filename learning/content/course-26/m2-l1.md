Every app you have ever used, from a game to a calculator, is a list of instructions a computer follows in order. A Python program is exactly that: a text file of instructions, one per line. This week you learn the most-used instruction in the language, `print()`, and the habit that separates tidy code from a mess: comments.

## How a program runs

When you press **F5**, Python starts at line 1 and runs each line in order, top to bottom, one at a time. It does not skip ahead or guess what you meant.

```python
print("Welcome to Code 4 Tomorrow!")
print("Today we write real programs.")
print("Python runs these lines from top to bottom.")
```

```text
Welcome to Code 4 Tomorrow!
Today we write real programs.
Python runs these lines from top to bottom.
```

Swap the first two lines and the output swaps too. Order is everything.

## Anatomy of print()

```python
print("Hello")
```

-   `print` is the name of a **function**, a built-in command that does a job. This one displays things.
-   The **parentheses** `( )` hold what you want to display.
-   The **quotes** `" "` mark the start and end of a piece of text. Programmers call text a **string**.

You can use double quotes `"like this"` or single quotes `'like this'`. Pick one style per string and close it with the same kind you opened it with.

## Text versus numbers

Quotes change everything. Inside quotes, Python treats characters as plain text and prints them exactly. Without quotes, Python works out the value first.

```python
print("2 + 3")
print(2 + 3)
print("I have", 3, "cats and", 2, "dogs.")
print("Total pets:", 3 + 2)
```

```text
2 + 3
5
I have 3 cats and 2 dogs.
Total pets: 5
```

Notice the commas in the last two lines. When you give `print()` several items separated by commas, it prints them all on one line with **a space between each one**. That is why `"I have", 3` comes out as `I have 3` without you typing a space.

## Controlling the output

`print()` has a few extra settings that help you lay out text exactly how you want.

```python
print("2026", "11", "15", sep="-")
print("Loading", end="")
print("...", end="")
print(" done!")
print()
print("Roses are red,\nViolets are blue.")
print("She said, 'Python is fun!'")
print("It's a great day.")
```

```text
2026-11-15
Loading... done!

Roses are red,
Violets are blue.
She said, 'Python is fun!'
It's a great day.
```

Here is what each trick does:

-   **`sep="-"`** changes the separator between items from a space to whatever you choose.
-   **`end=""`** stops `print()` from moving to a new line afterward, so the next print continues on the same line.
-   **`print()`** with nothing inside prints an empty line, handy for spacing.
-   **`\n`** inside a string means "new line here." It is one character even though you type two.
-   **Mixing quotes** lets you put one kind of quote inside the other. Use double quotes on the outside when your text has an apostrophe, like `"It's"`.

:::tip
Want a quick divider line? Multiply a string by a number: `print("=" * 20)` prints twenty equals signs in a row.
:::

## Comments: notes for humans

A **comment** starts with `#`. Python ignores everything from the `#` to the end of that line. Comments explain *why* code exists, label sections, and let you switch a line off without deleting it.

```python
# Recipe card printer
# Prints a short recipe so I can practice print().

print("=== Peanut Butter Toast ===")  # the title
print("1. Toast the bread.")
print("2. Spread peanut butter.")
# print("3. Add pickles.")   <- turned off for now
print("3. Enjoy!")
```

```text
=== Peanut Butter Toast ===
1. Toast the bread.
2. Spread peanut butter.
3. Enjoy!
```

The pickle line never runs because it starts with `#`. Turning code into a comment like this is called **commenting out**, and it is a great way to test ideas.

## Writing readable code

Code is read far more often than it is written, by your teammates, your instructor, and by you next week. A few habits make a big difference:

-   **Start each file with a comment** saying what the program does.
-   **Use blank lines** to separate sections, like paragraphs in an essay.
-   **Comment the why, not the obvious.** `# print hello` above `print("hello")` adds nothing. `# Banner shown before the game starts` helps.
-   **Keep lines short** so they fit on screen without scrolling sideways.
-   **Put one space after `#`** and two spaces before a comment that follows code on the same line. This matches the official Python style guide.

## What usually goes wrong

Forgetting the quotes makes Python think your text is the name of something:

```python
print(Hello)
```

```text
Traceback (most recent call last):
  File "hello.py", line 1, in <module>
    print(Hello)
          ^^^^^
NameError: name 'Hello' is not defined
```

Forgetting the *closing* quote leaves the string open forever:

```python
print("Hello)
```

```text
  File "hello.py", line 1
    print("Hello)
          ^
SyntaxError: unterminated string literal (detected at line 1)
```

Other classic slips:

-   **`Print` with a capital P.** Python is case-sensitive, so `Print` and `print` are different names.
-   **Missing a parenthesis.** Every `(` needs a `)`. IDLE highlights the matching one when you type the closing bracket, so watch for it.
-   **Curly quotes** copied from a document. Retype them in IDLE.

When you see an error, read the **last line first**. It names the kind of error and usually tells you what is missing.
