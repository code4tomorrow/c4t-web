Here are two lines of Python that differ by exactly two characters:

```python run
print("2 + 3")
print(2 + 3)
```

The first prints `2 + 3`. The second prints `5`. Those two quote marks are the difference between "show this text" and "work this out", and most of this week comes down to knowing which one you mean.

## Python follows your lines in order, every time

A program is a list of instructions in a text file. When you press **F5**, Python starts at line 1, does exactly what it says, moves to line 2, and keeps going to the bottom. It never skips ahead, never guesses what you meant, and never rearranges anything.

Step through this one and watch the output panel fill in, one line per step:

:::trace Watch the output appear line by line
```python

print("Today we write real programs.")
print("Python runs these from top to bottom.")
```
:::

Swap the first two lines in your own copy and the first two lines of output swap with them. The order you write is the order you get.

## The parts of a print() call

```python run
print("Hello")
```

Every piece has a job:

-   `print` is the name of a **function**, a built-in command that does one job. This one displays things in the Shell.
-   The **parentheses** `( )` hold whatever you want displayed. No parentheses, no printing.
-   The **quotes** mark where a piece of text starts and stops. Programmers call a piece of text a **string**, as in a string of characters.

Double quotes `"like this"` and single quotes `'like this'` both work. Close a string with the same kind of quote you opened it with.

## Quotes mean "show this exactly"

Inside quotes, Python treats every character as plain text and copies it to the screen. Outside quotes, Python treats what you wrote as something to *calculate* first, then prints the answer.

```python run
print("2 + 3")
print(2 + 3)
print("I have", 3, "cats and", 2, "dogs.")
print("Total pets:", 3 + 2)
```

Look at the last two lines. When you give `print()` several items separated by commas, it prints them all on one line with **one space between each**. That's why `"I have", 3` comes out as `I have 3` even though you never typed that space. In the last line, `3 + 2` sits outside the quotes, so Python adds it up before printing.

## Shaping the output: sep, end, and friends

`print()` takes a few extra settings for laying out text exactly how you want. Predict each line of output before you look at the result.

```python run
print("2026", "11", "15", sep="-")
print("Loading", end="")
print("...", end="")
print(" done!")
print()
print("Roses are red,\nViolets are blue.")
print("She said, 'Python is fun!'")
print("It's a great day.")
print("=" * 20)
```

What each trick does:

-   **`sep="-"`** replaces the space between items with whatever you choose. Here the three pieces of the date are glued with dashes.
-   **`end=""`** stops `print()` from starting a new line afterward, so the next `print()` keeps writing on the same line. Three calls built `Loading... done!`.
-   **`print()`** with nothing inside prints an empty line, which is handy for spacing.
-   **`\n`** inside a string means "start a new line here". You type two characters, a backslash and an `n`, but Python treats them as one.
-   **Mixing quotes** lets one kind sit inside the other. Use double quotes on the outside when the text has an apostrophe, like `"It's"`.
-   **`"=" * 20`** repeats a string 20 times. It's the quickest way to draw a divider.

The `end=""` idea is the one that trips people up, because the effect shows up on the *next* line of code. Step through it and watch where each piece lands:

:::trace See how `end` keeps writing on the same line
```python
print("Ready", end="... ")
print("Set", end="... ")
print("Go!")
print("Done.")
```
:::

## Comments: notes for humans

A **comment** starts with `#`. Python ignores everything from the `#` to the end of that line, so comments are free to say anything. Use them to explain *why* code exists, to label sections, and to switch a line off without deleting it.

```python run title="recipe_card.py"
# recipe_card.py
# Prints a short recipe so I can practice print().

print("=== Peanut Butter Toast ===")  # the title
print("1. Toast the bread.")
print("2. Spread peanut butter.")
# print("3. Add pickles.")   <- switched off for now
print("3. Enjoy!")
```

The pickle step never prints, because its line starts with `#`. Turning code into a comment like this is called **commenting out**. It's the fastest way to test "what happens without this line?" without losing the line. In IDLE you can select several lines and choose **Format › Comment Out Region** to do them all at once, and **Format › Uncomment Region** to bring them back.

:::note
A `#` *inside* quotes is just a character, not a comment. `print("Use a #2 pencil")` prints the whole sentence, `#2` included.
:::

## Habits that make code readable

Code gets read far more often than it gets written: by classmates, by your instructor, and by you next week when you've forgotten how it works. A few habits help a lot:

-   **Start each file with a comment** that says what the program does.
-   **Use blank lines** to separate sections, like paragraphs in an essay.
-   **Comment the why, not the obvious.** `# print hello` above `print("hello")` adds nothing. `# Banner shown before the game starts` tells the reader something the code can't.
-   **Put one space after `#`**, and two spaces before a comment that sits at the end of a line of code. That's what Python's official style guide, PEP 8, recommends.

## The two errors you'll meet first

**Forgetting the quotes.** Without quotes, Python thinks `Hello` is the name of something it should already know about. It doesn't, so it stops:

```python run raises
print(Hello)
```

`NameError` means "I don't recognize that name." The fix is `print("Hello")`.

**Forgetting the closing quote.** Now the string never ends, and Python reaches the end of the line still inside it:

```python run raises
print("Hello)
```

"Unterminated string literal" is Python's way of saying "this text never stops." Add the missing `"` before the `)`.

:::warning
Three more slips to watch for: `Print` with a capital P (Python is case-sensitive, so it's a different name), a missing `)` at the end of a line, and curly quotes `“ ”` pasted from a document. When you see any error, read the **last line first**. It names the kind of error and usually says what's wrong.
:::

:::quiz
Q: What does `print("5", 5 + 5)` show?
- [ ] `5 5 + 5`
  Only the first `5` is in quotes. The `5 + 5` is outside them, so Python adds it first.
- [x] `5 10`
  The string `"5"` prints as-is, the sum becomes 10, and the comma adds one space between them.
- [ ] `510`
  Commas in `print()` always put a space between items unless you change `sep`.

Q: A program runs `print("A", "B", "C", sep="")`, then `print("D", end="!")`, then `print("E")`. What appears?
- [ ] `A B C`, then `D!`, then `E` on three lines
  `sep=""` removes the spaces, and `end="!"` stops the line break after D.
- [x] `ABC` on one line, then `D!E` on the next
  No separator joins A, B, and C. Then `end="!"` replaces the line break, so E lands right after the `!`.
- [ ] `ABCD!E` all on one line
  The first `print()` still ends with a normal line break. Only the second one changed its `end`.

Q: Which line prints nothing at all?
- [ ] `print("# not a comment")`
  The `#` is inside quotes, so it's just text, and the whole string prints.
- [ ] `print()`
  This prints an empty line. You'd see the gap.
- [x] `# print("hello")`
  The line starts with `#`, so Python skips all of it.

Q: You run `print("Score:" 10)` and get a `SyntaxError`. What's missing?
- [ ] Quotes around `10`
  Numbers don't need quotes. `print("Score:", 10)` works fine.
- [x] A comma between the two items
  Each item you give `print()` must be separated by a comma.
- [ ] A second pair of parentheses
  One pair holds everything you want to print.
:::

:::takeaways
-   Python runs a program from the first line to the last, in order.
-   Text in quotes prints exactly as typed; code outside quotes is worked out first.
-   Commas in `print()` add a space between items. `sep` changes that space, and `end` changes the line break at the end.
-   `\n` starts a new line inside a string, and `"=" * 20` repeats a string.
-   `#` starts a comment. Use comments to explain why, and to switch lines off while testing.
-   Read error messages from the bottom line up.
:::
