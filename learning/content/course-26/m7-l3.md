:::objectives
- Write functions that take parameters and `return` an answer instead of printing it.
- Test a function with values whose answers you already know, including the boundaries.
- Fix syntax, indentation, name, and type errors one at a time by reading each traceback.
- Find a logic error that produces a wrong answer with no error message.
:::

This set has two halves. Exercises 1 to 4 have you **write** functions. Exercises 5 and 6 hand you **broken** code to fix. Debugging is a skill like any other: the more bugs you've met, the faster you recognize the next one, and your capstone will give you plenty of chances.

For every function you write, put a few test calls at the bottom with inputs where you already know the answer. If the function gets those right, you can trust it inside a bigger program.

## Warm-up: follow the calls

Predict all three lines this prints before you step through it. Watch the call stack: a `mystery()` box appears for each call and disappears when it returns.

:::trace Predict the output, then step through
```python
def mystery(n):
    print("got", n)
    return n + 1

a = mystery(1)
b = mystery(a * 10)
print(a, b)
```
:::

The second call is the tricky one. `a` is 2 by then, so `a * 10` is 20, and the function prints `got 20` and returns 21. The `print` inside the function and the value it returns are two separate things.

### Exercise 1: Square it

Write a function `square(n)` that **returns** `n` times `n`. Then use a `for` loop to print the squares of 1 through 5.

```text
1 -> 1
2 -> 4
3 -> 9
4 -> 16
5 -> 25
```

:::hint
The function body is one line, and it starts with `return`. The printing happens outside the function, in the loop, using whatever `square(i)` hands back.
:::

:::solution
```python run title="square.py"
def square(n):
    return n * n

for i in range(1, 6):
    print(i, "->", square(i))
```

If you wrote `print(n * n)` inside the function instead of `return`, each square would print on its own line, and then the loop's `print` would show `None`, because the function handed nothing back.
:::

### Exercise 2: Temperature converter

Write `to_fahrenheit(celsius)` using the formula F = C × 9 / 5 + 32. Loop over `temps_c = [0, 21, 37, 100]` and print each conversion.

```text
0 C is 32.0 F
21 C is 69.8 F
37 C is 98.6 F
100 C is 212.0 F
```

:::hint
Turn the formula straight into a `return` line. Then loop over the list, calling your function on each item. Which values in the list could you check without a calculator?
:::

:::solution
```python run title="temps.py"
def to_fahrenheit(celsius):
    return celsius * 9 / 5 + 32

temps_c = [0, 21, 37, 100]
for c in temps_c:
    print(c, "C is", to_fahrenheit(c), "F")
```

0 → 32 and 100 → 212 are the freezing and boiling points of water. That makes them perfect test values: you know the answers by heart, so a typo in the formula would jump out immediately.
:::

### Exercise 3: Letter grades

Write `letter_grade(score)` that returns `"A"` for 90 and up, `"B"` for 80 to 89, `"C"` for 70 to 79, `"D"` for 60 to 69, and `"F"` below 60. Test it on `[95, 90, 85, 72, 64, 30]`.

```text
95 A
90 A
85 B
...
30 F
```

:::hint
An `if`/`elif` chain with a `return` in every branch. Start from the top grade and work down; once a branch returns, the function is finished, so later checks don't need an upper limit.
:::

:::solution
```python run title="grades.py"
def letter_grade(score):
    if score >= 90:
        return "A"
    elif score >= 80:
        return "B"
    elif score >= 70:
        return "C"
    elif score >= 60:
        return "D"
    else:
        return "F"

for s in [95, 90, 85, 72, 64, 30]:
    print(s, letter_grade(s))
```

Because `return` ends the function immediately, only one branch can ever answer. Testing exactly 90 checks the boundary, which is where `>` versus `>=` mistakes show up.
:::

### Exercise 4: Step counter

Write `count_above(numbers, limit)` that returns how many items in the list `numbers` are greater than `limit`. Use it twice on the same list with two different limits.

```text
Days over 10,000 steps: 3
Days over 5,000 steps: 5
```

:::hint
Inside the function, it's the counter pattern from Week 4: start at 0, loop over the list, add 1 when an `if` is true. The difference is that `return count` goes at the very end, after the loop.
:::

:::solution
```python run title="steps.py"
def count_above(numbers, limit):
    count = 0
    for n in numbers:
        if n > limit:
            count = count + 1
    return count

steps = [4200, 10500, 8000, 12000, 9999, 15000]
print("Days over 10,000 steps:", count_above(steps, 10000))
print("Days over 5,000 steps:", count_above(steps, 5000))
```

Parameters make the function reusable. The same five lines answer both questions, and they'd work on any list and any limit.
:::

### Exercise 5: Bug hunt

This program should ask for a name and a number, shout the name, and then print the name that many times. It has **four** bugs. Fix them one at a time: run it, read the error, fix *only that one thing*, and run again. (`.upper()` turns text into capital letters.)

```python
def shout(word)
    return word.upper() + "!"

def repeat(word, times):
print(word * times)

name = input("Your name: ")
times = input("How many times? ")
print(shout(nmae))
repeat(name, times)
```

Goal output:

```text
Your name: Sam
How many times? 3
SAM!
SamSamSam
```

:::hint
Python reports bugs one at a time, in a fixed order. Problems with how the code is written (colons, indentation) are reported before the program starts. Problems with values (a misspelled name, the wrong type) only appear once the program reaches that line. For the last bug, ask yourself what type `input()` always gives back.
:::

:::solution
**Bug 1.** The first run stops before anything happens:

```python run raises title="bug.py"
def shout(word)
    return word.upper() + "!"

def repeat(word, times):
print(word * times)

name = input("Your name: ")
times = input("How many times? ")
print(shout(nmae))
repeat(name, times)
```

`expected ':'` on line 1. Add the colon: `def shout(word):`.

**Bug 2.** Run again, and Python gets one line further:

```python run raises title="bug.py"
def shout(word):
    return word.upper() + "!"

def repeat(word, times):
print(word * times)

name = input("Your name: ")
times = input("How many times? ")
print(shout(nmae))
repeat(name, times)
```

The body of `repeat` isn't indented. Indent `print(word * times)` so it belongs to the function.

**Bug 3.** Now the program starts and asks its questions (Sam, then 3), and then:

```python run raises title="bug.py" input="Sam|3"
def shout(word):
    return word.upper() + "!"

def repeat(word, times):
    print(word * times)

name = input("Your name: ")
times = input("How many times? ")
print(shout(nmae))
repeat(name, times)
```

It's a typo: change `nmae` to `name`. For small typos, Python often adds a guess like `Did you mean: 'score'?` to the end of the message, but `nmae` is too scrambled for it to suggest anything here.

**Bug 4.** `SAM!` prints this time, and then:

```python run raises title="bug.py" input="Sam|3"
def shout(word):
    return word.upper() + "!"

def repeat(word, times):
    print(word * times)

name = input("Your name: ")
times = input("How many times? ")
print(shout(name))
repeat(name, times)
```

`input()` always hands back a string, so `times` is `"3"`, not `3`, and you can't repeat a string `"3"` times. Convert it with `int()`. The fixed program:

```python run title="bug.py" input="Sam|3"
def shout(word):
    return word.upper() + "!"

def repeat(word, times):
    print(word * times)

name = input("Your name: ")
times = int(input("How many times? "))
print(shout(name))
repeat(name, times)
```

Look back at bug 4's traceback. The crash was *reported* inside `repeat` on line 5, but the real cause was on line 8, where `times` was read without `int()`. A traceback tells you where Python noticed the problem. Sometimes you have to trace backwards to where the bad value came from.
:::

### Exercise 6: The sneaky average

This runs without any error, but `average([10, 20, 30])` should be `20.0`. Run it, work out why the answer is wrong, and fix it.

```python run title="average.py"
def average(numbers):
    total = 0
    for n in numbers:
        total = total + n
        return total / len(numbers)

print(average([10, 20, 30]))
```

:::hint
3.33 is 10 divided by 3. So the function divided before it had added up all three numbers. Which line ends a function immediately, and which block is it indented under?
:::

:::solution
The `return` is indented *inside* the loop. On the first pass, `total` is 10, so the function returns 10 / 3 and stops before it ever sees 20 or 30. Move `return` out one level so it runs after the loop finishes:

```python run title="average.py"
def average(numbers):
    total = 0
    for n in numbers:
        total = total + n
    return total / len(numbers)

print(average([10, 20, 30]))
```

When the answer is wrong but there's no error, add `print("n:", n, "total:", total)` inside the loop. You'd have seen it print only once, which points straight at the bug. In IDLE, **Format > Dedent Region** moves selected lines one level to the left.
:::

### Challenge: Password checker

Write a program that keeps asking for a password until it's strong enough, and lists **every** problem each time. A strong password has at least 8 characters, at least one digit, and at least one capital letter. Use at least three functions. `ch.isdigit()` and `ch.isupper()` tell you whether a single character is a digit or a capital letter.

```text
Choose a password: cat
Not strong enough:
 - use at least 8 characters
 - add a number
 - add a capital letter
Try again: pizzapizza
Not strong enough:
 - add a number
 - add a capital letter
Try again: Pizza2026
Strong password saved!
```

:::hint
Write `has_digit(text)` and `has_upper(text)` first, each returning `True` or `False`, and test them on their own. Then write `problems(password)`, which builds and returns a **list** of messages. An empty list means the password passes, so the main loop can repeat while the list isn't empty.
:::

:::solution
```python run title="password.py" input="cat|pizzapizza|Pizza2026"
def has_digit(text):
    for ch in text:
        if ch.isdigit():
            return True
    return False


def has_upper(text):
    for ch in text:
        if ch.isupper():
            return True
    return False


def problems(password):
    found = []
    if len(password) < 8:
        found.append("use at least 8 characters")
    if not has_digit(password):
        found.append("add a number")
    if not has_upper(password):
        found.append("add a capital letter")
    return found


password = input("Choose a password: ")
issues = problems(password)
while len(issues) > 0:
    print("Not strong enough:")
    for issue in issues:
        print(" -", issue)
    password = input("Try again: ")
    issues = problems(password)
print("Strong password saved!")
```

In `has_digit`, `return True` sits inside the loop on purpose: as soon as one digit turns up, the answer is known. `return False` comes after the loop, because you can only say "no digits" once you've checked every character. Compare that with the bug in Exercise 6, where a `return` inside the loop was exactly the problem.
:::
