This set has two halves. Exercises 1–4 have you **write** functions. Exercises 5–6 hand you **broken** code to fix. Debugging is a skill you build with practice, just like writing code, and you'll do plenty of it on your capstone next week.

For every function you write, add a few test calls at the bottom with inputs where you already know the answer. If the function returns the right thing for those, you can trust it in a bigger program.

### Exercise 1: Square it

Write a function `square(n)` that **returns** `n` times `n`. Then use a `for` loop to print the squares of 1 through 5.

```text
1 -> 1
2 -> 4
3 -> 9
4 -> 16
5 -> 25
```

:::solution
```python
def square(n):
    return n * n

for i in range(1, 6):
    print(i, "->", square(i))
```

If you wrote `print(n * n)` inside the function instead of `return`, you'd see each square printed, followed by `None` from the outer `print`. The function needs to *give back* the value, not show it.
:::

### Exercise 2: Temperature converter

Write `to_fahrenheit(celsius)` using the formula F = C × 9 / 5 + 32. Loop over `temps_c = [0, 21, 37, 100]` and print each conversion.

:::solution
```python
def to_fahrenheit(celsius):
    return celsius * 9 / 5 + 32

temps_c = [0, 21, 37, 100]
for c in temps_c:
    print(c, "C is", to_fahrenheit(c), "F")
```

```text
0 C is 32.0 F
21 C is 69.8 F
37 C is 98.6 F
100 C is 212.0 F
```

0 → 32 and 100 → 212 are the freezing and boiling points of water. That makes them perfect test values, because you already know they're right.
:::

### Exercise 3: Letter grades

Write `letter_grade(score)` that returns `"A"` for 90 and up, `"B"` for 80–89, `"C"` for 70–79, `"D"` for 60–69, and `"F"` below 60. Test it on `[95, 90, 85, 72, 64, 30]`.

:::solution
```python
def letter_grade(score):
    if score >= 90:
        return "A"
    elif score >= 80:
        return "B"
    elif score >= 70:
        return "C"
    elif score >= 60:
        return "D"
    else:
        return "F"

for s in [95, 90, 85, 72, 64, 30]:
    print(s, letter_grade(s))
```

```text
95 A
90 A
85 B
72 C
64 D
30 F
```

Because `return` ends the function right away, only one branch can ever answer. Testing exactly 90 checks the boundary, which is where `>` vs. `>=` mistakes show up.
:::

### Exercise 4: Step counter

Write `count_above(numbers, limit)` that returns how many items in the list `numbers` are greater than `limit`. Use it twice on the same list with different limits.

:::solution
```python
def count_above(numbers, limit):
    count = 0
    for n in numbers:
        if n > limit:
            count = count + 1
    return count

steps = [4200, 10500, 8000, 12000, 9999, 15000]
print("Days over 10,000 steps:", count_above(steps, 10000))
print("Days over 5,000 steps:", count_above(steps, 5000))
```

```text
Days over 10,000 steps: 3
Days over 5,000 steps: 5
```

Parameters make the function reusable. The same code answers both questions, and it would work on any list.
:::

### Exercise 5: Bug hunt

This program should ask for a name and a number, shout the name, and then print the name that many times. It has **four** bugs. Fix them one at a time: run it, read the error, fix *only that*, and run again. (`.upper()` turns text into capital letters.)

```python
def shout(word)
    return word.upper() + "!"

def repeat(word, times):
print(word * times)

name = input("Your name: ")
times = input("How many times? ")
print(shout(nmae))
repeat(name, times)
```

Goal output:

```text
Your name: Sam
How many times? 3
SAM!
SamSamSam
```

:::solution
**Bug 1.** The first run stops before anything happens:

```text
  File "/Users/you/bug.py", line 1
    def shout(word)
                   ^
SyntaxError: expected ':'
```

Add the colon: `def shout(word):`.

**Bug 2.** Run again:

```text
  File "/Users/you/bug.py", line 5
    print(word * times)
    ^^^^^
IndentationError: expected an indented block after function definition on line 4
```

Indent `print(word * times)` so it's inside `repeat`.

**Bug 3.** Now the questions get asked, and then:

```text
Traceback (most recent call last):
  File "/Users/you/bug.py", line 9, in <module>
    print(shout(nmae))
                ^^^^
NameError: name 'nmae' is not defined
```

It's a typo. Change `nmae` to `name`.

**Bug 4.** `SAM!` prints, then:

```text
Traceback (most recent call last):
  File "/Users/you/bug.py", line 10, in <module>
    repeat(name, times)
    ~~~~~~^^^^^^^^^^^^^
  File "/Users/you/bug.py", line 5, in repeat
    print(word * times)
          ~~~~~^~~~~~~
TypeError: can't multiply sequence by non-int of type 'str'
```

`input()` always gives back a string, so `times` is `"3"`, not `3`. You can't repeat a string `"3"` times. Convert it with `int()`.

The fixed program:

```python
def shout(word):
    return word.upper() + "!"

def repeat(word, times):
    print(word * times)

name = input("Your name: ")
times = int(input("How many times? "))
print(shout(name))
repeat(name, times)
```

```text
Your name: Sam
How many times? 3
SAM!
SamSamSam
```

Notice that the error in bug 4 was *reported* inside `repeat` on line 5, but the real cause was back on line 8. A traceback tells you where Python noticed the problem. Sometimes you have to trace backwards to where the bad value came from.
:::

### Exercise 6: The sneaky average

This runs without any error, but `average([10, 20, 30])` should be `20.0`. Run it, work out why it's wrong, and fix it.

```python
def average(numbers):
    total = 0
    for n in numbers:
        total = total + n
        return total / len(numbers)

print(average([10, 20, 30]))
```

```text
3.3333333333333335
```

:::solution
The `return` is indented *inside* the loop. On the first iteration, `total` is 10, so the function returns 10 / 3 and stops before it ever sees 20 or 30. Move `return` out one level so it runs after the loop finishes:

```python
def average(numbers):
    total = 0
    for n in numbers:
        total = total + n
    return total / len(numbers)

print(average([10, 20, 30]))
```

```text
20.0
```

When the answer is wrong but there's no error, add `print("n:", n, "total:", total)` inside the loop. You'd have seen it print only once, which points straight at the bug.
:::

## Stretch challenge: Password checker

Write a program that keeps asking for a password until it's strong enough, and lists **every** problem each time. A strong password has at least 8 characters, at least one digit, and at least one capital letter. Use at least three functions. `ch.isdigit()` and `ch.isupper()` tell you if a single character is a digit or a capital letter.

```text
Choose a password: cat
Not strong enough:
 - use at least 8 characters
 - add a number
 - add a capital letter
Try again: pizzapizza
Not strong enough:
 - add a number
 - add a capital letter
Try again: Pizza2026
Strong password saved!
```

:::solution
`problems()` returns a **list** of messages. An empty list means the password passes.

```python
def has_digit(text):
    for ch in text:
        if ch.isdigit():
            return True
    return False


def has_upper(text):
    for ch in text:
        if ch.isupper():
            return True
    return False


def problems(password):
    found = []
    if len(password) < 8:
        found.append("use at least 8 characters")
    if not has_digit(password):
        found.append("add a number")
    if not has_upper(password):
        found.append("add a capital letter")
    return found


password = input("Choose a password: ")
issues = problems(password)
while len(issues) > 0:
    print("Not strong enough:")
    for issue in issues:
        print(" -", issue)
    password = input("Try again: ")
    issues = problems(password)
print("Strong password saved!")
```

In `has_digit`, `return True` sits inside the loop on purpose. As soon as one digit turns up, we know the answer. `return False` comes after the loop, because we can only say "no digits" once we've checked every character. Compare that with Exercise 6.
:::
