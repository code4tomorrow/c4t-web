For six weeks you've followed along with programs someone else designed. The capstone flips that. **You** decide what to build, and you use everything from this course to make it work from start to finish. Students who pick something they actually care about (their favorite video game, a sport, a tool they'd use themselves) almost always end up with the best projects, because they keep wanting to make it better.

## The brief

Build a **text game, quiz, or tool of your choice** in Python that runs in IDLE.

### Your program must use

| Requirement | Looks like |
| --- | --- |
| Variables | `score = 0`, `name = input(...)` |
| User input | at least one `input()` the program reacts to |
| Conditions | `if` / `elif` / `else` that make a real decision |
| A loop | `for` or `while`, for example a game round or "play again?" |
| A list | storing questions, items, scores, rooms, or answers |
| At least two functions you define | with `def`, and at least one that takes a parameter or returns a value |

### What you hand in

1.  **A `.py` file that runs** from top to bottom without crashing on normal use.
2.  **A test table** showing at least 6 inputs you tried, including **unusual** ones (a blank answer, letters where a number goes, capital letters, a number that's too big), with what you expected and what actually happened.
3.  **One bug you found and fixed**, written up in a few sentences: what went wrong, the error message if there was one, and how you fixed it.
4.  **A short demo** of 2–4 minutes in class, where you run the program and walk through one piece of your code.

## The smallest program that ticks every box

Before you think "that's a lot", here's a short program that already meets every requirement. Yours will be bigger and more *you*, but this shows that the list above is very doable.

```python
# Snack Stand: a tiny program that meets every capstone requirement

snacks = ["popcorn", "pretzel", "lemonade"]    # list
prices = [3, 4, 2]


def show_menu():                                # function 1
    for i in range(len(snacks)):               # loop
        print(str(i + 1) + ".", snacks[i], "$" + str(prices[i]))


def order_total(order):                         # function 2 (returns a value)
    total = 0
    for number in order:
        total = total + prices[number - 1]
    return total


name = input("Name for the order: ")           # input + variable
order = []
show_menu()
pick = input("Item number (or done): ")
while pick != "done":                           # loop
    if pick == "1" or pick == "2" or pick == "3":   # condition
        order.append(int(pick))
    else:
        print("That's not on the menu.")
    pick = input("Item number (or done): ")

print(name + ", you ordered", len(order), "items.")
print("Your total is $" + str(order_total(order)))
```

```text
Name for the order: Jordan
1. popcorn $3
2. pretzel $4
3. lemonade $2
Item number (or done): 1
Item number (or done): 3
Item number (or done): 7
That's not on the menu.
Item number (or done): 1
Item number (or done): done
Jordan, you ordered 3 items.
Your total is $8
```

Notice that `pick` is checked as text (`"1"`) *before* `int()` is called. That's why typing `7` or `banana` prints a friendly message instead of crashing.

## Ideas to get you started

Pick one, mix two, or invent your own.

**Text games**

-   **Rock, paper, scissors, best of 5.** Uses `random.choice(["rock", "paper", "scissors"])`, a score for each player, and a round loop.
-   **Choose-your-path adventure.** Each room is a function, and the player's inventory is a list. Can they find the key before running out of moves?
-   **Word guess (like Hangman).** Keep a list of letters guessed, show `_ _ a _`, and count wrong guesses.
-   **Dice duel.** Two players roll with `random.randint(1, 6)`, and the first to 20 wins.

**Quizzes**

-   **Trivia on a topic you know cold:** soccer, Minecraft, Marvel, a country, your favorite book series.
-   **Study flashcards** for a real class. Questions and answers go in two lists, and the program repeats the ones you missed.
-   **Personality quiz:** "Which planet are you?" Each answer adds points to a category.

**Tools**

-   **Grade calculator.** Enter scores, get the average, letter grade, and what you need on the final.
-   **Allowance or budget tracker.** Add income and expenses to lists, then see the balance and the biggest expense.
-   **Workout or reading log.** Record minutes per day and show the total, average, and best streak.
-   **Recipe scaler.** Scale every ingredient amount in a list for a different number of servings.

:::tip
Scope it so you can finish the basic version in about half your time. You can always add features later. A small program that works beats a giant one that crashes.
:::

## Plan before you code

Spend 20 minutes on paper (or in a comment block at the top of your file). It'll save you hours. Answer these:

```text
PROJECT PLAN
Name of my program:
One sentence: what does it do, and who is it for?

What the user types (inputs):
What the program shows (outputs):

My list(s) will hold:
My loop repeats:
Decisions my program makes (if/elif/else):

Functions (name - what it gets - what it gives back):
  1.
  2.
  3.

Must-have features (the basic version):
Nice-to-have features (only after the basic version works):
```

### Write the user's journey

Write out, step by step, what a person sees and types during one run. This is the "script" your program has to follow:

```text
1. Program says welcome and explains the rules
2. Asks the player's name
3. Asks question 1 -> player answers -> "Correct!" or shows the right answer
4. Repeats for every question in the list
5. Shows the score and a message based on how well they did
6. Asks "Play again?" -> back to step 3, or says goodbye
```

Every line here becomes a few lines of code, and the repeating steps show you exactly where your loop goes.

### Name your functions now

Good function names are verbs that say what the function does: `ask_question`, `show_menu`, `roll_dice`, `get_number`, `calculate_average`. If you can't name a function in two or three words, it's probably doing too many jobs. Split it in two.

## Common planning mistakes

-   **Too big.** "An RPG with 20 levels, shops, and a boss" won't fit. "One dungeon with 3 rooms and a key" will, and it can still be great.
-   **No list.** If your idea doesn't naturally need one, find a place for it: past guesses, high scores, menu items, questions.
-   **Functions as an afterthought.** Plan at least two now. Trying to squeeze them in at the end is much harder.
