The Riverside Animal Shelter is holding an adoption day on Saturday, and they want a poster. They don't have a designer. They have you, and you have `print()`. By the end of class you'll have a program of about 30 lines that prints this:

```text
********************************
*      ADOPT A FRIEND!         *
********************************

    /\_/\
   ( o.o )
    > ^ <

Name: Biscuit
Age: 2 years
Likes: naps | boxes | tuna

Saturday - Nov - 21 @ 10am
Riverside Animal Shelter

================================
```

Every line of it comes from a single `print()` call, or two calls working together. In IDLE, choose **File › New File** and save the empty file as `week1/adoption_poster.py` before you write anything.

## Step 1: Write the plan as comments

Experienced programmers often write the outline before the code. Type these comments first. They do nothing when you run them, but they give the file a shape to fill in, and later they'll tell a reader where each part of the poster lives.

```python run title="adoption_poster.py"
# adoption_poster.py
# Prints a poster for an animal shelter's adoption day.
# Week 1 code-along: practice print(), sep, end, and comments.

# ----- Top border and title -----

# ----- Picture -----

# ----- About the pet -----

# ----- Event details -----

# ----- Bottom border -----
```

Press **F5**. The Shell restarts and then shows nothing at all. That's correct: a file of only comments is a program with no instructions.

## Step 2: The border and the title

Under the "Top border and title" comment, add three lines:

```python run
print("*" * 32)
print("*      ADOPT A FRIEND!         *")
print("*" * 32)
```

`"*" * 32` repeats the star 32 times, so you don't have to type or count them. The middle line is also exactly 32 characters wide, which is why the box lines up. If your right edge looks crooked, count the spaces on each side of the title.

## Step 3: Draw the cat, and meet the backslash

Under "Picture", the obvious first try is to type the cat's ears just as they look:

```python run raises
print("    /\_/\")
```

The error says the string never ended, and Python even guesses why: *perhaps you escaped the end quote?* Inside a string, a backslash `\` doesn't mean "backslash". It means "the next character is special". You already met `\n`, which means "new line". Here, the last `\` grabbed the closing quote and turned it into an ordinary character, so the string has no end.

To print one real backslash, type **two** of them: `\\`. Python reads the pair as a single backslash character.

```python run
print("    /\\_/\\")
print("   ( o.o )")
print("    > ^ <")
```

In your file, add a `print()` before and after the cat to give it some breathing room.

## Step 4: About the pet

Now the details. Commas let you mix text and numbers on one line:

```python run
print("Name:", "Biscuit")
print("Age:", 2, "years")
print("Likes:", "naps", "boxes", "tuna", sep=" | ")
```

Compare the last line with the target poster. There's a stray bar right after `Likes:`. That's because `sep` goes between **every** pair of items, and the label counts as an item. We want bars between the three likes, but a plain space after the label.

The fix: print the label by itself with `end=" "`, so the next `print()` continues on the same line, and give only the likes the `" | "` separator.

```python run
print("Likes:", end=" ")
print("naps", "boxes", "tuna", sep=" | ")
```

Step through the fixed version and watch the cursor stay on the same line after the first call:

:::trace Two print() calls, one line of output
```python
print("Likes:", end=" ")
print("naps", "boxes", "tuna", sep=" | ")
print("Done with the pet section.")
```
:::

Bugs like this are a normal part of building anything. You ran the code, compared the output with what you wanted, spotted the difference, and changed one thing. That's most of programming.

## Step 5: Event details

The date line combines both settings: `sep` glues the parts of the date with dashes, and `end=""` keeps the cursor on the same line so the time lands right after it.

```python run
print("Saturday", "Nov", "21", sep=" - ", end="")
print(" @ 10am")
print("Riverside Animal Shelter")
```

Notice the space at the start of `" @ 10am"`. Because the first call ended with nothing at all, that space is the only thing separating `21` from `@`.

## Step 6: The finished program

Add a bottom border under the last comment, and your file should look like this:

```python run title="adoption_poster.py"
# adoption_poster.py
# Prints a poster for an animal shelter's adoption day.
# Week 1 code-along: practice print(), sep, end, and comments.

# ----- Top border and title -----
print("*" * 32)
print("*      ADOPT A FRIEND!         *")
print("*" * 32)
print()

# ----- Picture -----
# Each backslash is doubled so Python prints one real backslash.
print("    /\\_/\\")
print("   ( o.o )")
print("    > ^ <")
print()

# ----- About the pet -----
print("Name:", "Biscuit")
print("Age:", 2, "years")
print("Likes:", end=" ")
print("naps", "boxes", "tuna", sep=" | ")
print()

# ----- Event details -----
print("Saturday", "Nov", "21", sep=" - ", end="")
print(" @ 10am")
print("Riverside Animal Shelter")
print()

# ----- Bottom border -----
print("=" * 32)
```

Run it with **F5** and check it against the poster at the top of the page. Then read the file from top to bottom. Thanks to the section comments, anyone could find the part that prints the date in a couple of seconds without running anything. The comment above the cat explains the one line that would otherwise look like a typo.

:::warning
If an edit suddenly makes the whole poster fail with a `SyntaxError`, look for a missing closing quote or parenthesis on the line it names, or the line just above. One unclosed `"` swallows the rest of the line, and Python won't run any of the file until it's fixed.
:::

:::quiz
Q: Why does the finished program print the label `Likes:` with its own `print()` call?
- [ ] Python can only print four items at a time
  `print()` accepts as many items as you like.
- [x] So `sep=" | "` applies only to the three likes, not the label
  `sep` goes between every item in one call. Splitting the label off keeps the bar out of it.
- [ ] Because `end` can't be used with `sep`
  They work fine together, as the date line in Step 5 shows.

Q: What would `print("C:\\Users")` show?
- [ ] `C:\\Users`
  The pair of backslashes is one escape code, so only one backslash prints.
- [x] `C:\Users`
  `\\` stands for a single backslash character.
- [ ] A `SyntaxError`
  The string is properly closed; the doubled backslash doesn't touch the quote.

Q: What does the date line print if you delete `end=""` from the first call?
- [ ] `Saturday - Nov - 21 @ 10am`, same as before
  Without `end=""`, the first `print()` finishes with a normal line break.
- [x] `Saturday - Nov - 21` on one line and ` @ 10am` on the next
  The default `end` is a new line, so the second call starts a fresh line.
- [ ] `Saturday Nov 21 @ 10am`
  `sep=" - "` is still there, so the dashes stay.
:::

:::takeaways
-   Writing the plan as comments first gives your program a shape and labels for later.
-   String repetition like `"*" * 32` draws borders without counting characters.
-   A backslash starts an escape code inside a string. Use `\\` to print one real backslash.
-   `sep` goes between every item in a single `print()`, so split a call when only some items should be separated.
-   `end=""` lets two `print()` calls build one line of output.
:::
