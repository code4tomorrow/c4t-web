- Pick the right `range()` for a counting job on the first try.
- Use the accumulator and counter patterns without resetting them by mistake.
- Write `while` loops that stop for the right reason, including after a set number of tries.
- Combine loops with `if` and string tricks to draw a pattern.

Loops click through repetition, which is fitting. Make a new IDLE file for each exercise, run it, and compare what you see with the sample output. Open a hint only after a real attempt, and the solution only after the hint. Ten minutes of being stuck teaches you more than ten seconds of reading an answer.

When a loop misbehaves, add a `print()` inside the body that shows your variables, like `print("i is", i, "total is", total)`. Watching the values change one iteration at a time usually exposes the bug in seconds. Delete the extra line once it's fixed.

## Warm-up: predict the last number

Read this program and decide what the final line prints **before** you step through it. Hint: `x` triples every pass.

:::trace Predict, then step through
```python
x = 1
while x < 50:
    x = x * 3
print(x)
```
:::

Did you say 27? Lots of people do. The loop checks `x < 50` only at the top of each pass. When `x` is 27, the check passes, and the body triples it to 81 before Python checks again. A `while` loop can overshoot its target, because the condition is tested before the body runs, not after.

### Exercise 1: Cheer squad

Print the even numbers from 2 to 20, one per line, and then print `Who do we appreciate?`. Use one `range()` with three numbers and no `if`.

```text
2
4
6
...
20
Who do we appreciate?
```

:::hint
The third number in `range()` is how far to jump each time. Where should you start, how far should you jump, and what stop number makes sure 20 is included?
:::

:::solution
Start at 2, jump by 2, and stop *before* 21 so 20 makes it in.

```python run title="cheer_squad.py"
for n in range(2, 21, 2):
    print(n)
print("Who do we appreciate?")
```

The last `print` isn't indented, so it runs once after the loop ends. `range(2, 20, 2)` would stop at 18.
:::

### Exercise 2: Times table

Ask the user for a number and print its times table from 1 to 10.

```text
Which times table? 7
7 x 1 = 7
7 x 2 = 14
...
7 x 10 = 70
```

:::hint
The number the user types stays the same the whole time. What changes on each line is the number you multiply it by, so that's the loop variable. Remember `int()`, because `input()` gives you text.
:::

:::solution
```python run title="times_table.py" input="7"
n = int(input("Which times table? "))
for i in range(1, 11):
    print(f"{n} x {i} = {n * i}")
```

`range(1, 11)` gives 1 through 10. A common slip is `range(10)`, which starts at 0 and ends at 9, so your table would start with `7 x 0 = 0` and miss `7 x 10`.
:::

### Exercise 3: Add it all up

Ask for a number `n` and print the sum 1 + 2 + 3 + ... + n. There's a story that a young Carl Friedrich Gauss, later a famous mathematician, was told by his teacher to add 1 to 100 and finished almost instantly. Your loop will be even faster. Check that 100 gives `5050`.

```text
Add up 1 to what number? 100
The total is 5050
```

:::hint
This is the accumulator pattern from the notes. You need a variable that starts at 0 *before* the loop. Then think hard about the stop number: does your `range()` include `n` itself?
:::

:::solution
```python run title="add_it_up.py" input="100"
n = int(input("Add up 1 to what number? "))
total = 0
for i in range(1, n + 1):
    total = total + i
print("The total is", total)
```

We stop at `n + 1` because `range` never includes its stop number. With `range(1, n)` you'd get 4950, since 100 itself would be left out. That's the off-by-one error in the wild.
:::

### Exercise 4: Three strikes

The secret password is `tacocat`. Keep asking until the user types it **or** has tried 3 times. Print `Wrong password.` after each wrong try. At the end, print `Access granted.` or `Locked out. Try again later.`

```text
Password: taco
Wrong password.
Password: Tacocat
Wrong password.
Password: tacocat
Access granted.
```

:::hint
This loop has two reasons to stop, just like the guessing game: a correct password, or running out of tries. Join the two "keep going" conditions with `and`. After the loop, check which reason it was.
:::

:::solution
```python run title="three_strikes.py" input="taco|Tacocat|tacocat"
password = "tacocat"
attempts = 0
entry = ""

while entry != password and attempts < 3:
    entry = input("Password: ")
    attempts = attempts + 1
    if entry != password:
        print("Wrong password.")

if entry == password:
    print("Access granted.")
else:
    print("Locked out. Try again later.")
```

`Tacocat` is rejected because string comparisons care about capital letters. `entry = ""` before the loop gives `entry` a starting value that can't be the password. Here's the same program with three wrong tries, to check the other ending:

```python run title="three_strikes.py" input="pizza|pasta|soup"
password = "tacocat"
attempts = 0
entry = ""

while entry != password and attempts < 3:
    entry = input("Password: ")
    attempts = attempts + 1
    if entry != password:
        print("Wrong password.")

if entry == password:
    print("Access granted.")
else:
    print("Locked out. Try again later.")
```
:::

### Exercise 5: Savings goal

You want to save up for something. Ask for the goal and how much you save each week (both can have decimals, so use `float()`). Use a `while` loop to add one week of savings at a time, print the running total each week, and finish by saying how many weeks it took.

```text
Savings goal in dollars: 50
Amount saved each week: 15
Week 1 - saved 15.0
Week 2 - saved 30.0
Week 3 - saved 45.0
Week 4 - saved 60.0
You reach your goal in 4 weeks!
```

:::hint
You need two variables that change every pass: the money saved so far and the number of weeks. What condition should keep the loop going? Think "not there yet".
:::

:::solution
```python run title="savings.py" input="50|15"
goal = float(input("Savings goal in dollars: "))
weekly = float(input("Amount saved each week: "))

saved = 0
weeks = 0
while saved < goal:
    saved = saved + weekly
    weeks = weeks + 1
    print("Week", weeks, "- saved", saved)

print("You reach your goal in", weeks, "weeks!")
```

`while` fits because nobody knows the number of weeks in advance. One more thing to think about: what happens if someone types `0` for the weekly amount? `saved` never grows, so `saved < goal` is `True` forever. That's an infinite loop (Ctrl+C to escape). Can you add an `if` before the loop that catches it and prints a polite message instead?
:::

### Exercise 6: Vowel counter

Ask for a word and count its vowels, capital or lowercase. You'll need a `for` loop over the string, plus one new trick: `letter in "aeiouAEIOU"` is `True` when `letter` is one of those characters.

```text
Type a word: Education
Education has 5 vowels
```

:::hint
Loop over the word one letter at a time. Inside the loop, an `if` decides whether this letter deserves a point. That makes it a counter, so where does `vowels = 0` belong?
:::

:::solution
```python run title="vowels.py" input="Education"
word = input("Type a word: ")
vowels = 0
for letter in word:
    if letter in "aeiouAEIOU":
        vowels = vowels + 1
print(word, "has", vowels, "vowels")
```

On each pass, `letter` holds one character: `E`, then `d`, then `u`, and so on. The counter only goes up when the `if` is `True`. Without the capitals in `"aeiouAEIOU"`, the capital `E` wouldn't count and you'd get 4.
:::

## Before the challenge: strings can be multiplied

Multiplying a string by a whole number repeats it. `"*" * 3` is `"***"`, and `" " * 2` is two spaces. Put that inside a loop and the loop variable controls how long each line is. Step through this staircase and watch the line grow:

:::trace A loop variable that sets the length of each line
```python
for row in range(1, 5):
    print("#" * row)
```
:::

### Challenge: Star pyramid

Ask for a height and print a centered pyramid of stars, like this:

```text
Height: 4
   *
  ***
 *****
*******
```

For a height of 4, here's what each row needs. Your job is to find the rule that turns `row` into these numbers.

| Row | Spaces in front | Stars |
| --- | --- | --- |
| 1 | 3 | 1 |
| 2 | 2 | 3 |
| 3 | 1 | 5 |
| 4 | 0 | 7 |

:::hint
Each row has 2 more stars than the one before, starting from 1. Try doubling the row number and adjusting. The spaces go *down* by one each row and end at 0 on the last row, so they depend on both `height` and `row`.
:::

:::solution
Row `row` (counting from 1) has `2 * row - 1` stars, with `height - row` spaces in front of them.

```python run title="pyramid.py" input="4"
height = int(input("Height: "))
for row in range(1, height + 1):
    print(" " * (height - row) + "*" * (2 * row - 1))
```

Want more? Flip the pyramid upside down by counting `row` down with `range(height, 0, -1)`. Or ask for the character to draw with, so the pyramid can be made of `#` or `@`.
:::
