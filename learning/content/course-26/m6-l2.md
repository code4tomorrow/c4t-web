:::objectives
- Build a menu-driven program that keeps running until the user quits.
- Store tasks in a list and add, show, and remove them as the user asks.
- Translate between the numbers people see (1, 2, 3) and Python's indexes (0, 1, 2).
- Check a number is in range before using it as an index, so the app can't crash on a bad task number.
:::

Every to-do app on your phone, from Google Tasks to Apple Reminders, is built around the same idea as a Python list: an ordered row of items you can add to, read, and remove from. Today you'll build a small one that runs in the IDLE Shell. It shows a menu, the user types a letter, the program changes the list to match, and when they quit it reports what they got done.

This is the shape of the finished program. The whole app lives inside one loop that only ends when the user types `q`.

```mermaid caption="The menu loop: every choice leads back to the menu, except q"
flowchart TD
    A[Show the menu] --> B{What did they type?}
    B -->|a| C[Add a task to the list]
    B -->|s| D[Print the numbered list]
    B -->|d| E[Remove a finished task]
    B -->|anything else| F[Explain the choices]
    C --> A
    D --> A
    E --> A
    F --> A
    B -->|q| G[Print a summary and stop]
```

Create a new file in IDLE and save it as `todo.py`. You'll use a list, `append`, `pop`, `len()`, indexes, `for` loops, and a `while True` loop with `break`.

## Step 1: Show a list with numbers

Start with three tasks already in the list, so there's something to look at:

```python run title="todo.py"
tasks = ["finish math homework", "feed the cat", "practice piano"]

for i in range(len(tasks)):
    print(f"{i + 1}. {tasks[i]}")
```

`range(len(tasks))` gives the indexes 0, 1, 2, and we print `i + 1` because people count from 1. Hold on to that idea: in Step 4, the user will type a number they *see*, and you'll have to turn it back into an index.

## Step 2: A menu that keeps coming back

An app should keep running until the user decides to stop. `while True` repeats forever, and `break` gets us out when the user types `q`. Replace everything in your file with this. The run below tests all three paths: adding a task, a wrong letter, and quitting.

```python run title="todo.py" input="a|walk the dog|x|q"
tasks = []

while True:
    print()
    print("a = add, q = quit")
    choice = input("Choose: ")

    if choice == "a":
        task = input("New task: ")
        tasks.append(task)
        print("Added:", task)
    elif choice == "q":
        print("Bye!")
        break
    else:
        print("Please type a or q.")
```

`print()` with nothing inside prints a blank line, which keeps each menu from running into the last one. The list now starts empty (`[]`) and grows with `append`.

Why `while True` with a `break`, instead of a condition like `while choice != "q"`? Because the program has to *ask* before it can know whether to stop, and the question is in the middle of the loop. `while True` says "keep going", and `break` stops the loop right at the moment the answer comes in.

:::tip
Always include an `else` for "none of the above". Without it, a typo like `x` does nothing at all, and the user can't tell whether the app is broken or just waiting.
:::

## Step 3: Show the tasks

Add a new branch for `s`. If the list is empty, a friendly message beats printing nothing. Put this just above `elif choice == "q":`:

```python
    elif choice == "s":
        if len(tasks) == 0:
            print("Nothing to do. Nice!")
        else:
            for i in range(len(tasks)):
                print(f"{i + 1}. {tasks[i]}")
```

Watch the indentation. The `elif` lines up with `if choice == "a":`, the `for` sits inside the `else`, and the `print` sits inside the `for`. That's three levels deep. Update the menu line to `"a = add, s = show, q = quit"` too. Here's the whole file so far, tested with an `s` before anything's been added, then an add, then another `s`:

```python run title="todo.py" input="s|a|feed the cat|s|q"
tasks = []

while True:
    print()
    print("a = add, s = show, q = quit")
    choice = input("Choose: ")

    if choice == "a":
        task = input("New task: ")
        tasks.append(task)
        print("Added:", task)
    elif choice == "s":
        if len(tasks) == 0:
            print("Nothing to do. Nice!")
        else:
            for i in range(len(tasks)):
                print(f"{i + 1}. {tasks[i]}")
    elif choice == "q":
        print("Bye!")
        break
    else:
        print("Please type a, s, or q.")
```

## Step 4: Check off a task

To remove a task by its position, use `pop` with an index. `tasks.pop(1)` removes the item at index 1 and hands it back, so you can print it. Before adding it to the app, try the idea on its own. Step through and watch the list close up the gap:

:::trace The user picks task 2, which is index 1
```python
tasks = ["finish math homework", "feed the cat", "practice piano"]
number = 2
finished = tasks.pop(number - 1)
print("Finished:", finished)
print(tasks)
```
:::

The user sees task **2**, but Python stores it at index **1**. That's why we `pop(number - 1)`. And after the pop, `"practice piano"` slid from index 2 to index 1, so it would show up as task 2 next time.

There's one more danger: `tasks.pop(7)` on a three-item list crashes with `IndexError`. So we check that the number is between 1 and the length of the list before popping. Add this branch next to the others:

```python
    elif choice == "d":
        number = int(input("Which task number is done? "))
        if number >= 1 and number <= len(tasks):
            finished = tasks.pop(number - 1)
            print("Finished:", finished)
        else:
            print("There is no task number", number)
```

## Step 5: Keep score and say goodbye

A second list, `done`, collects finished tasks. Each time you `pop` from `tasks`, `append` the same item to `done`. When the user quits, loop over `done` to show what they got through. Here's the finished program, with a full test run: three tasks added, the list shown, task 2 finished, a task number that doesn't exist, the list shown again, and quit.

```python run title="todo.py" input="a|finish math homework|a|feed the cat|a|practice piano|s|d|2|d|7|s|q"
tasks = []
done = []

print("=== My To-Do List ===")
while True:
    print()
    print("a = add, s = show, d = done, q = quit")
    choice = input("Choose: ")

    if choice == "a":
        task = input("New task: ")
        tasks.append(task)
        print("Added:", task)

    elif choice == "s":
        if len(tasks) == 0:
            print("Nothing to do. Nice!")
        else:
            for i in range(len(tasks)):
                print(f"{i + 1}. {tasks[i]}")

    elif choice == "d":
        number = int(input("Which task number is done? "))
        if number >= 1 and number <= len(tasks):
            finished = tasks.pop(number - 1)
            done.append(finished)
            print("Finished:", finished)
        else:
            print("There is no task number", number)

    elif choice == "q":
        print("You finished", len(done), "tasks today:")
        for task in done:
            print("  *", task)
        print("Still to do:", len(tasks))
        break

    else:
        print("Please type a, s, d, or q.")
```

Look at the second `s` in the output. After `feed the cat` was popped, `practice piano` moved up from number 3 to number 2. The list closed the gap, exactly like the trace in Step 4. And task number 7 got a polite message instead of a crash, thanks to the range check.

:::quiz
Q: The user types `3` to finish their third task. Why does the code call `tasks.pop(number - 1)`?
- [ ] Because `pop` always removes the item before the one you name
  `pop(i)` removes exactly the item at index `i`. The `- 1` is about how people count.
- [x] Because the user counts from 1 but Python's indexes start at 0
  Task 3 on screen is stored at index 2, so we subtract 1 to translate.
- [ ] To leave the last task in the list
  Subtracting 1 changes which index is used, not how many items stay.

Q: What would happen without the check `number >= 1 and number <= len(tasks)`?
- [ ] Nothing different, because `pop` ignores numbers that are too big
  `pop` doesn't ignore them. Asking for an index past the end crashes.
- [x] Typing a task number that doesn't exist would crash the app with `IndexError`
  `tasks.pop(6)` on a 3-item list has nowhere to look. The check catches it and prints a message instead.
- [ ] The app would remove the last task instead
  Only `pop()` with no index removes the last item. A bad index is an error.

Q: Why is the whole app inside `while True` with a `break`, rather than a loop that runs a fixed number of times?
- [x] Nobody knows how many choices the user will make before quitting
  `while True` keeps the menu coming back as long as needed, and `break` ends it the moment the user types `q`.
- [ ] `for` loops can't contain `if` statements
  They can. The problem is that a `for` loop needs to know how many times to run.
- [ ] `break` is required for any program that uses `input()`
  Many programs use `input()` without `break`. Here it's simply the cleanest way to stop a menu loop.
:::

:::takeaways
- A menu app is a `while True` loop: show the choices, read one, act on it, and `break` on quit.
- Give every menu an `else` so wrong input gets a helpful message.
- People count from 1, Python from 0: show `i + 1`, and use `number - 1` to turn a typed number back into an index.
- `pop(index)` removes an item and hands it back, and the items after it shift down to fill the gap.
- Check a number is in range before using it as an index.
:::
