## Warm-up: one value, two types

Predict both numbers this prints before you run it. One of them surprises most people.

```python run
a = "3"
b = 3
print(a * 2, b * 2)
```

`a` is the string `"3"`, so doubling it repeats it: `33`. `b` is the number 3, so doubling it gives `6`. Same-looking values, different types, completely different results.

### Exercise 1: Trace it by hand

Without running it, predict exactly what this program prints. Write your answer down, then run it.

```python
coins = 5
gems = coins
coins = coins + 2
gems = gems * 10
print(coins, gems)
```

:::hint
Make a table with a `coins` column and a `gems` column. Go one line at a time, and write the new value in the right column. On line 2, ask: does `gems` get the *name* `coins`, or the value 5?
:::

:::solution
```python run title="ex1_trace.py"
coins = 5
gems = coins
coins = coins + 2
gems = gems * 10
print(coins, gems)
```

`coins` starts at 5. `gems = coins` gives `gems` the **value** 5. When `coins` becomes 7 on line 3, `gems` doesn't change: it isn't connected to `coins`, it just got a copy of what `coins` held at that moment. Then `gems` becomes 5 × 10 = 50.

The most common wrong answer is `7 70`, which assumes `gems` keeps following `coins`. For numbers and strings, it doesn't.
:::


### Exercise 2: Favorite color greeting

Ask the user for their name and their favorite color, then print two lines with f-strings. A run where the user types `Sam` and `teal` should look like this:

```text
What is your name? Sam
What is your favorite color? teal
Hi Sam! teal is a great color.
Sam + teal = best team ever
```

:::hint
Two `input()` calls, two variables, two f-strings. Does either answer need converting?
:::

:::solution
```python run title="ex2_colors.py" input="Sam|teal"
name = input("What is your name? ")
color = input("What is your favorite color? ")
print(f"Hi {name}! {color} is a great color.")
print(f"{name} + {color} = best team ever")
```

No conversion is needed. Names and colors are text, so the strings from `input()` are already the right type. The `+` in the second line is just a character inside the f-string, not an operator.
:::

### Exercise 3: Type detective

For each line, predict whether `type()` will say `str`, `int`, `float`, or `bool`. Then run it.

```python
print(type("7"))
print(type(7))
print(type(7.0))
print(type(False))
print(type("False"))
print(type(7 / 7))
```

:::hint
Two of these are traps. Look for quote marks, and remember what kind of number `/` always gives you.
:::

:::solution
```python run title="ex3_types.py"
print(type("7"))
print(type(7))
print(type(7.0))
print(type(False))
print(type("False"))
print(type(7 / 7))
```

The traps are `"False"`, which has quotes and is therefore a string, and `7 / 7`. Division with `/` always gives a float, even when the answer is a whole number, so the result is `1.0`.

### Exercise 4: Temperature converter

Write `temp_converter.py`. It asks for a temperature in Fahrenheit, converts it to Celsius with the formula `(F - 32) * 5 / 9`, and prints the result rounded to one decimal place.

Test it with three inputs. You should get these results:

```text
Temperature in Fahrenheit: 98.6
98.6 F is 37.0 C
```

```text
Temperature in Fahrenheit: 32
32.0 F is 0.0 C
```

```text
Temperature in Fahrenheit: -40
-40.0 F is -40.0 C
```

:::hint
Temperatures like 98.6 have decimals, which tells you which conversion to use. Copy the formula exactly, parentheses included.
:::

:::solution
```python run title="temp_converter.py" input="98.6"
# temp_converter.py
# Converts a temperature from Fahrenheit to Celsius.

fahrenheit = float(input("Temperature in Fahrenheit: "))
celsius = (fahrenheit - 32) * 5 / 9
print(f"{fahrenheit} F is {round(celsius, 1)} C")
```

Use `float()`, not `int()`, because `int("98.6")` would crash. The parentheses around `fahrenheit - 32` matter: without them, Python would work out `32 * 5 / 9` first and subtract that instead. You'll learn the full order of operations next week. Try 32 and -40 yourself; -40 is the one temperature that's the same on both scales.
:::

### Exercise 5: The reading-log bug

This program is supposed to tell you how many pages you read in a week. Here's what happens when the user types `20`:

```python run input="20" title="reading_log.py"
pages_per_day = input("How many pages do you read per day? ")
days = 7
pages_per_week = pages_per_day * days
print("You read " + pages_per_week + " pages a week!")
```

Explain why, then fix it so it prints `You read 140 pages a week!`.

:::hint
Fixing the first problem reveals a second one. That's completely normal. After you add a conversion, run it again and read the new message.
:::

:::solution
`input()` returned the string `"20"`, and a string times 7 repeats it seven times. Converting with `int()` fixes the math, but then the program crashes on the last line:

```python run raises input="20" title="reading_log.py"
pages_per_day = int(input("How many pages do you read per day? "))
days = 7
pages_per_week = pages_per_day * days
print("You read " + pages_per_week + " pages a week!")
```

Now `pages_per_week` is the number 140, and `+` can't join a string to a number. An f-string fixes that too, because it converts whatever is in the braces to text for you:

```python run input="20" title="reading_log.py"
pages_per_day = int(input("How many pages do you read per day? "))
days = 7
pages_per_week = pages_per_day * days
print(f"You read {pages_per_week} pages a week!")
```
:::

### Exercise 6: Swap two variables

Start with these two lines:

```python
left = "cat"
right = "dog"
```

Add lines that swap the values, so that the program then prints `left is dog, right is cat`. The rule: you may not type `"cat"` or `"dog"` again.

:::hint
Try `left = right` followed by `right = left` and trace it in your table. What happened to `"cat"`? You need somewhere to keep it safe for a moment, the way you'd use a third cup to swap the drinks in two full cups.
:::

:::solution
```python run title="ex6_swap.py"
left = "cat"
right = "dog"

spare = left      # keep "cat" safe
left = right      # left is now "dog"
right = spare     # right gets "cat" back

print(f"left is {left}, right is {right}")
```

The obvious attempt, `left = right` then `right = left`, leaves both variables holding `"dog"`, because the first line throws away `"cat"` before anything saved it. A third variable holds it for one step. Python also has a shortcut, `left, right = right, left`, which you'll see in other people's code.
:::

Step through the swap and watch `spare` hold `"cat"` while the other two change:

:::trace The three-cup swap
```python
left = "cat"
right = "dog"
spare = left
left = right
right = spare
print(left, right)
```
:::

### Challenge: Bill splitter

Three friends go out for pizza. Write `bill_splitter.py` that asks for the bill total, the tip percent, and the number of people. It prints the tip, the total with tip, and what each person pays.

Money should always show two decimal places, and `round(6.0, 2)` shows `6.0`, which looks odd on a receipt. Use the `:.2f` format code instead: `f"{price:.2f}"` shows a number with exactly two decimals.

Target runs:

```text
Bill total in dollars: 40
Tip percent (for example 15): 15
How many people are splitting it? 3

Tip:        $6.00
Total:      $46.00
Each pays:  $15.33
```

```text
Bill total in dollars: 48.50
Tip percent (for example 15): 18
How many people are splitting it? 3

Tip:        $8.73
Total:      $57.23
Each pays:  $19.08
```

:::hint
Decide on a type for each of the three answers first. Then remember that 15 percent means 15 divided by 100. Work out the tip, then the total, then each share, storing each in its own variable.
:::

:::solution
```python run title="bill_splitter.py" input="48.50|18|3"
# bill_splitter.py
# Splits a restaurant bill, including tip, between friends.

bill = float(input("Bill total in dollars: "))
tip_percent = int(input("Tip percent (for example 15): "))
people = int(input("How many people are splitting it? "))

tip = bill * tip_percent / 100
total = bill + tip
each = total / people

print()
print(f"Tip:        ${tip:.2f}")
print(f"Total:      ${total:.2f}")
print(f"Each pays:  ${each:.2f}")
```

Each answer gets the type that fits it. The bill can have cents, so it's a `float`. The tip percent and the number of people are whole numbers, so they're `int`s. Dividing by 100 turns 18 into 0.18. Try typing `0` for the number of people and read the error. Next week you'll learn how to stop that from happening.
:::
