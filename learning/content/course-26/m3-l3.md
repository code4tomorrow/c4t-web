### Exercise 1: Trace it by hand

Without running it, predict exactly what this program prints. Write your answer down, then run it to check.

```python
coins = 5
gems = coins
coins = coins + 2
gems = gems * 10
print(coins, gems)
```

:::solution
```text
7 50
```

Go line by line. `coins` starts at 5. `gems = coins` copies the **value** 5 into `gems`. Then `coins` becomes 7, but `gems` does not change, because it got its own copy of 5 back on line 2. Finally `gems` becomes 5 × 10 = 50.

The common wrong answer is `7 70`, which assumes `gems` "follows" `coins`. For numbers and strings, it does not.
:::

### Exercise 2: Favorite color greeting

Ask the user for their name and their favorite color, then print two lines using f-strings. A run where the user types `Sam` and `teal` should look like this:

```text
What is your name? Sam
What is your favorite color? teal
Hi Sam! teal is a great color.
Sam + teal = best team ever
```

:::solution
```python
name = input("What is your name? ")
color = input("What is your favorite color? ")
print(f"Hi {name}! {color} is a great color.")
print(f"{name} + {color} = best team ever")
```

No conversion is needed: names and colors are text, so the strings from `input()` are already the right type.
:::

### Exercise 3: Type detective

For each line, predict whether `type()` will say `str`, `int`, `float`, or `bool`. Then run it.

```python
print(type("7"))
print(type(7))
print(type(7.0))
print(type(False))
print(type("False"))
print(type(7 / 7))
```

:::solution
```text
<class 'str'>
<class 'int'>
<class 'float'>
<class 'bool'>
<class 'str'>
<class 'float'>
```

The two traps are `"False"`, which has quotes and is therefore a string, and `7 / 7`. Division with `/` always gives a float, even when the answer is a whole number, so the result is `1.0`.
:::

### Exercise 4: Temperature converter

Write `temp_converter.py`. It asks for a temperature in Fahrenheit, converts it to Celsius with the formula `(F - 32) * 5 / 9`, and prints the result rounded to one decimal place.

Test it with these three inputs. You should get:

```text
Temperature in Fahrenheit: 98.6
98.6 F is 37.0 C
```

```text
Temperature in Fahrenheit: 32
32.0 F is 0.0 C
```

```text
Temperature in Fahrenheit: -40
-40.0 F is -40.0 C
```

:::solution
```python
# temp_converter.py
# Converts a temperature from Fahrenheit to Celsius.

fahrenheit = float(input("Temperature in Fahrenheit: "))
celsius = (fahrenheit - 32) * 5 / 9
print(f"{fahrenheit} F is {round(celsius, 1)} C")
```

Use `float()`, not `int()`, because temperatures like 98.6 have decimals. The parentheses around `fahrenheit - 32` matter: without them, Python would multiply `32 * 5 / 9` first. You will learn the full order of operations next week.
:::

### Exercise 5: The reading-log bug

This program is supposed to tell you how many pages you read in a week. Run it and type `20`.

```python
pages_per_day = input("How many pages do you read per day? ")
days = 7
pages_per_week = pages_per_day * days
print("You read " + pages_per_week + " pages a week!")
```

It prints:

```text
How many pages do you read per day? 20
You read 20202020202020 pages a week!
```

Explain why, then fix it so it prints `You read 140 pages a week!`.

:::tip
Fixing the first problem reveals a second one. That is completely normal.
:::

:::solution
`input()` returns the string `"20"`, and a string times 7 repeats the text seven times. Converting with `int()` fixes the math, but then the program crashes:

```text
Traceback (most recent call last):
  File "reading_log.py", line 4, in <module>
    print("You read " + pages_per_week + " pages a week!")
          ~~~~~~~~~~~~^~~~~~~~~~~~~~~~
TypeError: can only concatenate str (not "int") to str
```

Now `pages_per_week` is the number `140`, and `+` cannot join a string to a number. Switching to an f-string fixes that too:

```python
pages_per_day = int(input("How many pages do you read per day? "))
days = 7
pages_per_week = pages_per_day * days
print(f"You read {pages_per_week} pages a week!")
```

```text
How many pages do you read per day? 20
You read 140 pages a week!
```
:::

### Exercise 6: Bill splitter (stretch challenge)

Three friends go out for pizza. Write `bill_splitter.py` that asks for the bill total, the tip percent, and the number of people. It prints the tip, the total with tip, and what each person pays.

Money should always show two decimal places. `round(6.0, 2)` prints `6.0`, which looks odd on a receipt. Look up the `:.2f` format code: `f"{price:.2f}"` shows a number with exactly two decimals.

Expected runs:

```text
Bill total in dollars: 40
Tip percent (for example 15): 15
How many people are splitting it? 3

Tip:        $6.00
Total:      $46.00
Each pays:  $15.33
```

```text
Bill total in dollars: 48.50
Tip percent (for example 15): 18
How many people are splitting it? 3

Tip:        $8.73
Total:      $57.23
Each pays:  $19.08
```

:::solution
```python
# bill_splitter.py
# Splits a restaurant bill, including tip, between friends.

bill = float(input("Bill total in dollars: "))
tip_percent = int(input("Tip percent (for example 15): "))
people = int(input("How many people are splitting it? "))

tip = bill * tip_percent / 100
total = bill + tip
each = total / people

print()
print(f"Tip:        ${tip:.2f}")
print(f"Total:      ${total:.2f}")
print(f"Each pays:  ${each:.2f}")
```

Each input gets the type that fits it: the bill can have cents, so it is a `float`; the tip percent and number of people are whole numbers, so they are `int`s. Dividing the tip percent by 100 turns 15 into 0.15. Try entering `0` people and see what error you get. Next week you will learn how to stop that from happening.
:::
