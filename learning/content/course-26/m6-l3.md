Each exercise below uses this week's list skills on a new problem. Type each one yourself instead of pasting; typing is how your fingers learn where the square brackets and colons go. If a list isn't doing what you expect, `print()` the whole list partway through your program. Seeing `[71.0, 80.5, 64.0]` tells you far more than guessing.

## Warm-up: track the list in your head

Before you step through this, write down what you think the last line prints: the list and its length.

:::trace Predict the final list, then check
```python
letters = ["a", "b", "c", "d"]
letters[1] = "z"
letters.append(letters[0])
letters.pop(0)
print(letters, len(letters))
```
:::

The trick is line 3. `letters[0]` is read *before* anything is removed, so `"a"` gets copied onto the end. Then `pop(0)` removes the original `"a"` from the front, and everything shifts left by one.

### Exercise 1: Favorite foods

Make a list of your three favorite foods. Print the first one, the last one (using a negative index), and how many foods are in the list.

```text
First: tacos
Last: mango
I listed 3 foods.
```

:::hint
The first item is at index 0. For the last item, there's an index that works no matter how long the list is. `len()` does the counting.
:::

:::solution
```python run title="foods.py"
foods = ["tacos", "ramen", "mango"]
print("First:", foods[0])
print("Last:", foods[-1])
print("I listed", len(foods), "foods.")
```

`foods[-1]` still gives the last item if you add a fourth food later. `foods[2]` wouldn't, because the fourth food would be at index 3.
:::

### Exercise 2: Receipt

You have `prices = [4.50, 12.00, 3.25, 8.75]`. Using **one** loop, and without `sum()` or `max()`, work out the total and the most expensive item.

```text
Total: 28.5
Most expensive: 12.0
```

:::hint
You need two variables that update on every pass. The total starts at 0. For the most expensive, start with a price you know is in the list, then replace it whenever you find a bigger one.
:::

:::solution
`biggest` starts as the first price, and the loop replaces it whenever something larger comes along.

```python run title="receipt.py"
prices = [4.50, 12.00, 3.25, 8.75]

total = 0
biggest = prices[0]
for price in prices:
    total = total + price
    if price > biggest:
        biggest = price

print("Total:", total)
print("Most expensive:", biggest)
```

Why not start `biggest` at 0? Here it would work, but if every value were negative (winter temperatures, say), 0 would wrongly "win". Starting with a real item from the list is always safe.
:::

### Exercise 3: Who passed?

Given `scores = [72, 55, 90, 68, 100, 70, 43]`, count how many scores are 70 or higher and print the sentence below. Don't type the 7 yourself; let Python count the list.

```text
4 out of 7 students passed.
```

:::hint
It's a counter with an `if` inside the loop. Look closely at "70 or higher": which comparison operator includes 70 itself?
:::

:::solution
```python run title="passed.py"
scores = [72, 55, 90, 68, 100, 70, 43]

passing = 0
for score in scores:
    if score >= 70:
        passing = passing + 1

print(passing, "out of", len(scores), "students passed.")
```

With `>` instead of `>=`, the student with exactly 70 would fail, and you'd print 3. Boundaries are where bugs hide, which is why the list includes a 70.
:::

### Exercise 4: Weather report

Ask for five daily high temperatures (they can have decimals) and store them in a list. Then print the list, the average rounded to 1 decimal place, the hottest temperature, and how many days were above average.

```text
Day 1 high temperature: 71
...
Temperatures: [71.0, 80.5, 64.0, 90.0, 77.0]
Average: 76.5
Hottest: 90.0
Days above average: 3
```

:::hint
Start with an empty list and `append` each temperature inside a `for` loop over `range(1, 6)`. You can't know which days are above average until you've collected all five, so you'll need a second loop after the first one.
:::

:::solution
```python run title="weather.py" input="71|80.5|64|90|77"
temps = []
for day in range(1, 6):
    temp = float(input(f"Day {day} high temperature: "))
    temps.append(temp)

average = sum(temps) / len(temps)
warm_days = 0
for temp in temps:
    if temp > average:
        warm_days = warm_days + 1

print("Temperatures:", temps)
print("Average:", round(average, 1))
print("Hottest:", max(temps))
print("Days above average:", warm_days)
```

The first loop collects, and the second loop compares. Notice the list shows `71.0` even though the user typed `71`: `float()` turns every answer into a decimal number.
:::

### Exercise 5: Ten percent off

A store is having a sale. Change every price in `prices = [20.0, 15.0, 9.99, 42.5]` to 90% of what it was, rounded to 2 decimal places. You must change the list itself, not just print new numbers.

```text
Sale prices: [18.0, 13.5, 8.99, 38.25]
```

:::hint
Remember the copy trap from the notes. To write a new value back into the list, you need to know *where* in the list it goes, so loop over the indexes.
:::

:::solution
```python run title="sale.py"
prices = [20.0, 15.0, 9.99, 42.5]

for i in range(len(prices)):
    prices[i] = round(prices[i] * 0.9, 2)

print("Sale prices:", prices)
```

If you wrote `for price in prices:` with `price = price * 0.9` inside, the list didn't change, because that loop only updates a copy. Assigning to `prices[i]` is what changes the list.
:::

### Exercise 6: Find your spot in line

`lineup = ["Ava", "Ben", "Chloe", "Dev", "Eli"]`. Ask for a name. If it's in the list, print its position counting from 1. If not, say so.

```text
Who are you looking for? Chloe
Chloe is number 3 in line.
```

:::hint
Loop over the indexes and compare each name. The tricky part is the "not in line" message: you can only know nobody matched after checking *everyone*. Use a variable that starts as `False` and flips to `True` when you find a match.
:::

:::solution
A **flag** variable remembers whether something happened during the loop.

```python run title="lineup.py" input="Chloe"
lineup = ["Ava", "Ben", "Chloe", "Dev", "Eli"]
name = input("Who are you looking for? ")

found = False
for i in range(len(lineup)):
    if lineup[i] == name:
        print(name, "is number", i + 1, "in line.")
        found = True

if not found:
    print(name, "is not in line.")
```

And with a name that isn't there:

```python run title="lineup.py" input="Zara"
lineup = ["Ava", "Ben", "Chloe", "Dev", "Eli"]
name = input("Who are you looking for? ")

found = False
for i in range(len(lineup)):
    if lineup[i] == name:
        print(name, "is number", i + 1, "in line.")
        found = True

if not found:
    print(name, "is not in line.")
```

The "not in line" message has to come *after* the loop. If you put it in an `else` inside the loop, it would print once for every name that doesn't match: four times for Chloe.
:::

## Before the challenge: a loop inside a loop

The challenge needs one loop inside another. The rule is simple once you see it: **the inner loop runs all the way through for every single pass of the outer loop**. Step through this and count how many times the inner `print` runs.

:::trace Every outer pass runs the whole inner loop
```python
for team in ["Red", "Blue"]:
    for player in range(1, 4):
        print(team, "player", player)
print("Teams ready")
```
:::

Two teams times three players makes six lines. Any variable you want to start fresh for each outer pass (like a counter) must be set *inside* the outer loop, just above the inner one.

### Challenge: Lunch vote

The class voted on a party lunch:

```python
votes = ["pizza", "tacos", "pizza", "sushi", "tacos", "pizza", "salad"]
```

1.  Build a new list `unique` with each option only once, in the order it first appears.
2.  Print how many repeat votes were left out.
3.  Print how many votes each option got.

```text
Options: ['pizza', 'tacos', 'sushi', 'salad']
Removed 3 repeats.
pizza got 3 votes
...
```

:::hint
For part 1, `not in` is the opposite of `in`: only `append` a vote if it isn't in `unique` yet. For part 3, the outer loop goes over `unique`, and the inner loop goes over every vote and counts the ones that match. Where does the counter reset?
:::

:::solution
```python run title="lunch_vote.py"
votes = ["pizza", "tacos", "pizza", "sushi", "tacos", "pizza", "salad"]

unique = []
for vote in votes:
    if vote not in unique:
        unique.append(vote)

print("Options:", unique)
print("Removed", len(votes) - len(unique), "repeats.")

for option in unique:
    count = 0
    for vote in votes:
        if vote == option:
            count = count + 1
    print(option, "got", count, "votes")
```

The outer loop picks one option, and the inner loop counts it through the whole `votes` list. `count = 0` sits inside the outer loop so every option starts counting from zero. (Put it above both loops and the counts pile up: 3, 5, 6, 7.) Lists also have a shortcut, `votes.count("pizza")`, and now you know what it's doing behind the scenes.

Polish idea: `sushi got 1 votes` isn't quite English. An `if count == 1:` can fix it.
:::
