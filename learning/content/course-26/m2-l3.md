### Exercise 1: Three facts about you

Write a program that prints three lines: your name, your favorite food, and something you want to build with code someday. Each fact goes on its own line.

### Exercise 2: Fix the quiz

This program has **three** bugs. Type it into IDLE, run it, fix whatever the message points to, and run it again. Repeat until it works. Here's what the first run tells you:

```python run raises title="quiz.py"
Print("Welcome to the quiz!")
print("Question 1: What is 4 + 4?)
print("Answer:", 4 + 4
```

When it's fixed, it should print:

```text
Welcome to the quiz!
Question 1: What is 4 + 4?
Answer: 8
```

:::hint
Python checks the whole file's *shape* before running any of it, so syntax errors get reported first, one at a time, even if they're lower down. The capital-P problem on line 1 only shows up once the file's shape is fixed.
:::

:::solution
The first run complains about line 2: the string never ends. Add the closing `"` after the question mark. The second run complains about line 3: `'(' was never closed`. Add the `)`. Now the file's shape is fine, so Python finally starts running it and stops on line 1 with `NameError: name 'Print' is not defined. Did you mean: 'print'?`. Change `Print` to `print`.

```python run title="quiz.py"
print("Welcome to the quiz!")
print("Question 1: What is 4 + 4?")
print("Answer:", 4 + 4)
```

The order you met the bugs in (2, then 3, then 1) is the useful lesson here: syntax errors first, everything else after.
:::

### Exercise 3: Glue text together with sep and end

Print exactly these three lines. The catch: every `-` and `@` must come from `sep`, and the dots must come from `end`.

```text
555-867-5309
ada@example.com
Ready... Set... Go!
```

:::hint
The phone number is three separate strings: `"555"`, `"867"`, and `"5309"`. The email is two strings, `"ada"` and `"example.com"`. The last line takes three separate `print()` calls, and two of them need an `end` that isn't a line break.
:::

:::solution
```python run title="ex3_glue.py"
print("555", "867", "5309", sep="-")
print("ada", "example.com", sep="@")
print("Ready", end="... ")
print("Set", end="... ")
print("Go!")
```

`sep="@"` puts the `@` between the two halves of the email. `end="... "` swaps the usual line break for three dots and a space, so the next `print()` carries on along the same line.
:::

### Exercise 4: Draw a tree

Print this tree. The top star has four spaces before it, and each row below has one space fewer and two stars more.

```text
    *
   ***
  *****
 *******
*********
   | |
```

:::hint
Typing each row works. For a neater version, remember that `" " * 3` makes three spaces, and `+` glues two strings together: `" " * 3 + "*" * 3`.
:::

:::solution
The direct way types each row:

```python run title="ex4_tree.py"
print("    *")
print("   ***")
print("  *****")
print(" *******")
print("*********")
print("   | |")
```

The sneakier way builds each row from repeated spaces and stars. It prints exactly the same tree, and it makes the pattern visible in the code: spaces go down by one, stars go up by two.

```python run title="ex4_tree_pattern.py"
print(" " * 4 + "*" * 1)
print(" " * 3 + "*" * 3)
print(" " * 2 + "*" * 5)
print(" " * 1 + "*" * 7)
print(" " * 0 + "*" * 9)
print("   | |")
```
:::

### Exercise 5: Make it readable

Here is a program with no comments at all:

```python run
print("WEATHER REPORT")
print("Monday: sunny")
print("Tuesday: rain")
print("Wednesday: snow")
print("Stay warm!")
```

Improve it:

1.  Add a header comment that says what the file does.
2.  Split it into a "Forecast" section and a "Sign-off" section, each with a comment label and a blank line before it.
3.  Comment out the Wednesday line, with a note saying why, so it doesn't print.

Target output:

```text
WEATHER REPORT
Monday: sunny
Tuesday: rain
Stay warm!
```

:::hint
A comment can sit at the end of a line, after the code. That's a good spot for the "why" on the Wednesday line.
:::

:::solution
```python run title="ex5_weather.py"
# weather_report.py
# Prints a three-day forecast for the class newsletter.

print("WEATHER REPORT")

# ----- Forecast -----
print("Monday: sunny")
print("Tuesday: rain")
# print("Wednesday: snow")  # forecast not confirmed yet

# ----- Sign-off -----
print("Stay warm!")
```

The note after the Wednesday line explains *why* it's switched off. Six months from now, "forecast not confirmed yet" tells you whether it's safe to bring the line back; a bare `#` doesn't.
:::

### Exercise 6: Which lines run?

Without running it, write down exactly what this program prints. Then run it to check.

```python
# print("A")
print("B")  # print("C")
print("D # E")
print("F")  #
#print("G")
```

:::hint
A `#` starts a comment only when it's *outside* quotes. Inside a string, it's an ordinary character.
:::

:::solution
```python run title="ex6_which_lines.py"
# print("A")
print("B")  # print("C")
print("D # E")
print("F")  #
#print("G")
```

Line 1 and line 5 are entirely comments. On line 2, everything after the `#` is a comment, so only `B` prints. On line 3, the `#` sits inside the quotes, so `D # E` prints in full. Line 4 has an empty comment at the end, which changes nothing.
:::

### Challenge: Snack-bar receipt

Print a receipt for a pretzel ($3), a lemonade ($2), and two cookies ($2 each). The rules:

-   Python must calculate the cookie cost and the total. Don't type `4` or `9` yourself.
-   No space between the `$` and the price.
-   The borders come from string repetition.
-   "Thanks!" and "Come back soon." come from **one** `print()` call but appear on two lines.

Target output:

```text
======================
    C4T SNACK BAR
======================
Pretzel        $3
Lemonade       $2
Cookie x2      $4
----------------------
TOTAL          $9
======================
Thanks!
Come back soon.
```

:::hint
`print("$", 3)` prints `$ 3` because of the default space. Which setting removes that space? For the last line, think about what `sep` could be instead of a space.
:::

:::solution
```python run title="receipt.py"
# receipt.py
# Prints a snack-bar receipt. Python does the math.

print("=" * 22)
print("    C4T SNACK BAR")
print("=" * 22)
print("Pretzel        $", 3, sep="")
print("Lemonade       $", 2, sep="")
print("Cookie x2      $", 2 * 2, sep="")
print("-" * 22)
print("TOTAL          $", 3 + 2 + 2 * 2, sep="")
print("=" * 22)
print("Thanks!", "Come back soon.", sep="\n")
```

`sep=""` removes the space `print()` would put between `$` and the number. The spaces inside each label line the prices up in one column. In the total, Python multiplies before adding, so `3 + 2 + 2 * 2` is 9, not 14. On the last line, `sep="\n"` puts a line break between the two strings where a space would normally go.
:::
