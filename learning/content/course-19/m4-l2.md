:::objectives
- Turn a time budget into a number of search candidates.
- Use early stopping and read a model's training and validation curves.
- Search a pipeline's hyperparameters with sensible distributions and prefixed names.
- Read `cv_results_` to spot a search range that's too narrow, and a validation curve to spot a plateau.
- Decide whether a tuning gain is real by comparing folds, before touching the test set.
:::

Module 2's churn model reached its best score with hand-built features. Gradient boosting can learn curves and interactions by itself, but it has more settings, and every setting is a temptation to search too long. The goal here is a disciplined run that fits inside about 15 seconds of compute:

```mermaid caption="The tuning run, step by step"

## Step 1: Data, pipeline, and two baselines

The same streaming-service generator as Module 2, with 2,000 customers. The pipeline keeps only the two simplest engineered features (tenure and log hours per device); boosting has to discover the rest. `HistGradientBoostingClassifier` handles missing values natively, so the numeric columns pass straight through with no imputer or scaler.

```python run
import os
os.environ["OMP_NUM_THREADS"] = "1"          # one thread per fit, so timings are steady on shared machines
import time
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.compose import ColumnTransformer
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import StratifiedKFold, cross_validate, train_test_split
from sklearn.pipeline import Pipeline, make_pipeline
from sklearn.preprocessing import FunctionTransformer, OneHotEncoder, StandardScaler

def make_churn(n=1500, seed=7):
    rng = np.random.default_rng(seed)
    plan = rng.choice(["basic", "standard", "premium"], n, p=[0.5, 0.32, 0.18])
    fee = np.select([plan == "basic", plan == "standard"], [7.99, 12.99], 18.99)
    devices = rng.integers(1, 6, n)
    hours = rng.lognormal(2.6, 0.9, n).round(1)
    tickets = rng.poisson(0.6, n)
    age = rng.integers(16, 76, n).astype(float)
    payment = rng.choice(["card", "paypal", "gift_card", "crypto"], n, p=[0.6, 0.3, 0.08, 0.02])
    postcode = np.array([f"P{k:03d}" for k in rng.integers(0, 300, n)])
    signup = pd.Timestamp("2023-01-01") + pd.to_timedelta(rng.integers(0, 1000, n), unit="D")
    tenure = (pd.Timestamp("2025-10-01") - signup).days.to_numpy()
    logit = 2 * (1.5 - 1.3 * np.log1p(hours / devices) + 0.5 * tickets
                 + 0.6 * (plan == "basic") + 1.0 * (payment == "gift_card")
                 - 0.002 * tenure + 1.5 * ((tickets >= 2) & (tenure < 365))
                 + 0.002 * (age - 45) ** 2)
    df = pd.DataFrame({"plan": plan, "monthly_fee": fee, "devices": devices,
                       "watch_hours": hours, "support_tickets": tickets, "age": age,
                       "payment": payment, "postcode": postcode, "signup_date": signup})
    df["churned"] = (rng.random(n) < 1 / (1 + np.exp(-logit))).astype(int)
    df.loc[rng.random(n) < 0.08, "age"] = np.nan
    df.loc[rng.random(n) < 0.05, "watch_hours"] = np.nan
    return df

def add_features(frame):
    out = frame.copy()
    out["tenure_days"] = (pd.Timestamp("2025-10-01") - out["signup_date"]).dt.days
    out["log_hours_per_device"] = np.log1p(out["watch_hours"] / out["devices"])
    return out

NUMERIC = ["monthly_fee", "devices", "watch_hours", "support_tickets", "age", "tenure_days", "log_hours_per_device"]
def columns(numeric_steps):
    return ColumnTransformer([
        ("num", numeric_steps, NUMERIC),
        ("cat", OneHotEncoder(handle_unknown="infrequent_if_exist", min_frequency=30, sparse_output=False),
         ["plan", "payment"]),
    ])

df = make_churn(n=2000)
X, y = df.drop(columns="churned"), df["churned"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, stratify=y, random_state=0)
cv = StratifiedKFold(n_splits=3, shuffle=True, random_state=0)

logistic = make_pipeline(FunctionTransformer(add_features),
                         columns(make_pipeline(SimpleImputer(strategy="median"), StandardScaler())),
                         LogisticRegression(max_iter=1000))
boosted = Pipeline([
    ("features", FunctionTransformer(add_features)),
    ("columns", columns("passthrough")),
    ("boost", HistGradientBoostingClassifier(early_stopping=True, max_iter=500, random_state=0)),
])
baseline = {}
for name, model in [("logistic", logistic), ("boosted, defaults", boosted)]:
    result = cross_validate(model, X_train, y_train, cv=cv, scoring="roc_auc")
    baseline[name] = result["test_score"]
    print(f"{name:<18} CV AUC {result['test_score'].mean():.3f}   seconds per fit {result['fit_time'].mean():.2f}")
```

Two things to keep from this cell: the default boosted model already beats logistic regression on these features, and one fit takes a fraction of a second. The pipeline step is named `boost`, so every hyperparameter in the search below will be spelled `boost__<name>`.

## Step 2: Let early stopping choose the number of trees

Fit once and look inside the boosting step. With `early_stopping=True`, it set aside 10% of the training rows and recorded the loss on both parts after every iteration.

```python run alt="Line chart of log loss against boosting iteration for one fit. Training loss falls steadily from about 0.65 to below 0.2. Validation loss falls to about 0.40 by iteration 35 and then stays flat until training stops at iteration 45." caption="Training loss keeps falling; validation loss stops improving after about 35 trees, and early stopping ends the run 10 trees later."
boosted.fit(X_train, y_train)
booster = boosted.named_steps["boost"]

fig, ax = plt.subplots(figsize=(7, 2.8))
ax.plot(-booster.train_score_, color="#2a78d6", label="training part")
ax.plot(-booster.validation_score_, color="#eb6834", label="validation part (10%)")
ax.set_xlabel("boosting iteration")
ax.set_ylabel("log loss")
ax.legend(frameon=False, fontsize=8)
ax.spines[["top", "right"]].set_visible(False)
plt.tight_layout()
plt.show()
print("iterations used:", booster.n_iter_, "of a possible", booster.max_iter)
```

The scores are stored as *negative* loss (so that higher is better everywhere in scikit-learn), hence the minus signs. The model stopped far below its ceiling of 500, so `max_iter` doesn't need tuning, and the search can spend its budget elsewhere. The growing gap between the curves is normal for boosting; what matters is that the validation curve has flattened.

## Step 3: Size the search to a budget

Say you're willing to spend about 10 seconds on the search. From Step 1, a fit takes well under a second, and early stopping will keep most candidates short.

```python run
seconds_per_fit = float(np.mean(cross_validate(boosted, X_train, y_train, cv=cv)["fit_time"]))
budget_seconds = 10
n_iter = max(4, int(budget_seconds / (seconds_per_fit * cv.get_n_splits())))
print(f"{seconds_per_fit:.2f} s per fit x {cv.get_n_splits()} folds -> room for about {n_iter} candidates")
```

The formula is the one from the Notes, solved for the number of candidates. Your machine will print a different number, which is the point: the budget, not the candidate count, is what you decide.

## Step 4: Run the randomized search

Four settings shape the trees: the learning rate (multiplicative, so `loguniform`), the number of leaves per tree (an integer, `randint`), the minimum rows per leaf (an integer on a log scale, so a list), and L2 regularization (`loguniform`).

```python run
from scipy.stats import loguniform, randint
from sklearn.model_selection import RandomizedSearchCV

space = {
    "boost__learning_rate": loguniform(0.01, 0.5),
    "boost__max_leaf_nodes": randint(4, 64),
    "boost__min_samples_leaf": [5, 10, 20, 40, 80, 160],
    "boost__l2_regularization": loguniform(1e-3, 10),
}
start = time.perf_counter()
search = RandomizedSearchCV(boosted, space, n_iter=min(n_iter, 12), cv=cv, scoring="roc_auc",
                            random_state=0).fit(X_train, y_train)
print(f"{len(search.cv_results_['params'])} candidates in {time.perf_counter() - start:.1f} s")
print(f"best CV AUC {search.best_score_:.3f} (defaults: {baseline['boosted, defaults'].mean():.3f})")
for name, value in search.best_params_.items():
    print(f"  {name.replace('boost__', '')}: {value:.4g}")
```

`min(n_iter, 12)` caps the search so the lesson stays quick even on a fast machine. The winner trains slowly (small learning rate) with small trees, a common pattern on a dataset this size.

## Step 5: Read the search, not just the winner

`cv_results_` holds every candidate's settings and fold scores. Two questions to ask of it: did the winner sit at the edge of a range, and how flat is the top?

```python run alt="Scatter plot of mean CV AUC for 12 candidates against learning rate on a log axis from 0.01 to 0.5, colored by number of leaves. The best candidates, near AUC 0.885, are spread between learning rates of about 0.04 and 0.33 and mostly have few leaves; the lowest scores come from the largest trees and the highest learning rate." caption="Each dot is one candidate. The top is a broad plateau rather than a sharp peak, and the best points are inside the range, not at its edge."
results = pd.DataFrame(search.cv_results_)
top = results.sort_values("rank_test_score")[
    ["param_boost__learning_rate", "param_boost__max_leaf_nodes", "param_boost__min_samples_leaf", "mean_test_score", "std_test_score"]
].head(5)
print(top.round(4).to_string(index=False))

fig, ax = plt.subplots(figsize=(6.5, 3))
points = ax.scatter(results["param_boost__learning_rate"].astype(float), results["mean_test_score"],
                    c=results["param_boost__max_leaf_nodes"].astype(int), cmap="viridis", s=45)
fig.colorbar(points, ax=ax, label="max_leaf_nodes")
ax.set_xscale("log")
ax.set_xlabel("learning rate")
ax.set_ylabel("mean CV AUC")
ax.spines[["top", "right"]].set_visible(False)
plt.tight_layout()
plt.show()
```

Look at the `std_test_score` column next to the means: the top few candidates differ by less than their own fold-to-fold spread. That's a plateau, and it's good news, because it means the exact values don't matter much. If instead the best dots had crowded against an end of the axis, the right move would be to widen that range and search again.

A **validation curve** checks one setting more carefully: hold the others at the winner's values and sweep just that one.

```python run alt="Line chart of mean AUC against learning rate on a log axis with four points from 0.01 to 0.3. Training AUC rises steadily from about 0.96 to about 0.98. Validation AUC stays nearly flat around 0.88." caption="Training AUC keeps climbing with the learning rate; validation AUC barely moves. More aggressive settings mostly buy overfitting."
from sklearn.model_selection import validation_curve

rates = [0.01, 0.03, 0.1, 0.3]
train_scores, val_scores = validation_curve(search.best_estimator_, X_train, y_train,
                                            param_name="boost__learning_rate", param_range=rates,
                                            cv=cv, scoring="roc_auc")
fig, ax = plt.subplots(figsize=(6, 2.8))
ax.plot(rates, train_scores.mean(axis=1), marker="o", color="#2a78d6", label="training folds")
ax.plot(rates, val_scores.mean(axis=1), marker="o", color="#eb6834", label="validation folds")
ax.set_xscale("log")
ax.set_xlabel("learning rate (other settings fixed at the winner)")
ax.set_ylabel("mean AUC")
ax.legend(frameon=False, fontsize=8)
ax.spines[["top", "right"]].set_visible(False)
plt.tight_layout()
plt.show()
```

## Step 6: Is the gain real?

The search compared every candidate on the same three folds as the baseline (same splitter, same integer seed), so the winner's per-fold scores pair up with the defaults' per-fold scores:

```python run
best_folds = np.array([search.cv_results_[f"split{k}_test_score"][search.best_index_] for k in range(3)])
gain = best_folds - baseline["boosted, defaults"]
print("tuned minus defaults, per fold:", gain.round(3))
print(f"mean gain {gain.mean():+.3f}; folds improved: {np.sum(gain > 0)} of {len(gain)}")
```

Tuning helped on every fold, by about a point of AUC. Remember Module 3, though: the winner was *selected* using these very folds, so this gain is a little optimistic. It's still the right check to make before spending more compute; if the gain had been mixed in sign, the honest decision would be to keep the defaults.

## Step 7: Open the test set once

```python run
from sklearn.metrics import roc_auc_score

for name, model in [("logistic", logistic.fit(X_train, y_train)),
                    ("boosted, defaults", boosted.fit(X_train, y_train)),
                    ("boosted, tuned", search.best_estimator_)]:
    print(f"{name:<18} test AUC {roc_auc_score(y_test, model.predict_proba(X_test)[:, 1]):.3f}")
```

The ordering matches cross-validation: tuned boosting first, then the defaults, then logistic regression. The test gaps are small, and with 500 test customers, a difference under about 0.01 is within the noise. The honest summary: tuning was worth doing because it was cheap and consistent across folds, and it is not a dramatic improvement. In Module 2 the hand-built age gap and first-year interaction did more for logistic regression than this whole search did for boosting, a useful reminder that features usually matter more than settings.

## The finished program

Once tuning is done, freeze the chosen settings (rounded) in the training code and stop searching. This cell trains the final model from scratch with them. Rounding nudges the result in the third decimal place, and that's fine: on the plateau, nearby settings behave alike.

```python run title="train_final.py"
final_model = Pipeline([
    ("features", FunctionTransformer(add_features)),
    ("columns", columns("passthrough")),
    ("boost", HistGradientBoostingClassifier(
        learning_rate=0.042, max_leaf_nodes=9, min_samples_leaf=5, l2_regularization=0.39,
        early_stopping=True, max_iter=500, random_state=0)),
])
final_model.fit(X_train, y_train)
print("iterations used:", final_model.named_steps["boost"].n_iter_)
print(f"test AUC {roc_auc_score(y_test, final_model.predict_proba(X_test)[:, 1]):.3f}")
```

:::quiz
Q: Why didn't the search include `max_iter`?
- [x] Early stopping picks the number of iterations per fit, and Step 2 showed it stopping well below the ceiling
  With early stopping on, `max_iter` is only a ceiling. Searching it would waste candidates.
- [ ] `max_iter` has no effect on gradient boosting
  It caps the number of trees, which matters a lot without early stopping.
- [ ] The search can't handle integer settings
  `max_leaf_nodes` is an integer and was searched with `randint`.

Q: The top five candidates' mean AUCs differ by 0.003, and each has a fold std of about 0.015. What should you conclude?
- [ ] The top candidate is clearly best and its exact values matter
  Differences far smaller than the fold-to-fold spread can't separate the candidates.
- [x] The scores form a plateau; any of the top candidates is a reasonable choice
  A flat top means the model isn't sensitive to these settings in that region, which makes the choice robust.
- [ ] The search failed and should be rerun with more candidates
  Nothing failed; a plateau is a common and useful finding.

Q: Why compare tuned and default scores fold by fold rather than just comparing their means?
- [ ] Means can't be computed for AUC
  They can; pairing adds information the means hide.
- [x] Pairing cancels out how easy or hard each fold was, so a consistent gain stands out from fold noise
  If the gain has the same sign on every fold, it's more convincing than a small difference in means.
- [ ] Fold-by-fold comparison removes the optimism of selecting the best candidate
  It doesn't; the winner was chosen on these folds, so a small optimism remains.
:::

:::takeaways
- Decide a time budget, then derive the number of candidates from seconds per fit and folds.
- Turn on early stopping and search learning rate and tree shape instead of the number of trees.
- In a pipeline, every searched name carries the step prefix (`boost__learning_rate`).
- Read `cv_results_`: winners at the edge mean widen the range; a flat top means stop searching.
- Check a tuning gain fold by fold before you trust it, then open the test set once.
:::
