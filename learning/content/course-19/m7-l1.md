A weather app says "70% chance of rain" on 100 different days. If it rained on about 70 of them, the forecasts were **calibrated**. If it rained on 95, the app was too timid; on 40, too confident. Ranking metrics like ROC AUC can't see the difference. They only check that rainy days got higher numbers than dry ones.

That matters the moment someone uses the number itself: to compute an expected cost, to set a threshold from costs as in Module 5, or to tell a person "your risk is 30%". So before recommending a model, check three more things: whether its probabilities mean what they say, whether its reasoning makes sense, and where its mistakes concentrate.

## Same ranking, different probabilities

Here are three classifiers on the same data. Two of them rank the test rows almost identically well.

```python run alt="Reliability diagram with three curves against the diagonal: boosting hugs the diagonal, the random forest forms a gentle S-shape that is too low on the left and too high on the right of the middle, and naive Bayes swings far from the diagonal" caption="A perfectly calibrated model lies on the dashed diagonal."
import sklearn
from threadpoolctl import threadpool_limits
threadpool_limits(limits=1, user_api="openmp")   # see Module 6: avoids thread oversubscription

import matplotlib.pyplot as plt
import numpy as np
from sklearn.calibration import CalibrationDisplay
from sklearn.datasets import make_classification
from sklearn.ensemble import HistGradientBoostingClassifier, RandomForestClassifier
from sklearn.metrics import brier_score_loss, log_loss, roc_auc_score
from sklearn.model_selection import train_test_split
from sklearn.naive_bayes import GaussianNB

X, y = make_classification(n_samples=6000, n_features=20, n_informative=4,
                           n_redundant=6, random_state=42)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.4, random_state=0)
models = {
    "boosting": HistGradientBoostingClassifier(random_state=0),
    "forest": RandomForestClassifier(n_estimators=100, random_state=0),
    "naive Bayes": GaussianNB(),
}
fig, ax = plt.subplots(figsize=(5, 4.6))
for (name, model), color in zip(models.items(), ["#2a78d6", "#eb6834", "#1baf7a"]):
    p = model.fit(X_train, y_train).predict_proba(X_test)[:, 1]
    print(f"{name:>11}: ROC AUC {roc_auc_score(y_test, p):.3f}   "
          f"Brier {brier_score_loss(y_test, p):.3f}   log loss {log_loss(y_test, p):.3f}")
    CalibrationDisplay.from_predictions(y_test, p, n_bins=10, name=name, ax=ax, color=color)
ax.set_title("Reliability diagram (test set)")
```

Each point groups the test rows by predicted probability (0 to 0.1, 0.1 to 0.2, and so on) and plots the average prediction against the share that really were positive. Boosting stays close to the diagonal. The forest has the same ROC AUC, but its curve is an S: when it says 0.25 the true rate is about 0.1, and when it says 0.75 it is about 0.9. Averaging hundreds of trees pulls predictions toward the middle, because it is rare for every tree to agree on an extreme. Naive Bayes assumes the features are independent, so on data with redundant features it double-counts evidence and its probabilities swing badly.

Two scores summarize calibration and sharpness together:

-   **Brier score**: the mean of `(p − y)²`. Zero is perfect; always predicting 0.5 on balanced data scores 0.25.
-   **Log loss**: the mean of `−log(probability given to what actually happened)`. It punishes confident mistakes very hard: a 0.99 on a row that turns out negative costs 4.6, while a 0.6 costs 0.9.

Both are **proper scoring rules**: a model gets its best expected score by reporting its true beliefs, so neither can be gamed by shading probabilities up or down.

## Recalibrate with `CalibratedClassifierCV`

Calibration fits a small one-input model that maps a classifier's raw scores to better probabilities. scikit-learn offers two main mappings:

-   **`method="sigmoid"`** (Platt scaling) fits a logistic curve. It has two parameters, so it works on small data but can only fix S-shaped distortions.
-   **`method="isotonic"`** fits any non-decreasing step function. It can fix any monotonic distortion but needs more data, roughly a thousand rows or more, or it overfits.

The mapping must be learned on predictions for rows the classifier didn't train on. `CalibratedClassifierCV(model, cv=5)` handles that: on each fold it trains the model on four fifths of the data, fits the calibrator on the remaining fifth, and at prediction time averages the five calibrated pairs.

```python run alt="Reliability diagram after calibration: the calibrated forest and calibrated naive Bayes both lie close to the diagonal" caption="After calibration, both curves sit near the diagonal."
from sklearn.calibration import CalibratedClassifierCV

fixes = {
    "forest + isotonic": CalibratedClassifierCV(
        RandomForestClassifier(n_estimators=100, random_state=0), method="isotonic", cv=5),
    "naive Bayes + sigmoid": CalibratedClassifierCV(GaussianNB(), method="sigmoid", cv=5),
    "naive Bayes + isotonic": CalibratedClassifierCV(GaussianNB(), method="isotonic", cv=5),
}
fig, ax = plt.subplots(figsize=(5, 4.6))
for (name, model), color in zip(fixes.items(), ["#eb6834", "#6250d6", "#1baf7a"]):
    p = model.fit(X_train, y_train).predict_proba(X_test)[:, 1]
    print(f"{name:>22}: ROC AUC {roc_auc_score(y_test, p):.3f}   "
          f"Brier {brier_score_loss(y_test, p):.3f}   log loss {log_loss(y_test, p):.3f}")
    CalibrationDisplay.from_predictions(y_test, p, n_bins=10, name=name, ax=ax, color=color)
```

The calibrated forest now matches boosting on Brier score and log loss, with the same ROC AUC: calibration repaired the probabilities without touching the ranking. Naive Bayes improves too, and isotonic beats sigmoid because its distortion isn't a simple S. Calibration can't add ranking skill, though; naive Bayes still ranks worst.

:::note
To calibrate a model you have already trained, wrap it in `FrozenEstimator` (in `sklearn.frozen`, available since scikit-learn 1.6) and fit `CalibratedClassifierCV` on a separate calibration set. Older tutorials use `cv="prefit"`, which newer versions have removed. And remember Module 5: a model trained with `class_weight="balanced"` is miscalibrated on purpose, so calibrate it before using its probabilities.
:::

## What the model relies on: permutation importance

The diabetes dataset predicts a disease-progression score one year after 10 baseline measurements. Loading it with `scaled=False` keeps real units (age in years, BMI, blood pressure). We'll fit a small boosted model and ask which features its test-set accuracy depends on.

```python run
import pandas as pd
from sklearn.datasets import load_diabetes
from sklearn.ensemble import HistGradientBoostingRegressor
from sklearn.inspection import permutation_importance

diabetes = load_diabetes(as_frame=True, scaled=False)
Xd, yd = diabetes.data, diabetes.target
Xd_train, Xd_test, yd_train, yd_test = train_test_split(Xd, yd, test_size=0.3, random_state=0)
reg = HistGradientBoostingRegressor(max_iter=150, learning_rate=0.05, max_leaf_nodes=8,
                                    min_samples_leaf=20, random_state=0).fit(Xd_train, yd_train)
perm = permutation_importance(reg, Xd_test, yd_test, scoring="neg_mean_absolute_error",
                              n_repeats=10, random_state=0)
print(pd.DataFrame({"MAE increase when shuffled": perm.importances_mean,
                    "± std": perm.importances_std}, index=Xd.columns)
      .sort_values("MAE increase when shuffled", ascending=False).round(2).head(5))
```

With `scoring="neg_mean_absolute_error"`, the importance is in the target's own units: shuffling `s5` (a blood serum measurement) makes predictions worse by about 10 points on average. Two cautions from Module 6 still apply. Compute it on held-out data, and remember that correlated features share credit, so a low score can mean "redundant" rather than "useless". Importance also says *how much* the model uses a feature, never *which direction* it pushes.

## Which direction: partial dependence and ICE curves

A **partial dependence** curve answers: if every row had BMI = 25, what would the average prediction be? Then 26, 27, and so on. Here is the computation by hand for a made-up model and three patients.

:::trace Compute a partial dependence curve by hand
```python
def model(bmi, age):                  # a made-up fitted model
    return 50 + 4 * bmi + (2 * age if bmi > 30 else 0)

patients = [(22, 30), (28, 60), (35, 45)]   # (bmi, age)
for value in [20, 30, 40]:
    total = 0
    for bmi, age in patients:
        total += model(value, age)          # pretend this patient had bmi = value
    print("bmi", value, "-> average prediction", round(total / len(patients), 1))
```
:::

Each inner value, `model(value, age)` for one patient, is a point on that patient's **ICE** (individual conditional expectation) curve. The partial dependence curve is their average. At BMI 40 the three ICE values differ (270, 330, 300) because the model has an age interaction there, which the average alone would hide. `PartialDependenceDisplay` with `kind="both"` draws both at once.

```python run alt="Two panels of step-shaped curves. For bmi, the thick average line climbs from about 130 at BMI 20 to about 215 above BMI 33, with jumps near 27 and 33. For s5, it climbs from about 110 to about 205, with the biggest jump near 4.9. Thin individual lines follow the same steps at different heights." caption="Thin lines: individual patients (ICE). Thick line: their average (partial dependence)."
from sklearn.inspection import PartialDependenceDisplay

fig, axes = plt.subplots(1, 2, figsize=(8, 3.3), sharey=True)
PartialDependenceDisplay.from_estimator(reg, Xd_train, ["bmi", "s5"], kind="both",
                                        subsample=60, random_state=0, ax=axes,
                                        ice_lines_kw={"color": "#2a78d6", "alpha": 0.25},
                                        pd_line_kw={"color": "#eb6834", "lw": 3})
```

Predicted progression climbs with both features, from about 130 to 215 across the BMI range, with the biggest jumps near BMI 27 and 33 and near `s5` = 4.9. The curves are staircases because a boosted model is a sum of trees, and every tree is a step function. The ICE lines mostly run parallel at different heights, so the model shifts every patient by a similar amount. If they crossed or fanned out, the average would be hiding an interaction. One limit: partial dependence pretends you can change one feature while holding the others fixed. When features are strongly correlated, that creates patients who could never exist, and the curve over those regions is guesswork.

## Where it fails: errors by slice

An average error hides how it is distributed. Slice-based error analysis computes the error separately for meaningful subgroups. Three rules make it trustworthy: use out-of-fold predictions for every row, attach an uncertainty interval to each slice, and compare each slice with a baseline on the *same* slice, since some groups are simply harder to predict.

```python run
from sklearn.dummy import DummyRegressor
from sklearn.model_selection import KFold, cross_val_predict

folds = KFold(n_splits=5, shuffle=True, random_state=0)
oof_model = cross_val_predict(reg, Xd, yd, cv=folds)
oof_dummy = cross_val_predict(DummyRegressor(strategy="mean"), Xd, yd, cv=folds)
errors = pd.DataFrame({
    "model": (yd - oof_model).abs(), "baseline": (yd - oof_dummy).abs(),
    "sex": "sex=" + Xd.sex.astype(int).astype(str),
    "age": pd.cut(Xd.age, [0, 40, 55, 100], labels=["age<40", "age 40-54", "age 55+"]),
    "bmi": pd.cut(Xd.bmi, [0, 25, 30, 100], labels=["bmi<25", "bmi 25-30", "bmi 30+"]),
})

rng = np.random.default_rng(0)
rows = []
for column in ["sex", "age", "bmi"]:
    for level, part in errors.groupby(column, observed=True):
        boot = [rng.choice(part.model.values, len(part)).mean() for _ in range(1000)]
        low, high = np.percentile(boot, [5, 95])
        rows.append({"slice": level, "n": len(part), "model MAE": part.model.mean(),
                     "90% interval": f"{low:.0f} to {high:.0f}",
                     "baseline MAE": part.baseline.mean(),
                     "skill": 1 - part.model.mean() / part.baseline.mean()})
print(f"overall: model MAE {errors.model.mean():.1f}, baseline MAE {errors.baseline.mean():.1f}")
print(pd.DataFrame(rows).round(2).to_string(index=False))
```

On raw error, the two higher-BMI slices look alike (about 54 and 50) and much worse than BMI under 25. The baseline column changes the story. Outcomes in the BMI 30+ group vary far more (the baseline is off by 81 points there), so the model is actually removing a large share of the error, with a **skill** of 0.38. The slice where the model helps least is BMI 25 to 30, with a skill of only 0.16. That is the one worth investigating. Also check the intervals: with 95 patients in the BMI 30+ slice, its interval is 15 points wide, so a gap of a few points between slices is noise.

:::warning
**Classic mistakes**

1.  **Calibrating on the training data.** The model's in-sample predictions are overconfident, so the calibrator learns the wrong mapping. Use `CalibratedClassifierCV` with `cv`, or a separate calibration set.
2.  **Using isotonic calibration on a few hundred rows.** It overfits into a jagged staircase. Use sigmoid on small data.
3.  **Reading a partial dependence plot as cause and effect.** It shows what the *model* does when you change an input, not what would happen to a patient. And with correlated features it extrapolates into impossible combinations.
4.  **Declaring the worst slice a problem without an interval or a baseline.** The worst of many small slices always looks bad by chance, and some groups are simply harder.
:::

:::quiz
Q: Two models have the same ROC AUC. Model A's Brier score is 0.036 and model B's is 0.041. What can you conclude?
- [ ] A ranks positives above negatives more reliably
  Equal ROC AUC means they rank about equally well; the Brier gap comes from the probabilities themselves.
- [x] A's probabilities are closer to the true outcome rates, so A is the better choice when the probability is used directly
  With ranking equal, the Brier difference reflects calibration, which is what a cost-based threshold or a risk estimate relies on.
- [ ] B is overfitting
  Brier score alone doesn't diagnose overfitting; compare train and validation scores for that.

Q: You have 300 labelled rows to calibrate an SVM's scores. Which method is the safer choice?
- [x] `method="sigmoid"`
  Two parameters can't overfit much, which matters with only 300 rows.
- [ ] `method="isotonic"`
  Isotonic regression can fit any staircase, so with 300 rows it tends to memorize noise.
- [ ] No calibration, because SVMs are always calibrated
  SVM decision values aren't probabilities at all; they need a mapping.

Q: A partial dependence curve for `income` is flat, but the ICE lines form an X: half rise, half fall. What does that mean?
- [ ] Income has no effect on the predictions
  The individual lines move a lot; they just cancel out on average.
- [x] Income interacts with another feature: it pushes predictions up for some rows and down for others
  The average hides opposite effects, which is exactly what ICE curves exist to reveal.
- [ ] The model is miscalibrated
  ICE curves describe how predictions change with an input, not whether probabilities match outcome rates.

Q: The error rate for one region is 9% versus 6% overall, measured on 40 rows. What should you check first?
- [ ] Whether the model should be retrained on that region alone
  That might come later, but first you need to know whether the gap is real.
- [x] An uncertainty interval for that slice and a baseline's error on the same slice
  With 40 rows a 3-point gap can be chance, and the region might be harder for any model.
:::

:::takeaways
- ROC AUC measures ranking; reliability diagrams, Brier score, and log loss measure whether probabilities can be taken at face value.
- `CalibratedClassifierCV` fixes probabilities without changing the ranking. Prefer sigmoid on small data and isotonic on large data, and always calibrate on rows the model didn't train on.
- Permutation importance says how much a model uses a feature; partial dependence and ICE curves show in which direction, and whether the effect differs between rows.
- Slice errors need out-of-fold predictions, intervals, and a per-slice baseline before they mean anything.
:::
