Run this cell three times in a row, or just read the output: the loop already does it three times.

```python run
import numpy as np
from sklearn.datasets import load_diabetes
from sklearn.ensemble import RandomForestRegressor
from sklearn.model_selection import KFold, cross_val_score

X, y = load_diabetes(return_X_y=True)   # 442 patients, 10 measurements, disease progression

for run in range(3):
    cv = KFold(n_splits=5, shuffle=True)
    scores = cross_val_score(RandomForestRegressor(n_estimators=30), X, y, cv=cv, scoring="r2")
    print(f"run {run + 1}: mean R^2 = {scores.mean():.4f}")
```

Same data, same model, same code, and three different answers. If you were comparing this forest with another model, which of the three numbers would go in your report? None of them should, until you control where the randomness comes from. This course is about comparisons you can defend, and a comparison you can't repeat isn't one.

## Where randomness hides

A typical workflow has several independent sources of randomness, and each one needs its own seed:

```mermaid caption="Five places a scikit-learn workflow draws random numbers"
flowchart LR
    G["Generating synthetic data"] --> S["train_test_split shuffle"]
    S --> F["CV fold shuffle"]
    F --> M["Model internals: bootstrap rows, feature subsets"]
    M --> H["Search: sampling candidates"]
```

In the cell above, two of them were left free: `KFold(shuffle=True)` reshuffled which patients landed in which fold, and the forest drew different bootstrap samples and feature subsets for its trees. Models that don't use randomness (plain linear regression, k-nearest neighbors) have no `random_state` parameter at all, which is a quick way to tell.

## Pin it with `random_state`

Give every random component an integer seed, and the three runs collapse into one number:

```python run
SEED = 0

for run in range(3):
    cv = KFold(n_splits=5, shuffle=True, random_state=SEED)
    forest = RandomForestRegressor(n_estimators=30, random_state=SEED)
    scores = cross_val_score(forest, X, y, cv=cv, scoring="r2")
    print(f"run {run + 1}: mean R^2 = {scores.mean():.4f}")
```

Keep one `SEED` constant at the top of the notebook and pass it everywhere. Changing a single line then reruns the whole analysis under a new seed, which you'll do in a moment on purpose.

For random numbers you generate yourself (synthetic data, noise, a random subset of rows), use NumPy's `Generator`: `rng = np.random.default_rng(SEED)`. Keep it separate from scikit-learn's `random_state`, which accepts `None`, an integer, or a legacy `np.random.RandomState` object, but not a `Generator`.

## An integer seed and a RandomState object are not the same

Here's a subtle one that bites careful people. You might think passing a seeded `RandomState` object is the same as passing the integer. Watch what happens when the same splitter is used twice:

```python run
cv_int = KFold(n_splits=5, shuffle=True, random_state=0)
cv_obj = KFold(n_splits=5, shuffle=True, random_state=np.random.RandomState(0))

def first_test_rows(cv):
    train_idx, test_idx = next(cv.split(X))
    return test_idx[:6]

print("integer seed, call 1:", first_test_rows(cv_int))
print("integer seed, call 2:", first_test_rows(cv_int))
print("RandomState,  call 1:", first_test_rows(cv_obj))
print("RandomState,  call 2:", first_test_rows(cv_obj))
```

With an integer, the splitter restarts from the same seed on every call to `split`, so every model you evaluate with `cv_int` sees identical folds. With a `RandomState` object, each call draws from the object's stream and moves it forward, so the second call produces different folds. Compare two models with `cv_obj` and you have compared them on different test sets, which muddies exactly the difference you were trying to measure.

:::warning
Pass **integers** to splitters and models when you compare things. A shared `RandomState` object (or `random_state=None`) gives each model different folds, so part of the gap between two scores is just the folds changing.
:::

## A seed is not a result

Pinning a seed makes a number repeatable. It doesn't make it *right*: seed 0 is just one draw out of many equally valid ones. So measure how much the score moves when you change only the seed. Here the forest seed and the fold seed are varied separately, ten values each:

```python run alt="Dot plot with two rows. Changing only the forest's seed keeps mean R squared between about 0.40 and 0.43. Changing only the fold seed spreads it from about 0.36 to 0.43, roughly three times wider." caption="The same model scored under ten seeds. Which rows land in which fold matters more than the forest's own randomness."
import matplotlib.pyplot as plt

def cv_r2(model_seed, fold_seed):
    forest = RandomForestRegressor(n_estimators=30, random_state=model_seed)
    cv = KFold(n_splits=5, shuffle=True, random_state=fold_seed)
    return cross_val_score(forest, X, y, cv=cv, scoring="r2").mean()

seeds = range(10)
by_model_seed = [cv_r2(s, 0) for s in seeds]
by_fold_seed = [cv_r2(0, s) for s in seeds]

fig, ax = plt.subplots(figsize=(7, 2.6))
ax.scatter(by_model_seed, [1] * 10, color="#2a78d6", s=40, alpha=0.8)
ax.scatter(by_fold_seed, [0] * 10, color="#eb6834", s=40, alpha=0.8)
ax.set_yticks([0, 1], ["fold seed varies", "forest seed varies"])
ax.set_ylim(-0.6, 1.6)
ax.set_xlabel("mean cross-validated R^2")
ax.spines[["top", "right"]].set_visible(False)
plt.tight_layout()
plt.show()

print(f"forest seed range: {max(by_model_seed) - min(by_model_seed):.3f}")
print(f"fold seed range:   {max(by_fold_seed) - min(by_fold_seed):.3f}")
```

Look at the printed ranges. On this dataset, reshuffling the folds moves the score about three times as much as reseeding the forest. Now suppose a second model beats this one by 0.02 under seed 0. That gap is smaller than the spread you get from reshuffling alone, so it tells you nothing yet. Module 3 turns this into a proper tool (repeated cross-validation and fold-by-fold comparisons), but the habit starts here: before you believe a difference, know how big the noise is.

:::note
The same seed can still give slightly different numbers on a different machine. Library versions, the math library NumPy was built with, and multithreaded code can change the last few digits. That's why the setup lesson had you print versions: when two people's results disagree in the third decimal place, versions are the first thing to compare.
:::

## Smoke test: one cell that touches everything

The last step proves the toolkit works end to end: a pandas DataFrame with a text column, a `ColumnTransformer`, a `Pipeline`, `cross_validate` with two metrics, and an assertion that fails loudly if anything is off. Paste it into your setup notebook and keep it there.

```python run title="smoke_test.py"
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.linear_model import Ridge
from sklearn.model_selection import cross_validate
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

frame = load_diabetes(as_frame=True).frame
rng = np.random.default_rng(SEED)
frame["clinic"] = rng.choice(["north", "south", "east"], size=len(frame))  # a text column

features = frame.drop(columns="target")
numeric = [c for c in features.columns if c != "clinic"]
model = Pipeline([
    ("prep", ColumnTransformer([
        ("num", StandardScaler(), numeric),
        ("cat", OneHotEncoder(handle_unknown="ignore"), ["clinic"]),
    ])),
    ("ridge", Ridge(alpha=1.0)),
])
result = cross_validate(model, features, frame["target"],
                        cv=KFold(5, shuffle=True, random_state=SEED),
                        scoring=["r2", "neg_mean_absolute_error"])

r2 = result["test_r2"].mean()
mae = -result["test_neg_mean_absolute_error"].mean()
print(f"Ridge pipeline: R^2 = {r2:.3f}, MAE = {mae:.1f}")
assert 0.3 < r2 < 0.6, "unexpected score: check versions and the data"
print("Smoke test passed")
```

If this prints `Smoke test passed`, every library is installed, they work together, and your numbers match the page. The `assert` line is a cheap habit worth keeping: it turns "this looks about right" into a check that stops the notebook when something drifts. Notice also the `neg_` in the scorer name. scikit-learn always maximizes scores, so error metrics come back negated, and you flip the sign to report them.

:::quiz
Q: You compare a forest and a boosted model with `cv = KFold(5, shuffle=True, random_state=np.random.RandomState(1))`, calling `cross_val_score(model, X, y, cv=cv)` for each. What's wrong?
- [ ] Nothing: the RandomState is seeded, so both models see the same folds
  The object is seeded once, but each `split` call advances it, so the second model gets different folds.
- [x] The two models are scored on different folds, so part of the gap is fold noise
  Use `random_state=1` (an integer) so every call to `split` produces the same folds.
- [ ] `KFold` doesn't accept a `RandomState` object
  It does accept one; it just behaves differently from an integer.

Q: Under seed 0, model B beats model A by 0.01 R^2. Reshuffling the folds alone moves A's score by about 0.07. What should you conclude?
- [ ] B is better, because 0.01 is a positive difference
  A positive gap smaller than the seed-to-seed noise could easily flip under another seed.
- [x] Nothing yet: the gap is smaller than the noise from reshuffling
  You need repeated or paired comparisons (Module 3) before calling a winner.
- [ ] A is better, because seed 0 is unreliable
  Seed 0 is no worse than any other seed; it's just one draw.

Q: Which of these models has no `random_state` parameter because it never draws random numbers?
- [ ] `RandomForestRegressor`
  Forests bootstrap rows and sample features, so they need a seed.
- [x] `LinearRegression`
  Least squares has one exact solution, so the same data always gives the same model.
- [ ] `KFold(shuffle=True)`
  Shuffling is random, so the splitter takes a `random_state`.
:::

:::takeaways
- Randomness enters through data generation, splitting, fold shuffling, model internals, and search sampling; seed each one.
- Keep one `SEED` constant and pass it as an integer; a shared `RandomState` object gives each call different folds.
- Use `np.random.default_rng(SEED)` for random numbers you generate yourself.
- A pinned seed is repeatable, not representative. Measure the seed-to-seed spread before trusting a small difference.
- Keep a smoke-test cell with an `assert` at the top of your setup notebook.
:::
