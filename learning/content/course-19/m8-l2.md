This lesson is a complete, runnable starter for the medium project from the brief: **fast diabetes progression** (progression above 200 after one year), where a positive prediction books an earlier follow-up. Every milestone is one or two notebook cells and ends with something printed that you can check. Lines marked `# SWAP` are the ones you change for a different project; a table at the end lists them.

The whole notebook runs in well under a minute on Colab. If a milestone surprises you, stop and investigate before moving on: a capstone fails at the milestone where someone ignored a strange number.

## Milestone 1: Write the plan into the code, and seal the test set

The plan from the brief becomes a dictionary at the top of the notebook. Every later cell reads from it, so changing a choice means changing it here, in one visible place.

```python run
import sklearn
from threadpoolctl import threadpool_limits
threadpool_limits(limits=1, user_api="openmp")   # optional in Colab; see Module 6

import numpy as np
import pandas as pd
from sklearn.datasets import load_diabetes
from sklearn.model_selection import train_test_split

SEED = 42
PLAN = {
    "decision": "book an earlier follow-up for patients likely to progress fast",
    "positive": "progression score above 200 after one year",
    "metric": "average_precision",
    "cost_miss": 3, "cost_false_alarm": 1,       # a missed fast progressor costs 3x
    "min_gap": 0.02,                             # smallest AP gap worth acting on
}

data = load_diabetes(as_frame=True, scaled=False)       # SWAP: load your data
X = data.data
y = (data.target > 200).astype(int)                     # SWAP: your positive class
X_dev, X_test, y_dev, y_test = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=SEED)

print(f"development rows {len(X_dev)}, sealed test rows {len(X_test)}, "
      f"positive share {y_dev.mean():.3f}")
```

From here until Milestone 9, `X_test` and `y_test` are never used. If you search the notebook for `X_test` before submitting, it should appear only here and in Milestone 9.

## Milestone 2: Shared folds and a baseline

One outer splitter (5 folds, repeated twice with different shuffles) is shared by every candidate, so fold *i* means the same rows for all of them. A helper records each candidate's per-fold scores.

```python run
from sklearn.dummy import DummyClassifier
from sklearn.model_selection import RepeatedStratifiedKFold, StratifiedKFold, cross_validate

outer = RepeatedStratifiedKFold(n_splits=5, n_repeats=2, random_state=SEED)
inner = StratifiedKFold(n_splits=3, shuffle=True, random_state=SEED)
results = {}

def evaluate(name, model):
    r = cross_validate(model, X_dev, y_dev, cv=outer,
                       scoring=["average_precision", "roc_auc", "neg_brier_score"])
    results[name] = r
    ap = r["test_average_precision"]
    print(f"{name:>9}: AP {ap.mean():.3f} ± {ap.std():.3f}   ROC AUC {r['test_roc_auc'].mean():.3f}"
          f"   Brier {-r['test_neg_brier_score'].mean():.3f}")

evaluate("baseline", DummyClassifier(strategy="prior"))
```

The baseline's AP equals the positive share (about 0.27), and its Brier score is what you get by predicting that share for everyone. Every real model must clear both.

## Milestone 3: Tune each candidate inside the folds

Each candidate is a `GridSearchCV` with a small, fixed grid: that is the bounded budget from the plan. Passing the search object itself to `cross_validate` makes it **nested**: on every outer fold, the grid search runs its own 3-fold search on the outer training part only, so the outer score never sees the rows that chose the settings.

```python run
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import GridSearchCV
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

candidates = {                                           # SWAP: your candidates and grids
    "logistic": GridSearchCV(
        make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000)),
        {"logisticregression__C": [0.01, 0.1, 1, 10]}, cv=inner, scoring=PLAN["metric"]),
    "boosting": GridSearchCV(
        HistGradientBoostingClassifier(max_iter=100, random_state=SEED),
        {"learning_rate": [0.03, 0.1], "max_leaf_nodes": [4, 8]}, cv=inner, scoring=PLAN["metric"]),
}
for name, search in candidates.items():
    evaluate(name, search)
```

Both clear the baseline by a wide margin. Logistic regression is ahead on all three metrics, but the spreads are large. Whether the lead is real is the next milestone's job.

## Milestone 4: A paired comparison and the decision rule

The corrected resampled t-test from the brief works on the per-fold differences. Its only change from an ordinary paired t-test is the extra `test_share / (1 - test_share)` term, which widens the standard error because overlapping training sets make the folds' scores correlated.

```python run alt="Dot plot of ten paired fold differences in average precision, logistic minus boosting; seven dots are right of zero and three are left, with the mean marked near 0.03" caption="One dot per outer fold. Right of zero means logistic regression won that fold."
import matplotlib.pyplot as plt
from scipy import stats

def corrected_ttest(a, b, test_share):
    d = np.asarray(a) - np.asarray(b)
    k = len(d)
    se = np.sqrt(d.var(ddof=1) * (1 / k + test_share / (1 - test_share)))
    return d.mean(), 2 * stats.t.sf(abs(d.mean() / se), df=k - 1)

a = results["logistic"]["test_average_precision"]
b = results["boosting"]["test_average_precision"]
gap, p_value = corrected_ttest(a, b, test_share=1 / 5)
print(f"logistic minus boosting: mean AP gap {gap:.3f}, wins {np.sum(a > b)} of {len(a)} folds, "
      f"corrected p = {p_value:.2f}")

clear_win = gap > PLAN["min_gap"] and np.sum(a > b) > len(a) / 2 and p_value < 0.05
print("decision:", "logistic is clearly better" if clear_win
      else "no clear winner, so the plan says: prefer the simpler model, logistic regression")

fig, ax = plt.subplots(figsize=(6.5, 1.8))
ax.scatter(a - b, np.zeros(len(a)), s=60, color="#2a78d6", zorder=3)
ax.axvline(0, color="#52514e", lw=1)
ax.axvline(gap, color="#eb6834", lw=2, ls="--", label=f"mean gap {gap:.3f}")
ax.set_yticks([])
ax.set_xlabel("AP(logistic) minus AP(boosting), per outer fold")
ax.legend(frameon=False, loc="upper left")
```

Logistic regression wins 7 of 10 folds by about 0.03 on average, but the corrected test can't rule out chance (p around 0.4). The plan anticipated this: when neither model is clearly better, prefer the simpler, cheaper, easier-to-explain one. That sentence, written before you saw any numbers, is what makes this a decision rather than a preference.

:::note
A naive paired t-test on the same ten differences, `stats.ttest_rel(a, b)`, reports p of about 0.16, less than half the corrected value. That difference is the overconfidence the correction removes. With more folds or a slightly bigger gap, the naive test would cross 0.05 while the corrected one would not.
:::

## Milestone 5: Imbalance and the threshold

About 27% of patients are positive, so imbalance is moderate. The plan says to test class weights by AP and to pick the threshold from costs. First, fix the logistic model's `C` by refitting its search on all development rows.

```python run
from sklearn.metrics import confusion_matrix, make_scorer
from sklearn.model_selection import TunedThresholdClassifierCV, cross_val_score

best_C = candidates["logistic"].fit(X_dev, y_dev).best_params_["logisticregression__C"]
print("chosen C:", best_C)
for weights in [None, "balanced"]:
    model = make_pipeline(StandardScaler(), LogisticRegression(C=best_C, class_weight=weights,
                                                               max_iter=1000))
    ap = cross_val_score(model, X_dev, y_dev, cv=outer, scoring="average_precision")
    print(f"class_weight={weights!s:>8}: AP {ap.mean():.3f}")

def cost(y_true, y_pred):
    tn, fp, fn, tp = confusion_matrix(y_true, y_pred, labels=[0, 1]).ravel()
    return PLAN["cost_miss"] * fn + PLAN["cost_false_alarm"] * fp

neg_cost = make_scorer(lambda yt, yp: -cost(yt, yp))
final = make_pipeline(StandardScaler(), LogisticRegression(C=best_C, max_iter=1000))
detector = TunedThresholdClassifierCV(final, scoring=neg_cost, cv=inner, random_state=SEED)
at_half = -cross_val_score(final, X_dev, y_dev, cv=outer, scoring=neg_cost)
at_tuned = -cross_val_score(detector, X_dev, y_dev, cv=outer, scoring=neg_cost)
print(f"cost per fold: threshold 0.5 -> {at_half.mean():.1f}, tuned threshold -> {at_tuned.mean():.1f}")
detector.fit(X_dev, y_dev)
print(f"threshold chosen on all development rows: {detector.best_threshold_:.3f}")
```

Class weights change AP by less than 0.01, so we keep the unweighted model and its honest probabilities. The tuned threshold (evaluated with the threshold chosen inside each outer fold, so the comparison is fair) lowers the cost a little and ends up near 0.2, close to the textbook `1 / (1 + 3) = 0.25` for these costs.

## Milestone 6: Check calibration

The threshold logic assumes the probabilities are roughly right, so check them on out-of-fold predictions.

```python run alt="Reliability diagram with five quantile bins for the final logistic model: the points lie near the diagonal, slightly above it at the top end" caption="Out-of-fold reliability for the final model, five equal-size bins."
from sklearn.calibration import CalibrationDisplay
from sklearn.metrics import brier_score_loss
from sklearn.model_selection import cross_val_predict

five_fold = StratifiedKFold(n_splits=5, shuffle=True, random_state=SEED)
oof = cross_val_predict(final, X_dev, y_dev, cv=five_fold, method="predict_proba")[:, 1]
print(f"out-of-fold Brier {brier_score_loss(y_dev, oof):.3f} "
      f"(baseline {brier_score_loss(y_dev, np.full(len(y_dev), y_dev.mean())):.3f})")
fig, ax = plt.subplots(figsize=(4.6, 4.2))
CalibrationDisplay.from_predictions(y_dev, oof, n_bins=5, strategy="quantile",
                                    name="final logistic", ax=ax, color="#2a78d6")
```

With only about 66 patients per bin the points wobble, but none sits far from the diagonal, and the Brier score is well below the baseline's. No recalibration needed. Write that sentence, with the numbers, into the report.

## Milestone 7: Leak checks

Three quick checks from Module 6. Shuffled labels should drop AP to about the positive share. No single column should be suspiciously strong. Development and test rows must not overlap or repeat.

```python run
from sklearn.metrics import roc_auc_score

shuffled = pd.Series(np.random.default_rng(SEED).permutation(y_dev.to_numpy()), index=y_dev.index)
ap_shuffled = cross_val_score(final, X_dev, shuffled, cv=outer, scoring="average_precision").mean()
print(f"AP with shuffled labels: {ap_shuffled:.3f} (positive share {y_dev.mean():.3f})")

solo = {c: max(roc_auc_score(y_dev, X_dev[c]), 1 - roc_auc_score(y_dev, X_dev[c])) for c in X_dev}
print("strongest single columns:", {c: round(v, 3) for c, v in
                                   sorted(solo.items(), key=lambda kv: -kv[1])[:3]})
print("duplicate development rows:", int(X_dev.duplicated().sum()),
      "| rows in both dev and test:", len(set(X_dev.index) & set(X_test.index)))
```

Shuffled labels give an AP close to the positive share (the small excess is noise from only 331 rows), so the pipeline can't find signal where there is none. The strongest single columns (`s5` and `bmi`, around 0.8 each) are plausible clinical measurements taken at baseline, not consequences of the outcome. There are no duplicates. The diabetes data has one row per patient, so no group split is needed; say so explicitly in the report.

## Milestone 8: Explain the model and slice its errors

Permutation importance uses a held-out slice of the development rows. Slices use the out-of-fold probabilities from Milestone 6, cut at the chosen threshold, with bootstrap intervals.

```python run
from sklearn.inspection import permutation_importance

X_fit, X_hold, y_fit, y_hold = train_test_split(X_dev, y_dev, test_size=0.3, stratify=y_dev,
                                                random_state=SEED)
perm = permutation_importance(final.fit(X_fit, y_fit), X_hold, y_hold,
                              scoring="average_precision", n_repeats=20, random_state=SEED)
importance = pd.Series(perm.importances_mean, X.columns).sort_values(ascending=False)
print("AP lost when shuffled:", importance.head(4).round(3).to_dict())

flagged = oof >= detector.best_threshold_
frame = pd.DataFrame({"y": y_dev.to_numpy(), "flag": flagged,
                      "sex": "sex=" + X_dev.sex.astype(int).astype(str).to_numpy(),   # SWAP: slices
                      "age": pd.cut(X_dev.age, [0, 45, 60, 100],
                                    labels=["age<45", "age 45-59", "age 60+"]).astype(str).to_numpy()})
frame["missed"] = (frame.y == 1) & ~frame.flag
rng = np.random.default_rng(SEED)
rows = []
for column in ["sex", "age"]:
    for level, part in frame.groupby(column):
        pos = part[part.y == 1]
        boot = [rng.choice(pos.missed.to_numpy(), len(pos)).mean() for _ in range(1000)]
        rows.append({"slice": level, "patients": len(part), "fast progressors": len(pos),
                     "miss rate": pos.missed.mean(),
                     "90% interval": f"{np.percentile(boot, 5):.2f}-{np.percentile(boot, 95):.2f}"})
slices = pd.DataFrame(rows)
print(f"overall miss rate: {frame[frame.y == 1].missed.mean():.3f}")
print(slices.round(3).to_string(index=False))
```

The miss rate (the share of fast progressors the model fails to flag) is the slice metric that matches the decision, since a miss is the expensive mistake. Read the intervals before the point estimates: with a few dozen fast progressors per slice, every interval is wide and they overlap, so the honest finding is "no slice is detectably worse", plus the sample sizes that limit that claim. The youngest group's miss rate is about twice the middle group's; that is worth listing as something to monitor, not as a finding.

## Milestone 9: Open the test set once, and draft the report

Everything is fixed: model, `C`, threshold. Fit on all development rows, score the sealed test set once, and let the code write the numbers into the report draft.

```python run
from sklearn.metrics import average_precision_score

proba = detector.estimator_.predict_proba(X_test)[:, 1]
pred = detector.predict(X_test)
tn, fp, fn, tp = confusion_matrix(y_test, pred).ravel()
cv_ap = results["logistic"]["test_average_precision"]

report = f"""
RECOMMENDATION: logistic regression (C={best_C}), flag patients with probability >= {detector.best_threshold_:.2f}.
Decision: {PLAN['decision']}. Positive class: {PLAN['positive']}.

Evidence (cross-validation, 5 folds x 2 repeats, tuning nested inside):
  AP {cv_ap.mean():.3f} +/- {cv_ap.std():.3f} vs boosting {b.mean():.3f}; baseline {results['baseline']['test_average_precision'].mean():.3f}
  Paired gap {gap:.3f} AP, logistic wins {np.sum(a > b)}/10 folds, corrected p = {p_value:.2f}: no clear winner,
  so the simpler model is preferred, as the plan specified.
Sealed test set ({len(y_test)} patients, opened once):
  AP {average_precision_score(y_test, proba):.3f}, ROC AUC {roc_auc_score(y_test, proba):.3f}, Brier {brier_score_loss(y_test, proba):.3f}
  Flags {tp + fp} patients: {tp} fast progressors and {fp} false alarms; misses {fn} of {tp + fn}.
Checks: shuffled-label AP {ap_shuffled:.3f} (positive share {y_dev.mean():.3f}); no duplicates; one row per patient.
Drivers: {', '.join(importance.index[:3])} matter most (permutation importance).
Limits: 442 patients from one study; slices too small to rule out subgroup gaps; probabilities checked
  only on this population.
"""
print(report)
```

The test numbers should land inside the range the cross-validation predicted. If they had been far outside it, the right response would be to report that and investigate, not to go back and change the model, because the test set has now been used.

:::quiz
Q: In Milestone 3, why pass the `GridSearchCV` object to `cross_validate` instead of tuning once and then cross-validating the best settings?
- [ ] It runs faster
  Nesting runs the search once per outer fold, so it is slower.
- [x] So each outer score comes from settings chosen without that fold's rows, which keeps the comparison free of tuning optimism
  Tuning on all rows first would let the outer folds grade settings they helped choose.
- [ ] Because `cross_validate` refuses untuned models
  It accepts any estimator; the baseline in Milestone 2 is untuned.

Q: Milestone 4 found a 0.03 AP gap in 7 of 10 folds with p around 0.4. What does the plan's decision rule do with that?
- [x] Recommends the simpler logistic model because the complex model isn't clearly better
  The rule was written to break exactly this kind of near-tie, before the numbers were known.
- [ ] Declares logistic regression significantly better
  The corrected test says the gap could easily be chance.
- [ ] Asks you to add more folds until the p-value drops below 0.05
  Adding resamples of the same 331 rows can't create new information, and running tests until one passes is the self-deception the plan prevents.

Q: Why is the report text generated by code in Milestone 9?
- [ ] Because Colab can't display Markdown
  Colab renders Markdown cells fine.
- [x] So every number in the write-up comes from the same run, and rerunning the notebook updates the report instead of leaving stale numbers
  Copying numbers by hand is how reports drift away from the code that supposedly produced them.
:::
