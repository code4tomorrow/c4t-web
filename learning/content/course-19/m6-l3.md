:::objectives
- Use out-of-bag scores to decide how many trees a random forest needs.
- Trade learning rate against boosting rounds with early stopping.
- Diagnose bias and variance from training and validation scores.
- Show how correlated features split permutation importance, and measure them jointly.
- Catch leakage from target encoding and from shuffled time-ordered data, and fix both.
:::

These exercises go from tuning the two ensembles to catching leaks that don't look like leaks. Boosting cells start by capping OpenMP threads, as in the Build-along, so they stay fast on a shared machine; in Colab you can drop those lines.

## Warm-up: safe, target leak, or contamination?

For each situation, decide before opening the solution.

1.  Predicting next month's loan default from `missed_payments_last_6_months`, measured at the start of the month.
2.  Predicting customer churn from `account_closed_reason`.
3.  Scaling every image by the mean and standard deviation of the *whole* dataset, then cross-validating.
4.  Five X-rays per patient, with rows shuffled into folds.
5.  Predicting a diagnosis from `treatment_given`.

:::solution
1.  **Safe.** It is known before the outcome.
2.  **Target leak.** The reason only exists after the account has closed.
3.  **Contamination.** Validation images influenced the scaling. Usually small, but a pipeline removes it for free.
4.  **Contamination.** The model can recognize patients; split with `GroupKFold`.
5.  **Target leak.** Treatment is chosen *because of* the diagnosis.
:::

### Exercise 1: How many trees does a forest need?

Each tree in a random forest skips about a third of the rows in its bootstrap sample. Scoring every row using only the trees that didn't see it gives the **out-of-bag (OOB)** score, a free validation estimate. On `load_digits`, grow one forest with `warm_start=True` from 10 to 200 trees and print the OOB accuracy at 10, 25, 50, 100, and 200 trees. Where does adding trees stop paying off?

:::hint
Create `RandomForestClassifier(oob_score=True, warm_start=True, random_state=0)`, then in a loop call `set_params(n_estimators=n)` and `fit` again. With `warm_start`, each fit only adds the new trees. Expect a warning at 10 trees: some rows haven't been left out by any tree yet.
:::

:::solution
```python run
import warnings
from sklearn.datasets import load_digits
from sklearn.ensemble import RandomForestClassifier

warnings.filterwarnings("ignore", message="Some inputs do not have OOB scores")
X, y = load_digits(return_X_y=True)
forest = RandomForestClassifier(oob_score=True, warm_start=True, random_state=0)
for n in [10, 25, 50, 100, 200]:
    forest.set_params(n_estimators=n).fit(X, y)
    print(f"{n:>4} trees: OOB accuracy {forest.oob_score_:.4f}")
```

Accuracy climbs fast to 100 trees and then creeps up by a fraction of a percent. More trees never make a forest worse; they just cost time. Pick the point where the curve flattens for your budget.
:::

### Exercise 2: Learning rate against rounds

On `make_classification(n_samples=5000, n_features=20, n_informative=8, flip_y=0.05, random_state=0)`, fit `HistGradientBoostingClassifier` with early stopping (`max_iter=1000`, `validation_fraction=0.2`, `n_iter_no_change=15`) at learning rates 0.3, 0.1, and 0.03. Report the number of rounds used (`n_iter_`) and the best held-out log loss for each.

:::hint
The held-out scores are in `validation_score_`, stored as negative loss. The best loss is `-validation_score_.max()`.
:::

:::solution
```python run
import sklearn
from threadpoolctl import threadpool_limits
threadpool_limits(limits=1, user_api="openmp")
from sklearn.datasets import make_classification
from sklearn.ensemble import HistGradientBoostingClassifier

X, y = make_classification(n_samples=5000, n_features=20, n_informative=8,
                           flip_y=0.05, random_state=0)
for rate in [0.3, 0.1, 0.03]:
    model = HistGradientBoostingClassifier(learning_rate=rate, max_iter=1000, early_stopping=True,
                                           validation_fraction=0.2, n_iter_no_change=15,
                                           random_state=0).fit(X, y)
    print(f"learning rate {rate:<5} rounds {model.n_iter_:>4}   best held-out log loss "
          f"{-model.validation_score_.max():.4f}")
```

Cutting the rate by 10 multiplies the rounds by about 6 and buys a slightly better loss. That is the usual pattern: a small learning rate with early stopping is a safe default, and the price is training time.
:::

### Exercise 3: Bias or variance?

Using `cross_validate(..., return_train_score=True)` with ROC AUC on `make_classification(n_samples=3000, n_features=20, n_informative=8, flip_y=0.05, random_state=1)`, compare a depth-2 decision tree, an unlimited decision tree, a random forest, and histogram gradient boosting. For each, say whether its main problem is bias, variance, or neither.

:::hint
High bias: training and validation scores are both mediocre and close together. High variance: training is near perfect but validation is much lower.
:::

:::solution
```python run
import sklearn
from threadpoolctl import threadpool_limits
threadpool_limits(limits=1, user_api="openmp")
from sklearn.datasets import make_classification
from sklearn.ensemble import HistGradientBoostingClassifier, RandomForestClassifier
from sklearn.model_selection import cross_validate
from sklearn.tree import DecisionTreeClassifier

X, y = make_classification(n_samples=3000, n_features=20, n_informative=8,
                           flip_y=0.05, random_state=1)
models = {
    "depth-2 tree": DecisionTreeClassifier(max_depth=2),
    "deep tree": DecisionTreeClassifier(random_state=0),
    "forest": RandomForestClassifier(n_estimators=100, random_state=0),
    "boosting": HistGradientBoostingClassifier(random_state=0),
}
for name, model in models.items():
    r = cross_validate(model, X, y, cv=5, scoring="roc_auc", return_train_score=True)
    print(f"{name:>13}: train {r['train_score'].mean():.3f}   validation {r['test_score'].mean():.3f}")
```

The depth-2 tree has **bias**: about 0.8 on both. The deep tree has **variance**: perfect on training, 0.85 on validation. The forest and boosting also score near 1.0 on training, yet both reach about 0.97 on validation. A perfect training score is normal for these ensembles; what matters is the validation score and its gap to other models, not the gap to training.
:::

### Exercise 4: A duplicated feature hides its own importance

On `load_diabetes(as_frame=True)` with a 70/30 split (`random_state=0`), fit `RandomForestRegressor(n_estimators=200, min_samples_leaf=3, random_state=0)` and print the top permutation importances on the test set. Then add `bmi_copy` (bmi plus tiny noise), refit, and print them again. Finally, measure the drop in test R² when you shuffle `bmi` and `bmi_copy` *together*, with the same permutation.

:::hint
For the joint shuffle, draw one permutation `perm` and assign `X_shuffled[["bmi", "bmi_copy"]] = X_test[["bmi", "bmi_copy"]].values[perm]`. Compare `model.score` before and after, averaged over a few permutations.
:::

:::solution
```python run
import numpy as np
import pandas as pd
from sklearn.datasets import load_diabetes
from sklearn.ensemble import RandomForestRegressor
from sklearn.inspection import permutation_importance
from sklearn.model_selection import train_test_split

data = load_diabetes(as_frame=True)
X, y = data.data.copy(), data.target
X["bmi_copy"] = X.bmi + np.random.default_rng(0).normal(0, 0.002, len(X))

def top_importances(columns):
    X_tr, X_te, y_tr, y_te = train_test_split(X[columns], y, test_size=0.3, random_state=0)
    model = RandomForestRegressor(n_estimators=200, min_samples_leaf=3,
                                  random_state=0).fit(X_tr, y_tr)
    perm = permutation_importance(model, X_te, y_te, n_repeats=10, random_state=0)
    print(pd.Series(perm.importances_mean, columns).sort_values(ascending=False)
          .head(4).round(3).to_dict())
    return model, X_te, y_te

top_importances(list(data.feature_names))
model, X_te, y_te = top_importances(list(data.feature_names) + ["bmi_copy"])

base = model.score(X_te, y_te)
drops = []
for seed in range(10):
    perm = np.random.default_rng(seed).permutation(len(X_te))
    shuffled = X_te.copy()
    shuffled[["bmi", "bmi_copy"]] = X_te[["bmi", "bmi_copy"]].values[perm]
    drops.append(base - model.score(shuffled, y_te))
print(f"shuffling bmi and bmi_copy together: R² drops by {np.mean(drops):.3f}")
```

Alone, `bmi` is the second most important feature (0.157). With a near-identical copy, the credit splits unevenly: `bmi_copy` keeps about a third of it and `bmi` drops out of the top four, because shuffling one twin leaves the other to carry the information. Shuffled together, they cost 0.150, about what `bmi` was worth alone. Real data is full of near-twins (the diabetes features `s1` and `s2` correlate at about 0.9), so group strongly correlated features and permute each group together.
:::

### Exercise 5: The target-encoding leak

Target encoding replaces each category with the average target for that category. A teammate encodes a 400-value `zip_code` column using *all* the rows, then cross-validates a logistic regression on it. The target below is pure noise, so the honest AUC is 0.5. Reproduce their result, then fix it with scikit-learn's `TargetEncoder` inside a pipeline.

```python
import numpy as np
import pandas as pd

rng = np.random.default_rng(0)
n = 2000
df = pd.DataFrame({"zip_code": rng.integers(0, 400, n).astype(str), "x1": rng.normal(size=n)})
y = (rng.random(n) < 0.3).astype(int)          # no real link to anything
encoded = df.zip_code.map(pd.Series(y).groupby(df.zip_code).mean())
print(encoded.head(3).round(2).tolist())
```

:::hint
`TargetEncoder` uses internal cross-fitting in `fit_transform`: each row is encoded with statistics from other folds, so a row never sees its own label. Put it in a `make_column_transformer` for the `zip_code` column with `remainder="passthrough"`.
:::

:::solution
```python run
import numpy as np
import pandas as pd
from sklearn.compose import make_column_transformer
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import StratifiedKFold, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import TargetEncoder

rng = np.random.default_rng(0)
n = 2000
df = pd.DataFrame({"zip_code": rng.integers(0, 400, n).astype(str), "x1": rng.normal(size=n)})
y = (rng.random(n) < 0.3).astype(int)
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)

leaky = pd.DataFrame({"zip_te": df.zip_code.map(pd.Series(y).groupby(df.zip_code).mean()),
                      "x1": df.x1})
print("encode first, then CV:", cross_val_score(LogisticRegression(), leaky, y, cv=cv,
                                                scoring="roc_auc").mean().round(3))

pipe = make_pipeline(
    make_column_transformer((TargetEncoder(random_state=0), ["zip_code"]), remainder="passthrough"),
    LogisticRegression())
print("TargetEncoder in a pipeline:", cross_val_score(pipe, df, y, cv=cv,
                                                       scoring="roc_auc").mean().round(3))
```

With only 5 rows per zip code, each row's own label makes up a fifth of its encoding, so the encoded value partly *is* the answer. The leaky version scores about 0.76 on noise. Inside the pipeline, encodings are learned on training folds only and cross-fitted within them, and the score falls to 0.5, which is the truth.
:::

### Exercise 6: Shuffled time series

A shop's daily demand depends on temperature, promotions, and a slowly wandering level of popularity. Generate two years of it as below, then estimate a random forest's mean absolute error with shuffled `KFold` and with `TimeSeriesSplit`. Which number would you put in a report, and why are they so different?

```python
import numpy as np

rng = np.random.default_rng(3)
day = np.arange(730)
popularity = np.cumsum(rng.normal(0, 1, 730))            # drifts slowly over time
temperature = 15 + 10 * np.sin(2 * np.pi * day / 365) + rng.normal(0, 3, 730)
promo = rng.integers(0, 2, 730)
demand = 100 + 3 * popularity + 1.5 * temperature + 20 * promo + rng.normal(0, 5, 730)
X = np.column_stack([day, temperature, promo])
print(X.shape, round(demand.mean(), 1))
```

:::hint
`TimeSeriesSplit(n_splits=5)` always trains on earlier days and tests on the block that follows. Use `scoring="neg_mean_absolute_error"` and flip the sign.
:::

:::solution
```python run
import numpy as np
from sklearn.ensemble import RandomForestRegressor
from sklearn.model_selection import KFold, TimeSeriesSplit, cross_val_score

rng = np.random.default_rng(3)
day = np.arange(730)
popularity = np.cumsum(rng.normal(0, 1, 730))
temperature = 15 + 10 * np.sin(2 * np.pi * day / 365) + rng.normal(0, 3, 730)
promo = rng.integers(0, 2, 730)
demand = 100 + 3 * popularity + 1.5 * temperature + 20 * promo + rng.normal(0, 5, 730)
X = np.column_stack([day, temperature, promo])

for name, cv in [("shuffled KFold", KFold(5, shuffle=True, random_state=0)),
                 ("TimeSeriesSplit", TimeSeriesSplit(n_splits=5))]:
    mae = -cross_val_score(RandomForestRegressor(n_estimators=100, random_state=0),
                           X, demand, cv=cv, scoring="neg_mean_absolute_error")
    print(f"{name:>16}: MAE per fold {mae.round(1)}   mean {mae.mean():.1f}")
```

Report the `TimeSeriesSplit` number, about 26. With shuffled folds, every test day has training days on both sides of it, and the `day` column lets the forest look up the popularity level of its neighbours: interpolation, which is easy. In real use the model must extrapolate into the future, where popularity has drifted, and the error is more than four times larger.
:::

### Challenge: Write a leak scanner

Write `leak_scan(df, target, group_col=None)` that prints three warnings: any single column whose ROC AUC against the target is above 0.9 (or below 0.1), whether any group appears in more than one row, and how many rows are exact duplicates of another row once the target is removed. Test it on this planted dataset, which hides one of each problem.

:::hint
For a numeric column, `roc_auc_score(df[target], df[col])` works directly; use `max(auc, 1 - auc)` so a column that predicts the opposite way is caught too. Skipping text columns is fine for a first version. `df.drop(columns=target).duplicated().sum()` counts duplicate rows.
:::

:::solution
```python run
import numpy as np
import pandas as pd
from sklearn.metrics import roc_auc_score

def leak_scan(df, target, group_col=None):
    features = df.drop(columns=[target])
    for col in features.select_dtypes("number").columns:
        if col == group_col:
            continue
        auc = roc_auc_score(df[target], df[col])
        if max(auc, 1 - auc) > 0.9:
            print(f"WARNING: '{col}' alone gives ROC AUC {max(auc, 1 - auc):.3f}. When is it known?")
    if group_col is not None:
        repeats = df[group_col].value_counts()
        if (repeats > 1).any():
            print(f"WARNING: {int((repeats > 1).sum())} values of '{group_col}' appear in several "
                  "rows. Split with GroupKFold.")
    dupes = int(features.duplicated().sum())
    if dupes:
        print(f"WARNING: {dupes} rows duplicate an earlier row's features.")

rng = np.random.default_rng(5)
patients = rng.integers(0, 150, 500)
age = rng.integers(20, 80, 500)
blood_pressure = rng.normal(125, 15, 500).round()
sick = (rng.random(500) < 1 / (1 + np.exp(-(age - 55) / 8))).astype(int)
df = pd.DataFrame({"patient_id": patients, "age": age, "blood_pressure": blood_pressure,
                   "days_in_hospital": np.where(sick == 1, rng.integers(3, 15, 500), 0),
                   "sick": sick})
df = pd.concat([df, df.sample(20, random_state=0)], ignore_index=True)   # accidental re-import
leak_scan(df, "sick", group_col="patient_id")
```

All three warnings fire. `days_in_hospital` is a consequence of being sick, most of the 150 patients appear more than once, and the re-imported rows are exact copies. A scanner like this won't find every leak, but it costs a second and catches the loud ones before they win a model comparison for you.
:::
