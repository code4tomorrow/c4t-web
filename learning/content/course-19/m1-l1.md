- Run a cell that prints the versions of Python, scikit-learn, NumPy, pandas, SciPy, and matplotlib, and stops loudly if scikit-learn is too old.
- Upgrade scikit-learn inside Colab and restart the session so the upgrade actually loads.

Here is a line you will write in Module 2:

```python
from sklearn.preprocessing import OneHotEncoder

OneHotEncoder(handle_unknown="infrequent_if_exist", min_frequency=20, sparse_output=False)
```

On scikit-learn 1.0 that line fails with a `TypeError` about an unexpected keyword argument, because `min_frequency` and `sparse_output` did not exist yet. On a current version it runs fine. This course uses parts of scikit-learn that arrived or changed in recent releases (`TargetEncoder`, pandas output from transformers, rare-category handling in `OneHotEncoder`), so the very first thing to settle is which versions you are running. It takes five minutes, and it saves you an afternoon of confusing errors later.

## What you need

- **A Google account.** A personal one is the safest choice. Some school accounts have Colab switched off by an administrator, and you'll see a "not allowed" page instead of a notebook.
- **A recent browser** (Chrome, Edge, Firefox, or Safari) on any computer, Chromebooks included.
- **Nothing to install.** Colab runs your Python on a Google-hosted virtual machine and shows the notebook in your browser. scikit-learn, pandas, NumPy, SciPy, and matplotlib are already there.

A local install is optional and covered further down for people who want to work offline.

## Create your course notebook

1.  Go to [colab.research.google.com](https://colab.research.google.com/) and sign in with the button at the top right.
2.  Choose **File › New notebook in Drive**. (If a welcome dialog opens instead, its **New notebook** button does the same thing.)
3.  Click the name `Untitled0.ipynb` at the top left and rename it, for example `ml-eval-00-setup.ipynb`.
4.  Click into the empty code cell, type `print("hello from Colab")`, and press **Shift+Enter**.

The first run takes a few seconds while Colab assigns you a machine (a *runtime*). When it's connected, the top right shows small RAM and Disk bars, and the output appears under the cell. Open Google Drive in another tab: your notebook is in a folder called **Colab Notebooks**. That folder is where every notebook from this course will live unless you move it.

:::tip
**Tools › Keyboard shortcuts** lists every shortcut. The two you'll use constantly are **Shift+Enter** (run this cell and move to the next) and **Ctrl+Enter** (run this cell and stay; **Cmd+Enter** on a Mac).
:::

## Check your versions

Paste this into a new cell and run it. It prints each library's version and then checks the one this course depends on most.

```python run title="version_check.py"
import sys
import numpy, pandas, scipy, matplotlib, sklearn

print("Python      ", sys.version.split()[0])
for lib in (sklearn, numpy, pandas, scipy, matplotlib):
    print(f"{lib.__name__:<12}", lib.__version__)

major, minor = (int(part) for part in sklearn.__version__.split(".")[:2])
if (major, minor) < (1, 6):
    raise RuntimeError("scikit-learn is older than 1.6: run the upgrade cell below")
print("Ready for the course")
```

That output came from the machine that built these pages, so every number and chart in the course comes from scikit-learn 1.8. Your Colab may report a slightly different version. Anything from 1.6 up runs every lesson; small differences in the last decimal place of a score are normal across versions and are not a bug in your code.

The comparison `(major, minor) < (1, 6)` works because Python compares tuples item by item, so `(1, 10)` correctly counts as newer than `(1, 6)`. Comparing the version strings directly would get that wrong, since the text `"1.10"` sorts before `"1.6"`.

## Upgrade scikit-learn when Colab's copy is too old

If the check raised the `RuntimeError`, run this in a new cell:

```python
%pip install -U scikit-learn
```

Then choose **Runtime › Restart session** and run the version cell again. The restart is the step people skip. Python had already imported the old scikit-learn into memory, and installing new files on disk does not replace a module that is already loaded. Restarting starts a fresh Python process that imports the new copy.

:::note
An upgrade only lasts as long as that runtime. When Colab gives you a fresh machine (after you disconnect, after a long idle period, or the next day), the preinstalled version is back. If you needed the upgrade once, keep the `%pip` cell at the top of your notebooks.
:::

## Optional: the same tools on your own computer

A local setup works offline and has no session time limits. Use Python 3.10 or newer and a virtual environment, so this course's packages don't collide with anything else on your machine.

:::tabs
@tab Windows
1. Install Python from [python.org/downloads](https://www.python.org/downloads/) and tick **Add python.exe to PATH** on the first installer screen.
2. Open **PowerShell** in a folder for the course and run:

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install scikit-learn pandas scipy matplotlib jupyterlab
jupyter lab
```

If PowerShell refuses to run `Activate.ps1`, run `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once and try again.
@tab macOS
1. Install Python from [python.org/downloads](https://www.python.org/downloads/).
2. Open **Terminal** in a folder for the course and run:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install scikit-learn pandas scipy matplotlib jupyterlab
jupyter lab
```
@tab Chromebook or Linux
On a Chromebook, Colab is the recommended path. If you have turned on the Linux development environment (or you use a Linux computer), run:

```bash
sudo apt install python3-venv
python3 -m venv .venv
source .venv/bin/activate
python -m pip install scikit-learn pandas scipy matplotlib jupyterlab
jupyter lab
```
:::

JupyterLab opens in your browser. Create a notebook with **File › New › Notebook**, pick the Python 3 kernel, and run the same version cell. Each time you come back, activate the environment again before starting `jupyter lab`.

## Problems you might hit, and the fixes

**A page says Colab is not available for your account.** Your organization has turned it off. Click your profile picture at the top right of Colab, switch to (or add) a personal Google account, and create the notebook there.

**You opened a notebook someone shared, and your edits vanish.** Shared notebooks often open in *playground mode*, which never saves. Choose **File › Save a copy in Drive** and work in the copy, which belongs to you.

**`NameError: name 'X' is not defined` in a cell that worked an hour ago.** The runtime was recycled, so every variable is gone, even though the old outputs are still drawn on the page. Choose **Runtime › Run all** to rebuild the state from the top.

**`TypeError: ... got an unexpected keyword argument` or `ImportError: cannot import name 'TargetEncoder'`.** Your scikit-learn is older than the lesson's. Run the upgrade cell, restart the session, and check the version again.

**Locally: `jupyter: command not found` or `No module named sklearn`.** The virtual environment isn't active in that terminal. Activate it (the prompt then starts with `(.venv)`) and try again.

:::quiz
Q: You run `%pip install -U scikit-learn`, the install succeeds, but `sklearn.__version__` still prints the old number. Why?
- [ ] The install went to a different computer
  It installed on the same Colab runtime; the files on disk are new.
- [x] The old version was already imported, and Python keeps using it until the session restarts
  Imported modules stay in memory. **Runtime › Restart session** starts a fresh process that loads the new files.
- [ ] Colab blocks upgrades of preinstalled packages
  Colab allows it; the upgrade just isn't loaded yet.

Q: Why does the version check compare `(major, minor)` as numbers instead of comparing the strings `"1.10"` and `"1.6"`?
- [x] As text, `"1.10"` sorts before `"1.6"`, so a newer version would look older
  Text compares character by character, and `"1"` comes before `"6"`. Integers in a tuple compare correctly.
- [ ] Strings can't be compared in Python
  They can; they just compare alphabetically, which is wrong for version numbers.
- [ ] Version strings always contain letters
  Some do (like `1.8.dev0`), but the real issue is the alphabetical ordering.
:::

:::takeaways
- Colab needs only a Google account and a browser, and saves notebooks to **Colab Notebooks** in your Drive.
- Print your library versions at the top of every project notebook; this course needs scikit-learn 1.6 or newer.
- After `%pip install -U`, restart the session, or the old version stays loaded.
- A recycled runtime keeps the old outputs on screen but loses every variable: **Runtime › Run all** rebuilds them.
:::
