:::objectives
- Show that a ROC AUC tie can hide differences that change a decision.
- Diagnose and repair a class-weighted model's probabilities with `CalibratedClassifierCV`.
- Use permutation importance and per-group partial dependence to see *how* two models differ.
- Run a slice analysis with bootstrap intervals, and turn all the evidence into a recommendation.
:::

A school library lends books, DVDs, and laptops, and about 38% of loans come back late. The librarians want a model that estimates the chance each new loan will be late, so they can send a friendly reminder to the riskiest third. A previous student project left two candidate models: a logistic regression trained with `class_weight="balanced"` and a gradient-boosted model. Their cross-validated ROC AUCs differ by about 0.01. Which should the library use?

By the end you'll have a short evidence table like this one, with the numbers filled in by your own run:

| Question | Logistic (balanced) | Boosting |
| --- | --- | --- |
| Ranks loans well overall? | step 2 | step 2 |
| Probabilities trustworthy? | step 3 | step 3 |
| Relies on sensible features? | step 4 | step 4 |
| Works for every item type? | step 5 | step 5 |

## Step 1: Load the loans and seal a test set

As in earlier modules, the data is generated so everyone gets the same numbers; the columns are what a library system could export at checkout time. The thread cap at the top is the same one from Module 6.

```python run
import sklearn
from threadpoolctl import threadpool_limits
threadpool_limits(limits=1, user_api="openmp")

import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split

rng = np.random.default_rng(11)
n = 5000
loans = pd.DataFrame({
    "item_type": rng.choice(["book", "dvd", "laptop"], n, p=[0.72, 0.18, 0.10]),
    "borrower": rng.choice(["student", "staff", "public"], n, p=[0.5, 0.15, 0.35]),
    "distance_km": rng.gamma(2.0, 2.5, n).round(1),
    "past_late_returns": rng.poisson(0.7, n),
    "items_on_loan": rng.integers(1, 9, n),
})
laptop = loans.item_type == "laptop"
far = np.clip(loans.distance_km - 8, 0, None)
logit = (~laptop * (-2.6 + 0.8 * loans.past_late_returns + 0.2 * loans.items_on_loan + 0.5 * far
                    + 0.7 * (loans.borrower == "student") - 0.6 * (loans.borrower == "staff")
                    + 0.3 * (loans.item_type == "dvd"))
         + laptop * (-3.0 + 0.45 * loans.distance_km))
loans["late"] = (rng.random(n) < 1 / (1 + np.exp(-logit))).astype(int)
for col in ["item_type", "borrower"]:
    loans[col] = loans[col].astype("category")

X, y = loans.drop(columns="late"), loans.late
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, stratify=y, random_state=0)
print(f"{len(X_train)} training loans, {len(X_test)} sealed test loans, late share {y.mean():.3f}")
print(loans.groupby("item_type", observed=True).late.agg(["size", "mean"]).round(3))
```

## Step 2: Confirm the tie

Both models go into the same `StratifiedKFold`. We keep their out-of-fold probabilities, because every later step reuses them.

```python run
from sklearn.compose import make_column_transformer
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import brier_score_loss, roc_auc_score
from sklearn.model_selection import StratifiedKFold, cross_val_predict
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

categorical = ["item_type", "borrower"]
numeric = ["distance_km", "past_late_returns", "items_on_loan"]
models = {
    "logistic": make_pipeline(
        make_column_transformer((OneHotEncoder(), categorical), (StandardScaler(), numeric)),
        LogisticRegression(class_weight="balanced", max_iter=1000)),
    "boosting": HistGradientBoostingClassifier(learning_rate=0.05, max_iter=300,
                                               max_leaf_nodes=15, random_state=0),
}
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
oof = pd.DataFrame(index=X_train.index)
for name, model in models.items():
    oof[name] = cross_val_predict(model, X_train, y_train, cv=cv, method="predict_proba")[:, 1]
    print(f"{name:>9}: ROC AUC {roc_auc_score(y_train, oof[name]):.3f}")
```

0.718 against 0.728. With 3,750 training loans that gap is about the size of the noise, so on ranking alone this is a tie. If we stopped here we'd pick by coin flip or by habit.

## Step 3: Check whether the probabilities mean what they say

The library plans to use the probabilities directly ("remind anyone above 40%"), so calibration matters.

```python run alt="Reliability diagram: boosting lies close to the diagonal; the balanced logistic regression lies well below it, predicting probabilities that are too high; the recalibrated logistic regression moves back near the diagonal" caption="Out-of-fold reliability diagram on the training set."
import matplotlib.pyplot as plt
from sklearn.calibration import CalibratedClassifierCV, CalibrationDisplay

models["logistic, recalibrated"] = CalibratedClassifierCV(models["logistic"], method="sigmoid", cv=5)
oof["logistic, recalibrated"] = cross_val_predict(models["logistic, recalibrated"], X_train, y_train,
                                                  cv=cv, method="predict_proba")[:, 1]

fig, ax = plt.subplots(figsize=(5, 4.6))
for name, color in zip(oof.columns, ["#2a78d6", "#eb6834", "#1baf7a"]):
    p = oof[name]
    print(f"{name:>23}: mean probability {p.mean():.3f}   Brier {brier_score_loss(y_train, p):.4f}   "
          f"ROC AUC {roc_auc_score(y_train, p):.3f}")
    CalibrationDisplay.from_predictions(y_train, p, n_bins=8, name=name, ax=ax, color=color)
print(f"{'actual late share':>23}: {y_train.mean():.3f}")
```

The balanced logistic regression says the average loan has a 48% chance of being late, when the real share is 38%. That's the price of `class_weight="balanced"` from Module 5: it pushed every score toward the rare class. Under a "remind above 40%" rule it would flag far more loans than intended. Sigmoid recalibration fixes the scale, bringing its Brier score level with boosting's, and leaves its ROC AUC exactly where it was. So calibration doesn't break the tie either; it just removes one reason to reject the logistic model.

## Step 4: Compare what the models rely on

Permutation importance needs a fitted model and rows it didn't see, so we carve a validation set out of the training data.

```python run
from sklearn.inspection import permutation_importance

X_fit, X_val, y_fit, y_val = train_test_split(X_train, y_train, test_size=0.3,
                                              stratify=y_train, random_state=1)
importance = {}
for name in ["logistic", "boosting"]:
    fitted = models[name].fit(X_fit, y_fit)
    result = permutation_importance(fitted, X_val, y_val, scoring="roc_auc",
                                    n_repeats=10, random_state=0)
    importance[name] = result.importances_mean
print(pd.DataFrame(importance, index=X.columns).round(3)
      .sort_values("boosting", ascending=False))
```

Both use the same five features, but boosting leans on `distance_km` and `item_type` noticeably more, and the logistic model barely uses `item_type` at all. Importance can't say *why*. Partial dependence can, especially if we compute it separately for laptops and for everything else.

```python run alt="Two panels showing the predicted chance of a late return against distance. In the logistic panel the laptop and other-item curves rise together with nearly the same shape. In the boosting panel the laptop curve starts lower and climbs steeply between about 5 and 10 km, while books and DVDs stay roughly flat until about 9 km and then rise." caption="Partial dependence on distance, computed separately for laptops and for other items."
from sklearn.inspection import partial_dependence

fig, axes = plt.subplots(1, 2, figsize=(8.5, 3.4), sharey=True)
for ax, name in zip(axes, ["logistic", "boosting"]):
    for label, mask, color in [("laptops", X_val.item_type == "laptop", "#eb6834"),
                               ("books and DVDs", X_val.item_type != "laptop", "#2a78d6")]:
        pdep = partial_dependence(models[name], X_val[mask], ["distance_km"], kind="average",
                                  method="brute", response_method="predict_proba",
                                  grid_resolution=25)
        ax.plot(pdep["grid_values"][0], pdep["average"][0], lw=2, color=color, label=label)
    ax.set_title(name)
    ax.set_xlabel("distance from home (km)")
    ax.grid(alpha=0.3)
axes[0].set_ylabel("average predicted chance of late")
axes[1].legend(frameon=False)
```

Here is the difference. Boosting has learned two separate stories: for books and DVDs, distance barely matters until a long trip (around 9 km here), but for laptops the risk starts low and climbs fast with distance, perhaps because a laptop is awkward to carry back from far away. The boosting curves are jagged because each is an average over only a few hundred validation loans. The logistic model has one coefficient for distance shared by every item type, so its two curves have the same shape, just shifted. It averages the two stories, which is a little wrong for books and very wrong for laptops.

## Step 5: Slice the errors by item type and borrower

If the logistic model misunderstands laptops, its errors should pile up there. We compute ROC AUC per slice from the out-of-fold probabilities, with a bootstrap interval so small slices don't fool us.

```python run
def slice_report(column, models_to_show, n_boot=300, seed=0):
    rng = np.random.default_rng(seed)
    rows = []
    for level, idx in X_train.groupby(column, observed=True).groups.items():
        truth = y_train.loc[idx].to_numpy()
        row = {"slice": f"{column}={level}", "n": len(idx)}
        for name in models_to_show:
            p = oof.loc[idx, name].to_numpy()
            boots = []
            for _ in range(n_boot):
                b = rng.integers(0, len(idx), len(idx))
                if truth[b].min() != truth[b].max():
                    boots.append(roc_auc_score(truth[b], p[b]))
            low, high = np.percentile(boots, [5, 95])
            row[name] = f"{roc_auc_score(truth, p):.3f} ({low:.2f}-{high:.2f})"
        rows.append(row)
    return pd.DataFrame(rows)

show = ["logistic, recalibrated", "boosting"]
print(pd.concat([slice_report("item_type", show), slice_report("borrower", show)])
      .to_string(index=False))
```

For books, DVDs, and every borrower group the two models are within about 0.03 of each other, with overlapping intervals. Laptops are different: boosting ranks them at about 0.79 and the logistic model at about 0.66, and the intervals don't overlap. That is a real failure, invisible in the overall score because laptops are only one loan in ten. If the library ever lends more laptops, the logistic model will get worse while its headline number stays the same.

## Step 6: Decide, then confirm once on the test set

The evidence points to boosting: same overall ranking, probabilities that are already calibrated, and it understands the laptop pattern. Now we fit both finalists on all the training data and score the sealed test set once, overall and on laptops.

```python run
final = {name: models[name].fit(X_train, y_train) for name in show}
test_laptop = X_test.item_type == "laptop"
rows = []
for name, model in final.items():
    p = model.predict_proba(X_test)[:, 1]
    rows.append({"model": name,
                 "ROC AUC": roc_auc_score(y_test, p),
                 "Brier": brier_score_loss(y_test, p),
                 "laptop ROC AUC": roc_auc_score(y_test[test_laptop], p[test_laptop]),
                 "flagged above 0.4": f"{(p > 0.4).mean():.0%}"})
print(pd.DataFrame(rows).round(3).to_string(index=False))
print(f"\ntest loans: {len(y_test)}, of which laptops: {test_laptop.sum()}")
```

The test set agrees with the cross-validated evidence: overall the two are nearly identical, and boosting is still ahead on laptops (about 0.76 against 0.71). With only 121 test laptops that test gap alone would be weak evidence, but it points the same way as the larger cross-validated one. Here is the evidence table, filled in.

| Question | Logistic (balanced) | Boosting |
| --- | --- | --- |
| Ranks loans well overall? | yes, about 0.72 | yes, about 0.73 |
| Probabilities trustworthy? | no, until recalibrated | yes |
| Relies on sensible features? | one distance effect for every item | separate distance effects per item type |
| Works for every item type? | weak on laptops (about 0.66) | yes (about 0.79 on laptops) |

The recommendation writes itself: use boosting, and keep monitoring the laptop slice, because it has the fewest loans and the widest intervals.

:::quiz
Q: After recalibration, the logistic model's Brier score matched boosting's. Why didn't that settle the choice?
- [ ] Because recalibration lowered its ROC AUC
  Sigmoid recalibration is monotonic, so the AUC stayed exactly the same.
- [x] Because calibration fixes the probability scale, but not which loans the model ranks as risky, and its ranking failed on laptops
  Overall Brier and AUC can tie while one slice is badly served; only the slice analysis revealed it.
- [ ] Because Brier score doesn't apply to class-weighted models
  Brier score applies to any probability; it's how we saw the weighted model was off in the first place.

Q: Why did Step 4 compute partial dependence separately for laptops and for other items instead of once for all loans?
- [x] An overall curve would average two different relationships and hide the interaction
  Laptops are 10% of loans, so their steep curve would barely bend the average.
- [ ] `partial_dependence` can't handle categorical columns
  It handles them; splitting the data was a choice to expose an interaction.
- [ ] To make the computation faster
  Computing twice is slower; the point was to see two stories instead of one.

Q: The laptop slice has about 360 loans in training. Why attach bootstrap intervals to its AUC?
- [ ] Bootstrapping makes the AUC more accurate
  It doesn't change the estimate; it shows how much the estimate could move with a different sample.
- [x] To check that the gap between models is bigger than what sampling noise alone could produce
  With a few hundred rows, AUC can move by several hundredths by chance; non-overlapping intervals make the gap believable.
:::

:::takeaways
- A tie on ROC AUC is where evaluation starts, not where it ends.
- Class-weighted models need recalibration before their probabilities can drive a threshold.
- Permutation importance tells you what a model uses; partial dependence per subgroup shows interactions a single curve hides.
- Slice the out-of-fold errors by every group that matters to the people using the model, and attach intervals before declaring a failure.
- Turn the evidence into a short table with a recommendation and a monitoring note.
:::
