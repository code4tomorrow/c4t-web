## Warm-up: count the fits

`cross_validate(GridSearchCV(model, grid, cv=5), X, y, cv=4)`, where `grid` has 3 values of one parameter and 4 of another. How many times is `model` fitted in total?

:::solution
Each search tries 3 × 4 = 12 candidates on 5 inner folds (60 fits), then refits the winner on its whole training part (1 more): 61 fits. The outer loop runs that search 4 times, so **244 fits**. Multiply before you press run: at half a second per fit, that's two minutes, and a 10-value grid would make it twenty.
:::

### Exercise 1: Match the splitter to the data

Write the splitter you'd use for each case, with its key arguments:

1. 5,000 product reviews, one per customer, rating predicted as positive or negative (12% negative).
2. 900 recordings of 30 speakers, classifying the spoken word; the model must work for new speakers.
3. Daily electricity use for two years, predicting tomorrow; features include a 7-day rolling average.
4. 40,000 house sales from one year, predicting price.

:::hint
Ask three questions in order: does time order matter, do rows share a source, and is it classification with uneven classes?
:::

:::solution
```python run
choices = {
    "1 reviews (rare negatives)": StratifiedKFold(n_splits=5, shuffle=True, random_state=0),
    "2 speakers": GroupKFold(n_splits=5),                    # groups=speaker_id; StratifiedGroupKFold if a word is rare
    "3 electricity": TimeSeriesSplit(n_splits=5, gap=7),     # gap covers the 7-day rolling window
    "4 house prices": KFold(n_splits=5, shuffle=True, random_state=0),
}
for case, splitter in choices.items():
    print(f"{case:<28} {splitter}")
```

The `gap=7` in case 3 matters because the rolling average for the first test days is computed from days that are also in training; leaving a week out keeps the two parts apart. In case 4, if the same houses sold more than once, you'd group by house ID; and if the model will price *next* year's sales, a time-based split by sale date would be more honest still.
:::

### Exercise 2: Why are my scores NaN?

The rows below are sorted by label (all negatives first), as happens when data is exported from a database ordered by outcome. Run the cross-validation, explain every `nan`, and fix it.

```python run
X2, y2 = make_classification(n_samples=200, n_features=6, weights=[0.85], random_state=1)
order = np.argsort(y2, kind="stable")
X2, y2 = X2[order], y2[order]

model2 = make_pipeline(StandardScaler(), LogisticRegression())
bad = cross_validate(model2, X2, y2, cv=KFold(5), scoring=["roc_auc", "accuracy"])
print("AUC:     ", bad["test_roc_auc"])
print("accuracy:", bad["test_accuracy"])
```

:::hint
Without shuffling, fold 1 is rows 0 to 39. What labels do those rows have? Now look at the *training* part of fold 5.
:::

:::solution
```python run
good = cross_validate(model2, X2, y2, cv=StratifiedKFold(5, shuffle=True, random_state=0), scoring=["roc_auc", "accuracy"])
print("AUC:     ", good["test_roc_auc"].round(3))
print("accuracy:", good["test_accuracy"].round(3))
```

Folds 1 to 4 contain only negatives, so AUC (which compares positives against negatives) is undefined there, and accuracy just measures how often the model says "negative". Fold 5's *training* part is rows 0 to 159, all negatives, so logistic regression can't even be fitted, and every metric for that fold is `nan`. By default, `cross_validate` records a failure as `nan` (`error_score=np.nan`) instead of stopping, which is why it's easy to miss. Shuffled, stratified folds fix both problems. Set `error_score="raise"` while developing if you'd rather fail loudly.
:::

### Exercise 3: Validate a forecast the way it will be used

Below is a year of daily demand with a drifting level and a weekend bump. Features are yesterday's demand, the demand a week ago, a weekend flag, and the day number. Compare MAE from shuffled `KFold(5)` with `TimeSeriesSplit(n_splits=5, test_size=30, gap=7)`, and print the date range of each time-based split. Which estimate should you report for "predict tomorrow"?

```python run
from sklearn.ensemble import RandomForestRegressor

rng = np.random.default_rng(0)
days = pd.date_range("2024-01-01", periods=365, freq="D")
level = np.cumsum(rng.normal(0, 3, 365)) + np.linspace(100, 160, 365)
demand = pd.DataFrame({"date": days,
                       "demand": level + 15 * (days.dayofweek >= 5) + rng.normal(0, 5, 365)})
demand["lag_1"] = demand["demand"].shift(1)
demand["lag_7"] = demand["demand"].shift(7)
demand["weekend"] = (demand["date"].dt.dayofweek >= 5).astype(int)
demand["day_number"] = np.arange(365)
demand = demand.dropna().reset_index(drop=True)
X3, y3 = demand[["lag_1", "lag_7", "weekend", "day_number"]], demand["demand"]
forest = RandomForestRegressor(n_estimators=50, random_state=0)
```

:::hint
`cross_val_score(..., scoring="neg_mean_absolute_error")` returns negative numbers; flip the sign. For the date ranges, loop over `TimeSeriesSplit(...).split(X3)` and index `demand["date"]` with the train and test positions.
:::

:::solution
```python run
time_cv = TimeSeriesSplit(n_splits=5, test_size=30, gap=7)
for name, cv in [("shuffled KFold", KFold(5, shuffle=True, random_state=0)), ("TimeSeriesSplit", time_cv)]:
    mae = -cross_val_score(forest, X3, y3, cv=cv, scoring="neg_mean_absolute_error").mean()
    print(f"{name:<16} MAE = {mae:.2f}")

for train_idx, test_idx in time_cv.split(X3):
    d = demand["date"]
    print(f"train {d[train_idx].min():%b %d} to {d[train_idx].max():%b %d}  |  test {d[test_idx].min():%b %d} to {d[test_idx].max():%b %d}")
```

Shuffled folds look better because the forest gets to train on the days *on both sides* of each test day and simply interpolates; it never has to deal with the level drifting somewhere new. A forest also can't extrapolate `day_number` beyond what it has seen, a weakness only the time-ordered split exposes. Report the `TimeSeriesSplit` number. The printout confirms each test month starts a week after training ends.
:::

### Exercise 4: Score by what mistakes cost

In a fraud-review queue, a missed fraud (false negative) costs 5 units and a false alarm costs 1. Write a scorer for total cost with `make_scorer`, and cross-validate three models with accuracy, recall, and cost. Does the ranking change with the metric?

```python run
from sklearn.metrics import confusion_matrix, make_scorer
from sklearn.tree import DecisionTreeClassifier

X4, y4 = make_classification(n_samples=600, n_features=8, n_informative=4, weights=[0.88], flip_y=0.02, random_state=4)
candidates4 = {
    "logistic": make_pipeline(StandardScaler(), LogisticRegression()),
    "k-NN": make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=15)),
    "tree": DecisionTreeClassifier(max_depth=4, random_state=0),
}
```

:::hint
Your cost function takes `(y_true, y_pred)`; get the four counts with `confusion_matrix(y_true, y_pred, labels=[0, 1]).ravel()`, which returns `tn, fp, fn, tp`. Lower cost is better, so pass `greater_is_better=False`, and expect scikit-learn to report the cost as a negative number.
:::

:::solution
```python run
def total_cost(y_true, y_pred):
    tn, fp, fn, tp = confusion_matrix(y_true, y_pred, labels=[0, 1]).ravel()
    return 5 * fn + 1 * fp

cost_scorer = make_scorer(total_cost, greater_is_better=False)
scoring = {"accuracy": "accuracy", "recall": "recall", "cost": cost_scorer}
rows = {}
for name, model in candidates4.items():
    r = cross_validate(model, X4, y4, cv=StratifiedKFold(5, shuffle=True, random_state=0), scoring=scoring)
    rows[name] = {"accuracy": r["test_accuracy"].mean(), "recall": r["test_recall"].mean(),
                  "cost per fold": -r["test_cost"].mean()}
print(pd.DataFrame(rows).T.round(3))
```

k-NN has the best accuracy and the worst cost: it rarely flags anything, which is cheap in accuracy terms (most rows are negative) and expensive when misses cost five times more. With `greater_is_better=False`, scikit-learn negates the score so that "higher is better" holds for every scorer; that's why `test_cost` came back negative. Choosing the metric is choosing the winner, so write the metric down before you compare models.
:::

### Exercise 5: Out-of-fold predictions are for looking, not for scoring

Use `cross_val_predict` to get a prediction for every diabetes patient from a model that never saw that patient, and plot predicted against actual. Then compute R² on those pooled predictions and compare it with the mean of the per-fold R² from `cross_val_score` on the same folds. Why do they differ?

:::hint
Use one `KFold(5, shuffle=True, random_state=0)` object for both calls. `from sklearn.metrics import r2_score`.
:::

:::solution
```python run alt="Scatter plot of out-of-fold predicted disease progression against actual values for 442 patients. Points rise along the diagonal but spread widely; predictions are compressed between about 40 and 300 while actual values run from about 25 to 346." caption="Each prediction comes from a model that never saw that patient. The model compresses extremes toward the middle."
from sklearn.metrics import r2_score

X5, y5 = load_diabetes(return_X_y=True)
cv5 = KFold(5, shuffle=True, random_state=0)
ridge = make_pipeline(StandardScaler(), Ridge())

oof = cross_val_predict(ridge, X5, y5, cv=cv5)
print(f"R^2 of pooled out-of-fold predictions: {r2_score(y5, oof):.3f}")
print(f"mean of per-fold R^2:                   {cross_val_score(ridge, X5, y5, cv=cv5, scoring='r2').mean():.3f}")

fig, ax = plt.subplots(figsize=(4.2, 4))
ax.scatter(y5, oof, s=12, alpha=0.5, color="#2a78d6")
ax.plot([25, 346], [25, 346], color="#52514e", linestyle="--", linewidth=1)
ax.set_xlabel("actual progression")
ax.set_ylabel("out-of-fold prediction")
ax.spines[["top", "right"]].set_visible(False)
plt.tight_layout()
plt.show()
```

The two numbers measure different things. Per-fold R² compares each fold's predictions with *that fold's* mean; pooled R² compares all predictions with the overall mean, mixing predictions from five different models. scikit-learn's documentation warns against reporting the pooled number as a generalization score. Out-of-fold predictions shine for plots like this one, for error analysis (which patients are badly predicted?), and as inputs to later steps such as stacking.
:::

### Exercise 6: Is logistic regression really better than k-NN?

On the `make_classification` data from the Notes lesson (`n_samples=300, n_features=10, n_informative=4, n_redundant=2, flip_y=0.08, random_state=5`), score both models from the Notes on the **same** 50 splits from `RepeatedStratifiedKFold(n_splits=5, n_repeats=10, random_state=0)`. Compute the per-split difference, plot its distribution, and count wins, losses, and ties.

:::hint
Pass the same `RepeatedStratifiedKFold` object to both `cross_val_score` calls; because its seed is an integer, both get identical splits, so `scores_a - scores_b` pairs up correctly.
:::

:::solution
```python run alt="Histogram of 50 per-split accuracy differences, logistic regression minus k-NN. Bars run from about minus 0.10 to plus 0.13; the tallest bar sits at zero, for ties, and most of the remaining splits are above zero." caption="Paired differences over 50 splits: logistic regression wins most, but not all, of them."
X6, y6 = make_classification(n_samples=300, n_features=10, n_informative=4, n_redundant=2, flip_y=0.08, random_state=5)
repeated = RepeatedStratifiedKFold(n_splits=5, n_repeats=10, random_state=0)
lr_scores = cross_val_score(make_pipeline(StandardScaler(), LogisticRegression()), X6, y6, cv=repeated)
knn_scores = cross_val_score(make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=15)), X6, y6, cv=repeated)
diff = lr_scores - knn_scores

print(f"mean difference {diff.mean():+.3f}, std {diff.std():.3f}")
print(f"logistic wins {np.sum(diff > 0)}, k-NN wins {np.sum(diff < 0)}, ties {np.sum(diff == 0)}")

fig, ax = plt.subplots(figsize=(6, 2.6))
ax.hist(diff, bins=15, color="#2a78d6", edgecolor="white")
ax.axvline(0, color="#52514e", linewidth=1)
ax.set_xlabel("accuracy difference (logistic minus k-NN)")
ax.set_ylabel("splits")
ax.spines[["top", "right"]].set_visible(False)
plt.tight_layout()
plt.show()
```

Logistic regression wins clearly more often than it loses, and the average edge is a couple of points. Pairing is what makes this visible: each difference cancels out how easy or hard that particular test fold was. One caution before reaching for a t-test: the 50 differences aren't independent (the splits share training rows), so a standard t-test overstates confidence. If you need a p-value, use a test corrected for this, such as the Nadeau–Bengio corrected t-test, or simply report the win rate and the spread.
:::

### Challenge: How optimistic is `best_score_`?

The Notes showed one search whose `best_score_` beat its nested estimate. Is that a fluke? For 6 different small datasets (`make_classification(n_samples=120, n_features=8, n_informative=3, flip_y=0.1, random_state=seed)`), run a `GridSearchCV` over an SVM's `C` in `[0.1, 1, 10]` and `gamma` in `[0.01, 0.1, 1]`, record `best_score_`, then compute the nested estimate with a 5-fold outer loop. Plot one against the other and report the average gap.

:::hint
Use different seeds for the inner and outer splitters. A scatter plot with a diagonal line makes the pattern obvious: points above the line are searches that oversold themselves.
:::

:::solution
```python run alt="Scatter plot of six datasets, nested CV accuracy on the x axis and best_score_ on the y axis, with a dashed diagonal. Four of the six points sit on or above the diagonal, meaning the search's own best score was at least as high as the nested estimate; the largest gap is about 0.1 for the hardest dataset." caption="Points above the diagonal are searches whose best score was optimistic."
from sklearn.svm import SVC

pairs = []
for seed in range(6):
    Xc, yc = make_classification(n_samples=120, n_features=8, n_informative=3, flip_y=0.1, random_state=seed)
    search = GridSearchCV(make_pipeline(StandardScaler(), SVC()),
                          {"svc__C": [0.1, 1, 10], "svc__gamma": [0.01, 0.1, 1]},
                          cv=StratifiedKFold(4, shuffle=True, random_state=seed))
    search.fit(Xc, yc)
    nested = cross_val_score(search, Xc, yc, cv=StratifiedKFold(5, shuffle=True, random_state=seed + 100)).mean()
    pairs.append((nested, search.best_score_))

nested_scores, best_scores = np.array(pairs).T
print(f"average optimism (best_score_ minus nested): {np.mean(best_scores - nested_scores):+.3f}")

fig, ax = plt.subplots(figsize=(4, 4))
ax.scatter(nested_scores, best_scores, color="#eb6834", s=40)
ax.plot([0.55, 1], [0.55, 1], color="#52514e", linestyle="--", linewidth=1)
ax.set_xlabel("nested CV estimate")
ax.set_ylabel("best_score_ from the search")
ax.spines[["top", "right"]].set_visible(False)
plt.tight_layout()
plt.show()
```

On average the search's own best score sits above the nested estimate, as theory predicts: it is the maximum over nine noisy candidates evaluated on the same folds. Individual datasets can land below the line (with 120 rows, every estimate is noisy), which is why one comparison proves little and a repeated experiment like this one tells you more. The bias grows with the number of candidates you try and shrinks with more data.
