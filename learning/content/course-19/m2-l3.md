## Warm-up: count the output columns

Without running anything: a `ColumnTransformer` sends `["age", "income"]` through `StandardScaler` and `["city"]` (four distinct cities in training) through `OneHotEncoder()`. The input has five columns. How many columns come out?

:::solution
Six. Two scaled numbers plus four one-hot columns. The fifth input column isn't listed, and the default `remainder="drop"` throws it away. If that surprised you, Exercise 1 is for you.
:::

### Exercise 1: The column that vanished

A teammate's model ignores `days_since_login`, one of the strongest churn signals, and they can't see why. Print the output feature names of their transformer, explain the problem, then fix it two ways: by listing the column, and by using `remainder`.

```python run
logins = pd.DataFrame({
    "plan": ["basic", "premium", "basic", "standard"],
    "monthly_fee": [7.99, 18.99, 7.99, 12.99],
    "days_since_login": [40, 2, 11, 90],
    "user_id": ["u81", "u12", "u55", "u07"],
})
teammate = ColumnTransformer([
    ("num", StandardScaler(), ["monthly_fee"]),
    ("cat", OneHotEncoder(), ["plan"]),
])
```

Sample output after your fix:

```text
['num__monthly_fee' 'num__days_since_login' 'cat__plan_basic' 'cat__plan_premium' 'cat__plan_standard']
```

:::hint
Call `teammate.fit(logins)` and then `get_feature_names_out()`. For the `remainder` fix, think about what else would pass through, and whether you want it to.
:::

:::solution
```python run
print(teammate.fit(logins).get_feature_names_out())

fixed = ColumnTransformer([
    ("num", StandardScaler(), ["monthly_fee", "days_since_login"]),
    ("cat", OneHotEncoder(), ["plan"]),
])
print(fixed.fit(logins).get_feature_names_out())

passthrough = ColumnTransformer(
    [("num", StandardScaler(), ["monthly_fee"]), ("cat", OneHotEncoder(), ["plan"])],
    remainder="passthrough",
)
print(passthrough.fit(logins).get_feature_names_out())
```

Unlisted columns are dropped by default, so `days_since_login` never reached the model. Listing it is the better fix. `remainder="passthrough"` also lets through `user_id`, an identifier the model should never see (and a text column that would crash `LogisticRegression`). It also leaves `days_since_login` unscaled. Passthrough is useful while exploring; in a final pipeline, list every column you mean to use.
:::

### Exercise 2: New and rare categories

A device-type column has 40 `phone` rows, 30 `tv`, 3 `console`, and 2 `car` in training. Fit two encoders: `OneHotEncoder(handle_unknown="ignore")` and `OneHotEncoder(handle_unknown="infrequent_if_exist", min_frequency=5)`. **Before running**, predict the output for the rows `["console", "watch"]` from each. Then decide which you'd use for a churn model, and why.

:::hint
With `min_frequency=5`, any category seen fewer than 5 times during `fit` joins one shared `infrequent` column. With `"ignore"`, an unseen category becomes a row of zeros.
:::

:::solution
```python run
devices = pd.DataFrame({"device": ["phone"] * 40 + ["tv"] * 30 + ["console"] * 3 + ["car"] * 2})
probe = pd.DataFrame({"device": ["console", "watch"]})

ignore = OneHotEncoder(handle_unknown="ignore", sparse_output=False).fit(devices)
rare = OneHotEncoder(handle_unknown="infrequent_if_exist", min_frequency=5, sparse_output=False).fit(devices)

print(ignore.get_feature_names_out(), "\n", ignore.transform(probe))
print(rare.get_feature_names_out(), "\n", rare.transform(probe))
```

With `"ignore"`, `console` keeps its own column (learned from 3 rows) and `watch` becomes all zeros, which the model reads as "none of the known devices". With the infrequent setting, `console` and `car` share one column, and the unseen `watch` lands there too. For churn, the second is usually better: three rows can't support a reliable coefficient, and "a rare device" is a sensible guess for a device you've never seen.
:::

### Exercise 3: Put the clock on a circle

Login hour runs from 0 to 23. As a plain number, 23:00 and 00:00 look 23 units apart even though they're one hour apart. Write a `FunctionTransformer` that replaces `hour` with `hour_sin` and `hour_cos` (angle = 2π·hour/24). Check that the distance between 23 and 0 is now smaller than between 23 and 12, and plot the 24 encoded points.

:::hint
`np.sin(2 * np.pi * hour / 24)` and the same with `np.cos`. Return a DataFrame from your function so the column names survive, and pass `feature_names_out` a function that returns the new names if you want `get_feature_names_out()` to work.
:::

:::solution
```python run alt="Scatter plot of 24 points arranged evenly on a circle, labelled by hour. Hour 0 sits at the right, 6 at the top, 12 at the left, and 18 at the bottom, with 23 next to 0." caption="Every hour is the same distance from its neighbours, including the step from 23 back to 0."
def cyclical_hour(frame):
    angle = 2 * np.pi * frame["hour"] / 24
    return pd.DataFrame({"hour_sin": np.sin(angle), "hour_cos": np.cos(angle)}, index=frame.index)

clock = FunctionTransformer(cyclical_hour, feature_names_out=lambda transformer, names: ["hour_sin", "hour_cos"])
points = clock.fit_transform(pd.DataFrame({"hour": range(24)}))
print(clock.get_feature_names_out())

def gap(a, b):
    return float(np.linalg.norm(points.iloc[a] - points.iloc[b]))
print(f"23 to 0: {gap(23, 0):.2f}   23 to 12: {gap(23, 12):.2f}")

fig, ax = plt.subplots(figsize=(3.6, 3.6))
ax.scatter(points["hour_cos"], points["hour_sin"], color="#2a78d6")
for hour in (0, 6, 12, 18, 23):
    ax.annotate(str(hour), (points["hour_cos"][hour], points["hour_sin"][hour]),
                textcoords="offset points", xytext=(6, 4))
ax.set_aspect("equal")
ax.set_xlabel("hour_cos")
ax.set_ylabel("hour_sin")
plt.tight_layout()
plt.show()
```

A model now sees 23:00 and 00:00 as neighbours. You need both sine and cosine: sine alone gives 03:00 and 09:00 the same value. This transformer learns nothing, so `FunctionTransformer` is the right tool.
:::

### Exercise 4: A transformer that learns its limits

Write `QuantileClipper(lower=0.01, upper=0.99)`. `fit` stores each column's lower and upper quantile from the training data in `bounds_`; `transform` clips values to those bounds. It must work inside a pipeline (inherit from the right classes, keep `__init__` simple), and calling `transform` before `fit` should raise scikit-learn's `NotFittedError`. Test it on a column with one huge outlier, then transform a *new* batch and confirm it uses the training bounds.

:::hint
`X.quantile([self.lower, self.upper])` on a DataFrame gives both bounds for every column at once. `DataFrame.clip(lower=..., upper=..., axis=1)` clips each column to its own bounds. `from sklearn.utils.validation import check_is_fitted` and call `check_is_fitted(self)` at the top of `transform`.
:::

:::solution
```python run
from sklearn.utils.validation import check_is_fitted

class QuantileClipper(TransformerMixin, BaseEstimator):
    def __init__(self, lower=0.01, upper=0.99):
        self.lower = lower
        self.upper = upper

    def fit(self, X, y=None):
        self.bounds_ = X.quantile([self.lower, self.upper])
        return self

    def transform(self, X):
        check_is_fitted(self)
        return X.clip(lower=self.bounds_.iloc[0], upper=self.bounds_.iloc[1], axis=1)

train = pd.DataFrame({"watch_hours": list(range(1, 100)) + [5000]})
clipper = QuantileClipper(lower=0.05, upper=0.95).fit(train)
print(clipper.bounds_)
print(clipper.transform(pd.DataFrame({"watch_hours": [0, 50, 9999]})))

try:
    QuantileClipper().transform(train)
except Exception as error:
    print(type(error).__name__)
```

`check_is_fitted` looks for attributes ending in `_`, which is one more reason to follow the naming rule. The new batch's 9999 is clipped to the *training* upper bound, so the outlier in tomorrow's data can't shift the limits.
:::

### Exercise 5: The imputer that peeked

A lab-results dataset has its two most useful measurements missing in about half the rows. Someone fills the blanks with `KNNImputer` **on a table that still includes the outcome column**, then cross-validates. Run their code, then write the honest version with the imputer inside the pipeline and without the outcome. How big is the gap, and why does it happen?

```python run
from sklearn.datasets import make_classification
from sklearn.impute import KNNImputer

X_lab, y_lab = make_classification(n_samples=600, n_features=6, n_informative=3, n_redundant=0,
                                   flip_y=0.15, class_sep=0.6, shuffle=False, random_state=3)
X_lab = pd.DataFrame(X_lab, columns=[f"lab_{i}" for i in range(6)])
blanks = np.random.default_rng(0)
X_lab.loc[blanks.random(600) < 0.5, "lab_0"] = np.nan
X_lab.loc[blanks.random(600) < 0.5, "lab_1"] = np.nan
cv5 = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)

with_outcome = X_lab.assign(outcome=y_lab)
filled = pd.DataFrame(KNNImputer(n_neighbors=5).fit_transform(with_outcome),
                      columns=with_outcome.columns).drop(columns="outcome")
leaky = cross_val_score(make_pipeline(StandardScaler(), LogisticRegression()), filled, y_lab, cv=cv5, scoring="roc_auc")
print(f"their AUC: {leaky.mean():.3f}")
```

:::hint
`KNNImputer` fills a blank by averaging the nearest rows. Ask yourself which column makes two rows look "near" when the outcome is part of the distance.
:::

:::solution
```python run
honest = cross_val_score(make_pipeline(KNNImputer(n_neighbors=5), StandardScaler(), LogisticRegression()),
                         X_lab, y_lab, cv=cv5, scoring="roc_auc")
print(f"leaky AUC: {leaky.mean():.3f}   honest AUC: {honest.mean():.3f}   gap: {leaky.mean() - honest.mean():.3f}")
```

With the outcome in the table, each blank is filled from neighbours that mostly share the row's own label, so the filled-in values quietly encode the answer. Two mistakes stack: the label was an imputation input, and the imputer saw validation rows. At prediction time there is no label to use, so the leaky score can never be reached in practice. Inside the pipeline, the imputer only sees features, and only from each fold's training part.
:::

### Exercise 6: A skewed target

Monthly spend is positive and right-skewed: most customers spend $10–$35, and a few spend over $100. Compare a scaled `Ridge` fitted on raw spend with the same model wrapped in `TransformedTargetRegressor(func=np.log1p, inverse_func=np.expm1)`. Report mean and median absolute error from 5-fold CV. Which errors improve more, and why?

```python run
gen = np.random.default_rng(1)
visits = gen.poisson(6, 800)
premium = gen.integers(0, 2, 800)
tenure = gen.uniform(0, 36, 800)
spend = np.exp(1.5 + 0.12 * visits + 0.6 * premium + 0.03 * tenure + gen.normal(0, 0.5, 800))
X_spend = pd.DataFrame({"visits": visits, "premium": premium, "tenure_months": tenure})
print(pd.Series(spend).describe().round(1).to_dict())
```

:::hint
`from sklearn.compose import TransformedTargetRegressor`. Pass `scoring=["neg_mean_absolute_error", "neg_median_absolute_error"]` to `cross_validate` and flip the signs.
:::

:::solution
```python run
from sklearn.compose import TransformedTargetRegressor
from sklearn.linear_model import Ridge

models = {
    "raw target": make_pipeline(StandardScaler(), Ridge()),
    "log target": TransformedTargetRegressor(regressor=make_pipeline(StandardScaler(), Ridge()),
                                             func=np.log1p, inverse_func=np.expm1),
}
for name, model in models.items():
    result = cross_validate(model, X_spend, spend, cv=KFold(5, shuffle=True, random_state=0),
                            scoring=["neg_mean_absolute_error", "neg_median_absolute_error"])
    print(f"{name}: MAE {-result['test_neg_mean_absolute_error'].mean():.2f}, "
          f"median AE {-result['test_neg_median_absolute_error'].mean():.2f}")
```

Spend grows *multiplicatively* with visits and plan here, so a straight line fits the log of spend far better than spend itself. The median error, which describes the typical customer, improves most; the raw model was bending itself toward the few huge spenders. The wrapper also handles the round trip: you call `predict` and get dollars back, and cross-validation scores in dollars too.
:::

### Challenge: a pipeline that adapts to any table

Write a preprocessing transformer that works on **any** DataFrame without listing column names: numbers get median imputation and scaling, text columns get one-hot encoding with an infrequent bucket. Add a custom `MissingCount` step that appends one column, `n_missing`, counting blanks per row, and give it a `get_feature_names_out` so `.set_output(transform="pandas")` works. Run it unchanged on two tables: the `logins` frame from Exercise 1 (with a blank added) and `X_spend` from Exercise 6.

:::hint
`from sklearn.compose import make_column_selector` and use `make_column_selector(dtype_include="number")` and `make_column_selector(dtype_include=object)` in place of column lists. Put `MissingCount` *before* the `ColumnTransformer` so it counts the original blanks, and let the numeric selector pick up `n_missing` automatically. `get_feature_names_out(self, input_features=None)` should return the input names plus `"n_missing"`; store the input names in `fit` as `self.feature_names_in_ = np.asarray(X.columns)`.
:::

:::solution
```python run
from sklearn.compose import make_column_selector

class MissingCount(TransformerMixin, BaseEstimator):
    def fit(self, X, y=None):
        self.feature_names_in_ = np.asarray(X.columns, dtype=object)
        return self

    def transform(self, X):
        return X.assign(n_missing=X.isna().sum(axis=1))

    def get_feature_names_out(self, input_features=None):
        return np.append(self.feature_names_in_, "n_missing")

def any_table_prep():
    return make_pipeline(
        MissingCount(),
        ColumnTransformer([
            ("num", make_pipeline(SimpleImputer(strategy="median"), StandardScaler()),
             make_column_selector(dtype_include="number")),
            ("cat", OneHotEncoder(handle_unknown="infrequent_if_exist", min_frequency=2, sparse_output=False),
             make_column_selector(dtype_include=object)),
        ]),
    ).set_output(transform="pandas")

messy = logins.drop(columns="user_id").assign(monthly_fee=[7.99, np.nan, 7.99, 12.99])
print(any_table_prep().fit_transform(messy).round(2).to_string())
print(any_table_prep().fit_transform(X_spend).columns.tolist())
```

The selectors are evaluated at `fit` time, so the same recipe adapts to each table's columns. (In the four-row table, `premium` and `standard` appear once each, so `min_frequency=2` merges them into the infrequent column; with real data you'd pick a larger threshold.) Notice that `n_missing` is created before the column selection, so the numeric selector picks it up and scales it like any other number. Selecting by dtype has one risk: an ID stored as text gets one-hot encoded, so drop identifiers before the pipeline, as done with `user_id` here.
