A subscription company's churn model scores ROC AUC 0.99 in cross-validation. Its most important feature is `days_since_last_login`. Then someone notices that the column was computed on the day the data was exported, weeks after the customers in the table had already cancelled, and of course people who cancelled stopped logging in. The model hasn't learned to predict churn. It has learned to read the answer from a column that was written after the fact.

Random forests and gradient boosting are the two strongest general-purpose models for tables, and they are also the two that find a leaked column fastest. This module compares them properly, then teaches you to spot the leak before it wins the comparison for you.

## Two ways to build a team of trees

A single deep decision tree fits its training data closely, so a slightly different training set gives a noticeably different tree. That sensitivity is **variance**. A shallow tree is stable but too simple to follow the real pattern. That systematic miss is **bias**. The two big ensembles attack different halves of the problem.

-   **Bagging (random forests)** trains hundreds of deep trees, each on a bootstrap sample of the rows and with a random subset of features at each split, then averages them. Averaging many noisy but different trees cancels much of their variance while keeping their low bias.
-   **Boosting** trains shallow trees one after another, each fitted to the errors the ensemble is still making. Every round chips away at the bias. Because the trees stay small, variance grows slowly, but it does grow if you keep adding rounds.

The experiment below draws 25 different training sets of 60 noisy points from the same curve, fits each model to every set, and plots all 25 fitted lines. Spread between the lines is variance; distance between their average and the true curve is bias.

```python run alt="Four panels in a 2 by 2 grid, 25 fitted curves each. The depth-2 tree gives blocky step functions that miss the wave. The deep tree's curves are jagged and spread widely. The random forest's curves are smoother and tighter. Boosting's curves are smooth and close to the true curve." caption="Each thin line is one model trained on a different sample. The black line is the truth."
import matplotlib.pyplot as plt
import numpy as np
from sklearn.ensemble import GradientBoostingRegressor, RandomForestRegressor
from sklearn.tree import DecisionTreeRegressor

def truth(x):
    return np.sin(x) + 0.3 * x

rng = np.random.default_rng(0)
grid = np.linspace(0, 10, 200).reshape(-1, 1)
makers = {
    "shallow tree (depth 2)": lambda: DecisionTreeRegressor(max_depth=2),
    "deep tree": lambda: DecisionTreeRegressor(),
    "random forest": lambda: RandomForestRegressor(n_estimators=50, random_state=0),
    "boosting (depth-2 trees)": lambda: GradientBoostingRegressor(max_depth=2, n_estimators=100),
}
curves = {name: [] for name in makers}
for _ in range(25):
    x = rng.uniform(0, 10, 60)
    y = truth(x) + rng.normal(0, 0.5, 60)
    for name, make in makers.items():
        curves[name].append(make().fit(x.reshape(-1, 1), y).predict(grid))

fig, axes = plt.subplots(2, 2, figsize=(8, 5.2), sharex=True, sharey=True)
for ax, (name, preds) in zip(axes.ravel(), curves.items()):
    preds = np.array(preds)
    for p in preds:
        ax.plot(grid, p, color="#2a78d6", lw=0.6, alpha=0.35)
    ax.plot(grid, truth(grid), color="black", lw=2)
    ax.set_title(name, fontsize=10)
    bias2 = np.mean((preds.mean(axis=0) - truth(grid.ravel())) ** 2)
    print(f"{name:>25}: bias² {bias2:.3f}   variance {preds.var(axis=0).mean():.3f}")
```

The deep tree has almost no bias and by far the most variance. The forest keeps the deep tree's low bias and halves its variance just by averaging. Boosting is built from the same depth-2 trees as the first panel, yet adding 100 of them in sequence cuts that panel's bias by more than ten times while adding very little variance.

## Boosting, one correction at a time

Here is gradient boosting for squared error with nothing hidden. Start by predicting the mean. Each round, compute the residuals (truth minus prediction), fit a one-split tree to them, and move every prediction a fraction of the way (the **learning rate**) toward that tree's output. A real booster searches for the best split each round; here the splits are given so the trace stays short.

:::trace Watch the residuals shrink round by round
```python
x = [1, 2, 3, 4, 5]
y = [3, 4, 8, 9, 11]
pred = [7.0, 7.0, 7.0, 7.0, 7.0]   # round 0: predict the mean
rate = 0.5
for split in [3, 4, 2]:            # each round adds a one-split tree
    resid = [round(a - b, 2) for a, b in zip(y, pred)]
    print("residuals:", resid)
    left = [r for xi, r in zip(x, resid) if xi < split]
    right = [r for xi, r in zip(x, resid) if xi >= split]
    lmean = sum(left) / len(left)
    rmean = sum(right) / len(right)
    for i in range(5):
        step = lmean if x[i] < split else rmean
        pred[i] = round(pred[i] + rate * step, 2)
print("final:", pred)
```
:::

The biggest residual goes from 4.0 to 1.91 in three rounds. With a learning rate of 0.5 each tree only takes half a step, so the ensemble needs more rounds but is less likely to chase noise. That trade (smaller rate, more rounds) is the main dial on any booster.

scikit-learn's `HistGradientBoostingClassifier` and `HistGradientBoostingRegressor` first sort each feature's values into at most 255 bins, which makes split search fast on large tables. They also handle missing values without imputation and can treat pandas `category` columns as categories directly. Because extra rounds can eventually overfit, they offer **early stopping**: hold out a slice of the training data, track the loss on it, and stop when it hasn't improved for `n_iter_no_change` rounds. It switches on by itself above 10,000 rows; on smaller data, set `early_stopping=True`.

```python run alt="Training loss falls steadily over 36 boosting rounds while validation loss bottoms out around round 16 and then drifts up slightly; a dotted line marks round 16" caption="Training loss keeps falling; the held-out loss tells you when to stop."
from sklearn.datasets import make_classification
from sklearn.ensemble import HistGradientBoostingClassifier

X, y = make_classification(n_samples=4000, n_features=20, n_informative=8,
                           flip_y=0.05, random_state=0)
hgb = HistGradientBoostingClassifier(max_iter=500, learning_rate=0.3, early_stopping=True,
                                     validation_fraction=0.2, n_iter_no_change=20,
                                     random_state=0).fit(X, y)
best = int(np.argmax(hgb.validation_score_))
print(f"stopped after {hgb.n_iter_} rounds; held-out loss was lowest at round {best}")

fig, ax = plt.subplots(figsize=(6, 3))
ax.plot(-hgb.train_score_, lw=2, color="#2a78d6", label="training loss")
ax.plot(-hgb.validation_score_, lw=2, color="#eb6834", label="held-out loss")
ax.axvline(best, ls=":", color="#52514e")
ax.set_xlabel("boosting round")
ax.set_ylabel("log loss")
ax.legend(frameon=False)
ax.grid(alpha=0.3)
```

The scores are stored as negative losses (higher is better), which is why the code flips their sign. With a high learning rate of 0.3 the held-out loss stops improving after about 16 rounds; the model ran 20 more to be sure, then stopped. Without early stopping it would have run all 500.

| | Random forest | Histogram gradient boosting |
| --- | --- | --- |
| Trees | deep, independent, averaged | shallow, sequential, summed |
| Mainly reduces | variance | bias |
| More trees | never hurts accuracy, only time | can overfit; use early stopping |
| Key knobs | `max_features`, `min_samples_leaf` | `learning_rate`, `max_iter`, `max_leaf_nodes` |
| Large tables | slower | fast, thanks to binning |
| Missing values, categories | missing values yes; categories need encoding | both handled natively |

## The serial-number trap in feature importance

Tree ensembles offer a tempting shortcut, `feature_importances_`, which adds up how much each feature reduced impurity across all splits. It has two flaws: it is computed on the *training* data, and features with many distinct values offer many more split points to overfit with. To see this, take a machine-fault dataset with three real sensors, one real yes/no feature (`night_shift`), and two columns of pure noise: a unique `serial_number` and a `coin_flip`.

```python run
import pandas as pd
from sklearn.ensemble import RandomForestClassifier
from sklearn.inspection import permutation_importance
from sklearn.model_selection import train_test_split

rng = np.random.default_rng(0)
n = 1500
parts = pd.DataFrame({
    "temperature": rng.normal(0, 1, n),
    "pressure": rng.normal(0, 1, n),
    "vibration": rng.normal(0, 1, n),
    "night_shift": rng.integers(0, 2, n),
})
logit = (1.2 * parts.temperature + 0.8 * parts.pressure * parts.vibration
         + 1.5 * parts.night_shift - 0.7)
fault = (rng.random(n) < 1 / (1 + np.exp(-logit))).astype(int)
parts["serial_number"] = rng.permutation(n).astype(float)   # unique, meaningless
parts["coin_flip"] = rng.integers(0, 2, n)                    # meaningless

X_train, X_test, y_train, y_test = train_test_split(
    parts, fault, test_size=0.3, stratify=fault, random_state=0)
forest = RandomForestClassifier(n_estimators=200, random_state=0).fit(X_train, y_train)
perm = permutation_importance(forest, X_test, y_test, scoring="roc_auc",
                              n_repeats=10, random_state=0)
print(pd.DataFrame({"impurity (train)": forest.feature_importances_,
                    "permutation (test)": perm.importances_mean,
                    "± std": perm.importances_std}, index=parts.columns)
      .round(3).sort_values("impurity (train)", ascending=False))
```

Impurity importance puts `serial_number` fourth, about twice as important as `night_shift`, which genuinely drives faults. **Permutation importance** asks a better question: if I shuffle this column in the *test* set, breaking its link with the target, how much does the test score drop? Shuffling the serial number changes nothing (−0.001, well inside its own standard deviation), while shuffling `night_shift` costs 0.11 of AUC, making it the second most useful feature. `HistGradientBoosting` models don't even offer `feature_importances_`, so permutation importance is the tool for both families. Module 7 looks at its own pitfall, correlated features.

## Leakage comes in two flavours

**Target leakage** means a feature carries information that won't exist when the model is used, usually because it was recorded after, or because of, the outcome. The churn column in the opening story is one. So is "antibiotics prescribed" when predicting infection, or "final invoice amount" when predicting whether an order ships. No validation scheme catches it, because the leak is real in every row; only asking "when is this value known?" does.

**Train-test contamination** means information from the evaluation rows reaches training. Fitting a scaler or feature selector on all rows before cross-validation is the version pipelines prevent. The sneakier version is the same *entity* (a patient, a customer, a machine) appearing in several rows that land on both sides of a split. The model learns to recognize the entity rather than the pattern. Here are 120 people with 8 recordings each, where the label belongs to the person:

```python run
from sklearn.model_selection import StratifiedGroupKFold, StratifiedKFold, cross_val_score

rng = np.random.default_rng(1)
people, per_person = 120, 8
label = rng.integers(0, 2, people)
fingerprint = rng.normal(0, 1, (people, 12))         # what makes each person unique
X = np.repeat(fingerprint, per_person, axis=0) + rng.normal(0, 0.35, (people * per_person, 12))
X[:, :2] += 0.5 * np.repeat(label, per_person)[:, None]   # the real, weak signal
y = np.repeat(label, per_person)
person = np.repeat(np.arange(people), per_person)

model = RandomForestClassifier(n_estimators=100, random_state=0)
rows_split = cross_val_score(model, X, y, scoring="roc_auc",
                             cv=StratifiedKFold(5, shuffle=True, random_state=0))
people_split = cross_val_score(model, X, y, scoring="roc_auc", groups=person,
                               cv=StratifiedGroupKFold(5, shuffle=True, random_state=0))
print(f"rows shuffled into folds:    ROC AUC {rows_split.mean():.3f}")
print(f"whole people kept together:  ROC AUC {people_split.mean():.3f}")
```

Splitting by row gives 0.98; keeping each person's recordings in one fold gives about 0.60, which is what the model will really do for a new person. That is a bigger swing than any difference between model families you'll see in this module. The fixes are the splitters from Module 3: `StratifiedGroupKFold` for repeated entities, and `TimeSeriesSplit` for time-ordered data, where shuffling lets the model train on the future to predict the past. The flexible models in this module are the ones best at exploiting the leak, so the split matters even more here.

:::warning
**Classic mistakes with tree ensembles**

1.  **Reading `feature_importances_` as truth.** It is measured on training data and favours many-valued columns. Use `permutation_importance` on held-out data.
2.  **Comparing a tuned booster with a default forest.** Give both families a comparable tuning budget on the same folds, or the comparison says more about effort than about models.
3.  **Celebrating a near-perfect score.** An AUC of 0.99 on a messy real-world problem is more often a leak than a breakthrough. Check the top feature and ask when its value becomes known.
4.  **Splitting rows when the data has repeated entities.** If one customer or patient can appear twice, split by group.
:::

:::quiz
Q: Your random forest overfits less as you add trees, but your gradient boosting model starts to get worse after 300 rounds. Why the difference?
- [ ] The forest's trees are shallower
  It's the other way around: forest trees are usually deep, and boosting trees are shallow.
- [x] Forest trees are averaged independently, so adding more only reduces variance; boosting keeps fitting the remaining errors, which eventually means fitting noise
  That's why boosters need early stopping or a tuned `max_iter`, while a forest just needs "enough" trees.
- [ ] Boosting can't handle more than 255 rounds because of binning
  The 255 limit is on the number of bins per feature, not on the number of rounds.

Q: A random forest's `feature_importances_` ranks `customer_id` third. What should you do first?
- [ ] Keep it, because the model found it useful
  The forest used it to memorize training rows; that rarely transfers to new customers.
- [x] Check permutation importance on held-out data, and suspect overfitting or leakage
  If shuffling the column on test rows doesn't hurt, its impurity importance came from memorization.
- [ ] Switch to `HistGradientBoostingClassifier`, which has no `feature_importances_`
  Hiding the symptom doesn't remove the problem.

Q: Which of these is target leakage rather than train-test contamination?
- [ ] Fitting `StandardScaler` on the whole dataset before cross-validation
  That lets validation rows influence training: contamination, and a pipeline fixes it.
- [x] Predicting loan default using "number of collection calls received"
  Collection calls happen because of default, so the value isn't available when the loan decision is made.
- [ ] The same patient's X-rays appearing in both training and test folds
  That's contamination through a shared entity; group splitting fixes it.
:::

:::takeaways
- Random forests average deep trees to cut variance; boosting adds shallow trees in sequence to cut bias.
- Boosting's learning rate and number of rounds trade against each other; early stopping picks the number of rounds from held-out data.
- Impurity-based importances are biased toward many-valued features and measured on training data. Use permutation importance on held-out data.
- Target leakage is a feature that knows the future; contamination is evaluation rows reaching training. Ask "when is this value known?" for the first, and split by group or time for the second.
:::
