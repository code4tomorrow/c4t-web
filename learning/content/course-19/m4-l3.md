## Warm-up: count a grid with alternatives

`param_grid` can be a **list** of dictionaries; the search tries each dictionary's combinations and adds them up. How many candidates does this have, and how many fits with `cv=5`?

```python
[{"model__C": [0.01, 0.1, 1, 10], "model__penalty": ["l1", "l2"]},
 {"model__n_neighbors": [5, 15, 45]}]
```

:::solution
4 × 2 = 8 from the first dictionary plus 3 from the second: **11 candidates**, so 55 fits plus 1 refit. Lists add; values inside one dictionary multiply. (As written, the second dictionary would fail, since `n_neighbors` isn't a logistic regression setting. Exercise 1 shows how to swap the model itself.)
:::

### Exercise 1: Search over model families, not just settings

Build `Pipeline([("scale", StandardScaler()), ("model", LogisticRegression())])` and one `GridSearchCV` that compares three families, each with its own settings: logistic regression with `C` in `[0.01, 0.1, 1, 10]`, k-NN with `n_neighbors` in `[5, 15, 45]`, and a decision tree with `max_depth` in `[3, 5, 8]` and the scaler turned off. Print the candidate count, the best candidate, and the best score for each family.

:::hint
A whole step can be a searched value: `{"model": [KNeighborsClassifier()], "model__n_neighbors": [...]}`. Setting `"scale": ["passthrough"]` turns the scaler off for that dictionary. To get each family's best, group `cv_results_` by the type of `param_model`.
:::

:::solution
```python run
pipe = Pipeline([("scale", StandardScaler()), ("model", LogisticRegression())])
families = [
    {"model": [LogisticRegression(max_iter=1000)], "model__C": [0.01, 0.1, 1, 10]},
    {"model": [KNeighborsClassifier()], "model__n_neighbors": [5, 15, 45]},
    {"model": [DecisionTreeClassifier(random_state=0)], "model__max_depth": [3, 5, 8], "scale": ["passthrough"]},
]
print("candidates:", len(ParameterGrid(families)))
family_search = GridSearchCV(pipe, families, cv=cv, scoring="roc_auc").fit(X, y)
print("best:", family_search.best_params_)

table = pd.DataFrame(family_search.cv_results_)
table["family"] = table["param_model"].map(lambda model: type(model).__name__)
print(table.groupby("family")["mean_test_score"].max().round(3).sort_values(ascending=False))
```

Ten candidates, one consistent set of folds, one table. Because every family is scored on the same folds, the comparison is fair, and the search refits the overall winner automatically. Turning the scaler off for the tree is tidy rather than necessary, since trees ignore scale.
:::

### Exercise 2: What do these distributions really produce?

Before running anything, predict: (a) can `randint(2, 64)` ever produce 64? (b) what range does `uniform(0.1, 0.9)` cover? (c) roughly what share of `loguniform(1e-4, 1e2)` draws fall below 1? Then check all three with 10,000 draws each.

:::hint
scipy's `randint(low, high)` follows Python's `range`. scipy's `uniform(loc, scale)` covers `[loc, loc + scale]`. A log-uniform distribution gives every factor of ten the same share.
:::

:::solution
```python run
ints = randint(2, 64).rvs(10_000, random_state=0)
fracs = uniform(0.1, 0.9).rvs(10_000, random_state=0)
logs = loguniform(1e-4, 1e2).rvs(10_000, random_state=0)
print(f"randint(2, 64):        min {ints.min()}, max {ints.max()}")
print(f"uniform(0.1, 0.9):     min {fracs.min():.3f}, max {fracs.max():.3f}")
print(f"loguniform(1e-4, 1e2): share below 1 = {np.mean(logs < 1):.1%}")
```

(a) No: the upper bound is excluded, so the largest value is 63. Write `randint(2, 65)` if you mean 64. (b) 0.1 to **1.0**, not 0.1 to 0.9: the second argument is the width. This is the most common distribution bug in tuning code. (c) Four of the six decades lie below 1, so about 67%.
:::

### Exercise 3: Prefer the simplest model that ties with the best

Grid-search a decision tree's `max_depth` over 1 to 14, scored by accuracy. Instead of keeping the top scorer, keep the **shallowest** tree whose mean score is within one standard error of the best (the one-standard-error rule). Write it as a function and pass it as `refit=`. Compare the depth it picks with the raw best depth, and plot the mean score with error bars.

:::hint
A callable `refit` receives `cv_results_` and must return an index. Standard error = `std_test_score / sqrt(n_splits)`. Find the best mean, compute its threshold, then choose the smallest depth whose mean clears it.
:::

:::solution
```python run alt="Line chart with error bars of mean cross-validated accuracy against tree depth from 1 to 14. Accuracy rises steeply up to a depth of about 5, peaks at 7, then declines slightly for deeper trees. A dashed line marks the one-standard-error threshold below the best score, and an orange marker shows the shallower depth, 5, that the rule selects." caption="Deeper trees past the peak overfit. The one-standard-error rule picks a simpler tree whose score is statistically tied with the best."
def simplest_within_one_se(results):
    means = results["mean_test_score"]
    se = results["std_test_score"] / np.sqrt(cv.get_n_splits())
    best = np.argmax(means)
    tied = np.flatnonzero(means >= means[best] - se[best])
    depths = np.array(results["param_max_depth"], dtype=int)
    return int(tied[np.argmin(depths[tied])])

depths = list(range(1, 15))
depth_search = GridSearchCV(DecisionTreeClassifier(random_state=0), {"max_depth": depths}, cv=cv,
                            scoring="accuracy", refit=simplest_within_one_se).fit(X, y)
res = depth_search.cv_results_
raw_best = depths[int(np.argmax(res["mean_test_score"]))]
print("highest mean at depth", raw_best, "| one-SE rule picks depth", depth_search.best_params_["max_depth"])

se = res["std_test_score"] / np.sqrt(5)
fig, ax = plt.subplots(figsize=(6.5, 2.8))
ax.errorbar(depths, res["mean_test_score"], yerr=se, color="#2a78d6", marker="o", capsize=3)
ax.axhline(res["mean_test_score"].max() - se[np.argmax(res["mean_test_score"])], color="#52514e", linestyle="--", linewidth=1)
chosen = depth_search.best_params_["max_depth"]
ax.scatter([chosen], [res["mean_test_score"][chosen - 1]], color="#eb6834", s=90, zorder=3)
ax.set_xlabel("max_depth")
ax.set_ylabel("mean CV accuracy")
ax.spines[["top", "right"]].set_visible(False)
plt.tight_layout()
plt.show()
```

When several settings tie within noise, the simpler one is the safer bet: it has fewer ways to have fit quirks of these particular folds. Note that with a callable `refit`, the search has no `best_score_`; read the chosen candidate's score from `cv_results_` instead.
:::

### Exercise 4: Learning rate versus number of trees

With early stopping on and `max_iter=1000`, fit `HistGradientBoostingClassifier` with learning rates 0.03, 0.1, 0.3, and 1.0 on a 75/25 split. For each, record `n_iter_`, fit time, and held-out AUC, and plot the validation loss curves on one chart. What trade-off do you see?

:::hint
`model.validation_score_` holds negative log loss per iteration; plot its negative. Time each fit with `time.perf_counter()`. Score with `roc_auc_score(y_hold, model.predict_proba(X_hold)[:, 1])`.
:::

:::solution
```python run alt="Line chart of validation log loss against iteration for four learning rates. The 1.0 curve plunges within a few iterations, then climbs sharply and stops at 17. The 0.3 and 0.1 curves reach losses near 0.2 within 40 to 75 iterations. The 0.03 curve descends slowly over 200 iterations to a similar low loss." caption="Smaller learning rates need many more trees to reach the same loss; the largest one stops early at a worse loss."
from sklearn.metrics import roc_auc_score

X_fit, X_hold, y_fit, y_hold = train_test_split(X, y, test_size=0.25, stratify=y, random_state=0)
fig, ax = plt.subplots(figsize=(7, 2.8))
for rate, color in zip([0.03, 0.1, 0.3, 1.0], ["#2a78d6", "#3fa66b", "#eb6834", "#8a3ffc"]):
    start = time.perf_counter()
    model = HistGradientBoostingClassifier(learning_rate=rate, max_iter=1000, early_stopping=True,
                                           random_state=0).fit(X_fit, y_fit)
    seconds = time.perf_counter() - start
    auc = roc_auc_score(y_hold, model.predict_proba(X_hold)[:, 1])
    print(f"learning_rate {rate:<5} iterations {model.n_iter_:>4}   fit {seconds:.2f} s   held-out AUC {auc:.3f}")
    ax.plot(-model.validation_score_, color=color, label=f"lr {rate}")
ax.set_xlabel("iteration")
ax.set_ylabel("validation log loss")
ax.legend(frameon=False, fontsize=8)
ax.spines[["top", "right"]].set_visible(False)
plt.tight_layout()
plt.show()
```

Smaller learning rates take smaller steps, so they need many more trees and more time, and they usually end up as good or slightly better. Very large rates overshoot and stop early at a worse loss. In practice: pick a moderate rate (0.05 to 0.2), let early stopping set the length, and only shrink the rate if you have time to spare.
:::

### Exercise 5: Predict the halving rounds

A `HalvingRandomSearchCV` gets `n_candidates=40`, `factor=2`, `min_resources=100`, on 1,600 rows. **Write down** how many rounds it will run, and how many candidates and rows each round uses. Then run it with a cheap decision tree and compare with `n_candidates_` and `n_resources_`.

:::hint
Rows multiply by `factor` each round until they would pass 1,600. Candidates are divided by `factor` each round, rounded up.
:::

:::solution
```python run
from sklearn.experimental import enable_halving_search_cv  # noqa: F401
from sklearn.model_selection import HalvingRandomSearchCV

X_big, y_big = make_classification(n_samples=1600, n_features=15, n_informative=5, flip_y=0.12, random_state=8)
halving = HalvingRandomSearchCV(
    DecisionTreeClassifier(random_state=0),
    {"max_depth": randint(2, 16), "min_samples_leaf": [1, 2, 5, 10, 20, 50], "ccp_alpha": loguniform(1e-5, 1e-1)},
    n_candidates=40, factor=2, min_resources=100, cv=cv, random_state=0,
).fit(X_big, y_big)
print("rounds:    ", halving.n_iterations_)
print("candidates:", halving.n_candidates_)
print("rows:      ", halving.n_resources_)
```

Rows double from 100 to 1,600 (100, 200, 400, 800, 1,600): five rounds. Candidates halve, rounding up: 40, 20, 10, 5, 3. The final round compares three finalists on all the data. A smaller `factor` means more, gentler rounds; a larger one eliminates aggressively.
:::

### Exercise 6: The winner on the edge

A teammate grid-searches k-NN's `n_neighbors` over 1 to 9 and reports "best k = 9". Rerun their search, notice the problem, then draw a validation curve over a much wider range (1 to 200, log-spaced) and report a better k.

```python run
knn_pipe = Pipeline([("scale", StandardScaler()), ("knn", KNeighborsClassifier())])
narrow = GridSearchCV(knn_pipe, {"knn__n_neighbors": list(range(1, 10))}, cv=cv, scoring="roc_auc").fit(X, y)
print("best k:", narrow.best_params_["knn__n_neighbors"], "  CV AUC:", round(narrow.best_score_, 3))
```

:::hint
The grid's largest value is 9, so "best k = 9" can't tell you whether larger is better. For the curve, `np.unique(np.logspace(0, np.log10(200), 12).astype(int))` gives log-spaced integers.
:::

:::solution
```python run alt="Line chart of mean AUC against k on a log axis from 1 to 200, with the range 1 to 9 shaded. Training AUC starts at 1.0 for k equal to 1 and falls as k grows. Validation AUC rises from about 0.79 at k equal to 1, keeps climbing past 9, peaks near 0.92 between about 17 and 29, then slowly declines." caption="The grid stopped at k = 9 while validation AUC was still rising. A wider sweep shows where it peaks."
ks = np.unique(np.logspace(0, np.log10(200), 12).astype(int))
train_auc, val_auc = validation_curve(knn_pipe, X, y, param_name="knn__n_neighbors", param_range=ks,
                                      cv=cv, scoring="roc_auc")
best_k = int(ks[np.argmax(val_auc.mean(axis=1))])
print("best k on the wide curve:", best_k, "  CV AUC:", round(val_auc.mean(axis=1).max(), 3))

fig, ax = plt.subplots(figsize=(6.5, 2.8))
ax.plot(ks, train_auc.mean(axis=1), marker="o", color="#2a78d6", label="training folds")
ax.plot(ks, val_auc.mean(axis=1), marker="o", color="#eb6834", label="validation folds")
ax.axvspan(1, 9, color="#d9e6f7", alpha=0.6, label="teammate's range")
ax.set_xscale("log")
ax.set_xlabel("n_neighbors (k)")
ax.set_ylabel("mean AUC")
ax.legend(frameon=False, fontsize=8)
ax.spines[["top", "right"]].set_visible(False)
plt.tight_layout()
plt.show()
```

A winner at the boundary of the search space means "at least this much, maybe more". With 12% flipped labels, small k fits the noise; the curve keeps improving past 9 and peaks in the high teens, before averaging over too many neighbors starts to blur the classes. Add an edge check to every search: if a numeric best value equals the range's minimum or maximum, widen the range and run again.
:::

### Challenge: What tuning on the test set costs

Simulate it. From one large pool of generated data, take 300 training rows, 300 "test" rows, and 5,000 "future" rows that stand in for real use. Sample 40 random decision-tree settings. Method A picks the setting with the best **test** score; method B picks the best **5-fold CV** score on the training rows. For each method, compare the score it *claims* (test score or CV score) with its real score on the future rows. Repeat over 5 seeds and report the average optimism (claimed minus future).

```mermaid caption="Three roles for three slices of data in the simulation"
flowchart LR
    T["300 training rows"] --> A["A: fit each candidate, pick best TEST score"]
    T --> B["B: pick best 5-fold CV score"]
    S["300 test rows"] --> A
    A --> F["5,000 future rows: the real score"]
    B --> F
```

:::hint
For each seed: draw the pool with `make_classification(n_samples=5600, ..., random_state=seed)` and slice it. Use `ParameterSampler(space, n_iter=40, random_state=seed)` to get the 40 settings. For B you can simply run `RandomizedSearchCV` on the training rows with the same 40 settings via `n_iter=40, random_state=seed`.
:::

:::solution
```python run
from sklearn.model_selection import ParameterSampler, cross_val_score

tree_space = {"max_depth": randint(2, 16), "min_samples_leaf": [1, 2, 5, 10, 20, 50], "ccp_alpha": loguniform(1e-5, 1e-1)}
rows = []
for seed in range(5):
    Xp, yp = make_classification(n_samples=5600, n_features=15, n_informative=5, n_redundant=3,
                                 flip_y=0.12, random_state=seed)
    X_tr, y_tr = Xp[:300], yp[:300]
    X_te, y_te = Xp[300:600], yp[300:600]
    X_fu, y_fu = Xp[600:], yp[600:]
    settings = list(ParameterSampler(tree_space, n_iter=40, random_state=seed))

    fitted = [DecisionTreeClassifier(random_state=0, **s).fit(X_tr, y_tr) for s in settings]
    test_scores = [m.score(X_te, y_te) for m in fitted]
    a = int(np.argmax(test_scores))
    rows.append({"method": "A: best test score", "claimed": test_scores[a], "future": fitted[a].score(X_fu, y_fu)})

    cv_scores = [cross_val_score(DecisionTreeClassifier(random_state=0, **s), X_tr, y_tr, cv=cv).mean() for s in settings]
    b = int(np.argmax(cv_scores))
    rows.append({"method": "B: best CV score", "claimed": cv_scores[b], "future": fitted[b].score(X_fu, y_fu)})

sim = pd.DataFrame(rows)
sim["optimism"] = sim["claimed"] - sim["future"]
print(sim.groupby("method")[["claimed", "future", "optimism"]].mean().round(3))
```

Both claims are optimistic, because both are the maximum of 40 noisy scores. Method A's test score was supposed to be the untouched, honest number, and choosing by it spent that honesty: what remains is a selection score like any other, measured on fewer rows (300 versus 5 folds of 60 that cover all 300), so it's typically the noisier and more inflated of the two. Method B leaves the test set unused, so you can still score the chosen model on it once and get an unbiased estimate. That's the whole argument for keeping the test set sealed until the end.
:::
