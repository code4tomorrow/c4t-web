:::objectives
- Turn a balanced dataset into a realistic rare-class problem and seal a test set before modelling.
- Compare several model families on identical folds with average precision, and read the fold-by-fold numbers.
- Measure whether models make *different* mistakes before you combine them.
- Build and compare a soft-voting and a stacking ensemble.
- Tune the decision threshold for a recall-heavy goal, then evaluate everything once on the test set.
:::

The digits dataset that ships with scikit-learn has 1,797 tiny 8×8 handwritten digits, about 180 of each. That balance is unusual. Real detection problems look more like "find the few interesting items in a big pile", so we'll recreate one: keep only 80 of the 8s, and build a model whose job is to flag them. The 8 is a good choice because it looks like a 3, a 9, and a 0 when written carelessly.

Here is the plan for the whole notebook.

```mermaid caption="From raw digits to a tuned ensemble, with the test set touched once at the end"
flowchart LR

    B --> C[Four models on shared folds]

    E --> F[Tune the threshold]
    F --> G[One look at the test set]
```

## Step 1: Make the 8s rare and lock away a test set

We remove a random subset of the 8s (with a fixed seed so the run repeats), relabel the problem as "8 or not", and split off a stratified test set right away. The original digit labels ride along in the split so we can inspect mistakes later. Nothing below touches `X_test` until Step 7.

```python run
import numpy as np
import pandas as pd
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split

digits = load_digits()
rng = np.random.default_rng(0)
eights = np.flatnonzero(digits.target == 8)
drop = rng.choice(eights, size=len(eights) - 80, replace=False)
keep = np.setdiff1d(np.arange(len(digits.target)), drop)

X = digits.data[keep]
y = (digits.target[keep] == 8).astype(int)
X_train, X_test, y_train, y_test, digit_train, digit_test = train_test_split(
    X, y, digits.target[keep], test_size=0.3, stratify=y, random_state=0)

print(f"{len(y)} images, {y.sum()} eights ({y.mean():.1%})")
print(f"train: {y_train.sum()} eights of {len(y_train)}   test: {y_test.sum()} eights of {len(y_test)}")
```

About 4.7% of the images are now 8s. With 56 eights in training, each of five folds will see roughly 11 of them, so expect noisy fold scores.

## Step 2: Score four different models on the same folds

Every model gets the same `StratifiedKFold` object, so they are graded on identical rows. The scaled models sit inside pipelines, so the scaler is refit inside every fold. The `DummyClassifier` shows the floor: its AP equals the share of 8s.

```python run
from sklearn.dummy import DummyClassifier
from sklearn.ensemble import RandomForestClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import StratifiedKFold, cross_validate
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.svm import SVC

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
members = {
    "logreg": make_pipeline(StandardScaler(), LogisticRegression(C=0.1, max_iter=2000)),
    "knn": make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=5)),
    "svc": make_pipeline(StandardScaler(), SVC(probability=True, random_state=0)),
    "forest": RandomForestClassifier(n_estimators=200, random_state=0),
}

fold_ap = {}
for name, model in {"baseline": DummyClassifier(strategy="prior"), **members}.items():
    res = cross_validate(model, X_train, y_train, cv=cv, scoring=["average_precision", "recall"])
    fold_ap[name] = res["test_average_precision"]
    print(f"{name:>8}: AP {fold_ap[name].mean():.3f} ± {fold_ap[name].std():.3f}   "
          f"recall at 0.5 {res['test_recall'].mean():.2f}")
```

The SVC ranks best (AP about 0.92), and the forest's recall at the default threshold is only about 0.23 even though its AP is decent. That gap between "ranks well" and "flags enough at 0.5" is the pattern from the Notes, and it tells you the threshold, not the model, is the first thing to fix.

## Step 3: Do class weights help here?

Three of the four models accept `class_weight`. Let's see what it buys.

```python run
weighted = {
    "logreg": make_pipeline(StandardScaler(),
                            LogisticRegression(C=0.1, max_iter=2000, class_weight="balanced")),
    "svc": make_pipeline(StandardScaler(),
                         SVC(probability=True, random_state=0, class_weight="balanced")),
    "forest": RandomForestClassifier(n_estimators=200, random_state=0, class_weight="balanced"),
}
for name, model in weighted.items():
    res = cross_validate(model, X_train, y_train, cv=cv, scoring=["average_precision", "recall"])
    print(f"{name:>7} balanced: AP {res['test_average_precision'].mean():.3f} "
          f"(was {fold_ap[name].mean():.3f})   recall at 0.5 {res['test_recall'].mean():.2f}")
```

Recall at 0.5 jumps for logistic regression and the SVC, but AP stays within a couple of hundredths, and for logistic regression it even drops. The weights moved the line without making the models better at telling 8s from everything else. We'll keep the unweighted models, which also keeps their probabilities meaningful, and fix recall with a tuned threshold in Step 6.

## Step 4: Check that the models fail in different ways

An ensemble of four models that make the same mistakes is just one model, four times slower. `cross_val_predict` gives every training image a probability from a model that never saw it, so we can compare the members' out-of-fold scores directly.

```python run
from sklearn.model_selection import cross_val_predict

oof = pd.DataFrame({
    name: cross_val_predict(model, X_train, y_train, cv=cv, method="predict_proba")[:, 1]
    for name, model in members.items()
})
print("Rank correlation of out-of-fold scores:")
print(oof.corr(method="spearman").round(2))

missed = oof[y_train == 1] < 0.5
print("\n8s each model misses at 0.5:", missed.sum().to_dict())
print("8s missed by every model:", int(missed.all(axis=1).sum()), "of", int(y_train.sum()))
```

The k-NN scores correlate only about 0.4 with the others, so it sees the problem differently from the three models that draw smooth boundaries. Each model misses between 8 and 43 of the 56 eights at 0.5, but only a handful are missed by all four. Those few are the ones no ensemble can rescue; every other miss is a chance for a teammate to cover.

## Step 5: Combine the models, and compare fold by fold

Now the two ensembles from the Notes. Because they use the same `cv` object as the members in Step 2, we can line their scores up fold by fold.

```python run
from sklearn.ensemble import StackingClassifier, VotingClassifier

member_list = list(members.items())
ensembles = {
    "vote": VotingClassifier(member_list, voting="soft"),
    "stack": StackingClassifier(member_list, final_estimator=LogisticRegression(), cv=5),
}
for name, model in ensembles.items():
    fold_ap[name] = cross_validate(model, X_train, y_train, cv=cv,
                                   scoring="average_precision")["test_score"]

table = pd.DataFrame(fold_ap).drop(columns="baseline")
table.index = [f"fold {i + 1}" for i in range(5)]
print(table.round(3))
print("\nmean:", table.mean().round(3).to_dict())
print("folds where the vote beats the best single model:",
      int((table["vote"] > table[list(members)].max(axis=1)).sum()), "of 5")
```

Both ensembles average about 0.94, ahead of the best member's 0.92, and they beat the best single model in most individual folds. That fold-level view is stronger evidence than the means alone, because each fold is a paired comparison on the same rows.

Which members does the stack trust? Its final estimator is a logistic regression, so its coefficients are the weights it gives each member's probability.

```python run
stack = ensembles["stack"].fit(X_train, y_train)
print(dict(zip(members, stack.final_estimator_.coef_[0].round(2).tolist())))
```

It leans most on k-NN and the SVC, the two strongest and least similar members. Since the vote and the stack score the same, we'll take the soft vote forward: it is simpler to explain and trains about five times faster, because it has no internal cross-validation.

## Step 6: Tune the threshold for a recall-heavy goal

Suppose every flagged image goes to a person who checks it, and missing an 8 is worse than an extra check. The F-beta score with `beta=2` treats recall as twice as important as precision, which captures that preference in one number. `TunedThresholdClassifierCV` searches for the cutoff that maximizes it, using its own internal folds on the training data.

```python run
from sklearn.metrics import fbeta_score, make_scorer
from sklearn.model_selection import TunedThresholdClassifierCV

f2 = make_scorer(fbeta_score, beta=2)
detector = TunedThresholdClassifierCV(ensembles["vote"], scoring=f2, cv=5,
                                      random_state=0).fit(X_train, y_train)
print(f"chosen threshold: {detector.best_threshold_:.3f}")
print(f"cross-validated F2 at that threshold: {detector.best_score_:.3f}")
```

The chosen cutoff is about 0.2: an image only needs a one-in-five ensemble probability to be flagged. Because the vote's members are unweighted, that probability is still on a sensible scale.

## Step 7: Open the test set once

Everything is decided: the members, the ensemble, and the threshold. Now, and only now, we score the 511 sealed test images, comparing the ensemble with the best single model.

```python run alt="Precision-recall curves on the test set: both models keep precision 1.0 up to about 0.88 recall, the soft vote holds high precision slightly longer (AP 0.97 against 0.96), and both sit far above the chance line at 0.05" caption="Test-set precision-recall curves. The dashed line is a model that guesses at random."
import matplotlib.pyplot as plt
from sklearn.metrics import PrecisionRecallDisplay, confusion_matrix, precision_score, recall_score

svc_alone = members["svc"].fit(X_train, y_train)
fig, ax = plt.subplots(figsize=(5.5, 4))
PrecisionRecallDisplay.from_estimator(svc_alone, X_test, y_test, name="SVC alone",
                                      ax=ax, color="#2a78d6")
PrecisionRecallDisplay.from_estimator(detector.estimator_, X_test, y_test, name="soft vote",
                                      ax=ax, color="#eb6834", plot_chance_level=True)
ax.set_title("Finding 8s in the sealed test set")
ax.grid(alpha=0.3)

pred = detector.predict(X_test)
tn, fp, fn, tp = confusion_matrix(y_test, pred).ravel()
print(f"flagged {tp + fp} images: {tp} real 8s, false alarms: {fp}, missed 8s: {fn} of {tp + fn}")
print(f"precision {precision_score(y_test, pred):.3f}   recall {recall_score(y_test, pred):.3f}")
```

Out of 511 test images the detector flags 23, gets 22 of them right, and misses 2 of the 24 eights. Test AP (in the legend) is close to the cross-validated estimate, which is what you hope to see when nothing leaked. Notice, too, that the test set barely separates the ensemble from the SVC: with only 24 eights, one image more or less moves AP by a few hundredths. The fold-by-fold comparison in Step 5 is the stronger evidence for the ensemble; the test set's job is to confirm that nothing broke.

Numbers are not the end of an evaluation. Look at the mistakes.

```python run alt="The three test images the detector got wrong, each labelled with its true digit and the ensemble's probability" caption="Every test mistake, with the ensemble's probability that it is an 8."
proba = detector.estimator_.predict_proba(X_test)[:, 1]
wrong = np.flatnonzero(pred != y_test)

fig, axes = plt.subplots(1, len(wrong), figsize=(2.2 * len(wrong), 2.6))
for ax, i in zip(np.atleast_1d(axes), wrong):
    ax.imshow(X_test[i].reshape(8, 8), cmap="gray_r")
    ax.set_title(f"a {digit_test[i]}, p = {proba[i]:.2f}", fontsize=10)
    ax.axis("off")
```

The false alarm is a heavy, blobby 1 that only just crossed the cutoff (0.20 against a threshold of 0.197). The two missed 8s barely look like 8s: one is a squiggle and the other is almost a single stroke. A person would hesitate over these too, so they are hard cases rather than evidence that the model latched onto something strange.

## The finished program

Here is the whole detector in one cell, without the exploration: the data, the four members, the soft vote, the tuned threshold, and the single test evaluation.

```python run title="rare_eights.py"
import numpy as np
from sklearn.datasets import load_digits
from sklearn.ensemble import RandomForestClassifier, VotingClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import average_precision_score, fbeta_score, make_scorer, recall_score
from sklearn.model_selection import TunedThresholdClassifierCV, train_test_split
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.svm import SVC

digits = load_digits()
rng = np.random.default_rng(0)
eights = np.flatnonzero(digits.target == 8)
keep = np.setdiff1d(np.arange(len(digits.target)),
                    rng.choice(eights, size=len(eights) - 80, replace=False))
X, y = digits.data[keep], (digits.target[keep] == 8).astype(int)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, stratify=y, random_state=0)

vote = VotingClassifier([
    ("logreg", make_pipeline(StandardScaler(), LogisticRegression(C=0.1, max_iter=2000))),
    ("knn", make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=5))),
    ("svc", make_pipeline(StandardScaler(), SVC(probability=True, random_state=0))),
    ("forest", RandomForestClassifier(n_estimators=200, random_state=0)),
], voting="soft")
detector = TunedThresholdClassifierCV(vote, scoring=make_scorer(fbeta_score, beta=2),
                                      cv=5, random_state=0).fit(X_train, y_train)

proba = detector.estimator_.predict_proba(X_test)[:, 1]
print(f"threshold {detector.best_threshold_:.3f}   test AP {average_precision_score(y_test, proba):.3f}   "
      f"test recall {recall_score(y_test, detector.predict(X_test)):.3f}")
```

:::quiz
Q: In Step 3, `class_weight="balanced"` raised the SVC's recall at 0.5 from about 0.68 to 0.89. Why did we still keep the unweighted SVC?
- [ ] Because weighted models can't go inside a `VotingClassifier`
  They can; any classifier with `predict_proba` can be a soft-voting member.
- [x] Because its AP barely moved, so the gain came from shifting the cutoff, which the tuned threshold does anyway without distorting probabilities
  Weighting and thresholding both move the decision line; only the threshold leaves the probabilities on their real scale for averaging.
- [ ] Because recall doesn't matter for this problem
  Recall matters a lot here, which is why Step 6 tunes for F2.

Q: Why did Step 4 look at correlations between the members' out-of-fold scores before building any ensemble?
- [ ] To find which member has the highest AP
  Step 2 already ranked the members by AP; correlation measures something else.
- [x] Because averaging only helps if members make different mistakes, and low correlation is evidence that they do
  Four models with near-identical scores would average to the same ranking, so the ensemble would gain nothing.
- [ ] Because `VotingClassifier` refuses members whose scores correlate above 0.9
  There is no such rule; correlated members are allowed, they just add little.

Q: The tuned threshold came out at about 0.2. What would choosing it by maximizing F2 on the test set have done?
- [ ] Nothing different, since the test set is drawn from the same data
  The test set is a fresh sample; choosing on it means the final score was optimized on the very rows used to report it.
- [x] Made the reported test score optimistic, because the threshold would be fitted to those 24 test eights
  A threshold is a fitted value. Fitting it on the test rows leaks, just like tuning `C` on them would.
:::

:::takeaways
- Make the evaluation decisions (metric, folds, test set) before training anything, and share one `cv` object across every candidate.
- When class weights raise recall but not AP, a tuned threshold gives the same benefit while keeping probabilities meaningful.
- Check that members disagree before combining them; uncorrelated, similarly strong members are what make an ensemble work.
- Compare candidates fold by fold, not only by their means.
- Look at the actual mistakes; they tell you whether the model learned something sensible.
:::

## Extend it

-   Swap the target to another digit (try 1, which is often confused with 7) and see whether the same ensemble still wins.
-   Make the 8s rarer (keep 30) and watch the fold-to-fold spread grow. How many eights per fold do you need before the ranking of models stops changing?
-   Replace soft voting with `VotingClassifier(..., weights=[1, 2, 2, 1])` based on the stack's coefficients, and check whether hand-set weights beat the learned stack.
-   Write a cost-based scorer (for example, a miss costs 10 checks) and compare its threshold with the F2 threshold.
