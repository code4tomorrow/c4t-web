:::objectives
- Decide MAJOR, MINOR, PATCH, or no model version for realistic changes.
- Build a dataset fingerprint that ignores row and column order but catches any changed value.
- Audit a registry record by re-hashing its artifact and training files.
- Answer lineage questions: which versions used a bad file, and which alias served at a given time.
- Write a promotion gate with several rules, and a function that proposes the next version number.
:::

## Warm-up: which bump?

Using the convention from the Notes lesson (MAJOR = the request or response contract changes, MINOR = same contract but outputs change, PATCH = outputs identical), decide each case. One of them isn't a new model version at all.

1. Retrain on March's orders with the same features and code.
2. Add a required `restaurant_id` field to the request.
3. Fix a misspelled word in the record's `params` description; the artifact is untouched.
4. Lower the decision threshold from 0.5 to 0.45.
5. Rename the response field `late_probability` to `p_late`.
6. Rebuild the Docker image because the `python:3.12-slim` base image got a security patch; `model.joblib` is byte-identical.

:::solution
1. **MINOR.** Same contract, new weights, so some outputs change.
2. **MAJOR.** Every client must start sending a new field.
3. **PATCH.** Nothing any client can observe changed. (Some teams skip a version entirely for this; a PATCH keeps the record immutable.)
4. **MINOR.** The response has the same fields, but `late` flips for some orders.
5. **MAJOR.** Renaming a response field breaks every client that reads it, even though the numbers are the same.
6. **No new model version.** The model didn't change; the *image* did. It gets a new image digest (and usually a new image tag such as `1.1.0-2`), while the registry record for 1.1.0 stays as it is. Keeping model versions and image builds separate is what lets you patch the OS without re-validating the model.
:::

## Setup

```python run
import hashlib
import json
from datetime import datetime
from importlib.metadata import PackageNotFoundError, version as installed_version
from pathlib import Path

import numpy as np
import pandas as pd

def make_orders(n, seed):
    rng = np.random.default_rng(seed)
    distance_km = rng.gamma(shape=2.0, scale=2.0, size=n).round(2)
    items = rng.integers(1, 9, size=n)
    hour = rng.integers(10, 23, size=n)
    raining = (rng.random(n) < 0.25).astype(int)
    rush = (hour >= 17) & (hour <= 19)
    logit = -4.0 + 0.45 * distance_km + 0.15 * items + 1.2 * raining + 0.9 * rush
    late = (rng.random(n) < 1 / (1 + np.exp(-logit))).astype(int)
    return pd.DataFrame({"distance_km": distance_km, "items": items,
                         "hour": hour, "raining": raining, "late": late})

def sha256_file(path):
    with open(path, "rb") as f:
        return hashlib.file_digest(f, "sha256").hexdigest()

Path("data").mkdir(exist_ok=True)
orders = make_orders(2000, seed=23)
orders.to_csv("data/orders.csv", index=False)
print("setup done")
```

### Exercise 1: A fingerprint that ignores order

The file hash changes when rows are shuffled, even though the data is the same. Write `dataset_fingerprint(frame)` that returns the same SHA-256 for the same set of rows and columns in any order, and a different one if any value changes. Check it on four frames: the original, shuffled rows, reordered columns, and one value edited.

```text
original          file b0efa125...  fingerprint 436ef871...
shuffled rows     file f7c3eb12...  fingerprint 436ef871...
columns reordered file 210baf70...  fingerprint 436ef871...
one value edited  file 18be8d22...  fingerprint 182eb6c4...
```

:::hint
Put the frame in a canonical form first: columns in sorted order, then rows sorted by every column, then a fresh index. `pd.util.hash_pandas_object(frame, index=False)` gives one 64-bit hash per row; hash the bytes of that array with SHA-256.
:::

:::solution
```python run
def dataset_fingerprint(frame):
    canonical = frame[sorted(frame.columns)]
    canonical = canonical.sort_values(list(canonical.columns)).reset_index(drop=True)
    row_hashes = pd.util.hash_pandas_object(canonical, index=False).to_numpy()
    header = ",".join(canonical.columns).encode()
    return hashlib.sha256(header + row_hashes.tobytes()).hexdigest()

edited = orders.copy()
edited.loc[5, "items"] += 1
versions = {
    "original": orders,
    "shuffled rows": orders.sample(frac=1, random_state=1),
    "columns reordered": orders[["late", "hour", "raining", "items", "distance_km"]],
    "one value edited": edited,
}
for label, frame in versions.items():
    path = Path("data") / f"{label.replace(' ', '_')}.csv"
    frame.to_csv(path, index=False)
    print(f"{label:17} file {sha256_file(path)[:8]}...  fingerprint {dataset_fingerprint(frame)[:8]}...")
```

The column names go into the hash too; otherwise renaming `items` to `basket_size` would leave the fingerprint unchanged. Which hash should a registry record use? Both answer different questions. The file hash says "these exact bytes", which is what reproducing a training run needs (the Notes lesson showed that row order changes the artifact's bytes slightly). The fingerprint says "the same data", which is what you want when comparing exports from two systems.
:::

:::video DMtFhACPnTY
What to watch for: what makes a hash function cryptographic (a tiny input change scrambles the output, and you can't work backwards or find collisions), which is why a 64-character SHA-256 can stand in for a whole file.
:::

### Exercise 2: Audit a record against the disk

A registry record claims a data hash and an artifact hash. Write `audit(record)` that re-hashes the artifact and every training file and returns a list of problems (an empty list means the record checks out). Then append one row to the training file and audit again.

```text
clean audit: []
after editing data/orders.csv:
 - training file data/orders.csv changed since registration (b0efa125... -> e0e35b3f...)
```

:::hint
Loop over `record["training_data"]`. Use `Path(...).exists()` before hashing, so a missing file is reported as a problem instead of crashing the audit.
:::

:::solution
```python run
import joblib
from sklearn.linear_model import LogisticRegression

FEATURES = ["distance_km", "items", "hour", "raining"]
Path("models").mkdir(exist_ok=True)
joblib.dump(LogisticRegression(max_iter=1000).fit(orders[FEATURES], orders["late"]), "models/audit_me.joblib")
record = {
    "version": "1.0.0",
    "artifact": {"file": "models/audit_me.joblib", "sha256": sha256_file("models/audit_me.joblib")},
    "training_data": [{"file": "data/orders.csv", "sha256": sha256_file("data/orders.csv")}],
}

def audit(record):
    problems = []
    checks = [("artifact", record["artifact"])] + [("training file", d) for d in record["training_data"]]
    for kind, item in checks:
        path = Path(item["file"])
        if not path.exists():
            problems.append(f"{kind} {path} is missing")
            continue
        actual = sha256_file(path)
        if actual != item["sha256"]:
            problems.append(f"{kind} {path} changed since registration ({item['sha256'][:8]}... -> {actual[:8]}...)")
    return problems

print("clean audit:", audit(record))
with open("data/orders.csv", "a") as f:
    f.write("3.1,2,12,0,0\n")
print("after editing data/orders.csv:")
for problem in audit(record):
    print(" -", problem)
orders.to_csv("data/orders.csv", index=False)       # restore the original file
```

An audit like this is cheap enough to run in CI on every commit. It catches the quiet failure where someone "fixes" a training file in place, and every record that points at it silently stops being reproducible.
:::

### Exercise 3: Which versions used the bad file?

The data team reports that `orders_2026_02.csv` with hash `e0b9e96a...` had labels shifted by one row. Given these registry records and the current aliases, list every version trained on that file, and say whether any alias points at one of them right now.

```python run
records = [
    {"version": "1.0.0", "training_data": [{"file": "orders_2026_01.csv", "sha256": "b0efa125"}]},
    {"version": "1.1.0", "training_data": [{"file": "orders_2026_01.csv", "sha256": "b0efa125"},
                                           {"file": "orders_2026_02.csv", "sha256": "e0b9e96a"}]},
    {"version": "1.1.1", "training_data": [{"file": "orders_2026_01.csv", "sha256": "b0efa125"},
                                           {"file": "orders_2026_02.csv", "sha256": "e0b9e96a"}]},
    {"version": "1.2.0", "training_data": [{"file": "orders_2026_02.csv", "sha256": "7f12aa03"},
                                           {"file": "orders_2026_03.csv", "sha256": "c41d9b2e"}]},
]
aliases = {"champion": "1.1.1", "challenger": "1.2.0"}
BAD_HASH = "e0b9e96a"
```

```text
trained on the bad file: ['1.1.0', '1.1.1']
champion -> 1.1.1  AFFECTED
challenger -> 1.2.0  ok
```

:::hint
Match on the hash, not the file name. Version 1.2.0 was trained on a file with the *same name* but different contents.
:::

:::solution
```python run
affected = [r["version"] for r in records if any(d["sha256"] == BAD_HASH for d in r["training_data"])]
print("trained on the bad file:", affected)
for alias, target in aliases.items():
    print(f"{alias} -> {target}  {'AFFECTED' if target in affected else 'ok'}")
```

Matching by name would have flagged 1.2.0 too, and the team would have rolled back their only clean candidate. Names say where a file lives; hashes say what's in it. The answer also tells you what to do: the champion is affected, 1.0.0 is the most recent unaffected version with a record, so the fast fix is to roll `champion` back to 1.0.0 while 1.2.0 finishes evaluation.
:::

### Exercise 4: What was serving at 14:05?

An incident started at 14:05 on 17 November. Write `alias_at(history, alias, when)` that returns which version an alias pointed to at a given moment, using the append-only history from the Build-along. Test it at four times, including one before the alias existed.

```python run
history = [
    {"alias": "champion",   "to": "1.0.0", "at": "2026-11-10T09:00:00"},
    {"alias": "champion",   "to": "1.1.0", "at": "2026-11-17T13:30:00"},
    {"alias": "challenger", "to": "1.2.0", "at": "2026-11-17T13:45:00"},
    {"alias": "champion",   "to": "1.0.0", "at": "2026-11-17T15:10:00"},
]
```

```text
2026-11-01T12:00:00 -> None
2026-11-17T13:00:00 -> 1.0.0
2026-11-17T14:05:00 -> 1.1.0
2026-11-17T16:00:00 -> 1.0.0
```

:::hint
Walk the moves in time order and remember the latest move for this alias that happened at or before `when`. Compare times as `datetime` objects with `datetime.fromisoformat`, not as strings.
:::

:::solution
```python run
def alias_at(history, alias, when):
    when = datetime.fromisoformat(when)
    current = None
    for move in sorted(history, key=lambda m: datetime.fromisoformat(m["at"])):
        if move["alias"] == alias and datetime.fromisoformat(move["at"]) <= when:
            current = move["to"]
    return current

for moment in ["2026-11-01T12:00:00", "2026-11-17T13:00:00", "2026-11-17T14:05:00", "2026-11-17T16:00:00"]:
    print(moment, "->", alias_at(history, "champion", moment))
```

This is the question from the Notes lesson's incident report, answered in one line. It only works because the history is append-only: if `set_alias` had simply overwritten `current`, 14:05 would be unanswerable. (Comparing ISO strings happens to work when every timestamp has the same format and time zone; converting to `datetime` stays correct when they don't.)
:::

### Exercise 5: A promotion gate with several rules

Write `gate(candidate, champion, serving_sklearn)` returning a list of reasons to refuse promotion. Refuse if:

- the holdout AUC drops by more than 0.002,
- the feature list changed but the MAJOR number didn't go up,
- the candidate was built with a different scikit-learn than the serving image has,
- the candidate has no model card.

Test it on the three candidates below.

```python run
champion = {"version": "1.1.0", "features": ["distance_km", "items", "hour", "raining"],
            "holdout_auc": 0.8104, "sklearn": "1.8.0", "model_card": True}
candidates = [
    {"version": "1.2.0", "features": ["distance_km", "items", "hour", "raining"],
     "holdout_auc": 0.8121, "sklearn": "1.8.0", "model_card": True},
    {"version": "1.2.0", "features": ["distance_km", "items", "hour", "raining", "restaurant_id"],
     "holdout_auc": 0.8350, "sklearn": "1.8.0", "model_card": True},
    {"version": "1.3.0", "features": ["distance_km", "items", "hour", "raining"],
     "holdout_auc": 0.8060, "sklearn": "1.9.1", "model_card": False},
]
```

```text
1.2.0: promote
1.2.0: REFUSE - feature list changed without a MAJOR bump (1.2.0)
1.3.0: REFUSE - holdout AUC fell by 0.0044; built with scikit-learn 1.9.1 but serving has 1.8.0; no model card
```

:::hint
`int(version.split(".")[0])` gives the MAJOR number. Collect every problem rather than returning at the first one: a person fixing a candidate wants the whole list at once.
:::

:::solution
```python run
def gate(candidate, champion, serving_sklearn, max_drop=0.002):
    problems = []
    drop = champion["holdout_auc"] - candidate["holdout_auc"]
    if drop > max_drop:
        problems.append(f"holdout AUC fell by {drop:.4f}")
    major = lambda v: int(v.split(".")[0])
    if candidate["features"] != champion["features"] and major(candidate["version"]) <= major(champion["version"]):
        problems.append(f"feature list changed without a MAJOR bump ({candidate['version']})")
    if candidate["sklearn"] != serving_sklearn:
        problems.append(f"built with scikit-learn {candidate['sklearn']} but serving has {serving_sklearn}")
    if not candidate["model_card"]:
        problems.append("no model card")
    return problems

for candidate in candidates:
    problems = gate(candidate, champion, serving_sklearn="1.8.0")
    print(f"{candidate['version']}: " + ("promote" if not problems else "REFUSE - " + "; ".join(problems)))
```

The second candidate is the interesting one: it's the *best* model by far, and the gate still refuses it. A new required feature means every client must change, so it has to ship as 2.0.0 with a new contract, a migration plan, and probably both versions served side by side for a while. A gate that only looked at metrics would have broken every client at once.
:::

### Exercise 6: Does this environment match the record?

A record lists the library versions the model was trained with. Write `environment_mismatches(recorded)` that compares them with what's installed right now (using `importlib.metadata.version`) and lists every difference, including packages that aren't installed. Test it with a record that has one stale version and one package this machine lacks.

```text
numpy: recorded 2.0.0, installed 2.1.3
lightgbm: recorded 4.5.0, not installed
```

:::hint
`installed_version("scikit-learn")` returns a string such as `"1.8.0"`. It raises `PackageNotFoundError` for a package that isn't installed. Use distribution names as pip knows them (`scikit-learn`, not `sklearn`).
:::

:::solution
```python run
def environment_mismatches(recorded):
    problems = []
    for package, wanted in recorded.items():
        try:
            found = installed_version(package)
        except PackageNotFoundError:
            problems.append(f"{package}: recorded {wanted}, not installed")
            continue
        if found != wanted:
            problems.append(f"{package}: recorded {wanted}, installed {found}")
    return problems

recorded = {"scikit-learn": "1.8.0", "numpy": "2.0.0", "pandas": "2.2.3", "lightgbm": "4.5.0"}
for problem in environment_mismatches(recorded):
    print(problem)
```

Run this at service startup (like the Module 2 challenge did for scikit-learn alone) or as a CI step that compares the training record with the serving image's `requirements.txt`. Either way, a mismatch becomes a clear message instead of a silent change in predictions.
:::

### Challenge: Propose the next version automatically

Write `next_version(champion, candidate)` that compares two records and proposes the candidate's version number from the champion's: MAJOR if the features or the response fields differ, MINOR if the artifact hash or the threshold differs, otherwise PATCH. Write unit tests for each case and run them so the results print.

```text
test_identical_artifact_is_patch ... ok
test_new_feature_is_major ... ok
test_new_threshold_is_minor ... ok
test_renamed_response_field_is_major ... ok
test_retrained_weights_are_minor ... ok
...
OK
```

:::hint
Parse `"1.4.2"` into three integers. A MAJOR bump resets MINOR and PATCH to zero (1.4.2 becomes 2.0.0), and a MINOR bump resets PATCH (1.4.2 becomes 1.5.0). Build the test records with a helper that starts from a base record and overrides one field.
:::

:::solution
```python run
import sys
import unittest

def next_version(champion, candidate):
    major, minor, patch = (int(part) for part in champion["version"].split("."))
    if candidate["features"] != champion["features"] or candidate["response_fields"] != champion["response_fields"]:
        return f"{major + 1}.0.0"
    if candidate["artifact_sha256"] != champion["artifact_sha256"] or candidate["threshold"] != champion["threshold"]:
        return f"{major}.{minor + 1}.0"
    return f"{major}.{minor}.{patch + 1}"

BASE = {"version": "1.4.2", "features": ["distance_km", "items", "hour", "raining"],
        "response_fields": ["late_probability", "late", "model_version"],
        "artifact_sha256": "d3a9be76", "threshold": 0.5}

def candidate(**changes):
    return {**BASE, **changes}

class NextVersionTests(unittest.TestCase):
    def test_identical_artifact_is_patch(self):
        self.assertEqual(next_version(BASE, candidate()), "1.4.3")

    def test_retrained_weights_are_minor(self):
        self.assertEqual(next_version(BASE, candidate(artifact_sha256="6a7d2ff6")), "1.5.0")

    def test_new_threshold_is_minor(self):
        self.assertEqual(next_version(BASE, candidate(threshold=0.45)), "1.5.0")

    def test_new_feature_is_major(self):
        self.assertEqual(next_version(BASE, candidate(features=BASE["features"] + ["restaurant_id"])), "2.0.0")

    def test_renamed_response_field_is_major(self):
        renamed = ["p_late", "late", "model_version"]
        self.assertEqual(next_version(BASE, candidate(response_fields=renamed)), "2.0.0")

    def test_major_wins_when_everything_changed(self):
        changed = candidate(features=["distance_km"], artifact_sha256="ffff0000", threshold=0.3)
        self.assertEqual(next_version(BASE, changed), "2.0.0")

suite = unittest.defaultTestLoader.loadTestsFromTestCase(NextVersionTests)
unittest.TextTestRunner(stream=sys.stdout, verbosity=2).run(suite)
```

The order of the checks encodes the priority: a contract change outranks everything else. A tool like this belongs in the training pipeline, which can then refuse to register a candidate whose hand-typed version disagrees with the proposal. That turns the convention from something people remember into something the pipeline enforces.
:::
