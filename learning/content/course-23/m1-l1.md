Here is a bug that has nothing to do with machine learning. A model is trained on a laptop with scikit-learn 1.8 and saved to a file. The server that loads it has scikit-learn 1.5. On load, scikit-learn raises an `InconsistentVersionWarning`, and if nobody reads the logs, the service keeps running with a model that may now compute different answers. No test caught it, because the tests ran on the laptop.

The code in this course will run in three places: your computer, a Docker container, and (from Module 5) a GitHub Actions runner. The fix for the bug above is to make all three agree, down to the exact Python and library versions. That's why this setup is fussier about versions than most.

## What you're installing and why

| Tool | What it does in this course | Cost |
| --- | --- | --- |
| Python 3.12 | Trains models, runs the FastAPI service and the tests | Free, open source |
| Docker | Builds the service into an image and runs it as a container | Docker Desktop is free for personal use, education, non-commercial open source, and small businesses; Docker Engine on Linux is open source |
| Git and a GitHub account | Version history, and later CI/CD with GitHub Actions | Free |
| A code editor | Editing files; VS Code is a good free choice | Free |

Why Python 3.12 and not the newest release? The container in Module 2 starts from the official `python:3.12-slim` image, and the library versions this course pins (NumPy 2.1.3, pandas 2.2.3, and friends) publish ready-made packages for Python 3.12 and 3.13 but not 3.14. Matching your laptop to the container removes a whole category of "works on my machine" bugs.

Check your hardware before starting: a 64-bit computer, at least 8 GB of RAM if you're on Windows (Docker's stated minimum), hardware virtualization switched on, and several gigabytes of free disk for Docker images.

## Step 1: Install Python 3.12

:::tabs
@tab Windows
1. Open **PowerShell** and run `winget install --id Python.Python.3.12 -e`. If `winget` isn't available, download the **Windows installer (64-bit)** for Python 3.12.10 from python.org and tick **Add python.exe to PATH** on the first screen.
2. Close PowerShell and open a new window so it picks up the new PATH.
3. Run `py -3.12 --version`. The `py` launcher lets you choose a version even when several are installed.
@tab macOS
1. Either download the **macOS 64-bit universal2 installer** for Python 3.12.10 from python.org and run it, or, if you use Homebrew, run `brew install python@3.12`.
2. Open a new Terminal window.
3. Run `python3.12 --version`.
@tab Linux
1. Ubuntu 24.04 ships Python 3.12. Install it with the `venv` module (Ubuntu packages it separately): `sudo apt update && sudo apt install python3.12 python3.12-venv`.
2. Run `python3.12 --version`.
3. On other distributions, install Python 3.12 from your package manager, or use pyenv to build it.
@tab Chromebook
Skip to **No admin rights or on a Chromebook** below. A GitHub Codespace gives you Python 3.12, Docker, and Git in the browser.
:::

```text
Python 3.12.10
```

Any `3.12.x` is fine. If you see `3.13.x`, the course still works on your machine, but your container will run 3.12, so prefer 3.12 locally if you can.

## Step 2: Install Docker

:::tabs
@tab Windows
1. Docker Desktop runs Linux containers inside WSL 2. In an **administrator** PowerShell, run `wsl --install`, then restart. (If WSL is already installed, `wsl --update` brings it up to date.)
2. Download **Docker Desktop for Windows** from docs.docker.com and double-click `Docker Desktop Installer.exe`.
3. On the **Configuration** page, choose **Use WSL 2 instead of Hyper-V** if it asks. Finish the wizard and select **Close**.
4. Docker Desktop doesn't start by itself. Search for **Docker Desktop** in the Start menu, open it, and accept the Docker Subscription Service Agreement.
5. Requirements: 64-bit Windows 10 (22H2) or Windows 11 (23H2 or later). Home and Education editions run Linux containers, which is all this course needs.
@tab macOS
1. Check your chip under **Apple menu › About This Mac**, then download **Docker Desktop for Mac with Apple silicon** or **with Intel chip**.
2. Double-click `Docker.dmg` and drag the Docker icon into **Applications**.
3. Open **Docker.app** from Applications and accept the agreement. The whale icon in the menu bar shows that the engine is running.
4. Docker Desktop supports the current macOS release and the two before it.
@tab Linux
1. Install **Docker Engine** (no Desktop needed). The most reliable route is Docker's own apt repository; follow "Install Docker Engine on Ubuntu" at docs.docker.com. For a personal dev machine, Docker's convenience script also works: `curl -fsSL https://get.docker.com -o get-docker.sh` then `sudo sh get-docker.sh`.
2. To run `docker` without `sudo`, add yourself to the `docker` group: `sudo groupadd docker`, `sudo usermod -aG docker $USER`, then log out and back in (or run `newgrp docker`). This group grants root-level access to the machine, so only do it on a computer you control.
@tab Chromebook
The Codespace setup below includes Docker. Personal Chromebooks with the Linux development environment can also install Docker Engine with the Linux steps, but school-managed Chromebooks usually block it.
:::

Now prove the engine works. `hello-world` is a tiny official image whose only job is to print a message:

```bash
docker run hello-world
```

```text
Unable to find image 'hello-world:latest' locally
latest: Pulling from library/hello-world
...
Hello from Docker!
This message shows that your installation appears to be working correctly.
```

The first two lines appear only the first time, while Docker downloads the image. Run it again and they disappear, because the image is now cached on your machine.

What to watch for: the install steps on Windows and macOS, and how Docker Desktop shows that the engine is running. Afterwards, run `docker version` yourself: both a **Client** and a **Server** section should appear, and a missing Server section means the engine isn't running.
:::

## Step 3: Git and a GitHub account

:::tabs
@tab Windows
Run `winget install --id Git.Git -e`, or download Git for Windows from git-scm.com. Accept the installer's defaults. Open a new terminal afterwards.
@tab macOS
Run `git --version` in Terminal. If Git isn't installed, macOS offers to install the Command Line Developer Tools; accept, and Git comes with them.
@tab Linux
Run `sudo apt install git` (or your distribution's equivalent).
@tab Chromebook
Git is already installed in every Codespace.
:::

Then create a free account at github.com and tell Git who you are. GitHub can hide your real email: under **Settings › Emails**, turn on **Keep my email addresses private** and copy the `@users.noreply.github.com` address it shows you.

```bash
git config --global user.name "Your Name"
git config --global user.email "12345678+yourname@users.noreply.github.com"
git --version
```

```text
git version 2.47.0
```

Any recent version number is fine.

## No admin rights or on a Chromebook: use a GitHub Codespace

A Codespace is a Linux machine in GitHub's cloud with VS Code in your browser. GitHub Free accounts get a monthly allowance (listed as 120 hours of compute time and 15 GB-month of storage at the time of writing), and if you have no payment method on file, GitHub stops usage at the limit instead of charging you. Codespaces stop after 30 minutes of inactivity by default, which protects the allowance.

1. On GitHub, click **New repository**, name it `late-delivery`, tick **Add a README file**, and create it. (Modules 2 to 4 build this one project: a service that predicts whether a food delivery will arrive late.)
2. In the repository, choose **Add file › Create new file**, type the name `.devcontainer/devcontainer.json`, paste the configuration below, and commit it.
3. Click the green **Code** button, open the **Codespaces** tab, and create a codespace on `main`.

```json title=".devcontainer/devcontainer.json"
{
  "image": "mcr.microsoft.com/devcontainers/python:3.12",
  "features": {
    "ghcr.io/devcontainers/features/docker-in-docker:4": {}
  },
  "forwardPorts": [8000]
}
```

The `image` line pins Python 3.12. Without this file, Codespaces uses its default "universal" image, which currently defaults to a newer Python. The `docker-in-docker` feature installs a Docker engine inside the codespace, so `docker run hello-world` works in its terminal. `forwardPorts` makes your API reachable from the browser in Module 2.

## When something goes wrong

:::warning
**Windows: `Python was not found; run without arguments to install from the Microsoft Store`.** Windows ships placeholder `python.exe` aliases that open the Store. Use `py -3.12` instead, or turn the aliases off under **Settings › Apps › Advanced app settings › App execution aliases** (switch off the two **python** entries).
:::

:::warning
**`Cannot connect to the Docker daemon ... Is the docker daemon running?`** (on Windows the message mentions a pipe such as `dockerDesktopLinuxEngine` instead). The `docker` command works, but the engine behind it is stopped. Open Docker Desktop and wait for it to say the engine is running; on Linux, run `sudo systemctl start docker`. On Windows, if Docker Desktop itself complains about WSL or virtualization, run `wsl --update` and check that virtualization is enabled in your BIOS/UEFI settings.
:::

:::warning
**Linux: `permission denied while trying to connect to the Docker daemon socket`.** Your user isn't in the `docker` group yet, or you added it but haven't logged out and back in. Run `groups` to check, and repeat the group steps in Step 2 if `docker` isn't listed.
:::

:::warning
**Ubuntu: `The virtual environment was not created successfully because ensurepip is not available`.** Ubuntu splits `venv` into its own package. Run `sudo apt install python3.12-venv`, delete the half-made `.venv` folder, and create it again.
:::

## Check yourself

:::quiz
Q: Your laptop has Python 3.14 and your Dockerfile starts `FROM python:3.12-slim`. What's the real risk?
- [ ] None; Python is backward compatible
  New Python versions do remove and change things, and compiled libraries publish separate packages per version, so "it installed on my laptop" says little about the container.
- [x] Your tests pass on 3.14 with one set of library builds, while the container runs 3.12 with others
  Exactly. You'd be testing a different environment from the one you ship. Matching versions makes your local tests evidence about production.
- [ ] Docker refuses to build images on machines with a newer Python
  Docker doesn't look at your laptop's Python at all; the image brings its own.

Q: `docker --version` prints a version, but `docker run hello-world` says it cannot connect to the Docker daemon. What's wrong?
- [ ] Docker isn't installed
  If it weren't, `docker --version` would fail with "command not found".
- [x] The command-line client is installed, but the engine isn't running
  The `docker` command is only a client that talks to the engine. Start Docker Desktop (or the `docker` service on Linux) and try again.
- [ ] The hello-world image has been deleted from Docker Hub
  A missing image gives a "pull access denied" or "not found" error, not a daemon connection error.

Q: On a school Chromebook without Linux enabled, which setup covers every lesson for $0?
- [ ] Installing Docker Desktop from the Chrome Web Store
  Docker Desktop isn't available for ChromeOS.
- [x] A GitHub Codespace with a `devcontainer.json` that pins Python 3.12 and adds Docker
  It runs in the browser, includes Python, Docker, and Git, and stops at the free allowance instead of billing you.
- [ ] Any online Python notebook
  A notebook can train a model, but it can't build or run Docker images, which you'll need from Module 2.
:::
