:::objectives
- Register model versions as immutable folders, each with the artifact and a JSON record.
- Record content hashes for every training file and for the artifact.
- Keep aliases in a file whose history is only ever appended to.
- Promote a retrained candidate only after comparing it with the champion on a fixed holdout.
- Load models by alias, verifying the artifact hash before unpickling, and generate a model card from the record.
:::

When this lesson is done, your project will have a registry you can read with any text editor, and a service that loads whatever the `champion` alias points to:

```text
registry/late-delivery/
├── aliases.json              where champion points now, plus every move ever made
├── 1.0.0/
│   ├── model.joblib
│   └── record.json           data hashes, params, metrics, environment, parent
└── 1.1.0/
    ├── model.joblib
    ├── record.json
    └── MODEL_CARD.md
```

There's no server and no database: a folder in your repository and about 80 lines of Python. That's enough to see every moving part of a registry clearly, and each function maps onto an MLflow call (there's a table at the end).

```mermaid caption="The lifecycle this lesson builds: register, compare, promote, serve, and roll back by moving an alias"

    [*] --> Registered: register() writes folder + record
    Registered --> Champion: set_alias("champion") after the gate passes

    Retired --> Champion: rollback moves the alias back
```

## Step 1: Data for two months, and a fixed holdout

The team trained version 1.0.0 on January's orders. February's orders have now arrived. Every version will be scored on the same frozen holdout file, so their metrics are comparable.

```python run
import hashlib
import json
import platform
import shutil
from datetime import datetime, timezone
from pathlib import Path

import joblib
import numpy as np
import pandas as pd
import sklearn
from sklearn.compose import ColumnTransformer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import roc_auc_score
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

def make_orders(n, seed):
    rng = np.random.default_rng(seed)
    distance_km = rng.gamma(shape=2.0, scale=2.0, size=n).round(2)
    items = rng.integers(1, 9, size=n)
    hour = rng.integers(10, 23, size=n)
    raining = (rng.random(n) < 0.25).astype(int)
    rush = (hour >= 17) & (hour <= 19)
    logit = -4.0 + 0.45 * distance_km + 0.15 * items + 1.2 * raining + 0.9 * rush
    late = (rng.random(n) < 1 / (1 + np.exp(-logit))).astype(int)
    return pd.DataFrame({"distance_km": distance_km, "items": items,
                         "hour": hour, "raining": raining, "late": late})

Path("data").mkdir(exist_ok=True)
make_orders(2000, seed=23).to_csv("data/orders_2026_01.csv", index=False)
make_orders(3000, seed=24).to_csv("data/orders_2026_02.csv", index=False)
make_orders(1000, seed=99).to_csv("data/holdout.csv", index=False)

FEATURES = ["distance_km", "items", "hour", "raining"]

def train(files):
    frame = pd.concat([pd.read_csv(f) for f in files], ignore_index=True)
    prep = ColumnTransformer([
        ("scale", StandardScaler(), ["distance_km", "items"]),
        ("hour", OneHotEncoder(handle_unknown="ignore"), ["hour"]),
    ], remainder="passthrough")
    model = Pipeline([("prep", prep), ("clf", LogisticRegression(max_iter=1000))])
    return model.fit(frame[FEATURES], frame["late"]), len(frame)

def holdout_auc(model):
    holdout = pd.read_csv("data/holdout.csv")
    return round(roc_auc_score(holdout["late"], model.predict_proba(holdout[FEATURES])[:, 1]), 4)

print("data ready:", sorted(p.name for p in Path("data").iterdir()))
```

## Step 2: Register immutable versions

`register()` is the heart of the registry. Three details carry the weight:

- It **refuses to overwrite** an existing version. Immutability isn't a promise in a README; it's an exception.
- It builds the version in a temporary folder and **renames** it into place at the end, so a crash never leaves a half-registered version that looks complete.
- It hashes **every training file** and **the artifact** it just wrote, and records the parent version it replaces.

```python run title="registry.py"
REGISTRY = Path("registry")

def sha256_file(path):
    with open(path, "rb") as f:
        return hashlib.file_digest(f, "sha256").hexdigest()

def register(model, name, version, *, training_files, rows, params, metrics, parent=None, threshold=0.5):
    final = REGISTRY / name / version
    if final.exists():
        raise FileExistsError(f"{name} {version} is already registered; versions are immutable")
    staging = REGISTRY / name / f".{version}.tmp"
    shutil.rmtree(staging, ignore_errors=True)
    staging.mkdir(parents=True)
    joblib.dump(model, staging / "model.joblib")
    record = {
        "name": name,
        "version": version,
        "created_at": datetime.now(timezone.utc).isoformat(timespec="seconds"),
        "artifact_sha256": sha256_file(staging / "model.joblib"),
        "training_data": [{"file": str(f), "sha256": sha256_file(f)} for f in training_files],
        "training_rows": rows,
        "params": params,
        "metrics": metrics,
        "schema": {"features": FEATURES, "threshold": threshold},
        "environment": {"python": platform.python_version(), "scikit-learn": sklearn.__version__,
                        "numpy": np.__version__, "pandas": pd.__version__},
        "parent": parent,
    }
    (staging / "record.json").write_text(json.dumps(record, indent=2))
    staging.rename(final)
    return record

def read_record(name, version):
    return json.loads((REGISTRY / name / version / "record.json").read_text())
```

Register January's model as 1.0.0, and then try to register 1.0.0 a second time:

```python run
january = ["data/orders_2026_01.csv"]
model_v1, rows_v1 = train(january)
record_v1 = register(model_v1, "late-delivery", "1.0.0", training_files=january, rows=rows_v1,
                     params={"estimator": "LogisticRegression", "max_iter": 1000},
                     metrics={"holdout_roc_auc": holdout_auc(model_v1)})
print("registered", record_v1["version"], "artifact", record_v1["artifact_sha256"][:16],
      "holdout AUC", record_v1["metrics"]["holdout_roc_auc"])

try:
    register(model_v1, "late-delivery", "1.0.0", training_files=january, rows=rows_v1, params={}, metrics={})
except FileExistsError as error:
    print("refused:", error)
```

## Step 3: Aliases with a history that's never rewritten

Aliases live in one small JSON file. `current` says where each alias points now; `history` records every move with the reason and time. The history is only appended to, never edited, so "what was serving at 14:05 on Tuesday?" always has an answer.

```python run
def aliases_file(name):
    return REGISTRY / name / "aliases.json"

def read_aliases(name):
    path = aliases_file(name)
    return json.loads(path.read_text()) if path.exists() else {"current": {}, "history": []}

def set_alias(name, alias, version, reason):
    if not (REGISTRY / name / version / "record.json").exists():
        raise ValueError(f"{name} {version} is not registered")
    aliases = read_aliases(name)
    aliases["history"].append({
        "alias": alias, "from": aliases["current"].get(alias), "to": version, "reason": reason,
        "at": datetime.now(timezone.utc).isoformat(timespec="seconds"),
    })
    aliases["current"][alias] = version
    aliases_file(name).write_text(json.dumps(aliases, indent=2))

set_alias("late-delivery", "champion", "1.0.0", reason="first production model")
print(json.dumps(read_aliases("late-delivery")["current"]))
```

`set_alias` checks that the version exists, so a typo like `"1.1"` fails immediately instead of pointing production at nothing.

## Step 4: Retrain, compare on the holdout, and promote through a gate

Now retrain on January plus February. The request and response contract hasn't changed (same features, same output), so by the convention from the Notes lesson this is a MINOR bump: **1.1.0**, with 1.0.0 as its parent.

```python run
both_months = ["data/orders_2026_01.csv", "data/orders_2026_02.csv"]
model_v11, rows_v11 = train(both_months)
record_v11 = register(model_v11, "late-delivery", "1.1.0", training_files=both_months, rows=rows_v11,
                      params={"estimator": "LogisticRegression", "max_iter": 1000},
                      metrics={"holdout_roc_auc": holdout_auc(model_v11)}, parent="1.0.0")

champion = read_record("late-delivery", read_aliases("late-delivery")["current"]["champion"])
print(f"{'version':8} {'rows':>6} {'holdout AUC':>12}")
for record in [champion, record_v11]:
    print(f"{record['version']:8} {record['training_rows']:6} {record['metrics']['holdout_roc_auc']:12.4f}")
```

Registering a version doesn't deploy it. Promotion is a separate, deliberate step with written rules. This gate allows a tiny drop (0.002 AUC is within the noise of a 1,000-row holdout) but refuses a real regression or any change to the feature list:

```python run
def promotion_problems(candidate, champion, max_auc_drop=0.002):
    problems = []
    drop = champion["metrics"]["holdout_roc_auc"] - candidate["metrics"]["holdout_roc_auc"]
    if drop > max_auc_drop:
        problems.append(f"holdout AUC fell by {drop:.4f} (allowed {max_auc_drop})")
    if candidate["schema"]["features"] != champion["schema"]["features"]:
        problems.append("feature list changed: that is a MAJOR version, not a promotion")
    return problems

problems = promotion_problems(record_v11, champion)
if problems:
    print("not promoted:", "; ".join(problems))
else:
    set_alias("late-delivery", "champion", "1.1.0", reason="retrained on Jan+Feb; holdout AUC held up")
    print("champion is now", read_aliases("late-delivery")["current"]["champion"])
```

## Step 5: Serve by alias, and refuse a tampered artifact

The service now asks the registry for "whatever `champion` points to" instead of a hard-coded file. Before unpickling, it checks the artifact's hash against the record. That catches a corrupted download or an edited file, and because unpickling can run code, it means an artifact that isn't the one you registered is never even opened.

```python run title="app/registry_loader.py"
def load_alias(name, alias):
    version = read_aliases(name)["current"][alias]
    folder = REGISTRY / name / version
    record = json.loads((folder / "record.json").read_text())
    actual = sha256_file(folder / "model.joblib")
    if actual != record["artifact_sha256"]:
        raise RuntimeError(f"{name} {version}: artifact hash {actual[:12]} does not match "
                           f"the registry record {record['artifact_sha256'][:12]}; refusing to load")
    return joblib.load(folder / "model.joblib"), record
```

Plug it into the FastAPI lifespan. `/health` now reports both the version and the start of the artifact hash, so anyone can check what's serving without logging into the server.

```python run title="app/main.py"
from contextlib import asynccontextmanager
from fastapi import FastAPI
from fastapi.testclient import TestClient

state = {}

@asynccontextmanager
async def lifespan(app):
    state["model"], state["record"] = load_alias("late-delivery", "champion")
    yield
    state.clear()

app = FastAPI(lifespan=lifespan)

@app.get("/health")
def health():
    record = state["record"]
    return {"status": "ok", "model_version": record["version"], "artifact_sha256": record["artifact_sha256"][:12]}

with TestClient(app) as client:
    print(client.get("/health").json())
```

Now simulate the file being altered after registration: one extra byte at the end of 1.1.0's artifact.

```python run
artifact = REGISTRY / "late-delivery" / "1.1.0" / "model.joblib"
original_bytes = artifact.read_bytes()
artifact.write_bytes(original_bytes + b"\x00")

try:
    with TestClient(app) as client:
        print("served (this should not happen)")
except RuntimeError as error:
    print("startup refused:", error)

artifact.write_bytes(original_bytes)          # put the real file back
with TestClient(app) as client:
    print("after restoring:", client.get("/health").json()["model_version"])
```

One byte was enough. In a container, that `RuntimeError` makes uvicorn print `Application startup failed. Exiting.`, the container stops, and the health check never goes green, so the bad artifact never takes traffic.

## Step 6: Roll back by moving the alias

Suppose 1.1.0 misbehaves in production. Rollback doesn't rebuild or retrain anything; it points `champion` back at the version it replaced, which is recorded in the history:

```python run
def rollback(name, alias, reason):
    history = [move for move in read_aliases(name)["history"] if move["alias"] == alias]
    previous = history[-1]["from"]
    if previous is None:
        raise ValueError(f"{alias} has no earlier version to roll back to")
    set_alias(name, alias, previous, reason=f"rollback: {reason}")

rollback("late-delivery", "champion", reason="late-rate complaints in one city")
for move in read_aliases("late-delivery")["history"]:
    print(f"{move['alias']}: {move['from']} -> {move['to']}  ({move['reason']})")
```

Three moves, all visible. The 1.1.0 folder is untouched, so it can be investigated, fixed as 1.1.1 or 1.2.0, and promoted again later.

:::video 97i9pOa2EyE
What to watch for: what MAJOR, MINOR, and PATCH promise to the people depending on a library. This course borrows the same promises for models: MAJOR means clients must change, MINOR means behaviour changed under the same contract, PATCH means nothing observable changed.
:::

## Step 7: Generate the model card from the record

A model card written by hand drifts from the truth the first time someone retrains without updating it. Generate the factual parts from the record, and keep only the judgment (intended use, limitations) hand-written:

```python run
def write_model_card(record, intended_use, not_for, limitations):
    data_lines = [f"- `{d['file']}` (sha256 `{d['sha256'][:12]}...`)" for d in record["training_data"]]
    card = "\n".join([
        f"# Model card: {record['name']} {record['version']}",
        "",
        f"**Intended use.** {intended_use}",
        f"**Not for.** {not_for}",
        "",
        "## Training data",
        *data_lines,
        f"- {record['training_rows']:,} rows in total",
        "",
        "## Performance",
        f"- Holdout ROC AUC: {record['metrics']['holdout_roc_auc']} (fixed holdout, `data/holdout.csv`)",
        "",
        "## Known limitations",
        *[f"- {item}" for item in limitations],
        "",
        f"Inputs: {', '.join(record['schema']['features'])}. Threshold: {record['schema']['threshold']}. "
        f"Parent version: {record['parent']}. Built with scikit-learn {record['environment']['scikit-learn']}.",
    ])
    path = REGISTRY / record["name"] / record["version"] / "MODEL_CARD.md"
    path.write_text(card + "\n")
    return card

print(write_model_card(
    record_v11,
    intended_use="Rank today's orders by risk of arriving late, to plan driver capacity.",
    not_for="Judging individual drivers or restaurants; the model has no driver features.",
    limitations=["Trained only on orders placed 10:00-22:59; other hours get no hour signal.",
                 "Not yet evaluated separately by city or weather."],
))
```

`MODEL_CARD.md` sits inside the version folder, so it's versioned with the artifact. Writing it doesn't break immutability: the record and the artifact are the parts that never change, and the hash check covers the artifact.

## Step 8: The same registry in MLflow

Every function you wrote has an MLflow equivalent, so moving to a shared server later changes the calls, not the ideas:

| This lesson | MLflow (3.x) |
| --- | --- |
| `register(model, name, version, ...)` | `mlflow.sklearn.log_model(sk_model=model, name="model", registered_model_name=name)` inside a run |
| `record.json` params and metrics | `mlflow.log_params(...)`, `mlflow.log_metrics(...)` |
| `training_data` hashes | `mlflow.log_input(mlflow.data.from_pandas(...), context="training")`, plus a `data_sha256` tag if you want the file hash |
| Semantic version string | MLflow's integer version, with `client.set_model_version_tag(name, version, "semver", "1.1.0")` |
| `set_alias(name, "champion", version)` | `client.set_registered_model_alias(name, "champion", version)` |
| `load_alias(name, "champion")` | `mlflow.sklearn.load_model("models:/late-delivery@champion")` |
| `aliases.json` history | Not kept by MLflow automatically; record moves in tags or your deploy log |

That last row is a real difference worth knowing: a registry service tells you where an alias points *now*, and you may still need your own record of where it pointed *then*.

## The finished registry

```python run
for path in sorted(REGISTRY.rglob("*")):
    if path.is_file():
        print(path, f"({path.stat().st_size:,} bytes)")
```

Commit `registry/` while the artifacts are small. When they grow to many megabytes, keep the records and aliases in Git and move the `model.joblib` files to object storage (an S3-compatible bucket, for example), still addressed by version and still checked against the recorded hash.

:::quiz
Q: Why does `register()` raise instead of overwriting when a version already exists?
- [ ] To save disk space
  The point isn't space; it's that a version number must always mean the same bytes.
- [x] Because once a version might be deployed or written in a log, changing its contents makes every past reference to it untrue
  Immutability is what lets an incident review trust "1.1.0 was serving". A fix gets a new version number.
- [ ] Because joblib can't overwrite files
  joblib overwrites files without complaint; the check exists because it would.

Q: Why does `load_alias` hash the artifact *before* calling `joblib.load`?
- [ ] Hashing is faster after loading
  Order doesn't affect hashing speed; it affects what runs first.
- [x] Because unpickling can run code, and a file that doesn't match the record shouldn't get that chance
  Checking first catches corruption and tampering before the file is ever opened as a model.
- [ ] Because the record stores the hash of the loaded Python object
  The record stores the hash of the file's bytes, written right after `joblib.dump`.

Q: 1.1.0 is champion and misbehaving. What does `rollback()` change on disk?
- [ ] It deletes the 1.1.0 folder
  Deleting it would destroy the evidence you need to investigate, and the version could never be reproduced.
- [x] It appends a move to the alias history and points `champion` at 1.0.0
  Only `aliases.json` changes. Both version folders stay exactly as registered.
- [ ] It retrains 1.0.0 from January's data
  Unnecessary: 1.0.0's artifact is still in the registry, and its hash proves it's unchanged.
:::

:::takeaways
- A version is a folder that is written once: artifact, record, and (optionally) a model card.
- Records hash every training file and the artifact, and name the parent version.
- Aliases move; their history is appended, never edited, so rollback is one recorded move.
- Promotion goes through a written gate on a fixed holdout; registering is not deploying.
- Verify the artifact's hash before unpickling, and expose version and hash on `/health`.
:::

## Ideas to extend it

- Add a `challenger` alias and have the service score each request with both models, returning only the champion's answer and logging the challenger's for comparison (called shadow deployment).
- Pass the version into the Docker build with `ARG MODEL_VERSION` and `COPY registry/late-delivery/${MODEL_VERSION}/ models/`, and tag the image with the same version.
- Make `register()` record `git_commit()` from the Notes lesson, and refuse to register from a `-dirty` working tree.
