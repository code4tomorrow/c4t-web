This workout summary has the same three lines of math pasted three times. Look closely at the output:

```python run title="workout_v1.py"
warmup = 185
run_time = 1260
cooldown = 307

minutes = warmup // 60
seconds = warmup % 60
print(f"Warm-up: {minutes}:{seconds:02d}")

minutes = run_time // 60
seconds = run_time % 60
print(f"Run: {minutes}:{seconds:02d}")

minutes = cooldown // 60
seconds = cooldown % 60
print(f"Cool-down: {minutes}:{seconds}")
```

`5:7` should be `5:07`. The first two copies use `:02d`, which pads a number to two digits with a leading zero, but whoever pasted the third copy dropped it. This is the real cost of copy and paste: every copy is a separate place for a bug to hide, and fixing one copy doesn't fix the others. A **function** gives the logic one home, so you write it once, test it once, and fix it once.

## One copy instead of three: `def`

Here's the same program with the time math moved into a function:

```python run title="workout_v2.py"
def format_time(total_seconds):
    minutes = total_seconds // 60
    seconds = total_seconds % 60
    return f"{minutes}:{seconds:02d}"

print("Warm-up:", format_time(185))
print("Run:", format_time(1260))
print("Cool-down:", format_time(307))
```

Read the first line piece by piece:

-   `def` tells Python you're **defining** a function.
-   `format_time` is its name. Use the same naming rules as variables, and pick a verb or a description of what it gives back.
-   `(total_seconds)` is the **parameter**: a variable that will hold whatever value the caller passes in.
-   The colon and the indented block form the **body**, the code that runs each time the function is called.

Defining a function doesn't run its body. Python just remembers it. The body runs when you **call** the function by writing its name with parentheses, like `format_time(307)`. The value inside the parentheses at the call is the **argument**, and it becomes the parameter's value for that call.

Step through this and watch the stack on the right. Each call adds a new box (a **frame**) with its own variables. When the call returns, the box disappears and its answer lands in the variable on the left.

:::trace Watch a frame appear for each call
```python
def format_time(total_seconds):
    minutes = total_seconds // 60
    seconds = total_seconds % 60
    return f"{minutes}:{seconds:02d}"

warmup = format_time(185)
cooldown = format_time(307)
print(warmup, cooldown)
```
:::

Notice that the trace jumps from line 1 straight to line 6 at the start. Python reads the `def` and moves on; it only enters the body at the call.

## Parameters carry values in

A function can take several parameters, separated by commas. Arguments match parameters **by position**: first to first, second to second. You can also give a parameter a **default value**, used when the caller leaves it out.

```python run title="heroes.py"
def describe_hero(name, power, level=1):
    return f"{name} (level {level}) uses {power}!"

print(describe_hero("Nova", "light beam", 7))
print(describe_hero("Rook", "stone wall"))
print(describe_hero(level=3, power="echo", name="Wren"))
print(describe_hero("light beam", "Nova"))
```

Line by line:

-   Three arguments fill all three parameters.
-   Rook gets the default `level=1` because no third argument was passed.
-   **Keyword arguments** (`name="Wren"`) match by name, so their order doesn't matter.
-   The last call swaps the first two arguments. Python can't tell that's a mistake; it just matches by position and produces nonsense.

Leave out a parameter that has no default and Python refuses to run the call:

```python run raises
def describe_hero(name, power, level=1):
    return f"{name} (level {level}) uses {power}!"

print(describe_hero("Nova"))
```

The message names the function and the exact parameter that's missing, which makes this one of the friendlier errors to fix.

## `return` sends a value back (and `print` doesn't)

`print` shows text to the person at the screen. `return` hands a value back to the code that made the call, so that code can store it, add it up, compare it, or pass it to another function. They look similar when you test in the Shell, which is why they get confused so often.

```python run raises title="tax.py"
def add_tax_return(price):
    return price * 1.08

def add_tax_print(price):
    print(price * 1.08)

total = add_tax_return(10) + add_tax_return(5)
print("Total with return:", round(total, 2))

total = add_tax_print(10) + add_tax_print(5)
print("Total with print:", total)
```

The `return` version works. The `print` version *shows* 10.8 and 5.4, then crashes. A function with no `return` gives back a special value called `None`, so Python ends up trying to compute `None + None`. Read the last line of the error with that in mind: `NoneType` is the type of `None`.

`return` also **ends the function** on the spot. That lets you write a chain of checks without `elif`, because the first one that matches stops everything else:

```python run title="wind.py"
def wind_label(kmh):
    if kmh >= 62:
        return "gale"
    if kmh >= 39:
        return "strong wind"
    if kmh >= 20:
        return "breezy"
    return "light"

for speed in [8, 25, 45, 70]:
    print(f"{speed} km/h: {wind_label(speed)}")
```

For 70 km/h the first `if` returns `"gale"` and the other checks never run.

## Variables inside a function stay inside

Variables created inside a function, including its parameters, are **local**. They're created when the call starts and thrown away when it ends. Code outside the function can't see them:

```python run raises
def format_time(total_seconds):
    minutes = total_seconds // 60
    seconds = total_seconds % 60
    return f"{minutes}:{seconds:02d}"

print(format_time(95))
print(minutes)
```

The function worked and printed `1:35`, but `minutes` vanished when the call ended. This is a feature: you can use simple names like `minutes` inside many functions without them overwriting each other.

The flip side surprises nearly everyone. Predict what this prints before you step through it:

:::trace Two variables named `coins`
```python
coins = 10

def collect(coins):
    coins = coins + 5
    print("Inside:", coins)

collect(coins)
print("Outside:", coins)
```
:::

There are two separate variables called `coins`: one in the Global frame and one in the `collect()` frame. The function changes its own copy to 15, and the outside one stays at 10. The fix is the rule that makes functions easy to reason about: **values go in through parameters and come out through `return`**.

```python run title="coins_fixed.py"
def collect(coins):
    return coins + 5

coins = 10
coins = collect(coins)
print("Outside:", coins)
```

## Docstrings say what a function is for

A **docstring** is a string in triple quotes on the first line of the body. Python stores it with the function, and `help()` prints it:

```python run title="format_time.py"
def format_time(total_seconds):
    """Turn a number of seconds into an m:ss string, like 307 -> '5:07'."""
    minutes = total_seconds // 60
    seconds = total_seconds % 60
    return f"{minutes}:{seconds:02d}"

help(format_time)
print(format_time(307))
```

A good docstring says what goes in, what comes out, and gives one example. Write it before the body and you'll often find you understand the function better before you've typed a line of it.

## Mistakes worth recognizing on sight

:::warning
**Calling a function before Python has read its `def`.** Python runs a file from top to bottom, so a call on line 1 to a function defined on line 5 fails with `NameError: name '...' is not defined`. Put your function definitions at the top of the file and the code that uses them below.
:::

:::warning
**Forgetting the parentheses.** `print(format_time)` doesn't call the function; it prints something like `<function format_time at 0x10a3f2e80>`, which is Python describing the function itself. If you see that, add the parentheses and the argument.
:::

:::warning
**Printing when you meant to return.** If a calculation shows the right number but then the next line crashes with something about `NoneType`, look for a `print` where a `return` should be.
:::

:::quiz
Q: What does this print? `def double(n):` with the body `n * 2`, then `print(double(4))`.
- [ ] `8`
  The body calculates 8, but nothing sends it back.
- [x] `None`
  There's no `return`, so the function gives back `None`, and that's what gets printed.
- [ ] An error
  Calculating a value and not using it is allowed; it just gets thrown away.

Q: This program has `def greet():` with the body `print("A")`, then `print("B")`, then `greet()`. What appears, in order?
- [ ] A then B
  The `def` only defines `greet`; its body doesn't run until the call on the last line.
- [x] B then A
  Python skips over the body when it reads the `def`, prints B, and then prints A when `greet()` is called.
- [ ] Only B
  `greet()` on the last line does call the function, so A is printed too.

Q: `x = 5`, then `def bump(x):` with the body `x = x + 1` and `return x`, then `bump(x)` and `print(x)`. What prints?
- [x] `5`
  `bump` changes its own local `x` and returns 6, but the result isn't stored, so the global `x` is still 5.
- [ ] `6`
  You'd need `x = bump(x)` to keep the 6.
- [ ] An error, because `x` is used twice
  A parameter can share a name with a global variable; they're separate variables.

Q: Which call to `def describe_hero(name, power, level=1)` gives `"Ivy (level 1) uses vines!"`?
- [ ] `describe_hero("vines", "Ivy")`
  Arguments match by position, so this makes "vines" the name.
- [x] `describe_hero(power="vines", name="Ivy")`
  Keyword arguments match by name, so order doesn't matter, and `level` uses its default.
- [ ] `describe_hero("Ivy")`
  `power` has no default, so this raises a `TypeError`.
:::

:::takeaways
- `def name(parameters):` defines a function; the body only runs when you call `name(arguments)`.
- Arguments match parameters by position unless you use keyword arguments; defaults fill in anything left out.
- `return` hands a value back and ends the call. With no `return`, a function gives back `None`.
- Variables inside a function are local to that call. Pass values in with parameters and get results out with `return`.
- A docstring on the first line of the body explains the function, and `help()` shows it.
:::
