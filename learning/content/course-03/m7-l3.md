- Use `try` and `except ValueError` to validate decimal input.

Half of these exercises hand you broken code. Resist the urge to rewrite it from scratch; the skill you're practicing is finding the *one* thing that's wrong. Read the error first, form a guess, and test the guess. When there's no error message, use `print(f"{name=}")` or Thonny's debugger to check values.

## Warm-up: read before you fix

This checkout program crashes. Without changing anything, answer three questions: What type of error is it? On which line and in which function does it happen? Which value in the data is the real culprit?

```python run raises title="checkout.py"
def price_with_discount(price, percent):
    return price - price * percent / 100

def checkout(cart):
    total = 0
    for item in cart:
        total = total + price_with_discount(item["price"], item["discount"])
    return total

cart = [{"price": 20, "discount": 10}, {"price": 15, "discount": "5"}]
print(checkout(cart))
```

:::solution
-   **Type:** `TypeError`, because `/` was used with a string and a number.
-   **Where:** line 2, in `price_with_discount`. It was called from line 7 in `checkout`, which was called from line 11.
-   **Culprit:** the second item's discount is `"5"`, a string, not the number `5`.

Here's the sneaky part: `15 * "5"` doesn't crash. Multiplying a string by a whole number repeats it, so Python made `"555555555555555"` and only failed one step later, at `/ 100`. The fix is in the data: change `"5"` to `5`. The crash line and the cause are often a few steps apart, which is why you check the *values* on the failing line, not just the line itself.
:::

### Exercise 1: A birthday card with two bugs

This program has two bugs. Fix the first, run it, read the next error, and fix that too.

```python run raises title="birthday.py" input="Sam|14"
name = input("Name: ")
age = input("Age: ")
print("Happy birthday, " + nmae + "! Next year you'll be " + age + 1)
```

When it works, it should print:

```text
Happy birthday, Sam! Next year you'll be 15
```

:::hint
The first error names the exact word Python doesn't recognize; compare it, letter by letter, with the variables the program creates. After that, remember what type `input()` returns. Can you add `1` to a string? And can you join a number onto a string with `+`?
:::

:::solution
```python run title="birthday.py" input="Sam|14"
name = input("Name: ")
age = int(input("Age: "))
print(f"Happy birthday, {name}! Next year you'll be {age + 1}")
```

Bug 1 was the typo `nmae` (a `NameError`). Bug 2 was a `TypeError`: `age` was the string `"14"`, so `age + 1` can't work. Converting with `int()` fixes the math, and the f-string handles turning the number back into text.
:::

### Exercise 2: Ask for a price

Write `ask_price(prompt)` that keeps asking until the user types a number of zero or more, then returns it as a float. Decimals like `4.50` must work.

```text
Price: $4
  Type a number like 4.50, without the $ sign.
Price: 
  Type a number like 4.50, without the $ sign.
Price: -2
  A price can't be negative.
Price: 4.50
You entered 4.50
```

:::hint
`.isdigit()` won't work here because of the decimal point. Use `try:` with `float(text)` and `except ValueError:`. Inside a `while True` loop, `continue` sends you back for another try, and `return` ends everything once the price is good.
:::

:::solution
```python run title="ask_price.py" input="$4||-2|4.50"
def ask_price(prompt):
    """Ask until the user types a number of 0 or more; return it as a float."""
    while True:
        text = input(prompt).strip()
        try:
            price = float(text)
        except ValueError:
            print("  Type a number like 4.50, without the $ sign.")
            continue
        if price < 0:
            print("  A price can't be negative.")
            continue
        return price

price = ask_price("Price: ")
print(f"You entered {price:.2f}")
```

There are two kinds of bad input, so there are two checks: `except` handles text that isn't a number at all, and the `if` handles numbers that are the wrong size.
:::

### Exercise 3: The podium is off by one

This should print the top three finishers as 1 Mia, 2 Theo, 3 Ana. It prints the wrong names, then crashes.

```python run raises title="podium.py"
finishers = ["Mia", "Theo", "Ana"]
for place in range(1, 4):
    print(place, finishers[place])
```

:::hint
People count places from 1. Lists count positions from 0. Which list index holds the first-place finisher?
:::

:::solution
```python run title="podium.py"
finishers = ["Mia", "Theo", "Ana"]
for place in range(1, 4):
    print(place, finishers[place - 1])
```

`finishers[place - 1]` turns place 1 into index 0. (Python also has `enumerate(finishers, start=1)`, which gives you the number and the item together, but the subtraction makes the off-by-one visible.)
:::

### Exercise 4: The snack shop

Use this price list. Keep asking for items until the customer types `done`. Add each known item to the total; for anything else, print a polite message instead of crashing. Then print the total.

```python
prices = {"chips": 1.50, "juice": 2.00, "apple": 0.75}
```

```text
Item (or done): chips
Item (or done): cookie
  Sorry, we don't sell cookie.
Item (or done): juice
Item (or done): chips
Item (or done): done
Total: $5.00
```

:::hint
`prices["cookie"]` would raise a `KeyError`. Check first with `if item in prices:`, which is `True` only when the key exists.
:::

:::solution
```python run title="snack_shop.py" input="chips|cookie|juice|Chips|done"
prices = {"chips": 1.50, "juice": 2.00, "apple": 0.75}
total = 0
while True:
    item = input("Item (or done): ").strip().lower()
    if item == "done":
        break
    if item in prices:
        total = total + prices[item]
    else:
        print(f"  Sorry, we don't sell {item}.")
print(f"Total: ${total:.2f}")
```

`.lower()` lets `Chips` match the key `"chips"`. Adding a new snack to the shop is now a one-word change to the dictionary; none of the loop needs to change.
:::

### Exercise 5: The high score that's too low

No crash, no traceback, just a wrong answer. The scores entered are 9, 10, and 7, but the program says the high score is 9.

```python run title="high_score.py" input="9|10|7|done"
best = ""
while True:
    entry = input("Score (or done): ")
    if entry == "done":
        break
    if entry > best:
        best = entry
print("High score:", best)
```

Step through a shorter run and watch `best` refuse to change when 10 arrives:

:::trace Watch `best` ignore the 10
```python input="9|10|done"
best = ""
while True:
    entry = input("Score: ")
    if entry == "done":
        break
    if entry > best:
        best = entry
print("High score:", best)
```
:::

:::hint
Look at the quotes around the values in the trace. How does Python compare two *strings*? It goes character by character, like a dictionary does with words. Which comes first, `"1"` or `"9"`?
:::

:::solution
```python run title="high_score.py" input="9|10|7|done"
best = 0
while True:
    entry = input("Score (or done): ")
    if entry == "done":
        break
    score = int(entry)
    if score > best:
        best = score
print("High score:", best)
```

As strings, `"10"` is "less than" `"9"`, because the first characters are compared first and `"1"` comes before `"9"`. Converting to `int` compares the numbers instead. This is the most dangerous kind of bug: it doesn't crash, so you only catch it if you test with an input whose answer you already know.
:::

### Exercise 6: Count the words

Count how many times each word appears in a sentence, print every count, then print the most common word.

```python
sentence = "the cat and the hat and the bat"
```

```text
the: 3
cat: 1
and: 2
hat: 1
bat: 1
Most common: the (3 times)
```

:::hint
`sentence.split()` turns the sentence into a list of words. Start with an empty dictionary, `counts = {}`. For each word, `counts.get(word, 0) + 1` gives the new count whether or not the word has been seen before. Find the most common with a best-so-far loop over `counts.items()`.
:::

:::solution
```python run title="word_count.py"
sentence = "the cat and the hat and the bat"
counts = {}
for word in sentence.lower().split():
    counts[word] = counts.get(word, 0) + 1

top_word = ""
top_count = 0
for word, count in counts.items():
    print(f"{word}: {count}")
    if count > top_count:
        top_word = word
        top_count = count

print(f"Most common: {top_word} ({top_count} times)")
```

Dictionaries remember the order keys were added, which is why the words print in the order they first appear. The `.get(word, 0)` trick is the standard way to count with a dictionary.
:::

### Challenge: An arcade high-score table

Build a small command-driven app that keeps each player's best score in a dictionary. It understands four commands:

-   `add NAME SCORE` records a score, but only replaces a player's entry if the new score is higher.
-   `show` lists every player and their best score.
-   `best` names the top player.
-   `quit` ends the program.

Anything else, a missing part, or a score that isn't a whole number should get a helpful message, never a traceback.

```text
> add Ana 1200
  Saved: Ana 1200
> add Leo 950
  Saved: Leo 950
> add Ana 800
  Ana's best is still 1200.
> add Mo lots
  The score must be a whole number.
> best
  Top player: Ana with 1200
> show
  Ana: 1200
  Leo: 950
> quit
```

:::hint
`command.split()` turns `"add Ana 1200"` into `["add", "Ana", "1200"]`. Check `len(parts)` before using `parts[1]` or `parts[2]`, or you'll hit an `IndexError`. Put `int(parts[2])` inside `try`. Write a function for each command, such as `add_score(scores, name, points)`, and keep the main loop to choosing which one to call.
:::

:::solution
```python run title="arcade.py" input="add Ana 1200|add Leo 950|add Ana 800|add Mo lots|add|best|show|dance|quit"
def add_score(scores, name, points):
    """Record points for name if it beats their best (or they're new)."""
    if name not in scores or points > scores[name]:
        scores[name] = points
        print(f"  Saved: {name} {points}")
    else:
        print(f"  {name}'s best is still {scores[name]}.")


def show_scores(scores):
    """Print every player's best score."""
    if len(scores) == 0:
        print("  No scores yet.")
    for name, points in scores.items():
        print(f"  {name}: {points}")


def show_best(scores):
    """Print the player with the highest score."""
    top_name = ""
    top_points = -1
    for name, points in scores.items():
        if points > top_points:
            top_name = name
            top_points = points
    if top_name == "":
        print("  No scores yet.")
    else:
        print(f"  Top player: {top_name} with {top_points}")


scores = {}
while True:
    parts = input("> ").split()
    if len(parts) == 0:
        continue
    command = parts[0].lower()

    if command == "quit":
        break
    elif command == "show":
        show_scores(scores)
    elif command == "best":
        show_best(scores)
    elif command == "add":
        if len(parts) != 3:
            print("  Use: add NAME SCORE")
            continue
        try:
            points = int(parts[2])
        except ValueError:
            print("  The score must be a whole number.")
            continue
        add_score(scores, parts[1], points)
    else:
        print("  Commands: add NAME SCORE, show, best, quit")
```

The order of checks in the `add` branch matters: count the parts *before* reading `parts[2]`, and convert inside `try` *before* calling `add_score`. By the time `add_score` runs, its inputs are guaranteed to be clean, so the function itself stays simple. That "check at the door" design is exactly what your capstone will need.
:::
