A club sign-up program gives 2 free stickers with every T-shirt. Someone orders 3 shirts:

```python run title="stickers.py" input="3"
shirts = input("How many club T-shirts? ")
print("You'll get", shirts * 2, "stickers (2 per shirt).")
```

Thirty-three stickers. No error, no warning, just a wrong answer that a real person would see. The cause is the most important fact on this page: **`input()` always gives you text**, even when the person types digits. `"3" * 2` repeats the text twice, giving `"33"`. By the end of this page you'll know how to fix it, and why it happened.

## A string is a row of characters

Text in Python is a **string** (`str`): a sequence of characters in a fixed order. Each character has a numbered position called an **index**. Counting starts at 0, and negative numbers count back from the end:

```text
 R   o   b   o   t   i   c   s
 0   1   2   3   4   5   6   7
-8  -7  -6  -5  -4  -3  -2  -1
```

Square brackets pick out characters. Put a colon inside them to take a **slice**, a piece of the string from one index up to, but not including, another:

```python run title="string_parts.py"
club = "Robotics"
print(len(club))
print(club[0], club[1], club[-1])
print(club[0:4])
print(club[4:])
print(club[:3].upper())
```

`len()` counts the characters: 8. `club[0:4]` takes indexes 0, 1, 2 and 3, and stops *before* 4, giving `Robo`. Leave out a number and the slice runs to that end of the string, so `club[4:]` is everything from index 4 on. The "up to but not including" rule seems odd at first, but it means `club[:4] + club[4:]` always rebuilds the whole word.

Ask for an index that doesn't exist and Python stops:

```python run raises
club = "Robotics"
print(club[8])
```

The last index of an 8-character string is 7, because counting started at 0.

## String methods clean and change text

A **method** is a function that belongs to a value. You call it with a dot: `club.upper()`. Strings have dozens of methods, and a handful do most of the work in programs that read what people type:

```python run title="clean_name.py"
raw = "   mAYA   chen  "
print("[" + raw + "]")
print("[" + raw.strip() + "]")
print("[" + raw.strip().title() + "]")
print("[" + raw.strip().lower() + "]")
print("chess club".replace("chess", "drama"))
print("Robotics".count("o"))
```

The square brackets are printed only so you can see where the spaces are. `.strip()` removes spaces from both **ends**, but leaves the spaces in the middle alone. `.title()` capitalizes the first letter of each word and lowercases the rest, and `.lower()` and `.upper()` change everything. You can chain methods, as in `raw.strip().title()`: Python runs them left to right, each on the result of the one before.

Here is the rule that causes the most bugs: **strings never change.** Every method gives back a *new* string and leaves the original as it was. So this does nothing useful:

```python run
name = "  maya  "
name.strip()
print("[" + name + "]")
```

The stripped copy was made and immediately thrown away. To keep it, store it: `name = name.strip()`.

## Yes-or-no questions about text

Some string tools answer with `True` or `False` instead of a new string. They're the bridge to Module 4, where your program will act on the answer:

```python run title="text_checks.py"
print("bot" in "Robotics")
print("Bot" in "Robotics")
print("2027".isdigit())
print("20.5".isdigit())
print("Yes please".lower().startswith("y"))
```

`in` checks whether one piece of text appears inside another, and it's case-sensitive, so `"Bot"` isn't found. `.isdigit()` is `True` only when every character is a digit, which is why the decimal point makes `"20.5"` fail. Lowering a reply before checking it means `Yes`, `yes`, and `YES` are all treated alike.

## Numbers: converting between text and numbers

Back to the stickers. To do math with what someone typed, convert it first. Each type's name works as a converter:

| You have | You want | Use | Example | Result |
| --- | --- | --- | --- | --- |
| `"3"` | a whole number | `int()` | `int("3")` | `3` |
| `"2.5"` | a decimal | `float()` | `float("2.5")` | `2.5` |
| `3.99` | a whole number | `int()` | `int(3.99)` | `3` (it chops, it doesn't round) |
| `7 / 3` | 2 decimal places | `round()` | `round(7 / 3, 2)` | `2.33` |
| `15` | text | `str()` | `str(15) + "!"` | `"15!"` |

Step through the fixed sticker program and watch the type of each variable. `shirts` holds the text `'3'`, while `count` holds the number `3`:

:::trace From text to a number
```python input="3"
shirts = input("How many club T-shirts? ")
wrong = shirts * 2
count = int(shirts)
stickers = count * 2
print("You'll get", stickers, "stickers.")
```
:::

Most programs convert straight away, in one line: `shirts = int(input("How many club T-shirts? "))`. Python runs the inner part first (show the question, wait for the answer), then hands the text to `int()`.

`int()` is forgiving about spaces around the digits (`int(" 3 ")` is `3`), but it can't read words or decimals:

```python run raises input="three"
shirts = int(input("How many club T-shirts? "))
```

`ValueError: invalid literal for int() with base 10: 'three'` means "this text doesn't look like a whole number". You'll get the same error for `"2.5"`; use `float()` when decimals are allowed. Module 5 shows how to keep asking until the answer is valid.

## f-strings: output that looks the way you want

Put an `f` before the opening quote and you can drop any variable or calculation into the text inside `{ }`. Add a colon and a **format spec** after it to control how the value looks:

```python run title="order_line.py"
item = "Club hoodie"
price = 24.5
qty = 2
print(f"{item} x{qty}: ${price * qty}")
print(f"{item} x{qty}: ${price * qty:.2f}")
print(f"|{item:<14}|{qty:>3}|{price * qty:>8.2f}|")
print(f"Members so far: {1234567:,}")
```

Line by line: without a spec, `49.0` looks wrong for money. `:.2f` means "a float with exactly 2 decimal places". In the third line, `:<14` pads the item to 14 characters, lined up on the left; `:>3` pads the quantity to 3 characters, lined up on the right; and `:>8.2f` does both jobs at once. Lining values up in fixed widths is how you print tidy columns. `:,` adds thousands separators.

| Spec | Meaning |
| --- | --- |
| `.2f` | exactly 2 decimal places |
| `>6` | right-align in 6 characters |
| `<6` | left-align in 6 characters |
| `^7` | center in 7 characters |
| `>8.2f` | both at once: 2 decimals, right-aligned in 8 characters |

Here they are applied to the same number. The square brackets are there only to show where the padding spaces go:

```python run title="format_specs.py"
x = 7.5
print(f"[{x:.2f}]")
print(f"[{x:>6}]")
print(f"[{x:<6}]")
print(f"[{x:^7}]")
print(f"[{x:>8.2f}]")
```

f-strings also save you from a classic crash. Gluing text to a number with `+` doesn't work, because Python won't guess whether you meant math or text:

```python run raises
stickers = 6
print("Stickers: " + stickers)
```

Write `f"Stickers: {stickers}"` instead, or use `str(stickers)`.

:::warning
**Three mistakes to look out for in this module:**

1.  Calling a method without storing the result: `email.lower()` on its own changes nothing. Write `email = email.lower()`.
2.  Doing math on `input()` without converting it. If a number comes out strangely repeated (`33`, `555`), you forgot `int()` or `float()`.
3.  Using `int()` on something that might have a decimal point. `int("2.5")` crashes; `float("2.5")` works.
:::

:::quiz
Q: What does `"Chess"[1:3]` give?
- [ ] `"Ch"`
  That would be `[0:2]`. Index 1 is the second character, because counting starts at 0.
- [x] `"he"`
  It takes indexes 1 and 2 (`h` and `e`) and stops before index 3.
- [ ] `"hes"`
  The slice stops *before* the second number, so index 3 isn't included.

Q: `name = "  Leo "`, then `name.strip()`, then `print(len(name))`. What prints?
- [ ] `3`
  That's the length of the stripped copy, but it was never stored back into `name`.
- [x] `6`
  `.strip()` made a new string and it was thrown away. `name` still has its 3 spaces, so it's 6 characters.
- [ ] An error, because strings can't be changed
  It's true that strings can't be changed, but calling `.strip()` is fine; it just returns a new string.

Q: A user types `2.5` at `int(input("Hours? "))`. What happens?
- [ ] `hours` becomes `2`
  `int()` chops decimals off a float, but it can't read decimal *text*.
- [ ] `hours` becomes `2.5`
  `int()` never produces a decimal.
- [x] The program stops with a `ValueError`
  The text `"2.5"` doesn't look like a whole number to `int()`. Use `float()` instead.

Q: What does `f"{3.14159:.2f}"` produce?
- [x] `3.14`
  `.2f` shows the float with exactly two decimal places.
- [ ] `3.1`
  That would be `.1f`.
- [ ] `3.14159`
  Without a format spec you'd get every digit; the spec is what trims it.
:::

:::takeaways
- `input()` always returns a `str`. Convert with `int()` or `float()` before doing math.
- Indexes start at 0; a slice `[a:b]` stops just before `b`.
- String methods return new strings. Store the result, or it's lost.
- `in`, `.isdigit()`, and `.startswith()` answer True or False about text.
- f-strings with format specs (`:.2f`, `:<10`, `:>8`) control exactly how output looks.
:::
