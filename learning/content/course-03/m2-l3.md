:::objectives
- Predict a program's output by tracking every variable on paper.
- Fix `NameError` crashes caused by order and spelling.
- Swap the values of two variables without losing either one.
- Use Thonny's Variables panel to find the line where a value goes wrong.
- Recalculate a value that depends on other variables each time they change.
:::

Make a file for each exercise in your `m2` folder (`ex1.py`, `ex2.py`, and so on), and keep **View › Variables** open while you work. Try each exercise before opening the hint, and try the hint before opening the solution.

**Warm-up.** In the Shell, type `n = 4`, then `n *= 3`, then `n`. Before you press Enter on the last one, say what you expect. `*=` multiplies a variable in place, the same way `+=` adds.

### Exercise 1: Predict it on paper

Without running it, work out exactly what this prints:

```python
laps = 2
best = laps
laps = laps * 3
best = best + laps
laps -= 1
print(laps, best)
```

Write your answer down, then run it to check.

:::hint
Draw a table with a column for `laps` and a column for `best`, and one row per line. On each line, only the variable on the left of `=` changes. Line 2 copies the value `laps` has *at that moment*.
:::

:::solution
```python run
laps = 2
best = laps
laps = laps * 3
best = best + laps
laps -= 1
print(laps, best)
```

| Line | `laps` | `best` |
| --- | --- | --- |
| `laps = 2` | 2 | |
| `best = laps` | 2 | 2 |
| `laps = laps * 3` | 6 | 2 |
| `best = best + laps` | 6 | 8 |
| `laps -= 1` | 5 | 8 |

Line 2 copies the number 2 into `best`; it doesn't tie `best` to `laps`. That's why tripling `laps` on line 3 leaves `best` at 2.
:::

### Exercise 2: Fix the ticket printer

This program should print a two-line ticket, but it crashes. Fix it so the output is exactly:

```text
Ticket for Priya
Row C seat 14
```

```python run raises
print("Ticket for", guest)
guest = "Priya"
seat = 14
row = "C"
print("Row", row, "seat", seet)
```

:::hint
There are two separate bugs. Fix the one the error points at, run it again, and let the next error lead you to the second. One is about order, one is about spelling.
:::

:::solution
```python run
guest = "Priya"
seat = 14
row = "C"
print("Ticket for", guest)
print("Row", row, "seat", seat)
```

The first `NameError` happens because `guest` is used on line 1 but not created until line 2, so the `print` moves below the assignment. The second is the typo `seet`. Fixing errors one at a time, rerunning after each, is normal: Python only ever reports the first problem it hits.
:::

### Exercise 3: Swap two items

A game character holds a sword in the left hand and a shield in the right:

```python
left = "sword"
right = "shield"
```

Add lines so that `print(left, right)` prints `shield sword`. Here's the first idea most people try. Step through it and watch the sword disappear:

:::trace Why the obvious swap loses the sword
```python
left = "sword"
right = "shield"
left = right
right = left
print(left, right)
```
:::

:::hint
After `left = right`, nothing refers to `"sword"` any more. Before you overwrite `left`, put its value somewhere safe: a third variable.
:::

:::solution
```python run
left = "sword"
right = "shield"
spare = left
left = right
right = spare
print(left, right)
```

`spare` keeps the sword while `left` gets overwritten, and then `right` takes it from `spare`. Python also has a one-line swap, `left, right = right, left`, which works out both values on the right before assigning either. It's worth knowing, but make sure you understand the three-line version first, because most other languages need it.
:::

### Exercise 4: Savings jar

Start a variable `jar` at 0 and print it after each week:

-   Week 1: you save 12.50.
-   Week 2: you save 12.50 again.
-   Week 3: you spend 8.75 on a game.
-   Week 4: you save 12.50 and get 20 for your birthday.

Sample output:

```text
Week 1: 12.5
Week 2: 25.0
Week 3: 16.25
Week 4: 48.75
```

:::hint
Use `+=` for money in and `-=` for money out, with a `print` after each week. Python drops the trailing zero in `12.50`; Module 3 shows how to always print two decimal places.
:::

:::solution
```python run
jar = 0
jar += 12.50
print("Week 1:", jar)
jar += 12.50
print("Week 2:", jar)
jar -= 8.75
print("Week 3:", jar)
jar += 12.50 + 20
print("Week 4:", jar)
```

`jar` starts as the `int` 0 and becomes a `float` the moment a decimal is added. In week 4, Python works out `12.50 + 20` first and then adds that 32.5 to the jar.
:::

### Exercise 5: The practice log that undercounts

This program should add up three days of guitar practice, but it reports 90 minutes instead of 135. Don't read it line by line looking for the bug. Instead, save it, click **Debug**, press **F6** line by line, and find the first line after which `total` in the Variables panel isn't what it should be.

```python run
monday = 45
tuesday = 30
wednesday = 60
total = monday
total = tuesday
total = total + wednesday
print("Total minutes:", total)
print("Daily average:", total / 3)
```

:::hint
After line 4, `total` should be 45. After line 5, it should be 45 + 30. What is it really?
:::

:::solution
```python run
monday = 45
tuesday = 30
wednesday = 60
total = monday
total = total + tuesday
total = total + wednesday
print("Total minutes:", total)
print("Daily average:", total / 3)
```

Line 5 replaced the running total with Tuesday's minutes instead of adding to it, so Monday's 45 was thrown away. In the debugger, `total` drops from 45 to 30 at that line, which is the clue. Writing `total += tuesday` would also work.
:::

### Exercise 6: Quiz-bowl scoreboard

Two teams, the Owls and the Foxes, start at 0. A correct answer is worth 10 points and a wrong buzz loses 5. Here's what happens:

1.  Owls answer correctly.
2.  Foxes answer correctly.
3.  Foxes buzz in wrong.
4.  Owls answer correctly.
5.  Foxes answer correctly.

After each question, print both scores and the Owls' **lead** (Owls minus Foxes). Sample output:

```text
After Q1: Owls 10 Foxes 0 lead 10
After Q2: Owls 10 Foxes 10 lead 0
After Q3: Owls 10 Foxes 5 lead 5
After Q4: Owls 20 Foxes 5 lead 15
After Q5: Owls 20 Foxes 15 lead 5
```

:::hint
It's tempting to write `lead = owls - foxes` once at the top. Remember the kiosk greeting from the Notes: a variable doesn't update itself when the values it was built from change. Where does the line need to go?
:::

:::solution
```python run
owls = 0
foxes = 0

owls += 10
lead = owls - foxes
print("After Q1: Owls", owls, "Foxes", foxes, "lead", lead)

foxes += 10
lead = owls - foxes
print("After Q2: Owls", owls, "Foxes", foxes, "lead", lead)

foxes -= 5
lead = owls - foxes
print("After Q3: Owls", owls, "Foxes", foxes, "lead", lead)

owls += 10
lead = owls - foxes
print("After Q4: Owls", owls, "Foxes", foxes, "lead", lead)

foxes += 10
lead = owls - foxes
print("After Q5: Owls", owls, "Foxes", foxes, "lead", lead)
```

`lead` is recalculated after every score change. If you calculated it once at the top, it would be stuck at 0 for the whole game. A value that is worked out from other variables has to be worked out again whenever they change.
:::

### Challenge: Musical chairs

Three friends sit in seats A, B and C:

```python
seat_a = "Jo"
seat_b = "Kai"
seat_c = "Lu"
```

Everyone moves one seat along: whoever was in A moves to B, B moves to C, and C wraps around to A. Write the moves so that `print(seat_a, seat_b, seat_c)` prints `Lu Jo Kai`. Use only **one** spare variable. Then find a way to do it in one line.

```mermaid caption="Each person moves one seat along, and C wraps round to A"
flowchart LR
    A["Seat A: Jo"] -->|moves to| B["Seat B: Kai"]
    B -->|moves to| C["Seat C: Lu"]
    C -->|wraps to| A
```

:::hint
Every move overwrites someone, so start by putting one person in the spare variable. If you save the person in C first, which seat can you fill straight away without losing anyone?
:::

:::solution
```python run
seat_a = "Jo"
seat_b = "Kai"
seat_c = "Lu"

spare = seat_c
seat_c = seat_b
seat_b = seat_a
seat_a = spare
print(seat_a, seat_b, seat_c)

seat_a, seat_b, seat_c = "Jo", "Kai", "Lu"
seat_a, seat_b, seat_c = seat_c, seat_a, seat_b
print(seat_a, seat_b, seat_c)
```

Saving Lu first frees up seat C, so Kai can move in, which frees seat B for Jo, and finally Lu comes out of `spare` into seat A. Each move fills the seat that the previous move just emptied. In the one-line version, Python reads all three values on the right before changing any of them, so nobody gets overwritten.
:::
