A welcome kiosk in a library lobby greets each visitor by name. Read this program and decide, before you look at the output, whether it welcomes Ana or Ben:

```python run title="kiosk_greeting.py"
visitor = "Ana"
greeting = "Welcome back, " + visitor + "!"
visitor = "Ben"
print(greeting)
print("Now at the desk:", visitor)
```

It welcomes Ana, even though `visitor` is `"Ben"` by the time `print(greeting)` runs. Line 2 built the text `"Welcome back, Ana!"` at the moment it ran and stored that finished text. Changing `visitor` on line 3 doesn't go back and rebuild it. A variable isn't a formula that keeps itself up to date, like a spreadsheet cell; it holds whatever value was last put in it.

That one idea explains most of the surprises beginners meet with variables, so the rest of this page builds on it.

## A variable is a name stuck on a value

Here's the intuition: a value like `"Ana"` or `15` sits in the computer's memory, and a variable is a name tag stuck onto it so you can find it again. Moving the tag to a new value doesn't change the old value; it just means the name now points somewhere else.

Now precisely. A line like `visits = visits + 1` is an **assignment**, and Python always handles it in two steps:

1.  Work out the right-hand side, using the values the variables have *right now*.
2.  Make the name on the left refer to the result.

So the `=` sign doesn't mean "is equal to" the way it does in math. Read it as **becomes**: "visits becomes visits plus one".

```python run title="visit_counter.py"
visits = 1
print("Visits:", visits)
visits = visits + 1
print("Visits:", visits)
visits += 1
print("Visits:", visits)
```

On line 3, Python reads `visits` (it's `1`), adds 1 to get `2`, and only then makes `visits` refer to `2`. Line 5 uses `+=`, a shortcut that means exactly the same thing as `visits = visits + 1`. You'll see `+=` everywhere in real code, along with `-=` for subtracting.

## Watch the values change

Step through a slightly longer kiosk program. Keep your eye on the variables list: each assignment adds a name or changes one value, and `print` never changes anything.

:::trace Track each variable as the kiosk runs
```python
visitor = "Ana"
first_visit = True
visits = 0
visits = visits + 1
greeting = "Welcome, " + visitor
first_visit = False
visits = visits + 1
visitor = "Ben"
print(greeting, visits, first_visit)
```
:::

When you reach the last line, three things should make sense. `visits` is `2` because it was increased twice. `first_visit` is `False` because the later assignment replaced `True`. And `greeting` still mentions Ana, because it was built before `visitor` changed.

## Order matters: Python can't look ahead

Python runs your file from top to bottom and only knows about a variable once the line that creates it has run. Use a name too early and the program stops:

```python run raises
print("Hello,", name)
name = "Ana"
```

`NameError: name 'name' is not defined` means "I've never heard of this name". The variable *is* created on line 2, but line 1 runs first. The fix is to swap the two lines. Whenever you see a `NameError`, ask two questions: is the name spelled the same everywhere, and does the line that creates it run before the line that uses it?

## Every value has a type

Python sorts values into **types**, and the type decides what operations do. You'll use four constantly:

| Type | What it holds | Examples |
| --- | --- | --- |
| `str` (string) | Text, always inside quotes | `"Ana"`, `"15"`, `""` |
| `int` (integer) | Whole numbers | `0`, `15`, `-3` |
| `float` | Numbers with a decimal point | `4.5`, `0.25`, `15.0` |
| `bool` (Boolean) | One of two values: `True` or `False` | `True`, `False` |

The built-in `type()` function tells you the type of any value. Watch how the same symbol does different jobs depending on the types around it:

```python run title="types.py"
print(type("Ana"), type(15), type(4.5), type(True))
print(type("15"))
print(3 + 4)
print("3" + "4")
print("ha" * 3)
```

`3 + 4` adds numbers and gives `7`, but `"3" + "4"` glues two pieces of text together and gives `34`. And `"15"` is a `str`, not an `int`, because the quotes make it text that happens to look like a number. That difference causes one of the most common bugs in Module 3, when your programs start reading what people type.

`True` and `False` are written with capital letters and no quotes. A `bool` answers a yes-or-no question, like whether this is someone's first visit. Module 4 uses them to make decisions.

## Watching variables in Thonny

You don't have to track values in your head. In Thonny, open **View › Variables**. A panel appears that lists every variable your program has made, with its current value.

1.  Open `kiosk_greeting.py` (or type it in and save it in your `m2` folder).
2.  Click Run. The Variables panel now shows the final value of each name.
3.  Now click **Debug** (Ctrl+F5) and press **F6** (Over) one line at a time. Watch `greeting` appear in the panel with Ana's name in it, and then watch `visitor` change to `"Ben"` while `greeting` stays exactly the same.

This is the single most useful debugging habit you can build. When a program prints something you didn't expect, step through it and find the first line where a value in the panel isn't what you thought it would be. The bug is on or just above that line.

## Choosing names Python accepts (and humans understand)

Python is strict about the shape of a name:

| Name | Allowed? | Why |
| --- | --- | --- |
| `first_visit` | Yes | Letters and underscores are fine |
| `visitor2` | Yes | Digits are fine after the first character |
| `2nd_visitor` | No | A name can't start with a digit |
| `first visit` | No | No spaces; Python sees two names |
| `Visitor` | Yes, but… | It's a different name from `visitor`, because case matters |
| `print` | Technically, but don't | It replaces the real `print` for the rest of the program |

Try one of the forbidden ones and you get a syntax error before anything runs:

```python run raises
2nd_visitor = "Cal"
```

Beyond the rules, pick names that say what the value means. `visits` beats `v`, and `first_visit` beats `flag`. Python programmers write multi-word names in lowercase joined by underscores, a style called **snake_case**.

:::warning
**A typo makes a brand-new variable, with no error.** This program is meant to add 5 points:

```python run
score = 10
scroe = score + 5
print(score)
```

It prints `10`. Line 2 created a second variable called `scroe` and stored 15 in it, while `score` stayed at 10. Python can't know you misspelled it. The Variables panel gives it away, because you'd see both `score` and `scroe` listed. Whenever a value refuses to change, look for a twin with a slightly different spelling.
:::

:::warning
**Quotes turn a name into plain text.** `print("visitor")` prints the word *visitor*. `print(visitor)` looks up the variable and prints its value, like `Ben`.
:::

:::quiz
Q: A program runs `price = 4`, then `total = price * 3`, then `price = 5`, then `print(total)`. What does it print?
- [x] `12`
  `total` was worked out as 4 × 3 when its line ran. Changing `price` afterwards doesn't redo that calculation.
- [ ] `15`
  That would only happen if `total` updated itself like a spreadsheet formula. It doesn't; it keeps the value it was given.
- [ ] `price * 3`
  There are no quotes, so Python calculates the expression instead of printing it as text.

Q: After `count = 7` and then `count += 2`, what is `count`?
- [ ] `7`
  `+=` changes the variable: it adds 2 to the current value and stores the result back.
- [x] `9`
  `count += 2` means `count = count + 2`, so 7 + 2 = 9 is stored in `count`.
- [ ] `72`
  That would happen with text (`"7" + "2"`), but `7` and `2` are integers.

Q: Which value is a `str`, not a number?
- [ ] `15.0`
  The decimal point makes this a `float`, a number.
- [x] `"15"`
  The quotes make it text. It looks like a number, but Python treats it as two characters.
- [ ] `-15`
  A minus sign doesn't change the type; this is an `int`.

Q: A program sets `lives = 3`, later has the line `livs = lives - 1`, and finally prints `lives`. What do you see?
- [ ] An error, because `livs` was never created
  Assigning to a name creates it, so `livs = …` makes a new variable without complaint.
- [x] `3`
  The typo stored 2 in a new variable, `livs`, and `lives` never changed.
- [ ] `2`
  That would be right if the name were spelled `lives` on both sides of the `=`.
:::

:::takeaways
- `=` means "becomes": Python works out the right side first, then stores it under the name on the left.
- A variable keeps the value it was given; it doesn't update when other variables change later.
- Python runs top to bottom, so a variable must be created before it's used, or you get a `NameError`.
- `str`, `int`, `float`, and `bool` are the four basic types, and `"15"` is text, not a number.
- **View › Variables** plus stepping with F6 shows every value as it changes, which is the fastest way to find a bug.
:::
