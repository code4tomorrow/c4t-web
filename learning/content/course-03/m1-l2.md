:::objectives
- Tell the editor and the Shell apart, and know when to use each.
- Make a course folder and save a program in it as a `.py` file.
- Run a program and match each line of output to the line of code that made it.
- Break a program on purpose and read the error message Python gives back.
:::

Anything you type in the Shell disappears when you close Thonny. That's fine for a quick sum, but real programs need to be kept, changed, and run again tomorrow. So programs live in **files**, and Python files end in `.py`.

By the end of this page you'll have a file called `first_run.py` that works out how many times your heart beats in a day, saved somewhere you can find it again.

## Editor or Shell?

Both run Python, but they do different jobs:

```mermaid caption="The editor keeps a whole program; the Shell answers one line at a time"
flowchart LR
    A["Write lines in the editor"] --> B["Save as first_run.py"]
    B --> C["Click Run"]
    C --> D["Python runs every line, top to bottom"]
    D --> E["Output appears in the Shell"]
    F[">>> one line in the Shell"] --> G["Answer right away, nothing saved"]
```

Use the Shell to test a tiny idea ("what does `7 / 2` give?"). Use the editor for anything you'd want to run twice.

## Step 1: Make a folder for this course

Every program you write in this course will go in one folder. Make it now, outside Thonny:

:::tabs
@tab Windows
Open **File Explorer** and click **Documents** on the left. Right-click an empty spot, choose **New › Folder**, and name it `beginner-python`.
@tab macOS
Open **Finder** and click **Documents** in the sidebar. Choose **File › New Folder** and name it `beginner-python`.
@tab Chromebook
Open the **Files** app and click **Linux files** on the left. (Thonny can only see files in this area.) Right-click an empty spot, choose **New folder**, and name it `beginner-python`.
:::

Use exactly that name: lowercase, with a dash instead of a space. The next lesson explains why spaces in names cause trouble.

## Step 2: Type the program

Click in Thonny's editor (the `<untitled>` tab) and type these four lines. Type them yourself rather than copying: your fingers learn where the brackets and quotes go.

```python run title="first_run.py"
print("Hello from my first Python file!")
print("Seconds in one day:", 60 * 60 * 24)
print("Seconds in one year:", 60 * 60 * 24 * 365)
print("Heartbeats in a day at 70 per minute:", 70 * 60 * 24)
```

Each line is one instruction. Inside each `print(...)`, the part in quotes is text that gets shown exactly as typed. The part after the comma is a calculation; Python works it out first and then prints the answer. The comma tells `print` to show both things with a space between them.

## Step 3: Save it as first_run.py

Press **Ctrl+S** (**Cmd+S** on a Mac), or click the **Save** button. In the dialog, open **Documents**, then your `beginner-python` folder (on a Chromebook, it's in your home folder), type `first_run.py` as the name, and click **Save**.

The editor tab now says `first_run.py` instead of `<untitled>`. If you forget the `.py`, Thonny adds it for you.

## Step 4: Run it

Click the green **Run** button, press **F5**, or choose **Run › Run current script**. On a Mac, F5 may need the **fn** key held down; **Cmd+R** works too.

Look at the Shell. Thonny writes `%Run first_run.py` to show which file it ran, then the program's output appears underneath, matching the output shown above.

Match each output line to its code line. Line 2 printed `86400`, never `60 * 60 * 24`, because Python works out calculations before printing them. Only the text inside quotes is printed exactly as written.

:::try
Change `70` to your own resting heart rate (most teens are somewhere between 60 and 100), then click Run again. Thonny saves the file for you every time you run it, so you don't need to press Save first.
:::

## Step 5: Watch it run one line at a time

Python runs a file from the top line to the bottom line, one line at a time, and never skips ahead. Step through the same program below and watch the output grow by one line per step.

:::trace Python runs line 1, then line 2, then line 3…
```python
print("Hello from my first Python file!")
print("Seconds in one day:", 60 * 60 * 24)
print("Seconds in one year:", 60 * 60 * 24 * 365)
print("Heartbeats in a day at 70 per minute:", 70 * 60 * 24)
```
:::

Thonny can do the same thing with your file. Click the **Debug** button (the bug) or press **Ctrl+F5**. The first line is highlighted, and nothing has run yet. Now press **F6** (the **Over** button) to run one line. Keep pressing it and watch the Shell fill up.

Want to go even slower? Press **F7** (the **Into** button) instead, and Thonny shows a calculation like `60 * 60 * 24` being worked out piece by piece: first `3600`, then `86400`. You'll use this a lot from Module 2 onward. Note that Thonny can only debug a program that has been saved.

:::video QQAqQp06nXo
A short demo of Thonny's step buttons. Watch for the difference between stepping over a line (one big step) and stepping into it (many small steps that show each part of a calculation).
:::

## Step 6: Break it on purpose

Every programmer sees error messages every day. The skill is reading them calmly. Make each change below to `first_run.py`, run it, read the error, then undo the change.

**Break 1: delete the closing quote on line 1.**

```python run raises
print("Hello from my first Python file!)
```

Python reads the opening `"` and keeps looking for the matching one until the line ends. The last line of the message names the problem: an **unterminated string literal**, meaning text that was opened and never closed. The line number above it tells you where. Thonny also underlines the problem spot in the editor.

**Break 2: change `print` to `Print` on line 1.**

```python run raises
Print("Hello from my first Python file!")
```

Python is case-sensitive, so `Print` and `print` are different names, and nothing called `Print` exists. This is a `NameError`, and Python even suggests the fix: `Did you mean: 'print'?`

**Break 3: delete the last `)` on line 2.**

```python run raises
print("Hello from my first Python file!")
print("Seconds in one day:", 60 * 60 * 24
print("Seconds in one year:", 60 * 60 * 24 * 365)
```

Every `(` needs a matching `)`. Notice that this error stopped the program before line 1 ran, so nothing was printed at all. Python checks the whole file for this kind of mistake (a **syntax error**) before it runs anything.

When a program crashes, Thonny may open an **Assistant** panel on the right with a plain-English explanation. Read it, but read Python's last line first: that's the one you'll see in every editor, for the rest of your programming life.

## Proof that your setup works

Tick these off before moving on:

1.  `first_run.py` is in your `beginner-python` folder. Check in File Explorer, Finder, or Files.
2.  Close Thonny completely, open it again, and use **File › Open** (or **File › Recent files**) to open `first_run.py`.
3.  Click Run. You get the same four lines of output, with no red text.

If all three work, your computer is ready for the rest of the course.

:::quiz
Q: You type `print(60 * 60)` in the editor, save, and run. What appears in the Shell?
- [ ] `60 * 60`
  The calculation isn't in quotes, so Python works it out instead of printing it as text.
- [x] `3600`
  Python evaluates `60 * 60` first, then prints the result.
- [ ] Nothing, because files don't show results
  Files don't show bare calculations, but `print` always displays what it's given.

Q: A program's line 2 is missing a `)`. Line 1 is a correct `print`. What happens when you run it?
- [ ] Line 1 prints, then the program crashes on line 2
  That's how most errors behave, but a missing bracket is a syntax error, found before anything runs.
- [x] Nothing prints, and Python reports a syntax error
  Python checks the whole file's grammar first, so line 1 never gets a chance to run.
- [ ] Python adds the bracket and runs normally
  Python never guesses what you meant; it stops and tells you.
:::

:::takeaways
- Programs live in `.py` files; the Shell is for quick one-line tests.
- Python runs a file from top to bottom, one line at a time.
- The last line of an error message names the problem, and the line number tells you where to look.
- Debug (Ctrl+F5) plus Over (F6) lets you run your program one line at a time.
:::
