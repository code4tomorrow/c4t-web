Games are a good place to practice variables, because a game is mostly a pile of values that keep changing: health goes down, gold goes up, a door unlocks. You'll write a four-scene adventure called *The Lantern Cave*. The story is fixed (you'll make it respond to the player in later modules), but every number in it is tracked and updated by the program.

Here's the plan, with what each scene does to the hero's stats:

```mermaid caption="Each scene changes one or two values; the program prints the status after every scene"
flowchart LR
    A["Start: health 100, gold 0"] --> B["Forest: +40 gold, +0.75 kg lantern"]
    B --> C["River: -30 health"]
    C --> D["Market: -12 gold, +20 health"]
    D --> E["Cave: half the gold, +key"]
    E --> F["Ending: final score"]
```

Make a new file in Thonny and save it as `adventure_stats.py` in your `m2` folder. Open **View › Variables** too, so you can watch the values as you go.

:::note
Each step below adds lines to the **bottom** of your file. The output under each step shows only what the new lines print. In Thonny, clicking Run runs the whole file, so you'll see the earlier output above it as well.
:::

## Step 1: Decide what to remember

Before writing any story, list the facts about the hero that can change, and choose a type for each:

| Variable | Type | Starting value | Why this type |
| --- | --- | --- | --- |
| `hero` | `str` | `"Robin"` | A name is text |
| `health` | `int` | `100` | Health points are whole numbers |
| `gold` | `int` | `0` | You can't have half a coin |
| `bag_kg` | `float` | `1.5` | Weight needs a decimal point |
| `has_key` | `bool` | `False` | You either have the key or you don't |

Type the setup, plus a title and a first status line:

```python run title="adventure_stats.py"
# adventure_stats.py: a short adventure that tracks the hero's stats
hero = "Robin"
health = 100
gold = 0
bag_kg = 1.5
has_key = False

print("=== The Lantern Cave ===")
print(hero, "| health", health, "| gold", gold, "| bag", bag_kg, "kg | key", has_key)
```

The first line starts with `#`, which makes it a **comment**: a note for humans that Python skips. The long `print` mixes text in quotes with variable names without quotes, separated by commas. Python prints each piece with a space between them, swapping each name for its current value.

Run it and check the Variables panel. You should see all five names with their starting values.

## Step 2: The forest

The hero finds 40 gold and picks up a lantern weighing 0.75 kg. Add a blank line, a line of story, the two updates, and a fresh status line:

```python run
# Scene 1: the forest
print()
print("You find a pouch of 40 gold and an old lantern.")
gold += 40
bag_kg += 0.75
print(hero, "| health", health, "| gold", gold, "| bag", bag_kg, "kg | key", has_key)
```

An empty `print()` prints a blank line, which spaces the scenes out. `gold += 40` reads the current gold (0), adds 40, and stores 40. `bag_kg += 0.75` does the same with a float, so the bag now weighs 2.25 kg.

Notice the order: story first, then the updates, then the status. If you printed the status *before* the updates, it would show the old values, because `print` shows what's stored at the moment it runs.

## Step 3: The river

```python run
# Scene 2: the river
print()
print("You slip on a wet rock crossing the river.")
health -= 30
print(hero, "| health", health, "| gold", gold, "| bag", bag_kg, "kg | key", has_key)
```

`-=` subtracts: health goes from 100 to 70. You've now typed the same status line three times. That's a sign that something could be packaged up and reused, and later in the course you'll learn to do exactly that with a function. For now, copying it is fine.

## Step 4: The market

The potion's price goes in its own variable, so the story line and the subtraction can't disagree about what it costs:

```python run
# Scene 3: the market
print()
potion_price = 12
print("A trader sells you a potion for", potion_price, "gold. You drink it.")
gold -= potion_price
health += 20
print(hero, "| health", health, "| gold", gold, "| bag", bag_kg, "kg | key", has_key)
```

If you later decide potions cost 15, you change one number and both the message and the math follow. Typing `12` in two places would work today, but sooner or later someone changes one and forgets the other.

## Step 5: The cave, and a bug with no error message

Bandits take half the hero's gold, and the hero finds a brass key weighing 0.25 kg. Here is the scene as a beginner might first type it. Add it and run it:

```python run
# Scene 4: the cave
print()
print("Bandits take half your gold, but you find a brass key.")
glod = gold // 2
has_key = True
bag_kg += 0.25
print(hero, "| health", health, "| gold", gold, "| bag", bag_kg, "kg | key", has_key)
```

The story says the bandits took half the gold, but the status still says 28. There's no red text and no crash, so the error message routine from Module 1 can't help. This is the kind of bug the debugger is for.

Click **Debug** (Ctrl+F5) and press **F6** repeatedly until you reach the bandits line, keeping your eyes on the Variables panel. After that line runs, a new name appears in the list, `glod`, holding 14, while `gold` sits unchanged at 28. The typo created a second variable instead of updating the first. You can step through the same moment here:

:::trace Watch a typo create a second variable
```python
gold = 28
health = 90
glod = gold // 2
has_key = True
print("gold", gold)
```
:::

Fix the spelling so the line updates `gold` itself:

```python run
gold = gold // 2
print(hero, "| health", health, "| gold", gold, "| bag", bag_kg, "kg | key", has_key)
```

Now the gold drops to 14. Why `//` and not `/`? Both divide, but `/` always produces a float, so you'd get `14.0` coins. `//` divides and throws away anything after the decimal point, which keeps gold a whole number. Module 4 covers both properly. In your file, delete the old `glod` line rather than adding this fix underneath it.

## Step 6: The ending

Finish with a score that combines two stats. Each coin is worth 10 points, and every point of health left counts once:

```python run
# The ending
print()
score = gold * 10 + health
print("You reach the lantern door with", gold, "gold and", health, "health.")
print("Final score:", score)
```

Python multiplies before it adds, just like in math class, so this is `14 * 10 + 90`, which is 230.

## The finished program

Here is the whole file in one piece, with the bug fixed. Run yours and compare.

```python run title="adventure_stats.py"
# adventure_stats.py: a short adventure that tracks the hero's stats
hero = "Robin"
health = 100
gold = 0
bag_kg = 1.5
has_key = False

print("=== The Lantern Cave ===")
print(hero, "| health", health, "| gold", gold, "| bag", bag_kg, "kg | key", has_key)

# Scene 1: the forest
print()
print("You find a pouch of 40 gold and an old lantern.")
gold += 40
bag_kg += 0.75
print(hero, "| health", health, "| gold", gold, "| bag", bag_kg, "kg | key", has_key)

# Scene 2: the river
print()
print("You slip on a wet rock crossing the river.")
health -= 30
print(hero, "| health", health, "| gold", gold, "| bag", bag_kg, "kg | key", has_key)

# Scene 3: the market
print()
potion_price = 12
print("A trader sells you a potion for", potion_price, "gold. You drink it.")
gold -= potion_price
health += 20
print(hero, "| health", health, "| gold", gold, "| bag", bag_kg, "kg | key", has_key)

# Scene 4: the cave
print()
print("Bandits take half your gold, but you find a brass key.")
gold = gold // 2
has_key = True
bag_kg += 0.25
print(hero, "| health", health, "| gold", gold, "| bag", bag_kg, "kg | key", has_key)

# The ending
print()
score = gold * 10 + health
print("You reach the lantern door with", gold, "gold and", health, "health.")
print("Final score:", score)
```

:::quiz
Q: Why is `has_key` stored as `False` rather than as the text `"no"`?
- [ ] Python can't store the word "no" in a variable
  It can; any text works as a string. The question is which type fits the meaning.
- [x] It's a yes-or-no fact, and a `bool` is the type made for those
  `True` and `False` can't be misspelled as `"No"` or `"nope"`, and Module 4's decisions can use them directly.
- [ ] Booleans use less memory, so programs run faster
  The difference is too tiny to matter. The reason is meaning and safety, not speed.

Q: In Step 5, what would `gold = gold / 2` have stored?
- [ ] `14`
  That's what `//` gives. Plain `/` always produces a float.
- [x] `14.0`
  `/` always returns a float, even when the division comes out even, so the status would show 14.0 gold.
- [ ] An error, because gold is an `int`
  Dividing an `int` is fine; the result is just a float.

Q: The status line was printed after the updates in every scene. What would printing it before the updates show?
- [x] The values from the end of the previous scene
  `print` shows what is stored at the moment it runs, and the updates haven't happened yet.
- [ ] The new values, because Python reads ahead
  Python never looks ahead; it runs one line at a time, top to bottom.
- [ ] An error, because the variables are being changed
  Reading a variable before changing it is completely normal.
:::

:::takeaways
- Start a program by listing the values that will change, with a sensible type for each.
- `+=` and `-=` update a variable using its current value.
- Put a value used in more than one place, like a price, in its own variable.
- A misspelled name creates a new variable with no error; the Variables panel shows the twin.
- `/` always gives a float, while `//` drops the decimal part.
:::
