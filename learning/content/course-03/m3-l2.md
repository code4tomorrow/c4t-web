:::objectives
- Ask a series of questions with `input()` and clean every answer before using it.
- Convert answers to `int` where you need to do math, and leave them as text where you don't.
- Build a new piece of text from slices of other strings.
- Line up a printed slip in columns with f-string widths and `.2f`.
- Test a program with messy input on purpose.
:::

People type answers carelessly. They add spaces, forget capital letters, or press Caps Lock halfway through an email address. A good program accepts the mess and tidies it up, so you never see it in the output. You'll build a sign-up program for a school club that does exactly that.

When it's finished, someone who types `   maya CHEN `, ` robotics `, `m`, and ` Maya.Chen@School.ORG ` gets this:

```text
================================
   CLUB SIGN-UP CONFIRMATION
================================
Name:         Maya Chen
Grade:        9
Club:         Robotics
Member code:  ROB-9-MAY
Shirts:       2 x size M
Email:        maya.chen@school.org
Newsletter:   True
--------------------------------
Dues ($)         15.00
Shirts ($)       25.00
Total ($)        40.00
================================
Thanks, Maya Chen. See you at Robotics!
```

Save a new file as `signup_slip.py` in your `m3` folder.

:::note
Each step adds lines to the **bottom** of the file, and the output shows only the new lines. In Thonny, each run asks *all* the questions so far, so you'll answer the earlier ones again every time. That's normal while you're building.
:::

## Step 1: Ask for the name and clean it

```python run title="signup_slip.py" input="   maya CHEN "
# signup_slip.py: collects a club sign-up and prints a confirmation slip
name = input("Full name: ").strip().title()
print(f"[{name}]")
```

Three things happen on line 2, from the inside out. `input()` shows the question and returns whatever was typed, spaces and all. `.strip()` cuts the spaces off both ends. `.title()` turns `maya CHEN` into `Maya Chen`. The brackets in the `print` are temporary, there only so you can see that no stray spaces survived. Delete that line once you've checked.

Cleaning at the moment you read the answer means every later line can trust `name`. If you cleaned it later, you'd have to remember to do it everywhere you used it.

## Step 2: The grade, as a number

```python run input="9"
grade = int(input("Grade (6-12): "))
years_left = 12 - grade
print(f"{years_left} more years of school after this one.")
```

Here the answer has to become an `int`, because the program does math with it. Without `int()`, `12 - grade` would crash with a `TypeError`, since you can't subtract text from a number. Now compare that with the next step, where none of the answers get converted.

## Step 3: Club, size, email, and newsletter

```python run input=" robotics |m| Maya.Chen@School.ORG |Yes"
club = input("Which club? ").strip().title()
size = input("T-shirt size (S, M, L, XL): ").strip().upper()
email = input("Email: ").strip().lower()
newsletter = input("Newsletter? (yes/no) ").strip().lower().startswith("y")
print(club, size, email, newsletter)
```

Each answer gets the cleaning that suits it. Club names look best in title case, sizes are always capitals, and email addresses are conventionally written in lowercase.

The newsletter line is different: it ends with `.startswith("y")`, which turns the answer into `True` or `False`. Lowering it first means `Yes`, `YES`, `y`, and `yeah` all count as yes. Storing a `bool` rather than the raw text means the rest of the program never has to worry about how the person spelled it.

## Step 4: The money

```python run input="2"
DUES = 15.00
SHIRT_PRICE = 12.50
shirts = int(input("How many shirts? "))
shirt_cost = shirts * SHIRT_PRICE
total = DUES + shirt_cost
print(f"Shirts: {shirt_cost}  Total: {total}  Total, formatted: {total:.2f}")
```

`DUES` and `SHIRT_PRICE` are written in capitals. Python doesn't treat them any differently, but programmers use capitals for values that are set once and never changed, called **constants**. In a real project you'd move them to the very top of the file, so next year's treasurer can update the prices without hunting through the code.

Look at the output: `40.0` is correct, but it doesn't look like money. `:.2f` fixes that by always showing two decimal places.

## Step 5: A member code from slices

The club wants a short code for each member: the first three letters of the club, the grade, and the first three letters of the name, like `ROB-9-MAY`.

```python run
code = f"{club[:3].upper()}-{grade}-{name[:3].upper()}"
print(code)
```

`club[:3]` slices off the first three characters, `Rob`, and `.upper()` capitalizes them. The f-string glues everything together with dashes, and `grade` goes in without any conversion because f-strings turn numbers into text for you.

This is also why the cleaning in Step 1 mattered. Without `.strip()`, the slice of `"   maya CHEN "` would be three spaces, and Maya's code would be `ROB-9-   `.

## Step 6: Print the slip

Now line everything up. Each label is padded to 14 characters with `:<14`, so every value starts in the same column. The money is right-aligned in 8 characters with `:>8.2f`, so the decimal points line up.

```python run
width = 32
print()
print("=" * width)
print(f"{'CLUB SIGN-UP CONFIRMATION':^{width}}")
print("=" * width)
print(f"{'Name:':<14}{name}")
print(f"{'Grade:':<14}{grade}")
print(f"{'Club:':<14}{club}")
print(f"{'Member code:':<14}{code}")
print(f"{'Shirts:':<14}{shirts} x size {size}")
print(f"{'Email:':<14}{email}")
print(f"{'Newsletter:':<14}{newsletter}")
print("-" * width)
print(f"{'Dues ($)':<14}{DUES:>8.2f}")
print(f"{'Shirts ($)':<14}{shirt_cost:>8.2f}")
print(f"{'Total ($)':<14}{total:>8.2f}")
print("=" * width)
print(f"Thanks, {name}. See you at {club}!")
```

A few details are worth a closer look:

-   `"=" * width` repeats a character, so you can change the slip's width in one place.
-   `{'Name:':<14}` puts a plain string inside the braces. It uses single quotes because the f-string itself is in double quotes. Python 3.12 and newer would accept double quotes there too, but older versions (like the one on some Chromebooks) would think the f-string had ended, so mixing the two kinds is the safe habit.
-   `{'CLUB SIGN-UP CONFIRMATION':^{width}}` centers the title. The width can itself be a `{variable}` inside the format spec.

## The finished program

```python run title="signup_slip.py" input="   maya CHEN |9| robotics |m|2| Maya.Chen@School.ORG |Yes"
# signup_slip.py: collects a club sign-up and prints a confirmation slip
DUES = 15.00
SHIRT_PRICE = 12.50

name = input("Full name: ").strip().title()
grade = int(input("Grade (6-12): "))
club = input("Which club? ").strip().title()
size = input("T-shirt size (S, M, L, XL): ").strip().upper()
shirts = int(input("How many shirts? "))
email = input("Email: ").strip().lower()
newsletter = input("Newsletter? (yes/no) ").strip().lower().startswith("y")

shirt_cost = shirts * SHIRT_PRICE
total = DUES + shirt_cost
code = f"{club[:3].upper()}-{grade}-{name[:3].upper()}"

width = 32
print()
print("=" * width)
print(f"{'CLUB SIGN-UP CONFIRMATION':^{width}}")
print("=" * width)
print(f"{'Name:':<14}{name}")
print(f"{'Grade:':<14}{grade}")
print(f"{'Club:':<14}{club}")
print(f"{'Member code:':<14}{code}")
print(f"{'Shirts:':<14}{shirts} x size {size}")
print(f"{'Email:':<14}{email}")
print(f"{'Newsletter:':<14}{newsletter}")
print("-" * width)
print(f"{'Dues ($)':<14}{DUES:>8.2f}")
print(f"{'Shirts ($)':<14}{shirt_cost:>8.2f}")
print(f"{'Total ($)':<14}{total:>8.2f}")
print("=" * width)
print(f"Thanks, {name}. See you at {club}!")
```

The questions now all come first, then the calculations, then the output. Grouping a program into **input, processing, output** like this makes it much easier to read than mixing the three together.

:::quiz
Q: Why does the program call `.strip()` on the name *before* taking `name[:3]` for the member code?
- [ ] `.strip()` makes the name shorter, so the slice runs faster
  Speed isn't the issue; it's which characters end up in the code.
- [x] Leading spaces would otherwise become the first three characters of the slice
  `"   maya"[:3]` is three spaces, so the code would be `ROB-9-   `.
- [ ] Slices don't work on strings with spaces in them
  Slices work on any string; spaces are just characters like any other.

Q: Why is `grade` converted with `int()` but `size` is left as text?
- [x] The program does math with the grade but only displays the size
  You only need a number when you calculate with it, like `12 - grade`. A size like `M` isn't a number at all.
- [ ] `int()` only works on answers that come first
  `int()` works on any text that looks like a whole number, wherever it appears.
- [ ] f-strings can't display integers
  f-strings display integers fine; the slip prints `grade` directly.

Q: What would `{total}` show on the slip without `:.2f`?
- [ ] `40.00`
  Python doesn't add trailing zeros unless you ask it to.
- [x] `40.0`
  A float prints with as few decimal places as it needs, which looks odd for money.
- [ ] `40`
  `total` is a float (it was built from `15.00` and `12.50`), so it keeps a decimal point.
:::

:::takeaways
- Clean each answer the moment you read it (`.strip()` plus `.title()`, `.upper()`, or `.lower()`), so later code can trust it.
- Convert with `int()` only when you need to calculate; keep other answers as text.
- `.lower().startswith("y")` turns a messy yes/no answer into a reliable `True` or `False`.
- Fixed widths (`:<14`, `:>8.2f`) line output up in columns.
- Test with messy and wrong input on purpose; the crashes you find are the next things to fix.
:::
