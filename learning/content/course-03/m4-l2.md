:::objectives
- Turn written pricing rules into constants and calculations.
- Choose a rate with `if`/`else` and a discount with conditions joined by `and`.
- Decide between `>` and `>=` by reading what a rule really says.
- Reject impossible input before doing any math.
- Build a boundary-test table and use it to check every rule.
:::

Riverton, a made-up city, has a bike-share scheme, and it needs a program that prices each ride. Here are its rules, exactly as the city wrote them:

-   Every ride costs a **$1.25 unlock fee**, plus a **per-minute** charge: $0.15 for a classic bike, $0.30 for an e-bike.
-   **Members** pay no unlock fee, and their first **45 minutes** on a classic bike are free.
-   Rides **longer than 180 minutes** pay a $10.00 late fee.
-   A ride must last at least 1 minute, and the bike must be `classic` or `ebike`.

Here's the order the finished program makes its decisions in:

```mermaid caption="The fare calculator checks the input first, then applies each rule in turn"
flowchart TD
    A["Read minutes, bike, member"] --> B{"Minutes below 1?"}
    B -->|yes| X["Error: too short"]
    B -->|no| C{"Bike classic or ebike?"}
    C -->|no| Y["Error: unknown bike"]
    C -->|yes| D["Pick the rate"]
    D --> E["Work out billed minutes (member discount)"]
    E --> F["Add the unlock fee if not a member"]
    F --> G{"Over 180 minutes?"}
    G -->|yes| H["Add the late fee"]
    G -->|no| I["Print the fare"]
    H --> I
```

And here's what a member who rides a classic bike for 50 minutes will see:

```text
Ride length in minutes: 50
Bike type (classic or ebike): classic
Member? (yes/no): yes
Unlock fee: $0.00
Billed minutes: 5 at $0.15 a minute
Total fare: $0.75
```

Save a new file as `bike_fare.py` in your `m4` folder. This time every step shows the whole program so far, because the new code often goes in the middle, not at the bottom.

## Step 1: One kind of bike, no discounts

Start with the simplest rider: a non-member on a classic bike.

```python run title="bike_fare.py" input="30"
UNLOCK_FEE = 1.25
CLASSIC_RATE = 0.15

minutes = int(input("Ride length in minutes: "))
fare = UNLOCK_FEE + minutes * CLASSIC_RATE
print(f"Total fare: ${fare:.2f}")
```

The prices go in capitalized constants at the top, so a price change means editing one line. In `UNLOCK_FEE + minutes * CLASSIC_RATE`, Python multiplies first (30 × 0.15 = 4.50) and then adds the 1.25, which is exactly what the rule says. Check it against the rule by hand before moving on; that one habit catches a surprising number of bugs.

## Step 2: Classic or e-bike

Now the rate depends on the bike, so the program has to choose:

```python run title="bike_fare.py" input="30| E-Bike "
UNLOCK_FEE = 1.25
CLASSIC_RATE = 0.15
EBIKE_RATE = 0.30

minutes = int(input("Ride length in minutes: "))
bike = input("Bike type (classic or ebike): ").strip().lower().replace("-", "")

if bike == "ebike":
    rate = EBIKE_RATE
else:
    rate = CLASSIC_RATE

fare = UNLOCK_FEE + minutes * rate
print(f"Billed minutes: {minutes} at ${rate:.2f} a minute")
print(f"Total fare: ${fare:.2f}")
```

The rider typed ` E-Bike ` with spaces and a capital and a dash, and it still worked. `.strip()` removed the spaces, `.lower()` made it `e-bike`, and `.replace("-", "")` removed the dash to give `ebike`. All the cleaning happens on one line, so the `if` only ever has to compare against one spelling.

The `if`/`else` sets a variable called `rate`, and the calculation below uses `rate` without caring which branch set it. That's a pattern worth copying: let the decision pick a *value*, then do the math once.

## Step 3: Members

Members get two perks, and each one is a separate decision. Add the third question, then replace the fare calculation with the new section:

```python run title="bike_fare.py" input="50|classic|yes"
UNLOCK_FEE = 1.25
CLASSIC_RATE = 0.15
EBIKE_RATE = 0.30
MEMBER_FREE_MINUTES = 45

minutes = int(input("Ride length in minutes: "))
bike = input("Bike type (classic or ebike): ").strip().lower().replace("-", "")
is_member = input("Member? (yes/no): ").strip().lower().startswith("y")

if bike == "ebike":
    rate = EBIKE_RATE
else:
    rate = CLASSIC_RATE

if is_member and bike == "classic" and minutes > MEMBER_FREE_MINUTES:
    billed_minutes = minutes - MEMBER_FREE_MINUTES
elif is_member and bike == "classic":
    billed_minutes = 0
else:
    billed_minutes = minutes

if is_member:
    unlock = 0
else:
    unlock = UNLOCK_FEE

fare = unlock + billed_minutes * rate
print(f"Unlock fee: ${unlock:.2f}")
print(f"Billed minutes: {billed_minutes} at ${rate:.2f} a minute")
print(f"Total fare: ${fare:.2f}")
```

The free-minutes chain has three cases. A member on a classic bike riding *more* than 45 minutes pays for the minutes beyond 45. A member on a classic bike riding 45 minutes *or less* pays for none. Everyone else pays for every minute.

The `elif` doesn't need to say `minutes <= 45`. Any member on a classic bike who reaches the `elif` must have failed the `minutes > 45` test above it, so the order of the chain does that work for you. Why not simply subtract 45 for every member on a classic bike? Because a 30-minute ride would then be billed for -15 minutes, and Riverton would owe the rider money.

`is_member` is already a `bool`, so `if is_member:` reads like English. There's no need to write `if is_member == True:`.

## Step 4: The late fee, and choosing between > and >=

The rule says rides **longer than** 180 minutes pay the late fee. A ride of exactly 180 minutes is not longer than 180 minutes, so the right comparison is `>`, not `>=`. Add the constants and put the late fee check just before the total is printed:

```python run title="bike_fare.py" input="181|classic|no"
UNLOCK_FEE = 1.25
CLASSIC_RATE = 0.15
EBIKE_RATE = 0.30
MEMBER_FREE_MINUTES = 45
LATE_LIMIT = 180
LATE_FEE = 10.00

minutes = int(input("Ride length in minutes: "))
bike = input("Bike type (classic or ebike): ").strip().lower().replace("-", "")
is_member = input("Member? (yes/no): ").strip().lower().startswith("y")

if bike == "ebike":
    rate = EBIKE_RATE
else:
    rate = CLASSIC_RATE

if is_member and bike == "classic" and minutes > MEMBER_FREE_MINUTES:
    billed_minutes = minutes - MEMBER_FREE_MINUTES
elif is_member and bike == "classic":
    billed_minutes = 0
else:
    billed_minutes = minutes

if is_member:
    unlock = 0
else:
    unlock = UNLOCK_FEE

fare = unlock + billed_minutes * rate
print(f"Unlock fee: ${unlock:.2f}")
print(f"Billed minutes: {billed_minutes} at ${rate:.2f} a minute")
if minutes > LATE_LIMIT:
    fare += LATE_FEE
    print(f"Late fee: ${LATE_FEE:.2f} for going over {LATE_LIMIT} minutes")
print(f"Total fare: ${fare:.2f}")
```

A 181-minute ride gets the fee. Run your own file with 180 and check that it doesn't: the total should be $28.25. Notice the late fee is checked on `minutes`, the real length of the ride, not `billed_minutes`. A member's free minutes don't make a long ride any shorter.

## Step 5: Reject impossible rides

Try a ride of `0` minutes or `-5` minutes in your current version. It happily prints a fare. And a bike type of `scooter` is charged as a classic bike, because it falls into the `else`. Impossible input should get an error message, not a price.

The fix is an `if`/`elif`/`else` around everything after the questions. The two checks come first; all the pricing moves inside the `else`, so it only runs for valid rides. To move a chunk of code inside, select those lines in Thonny and press **Tab** (or choose **Edit › Indent selected lines**). **Shift+Tab** moves them back out.

```python run title="bike_fare.py" input="20|scooter|no"
UNLOCK_FEE = 1.25
CLASSIC_RATE = 0.15
EBIKE_RATE = 0.30
MEMBER_FREE_MINUTES = 45
LATE_LIMIT = 180
LATE_FEE = 10.00

minutes = int(input("Ride length in minutes: "))
bike = input("Bike type (classic or ebike): ").strip().lower().replace("-", "")
is_member = input("Member? (yes/no): ").strip().lower().startswith("y")

if minutes < 1:
    print("A ride has to last at least 1 minute.")
elif bike != "classic" and bike != "ebike":
    print(f"Sorry, there's no bike type called '{bike}'. Type classic or ebike.")
else:
    if bike == "ebike":
        rate = EBIKE_RATE
    else:
        rate = CLASSIC_RATE

    if is_member and bike == "classic" and minutes > MEMBER_FREE_MINUTES:
        billed_minutes = minutes - MEMBER_FREE_MINUTES
    elif is_member and bike == "classic":
        billed_minutes = 0
    else:
        billed_minutes = minutes

    if is_member:
        unlock = 0
    else:
        unlock = UNLOCK_FEE

    fare = unlock + billed_minutes * rate
    print(f"Unlock fee: ${unlock:.2f}")
    print(f"Billed minutes: {billed_minutes} at ${rate:.2f} a minute")
    if minutes > LATE_LIMIT:
        fare += LATE_FEE
        print(f"Late fee: ${LATE_FEE:.2f} for going over {LATE_LIMIT} minutes")
    print(f"Total fare: ${fare:.2f}")
```

Look closely at the bike check: `bike != "classic" and bike != "ebike"`. It means "it's not classic, and it's also not ebike", which is true only for something else. If you wrote `or` here, every bike would be rejected, because any bike is always "not classic" or "not ebike". When a condition says what something *isn't*, read it aloud slowly before trusting it.

The `if` statements inside the `else` are indented twice as far, and that's fine. Each level of indentation means "this belongs to the line above that ends in a colon".

## Step 6: Test every rule at its edges

The program has four cutoffs: under 1 minute, the 45 free minutes, the 180-minute late limit, and the two valid bike names. Test each one just below, on, and just above. Here's a table with the answers worked out by hand from the rules. Run your file once per row and tick off each one:

| Minutes | Bike | Member | Expected total | Checks |
| --- | --- | --- | --- | --- |
| `0` | classic | no | error: at least 1 minute | the shortest ride |
| `1` | classic | no | $1.40 | just above it |
| `45` | classic | yes | $0.00 | exactly the free limit |
| `46` | classic | yes | $0.15 | one minute past it |
| `50` | ebike | yes | $15.00 | free minutes are classic only |
| `180` | classic | no | $28.25 | exactly the late limit: no fee |
| `181` | classic | no | $38.40 | one minute over: fee added |
| `200` | classic | yes | $33.25 | member discount *and* late fee |
| `30` | ` E-Bike ` | no | $10.25 | messy typing still works |
| `20` | scooter | no | error: no such bike | unknown bike type |

If any row disagrees with your program, work out which rule it's testing and look at that part of the code. Writing the expected answer *before* running is what makes a test useful; if you write it afterwards, you'll just copy whatever the program said.

## The finished program

```python run title="bike_fare.py" input="50|classic|yes"
# bike_fare.py: works out the cost of one bike-share ride
UNLOCK_FEE = 1.25
CLASSIC_RATE = 0.15
EBIKE_RATE = 0.30
MEMBER_FREE_MINUTES = 45
LATE_LIMIT = 180
LATE_FEE = 10.00

minutes = int(input("Ride length in minutes: "))
bike = input("Bike type (classic or ebike): ").strip().lower().replace("-", "")
is_member = input("Member? (yes/no): ").strip().lower().startswith("y")

if minutes < 1:
    print("A ride has to last at least 1 minute.")
elif bike != "classic" and bike != "ebike":
    print(f"Sorry, there's no bike type called '{bike}'. Type classic or ebike.")
else:
    if bike == "ebike":
        rate = EBIKE_RATE
    else:
        rate = CLASSIC_RATE

    if is_member and bike == "classic" and minutes > MEMBER_FREE_MINUTES:
        billed_minutes = minutes - MEMBER_FREE_MINUTES
    elif is_member and bike == "classic":
        billed_minutes = 0
    else:
        billed_minutes = minutes

    if is_member:
        unlock = 0
    else:
        unlock = UNLOCK_FEE

    fare = unlock + billed_minutes * rate
    print(f"Unlock fee: ${unlock:.2f}")
    print(f"Billed minutes: {billed_minutes} at ${rate:.2f} a minute")
    if minutes > LATE_LIMIT:
        fare += LATE_FEE
        print(f"Late fee: ${LATE_FEE:.2f} for going over {LATE_LIMIT} minutes")
    print(f"Total fare: ${fare:.2f}")
```

:::quiz
Q: The rule says the fee applies to rides "longer than 180 minutes". Why is the check `minutes > LATE_LIMIT` and not `>=`?
- [ ] `>=` doesn't work with constants
  Both operators work with any numbers, constants included.
- [x] A 180-minute ride isn't longer than 180 minutes, so it shouldn't pay
  `>=` would charge the 180-minute rider too. The 180 and 181 boundary tests are what prove you chose correctly.
- [ ] `>` is faster to run
  There's no speed difference worth thinking about; the choice is about meaning.

Q: Why do the two error checks come before the pricing code instead of after it?
- [x] So that impossible rides never get priced at all
  The pricing sits inside the `else`, so it only runs when both checks pass.
- [ ] Python requires `if` statements to be at the top of a file
  `if` can go anywhere. The order here is a design choice.
- [ ] So the error messages print faster
  The point isn't speed; it's that a 0-minute ride shouldn't be charged anything.

Q: What would `elif bike != "classic" or bike != "ebike":` do?
- [ ] The same as the `and` version
  Try `classic`: it's not `ebike`, so the `or` is true and the ride is rejected.
- [x] Reject every ride, even valid ones
  Every bike is "not classic" or "not ebike" (usually both), so the condition is always true.
- [ ] Accept every ride, even scooters
  It does the opposite: it rejects everything.
:::

:::takeaways
- Put every price and limit in a named constant, and check the first calculation against the rules by hand.
- Let an `if`/`else` choose a value, then do the calculation once with that value.
- Read the rule's wording to choose `>` or `>=`; "longer than" and "at least" mean different things.
- Check for impossible input first and put the real work in the `else`.
- `x != "a" and x != "b"` rejects anything that isn't one of the two; with `or` it rejects everything.
- Write expected answers before testing, at just below, on, and just above every cutoff.
:::
