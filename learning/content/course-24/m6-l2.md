:::objectives
- Write an agent's permissions as a data structure (a task profile) instead of scattered `if` statements.
- Enforce read and write scopes, a never-touch list, and a named-command allowlist.
- Run allowed commands with a scrubbed environment so inherited secrets don't leak into them.
- Pause external actions for a human, with a prompt that shows the exact call, and log every decision.
:::

You're going to build the gate that sits between an agent and its tools, then send a docs-fixing agent through it. The agent will do nine things. Five are reasonable for the task, and four aren't: reading `.env`, editing source code, running an arbitrary command, and deploying. When you're done, the log at the end will show every one of the nine with a decision and a reason.

```mermaid caption="Every call passes the same checkpoints before anything runs"
flowchart TD
    A["Tool call from the agent"] --> B{"Tool in profile?"}
    B -->|no| D["Deny and log"]
    B -->|yes| C{"Arguments in scope?"}
    C -->|no| D
    C -->|yes| E{"Tier rule"}
    E -->|allow| R["Run with scrubbed env"]
    E -->|ask| H{"Human approves this exact call?"}
    H -->|yes| R
    H -->|no| D
    R --> L["Log the result"]
```

The cells share state, so run them in order. This lesson leaves out the schema validation from Module 5 to keep the focus on policy; in a real harness, validation runs first and the gate runs second.

## Step 1: A repository with something worth protecting

The sandbox repo has two docs, a source file, a `.env` holding a (fake) deploy token, and a small spellcheck script the agent will be allowed to run. The cell also puts a secret in the *parent* process's environment, the way a developer's shell often has one.

```python run title="permission_gate.py"
import os
from pathlib import Path

ROOT = Path("docs_repo").resolve()
files = {
    "docs/setup.md": "# Setup\nInstal the CLI with pip, then run it once.\n",
    "docs/faq.md": "# FAQ\nAsk in the forum.\n",
    "src/app.py": "print('hello')\n",
    ".env": "DEPLOY_TOKEN=fake-deploy-token-0000\n",
    "tools/spellcheck.py": (
        "import os, pathlib, sys\n"
        "TYPOS = {'Instal', 'teh', 'recieve'}\n"
        "found = [(p.name, w) for p in pathlib.Path('docs').glob('*.md')\n"
        "         for w in p.read_text().split() if w in TYPOS]\n"
        "print(f'{len(found)} typo(s) {found}')\n"
        "print('DEPLOY_TOKEN visible to this process:', 'DEPLOY_TOKEN' in os.environ)\n"
        "sys.exit(1 if found else 0)\n"
    ),
}
for name, text in files.items():
    (ROOT / name).parent.mkdir(parents=True, exist_ok=True)
    (ROOT / name).write_text(text)

# The harness itself was started from a shell that holds a deploy token.
os.environ["DEPLOY_TOKEN"] = "fake-deploy-token-0000"
print(sorted(str(p.relative_to(ROOT)) for p in ROOT.rglob("*") if p.is_file()))
```

## Step 2: Write the task profile as data

Permissions buried in code are hard to review. Permissions in one dictionary can be read in a minute, diffed in a pull request, and loaded from a file the agent can't edit. Here's the profile for a docs fix:

```python run title="permission_gate.py"
import sys

POLICY = {
    "profile": "docs-fix",
    "readable": ["docs/*", "README.md", "tools/*"],
    "writable": ["docs/*.md"],
    "never": [".env", ".env.*", "*.pem", ".git/*"],
    "commands": {"spellcheck": [sys.executable, "tools/spellcheck.py"]},
    "tool_tiers": {
        "read_file": "read",
        "replace_text": "write",
        "run_command": "write",
        "git_push": "external",
        "deploy": "external",
    },
    "tier_rules": {"read": "allow", "write": "allow", "external": "ask"},
    "denied_tools": ["deploy"],
    "env_passthrough": ["PATH", "LANG"],
}
print(f"profile {POLICY['profile']!r}: {len(POLICY['tool_tiers'])} tools, "
      f"{len(POLICY['commands'])} command, writes limited to {POLICY['writable']}")
```

Each key answers one question a reviewer would ask. What can it read? What can it change? What must it never touch, even inside those areas? Which commands can it run? Which tools need a person? Notice that `commands` maps a **name** to a fixed argument list. The agent can ask for `"spellcheck"`; it can never supply the argument list itself.

## Step 3: Check paths against the scopes

`check_path` applies the rules in a fixed order: containment first, then the never-touch list, then the read or write scope. Order matters. Because `never` is checked before `writable`, a later edit that widens `writable` to `"*"` still can't expose `.env`.

```python run title="permission_gate.py"
from fnmatch import fnmatchcase


def check_path(relative, mode):
    """Return (path, None) if the policy allows `mode` ('read' or 'write'), else (None, reason)."""
    target = (ROOT / relative).resolve()
    if not target.is_relative_to(ROOT):
        return None, f"{relative!r} resolves outside the project"
    rel = target.relative_to(ROOT).as_posix()
    if any(fnmatchcase(rel, pattern) for pattern in POLICY["never"]):
        return None, f"{rel} is on the never-touch list"
    allowed = POLICY["readable"] if mode == "read" else POLICY["writable"]
    if not any(fnmatchcase(rel, pattern) for pattern in allowed):
        word = "readable" if mode == "read" else "writable"
        return None, f"{rel} is not {word} in profile {POLICY['profile']!r}"
    return target, None


for path, mode in [("docs/setup.md", "write"), ("../../etc/hosts", "read"),
                   (".env", "read"), ("src/app.py", "write")]:
    print(f"{mode:5} {path:18} ->", check_path(path, mode)[1] or "allowed")
```

`fnmatchcase` matches the pattern against the path relative to the root, always with forward slashes (`as_posix()`), so the same profile works on Windows. Its `*` also matches `/`, which means `docs/*` covers `docs/guides/intro.md` too. That's convenient here, but remember it when you write a pattern meant to cover one folder level only.

## Step 4: Decide allow, ask, or deny

`decide` combines the tool tier with the argument checks. Anything it doesn't recognize falls through to `deny`.

```python run title="permission_gate.py"
def decide(call):
    """Return ('allow' | 'ask' | 'deny', reason) for one tool call."""
    name, args = call["name"], call["arguments"]
    if name in POLICY["denied_tools"]:
        return "deny", f"{name} is denied in profile {POLICY['profile']!r}"
    tier = POLICY["tool_tiers"].get(name)
    if tier is None:
        return "deny", f"unknown tool {name!r}"
    if name == "read_file":
        _, reason = check_path(args["path"], "read")
        if reason:
            return "deny", reason
    if name == "replace_text":
        _, reason = check_path(args["path"], "write")
        if reason:
            return "deny", reason
    if name == "run_command" and args["name"] not in POLICY["commands"]:
        return "deny", f"command {args['name']!r} is not on the allowlist"
    return POLICY["tier_rules"][tier], f"{tier} tier"


for call in [
    {"name": "read_file", "arguments": {"path": "docs/faq.md"}},
    {"name": "run_command", "arguments": {"name": "bash"}},
    {"name": "git_push", "arguments": {"branch": "docs/fix-typo"}},
    {"name": "deploy", "arguments": {}},
]:
    print(f"{call['name']:12}", decide(call))
```

`deploy` is both in the external tier and on `denied_tools`, and the denial wins because it's checked first. That's the right outcome for a docs task: asking a human "may I deploy?" would suggest deploying is a reasonable step here, and it isn't.

## Step 5: Ask a human, and show them the exact call

For `ask` decisions, the gate builds a prompt with the full tool name and arguments (never truncated), the effect, and the agent's stated reason. Each prompt also shows a **fingerprint**: a short hash of the exact name and arguments. If the arguments change by one character, the fingerprint changes, so an approval can't quietly carry over to a different call.

`ScriptedHuman` stands in for the reviewer so the demo runs offline. Note the default: when it runs out of answers, it says no.

```python run title="permission_gate.py"
import hashlib
import json


def fingerprint(call):
    canonical = json.dumps({"name": call["name"], "arguments": call["arguments"]}, sort_keys=True)
    return hashlib.sha256(canonical.encode()).hexdigest()[:12]


class ScriptedHuman:
    """Plays the reviewer: answers prompts from a script, and refuses once the script runs out."""

    def __init__(self, answers):
        self.answers = list(answers)

    def review(self, prompt):
        print(prompt)
        answer = self.answers.pop(0) if self.answers else "deny"
        print(f"  reviewer answered: {answer}\n")
        return answer == "approve"


def approval_prompt(call, reason):
    return "\n".join([
        f"APPROVAL NEEDED  profile={POLICY['profile']}  call={fingerprint(call)}",
        f"  tool:   {call['name']}",
        f"  args:   {json.dumps(call['arguments'], sort_keys=True)}",
        f"  effect: {reason}; visible outside this machine",
        f"  why:    {call.get('reason', '(no reason given)')}",
    ])


print(fingerprint({"name": "git_push", "arguments": {"branch": "docs/fix-typo"}}))
print(fingerprint({"name": "git_push", "arguments": {"branch": "docs/fix-typo", "force": True}}))
```

The "why" line is the agent's own explanation. Show it, because it helps the reviewer understand intent, but don't treat it as evidence: it's text the model generated, and an injected instruction can write a very convincing reason.

## Step 6: The gate, the tools, and a scrubbed environment

Now the tools themselves, plus `gated_execute`, which every call goes through. Look at `run_command`: it builds the child's environment from an allowlist of variable names instead of passing `os.environ` along. And `replace_text` refuses unless the old text appears exactly once, so an edit can't silently land in the wrong place.

```python run title="permission_gate.py"
import subprocess


def read_file(path):
    return check_path(path, "read")[0].read_text()


def replace_text(path, old, new):
    target = check_path(path, "write")[0]
    text = target.read_text()
    if text.count(old) != 1:
        raise ValueError(f"expected exactly one {old!r} in {path}, found {text.count(old)}")
    target.write_text(text.replace(old, new))
    return f"replaced 1 occurrence in {path}"


def run_command(name):
    env = {key: os.environ[key] for key in POLICY["env_passthrough"] if key in os.environ}
    proc = subprocess.run(POLICY["commands"][name], cwd=ROOT, env=env,
                          capture_output=True, text=True, timeout=30)
    return f"exit {proc.returncode}: {proc.stdout.strip()}"


def git_push(branch, force=False):
    return f"(simulated) pushed {branch}" + (" with --force" if force else "")


IMPLEMENTATIONS = {"read_file": read_file, "replace_text": replace_text,
                   "run_command": run_command, "git_push": git_push}
LOG = []


def gated_execute(call, human):
    decision, reason = decide(call)
    if decision == "ask":
        approved = human.review(approval_prompt(call, reason))
        decision = "allow" if approved else "deny"
        reason += ", human " + ("approved" if approved else "refused")
    entry = {"call": fingerprint(call), "tool": call["name"], "decision": decision, "reason": reason}
    if decision == "allow":
        try:
            entry["result"] = IMPLEMENTATIONS[call["name"]](**call["arguments"])
        except (ValueError, OSError) as exc:
            entry["decision"], entry["result"] = "error", str(exc)
    LOG.append(entry)
    return entry


print("gate ready:", sorted(IMPLEMENTATIONS))
```

`git_push` is simulated so nothing leaves this page. In your own harness it would run `git push` through the same scrubbed-environment path as `run_command`, with a credential scoped to this one repository.

## Step 7: Send the agent through

Here are the agent's nine calls, in the order a real model might make them for "fix the typo in `docs/setup.md`." In a full harness they'd come from the loop you built in Module 5. The reviewer will approve the first push and refuse the second.

```python run title="permission_gate.py"
agent_calls = [
    {"name": "read_file", "arguments": {"path": "docs/setup.md"}},
    {"name": "read_file", "arguments": {"path": ".env"}},
    {"name": "replace_text", "arguments": {"path": "docs/setup.md", "old": "Instal ", "new": "Install "}},
    {"name": "replace_text", "arguments": {"path": "src/app.py", "old": "hello", "new": "hi"}},
    {"name": "run_command", "arguments": {"name": "spellcheck"}},
    {"name": "run_command", "arguments": {"name": "bash"}},
    {"name": "git_push", "arguments": {"branch": "docs/fix-typo"},
     "reason": "Push the fix so a pull request can be opened."},
    {"name": "git_push", "arguments": {"branch": "main", "force": True},
     "reason": "Main was out of date, so I am updating it."},
    {"name": "deploy", "arguments": {}},
]
human = ScriptedHuman(["approve", "deny"])
for call in agent_calls:
    gated_execute(call, human)

for entry in LOG:
    result = entry.get("result", "").replace("\n", " | ")
    print(f"{entry['tool']:13} {entry['decision']:6} {entry['reason'][:50]:50} {result[:72]}")
```

Read the log from top to bottom. The `.env` read and the `src/app.py` edit were refused by scope, before any file was opened. The spellcheck ran and found no typos (the fix had already landed), and its last line reports `DEPLOY_TOKEN visible to this process: False`: the secret in the harness's environment never reached the child process. `bash` was refused because it isn't a named command. The two pushes show the approval step doing its job, and `deploy` never got as far as a human.

## The finished gate

All seven steps as one program:

```python title="permission_gate.py"
import hashlib
import json
import os
import subprocess
import sys
from fnmatch import fnmatchcase
from pathlib import Path

ROOT = Path("docs_repo").resolve()
for name, text in {
    "docs/setup.md": "# Setup\nInstal the CLI with pip, then run it once.\n",
    "src/app.py": "print('hello')\n",
    ".env": "DEPLOY_TOKEN=fake-deploy-token-0000\n",
    "tools/spellcheck.py": "import os\nprint('DEPLOY_TOKEN' in os.environ)\n",
}.items():
    (ROOT / name).parent.mkdir(parents=True, exist_ok=True)
    (ROOT / name).write_text(text)
os.environ["DEPLOY_TOKEN"] = "fake-deploy-token-0000"

POLICY = {
    "profile": "docs-fix",
    "readable": ["docs/*", "README.md", "tools/*"],
    "writable": ["docs/*.md"],
    "never": [".env", ".env.*", "*.pem", ".git/*"],
    "commands": {"spellcheck": [sys.executable, "tools/spellcheck.py"]},
    "tool_tiers": {"read_file": "read", "replace_text": "write", "run_command": "write",
                   "git_push": "external", "deploy": "external"},
    "tier_rules": {"read": "allow", "write": "allow", "external": "ask"},
    "denied_tools": ["deploy"],
    "env_passthrough": ["PATH", "LANG"],
}


def check_path(relative, mode):
    target = (ROOT / relative).resolve()
    if not target.is_relative_to(ROOT):
        return None, f"{relative!r} resolves outside the project"
    rel = target.relative_to(ROOT).as_posix()
    if any(fnmatchcase(rel, p) for p in POLICY["never"]):
        return None, f"{rel} is on the never-touch list"
    if not any(fnmatchcase(rel, p) for p in POLICY["readable" if mode == "read" else "writable"]):
        return None, f"{rel} is outside the {mode} scope"
    return target, None


def decide(call):
    name, args = call["name"], call["arguments"]
    if name in POLICY["denied_tools"]:
        return "deny", f"{name} is denied in this profile"
    tier = POLICY["tool_tiers"].get(name)
    if tier is None:
        return "deny", f"unknown tool {name!r}"
    if name in ("read_file", "replace_text"):
        _, reason = check_path(args["path"], "read" if name == "read_file" else "write")
        if reason:
            return "deny", reason
    if name == "run_command" and args["name"] not in POLICY["commands"]:
        return "deny", f"command {args['name']!r} is not on the allowlist"
    return POLICY["tier_rules"][tier], f"{tier} tier"


def fingerprint(call):
    canonical = json.dumps({"name": call["name"], "arguments": call["arguments"]}, sort_keys=True)
    return hashlib.sha256(canonical.encode()).hexdigest()[:12]


class ScriptedHuman:
    def __init__(self, answers):
        self.answers = list(answers)

    def review(self, prompt):
        print(prompt)
        return (self.answers.pop(0) if self.answers else "deny") == "approve"


def read_file(path):
    return check_path(path, "read")[0].read_text()


def replace_text(path, old, new):
    target = check_path(path, "write")[0]
    text = target.read_text()
    if text.count(old) != 1:
        raise ValueError(f"expected exactly one {old!r} in {path}")
    target.write_text(text.replace(old, new))
    return f"replaced 1 occurrence in {path}"


def run_command(name):
    env = {k: os.environ[k] for k in POLICY["env_passthrough"] if k in os.environ}
    proc = subprocess.run(POLICY["commands"][name], cwd=ROOT, env=env,
                          capture_output=True, text=True, timeout=30)
    return f"exit {proc.returncode}: {proc.stdout.strip()}"


def git_push(branch, force=False):
    return f"(simulated) pushed {branch}"


IMPLEMENTATIONS = {"read_file": read_file, "replace_text": replace_text,
                   "run_command": run_command, "git_push": git_push}


def gated_execute(call, human, log):
    decision, reason = decide(call)
    if decision == "ask":
        prompt = (f"APPROVE? {call['name']} {json.dumps(call['arguments'], sort_keys=True)} "
                  f"[{fingerprint(call)}] why: {call.get('reason', '-')}")
        decision = "allow" if human.review(prompt) else "deny"
    entry = {"call": fingerprint(call), "tool": call["name"], "decision": decision, "reason": reason}
    if decision == "allow":
        try:
            entry["result"] = IMPLEMENTATIONS[call["name"]](**call["arguments"])
        except (ValueError, OSError) as exc:
            entry["decision"], entry["result"] = "error", str(exc)
    log.append(entry)
    return entry


if __name__ == "__main__":
    log = []
    human = ScriptedHuman(["approve"])
    for call in [
        {"name": "read_file", "arguments": {"path": ".env"}},
        {"name": "replace_text", "arguments": {"path": "docs/setup.md", "old": "Instal ", "new": "Install "}},
        {"name": "run_command", "arguments": {"name": "spellcheck"}},
        {"name": "git_push", "arguments": {"branch": "docs/fix-typo"}, "reason": "open a PR"},
        {"name": "deploy", "arguments": {}},
    ]:
        gated_execute(call, human, log)
    for entry in log:
        print(entry)
```

:::quiz
Q: Why does `run_command` build the child's environment from `env_passthrough` instead of passing `os.environ`?
- [ ] `subprocess.run` can't accept the full environment
  It can; that's even the default when you pass no `env` at all.
- [x] So secrets in the harness's environment, like `DEPLOY_TOKEN`, never reach code the agent can run
  The spellcheck output proves it: the token existed in the parent but was invisible to the child.
- [ ] To make the command run faster
  Environment size has no meaningful effect on speed here.

Q: Why is the never-touch list checked before the writable scope?
- [ ] Python requires `never` to come first in the dictionary
  Dictionary order has nothing to do with it; the order of the checks in `check_path` does.
- [x] So no later widening of `writable` can ever expose `.env` or keys
  The most important refusals should be the hardest to undo by accident.
- [ ] Because reading `.env` is slower than reading Markdown
  Speed isn't the reason; safety is.

Q: The reviewer approved `git_push {"branch": "docs/fix-typo"}`. Why was the force-push to `main` prompted again?
- [ ] The scripted human always asks twice
  The gate asks; the human only answers.
- [x] Its arguments differ, so its fingerprint differs, and every distinct external call needs its own approval
  Binding approvals to the exact call stops an approval for something harmless from covering something harmful.
:::

:::takeaways
- A task profile written as data is easier to review, diff, and keep out of the agent's reach than rules spread through code.
- Check paths in a fixed order: containment, never-touch, then scope. The strongest refusals come first.
- Let the agent pick a command by name; the harness owns the argument list and the environment.
- Scrub the environment for anything the agent runs, so inherited credentials stay in the harness.
- Approval prompts show the full call and a fingerprint, default to "no", and log every outcome.
:::

## Ideas to extend it

- Load `POLICY` from a JSON file stored outside the repository, so the agent's write scope can never include its own rules.
- Add a timeout to `ScriptedHuman.review` and treat silence as a refusal.
- Count calls per tool and deny once a budget is used up (for example, at most 20 file writes per task).
- Put the schema validation from Module 5 in front of `decide`, and route both kinds of refusal back to the model as error results.
