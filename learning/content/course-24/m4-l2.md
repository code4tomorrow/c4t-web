- Confirm an agent's claim exactly as stated, then test what the claim leaves out.
- Write acceptance tests from the spec, using `subTest` to cover many inputs.
- Read real `unittest` failures, fix the code, and record evidence: command, exit code, summary, and files changed.

The agent's message is polite and specific: *"Fixed: the leftover cents now go to the last person. Added a test; all tests pass."* And it's true. All the tests do pass. The fix is still wrong, and by the end of this lesson your own tests will prove it.

You'll run every check the way you would in a terminal, with `python -m unittest -v`, called from Python so the real output appears on the page. The finished script ends with a three-line verdict and an evidence block:

```mermaid caption="Review pipeline for an agent's fix"
flowchart LR
    A["Reproduce the bug"] --> B["Apply agent's patch"]
    B --> C["Run agent's tests: OK"]
    C --> D["Add tests from the spec"]
    D --> E["Run again: FAILED"]
    E --> F["Fix, rerun: OK"]
    F --> G["Record evidence"]
```

## Step 1: Reproduce the bug

`split_bill` divides a restaurant bill between friends, in whole cents. The bug report: *"`split_bill(1000, 3)` gives `[333, 333, 333]`. A cent disappears."* Write the original code and its one test to disk, then reproduce the report and run the suite.

```python run
import os
import subprocess
import sys
from pathlib import Path

ORIGINAL_CODE = '''\
def split_bill(total_cents, people):
    """Split a bill into whole-cent shares that add up exactly to total_cents."""
    share = total_cents // people
    return [share] * people
'''
ORIGINAL_TESTS = '''\
import unittest

from bills import split_bill


class SplitBillTests(unittest.TestCase):
    def test_even_split(self):
        self.assertEqual(split_bill(900, 3), [300, 300, 300])
'''
Path("bills.py").write_text(ORIGINAL_CODE)
Path("test_bills.py").write_text(ORIGINAL_TESTS)


def run_tests():
    """Run the suite as you would in a terminal and show everything it printed."""
    # -B: don't cache compiled files; this script rewrites them faster than the cache notices.
    result = subprocess.run([sys.executable, "-B", "-m", "unittest", "-v"],
                            capture_output=True, text=True)
    print(result.stderr.replace(os.getcwd() + os.sep, "").strip())
    print("exit code:", result.returncode)
    return result.returncode


shares = subprocess.run([sys.executable, "-B", "-c", "from bills import split_bill; print(split_bill(1000, 3))"],
                        capture_output=True, text=True).stdout.strip()
print("split_bill(1000, 3) =", shares)
print()
run_tests()
```

The bug is real, and the suite is green anyway: the only test uses 900, which divides evenly. That's how this bug got merged in the first place. Note that `unittest` writes its report to **stderr**, which is why `run_tests` prints `result.stderr`.

The shape is good: two expected files, a test added and none edited. The idea is reasonable too. `total_cents - share * people` is the leftover, and the last person pays it. Before reading further, ask the question the patch doesn't: **how big can the leftover get?**

Two tests, `OK`, exit code 0. The agent didn't lie. But its test checks one input, and that input was chosen by the same process that wrote the code. A test written that way tends to confirm the code rather than the requirement.

## Step 4: Write tests from the spec, not from the patch

Go back to what the function is *for*. Here's the spec, which in a real project would be in the issue or the task you wrote:

```text
split_bill(total_cents, people) returns a list of `people` whole-cent shares.
1. The shares add up exactly to total_cents.
2. No two shares differ by more than 1 cent.
3. Any extra cents go to the first people in the list.
4. people < 1 raises ValueError.
```

Each rule becomes a test. Rules 1 and 2 should hold for *every* input, so they loop over a handful of cases with `subTest`, which reports each failing case separately instead of stopping at the first. The cases are picked to probe edges: a remainder of 3 (`1003, 4`), a total smaller than the head count (`1, 4`), zero, and an even split.

```python run
ACCEPTANCE = '''

class AcceptanceTests(unittest.TestCase):
    """Written from the spec, not from the patch."""

    CASES = [(1000, 3), (1003, 4), (7, 3), (5, 5), (0, 2), (1, 4)]

    def test_shares_add_up_to_the_total(self):
        for total, people in self.CASES:
            with self.subTest(total=total, people=people):
                self.assertEqual(sum(split_bill(total, people)), total)

    def test_shares_differ_by_at_most_one_cent(self):
        for total, people in self.CASES:
            with self.subTest(total=total, people=people):
                shares = split_bill(total, people)
                self.assertLessEqual(max(shares) - min(shares), 1, shares)

    def test_extra_cents_go_to_the_first_people(self):
        self.assertEqual(split_bill(1003, 4), [251, 251, 251, 250])

    def test_nobody_to_split_with_is_an_error(self):
        with self.assertRaises(ValueError):
            split_bill(1000, 0)
'''
print(f"{ACCEPTANCE.count('def test_')} acceptance tests written")
```

## Step 5: Run them and read the failures

```python run
Path("test_bills.py").write_text(ORIGINAL_TESTS + AGENT_TEST + ACCEPTANCE)
run_tests()
```

Read the report from the bottom up. `FAILED (failures=2, errors=1)` and exit code 1 are the verdict. Then each block explains one problem:

- **`(total=1003, people=4)`**, from the `subTest`: the shares are `[250, 250, 250, 253]`. The leftover can be as large as `people - 1` cents, and the patch dumps all of it on one person. With 1000 and 3, the leftover happened to be 1, which is why the agent's test passed.
- **`test_extra_cents_go_to_the_first_people`**: same root cause, seen through rule 3.
- **`ERROR`, not `FAIL`, for zero people**: the code raised `ZeroDivisionError` before `assertRaises(ValueError)` could match. In `unittest`, FAIL means an assertion was false; ERROR means the code crashed with an exception the test didn't expect.

Notice what passed: rule 1. The patch *does* make the shares add up, which is the only thing its test and its summary claimed.

## Step 6: Fix it properly

`divmod(total, people)` returns the share and the leftover in one step. The first `extra` people pay one cent more, so no two shares differ by more than 1. A guard clause handles zero people before any division happens.

```python run
OUR_CODE = ORIGINAL_CODE.replace(
    "    share = total_cents // people\n    return [share] * people\n",
    "    if people < 1:\n"
    '        raise ValueError(f"people must be at least 1, got {people}")\n'
    "    share, extra = divmod(total_cents, people)\n"
    "    return [share + 1 if i < extra else share for i in range(people)]\n",
)
Path("bills.py").write_text(OUR_CODE)
print(OUR_CODE)
run_tests()
```

Five tests pass, and the agent's own test now fails: it expected `[333, 333, 334]`, but the spec says the extra cent goes to the *first* person. In the previous lesson, a test edited in the same change as the code was a red flag. Here you'll edit one, and the difference is the reason: the expectation conflicts with a written spec that you own, and you can point at the rule. Write that reason in the commit message.

## Step 7: Rerun and record the evidence

```python run
import difflib


def line_counts(old, new):
    """Lines added and removed, the numbers `git diff --stat` would show."""
    diff = list(difflib.unified_diff(old.splitlines(), new.splitlines(), lineterm=""))
    added = sum(1 for line in diff if line.startswith("+") and not line.startswith("+++"))
    removed = sum(1 for line in diff if line.startswith("-") and not line.startswith("---"))
    return f"+{added} -{removed}"


FINAL_TESTS = ORIGINAL_TESTS + AGENT_TEST.replace("[333, 333, 334]", "[334, 333, 333]") + ACCEPTANCE
Path("test_bills.py").write_text(FINAL_TESTS)
exit_code = run_tests()
print()
print("evidence")
print("  command:   python -m unittest -v")
print("  exit code:", exit_code)
print("  files:     bills.py", line_counts(ORIGINAL_CODE, OUR_CODE),
      "| test_bills.py", line_counts(ORIGINAL_TESTS, FINAL_TESTS))
```

That block is what "all tests pass" should look like when anyone, human or agent, says it: a command someone else can rerun, its exit code, and a list of what changed. Paste it into the pull request.

## The finished review script

This version runs all three stages quietly and prints one line per stage, then the evidence.

```python run title="review_fix.py"
import difflib
import subprocess
import sys
from pathlib import Path

ORIGINAL_CODE = '''\
def split_bill(total_cents, people):
    """Split a bill into whole-cent shares that add up exactly to total_cents."""
    share = total_cents // people
    return [share] * people
'''
ORIGINAL_TESTS = '''\
import unittest

from bills import split_bill


class SplitBillTests(unittest.TestCase):
    def test_even_split(self):
        self.assertEqual(split_bill(900, 3), [300, 300, 300])
'''

# What the agent sent: a patch, one new test, and a claim.
AGENT_CODE = ORIGINAL_CODE.replace(
    "    return [share] * people\n",
    "    shares = [share] * people\n"
    "    shares[-1] += total_cents - share * people\n"
    "    return shares\n",
)
AGENT_TEST = '''
    def test_leftover_cent_is_not_lost(self):
        self.assertEqual(split_bill(1000, 3), [333, 333, 334])
'''
AGENT_CLAIM = "Fixed: the leftover cents now go to the last person. Added a test; all tests pass."

# What we wrote: tests from the spec, and a fix that satisfies them.
ACCEPTANCE = '''

class AcceptanceTests(unittest.TestCase):
    CASES = [(1000, 3), (1003, 4), (7, 3), (5, 5), (0, 2), (1, 4)]

    def test_shares_add_up_to_the_total(self):
        for total, people in self.CASES:
            with self.subTest(total=total, people=people):
                self.assertEqual(sum(split_bill(total, people)), total)

    def test_shares_differ_by_at_most_one_cent(self):
        for total, people in self.CASES:
            with self.subTest(total=total, people=people):
                shares = split_bill(total, people)
                self.assertLessEqual(max(shares) - min(shares), 1, shares)

    def test_extra_cents_go_to_the_first_people(self):
        self.assertEqual(split_bill(1003, 4), [251, 251, 251, 250])

    def test_nobody_to_split_with_is_an_error(self):
        with self.assertRaises(ValueError):
            split_bill(1000, 0)
'''
OUR_CODE = ORIGINAL_CODE.replace(
    "    share = total_cents // people\n    return [share] * people\n",
    "    if people < 1:\n"
    '        raise ValueError(f"people must be at least 1, got {people}")\n'
    "    share, extra = divmod(total_cents, people)\n"
    "    return [share + 1 if i < extra else share for i in range(people)]\n",
)


def run_tests():
    result = subprocess.run([sys.executable, "-B", "-m", "unittest", "-v"],
                            capture_output=True, text=True)
    return result.returncode, result.stderr.strip().splitlines()


def stage(label, code, tests):
    Path("bills.py").write_text(code)
    Path("test_bills.py").write_text(tests)
    exit_code, output = run_tests()
    print(f"{label:<36} {output[-1]} (exit {exit_code})")
    return exit_code, output


def line_counts(old, new):
    diff = list(difflib.unified_diff(old.splitlines(), new.splitlines(), lineterm=""))
    added = sum(1 for line in diff if line.startswith("+") and not line.startswith("+++"))
    removed = sum(1 for line in diff if line.startswith("-") and not line.startswith("---"))
    return f"+{added} -{removed}"


print("agent says:", AGENT_CLAIM)
stage("agent's patch, agent's tests:", AGENT_CODE, ORIGINAL_TESTS + AGENT_TEST)
stage("agent's patch, acceptance tests:", AGENT_CODE, ORIGINAL_TESTS + AGENT_TEST + ACCEPTANCE)
final_tests = ORIGINAL_TESTS + AGENT_TEST.replace("[333, 333, 334]", "[334, 333, 333]") + ACCEPTANCE
exit_code, output = stage("our fix, acceptance tests:", OUR_CODE, final_tests)

print()
print("evidence")
print("  command:  ", "python -m unittest -v")
print("  exit code:", exit_code)
print("  summary:  ", " / ".join(line for line in output[-3:] if line))
print("  files:    ", f"bills.py ({line_counts(ORIGINAL_CODE, OUR_CODE)}),",
      f"test_bills.py ({line_counts(ORIGINAL_TESTS, final_tests)})")
```

:::quiz
Q: The agent's test passed with its own patch. Why wasn't that enough to approve it?
- [ ] The test had a typo
  The test was correct for the one input it checked.
- [x] It checked a single input chosen by the same process that wrote the code, and that input hid the bug
  With 1000 and 3 the leftover is 1 cent, so dumping it on one person looks fine. Inputs chosen from the spec exposed the problem.
- [ ] Agent-written tests never count
  They count as some evidence. They just can't be the only evidence.

Q: Why was editing the agent's expected value from `[333, 333, 334]` to `[334, 333, 333]` acceptable here, when Module 4's Notes called edited expectations a red flag?
- [x] The new value follows a written rule in the spec, and the reason goes in the commit message
  The red flag is an expectation changed to match the code. This one changed to match the requirement, and anyone can check that.
- [ ] Because we wrote the fix, not the agent
  Who made the edit doesn't matter; whether it follows the spec does.
- [ ] Because the test was failing
  A failing test is never, on its own, a reason to change its expectation.

Q: Why does `run_tests` call `python -m unittest` in a subprocess and keep its exit code?
- [ ] Subprocesses make tests run faster
  They're slightly slower. Speed isn't the reason.
- [x] It's exactly the command a reviewer or CI would run, and the exit code is the machine-readable verdict
  Running the real command makes the evidence reproducible, and an exit code of 0 or 1 can't be paraphrased.
:::

:::takeaways
- Reproduce the bug and run the existing suite before looking at any fix; a green suite that misses the bug explains how it shipped.
- Check the agent's claim exactly as stated, then ask what the claim leaves out.
- Write acceptance tests from the spec, with edge-case inputs, using `subTest` to cover many cases.
- In `unittest`, FAIL means an assertion was false and ERROR means an unexpected exception.
- Evidence is a rerunnable command, its exit code, the summary line, and the files changed.
:::

## Ideas to extend it

- Turn rules 1 and 2 into a *property test*: generate 1,000 random `(total, people)` pairs with `random.randint` (with a fixed seed so failures repeat) instead of six hand-picked cases.
- Add a check that fails the review if any existing test method disappeared between `ORIGINAL_TESTS` and the final file.
- Run `ruff check` and `mypy` as extra stages when they're installed, and skip them with a note when they aren't.
