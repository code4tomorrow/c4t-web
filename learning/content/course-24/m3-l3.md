:::objectives
- Turn claims from an AI's repository map into searches, and read the results correctly.
- Catch file paths an AI invented by comparing them with the tracked file list.
- Critique a plan in writing and name the questions to ask before approving a risky one.
- Extend a plan checker with a tests-first rule and a dependency-order check.
:::

Most exercises use the same small `shop` repository, so its files are in the first solution and reused after that. Each solution is self-contained: copy it, run it, then change the inputs and see what breaks.

## Warm-up: what kind of claim is this?

:::quiz
Q: "The `Order` class is defined in `shop/models.py`." What's the cheapest way to check it?
- [x] `git grep -n "class Order"`
  One search shows every file that defines it, including the case where it's defined twice.
- [ ] Run the whole test suite
  Tests can pass whether or not this claim is true; they don't tell you where a class lives.
- [ ] Ask the AI to double-check
  The same model rereading the same context tends to repeat the same answer.

Q: "Nothing reads the `LEGACY_MODE` setting anymore." What kind of claim is it, and how much do you trust a search with no hits?
- [ ] Existence; fully
  It's a claim that something *doesn't* exist, which is the hard kind.
- [x] Absence; strong evidence in a small repo, weaker if config can be read by building names as strings
  Code like `os.environ["LEGACY_" + mode]` can read it without the full name ever appearing.

Q: "`apply_coupon` returns the total unchanged for unknown codes." How do you check it?
- [ ] Search for `apply_coupon`
  The search finds where it's used, not what it does.
- [x] Read the function, then run it (or a test) with an unknown code
  Behavior claims need the code to run. Searching only answers where things are.
:::

### Exercise 1: Count the real call sites

The AI's map says: *"`apply_coupon` is called in exactly one place, `shop/checkout.py`."* Write `call_sites(files, name)` that returns `file:line` for every line calling `name(`, excluding the line that defines it. Make sure `apply_coupon_v2(` doesn't count as a call to `apply_coupon`.

```text
apply_coupon is called at:
   shop/cart.py:6
   shop/checkout.py:5
   tests/test_cart.py:5
```

:::hint
`\b` in a regex marks a word boundary, and `(` must be escaped as `\(`. Since `_` counts as a word character, `\bapply_coupon\(` doesn't match `apply_coupon_v2(`. Skip lines whose stripped text starts with `def `.
:::

:::solution
```python run title="call_sites.py"
import re

FILES = {
    "shop/cart.py": (
        "def apply_coupon(total, code):\n"
        "    return total - COUPONS.get(code, 0)\n"
        "\n"
        "\n"
        "def apply_coupon_v2(total, code, user):\n"
        "    return apply_coupon(total, code) if user.active else total\n"
    ),
    "shop/checkout.py": (
        "from shop.cart import apply_coupon\n"
        "\n"
        "\n"
        "def checkout(cart, code):\n"
        "    return apply_coupon(cart.total, code)\n"
    ),
    "tests/test_cart.py": (
        "from shop.cart import apply_coupon\n"
        "\n"
        "\n"
        "def test_unknown_code_changes_nothing():\n"
        '    assert apply_coupon(100, "NOPE") == 100\n'
    ),
}


def call_sites(files, name):
    pattern = re.compile(rf"\b{re.escape(name)}\(")
    hits = []
    for path, text in sorted(files.items()):
        for number, line in enumerate(text.splitlines(), start=1):
            if pattern.search(line) and not line.lstrip().startswith("def "):
                hits.append(f"{path}:{number}")
    return hits


print("apply_coupon is called at:")
for hit in call_sites(FILES, "apply_coupon"):
    print("  ", hit)
```

Three call sites, not one. The import lines don't count because they have no `(` after the name. The one in `cart.py` is the interesting miss: `apply_coupon_v2` calls the original, so changing `apply_coupon`'s behavior changes `v2` too, which a fix based on the AI's claim would never test. `re.escape` makes the function safe for names containing regex characters.
:::

### Exercise 2: Catch the invented paths

Here is part of an AI's repository map and the repository's tracked files:

```python
TRACKED = {"README.md", "shop/__init__.py", "shop/cart.py", "shop/checkout.py",
           "shop/emails.py", "shop/templates/receipt.txt", "tests/test_cart.py"}

AI_MAP = """The cart logic lives in shop/cart.py, and shop/checkout.py calls it.
Coupons are loaded from shop/coupons.json at startup.
Emails are rendered by shop/emails.py using shop/templates/receipt.html.
Tests are in tests/test_cart.py and tests/test_checkout.py."""
```

Write `invented_paths(text, tracked)` that finds every path-like string in the map and returns the ones that don't exist.

```text
['shop/coupons.json', 'shop/templates/receipt.html', 'tests/test_checkout.py']
```

:::hint
A path here is a run of letters, digits, `_`, `.`, `/`, or `-`, followed by a dot and an extension: `[\w./-]+\.\w+`. A sentence-ending period can stick to the match, so strip trailing dots. Then it's a set difference.
:::

:::solution
```python run title="invented_paths.py"
import re

TRACKED = {"README.md", "shop/__init__.py", "shop/cart.py", "shop/checkout.py",
           "shop/emails.py", "shop/templates/receipt.txt", "tests/test_cart.py"}

AI_MAP = """The cart logic lives in shop/cart.py, and shop/checkout.py calls it.
Coupons are loaded from shop/coupons.json at startup.
Emails are rendered by shop/emails.py using shop/templates/receipt.html.
Tests are in tests/test_cart.py and tests/test_checkout.py."""


def invented_paths(text, tracked):
    mentioned = {path.rstrip(".") for path in re.findall(r"[\w./-]+\.\w+", text)}
    return sorted(mentioned - tracked)


print(invented_paths(AI_MAP, TRACKED))
```

Look at the shapes of the three mistakes. `receipt.html` is a near miss of the real `receipt.txt`. `test_checkout.py` is the file that *should* exist by naming convention, so the model assumed it did, which also tells you checkout has no tests. `coupons.json` is invented outright. Pattern-completion errors like these are why every path in a map gets checked.
:::

### Exercise 3: Critique this plan

Task: *"Add a `--dry-run` flag to `cleanup.py` that prints which old log files would be deleted, without deleting them."* The agent's plan:

```text
1. Run python cleanup.py on the logs/ folder to see what it currently does.
2. Switch the script from argparse to click for nicer flags.
3. Add --dry-run.
4. Update the CI config so the cleanup job uses --dry-run.
5. Done; the flag works.
```

Write down at least four problems, and say which one you'd raise first.

:::hint
Which step changes real data? Which steps aren't part of the task? Where is the evidence that the flag works? What is the plan assuming about the code?
:::

:::solution
- **Step 1 is the one to raise first.** Running the script without the flag *deletes the log files*, the exact thing the task is trying to avoid. Read the code instead, or run it on a copied folder.
- **Step 2 is scope creep with a cost.** Switching libraries adds a dependency and changes every flag's behavior, and the task never asked for it.
- **Step 3 is vague.** "Add --dry-run" doesn't say what the dry run prints or which code path it skips.
- **Step 4 changes shared infrastructure.** CI configuration affects everyone. It's out of scope and needs its own approval.
- **Step 5 claims success without evidence.** There's no test, for example one that creates temporary old files, runs with `--dry-run`, and checks that every file still exists.
- **Hidden assumption:** that the script uses argparse at all, and that nothing else imports it. Neither was checked.

Step 1 goes first because it's the only step that can cause harm Git can't undo: deleted log files were never in the repository.
:::

### Exercise 4: Check a "safe to delete" claim

The AI says three functions are unused and safe to delete: `apply_coupon_v2`, `send_welcome`, and `format_total`. Write `references(files, name)` that finds every line in **any** tracked file (not only `.py` files) that mentions the name as a whole word, other than its own `def` line. Then report on each claim.

```text
apply_coupon_v2: no references found in tracked files
send_welcome: NOT safe to delete, referenced at shop/emails.py:9
format_total: NOT safe to delete, referenced at shop/templates/receipt.txt:1
```

:::hint
Search for the bare name with `\bname\b`, not `name(`. One of these functions is never called with parentheses in the code, only named in a string.
:::

:::solution
```python run title="safe_to_delete.py"
import re

FILES = {
    "shop/cart.py": (
        "def apply_coupon(total, code):\n"
        "    return total - COUPONS.get(code, 0)\n"
        "\n"
        "\n"
        "def apply_coupon_v2(total, code, user):\n"
        "    return apply_coupon(total, code) if user.active else total\n"
    ),
    "shop/emails.py": (
        "def send_welcome(user):\n"
        '    return f"Welcome, {user.name}!"\n'
        "\n"
        "\n"
        "def format_total(cents):\n"
        '    return f"${cents / 100:.2f}"\n'
        "\n"
        "\n"
        'HANDLERS = {"welcome": "send_welcome"}\n'
        "\n"
        "\n"
        "def dispatch(kind, user):\n"
        "    return globals()[HANDLERS[kind]](user)\n"
    ),
    "shop/templates/receipt.txt": "Thanks! You paid {{ format_total(total) }}.\n",
}


def references(files, name):
    """Every file:line that mentions name as a whole word, except its own def line."""
    word = re.compile(rf"\b{re.escape(name)}\b")
    hits = []
    for path, text in sorted(files.items()):
        for number, line in enumerate(text.splitlines(), start=1):
            if word.search(line) and not re.match(rf"\s*def {re.escape(name)}\(", line):
                hits.append(f"{path}:{number}")
    return hits


for name in ["apply_coupon_v2", "send_welcome", "format_total"]:
    hits = references(FILES, name)
    if hits:
        print(f"{name}: NOT safe to delete, referenced at {', '.join(hits)}")
    else:
        print(f"{name}: no references found in tracked files")
```

`send_welcome` is reached through a string in `HANDLERS` and a `globals()` lookup, so searching for `send_welcome(` would have missed it. `format_total` is used only by a template, which an AI that read only Python files would never see. And "no references" for `apply_coupon_v2` still only covers *this* repository: another project could import it, which is why deleting a public function is a question for a human.
:::

### Exercise 5: Add a tests-first rule to the plan checker

For a bug fix, the safest plan changes a test before it changes the code (so the test can fail first). Write `check_test_first(steps)` that returns a `WARN` finding if the first `.py` file a plan edits isn't a test file (`test_*.py`).

```text
code first: [('WARN', 2, 'edits app/pricing.py before adding or changing any test')]
test first: []
```

:::hint
Walk the steps in order and stop at the first `edit` of a `.py` file. If it's a test file, there's nothing to report; otherwise return one finding with that step's number.
:::

:::solution
```python run title="test_first.py"
def is_test_file(path):
    name = path.rsplit("/", 1)[-1]
    return name.startswith("test_") and name.endswith(".py")


def check_test_first(steps):
    """WARN if the plan edits code before it edits any test file."""
    for number, step in enumerate(steps, start=1):
        if step.get("action") != "edit" or not step.get("path", "").endswith(".py"):
            continue
        if is_test_file(step["path"]):
            return []
        return [("WARN", number, f"edits {step['path']} before adding or changing any test")]
    return []


code_first = [
    {"action": "read", "path": "app/pricing.py"},
    {"action": "edit", "path": "app/pricing.py"},
    {"action": "edit", "path": "tests/test_pricing.py"},
    {"action": "run", "command": "python -m unittest discover -s tests"},
]
test_first = [code_first[0], code_first[2], code_first[1], code_first[3]]
print("code first:", check_test_first(code_first))
print("test first:", check_test_first(test_first))
```

It's a WARN, not a BLOCK, because some correct plans edit code first (a pure refactor with existing tests, for instance). The rule is a prompt for a question: "how will you know the bug was there before your fix?"
:::

### Exercise 6: Questions before a risky plan

An agent's plan for *"Speed up the orders page"* includes this step:

```text
4. Add a migration that drops the unused orders.notes column and adds an index on orders.created_at.
```

Write four questions you'd want answered before approving step 4.

:::hint
Think about data that can't come back, about what "unused" was based on, about how the change reaches the real database, and about how you'd know it helped.
:::

:::solution
1. **How do we know `notes` is unused?** Which search was run, and did it cover reports, admin tools, and other services that read the same database?
2. **Can it be undone?** Dropping a column deletes its data. Is there a backup, and does the migration have a working reverse step?
3. **Where does this run first?** On a copy of production data, or straight against the real database? How long does building the index take on the real table size, and does it lock writes while it runs?
4. **What's the evidence it's faster?** Which query is slow today, how long does it take, and what number counts as fixed?

A good outcome is often to split the step: approve the index (reversible, directly tied to the task) and send the column drop back as its own reviewed change.
:::

### Challenge: Steps out of order and circular plans

Some agents return plans as a graph: each step has an `id` and an `after` list of steps it depends on. Write `order_problems(steps)` that reports (1) any step listed before a step it depends on, (2) any dependency that isn't in the plan, and (3) a dependency cycle, if there is one.

```mermaid caption="The first test plan: edit-code is listed before add-test, which it depends on"
flowchart LR
    R["read-code"] --> T["add-test"]
    R --> E["edit-code"]
    T --> E
    E --> U["run-tests"]
    T --> U
    W["write-changelog (missing)"] -.-> D["update-docs"]
```

```text
edit-code runs before add-test, which it depends on
update-docs depends on write-changelog, which isn't in the plan
---
a runs before c, which it depends on
cycle: a needs c needs b needs a
```

:::hint
Map each id to its position in the list; a dependency with a larger position than the step is out of order. For cycles, do a depth-first walk along `after` links while keeping the current path. Reaching a node that's already on the path means you've found a cycle.
:::

:::solution
```python run title="plan_order.py"
def order_problems(steps):
    """Find steps that come before something they depend on, and dependency cycles."""
    position = {step["id"]: index for index, step in enumerate(steps)}
    after = {step["id"]: step.get("after", []) for step in steps}
    problems = []
    for step in steps:
        for need in step.get("after", []):
            if need not in position:
                problems.append(f"{step['id']} depends on {need}, which isn't in the plan")
            elif position[need] > position[step["id"]]:
                problems.append(f"{step['id']} runs before {need}, which it depends on")

    def find_cycle(node, path):
        if node in path:
            return path[path.index(node):] + [node]
        for need in after.get(node, []):
            cycle = find_cycle(need, path + [node])
            if cycle:
                return cycle
        return None

    for step in steps:
        cycle = find_cycle(step["id"], [])
        if cycle:
            problems.append("cycle: " + " needs ".join(cycle))
            break
    return problems


plan = [
    {"id": "read-code", "after": []},
    {"id": "edit-code", "after": ["read-code", "add-test"]},
    {"id": "add-test", "after": ["read-code"]},
    {"id": "run-tests", "after": ["edit-code", "add-test"]},
    {"id": "update-docs", "after": ["write-changelog"]},
]
for problem in order_problems(plan):
    print(problem)
print("---")
loop = [
    {"id": "a", "after": ["c"]},
    {"id": "b", "after": ["a"]},
    {"id": "c", "after": ["b"]},
]
for problem in order_problems(loop):
    print(problem)
```

`path + [node]` builds a new list on each call instead of changing a shared one, so every branch of the search keeps its own path. A cycle in a plan is never a reordering problem: no order can satisfy it, so it goes back to the agent with the cycle spelled out. For large plans you'd want Python's built-in `graphlib.TopologicalSorter`, which raises `CycleError` on the same input.
:::
