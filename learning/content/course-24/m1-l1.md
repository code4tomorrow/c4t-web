:::objectives
- Install Python 3.10 or newer, Git, and VS Code on Windows, macOS, or Linux.
- Configure Git with your name, email, and `main` as the default branch.
- Connect one AI coding assistant: GitHub Copilot Free, or a local model served by Ollama.
- Create a course virtual environment with `jsonschema` installed.
- Run a script that checks every tool and recognize the install problems people hit most.
:::

A coding agent that can edit files and run commands on your laptop is a program running with **your** permissions. It can delete a folder as easily as you can. So before you hand one a task, you want three things already in place: a language that runs the code it writes, a version-control system that can undo anything it does, and an editor where you can watch every change land.

That is the whole setup for this course. Everything here is free, and no step needs a credit card.

## What each piece does

```mermaid caption="Your workbench: the assistant proposes, Git records, Python checks"
flowchart LR
    You["You (task + review)"] --> Code["VS Code"]
    Code <--> AI["AI assistant (Copilot or Ollama)"]
    Code --> Repo["Git repo on a branch"]
    Repo --> Tests["python -m unittest"]
    Tests -->|evidence| You
```

- **Python 3** runs the practice code and its tests. Most examples use only the standard library. Module 5 adds two packages, `jsonschema` (installed in Step 5) and the MCP Python SDK (installed in that module).
- **Git** takes snapshots of your project. When an agent makes a mess, `git diff` shows exactly what it touched and `git restore` puts it back.
- **VS Code** is the editor. Its chat panel is where you talk to an assistant, and its source-control view shows every change before you commit it.
- **An AI assistant** suggests or makes changes. You pick one in Step 4. The course never depends on a particular company's model; the skills (scoping, reviewing, verifying) transfer to any of them.

## Step 1: Install Python 3.10 or newer

Already have Python? Run `python --version` (Windows) or `python3 --version` (macOS, Linux). If it says 3.10 or higher, skip ahead.

:::tabs
@tab Windows
1. Open [python.org/downloads](https://www.python.org/downloads/) and download the **Python install manager** (the Microsoft Store's "Python install manager" is the same program).
2. Run it and choose **Install**.
3. Open a new **PowerShell** window and install the current release:

```powershell
py install default
python --version
```

If no runtime is installed yet, simply typing `python` also triggers the install.
@tab macOS
1. Download the macOS installer from [python.org/downloads](https://www.python.org/downloads/) and run the `.pkg` with the default options.
2. Open **Terminal** and check:

```bash
python3 --version
```

On a Mac, type `python3`. Plain `python` usually doesn't exist.
@tab Linux / Chromebook
On a Chromebook, first turn on Linux in **Settings › About ChromeOS › Developers › Linux development environment**, then use its Terminal. On Debian or Ubuntu:

```bash
sudo apt update
sudo apt install python3 python3-venv
python3 --version
```
:::

## Step 2: Install Git and introduce yourself to it

:::tabs
@tab Windows
Download **Git for Windows** from [git-scm.com/install/windows](https://git-scm.com/install/windows) and accept the defaults, or install it from PowerShell:

```powershell
winget install --id Git.Git -e --source winget
```

Close PowerShell and open a new window so it picks up the new `git` command.
@tab macOS
Apple ships Git with the Xcode Command Line Tools:

```bash
xcode-select --install
```

If you use Homebrew, `brew install git` gets a newer version.
@tab Linux / Chromebook
```bash
sudo apt install git
```
:::

Now tell Git who you are. These values label your commits. Then make new repositories start on a branch named `main`:

```bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
git --version
```

## Step 3: Install VS Code and the Python extension

Download VS Code from [code.visualstudio.com](https://code.visualstudio.com/) and install it. On Linux or a Chromebook, choose the `.deb` package and install it with `sudo apt install ./code_*.deb` from the folder you saved it in.

Open VS Code, press **Ctrl+Shift+X** (**Cmd+Shift+X** on a Mac) to open Extensions, search for `Python`, and install the one published by **Microsoft**. Open a terminal inside VS Code with **Terminal › New Terminal**; you'll use it constantly.

## Step 4: Connect an AI assistant

Pick one path. You can add the other later.

| | Path A: GitHub Copilot Free | Path B: Ollama with a local model |
| --- | --- | --- |
| Where the model runs | GitHub's servers | Your own computer |
| Account needed | A GitHub account (you must be 13 or older) | None |
| Inline suggestions while typing | Yes | No (VS Code can't use local models for these) |
| Chat and agent work | Yes, within a monthly allowance | Yes, if the model supports tool calling |
| Quality on hard tasks | Strong | Weaker; small models make more mistakes |
| Your code leaves your machine | Yes | No |

**Path A: Copilot Free.** In VS Code, hover over the Copilot icon in the Status Bar (the bar along the bottom) and select **Use AI Features**, then sign in with GitHub. An account without a paid plan is enrolled in Copilot Free, which includes up to 2,000 completions a month and an allowance for chat. If you're a verified student through [GitHub Education](https://docs.github.com/en/copilot/how-tos/copilot-on-github/set-up-copilot/enable-copilot/set-up-for-students), you may get the larger Copilot Student plan at no cost.

**Path B: Ollama.** Install it from [ollama.com/download](https://ollama.com/download). Ollama needs Windows 10 22H2 or newer, or macOS 14 (Sonoma) or newer; on Linux, use `curl -fsSL https://ollama.com/install.sh | sh`. Then download a small model that supports tool calling and talk to it:

```bash
ollama pull qwen3:1.7b
ollama run qwen3:1.7b
```

The download is about 1.4 GB. Type a question, read the answer, and type `/bye` to leave. To use the model inside VS Code, install the **Ollama** extension (published by Ollama) from the Extensions view, then choose the model from the model picker in the Chat view. If it doesn't appear, run **Chat: Manage Language Models** from the Command Palette (**Ctrl+Shift+P**, or **Cmd+Shift+P** on a Mac) and reload the window.

:::note
Paid assistants (Copilot Pro, or the coding agents sold by model companies) work with this course too, but nothing requires them. When a lesson shows a prompt, paste it into whichever assistant you set up.
:::

## Step 5: Make the course folder and its virtual environment

Make a folder named `agent-course` somewhere easy to find and open it in VS Code with **File › Open Folder…**. Then, in a VS Code terminal, create a **virtual environment**: a private Python inside this folder, so packages you install for the course can't clash with anything else on your computer.

:::tabs
@tab Windows
```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install jsonschema
```
@tab macOS
```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install jsonschema
```
@tab Linux / Chromebook
```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install jsonschema
```
:::

Your prompt now starts with `(.venv)`. If VS Code asks whether to use the new environment for this workspace, choose **Yes**. Activate it again (the second line above) whenever you open a new terminal for the course. While it's active, plain `python` means the environment's Python on every system, macOS included.

`jsonschema` checks data against a JSON Schema, which Module 5 uses to validate the arguments a model sends to a tool. Starting the install with `python -m pip` guarantees it goes into the environment you just activated.

## Step 6: Check everything at once

Create `check_setup.py` in `agent-course`:

```python title="check_setup.py"
import shutil
import subprocess
import sys


def version_of(command):
    """Return the tool's --version text, or None if it isn't on PATH."""
    if shutil.which(command) is None:
        return None
    result = subprocess.run([command, "--version"], capture_output=True, text=True)
    return (result.stdout or result.stderr).strip().splitlines()[0]


print("python:", sys.version.split()[0])
if sys.version_info < (3, 10):
    print("  Python 3.10 or newer is needed. Install a newer one.")

print("in a virtual environment:", sys.prefix != sys.base_prefix)

for tool, required in [("git", True), ("ollama", False)]:
    found = version_of(tool)
    if found:
        print(f"{tool}: {found}")
    elif required:
        print(f"{tool}: NOT FOUND. Install it, then open a new terminal.")
    else:
        print(f"{tool}: not installed (optional)")

try:
    import jsonschema  # noqa: F401
    print("jsonschema: installed")
except ImportError:
    print("jsonschema: NOT FOUND. Activate .venv, then: python -m pip install jsonschema")
```

Run it from the VS Code terminal, with `(.venv)` showing, using `python check_setup.py`. Success looks like this, with your own version numbers:

```text
python: 3.13.0
in a virtual environment: True
git: git version 2.47.0
ollama: not installed (optional)
jsonschema: installed
```

Inside a virtual environment, `sys.prefix` points at `.venv` while `sys.base_prefix` still points at the Python you installed, so `False` on that line means the environment isn't active.

`shutil.which` looks a command up on your `PATH`, the list of folders your terminal searches. That's why a fresh install sometimes reports "NOT FOUND" until you open a new terminal: the old one is still using the old `PATH`.

Finally, test the assistant. Open the Chat view and ask: *"In one sentence, what does shutil.which do?"* Any sensible answer means the connection works.

## Fixes for the problems people actually hit

:::warning
**`python` opens the Microsoft Store, or says it isn't recognized (Windows).** Windows ships a placeholder `python` command. Install the Python install manager from Step 1, then close every terminal and open a new one. In VS Code, also close and reopen the editor so its terminal inherits the new `PATH`.
:::

:::warning
**`git: command not found` right after installing.** Same cause: the terminal started before Git existed. Open a new terminal. On macOS, if `xcode-select --install` says the tools are already installed, `git --version` should work; if it doesn't, run **Software Update** and try again.
:::

:::warning
**Copilot won't activate, or says you don't have access.** If your GitHub account gets Copilot through a school or company organization, Copilot Free isn't offered to it, and the organization's settings decide what you can use. Sign out (Accounts menu at the bottom of the Activity Bar) and sign in with a personal account, or use Path B.
:::

:::warning
**PowerShell says `Activate.ps1 cannot be loaded because running scripts is disabled on this system`.** Windows blocks scripts by default. Allow scripts you create yourself, for your account only, then activate again:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```
:::

:::warning
**Ollama says it can't connect, or the model is painfully slow.** The `ollama` command talks to a background server. On Windows and macOS, start the Ollama app; on Linux, run `ollama serve` in a separate terminal. If answers crawl, your computer is short on memory: try `ollama pull qwen3:0.6b`, which is about a third of the size, and accept that it will be less accurate.
:::
