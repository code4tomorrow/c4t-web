An expense tracker that forgets everything is worse than a notebook. Run this twice:

```python run title="tracker_v1.py"
expenses = []
expenses.append({"item": "lunch", "amount": 6.50})
expenses.append({"item": "bus pass", "amount": 20.00})
print(len(expenses), "expenses so far")
```

It says 2 both times, never 4. Variables live in memory, which is wiped the moment the program ends. To remember something until next time, a program must write it to a **file** on disk and read it back when it starts.

## Write and read text with `with open`

`open` connects your program to a file. The `with` block closes the file for you when the block ends, even if an error happens inside it:

```python run title="write_text.py"
with open("expenses.txt", "w", encoding="utf-8") as file:
    file.write("lunch,6.50\n")
    file.write("bus pass,20.00\n")
print("saved")
```

`write` adds exactly what you give it and nothing more, so you add the `"\n"` (newline) yourself. Leave it out and both expenses end up on one line. The file now exists beside your program. A separate program can read it back:

```python run title="read_text.py"
with open("expenses.txt", encoding="utf-8") as file:
    for line in file:
        print(repr(line))

with open("expenses.txt", encoding="utf-8") as file:
    for line in file:
        item, amount = line.strip().split(",")
        print(f"{item}: ${float(amount):.2f}")
```

Looping over a file gives one line at a time, **with** its newline on the end, as `repr` shows. `.strip()` removes it before you split. Everything read from a text file is a string, so `float(amount)` is needed before any math.

The second argument to `open` is the **mode**:

| Mode | Means | If the file exists | If it doesn't |
| --- | --- | --- | --- |
| `"r"` (the default) | read | reads from the start | `FileNotFoundError` |
| `"w"` | write | **erases it first** | creates it |
| `"a"` | append | adds to the end | creates it |

```python run title="append_text.py"
with open("expenses.txt", "a", encoding="utf-8") as file:
    file.write("snack,2.25\n")

with open("expenses.txt", encoding="utf-8") as file:
    print(file.read())
```

`"a"` kept the two earlier lines and added a third. `file.read()` returns the whole file as one string.

:::warning
Opening with `"w"` empties the file **immediately**, before you write a single character. If you meant to add a line and used `"w"`, the old contents are already gone. When in doubt, read first, then write.
:::

Always pass `encoding="utf-8"`. Without it, some computers (especially Windows ones with older versions of Python) use a different default, and a name like "Zoë" or an emoji can crash the program or come back garbled.

## JSON: save a whole structure in one call

Your grade book and contacts are lists of dicts, and flattening those into lines by hand is tedious. **JSON** is a text format that looks almost exactly like Python's lists and dicts, and the `json` module converts in both directions:

```python run title="save_json.py"
import json

expenses = [
    {"item": "lunch", "amount": 6.5, "tags": ["food"]},
    {"item": "bus pass", "amount": 20.0, "tags": ["travel", "monthly"]},
]

with open("expenses.json", "w", encoding="utf-8") as file:
    json.dump(expenses, file, indent=2)

with open("expenses.json", encoding="utf-8") as file:
    print(file.read())
```

`json.dump(data, file)` writes the data; `indent=2` spreads it over several lines so a person can read and even edit it. Loading is one call:

```python run title="load_json.py"
import json

with open("expenses.json", encoding="utf-8") as file:
    expenses = json.load(file)

print(type(expenses), len(expenses))
print(expenses[1]["tags"][0])
print(sum(e["amount"] for e in expenses))
```

What comes back is ordinary Python: a list of dicts with real numbers in them, ready to use. (`json.dumps` and `json.loads`, with an **s** for "string", do the same thing with a string instead of a file.)

JSON isn't Python, though, and a few things change on the round trip. Predict the second line before you run this:

```python run title="round_trip.py"
import json

data = {"week": 46, "paid": True, "note": None, "range": (1, 5), 7: "seven"}
text = json.dumps(data)
print(text)
back = json.loads(text)
print(back)
print(back == data)
```

`True` and `None` become JSON's `true` and `null`, and come back fine. But JSON has no tuples, so `(1, 5)` returns as the list `[1, 5]`. And JSON keys must be strings, so the key `7` comes back as `"7"`; `back[7]` would now be a `KeyError`. Sets are worse: JSON has nothing like them, so `json.dumps({"tags": {"food"}})` stops with `TypeError: Object of type set is not JSON serializable`. Convert sets with `sorted(tags)` before saving and back with `set(...)` after loading.

## When the file is missing or broken

The very first time a program runs, its data file doesn't exist yet. That's normal, not an error, and the program should start with an empty list. A `try` block lets you handle it: Python runs the code under `try`, and if one of the named errors happens, it jumps to the matching `except` instead of crashing.

```python run title="load_or_empty.py"
import json


def load_expenses(path):
    try:
        with open(path, encoding="utf-8") as file:
            return json.load(file)
    except FileNotFoundError:
        return []


print(load_expenses("expenses.json")[0]["item"])
print(load_expenses("no_such_file.json"))
```

A **corrupt** file is a different situation. Maybe someone edited it by hand and deleted a bracket. Here's what loading one looks like:

```python run raises title="corrupt.py"
import json

with open("broken.json", "w", encoding="utf-8") as file:
    file.write('[{"item": "lunch", "amount": 6.5},')

with open("broken.json", encoding="utf-8") as file:
    json.load(file)
```

The traceback is long because the error was raised deep inside the `json` module's own code. As always, read the last line first. `json.JSONDecodeError` tells you where parsing gave up (line 1, column 35 here, just past the trailing comma). The tempting fix is to catch it and return `[]`, but think about what happens next: the program starts empty, the user adds one expense, and saving **overwrites** the broken file, along with every expense that was in it and could have been repaired by hand. Keep a copy first:

```python run title="load_safely.py"
import json
from pathlib import Path


def load_expenses(path):
    path = Path(path)
    try:
        return json.loads(path.read_text(encoding="utf-8"))
    except FileNotFoundError:
        return []
    except json.JSONDecodeError as error:
        backup = path.with_name(path.name + ".bak")
        path.replace(backup)
        print(f"Warning: {path.name} was damaged ({error}). Saved a copy as {backup.name}.")
        return []


print(load_expenses("broken.json"))
print(Path("broken.json.bak").exists())
```

## Paths that work on every computer

That example used `pathlib`, the modern way to handle file locations. A `Path` joins folder names correctly on every system and has handy methods built in:

```python run title="paths.py"
from pathlib import Path

data_dir = Path("data")
data_dir.mkdir(parents=True, exist_ok=True)
budget = data_dir / "budget.json"
budget.write_text('{"limit": 100}', encoding="utf-8")

print(budget)
print(budget.name, budget.stem, budget.suffix)
print(budget.exists(), budget.read_text(encoding="utf-8"))
```

The `/` operator joins path pieces, so you never type a slash or backslash yourself. (On Windows, the first line prints as `data\budget.json`, with the backslash Windows uses.) `mkdir(parents=True, exist_ok=True)` makes the folder, and any missing folders above it, without complaining if it already exists.

There's one trap specific to running code from VS Code. When you press **Run Python File**, the terminal's current folder is the folder you opened (`python-projects`), not the subfolder your script is in. So `open("expenses.json")` in `m4-quiz/tracker.py` looks for `python-projects/expenses.json`, and you get `FileNotFoundError` for a file you can see right there in the Explorer. The fix is to build paths from the script's own location:

```python title="tracker.py"
from pathlib import Path

HERE = Path(__file__).parent
DATA_FILE = HERE / "expenses.json"
print(DATA_FILE)
```

`__file__` is the path of the script that's running, and `.parent` is its folder. Now `DATA_FILE` points beside the script however the program is started. (This one can't run on the page, because code here doesn't come from a saved file.)

## Save so a crash can't leave half a file

If the program crashes or the battery dies halfway through writing, you're left with half a JSON file, which is a corrupt file. The safe pattern is to write a temporary file completely, then swap it into place in one step:

```python run title="save_safely.py"
import json
from pathlib import Path


def save_expenses(path, expenses):
    path = Path(path)
    temp = path.with_name(path.name + ".tmp")
    temp.write_text(json.dumps(expenses, indent=2), encoding="utf-8")
    temp.replace(path)


save_expenses("expenses.json", [{"item": "lunch", "amount": 6.5}])
print(Path("expenses.json").read_text(encoding="utf-8"))
print(Path("expenses.json.tmp").exists())
```

`replace` swaps the finished file in all at once, so at every moment `expenses.json` is either the complete old version or the complete new one. Together with the careful loader, the whole life of the data looks like this:

```mermaid caption="Load at start, save after every change, and never lose a damaged file"
flowchart TD
    A["Program starts"] --> B{"Data file exists?"}
    B -->|no| C["Start with an empty list"]
    B -->|yes| D{"Valid JSON?"}
    D -->|no| E["Rename it to .bak, warn, start empty"]
    D -->|yes| F["Use the loaded data"]
    C --> G["User makes a change"]
    E --> G
    F --> G
    G --> H["Write .tmp file, then replace the real file"]
    H --> G
```

:::quiz
Q: `notes.txt` has 50 lines. A program runs `with open("notes.txt", "w") as f: pass` and ends. How many lines are left?
- [ ] 50
  Opening in `"w"` mode doesn't wait for a write. It empties the file straight away.
- [x] 0
  `"w"` truncates the file the moment it opens, and nothing was written afterwards.
- [ ] 51
  That would need `"a"` mode and a write.

Q: You save `{1: "gold", 2: "silver"}` with `json.dump` and load it back. What's the result?
- [ ] `{1: "gold", 2: "silver"}`
  JSON keys are always strings, so the numbers don't survive as numbers.
- [x] `{"1": "gold", "2": "silver"}`
  The keys were turned into strings on the way out and stay strings on the way back.
- [ ] A `TypeError`
  Number keys are allowed when saving; they're quietly converted. Sets are what raise `TypeError`.

Q: `quiz.py` and `questions.json` are both in `python-projects/m4-quiz/`. Pressing **Run Python File** gives `FileNotFoundError: 'questions.json'`. Why?
- [ ] JSON files must be in the same folder as Python itself
  Files can be anywhere; what matters is the folder the path is relative to.
- [x] The terminal's current folder is `python-projects`, so a bare file name is looked up there
  Relative paths start from the current folder, not the script's folder. `Path(__file__).parent / "questions.json"` fixes it.
- [ ] The file needs to be opened in `"w"` mode first
  That would create an empty file in the wrong place, or erase the right one.

Q: Why save to `expenses.json.tmp` and then call `replace` instead of writing `expenses.json` directly?
- [ ] Writing to a `.tmp` file is faster
  It's the same amount of writing. The benefit is safety.
- [x] If the program dies mid-write, only the `.tmp` file is damaged; the real file is untouched
  `replace` happens in one step, so the real file is always a complete version.
- [ ] JSON can only be written to files ending in `.tmp`
  `json.dump` works with any file you've opened for writing.
:::

:::takeaways
- Memory is wiped when a program ends; files on disk persist.
- `with open(path, mode, encoding="utf-8")` closes the file for you. `"w"` erases, `"a"` adds, `"r"` reads.
- `json.dump` and `json.load` save and restore lists and dicts. Tuples come back as lists, number keys as strings, and sets can't be saved at all.
- A missing file usually means "first run, start empty". A corrupt file should be backed up before anything overwrites it.
- Use `pathlib.Path`, build data paths from `Path(__file__).parent`, and save through a temporary file plus `replace`.
:::
