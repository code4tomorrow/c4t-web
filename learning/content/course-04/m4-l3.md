## Warm-up: what's in the file?

Four `with` blocks, three modes. Predict the output before running:

```python run title="warmup.py"
with open("warm.txt", "w", encoding="utf-8") as f:
    f.write("one\n")
with open("warm.txt", "a", encoding="utf-8") as f:
    f.write("two\n")
with open("warm.txt", "w", encoding="utf-8") as f:
    f.write("three\n")
with open("warm.txt", encoding="utf-8") as f:
    print(f.read())
```

Only `three` survives. The append worked, but the second `"w"` erased both lines the moment it opened the file.

### Exercise 1: A numbered journal

Write `read_entries(path)`, which returns the file's lines without their newlines (or `[]` if the file doesn't exist yet), and `add_entry(path, text)`, which appends one line numbered after the existing ones. Start from no file and add three entries.

Expected output:

```text
[]
1. Started Module 4
2. Saved my first JSON file
3. Broke a file on purpose and recovered it
```

:::hint
`add_entry` can call `read_entries` to count the lines already there. Use mode `"a"` to add to the end, and remember the `"\n"`. To start clean each time you test, `Path("journal.txt").unlink(missing_ok=True)` deletes the file if it exists.
:::

:::solution
```python run title="ex1_journal.py"
from pathlib import Path


def read_entries(path):
    try:
        with open(path, encoding="utf-8") as file:
            return [line.rstrip("\n") for line in file]
    except FileNotFoundError:
        return []


def add_entry(path, text):
    number = len(read_entries(path)) + 1
    with open(path, "a", encoding="utf-8") as file:
        file.write(f"{number}. {text}\n")


Path("journal.txt").unlink(missing_ok=True)
print(read_entries("journal.txt"))
add_entry("journal.txt", "Started Module 4")
add_entry("journal.txt", "Saved my first JSON file")
add_entry("journal.txt", "Broke a file on purpose and recovered it")
for entry in read_entries("journal.txt"):
    print(entry)
```

`rstrip("\n")` removes only the newline at the end, so spaces the user typed stay as they were. Run the program again without the `unlink` line and the entries continue at 4: the file remembers.
:::

### Exercise 2: Measure a file

Save the poem below to `poem.txt`, then write `file_stats(path)` that returns a tuple of the number of lines, the number of words, and the longest line.

```python
poem = """I opened a file in write mode,
and everything in it was gone.
Now I read before I write,
and append when I carry on.
"""
```

Expected output:

```text
Lines: 4
Words: 25
Longest: 'I opened a file in write mode,'
```

:::hint
Read the lines into a list first, since you need to look at them more than once. A line's word count is `len(line.split())`. `max(lines, key=len)` finds the longest line, but it crashes on an empty list, so guard against an empty file.
:::

:::solution
```python run title="ex2_stats.py"
poem = """I opened a file in write mode,
and everything in it was gone.
Now I read before I write,
and append when I carry on.
"""
with open("poem.txt", "w", encoding="utf-8") as file:
    file.write(poem)


def file_stats(path):
    with open(path, encoding="utf-8") as file:
        lines = [line.rstrip("\n") for line in file]
    words = sum(len(line.split()) for line in lines)
    longest = max(lines, key=len) if lines else ""
    return len(lines), words, longest


count, words, longest = file_stats("poem.txt")
print("Lines:", count)
print("Words:", words)
print("Longest:", repr(longest))
```

A file can only be looped over once per `open`; after the loop, the reading position is at the end. Saving the lines in a list lets you count words and find the longest line from the same data.
:::

### Exercise 3: The level that disappeared

A game saves how many stars you earned on each level. After loading, asking for level 2 crashes. Run it, read the error, then write `save_progress` and `load_progress` so that `loaded["stars"][2]` works.

```python run raises title="ex3_progress.py"
import json

progress = {"player": "Ava", "stars": {1: 3, 2: 2, 3: 0}}
with open("progress.json", "w", encoding="utf-8") as file:
    json.dump(progress, file)

with open("progress.json", encoding="utf-8") as file:
    loaded = json.load(file)

print("Level 2 stars:", loaded["stars"][2])
```

Expected output once fixed:

```text
Level 2 stars: 2
Total stars: 5
```

:::hint
Open `progress.json` in VS Code and look at the keys: they have quotes around them now. After loading, rebuild the `stars` dict with a dict comprehension that converts each key with `int()`.
:::

:::solution
```python run title="ex3_progress.py"
import json


def save_progress(path, progress):
    with open(path, "w", encoding="utf-8") as file:
        json.dump(progress, file)


def load_progress(path):
    with open(path, encoding="utf-8") as file:
        data = json.load(file)
    data["stars"] = {int(level): stars for level, stars in data["stars"].items()}
    return data


save_progress("progress.json", {"player": "Ava", "stars": {1: 3, 2: 2, 3: 0}})
loaded = load_progress("progress.json")
print("Level 2 stars:", loaded["stars"][2])
print("Total stars:", sum(loaded["stars"].values()))
```

`KeyError: 2` meant "there's no key that is the number 2", which was true: the key was the string `"2"`. Putting the conversion inside `load_progress` means the rest of the program never has to know JSON was involved.
:::

### Exercise 4: Save the planner, sets and all

The study planner from Module 2's challenge stores each task's tags as a set. Saving it crashes, and the crash does something worse than crash. Run this, then run the cell after it to see what was left on disk:

```python run raises title="ex4_planner.py"
import json

planner = {"MATH": {"title": "Algebra II", "tasks": [
    {"title": "Worksheet 4", "due": "2026-11-18", "tags": {"homework"}, "done": False},
]}}

with open("planner.json", "w", encoding="utf-8") as file:
    json.dump(planner, file)
```

```python run title="look.py"
print(repr(open("planner.json", encoding="utf-8").read()))
```

`json.dump` writes to the file piece by piece, so by the time it reached the set, half the planner was already on disk. The file is now corrupt. Write `save_planner(path, planner)`, which turns each task's tags into a sorted list before saving, and `load_planner(path)`, which turns them back into sets, so that the loaded planner equals the original.

:::hint
In `save_planner`, build a new structure instead of changing the planner you were given: `dict(task, tags=sorted(task["tags"]))` copies a task with one field replaced. In `load_planner`, loop over every course and every task and replace `task["tags"]` with `set(task["tags"])`.
:::

:::solution
```python run title="ex4_planner.py"
import json


def save_planner(path, planner):
    ready = {}
    for code, course in planner.items():
        tasks = [dict(task, tags=sorted(task["tags"])) for task in course["tasks"]]
        ready[code] = {"title": course["title"], "tasks": tasks}
    with open(path, "w", encoding="utf-8") as file:
        json.dump(ready, file, indent=2)


def load_planner(path):
    with open(path, encoding="utf-8") as file:
        planner = json.load(file)
    for course in planner.values():
        for task in course["tasks"]:
            task["tags"] = set(task["tags"])
    return planner


planner = {"MATH": {"title": "Algebra II", "tasks": [
    {"title": "Worksheet 4", "due": "2026-11-18", "tags": {"homework", "math"}, "done": False},
]}}
save_planner("planner.json", planner)
loaded = load_planner("planner.json")
print(loaded == planner)
print(type(loaded["MATH"]["tasks"][0]["tags"]))
```

`sorted()` turns a set into a list and puts the tags in a fixed order, so saving the same planner twice gives an identical file. The half-written file also shows why the safe save from the Notes builds the whole text with `json.dumps` first: if that fails, nothing has touched the disk yet.
:::

### Exercise 5: An expense tracker that remembers

Write four functions: `load_expenses(path)` (an empty list if the file is missing), `save_expenses(path, expenses)` (through a `.tmp` file), `add_expense(path, item, amount, category)`, which loads, appends, saves, and returns how many expenses there are now, and `totals_by_category(path)`, which returns a dict of category totals, biggest first.

Expected output, starting from no file:

```text
1
2
3
{'travel': 20.0, 'food': 8.75}
```

:::hint
`add_expense` doesn't keep the list in a variable between calls. Each call loads from the file, so it always sees what earlier calls saved. That's what makes it work across separate runs of the program, too. For the totals, count into a dict with `.get(category, 0)`, then sort its items by `-total`.
:::

:::solution
```python run title="ex5_tracker.py"
import json
from pathlib import Path


def load_expenses(path):
    try:
        return json.loads(Path(path).read_text(encoding="utf-8"))
    except FileNotFoundError:
        return []


def save_expenses(path, expenses):
    path = Path(path)
    temp = path.with_name(path.name + ".tmp")
    temp.write_text(json.dumps(expenses, indent=2), encoding="utf-8")
    temp.replace(path)


def add_expense(path, item, amount, category):
    expenses = load_expenses(path)
    expenses.append({"item": item, "amount": round(amount, 2), "category": category})
    save_expenses(path, expenses)
    return len(expenses)


def totals_by_category(path):
    totals = {}
    for expense in load_expenses(path):
        totals[expense["category"]] = totals.get(expense["category"], 0) + expense["amount"]
    return dict(sorted(totals.items(), key=lambda pair: -pair[1]))


Path("tracker.json").unlink(missing_ok=True)
print(add_expense("tracker.json", "lunch", 6.50, "food"))
print(add_expense("tracker.json", "bus pass", 20.00, "travel"))
print(add_expense("tracker.json", "snack", 2.25, "food"))
print(totals_by_category("tracker.json"))
```

`dict(sorted(...))` builds a new dictionary from the sorted pairs. Dictionaries keep the order their keys were added in, so the biggest category prints first.
:::

### Exercise 6: One file per month

Write `save_month(folder, month, expenses)`, which creates the folder if needed and saves the list as `<month>.json` inside it, and `yearly_report(folder)`, which finds every `.json` file in the folder, in order, and returns a report string with each month's count and total plus a grand total.

Test it by saving three months out of order: `2026-10` with a 6.50 lunch and a 12.00 book, `2026-09` with a 20.00 bus pass, and `2026-11` with no expenses at all. Then `print(yearly_report("months"))` should show:

```text
2026-09: 1 expenses, $20.00
2026-10: 2 expenses, $18.50
2026-11: 0 expenses, $0.00
All months: $38.50
```

:::hint
`Path(folder).glob("*.json")` finds every file ending in `.json` in that folder, in no guaranteed order, so wrap it in `sorted()`. Year-month names like `2026-09` sort correctly as text. `path.stem` is the file name without `.json`.
:::

:::solution
```python run title="ex6_months.py"
import json
from pathlib import Path


def save_month(folder, month, expenses):
    folder = Path(folder)
    folder.mkdir(parents=True, exist_ok=True)
    path = folder / f"{month}.json"
    path.write_text(json.dumps(expenses), encoding="utf-8")
    return path


def yearly_report(folder):
    lines = []
    grand_total = 0
    for path in sorted(Path(folder).glob("*.json")):
        expenses = json.loads(path.read_text(encoding="utf-8"))
        total = sum(e["amount"] for e in expenses)
        grand_total += total
        lines.append(f"{path.stem}: {len(expenses)} expenses, ${total:.2f}")
    lines.append(f"All months: ${grand_total:.2f}")
    return "\n".join(lines)


save_month("months", "2026-10", [{"item": "lunch", "amount": 6.5}, {"item": "book", "amount": 12.0}])
save_month("months", "2026-09", [{"item": "bus pass", "amount": 20.0}])
save_month("months", "2026-11", [])
print(yearly_report("months"))
```

Keeping the months in their own folder matters: `glob("*.json")` in your main project folder would also pick up `questions.json`, `scores.json`, and anything else that happens to end in `.json`.
:::

### Challenge: Give the contacts manager a memory

Make Module 3's contacts manager keep its contacts in `contacts.json` beside the script. Write `load_contacts(path)`, returning `(contacts, warning)`, and `save_contacts(path, contacts)`. Your loader must handle four situations:

1.  No file yet: an empty list and no warning.
2.  A damaged file: rename it to `contacts.json.bak`, return an empty list and a warning.
3.  Valid JSON that isn't a list: an empty list and a warning.
4.  A list where some records are missing a name, phone, or email: keep the good ones and say how many were skipped.

Then change `main()` to load at the start and save after every successful add and delete. Test the loader by simulating several sessions in one script.

:::hint
Write a small `is_contact(record)` that checks the record is a dict and that `name`, `phone`, and `email` are all strings; `all(...)` with a generator does the "all three" part in one line. Save immediately after each change rather than when the user quits, so a crash or a closed terminal can't lose anything the user already entered.
:::

:::solution
```python run title="contacts_storage.py"
import json
from pathlib import Path

FIELDS = ("name", "phone", "email")


def is_contact(record):
    return isinstance(record, dict) and all(isinstance(record.get(f), str) for f in FIELDS)


def load_contacts(path):
    try:
        data = json.loads(path.read_text(encoding="utf-8"))
    except FileNotFoundError:
        return [], None
    except json.JSONDecodeError as error:
        backup = path.with_name(path.name + ".bak")
        path.replace(backup)
        return [], f"{path.name} was damaged ({error}); saved it as {backup.name}"
    if not isinstance(data, list):
        return [], f"{path.name} doesn't hold a list, so it was ignored"
    contacts = [record for record in data if is_contact(record)]
    skipped = len(data) - len(contacts)
    return contacts, (f"skipped {skipped} incomplete contact(s)" if skipped else None)


def save_contacts(path, contacts):
    temp = path.with_name(path.name + ".tmp")
    temp.write_text(json.dumps(contacts, indent=2), encoding="utf-8")
    temp.replace(path)


path = Path("contacts.json")
path.unlink(missing_ok=True)

contacts, warning = load_contacts(path)
print("Session 1 starts with", contacts, warning)
contacts.append({"name": "Maya Patel", "phone": "4155550123", "email": "maya@example.com"})
save_contacts(path, contacts)
contacts.append({"name": "Leo Chen", "phone": "6505550199", "email": "leo@example.com"})
save_contacts(path, contacts)

contacts, warning = load_contacts(path)
print("Session 2 starts with", [c["name"] for c in contacts], warning)

path.write_text('[{"name": "Maya Patel", "phone": "4155550123", "email": "maya@example.com"}, {"name": "Zoe"}]', encoding="utf-8")
contacts, warning = load_contacts(path)
print("Session 3 starts with", [c["name"] for c in contacts], warning)

path.write_text("[{", encoding="utf-8")
contacts, warning = load_contacts(path)
print("Session 4 starts with", contacts, warning)
print(Path("contacts.json.bak").read_text(encoding="utf-8"))
```

Each "session" calls `load_contacts` fresh, just as a new run of the program would, and finds exactly what the previous one saved.
