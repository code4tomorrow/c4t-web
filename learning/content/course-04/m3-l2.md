:::objectives
- Plan a program as a set of small functions before writing any of them.
- Clean and check input with guard clauses that return early.
- Return values and messages instead of printing them inside helpers.
- Change a list passed into a function, and explain why the caller sees the change.
- Keep all `input()` and menu printing in one `main()` function.
:::

You're building a contacts manager that runs in the terminal. You'll be able to add people, search by name, email, or part of a phone number, list everyone, and delete people. It will also refuse bad data politely: a phone number with seven digits or an email with no dot after the `@` gets an explanation, not a crash.

The design rule for this build comes straight from the last lesson: **helpers calculate and return; only `main()` talks to the user.** Here's the plan:

## Step 1: Decide what a contact looks like

Before writing functions, settle the data. Each contact is a dictionary, and all contacts live in one list:

```python run
example = {"name": "Maya Patel", "phone": "4155550123", "email": "maya@example.com"}
print(example["name"], "->", example["phone"])
```

Notice the phone is stored as **digits only**, as text. People type numbers as `415-555-0123`, `(415) 555-0123`, or `+1 415 555 0123`. Storing one clean form means searching and comparing never have to worry about dashes and brackets. It's text, not an `int`, because a phone number is a label you never do math on, and some begin with 0.

## Step 2: Clean up phone numbers

```python run
def normalize_phone(raw):
    digits = "".join(ch for ch in raw if ch.isdigit())
    if len(digits) == 11 and digits.startswith("1"):
        digits = digits[1:]
    if len(digits) != 10:
        return None
    return digits


def format_phone(digits):
    return f"({digits[:3]}) {digits[3:6]}-{digits[6:]}"


for typed in ["415-555-0123", "(415) 555 0123", "+1 415 555 0123", "555-0123"]:
    print(repr(typed), "->", normalize_phone(typed))

assert normalize_phone("415.555.0123") == "4155550123"
assert normalize_phone("12") is None
assert format_phone("4155550123") == "(415) 555-0123"
print("phone checks passed")
```

`normalize_phone` keeps only the digit characters, drops a leading country code `1`, and then uses a guard clause: anything that isn't exactly ten digits returns `None`. It doesn't print "invalid phone". The function can't know whether the caller wants to show a message, try again, or skip the record, so it reports the fact and lets the caller decide. The `assert` lines are tiny tests; leave them in while you build, and they'll shout if a later change breaks something.

## Step 3: A sanity check for email addresses

Fully checking an email address is surprisingly hard (the official rules run to pages). This version only catches obvious typos, which is all a contacts list needs:

```python run
def is_valid_email(text):
    if " " in text or text.count("@") != 1:
        return False
    user, domain = text.split("@")
    if not user:
        return False
    return "." in domain and not domain.startswith(".") and not domain.endswith(".")


for typed in ["maya@example.com", "maya@example", "maya@@example.com", "@example.com", "maya @x.org"]:
    print(f"{typed:<20}{is_valid_email(typed)}")
```

Each guard throws out one kind of mistake. Once a line has survived the guards, the code below it can safely assume there is exactly one `@` and a non-empty name before it. The last line returns the result of a test directly, instead of writing `if ...: return True else: return False`.

## Step 4: Format one contact for display

```python run
def format_contact(contact):
    return f"{contact['name']:<14}{format_phone(contact['phone'])}  {contact['email']}"


print(format_contact(example))
```

This returns a string rather than printing it. That means a search result, a full list, or a future "export to file" feature can all reuse it. The dictionary keys use single quotes because the f-string itself uses double quotes.

## Step 5: Add a contact, with guard clauses

```python run
def find_by_name(contacts, name):
    for contact in contacts:
        if contact["name"].lower() == name.lower():
            return contact
    return None


def add_contact(contacts, name, phone, email):
    name = name.strip()
    if not name:
        return False, "A name is required."
    if find_by_name(contacts, name):
        return False, f"{name} is already in your contacts."
    digits = normalize_phone(phone)
    if digits is None:
        return False, "A phone number needs 10 digits."
    if not is_valid_email(email):
        return False, f"{email!r} doesn't look like an email address."
    contacts.append({"name": name, "phone": digits, "email": email.lower()})
    return True, f"Added {name}."


book = []
print(add_contact(book, "Maya Patel", "415-555-0123", "maya@example.com"))
print(add_contact(book, "maya patel", "415-555-0999", "m@example.com"))
print(add_contact(book, "Leo Chen", "555-0199", "leo@example.com"))
print(add_contact(book, "Leo Chen", "650.555.0199", "Leo@Example.com"))
print(len(book), "contacts:", [c["name"] for c in book])
```

`add_contact` returns a pair: did it work, and a message explaining what happened. The four guards run in order, and the first problem found is the one reported. Only a contact that passes all of them reaches `contacts.append(...)` at the bottom.

Here's the part that surprises people: `add_contact` never returns the list, yet `book` grew. When you pass a list to a function, the function gets **the same list**, not a copy. Appending inside the function changes the one list both names refer to. That's useful here, but it's also why a helper should only change a list when changing it is the whole point of the function, as its name says.

## Step 6: Search

```python run
def find_contacts(contacts, query):
    query = query.strip().lower()
    digits = "".join(ch for ch in query if ch.isdigit())
    matches = [
        c for c in contacts
        if query in c["name"].lower()
        or query in c["email"]
        or (digits and digits in c["phone"])
    ]
    return sorted(matches, key=lambda c: c["name"].lower())


print([c["name"] for c in find_contacts(book, "CHEN")])
print([c["name"] for c in find_contacts(book, "415")])
print(find_contacts(book, "zoe"))
```

One comprehension checks three things, joined with `or`. The phone check is wrapped in `(digits and ...)` so a query with no digits, such as `"chen"`, doesn't count as matching every phone number (every string contains the empty string). Results come back sorted, and an empty list means no matches, which the caller can handle however it likes.

## Step 7: Delete

```python run
def delete_contact(contacts, name):
    for index, contact in enumerate(contacts):
        if contact["name"].lower() == name.strip().lower():
            del contacts[index]
            return True
    return False


print(delete_contact(book, "zoe"))
print(delete_contact(book, "leo chen"))
print([c["name"] for c in book])
```

`enumerate` gives each contact's position so `del contacts[index]` can remove it. The function returns **immediately** after deleting. Carrying on with a loop over a list you've just shortened makes Python skip the item that slid into the gap. And `return False` sits after the loop, so it only runs once every contact has been checked.

## Step 8: The menu, the only part that talks

```python run input="1|Maya Patel|415-555-0123|maya@example.com|1|Leo Chen|555-0199|leo@example.com|3|q"
MENU = "\n1) Add  2) Search  3) List all  4) Delete  q) Quit"


def show(contacts):
    if not contacts:
        print("  (no contacts)")
    for contact in contacts:
        print("  " + format_contact(contact))


def main():
    contacts = []
    while True:
        print(MENU)
        choice = input("Choose: ").strip().lower()
        if choice == "q":
            print("Bye!")
            return
        if choice == "1":
            name = input("Name: ")
            phone = input("Phone: ")
            email = input("Email: ")
            ok, message = add_contact(contacts, name, phone, email)
            print(message)
        elif choice == "2":
            show(find_contacts(contacts, input("Search for: ")))
        elif choice == "3":
            show(sorted(contacts, key=lambda c: c["name"].lower()))
        elif choice == "4":
            name = input("Name to delete: ")
            print("Deleted." if delete_contact(contacts, name) else f"No contact named {name}.")
        else:
            print("Please choose 1, 2, 3, 4, or q.")


main()
```

`main` is all conversation: it asks, calls a helper, and prints what came back. Choosing `q` uses `return` to leave the `while True` loop and end the program. Any choice that isn't on the menu falls through to the final `else` instead of being silently ignored.

:::quiz
Q: Why does `normalize_phone` return `None` for a bad number instead of printing "Invalid phone"?
- [ ] Printing inside a function is a syntax error
  Functions can print; it's a design choice, not a rule of the language.
- [x] The caller decides what to do about it, and the function stays easy to test
  `add_contact` turns `None` into a message; a file importer could skip the row instead. An `assert` can check `None` directly.
- [ ] `None` takes less memory than a string
  The difference is negligible. The reason is who gets to decide what happens next.

Q: `add_contact(book, ...)` never returns `book`, but afterwards `book` has a new contact. Why?
- [ ] `book` is a global variable, so every function can change it
  `add_contact` never mentions `book`. It changes whatever list it was given.
- [x] The function received the same list object, and `.append` changed that list
  Passing a list doesn't copy it, so the parameter `contacts` and the caller's `book` are two names for one list.
- [ ] Python automatically returns the first parameter
  It doesn't. `add_contact` returns the `(ok, message)` pair and nothing else.

Q: Why does `delete_contact` return straight after `del contacts[index]`?
- [x] The job is done, and continuing to loop over a list you just shortened can skip items
  Deleting shifts later items left by one, so the loop would jump over the next contact.
- [ ] `del` only works on the last line of a function
  `del` works anywhere. The early return is about the loop, not about `del`.
- [ ] To make `return False` run afterwards
  The early `return True` ends the function, so `return False` doesn't run at all in that case.
:::

:::takeaways
- Sketch the functions and the data before writing code; decide which single function talks to the user.
- Guard clauses in helpers reject bad input early and return a value that explains why.
- Return pairs like `(ok, message)` when the caller needs both a result and an explanation.
- A list passed into a function is shared, not copied, so changes inside are visible outside.
- After deleting from a list inside a loop, stop looping (return) or you'll skip items.
:::
