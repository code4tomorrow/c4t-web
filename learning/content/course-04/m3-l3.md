## Warm-up: predict it

What does the last line print? Decide before running it.

```python run title="warmup.py"
def double(n):
    n * 2


def triple(n):
    return n * 3


print(double(4), triple(4))
```

`double` works out `8` and then throws it away, because nothing returns it. A line like `n * 2` on its own is legal Python, which is why this bug never produces an error message of its own.

### Exercise 1: The average that isn't there

This program crashes. Fix `average` so the `if` works, and make it return `0` for an empty list instead of crashing on division by zero. Then print a status for each list of scores.

```python run raises title="ex1_average.py"
def average(scores):
    print(sum(scores) / len(scores))


scores = [72, 81, 64]
if average(scores) >= 70:
    print("Passing")
```

Expected output once fixed, for the lists `[72, 81, 64]`, `[55, 61]`, and `[]`:

```text
[72, 81, 64] 72.3 Passing
[55, 61] 58.0 Not yet
[] 0 Not yet
```

:::hint
The error message names `NoneType`: something that should be a number is `None`. Replace `print` with `return`. Add a guard clause as the first line of the function for the empty list.
:::

:::solution
```python run title="ex1_average.py"
def average(scores):
    if not scores:
        return 0
    return sum(scores) / len(scores)


for scores in [[72, 81, 64], [55, 61], []]:
    avg = average(scores)
    status = "Passing" if avg >= 70 else "Not yet"
    print(scores, round(avg, 1), status)
```

`if not scores` is true for an empty list, so the guard returns before the division can fail. Returning `0` is a choice; returning `None` would be more honest ("there's no average"), but then every caller must check for `None` before comparing.
:::

### Exercise 2: Flatten the staircase

Rewrite this function with guard clauses so no line is indented more than once inside the function. It must give the same message for every input.

```python
def can_join(age, has_form, spots_left, grade):
    if has_form:
        if spots_left > 0:
            if 13 <= age <= 18:
                if grade >= 70:
                    return "Welcome!"
                else:
                    return "Grade must be at least 70."
            else:
                return "Age must be 13 to 18."
        else:
            return "The team is full."
    else:
        return "Bring a signed form first."
```

Test it with these cases:

```text
(15, True, 3, 88) -> Welcome!
(15, False, 3, 88) -> Bring a signed form first.
(15, True, 0, 88) -> The team is full.
(12, True, 3, 88) -> Age must be 13 to 18.
(15, True, 3, 65) -> Grade must be at least 70.
```

:::hint
Find each `else` and the `if` it belongs to. Flip that `if`'s condition (`has_form` becomes `not has_form`) and return the `else` message straight away. Keep the checks in the same order, because the order decides which message wins when several things are wrong.
:::

:::solution
```python run title="ex2_guards.py"
def can_join(age, has_form, spots_left, grade):
    if not has_form:
        return "Bring a signed form first."
    if spots_left <= 0:
        return "The team is full."
    if not 13 <= age <= 18:
        return "Age must be 13 to 18."
    if grade < 70:
        return "Grade must be at least 70."
    return "Welcome!"


tests = [(15, True, 3, 88), (15, False, 3, 88), (15, True, 0, 88), (12, True, 3, 88), (15, True, 3, 65)]
for age, form, spots, grade in tests:
    print((age, form, spots, grade), "->", can_join(age, form, spots, grade))
```

Each guard sits next to the message it produces, instead of the message appearing ten lines below its condition. Flipping `spots_left > 0` gives `spots_left <= 0`, not `spots_left < 0`; getting that boundary right is the one tricky part.
:::

### Exercise 3: Calculate here, display there

Write three functions for a school-store receipt: `subtotal(items)` returns the cost before tax, `tax(amount, rate)` returns the tax rounded to cents, and `format_receipt(items, rate)` **returns** the whole receipt as one string. Only the last line of the program should print.

```python
items = [("notebook", 2, 3.50), ("pens", 1, 4.25), ("binder", 1, 6.00)]
TAX_RATE = 0.08
```

Expected output:

```text
notebook    2 x  3.50
pens        1 x  4.25
binder      1 x  6.00
Subtotal             17.25
Tax                   1.38
Total                18.63
```

:::hint
Build a list of lines, one string each, then return `"\n".join(lines)`. `format_receipt` should call `subtotal` and `tax` rather than repeating their math. Check the first two functions with `assert` before formatting anything.
:::

:::solution
```python run title="ex3_receipt.py"
items = [("notebook", 2, 3.50), ("pens", 1, 4.25), ("binder", 1, 6.00)]
TAX_RATE = 0.08


def subtotal(items):
    return sum(qty * price for name, qty, price in items)


def tax(amount, rate):
    return round(amount * rate, 2)


def format_receipt(items, rate):
    lines = [f"{name:<10}{qty:>3} x {price:>5.2f}" for name, qty, price in items]
    before_tax = subtotal(items)
    added = tax(before_tax, rate)
    lines.append(f"{'Subtotal':<20}{before_tax:>6.2f}")
    lines.append(f"{'Tax':<20}{added:>6.2f}")
    lines.append(f"{'Total':<20}{before_tax + added:>6.2f}")
    return "\n".join(lines)


assert subtotal(items) == 17.25
assert tax(10, 0.08) == 0.8
print(format_receipt(items, TAX_RATE))
```

Because `format_receipt` returns a string, the same receipt could be emailed, saved to a file in Module 4, or compared in a test, all without touching the math.
:::

### Exercise 4: The high score that won't update

Run this and read the error. Then rewrite `record` so it takes the current high score as a parameter and returns the new one. The program should print `75`.

```python run raises title="ex4_high_score.py"
high_score = 0


def record(score):
    if score > high_score:
        high_score = score


for s in [40, 75, 60]:
    record(s)
print(high_score)
```

:::hint
The assignment `high_score = score` makes `high_score` local to `record` everywhere in that function, including the `if` line above it. Give the function a second parameter, return whichever score is higher, and assign the result back in the loop.
:::

:::solution
```python run title="ex4_high_score.py"
def record(score, high_score):
    if score > high_score:
        return score
    return high_score


high_score = 0
for s in [40, 75, 60]:
    high_score = record(s, high_score)
print(high_score)
```

Now `record` has no hidden connection to the outside: the current best comes in, the new best goes out. (Python's built-in `max(score, high_score)` does the same job, which is a good sign you've designed it sensibly.)
:::

### Exercise 5: Find double-booked rooms

Two groups clash if they've booked the same room in the same period. Write `find_clashes(bookings)` that returns a list of `(room, period, group_a, group_b)` tuples, checking every **pair** of bookings exactly once.

```python
bookings = [
    ("Room 12", 3, "Robotics"),
    ("Room 4", 3, "Debate"),
    ("Room 12", 5, "Art"),
    ("Room 12", 3, "Chess"),
    ("Room 4", 5, "Band"),
    ("Room 4", 3, "Yearbook"),
]
```

Expected output:

```text
Clash: Room 12, period 3: Robotics and Chess
Clash: Room 4, period 3: Debate and Yearbook
```

To visit every pair once, the inner loop starts one position after the outer loop. Step through it with three items and watch which `(i, j)` pairs appear:

:::trace Every pair once: j always starts after i
```python
groups = ["Robotics", "Debate", "Art"]
for i in range(len(groups)):
    for j in range(i + 1, len(groups)):
        print(groups[i], "vs", groups[j])
```
:::

:::hint
Use `for i in range(len(bookings))` and `for j in range(i + 1, len(bookings))`. Inside, unpack `bookings[i]` and `bookings[j]` into room, period, and group, and compare the room and period.
:::

:::solution
```python run title="ex5_clashes.py"
bookings = [
    ("Room 12", 3, "Robotics"),
    ("Room 4", 3, "Debate"),
    ("Room 12", 5, "Art"),
    ("Room 12", 3, "Chess"),
    ("Room 4", 5, "Band"),
    ("Room 4", 3, "Yearbook"),
]


def find_clashes(bookings):
    clashes = []
    for i in range(len(bookings)):
        for j in range(i + 1, len(bookings)):
            room_a, period_a, group_a = bookings[i]
            room_b, period_b, group_b = bookings[j]
            if room_a == room_b and period_a == period_b:
                clashes.append((room_a, period_a, group_a, group_b))
    return clashes


for room, period, first, second in find_clashes(bookings):
    print(f"Clash: {room}, period {period}: {first} and {second}")
```

Starting `j` at `i + 1` skips comparing a booking with itself and avoids reporting each clash twice (once as A-B, once as B-A). For six bookings that's 15 comparisons. With a thousand bookings it would be about half a million, and grouping by `(room, period)` in a dictionary, as in Module 2, would be far quicker.
:::

### Exercise 6: Split the sales report

Write three functions: `group_by_store(sales)` returns a dict of store to a list of `(item, amount)` pairs, where amount is quantity times price; `store_summary(lines)` returns `(revenue, best_item)`; and `format_report(groups)` returns the report as a string, highest revenue first. Test the first two with `assert`.

```python
sales = [
    ("North", "pencils", 40, 0.50),
    ("South", "binders", 12, 4.00),
    ("North", "binders", 6, 4.00),
    ("South", "pencils", 100, 0.50),
    ("East", "markers", 30, 1.25),
    ("North", "markers", 8, 1.25),
]
```

Expected output:

```text
South  $  98.00  best: pencils
North  $  54.00  best: binders
East   $  37.50  best: markers
```

:::hint
`group_by_store` is the "dict of lists" pattern with `setdefault`. In `store_summary`, `max(lines, key=lambda line: line[1])` finds the pair with the biggest amount. In `format_report`, build a dict of summaries first, then sort its items by revenue.
:::

:::solution
```python run title="ex6_sales_report.py"
sales = [
    ("North", "pencils", 40, 0.50),
    ("South", "binders", 12, 4.00),
    ("North", "binders", 6, 4.00),
    ("South", "pencils", 100, 0.50),
    ("East", "markers", 30, 1.25),
    ("North", "markers", 8, 1.25),
]


def group_by_store(sales):
    groups = {}
    for store, item, qty, price in sales:
        groups.setdefault(store, []).append((item, qty * price))
    return groups


def store_summary(lines):
    revenue = sum(amount for item, amount in lines)
    best_item, best_amount = max(lines, key=lambda line: line[1])
    return revenue, best_item


def format_report(groups):
    summaries = {store: store_summary(lines) for store, lines in groups.items()}
    ranked = sorted(summaries.items(), key=lambda pair: -pair[1][0])
    rows = [f"{store:<7}${revenue:>7.2f}  best: {best}" for store, (revenue, best) in ranked]
    return "\n".join(rows)


groups = group_by_store(sales)
assert store_summary([("a", 2.0), ("b", 5.0)]) == (7.0, "b")
assert len(groups["North"]) == 3
print(format_report(groups))
```

`pair[1][0]` reads as "the summary, then its revenue": each item of `summaries.items()` is `(store, (revenue, best))`. If that line feels cryptic, a named function `def by_revenue(pair): return pair[1][0]` says the same thing more clearly.
:::

### Challenge: Rescue the attendance report

This function works, but it prints from four levels deep and nothing in it can be tested on its own. Refactor it into small functions (`days_present`, `has_perfect_attendance`, `class_summary`, `format_summary`, and an `attendance_report` that **returns** a string), add `assert` tests, and add one feature: each class's attendance rate as a percentage, with classes listed highest rate first. A class with no students who have any recorded days should be left out, just as it is now.

```python run title="challenge_attendance.py"
classes = [
    {"name": "Algebra", "students": [
        {"name": "Ava", "days": ["P", "P", "P", "P"]},
        {"name": "Ben", "days": ["P", "A", "P", "L"]},
        {"name": "Cleo", "days": []},
    ]},
    {"name": "Biology", "students": []},
    {"name": "Chorus", "students": [
        {"name": "Dev", "days": ["P", "P", "L", "P"]},
        {"name": "Eli", "days": ["P", "P", "P", "P"]},
    ]},
]


def attendance_report(classes):
    for c in classes:
        if c["students"]:
            present_total = 0
            perfect = []
            for s in c["students"]:
                if s["days"]:
                    present = 0
                    for d in s["days"]:
                        if d == "P":
                            present += 1
                    present_total += present
                    if present == len(s["days"]):
                        perfect.append(s["name"])
            print(c["name"], present_total, perfect)


attendance_report(classes)
```

:::hint
Start from the innermost loop: counting `"P"` in a list is `days.count("P")`. Let `class_summary` return a dict (or `None` for a class with nothing to report), so the rate can be calculated as present days divided by possible days. An f-string format of `:.0%` turns `0.875` into `88%`.
:::

:::solution
```python run title="challenge_attendance.py"
classes = [
    {"name": "Algebra", "students": [
        {"name": "Ava", "days": ["P", "P", "P", "P"]},
        {"name": "Ben", "days": ["P", "A", "P", "L"]},
        {"name": "Cleo", "days": []},
    ]},
    {"name": "Biology", "students": []},
    {"name": "Chorus", "students": [
        {"name": "Dev", "days": ["P", "P", "L", "P"]},
        {"name": "Eli", "days": ["P", "P", "P", "P"]},
    ]},
]


def days_present(days):
    return days.count("P")


def has_perfect_attendance(student):
    days = student["days"]
    return bool(days) and days_present(days) == len(days)


def class_summary(cls):
    students = [s for s in cls["students"] if s["days"]]
    if not students:
        return None
    present = sum(days_present(s["days"]) for s in students)
    possible = sum(len(s["days"]) for s in students)
    perfect = [s["name"] for s in students if has_perfect_attendance(s)]
    return {"name": cls["name"], "present": present, "rate": present / possible, "perfect": perfect}


def format_summary(summary):
    perfect = ", ".join(summary["perfect"]) or "nobody"
    return f"{summary['name']:<9}{summary['present']:>3} present  {summary['rate']:>4.0%}  perfect: {perfect}"


def attendance_report(classes):
    summaries = [class_summary(c) for c in classes]
    summaries = [s for s in summaries if s is not None]
    summaries.sort(key=lambda s: s["rate"], reverse=True)
    return "\n".join(format_summary(s) for s in summaries)


assert days_present(["P", "A", "P", "L"]) == 2
assert not has_perfect_attendance({"name": "X", "days": []})
assert class_summary({"name": "Empty", "students": []}) is None
assert class_summary(classes[0])["perfect"] == ["Ava"]
print(attendance_report(classes))
print("all checks passed")
```

The four nested levels became four functions, none more than one level deep. The guard in `class_summary` replaced both the outer `if c["students"]` and the inner `if s["days"]`, because filtering students first means an empty class and a class of students with no days are the same case. Adding the rate needed one new line in `class_summary` and one change in `format_summary`; in the original it would have meant another variable threaded through every level.
:::
