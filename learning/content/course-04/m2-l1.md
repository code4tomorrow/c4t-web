Here's a grade book that lies. It keeps names in one list and scores in another, matched by position. Then it sorts the scores so the best is first:

```python run title="parallel_lists.py"
names = ["Ava", "Ben", "Cleo", "Dev"]
scores = [88, 72, 95, 64]

scores.sort(reverse=True)  # best score first
print("Top student:", names[0], "with", scores[0])
```

Cleo got the 95, not Ava. Sorting moved the scores but not the names, so the two lists no longer line up. Lists that are matched only by position stay matched only until one of them changes. The fix is to stop splitting a record across two lists.

## Keep each record together

A **dictionary** stores values under names called **keys**. One dictionary per student keeps the name and score welded together, and a **list** holds all the students in order:

```python run title="records.py"
students = [
    {"name": "Ava", "score": 88},
    {"name": "Ben", "score": 72},
    {"name": "Cleo", "score": 95},
    {"name": "Dev", "score": 64},
]

best = max(students, key=lambda s: s["score"])
print("Top student:", best["name"], "with", best["score"])
print(students[1])
print(students[1]["name"])
```

Now `max` hands back the whole record, so the name can't drift away from the score. (The `key=` part tells `max` what to compare; it gets its own section below.) Notice the two kinds of brackets: `students[1]` picks the second item of the list by position, and `["name"]` picks a value from that dictionary by key.

Dictionaries are easy to change. Assigning to a new key adds it, and assigning to an existing key replaces the value:

```python run title="dict_basics.py"
ava = {"name": "Ava", "score": 88}
ava["club"] = "robotics"
ava["score"] = 90
print(ava)
print("email" in ava)
print(ava.get("email", "no email on file"))
```

`ava["email"]` would crash with `KeyError: 'email'`. When a key might be missing, check with `in` or use `.get(key, default)`, which returns the default instead of crashing.

## Choose the collection by the question you'll ask

Python has four everyday collections, and the right one depends on how you'll use the data, not on what the data is.

| If you need to… | Use a | Example |
| --- | --- | --- |
| Keep items in order, duplicates allowed | list | `["worksheet 4", "lab report"]` |
| Look a value up by a name or ID | dict | `{"MATH": "Algebra II", "BIO": "Biology"}` |
| Keep only unique items and test membership quickly | set | `{"math", "exam"}` |
| Bundle a fixed group of values that belong together | tuple | `("2026-11-20", "09:00")` |

```python run title="sets_and_tuples.py"
tags = ["math", "exam", "math", "reading", "exam"]
unique = set(tags)
print(len(tags), "tags,", len(unique), "unique")
print(sorted(unique))
print("exam" in unique)

due = ("2026-11-20", "09:00")
day, time = due
print("Due", day, "at", time)
```

A set throws duplicates away the moment you build it. Sets have no fixed order, so print them through `sorted()` when the order matters to a reader. A tuple can't be changed after it's made, and `day, time = due` **unpacks** it into two variables in one line.

## Reach into nested data

Real data nests: a planner holds courses, each course holds tasks. Read a chain of brackets left to right, one level per bracket:

```python run title="planner.py"
planner = {
    "owner": "Ava",
    "courses": {
        "MATH": {"title": "Algebra II", "tasks": ["worksheet 4", "quiz review"]},
        "BIO": {"title": "Biology", "tasks": ["lab report"]},
    },
}

print(planner["courses"]["MATH"]["title"])
print(planner["courses"]["MATH"]["tasks"][-1])

planner["courses"]["BIO"]["tasks"].append("read ch. 6")
for code, course in planner["courses"].items():
    print(code, "-", course["title"])
    for task in course["tasks"]:
        print("   *", task)
```

`planner["courses"]` is a dict of courses, `["MATH"]` is one course (another dict), `["tasks"]` is its list, and `[-1]` is the last task. `.items()` gives you each key and value together, which is what you almost always want when looping over a dict.

The loop inside a loop is the part people misread. The inner loop runs **all the way through** for each single pass of the outer loop. Step through it and watch `total` reset for each student:

:::trace Watch the inner loop finish before the outer loop moves on
```python
students = [
    {"name": "Ava", "scores": [88, 92]},
    {"name": "Ben", "scores": [72, 65, 80]},
]
for student in students:
    total = 0
    for score in student["scores"]:
        total = total + score
    print(student["name"], total)
```
:::

## Comprehensions build new lists

A lot of loops have the same shape: start with an empty list, loop, maybe test something, append. A **comprehension** writes that whole shape in one line:

```python run title="comprehensions.py"
scores = [88, 72, 95, 64]
curved = [s + 5 for s in scores]
passing = [s for s in scores if s >= 70]
print(curved)
print(passing)
```

Read `[s + 5 for s in scores]` as "give me `s + 5`, for each `s` in `scores`." The optional `if` at the end filters: items that fail the test are skipped. Here is the loop that a filtering comprehension stands for. Step through it, then compare with the one-liner on its last line:

:::trace The loop hiding inside a comprehension
```python
scores = [88, 72, 95, 64]
passing = []
for s in scores:
    if s >= 70:
        passing.append(s)
print(passing)
print(passing == [s for s in scores if s >= 70])
```
:::

Comprehensions work on records too, and with curly braces they build dictionaries. Combined with string methods they turn messy text into clean data:

```python run title="reshape.py"
students = [
    {"name": "Ava", "score": 88},
    {"name": "Ben", "score": 72},
    {"name": "Cleo", "score": 95},
]
honor_roll = [s["name"] for s in students if s["score"] >= 85]
score_of = {s["name"]: s["score"] for s in students}
print(honor_roll)
print(score_of["Cleo"])

raw = "  Math, exam ,READING,  math "
tags = [t.strip().lower() for t in raw.split(",")]
print(tags)
print(", ".join(sorted(set(tags))))
```

`raw.split(",")` cuts the text at each comma, `.strip()` trims spaces from both ends, and `.lower()` makes `"Math"` and `"math"` the same tag. `", ".join(...)` goes the other way, gluing a list of strings into one. Keep comprehensions short. If one needs two `if`s and a nested loop, a regular loop is easier to read.

## Sort by any field with key=

`sorted(students)` alone crashes, because Python has no idea how to compare one dictionary with another. You tell it with `key=`: a function that takes **one item** and returns the value to compare.

```python run title="sorting.py"
students = [
    {"name": "Dev", "score": 88},
    {"name": "Ben", "score": 72},
    {"name": "Cleo", "score": 95},
    {"name": "Ava", "score": 88},
]

for s in sorted(students, key=lambda s: s["score"], reverse=True):
    print(s["name"], s["score"])

print("---")
for s in sorted(students, key=lambda s: (-s["score"], s["name"])):
    print(s["name"], s["score"])
```

`lambda s: s["score"]` is a tiny unnamed function: given a student, return their score. In the second sort the key returns a **tuple**. Tuples compare item by item, so students are ordered by `-score` first (highest first, because the scores are negated) and ties are broken by name. Dev and Ava both have 88. In the first list Dev comes first only because he was typed first; with the tuple key, ties always come out alphabetically.

`sorted()` returns a **new** list and leaves the original alone. A list's own `.sort()` method rearranges the list in place and returns `None`, which leads straight to the most common sorting bug:

```python run raises title="sort_bug.py"
names = ["Cleo", "Ava", "Ben"]
names = names.sort()
for name in names:
    print(name)
```

:::warning
`names = names.sort()` sorts the list, then replaces it with `None`, the value `.sort()` returns. The crash comes a line later: `TypeError: 'NoneType' object is not iterable`. Either call `names.sort()` on its own line, or write `names = sorted(names)`.
:::

:::warning
Passing `key=score_of()` with parentheses calls the function immediately, with no student to work on. Pass the function itself, `key=score_of`, and `sorted` will call it once per item.
:::

:::quiz
Q: What does `[n * 2 for n in [1, 2, 3, 4] if n % 2 == 0]` give?
- [ ] `[2, 4, 6, 8]`
  That doubles every number. The `if` keeps only the even ones first.
- [x] `[4, 8]`
  Only 2 and 4 pass `n % 2 == 0`, and each is doubled.
- [ ] `[2, 4]`
  Those are the numbers that pass the filter, but the comprehension outputs `n * 2`.

Q: A check-in desk needs to answer "has this student arrived yet?" thousands of times. Which collection fits best for the arrived students?
- [ ] A list
  It works, but `in` has to scan the list item by item, and duplicates can creep in.
- [x] A set
  Sets keep each item once and answer `in` almost instantly, however big they get.
- [ ] A tuple
  Tuples can't change, and students keep arriving.

Q: With the `planner` from this page, what is `planner["courses"]["BIO"]["tasks"][0]`?
- [x] `"lab report"`
  BIO's task list starts with `"lab report"`, and `[0]` is the first item.
- [ ] `"Biology"`
  That is the value under `"title"`, not the first task.
- [ ] `"worksheet 4"`
  That is MATH's first task. The `["BIO"]` step chooses a different course.

Q: `order = [3, 1, 2].sort()`. What is `order`?
- [ ] `[1, 2, 3]`
  The list does get sorted, but the variable doesn't receive it.
- [x] `None`
  `.sort()` changes a list in place and returns `None`. Use `sorted([3, 1, 2])` to get a new list back.
:::

:::takeaways
- Keep a record's fields together in a dict, and a group of records in a list.
- Lists for order, dicts for lookup by key, sets for uniqueness, tuples for fixed bundles.
- Read nested brackets left to right, one level each; the inner loop finishes before the outer one advances.
- `[expr for item in items if test]` builds a list; `{k: v for ...}` builds a dict.
- `sorted(items, key=...)` returns a new list ordered by whatever the key function returns; `.sort()` returns `None`.
:::
