## The starter

Make a folder called `habits` with three empty files: `storage.py`, `tracker.py` (the logic), and `habits.py` (the command line). Here are the signatures to aim for. Each milestone below fills some of them in.


`raise NotImplementedError` is a placeholder that crashes loudly if you call a function you haven't written yet, which is much better than a silent `pass` that returns `None`.

## Milestone 1: Storage you can trust

```python run
import json
import os


def load_data(path):
    """Return the saved data, or an empty tracker if there's no file yet."""
    try:
        with open(path, encoding="utf-8") as file:
            data = json.load(file)
    except FileNotFoundError:
        return {"habits": {}}
    except json.JSONDecodeError:
        raise ValueError(f"{path} is damaged; fix it or move it out of the way")
    if not isinstance(data, dict) or not isinstance(data.get("habits"), dict):
        raise ValueError(f"{path} doesn't look like a habits file")
    return data


def save_data(path, data):
    """Write to a temporary file first, then swap it in, so a crash can't leave half a file."""
    temp = path + ".tmp"
    with open(temp, "w", encoding="utf-8") as file:
        json.dump(data, file, indent=2)
    os.replace(temp, path)


print(load_data("practice.json"))
example = {"habits": {"stretch": {"days": ["2026-11-11", "2026-11-12"]}}}
save_data("practice.json", example)
assert load_data("practice.json") == example
print("temp file left behind?", os.path.exists("practice.json.tmp"))

with open("practice.json", "w") as file:
    file.write('{"habits": ')
try:
    load_data("practice.json")
except ValueError as error:
    print("error:", error)
```

The new idea is in `save_data`. Opening a file with `"w"` empties it immediately, so if the program crashed (or the laptop died) halfway through `json.dump`, the real file would be left half-written and the user's history gone. Writing to `habits.json.tmp` first and then calling `os.replace` avoids that: the swap happens in one step, so `habits.json` is always either the old complete file or the new complete one. The shape check in `load_data` catches a file that's valid JSON but not *our* JSON.

**Checkpoint:** the round trip asserts pass, a missing file prints the empty tracker, and a damaged file produces an `error:` line, not a traceback.

## Milestone 2: Add habits, and decide what a name is

```python run
def normalize(name):
    name = " ".join(name.split()).lower()
    if not name:
        raise ValueError("a habit needs a name")
    if len(name) > 30:
        raise ValueError("keep habit names to 30 characters or fewer")
    return name


def get_habit(data, name):
    key = normalize(name)
    if key not in data["habits"]:
        raise ValueError(f"no habit called '{key}' (see: python habits.py list)")
    return key, data["habits"][key]


def add_habit(data, name):
    key = normalize(name)
    if key in data["habits"]:
        raise ValueError(f"you already track '{key}'")
    data["habits"][key] = {"days": []}
    return key


data = {"habits": {}}
print(add_habit(data, "  Read   20 Pages "))
for bad in ["read 20 pages", "   ", "x" * 31]:
    try:
        add_habit(data, bad)
    except ValueError as error:
        print("rejected:", error)
print(data)
```

`" ".join(name.split())` is a small trick worth remembering: `split()` with no argument breaks on any run of whitespace and drops the ends, and `join` puts single spaces back. Every function that takes a name goes through `normalize`, so `Read 20 Pages`, `read 20 pages`, and `  READ 20   pages` all find the same habit. `get_habit` exists because three commands need "find this habit or explain why not," and writing that once means the message is the same everywhere.

**Checkpoint:** duplicates, blank names, and very long names are rejected with readable messages.

## Milestone 3: Check-ins, with dates stored as text

```python run
from datetime import date, timedelta


def check_in(data, name, day, today):
    key, habit = get_habit(data, name)
    if day > today:
        raise ValueError("you can't check in for a day that hasn't happened yet")
    text = day.isoformat()
    if text in habit["days"]:
        raise ValueError(f"'{key}' is already checked in for {text}")
    habit["days"].append(text)
    habit["days"].sort()
    return key


def done_days(habit):
    return {date.fromisoformat(text) for text in habit["days"]}


TODAY = date(2026, 11, 15)
check_in(data, "read 20 pages", date(2026, 11, 14), TODAY)
check_in(data, "READ 20 PAGES", TODAY, TODAY)
for day in [TODAY, date(2026, 11, 16)]:
    try:
        check_in(data, "read 20 pages", day, TODAY)
    except ValueError as error:
        print("rejected:", error)
print(data["habits"]["read 20 pages"])
print(done_days(data["habits"]["read 20 pages"]))
```

Dates live in two forms. In the file they're `"2026-11-14"` strings, because JSON can't hold anything else. In the logic they're `date` objects, because those can be compared (`day > today`) and stepped (`today - timedelta(days=1)`). `isoformat()` and `fromisoformat()` convert between the two, and `done_days` builds a **set**, because the streak code is about to ask "is this day in there?" many times. Sorting after each append keeps the file readable when someone checks in for a past day.

**Checkpoint:** repeat check-ins and future dates are rejected; a check-in for any past day works.

## Milestone 4: The streak, from words to code

The plan defined it in words: *days in a row ending today; if today isn't done yet, count back from yesterday instead.* The code is that sentence, almost word for word. Step through it with today not yet checked in, and watch `day` walk backward until it hits a gap:

:::trace Watch current_streak count back from yesterday
```python
from datetime import date, timedelta

def current_streak(days, today):
    day = today if today in days else today - timedelta(days=1)
    streak = 0
    while day in days:
        streak += 1
        day -= timedelta(days=1)
    return streak

done = {date(2026, 11, 12), date(2026, 11, 13), date(2026, 11, 14)}
print(current_streak(done, date(2026, 11, 15)))
```
:::

Now the full set of streak functions, checked against the table from the plan:

```python run
def current_streak(days, today):
    """Days in a row ending today, or ending yesterday if today isn't done yet."""
    day = today if today in days else today - timedelta(days=1)
    streak = 0
    while day in days:
        streak += 1
        day -= timedelta(days=1)
    return streak


def longest_streak(days):
    best = 0
    for day in days:
        if day - timedelta(days=1) not in days:
            length = 1
            while day + timedelta(days=length) in days:
                length += 1
            best = max(best, length)
    return best


def history_strip(days, today, count):
    """One character per day, oldest first: '#' done, '.' missed."""
    marks = []
    for back in range(count - 1, -1, -1):
        day = today - timedelta(days=back)
        marks.append("#" if day in days else ".")
    return "".join(marks)


def nov(*numbers):
    return {date(2026, 11, n) for n in numbers}


assert current_streak(nov(13, 14, 15), TODAY) == 3
assert current_streak(nov(13, 14), TODAY) == 2
assert current_streak(nov(10, 11, 13), TODAY) == 0
assert current_streak({date(2026, 10, 31), date(2026, 11, 1)}, date(2026, 11, 1)) == 2
assert longest_streak(nov(1, 2, 3, 7, 8)) == 3
print("streak table passes")
print(history_strip(nov(9, 12, 13, 15), TODAY, 7))
```

`longest_streak` only starts counting at days that *begin* a run (the day before isn't in the set), then counts forward. That way each run is measured once, instead of re-counting from every day inside it. The month-boundary row passes without any special code: `timedelta` knows October has 31 days, which is the reason to use it instead of subtracting 1 from a day number.

**Checkpoint:** every row of the streak table passes as an `assert`.

## Milestone 5: The command line

Every handler takes `(data, args, today)` and returns a message. `main` is the same shape as the reading log's, plus one new parameter: `today`, which defaults to the real date but can be fixed for testing.

```python run
import argparse
import sys

DATA_FILE = "habits.json"


def iso_date(text):
    try:
        return date.fromisoformat(text)
    except ValueError:
        raise argparse.ArgumentTypeError(f"'{text}' is not a date like 2026-11-15")


def cmd_add(data, args, today):
    key = add_habit(data, args.name)
    return f"Now tracking '{key}'. Check in with: python habits.py check \"{key}\""


def cmd_check(data, args, today):
    day = args.date or today
    key = check_in(data, args.name, day, today)
    if day != today:
        return f"Checked in '{key}' for {day.isoformat()}."
    streak = current_streak(done_days(data["habits"][key]), today)
    return f"Checked in '{key}' for today. Streak: {streak} day(s)."


def cmd_list(data, args, today):
    if not data["habits"]:
        return "No habits yet. Start one with: python habits.py add NAME"
    width = max(len(key) for key in data["habits"])
    lines = []
    for key in sorted(data["habits"]):
        days = done_days(data["habits"][key])
        mark = "x" if today in days else " "
        lines.append(f"[{mark}] {key:<{width}}  streak {current_streak(days, today):>3}"
                     f"  best {longest_streak(days):>3}")
    return "\n".join(lines)


def cmd_history(data, args, today):
    if not 7 <= args.days <= 60:
        raise ValueError("--days must be from 7 to 60")
    key, habit = get_habit(data, args.name)
    strip = history_strip(done_days(habit), today, args.days)
    return f"{key}: {strip}  (last {args.days} days, today on the right)"


def cmd_remove(data, args, today):
    key, _ = get_habit(data, args.name)
    del data["habits"][key]
    return f"Stopped tracking '{key}'."


HANDLERS = {"add": cmd_add, "check": cmd_check, "list": cmd_list,
            "history": cmd_history, "remove": cmd_remove}


def build_parser():
    parser = argparse.ArgumentParser(prog="habits.py", description="Track daily habits and streaks.")
    commands = parser.add_subparsers(dest="command", required=True)

    add = commands.add_parser("add", help="start tracking a habit")
    add.add_argument("name")

    check = commands.add_parser("check", help="mark a habit done")
    check.add_argument("name")
    check.add_argument("--date", type=iso_date, help="a past day, as YYYY-MM-DD (default: today)")

    commands.add_parser("list", help="every habit with its streaks")

    history = commands.add_parser("history", help="show recent days for one habit")
    history.add_argument("name")
    history.add_argument("--days", type=int, default=14, help="how many days to show, 7-60 (default: 14)")

    remove = commands.add_parser("remove", help="stop tracking a habit")
    remove.add_argument("name")
    return parser


def main(argv=None, path=DATA_FILE, today=None):
    args = build_parser().parse_args(argv)
    today = today or date.today()
    try:
        data = load_data(path)
        message = HANDLERS[args.command](data, args, today)
    except ValueError as error:
        print(f"error: {error}", file=sys.stderr)
        return 1
    save_data(path, data)
    print(message)
    return 0


for argv in [
    ["add", "Read 20 pages"],
    ["add", "stretch"],
    ["check", "read 20 pages", "--date", "2026-11-13"],
    ["check", "read 20 pages", "--date", "2026-11-14"],
    ["check", "Read 20 Pages"],
    ["check", "stretch", "--date", "2026-11-12"],
    ["list"],
    ["history", "read 20 pages", "--days", "7"],
    ["check", "stretch", "--date", "2026-11-30"],
    ["remove", "guitar"],
]:
    code = main(argv, today=TODAY)
    if code:
        print("  exit code", code, "for", argv)
```

Each `main()` call loads `habits.json`, runs one command, and saves, exactly like separate runs in the terminal. The two failures at the end return 1, their messages go to the error stream, and nothing is saved for them. `--date` uses the `iso_date` type from Module 5's practice, so `--date 11/14` is rejected by `argparse` before any of your code runs, while `--days 3` is a perfectly good integer that `cmd_history` rejects with its own range rule.

**Checkpoint:** every command runs through `main()`, and every mistake ends with an `error:` line and exit code 1 or 2.

## Split it into three files

Move each piece into the file the plan gave it: the Milestone 1 functions into `storage.py`, Milestones 2 to 4 into `tracker.py`, and Milestone 5 into `habits.py`. The top of `habits.py` imports from the other two, and the bottom gets the usual guard:

```py title="habits.py (top and bottom)"
import argparse
import sys
from datetime import date

from storage import load_data, save_data
from tracker import (add_habit, check_in, current_streak, done_days,
                     get_habit, history_strip, longest_streak)

DATA_FILE = "habits.json"

# ... iso_date, the cmd_ handlers, HANDLERS, build_parser, and main from Milestone 5 ...


if __name__ == "__main__":
    sys.exit(main())
```

`tracker.py` needs `from datetime import date, timedelta` at its top, and `storage.py` needs `import json` and `import os`. The parentheses around the long `from tracker import (...)` line let it continue onto a second line. Then run it for real in the VS Code terminal. On November 15, 2026, a session looks like this:

```bash
$ python habits.py add "Read 20 pages"
Now tracking 'read 20 pages'. Check in with: python habits.py check "read 20 pages"
$ python habits.py check "Read 20 Pages"
Checked in 'read 20 pages' for today. Streak: 1 day(s).
$ python habits.py check "read 20 pages" --date 2026-11-14
Checked in 'read 20 pages' for 2026-11-14.
$ python habits.py list
[x] read 20 pages  streak   2  best   2
$ python habits.py check stretch
error: no habit called 'stretch' (see: python habits.py list)
$ python habits.py check "read 20 pages" --date 11/14
usage: habits.py check [-h] [--date DATE] name
habits.py check: error: argument --date: '11/14' is not a date like 2026-11-15
```

Close the terminal, open a new one, and run `python habits.py list` again. The streak is still there. That's the capstone's main requirement, working.

:::quiz
Q: Why does `save_data` write `habits.json.tmp` and then call `os.replace`, instead of writing `habits.json` directly?
- [ ] Because `json.dump` can't write to a file that already exists
  It can; `"w"` mode empties the file first, which is exactly the risk.
- [x] So a crash during writing can't leave `habits.json` half-written
  Until the swap, the old complete file is still in place; after it, the new complete one is.
- [ ] To keep a backup copy of yesterday's data
  The temporary file is replaced into the real one, so no backup is kept.

Q: The streak counts back from yesterday when today isn't checked in. What would happen without that rule?
- [x] Every streak would show 0 each morning until you checked in, which feels like losing it
  The rule is about what "current streak" should mean to a person, written down in the plan before the code.
- [ ] The program would crash on the first check-in of the day
  Nothing crashes; the number would just be misleading.
- [ ] Streaks across a month boundary would break
  `timedelta` handles month boundaries either way.

Q: `cmd_history` checks `7 <= args.days <= 60` itself. Why not let `argparse` do all the checking?
- [ ] `argparse` can't check integers
  `type=int` checks that it *is* an integer; the allowed range is a rule of this program.
- [x] `type=int` only checks the type, so the range rule needs a check of its own, which then reports through the same `error:` path
  Raising `ValueError` makes the range message look like every other error and return exit code 1.
- [ ] Because `--days` is optional
  Optional arguments can have types and choices like any other.
:::

:::takeaways
- Run something at the end of every milestone; never write three milestones before testing one.
- Write JSON to a temporary file and `os.replace` it, so a crash can't destroy the data.
- Keep dates as `YYYY-MM-DD` text in the file and as `date` objects in the logic; convert at the boundary.
- A rule defined in words, with a table of examples, turns almost line for line into code and `assert`s.
- Passing `today` into `main()` and the logic is what makes the whole program testable, which is the next lesson.
:::
