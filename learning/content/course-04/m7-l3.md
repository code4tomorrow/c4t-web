## Warm-up: which layer?

Sort these into **interface**, **logic**, or **storage**: (a) `format_table(books)`, (b) `load_books(path)`, (c) `log_pages(books, title, pages)`, (d) `build_parser()`, (e) a function that decides whether a habit's streak is broken, (f) a function that writes a backup copy of `books.json`.

Answers: (a) interface, since it decides how things look. (b) and (f) storage. (c) and (e) logic, since they're rules about the data. (d) interface. If you hesitated on (e), ask: does it print, prompt, or touch a file? No, so it's logic.

### Exercise 1: Commands before code

A friend wants `money.py` to track pocket money: record money coming in and going out with a category (`snacks`, `games`, `savings`...), show the current balance, and list recent entries, optionally just one category. Write four example commands with the output each should print, and the JSON shape for the data file. No Python yet.

:::hint
Decide how a user types an amount going *out*. A separate `spend` command is clearer than asking people to type negative numbers. Then ask what each entry must remember for `list` to work.
:::

:::solution
One good design (yours can differ, as long as every command's output can be produced from the stored data):

```bash
$ python money.py earn 20 --note "birthday card"
+$20.00 (balance $20.00)
$ python money.py spend 4.50 snacks
-$4.50 on snacks (balance $15.50)
$ python money.py balance
$15.50
$ python money.py list --category snacks
2026-11-15  snacks  -$4.50
```

```json
[
  {"date": "2026-11-15", "amount": 20.0, "category": "income", "note": "birthday card"},
  {"date": "2026-11-15", "amount": -4.5, "category": "snacks", "note": ""}
]
```

The balance isn't stored; it's the sum of the amounts, so it can never disagree with the entries. Storing spending as negative numbers internally keeps that sum simple, even though users never type a minus sign.
:::

### Exercise 2: Untangle the report

This function reads scores, does the math, and prints, all at once. Split it into `read_scores()` (interface), `summarize(scores)` (logic, returns a dictionary), and `format_summary(summary)` (interface, returns a string). Make `summarize([])` return sensible values instead of crashing, and test it with `assert`.

```python
def report():
    scores = []
    while True:
        text = input("Score (blank to finish): ")
        if text == "":
            break
        scores.append(int(text))
    print("Count:", len(scores))
    print("Average:", round(sum(scores) / len(scores), 1))
    print("Passing:", len([s for s in scores if s >= 60]))
```

:::hint
`summarize` should return something like `{"count": 3, "average": 72.3, "passing": 2}`. For an empty list, `None` is an honest average. Write the asserts *before* you write `summarize`.
:::

:::solution
```python run input="72|55|90|"
def read_scores():
    scores = []
    while True:
        text = input("Score (blank to finish): ").strip()
        if text == "":
            return scores
        scores.append(int(text))


def summarize(scores):
    if not scores:
        return {"count": 0, "average": None, "passing": 0}
    return {
        "count": len(scores),
        "average": round(sum(scores) / len(scores), 1),
        "passing": sum(1 for score in scores if score >= 60),
    }


def format_summary(summary):
    average = "n/a" if summary["average"] is None else summary["average"]
    return f"Count: {summary['count']}\nAverage: {average}\nPassing: {summary['passing']}"


assert summarize([]) == {"count": 0, "average": None, "passing": 0}
assert summarize([60, 59]) == {"count": 2, "average": 59.5, "passing": 1}

print(format_summary(summarize(read_scores())))
```

The two asserts test the logic with no typing at all, including the boundary at exactly 60. The last line reads like a sentence: read, summarize, format, print. `read_scores` still crashes on `abc`; swapping in the validated loop from Module 5 is a one-function change now that input lives in one place.
:::

### Exercise 3: Add `remove` and a sort option

Start from the planner parser in the notes. Add a `remove ID` subcommand (an integer), and give `list` a `--sort` option that only accepts `due` or `title`, defaulting to `due`. Check it by parsing `["remove", "3"]`, `["list"]`, and `["list", "--sort", "title", "--all"]`.

:::hint
`add_argument("--sort", choices=["due", "title"], default="due")` makes `argparse` reject anything else for you.
:::

:::solution
```python run
import argparse


def build_parser():
    parser = argparse.ArgumentParser(prog="plan.py", description="A homework planner.")
    commands = parser.add_subparsers(dest="command", required=True)

    add = commands.add_parser("add", help="add a task")
    add.add_argument("title")
    add.add_argument("--due", help="due date as YYYY-MM-DD")

    done = commands.add_parser("done", help="mark a task finished")
    done.add_argument("id", type=int)

    remove = commands.add_parser("remove", help="delete a task")
    remove.add_argument("id", type=int)

    listing = commands.add_parser("list", help="show tasks")
    listing.add_argument("--all", action="store_true", help="include finished tasks")
    listing.add_argument("--sort", choices=["due", "title"], default="due", help="order of the list")
    return parser


parser = build_parser()
print(parser.parse_args(["remove", "3"]))
print(parser.parse_args(["list"]))
print(parser.parse_args(["list", "--sort", "title", "--all"]))
```

`--sort size` would now fail with a usage message listing the allowed choices, and the help screen shows them too. Options can come in any order after the subcommand, which is why `--all` after `--sort title` works.
:::

### Exercise 4: Test the whole program through `main()`

Here's a small `calc.py`. Write a helper `exit_code(argv)` that calls `main(argv)` and returns its exit code, *including* when `argparse` stops the program. Then assert these four results: `total 2 3.5` gives 0, `avg 70 --drop-lowest` gives 1, `mean 1` gives 2, and `total two` gives 2.

```python
import argparse
import sys
from statistics import mean


def build_parser():
    parser = argparse.ArgumentParser(prog="calc.py", description="Quick number tools.")
    commands = parser.add_subparsers(dest="command", required=True)
    total = commands.add_parser("total", help="add numbers together")
    total.add_argument("numbers", type=float, nargs="+")
    avg = commands.add_parser("avg", help="average of numbers")
    avg.add_argument("numbers", type=float, nargs="+")
    avg.add_argument("--drop-lowest", action="store_true")
    return parser


def main(argv=None):
    args = build_parser().parse_args(argv)
    numbers = sorted(args.numbers)
    if args.command == "total":
        print(sum(numbers))
        return 0
    if args.drop_lowest:
        if len(numbers) < 2:
            print("error: --drop-lowest needs at least 2 numbers", file=sys.stderr)
            return 1
        numbers = numbers[1:]
    print(round(mean(numbers), 2))
    return 0
```

:::hint
When `argparse` rejects the command line it raises `SystemExit`, and the exception's `.code` attribute holds the exit code. Catch it with `except SystemExit as stop:`.
:::

:::solution
```python run
import argparse
import sys
from statistics import mean


def build_parser():
    parser = argparse.ArgumentParser(prog="calc.py", description="Quick number tools.")
    commands = parser.add_subparsers(dest="command", required=True)
    total = commands.add_parser("total", help="add numbers together")
    total.add_argument("numbers", type=float, nargs="+")
    avg = commands.add_parser("avg", help="average of numbers")
    avg.add_argument("numbers", type=float, nargs="+")
    avg.add_argument("--drop-lowest", action="store_true")
    return parser


def main(argv=None):
    args = build_parser().parse_args(argv)
    numbers = sorted(args.numbers)
    if args.command == "total":
        print(sum(numbers))
        return 0
    if args.drop_lowest:
        if len(numbers) < 2:
            print("error: --drop-lowest needs at least 2 numbers", file=sys.stderr)
            return 1
        numbers = numbers[1:]
    print(round(mean(numbers), 2))
    return 0


def exit_code(argv):
    try:
        return main(argv)
    except SystemExit as stop:
        return stop.code


assert exit_code(["total", "2", "3.5"]) == 0
assert exit_code(["avg", "70", "--drop-lowest"]) == 1
assert exit_code(["mean", "1"]) == 2
assert exit_code(["total", "two"]) == 2
print("all four exit codes are right")
```

`total 2 3.5` also printed `5.5`, which shows these are real runs of the program. The exit codes split mistakes into two kinds: 2 means "you typed the command wrong" (caught by `argparse`), and 1 means "the command made sense but couldn't be done" (caught by your own rules). `nargs="+"` collects one or more values into a list, which is how `avg` accepts any number of scores.
:::

### Exercise 5: A loader that trusts nothing

`load_books` handles a missing file and broken JSON. But someone could hand-edit `books.json` into valid JSON of the *wrong shape*, like `{"title": "Dune"}`, a dictionary instead of a list, and every command would then crash in a confusing way. Write `load_list(path)` that returns `[]` for a missing file and raises a `ValueError` with a clear message for broken JSON *or* for anything that isn't a list. Test it on four files.

:::hint
After `json.load`, check `isinstance(data, list)`. `type(data).__name__` gives a readable name like `dict` for the message.
:::

:::solution
```python run
import json


def load_list(path):
    try:
        with open(path, encoding="utf-8") as file:
            data = json.load(file)
    except FileNotFoundError:
        return []
    except json.JSONDecodeError:
        raise ValueError(f"{path} is not valid JSON")
    if not isinstance(data, list):
        raise ValueError(f"{path} should hold a list, but it holds a {type(data).__name__}")
    return data


samples = {"good.json": '[{"title": "Dune"}]', "broken.json": '[{"title": ', "shape.json": '{"title": "Dune"}'}
for name, text in samples.items():
    with open(name, "w", encoding="utf-8") as file:
        file.write(text)

for name in ["missing.json", "good.json", "broken.json", "shape.json"]:
    try:
        print(name, "->", load_list(name))
    except ValueError as error:
        print(name, "-> error:", error)
```

A program's data file is input too, just like what people type, and it deserves the same suspicion. Checking the shape at the door means every other function can assume it really has a list.
:::

### Exercise 6: Write the README for `calc.py`

Write a complete README for the `calc.py` tool from Exercise 4, covering the five questions: what it is, what you need, how to use it (with copyable examples of both commands and the option), how it's organized, and its limits.

:::hint
Run `python calc.py -h` and `python calc.py avg -h` and use the help text as a checklist: every command and option there should appear in an example.
:::

:::solution
```markdown title="README.md"
# calc

Quick number tools for the terminal: totals and averages.

## Setup
Python 3.10 or newer. No packages to install.

## Usage
    python calc.py total 12 7.5 3       # prints 22.5
    python calc.py avg 70 90 100        # prints 86.67
    python calc.py avg 70 90 100 --drop-lowest   # prints 95.0
    python calc.py -h                   # all commands

## Exit codes
- 0: success
- 1: the numbers can't be used (for example, --drop-lowest with one number)

## Files
- calc.py: everything (small enough for one file)

## Known limits
Numbers only; no saved history.
```

The "Exit codes" section isn't required for every tool, but it's what lets another program or a teacher's grading script use yours reliably. The example outputs let a reader check that their copy works.

### Challenge: Export the reading log to CSV

Add an `export` command to `shelf.py` that writes every book to a CSV file a spreadsheet can open, with the columns `title`, `pages`, `read`, and `percent`. It takes `--output PATH` (default `books.csv`) and refuses to overwrite an existing file unless `--force` is given. Put the file-writing in a function `export_csv(books, path, force=False)` that returns how many books it wrote, and test it before wiring it to the parser.

:::hint
`csv.DictWriter(file, fieldnames=[...])` writes dictionaries as rows; call `writeheader()` first. Open the file with `newline=""`, which the `csv` docs require so Windows doesn't get blank lines between rows. `os.path.exists(path)` tells you if the file is already there.
:::

:::solution
```python run
import csv
import os


def export_csv(books, path, force=False):
    if os.path.exists(path) and not force:
        raise ValueError(f"{path} already exists (add --force to replace it)")
    with open(path, "w", newline="", encoding="utf-8") as file:
        writer = csv.DictWriter(file, fieldnames=["title", "pages", "read", "percent"])
        writer.writeheader()
        for book in books:
            percent = round(100 * book["read"] / book["pages"])
            writer.writerow({**book, "percent": percent})
    return len(books)


books = [{"title": "The Hobbit", "pages": 310, "read": 85}, {"title": "Hatchet", "pages": 195, "read": 195}]
print("wrote", export_csv(books, "books.csv"))
try:
    export_csv(books, "books.csv")
except ValueError as error:
    print("error:", error)
print("wrote", export_csv(books, "books.csv", force=True))

with open("books.csv", encoding="utf-8") as file:
    print(file.read())
```

`{**book, "percent": percent}` copies the book's fields and adds one more, without changing the stored book. Then wire it in: `export_csv` goes in `storage.py`, and `shelf.py` gets a handler and a subparser.

```py title="shelf.py (additions)"
from storage import export_csv, load_books, save_books


def cmd_export(books, args):
    count = export_csv(books, args.output, force=args.force)
    return f"Exported {count} books to {args.output}."


HANDLERS["export"] = cmd_export

# inside build_parser():
export = commands.add_parser("export", help="save your shelf as a CSV file")
export.add_argument("--output", default="books.csv", help="file to write (default: books.csv)")
export.add_argument("--force", action="store_true", help="replace the file if it exists")
```

Because `export_csv` raises `ValueError`, the existing `main()` already turns "file exists" into an `error:` line and exit code 1. No change to `main()` at all: that's the payoff of the design.
:::
