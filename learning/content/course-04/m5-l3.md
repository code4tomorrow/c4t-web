## Warm-up: which line fails?

Predict what this prints before you look at the output. One line crashes. Which one, and what kind of error is it?

```python run raises
import math
from math import sqrt

print(math.sqrt(49), sqrt(49))
print(math.floor(2.7))
print(floor(2.7))
```

`import math` gives you the name `math`, and `from math import sqrt` gives you `sqrt`. Nothing gave you a bare `floor`, so the last line is a `NameError`. Fix it with `math.floor`, or add `floor` to the `from` line.

### Exercise 1: Split the class into random teams

You have eight names. Split them into two teams of four at random, print each team in alphabetical order, and make the split repeatable with a seed so you can show a friend the same result. Don't change the original list.

```text
Team A: Ben, Eli, Fatima, Gus
Team B: Ava, Chen, Dara, Hana
```

:::hint
Copy the list with `names[:]`, then `shuffle` the copy with a `random.Random(4)` generator. The first half of the shuffled list is Team A.
:::

:::solution
```python run
import random

names = ["Ava", "Ben", "Chen", "Dara", "Eli", "Fatima", "Gus", "Hana"]

rng = random.Random(4)
shuffled = names[:]
rng.shuffle(shuffled)
half = len(shuffled) // 2

print("Team A:", ", ".join(sorted(shuffled[:half])))
print("Team B:", ", ".join(sorted(shuffled[half:])))
```

`shuffle` rearranges a list in place and returns `None`, which is why we shuffle a copy. Writing `shuffled = names` would not copy anything; both names would point to the same list, and the original order would be lost. Using `len(shuffled) // 2` instead of `4` keeps it working for a class of ten.
:::

### Exercise 2: "Tomorrow", not "in 1 days"

Write `days_until(deadline_text, today)`. It takes a date string like `"2026-12-04"` and a `date`, and returns `"today"`, `"tomorrow"`, `"in 19 days"`, `"yesterday"`, or `"3 days ago"`. Test it with `today = date(2026, 11, 15)`.

```text
2026-11-15 today
2026-11-16 tomorrow
2026-12-04 in 19 days
2026-11-14 yesterday
2026-11-12 3 days ago
```

:::hint
Subtract `today` from the parsed deadline and take `.days`. That number is negative for past dates. Handle 0, 1, and -1 first, then the general cases.
:::

:::solution
```python run
from datetime import date


def days_until(deadline_text, today):
    gap = (date.fromisoformat(deadline_text) - today).days
    if gap == 0:
        return "today"
    if gap == 1:
        return "tomorrow"
    if gap == -1:
        return "yesterday"
    if gap > 1:
        return f"in {gap} days"
    return f"{-gap} days ago"


today = date(2026, 11, 15)
for text in ["2026-11-15", "2026-11-16", "2026-12-04", "2026-11-14", "2026-11-12"]:
    print(text, days_until(text, today))
```

Taking `today` as a parameter, instead of calling `date.today()` inside, is what makes the output above repeatable. Your real program passes `date.today()`, and your tests pass a fixed date.
:::

### Exercise 3: A yes/no question that accepts real answers

Write `ask_yes_no(prompt)`. It should accept `y`, `yes`, `n`, or `no` in any capitalization, with or without spaces around them, and return `True` or `False`. Anything else gets a short message and the question again.

```text
Save before quitting? (y/n) maybe
  Please answer y or n.
Save before quitting? (y/n)   YES
Saving.
```

:::hint
Clean the answer once with `.strip().lower()`, then check membership with `in` against a set of accepted words.
:::

:::solution
```python run input="maybe|  YES "
def ask_yes_no(prompt):
    while True:
        answer = input(prompt).strip().lower()
        if answer in {"y", "yes"}:
            return True
        if answer in {"n", "no"}:
            return False
        print("  Please answer y or n.")


if ask_yes_no("Save before quitting? (y/n) "):
    print("Saving.")
else:
    print("Not saved.")
```

No `try` is needed here, because nothing raises an error: a string comparison just returns `False`. Use `try`/`except` when a conversion like `int()` can fail, and plain `if` checks when you only need to compare.
:::

### Exercise 4: Ask for a due date that's real and not in the past

Write `ask_date(prompt, today)`. Keep asking until the user types a valid `YYYY-MM-DD` date that is today or later. Show the reason for each rejection.

```text
Due date (YYYY-MM-DD): 12/18/2026
  Invalid isoformat string: '12/18/2026'
Due date (YYYY-MM-DD): 2026-02-30
  day is out of range for month
Due date (YYYY-MM-DD): 2026-11-01
  That date has already passed.
Due date (YYYY-MM-DD): 2026-12-18
Due on Friday, December 18
```

:::hint
`except ValueError as error:` gives you the exception object, and `print(error)` shows Python's own explanation. The "already passed" check is a plain `if` after the conversion succeeds.
:::

:::solution
```python run input="12/18/2026|2026-02-30|2026-11-01|2026-12-18"
from datetime import date


def ask_date(prompt, today):
    while True:
        text = input(prompt).strip()
        try:
            chosen = date.fromisoformat(text)
        except ValueError as error:
            print(" ", error)
            continue
        if chosen < today:
            print("  That date has already passed.")
            continue
        return chosen


due = ask_date("Due date (YYYY-MM-DD): ", date(2026, 11, 15))
print("Due on", due.strftime("%A, %B %d"))
```

`fromisoformat` checks the calendar for you, which is why February 30 fails with its own message. Dates compare with `<` the way numbers do, so the past-date check is one line.
:::

### Exercise 5: Where did the study time go?

Given this list of study sessions, print the total minutes per subject (largest first) and the subject you studied most *often*.

```python
sessions = [
    {"subject": "math", "minutes": 30},
    {"subject": "bio", "minutes": 45},
    {"subject": "math", "minutes": 20},
    {"subject": "history", "minutes": 60},
    {"subject": "math", "minutes": 25},
    {"subject": "bio", "minutes": 15},
]
```

```text
math: 75 min
bio: 60 min
history: 60 min
Most often: math (3 sessions)
```

:::hint
A `defaultdict(int)` adds up minutes without checking whether the key exists. A `Counter` of just the subject names answers "most often." `sorted(totals.items(), key=lambda pair: pair[1], reverse=True)` sorts by the minutes.
:::

:::solution
```python run
from collections import Counter, defaultdict

sessions = [
    {"subject": "math", "minutes": 30},
    {"subject": "bio", "minutes": 45},
    {"subject": "math", "minutes": 20},
    {"subject": "history", "minutes": 60},
    {"subject": "math", "minutes": 25},
    {"subject": "bio", "minutes": 15},
]

totals = defaultdict(int)
for session in sessions:
    totals[session["subject"]] += session["minutes"]

for subject, minutes in sorted(totals.items(), key=lambda pair: pair[1], reverse=True):
    print(f"{subject}: {minutes} min")

counts = Counter(session["subject"] for session in sessions)
subject, times = counts.most_common(1)[0]
print(f"Most often: {subject} ({times} sessions)")
```

"Most minutes" and "most sessions" are different questions, and here they even have the same answer by coincidence. Change history to 90 minutes and the first line changes while the last one doesn't.
:::

### Exercise 6: A countdown command with a friendly date error

Write `countdown.py` that runs like `python countdown.py 2026-12-18 --label "winter break"` and prints `33 days until winter break.` (when today is November 15). The date is a **positional** argument. A bad date should produce a clear message, not a traceback:

```bash
$ python countdown.py 12/18/2026
usage: countdown.py [-h] [--label LABEL] deadline
countdown.py: error: argument deadline: '12/18/2026' is not a date like 2026-12-18
```

:::hint
`type=` can be any function that takes a string. Write `iso_date(text)` that calls `date.fromisoformat` and, on `ValueError`, raises `argparse.ArgumentTypeError` with your message. `argparse` prints that message for you.
:::

:::solution
```python run
import argparse
from datetime import date


def iso_date(text):
    try:
        return date.fromisoformat(text)
    except ValueError:
        raise argparse.ArgumentTypeError(f"'{text}' is not a date like 2026-12-18")


def build_parser():
    parser = argparse.ArgumentParser(prog="countdown.py", description="Count the days to a deadline.")
    parser.add_argument("deadline", type=iso_date, help="the date, as YYYY-MM-DD")
    parser.add_argument("--label", default="the deadline", help="what the date is for")
    return parser


def main(argv=None, today=None):
    args = build_parser().parse_args(argv)
    today = today or date.today()
    days = (args.deadline - today).days
    print(f"{days} days until {args.label}.")


main(["2026-12-18", "--label", "winter break"], today=date(2026, 11, 15))
main(["2027-01-04"], today=date(2026, 11, 15))
```

In the real file, end with `if __name__ == "__main__": main()` so it reads the real command line and today's date. Positional arguments have no dashes and are required, so `python countdown.py` alone prints "the following arguments are required: deadline".
:::

### Challenge: A study-log menu that can't be broken

Build a menu loop with three choices: `a` adds a study session (1 to 240 minutes), `s` shows the number of sessions and total minutes, and `q` quits. Bad menu letters, non-numbers, and out-of-range minutes all get a message and another try. Nothing the user types should crash it.

```text
[a]dd  [s]how  [q]uit
> 5
  Choose one of: a, s, q
> a
Minutes studied (1-240): abc
  'abc' is not a whole number.
Minutes studied (1-240): 30
...
```

```mermaid caption="Every path in the menu loop leads back to the prompt or to quit"
flowchart TD
    A[Show menu] --> B{"Choice is a, s, or q?"}
    B -->|no| A
    B -->|a| C["ask_int(1, 240)"]
    C --> D[Add to log]
    D --> A
    B -->|s| E[Print count and total]
    E --> A
    B -->|q| F[Say goodbye and stop]
```

:::hint
Write two small helpers first, `ask_choice(prompt, options)` and `ask_int(prompt, low, high)`, and test each one alone. Then the menu loop is just `if`/`elif` on a choice you already know is valid.
:::

:::solution
```python run input="5|a|abc|30|a|300|90|s|q"
def ask_choice(prompt, options):
    while True:
        choice = input(prompt).strip().lower()
        if choice in options:
            return choice
        print("  Choose one of:", ", ".join(options))


def ask_int(prompt, low, high):
    while True:
        text = input(prompt).strip()
        try:
            number = int(text)
        except ValueError:
            print(f"  '{text}' is not a whole number.")
            continue
        if low <= number <= high:
            return number
        print(f"  Enter {low} to {high}.")


log = []
while True:
    print("[a]dd  [s]how  [q]uit")
    choice = ask_choice("> ", ["a", "s", "q"])
    if choice == "a":
        log.append(ask_int("Minutes studied (1-240): ", 1, 240))
    elif choice == "s":
        print(f"{len(log)} sessions, {sum(log)} minutes total")
    else:
        print("Bye!")
        break
```

The menu code never checks for bad input itself. Each helper promises to return only valid values, so the loop body can be short and trusting. That split, where input is checked at the door and logic assumes it's clean, is the same one you'll use in every project for the rest of the course.
:::
