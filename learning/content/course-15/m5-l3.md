## Warm-up

A smoke alarm was tested 20 times with smoke and 20 times without. With smoke it went off 19 times. Without smoke it went off 3 times. How many false positives and false negatives for **Smoke**?

:::solution
**3 false positives** (it went off with no smoke) and **1 false negative** (it stayed quiet once when there was smoke). Write the matrix if it helps: the Smoke row is 19 and 1, the No smoke row is 3 and 17.
:::

### Exercise 1: Count errors for one class

A smart doorbell sound detector has three classes. Here's its test on 60 one-second clips:

```text
                      said Background   said Doorbell   said Knock
Background Noise            18               2              0
Doorbell                     3              16              1
Knock                        1               0             19
```

How many false negatives and false positives does **Doorbell** have? What does each one mean for the person at the door?

Sample answer format: `Doorbell: ? false negatives, ? false positives`

:::hint
False negatives are the off-diagonal cells in the Doorbell **row**. False positives are the off-diagonal cells in the Doorbell **column**.
:::

:::solution
```python run
labels = ["Background Noise", "Doorbell", "Knock"]
m = [[18,  2,  0],
     [ 3, 16,  1],
     [ 1,  0, 19]]
d = labels.index("Doorbell")
fn = sum(m[d]) - m[d][d]
fp = sum(m[r][d] for r in range(3)) - m[d][d]
print(f"Doorbell: {fn} false negatives, {fp} false positives")
```

Four real rings were missed: three were heard as background noise and one as a knock. Those four visitors stand outside with no notification. The two false positives are background sounds that buzzed your phone for nothing, which is annoying but harmless.
:::

### Exercise 2: Which letters does the sign helper mix up?

A sign-language letter helper recognizes the fingerspelled letters A, S, and B, plus Nothing. It was tested on 10 unseen tries per class:

```python run alt="A 4-by-4 confusion matrix for A, S, B, and Nothing. Diagonal: A 7, S 8, B 10, Nothing 10. A is called S 3 times and S is called A 2 times; every other off-diagonal cell is 0." caption="Sign helper, 40 unseen tries"
import matplotlib.pyplot as plt
from matplotlib.colors import LinearSegmentedColormap

BLUES = LinearSegmentedColormap.from_list("blues", ["#f2f7fd", "#86b6ef", "#1c5cab", "#0d366b"])
labels = ["A", "S", "B", "Nothing"]
m = [[7, 3,  0,  0],
     [2, 8,  0,  0],
     [0, 0, 10,  0],
     [0, 0,  0, 10]]

fig, ax = plt.subplots(figsize=(4.8, 4.2))
ax.imshow(m, cmap=BLUES, vmin=0, vmax=10)
ax.set_xticks(range(4), labels)
ax.set_yticks(range(4), labels)
ax.set_xlabel("Prediction")
ax.set_ylabel("Class (truth)")
for r in range(4):
    for c in range(4):
        ax.text(c, r, m[r][c], ha="center", va="center", fontsize=12,
                color="white" if m[r][c] > 5 else "#1d1b22")
```

Name the confused pair, say which direction is worse, and suggest why these two letters in particular get confused.

:::hint
Look for errors that appear in *both* directions between the same two classes. Then think about how the two handshapes actually differ.
:::

:::solution
**A and S** are confused both ways: A called S three times, S called A twice. Confusion in both directions usually means the two classes look nearly the same to the model. Both letters are a closed fist; the difference is mostly where the thumb sits (alongside the fist for A, across the front of the fingers for S). That's a small detail in a webcam frame. A targeted fix: record new A and S samples close to the camera with the thumb clearly visible, from a few angles, in both classes. B and Nothing are perfect, so leave them alone.
:::

### Exercise 3: Match the symptom to the cause

For each symptom, pick the most likely data gap and a targeted fix.

1. A posture reminder (a pose project with **Upright** and **Slouching**) calls you Upright whenever you sit on the left side of the camera view, even while slouching.
2. The doorbell detector misses rings, but only while the dishwasher is running.
3. A recycling sorter calls every crumpled item Trash, including crumpled clean paper.

:::hint
For each one, ask: what condition is present in the failing tests that was missing from the training samples of the class that lost?
:::

:::solution
1. **Position in the frame.** Teachable Machine's pose model tracks where your body is in the frame, not only its shape, so the FAQ warns that standing on the left looks like a different pose from standing on the right. Training was probably all centered. Fix: record both Upright and Slouching at left, center, and right positions.
2. **Missing background condition.** No Doorbell samples were recorded with the dishwasher running, so the dishwasher sound drowns out what the model learned. Fix: record new Doorbell clips with the dishwasher on, and add dishwasher noise to Background Noise too, so the model learns that dishwasher alone means "nothing".
3. **Recycling had only flat paper.** The model learned "crumpled means trash". Fix: add crumpled clean paper to Recycling, and keep the class sizes even.
:::

### Exercise 4: Which error would you reduce?

For each app, say which error type you'd reduce first, and what you'd accept in exchange.

1. A game where a pose triggers "jump".
2. A helper that warns a cyclist when it hears a car horn behind them.
3. A sorter that sends anything it isn't sure about to a human checker.

:::hint
Picture each mistake happening for real. Which one makes the person stop trusting the app, or puts them at risk?
:::

:::solution
1. **False positives.** A character jumping when you didn't ask feels broken. You'd accept a few missed jumps, which players read as "I didn't do it right".
2. **False negatives.** Missing a real horn could hurt someone. You'd accept extra false alarms, as long as they aren't so frequent that the cyclist starts ignoring them.
3. Here the human checker changes the trade-off: an "unsure" item costs a few seconds of someone's time. You'd reduce **wrong confident answers** in both directions and accept more items going to the checker.
:::

### Exercise 5: Did the fix really help?

A school's recycling sorter was retrained after someone added more Recycling examples. The plant that takes the recycling says trash in the recycling (a false positive for Recycling) is the costly error. Same 100 test items both times:

```text
before                 said Recycling   said Trash
Recycling                   44              6
Trash                        3             47

after                  said Recycling   said Trash
Recycling                   49              1
Trash                        5             45
```

Compute accuracy and Recycling's false positives for both versions. Is the new version better *for this plant*?

:::hint
Accuracy is the diagonal over the total. The false positives for Recycling are in the Trash row, Recycling column.
:::

:::solution
```python run
versions = {
    "before": [[44, 6], [3, 47]],
    "after":  [[49, 1], [5, 45]],
}
for name, m in versions.items():
    accuracy = (m[0][0] + m[1][1]) / 100
    fp = m[1][0]   # really Trash, said Recycling
    fn = m[0][1]   # really Recycling, said Trash
    print(f"{name:6}  accuracy {accuracy:.0%}   false positives {fp}   false negatives {fn}")
```

Accuracy went up from 91% to 94%, but false positives went **up** from 3 to 5. Adding Recycling examples made the model more eager to say Recycling, which fixed misses and created more of the costly mistake. For this plant it's not a clear improvement. A better next step is a targeted look at the five trash items that got through: what do they share?
:::

### Exercise 6: Catch the cheating retest

A classmate's log says:

```text
v1 scored 31/40 on my unseen test.
I put the 9 photos it got wrong into their correct classes and retrained.
v2 scored 40/40 on the same 40 photos. Fixed!
```

What's wrong with this conclusion, and how could they get a fair answer now?

:::hint
What has v2 seen that v1 hadn't, and is the test still "unseen" for v2?
:::

:::solution
The 9 hardest test photos are now training data, so v2 has studied the answers. A perfect score on photos it trained on says nothing about new photos. The fix: take a **new** set of 40 unseen photos (different from both training and the old test), run **both** v1 and v2 on it, and compare those results. The 9 photos can stay in training, but the old test set can't be used as a test for v2 any more.
:::

### Challenge: A full repair round on your own model

Run one complete repair round on your rock, paper, scissors model or any other Teachable Machine model you've built: unseen test sheet with notes, matrix, one hypothesis written as a sentence, one data change, retrain, retest on the same items, and a log entry. Use this template to draw your before and after matrices and list every cell that moved. Change the labels and counts to yours.

```python run alt="Two confusion matrices side by side for a three-class example, before and after a data change. The Cat row, Dog column drops from 4 to 1." caption="Template: replace the labels and counts with your own"
import matplotlib.pyplot as plt
from matplotlib.colors import LinearSegmentedColormap

BLUES = LinearSegmentedColormap.from_list("blues", ["#f2f7fd", "#86b6ef", "#1c5cab", "#0d366b"])
labels = ["Cat", "Dog", "Nothing"]
before = [[6, 4, 0],
          [1, 9, 0],
          [0, 0, 10]]
after = [[9, 1, 0],
         [1, 9, 0],
         [0, 0, 10]]

fig, axes = plt.subplots(1, 2, figsize=(9, 3.9))
for ax, m, title in [(axes[0], before, "before"), (axes[1], after, "after")]:
    top = max(max(row) for row in m)
    ax.imshow(m, cmap=BLUES, vmin=0, vmax=top)
    ax.set_xticks(range(len(labels)), labels)
    ax.set_yticks(range(len(labels)), labels)
    ax.set_xlabel("Prediction")
    ax.set_ylabel("Class (truth)")
    ax.set_title(title)
    for r, row in enumerate(m):
        for c, n in enumerate(row):
            ax.text(c, r, n, ha="center", va="center", fontsize=12,
                    color="white" if n > top * 0.55 else "#1d1b22")
fig.tight_layout()

for r, truth in enumerate(labels):
    for c, said in enumerate(labels):
        if r != c and before[r][c] != after[r][c]:
            print(f"{truth} called {said}: {before[r][c]} → {after[r][c]}")
```

Your log entry should end with a decision (keep or roll back) and one sentence on the trade-off you accepted.
