## Warm-up

A dataset has 50 Cat, 50 Dog, and 250 Rabbit samples. What accuracy does a model get if it answers Rabbit for everything?

:::solution
250 out of 350 samples are Rabbit, so it scores 250 ÷ 350 ≈ **71%** without looking at a single picture. Any accuracy you see for this dataset should be compared with 71%, not with 0%.
:::

### Exercise 1: The baseline for three datasets

For each dataset, calculate the "always pick the biggest class" accuracy, and say which dataset's 90% accuracy would impress you most.

| Dataset | Counts |
| --- | --- |
| A | Rock 100, Paper 100, Scissors 100 |
| B | Recycling 40, Trash 360 |
| C | Clap 30, Snap 30, Whistle 30, Background Noise 210 |

:::hint
Divide the biggest class by the total. A 90% model is only impressive when 90% is far above that baseline.
:::

:::solution
```python run
datasets = {
    "A": {"Rock": 100, "Paper": 100, "Scissors": 100},
    "B": {"Recycling": 40, "Trash": 360},
    "C": {"Clap": 30, "Snap": 30, "Whistle": 30, "Background Noise": 210},
}
for name, counts in datasets.items():
    biggest = max(counts, key=counts.get)
    baseline = counts[biggest] / sum(counts.values())
    print(f"{name}: always '{biggest}' scores {baseline:.0%}")
```

A 90% model on **A** is far above its 33% baseline, so it's genuinely learning. On **B** it is no better than always saying Trash, which also scores 90%. On **C** it beats the 70% baseline, but much of its score may come from Background Noise. Dataset A's 90% is the most impressive.
:::

### Exercise 2: Count the adjustments

You have 200 training samples. How many batches are in one epoch, and how many adjustments does training make in total, for each of these settings?

1. Batch Size 16, Epochs 50
2. Batch Size 32, Epochs 50
3. Batch Size 16, Epochs 10

:::hint
Batches per epoch is samples ÷ batch size, rounded **up**, because a leftover partial batch still counts. Total adjustments is batches per epoch × epochs.
:::

:::solution
1. 200 ÷ 16 = 12.5, so **13** batches per epoch (12 full, one of 8) and 13 × 50 = **650** adjustments.
2. 200 ÷ 32 = 6.25, so **7** batches per epoch and **350** adjustments.
3. **13** batches per epoch and 13 × 10 = **130** adjustments.

Bigger batches mean fewer, smoother adjustments per epoch. That's why Teachable Machine's tooltip says you probably won't need to change batch size: epochs have a much bigger effect.
:::

### Exercise 3: Diagnose three training runs

The graphs below show test accuracy and test loss for three made-up training runs. Label each run as underfitting, a healthy fit, or overfitting, and give the clue.

```python run alt="Two line charts of three training runs over 50 epochs. Run A's test accuracy creeps up to only about 0.5 and its loss barely falls. Run B's test accuracy rises to about 0.93 and its loss falls and stays low. Run C's test accuracy rises to 0.9 then sags, and its loss falls until epoch 15 then climbs." caption="Test accuracy and test loss for three made-up runs."
import numpy as np
import matplotlib.pyplot as plt

e = np.arange(1, 51)
runs = {
    "Run A": (0.25 + 0.27 * (1 - np.exp(-e / 25)), 1.4 - 0.35 * (1 - np.exp(-e / 25))),
    "Run B": (0.93 - 0.6 * np.exp(-e / 5), 0.2 + 1.1 * np.exp(-e / 6)),
    "Run C": (0.9 - 0.6 * np.exp(-e / 4) - 0.003 * np.clip(e - 15, 0, None),
              0.25 + 1.1 * np.exp(-e / 5) + 0.02 * np.clip(e - 15, 0, None)),
}
fig, (left, right) = plt.subplots(1, 2, figsize=(9, 3.4))
for name, (test_acc, test_loss) in runs.items():
    left.plot(e, test_acc, label=name)
    right.plot(e, test_loss, label=name)
left.set_title("test acc")
left.set_ylim(0, 1)
right.set_title("test loss")
for ax in (left, right):
    ax.set_xlabel("Epochs")
    ax.legend()
plt.tight_layout()
```

:::hint
Underfitting: never gets good. Overfitting: gets good, then gets worse on the test samples. Healthy: gets good and stays there.
:::

:::solution
- **Run A: underfitting.** Test accuracy never climbs past about 0.5 and loss barely falls. The model hasn't found the difference between classes. Check for classes that look alike, too few samples, or a learning rate that was made tiny.
- **Run B: healthy.** Fast rise, then flat; loss falls and stays low.
- **Run C: overfitting.** Test loss bottoms out around epoch 15, then climbs, and test accuracy sags slightly. The model is fitting details of the training samples that don't carry over. More varied data helps more than fewer epochs, but for this run 15 to 20 epochs would also have done better than 50.
:::

### Exercise 4: Too few and too many epochs

In `rock-paper-scissors-v2`, open **Advanced** and **Under the hood**. Train three times, with **Epochs** set to **3**, then **50**, then **300**. Each time, note the final `test acc`, the shape of the curves, and how confident the preview is on a far-away Scissors.

:::hint
Most of the learning in the curves you've seen happens in the first 10 to 15 epochs. What does stopping at 3 cut off? What can 250 extra epochs add?
:::

:::solution
Expected results (your numbers will vary):

- **3 epochs:** the curves are three points that stop while still rising steeply. Test accuracy is often a few points lower, and the preview bars are less decisive: the winning class might show 60% to 80% where it showed 95%.
- **50 epochs:** curves rise and flatten, as in the build.
- **300 epochs:** training takes several times longer. Training loss keeps inching toward zero, test accuracy barely changes, and test loss may start drifting up. The preview looks about the same as 50, perhaps a little more extreme in its percentages.

Conclusion: past the point where the curves flatten, extra epochs cost time and invite overfitting without improving the model. Click **Reset Defaults** when you're done.
:::

### Exercise 5: Learning rate too big and too small

Train v2 twice more: once with **Learning Rate** set to **0.1** (100 times the default), and once with **0.00001** (100 times smaller). Keep the graphs open.

:::hint
The learning rate is the size of each adjustment. Picture walking downhill in fog with giant leaps versus tiny shuffles.
:::

:::solution
- **0.1:** the curves are jagged. Accuracy jumps up and down between epochs, and loss may spike instead of falling smoothly. The preview can be erratic, flipping between classes or showing 100% for the wrong one. Each step is so large it overshoots good settings.
- **0.00001:** the curves crawl. After 50 epochs test accuracy may still be well below the default run, and the preview's top bar is often split, like 55% and 40%. The model hasn't moved far enough.

This is why the tooltip says *"Be careful tweaking this number!"* Click **Reset Defaults** afterward.
:::

### Exercise 6: Choose how to rebalance

A classmate's counts are Rock 150, Paper 60, Scissors 90, Nothing 100. They want balance and have time for one more 15-minute recording session. Write a plan, and explain what goes wrong if they simply delete samples until every class has 60.

:::hint
Deleting is quick, but what does it throw away? And which classes most need *new* conditions, not just more of the same?
:::

:::solution
Deleting down to 60 each throws away 160 samples, and with them much of the variety in Rock, Scissors, and Nothing. Each class would also keep only 9 test samples (15% of 60, rounded up), so the per-class accuracy becomes jumpy.

A better plan for one session: record about 40 new **Paper** and 10 new **Scissors** samples in conditions they're missing (check their thumbnails for which lights, distances, and hands are thin). Then delete about 50 of the most repetitive **Rock** frames, which are usually long runs of near-identical thumbnails. Result: roughly 100 per class, with more variety than before.
:::

### Challenge: When a lean is on purpose

In a game, a wrong move is worse than no move. A classmate suggests giving **Nothing** three times as many samples as each sign, so the model "plays it safe." Train a copy of v2 that way (record about 200 extra Nothing samples), test it, and decide whether you agree.

:::hint
Test half-formed gestures and far-away signs. Then ask whether a cleaner way exists to get "don't act unless sure" without changing the data.
:::

:::solution
Expected result: close calls now go to **Nothing**. Clear, close-up signs still work, but far-away and slightly sloppy signs are often ignored. So the classmate gets what they wanted: fewer wrong moves, and more missed moves.

The catch is that you can't control how far it leans; it's set by the counts. A cleaner method is to keep the data balanced and let the *game* decide: act only when the top class's confidence is above a threshold, such as 80%. You'll see confidence properly in Module 4 and use thresholds in a game later in the course. Delete the copy; keep v2.
:::
