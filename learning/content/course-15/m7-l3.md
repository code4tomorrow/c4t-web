## Warm-up

A jump game gets these top labels, one per frame: `Stand Jump Jump Stand Jump Jump Jump Stand Stand Jump`. A naive game jumps every time the label *changes to* Jump. How many jumps? How many would you guess the player actually made?

:::solution

### Exercise 1: Fix the app that crashed after a cleanup

A wave-to-open app worked fine with the classes `Nothing`, `Old test`, `Wave`. Then its maker deleted the leftover `Old test` class, retrained, and updated the cloud model. Now it crashes:

```javascript run raises
// The new model has only two classes
const prediction = [
  { className: "Nothing", probability: 0.07 },
  { className: "Wave", probability: 0.93 },
];
if (prediction[2].probability > 0.9) {
  console.log("Opening the door");
}
```

Explain the error and rewrite the check so it can't happen again, no matter how the classes are ordered.

:::hint
`prediction[2]` meant "the third class". How many classes are there now? Look for a way to find an entry by its `className`.
:::

:::solution
`Wave` used to be the third entry (index 2). With `Old test` deleted, there are only two entries, so `prediction[2]` is `undefined`, and reading `.probability` from `undefined` throws. Worse things can happen without a crash: if the classes were reordered, index 2 could silently become a different class. Look classes up by name:

```javascript run
const prediction = [
  { className: "Nothing", probability: 0.07 },
  { className: "Wave", probability: 0.93 },
];
const wave = prediction.find(p => p.className === "Wave");
if (wave && wave.probability > 0.9) {
  console.log(`Opening the door (Wave ${wave.probability})`);
}
```

The `wave &&` part also guards against a renamed class: if no class is called `Wave`, the app does nothing instead of crashing.
:::

### Exercise 2: One ring, one notification

An audio model listens with `overlapFactor: 0.5`, so it scores the last second of sound every half second. One doorbell ring lasts about two seconds, so it shows up in several results in a row. Write `onResult(label, score, timeSec)` so that a ring notifies **once**: notify when `Doorbell` scores at least 0.9, then ignore Doorbell for 10 seconds. Test it on this log:

```text
time  label             score
0.0   Background Noise  0.98
0.5   Doorbell          0.93
1.0   Doorbell          0.97
1.5   Doorbell          0.95
2.0   Background Noise  0.91
9.0   Doorbell          0.88
14.0  Doorbell          0.96
14.5  Doorbell          0.94
```

Expected output: two notifications, at 0.5 s and 14.0 s.

:::hint
Keep one variable, `lastNotified`, starting far in the past (like `-Infinity`). Notify only if the score passes the threshold **and** at least 10 seconds have passed since `lastNotified`.
:::

:::solution
```javascript run
const THRESHOLD = 0.9, COOLDOWN_SEC = 10;
let lastNotified = -Infinity;

function onResult(label, score, timeSec) {
  if (label !== "Doorbell" || score < THRESHOLD) return;
  if (timeSec - lastNotified < COOLDOWN_SEC) return;
  lastNotified = timeSec;
  console.log(`${timeSec.toFixed(1)} s: Someone's at the door!`);
}

const log = [
  [0.0, "Background Noise", 0.98], [0.5, "Doorbell", 0.93], [1.0, "Doorbell", 0.97],
  [1.5, "Doorbell", 0.95], [2.0, "Background Noise", 0.91], [9.0, "Doorbell", 0.88],
  [14.0, "Doorbell", 0.96], [14.5, "Doorbell", 0.94],
];
for (const [time, label, score] of log) onResult(label, score, time);
```

The 1.0 s and 1.5 s results are the same ring, blocked by the cooldown. The 9.0 s result is blocked twice over: it's under the threshold *and* inside the cooldown. In the exported audio code, you'd call `onResult` inside `recognizer.listen`, using the top class from `result.scores` and `recognizer.wordLabels()`.
:::

### Exercise 3: A posture reminder that isn't a nag

A pose model reports `Upright` or `Slouching` once a second. Write `onPose(label, timeSec)` that reminds the user when `Slouching` has won for **10 seconds straight**, and then doesn't remind again until the user has sat up (any `Upright` result) and slouched for another 10 seconds. Test it on: slouch from 0 to 14 s, upright at 15 s, slouch from 16 to 30 s.

Expected output: reminders at 10 s and 26 s only.

:::hint
You need two pieces of memory: when the current slouch started (`slouchStart`, or `null` while upright), and whether you've already reminded during this slouch.
:::

:::solution
```javascript run
const SLOUCH_SEC = 10;
let slouchStart = null, reminded = false;

function onPose(label, timeSec) {
  if (label === "Upright") { slouchStart = null; reminded = false; return; }
  if (slouchStart === null) slouchStart = timeSec;
  if (!reminded && timeSec - slouchStart >= SLOUCH_SEC) {
    reminded = true;
    console.log(`${timeSec} s: Time to sit up and stretch.`);
  }
}

for (let t = 0; t <= 30; t++) {
  const label = t === 15 ? "Upright" : "Slouching";
  onPose(label, t);
}
```

`Upright` is the re-arm: it clears both the timer and the `reminded` flag. Notice that one upright second resets everything, which suits a posture app, since sitting up briefly is exactly what you wanted.
:::

### Exercise 4: Pick the threshold from a log

A family logged every time their doorbell detector's top class was `Doorbell` for a week, and marked whether the doorbell had really rung. Each dot is one event:

```python run alt="Strip chart of Doorbell confidence scores. Twelve real rings sit between 0.79 and 0.99, mostly above 0.9. Twelve other sounds sit between 0.58 and 0.88, mostly below 0.8. Dashed lines mark 0.8 and 0.9." caption="Real rings score higher, but the two groups overlap between about 0.79 and 0.88"
import matplotlib.pyplot as plt

rings = [0.97, 0.95, 0.93, 0.99, 0.88, 0.91, 0.96, 0.84, 0.98, 0.79, 0.94, 0.92]
other = [0.62, 0.71, 0.88, 0.66, 0.74, 0.58, 0.81, 0.69, 0.77, 0.64, 0.86, 0.72]

fig, ax = plt.subplots(figsize=(7.5, 2.6))
ax.scatter(rings, [1] * len(rings), s=70, color="#2a78d6", label="real ring")
ax.scatter(other, [0] * len(other), s=70, color="#eb6834", label="something else")
for x in (0.8, 0.9):
    ax.axvline(x, color="#5f5d66", linestyle="--", linewidth=1)
    ax.text(x + 0.004, 1.45, f"{x}", ha="left", color="#5f5d66")
ax.set_yticks([0, 1], ["something else", "real ring"])
ax.set_ylim(-0.6, 1.7)
ax.set_xlim(0.55, 1.0)
ax.set_xlabel("Doorbell confidence")
ax.spines[["top", "right", "left"]].set_visible(False)
```

The family can live with a few false alarms a week but wants **at most one missed ring**. Count the missed rings and false alarms for thresholds 0.7, 0.8, 0.85, and 0.9, and pick one.

:::hint
A missed ring is a real ring *below* the threshold. A false alarm is "something else" *at or above* it.
:::

:::solution
```python run
rings = [0.97, 0.95, 0.93, 0.99, 0.88, 0.91, 0.96, 0.84, 0.98, 0.79, 0.94, 0.92]
other = [0.62, 0.71, 0.88, 0.66, 0.74, 0.58, 0.81, 0.69, 0.77, 0.64, 0.86, 0.72]

for threshold in (0.7, 0.8, 0.85, 0.9):
    missed = sum(score < threshold for score in rings)
    false_alarms = sum(score >= threshold for score in other)
    print(f"threshold {threshold:.2f}: missed rings {missed}, false alarms {false_alarms}")
```

**0.8** is the highest threshold that keeps misses at one, with three false alarms a week. At 0.9 there are no false alarms, but three visitors would be left standing outside, which is the error this family cares about most. No threshold gets both to zero, because the groups overlap; only better data (Module 5) can pull them apart.
:::

### Exercise 5: Say "not sure" out loud

A sign-language helper shows the top label in big letters. When the model is unsure, that's misleading. Write `display(top)` that returns `"Not sure"` when the top confidence is below 0.7, and the label otherwise. Test it on the frames below.

```text
{ label: "A", confidence: 0.94 }
{ label: "S", confidence: 0.52 }
{ label: "B", confidence: 0.71 }
{ label: "Nothing", confidence: 0.99 }
```

:::hint
One `if` is enough. Decide whether exactly 0.7 counts as sure, and say which you chose.
:::

:::solution
```javascript run
function display(top) {
  return top.confidence < 0.7 ? "Not sure" : top.label;
}

const frames = [
  { label: "A", confidence: 0.94 },
  { label: "S", confidence: 0.52 },
  { label: "B", confidence: 0.71 },
  { label: "Nothing", confidence: 0.99 },
];
for (const top of frames) console.log(`${top.label} ${top.confidence} → ${display(top)}`);
```

Here 0.7 itself counts as sure. A visible "Not sure" is honest feedback: the signer can adjust their hand instead of trusting a wrong letter, which matters most in an app meant to help someone communicate.
:::

### Exercise 6: The letter helper

Build the logic for a fingerspelling helper with classes `A`, `B`, `C`, and `Nothing`, using this diagram:

```mermaid caption="Letter helper: type once per sign, space after a long pause"
stateDiagram-v2
    [*] --> Armed
    Armed --> Typed: letter held 1 s at 0.9+
    Typed --> Armed: Nothing held 0.5 s
    Armed --> Armed: Nothing held 2 s adds one space
```

Write `update(label, confidence, nowMs)` and a `text` variable. Rules: a letter held at 0.9 or more for 1000 ms is typed once; another letter can't be typed until `Nothing` has been held for 500 ms; `Nothing` held for 2000 ms adds one space (never two in a row, and never at the start). Test it with the stream below, which spells A, B, a pause, then A, with one flickering frame. Expected text: `AB A`.

```javascript
// Frames every 250 ms: [label, confidence]
const stream = [];
const hold = (label, frames, confidence = 0.95) => {
  for (let i = 0; i < frames; i++) stream.push([label, confidence]);
};
hold("A", 6); hold("Nothing", 3); hold("B", 2); hold("A", 1, 0.55);
hold("B", 6); hold("Nothing", 10); hold("A", 6);
```

:::hint
Reuse the `candidate` and `since` idea from the rock, paper, scissors game to measure how long the current label has been held. Then handle two cases: the label is `Nothing` (re-arm, maybe add a space), or it's a letter (type it if armed and held long enough).
:::

:::solution
```javascript run
const THRESHOLD = 0.9, LETTER_MS = 1000, REARM_MS = 500, SPACE_MS = 2000;
let candidate = "", since = 0, armed = true, text = "";

function update(label, confidence, nowMs) {
  if (confidence < THRESHOLD) { candidate = ""; return; }
  if (label !== candidate) { candidate = label; since = nowMs; }
  const held = nowMs - since;
  if (label === "Nothing") {
    if (held >= REARM_MS) armed = true;
    if (held >= SPACE_MS && text !== "" && !text.endsWith(" ")) text += " ";
  } else if (armed && held >= LETTER_MS) {
    text += label;
    armed = false;
  }
}

const stream = [];
const hold = (label, frames, confidence = 0.95) => {
  for (let i = 0; i < frames; i++) stream.push([label, confidence]);
};
hold("A", 6); hold("Nothing", 3); hold("B", 2); hold("A", 1, 0.55);
hold("B", 6); hold("Nothing", 10); hold("A", 6);

stream.forEach(([label, confidence], i) => update(label, confidence, i * 250));
console.log(`Typed: "${text}"`);
```

The unsure `A` at 0.55 resets the candidate, so `B` starts its one-second hold again at 3000 ms and is typed at 4000 ms instead of 3250 ms. That delay is the price of a rule that never types a letter it isn't sure of.
:::
