The plan from the last lesson tells you *what* to build. This lesson is the *how*, one milestone at a time, using a recycling helper screen as the running example. Swap in your own project at every step; the moves are the same.

| Milestone | Done when | Evidence in your log |
| --- | --- | --- |
| M2 Data | Every class recorded in every planned condition; v1 trained | `.tm` file for v1, sample counts per class |
| M3 Test | Unseen items recorded and run through v1 | Test sheet with notes, confusion matrix |
| M4 Repair | One change made, v2 retested on the same items | Hypothesis, change, before-and-after numbers |
| M5 Export | Link or files saved; model card written | `model-link.txt` or the zip, `MODEL_CARD.md` |
| M6 App | Rule passes the fake-data test and a play-test | Sketch file, play-test tally |

## M2: Data and model v1

Record exactly as in Module 2: short rounds, every class in every round, one condition changed per round. For the recycling helper that means a table, a plain background, and items moved through three positions and two lighting setups, with the **Nothing** class covering the empty table, your hands, and items being placed or removed.

Before training, check the counts. If one class is more than about 15% bigger than the others, trim it or record more of the small ones. Then train, run a quick smoke test in **Preview**, and save `recycling-helper-v1` with the date.

**Done when** the log has v1's counts per class and one line about what the smoke test showed.

## M3: The unseen test

Gather items you didn't use in training, at least 10 per class, and test them in a place or light you didn't train in. For image projects, photos in a `test-set` folder are easiest, because you can drop the exact same files into **Preview** again for v2. For audio, record your test sounds with your phone's voice recorder, and play the same recordings near the microphone when you test each version. For pose, write down the exact positions and clothing so you can repeat them.

Fill in the test sheet, with a notes column, and draw the matrix with the template from Module 5's practice lesson. For the example project, the biggest cell was **Compost called Trash: 4 of 10**, and the notes on all four said "not fruit": coffee grounds, a paper napkin, two tea bags.

**Done when** the log has the sheet, the matrix, and the biggest cell circled.

## M4: One repair round

Write the hypothesis as a sentence that could turn out wrong. For the example: *"Compost items that aren't fruit get called Trash because every Compost training sample was a fruit or vegetable peel."*

Then make **one** change that tests it. Here: record 30 new Compost samples of coffee grounds, napkins, and tea bags (check that your local compost actually accepts them), and remove 30 near-duplicate peel samples to keep the classes even. Retrain, rerun the same unseen test, and compare:

```python run alt="Grouped bar chart of correct answers out of 10 per class for v1 and v2. Recycling stays at 7, Trash stays at 9, Compost rises from 6 to 9, Nothing stays at 10." caption="One targeted change moved one class, and left the others alone"
import matplotlib.pyplot as plt

classes = ["Recycling", "Trash", "Compost", "Nothing"]
v1 = [7, 9, 6, 10]
v2 = [7, 9, 9, 10]

x = range(len(classes))
fig, ax = plt.subplots(figsize=(7, 3.4))
bars1 = ax.bar([i - 0.2 for i in x], v1, width=0.38, color="#2a78d6", label="v1")
bars2 = ax.bar([i + 0.2 for i in x], v2, width=0.38, color="#eb6834", label="v2")
ax.bar_label(bars1, padding=2)
ax.bar_label(bars2, padding=2)
ax.set_xticks(list(x), classes)
ax.set_ylabel("correct out of 10")
ax.set_ylim(0, 11.5)
ax.legend(loc="upper left", ncol=2, frameon=False)
ax.spines[["top", "right"]].set_visible(False)
print(f"Total: v1 {sum(v1)}/40, v2 {sum(v2)}/40")
```

This is the chart to put in your presentation. Compost jumped from 6 to 9 and nothing else moved, which is what a well-targeted change looks like. Recycling at 7 out of 10 is now the weakest class, and that's honest information for your model card, not a failure to hide. If you have time, it's your next repair round.

**Done when** the log has the hypothesis, the change, both sets of numbers, and a keep-or-roll-back decision.

## M5: Export and model card

Follow Module 6: run the pre-export check, choose upload or download, and write the model card with test numbers copied from your v2 sheet. Put the M4 chart's numbers in "How it was tested" and Recycling's weakness in "Known weak spots".

**Done when** the release folder has the link or files and a model card that passes the reader test.

## M6: The app, from a starter

This starter sketch works for any **image** or **sound** model. It uses the same `index.html` as the rock, paper, scissors game (p5.js and ml5.js version 1). You change only the top two sections: the settings and the actions table. The engine underneath applies a threshold, a hold time, a cooldown, and a re-arm on your idle class.

```javascript
// ===== Capstone starter: a Teachable Machine model drives an app =====

// 1. Settings: change these
const MODEL_URL = "https://teachablemachine.withgoogle.com/models/YOUR_ID/";
const MODEL_TYPE = "image";     // "image" or "sound"
const IDLE_LABEL = "Nothing";   // "Background Noise" for sound models
const THRESHOLD = 0.85;         // how sure the model must be
const HOLD_MS = 800;            // how long a label must stay on top
const COOLDOWN_MS = 3000;       // shortest time between two actions

// 2. Actions: one line per class that should do something.
//    The names must match your class names exactly, capitals included.
const ACTIONS = {
  Recycling: () => say("Blue bin: recycling", "#2a78d6"),
  Trash:     () => say("Black bin: trash", "#3a3a3a"),
  Compost:   () => say("Green bin: compost", "#008300"),
};

// 3. The engine: you shouldn't need to change anything below
let classifier, video;
let label = "", confidence = 0;
let candidate = "", since = 0, armed = true, lastAction = -Infinity;
let message = "Show me one item", messageColor = "#3a3a3a";

async function setup() {
  createCanvas(640, 600);
  if (MODEL_TYPE === "image") {
    classifier = await ml5.imageClassifier(MODEL_URL + "model.json");
    video = createCapture(VIDEO, { flipped: true });
    video.size(640, 480);
    video.hide();
    classifier.classifyStart(video, gotResult);
  } else {
    classifier = await ml5.soundClassifier(MODEL_URL);
    classifier.classifyStart(gotResult);
  }
}

function gotResult(results) {
  label = results[0].label;
  confidence = results[0].confidence;
}

function decide(label, confidence, now) {
  if (confidence < THRESHOLD) { candidate = ""; return null; }
  if (label !== candidate) { candidate = label; since = now; }
  if (now - since < HOLD_MS) return null;
  if (label === IDLE_LABEL) { armed = true; return null; }
  if (!armed || now - lastAction < COOLDOWN_MS || !(label in ACTIONS)) return null;
  armed = false;
  lastAction = now;
  return label;
}

function say(text, color) {
  message = text;
  messageColor = color;
}

function draw() {
  background(245);
  if (video) image(video, 0, 0);

  const action = decide(label, confidence, millis());
  if (action) {
    ACTIONS[action]();
    console.log(`${(millis() / 1000).toFixed(1)} s: ${action}`);
  }

  noStroke();
  fill(messageColor);
  rect(0, 480, width, 80);
  fill(255);
  textSize(30);
  textAlign(CENTER, CENTER);
  text(message, width / 2, 520);

  fill(60);
  textSize(16);
  textAlign(LEFT, CENTER);
  const shown = confidence < THRESHOLD ? "not sure" : label;
  text(`Model: ${label} ${confidence.toFixed(2)} (${shown})   ready: ${armed}`, 12, 585);
}
```

When it runs with an image model, you see the webcam with a colored message bar under it. Hold up a can, keep it still for a moment, and the bar turns blue with "Blue bin: recycling". The small line at the bottom shows what the model sees, which is invaluable while testing. Take the can away, and once **Nothing** has been on top for 0.8 seconds, `ready` flips back to `true` for the next item. The editor's console logs every action with a time, which is your play-test record.

### Test the engine before the camera

Here is the same `decide` function fed a scripted sequence: an empty table, a can held up, the can removed, a wobbly start with a banana peel, then the peel held steady. Predict how many actions fire, and when.

```javascript run
const IDLE_LABEL = "Nothing", THRESHOLD = 0.85, HOLD_MS = 800, COOLDOWN_MS = 3000;
const ACTIONS = { Recycling: 1, Trash: 1, Compost: 1 };
let candidate = "", since = 0, armed = true, lastAction = -Infinity;

function decide(label, confidence, now) {
  if (confidence < THRESHOLD) { candidate = ""; return null; }
  if (label !== candidate) { candidate = label; since = now; }
  if (now - since < HOLD_MS) return null;
  if (label === IDLE_LABEL) { armed = true; return null; }
  if (!armed || now - lastAction < COOLDOWN_MS || !(label in ACTIONS)) return null;
  armed = false;
  lastAction = now;
  return label;
}

// Frames every 200 ms
const stream = [];
const hold = (label, ms, confidence = 0.95) => {
  for (let t = 0; t < ms; t += 200) stream.push([label, confidence]);
};
hold("Nothing", 1000); hold("Recycling", 2000); hold("Nothing", 1000);
hold("Compost", 400, 0.6); hold("Compost", 1600);

stream.forEach(([label, confidence], i) => {
  const action = decide(label, confidence, i * 200);
  if (action) console.log(`${(i * 0.2).toFixed(1)} s: ${action}`);
});
console.log(`${stream.length} frames, ready at the end: ${armed}`);
```

Two actions: Recycling about 0.8 seconds after the can appears, and Compost once the peel has been steady for 0.8 seconds *and* 3 seconds have passed since the last action. The can staying up for two full seconds fires only once, because the engine isn't re-armed until Nothing returns. If you change `COOLDOWN_MS` to 6000 and rerun it in your head, the Compost action disappears; that's the kind of setting your play-test should decide.

### Pose projects

ml5.js doesn't load Teachable Machine pose models, so pose projects start from the **Javascript** snippet in the export window instead. Paste the whole snippet into `index.html` of a new p5.js Web Editor sketch, replacing everything, and add `<div id="message"></div>` under the Start button. Then, just above `async function init()`, paste four things from the starter: the settings, your own `ACTIONS` table, the `let candidate = ...` line, and the `decide` function. Finally, replace the snippet's `predict` function with this one:

```javascript
async function predict() {
    const { pose, posenetOutput } = await model.estimatePose(webcam.canvas);
    const prediction = await model.predict(posenetOutput);

    let top = prediction[0];
    for (const p of prediction) {
        if (p.probability > top.probability) top = p;
    }
    const action = decide(top.className, top.probability, performance.now());
    if (action) ACTIONS[action]();

    labelContainer.innerHTML = top.className + " " + top.probability.toFixed(2);
    drawPose(pose);
}
```

For a posture reminder, set `IDLE_LABEL = "Upright"`, `HOLD_MS = 10000`, and an action such as `Slouching: () => { document.getElementById("message").textContent = "Time to sit up and stretch"; }`. A ten-second hold makes the reminder wait for a real slouch, and **Upright** re-arms it.

## When something goes wrong

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| The bottom line shows the right label, but no action ever fires | A name in `ACTIONS` doesn't match the class name exactly (`recycling` vs `Recycling`) | Copy the class names from the bottom line into `ACTIONS` |
| It always says "not sure" | The threshold is higher than your model's usual confidence | Watch the numbers for a minute, then set `THRESHOLD` just below the typical score for a clear example |
| The first action works, then nothing ever fires again | `IDLE_LABEL` doesn't match your idle class exactly, so the engine never re-arms | Check `IDLE_LABEL` against the bottom line with nothing in view |
| Actions fire while an item is only passing through the frame | The hold time is too short | Raise `HOLD_MS` in steps of 200 and play-test again |
| Left and right are swapped | The camera isn't mirrored like the training webcam | Keep `{ flipped: true }` (or `flip = true` in the pose snippet) |
| Nothing loads at all | A typo in `MODEL_URL`, or the link is missing its final `/` | Open the link in a browser tab; it should show the model's page |

**Done when** the fake-data test behaves as you predicted, and a play-test of 10 tries per class is tallied in your log: wrong actions (false positives) and missed actions (false negatives).
