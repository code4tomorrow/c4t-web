## Warm-up: how many values are missing?

Predict both numbers before you run this. Which of the four odd-looking entries does pandas treat as missing on its own?

```python run
sheet = """name,club,hours
Ana,chess,3
Ben,,N/A
Cy,-,2
Di,art,
"""
print(pd.read_csv(io.StringIO(sheet)).isna().sum().sum())
print(pd.read_csv(io.StringIO(sheet), na_values=["-"]).isna().sum().sum())
```

The empty cells and `N/A` are on pandas' built-in list of missing markers, so the first count is 3. A lone `-` isn't on that list, so it only counts once you name it in `na_values`.

### Exercise 1: Attendance with gaps

A club logs how many sessions each member attended per week. Blank, `-`, and `n/a` all mean "not recorded", but `0` means the member was recorded as attending nothing. Load the sheet so that only the unrecorded entries are missing, then print each week's mean **and** how many members that mean is based on.

```python run
attendance = """student,week1,week2,week3
Ana,5,n/a,4
Ben,-,3,3
Cy,4,4,
Dee,0,2,5
"""
```

```text
       mean  members
week1   3.0        3
week2   3.0        3
week3   4.0        3
```

:::hint
Pass `na_values=["-", "n/a"]` to `read_csv`. On the three week columns, `.mean()` and `.count()` each give one number per week; put them side by side in a new DataFrame.
:::

:::solution
```python run
att = pd.read_csv(io.StringIO(attendance), na_values=["-", "n/a"])
weeks = att[["week1", "week2", "week3"]]
summary = pd.DataFrame({"mean": weeks.mean(), "members": weeks.count()})
print(summary)
```

Each mean uses only 3 of the 4 members, because `mean` skips `NaN`. Dee's `0` stays in, which is correct: it's a real record of zero sessions. If you'd filled the gaps with 0, every week's mean would drop and Ana, Ben, and Cy would be marked absent when nobody knows.
:::

### Exercise 2: People who signed up twice

Students order club T-shirts through a form, and some submitted twice. Keep only each person's **latest** submission. Watch out: the same email can appear with different capitals or a trailing space.

```python run
signups = pd.DataFrame({
    "email": ["ana@school.org", "Ben@School.org", "ana@school.org ", "cy@school.org",
              "ben@school.org", "dee@school.org"],
    "shirt": ["M", "L", "S", "M", "XL", "S"],
    "submitted": ["2026-09-01 08:10", "2026-09-01 09:00", "2026-09-02 17:45",
                  "2026-09-02 10:00", "2026-09-03 12:30", "2026-09-03 13:00"],
})
```

```text
            email shirt           submitted
2  ana@school.org     S 2026-09-02 17:45:00
4  ben@school.org    XL 2026-09-03 12:30:00
...
```

:::hint
Count duplicates on the raw `email` column first; you'll get 0. Clean the key with `.str.strip().str.lower()`, convert `submitted` with `pd.to_datetime`, sort by time, then `drop_duplicates(subset="email", keep="last")`.
:::

:::solution
```python run
print("Duplicates before cleaning the key:", signups.duplicated(subset="email").sum())

orders = signups.copy()
orders["email"] = orders["email"].str.strip().str.lower()
orders["submitted"] = pd.to_datetime(orders["submitted"])
print("Duplicates after:", orders.duplicated(subset="email").sum())

latest = (orders.sort_values("submitted")
                .drop_duplicates(subset="email", keep="last")
                .sort_values("email"))
print(latest)
```

On the raw column, `drop_duplicates` finds nothing, because `Ben@School.org` and `ben@school.org` are different strings. **Normalize the key, then deduplicate.** Ana changed her size from M to S and Ben from L to XL, and the latest orders are the ones to send to the printer.
:::

### Exercise 3: Prices stored as text

Convert the `price` column into a numeric `price_usd` column. `TBD` should become missing. Then print the mean price and how many bikes it's based on.

```python run
bikes = pd.DataFrame({
    "bike": ["Road", "Mountain", "Kids", "Hybrid", "Cargo"],
    "price": ["$1,200", "$950", "189.99", "TBD", "$2,450.50"],
})
```

```text
Mean price: $1,197.62 from 4 bikes
```

:::hint
Remove `$` and `,` with `.str.replace(..., "", regex=False)`, then `pd.to_numeric(..., errors="coerce")`. `regex=False` matters for `$`, which has a special meaning in patterns.
:::

:::solution
```python run
cleaned_text = (bikes["price"].str.replace("$", "", regex=False)
                              .str.replace(",", "", regex=False))
bikes["price_usd"] = pd.to_numeric(cleaned_text, errors="coerce")
print(bikes)
print(f"Mean price: ${bikes['price_usd'].mean():,.2f} from {bikes['price_usd'].count()} bikes")
```

The thousands comma has to go too: `pd.to_numeric("1,200")` fails, because Python never uses commas inside numbers. The `:,.2f` format puts commas back for display only.
:::

### Exercise 4: Fifteen ways to write four sizes

Map these shirt sizes to exactly `S`, `M`, `L`, `XL`. Print any values your mapping misses, then chart the counts **in size order**, not alphabetical order.

```python run
sizes = pd.Series(["S", "small", "M ", "medium", "L", "large", "M", "XL",
                   "x-large", "Sm", "m", "L", "XXL", "med", "l"])
```

:::hint
Normalize with `.str.strip().str.lower()` first, so your dictionary only needs lowercase keys. After `value_counts()`, `.reindex(["S", "M", "L", "XL"])` puts the bars in the order you choose.
:::

:::solution
```python run alt="Bar chart of shirt sizes in order: S 3, M 5, L 4, XL 2"
size_map = {"s": "S", "small": "S", "sm": "S",
            "m": "M", "medium": "M", "med": "M",
            "l": "L", "large": "L",
            "xl": "XL", "x-large": "XL"}
size = sizes.str.strip().str.lower().map(size_map)
print("Unmapped:", sizes[size.isna()].tolist())

counts = size.value_counts().reindex(["S", "M", "L", "XL"])
ax = counts.plot(kind="bar", color="#2a78d6", rot=0, figsize=(5, 3))
ax.set_ylabel("Shirts")
ax.set_title("Shirt orders by size (1 unmapped: XXL)")
```

`XXL` isn't a typo for another size; it's a size the form didn't offer. The unmapped list catches it, and someone needs to decide whether to order it. Never let a mapping silently drop a value.
:::

### Exercise 5: Suspicious reaction times

A reaction-time game recorded 45 tries in milliseconds. Use the 1.5 × IQR rule to flag outliers. Then apply two stated rules: under 100 ms is **impossible** for a human reacting to a signal (the player pressed early), and over 2,000 ms is **not a reaction** (they looked away). Print the mean and median before and after.

```python run
rng = np.random.default_rng(4)
times = pd.Series(np.concatenate([rng.normal(290, 45, 40).round(), [0, 12, 4800, 5200, 610]]), name="ms")
```

```text
IQR rule flags: [0.0, 12.0, 4800.0, 5200.0, 610.0]
All tries:    mean 489.1, median 290.0
Kept tries:   mean 292.7, median 290.0 (41 of 45)
```

:::hint
`times.quantile([0.25, 0.75])` gives Q1 and Q3. For the stated rules, one mask does it: `(times >= 100) & (times <= 2000)`.
:::

:::solution
```python run
q1, q3 = times.quantile([0.25, 0.75])
fence = 1.5 * (q3 - q1)
flagged = times[(times < q1 - fence) | (times > q3 + fence)]
print("IQR rule flags:", flagged.tolist())

kept = times[(times >= 100) & (times <= 2000)]
print(f"All tries:    mean {times.mean():.1f}, median {times.median():.1f}")
print(f"Kept tries:   mean {kept.mean():.1f}, median {kept.median():.1f} ({len(kept)} of {len(times)})")
```

The IQR rule flags five tries, including 610 ms, which is slow but completely possible. That's why a statistical rule should only *flag* values. The stated rules remove four tries for reasons you can explain, and keep the 610. Notice the median doesn't move at all, while the mean drops by almost 200 ms. When you can't defend removing extreme values, the median is the safer summary.
:::

### Exercise 6: A gradebook that's too wide

Reshape the gradebook so each row is one student's score on one quiz. Then print the average score per quiz and per student, and plot each student's scores across the three quizzes.

```python run
grades = pd.DataFrame({"student": ["Ana", "Ben", "Cy", "Dee"],
                       "quiz1": [8, 6, 9, 7], "quiz2": [9, 5, 7, 8], "quiz3": [10, 7, 6, 9]})
```

```mermaid caption="melt turns quiz columns into rows: 4 students x 3 quizzes = 12 rows"
flowchart LR
    W["Wide: student | quiz1 | quiz2 | quiz3"] -->|"melt(id_vars='student')"| L["Long: student | quiz | score"]
    L --> G1["groupby('quiz')"]
    L --> G2["groupby('student')"]
```

:::hint
`grades.melt(id_vars="student", var_name="quiz", value_name="score")`. For the chart, `long.pivot(index="quiz", columns="student", values="score")` gives one column per student, which `plot()` draws as one line each.
:::

:::solution
```python run alt="Line chart of four students' scores across quizzes 1 to 3. Ana rises from 8 to 10, Dee from 7 to 9, Ben dips to 5 then recovers to 7, and Cy falls from 9 to 6."
long = grades.melt(id_vars="student", var_name="quiz", value_name="score")
print(long.shape)
print(long.groupby("quiz")["score"].mean())
print(long.groupby("student")["score"].mean().round(2))

colors = {"Ana": "#2a78d6", "Ben": "#eb6834", "Cy": "#1baf7a", "Dee": "#6250d6"}
ax = long.pivot(index="quiz", columns="student", values="score").plot(
    marker="o", color=colors, linewidth=2, figsize=(5.5, 3.2))
ax.set_ylabel("Score (out of 10)")
ax.set_xlabel("")
ax.legend(frameon=False, ncols=4, loc="lower center")
```

In the long table, "quiz" is a real column, so one `groupby` answers each question, with no code that names `quiz1`, `quiz2`, `quiz3` one by one. Add a `quiz4` column to `grades` and every line above still works unchanged.
:::

### Challenge: Clean an animal-shelter log

Write `clean_shelter(raw)` that returns a clean DataFrame with columns `animal_id`, `species`, `age_years`, `days_in_shelter`, and `adopted` (a real `bool`). Ages like `6 months` become `0.5`; `?` is missing; a negative stay is impossible; repeated rows go. Then compare the average stay by species before and after cleaning.

```python run
shelter_csv = """animal_id,species,age,days_in_shelter,adopted
A01,Dog,2,14,yes
A02,cat,6 months,30,Y
A03,DOG,5,-3,no
A04,Cat,?,45,yes
A05,dog ,1,9,YES
A06,Cat,3,400,no
A07,Rabbit,1,21,yes
A08,cat,10,60,N
A03,DOG,5,-3,no
A09,Dog,8 months,7,yes
A10,dog,4,,no
"""
```

:::hint
Work column by column. For ages, mark which entries end in `months`, strip the word, convert to numbers, and divide those by 12. For `adopted`, normalize case and map `{"yes": True, "y": True, "no": False, "n": False}`. Keep 400 days: a long stay is unusual, not impossible.
:::

:::solution
```python run
def clean_shelter(raw):
    df = raw.drop_duplicates().copy()
    df["species"] = df["species"].str.strip().str.title()

    age_text = df["age"].astype(str).str.strip()
    in_months = age_text.str.endswith("months")
    age_number = pd.to_numeric(age_text.str.removesuffix("months").str.strip(), errors="coerce")
    df["age_years"] = np.where(in_months, age_number / 12, age_number).round(2)

    df["days_in_shelter"] = pd.to_numeric(df["days_in_shelter"], errors="coerce")
    df.loc[df["days_in_shelter"] < 0, "days_in_shelter"] = np.nan

    answers = {"yes": True, "y": True, "no": False, "n": False}
    df["adopted"] = df["adopted"].str.strip().str.lower().map(answers).astype(bool)
    return df[["animal_id", "species", "age_years", "days_in_shelter", "adopted"]]


raw = pd.read_csv(io.StringIO(shelter_csv))
clean = clean_shelter(raw)
print(clean)

before = raw.groupby("species")["days_in_shelter"].mean().round(1)
after = clean.groupby("species")["days_in_shelter"].agg(["mean", "count"]).round(1)
print(before)
print(after)
```

Before cleaning, dogs are split across `Dog`, `DOG`, `dog ` and `dog`, and the `DOG` group's average is −3 days, the impossible stay counted twice. After cleaning there are three species, and the `count` column shows each average's real basis. Cats average a long stay because of one 400-day resident. That's a real animal, and the right response is to report the median too, not to delete the cat. (The `.astype(bool)` at the end is safe here only because every answer mapped; check for unmapped values before forcing a type.)
:::
