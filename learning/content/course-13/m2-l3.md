## Warm-up: predict the dtypes

Before running anything, write down the dtype you expect for each of the four columns. One of them will probably surprise you.

```python run
shop = """item,price,in_stock,aisle
Milk,1.99,True,4
Bread,2.49,False,7
Eggs,3.10,True,
Apples,0.89,True,2
"""
print(pd.read_csv(io.StringIO(shop)).dtypes)
```

`aisle` holds whole numbers, but it's `float64`. Eggs has no aisle, the blank becomes `NaN`, and `NaN` is a float, so the whole column becomes float. Meanwhile `True`/`False` text does load as real booleans, while `yes`/`no` wouldn't.

### Exercise 1: Size up a library log

Load the checkout log below. Print its shape, its dtypes, and how many books have no due date.

```python run
checkouts = """book_id,title,pages,checked_out,due_date
B01,Hatchet,195,2026-10-02,2026-10-16
B02,Dune,617,2026-10-03,
B03,Holes,233,2026-10-03,2026-10-17
B04,Wonder,315,2026-10-05,2026-10-19
B05,Matilda,240,2026-10-06,
B06,Coraline,162,2026-10-06,2026-10-20
"""
```

```text
(6, 5)
...
Books with no due date: 2
```

:::hint
`isna()` gives True/False for each value, and `sum()` counts the Trues.
:::

:::solution
```python run
log = pd.read_csv(io.StringIO(checkouts))
print(log.shape)
print(log.dtypes)
print("Books with no due date:", log["due_date"].isna().sum())
```

Notice that both date columns are `object`. `read_csv` doesn't turn text into dates unless you ask (with `parse_dates=["checked_out", "due_date"]`), so for now they're strings that happen to look like dates.
:::

### Exercise 2: A file that loads as one column

A weather station in Lyon, France, exports this file. Load it so that `temp_c` and `rain_mm` are numbers, then print the mean temperature and total rain.

```python run
lyon = """station;date;temp_c;rain_mm
Lyon;2026-03-01;8,4;0,0
Lyon;2026-03-02;10,1;2,5
Lyon;2026-03-03;7,9;11,2
Lyon;2026-03-04;6,5;0,4
"""
```

```text
Mean temperature: 8.2
Total rain: 14.1
```

:::hint
Load it plainly first and print `.shape`. Then look up two `read_csv` options: one for what goes *between* values, and one for the character *inside* numbers.
:::

:::solution
```python run
plain = pd.read_csv(io.StringIO(lyon))
print("Plain load:", plain.shape)

lyon_df = pd.read_csv(io.StringIO(lyon), sep=";", decimal=",")
print(lyon_df.dtypes)
print("Mean temperature:", round(lyon_df["temp_c"].mean(), 1))
print("Total rain:", round(lyon_df["rain_mm"].sum(), 1))
```

The plain load has 1 column because there's no comma between fields. `sep=";"` splits the fields, and `decimal=","` reads `8,4` as 8.4. Without `decimal`, the temperatures would stay text.
:::

### Exercise 3: The vanishing zeros

A club roster has ZIP codes and phone numbers. Load it and print it. What happened to Ana's ZIP code? Fix the load so it matches the file exactly.

```python run
roster = """member,zip,phone
Ana,02139,6175550142
Ben,10001,2125550199
Cy,07030,2015550123
"""
```

:::hint
Is a ZIP code a quantity you'd ever average? `read_csv` takes a `dtype=` dictionary that maps column names to types.
:::

:::solution
```python run
guessed = pd.read_csv(io.StringIO(roster))
print(guessed)

fixed = pd.read_csv(io.StringIO(roster), dtype={"zip": str, "phone": str})
print(fixed)
```

`02139` looked like a number, so pandas read it as the integer 2139 and the leading zero was gone. ZIP codes, phone numbers, and ID numbers are **labels made of digits**. You'll never add them up, so load them as `str`. Any column where a leading zero matters needs this.
:::

### Exercise 4: Orders with a list of items inside

An online bookstore exports orders as JSON. Each order holds a **list** of items. Build a table with one row per item that also shows the order ID and customer city. Then add a `line_total` column (`qty × price`) and print the total sales.

```python run
orders_json = """[
 {"order_id": 501, "customer": {"name": "Lee", "city": "Austin"},
  "items": [{"title": "Holes", "qty": 1, "price": 8.99},
            {"title": "Dune", "qty": 2, "price": 10.50}]},
 {"order_id": 502, "customer": {"name": "Rosa", "city": "Fresno"},
  "items": [{"title": "Wonder", "qty": 1, "price": 9.25}]},
 {"order_id": 503, "customer": {"name": "Jin", "city": "Austin"},
  "items": [{"title": "Matilda", "qty": 3, "price": 7.00},
            {"title": "Hatchet", "qty": 1, "price": 8.50}]}
]"""
```

```text
     title  qty  price order_id customer.city  line_total
0    Holes    1   8.99      501        Austin        8.99
...
Total sales: 68.74
```

```mermaid caption="record_path makes one row per item; meta copies order fields onto each row"
flowchart LR
    O["Order 501 (customer: Austin)"] --> I1["Item: Holes"]
    O --> I2["Item: Dune"]
    I1 --> R1["Row: Holes, 501, Austin"]
    I2 --> R2["Row: Dune, 501, Austin"]
```

:::hint
Plain `pd.json_normalize(records)` gives one row per *order*, with the items list stuck in a single cell. Look at the `record_path` and `meta` parameters. A nested field in `meta` is written as a list of keys: `["customer", "city"]`.
:::

:::solution
```python run
order_records = json.loads(orders_json)
print(pd.json_normalize(order_records).shape)    # one row per order: not what we want

items = pd.json_normalize(
    order_records,
    record_path="items",                             # one row per entry in "items"
    meta=["order_id", ["customer", "city"]],         # copy these onto each row
)
items["line_total"] = items["qty"] * items["price"]
print(items)
print("Total sales:", round(items["line_total"].sum(), 2))
```

`record_path="items"` tells pandas which list to unroll, so 3 orders become 5 rows. `meta` copies fields from the parent order onto each of its rows, so every item knows which order and city it came from.
:::

### Exercise 5: Find the values that aren't prices

A bake-sale sheet has a `price` column that loads as `object`. Print each entry that's filled in but can't be read as a number, with its row number.

```python run
bake = pd.DataFrame({
    "item": ["brownie", "cookie", "muffin", "lemonade", "scone", "cupcake", "pie", "fudge"],
    "price": ["4.50", "$3.25", "2", "free", "1.75", "3,99", None, "0.50"],
})
```

```text
1    $3.25
3     free
5     3,99
```

:::hint
Convert with `pd.to_numeric(..., errors="coerce")`. A value is a culprit if it's missing **after** converting but wasn't missing **before**.
:::

:::solution
```python run
as_number = pd.to_numeric(bake["price"], errors="coerce")
culprits = as_number.isna() & bake["price"].notna()
print(bake.loc[culprits, "price"])
print(culprits.sum(), "values need a decision;", bake["price"].isna().sum(), "is truly missing")
```

The `pie` row is `None`, so it's missing both before and after, and the second condition leaves it out. Each culprit needs a different fix: strip the `$`, decide whether `free` means 0, and swap the decimal comma.
:::

### Exercise 6: The average rating that nobody gave

Twenty people rated a new cafeteria menu from 1 to 5. Print `describe()`, then make a bar chart of how many people gave each rating, including any rating nobody chose. What does the chart show that the mean hides?

```python run
ratings = pd.Series([5, 1, 5, 5, 1, 1, 5, 4, 1, 5, 5, 1, 5, 2, 5, 1, 5, 5, 1, 5], name="rating")
```

:::hint
`value_counts()` skips values that never appear. `.reindex(range(1, 6), fill_value=0)` puts them back with a count of 0.
:::

:::solution
```python run alt="Bar chart of menu ratings from 20 people: 7 people gave 1, 1 gave 2, nobody gave 3, 1 gave 4, and 11 gave 5"
print(ratings.describe().round(2))

counts = ratings.value_counts().reindex(range(1, 6), fill_value=0)
ax = counts.plot(kind="bar", color="#2a78d6", rot=0, figsize=(5, 3))
ax.set_xlabel("Rating")
ax.set_ylabel("People")
ax.set_title(f"Mean rating {ratings.mean():.1f}, but nobody chose 3")
```

The mean is 3.4, which sounds like "people thought it was okay". The chart says the opposite: almost everyone either loved it (11 fives) or hated it (7 ones). Nobody chose 3. A single summary number can describe a group that doesn't exist, so always look at the distribution of a column, not just its average.
:::

### Challenge: Do the CSV and JSON exports match?

A fundraiser exports its donations twice. Write code that prints (a) donor IDs that appear in only one file, and (b) every column whose dtype differs between the two files, side by side.

```python run
donations_csv = """donor_id,amount,recurring
D1,25,yes
D2,10,no
D3,50,yes
D4,15,no
"""
donations_json = """[
 {"donor_id": "D1", "amount": 25.0, "recurring": true},
 {"donor_id": "D2", "amount": 10.0, "recurring": false},
 {"donor_id": "D3", "amount": 50.0, "recurring": true},
 {"donor_id": "D5", "amount": 20.0, "recurring": false}
]"""
```

:::hint
Python sets support `-` for "in this set but not that one". For dtypes, `pd.DataFrame({"csv": a.dtypes, "json": b.dtypes})` builds a side-by-side table; keep the rows where the two columns differ.
:::

:::solution
```python run
from_csv = pd.read_csv(io.StringIO(donations_csv))
from_json = pd.json_normalize(json.loads(donations_json))

csv_ids, json_ids = set(from_csv["donor_id"]), set(from_json["donor_id"])
print("Only in CSV: ", sorted(csv_ids - json_ids))
print("Only in JSON:", sorted(json_ids - csv_ids))

types = pd.DataFrame({"csv": from_csv.dtypes, "json": from_json.dtypes}).astype(str)
print(types[types["csv"] != types["json"]])
```

D4 is missing from the JSON and D5 from the CSV, so neither file alone has every donation. The dtype table explains two traps: `amount` is `int64` in one file and `float64` in the other (harmless for math, but worth knowing), and `recurring` is the text `yes`/`no` in the CSV but a real `bool` in the JSON. Code that does `df[df["recurring"]]` works on the JSON version and fails on the CSV.
:::
