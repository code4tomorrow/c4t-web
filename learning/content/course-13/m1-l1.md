Here is a complete analysis in about a dozen lines. It builds a year of daily temperatures, finds the hottest week, and draws the whole year as a chart. In a spreadsheet you would click through menus for ten minutes, and next year you would click through them again. In a notebook you write the steps once and rerun them on new data in a second.

```python run alt="Line chart of 365 daily temperatures rising from about 3 °C in January to about 25 °C in July and falling again, with a smoother 7-day average line on top" caption="The kind of result you'll produce by the end of this lesson"
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

rng = np.random.default_rng(13)
days = pd.date_range("2025-01-01", periods=365, freq="D")
seasonal = 14 - 11 * np.cos(2 * np.pi * (np.arange(365) - 15) / 365)
temps = pd.Series(seasonal + rng.normal(0, 3, 365), index=days).round(1)

weekly = temps.rolling(7).mean()
print("Hottest 7-day stretch ended on", weekly.idxmax().date())
print(f"Its average was {weekly.max():.1f} °C")

fig, ax = plt.subplots(figsize=(8, 3.5))
ax.plot(temps.index, temps, color="#b8c7dc", linewidth=1, label="Daily reading")
ax.plot(weekly.index, weekly, color="#2a78d6", linewidth=2, label="7-day average")
ax.set_ylabel("Temperature (°C)")
ax.set_title("One year of simulated daily temperatures")
ax.legend(frameon=False)
```

You don't need to understand every line yet. By Module 3 you will. Right now the goal is a notebook where this code runs.

## What you need, and what you don't

This course uses **Google Colab**, a free notebook that runs in your browser. Your code runs on a computer in a Google data center, which already has pandas, NumPy, Matplotlib, seaborn, and scikit-learn installed. You install nothing.

You need three things:

1.  **A Google account.** A personal account always works. School accounts work only if your school's administrator has switched Colab on, so if a school account shows an access message, try a personal one or ask your teacher.
2.  **A current browser.** Google says Colab is tested most on the latest Chrome, Firefox, and Safari. Edge works too.
3.  **An internet connection.** Because the code runs remotely, Colab stops working when you go offline. If that's a problem where you study, use JupyterLab (further down this page).

You don't need a GPU, a paid plan, or a powerful laptop. Every dataset in this course is small enough for the free tier.

## Make your first notebook, step by step

1.  Go to **colab.research.google.com** and click **Sign in** in the top right if you aren't signed in already.
2.  A window for opening notebooks appears. Click **New notebook** at the bottom of it. If the window doesn't appear, use **File › New notebook in Drive**.
3.  The notebook opens with a name like `Untitled0.ipynb`. Click that name at the top left and rename it `ds-setup.ipynb`. Colab saves it in a folder called **Colab Notebooks** in your Google Drive.
4.  Click inside the gray box. That box is a **code cell**. Type `print("ready")`.
5.  Press **Shift + Enter**, or click the round play button at the left edge of the cell.

The first run takes a few seconds, because Colab has to start a machine for you. That machine is called the **runtime**. When it's ready, the top right shows small **RAM** and **Disk** bars, and `ready` appears under your cell. A small number in square brackets next to the cell, like `[1]`, counts the order in which cells ran.

:::tabs
@tab Windows
-   **Shift + Enter**: run the cell and move to the next one.
-   **Ctrl + Enter**: run the cell and stay on it.
-   **Ctrl + M**, then **B**: add a code cell below.
-   **Ctrl + M**, then **M**: turn the cell into a text (Markdown) cell.
-   **Ctrl + S**: save now. Colab also saves automatically as you work.
@tab macOS
-   **Shift + Return**: run the cell and move to the next one.
-   **⌘ + Return**: run the cell and stay on it.
-   **⌘ + M**, then **B**: add a code cell below.
-   **⌘ + M**, then **M**: turn the cell into a text (Markdown) cell.
-   **⌘ + S**: save a checkpoint right away.
@tab Chromebook
-   Shortcuts match Windows: **Shift + Enter** runs and moves on, **Ctrl + Enter** runs and stays.
-   **Ctrl + M**, then **B** adds a code cell below; **Ctrl + M**, then **M** makes a text cell.
-   Open Colab in a normal Chrome tab. Colab is the recommended path on a Chromebook, since installing JupyterLab needs the Linux development environment, which school Chromebooks often block.
:::

For the full list, open **Tools › Keyboard shortcuts**.

## Check that the data libraries are ready

Paste this into a new cell and run it:

```python run
import sys
import numpy as np
import pandas as pd
import matplotlib
import sklearn

print("Python      ", sys.version.split()[0])
print("NumPy       ", np.__version__)
print("pandas      ", pd.__version__)
print("Matplotlib  ", matplotlib.__version__)
print("scikit-learn", sklearn.__version__)
```

The versions above are from the computer that built this page. Colab updates its libraries a few times a year, so your numbers will probably differ. Anything from pandas 2.0 upward works for this course. If a line crashes with `ModuleNotFoundError`, see the fixes at the end of this lesson.

Now prove that charts work. This one draws a bar for each day of a week of bike rentals:

```python run alt="Bar chart of bike rentals for one week, lowest on Monday at 120 and highest on Saturday at 310"
rentals = pd.Series([120, 135, 128, 160, 240, 310, 275],
                    index=["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"])

ax = rentals.plot(kind="bar", color="#2a78d6", rot=0, figsize=(6, 3))
ax.set_ylabel("Rentals")
ax.set_title("Bike rentals in one week")
print("Busiest day:", rentals.idxmax())
```

In Colab the chart appears right under the cell. You don't need `plt.show()` at the end, although adding it does no harm.

:::note
**How output works on this page vs. in Colab.** Colab displays the value of a cell's **last line** automatically, so a cell ending in `rentals` shows the Series as a neat table. The pages in this course can only show what a program prints, so the examples use `print(...)`. In your own notebook, feel free to drop the `print` on a final line.
:::

## The local option: JupyterLab on your own computer

JupyterLab is the open-source notebook that Colab grew out of. The notebooks are the same `.ipynb` files, and every lesson in this course runs in it. Choose it if you have your own computer and want to work offline. It takes about ten minutes to set up.

:::tabs
@tab Windows
1.  Install Python 3.11 or newer from **python.org/downloads**. On the first installer screen, tick **Add python.exe to PATH**.
2.  Open **PowerShell** from the Start menu and install the libraries:

```powershell
py -m pip install jupyterlab pandas numpy matplotlib seaborn scikit-learn
```

3.  Make a folder for the course, move into it, and start JupyterLab:

```powershell
mkdir ds-course
cd ds-course
py -m jupyterlab
```

@tab macOS
1.  Install Python 3.11 or newer from **python.org/downloads** and run the installer.
2.  Open **Terminal** and create a private environment for the course, so the libraries don't clash with anything else on the Mac:

```bash
python3 -m venv ~/ds-env
source ~/ds-env/bin/activate
python -m pip install jupyterlab pandas numpy matplotlib seaborn scikit-learn
```

3.  Make a folder for the course and start JupyterLab from inside it:

```bash
mkdir ~/ds-course
cd ~/ds-course
jupyter lab
```

Next time, run `source ~/ds-env/bin/activate` before `jupyter lab`.
@tab Chromebook
Use Colab. JupyterLab needs Linux apps, which you turn on under **Settings › About ChromeOS › Developers › Linux development environment**. Many school Chromebooks hide that option. If yours has it, follow the macOS steps inside the Linux terminal after running `sudo apt install python3-venv`.
:::

Your browser opens a page whose address starts with `http://localhost:8888`. Click **Python 3 (ipykernel)** under **Notebook** in the Launcher to make a notebook. Leave the terminal window open while you work; closing it stops JupyterLab.

## When it doesn't work: the four usual problems

**1. "Colab isn't available" or an access-denied page.** This usually means a school account where Colab is switched off. Sign in with a personal Google account in a different browser profile, or use JupyterLab.

**2. The cell shows a spinning circle and nothing happens.** Look at the top right. If it still says **Connecting**, the runtime hasn't started yet; wait 30 seconds, then reload the page. If the page complains about a GPU, open **Runtime › Change runtime type** and choose **CPU**. This course never needs a GPU.

**3. A cell fails with `NameError`.** You ran a cell that uses a name before the cell that creates it. This is what happens if you run a cell that uses `survey` before any cell has defined it:

```python run raises
print(survey.head())
```

Read the last line of the error first: Python is saying `survey` doesn't exist in the runtime's memory. Run the earlier cells (**Runtime › Run before** runs everything above the current cell), then try again. You'll also see this after Colab disconnects an idle notebook, because a fresh runtime starts with empty memory.

**4. JupyterLab says `ModuleNotFoundError: No module named 'pandas'`.** The library went into a different Python than the one your notebook uses. Run this in a notebook cell, which installs into the notebook's own Python, then restart the kernel with **Kernel › Restart Kernel**:

```text
%pip install pandas numpy matplotlib seaborn scikit-learn
```

On a Mac, `pip` sometimes refuses with `externally-managed-environment`. That means you skipped the `venv` step; go back and create the environment.

:::quiz
Q: You open your notebook the next morning and run only the chart cell. It fails with `NameError: name 'pd' is not defined`. Why?
- [ ] pandas was uninstalled overnight
  Colab's libraries stay installed; what's gone is the memory of what you imported.
- [x] The runtime is new, so the `import pandas as pd` cell hasn't run yet
  Idle notebooks get a fresh runtime with empty memory. Run the import cell (or Runtime › Run before) first.
- [ ] Chart cells must be run twice
  One run is enough once the names it uses exist.

Q: Where does your Python code actually run when you use Colab?
- [ ] On your laptop, inside the browser tab
  The browser only shows the notebook; the work happens elsewhere.
- [x] On a Google machine called the runtime
  That's why Colab works on a Chromebook and why it stops working offline.
- [ ] In your Google Drive folder
  Drive stores the notebook file, but Drive doesn't run code.
:::

:::takeaways
- Colab is a free notebook in the browser; the code runs on a Google machine called the runtime, with the data libraries preinstalled.
- **Shift + Enter** runs a cell. The `[n]` beside it shows the order cells ran in.
- Notebooks save to the **Colab Notebooks** folder in your Drive.
- JupyterLab runs the same `.ipynb` notebooks locally and offline.
- `NameError` in a notebook usually means an earlier cell hasn't run in this runtime yet.
:::
