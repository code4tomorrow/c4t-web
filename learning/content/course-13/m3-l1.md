A weather network logs a million temperature readings in Fahrenheit, and your team needs them in Celsius. The first draft is the loop you'd write in any Python class. The second is one line of NumPy. Both produce the same million numbers:

```python run alt="Horizontal bar chart comparing the time to convert one million temperatures: the Python loop bar is many times longer than the NumPy bar"
import time
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

pd.set_option("display.width", 110)

rng = np.random.default_rng(3)
temps_f = rng.normal(68, 15, 1_000_000).round(1)   # a NumPy array of 1,000,000 readings
temps_list = temps_f.tolist()                      # the same values as a Python list

start = time.perf_counter()
celsius_loop = []
for t in temps_list:
    celsius_loop.append((t - 32) * 5 / 9)
loop_seconds = time.perf_counter() - start

start = time.perf_counter()
celsius = (temps_f - 32) * 5 / 9                   # the whole array at once
numpy_seconds = time.perf_counter() - start

print(f"Python loop: {loop_seconds:.3f} s")
print(f"NumPy:       {numpy_seconds:.4f} s  ({loop_seconds / numpy_seconds:.0f} times faster)")
print("Same answers:", np.allclose(celsius_loop, celsius))

fig, ax = plt.subplots(figsize=(6, 1.8))
ax.barh(["NumPy", "Python loop"], [numpy_seconds, loop_seconds], color=["#2a78d6", "#eb6834"])
ax.set_xlabel("Seconds to convert 1,000,000 readings")
```

The exact times depend on the computer, but the gap is always large, often well over 20 times. A million values is a small dataset by data-science standards, and the gap grows with the data. This lesson is about writing that second version by habit.

## Why the loop is slow

Step through the loop version on four readings. Each pass, Python fetches one value, works out what type it is, does three operations, and appends the result to a list:

:::trace One value per pass
```python
temps_f = [50.0, 68.0, 86.0, 104.0]
celsius = []
for t in temps_f:
    c = (t - 32) * 5 / 9
    celsius.append(c)
print(celsius)
```
:::

All of that bookkeeping happens again for every single value. A NumPy array is different: it's one block of memory holding numbers of **one type**, so NumPy can run the arithmetic for every element inside fast, compiled C code, with no per-item Python work. Doing math on a whole array at once is called **vectorization**.

## Arrays: one type, one shape, math on everything

```python run
a = np.array([3, 5, 2])
print(a * 2)               # every element doubled
print(a + a)               # element by element
print([3, 5, 2] * 2)       # a list just repeats

week = np.array([[21.5, 23.0, 19.8],     # station A, three days
                 [18.2, 17.9, 20.4]])    # station B, three days
print(week.shape, week.dtype)
print(week.mean(axis=1))   # average of each row (each station)
print(week.max(axis=0))    # hottest reading on each day (each column)
```

Two things to notice. Arithmetic on an array applies to every element, while the same operator on a list does list things (`*` repeats it). And `axis` picks the direction to summarize: `axis=1` collapses across columns, giving one answer per row, while `axis=0` collapses down the rows, giving one answer per column.

## Boolean masks pick values by a condition

Comparing an array with a value gives an array of `True`/`False` the same size, called a **mask**. Masks do three jobs:

```python run
hot = celsius > 30                       # True where the reading is over 30 °C
print(hot[:5])
print("Hot readings:", hot.sum())        # True counts as 1
print("Share hot:", round(hot.mean(), 3))
print("First five hot ones:", celsius[hot][:5].round(1))   # keep only the True positions

mild = (celsius > 15) & (celsius < 25)   # both conditions: use &, with parentheses
print("Share mild:", round(mild.mean(), 3))
```

`hot.sum()` counts, `hot.mean()` gives a proportion, and `celsius[hot]` filters. Combine conditions with `&` (and), `|` (or), and `~` (not), and wrap each comparison in parentheses, because `&` binds more tightly than `>`.

:::warning
Python's `and` and `or` don't work on arrays or columns:

```python run raises
mild = (celsius > 15) and (celsius < 25)
```

`and` needs a single True or False, and an array of a million answers isn't one. The message suggests `a.any()` or `a.all()`, but what you almost always want is `&`. The same error appears with pandas columns, worded as "The truth value of a Series is ambiguous".
:::

## pandas keeps the labels attached

NumPy arrays are fast but anonymous: position 0 is just position 0. That gets dangerous as soon as two lists come in different orders. Here are two days of readings from three stations, where Tuesday's file happens to be sorted differently:

```python run
monday = pd.Series([21.5, 18.2, 15.0], index=["Airport", "Harbor", "Hilltop"])
tuesday = pd.Series([14.1, 23.0, 19.0], index=["Hilltop", "Airport", "Harbor"])

print(tuesday.to_numpy() - monday.to_numpy())   # by position: wrong stations paired up
print(tuesday - monday)                         # by label: each station with itself
```

The NumPy subtraction paired Hilltop's Tuesday with Airport's Monday and reported a 7.4-degree drop that never happened. The pandas version **aligns on the index**: each value is matched by its label, whatever order the data arrives in. A **Series** is a NumPy array plus labels, and a **DataFrame** is a table of Series that share one index.

Here's a month of daily readings from four stations, 120 rows:

```python run
stations = {"Airport": 27, "Harbor": 23, "Hilltop": 21, "Downtown": 29}
days = pd.date_range("2026-07-01", periods=30)
weather = pd.DataFrame({
    "date": np.tile(days, 4),
    "station": np.repeat(list(stations), 30),
    "temp_f": np.concatenate([(c + rng.normal(0, 3, 30)) * 9 / 5 + 32 for c in stations.values()]).round(1),
    "rain_mm": rng.gamma(0.4, 3, 120).round(1),
})
print(weather.head(3))
print(weather.shape)
```

A new column is just a vectorized expression on existing columns, assigned to a new name. `np.where` makes a column from a condition:

```python run
weather["temp_c"] = ((weather["temp_f"] - 32) * 5 / 9).round(1)
weather["day_type"] = np.where(weather["rain_mm"] >= 1, "rainy", "dry")
print(weather.head(3))
```

To select, use `loc` with **labels and conditions** and `iloc` with **positions**:

```python run
print(weather.loc[weather["temp_c"] > 34, ["date", "station", "temp_c"]])   # rows by mask, columns by name
print(weather.iloc[0:2, 0:3])                                                # first 2 rows, first 3 columns
```

`loc[rows, columns]` reads like a sentence: "the rows where it's over 34 °C, and these three columns". `iloc` slices by position like a list, so `0:2` means positions 0 and 1. Prefer `loc` in analysis code, because column positions change when someone adds a column.

## Group, summarize, and join

"What's the average temperature at each station?" is a three-step idea called **split-apply-combine**:

```mermaid caption="groupby splits rows by a key, applies a summary to each group, and combines the results"
flowchart LR
    A[120 daily rows] --> B["Split by station"]
    B --> C1["Airport: 30 rows"]
    B --> C2["Harbor: 30 rows"]
    B --> C3["... 2 more"]
    C1 --> D["Apply mean, max, count"]
    C2 --> D
    C3 --> D
    D --> E["Combine: 4-row table"]
```

```python run alt="Bar chart of average July temperature by station: Downtown about 30 °C, Airport about 26, Harbor about 24, Hilltop about 21.5"
by_station = weather.groupby("station")["temp_c"].agg(["mean", "max", "count"]).round(1)
print(by_station)

ax = by_station["mean"].sort_values().plot(kind="barh", color="#2a78d6", figsize=(6, 2.6))
ax.set_xlabel("Average temperature (°C)")
ax.set_ylabel("")
ax.set_title("July average by station")
```

Station names alone don't tell you *why* Downtown runs hot. A second table, kept by the city, describes each station. `merge` joins the two on their shared column:

```python run
station_info = pd.DataFrame({
    "station": ["Airport", "Harbor", "Hilltop", "Downtown"],
    "district": ["East", "Waterfront", "North", "Center"],
    "elevation_m": [12, 3, 140, 25],
})
joined = by_station.reset_index().merge(station_info, on="station", how="left")
print(joined)
```

`on="station"` names the key, and `how="left"` keeps every row of the left table even if a station is missing from the info table (its new columns would be `NaN`). `reset_index()` turned `station` back from the index into an ordinary column so `merge` could find it. Now the pattern has an explanation you can check: Hilltop, at 140 m, is the coolest.

:::warning
**Changing a filtered copy changes nothing.** `weather[weather["station"] == "Hilltop"]["temp_c"] = 0` looks like it sets Hilltop's temperatures, but the first `[...]` makes a temporary copy, and the assignment goes into the copy. pandas may print a `SettingWithCopyWarning`, and `weather` is unchanged. Always do conditional assignment in one `loc` call: `weather.loc[weather["station"] == "Hilltop", "temp_c"] = 0`.
:::

:::quiz
Q: `a = np.array([2, 4, 6])`. What does `a[a > 3].sum()` give?
- [ ] `2`
  `a > 3` is `[False, True, True]`, and `sum()` of the mask alone would be 2. Here the mask filters `a` first.
- [x] `10`
  The mask keeps 4 and 6, and their sum is 10.
- [ ] `12`
  That's the sum of the whole array; the mask removed the 2.

Q: Which line correctly selects rainy days at the Harbor station?
- [ ] `weather[weather["station"] == "Harbor" and weather["day_type"] == "rainy"]`
  `and` fails on columns with "truth value ... is ambiguous".
- [ ] `weather[weather["station"] == "Harbor" & weather["day_type"] == "rainy"]`
  Without parentheses, `&` runs before `==` and pandas raises an error.
- [x] `weather[(weather["station"] == "Harbor") & (weather["day_type"] == "rainy")]`
  Each comparison makes a mask, and `&` combines them element by element.

Q: Two Series hold the same stations in different orders. Why does `b - a` still pair each station correctly?
- [x] pandas aligns values by index label before doing the math
  The labels, not the positions, decide which values meet.
- [ ] pandas sorts both Series alphabetically first
  Sorting isn't what happens; it matches labels, and the result's order is a side effect.
- [ ] It doesn't; you need `to_numpy()` first
  `to_numpy()` throws the labels away, which is exactly what causes mismatches.

Q: `weather.groupby("station")["rain_mm"].agg(["sum", "count"])` returns how many rows?
- [ ] 120, one per reading
  groupby combines each group into one row.
- [x] 4, one per station
  There are four stations, so four groups, each summarized into one row.
- [ ] 2, one per statistic
  The statistics become columns, not rows.
:::

:::takeaways
- Vectorized NumPy math runs in compiled code and is usually tens of times faster than a Python loop.
- Arithmetic and comparisons apply to every element; `axis` chooses rows or columns for summaries.
- A boolean mask counts (`sum`), measures a share (`mean`), and filters (`arr[mask]`). Combine masks with `&`, `|`, `~` and parentheses.
- pandas aligns by label, which keeps each value attached to the row it belongs to.
- `loc` selects by label or condition, `iloc` by position. Assign conditionally with a single `loc`.
- `groupby().agg()` is split-apply-combine; `merge(on=..., how="left")` joins tables on a shared key.
:::
