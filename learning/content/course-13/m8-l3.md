You present your findings, and the first question from the audience is: "If I run your notebook, will I get 0.59 too?" The second is: "What if you'd split the ages differently?" Good investigators have already asked themselves both. This lesson is the checklist that makes sure you have, and then it gets your work ready to show.

The examples continue the diabetes investigation from the previous lesson. Run this cell to rebuild its data:

```python run
import re
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.datasets import load_diabetes

BLUE, ORANGE, AQUA, INK, MUTED = "#2a78d6", "#eb6834", "#1baf7a", "#0b0b0b", "#52514e"
patients = load_diabetes(as_frame=True, scaled=False).frame.rename(columns={"target": "progression"})
patients["bmi_group"] = pd.cut(patients["bmi"], [0, 25, 30, 100], right=False,
                               labels=["under 25", "25 to 29.9", "30 or more"])
print(len(patients), "patients;", f"r = {patients['bmi'].corr(patients['progression']):.2f}")
```

## The test plan

| # | Test | How | Passes when |
| --- | --- | --- | --- |
| 1 | Fresh run | **Runtime › Restart session and run all** | No errors; cell counters go 1, 2, 3… in order |
| 2 | Someone else's run | Share the notebook with **Share** (top right in Colab) and ask a friend to run all in their own account | Their headline numbers match yours exactly |
| 3 | Tampered data | Feed your checks a copy of the data with a planted error | The checks catch it |
| 4 | Seeds | If anything is random, change `SEED` and rerun | The conclusions don't change (small numbers may) |
| 5 | Cutoffs | Change one choice you made (a group boundary, a threshold) | The main finding survives, or you report that it doesn't |
| 6 | Claims | Read every sentence of your summary against your results | Every claim points to a number or chart above it |

Tests 1 and 2 are the reproducibility tests from Module 7, and test 2 is the one people skip. It catches the problems you can't see from your own account: a file only you uploaded, a Google Drive path only you can reach, a library only you installed.

### Test 3: Plant an error and see if your checks catch it

Assertions that never fire might be checking nothing. Put your checks in a function, then give it a copy of the data with mistakes planted in it:

```python run
def run_checks(df):
    checks = {
        "no missing values": df.notna().all().all(),
        "ages between 18 and 100": df["age"].dropna().between(18, 100).all(),
        "BMI between 12 and 70": df["bmi"].dropna().between(12, 70).all(),
        "sex coded 1 or 2": df["sex"].isin([1, 2]).all(),
    }
    return [name for name, ok in checks.items() if not ok]

print("Real data, failed checks:", run_checks(patients))

tampered = patients.copy()
tampered.loc[0, "bmi"] = 251.0          # typo: 25.1 with a slipped decimal
tampered.loc[1, "age"] = np.nan         # a blank cell
print("Tampered data, failed checks:", run_checks(tampered))
```

Both planted errors were caught, each by the check meant for it (the range checks skip blanks with `dropna()`, so a missing value is reported only once). If one slipped through, you'd know a check was missing, and that's much better to learn now than after a slipped decimal ends up in your scatter plot.

### Test 5: Does the finding survive a different cutoff?

The age groups (under 40, 40 to 54, 55 and over) were a judgment call. Try other reasonable splits and see whether "the BMI link holds in every age group" stays true:

```python run
splits = {
    "3 groups (40, 55)": [0, 40, 55, 120],
    "2 groups (50)": [0, 50, 120],
    "4 groups (35, 50, 65)": [0, 35, 50, 65, 120],
}
for name, edges in splits.items():
    groups = pd.cut(patients["age"], edges, right=False)
    rs = patients.groupby(groups, observed=True).apply(
        lambda g: g["bmi"].corr(g["progression"]), include_groups=False)
    print(f"{name:<24} r within groups: {', '.join(f'{v:.2f}' for v in rs)}")
```

Every split gives a clearly positive r in every group, so the finding doesn't depend on where the lines were drawn. Say so in your report; it's one sentence and it answers the audience's second question before they ask it. If a different reasonable choice *had* flipped your finding, that would belong in your limitations, not in a drawer.

### Test 6: Scan the summary for overclaiming

Some words promise more than observational data can deliver. A tiny scanner won't judge your reasoning, but it will point you at sentences worth rereading:

```python run
RISKY = ["cause", "causes", "proves", "proof", "always", "never", "everyone", "all people", "definitely"]

def flag_overclaims(text):
    found = []
    for word in RISKY:
        if re.search(rf"\b{re.escape(word)}\b", text, flags=re.IGNORECASE):
            found.append(word)
    return found

draft = "This proves that high BMI causes diabetes to progress faster for everyone."
revised = ("Among 442 adults in one study, higher BMI went with faster progression (r = 0.59), "
           "in every age group we checked. The data can't show whether lowering BMI would slow it.")
print("Draft flags:  ", flag_overclaims(draft))
print("Revised flags:", flag_overclaims(revised))
```

The draft trips three flags; the revision trips none, and it also says more: the sample, the strength, and the open question. A flagged word isn't automatically wrong ("we can't say what causes this" is fine), which is why the scanner flags and you decide.

## Polish the charts

Default charts answer "what does the data look like?" Presentation charts answer "what should I notice?" Here's the same data both ways:

```python run alt="Two versions of the same bar chart of median disease progression by BMI group. Left, the default: three identical blue bars, the title 'progression', raw group labels, and no units. Right, polished: bars in three distinct colors labeled 95, 168, and 230, a title stating that median progression more than doubles from the lowest to the highest BMI group, a labeled y-axis, and no top or right border." caption="Default versus presentation-ready"
medians = patients.groupby("bmi_group", observed=True)["progression"].median()

fig, (before, after) = plt.subplots(1, 2, figsize=(11, 3.8))
before.bar(medians.index.astype(str), medians.values)
before.set_title("progression")

bars = after.bar(medians.index.astype(str), medians.values, color=[BLUE, ORANGE, AQUA], width=0.6)
after.bar_label(bars, fmt="%.0f", padding=3, color=INK)
after.set_xticks(range(3), [f"BMI {g}" for g in medians.index])
after.set_ylabel("Median progression one year later")
after.set_ylim(0, 270)
after.spines[["top", "right"]].set_visible(False)
after.set_title(f"Median progression more than doubles, {medians.iloc[0]:.0f} to {medians.iloc[-1]:.0f}",
                loc="left")
fig.tight_layout()
```

Before you export any figure, check it against this list:

- **Title states the finding**, computed from the data.
- **Axes have labels and units** (or say "units not given" when the source doesn't provide them).
- **Bars start at zero**; lines and scatters use a range that matches meaningful change.
- **Colors follow entities** and stay the same across every chart; nothing depends on color alone.
- **Direct labels** where they help, a legend only where needed, no clutter like heavy borders or 3D.
- **Readable at presentation size**: open the exported PNG at full screen and read the smallest text from across the room.
- **Alt text** written for each figure, describing what it shows and the main pattern.

## Present it in five minutes

Whether you speak, make slides, or write a one-page report, use the same five parts in this order:

1. **The question and why it matters** (two sentences).
2. **The data**: where it came from, who and what it covers, and what you cleaned.
3. **Two or three findings**, one chart each. Say the chart's title aloud; it's your topic sentence.
4. **Limits**: who isn't in the data, the confounders you couldn't test, and what you can't claim.
5. **What you'd do next** with more time or better data.

Lead with the answer, not the process: "BMI and progression rise together at every age" beats "First I loaded the data." Keep your notebook open in another tab. When someone asks "how do you know it isn't just age?", you can show them the within-group check, which is the most convincing answer there is.

## The rubric

| Criterion | Excellent (4) | Developing (2–3) | Beginning (1) |
| --- | --- | --- | --- |
| Question and data | Specific question; source, license, coverage, and a data dictionary with gaps noted | Clear question; source named but coverage or dictionary thin | Vague topic; source unclear |
| Reproducibility | Restart session and run all passes, and a second person got the same numbers; parameters and seeds in one setup cell | Runs top to bottom for the author; some hard-coded choices scattered through | Errors on a fresh run, or depends on hand-edited files |
| Cleaning and checks | Every step in code with a log; assertions that catch planted errors | Cleaning in code, few checks | Cleaning by hand or undocumented |
| Summaries | Center and spread chosen for each variable's shape, with reasons | Correct summaries, little explanation | Means everywhere, regardless of skew or outliers |
| Charts | At least three charts for three questions; honest axes; finding titles; consistent, accessible colors; dashboard exported | Appropriate charts with some default titles or styling issues | Charts that don't fit the question, or that mislead |
| Bias and limits | Pre-mortem done early; confounder tested within groups; sample limits and untestable confounders named; sensitivity checked | Limits listed but general ("more data needed") | No discussion of bias or limits |
| Communication | Computed executive summary; claims match the evidence; clear five-part presentation | Summary present but with typed numbers or some overclaiming | Findings hard to locate, or claims beyond the data |

A strong capstone scores 4 on most rows. A project with modest findings and an excellent bias section can outscore one with a dramatic finding and no limits; that's on purpose.
