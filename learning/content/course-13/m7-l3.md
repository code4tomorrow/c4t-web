## Warm-up

Which of these four cells could you run twice in a row and get the same result both times? Decide before reading the answer below.

```text
A:  scores = scores + 5
B:  curved = scores + 5
C:  df = df.drop(columns="notes")
D:  df["total"] = df["math"] + df["reading"]
```

B and D are safe: they compute something new from inputs they don't change. A adds 5 again on every run. C crashes on the second run with `KeyError`, because `notes` is already gone, which at least tells you something is wrong. A fails silently, and that makes it the worst of the four.

### Exercise 1: Make a sampled average repeatable

```python run
homework = pd.DataFrame({"minutes": np.random.default_rng(31).gamma(4, 12, 2000).round()})

def average_of_sample(df, n=30):
    return df.sample(n)["minutes"].mean()
```

`average_of_sample` gives a different answer every time it's called. Add a `seed` parameter so the same seed always gives the same answer, and prove it with an `assert`. Then call it with seeds 0 to 49 and print the lowest and highest result next to the true average of all 2,000 rows.

Sample output: `Seeds 0-49: lowest __, highest __, true average __`.

:::hint
`DataFrame.sample` takes `random_state=`. Pass the seed through to it. A dictionary or list comprehension over `range(50)` collects the 50 results.
:::

:::solution
```python run
def average_of_sample(df, n=30, seed=0):
    return df.sample(n, random_state=seed)["minutes"].mean()

assert average_of_sample(homework, seed=4) == average_of_sample(homework, seed=4)

results = pd.Series([average_of_sample(homework, seed=s) for s in range(50)])
print(f"Seeds 0-49: lowest {results.min():.1f}, highest {results.max():.1f}, "
      f"true average {homework['minutes'].mean():.1f}")
```

The assertion proves repeatability, and the range shows that two perfectly reproducible analyses with different seeds can disagree by many minutes. A sample of 30 is small; reporting the range keeps readers from over-trusting any single run.
:::

### Exercise 2: Survive Restart session and run all

Jamal's notebook worked all week. After a restart, **Run all** crashes at the second cell. Here are his cells in page order:

```python run raises
# Cell 1
club_dues = pd.DataFrame({"member": ["Ana", "Ben", "Cy", "Dee"], "paid": [20, 0, 20, 15]})

# Cell 2
print(f"Collected ${club_total} from {len(club_dues)} members")

# Cell 3
club_total = club_dues["paid"].sum()
unpaid = club_dues.loc[club_dues["paid"] == 0, "member"].tolist()

# Cell 4
print("Still owe dues:", ", ".join(unpaid))
```

Explain why it worked before the restart, then fix the notebook so it runs top to bottom on a fresh runtime. Add an `assert` that would catch a negative payment.

:::hint
Jamal ran Cell 3 at some point last week, so `club_total` was already in memory when he edited Cell 2. Every cell may only use names created *above* it.
:::

:::solution
```python run
# Cell 1: data
club_dues = pd.DataFrame({"member": ["Ana", "Ben", "Cy", "Dee"], "paid": [20, 0, 20, 15]})
assert (club_dues["paid"] >= 0).all(), "a payment is negative"

# Cell 2: calculations
club_total = club_dues["paid"].sum()
unpaid = club_dues.loc[club_dues["paid"] == 0, "member"].tolist()

# Cell 3: report
print(f"Collected ${club_total} from {len(club_dues)} members")
print("Still owe dues:", ", ".join(unpaid))
```

Before the restart, `club_total` existed in memory from an earlier run of the calculation cell, so the print worked even though it sat above the line that creates `club_total`. Ordering the cells as data, then calculations, then report means each one only depends on cells above it.
:::

### Exercise 3: Replace the hand-typed numbers

A reporter typed this summary last month. The data has since been updated.

```python run
fundraiser = pd.DataFrame({
    "club": ["Robotics", "Drama", "Chess", "Art", "Debate"],
    "raised": [1240, 860, 310, 975, 640],
    "goal": [1000, 1200, 400, 900, 800],
})
typed_summary = "Robotics raised the most ($1,180). 3 of 5 clubs met their goal, and the total was $3,890."
```

Write a function `fundraiser_summary(df)` that builds the same three facts from the data, then print both versions. How many of the typed numbers are now wrong?

:::hint
`df.loc[df["raised"].idxmax()]` gives the top row. `(df["raised"] >= df["goal"]).sum()` counts goals met. Format money with `f"${value:,}"`.
:::

:::solution
```python run
def fundraiser_summary(df):
    top = df.loc[df["raised"].idxmax()]
    met = int((df["raised"] >= df["goal"]).sum())
    return (f"{top['club']} raised the most (${top['raised']:,}). {met} of {len(df)} clubs "
            f"met their goal, and the total was ${df['raised'].sum():,}.")

print("Typed:   ", typed_summary)
print("Computed:", fundraiser_summary(fundraiser))
```

All three facts changed: the top amount, the number of clubs that met their goal, and the total. Nobody would have noticed, because a typed sentence never complains when the data under it moves. The computed version updates on every run.
:::

### Exercise 4: Report every data problem at once

An `assert` stops at the first failure, which means fixing problems one rerun at a time. Write a function `check_survey(df)` that runs all of these checks and returns a list of the ones that fail, so you see everything in one run:

- `student_id` has no duplicates
- `grade` is between 9 and 12
- `sleep_hours` is between 0 and 16
- no column has missing values

```python run
survey = pd.DataFrame({
    "student_id": [1, 2, 3, 4, 5, 5],
    "grade": [9, 10, 13, 11, 12, 12],
    "sleep_hours": [7.5, 8.0, 6.5, None, 7.0, 7.0],
})
```

Sample output: one line per failed check, then a final `assert` that stops the notebook if the list isn't empty.

:::hint
Build a dictionary that maps each check's description to a `True`/`False` result, then keep the descriptions whose result is `False`. Comparisons with `NaN` are `False`, so test for missing values separately with `.isna()`.
:::

:::solution
```python run raises
def check_survey(df):
    checks = {
        "student_id has no duplicates": df["student_id"].is_unique,
        "grade is between 9 and 12": df["grade"].between(9, 12).all(),
        "sleep_hours is between 0 and 16": df["sleep_hours"].dropna().between(0, 16).all(),
        "no missing values": not df.isna().any().any(),
    }
    return [name for name, passed in checks.items() if not passed]

problems = check_survey(survey)
for problem in problems:
    print("FAILED:", problem)
assert not problems, f"{len(problems)} data checks failed"
```

Three checks fail: a duplicated ID, a grade of 13, and a missing sleep value. The printout lists all three before the `AssertionError` stops the notebook. Notice the sleep-hours check uses `dropna()` so a missing value is reported once, by the check designed for it, rather than also making the range check fail.
:::

### Exercise 5: A titled chart and a predictable file name

Draw a bar chart of the fundraiser from Exercise 3 with bars from zero, a short black goal marker for each club, and a title computed from the data. Then write `figure_filename(number, description)` that turns `(2, "Fundraiser: raised vs. goal!")` into `fig02_fundraiser_raised_vs_goal.png`, and test it with `assert`.

:::hint
For the goal markers, `ax.scatter(x, goals, marker="_", s=900)` draws a wide horizontal tick. For the file name, lowercase the text, then `re.sub(r"[^a-z0-9]+", "_", text).strip("_")` replaces every run of other characters with one underscore.
:::

:::solution
```python run alt="Bar chart of money raised by five clubs with a short black tick marking each club's goal. Robotics at $1,240 and Art at $975 are above their goals; Drama, Chess, and Debate fall short. Title: 2 of 5 clubs met their goal; Robotics led with $1,240." caption="Bars from zero, goals marked, finding in the title"
def figure_filename(number, description, ext="png"):
    slug = re.sub(r"[^a-z0-9]+", "_", description.lower()).strip("_")
    return f"fig{number:02d}_{slug}.{ext}"

assert figure_filename(2, "Fundraiser: raised vs. goal!") == "fig02_fundraiser_raised_vs_goal.png"
assert figure_filename(11, "Bus delays", "svg") == "fig11_bus_delays.svg"

met = fundraiser["raised"] >= fundraiser["goal"]
top = fundraiser.loc[fundraiser["raised"].idxmax()]
x = np.arange(len(fundraiser))
fig, ax = plt.subplots(figsize=(7, 3.8))
bars = ax.bar(x, fundraiser["raised"], color=[BLUE if m else MUTED for m in met], width=0.6)
ax.scatter(x, fundraiser["goal"], marker="_", s=900, color=INK, linewidths=2, zorder=3)
ax.bar_label(bars, labels=[f"${v:,}" for v in fundraiser["raised"]], padding=3, color=INK)
ax.set_xticks(x, fundraiser["club"])
ax.set_ylim(0, 1450)
ax.set_ylabel("Raised (US dollars)")
ax.set_title(f"{met.sum()} of {len(fundraiser)} clubs met their goal; {top['club']} led with ${top['raised']:,}", loc="left")
print("Would save as:", figure_filename(2, "Fundraiser: raised vs. goal!"))
```

Two-digit numbering (`fig02`) keeps files in order when sorted by name, even past `fig09`. Blue bars mark clubs that met their goal; the black ticks carry the goals themselves, so the chart reads correctly in grayscale.
:::

### Exercise 6: Generate an executive summary

Write `executive_summary(question, findings, limits)` where `findings` and `limits` are lists of strings. It should return text with the question on the first line, the findings as a numbered list, and the limits as a single sentence starting with "Limits:". Use it with findings computed from `fundraiser`.

:::hint
`"\n".join(f"{i}. {text}" for i, text in enumerate(findings, start=1))` builds the numbered list. Join the limits with `"; "`.
:::

:::solution
```python run
def executive_summary(question, findings, limits):
    numbered = "\n".join(f"{i}. {text}" for i, text in enumerate(findings, start=1))
    return f"QUESTION: {question}\n{numbered}\nLimits: {'; '.join(limits)}."

short = fundraiser[fundraiser["raised"] < fundraiser["goal"]]
findings = [
    f"{int((fundraiser['raised'] >= fundraiser['goal']).sum())} of {len(fundraiser)} clubs met their goal.",
    f"Together the clubs raised ${fundraiser['raised'].sum():,} against goals of ${fundraiser['goal'].sum():,}.",
    f"The largest shortfall was {short.loc[(short['goal'] - short['raised']).idxmax(), 'club']}, "
    f"${(short['goal'] - short['raised']).max():,} below its goal.",
]
limits = ["one fundraiser season", "goals were set by each club, so they aren't equally ambitious"]
print(executive_summary("Did the clubs meet their fundraising goals?", findings, limits))
```

The function only handles layout; every number arrives already computed. Keeping the wording (your judgment) separate from the numbers (the data) means you can rewrite a sentence without risk of changing a figure.
:::

### Challenge: How much does the answer depend on the seed?

A study team estimates the share of students who walk to school by surveying a random 60 of the school's 900 students. Write `run_analysis(seed)` that draws the sample with that seed and returns the walking share as a percent. Run it for seeds 0 to 199, draw a histogram of the 200 results with the true share marked, and print the range that holds the middle 95% of results.

```python run
students = pd.DataFrame({"walks": np.random.default_rng(8).random(900) < 0.35})
```

:::hint
`np.percentile(results, [2.5, 97.5])` gives the bounds of the middle 95%. Mark the truth with `ax.axvline`. A sample of 60 can only produce shares that are multiples of 1/60, so give each possible count its own bin; equal-width bins of a round size would make some bars look taller just because they cover two possible values.
:::

:::solution
```python run alt="Histogram of 200 estimated walking shares, one per seed, ranging from about 20 to 50 percent and centered on a dashed line at the true share of about 34 percent." caption="Each bar counts seeds that gave that estimate"
def run_analysis(seed, n=60):
    return students.sample(n, random_state=seed)["walks"].mean() * 100

results = np.array([run_analysis(seed) for seed in range(200)])
low, high = np.percentile(results, [2.5, 97.5])
truth = students["walks"].mean() * 100

fig, ax = plt.subplots(figsize=(7, 3.4))
one_bar_per_count = (np.arange(8, 34) - 0.5) / 60 * 100
ax.hist(results, bins=one_bar_per_count, color=BLUE, edgecolor="white")
ax.axvline(truth, color=INK, linestyle="--", linewidth=1)
ax.annotate(f"true share {truth:.1f}%", (truth, 1), xycoords=("data", "axes fraction"),
            xytext=(5, -12), textcoords="offset points", color=INK)
ax.set_xlabel("Estimated share who walk (%)")
ax.set_ylabel("Seeds")
print(f"Seed 0 alone says {results[0]:.1f}%. Middle 95% of seeds: {low:.1f}% to {high:.1f}%. Truth: {truth:.1f}%.")
```

A single seed gives one number with false precision. The spread across seeds shows that with only 60 students, an honest report sounds like "about a third walk, give or take 12 points." This range is close to what a statistician would call a confidence interval, and you got it with nothing but a loop and a seed.
:::
