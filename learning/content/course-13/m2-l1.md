The student council ran a sleep and screen-time survey and exported the answers as a CSV file. You load it and ask the simplest possible question, the average hours of sleep:

```python run raises
import io
import pandas as pd

pd.set_option("display.width", 110)   # print wide tables on one line
pd.set_option("display.max_columns", 12)

csv_text = """student_id,grade,sleep_hours,screen_hours,phone_in_bedroom,club
S01,9,7.5,4,yes,robotics
S02,10,6,5.5,yes,
S03,9,8,2,no,band
S04,11,7 hrs,6,yes,soccer
S05,12,5.5,7,yes,
S06,10,9,1.5,no,band
S07,11,,3,no,debate
S08,12,6.5,8+,yes,soccer
S09,9,8,3.5,no,robotics
S10,10,7,4,yes,debate
S11,11,N/A,5,yes,
S12,12,6,6.5,yes,band
"""
survey = pd.read_csv(io.StringIO(csv_text))
print(survey["sleep_hours"].mean())
```

The last line of the error is the clue: `can only concatenate str`. pandas tried to add up the sleep hours and found **strings**. The column looks like numbers on screen, but pandas loaded it as text, so "averaging" it meant gluing words together. This lesson is about catching that before it bites. (`io.StringIO` wraps a string so `read_csv` can treat it like a file. With a real file you'd pass its name instead.)

## A CSV file is only text

Open any CSV in a text editor and you'll see what it really is: lines of characters, with commas between values and the first line naming the columns. Nothing in the file says "this column holds numbers". Here is a tiny CSV reader written in plain Python. Step through it and watch the type of every value:

:::trace Every value comes out of a CSV as a string
```python
text = "name,hours\nAva,7.5\nBo,8"
rows = []
for line in text.split("\n"):
    cells = line.split(",")
    rows.append(cells)
print(rows)
print(type(rows[1][1]))
```
:::

`'7.5'` is the three characters 7, dot, 5, not the number 7.5. `pd.read_csv` does the same splitting, then makes an extra pass over **each column**: if every value in the column can be read as a whole number, the column becomes `int64`; if they all read as decimals, `float64`; otherwise the column stays as text, which pandas calls `object`. A handful of strings, including an empty cell, `NA`, `N/A`, `NaN`, and `null`, are treated as missing and become `NaN` ("not a number"), the marker pandas uses for a missing value.

That explains the crash. `sleep_hours` contains `7 hrs`, which isn't a number, so the whole column stayed as text.

## JSON keeps numbers, true/false, and nesting

The same survey app can also export **JSON**. JSON writes numbers without quotes, has real `true`/`false` and `null` values, and can nest one record inside another or hold a list:

```python run
import json

json_text = """[
  {"student_id": "S01", "grade": 9, "sleep": {"hours": 7.5, "bedtime": "22:45"},
   "screen_hours": 4, "phone_in_bedroom": true, "clubs": ["robotics"]},
  {"student_id": "S02", "grade": 10, "sleep": {"hours": 6, "bedtime": "23:50"},
   "screen_hours": 5.5, "phone_in_bedroom": true, "clubs": []},
  {"student_id": "S03", "grade": 9, "sleep": {"hours": null, "bedtime": "22:10"},
   "screen_hours": 2, "phone_in_bedroom": false, "clubs": ["band", "debate"]}
]"""

records = json.loads(json_text)       # a list of Python dicts
app = pd.json_normalize(records)      # one row per record, nested keys flattened
print(app)
print(app.dtypes)
```

`json_normalize` turned the nested `sleep` object into two columns, `sleep.hours` and `sleep.bedtime`. Because JSON numbers aren't quoted, `screen_hours` arrived as `float64` with no guessing, `phone_in_bedroom` is a real `bool`, and `null` became `NaN`. The `clubs` lists stay as lists inside single cells, which you'd handle later by counting them or splitting them out.

| | CSV | JSON |
| --- | --- | --- |
| Shape | Flat grid: rows and columns | Records, which can nest and hold lists |
| Types | Everything is text; pandas guesses | Numbers, strings, `true`/`false`, `null` are explicit |
| Missing values | Empty cell or text like `N/A` | `null`, or the key is left out |
| Size | Small: names appear once, in the header | Bigger: every record repeats every key |
| Load with | `pd.read_csv` | `pd.json_normalize(json.loads(...))` or `pd.read_json` |

`pd.read_json` works well for flat JSON. For nested records like these, it would leave whole dictionaries sitting in a `sleep` column, so `json_normalize` is the better tool.

## The first-look checklist

Every time you load a dataset, run the same few checks before you calculate anything. Back to the CSV export:

```python run
print(survey.shape)          # (rows, columns)
print(survey.head(3))        # the first rows: did the columns line up?
print(survey.dtypes)         # what type pandas chose for each column
```

`grade` is `int64`, as it should be. But `sleep_hours` and `screen_hours`, which are obviously numbers, are `object`. Two numeric columns loaded as text is the single most common problem in real data. `info()` puts types and missing values side by side:

```python run
survey.info()
```

The **Non-Null Count** column says `sleep_hours` has 10 real values out of 12 (the empty cell and `N/A` became `NaN`), and `club` is missing for 3 students. Notice that `info()` prints its report itself, so you call it without `print`.

Now watch `describe()`, which summarizes numeric columns:

```python run
print(survey.describe())
print(survey["phone_in_bedroom"].value_counts())
```

`describe()` reported only `grade`. It didn't complain about sleep or screen time; it **silently skipped them**, because they're text. If you'd only looked at this table you might never notice two columns were missing. `value_counts()` is the matching tool for categories: 8 students keep a phone in the bedroom, 4 don't.

## Find the values that turn a column into text

`pd.to_numeric(..., errors="coerce")` converts what it can and replaces anything unreadable with `NaN`. Comparing before and after shows exactly which values are the problem:

```python run
for column in ["sleep_hours", "screen_hours"]:
    converted = pd.to_numeric(survey[column], errors="coerce")
    broke = converted.isna() & survey[column].notna()   # missing now, but not before
    print(column, "->", survey.loc[broke, column].tolist())
```

Two culprits: `7 hrs` and `8+`. Each one needs a human decision. `7 hrs` clearly means 7. `8+` means "at least 8", which isn't the same as 8. You'll fix values like these properly in Module 4. For now, look at what's left once they're set aside:

```python run alt="Two charts side by side. Left: a histogram of 9 usable sleep answers between 5.5 and 9 hours, most between 6 and 8. Right: a bar chart of values that are missing or unreadable per column: sleep_hours 3, club 3, screen_hours 1, the other columns 0."
import matplotlib.pyplot as plt
from matplotlib.ticker import MaxNLocator

sleep = pd.to_numeric(survey["sleep_hours"], errors="coerce")
unusable = survey.isna().sum()
unusable["sleep_hours"] = sleep.isna().sum()
unusable["screen_hours"] = pd.to_numeric(survey["screen_hours"], errors="coerce").isna().sum()

fig, (left, right) = plt.subplots(1, 2, figsize=(9, 3.2))
left.hist(sleep.dropna(), bins=[5, 6, 7, 8, 9, 10], color="#2a78d6", edgecolor="white")
left.set_title(f"Sleep hours ({sleep.notna().sum()} usable answers)")
left.set_xlabel("Hours")
left.set_ylabel("Students")
unusable.sort_values().plot(kind="barh", ax=right, color="#eb6834")
right.set_title("Missing or unreadable values")
right.set_xlabel("Rows")
left.yaxis.set_major_locator(MaxNLocator(integer=True))   # whole numbers on the axis
right.xaxis.set_major_locator(MaxNLocator(integer=True))
fig.tight_layout()
```

The right-hand chart is worth making for every new dataset. A quarter of the sleep answers can't be used yet, which matters a lot more than any average you compute from the rest.

:::warning
**Three loading mistakes to recognize on sight.**

-   **Everything lands in one column.** The file uses semicolons, common in countries where the comma is the decimal mark. `df.shape` shows 1 column and the header is one long string like `student_id;grade;sleep_hours`. Fix: `pd.read_csv(path, sep=";")`, adding `decimal=","` if numbers look like `7,5`.
-   **The first data row became the header.** Some exports have no header line, so pandas used the first row's values as column names. Fix: `header=None`, then set `df.columns = [...]` yourself.
-   **`df.info` without parentheses** prints a description of the method instead of the report. Methods need `()`; attributes like `shape` and `dtypes` don't.
:::

:::quiz
Q: A column of prices loads as `object`. What's the most likely reason?
- [ ] The prices have decimals
  Decimals load fine as `float64`.
- [x] At least one value can't be read as a number, such as `$4.50` or `free`
  One unreadable value keeps the whole column as text.
- [ ] Some prices are missing
  Missing values become `NaN`, and the column stays numeric (as `float64`).

Q: You run `survey.describe()` on a table with five number-like columns, and it reports only two of them. What should you check next?
- [ ] Nothing; `describe()` only ever shows two columns
  It shows every numeric column. Fewer than expected is a warning sign.
- [x] `survey.dtypes`, to see which columns loaded as `object`
  `describe()` skips text columns without saying so.
- [ ] Whether the file is JSON
  The file format doesn't change what `describe()` reports for a DataFrame.

Q: Which export would load `phone_in_bedroom` as a real `bool` with no extra work?
- [ ] The CSV, because `yes` and `no` are booleans
  To `read_csv`, `yes` and `no` are just text.
- [x] The JSON, because it stores `true` and `false` as values
  JSON has a boolean type, and pandas keeps it.
- [ ] Neither; pandas has no boolean type
  pandas has `bool`, as `app.dtypes` showed.
:::

:::takeaways
- A CSV is text. `read_csv` guesses each column's type, and one unreadable value keeps the whole column as `object`.
- JSON stores real numbers, booleans, and `null`, and can nest; `pd.json_normalize` flattens nested records into columns.
- First look, every time: `shape`, `head()`, `dtypes`, `info()`, `describe()`, `value_counts()`, `isna().sum()`.
- `describe()` skips text columns silently, so compare its output with `dtypes`.
- `pd.to_numeric(col, errors="coerce")` finds the values that need a decision.
:::
