A neighborhood group put low-cost air sensors in two areas, Eastside and Northgate, to measure PM2.5, the fine particles in smoke and exhaust, in micrograms per cubic meter. Their first report averaged the readings by neighborhood:

```python run
import io
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

pd.set_option("display.width", 110)

log_text = """sensor,neighborhood,time,pm25
A1,Eastside,2026-08-01 08:00,12.4
A1,Eastside,2026-08-01 09:00,-999
A1,East Side,2026-08-01 10:00,15.1
A2, eastside ,2026-08-01 08:00,
A2,EASTSIDE,2026-08-01 09:00,18.0
A2,EASTSIDE,2026-08-01 09:00,18.0
A2,Eastside,2026-08-01 10:00,16.6
B1,Northgate,2026-08-01 08:00,8.2
B1,Northgate,2026-08-01 09:00,7.9
B1,North Gate,2026-08-01 10:00,9.4 ug
B2,Northgate,2026-08-01 08:00,6.5
B2,northgate,2026-08-01 09:00,1450
B2,Northgate,2026-08-01 10:00,7.1
"""
air = pd.read_csv(io.StringIO(log_text))
first_try = pd.to_numeric(air["pm25"], errors="coerce")
print(first_try.groupby(air["neighborhood"]).mean().round(1))
```

Two neighborhoods became seven. One "average" is negative, which is impossible for a count of particles. One is 1,450, which would mean the air was unbreathable, and two are `NaN`. The code ran without a single error. Every one of these numbers comes from a data problem the code quietly accepted. This lesson fixes them one at a time, and each fix is a decision you should be able to explain.

## Fix the types first

The `pm25` column loaded as text, because one reading says `9.4 ug`. You can't compare text with numbers, so types come first. The obvious fix fails loudly:

```python run raises
air["pm25"].astype(float)
```

`astype` is strict: one bad value and the whole conversion stops. That's useful, because the error names the culprit. Strip the unit, then convert with `to_numeric`, and convert the time column too:

```python run
air["pm25_num"] = pd.to_numeric(air["pm25"].str.replace("ug", "").str.strip(), errors="coerce")
air["time"] = pd.to_datetime(air["time"])
print(air.dtypes)
```

The result goes into a **new** column, `pm25_num`, and the original stays untouched. That keeps the cell safe to run twice, and lets you compare raw and clean values side by side later.

## Missing values come in disguises

pandas knows a value is missing only if it's `NaN` (or `None`). Real data hides missing values in other forms: an empty string, `N/A`, `0`, or a **sentinel** like `-999`, a number deliberately chosen to be impossible so it means "no reading". Sensor A1's `-999` is a sentinel. Left alone, it gets averaged as if it were real air:

```python run
air["pm25_num"] = air["pm25_num"].replace(-999, np.nan)
print("Missing readings:", air["pm25_num"].isna().sum(), "of", len(air))
print("mean:", air["pm25_num"].mean().round(1), "| count:", air["pm25_num"].count(), "| len:", len(air))
```

Notice `count()` is smaller than `len()`. Statistics like `mean`, `sum`, and `median` **skip `NaN` by default**, so the mean here is the average of the 11 readings that exist (still inflated by the 1,450 reading, which you'll deal with below). That default is usually what you want, but it's silent. When a quarter of a group's readings are missing, its average rests on far fewer values than the row count suggests.

You have three choices for each gap, and each one changes the answer:

| Choice | Code | When it's reasonable |
| --- | --- | --- |
| Leave it as `NaN` | (do nothing) | Most of the time; statistics skip it, so report how many are missing |
| Drop the row | `df.dropna(subset=["pm25_num"])` | The row is useless without that value |
| Fill it | `df["pm25_num"].fillna(value)` | You have a defensible value, like the same sensor's previous reading |

Filling with `0` is almost never right for a measurement. Zero particles is a real (and remarkable) reading, not a stand-in for "unknown", and it drags every average down.

## Duplicates: exact and by key

Sensor A2 uploaded its 09:00 reading twice. `duplicated()` marks every row that repeats an earlier one exactly:

```python run
print(air[air.duplicated(keep=False)])           # keep=False shows both copies
print("Exact duplicates:", air.duplicated().sum())
print("Same sensor and time:", air.duplicated(subset=["sensor", "time"]).sum())
air = air.drop_duplicates(subset=["sensor", "time"], keep="first")
print("Rows left:", len(air))
```

Checking a **key** (here, sensor plus time) is stricter and usually more useful than exact matching. A sensor can only produce one reading per hour, so two rows with the same key are a duplicate even if one has a typo in another column. `keep="first"` keeps the earliest copy; `keep="last"` keeps the latest, which is the right choice when later uploads are corrections.

## Make category names agree

To a computer, `Eastside`, `EASTSIDE`, `East Side`, and ` eastside ` are four different strings. Step through the normalizing recipe on three of them:

:::trace Three spellings become one key
```python
raw = [" eastside ", "EASTSIDE", "East Side"]
keys = []
for name in raw:
    name = name.strip()
    name = name.lower()
    name = name.replace(" ", "")
    keys.append(name)
print(keys)
```
:::

pandas applies the same three steps to a whole column with the `.str` methods, and a small dictionary maps each key to the display name you want:

```python run alt="Two bar charts. Before: seven distinct neighborhood spellings, the largest being Northgate with 4 rows and Eastside with 3. After: two neighborhoods, Eastside with 6 rows and Northgate with 6 rows."
key = air["neighborhood"].str.strip().str.lower().str.replace(" ", "")
air["area"] = key.map({"eastside": "Eastside", "northgate": "Northgate"})
print("Unmapped:", air.loc[air["area"].isna(), "neighborhood"].tolist())

fig, (before, after) = plt.subplots(1, 2, figsize=(9, 3), sharex=True)
air["neighborhood"].value_counts().sort_values().plot(kind="barh", ax=before, color="#eb6834")
before.set_title("Before: 7 spellings")
air["area"].value_counts().sort_values().plot(kind="barh", ax=after, color="#2a78d6")
after.set_title("After: 2 neighborhoods")
for ax in (before, after):
    ax.set_ylabel("")
    ax.set_xlabel("Rows")
fig.tight_layout()
```

`map` turns any key that isn't in the dictionary into `NaN`, so printing the unmapped names is a free safety check. If next month's file says `Eastsde`, it shows up here instead of silently forming its own group.

## Impossible values and outliers are different things

An **impossible** value breaks a rule of the world or the instrument. PM2.5 can't be negative, and this sensor model can't report above 1,000. Those values are errors, so they become `NaN`:

```python run
impossible = (air["pm25_num"] < 0) | (air["pm25_num"] > 1000)
print(air.loc[impossible, ["sensor", "time", "pm25_num"]])
air.loc[impossible, "pm25_num"] = np.nan
print(air.groupby("area")["pm25_num"].agg(["mean", "count"]).round(1))
```

Two clean neighborhoods, believable averages, and a `count` column that admits how many readings each average rests on. Compare that with the seven-row table at the top.

An **outlier** is different: a value far from the rest that might be perfectly real. A common rule flags values more than 1.5 × IQR beyond the middle half of the data (the IQR, or interquartile range, is the distance between the 25th and 75th percentiles). Here's a month of daily averages from both areas, including two days of wildfire smoke:

```python run alt="Box plot of daily PM2.5 for August in two neighborhoods. Eastside's box sits around 14 to 19, Northgate's around 7 to 10. Each has two outlier points far above, between about 60 and 88, from the two smoke days."
rng = np.random.default_rng(8)
daily = pd.DataFrame({
    "Eastside": rng.normal(16, 3, 31).round(1),
    "Northgate": rng.normal(8.5, 2, 31).round(1),
})
daily.iloc[[19, 20]] = [[88.0, 71.5], [64.2, 59.8]]    # wildfire smoke, Aug 20-21

for area in daily:
    q1, q3 = daily[area].quantile([0.25, 0.75])
    fence = q3 + 1.5 * (q3 - q1)
    flagged = daily.loc[daily[area] > fence, area]
    print(f"{area}: upper fence {fence:.1f}, flagged days {list(flagged.index + 1)}")

ax = daily.plot(kind="box", figsize=(5.5, 3.4), color="#2a78d6")
ax.set_ylabel("Daily PM2.5 (µg/m³)")
ax.set_title("August daily averages")
```

The rule flags August 20 and 21 in both places. Deleting them would erase the most important days of the month: the smoke was real, and those are the days people needed to stay inside. **Flag outliers and investigate; delete only values that are impossible.** When an outlier is real but distorts a summary, report the median alongside the mean, or report results with and without it.

## Tidy data: one row per observation

Cleaning includes shape. Data is **tidy** when each variable is a column, each observation is a row, and each value sits in one cell. Spreadsheets often spread one variable across many columns:

```python run
wide = pd.DataFrame({"area": ["Eastside", "Northgate"],
                     "Jun": [14.2, 8.1], "Jul": [16.8, 9.0], "Aug": [21.5, 12.3]})
tidy = wide.melt(id_vars="area", var_name="month", value_name="pm25")
print(wide)
print(tidy)
```

In `wide`, "month" is hidden in the column names, so a question like "average PM2.5 per month" needs a different line of code for every column. `melt` turns those columns into rows. Now `month` is an ordinary column, and `groupby("month")`, filtering, and plotting all just work.

:::warning
**Three cleaning bugs that don't raise errors.**

-   `air.drop_duplicates()` on its own line returns a new DataFrame and changes nothing. Assign it: `air = air.drop_duplicates()`.
-   `df.dropna()` with no `subset` drops a row if **any** column is missing, including columns you don't care about. Name the column: `dropna(subset=["pm25_num"])`.
-   `fillna(0)` on a measurement invents a reading of zero. Leave it missing unless you can defend the fill value.
:::

:::quiz
Q: A column has the values `[10, 20, NaN, 30]`. What does `.mean()` return?
- [ ] `15.0`
  That divides 60 by 4, treating the missing value as 0.
- [x] `20.0`
  `NaN` is skipped by default, so it's 60 divided by the 3 real values.
- [ ] `NaN`
  That happens only with `mean(skipna=False)`.

Q: A temperature column contains `-99` on days the sensor was offline. What should you do first?
- [x] Replace `-99` with `NaN`, because it's a code for "no reading"
  Sentinels must become real missing values before any statistics are computed.
- [ ] Drop the column
  The other readings are fine; only the sentinel values are the problem.
- [ ] Keep it; cold days happen
  Check the documentation: an exact repeated value like `-99` is a code, not weather.

Q: A box plot flags three very high pollution days. Which action is right?
- [ ] Delete them so the averages look normal
  If they're real, deleting them hides the most important days in the data.
- [x] Check whether they're possible and explained; keep real ones, and report the median or results with and without them
  Outliers are worth investigating, not automatically removing.
- [ ] Replace them with the mean
  That invents data and hides a real event.

Q: Which table is tidy?
- [ ] One row per student, with columns `test1`, `test2`, `test3`
  The variable "test number" is hidden in the column names.
- [x] Columns `student`, `test`, `score`, with one row per student per test
  Each variable is a column and each observation (one score) is a row.
- [ ] One row per test, with a column for each student
  Students, a variable, are spread across columns.
:::

:::takeaways
- Fix types first: `astype` fails loudly on bad values; `to_numeric(errors="coerce")` and `to_datetime` convert what they can.
- Turn disguised missing values (`-999`, `N/A`, `""`) into `NaN`. Statistics skip `NaN` silently, so report `count()` alongside every average.
- Check duplicates by a key (`subset=[...]`) as well as exactly.
- Standardize categories with `.str.strip().str.lower()` plus a mapping, and print anything left unmapped.
- Impossible values are errors; outliers may be real. Flag outliers, investigate them, and keep the real ones.
- Tidy data has one variable per column and one observation per row; `melt` converts wide tables.
:::
