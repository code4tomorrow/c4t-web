## Warm-up

A parent sits at (2, 1) with rotation 180 degrees and scale (1, 1). Its child has local position (1, 0). Where is the child in world space?

Rotating 180 degrees turns the offset (1, 0) into (-1, 0), and adding the parent's position gives **(1, 1)**. If you got (3, 1), you added the local offset without rotating it first.

### Exercise 1: A pulsing coin

Make a yellow Circle named `Coin` and write a `Pulser` component that makes it grow and shrink between its original size and 1.2 times that size, once per second. The inspector should expose the amount and the speed.

Sample result: the coin smoothly breathes in and out, and if you set its scale to (0.5, 0.5, 1) before pressing Play, it pulses between 0.5 and 0.6, not between 1 and 1.2.

:::hint
Store `transform.localScale` once, before anything changes it. Then copy the idea behind `Bobber`: compute a value between 0 and 1 from `Time.time` each frame and set the scale from the stored original, never from last frame's scale.
:::

:::solution
```csharp title="Pulser.cs"
using UnityEngine;

public class Pulser : MonoBehaviour
{
    [SerializeField] private float extraScale = 0.2f;
    [SerializeField] private float pulsesPerSecond = 1f;

    private Vector3 baseScale;

    void Awake()
    {
        baseScale = transform.localScale;
    }

    void Update()
    {
        // Sin goes -1..1; shift it to 0..1.
        float wave = (Mathf.Sin(Time.time * pulsesPerSecond * 2f * Mathf.PI) + 1f) / 2f;
        transform.localScale = baseScale * (1f + extraScale * wave);
    }
}
```

Saving `baseScale` in `Awake` is what makes a half-size coin pulse around half size. Multiplying a `Vector3` by a `float` scales all three axes at once.
:::

### Exercise 2: Why is the tint script crashing?

A teammate wrote this to color the saw's tooth when the game starts, and attached it to the root `Saw` object:

```csharp title="ToothTint.cs"
using UnityEngine;

public class ToothTint : MonoBehaviour
{
    [SerializeField] private Color toothColor = Color.white;

    void Start()
    {
        Transform tooth = transform.Find("Tooth");
        tooth.GetComponent<SpriteRenderer>().color = toothColor;
    }
}
```

It works on most saws but one throws:

```text
NullReferenceException: Object reference not set to an instance of an object
ToothTint.Start () (at Assets/Scripts/ToothTint.cs:10)
```

Explain the cause and make the script safe, using a reference set in the Inspector instead of searching by name.

:::hint
`transform.Find` searches children by exact name. What happens if someone renamed the child on one instance to `Tooth (1)` or deleted it? And what does `Find` return then?
:::

:::solution
`transform.Find("Tooth")` returns `null` when no child has that exact name, and line 10 then calls `GetComponent` on `null`. Renaming a child breaks name searches silently. A serialized reference doesn't care about names:

```csharp title="ToothTint.cs"
using UnityEngine;

public class ToothTint : MonoBehaviour
{
    [SerializeField] private Color toothColor = Color.white;
    [SerializeField] private SpriteRenderer tooth;

    void Start()
    {
        if (tooth == null)
        {
            Debug.LogWarning($"{name} has no tooth assigned", this);
            return;
        }
        tooth.color = toothColor;
    }
}
```

Open `Saw.prefab` and drag its `Tooth` child into the **Tooth** slot once; every instance gets the reference. Passing `this` as the second argument to `Debug.LogWarning` makes the Console highlight the broken object when you click the message.
:::

### Exercise 3: Predict the order for spawned objects

`Spawner` makes a coin when you press **C**. Both scripts log their calls:

```csharp title="Spawner.cs"
using UnityEngine;
using UnityEngine.InputSystem;

public class Spawner : MonoBehaviour
{
    [SerializeField] private GameObject coinPrefab;

    void Update()
    {
        if (Keyboard.current != null && Keyboard.current.cKey.wasPressedThisFrame)
        {
            Debug.Log("Spawner: before Instantiate");
            Instantiate(coinPrefab, Vector3.zero, Quaternion.identity);
            Debug.Log("Spawner: after Instantiate");
        }
    }
}
```

The coin prefab has a `LoggingCoin` script that logs `Awake`, `OnEnable`, and `Start`. Write down the five lines in the order you expect after one press, then test.

:::hint
`Instantiate` doesn't return until the new object exists and is set up. Which of the three calls counts as "setting up", and which one waits until just before the coin's first `Update`?
:::

:::solution
```text
Spawner: before Instantiate
LoggingCoin: Awake
LoggingCoin: OnEnable
Spawner: after Instantiate
LoggingCoin: Start
```

`Awake` and `OnEnable` run inside `Instantiate`, before it returns. `Start` is deferred until just before the coin's first `Update`. This is why it's safe to configure a spawned object right after `Instantiate` returns (for example, setting its speed) and have its `Start` see the new value.
:::

### Exercise 4: A grid of coins

Write `CoinGrid`, which spawns a grid of coin prefabs in `Start`: 5 columns and 3 rows, 1.5 units apart, with the first coin at the spawner's position. Every coin should be a child of the spawner, so moving the spawner moves the whole grid.

Sample Hierarchy after pressing Play:

```text
CoinGrid
  Coin(Clone)
  Coin(Clone)
  ... (15 in total)
```

:::hint
Use one loop inside another, one for rows and one for columns. `Instantiate` has an overload with a fourth argument, the parent `Transform`.
:::

:::solution
```csharp title="CoinGrid.cs"
using UnityEngine;

public class CoinGrid : MonoBehaviour
{
    [SerializeField] private GameObject coinPrefab;
    [SerializeField] private int columns = 5;
    [SerializeField] private int rows = 3;
    [SerializeField] private float spacing = 1.5f;

    void Start()
    {
        for (int row = 0; row < rows; row++)
        {
            for (int col = 0; col < columns; col++)
            {
                Vector3 offset = new Vector3(col * spacing, row * spacing, 0f);
                Instantiate(coinPrefab, transform.position + offset, Quaternion.identity, transform);
            }
        }
    }
}
```

With the parent argument, each clone appears under `CoinGrid` in the Hierarchy. The position argument is still in world space, which is why it adds `transform.position`.
:::

### Exercise 5: Falling rocks on a timer

Make a `Rock` prefab (a gray Square) with a `Faller` script that moves it down at a set speed and destroys it after 4 seconds. Then write `RockSpawner`, which spawns a rock every 1.5 seconds at a random x between -7 and 7, at the spawner's height.

Sample result: rocks rain down at a steady rhythm, and the Hierarchy never holds more than three or so at a time.

:::hint
For the timer, keep a float that counts down by `Time.deltaTime` each frame; when it reaches zero, spawn and reset it. `Destroy(gameObject, 4f)` schedules a destroy for later, so it can go in `Start`. `Random.Range(-7f, 7f)` gives a random float.
:::

:::solution
```csharp title="Faller.cs"
using UnityEngine;

public class Faller : MonoBehaviour
{
    [SerializeField] private float speed = 3f;
    [SerializeField] private float lifetime = 4f;

    void Start()
    {
        Destroy(gameObject, lifetime);
    }

    void Update()
    {
        transform.position += Vector3.down * speed * Time.deltaTime;
    }
}
```

```csharp title="RockSpawner.cs"
using UnityEngine;

public class RockSpawner : MonoBehaviour
{
    [SerializeField] private GameObject rockPrefab;
    [SerializeField] private float secondsBetween = 1.5f;
    [SerializeField] private float halfWidth = 7f;

    private float timer;

    void Update()
    {
        timer -= Time.deltaTime;
        if (timer > 0f) return;

        timer = secondsBetween;
        float x = Random.Range(-halfWidth, halfWidth);
        Instantiate(rockPrefab, new Vector3(x, transform.position.y, 0f), Quaternion.identity);
    }
}
```

Each rock lives 4 seconds and a new one arrives every 1.5, so about three exist at once. `timer` starts at 0, which spawns the first rock immediately.
:::

### Exercise 6: Plan a coin family

Your level needs silver coins worth 1 point and gold coins worth 5. Gold coins are yellow, 1.3 times bigger, and pulse; silver coins are gray and still. Both spin slowly, and both should change together if you later swap the art.

Decide which prefab is the base, which is the variant, and which values live where. Then build it, using a `CoinValue` script with a serialized `int points`.

:::hint
Put everything the two coins share in the base. The variant should hold only differences. Is the `Pulser` a difference or a shared trait?
:::

:::solution
Make `Coin.prefab` the base: Circle sprite, `Spinner` (slow, about -60), `CoinValue` with **Points** 1, gray color. That base *is* the silver coin.

Make `GoldCoin` a variant of it, with these overrides: **Points** 5, yellow color, scale (1.3, 1.3, 1), plus an added `Pulser` component. Because `Pulser` exists only in the variant, it's a difference, not a shared trait.

```csharp title="CoinValue.cs"
using UnityEngine;

public class CoinValue : MonoBehaviour
{
    [SerializeField] private int points = 1;

    public int Points => points;
}
```

Swap the base coin's sprite later and gold coins pick it up too, while keeping their own color, size, and value. `Points` is a read-only property, so other scripts can read a coin's value without being able to change it.
:::

### Challenge: A ring of orbiting saws

Write `SawRing`, which spawns `count` saws evenly spaced on a circle of a given `radius` around the spawner, as its children. Then add a `Spinner` to the spawner itself. The whole ring should rotate while each saw keeps spinning on its own.

Here's where the six saws land for `count = 6` and `radius = 2`. Each saw sits at an angle of `i × 360° / count` from the right-hand side:

```python run alt="Six saw positions spaced 60 degrees apart on a circle of radius 2 around the origin" caption="Saw positions for count = 6, radius = 2"
import math
import matplotlib.pyplot as plt

count, radius = 6, 2.0
xs, ys = [], []
for i in range(count):
    angle = i * 2 * math.pi / count
    xs.append(radius * math.cos(angle))
    ys.append(radius * math.sin(angle))
    print(f"saw {i}: angle {math.degrees(angle):5.1f} deg -> ({xs[-1]:5.2f}, {ys[-1]:5.2f})")

fig, ax = plt.subplots(figsize=(4, 4))
ax.add_patch(plt.Circle((0, 0), radius, fill=False, linestyle="--", color="#888888"))
ax.scatter(xs, ys, s=300, color="#e4572e", zorder=3)
ax.scatter([0], [0], marker="+", s=200, color="#333333")
for i, (x, y) in enumerate(zip(xs, ys)):
    ax.annotate(str(i), (x, y), ha="center", va="center", color="white", fontsize=11)
ax.set_aspect("equal")
ax.set_xlim(-3, 3)
ax.set_ylim(-3, 3)
ax.set_title("SawRing: count = 6, radius = 2")
```

:::hint
Unity's `Mathf.Cos` and `Mathf.Sin` take radians, so convert with `Mathf.PI` (or multiply degrees by `Mathf.Deg2Rad`). Spawn each saw at `transform.position` plus the offset, and pass `transform` as the parent so the ring's rotation carries the saws around.
:::

:::solution
```csharp title="SawRing.cs"
using UnityEngine;

public class SawRing : MonoBehaviour
{
    [SerializeField] private GameObject sawPrefab;
    [SerializeField] private int count = 6;
    [SerializeField] private float radius = 2f;

    void Start()
    {
        for (int i = 0; i < count; i++)
        {
            float angle = i * 2f * Mathf.PI / count;
            Vector3 offset = new Vector3(Mathf.Cos(angle), Mathf.Sin(angle), 0f) * radius;
            Instantiate(sawPrefab, transform.position + offset, Quaternion.identity, transform);
        }
    }
}
```

Give the `SawRing` object a `Spinner` with a slow speed such as 45. Two rotations now stack: the ring's `Spinner` turns the parent, which carries every child around the circle, and each saw's own `Spinner` turns it in place. Neither script knows about the other.
:::
