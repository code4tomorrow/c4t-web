## Warm-up: which event fires?

For each pair, decide whether Unity calls `OnCollisionEnter2D`, `OnTriggerEnter2D`, or nothing.

| Pair | Your prediction |
| --- | --- |
| Player (Dynamic body, capsule) lands on Ground (Box Collider 2D, no body) | |
| Player touches a Coin (trigger, no body) | |
| A Coin overlaps a Saw (both triggers, no bodies) | |
| A falling crate (Dynamic body, box) hits a Saw (trigger, no body) | |

Answers: collision; trigger; **nothing** (neither has a Rigidbody 2D); trigger, where `Hazard` sees the crate isn't tagged `Player` and ignores it.

### Exercise 1: Falling off the world

Split `Ground` into two pieces with a 3-unit gap between them, somewhere past the first saws. Now make falling into the gap send the player back to the start. Try to do it **without writing any new code**.

Sample result: you walk into the gap, fall for a moment, and reappear at the spawn point with no velocity.

:::hint
What does `Hazard` actually check? It doesn't care what shape the trigger is or whether it looks like a saw.
:::

:::solution
Create an empty `KillZone` at (10, -9, 0) with a **Box Collider 2D** of **Size** (60, 2), tick **Is Trigger**, and add the existing `Hazard` component. `Hazard` only asks "did the Player enter my trigger?", so it works for saws, pits, or lava. Keep the zone below the camera bounds so players never see it.
:::

### Exercise 2: Hold to jump higher

In most platformers, tapping jump gives a small hop and holding it gives a full jump. Add this to `PlayerController`: if Space is released while the player is still rising, cut the upward velocity in half.

Sample result: a quick tap clears about a quarter of the height of a held jump; a held jump still reaches about 2.45 units.

:::hint
Releasing is a one-frame event, just like pressing, so detect it in `Update` with `wasReleasedThisFrame` and act on it in `FixedUpdate`. Only cut while `velocity.y > 0`, or releasing during a fall would slow the fall.
:::

:::solution
Add a field and a flag:

```csharp
[SerializeField, Range(0f, 1f)] private float jumpCutMultiplier = 0.5f;

private bool jumpCutQueued;
```

In `Update`, after the jump-press line:

```csharp
if (keyboard.spaceKey.wasReleasedThisFrame) jumpCutQueued = true;
```

In `FixedUpdate`, right after the line that sets `velocity.y = jumpSpeed`:

```csharp
if (jumpCutQueued && velocity.y > 0f) velocity.y *= jumpCutMultiplier;
jumpCutQueued = false;
```

Height grows with the square of launch speed, so half the speed gives a quarter of the height. Jumping before cutting means even a tap shorter than one physics step still gives a small hop.
:::

### Exercise 3: Coyote time

Players often press jump a moment *after* running off a ledge, and the game ignores them because they're no longer grounded. Add **coyote time**: the player may still jump for 0.1 seconds after leaving the ground.

Sample result: run off Platform B and press Space just after the edge. The player jumps instead of falling.

:::hint
Keep a `coyoteTimer`. In `FixedUpdate`, refill it to 0.1 while grounded, and count it down with `Time.fixedDeltaTime` otherwise. Jump when the timer is above zero instead of when `isGrounded` is true, and empty the timer when you jump.
:::

:::solution
```csharp
[SerializeField] private float coyoteTime = 0.1f;

private float coyoteTimer;
```

In `FixedUpdate`:

```csharp
isGrounded = Physics2D.OverlapCircle(groundCheck.position, groundCheckRadius, groundLayer) != null;
coyoteTimer = isGrounded ? coyoteTime : coyoteTimer - Time.fixedDeltaTime;

Vector2 velocity = rb.linearVelocity;
velocity.x = moveInput * moveSpeed;
if (jumpQueued && coyoteTimer > 0f)
{
    velocity.y = jumpSpeed;
    coyoteTimer = 0f;
}
jumpQueued = false;
```

Emptying `coyoteTimer` on a jump stops a second press in the next 0.1 seconds from jumping again in mid-air.
:::

### Exercise 4: A jump buffer

The opposite problem: the player presses jump a moment *before* landing, the press is dropped, and the player lands without jumping. Replace `jumpQueued` with a **jump buffer** that remembers a press for 0.1 seconds. Keep coyote time working.

Sample result: tap Space just before touching down and the player bounces straight back up.

:::hint
Instead of a bool that's cleared every physics step, store a `jumpBufferTimer`. Set it to 0.1 when Space is pressed, count it down every frame in `Update`, and jump in `FixedUpdate` when both timers are above zero. Then empty both.
:::

:::solution
Replace `private bool jumpQueued;` with:

```csharp
[SerializeField] private float jumpBufferTime = 0.1f;

private float jumpBufferTimer;
```

In `Update`, replace the jump-press line:

```csharp
jumpBufferTimer -= Time.deltaTime;
if (keyboard.spaceKey.wasPressedThisFrame) jumpBufferTimer = jumpBufferTime;
```

In `FixedUpdate`, replace the jump block and remove `jumpQueued = false;`:

```csharp
if (jumpBufferTimer > 0f && coyoteTimer > 0f)
{
    velocity.y = jumpSpeed;
    jumpBufferTimer = 0f;
    coyoteTimer = 0f;
}
```

Counting down before recording the press gives each press the full 0.1 seconds. Coyote time forgives pressing late; the buffer forgives pressing early.
:::

### Exercise 5: Watch a bullet tunnel

Build a test: a thin wall (a Square scaled to (0.2, 4, 1) with a Box Collider 2D) and, 5.5 units to its left, a `Cannon` that fires a bullet when you press **F**. The bullet is a small Circle (scale 0.2) with a Rigidbody 2D (**Gravity Scale** 0, **Collision Detection** Discrete), a Circle Collider 2D, and a script that logs "Hit" and destroys the bullet when it collides. Fire ten shots at 60 units per second and count the hits, then switch the bullet prefab to **Continuous** and count again.

Sample result:

```text
Discrete:   0 hits out of 10
Continuous: 10 hits out of 10
```

:::hint
Make the prefab field a `Rigidbody2D` instead of a `GameObject`. Then `Instantiate` hands back the new bullet's Rigidbody 2D directly, and you can set its `linearVelocity` on the next line.
:::

:::solution
```csharp title="Cannon.cs"
using UnityEngine;
using UnityEngine.InputSystem;

public class Cannon : MonoBehaviour
{
    [SerializeField] private Rigidbody2D bulletPrefab;
    [SerializeField] private float bulletSpeed = 60f;

    void Update()
    {
        if (Keyboard.current == null || !Keyboard.current.fKey.wasPressedThisFrame) return;

        Rigidbody2D bullet = Instantiate(bulletPrefab, transform.position, transform.rotation);
        bullet.linearVelocity = transform.right * bulletSpeed;
    }
}
```

```csharp title="BulletHit.cs"
using UnityEngine;

public class BulletHit : MonoBehaviour
{
    void OnCollisionEnter2D(Collision2D collision)
    {
        Debug.Log("Hit " + collision.gameObject.name);
        Destroy(gameObject);
    }
}
```

At 60 units per second each step moves 1.2 units. From 5.5 units away the steps land at 4.8 and 6.0, either side of the wall, so Discrete never sees an overlap. Move the cannon 0.3 units and it might hit every time, which is exactly why Discrete can't be trusted for fast objects. Continuous sweeps between steps, so every shot connects.
:::

### Exercise 6: Crates, and who ignores whom

Add a few crates (brown Squares with a Dynamic Rigidbody 2D and a Box Collider 2D). The design rules:

1. The player can push crates, stand on them, and **jump off them**.
2. Crates fall **through** saws and coins without setting them off or being destroyed.
3. Saws still hurt the player, and coins can still be collected.

:::hint
Right now the player, saws, and coins all share the Default layer, so you can't separate them in the matrix. Give the player its own layer. Then decide which boxes to untick in **Edit > Project Settings > Physics 2D**, on the **Layer Collision Matrix** tab, and what the player's **Ground Layer** mask should contain.
:::

:::solution
Create two layers, `Player` and `Crate`. Put the player on `Player` (when Unity asks whether to change its children too, say yes) and the crates on `Crate`. Saws and coins stay on Default.

In the Layer Collision Matrix, untick **Crate / Default**. Leave **Crate / Player**, **Crate / Ground**, and **Crate / Crate** ticked. Leave **Player / Default** ticked, so the player still triggers saws and coins.

Set the player's **Ground Layer** to **Ground** and **Crate** so crates can be jumped from, but never `Player`, or the check would find the player's own collider. Rule 2 works because an unticked pair never touches, so no trigger event is generated.
:::

### Challenge: A zoom-out zone

Make a `CameraZoomZone`: a wide trigger between Platform A and the Wall. While the player is inside, the camera eases from Orthographic Size 6 out to 7 at about 1.5 units per second, and eases back when they leave. Keep it gradual, since sudden framing jumps are uncomfortable. The confiner caches its area per lens size, so call `CinemachineConfiner2D.InvalidateLensCache()` whenever the size changes.

:::hint
Add `using Unity.Cinemachine;` to reach `CinemachineCamera`. Its lens is a public field, so `cinemachineCamera.Lens.OrthographicSize` can be read and assigned directly. Track whether the player is inside with `OnTriggerEnter2D` and `OnTriggerExit2D`, and move the size with `Mathf.MoveTowards` in `Update`. Why 7 and not 10? Check the height of `CameraBounds`.
:::

:::solution
```csharp title="CameraZoomZone.cs"
using UnityEngine;
using Unity.Cinemachine;

public class CameraZoomZone : MonoBehaviour
{
    [SerializeField] private CinemachineCamera cinemachineCamera;
    [SerializeField] private CinemachineConfiner2D confiner;
    [SerializeField] private float zoomedSize = 7f;
    [SerializeField] private float zoomSpeed = 1.5f;

    private float normalSize;
    private bool playerInside;

    void Start()
    {
        normalSize = cinemachineCamera.Lens.OrthographicSize;
    }

    void OnTriggerEnter2D(Collider2D other)
    {
        if (other.CompareTag("Player")) playerInside = true;
    }

    void OnTriggerExit2D(Collider2D other)
    {
        if (other.CompareTag("Player")) playerInside = false;
    }

    void Update()
    {
        float target = playerInside ? zoomedSize : normalSize;
        float current = cinemachineCamera.Lens.OrthographicSize;
        if (Mathf.Approximately(current, target)) return;

        cinemachineCamera.Lens.OrthographicSize = Mathf.MoveTowards(current, target, zoomSpeed * Time.deltaTime);
        if (confiner != null) confiner.InvalidateLensCache();
    }
}
```

Put it on an empty `ZoomZone` with a large trigger Box Collider 2D on Default, and drag the Cinemachine Camera into both slots. The `Approximately` check leaves the lens and cache alone once the zoom settles.

`CameraBounds` is 14 units tall, and size 7 shows exactly 14 units. Size 10 would show 20, more than the bounds hold, so the confiner couldn't keep the view inside. Make the bounds taller before zooming further.
:::
