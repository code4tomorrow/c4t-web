:::objectives
- Build a `SaveSystem` that writes JSON to a file on desktop and to `PlayerPrefs` in Web builds.
- Save at checkpoint triggers and restore position, score, and health when the scene loads.
- Store a volume setting with `PlayerPrefs` and apply it at startup.
- Test the save in every situation that breaks saves: first run, reload, damaged file, deleted file.
- Make a Web build with **File > Build Profiles**, test it locally, and publish it on itch.io for free.
:::

At the end of this build, anyone with the link can play your game in a browser. Touch a checkpoint flag and a "Saved" message appears; close the tab, come back tomorrow, and you start at that flag with your score and health intact. The volume slider remembers where you left it.

## Step 1: The save data and a save system with two backends

Create `SaveData.cs` with the class from the Notes lesson (version, scene name, checkpoint id, score, health). Then the save system. Desktop builds write a file. Web builds store the same JSON text in `PlayerPrefs` instead, because browser file storage doesn't always flush right away, while `PlayerPrefs.Save()` writes to the browser's storage when you call it.

```csharp
using System;
using System.IO;
using UnityEngine;

public static class SaveSystem
{
    const string WebKey = "save";
    static string FilePath => Path.Combine(Application.persistentDataPath, "save.json");

    public static void Save(SaveData data)
    {
        string json = JsonUtility.ToJson(data, true);
#if UNITY_WEBGL && !UNITY_EDITOR
        PlayerPrefs.SetString(WebKey, json);
        PlayerPrefs.Save();
#else
        File.WriteAllText(FilePath, json);
#endif
    }

    public static bool TryLoad(out SaveData data)
    {
        data = null;
        string json = ReadRaw();
        if (string.IsNullOrEmpty(json)) return false;

        try
        {
            data = JsonUtility.FromJson<SaveData>(json);
        }
        catch (ArgumentException e)
        {
            Debug.LogWarning($"Ignoring a damaged save: {e.Message}");
            return false;
        }
        return data != null;
    }

    public static void Delete()
    {
#if UNITY_WEBGL && !UNITY_EDITOR
        PlayerPrefs.DeleteKey(WebKey);
        PlayerPrefs.Save();
#else
        if (File.Exists(FilePath)) File.Delete(FilePath);
#endif
    }

    static string ReadRaw()
    {
#if UNITY_WEBGL && !UNITY_EDITOR
        return PlayerPrefs.GetString(WebKey, "");
#else
        return File.Exists(FilePath) ? File.ReadAllText(FilePath) : "";
#endif
    }
}
```

The `#if` lines are compiler directives: the compiler keeps only one branch, depending on the platform you build for. `UNITY_WEBGL` is the symbol Unity defines for Web builds, and `!UNITY_EDITOR` keeps the file version while you test in the Editor. `TryLoad` returns `false` instead of crashing when there's no save or the text isn't valid JSON (`FromJson` throws an `ArgumentException` for that), so the game simply starts fresh.

## Step 2: Restore methods on the scripts that own the data

`ScoreKeeper` and `Health` own their values, so they get the methods that set them. Add one method to each:

```csharp
// In ScoreKeeper
public void Set(int value)
{
    Score = value;
    ScoreChanged?.Invoke(Score);
}

// In Health
public void Restore(int value)
{
    Current = Mathf.Clamp(value, 1, maxHealth);
    Changed?.Invoke(Current, maxHealth);
}
```

Both raise their events, so the HUD updates on its own. `Restore` clamps to at least 1 so a save made at 0 health can never load a dead player.

## Step 3: Checkpoints that save, with feedback

Make a checkpoint from a flag sprite with a **Box Collider 2D** set to **Is Trigger**, and add:

```csharp
using System;
using UnityEngine;
using UnityEngine.SceneManagement;

public class Checkpoint : MonoBehaviour
{
    public static event Action Saved;

    [SerializeField] string id = "cp1";
    [SerializeField] AudioClip saveSound;

    public string Id => id;

    void OnTriggerEnter2D(Collider2D other)
    {
        if (!other.CompareTag("Player") || !other.TryGetComponent(out Health health)) return;

        SaveSystem.Save(new SaveData
        {
            sceneName = SceneManager.GetActiveScene().name,
            checkpointId = id,
            score = ScoreKeeper.Instance.Score,
            health = health.Current
        });

        SoundPlayer.Instance.Play(saveSound);
        Saved?.Invoke();
    }
}
```

Place one before the test corridor (`cp1`) and one before the twist room (`cp2`) from Module 6. Give each a different **Id**.

Players should see that saving happened. Add a TextMeshPro text saying "Saved" near the bottom of the HUD and this script on the HUD:

```csharp
using System.Collections;
using TMPro;
using UnityEngine;

public class SavedToast : MonoBehaviour
{
    [SerializeField] TextMeshProUGUI label;

    void OnEnable() => Checkpoint.Saved += Show;
    void OnDisable() => Checkpoint.Saved -= Show;
    void Start() => label.enabled = false;

    void Show()
    {
        StopAllCoroutines();
        StartCoroutine(Flash());
    }

    IEnumerator Flash()
    {
        label.enabled = true;
        yield return new WaitForSeconds(1.5f);
        label.enabled = false;
    }
}
```

`Saved` is `static` because there are several checkpoints and the toast doesn't care which one fired.

## Step 4: Load on startup

Add this to `GameSystems`, then drag in the Player, its Health, and both checkpoints:

```csharp
using UnityEngine;

public class SaveLoader : MonoBehaviour
{
    [SerializeField] Transform player;
    [SerializeField] Health playerHealth;
    [SerializeField] Checkpoint[] checkpoints;

    void Start()
    {
        if (!SaveSystem.TryLoad(out SaveData data)) return;

        foreach (Checkpoint checkpoint in checkpoints)
        {
            if (checkpoint.Id == data.checkpointId)
            {
                player.position = checkpoint.transform.position;
                break;
            }
        }

        ScoreKeeper.Instance.Set(data.score);
        playerHealth.Restore(data.health);
    }

    [ContextMenu("Delete save")]
    void DeleteSave()
    {
        SaveSystem.Delete();
        Debug.Log("Save deleted");
    }
}
```

The `Restart` button from Module 5 reloads the scene, so dying now sends the player back to the last checkpoint instead of the start. `[ContextMenu]` adds **Delete save** to the menu that opens when you right-click the component's header in the Inspector, which saves you from hunting for the file while you test.

## Step 5: A volume setting that sticks

Put a **UI > Slider** in your pause panel (or a corner of the HUD), set **Min Value** 0 and **Max Value** 1, and add:

```csharp
using UnityEngine;
using UnityEngine.UI;

public class VolumeSetting : MonoBehaviour
{
    const string Key = "masterVolume";

    [SerializeField] Slider slider;

    void Start()
    {
        float volume = PlayerPrefs.GetFloat(Key, 0.8f);
        slider.SetValueWithoutNotify(volume);
        AudioListener.volume = volume;
        slider.onValueChanged.AddListener(OnChanged);
    }

    void OnChanged(float value)
    {
        AudioListener.volume = value;
        PlayerPrefs.SetFloat(Key, value);
        PlayerPrefs.Save();
    }
}
```

`AudioListener.volume` scales every sound in the game. `SetValueWithoutNotify` moves the slider to the saved value without firing `onValueChanged`, so loading doesn't immediately write the value back. The setting lives apart from the progress save, so deleting the save never resets the volume.

## Step 6: Try to break the save

Run each test in the Editor and note the result. Use **Delete save** between tests.

```text

Touch cp2, die, press Restart              Respawns at cp2
```

Find `save.json` by logging `Application.persistentDataPath` once and opening that folder.

## Step 7: Make a Web build

1. Open **File > Build Profiles** and select **Web** under Platforms. If Unity says the module isn't installed, add **Web Build Support** to this Editor version in Unity Hub (**Installs**, then the Editor's options menu, then **Add modules**) and reopen the project.
2. Make Web the active platform with the **Switch Platform** button. The first switch reimports assets and can take several minutes.
3. In the **Scene List**, make sure your level is listed and ticked. Use **Add Open Scenes** if it isn't.
4. Open **Edit > Project Settings > Player**. Set **Company Name** and **Product Name** (the product name is the page title). On the Web tab, under **Resolution and Presentation**, note the **Default Canvas Width** and **Height** (960 × 600 is typical); itch.io will need the same numbers.
5. Back in Build Profiles, click **Build and Run** and choose a new, empty folder outside `Assets`, such as `Builds/Web` next to the `Assets` folder. Unity builds, starts a small local web server, and opens the game in your browser.

Play the build through from the start. Click inside the game first so it receives the keyboard. Then run the save tests again in this build: saves here go to browser storage, not to `save.json`.

The folder now holds `index.html`, a `Build` folder, and a `TemplateData` folder.

## Step 8: Publish it on itch.io

itch.io's terms say accounts are for people 13 and older, and that publishers must be 18 or have a parent's or guardian's consent. If that's not you yet, publish together with a parent or guardian on their account.

1. Open `Builds/Web`, select the **contents** (`index.html`, `Build`, `TemplateData`), and compress them into a zip. On Windows, right-click and choose **Compress to ZIP file** (or **Send to > Compressed (zipped) folder**); on a Mac, right-click and choose **Compress 3 Items**. Zipping the contents, not the folder around them, puts `index.html` at the top level of the zip.
2. On itch.io, open your dashboard and create a new project. Give it a title, and set the kind of project to **HTML**.
3. Upload the zip and tick the option that says the file will be played in the browser.
4. Under the embed options, set the viewport to your canvas size (960 × 600) and turn on the fullscreen button. Leave "mobile friendly" off for a keyboard game.
5. Set pricing to no payments (or "$0 or donate" if you'd like tips), and keep visibility on **Draft**.
6. Save, view the page, and play the whole game there. Check the save one more time.
7. When it works, change visibility to **Public**. A newly published page appears in itch.io's "most recent" listings once, so polish the page before you publish.

If the game loads forever on itch.io, the browser couldn't decompress the files. Tick **Decompression Fallback** in **Player > Web > Publishing Settings**, rebuild, and upload the new zip.

:::quiz
Q: Why does `SaveSystem` use `PlayerPrefs` in Web builds instead of writing `save.json`?
- [ ] Web builds can't use `JsonUtility`
  They can; the JSON text is exactly the same on every platform.
- [x] Browser file storage doesn't always flush right away, while `PlayerPrefs.Save()` writes to browser storage when called
  The data is the same JSON either way; only where it's kept changes.
- [ ] `PlayerPrefs` is encrypted on the Web
  It isn't encrypted on any platform.

Q: Why should the build go into a folder outside `Assets`?
- [x] Unity imports everything inside `Assets`, so a build there would be imported back into the project
  You'd get duplicate files, slow imports, and possibly a build that includes the previous build.
- [ ] Builds only work from the desktop
  Any folder outside `Assets` works.
- [ ] itch.io rejects zips that came from inside a project
  itch.io never sees where the folder was; the problem is Unity importing the build.

Q: A friend says the game on itch.io ignores the arrow keys, but the mouse works. What's the first thing to check?
- [ ] Whether the Input System package is installed in the build
  It is, or the game wouldn't compile. Input works once the game has focus.
- [x] Whether they clicked on the game first, so the page gives it keyboard focus
  Browsers send key presses to whatever part of the page has focus.
- [ ] Whether the viewport is exactly 960 × 600
  The size affects layout, not which element receives keys.
:::

:::takeaways
- Hide where saves live behind one `SaveSystem`, so the rest of the game just calls `Save` and `TryLoad`.
- Treat a missing or damaged save as "start fresh," never as a crash.
- Let the scripts that own data (`ScoreKeeper`, `Health`) restore it, so their events keep the HUD in sync.
- Keep settings separate from progress, so starting a new game doesn't reset them.
- Test the build itself, locally with **Build and Run** and again on itch.io as a draft, before making it public.
:::
