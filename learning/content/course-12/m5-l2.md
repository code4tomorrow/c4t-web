:::objectives
- Animate the player with Idle, Run, and Hurt states driven by parameters.
- Build a scaled HUD with a TextMeshPro score and a Slider health bar.
- Make coins, spikes, and a shared sound player that layers effects with `PlayOneShot`.
- Give damage three kinds of feedback (a flash, a Hurt animation, and a sound) through one `Health` event.
- Freeze the game on death and restart it from a UI Button.
:::

Your player can already run, jump, and collide with the level. By the end of this build the game will also explain itself: coins chime and raise a score in the corner, spikes knock the player upward, the sprite flashes red while a hurt pose plays, the health bar drops, and at zero health a Game Over panel offers a Restart button.

Here's every script you'll write and who talks to whom:

```mermaid caption="Gameplay scripts on the left raise events or call one shared service; feedback scripts on the right listen."
flowchart LR
    C[Coin] -->|Add| SK[ScoreKeeper]
    SK -->|ScoreChanged| SL[ScoreLabel]
    Z[Hazard] -->|TakeDamage| H[Health]
    H -->|Changed| HB[HealthBar]
    H -->|Damaged| HF[HurtFeedback]
    H -->|Died| GO[GameOverScreen]
    C --> SP[SoundPlayer]
    HF --> SP
```

## Step 1: Bring in art and sound you're allowed to use

You need a few animation frames, a coin, a spike, and three or four sounds. Two free sources with no strings attached:

- [Kenney's Pixel Platformer](https://kenney.nl/assets/pixel-platformer) has characters, coins, and spikes. Kenney's assets are released as CC0, so you can use them in anything without credit (credit is still polite).
- [sfxr.me](https://sfxr.me/) generates retro sound effects in the browser. Click **Pickup/Coin** or **Hit/Hurt** until you like one, then export it as a WAV.

Create folders `Art`, `Audio`, and `Scripts` in your Assets. Drag the files in. For pixel art, select the sprite sheet and set these in the Inspector, then click **Apply**:

- **Sprite Mode**: Multiple
- **Pixels Per Unit**: the size of one tile in the pack, so one tile is one Unity unit
- **Filter Mode**: Point (no filter), which keeps the pixels sharp
- **Compression**: None

Click **Open Sprite Editor**, choose **Slice > Grid By Cell Size**, enter the frame size, click **Slice**, then **Apply**. Each frame becomes its own sprite under the sheet.

## Step 2: Idle, Run, and Hurt in the Animator

Select the Player, open **Window > Animation > Animation**, click **Create**, and save `Idle.anim` in `Art/Animations`. Drag the idle frames onto the timeline. Use the clip dropdown's **Create New Clip...** to make `Run.anim` and `Hurt.anim` the same way. Open the Hurt clip and untick **Loop Time** in its Inspector, so it plays once.

In **Window > Animation > Animator**, add three parameters: `Speed` (Float), `Grounded` (Bool), and `Hurt` (Trigger). Then make these transitions:

| From → To | Has Exit Time | Transition Duration | Condition |
| --- | --- | --- | --- |
| Idle → Run | off | 0 | Speed Greater 0.1 |
| Run → Idle | off | 0 | Speed Less 0.1 |
| Any State → Hurt | off | 0 | Hurt (and untick Can Transition To Self) |
| Hurt → Idle | on, Exit Time 1 | 0 | none |

Add the `PlayerAnimation` script from the Notes lesson to the Player and set **Ground Layers** to the layer your level uses. Press Play and run back and forth. The Animator window should show the blue progress bar jumping between Idle and Run as you start and stop. If you made a Jump clip, add it with the `Grounded` transitions from the Notes diagram.

## Step 3: A Canvas that scales, with a score in the corner

Right-click in the Hierarchy, choose **UI > Text - TextMeshPro**, and import TMP Essentials if Unity asks. Rename the Canvas to `HUD` and the text to `ScoreText`.

On the HUD's **Canvas Scaler**, set **UI Scale Mode** to Scale With Screen Size, **Reference Resolution** to 1920 × 1080, and **Match** to 0.5. On `ScoreText`, open the anchor presets, hold **Alt** (**Option** on a Mac), and click top-left. Set **Pos X** to 40, **Pos Y** to -40, the font size to 48, and the text to `Score: 0`.

:::note
If the Console warns about the EventSystem using the old input module, select **EventSystem** in the Hierarchy and click **Replace with InputSystemUIInputModule**. Buttons won't respond to clicks until the EventSystem uses the Input System.
:::

## Step 4: A score keeper, a label, and coins

The score needs one owner. Create an empty GameObject called `GameSystems` and add this script:

```csharp
using System;
using UnityEngine;

public class ScoreKeeper : MonoBehaviour
{
    public static ScoreKeeper Instance { get; private set; }

    public int Score { get; private set; }
    public event Action<int> ScoreChanged;

    void Awake()
    {
        if (Instance != null && Instance != this)
        {
            Destroy(gameObject);
            return;
        }
        Instance = this;
    }

    public void Add(int points)
    {
        Score += points;
        ScoreChanged?.Invoke(Score);
    }
}
```

`Instance` lets a coin find the score keeper without an Inspector reference. That matters because the coin will be a prefab, and a prefab asset can't hold references to objects in a scene.

Add this label script to `ScoreText` and drag `ScoreText` into its **Label** slot:

```csharp
using TMPro;
using UnityEngine;

public class ScoreLabel : MonoBehaviour
{
    [SerializeField] TextMeshProUGUI label;

    void Start()
    {
        ScoreKeeper.Instance.ScoreChanged += Show;
        Show(ScoreKeeper.Instance.Score);
    }

    void OnDestroy()
    {
        if (ScoreKeeper.Instance != null) ScoreKeeper.Instance.ScoreChanged -= Show;
    }

    void Show(int score) => label.text = $"Score: {score}";
}
```

It subscribes in `Start` rather than `OnEnable`, because `Start` is guaranteed to run after `ScoreKeeper.Awake` has set `Instance`.

Now the coin. Drag a coin sprite into the scene, add a **Circle Collider 2D**, and tick **Is Trigger**. Make sure your Player's Tag is set to `Player`. Add:

```csharp
using UnityEngine;

public class Coin : MonoBehaviour
{
    [SerializeField] int points = 10;
    [SerializeField] AudioClip pickupSound;

    bool collected;

    void OnTriggerEnter2D(Collider2D other)
    {
        if (collected || !other.CompareTag("Player")) return;
        collected = true;

        ScoreKeeper.Instance.Add(points);
        SoundPlayer.Instance.Play(pickupSound);
        Destroy(gameObject);
    }
}
```

The `collected` flag is there because a player with two colliders (a body and a feet box, say) can enter the trigger twice in the same physics step, and `Destroy` doesn't take effect until the end of the frame. Without it, one coin sometimes scores 20.

Drag the coin from the Hierarchy into a `Prefabs` folder to make it a prefab, then place several. It won't compile until the next step adds `SoundPlayer`.

## Step 5: One sound player for every effect

If the coin played its sound from its own Audio Source, `Destroy(gameObject)` would delete the source in the same frame and the sound would stop almost before it started. Instead, every effect goes through one long-lived source. Add an **Audio Source** to `GameSystems`, untick **Play On Awake**, and add:

```csharp
using UnityEngine;

[RequireComponent(typeof(AudioSource))]
public class SoundPlayer : MonoBehaviour
{
    public static SoundPlayer Instance { get; private set; }

    AudioSource source;

    void Awake()
    {
        Instance = this;
        source = GetComponent<AudioSource>();
    }

    public void Play(AudioClip clip, float volume = 1f)
    {
        if (clip == null) return;
        source.pitch = Random.Range(0.92f, 1.08f);
        source.PlayOneShot(clip, volume);
    }
}
```

Select the coin prefab and drag your coin WAV into **Pickup Sound**. For music, create another empty object called `Music`, add an Audio Source, assign a looping track, and tick **Play On Awake** and **Loop** with Volume at 0.4.

Press Play and grab coins. The score climbs by 10 per coin, and the chime layers when you grab two quickly.

## Step 6: Health with a safety window, spikes, and a health bar

Taking damage every physics step while touching a spike would empty the bar in a blink. Real games give a short window of invulnerability after each hit. This `Health` extends the Notes version with that window and a separate `Damaged` event. Add it to the Player (if your Module 4 work already has a health script, merge these events into it):

```csharp
using System;
using UnityEngine;

public class Health : MonoBehaviour
{
    [SerializeField] int maxHealth = 5;
    [SerializeField] float invulnerableSeconds = 1f;

    public int Current { get; private set; }
    public int Max => maxHealth;

    public event Action<int, int> Changed;   // (current, max)
    public event Action Damaged;
    public event Action Died;

    float invulnerableUntil;

    void Awake() => Current = maxHealth;

    public void TakeDamage(int amount)
    {
        if (Current == 0 || Time.time < invulnerableUntil) return;

        Current = Mathf.Max(Current - amount, 0);
        invulnerableUntil = Time.time + invulnerableSeconds;

        Changed?.Invoke(Current, maxHealth);
        Damaged?.Invoke();
        if (Current == 0) Died?.Invoke();
    }

    public void Heal(int amount)
    {
        Current = Mathf.Min(Current + amount, maxHealth);
        Changed?.Invoke(Current, maxHealth);
    }
}
```

Spikes (and the saw blades from Module 2) get a trigger collider and this script. It damages anything with a `Health` and bounces it upward so the player isn't left standing in the hazard:

```csharp
using UnityEngine;

public class Hazard : MonoBehaviour
{
    [SerializeField] int damage = 1;
    [SerializeField] float bounceSpeed = 8f;

    void OnTriggerEnter2D(Collider2D other)
    {
        if (!other.TryGetComponent(out Health health)) return;
        health.TakeDamage(damage);

        Rigidbody2D body = other.attachedRigidbody;
        if (body != null) body.linearVelocity = new Vector2(body.linearVelocity.x, bounceSpeed);
    }
}
```

For the bar, right-click the HUD and choose **UI > Slider**. Name it `HealthBar` and anchor it top-right. Delete its child **Handle Slide Area**, and on the Slider component untick **Interactable** and tick **Whole Numbers**. Color the child **Fill** image red. Then add:

```csharp
using UnityEngine;
using UnityEngine.UI;

public class HealthBar : MonoBehaviour
{
    [SerializeField] Health health;
    [SerializeField] Slider slider;

    void OnEnable() => health.Changed += Show;
    void OnDisable() => health.Changed -= Show;
    void Start() => Show(health.Current, health.Max);

    void Show(int current, int max)
    {
        slider.maxValue = max;
        slider.value = current;
    }
}
```

Drag the Player (from the Hierarchy, not the Project window) into **Health** and the slider into **Slider**. Walk into the spikes: the bar drops one step, you bounce, and touching them again within a second does nothing.

## Step 7: Flash, hurt pose, sound, and game over

The hurt feedback listens to `Damaged`. The flashing lasts 0.8 seconds, inside the 1-second safety window, so it also tells the player "you can't be hit right now." It blinks two and a half times per second, under the limit of three flashes per second from the safety notes in Module 1.

```csharp
using System.Collections;
using UnityEngine;

public class HurtFeedback : MonoBehaviour
{
    static readonly int HurtId = Animator.StringToHash("Hurt");

    [SerializeField] Health health;
    [SerializeField] Animator animator;
    [SerializeField] SpriteRenderer sprite;
    [SerializeField] AudioClip hurtSound;
    [SerializeField] Color flashColor = new Color(1f, 0.35f, 0.35f);
    [SerializeField] int flashes = 2;
    [SerializeField] float flashInterval = 0.2f;

    void OnEnable() => health.Damaged += OnDamaged;
    void OnDisable() => health.Damaged -= OnDamaged;

    void OnDamaged()
    {
        animator.SetTrigger(HurtId);
        SoundPlayer.Instance.Play(hurtSound);
        StopAllCoroutines();
        StartCoroutine(Flash());
    }

    IEnumerator Flash()
    {
        for (int i = 0; i < flashes; i++)
        {
            sprite.color = flashColor;
            yield return new WaitForSeconds(flashInterval);
            sprite.color = Color.white;
            yield return new WaitForSeconds(flashInterval);
        }
    }
}
```

Add it to the Player and fill its slots from the Player's own components.

For game over, right-click the HUD and add **UI > Panel**, name it `GameOverPanel`, and give it a Text (TMP) child saying "Game Over" and a **UI > Button - TextMeshPro** child labeled "Restart". Add this script to the **HUD** object, not to the panel: a script on an inactive object never runs `OnEnable`, so it would never hear the `Died` event.

```csharp
using UnityEngine;
using UnityEngine.SceneManagement;

public class GameOverScreen : MonoBehaviour
{
    [SerializeField] Health health;
    [SerializeField] GameObject panel;

    void OnEnable() => health.Died += Show;
    void OnDisable() => health.Died -= Show;
    void Start() => panel.SetActive(false);

    void Show()
    {
        panel.SetActive(true);
        Time.timeScale = 0f;
    }

    public void Restart()
    {
        Time.timeScale = 1f;
        SceneManager.LoadScene(SceneManager.GetActiveScene().buildIndex);
    }
}
```

Select the Restart button, find **On Click ()** on its Button component, click **+**, drag the HUD into the object slot, and choose **GameOverScreen > Restart**. Restarting reloads the scene by its build index, so the scene must be listed in **File > Build Profiles** under **Scene List** (new projects already include `SampleScene`; use **Add Open Scenes** if yours isn't there).

Play through: grab coins, hit spikes five times, and press Restart. Expected behavior:

```text
Coin:      chime, "Score: 10" ... "Score: 50"
Spike 1-4: bounce, red flashing for 0.8 s, Hurt pose, hit sound, bar drops one step
Spike 5:   Game Over panel, everything frozen
Restart:   scene reloads, score 0, full bar, game running
```

:::quiz
Q: Why does the coin play its sound through `SoundPlayer` instead of an Audio Source on the coin itself?
- [ ] `PlayOneShot` only works on objects called GameSystems
  It works on any Audio Source; the name doesn't matter.
- [x] The coin is destroyed right after pickup, which would destroy its Audio Source and cut the sound off
  A long-lived source keeps playing after the coin is gone.
- [ ] Coins are prefabs, and prefabs can't have Audio Sources
  Prefabs can have any component. The problem is the coin's lifetime, not its type.

Q: `GameOverScreen` sits on the HUD, not on `GameOverPanel`. What would go wrong if it were on the panel?
- [x] The panel starts inactive, so the script's `OnEnable` never runs and it never subscribes to `Died`
  Scripts on inactive GameObjects don't run their lifecycle methods until the object is activated.
- [ ] The panel would appear twice
  Nothing duplicates. The panel would simply never appear.
- [ ] `Time.timeScale` can't be set from a UI object
  Any script can set `Time.timeScale`. The issue is that the script never hears the event.

Q: You remove the `invulnerableUntil` check from `Health`. The Hazard still uses `OnTriggerEnter2D`. What changes most noticeably?
- [ ] Nothing, since triggers only fire once
  Enter fires once per touch, but a second spike or an enemy touching you right after the first hit would also land.
- [x] Overlapping hazards can hit several times in a row with no gap, and the flashing no longer means "safe"
  The safety window is what stops back-to-back hits and gives the flash its meaning.
- [ ] The health bar stops updating
  The bar still updates; it may just drop several steps at once.
:::

:::takeaways
- A single owner (`ScoreKeeper`, `Health`) holds each value and raises an event when it changes.
- Effects play through a long-lived `SoundPlayer`, so destroying the object that caused a sound doesn't silence it.
- A short invulnerability window plus a flash turns "touching spikes" into one clear, readable hit.
- A script that must hear an event can't live on an object that starts inactive.
- `Time.timeScale = 0` freezes physics and animation; set it back to 1 before reloading a scene.
:::

## Ideas to extend it

- Replace the bar with a row of heart icons: one `Image` per heart, switched on or off in `Show`.
- Make the score count up over half a second instead of jumping, using a coroutine.
- Add a short hit pause: set `Time.timeScale` to 0.05 for 0.06 seconds of unscaled time (`WaitForSecondsRealtime`) when the player is hit.
- Add a **Heal** pickup that calls `health.Heal(1)` and plays its own sound.
