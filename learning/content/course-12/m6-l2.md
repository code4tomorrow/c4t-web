:::objectives
- Paint Background, Ground, and Hazards tilemaps and give Ground a single merged collider.
- Build a drone prefab that patrols, chases with line of sight, and searches before giving up.
- Show the drone's state to the player with color and an alert sound.
- Spawn drones from a capped spawner whose timing tightens over two minutes.
- Lay out a short level that teaches, tests, and twists the drone.
:::

By the end of this build you'll have a short, complete level. The player starts on a ledge and watches a drone sweep an empty room. Further on, the drone's route crosses the only path and a pillar offers cover. Then comes a room where drones keep arriving over a spike floor, and finally the exit. When a drone spots the player it turns red and beeps; when it loses them it turns yellow and drifts to where they were last seen.

## Step 1: Paint the level on three tilemaps

Right-click in the Hierarchy and choose **2D Object > Tilemap > Rectangular**. Unity creates a **Grid** with one child Tilemap. Rename the child `Ground`, then right-click the Grid and add two more tilemaps the same way: `Background` and `Hazards`.

Open **Window > 2D > Tile Palette**. Create a new palette (save it in `Art/Palettes`), then drag your sliced tile sheet into the palette window and choose a folder such as `Art/Tiles` for the tile assets Unity generates. Each sprite becomes a paintable tile.

Before painting, check that the tile sheet's **Pixels Per Unit** equals the tile size in pixels. Then one tile fills exactly one Grid cell. If tiles look tiny with gaps between them, or huge and overlapping, that number is wrong.

Choose which tilemap you're painting on with the target dropdown at the top of the Tile Palette, pick the brush (**B**), and paint. Box Fill (**U**) is quicker for big floors and walls, and Erase (**D**) removes tiles. Paint the floor and walls on `Ground`, decoration on `Background`, and spikes on `Hazards`.

Set the drawing order on each tilemap's **Tilemap Renderer**: **Order in Layer** -10 for Background and 0 for Ground and Hazards. Set the Player's Sprite Renderer to 10 so it's drawn in front.

## Step 2: One merged collider for the ground, a trigger for the spikes

Select `Ground` and add a **Tilemap Collider 2D**. Every tile now has its own small box. That works, but the player can snag on the seams where boxes meet, so merge them:

1. Add a **Composite Collider 2D**. Unity also adds a Rigidbody2D.
2. Set that Rigidbody2D's **Body Type** to **Static**.
3. On the Tilemap Collider 2D, set **Composite Operation** to **Merge**.

The green outline in the Scene view changes from a grid of squares to one smooth outline around each solid area. Set the `Ground` object's **Layer** to your Ground layer (the one your movement script and `PlayerAnimation` check).

Select `Hazards`, add a **Tilemap Collider 2D**, tick **Is Trigger**, and add the `Hazard` script from Module 5. Every spike tile now damages and bounces the player through one script.

## Step 3: The drone prefab and a route

Make the drone from any small sprite. Give it:

- a **Rigidbody2D** with **Body Type** set to **Kinematic**,
- a **Circle Collider 2D** with **Is Trigger** ticked,
- the `Hazard` script, with **Bounce Speed** at 5.

The kinematic body moves only where code puts it and ignores gravity. The trigger plus `Hazard` means touching the drone costs a heart, and the invulnerability window in `Health` stops it from draining you while it hovers over you.

Create an empty object called `Route_Teach` (not a child of the drone) and give it three or four empty children placed across the open room: `P0`, `P1`, `P2`. Click the cube icon at the top left of the Inspector for each to give it a colored label you can see in the Scene view.

Now the first version of the brain, which only patrols. Add `EnemyAI` to the drone:

```csharp
using UnityEngine;

[RequireComponent(typeof(Rigidbody2D))]
public class EnemyAI : MonoBehaviour
{
    [SerializeField] Transform[] waypoints;
    [SerializeField] float patrolSpeed = 2f;

    int waypointIndex;
    Rigidbody2D rb;

    void Awake() => rb = GetComponent<Rigidbody2D>();

    void FixedUpdate()
    {
        Vector2 target = waypoints[waypointIndex].position;
        rb.MovePosition(Vector2.MoveTowards(rb.position, target, patrolSpeed * Time.fixedDeltaTime));

        if (Vector2.Distance(rb.position, target) < 0.05f)
            waypointIndex = (waypointIndex + 1) % waypoints.Length;
    }
}
```

Lock the Inspector (the padlock icon at its top right) while the drone is selected, then drag `P0`, `P1`, and `P2` onto **Waypoints**. Press Play. The drone loops the route at a steady 2 units per second. Click the padlock again when you're done.

## Step 4: Senses, Chase, and Search

Replace the script with the full version. It keeps the patrol and adds the state machine from the Notes lesson, plus a `Setup` method the spawner will use:

```csharp
using UnityEngine;

[RequireComponent(typeof(Rigidbody2D))]
public class EnemyAI : MonoBehaviour
{
    enum State { Patrol, Chase, Search }

    [Header("Route")]
    [SerializeField] Transform[] waypoints;
    [SerializeField] float patrolSpeed = 2f;

    [Header("Senses")]
    [SerializeField] Transform player;
    [SerializeField] float detectRadius = 5f;
    [SerializeField] float loseRadius = 7f;
    [SerializeField] LayerMask sightBlockers;

    [Header("Chase and search")]
    [SerializeField] float chaseSpeed = 3.5f;
    [SerializeField] float searchSeconds = 2f;

    [Header("Feedback")]
    [SerializeField] SpriteRenderer sprite;
    [SerializeField] AudioClip alertSound;

    State state = State.Patrol;
    int waypointIndex;
    Vector2 lastSeen;
    float searchUntil;
    Rigidbody2D rb;

    void Awake() => rb = GetComponent<Rigidbody2D>();

    public void Setup(Transform target, Transform[] route)
    {
        player = target;
        waypoints = route;
    }

    void FixedUpdate()
    {
        if (player == null || waypoints == null || waypoints.Length == 0) return;

        switch (state)
        {
            case State.Patrol:
                Patrol();
                if (CanSeePlayer(detectRadius)) SetState(State.Chase);
                break;

            case State.Chase:
                lastSeen = player.position;
                MoveTowards(lastSeen, chaseSpeed);
                if (!CanSeePlayer(loseRadius)) SetState(State.Search);
                break;

            case State.Search:
                MoveTowards(lastSeen, patrolSpeed);
                if (CanSeePlayer(detectRadius)) SetState(State.Chase);
                else if (Time.time > searchUntil) SetState(State.Patrol);
                break;
        }
    }

    void Patrol()
    {
        Vector2 target = waypoints[waypointIndex].position;
        MoveTowards(target, patrolSpeed);
        if (Vector2.Distance(rb.position, target) < 0.05f)
            waypointIndex = (waypointIndex + 1) % waypoints.Length;
    }

    void MoveTowards(Vector2 target, float speed)
    {
        rb.MovePosition(Vector2.MoveTowards(rb.position, target, speed * Time.fixedDeltaTime));
    }

    bool CanSeePlayer(float radius)
    {
        Vector2 toPlayer = (Vector2)player.position - rb.position;
        if (toPlayer.magnitude > radius) return false;
        return !Physics2D.Linecast(rb.position, player.position, sightBlockers);
    }

    void SetState(State next)
    {
        if (next == State.Chase && alertSound != null && SoundPlayer.Instance != null)
            SoundPlayer.Instance.Play(alertSound);
        if (next == State.Search)
            searchUntil = Time.time + searchSeconds;

        state = next;

        if (sprite != null)
        {
            sprite.color = next == State.Chase ? new Color(1f, 0.4f, 0.4f)
                         : next == State.Search ? new Color(1f, 0.9f, 0.4f)
                         : Color.white;
        }
    }

    void OnDrawGizmosSelected()
    {
        Gizmos.color = Color.yellow;
        Gizmos.DrawWireSphere(transform.position, detectRadius);
        Gizmos.color = Color.red;
        Gizmos.DrawWireSphere(transform.position, loseRadius);
    }
}
```

Fill the new slots: **Player** from the Hierarchy, **Sight Blockers** set to Ground only, **Sprite** from the drone's own Sprite Renderer, and an alert beep from sfxr.me. All state changes go through `SetState`, so the color, the sound, and the search timer can never get out of step with the state itself.

Look at what Search does with `lastSeen`. It's the player's position on the last physics step when the drone could still see them, so the straight line from the drone to that point was clear a moment ago. Search follows a path the drone knows is open.

Press Play and test each arrow of the diagram:

```text
Stay outside the yellow circle:           drone stays white, keeps patrolling
Step inside it in the open:               beep, drone turns red, chases at 3.5
Duck behind a wall:                       drone turns yellow, drifts to where you vanished
Stay hidden for 2 seconds:                drone turns white, returns to its route
Step back into view while it's yellow:    beep, red again
```

:::warning
A kinematic drone flies through tiles. While it chases or searches it follows lines it could see along, but its trip back to the route after a search is a straight line that can pass through a thin wall. This build handles that with level design: each drone gets an open room, as the Notes lesson suggested. Pathfinding is the code fix, and it's a much bigger job.
:::

## Step 5: Make it a prefab, then build the spawner

Drag the drone into `Prefabs`. Open the prefab and notice that **Player** is now empty and refuses the scene's Player. That's expected: prefabs can't reference scene objects. Drones you place by hand keep their scene references as overrides, and spawned drones get theirs from the spawner.

Create an empty `Spawner` object in the twist room, give it two empty children as spawn points near the ceiling, and make a `Route_Twist` with waypoints spread across the room. Add:

```csharp
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

public class EnemySpawner : MonoBehaviour
{
    [SerializeField] EnemyAI enemyPrefab;
    [SerializeField] Transform[] spawnPoints;
    [SerializeField] Transform[] route;
    [SerializeField] Transform player;
    [SerializeField] int maxAlive = 3;
    [SerializeField] float enemyLifetime = 15f;
    [SerializeField] AnimationCurve secondsBetweenSpawns = AnimationCurve.Linear(0f, 6f, 120f, 2f);

    readonly List<EnemyAI> alive = new List<EnemyAI>();

    IEnumerator Start()
    {
        float startTime = Time.time;

        while (true)
        {
            alive.RemoveAll(enemy => enemy == null);

            if (alive.Count < maxAlive)
            {
                Transform point = spawnPoints[Random.Range(0, spawnPoints.Length)];
                EnemyAI enemy = Instantiate(enemyPrefab, point.position, Quaternion.identity);
                enemy.Setup(player, route);
                Destroy(enemy.gameObject, enemyLifetime);
                alive.Add(enemy);
            }

            float elapsed = Time.time - startTime;
            yield return new WaitForSeconds(secondsBetweenSpawns.Evaluate(elapsed));
        }
    }
}
```

A few details matter here. Making `Start` return `IEnumerator` turns it into a coroutine, so the whole spawn loop reads top to bottom with a `yield` where it waits. `enemy == null` is true for drones Unity has destroyed, so `RemoveAll` keeps the count honest. `Destroy(enemy.gameObject, enemyLifetime)` retires each drone after 15 seconds, which keeps a steady stream flowing instead of three drones that hover forever.

Drag the drone prefab (from the Project window this time) into **Enemy Prefab**, and fill the spawn points, the route, and the Player.

## Step 6: Tune the beats by playing them

Now arrange the slice from the diagram and play it from the start each time you change something:

- **Teach room**: set the drone's **Detect Radius** small (4) and its route high, so a player on the floor is never seen. Put a coin trail along the floor that leads under its path.
- **Test corridor**: a hand-placed drone whose route crosses the path at head height, and a pillar of Ground tiles to hide behind. Waiting behind the pillar should be enough to pass.
- **Twist room**: the spawner, with spikes on parts of the floor so hiding isn't free. Start with **Max Alive** at 2 and raise it only if the room feels easy.
- **Exit**: a few safe tiles, a last coin, and the exit marker you'll wire up in the capstone.

Ask a friend to play without hints and watch where they hesitate. If they die in the teach room, it isn't teaching yet.

:::quiz
Q: Why does `SetState` handle the color, the alert sound, and the search timer, instead of each `case` doing it?
- [ ] C# doesn't allow method calls inside a `switch`
  It does; the cases already call `Patrol` and `MoveTowards`.
- [x] Every change goes through one place, so the feedback can never disagree with the actual state
  If one case forgot to recolor the drone, the player would see white while being chased.
- [ ] It makes the drone faster
  It changes nothing about speed; it keeps state and feedback in sync.

Q: Why is the Ground tilemap's collider merged with a Composite Collider 2D?
- [x] Separate per-tile boxes leave seams the player can snag on; a merged outline is smooth
  Merging turns hundreds of boxes into one shape per solid area.
- [ ] Tilemaps can't collide without one
  A Tilemap Collider 2D alone does collide; it's just made of many small boxes.
- [ ] It makes the drone collide with walls
  The drone is kinematic and passes through static colliders either way.

Q: The spawner's `alive` list keeps references to drones. Why call `alive.RemoveAll(enemy => enemy == null)` each loop?
- [ ] To destroy drones that are too far away
  It doesn't destroy anything; it only forgets drones that are already gone.
- [x] Destroyed drones compare equal to `null`, so removing them keeps the count of living drones correct
  Without it the list fills with dead entries, `alive.Count` stays at the cap, and spawning stops for good.
- [ ] `Instantiate` fails if the list has more than three items
  `Instantiate` doesn't know about the list. The cap is your own rule.
:::

:::takeaways
- Use separate tilemaps for background, solid ground, and hazards; merge the ground's collider with a Composite Collider 2D set to Merge.
- A kinematic drone with `MovePosition` gives exact patrols and still fires trigger events against the player.
- Route every state change through one method so color and sound always match the state.
- A spawner passes scene references to each copy, caps the count, and cleans up after destroyed enemies.
- Tune each section by playing it from the start, and watch someone else play it.
:::

## Ideas to extend it

- Add a **Rule Tile** (**Create > 2D > Tiles > Rule Tile**, from the 2D Tilemap Extras package) so edges and corners pick the right sprite automatically.
- Add a warning stage before Chase: the drone turns orange and pauses for 0.3 seconds before it moves, which gives the player time to react.
- Let the player defeat a drone by landing on it, and award points through `ScoreKeeper`.
