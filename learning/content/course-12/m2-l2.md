:::objectives
- Build an object from a parent sprite, a child sprite, and a script component.
- Turn it into a prefab, place instances, and edit them all at once in Prefab Mode.
- Decide when to apply an override to the prefab and when to revert it.
- Make a prefab variant that adds behavior while still following its base.
:::

You're building the first stretch of the course's platformer level: a floor with four saw blades spinning on it and two more bobbing up and down in the air. The player arrives in Module 4. For now the goal is to set the level up so that every saw is controlled from one place.

Here is the structure you'll end up with:

```mermaid caption="The finished prefab family. Arrows point from what's being copied to the copies."

    P["Saw.prefab: Circle + Tooth child + Spinner"] --> I1[Saw]
    P --> I2["Saw (1)"]

    P --> V["BobbingSaw.prefab: variant + Bobber"]
```

## Step 1: Folders and a floor

Open your `UnityPlatformer` project and the `SampleScene` scene (it's in `Assets/Scenes`). In the Project window, right-click `Assets` and create two folders, `Scripts` and `Prefabs`.

Now the floor:

1. **GameObject > 2D Object > Sprites > Square**, and rename it `Ground`.
2. In its Transform, set **Position** to (0, -3, 0) and **Scale** to (20, 1, 1).
3. In the Sprite Renderer, set **Color** to a dark gray.
4. Click **Add Component**, search for **Box Collider 2D**, and add it. Nothing uses it yet, but in Module 4 it's what the player stands on.

The square is 1 unit tall, so its top edge sits at y = -2.5. Press **Ctrl+S** (**⌘S**) to save the scene. Get in the habit now.

## Step 2: One saw, built by hand

1. **GameObject > 2D Object > Sprites > Circle**. Rename it `Saw`, set **Position** to (-6, -2.2, 0), and make its color red.
2. Right-click `Saw` in the Hierarchy and choose **2D Object > Sprites > Square**. The new square is created as a child. Rename it `Tooth`.
3. Give `Tooth` a **Position** of (0.5, 0, 0) and a **Scale** of (0.3, 0.3, 1), and color it near-black.
4. In the Tooth's Sprite Renderer, set **Order in Layer** to 1 so it always draws on top of the red circle.

Why the tooth? A plain circle spinning looks exactly like a circle sitting still. The tooth, half a unit from the center in the parent's local space, swings around as the parent rotates, so you can see the spin. It's the parent-child Transform rule from the Notes doing real work.

## Step 3: Make it spin

In `Assets/Scripts`, create a MonoBehaviour script named `Spinner` and replace its contents:

```csharp title="Spinner.cs"
using UnityEngine;

public class Spinner : MonoBehaviour
{
    [SerializeField] private float degreesPerSecond = -180f;

    void Update()
    {
        transform.Rotate(0f, 0f, degreesPerSecond * Time.deltaTime);
    }
}
```

Drag it onto `Saw` (the parent, not the tooth) and press Play. The tooth circles the blade clockwise, once every two seconds. In Unity's 2D view a positive Z rotation turns counterclockwise, so the negative default makes it turn clockwise. Stop Play mode before continuing.

## Step 4: Turn the saw into a prefab

Drag `Saw` from the Hierarchy into the `Prefabs` folder. Three things change:

-   A `Saw` asset with a blue cube icon appears in the Project window.
-   `Saw` in the Hierarchy turns blue. It's now an **instance** of that asset.
-   The top of its Inspector gains prefab controls, including the **Overrides** dropdown.

Now drag `Saw.prefab` from the Project window into the scene three more times. Unity names them `Saw (1)`, `Saw (2)`, and `Saw (3)`. Set their positions to (-2, -2.2, 0), (2, -2.2, 0), and (6, -2.2, 0). Press Play: four saws spin in step.

## Step 5: Change every saw at once

Double-click `Saw.prefab` in the Project window. The Scene view switches to **Prefab Mode** and shows only the saw, and the Hierarchy shows the prefab's contents with a back arrow at the top.

In Prefab Mode, select the root `Saw` and change two things: set the Sprite Renderer color to orange, and set the Spinner's **Degrees Per Second** to -270. With **Auto Save** ticked in the Scene view's top bar, changes save as you make them; otherwise click **Save**.

Click the back arrow in the Hierarchy to return to the scene. All four saws are orange and spin faster. You changed one asset and the level followed. That's the whole problem from the start of the Notes, solved.

## Step 6: Override one saw, then decide what to do with it

Select `Saw (3)` in the scene and set its **Degrees Per Second** to -540. The field's label turns **bold** with a blue line in the margin: this instance now overrides the prefab's value.

Open the **Overrides** dropdown at the top of its Inspector. It lists exactly what differs from the prefab. You have two choices:

-   **Revert All** throws the override away and returns to -270.
-   **Apply All** pushes -540 into the prefab, which changes every saw.

Here you want one unusually fast saw near the end of the level, so keep the override and close the dropdown. A single override like this is fine. When you find yourself repeating the same overrides on several instances, that's the sign you need a variant.

## Step 7: A bobbing variant

Two saws should float and bob up and down. They're still saws (same look, same spin), with one extra behavior.

First, the behavior. Create a script named `Bobber`:

```csharp title="Bobber.cs"
using UnityEngine;

public class Bobber : MonoBehaviour
{
    [SerializeField] private float height = 1.5f;
    [SerializeField] private float secondsPerCycle = 2f;
    [SerializeField] private float startOffset = 0f;

    private Vector3 startPosition;

    void Start()
    {
        startPosition = transform.position;
    }

    void Update()
    {
        float cycles = (Time.time + startOffset) / secondsPerCycle;
        float y = Mathf.Sin(cycles * 2f * Mathf.PI) * height;
        transform.position = startPosition + new Vector3(0f, y, 0f);
    }
}
```

`Mathf.Sin` swings smoothly between -1 and 1, so the saw moves between 1.5 units below and 1.5 units above where it started. The position is always computed from `startPosition`, never from where the saw was last frame, so small timing differences can't add up into drift.

Now the variant:

1. Right-click `Saw.prefab` in the Project window and choose **Create > Prefab Variant**. Name it `BobbingSaw`.
2. Double-click `BobbingSaw` to open it in Prefab Mode, and add the `Bobber` component to its root.
3. Return to the scene and drag `BobbingSaw` in twice. Place one at (-4, 0, 0) and the other at (4, 0, 0).
4. On the second one, set **Start Offset** to 1, so the two move in opposite directions.

Press Play. Four saws spin on the floor, two more spin while floating up and down, and one floor saw spins noticeably faster.

## Step 8: Prove the family works

Open `Saw.prefab` (the base, not the variant) and change the Tooth's color to white. Return to the scene: every saw, including both bobbing ones, now has a white tooth. Variants inherit everything they don't override.

Then open `BobbingSaw` and change its color to purple. Only the two bobbing saws turn purple, because that's an override in the variant. The base saws stay orange. Save the scene and commit if you use Git: "Saw prefab and bobbing variant".

## The finished scripts

Both scripts are small on purpose. Each does one job, and the saw's behavior comes from which ones are attached.

```csharp title="Spinner.cs"
using UnityEngine;

public class Spinner : MonoBehaviour
{
    [SerializeField] private float degreesPerSecond = -180f;

    void Update()
    {
        transform.Rotate(0f, 0f, degreesPerSecond * Time.deltaTime);
    }
}
```

```csharp title="Bobber.cs"
using UnityEngine;

public class Bobber : MonoBehaviour
{
    [SerializeField] private float height = 1.5f;
    [SerializeField] private float secondsPerCycle = 2f;
    [SerializeField] private float startOffset = 0f;

    private Vector3 startPosition;

    void Start()
    {
        startPosition = transform.position;
    }

    void Update()
    {
        float cycles = (Time.time + startOffset) / secondsPerCycle;
        float y = Mathf.Sin(cycles * 2f * Mathf.PI) * height;
        transform.position = startPosition + new Vector3(0f, y, 0f);
    }
}
```

:::quiz
Q: Why does the Saw need a Tooth child at all?
- [x] A spinning plain circle looks identical to a still one, so the tooth makes rotation visible
  The tooth sits off-center in the parent's local space, so it orbits as the parent turns.
- [ ] Children are required for the Spinner script to work
  `Spinner` rotates whatever object it's on, child or not.
- [ ] Prefabs must contain at least two objects
  A prefab can be a single GameObject.

Q: What would go wrong if `Bobber` did `transform.position += new Vector3(0f, y, 0f)` every frame?
- [ ] Nothing; it's the same thing
  It isn't: `+=` adds this frame's offset on top of last frame's position.
- [x] The offsets would pile up, so the saw would wander far away instead of bobbing in place
  Computing from the stored `startPosition` keeps the motion centered.
- [ ] It would cause a compile error
  The code compiles fine; it just behaves badly.

Q: You want a red saw that spins backward, used in eight places. What's the best choice?
- [ ] Override color and speed on eight Saw instances
  Eight copies of the same overrides will drift apart the first time you forget one.
- [x] Make a `ReverseSaw` prefab variant with those two overrides
  The variant holds the differences once, and still inherits everything else from Saw.
- [ ] Apply the overrides to the Saw prefab
  That would make every saw red and backward, not just these eight.
:::

:::takeaways
- Build an object once by hand, then drag it into the Project window to make it a prefab.
- Edit the prefab in Prefab Mode to change every instance; bold fields on an instance are overrides.
- One-off differences are fine as overrides. Repeated differences belong in a prefab variant.
- Variants inherit every change to their base except the values they override.
:::

## Ideas to extend it

-   Give each `BobbingSaw` a random **Start Offset** in `Awake` with `Random.Range(0f, secondsPerCycle)` so they never sync up.
-   Make a nested prefab: a floating platform (a Square with a Box Collider 2D) with two saws on top, saved as `SawPlatform.prefab`. Editing `Saw.prefab` still updates the saws inside it.
-   Add a `Spinner` to a Square to make a rotating bar hazard, and notice that you didn't write any new code.
