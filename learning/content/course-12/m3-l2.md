- Turn keyboard input into frame-rate-independent movement, and measure the result.
- Fix fast diagonals with normalization, and add acceleration with `Vector2.MoveTowards`.
- Add a sprint key, flip the character with its children, and keep it inside an arena.
- Organize a growing script into small methods with Inspector-tunable fields.

You're building the control script for a top-down explorer, the kind of view used in Zelda-style adventures and farming games. When it's finished, the explorer:

-   walks with WASD or the arrow keys at the same speed in all eight directions,
-   speeds up and slows down smoothly instead of starting and stopping instantly,
-   sprints while Left Shift is held,
-   turns to face left or right, eye included,
-   can't leave the arena.

Its Inspector will look like this:

```text
Top Down Mover (Script)
  Speed
    Walk Speed          4
    Sprint Multiplier   1.75
    Acceleration        30
  Arena
    Arena Size          X 15.2   Y 7.4
```

Physics and collisions come in Module 4. This explorer moves its Transform directly, which is the right tool for learning how movement math works.

## Step 1: A scene for the explorer

In the Project window, select `SampleScene` and press **Ctrl+D** (**⌘D**) to duplicate it. Rename the copy `TopDown` and double-click to open it. Delete the ground and all the saws, keeping **Main Camera** and **Global Light 2D**.

Add a floor to walk on: **GameObject > 2D Object > Sprites > Square**, named `Arena`, at position (0, 0, 0), scale (16, 9, 1), dark green, with its Sprite Renderer's **Order in Layer** set to -1 so it draws behind everything. The camera's default view is 10 units tall, so the whole arena fits on screen.

## Step 2: The explorer and its eye

1. **GameObject > 2D Object > Sprites > Capsule**. Name it `Explorer`, set scale to (0.8, 0.8, 1), and color it blue. The Capsule shape is 1 by 2 units, so the explorer ends up 0.8 wide and 1.6 tall.
2. Right-click `Explorer` and add a child **2D Object > Sprites > Square** named `Eye`. Set its position to (0.25, 0.5, 0), scale to (0.25, 0.25, 1), color to white, and **Order in Layer** to 1.

The eye sits on the right side of the head, so you'll always see which way the explorer faces.

## Step 3: First movement, with a speedometer

In `Assets/Scripts`, create a MonoBehaviour script named `TopDownMover` and attach it to `Explorer`. Start with the simplest version that works, plus a temporary log that prints the speed:

```csharp title="TopDownMover.cs (step 3)"
using UnityEngine;
using UnityEngine.InputSystem;

public class TopDownMover : MonoBehaviour
{
    [SerializeField] private float walkSpeed = 4f;

    void Update()
    {
        Vector2 input = ReadMoveInput();
        Vector2 step = input * walkSpeed * Time.deltaTime;
        transform.position += (Vector3)step;

        if (step != Vector2.zero)
            Debug.Log($"Speed: {step.magnitude / Time.deltaTime:F2} units/s");
    }

    Vector2 ReadMoveInput()
    {
        Keyboard keyboard = Keyboard.current;
        if (keyboard == null) return Vector2.zero;

        Vector2 input = Vector2.zero;
        if (keyboard.aKey.isPressed || keyboard.leftArrowKey.isPressed) input.x -= 1f;
        if (keyboard.dKey.isPressed || keyboard.rightArrowKey.isPressed) input.x += 1f;
        if (keyboard.sKey.isPressed || keyboard.downArrowKey.isPressed) input.y -= 1f;
        if (keyboard.wKey.isPressed || keyboard.upArrowKey.isPressed) input.y += 1f;
        return input;
    }
}
```

Press Play, click in the Game view, and hold D, then W and D together. With **Collapse** on in the Console, you'll see:

```text
Speed: 4.00 units/s
Speed: 5.66 units/s
```

Dividing the step by `Time.deltaTime` turns "distance this frame" back into "distance per second", so the log reads 4.00 whatever your frame rate is. The second line is the diagonal bug from the Notes, measured.

## Step 4: Same speed in every direction

Add one line right after reading the input:

```csharp
Vector2 input = ReadMoveInput();
if (input.sqrMagnitude > 1f) input = input.normalized;
```

`sqrMagnitude` is the length squared. Comparing it with 1 asks "is this longer than 1?" without computing a square root, and the check leaves (0, 0) alone. Press Play and hold W and D: the log now reads 4.00. Delete the `Debug.Log` lines once you've seen it.

## Step 5: Smooth starts and stops

Right now the explorer jumps from 0 to full speed in one frame. Real movement has a little acceleration. The fix is to keep a **velocity** that lasts between frames and nudge it toward the speed you want:

```csharp
[SerializeField] private float acceleration = 30f;

private Vector2 velocity;

void Update()
{
    Vector2 input = ReadMoveInput();
    if (input.sqrMagnitude > 1f) input = input.normalized;

    Vector2 targetVelocity = input * walkSpeed;
    velocity = Vector2.MoveTowards(velocity, targetVelocity, acceleration * Time.deltaTime);
    transform.position += (Vector3)(velocity * Time.deltaTime);
}
```

`Vector2.MoveTowards(current, target, maxDelta)` moves `current` toward `target` by at most `maxDelta`, without overshooting. With acceleration 30, the explorer reaches 4 units/s in about 0.13 seconds.

`Time.deltaTime` now appears twice, and both are needed. The first scales how much the *velocity* may change this frame (units per second, per second). The second scales how far the *position* moves at that velocity. Set **Acceleration** to 4 in the Inspector while playing and the explorer slides around as if on ice; 60 feels almost instant.

## Step 6: Sprint

Add a field and pick the speed before computing the target:

```csharp
[SerializeField] private float sprintMultiplier = 1.75f;

// in Update, replacing the targetVelocity line:
float speed = walkSpeed;
if (Keyboard.current != null && Keyboard.current.leftShiftKey.isPressed)
    speed *= sprintMultiplier;

Vector2 targetVelocity = input * speed;
```

Because the sprint changes only the *target*, the acceleration from Step 5 still applies: pressing Shift ramps up to 7 units/s rather than snapping there.

## Step 7: Face the way you're going

`flipX` would mirror the capsule but leave the eye behind, so flip with the scale instead:

```csharp
void FaceDirection(float x)
{
    if (Mathf.Approximately(x, 0f)) return;

    Vector3 scale = transform.localScale;
    scale.x = Mathf.Abs(scale.x) * Mathf.Sign(x);
    transform.localScale = scale;
}
```

Call `FaceDirection(input.x);` at the end of `Update`. `Mathf.Abs` keeps the size you set (0.8), and `Mathf.Sign` supplies the direction, so the explorer flips without growing or shrinking. Facing follows the *input*, not the velocity, so the explorer turns the instant you press the other key, while its body is still decelerating.

## Step 8: Arena walls

The explorer can walk off the green floor. Clamp the next position to a rectangle centered on the origin:

```csharp
[SerializeField] private Vector2 arenaSize = new Vector2(15.2f, 7.4f);

// in Update, replacing the transform.position line:
Vector3 next = transform.position + (Vector3)(velocity * Time.deltaTime);
Vector2 half = arenaSize / 2f;

float clampedX = Mathf.Clamp(next.x, -half.x, half.x);
float clampedY = Mathf.Clamp(next.y, -half.y, half.y);
if (clampedX != next.x) velocity.x = 0f;
if (clampedY != next.y) velocity.y = 0f;

transform.position = new Vector3(clampedX, clampedY, next.z);
```

Why 15.2 by 7.4 and not 16 by 9? The clamp limits the explorer's *center*. Shrinking the area by the explorer's own width (0.8) and height (1.6) keeps its whole body on the floor.

Zeroing the velocity when you hit a wall matters more than it looks. Without it, pushing into a wall keeps the velocity at full speed, and when you reverse, the explorer spends a moment decelerating from a speed it wasn't really moving at. The walls feel sticky.

To see the limits while editing, add this method; it draws a yellow outline whenever `Explorer` is selected:

```csharp
void OnDrawGizmosSelected()
{
    Gizmos.color = Color.yellow;
    Gizmos.DrawWireCube(Vector3.zero, new Vector3(arenaSize.x, arenaSize.y, 0f));
}
```

## The finished script

```csharp title="TopDownMover.cs"
using UnityEngine;
using UnityEngine.InputSystem;

public class TopDownMover : MonoBehaviour
{
    [Header("Speed")]
    [SerializeField] private float walkSpeed = 4f;
    [SerializeField] private float sprintMultiplier = 1.75f;
    [SerializeField] private float acceleration = 30f;

    [Header("Arena")]
    [SerializeField] private Vector2 arenaSize = new Vector2(15.2f, 7.4f);

    private Vector2 velocity;

    void Update()
    {
        Vector2 input = ReadMoveInput();
        if (input.sqrMagnitude > 1f) input = input.normalized;

        float speed = walkSpeed;
        if (Keyboard.current != null && Keyboard.current.leftShiftKey.isPressed)
            speed *= sprintMultiplier;

        Vector2 targetVelocity = input * speed;
        velocity = Vector2.MoveTowards(velocity, targetVelocity, acceleration * Time.deltaTime);

        MoveInsideArena();
        FaceDirection(input.x);
    }

    Vector2 ReadMoveInput()
    {
        Keyboard keyboard = Keyboard.current;
        if (keyboard == null) return Vector2.zero;

        Vector2 input = Vector2.zero;
        if (keyboard.aKey.isPressed || keyboard.leftArrowKey.isPressed) input.x -= 1f;
        if (keyboard.dKey.isPressed || keyboard.rightArrowKey.isPressed) input.x += 1f;
        if (keyboard.sKey.isPressed || keyboard.downArrowKey.isPressed) input.y -= 1f;
        if (keyboard.wKey.isPressed || keyboard.upArrowKey.isPressed) input.y += 1f;
        return input;
    }

    void MoveInsideArena()
    {
        Vector3 next = transform.position + (Vector3)(velocity * Time.deltaTime);
        Vector2 half = arenaSize / 2f;

        float clampedX = Mathf.Clamp(next.x, -half.x, half.x);
        float clampedY = Mathf.Clamp(next.y, -half.y, half.y);
        if (clampedX != next.x) velocity.x = 0f;
        if (clampedY != next.y) velocity.y = 0f;

        transform.position = new Vector3(clampedX, clampedY, next.z);
    }

    void FaceDirection(float x)
    {
        if (Mathf.Approximately(x, 0f)) return;

        Vector3 scale = transform.localScale;
        scale.x = Mathf.Abs(scale.x) * Mathf.Sign(x);
        transform.localScale = scale;
    }

    void OnDrawGizmosSelected()
    {
        Gizmos.color = Color.yellow;
        Gizmos.DrawWireCube(Vector3.zero, new Vector3(arenaSize.x, arenaSize.y, 0f));
    }
}
```

Press Play for a final test: all eight directions feel equally fast, Shift sprints, releasing the keys glides to a stop, the eye flips with the body, and every wall stops you cleanly.

:::quiz
Q: Why does facing use `input.x` instead of `velocity.x`?
- [x] So the explorer turns the moment the key is pressed, even while still sliding the other way
  Velocity lags behind input because of acceleration; facing based on it would feel delayed.
- [ ] Because velocity can't be negative
  Velocity is negative when moving left.
- [ ] Because `Mathf.Sign` only works on input values
  `Mathf.Sign` works on any float.

Q: In Step 8, what happens if you remove the two lines that zero the velocity at a wall?
- [ ] The explorer passes through the wall
  The clamp still holds the position inside the arena.
- [x] Reversing away from a wall is briefly sluggish
  The stored velocity stays at full speed into the wall, so turning around starts by decelerating from it.
- [ ] The game throws an error
  Nothing about the code becomes invalid.

Q: Why is the arena size 15.2 × 7.4 when the floor is 16 × 9?
- [ ] To leave a gap for a future wall sprite
  It's about the explorer's size, not decoration.
- [x] The clamp limits the explorer's center, so the area shrinks by the explorer's width and height
  Half of 0.8 on each side and half of 1.6 on top and bottom keeps the whole body on the floor.
- [ ] Unity's camera cuts off the edges
  The whole 16 × 9 floor is on screen.
:::

:::takeaways
- Measure movement with a log of `distance / Time.deltaTime` to prove it's frame-rate independent.
- Normalize input only when it's longer than 1, and keep velocity in a field so acceleration can shape it.
- Change the target speed for sprinting; let acceleration handle the transition.
- Flip with `localScale` when children must follow, and zero velocity at walls so they don't feel sticky.
:::

## Ideas to extend it

-   Add separate `acceleration` and `deceleration` values, so the explorer starts quickly but glides to a stop.
-   Replace the fixed arena with one read from the `Arena` sprite's bounds: `GetComponent<SpriteRenderer>().bounds` on a serialized reference.
-   Read the gamepad too: `Gamepad.current?.leftStick.ReadValue()` returns a `Vector2` you can add to the keyboard input before normalizing.
