## Warm-up: predict the animation

A teammate wrote this line and says "running right works, but running left stays in Idle." The Idle → Run condition is **Speed Greater 0.1**.

```csharp
animator.SetFloat("Speed", rb.linearVelocity.x);
```

Before reading on, decide why. Running left gives a negative x velocity such as -5, and -5 is not greater than 0.1, so the transition never fires. The fix is `Mathf.Abs(rb.linearVelocity.x)`: the Animator needs "how fast," and the sprite's `flipX` already handles "which way."

### Exercise 1: Add a Fall state

Right now the player shows the Jump clip all the way up and all the way down. Add a `Fall` clip that plays while moving downward in the air, and a `VerticalSpeed` Float parameter that drives it.

Expected behavior:

```text
On the ground:          Idle or Run
Leaving the ground:     Jump
At the top of the arc:  Jump switches to Fall
Landing:                Fall switches to Idle
```

:::hint
The top of a jump is the moment vertical velocity goes from positive to negative. You need one transition into Fall and one out of it, and neither should wait for an exit time.
:::

:::solution
Add `VerticalSpeed` (Float) in the Parameters tab, then make two transitions, both with **Has Exit Time** off and **Transition Duration** 0:

| From → To | Conditions |
| --- | --- |
| Jump → Fall | VerticalSpeed Less -0.1 |
| Fall → Idle | Grounded true |

In `PlayerAnimation`, add a hash and one line in `Update`:

```csharp
static readonly int VerticalSpeedId = Animator.StringToHash("VerticalSpeed");

// inside Update, after the other SetFloat:
animator.SetFloat(VerticalSpeedId, rb.linearVelocity.y);
```

Here you want the sign, so there's no `Mathf.Abs`. The small -0.1 margin stops Fall from flickering on for a single frame when the player brushes a ledge. If the player walks off a ledge without jumping, add Run → Fall with "Grounded false" and "VerticalSpeed Less -0.1" too.
:::

### Exercise 2: Read the compiler error

This script won't compile:

```csharp
using System;
using UnityEngine;

public class Footsteps : MonoBehaviour
{
    [SerializeField] AudioClip[] steps;
    public event Action Stepped;

    public AudioClip Pick() => steps[Random.Range(0, steps.Length)];
}
```

The Console says:

```text
error CS0104: 'Random' is an ambiguous reference between 'UnityEngine.Random' and 'System.Random'
```

Explain the error and give two fixes.

:::hint
Look at the two `using` lines. Each namespace contains a type called `Random`.
:::

:::solution
`using System;` (needed for `Action`) brings in `System.Random`, and `using UnityEngine;` brings in `UnityEngine.Random`. The compiler refuses to guess which one you mean. Either fix works:

```csharp
// Fix 1: say which one at the call site
public AudioClip Pick() => steps[UnityEngine.Random.Range(0, steps.Length)];

// Fix 2: add an alias under the using lines
using Random = UnityEngine.Random;
```

Notice that `Random.Range(0, steps.Length)` with whole numbers never returns `steps.Length`: the int version excludes the maximum, which is exactly right for array indexes.
:::

### Exercise 3: A countdown timer that turns red

Show a 90-second countdown in the top-center of the HUD as `m:ss`. Under 10 seconds the text turns red. At zero, call `health.TakeDamage(health.Max)` so the existing game-over flow runs.

Sample output on screen:

```text
1:30   (start)
1:05
0:10   (white)
0:09   (red)
0:00   (game over)
```

:::hint
Count down a float with `Time.deltaTime`, but display a whole number of seconds. Rounding up with `Mathf.CeilToInt` means the display shows 0:00 only when time has really run out.
:::

:::solution
Check the formatting rule quickly in Python before writing the C#:

```python run
import math

for remaining in [90.0, 65.2, 10.0, 9.99, 0.4, 0.0]:
    total = math.ceil(remaining)
    color = "red" if remaining < 10 else "white"
    print(f"{remaining:6.2f}s -> {total // 60}:{total % 60:02d} ({color})")
```

The C# version does the same thing every frame:

```csharp
using TMPro;
using UnityEngine;

public class CountdownTimer : MonoBehaviour
{
    [SerializeField] TextMeshProUGUI label;
    [SerializeField] Health health;
    [SerializeField] float seconds = 90f;

    float remaining;
    bool finished;

    void Start() => remaining = seconds;

    void Update()
    {
        if (finished) return;

        remaining = Mathf.Max(remaining - Time.deltaTime, 0f);
        int total = Mathf.CeilToInt(remaining);
        label.text = $"{total / 60}:{total % 60:00}";
        label.color = remaining < 10f ? Color.red : Color.white;

        if (remaining == 0f)
        {
            finished = true;
            health.TakeDamage(health.Max);
        }
    }
}
```

`{total % 60:00}` pads the seconds to two digits. Because the timer uses `Time.deltaTime`, it stops on its own when the game-over screen sets `Time.timeScale` to 0. Updating the text every frame is fine here since the value really does change; for a cheaper version, only assign `label.text` when `total` changes.
:::

### Exercise 4: Footsteps that don't sound robotic

Play a footstep every 0.3 seconds while the player is on the ground and moving faster than 0.5 units per second. Pick a random clip from an array each time.

:::hint
Keep a countdown float. Subtract `Time.deltaTime` each frame while walking; when it reaches zero, play a step and reset it to 0.3. Reuse the `Grounded` check you already have.
:::

:::solution
```csharp
using UnityEngine;

public class Footsteps : MonoBehaviour
{
    [SerializeField] AudioClip[] steps;
    [SerializeField] float interval = 0.3f;
    [SerializeField] float minSpeed = 0.5f;
    [SerializeField] LayerMask groundLayers;

    Rigidbody2D rb;
    ContactFilter2D groundFilter;
    float untilNextStep;

    void Awake()
    {
        rb = GetComponent<Rigidbody2D>();
        groundFilter.SetLayerMask(groundLayers);
        groundFilter.SetNormalAngle(45f, 135f);
    }

    void Update()
    {
        bool walking = rb.IsTouching(groundFilter) && Mathf.Abs(rb.linearVelocity.x) > minSpeed;
        if (!walking)
        {
            untilNextStep = 0f;   // the first step plays as soon as walking starts
            return;
        }

        untilNextStep -= Time.deltaTime;
        if (untilNextStep <= 0f)
        {
            AudioClip clip = steps[Random.Range(0, steps.Length)];
            SoundPlayer.Instance.Play(clip, 0.5f);
            untilNextStep = interval;
        }
    }
}
```

Three or four clips plus the pitch variation in `SoundPlayer` is enough to stop the ear from spotting the repeat. Resetting to zero when the player stops makes the first step land on the first frame of movement, which feels connected to the input.
:::

### Exercise 5: A heartbeat at low health

When health drops to 1, start a looping heartbeat sound. When the player heals above 1 (or the scene restarts), it stops. Use the `Changed` event, not `Update`.

:::hint
Give this script its own Audio Source with **Loop** ticked and **Play On Awake** unticked. `AudioSource.isPlaying` tells you whether it's already going, so you don't restart it on every hit.
:::

:::solution
```csharp
using UnityEngine;

[RequireComponent(typeof(AudioSource))]
public class LowHealthWarning : MonoBehaviour
{
    [SerializeField] Health health;
    [SerializeField] int threshold = 1;

    AudioSource heartbeat;

    void Awake() => heartbeat = GetComponent<AudioSource>();
    void OnEnable() => health.Changed += OnChanged;
    void OnDisable() => health.Changed -= OnChanged;

    void OnChanged(int current, int max)
    {
        bool low = current > 0 && current <= threshold;
        if (low && !heartbeat.isPlaying) heartbeat.Play();
        else if (!low && heartbeat.isPlaying) heartbeat.Stop();
    }
}
```

This is a case for `Play()` rather than `PlayOneShot`: there's one looping clip that you need to stop later, and `Stop()` controls the source's own clip. The `current > 0` check silences the heartbeat on death so it doesn't play over the Game Over panel.
:::

### Exercise 6: A pause menu that still works while paused

Pressing **Escape** shows a `PausePanel` with a Resume button and freezes the game. Pressing Escape again, or clicking Resume, unfreezes it. Sound effects and music should pause too.

:::hint
`Time.timeScale = 0` stops physics and anything that uses `Time.deltaTime`, but `Update` still runs, so you can still read the keyboard. `AudioListener.pause` pauses every Audio Source at once. Hook Resume to a public method through the button's **On Click ()** list.
:::

:::solution
```csharp
using UnityEngine;
using UnityEngine.InputSystem;

public class PauseMenu : MonoBehaviour
{
    [SerializeField] GameObject panel;

    bool paused;

    void Start() => panel.SetActive(false);

    void Update()
    {
        if (Keyboard.current != null && Keyboard.current.escapeKey.wasPressedThisFrame)
            SetPaused(!paused);
    }

    public void Resume() => SetPaused(false);

    void SetPaused(bool value)
    {
        paused = value;
        panel.SetActive(paused);
        Time.timeScale = paused ? 0f : 1f;
        AudioListener.pause = paused;
    }
}
```

Put it on the HUD (an always-active object), drag `PausePanel` into **Panel**, and point the Resume button's On Click at `PauseMenu.Resume`. UI buttons keep working at a time scale of 0 because the EventSystem doesn't depend on game time. If you animate the pause panel, set that Animator's **Update Mode** to **Unscaled Time**, or it will freeze along with everything else. And don't let Escape unpause the Game Over screen: check that the player is alive before toggling.
:::

### Challenge: Feedback everyone can perceive

Some players can't hear your sounds, can't tell red from green, or get headaches from flashing. Add a small **Options** panel (reachable from the pause menu) with:

1. A **Reduce flashing** toggle. When it's on, `HurtFeedback` tints the sprite once for 0.5 seconds instead of blinking.
2. A **Captions** toggle. When it's on, important sounds also show a short text line near the bottom of the screen for 1.5 seconds, such as `[hit]`, `[coin]`, or `[heartbeat]`.
3. A health bar that doesn't rely on color alone: show the number (`3/5`) beside the bar.

Keep the option values in one `GameOptions` script with static fields for now. In Module 7 you'll save them with `PlayerPrefs` so they survive a restart.

:::hint
A UI **Toggle** has an `onValueChanged` event that passes the new `bool`. For captions, give `SoundPlayer.Play` an optional caption string and let a `CaptionLabel` script subscribe to a static event that `SoundPlayer` raises.
:::
