Hand your game to a friend and watch them play. They brush a spike, lose a heart, and keep walking, because the only thing that changed was a number in an Inspector they can't see. Ten seconds later they "die out of nowhere" and put the controller down. The code worked perfectly. The game just never told them anything.

Players find out what happened through three channels: what moves, what they can read, and what they hear. Anything that matters should reach them through at least two.

| Event | Animation | UI | Audio |
| --- | --- | --- | --- |
| Took damage | Hurt pose, sprite flashes | Health bar drops | Short hit sound |
| Picked up a coin | Coin disappears | Score ticks up | Bright chime |
| Low on health | (optional) slower walk | Bar turns red | Heartbeat loop |
| Paused | Everything freezes | Pause panel appears | Music pauses |

Below is how each channel works in Unity 6. The build-along that follows wires all three into your game.

## Clips hold the frames; the Animator Controller picks which clip plays

Think of a flipbook for every action (idle, run, jump, hurt) plus a referee who decides which flipbook is open right now. The flipbooks are **Animation Clips**. The referee is an **Animator Controller**.

More precisely:

- An **Animation Clip** (`.anim` file) stores keyframes over time. In a 2D sprite clip, each keyframe swaps the Sprite shown by the `SpriteRenderer`.
- An **Animator Controller** (`.controller` file) is a state machine. Each **state** plays one clip. **Transitions** are arrows between states, and each arrow has **conditions**.
- Conditions are written in terms of **parameters**, which come in four types: Float, Int, Bool, and Trigger. A Trigger is a Bool that switches itself off as soon as a transition uses it.
- The **Animator** component on your Player runs the controller every frame.

To make the first clip, select the Player, open **Window > Animation > Animation**, click **Create**, and save the clip as `Idle.anim`. Unity creates the clip, creates an Animator Controller beside it, and adds an Animator component to the Player in one step. Drag the idle frames from the Project window onto the timeline. For the other actions, open the clip dropdown at the top left of the Animation window and choose **Create New Clip...**.

Then open **Window > Animation > Animator** to see the controller as a graph. Here is the one this module builds:

```mermaid caption="The player's Animator Controller. Each arrow is a transition, labeled with its condition."
stateDiagram-v2
    state "Any State" as AnyState
    [*] --> Idle
    Idle --> Run: Speed above 0.1
    Run --> Idle: Speed below 0.1
    Idle --> Jump: Grounded is false
    Run --> Jump: Grounded is false
    Jump --> Idle: Grounded is true
    AnyState --> Hurt: Hurt trigger
    Hurt --> Idle: clip finished
```

Add the parameters in the **Parameters** tab on the left of the Animator window (the **+** button). Right-click a state and choose **Make Transition** to draw an arrow, then click the arrow to edit it in the Inspector.

Two transition settings decide whether your animation feels responsive or sluggish:

- **Has Exit Time** makes the transition wait until the current clip reaches its **Exit Time** (1 means "the end of the clip"). That's right for Hurt → Idle, which should play the whole hurt clip and then return. It's wrong for Idle → Run, where the player pressed a key and expects to see running now. Untick it for every transition that a parameter controls.
- **Transition Duration**, under **Settings**, blends two clips over time. Sprite frames can't be blended halfway, so set it to 0 for crisp 2D art.

## Feeding parameters from C#

The Animator only knows what you tell it. A small script reads the Rigidbody2D and copies the facts into parameters every frame:

```csharp
using UnityEngine;

public class PlayerAnimation : MonoBehaviour
{
    static readonly int SpeedId = Animator.StringToHash("Speed");
    static readonly int GroundedId = Animator.StringToHash("Grounded");

    [SerializeField] LayerMask groundLayers;

    Animator animator;
    Rigidbody2D rb;
    SpriteRenderer sprite;
    ContactFilter2D groundFilter;

    void Awake()
    {
        animator = GetComponent<Animator>();
        rb = GetComponent<Rigidbody2D>();
        sprite = GetComponent<SpriteRenderer>();

        groundFilter.SetLayerMask(groundLayers);
        groundFilter.SetNormalAngle(45f, 135f); // only contacts whose normal points mostly up
    }

    void Update()
    {
        float xSpeed = rb.linearVelocity.x;
        animator.SetFloat(SpeedId, Mathf.Abs(xSpeed));
        animator.SetBool(GroundedId, rb.IsTouching(groundFilter));

        if (xSpeed > 0.05f) sprite.flipX = false;
        else if (xSpeed < -0.05f) sprite.flipX = true;
    }
}
```

Three lines deserve a closer look. `Mathf.Abs` matters because running left gives a negative speed, and the condition "Speed above 0.1" would never be true for it. `Animator.StringToHash` turns each parameter name into an integer once, so the name is typed in exactly one place and Unity doesn't compare strings every frame. The normal-angle filter counts only surfaces under the player's feet as ground: touching a wall gives a sideways normal (near 0° or 180°), which is filtered out.

This script reads the movement and never changes it. Your `PlayerController` from Module 4 already exposes its ground check as the `IsGrounded` property, so read that instead of checking twice.

Press Play with the Animator window open. The current state shows a blue progress bar, and the Parameters tab updates live, which is the fastest way to see why a transition isn't firing.

## A Canvas that fits every screen

UI lives on a sheet of glass in front of the camera, not in the game world. In Unity's built-in UI system that glass is a **Canvas**. With **Render Mode** set to **Screen Space - Overlay** (the default), the Canvas is drawn on top of everything in screen pixels, no matter where the camera goes.

Right-click in the Hierarchy and choose **UI > Text - TextMeshPro**. Unity creates a Canvas, an EventSystem, and a `Text (TMP)` object. The first time, a **TMP Importer** window asks to import the essential resources; click **Import TMP Essentials**.

Now the trap. The Canvas Scaler starts in **Constant Pixel Size** mode, so a 36-pixel score looks fine at 1920 × 1080, tiny on a 4K monitor, and huge in a small browser window. Select the Canvas and change its **Canvas Scaler**:

- **UI Scale Mode**: Scale With Screen Size
- **Reference Resolution**: 1920 × 1080
- **Screen Match Mode**: Match Width Or Height, with **Match** at 0.5

You now design the HUD once at 1080p, and Unity scales it to the real screen. Then anchor each element to the corner it belongs to. In the Rect Transform, click the anchor presets square and hold **Alt** (**Option** on a Mac) while you pick top-left, so the score moves to that corner as well as anchoring there.

:::try
In the Game view, open the aspect dropdown (it says something like "Free Aspect" or "Full HD") and switch between a wide and a tall size. With Scale With Screen Size, the score stays the same size relative to the screen and stays in its corner.
:::

Changing the text from code takes one field and one assignment:

```csharp
using TMPro;
using UnityEngine;

public class ScoreLabel : MonoBehaviour
{
    [SerializeField] TextMeshProUGUI label;

    public void Show(int score)
    {
        label.text = $"Score: {score}";
    }
}
```

## Sound: one listener, many sources

Unity's audio works like a room with one microphone and many speakers. The microphone is the **Audio Listener**, already on the Main Camera. Each speaker is an **Audio Source** component, and the sound file it plays is an **AudioClip**.

The Audio Source settings you'll use most:

- **Play On Awake** starts the clip when the object appears. Good for music, bad for a hurt sound.
- **Loop** repeats the clip. Again, music yes, effects no.
- **Spatial Blend** at 0 means 2D: the sound ignores where things are in the scene. Leave it at 0 for most 2D games.

There are two ways to play an effect, and the difference shows up the moment the player grabs two coins quickly:

```csharp
using UnityEngine;

public class SfxPlayer : MonoBehaviour
{
    [SerializeField] AudioSource source;
    [SerializeField] AudioClip coinClip;

    public void PlayCoinCutOff()
    {
        source.clip = coinClip;
        source.Play();              // restarts the source: the first chime is cut off
    }

    public void PlayCoin()
    {
        source.pitch = Random.Range(0.95f, 1.05f);
        source.PlayOneShot(coinClip, 0.8f);   // layers on top of anything already playing
    }
}
```

`Play()` restarts the one clip the source owns. `PlayOneShot` doesn't cancel clips that are already playing, so ten quick coins give ten overlapping chimes. The random pitch keeps repeated sounds from sounding like a machine gun. Pitch belongs to the whole source, though, so it also bends anything else that source is playing.

Give music its own Audio Source with Play On Awake and Loop ticked and Volume around 0.4, so you can change music and effects separately.

## Events keep gameplay and feedback apart

Here's the design mistake almost everyone makes first: the health script calls the health bar, the animator, the sound player, and the camera shake directly. Each new piece of feedback means editing the health script, and the health script breaks in any scene without a HUD.

The fix is for health to announce "I changed" and let anything that cares listen. In C# that announcement is an **event**:

```csharp
using System;
using UnityEngine;

public class Health : MonoBehaviour
{
    [SerializeField] int maxHealth = 5;

    public int Current { get; private set; }
    public int Max => maxHealth;

    public event Action<int, int> Changed;   // (current, max)
    public event Action Died;

    void Awake() => Current = maxHealth;

    public void TakeDamage(int amount)
    {
        if (Current == 0) return;
        Current = Mathf.Max(Current - amount, 0);
        Changed?.Invoke(Current, maxHealth);
        if (Current == 0) Died?.Invoke();
    }
}
```

And one listener:

```csharp
using TMPro;
using UnityEngine;

public class HealthLabel : MonoBehaviour
{
    [SerializeField] Health health;
    [SerializeField] TextMeshProUGUI label;

    void OnEnable() => health.Changed += Show;
    void OnDisable() => health.Changed -= Show;
    void Start() => Show(health.Current, health.Max);

    void Show(int current, int max) => label.text = $"HP {current}/{max}";
}
```

`Changed?.Invoke(...)` calls every subscriber, and the `?.` means "do nothing if nobody subscribed" instead of throwing. The listener subscribes in `OnEnable` and unsubscribes in `OnDisable`, so a destroyed HUD never gets called. It draws the starting value in `Start` because Unity runs every object's `Awake` before any `Start`, so `health.Current` is already set by then.


:::warning
**Parameter names must match exactly.** `animator.SetFloat("speed", 2f)` when the parameter is called `Speed` doesn't throw an error. It logs the warning `Parameter 'speed' does not exist.` and nothing animates. Declaring each hash once with `Animator.StringToHash` keeps the name in a single place.
:::

:::warning
**An Any State transition can fire every frame.** Any State → Jump with the condition "Grounded is false" restarts Jump on every frame you're in the air, so the clip freezes on its first frame. Untick **Can Transition To Self** on that transition, or use a Trigger, which switches itself off after one use.
:::

:::quiz
Q: The Idle → Run transition still has **Has Exit Time** ticked with Exit Time 1, and the Idle clip is 1 second long. The player presses right halfway through the Idle loop. What happens?
- [ ] Run starts immediately
  It would with Has Exit Time unticked. With it ticked, the transition also waits for the exit time.
- [x] The player slides for up to half a second before the Run clip starts
  The transition can only fire when Idle reaches the end of its loop, so the sprite keeps idling while the body moves.
- [ ] Run never starts
  It does start, just late: once the Idle clip reaches 100%, the Speed condition is checked and passes.

Q: Your coin script runs `source.clip = coinClip; source.Play();`. The player grabs three coins within 0.2 seconds. What does the player hear?
- [ ] Three overlapping chimes
  That's what `PlayOneShot` gives you. `Play` owns a single clip and restarts it.
- [x] One chime that restarts twice, with the first two cut off
  Each `Play()` call restarts the same clip from the beginning.
- [ ] Nothing, because the clip is already playing
  `Play()` doesn't skip when a clip is playing; it restarts it.

Q: You want the Hurt animation to play once per hit, then return to Idle. Which parameter type should the Any State → Hurt transition use?
- [ ] Bool, set to true when hit
  A Bool stays true until your code clears it, so Any State keeps re-entering Hurt.
- [ ] Float, set to the damage amount
  A Float can work with a condition, but you'd still need to reset it, which is exactly what a Trigger does for you.
- [x] Trigger, fired with `SetTrigger`
  The transition uses the trigger and the trigger switches itself off, so one hit gives one Hurt.

Q: The Canvas Scaler is left on **Constant Pixel Size**. You designed a 48-pixel score at 1920 × 1080. How does it look on a 3840 × 2160 monitor?
- [x] Half as tall relative to the screen
  Constant Pixel Size keeps 48 real pixels, and the screen now has twice as many.
- [ ] Exactly the same as at 1080p
  That's what Scale With Screen Size does, by scaling everything by 2.
- [ ] Twice as tall relative to the screen
  Pixels don't grow on a bigger screen; they shrink relative to it.
:::

:::takeaways
- Clips hold frames; the Animator Controller is a state machine whose transitions check parameters you set from code.
- Untick Has Exit Time on input-driven transitions, and set Transition Duration to 0 for sprite art.
- Use Scale With Screen Size on the Canvas Scaler and anchor each UI element to its corner.
- `PlayOneShot` layers sounds; `Play` restarts the one clip a source owns.
- Gameplay scripts raise events, and feedback scripts subscribe in `OnEnable` and unsubscribe in `OnDisable`.
:::
