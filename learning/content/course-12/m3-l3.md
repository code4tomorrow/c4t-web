## Warm-up

`speed` is 3 and the game runs at a steady 50 FPS, so `Time.deltaTime` is 0.02. How far does `speed * Time.deltaTime` move the player each frame, and after one second?

Each frame moves 3 × 0.02 = **0.06 units**. Fifty frames make one second, and 50 × 0.06 = **3 units**, which is exactly `speed`. That's the point of multiplying by `deltaTime`.

### Exercise 1: Three compile errors

This script won't compile. Fix all three errors without changing what it's meant to do (move right at 2.5 units per second, starting half a unit up).

```csharp title="Drifter.cs"
using UnityEngine;

public class Drifter : MonoBehaviour
{
    [SerializeField] private float speed = 2.5;

    void Start()
    {
        transform.position = new Vector3(0f, 1 / 2, 0f);
    }

    void Update()
    {
        Vector2 step = Vector2.right * speed * Time.deltaTime;
        transform.position = transform.position + step;
    }
}
```

The Console shows:

```text
Assets/Scripts/Drifter.cs(5,44): error CS0664: Literal of type double cannot be implicitly converted to type 'float'; use an 'F' suffix to create a literal of this type
Assets/Scripts/Drifter.cs(15,30): error CS0034: Operator '+' is ambiguous on operands of type 'Vector3' and 'Vector2'
```

:::hint
Only two errors are reported, but there are three bugs. One of them compiles fine and quietly produces the wrong number. Which expression in `Start` involves two integers?
:::

:::solution
```csharp title="Drifter.cs"
using UnityEngine;

public class Drifter : MonoBehaviour
{
    [SerializeField] private float speed = 2.5f;

    void Start()
    {
        transform.position = new Vector3(0f, 1f / 2f, 0f);
    }

    void Update()
    {
        Vector2 step = Vector2.right * speed * Time.deltaTime;
        transform.position = transform.position + (Vector3)step;
    }
}
```

`2.5` is a `double`, so it needs the `f`. `1 / 2` is integer division, which gives 0 with no error, so the object started at y = 0 instead of 0.5. The cast tells C# which of the two automatic conversions you mean.
:::

### Exercise 2: Prove it with the frame rate

Write a `FrameRateSwitcher` component that sets the game to 15 FPS when you press **1**, 60 FPS on **2**, and 240 FPS on **3**, and logs the change. Put it on the Main Camera, then hold D and watch the explorer at each setting.

Sample output:

```text
Target frame rate: 15
Target frame rate: 240
```

At 15 FPS the movement looks choppy but covers the same distance per second as at 240.

:::hint
`Application.targetFrameRate` is ignored while V-Sync is on, so set `QualitySettings.vSyncCount = 0` first. The number keys above the letters are `digit1Key`, `digit2Key`, and `digit3Key`.
:::

:::solution
```csharp title="FrameRateSwitcher.cs"
using UnityEngine;
using UnityEngine.InputSystem;

public class FrameRateSwitcher : MonoBehaviour
{
    void Start()
    {
        QualitySettings.vSyncCount = 0;
    }

    void Update()
    {
        Keyboard keyboard = Keyboard.current;
        if (keyboard == null) return;

        if (keyboard.digit1Key.wasPressedThisFrame) SetRate(15);
        if (keyboard.digit2Key.wasPressedThisFrame) SetRate(60);
        if (keyboard.digit3Key.wasPressedThisFrame) SetRate(240);
    }

    void SetRate(int fps)
    {
        Application.targetFrameRate = fps;
        Debug.Log("Target frame rate: " + fps);
    }
}
```

In the Editor, the target affects the Game view, which is where Play mode runs. Try deleting `* Time.deltaTime` from a copy of the mover and switching rates: the explorer becomes 16 times faster at 240 than at 15.
:::

### Exercise 3: A dash with a cooldown

Add a dash to a copy of `TopDownMover`. Pressing Space launches the explorer in its current input direction at 16 units per second for 0.15 seconds. After a dash, Space does nothing for 0.8 seconds. With no keys held, the dash goes the way the explorer faces.

:::hint
Keep two countdown floats, `dashTimeLeft` and `cooldownLeft`, and subtract `Time.deltaTime` from both every frame. While `dashTimeLeft > 0`, set the velocity straight to the dash velocity instead of using `MoveTowards`. The facing direction is the sign of `transform.localScale.x`.
:::

:::solution
Add these fields:

```csharp
[Header("Dash")]
[SerializeField] private float dashSpeed = 16f;
[SerializeField] private float dashDuration = 0.15f;
[SerializeField] private float dashCooldown = 0.8f;

private float dashTimeLeft;
private float cooldownLeft;
private Vector2 dashDirection;
```

Then replace the velocity part of `Update` with:

```csharp
dashTimeLeft -= Time.deltaTime;
cooldownLeft -= Time.deltaTime;

bool dashPressed = Keyboard.current != null && Keyboard.current.spaceKey.wasPressedThisFrame;
if (dashPressed && cooldownLeft <= 0f)
{
    dashDirection = input != Vector2.zero ? input : new Vector2(Mathf.Sign(transform.localScale.x), 0f);
    dashTimeLeft = dashDuration;
    cooldownLeft = dashDuration + dashCooldown;
}

if (dashTimeLeft > 0f)
{
    velocity = dashDirection * dashSpeed;
}
else
{
    Vector2 targetVelocity = input * speed;
    velocity = Vector2.MoveTowards(velocity, targetVelocity, acceleration * Time.deltaTime);
}
```

`input` is already normalized, so diagonal dashes aren't longer. When the dash ends, `MoveTowards` takes over from dash speed, which gives a short slide out of it. The cooldown starts at the dash's own length plus 0.8, so the 0.8 seconds count from when the dash *finishes*.
:::

### Exercise 4: Follow the mouse

Make a small Circle named `Firefly` with a `MouseFollower` script that flies toward the mouse pointer at 5 units per second and stops on it, without overshooting.

:::hint
`Mouse.current.position.ReadValue()` is in screen pixels. `Camera.main.ScreenToWorldPoint` converts it, but for an orthographic camera the result's z is the camera's z (-10). An object at the camera's depth is invisible, so set z to 0.
:::

:::solution
```csharp title="MouseFollower.cs"
using UnityEngine;
using UnityEngine.InputSystem;

public class MouseFollower : MonoBehaviour
{
    [SerializeField] private float speed = 5f;

    void Update()
    {
        Mouse mouse = Mouse.current;
        if (mouse == null) return;

        Vector3 target = Camera.main.ScreenToWorldPoint(mouse.position.ReadValue());
        target.z = 0f;

        transform.position = Vector3.MoveTowards(transform.position, target, speed * Time.deltaTime);
    }
}
```

Without `target.z = 0f`, the firefly "disappears" the moment you press Play: it moves to z = -10, the camera's own position, which is closer than the camera's near clipping plane. `MoveTowards` never overshoots, so the firefly settles exactly on the pointer.
:::

### Exercise 5: Wrap around the screen

Write a `ScreenWrap` component: when the object leaves one edge of the camera's view, it reappears at the opposite edge, like the ship in Asteroids. It should work alongside any movement script. Test it on the explorer with **Arena Size** set to (100, 100) so the clamp doesn't interfere.

:::hint
The camera's half-height in world units is `orthographicSize`, and the half-width is that times `aspect`. Do the wrap in `LateUpdate`, which runs after every `Update`, so the mover has already moved this frame.
:::

:::solution
```csharp title="ScreenWrap.cs"
using UnityEngine;

public class ScreenWrap : MonoBehaviour
{
    void LateUpdate()
    {
        Camera cam = Camera.main;
        float halfHeight = cam.orthographicSize;
        float halfWidth = halfHeight * cam.aspect;
        Vector3 center = cam.transform.position;
        Vector3 p = transform.position;

        if (p.x > center.x + halfWidth) p.x = center.x - halfWidth;
        else if (p.x < center.x - halfWidth) p.x = center.x + halfWidth;

        if (p.y > center.y + halfHeight) p.y = center.y - halfHeight;
        else if (p.y < center.y - halfHeight) p.y = center.y + halfHeight;

        transform.position = p;
    }
}
```

Measuring from the camera's position means the wrap still works if the camera moves. Because it's a separate component, the same script can wrap asteroids, bullets, or the player.
:::

### Exercise 6: Tile-by-tile movement

Write a `GridMover` for a puzzle-style game: holding an arrow key moves the object exactly one unit in that direction, sliding smoothly over 1/6 of a second, and it can't change direction halfway through a tile. It should start snapped to the nearest whole-number position.

:::hint
Store a `target` position and a `moving` flag. While moving, `MoveTowards` the target and ignore input; when you arrive, clear the flag. Read input only when not moving. `Mathf.Round` snaps a float to the nearest whole number.
:::

:::solution
```csharp title="GridMover.cs"
using UnityEngine;
using UnityEngine.InputSystem;

public class GridMover : MonoBehaviour
{
    [SerializeField] private float tilesPerSecond = 6f;

    private Vector3 target;
    private bool moving;

    void Start()
    {
        Vector3 p = transform.position;
        transform.position = new Vector3(Mathf.Round(p.x), Mathf.Round(p.y), 0f);
        target = transform.position;
    }

    void Update()
    {
        if (moving)
        {
            transform.position = Vector3.MoveTowards(transform.position, target, tilesPerSecond * Time.deltaTime);
            if (transform.position == target) moving = false;
            return;
        }

        Vector3 step = ReadStep();
        if (step != Vector3.zero)
        {
            target = transform.position + step;
            moving = true;
        }
    }

    Vector3 ReadStep()
    {
        Keyboard keyboard = Keyboard.current;
        if (keyboard == null) return Vector3.zero;

        if (keyboard.rightArrowKey.isPressed) return Vector3.right;
        if (keyboard.leftArrowKey.isPressed) return Vector3.left;
        if (keyboard.upArrowKey.isPressed) return Vector3.up;
        if (keyboard.downArrowKey.isPressed) return Vector3.down;
        return Vector3.zero;
    }
}
```

Using `isPressed` lets a held key walk tile after tile; `wasPressedThisFrame` would require one tap per tile, which suits some puzzle games better. Returning early from `ReadStep` means only one direction counts, so there are no diagonal steps.
:::

### Challenge: A turret that aims and fires

Build a stationary turret in the middle of the arena: a Square `Turret` with a child `Barrel` (a thin rectangle sticking out to the right). The barrel rotates to point at the mouse at all times, and a left click fires a bullet prefab from the barrel in the direction it's pointing. Bullets fly at 12 units per second and disappear after 2 seconds.

`Mathf.Atan2(y, x)` turns a direction into an angle, measured counterclockwise from the right. Note the argument order: y comes first.

```python run title="atan2_angles.py"
import math

for dx, dy in [(1, 0), (0, 1), (-1, 0), (0, -1), (1, 1), (-3, 4)]:
    angle = math.degrees(math.atan2(dy, dx))
    print(f"direction ({dx:2}, {dy:2}) -> {angle:7.2f} degrees")
```

:::hint
Get the mouse's world position as in Exercise 4, subtract the barrel's position to get a direction, convert it with `Atan2` and `Mathf.Rad2Deg`, and set the barrel's rotation with `Quaternion.Euler(0f, 0f, angle)`. A bullet can move along its own `transform.right`, so spawning it with the barrel's rotation is all the aiming it needs.
:::

:::solution
```csharp title="Turret.cs"
using UnityEngine;
using UnityEngine.InputSystem;

public class Turret : MonoBehaviour
{
    [SerializeField] private Transform barrel;
    [SerializeField] private GameObject bulletPrefab;

    void Update()
    {
        Mouse mouse = Mouse.current;
        if (mouse == null) return;

        Vector3 mouseWorld = Camera.main.ScreenToWorldPoint(mouse.position.ReadValue());
        mouseWorld.z = 0f;

        Vector2 toMouse = mouseWorld - barrel.position;
        float angle = Mathf.Atan2(toMouse.y, toMouse.x) * Mathf.Rad2Deg;
        barrel.rotation = Quaternion.Euler(0f, 0f, angle);

        if (mouse.leftButton.wasPressedThisFrame)
            Instantiate(bulletPrefab, barrel.position, barrel.rotation);
    }
}
```

```csharp title="Bullet.cs"
using UnityEngine;

public class Bullet : MonoBehaviour
{
    [SerializeField] private float speed = 12f;
    [SerializeField] private float lifetime = 2f;

    void Start()
    {
        Destroy(gameObject, lifetime);
    }

    void Update()
    {
        transform.position += transform.right * speed * Time.deltaTime;
    }
}
```

For the barrel to pivot around the turret instead of its own middle, make `Barrel` an empty child at the turret's center, and put the thin rectangle sprite inside it, offset to the right. Rotating the empty swings the sprite around the center, the same parent-child trick as the saw's tooth in Module 2. Point the turret's **Barrel** slot at the empty.
:::
