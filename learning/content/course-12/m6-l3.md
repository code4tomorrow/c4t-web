## Warm-up: where does the drone go next?

A drone has four waypoints and starts heading for index 0. After it reaches each one it runs `index = (index + 1) % 4;`. Write down the next eight indexes it heads for, then check:

```python run
index = 0
visited = []
for arrival in range(8):
    index = (index + 1) % 4
    visited.append(index)
print(visited)
```

The route loops, so after waypoint 3 the drone flies straight back to waypoint 0, crossing the whole room. That's fine for a circle-shaped route. For a route along a line, the next exercise is a better fit.

### Exercise 1: Ping-pong patrol

Make the drone go back and forth along its route instead of looping: with four waypoints it should head for 1, 2, 3, 2, 1, 0, 1, 2, and so on. Only the line that advances the index should change.

:::hint
Keep a `direction` that is +1 or -1. Before stepping, check whether the step would leave the array; if it would, flip the direction first.
:::

:::solution
Check the logic in Python first:

```python run
count = 4
index, direction = 0, 1
visited = []
for arrival in range(10):
    if not 0 <= index + direction < count:
        direction = -direction
    index += direction
    visited.append(index)
print(visited)
```

The C# version replaces the `%` line in `Patrol`:

```csharp
int direction = 1;

void AdvanceWaypoint()
{
    if (waypoints.Length < 2) return;
    int next = waypointIndex + direction;
    if (next < 0 || next >= waypoints.Length) direction = -direction;
    waypointIndex += direction;
}
```

Call `AdvanceWaypoint()` where `Patrol` used to update the index. The guard for fewer than two waypoints stops a one-point route from flipping direction forever.
:::

### Exercise 2: A walker that stays on its platform

Make a ground enemy (a slime, say) that walks left and right, turning around at walls and at the edge of a platform. It uses a **Dynamic** Rigidbody2D with gravity, and **Freeze Rotation Z** ticked under Constraints so it doesn't tip over.

Expected behavior:

```text
Platform 6 tiles wide:   walks to one edge, turns, walks to the other, forever
Wall in the way:         turns before touching it
Pushed off by the player: falls, lands, keeps patrolling the new floor
```

:::hint
Two raycasts each physics step. One points down from a spot just ahead of the feet ("is there floor ahead?"). The other points forward from the center ("is there a wall right in front?"). If there's no floor or there is a wall, flip direction.
:::

:::solution
```csharp
using UnityEngine;

[RequireComponent(typeof(Rigidbody2D))]
public class LedgeWalker : MonoBehaviour
{
    [SerializeField] float speed = 2f;
    [SerializeField] float lookAhead = 0.5f;
    [SerializeField] float floorProbe = 1f;
    [SerializeField] LayerMask groundLayers;

    Rigidbody2D rb;
    int direction = 1;

    void Awake() => rb = GetComponent<Rigidbody2D>();

    void FixedUpdate()
    {
        Vector2 forward = new Vector2(direction, 0f);
        Vector2 ahead = rb.position + forward * lookAhead;

        bool floorAhead = Physics2D.Raycast(ahead, Vector2.down, floorProbe, groundLayers);
        bool wallAhead = Physics2D.Raycast(rb.position, forward, lookAhead, groundLayers);

        if (!floorAhead || wallAhead) direction = -direction;

        rb.linearVelocity = new Vector2(direction * speed, rb.linearVelocity.y);
    }

    void OnDrawGizmosSelected()
    {
        Vector3 ahead = transform.position + new Vector3(direction * lookAhead, 0f, 0f);
        Gizmos.DrawLine(ahead, ahead + Vector3.down * floorProbe);
    }
}
```

Set `floorProbe` a little longer than the distance from the enemy's center to its feet; if it's too short, the ray never reaches the floor and the slime turns every step. Keep its own layer out of `groundLayers`, or the forward ray starts inside its own collider and always reports a wall. The script only sets the x velocity, so gravity still pulls it down if the player shoves it off a ledge.
:::

### Exercise 3: Fix a level that tests before it teaches

A teammate's level has these sections, left to right. Playtesters keep quitting in section 2.

```text
1. Long flat run with coins
2. Narrow shaft: spikes on the walls, a drone patrolling the shaft
3. A single spike pit with an easy jump
4. A drone patrolling an empty room
5. Exit
```

Rewrite the order (you may add or change sections) so each mechanic gets taught, tested, and then combined, and say what each section is for.

:::hint
List the mechanics first: spikes, drones, and the combination. Each needs its own safe introduction before the combination can be fair. Where would you put a checkpoint?
:::

:::solution
| # | Section | Purpose |
| --- | --- | --- |
| 1 | Short run with a coin trail | Warm up the controls |
| 2 | One spike pit with an easy jump | Teach spikes where failure is cheap (it was section 3) |
| 3 | Two pits with a shorter landing | Test spikes |
| 4 | Drone patrolling an empty room, seen from a ledge first | Teach drones (it was section 4) |
| 5 | Drone route crossing the path, pillar for cover | Test drones |
| 6 | Checkpoint and a quiet stretch | Rest before the hard part |
| 7 | Wide shaft with spikes and one drone | Twist: the combination, now fair (it was section 2) |
| 8 | Easy run to the exit | Conclude |

The original section 2 wasn't a bad idea, just early: it combined two mechanics the player hadn't met yet. Widening the shaft in its new position also leaves room to dodge, which a narrow shaft didn't.
:::

### Exercise 4: An attack that warns, commits, and recovers

Add three states after Chase. Within 2.5 units, the drone stops and glows orange for 0.5 seconds (**Windup**). Then it dashes 4 units in a straight line toward where the player was when the wind-up ended (**Dash**, 0.35 seconds, speed 9). Then it drifts slowly for 1 second (**Cooldown**) before returning to Chase.

:::hint
Each timed state needs an end time. Set it in `SetState` when the state begins, and in the `case`, compare `Time.time` against it. Lock the dash target at the moment Windup ends; if the dash kept tracking the player, nobody could dodge it.
:::

:::solution
```csharp
enum State { Patrol, Chase, Search, Windup, Dash, Cooldown }

[Header("Attack")]
[SerializeField] float attackRange = 2.5f;
[SerializeField] float windupSeconds = 0.5f;
[SerializeField] float dashSpeed = 9f;
[SerializeField] float dashSeconds = 0.35f;
[SerializeField] float cooldownSeconds = 1f;

Vector2 dashTarget;
float stateEndsAt;

// New and changed cases in FixedUpdate's switch:
case State.Chase:
    lastSeen = player.position;
    MoveTowards(lastSeen, chaseSpeed);
    if (!CanSeePlayer(loseRadius)) SetState(State.Search);
    else if (Vector2.Distance(rb.position, lastSeen) < attackRange) SetState(State.Windup);
    break;

case State.Windup:
    if (Time.time > stateEndsAt)
    {
        Vector2 toPlayer = ((Vector2)player.position - rb.position).normalized;
        dashTarget = rb.position + toPlayer * 4f;
        SetState(State.Dash);
    }
    break;

case State.Dash:
    MoveTowards(dashTarget, dashSpeed);
    if (Time.time > stateEndsAt) SetState(State.Cooldown);
    break;

case State.Cooldown:
    MoveTowards(lastSeen, patrolSpeed * 0.5f);
    if (Time.time > stateEndsAt) SetState(State.Chase);
    break;
```

And at the top of `SetState`:

```csharp
if (next == State.Windup) stateEndsAt = Time.time + windupSeconds;
if (next == State.Dash) stateEndsAt = Time.time + dashSeconds;
if (next == State.Cooldown) stateEndsAt = Time.time + cooldownSeconds;
```

Add an orange case to the color choice for Windup. This three-part shape (a warning the player can read, a committed action, and a window of safety afterward) is how most action games make attacks feel fair.
:::

### Exercise 5: Predict the pacing

The spawner from the build uses a curve that falls linearly from 6 seconds to 2 seconds over the first 120 seconds, then stays at 2. Before running anything, guess how many drones spawn in each 30-second block of a 3-minute run. Then work out when **Max Alive = 3** with a **15-second lifetime** starts to be the real limit.

:::hint
Simulate it: start at time 0, spawn, add the current interval, repeat. For the cap, think about how many drones are alive at once if a new one arrives every `interval` seconds and each lives 15.
:::

:::solution
```python run
def interval(t):
    if t >= 120:
        return 2.0
    return 6.0 + (2.0 - 6.0) * t / 120

t, spawns = 0.0, []
while t < 180:
    spawns.append(t)
    t += interval(t)

for start in range(0, 180, 30):
    count = sum(start <= s < start + 30 for s in spawns)
    print(f"{start:3d}-{start + 30:3d} s: {count} spawn attempts")
print("total:", len(spawns))

for t in [0, 30, 60, 90, 120]:
    print(f"at {t:3d} s: interval {interval(t):.1f} s, about {15 / interval(t):.1f} drones alive without a cap")
```

Spawn attempts climb from 6 in the first block to 15 in each of the last two. But with a 15-second lifetime, about 15 ÷ interval drones are alive at once, which reaches 3 when the interval drops to 5 seconds, 30 seconds in. After that the cap, not the curve, sets the pressure: attempts beyond it are skipped. If the late game feels flat, raise the cap over time instead of shortening the interval further.
:::

### Exercise 6: Spawn in waves

Replace the endless spawner in the twist room with three waves: 2 drones, then 3, then 5. Each wave starts 3 seconds after the previous wave is completely gone. A HUD label shows `Wave 2/3`, and at the end it shows `All waves cleared`.

:::hint
A `[System.Serializable]` class with `count` and `spacing` fields shows up as an editable list in the Inspector. `yield return new WaitUntil(() => condition)` waits until the condition is true. The drones need a way to disappear, so keep the lifetime from the build.
:::

:::solution
```csharp
using System.Collections;
using System.Collections.Generic;
using TMPro;
using UnityEngine;

public class WaveSpawner : MonoBehaviour
{
    [System.Serializable]
    public class Wave
    {
        public int count = 3;
        public float spacing = 1f;
    }

    [SerializeField] Wave[] waves;
    [SerializeField] EnemyAI enemyPrefab;
    [SerializeField] Transform[] spawnPoints;
    [SerializeField] Transform[] route;
    [SerializeField] Transform player;
    [SerializeField] TextMeshProUGUI waveLabel;
    [SerializeField] float enemyLifetime = 10f;
    [SerializeField] float breakSeconds = 3f;

    readonly List<EnemyAI> alive = new List<EnemyAI>();

    IEnumerator Start()
    {
        for (int w = 0; w < waves.Length; w++)
        {
            waveLabel.text = $"Wave {w + 1}/{waves.Length}";

            for (int i = 0; i < waves[w].count; i++)
            {
                Transform point = spawnPoints[i % spawnPoints.Length];
                EnemyAI enemy = Instantiate(enemyPrefab, point.position, Quaternion.identity);
                enemy.Setup(player, route);
                Destroy(enemy.gameObject, enemyLifetime);
                alive.Add(enemy);
                yield return new WaitForSeconds(waves[w].spacing);
            }

            yield return new WaitUntil(() => alive.TrueForAll(enemy => enemy == null));
            alive.Clear();
            yield return new WaitForSeconds(breakSeconds);
        }

        waveLabel.text = "All waves cleared";
    }
}
```

Fill the **Waves** list in the Inspector with counts 2, 3, and 5. Cycling spawn points with `i % spawnPoints.Length` spreads each wave out instead of stacking drones on one spot. Once you let the player defeat drones, the waves end sooner for players who fight, which rewards skill without any extra code.
:::

### Challenge: Raise the alarm

When a drone switches to Chase, every other drone within 8 units should switch to Search, heading for the player's current position, even if it can't see the player itself. Drones that are already chasing ignore the alarm.

:::hint
Put drones on an **Enemy** layer. In `SetState`, when entering Chase, call `Physics2D.OverlapCircleAll(rb.position, 8f, enemyLayers)`, get each collider's `EnemyAI`, skip `this`, and call a new public `Alert(Vector2 position)` method that sets `lastSeen` and enters Search only if the drone isn't already chasing. Check for alarm loops: if Alert could trigger Chase, one drone would alert the next forever.
