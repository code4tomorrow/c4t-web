:::objectives
- Create a project from the **Universal 2D** template in Unity Hub.
- Name the job of the Scene view, Game view, Hierarchy, Project, Inspector, and Console.
- Confirm the project uses the Input System package, which every script in this course relies on.
- Write, attach, and run a C# script that moves a sprite and reacts to the keyboard.
:::

By the end of this lesson a white square will spin on screen, reverse when you press Space, and print a line you wrote into the Console. That sounds small, but it exercises every link in the chain: the Hub opens the Editor, the Editor opens your code editor, Unity compiles your C#, and Play mode runs it. If all of that works, nothing in later modules will be blocked by setup.

## Step 1: Create the project

1. In Unity Hub, click **Projects**, then **New project**.
2. At the top, check that the **Editor version** is your 6000.3 LTS install.
3. In the template list, pick **Universal 2D** (it's in the **Core** group). If it shows a download button, click **Download template** and wait.
4. Set **Project name** to `UnityPlatformer` and choose a **Location** you'll remember, such as a `GameDev` folder in your Documents.
5. Leave any cloud or source control options off for now. Lesson 3 sets up backups your way.
6. Click **Create project**.

The first launch takes a few minutes because Unity imports the template's packages and builds the `Library` cache. Later launches are much faster.

The Universal 2D template sets up the Universal Render Pipeline with its 2D renderer and installs the 2D packages (sprites, tilemaps, 2D animation). The starting scene, `SampleScene`, holds just two objects: a **Main Camera** and a **Global Light 2D** that lights your sprites.

## Step 2: Learn the six windows

Unity's layout can be rearranged, but the default has these six areas. You'll use all of them in every module.

| Window | What it shows | What you do there |
| --- | --- | --- |
| **Hierarchy** | Every GameObject in the open scene, as a tree | Select, rename, parent, and create objects |
| **Scene view** | The scene from an editing camera | Place and arrange objects |
| **Game view** | What the Main Camera sees, which is what players will see | Watch and play the game in Play mode |
| **Inspector** | The components of whatever is selected | Change values like position, color, speed |
| **Project** | Every file in your `Assets` folder | Make and organize scripts, sprites, prefabs, scenes |
| **Console** | Messages, warnings, and errors | Read `Debug.Log` output and fix errors |

```mermaid caption="How the main windows relate: the Project holds files, the Hierarchy holds what's in the scene, and the Inspector shows whatever you selected"
flowchart LR
    P["Project: files on disk"] -->|drag into scene| H["Hierarchy: objects in this scene"]
    H -->|select one| I["Inspector: its components"]
    H --> S["Scene view: edit"]
    H --> G["Game view: camera output"]
    I -->|errors and logs| C[Console]
```

A few controls to try right now in the **Scene view**:

-   Scroll to zoom. Hold the middle mouse button and drag to pan, or press **Q** for the Hand tool and drag.
-   Select an object and press **F** to frame it.
-   **W**, **E**, **R**, and **T** switch to the Move, Rotate, Scale, and Rect tools.
-   The **2D** button in the Scene view's toolbar should be on. It locks the view to face the XY plane, which is where a 2D game lives.

The **Play**, **Pause**, and **Step** buttons sit at the top center of the Editor. Play starts the game inside the Editor, and pressing it again stops.

## Step 3: Check the Input System and your code editor

New Unity 6 projects include the **Input System** package, Unity's current way of reading keyboards, mice, and gamepads. This course reads devices directly with code like `Keyboard.current.spaceKey.wasPressedThisFrame`, which keeps every script short and readable. Two quick checks:

1.  Open **Edit > Project Settings > Player**, expand **Other Settings**, and find **Active Input Handling**. It should say **Input System Package (New)** or **Both**. If it says **Input Manager (Old)**, switch it to **Input System Package (New)** and let Unity restart.
2.  Open **Window > Package Management > Package Manager** (in Unity 6.0 it's **Window > Package Manager**). Click **In Project** and confirm **Input System** is listed.

You'll see an `InputSystem_Actions` asset in your Project window. That's the template's ready-made action map, used by a different style of input code. We won't need it, but leave it in place.

Now connect your code editor: **Edit > Preferences > External Tools** (macOS: **Unity > Settings > External Tools**), and set **External Script Editor** to Visual Studio or Visual Studio Code. If you use VS Code, also check the Package Manager list for **Visual Studio Editor** at version 2.0.20 or newer; it's the package that links Unity to both editors.

## Step 4: Make a sprite and a script

1. In the menu, choose **GameObject > 2D Object > Sprites > Square**. A white square appears in the scene.
2. In the Hierarchy, rename it `SpinTest` (select it and press **F2**, or **Return** on macOS).
3. In the Project window, right-click the `Assets` folder and choose **Create > Scripting > MonoBehaviour Script**.
4. Type the name `SpinTest` **immediately**, before clicking anywhere else, and press Enter.
5. Double-click the script to open it in your code editor. Replace everything with:

```csharp title="SpinTest.cs"
using UnityEngine;
using UnityEngine.InputSystem;

public class SpinTest : MonoBehaviour
{
    [SerializeField] private float degreesPerSecond = 90f;

    void Start()
    {
        Debug.Log("SpinTest is running on " + gameObject.name);
    }

    void Update()
    {
        transform.Rotate(0f, 0f, degreesPerSecond * Time.deltaTime);

        if (Keyboard.current != null && Keyboard.current.spaceKey.wasPressedThisFrame)
        {
            degreesPerSecond = -degreesPerSecond;
            Debug.Log("Reversed. Speed is now " + degreesPerSecond);
        }
    }
}
```

Save the file and switch back to Unity. A small spinner in the bottom-right corner means Unity is compiling.

Now attach the script: drag `SpinTest.cs` from the Project window onto the `SpinTest` object in the Hierarchy. Select the object and you'll see a **Spin Test (Script)** component in the Inspector, with a **Degrees Per Second** field showing 90.

## Step 5: Press Play and prove it works

Press **Play**. The square turns a quarter-circle every second. Click inside the **Game view** so it has keyboard focus, then press Space a few times. Open the **Console** tab (or **Window > General > Console**) and you should see:

```text
SpinTest is running on SpinTest
Reversed. Speed is now -90
Reversed. Speed is now 90
```

Three lines in this script are worth a second look. `Start` ran once, before the first frame, which is why its message appears first and only once. `Update` runs every frame, and multiplying by `Time.deltaTime` (the seconds since the last frame) makes the speed "90 degrees per second" on any computer, whatever its frame rate. And `wasPressedThisFrame` is true only on the single frame the key goes down, so holding Space reverses once, not sixty times a second.

:::try
While the game is still playing, change **Degrees Per Second** in the Inspector to 720. The square whirls. Now press Play again to stop: the value snaps back to 90. Changes made in Play mode are temporary, and Lesson 3 shows how to keep them when you want to.
:::

## When it doesn't work

:::warning "Can't add script component 'SpinTest' because the script class cannot be found"
The full message continues: "Make sure that there are no compile errors and that the file name and class name match." You renamed the file after Unity created it, so the file says `SpinTest.cs` but the code still says `public class NewMonoBehaviourScript`. Make the class name and file name identical, including capital letters, and save.
:::

:::warning error CS0103: The name 'Keyboard' does not exist in the current context
The `using UnityEngine.InputSystem;` line is missing or misspelled. Every script that reads `Keyboard.current` or `Mouse.current` needs it at the top. Until all compile errors are fixed, pressing Play shows "All compiler errors have to be fixed before you can enter playmode!"
:::

-   **Space does nothing, but there are no errors.** The Game view doesn't have focus. Click inside it once while playing.
-   **No autocomplete in VS Code.** Set the External Script Editor as in Step 3, then in Unity choose **Assets > Open C# Project** so VS Code opens the whole project rather than a single file.
-   **The square isn't visible in the Game view.** It's outside the camera's view. Select it and set its **Position** to 0, 0, 0 in the Inspector.

:::quiz
Q: You press Play, set a value in the Inspector, then stop. What happens to the value?
- [ ] It's saved into the scene
  Play mode runs on a temporary copy of the scene; edits there aren't kept.
- [x] It returns to what it was before you pressed Play
  Unity restores the scene when Play mode ends, so the change is lost.
- [ ] It's saved into the script file
  The Inspector never rewrites your C# source code.

Q: Which window would you use to change the color of the selected square?
- [ ] Project
  The Project window lists files; it doesn't edit the object's components.
- [ ] Hierarchy
  The Hierarchy selects and organizes objects, but values live in components.
- [x] Inspector
  The Sprite Renderer component, shown in the Inspector, has the Color field.

Q: If you hold Space down for two seconds, how many times does the spin reverse?
- [x] Once
  `wasPressedThisFrame` is true only on the frame the key goes down.
- [ ] About 120 times
  That's what `isPressed` would do, since it stays true every frame the key is held.
- [ ] Zero
  The press is detected on its first frame.
:::

:::takeaways
- The Universal 2D template gives you a URP 2D project with a camera, a 2D light, and the 2D packages.
- Hierarchy = objects in the scene, Inspector = the selected object's components, Project = files, Console = messages.
- This course reads input with `Keyboard.current` and `Mouse.current` from `UnityEngine.InputSystem`.
- A script's file name and class name must match, and changes made during Play mode are thrown away when you stop.
:::
