## Warm-up: what does a hash chain notice?

Each link hashes the previous hash together with the new event. Predict both booleans before running.

```python run
import hashlib, json

def link(prev, event):
    return hashlib.sha256((prev + json.dumps(event, sort_keys=True)).encode()).hexdigest()[:8]

h1 = link("0" * 8, {"push": "fix/a"})
h2 = link(h1, {"push": "fix/b"})
print(h1, h2)
print(link(h1, {"push": "fix/b"}) == h2, link(h1, {"push": "main"}) == h2)
```

Recomputing a link from the same inputs gives the same hash, so the first check is `True`. Changing the event, even one word, gives a completely different hash. That's the property every audit-log exercise below relies on.

### Exercise 1: A dollar cap across two models

A run mixes a cheap model and an expensive one. Write `CostMeter` with `reserve(model, input_tokens, max_output_tokens)`, which raises `OverBudget` if the **worst-case** cost of the next call would cross the cap, and `settle(...)`, which records what the call actually cost. Prices are example rates in dollars per million tokens.

```text
small call ok, spent $0.0015
large call ok, spent $0.0315
small call ok, spent $0.0331
stopped: large call could cost $0.0510; $0.0169 left
```

:::hint
Worst case means the input you're about to send plus the largest output you'll allow (`max_output_tokens`), priced at that model's rates.
:::

:::solution
```python run
PRICES = {"small": (0.15, 0.60), "large": (3.00, 15.00)}   # example $ per million tokens: (input, output)

class OverBudget(Exception):
    pass

class CostMeter:
    def __init__(self, max_dollars):
        self.max, self.spent = max_dollars, 0.0

    def cost(self, model, input_tokens, output_tokens):
        price_in, price_out = PRICES[model]
        return (input_tokens * price_in + output_tokens * price_out) / 1e6

    def reserve(self, model, input_tokens, max_output_tokens):
        worst = self.cost(model, input_tokens, max_output_tokens)
        if self.spent + worst > self.max:
            raise OverBudget(f"{model} call could cost ${worst:.4f}; ${self.max - self.spent:.4f} left")
        return worst

    def settle(self, model, input_tokens, output_tokens):
        self.spent += self.cost(model, input_tokens, output_tokens)

meter = CostMeter(max_dollars=0.05)
calls = [("small", 8_000, 500), ("large", 6_000, 800), ("small", 9_000, 400), ("large", 7_000, 900), ("large", 8_000, 1_000)]
for model, tokens_in, tokens_out in calls:
    try:
        meter.reserve(model, tokens_in, max_output_tokens=2_000)
    except OverBudget as stop:
        print("stopped:", stop)
        break
    meter.settle(model, tokens_in, tokens_out)
    print(f"{model:5} call ok, spent ${meter.spent:.4f}")
```

Reserving the worst case is what turns Module 2's soft budget into a hard cap: the run stops before a call that *might* cross the line. Setting `max_output_tokens` on the real API call is what makes the worst case a real bound.
:::

### Exercise 2: Find delegation cycles in a log

Each record says one agent handed a task to another, in time order. Write `cycles(log)` that tracks the chain of agents each task has passed through and reports every task whose chain comes back to an agent already on it.

```text
T1: planner -> coder -> tester -> coder
T3: planner -> coder -> planner
```

:::hint
Keep a dictionary from task id to its path, starting with the first sender. Before appending a receiver, check whether it's already in the path.
:::

:::solution
```python run
handoffs = [  # (task, sender, receiver), in time order
    ("T1", "planner", "coder"), ("T2", "planner", "docs"), ("T1", "coder", "tester"),
    ("T3", "planner", "coder"), ("T1", "tester", "coder"), ("T3", "coder", "planner"),
    ("T2", "docs", "reviewer"),
]

def cycles(log):
    paths, found = {}, []
    for task, sender, receiver in log:
        path = paths.setdefault(task, [sender])
        if receiver in path:
            found.append(f"{task}: {' -> '.join(path + [receiver])}")
        path.append(receiver)
    return found

print("\n".join(cycles(handoffs)))
```

Not every repeat is a bug: a tester returning work to the coder with a failing test is a normal revision. That's why handoffs (passing the task on) and results (returning work) should be different message types in your harness, so this check only looks at handoffs.
:::

### Exercise 3: Risk tiers that read the arguments

Write `tier(role, tool, args)` returning `auto`, `approve`, or `deny`. Reads are automatic. Writes are automatic unless the path escapes the workspace, is under `tests/`, or the role is `reviewer`. Pushes to `main` need approval for the `release` role and are denied for everyone else; other branches need approval for `worker`. Email always needs approval. Anything unknown is denied.

```text
worker   write_file {"path": "src/app.py"}         -> auto
worker   write_file {"path": "tests/test_app.py"}  -> deny
...
worker   shell      {"cmd": "rm -rf /"}            -> deny
```

:::hint
Handle each tool in its own `if` block and end the function with `return "deny"`, so a tool you forgot is denied by default.
:::

:::solution
```python run
def tier(role, tool, args):
    if tool in ("read_file", "run_tests"):
        return "auto"
    if tool == "write_file":
        path = args["path"]
        if path.startswith(("/", "..")) or "/../" in path:
            return "deny"
        if role == "reviewer" or path.startswith("tests/"):
            return "deny"
        return "auto"
    if tool == "git_push":
        if args["branch"] in ("main", "master"):
            return "approve" if role == "release" else "deny"
        return "approve" if role == "worker" else "deny"
    if tool == "send_email":
        return "approve"
    return "deny"

checks = [("worker", "write_file", {"path": "src/app.py"}), ("worker", "write_file", {"path": "tests/test_app.py"}),
          ("worker", "write_file", {"path": "../.ssh/config"}), ("reviewer", "write_file", {"path": "src/app.py"}),
          ("worker", "git_push", {"branch": "fix/x"}), ("worker", "git_push", {"branch": "main"}),
          ("release", "git_push", {"branch": "main"}), ("worker", "shell", {"cmd": "rm -rf /"})]
for role, tool, args in checks:
    print(f"{role:8} {tool:10} {json.dumps(args):30} -> {tier(role, tool, args)}")
```

The final `return "deny"` is the most important line. An allowlist fails safe when someone adds a new tool and forgets to classify it; a denylist fails open. The path check here is a quick filter, and the file tools from Module 2 still resolve and check every path themselves.
:::

### Exercise 4: Two people for the riskiest actions

Merging to `main` should need two approvals from two different people on the approver list, and the person who requested the merge can't be one of them. Approvals belong to the exact action, so approving PR 41 says nothing about PR 42.

```text
worker-1 -> worker-1 is not an approver  | allowed: False
sam      -> sam can't approve their own request  | allowed: False
maya     -> 1 of 2 approvals  | allowed: False
maya     -> 1 of 2 approvals  | allowed: False
lee      -> 2 of 2 approvals  | allowed: True
same approvals for PR 42? False
```

:::hint
Key the votes by `json.dumps(action, sort_keys=True)` and store a *set* of approvers, so the same person voting twice still counts once.
:::

:::solution
```python run
class TwoPersonGate:
    def __init__(self, approvers):
        self.approvers, self.votes = set(approvers), {}

    def vote(self, action, person):
        key = json.dumps(action, sort_keys=True)
        if person not in self.approvers:
            return f"{person} is not an approver"
        if person == action["requested_by"]:
            return f"{person} can't approve their own request"
        self.votes.setdefault(key, set()).add(person)
        return f"{len(self.votes[key])} of 2 approvals"

    def allowed(self, action):
        return len(self.votes.get(json.dumps(action, sort_keys=True), set())) >= 2

gate = TwoPersonGate(approvers={"maya", "lee", "sam"})
merge = {"tool": "merge", "branch": "main", "pr": 41, "requested_by": "sam"}
for person in ["worker-1", "sam", "maya", "maya", "lee"]:
    print(f"{person:8} -> {gate.vote(merge, person)}  | allowed: {gate.allowed(merge)}")
print("same approvals for PR 42?", gate.allowed({**merge, "pr": 42}))
```

The set does the heavy lifting: Maya's second vote changes nothing. An agent isn't on the approver list at all, so even an agent with access to the approval tool can't push a merge through.
:::

### Exercise 5: A chain doesn't notice a missing ending

An agent with write access to the audit file deletes its last line, which recorded the agent approving its own push. Show that a plain chain check still says `ok`, then fix `verify` to also compare against a head hash and an entry count stored somewhere the agent can't write.

```text
chain only:           ok
with head and count:  1 entries missing from the end
```

:::hint
Every remaining entry still links correctly to the one before it, so the chain alone can't tell. Only something outside the file knows how long it should be.
:::

:::solution
```python run
GENESIS = "0" * 16

def entry_hash(prev, event):
    return hashlib.sha256(json.dumps({"prev": prev, **event}, sort_keys=True).encode()).hexdigest()[:16]

def build(events):
    log, prev = [], GENESIS
    for event in events:
        prev = entry_hash(prev, event)
        log.append({**event, "hash": prev})
    return log

def verify(log, head=None, count=None):
    prev = GENESIS
    for number, entry in enumerate(log, 1):
        event = {k: v for k, v in entry.items() if k != "hash"}
        if entry_hash(prev, event) != entry["hash"]:
            return f"broken at entry {number}"
        prev = entry["hash"]
    if count is not None and len(log) != count:
        return f"{count - len(log)} entries missing from the end"
    if head is not None and prev != head:
        return "last hash doesn't match the stored head"
    return "ok"

events = [{"actor": "worker-1", "action": "push fix/x"}, {"actor": "worker-1", "action": "push main", "decision": "denied"},
          {"actor": "worker-1", "action": "push main", "decision": "approved by worker-1"}]
log = build(events)
head, count = log[-1]["hash"], len(log)        # stored somewhere the agents can't write
truncated = log[:-1]
print("chain only:          ", verify(truncated))
print("with head and count: ", verify(truncated, head, count))
```

This is why real tamper-evident logs publish their head hash somewhere else: a separate service, a signed Git commit, or a message to another system. The chain proves the entries you have weren't changed; the external head proves you have all of them.
:::

### Exercise 6: Scan a diff for secrets

Before release, scan only the lines a change **adds** (lines starting with `+`, but not the `+++` file header) for an AWS access key id, a GitHub token, a private key header, and a quoted password or key assigned to a variable.

```text
line 5: password or key assignment
line 6: AWS access key id
line 8: GitHub token
```

:::hint
Loop over `diff.splitlines()` with line numbers and skip anything that doesn't start with `+`. One regex per secret type keeps the report readable.
:::

:::solution
```python run
import re
SECRET_PATTERNS = {
    "AWS access key id": r"\bAKIA[0-9A-Z]{16}\b",
    "GitHub token": r"\b(ghp|github_pat)_[A-Za-z0-9_]{36,}\b",
    "private key": r"-----BEGIN (RSA |EC |OPENSSH )?PRIVATE KEY-----",
    "password or key assignment": r"(?i)\b(password|passwd|api_key|secret)\s*=\s*['\"][^'\"]{8,}['\"]",
}

def scan_diff(diff):
    findings = []
    for number, line in enumerate(diff.splitlines(), 1):
        if not line.startswith("+") or line.startswith("+++"):
            continue                     # only lines this change adds
        for name, pattern in SECRET_PATTERNS.items():
            if re.search(pattern, line):
                findings.append(f"line {number}: {name}")
    return findings

diff = """--- a/config.py
+++ b/config.py
@@ -1,3 +1,5 @@
-API_KEY = os.environ["API_KEY"]
+API_KEY = "sk-live-4f9a8b7c6d5e"
+AWS_KEY = "AKIAIOSFODNN7EXAMPLE"
 TIMEOUT = 30
+# token for CI: ghp_0123456789abcdefghijABCDEFGHIJ012345
"""
print("\n".join(scan_diff(diff)) or "clean")
```

The removed line (`-API_KEY = os.environ[...]`) is skipped, which is right: the change replaced a safe environment lookup with a hardcoded key, and only the added line is new risk. `AKIAIOSFODNN7EXAMPLE` is the example key from AWS's own documentation. Regex scanners miss secrets with unusual formats, so treat this as one layer next to tools like GitHub's secret scanning.
:::

### Exercise 7: A release gate as code

Turn the release checklist from the Notes lesson into `release_gate(report)`, returning `("SHIP", [])` or `("HOLD", reasons)`. Hold if any test fails, if the paired eval interval's lower bound is below −0.02, if any changed path is outside the allowed ones, if the scan found secrets, if any risky action lacks an approval, if the audit log doesn't verify, or if there's no rollback plan.

```mermaid caption="Every check must pass; any one failure holds the release"
flowchart LR
    R[Run report] --> T{Tests pass?}
    T -->|yes| E{"Eval CI low ≥ −0.02?"}
    E -->|yes| P{Paths allowed?}
    P -->|yes| S{No secrets?}
    S -->|yes| A{"Approvals + audit ok?"}
    A -->|yes| B{Rollback plan?}
    B -->|yes| SHIP[SHIP]
    T & E & P & S & A & B -->|no| HOLD[HOLD with reasons]
```

```text
HOLD
 - hidden eval may have regressed (paired CI lower bound -0.051)
 - changes outside the plan: ['ci/deploy.yml']
 - risky actions with no approval on record: ['merge #41']
```

:::hint
Collect every failing reason instead of returning at the first one. A person fixing a held release wants the whole list at once.
:::

:::solution
```python run
def release_gate(report):
    reasons = []
    if report["failing_tests"]:
        reasons.append(f"tests failing on a clean checkout: {report['failing_tests']}")
    low = report["eval_gap_ci"][0]
    if low < -0.02:
        reasons.append(f"hidden eval may have regressed (paired CI lower bound {low:+.3f})")
    stray = [p for p in report["changed_paths"] if not p.startswith(tuple(report["allowed_paths"]))]
    if stray:
        reasons.append(f"changes outside the plan: {stray}")
    if report["secret_findings"]:
        reasons.append(f"possible secrets: {report['secret_findings']}")
    unapproved = [a for a in report["risky_actions"] if a not in report["approved_actions"]]
    if unapproved:
        reasons.append(f"risky actions with no approval on record: {unapproved}")
    if report["audit_status"] != "ok":
        reasons.append(f"audit log: {report['audit_status']}")
    if not report.get("rollback"):
        reasons.append("no rollback plan")
    return ("SHIP", []) if not reasons else ("HOLD", reasons)

report = {
    "failing_tests": [], "eval_gap_ci": (-0.051, 0.064), "changed_paths": ["src/dates.py", "README.md", "ci/deploy.yml"],
    "allowed_paths": ["src/", "README.md"], "secret_findings": [],
    "risky_actions": ["push fix/dates", "merge #41"], "approved_actions": ["push fix/dates"],
    "audit_status": "ok", "rollback": "git revert of the merge commit",
}
decision, reasons = release_gate(report)
print(decision)
for reason in reasons:
    print(" -", reason)
```

The eval rule is the subtle one. The interval runs from −0.051 to +0.064, so even if the average gap is positive, a real regression of five points is still plausible. The −0.02 threshold says how much regression you're willing to risk; pick it before you see the numbers.
:::

### Challenge: All-or-nothing edits with rollback

Write `apply_all_or_nothing(root, edits, check)`. `edits` maps paths to new text, or to `None` to delete the file. Snapshot every affected path first (including "didn't exist"), apply all edits, run `check`, and if it reports problems or raises, restore every path exactly: rewrite changed files, delete files the edit created, and recreate files it deleted.

```text
rolled back: RATE 20 out of range
files unchanged: True | rates.py: RATE = 0.2
applied
['src/new.py', 'src/rates.py']
```

:::hint
Record a missing file as `None` in the snapshot. Then applying edits and restoring a snapshot are the same operation: write the text, or delete when it's `None`.
:::

:::solution
```python run
from pathlib import Path

def snapshot(root, paths):
    return {p: (Path(root, p).read_text() if Path(root, p).exists() else None) for p in paths}

def restore(root, saved):
    for p, text in saved.items():
        target = Path(root, p)
        if text is None:
            target.unlink(missing_ok=True)
        else:
            target.parent.mkdir(parents=True, exist_ok=True)
            target.write_text(text)

def apply_all_or_nothing(root, edits, check):
    """edits: {path: new text, or None to delete}. Keep them only if check(root) returns no problems."""
    saved = snapshot(root, edits)
    try:
        restore(root, edits)                 # same operation as restoring: write or delete each path
        problems = check(root)
    except Exception as exc:
        problems = [f"{type(exc).__name__}: {exc}"]
    if problems:
        restore(root, saved)
        return "rolled back: " + "; ".join(problems)
    return "applied"

root = Path("repo")
(root / "src").mkdir(parents=True, exist_ok=True)
(root / "src/rates.py").write_text("RATE = 0.2\n")
(root / "src/old.py").write_text("LEGACY = True\n")
before = sorted(str(p.relative_to(root)) for p in root.rglob("*") if p.is_file())

def check(root):
    ns = {}
    exec(Path(root, "src/rates.py").read_text(), ns)
    return [] if 0 <= ns["RATE"] <= 1 else [f"RATE {ns['RATE']} out of range"]

edits = {"src/rates.py": "RATE = 20\n", "src/new.py": "NEW = 1\n", "src/old.py": None}
print(apply_all_or_nothing(root, edits, check))
after = sorted(str(p.relative_to(root)) for p in root.rglob("*") if p.is_file())
print("files unchanged:", before == after, "| rates.py:", Path(root, "src/rates.py").read_text().strip())
edits["src/rates.py"] = "RATE = 0.25\n"
print(apply_all_or_nothing(root, edits, check))
print(sorted(str(p.relative_to(root)) for p in root.rglob("*") if p.is_file()))
```

Treating "absent" as a value is the whole trick: the snapshot `{"src/new.py": None}` means "this file must not exist", so restoring it deletes the file the failed edit created. The `try` matters too, because a check that crashes is a failed check, not a reason to keep half-applied edits.
