:::objectives
- Confirm you have Python 3.10 or newer, or install it, on Windows, macOS, or Linux (including a Chromebook's Linux environment).
- Create the `harness-lab` project folder and the virtual environment it will use for the whole course.
- Optionally install Ollama, pull a small model that supports tool calling, and confirm it answers.
- Fix the four setup problems that stop people most often: a missing `python` command, a blocked activation script, a missing `venv` module, and a busy port.
:::

Run the same agent task against a real model ten times and you can get ten different transcripts, a handful of timeouts, and a bill. That's fine for a demo and hopeless for development. You can't write a test whose correct output changes every run, and you can't fix a failure you can't reproduce.

So this course starts with a seam. Every model the harness talks to, real or fake, has exactly one method, `complete(messages, tools)`, which returns a reply. A **scripted model** answers from a list of replies you write in advance. It's offline, free, and gives the same answer every run, and every runnable cell in this course uses it. A real model, running on your computer through Ollama or hosted by a provider, plugs into the same seam whenever you want to see real behavior.

## What you'll build, module by module

You'll grow one Python package called `harness` inside a folder called `harness-lab`. Each module adds files to it, and later modules build on earlier ones instead of starting over.

```mermaid caption="The harness package. Modules 1 to 4 write these files; Modules 5 to 8 attack, measure, and scale them."
flowchart LR
    M["model.py and chat_api.py (Module 1)"] --> L["loop.py (Module 2)"]
    T["tools.py and files.py (Module 2)"] --> L
    S["sandbox.py and retry.py (Module 3)"] --> L
    L --> R["tracing.py (Module 4)"]
    R --> E["evals.py (Module 4)"]
    E --> X["Graders, routing, approvals (Modules 5 to 8)"]
```

The harness uses only Python's standard library: `urllib` to talk to model APIs, `subprocess` and `tempfile` for the sandbox, `json` for traces, and `dataclasses` here and there. There's nothing to `pip install`. That's a deliberate choice. Agent frameworks do the same jobs with more layers, and once you've written each layer yourself you can read any framework's source and know what it's doing.

## What you need

- A computer running Windows 10 or 11, macOS, or Linux. A Chromebook works once its Linux development environment is turned on.
- Python 3.10 or newer, a terminal, and any code editor. VS Code is a good free choice, but nothing in the course depends on it.
- Git, which the prerequisites assume you already use.
- Optional: about 2 GB of free disk and 8 GB of RAM for a small local model, or an API key from a hosted provider.

## Step 1: Check or install Python

Open a terminal and check your version first. If it prints 3.10 or higher, skip to Step 2.

:::tabs
@tab Windows
In PowerShell, run:

```powershell
py --version
```

If that fails, download Python from python.org/downloads and run the installer. If the installer offers a checkbox to add Python to PATH, tick it. Close and reopen PowerShell, then run `py --version` again. The `py` launcher is how this course runs Python on Windows, because it works even when `python` isn't on your PATH.
@tab macOS
In Terminal, run:

```bash
python3 --version
```

If it prints `Python 3.9.6`, that's the older copy Apple installs with its command-line developer tools. Leave it alone and install a current version from python.org/downloads (the macOS installer is a `.pkg` file). Open a new Terminal window and check again.
@tab Linux and Chromebook
On a Chromebook, open **Settings**, search for **Linux**, and turn on the Linux development environment. It opens a Terminal running Debian. Then, on Debian or Ubuntu:

```bash
sudo apt update
sudo apt install python3 python3-venv
python3 --version
```

Debian's `python3` package doesn't include the `venv` module on its own, which is why `python3-venv` is in that command.
:::

## Step 2: Create the project and its virtual environment

A virtual environment is a private copy of the Python interpreter for one project. You won't install anything in Modules 1 to 4, but the environment still earns its place: it pins which Python the project uses, and if you later add a package (an SDK from your provider, say), it lands in this project instead of your whole system.

:::tabs
@tab Windows
```powershell
mkdir harness-lab
cd harness-lab
py -m venv .venv
.venv\Scripts\Activate.ps1
mkdir harness, tests, workspace, traces, evals
New-Item harness\__init__.py, tests\__init__.py
```
@tab macOS
```bash
mkdir harness-lab && cd harness-lab
python3 -m venv .venv
source .venv/bin/activate
mkdir harness tests workspace traces evals
touch harness/__init__.py tests/__init__.py
```
@tab Linux and Chromebook
```bash
mkdir harness-lab && cd harness-lab
python3 -m venv .venv
source .venv/bin/activate
mkdir harness tests workspace traces evals
touch harness/__init__.py tests/__init__.py
```
:::

Once the environment is active, your prompt starts with `(.venv)`, and plain `python` means the project's Python on every system. Activation only lasts for that terminal window: open a new one and you have to activate again. Check both things at once:

```bash
python -c "import sys; print(sys.version_info[:3], sys.prefix != sys.base_prefix)"
```

```text
(3, 12, 7) True
```

The first part is your Python version. `True` means you're inside a virtual environment, because a venv's `sys.prefix` points at `.venv` while `sys.base_prefix` still points at the real installation. Here's the folder you just made, with the jobs each part will do:

```text
harness-lab/
├── .venv/            the virtual environment (never commit it)
├── harness/          the package you grow all course
│   └── __init__.py   marks the folder as a package
├── tests/            unittest files (Lesson 3)
│   └── __init__.py   lets python -m unittest find the tests
├── workspace/        the only folder the agent's file tools may touch (Module 2)
├── traces/           JSONL records of every run (Module 4)
└── evals/            frozen evaluation cases (Module 4)
```

:::video Y21OR1OPC9A
What to watch for: creating, activating, and deactivating a venv, and how the prompt changes while one is active. The parts about installing packages with pip are optional here, since the harness needs none.
:::

## Step 3 (optional): Install Ollama and a small tool-calling model

Ollama downloads open-weight models and runs them on your own computer. It serves an HTTP API on `http://localhost:11434`, and it includes an **OpenAI-compatible** endpoint under `/v1`, which is the API your real client will use in the next lesson. Your prompts never leave your machine.

Not every model can call tools. On the Ollama model library, the ones that can are tagged **tools**. This course suggests `qwen2.5:3b` (about a 1.9 GB download). On a machine with 8 GB of RAM or less, use `qwen2.5:1.5b` (about 1 GB) instead.

:::tabs
@tab Windows
Ollama needs Windows 10 22H2 or newer. Download `OllamaSetup.exe` from ollama.com/download and run it; it installs into your user folder, so it doesn't need administrator rights. Ollama then runs in the background. Open a new PowerShell window and check it with `ollama -v`.
@tab macOS
Ollama needs macOS 14 Sonoma or newer. Download it from ollama.com/download, open the file, and drag Ollama into **Applications**. Launch it once; it asks permission to add the `ollama` command to `/usr/local/bin`, so say yes. Open a new Terminal window and check it with `ollama -v`.
@tab Linux and Chromebook
Install with the official script, then check the version:

```bash
curl -fsSL https://ollama.com/install.sh | sh
ollama -v
```

If `ollama -v` warns that it can't connect to a running instance, start the server in a second terminal with `ollama serve` and leave it open. A Chromebook's Linux environment usually has no GPU access and limited memory, so pick `qwen2.5:1.5b`, or skip the local model; the scripted model covers every lesson.
:::

Now pull the model and ask it something:

```bash
ollama pull qwen2.5:3b
ollama run qwen2.5:3b "Reply with one word: ready"
ollama list
```

The first command downloads the model once. The second loads it and prints a reply; on a laptop CPU, the first answer can take 10 to 30 seconds while the model loads, and later ones are faster. `ollama list` shows every model you've pulled, which you'll want when an API call complains about a model name.

:::video UtSSMs6ObqY
What to watch for: the install, `ollama pull` and `ollama run`, and the part where requests go to the local HTTP API on port 11434. That API is what your harness will talk to.
:::

### Or use a hosted provider

If you'd rather use a hosted model, the real client reads three environment variables: `LLM_BASE_URL`, `LLM_MODEL`, and `LLM_API_KEY`. OpenAI's API and many other providers publish an OpenAI-compatible base URL; copy yours from the provider's docs. Hosted models usually cost money per token, and your prompts go to the provider's servers, which Lesson 3 covers in detail. Set a spending limit in the provider's dashboard before your first call.

:::tabs
@tab Windows
```powershell
$env:LLM_BASE_URL = "https://api.openai.com/v1"
$env:LLM_MODEL = "your-model-name"
$env:LLM_API_KEY = "paste-your-key-here"
```
@tab macOS
```bash
export LLM_BASE_URL="https://api.openai.com/v1"
export LLM_MODEL="your-model-name"
export LLM_API_KEY="paste-your-key-here"
```
@tab Linux and Chromebook
```bash
export LLM_BASE_URL="https://api.openai.com/v1"
export LLM_MODEL="your-model-name"
export LLM_API_KEY="paste-your-key-here"
```
:::

These last only for the current terminal window, which is the point: the key never gets written into a file that could be committed.

## When setup goes wrong

:::warning
**Windows: `python` opens the Microsoft Store, or `py` isn't recognized.** Windows ships a `python` shortcut that points at the Store. Use `py`, or turn the shortcut off: open **Settings**, search for **App execution aliases**, and switch off the entries for `python.exe` and `python3.exe`. If `py` itself is missing, rerun the python.org installer and make sure the launcher is selected.
:::

:::warning
**Windows: `Activate.ps1 cannot be loaded because running scripts is disabled on this system`.** PowerShell blocks scripts by default. Allow locally created scripts for your account only, then activate again:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
.venv\Scripts\Activate.ps1
```
:::

:::warning
**Debian, Ubuntu, or Chromebook: `ensurepip is not available`.** The message says the virtual environment wasn't created successfully. Install the missing piece with `sudo apt install python3-venv`, delete the half-made `.venv` folder, and run `python3 -m venv .venv` again.
:::

:::warning
**`Error: listen tcp 127.0.0.1:11434: bind: address already in use`.** You ran `ollama serve` while Ollama was already running (the desktop app or the Linux service starts it for you). Nothing is broken. Close the extra terminal and use the copy that's running.
:::

:::quiz
Q: Why does every runnable cell in this course use a scripted model instead of a real one?
- [ ] Real models can't call tools from Python
  They can; the next lesson writes a client that does exactly that.
- [x] A scripted model gives the same reply every run, offline and free, so tests and examples are repeatable
  Development needs reproducible runs. The real model plugs into the same `complete` method when you want it.
- [ ] Scripted models are more accurate than real ones
  A scripted model only says what you wrote for it; it's a test double, not a better model.

Q: On a Mac, `python3 --version` prints `Python 3.9.6`. What should you do?
- [ ] Use it; any Python 3 works
  The harness uses features from Python 3.10 and newer, so 3.9 will fail.
- [ ] Delete Apple's copy of Python
  macOS tools depend on it. Leave it in place.
- [x] Install a current Python from python.org and open a new Terminal window
  The new install comes first on your PATH, and Apple's copy stays untouched.

Q: You activate `.venv`, open a second terminal tab, and run `python --version` there. Which Python runs?
- [x] Whatever is on your system PATH, because activation only applies to the window where you ran it
  Each terminal session starts fresh. Activate again in every new window.
- [ ] The project's `.venv` Python, because the folder contains `.venv`
  Being in the folder doesn't activate anything; the activation script does.
:::

:::takeaways
- The harness talks to every model through one method, `complete(messages, tools)`, so a scripted model and a real one are interchangeable.
- The project lives in `harness-lab`, with its own `.venv` that you activate in every new terminal window.
- Ollama is optional; if you use it, pick a model tagged **tools**, such as `qwen2.5:3b` or `qwen2.5:1.5b`.
- API keys go in environment variables for the current session, never in a file.
:::
