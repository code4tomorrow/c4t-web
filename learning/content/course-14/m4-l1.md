Two students prepare for a history test. One studies the topics. The other finds last year's answer key and memorizes it: question 1 is B, question 2 is D. On last year's test, the memorizer scores 100%. On this year's test, with the questions reworded, they score 40%. The first student scores 85% on both.

If you only ever graded them on last year's test, you'd pick the wrong student. Models can memorize too, and they can fool you in exactly the same way. This lesson is about how to grade a model fairly, and then about what's actually happening inside one when it "learns".

## Hold some examples back

The fix is simple to say: before training, set some labeled examples aside and never let the model see them. After training, score the model on those. They play the role of this year's test.

In practice, data is usually split three ways:

```mermaid caption="A common way to split labeled examples; the test set is opened once, at the end"
flowchart LR
    A[All labeled examples] --> B["Training set (~70%)<br/>the model learns from these"]
    A --> C["Validation set (~15%)<br/>you compare settings with these"]
    A --> D["Test set (~15%)<br/>the final score, used once"]
```

-   **Training set**: what the model learns from.
-   **Validation set**: what *you* use to make choices, like how long to train or which version of the model to keep. Every time you peek at a score and change something, you're learning from that set too.
-   **Test set**: locked away until the very end. One score, reported honestly. If you keep tweaking until the test score looks good, it has quietly become a validation set, and you no longer have an honest score.

Teachable Machine does a simpler version automatically. Its "Under the hood" panel explains that it splits your samples into two buckets: 85% for training and 15% as test samples that "are never used to train the model". You'll look at those charts in the next lesson.

## Overfitting: memorizing the noise

Here's a pattern hidden in some noisy measurements (it happens to be a smooth wave). Each panel fits a model with a different amount of freedom to bend, using only the filled-in training points, then checks it against the hollow test points it never saw:

```python run alt="Three panels fitting a curve to ten blue training points. Left: a straight line that misses the wave shape. Middle: a smooth curve that follows the wave and passes near both training and test points. Right: a wild curve that passes exactly through every training point but swings far away from the hollow test points." caption="Too simple, about right, and memorized"
import numpy as np
import matplotlib.pyplot as plt
from numpy.polynomial import Polynomial

rng = np.random.default_rng(34)
# The hidden pattern is a smooth wave; every measurement has a bit of noise
x_train = np.linspace(0.2, 5.8, 10) + rng.uniform(-0.2, 0.2, 10)
y_train = np.sin(x_train) + rng.normal(0, 0.3, 10)
x_test = np.linspace(0.4, 5.6, 10) + rng.uniform(-0.15, 0.15, 10)
y_test = np.sin(x_test) + rng.normal(0, 0.3, 10)

xs = np.linspace(0.1, 5.9, 300)
fig, axes = plt.subplots(1, 3, figsize=(11, 3.4), sharey=True)
for ax, wiggle, name in zip(axes, [1, 3, 9], ["Too simple", "About right", "Memorized"]):
    model = Polynomial.fit(x_train, y_train, wiggle)
    train_error = np.mean((model(x_train) - y_train) ** 2)
    test_error = np.mean((model(x_test) - y_test) ** 2)
    ax.plot(xs, model(xs), color="#eb6834", linewidth=2)
    ax.scatter(x_train, y_train, color="#2a78d6", label="training examples", zorder=3)
    ax.scatter(x_test, y_test, facecolor="white", edgecolor="#2a78d6", label="test examples", zorder=3)
    ax.set_title(f"{name}\ntraining error {train_error:.2f}, test error {test_error:.2f}", loc="left", fontsize=10)
    ax.set_ylim(-2.2, 2.2)
    ax.set_xticks([])
    ax.set_yticks([])
    ax.spines[["top", "right"]].set_visible(False)
axes[0].legend(frameon=False, loc="lower left", fontsize=9)
fig.tight_layout()
```

**Left:** a straight line can't bend, so it misses the wave on both training and test points. That's **underfitting**: the model is too simple for the pattern.

**Middle:** a gently curving model follows the wave and lands close to the test points it never saw. Low error on both.

**Right:** a model allowed to bend nine times threads through every training point exactly, so its training error is 0.00. But to do it, it learned the random noise in those ten points, and it swings wildly between them. Its test error is the worst of the three. That's **overfitting**: excellent on the examples it trained on, poor on new ones. It's the memorizer with the answer key.

Now repeat that experiment on 200 fresh datasets for every amount of bendiness from 0 (a flat line) to 7, and plot the typical errors:

```python run alt="Line chart. The x axis is how wiggly the model is allowed to be, from 0 to 7. Training error (blue) falls steadily toward zero. Test error (orange) falls to its lowest point at 3, then rises again toward 0.55 at 7." caption="The gap between the lines is overfitting"
import numpy as np
import matplotlib.pyplot as plt
from numpy.polynomial import Polynomial

rng = np.random.default_rng(0)
wiggles = range(0, 8)
train_errors, test_errors = [], []
for wiggle in wiggles:
    train_runs, test_runs = [], []
    for _ in range(200):                       # 200 fresh datasets, then the typical result
        x_train = rng.uniform(0, 6, 12)
        y_train = np.sin(x_train) + rng.normal(0, 0.3, 12)
        x_test = rng.uniform(0.3, 5.7, 20)
        y_test = np.sin(x_test) + rng.normal(0, 0.3, 20)
        model = Polynomial.fit(x_train, y_train, wiggle)
        train_runs.append(np.mean((model(x_train) - y_train) ** 2))
        test_runs.append(np.mean((model(x_test) - y_test) ** 2))
    train_errors.append(np.median(train_runs))
    test_errors.append(np.median(test_runs))

fig, ax = plt.subplots(figsize=(6.5, 3.8))
ax.plot(wiggles, train_errors, color="#2a78d6", linewidth=2, marker="o", label="Training error")
ax.plot(wiggles, test_errors, color="#eb6834", linewidth=2, marker="^", label="Test error")
best = int(np.argmin(test_errors))
ax.annotate("best on new data", (best, test_errors[best]), xytext=(best - 0.4, 0.5),
            arrowprops={"arrowstyle": "->", "color": "#555"}, color="#333")
ax.set_xlabel("How wiggly the model is allowed to be")
ax.set_ylabel("Error (lower is better)")
ax.set_ylim(0, 0.8)
ax.legend(frameon=False, loc="upper right")
ax.spines[["top", "right"]].set_visible(False)
ax.set_title("Training error keeps falling; test error turns back up", loc="left")
fig.tight_layout()
```

This is the most important chart in machine learning, and it's worth reading slowly. The **blue line only ever goes down**: more freedom always fits the training examples better. If that were the only number you looked at, you'd always pick the most complicated model. The **orange line** falls at first, as the model gains enough freedom to capture the wave, then turns back up once the extra freedom is spent on memorizing noise. The best model is at the bottom of the orange curve, and you can only find it with examples the model didn't train on.

## When the test set isn't really new

Holding examples back only works if they're truly different from the training ones. Some ways a test set secretly isn't:

-   **Near-duplicates.** Teachable Machine's webcam records many frames per second. Two frames a fraction of a second apart are practically the same picture. If one lands in training and its twin in the test bucket, the "test" is a memory check.
-   **The same person, place, or object on both sides.** A gesture model tested on photos of the same hands, in the same room, says little about other hands in other rooms.
-   **Information from the future.** A model that predicts tomorrow's attendance shouldn't be tested on days that came before its training days.

When test examples leak information from training, the score comes out too good. You'll see this happen inside Teachable Machine in the next lesson, and Module 5 builds a stress test that gets around it.

## A neuron is a weighted vote

Teachable Machine's model is a **neural network**. Under the name, the basic part is simple. A single **neuron** takes some input numbers, multiplies each by a **weight** that says how much it matters, adds them up with an extra number called a **bias**, and squashes the total into a range like 0 to 1.

Think of deciding whether to go to the park. Inputs: how sunny it is, whether friends are going, whether homework is done. Weights: friends might matter a lot (a big weight), sunshine a little. The bias is your general mood: a bit lazy today means the total has to be higher before you go.

Here's one neuron with a single input, drawn three ways:

```python run alt="Three S-shaped curves rising from 0 to 1 as the input goes from 0 to 10. The blue curve (weight 1, bias -5) rises gently and crosses 0.5 at input 5. The orange curve (weight 4, bias -20) rises sharply, also at input 5. The green curve (weight 1, bias -2) rises gently but crosses 0.5 at input 2." caption="One neuron, three settings of its weight and bias"
import numpy as np
import matplotlib.pyplot as plt

def neuron(x, weight, bias):
    total = weight * x + bias            # weighted input plus bias
    return 1 / (1 + np.exp(-total))      # squash into the range 0 to 1

x = np.linspace(0, 10, 200)
fig, ax = plt.subplots(figsize=(6.5, 3.8))
for weight, bias, color, label in [
    (1, -5, "#2a78d6", "weight 1, bias -5"),
    (4, -20, "#eb6834", "weight 4, bias -20"),
    (1, -2, "#1baf7a", "weight 1, bias -2"),
]:
    ax.plot(x, neuron(x, weight, bias), color=color, linewidth=2, label=label)
ax.set_xlabel("Input (say, how sunny it is, 0 to 10)")
ax.set_ylabel("Neuron's output (0 to 1)")
ax.legend(frameon=False, loc="lower right")
ax.spines[["top", "right"]].set_visible(False)
ax.set_title("Weight sets how sharp the switch is; bias sets where it flips", loc="left")
fig.tight_layout()
```

Compare blue and orange: same flip point (input 5), but the bigger weight makes orange snap from "no" to "yes" almost instantly. Compare blue and green: same weight, but the bias moves the flip point from 5 down to 2. A neuron is a dimmer switch whose sharpness and position are set by its weight and bias.

A network stacks thousands or millions of these in layers. The outputs of one layer are the inputs to the next, so later neurons can respond to combinations: not just "edge here", but "edges arranged like a thumb". The final layer has one output per class; those are your Output bars.

## Learning means nudging the weights

Nobody sets those millions of weights by hand. They start out random, and training adjusts them. The recipe:

1.  Show the network an example and let it guess.
2.  Measure how wrong the guess was. That number is the **error** (Teachable Machine's charts call it **loss**).
3.  Nudge every weight a tiny bit in whichever direction would have made the error smaller.
4.  Repeat, many thousands of times.

Here's the smallest possible version: a model with one weight, learning how many minutes a delivery takes per kilometer. The examples were all made at exactly 5 minutes per km, but the model starts out guessing 0. Step through it and watch `w` and `error`:

:::trace Watch the weight get nudged toward 5
```python
examples = [(2, 10), (4, 20), (5, 25)]   # (km, minutes)
w = 0.0        # the model's one weight: minutes per km
rate = 0.02    # learning rate: the size of each nudge

for epoch in range(4):
    for km, minutes in examples:
        guess = w * km
        error = guess - minutes
        w = w - rate * error * km

print("learned minutes per km:", round(w, 2))
```
:::

Early on, guesses are far too low, so `error` is a big negative number, and the nudge pushes `w` up a lot. As `w` approaches 5, the errors shrink, and so do the nudges. After four passes it's close to 5, and nobody told it the answer. The same three ideas appear in Teachable Machine's **Advanced** panel:

-   **Epochs** (50 by default): how many full passes through the training examples. Our loop had 4.
-   **Learning Rate** (0.001 by default): the size of each nudge, our `rate`. Too small and learning crawls; too big and the weights overshoot back and forth. Teachable Machine's own tooltip warns that even small changes can have huge effects.
-   **Batch Size** (16 by default): how many examples are looked at together before each nudge. Our loop nudged after every single example.

In a real network the hard part is step 3: working out the right direction for millions of weights at once. The method that does it is called **backpropagation**, and the second video below shows the "walking downhill" idea behind it.

:::warning
**Scoring a model on its own training examples.** It's the most common mistake in machine learning, and it always looks like success: the right-hand panel above scored a perfect 0.00. A score only means something on examples the model didn't train on.
:::

:::warning
**"More training is always better."** More epochs drive training error down, but past a point the model starts fitting noise and test error goes up. Watch the test line, not the training line.
:::

:::quiz
Q: A model scores 99% on its training examples and 61% on the test set. What's the best description?
- [ ] Underfitting: the model is too simple
  An underfit model does poorly on training examples too. This one aces them.
- [x] Overfitting: it learned details of the training examples that don't carry over
  A big gap between training and test performance is the signature of overfitting.
- [ ] The test set must be wrong
  A low test score is the test set doing its job: revealing what the training score hid.

Q: You try 12 different settings, check the test score after each, and keep the best one. Why is that final test score too optimistic?
- [ ] Because 12 is too many settings to try
  Trying many settings is fine. The problem is which set of examples you chose them with.
- [x] You used the test set to make choices, so it acted as a validation set
  You picked the setting that happened to suit those particular test examples. An honest final score needs examples that played no part in any choice.
- [ ] Because test scores always go down over time
  They don't drift by themselves; the issue is how the score was used.

Q: Using the neuron chart: which change makes a neuron flip from "no" to "yes" at a lower input, without changing how sharp the flip is?
- [ ] A bigger weight
  A bigger weight makes the switch sharper, like the orange curve.
- [x] A different bias
  The green curve kept weight 1 but changed the bias, which slid the flip point from 5 to 2.
- [ ] A smaller learning rate
  The learning rate controls how training nudges the weights, not the shape of a finished neuron.

Q: In the trace, what would happen if `rate` were much bigger, say 0.2?
- [x] Each nudge would overshoot 5, and `w` could swing further away each time
  With a big learning rate, a large error causes a huge nudge that jumps past the answer. Teachable Machine's tooltip warns about exactly this.
- [ ] It would reach exactly 5 in one step
  The nudge depends on the error and the distance, so a bigger rate overshoots rather than landing exactly.
- [ ] Nothing, because the examples are the same
  The examples are the same, but the size of each step changes, and so does where the steps land.
:::

:::takeaways
- Score a model only on examples it never trained on; the training score always flatters it.
- Training set to learn, validation set to choose settings, test set for one honest final score.
- Overfitting shows up as training error falling while test error rises.
- Near-duplicate examples split across training and test make a score look better than it is.
- A neuron is a weighted vote squashed into 0 to 1; training nudges weights to reduce error. Epochs, learning rate, and batch size control that process.
:::
