## Step 1: Work out the resistor value

A typical red LED has a forward voltage of about 2.0 V. We'll aim for 15 mA: bright, but comfortably below the 20 mA that most small LEDs and Uno pins are rated for. The formula gives an exact value, but resistors come in standard sizes, so the code picks the next standard value **up**. These cells share variables, so later steps can reuse the function.

```python run title="led_resistor.py"
E12 = [10, 12, 15, 18, 22, 27, 33, 39, 47, 56, 68, 82]   # standard resistor values

def next_standard(ohms):
    """Smallest standard (E12) value that is at least `ohms`."""
    decade = 1
    while True:
        for base in E12:
            if base * decade >= ohms:
                return base * decade
        decade *= 10

def led_resistor(supply, forward, target_ma):
    exact = (supply - forward) / (target_ma / 1000)
    chosen = next_standard(exact)
    actual_ma = (supply - forward) / chosen * 1000
    return exact, chosen, actual_ma

exact, chosen, actual = led_resistor(5.0, 2.0, 15)
print(f"Exact value:    {exact:.0f} ohms")
print(f"Standard part:  {chosen} ohms")
print(f"Real current:   {actual:.1f} mA")
```

The exact answer is 200 Ω, but 200 isn't a standard value, so we use **220 Ω**. Rounding up always gives *less* current than the target, which is the safe direction. Rounding down to 180 Ω would give 16.7 mA, more than we planned.

## Step 2: Check the pin and the resistor

Two limits matter. Arduino's Uno documentation lists **20 mA** as the DC current per I/O pin. Its guide to digital pins says the chip can source up to 40 mA, but warns that overloading a pin can kill it, so treat 20 mA as your ceiling. And the resistor must not turn more power into heat than its ¼ W rating.

```python run title="safety_check.py"
current_a = actual / 1000
resistor_watts = current_a ** 2 * chosen      # P = I x I x R

print(f"Pin current:    {actual:.1f} mA  (limit 20 mA)  ->", "OK" if actual <= 20 else "TOO HIGH")
print(f"Resistor power: {resistor_watts:.3f} W  (rating 0.25 W) ->", "OK" if resistor_watts <= 0.25 else "TOO HOT")
```

The resistor runs at about a sixth of its rating, so it will barely get warm. Now let's see how the current changes across the whole range of common resistors, so you know which values are off-limits for a red LED on a 5 V pin:

```python run alt="Bar chart of red LED current for resistors from 68 to 1000 ohms. Current falls as resistance rises; 68, 82, 100 and 120 ohms are above the 20 mA line, 150 ohms sits exactly on it, and 220 ohms gives about 14 mA." caption="Red LED on a 5 V pin. Anything below 150 Ω pushes the pin past its 20 mA rating."
import matplotlib.pyplot as plt

values = [68, 82, 100, 120, 150, 180, 220, 270, 330, 470, 680, 1000]
currents = [(5.0 - 2.0) / r * 1000 for r in values]
colors = ["#eb6834" if c > 20 else "#2a78d6" for c in currents]

plt.figure(figsize=(8, 4))
plt.bar([str(v) for v in values], currents, color=colors)
plt.axhline(20, color="#52514e", linestyle="--", linewidth=1)
plt.text(8.6, 22, "20 mA pin rating", color="#52514e")
plt.xlabel("Resistor (ohms)")
plt.ylabel("LED current (mA)")
plt.title("Orange bars are over the limit")
```

Notice how gently the current falls at the high end. 1 kΩ still gives 3 mA, which is dim but visible. When in doubt, a bigger resistor is the safe guess.

Each line in `connections` is one wire: from a pin, to a pin, then a color. ## Step 5: Fade it with PWM

Pin 9 has the **~** mark, so it supports **PWM** (pulse-width modulation). A PWM pin can't output 2.5 V. Instead it switches between 0 V and 5 V very fast (about 490 times a second on pin 9) and varies how much of each cycle is spent on. `analogWrite(pin, value)` takes a value from 0 (always off) to 255 (always on).

```python run alt="Three stacked square waves over two PWM cycles. The top wave is on for 10 percent of each cycle, the middle for 50 percent, and the bottom for 90 percent." caption="analogWrite values 25, 128, and 230 are about 10%, 50%, and 90% on-time."
import matplotlib.pyplot as plt

period_ms = 1000 / 490
fig, axes = plt.subplots(3, 1, figsize=(7, 4.5), sharex=True)
for ax, value in zip(axes, [25, 128, 230]):
    duty = value / 255
    times, levels = [], []
    for cycle in range(2):
        start = cycle * period_ms
        times += [start, start, start + duty * period_ms, start + duty * period_ms]
        levels += [0, 5, 5, 0]
    times.append(2 * period_ms)
    levels.append(0)
    ax.plot(times, levels, color="#2a78d6", linewidth=2)
    ax.set_ylabel("V")
    ax.set_title(f"analogWrite(9, {value}): on {duty:.0%} of the time", fontsize=10)
axes[-1].set_xlabel("Time (ms)")
fig.tight_layout()
```

Your eye can't follow 490 flashes a second, so it sees the average as brightness. Importantly, while the pin is on, the current is still the full 13.6 mA our resistor allows. PWM changes *how long* the current flows, not *how much*, so the safety check from Step 2 still holds at every brightness.

```arduino title="sketch.ino"
const int RED_LED = 9;

void setup() {
  pinMode(RED_LED, OUTPUT);
}

void loop() {
  for (int level = 0; level <= 255; level++) {   // fade up
    analogWrite(RED_LED, level);
    delay(5);
  }
  for (int level = 255; level >= 0; level--) {   // fade down
    analogWrite(RED_LED, level);
    delay(5);
  }
}
```

```text
The LED glows up from dark to full brightness in about 1.3 seconds, then back down, over and over.
```

:::tip
Move the LED to pin 8 (no **~**) and run it again. The LED snaps between off and on instead of fading. On a non-PWM pin, `analogWrite` can only give fully off (values below 128) or fully on (128 and above).
:::

## Step 6: Add a blue LED with its own resistor

Blue LEDs need more voltage, about 3.0 V, so they need a different resistor. Reuse the function from Step 1:

```python run title="blue_led.py"
for name, forward in [("red", 2.0), ("blue", 3.0)]:
    exact, chosen, actual = led_resistor(5.0, forward, 15)
    print(f"{name:>5}: exact {exact:.0f} ohms -> use {chosen} ohms -> {actual:.1f} mA")
```

The blue LED gets **150 Ω**. It goes on pin 10, which also has PWM. Each LED gets its own resistor: if two LEDs shared one resistor in parallel, the red one (lower forward voltage) would take nearly all the current and the blue one would barely glow.

```arduino title="sketch.ino"
const int RED_LED = 9;    // 220 ohm resistor, about 13.6 mA when on
const int BLUE_LED = 10;  // 150 ohm resistor, about 13.3 mA when on

void setup() {
  pinMode(RED_LED, OUTPUT);
  pinMode(BLUE_LED, OUTPUT);
  Serial.begin(9600);
  Serial.println("Crossfade running");
}

void crossfade(int level) {
  analogWrite(RED_LED, level);
  analogWrite(BLUE_LED, 255 - level);   // opposite brightness
  delay(5);
}

void loop() {
  for (int level = 0; level <= 255; level++) {
    crossfade(level);
  }
  for (int level = 255; level >= 0; level--) {
    crossfade(level);
  }
}
```

```text
Serial Monitor: Crossfade running
The red LED brightens while the blue one dims, then they swap, about every 1.3 seconds.
```

On a real breadboard the circuit is the same. The LED's **longer leg** is the anode (+) and goes toward the resistor and pin; the shorter leg, on the side with a flat edge on the LED's rim, goes to GND. The 220 Ω resistor has bands red-red-brown, and 150 Ω is brown-green-brown.

:::quiz
Q: The formula said 200 Ω. Why did we use 220 Ω instead of 180 Ω?
- [ ] 220 Ω is closer to 200 Ω
  Both are 20 Ω away. The reason is which direction is safe.
- [x] A larger resistor gives a little less current, which is the safe direction
  220 Ω gives 13.6 mA, under the target. 180 Ω would give 16.7 mA, over it.
- [ ] Wokwi only accepts 220 Ω resistors
  Wokwi accepts any value in the `value` attribute.

Q: Why are the LEDs on pins 9 and 10 instead of 7 and 8?
- [ ] Pins 7 and 8 can't supply enough current
  All the digital pins have the same current rating.
- [x] Pins 9 and 10 support PWM, so `analogWrite` can fade them
  Only the pins marked **~** (3, 5, 6, 9, 10, 11) produce PWM on the Uno.
- [ ] Pins 7 and 8 are reserved for the Serial Monitor
  The serial link uses pins 0 and 1.

Q: At `analogWrite(9, 64)`, the LED looks about a quarter as bright. What is the current through it while the pin is on?
- [ ] About 3.4 mA, a quarter of 13.6 mA
  PWM doesn't reduce the current; it reduces the time the current flows.
- [x] About 13.6 mA, the same as fully on
  During each "on" slice the pin is at 5 V, so the resistor sets the same current. Only the on-time changes.
- [ ] 0 mA, because 64 is below the threshold
  `analogWrite` on a PWM pin has no threshold; 64 means on for about 25% of each cycle.
:::

:::takeaways
- Resistor = (supply − forward voltage) / target current, rounded **up** to a standard value.
- Check every design twice: pin current at or below 20 mA, resistor power below its ¼ W rating.
- Every LED gets its own resistor, because LEDs with different forward voltages don't share current fairly.
- PWM (`analogWrite`, 0 to 255, on **~** pins only) dims an LED by changing on-time, not current.
- `diagram.json` describes a circuit as text, so you can paste, copy, and save circuits exactly.
:::

## Ideas to extend it

-   Swap in an RGB LED (three LEDs in one package) with three resistors, one per color, and mix colors with three `analogWrite` values.
-   Make a "breathing" fade by stepping `level` with a sine curve instead of a straight count, so it lingers near dark.
-   The fade looks like it spends a long time near full brightness. Your eye's response isn't linear; search "LED gamma correction" to see how lighting designers fix it.
