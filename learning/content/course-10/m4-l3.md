### Exercise 1: Digital or analog?

For each sensor, say whether it gives a digital or an analog signal, which kind of Uno pin it goes on, and which function reads it.

1.  A magnetic door switch
2.  A potentiometer used as a volume knob
3.  A soil moisture probe with a single output pin labeled "AO"
4.  A tilt switch (a ball that rolls to close a contact)
5.  A thermistor in a divider with a 10 kΩ resistor
6.  The "DO" pin on a light sensor module

:::hint
Ask: can the output only be "near 0 V or near 5 V", or can it be anywhere in between? "AO" and "DO" on module labels usually stand for analog out and digital out.
:::

:::solution
| Sensor | Signal | Pin | Function |
| --- | --- | --- | --- |
| Door switch | Digital | Any digital pin, with `INPUT_PULLUP` | `digitalRead` |
| Potentiometer | Analog | A0–A5 | `analogRead` |
| Soil probe "AO" | Analog | A0–A5 | `analogRead` |
| Tilt switch | Digital | Any digital pin, with `INPUT_PULLUP` | `digitalRead` |
| Thermistor divider | Analog | A0–A5 | `analogRead` |
| Light module "DO" | Digital | Any digital pin | `digitalRead` |

Switches are just buttons that something other than a finger presses, so they get the same pull-up treatment. The A pins can also act as digital pins if you run out, but digital pins can't read analog values.
:::

### Exercise 2: Readings to volts and back, without the integer bug

Write `to_volts(reading)` and `to_reading(volts)` for a 5 V Uno, and check that they round-trip. Then show what the buggy C expression `reading * 5 / 1023` (whole-number math) gives for readings 100, 600, and 1000, next to the correct answer.

```text
reading 100: correct 0.489 V, whole-number math gives 0
reading 600: correct 2.933 V, whole-number math gives 2
reading 1000: correct 4.888 V, whole-number math gives 4
```

:::hint
`to_reading` is the formula turned around: reading = volts × 1023 / 5, rounded to a whole number. In Python, `//` imitates C's division of two `int`s for positive numbers.
:::

:::solution
```python run
def to_volts(reading):
    return reading * 5.0 / 1023.0

def to_reading(volts):
    return round(volts * 1023 / 5.0)

for volts in [0.0, 1.25, 2.5, 3.3, 5.0]:
    raw = to_reading(volts)
    print(f"{volts:.2f} V -> reading {raw} -> {to_volts(raw):.3f} V")

print()
for reading in [100, 600, 1000]:
    print(f"reading {reading}: correct {to_volts(reading):.3f} V, "
          f"whole-number math gives {reading * 5 // 1023}")
```

The round trip is only off by a few millivolts, less than one ADC step. The whole-number version throws away everything after the decimal point, so it can only ever answer 0, 1, 2, 3, 4, or 5 volts.
:::

### Exercise 3: Read a TMP36

A TMP36 outputs 0.5 V at 0 °C and rises 10 mV per degree. Convert readings 143, 153, and 184 to °C. Then find the reading that means 30 °C, so a sketch could compare raw readings without converting each time.

:::hint
First convert the reading to volts. Then °C = (volts − 0.5) × 100. For the reverse, 30 °C is 0.5 + 0.30 = 0.80 V; turn that into a reading.
:::

:::solution
```python run
def tmp36_celsius(reading):
    volts = reading * 5.0 / 1023.0
    return (volts - 0.5) * 100

for reading in [143, 153, 184]:
    print(f"reading {reading} -> {tmp36_celsius(reading):.1f} C")

volts_at_30 = 0.5 + 30 * 0.010
print(f"30 C = {volts_at_30:.2f} V = reading {round(volts_at_30 * 1023 / 5.0)}")
```

In a sketch, the conversion is one line:

```arduino
float celsius = (analogRead(A0) * 5.0 / 1023.0 - 0.5) * 100;
```

Each reading step is about 0.49 °C for a TMP36 on a 5 V Uno, so don't expect it to resolve tenths of a degree.
:::

### Exercise 4: Pick the divider resistor

A photoresistor measures about 1 kΩ in bright light and 100 kΩ in darkness. It goes on the bottom of a divider. Which fixed top resistor, 1 kΩ, 10 kΩ, or 100 kΩ, gives the biggest difference between the bright and dark readings? Plot the reading against the photoresistor's resistance for all three.

:::hint
Reading = 1023 × R_ldr / (R_top + R_ldr). Compute it at 1 kΩ and at 100 kΩ for each choice, and subtract. Think about what happens when R_top is much bigger, or much smaller, than the photoresistor.
:::

:::solution
```python run alt="Three curves of analogRead value against photoresistor resistance on a log axis from 1 to 100 kilohms. With a 1 kilohm top resistor the reading only spans about 512 to 1013; with 100 kilohms it spans about 10 to 512; with 10 kilohms it spans about 93 to 930, the widest range." caption="A top resistor near the middle of the sensor's range (10 kΩ) uses the most of the ADC's 0 to 1023."
import matplotlib.pyplot as plt

def reading(r_top, r_ldr):
    return round(1023 * r_ldr / (r_top + r_ldr))

for r_top in [1_000, 10_000, 100_000]:
    bright, dark = reading(r_top, 1_000), reading(r_top, 100_000)
    print(f"top {r_top:>6} ohms: bright {bright:>4}, dark {dark:>4}, spread {dark - bright}")

ldr_values = [1000 * 10 ** (i / 20) for i in range(41)]
plt.figure(figsize=(7, 3.8))
for r_top, color in [(1_000, "#eb6834"), (10_000, "#2a78d6"), (100_000, "#1baf7a")]:
    plt.plot([r / 1000 for r in ldr_values], [reading(r_top, r) for r in ldr_values],
             color=color, linewidth=2, label=f"top resistor {r_top // 1000} kΩ")
plt.xscale("log")
plt.xlabel("Photoresistor resistance (kΩ, log scale)")
plt.ylabel("analogRead value")
plt.title("Which fixed resistor spreads the readings widest?")
plt.legend()
plt.grid(alpha=0.3)
plt.tight_layout()
```

10 kΩ wins with a spread of over 800 counts; the others manage about 500. A useful rule of thumb: pick a fixed resistor near the geometric middle of the sensor's range. For 1 kΩ to 100 kΩ, that's √(1,000 × 100,000) = 10 kΩ.
:::

### Exercise 5: Two ways to smooth

A **moving average** of the last 8 readings is one way to smooth. Another is **exponential smoothing**, which needs only one variable: `smoothed = smoothed + 0.2 * (raw - smoothed)`. Each new reading pulls the smoothed value 20% of the way toward it.

Apply both to a noisy signal that jumps from 300 to 700 at reading 40. For each method, find how many readings after the jump it takes to get within 20 of 700, and plot both.

:::hint
Use `random.seed` so the noise is the same every run. For the "within 20" check, loop over the smoothed list from index 40 and stop at the first value above 680.
:::

:::solution
```python run alt="Line chart of 100 readings. Raw readings jitter around 300, then jump to about 700 at reading 40. The 8-reading moving average climbs in a straight ramp and reaches 700 about 8 readings later. Exponential smoothing curves up quickly at first, then approaches 700 more slowly." caption="Both remove most of the noise. The moving average ramps in a straight line and settles first; exponential smoothing moves first, then eases in slowly."
import random
import matplotlib.pyplot as plt

random.seed(7)
raw = [(300 if i < 40 else 700) + random.randint(-25, 25) for i in range(100)]

moving = []
for i in range(len(raw)):
    recent = raw[max(0, i - 7): i + 1]
    moving.append(sum(recent) / len(recent))

exponential = []
smoothed = raw[0]
for value in raw:
    smoothed = smoothed + 0.2 * (value - smoothed)
    exponential.append(smoothed)

def readings_to_settle(series):
    for i in range(40, len(series)):
        if series[i] > 680:
            return i - 40
    return None

print("Moving average (8):      ", readings_to_settle(moving), "readings to get within 20")
print("Exponential (alpha 0.2): ", readings_to_settle(exponential), "readings to get within 20")

plt.figure(figsize=(7, 3.8))
plt.plot(raw, color="#52514e", linewidth=1, alpha=0.5, label="raw")
plt.plot(moving, color="#2a78d6", linewidth=2, label="moving average, 8 readings")
plt.plot(exponential, color="#eb6834", linewidth=2, label="exponential, alpha 0.2")
plt.xlabel("Reading number")
plt.ylabel("Value")
plt.title("Same noise, two smoothers")
plt.legend()
plt.grid(alpha=0.3)
plt.tight_layout()
```

Exponential smoothing moves first (it jumps 20% of the way on the very first new reading), but the moving average finishes sooner: about 7 readings against 13 here. The moving average's delay is fixed by its window; the exponential one creeps up on the new value without ever quite arriving. Exponential smoothing's real advantage is memory: no array, just one `float`, which matters on a chip with 2 KB of RAM. On the Uno it looks like this:

```arduino
float smoothed = analogRead(A0);   // set once in setup()

// in loop():
smoothed = smoothed + 0.2 * (analogRead(A0) - smoothed);
```

A smaller factor (0.1) smooths more and reacts more slowly; a larger one (0.5) does the opposite.
:::

### Exercise 6: Report light levels only when they change

With the Wokwi photoresistor module on A0, print `dark`, `dim`, or `bright`, but only when the category changes, checking every 250 ms with `millis()`. Use the model from the notes to set the boundaries: darker than 20 lux is a reading above 772, and brighter than 500 lux is a reading below 250.

```text
Light monitor
bright
dim
dark
dim
```

:::hint
Write a function that turns a reading into a category number (0, 1, or 2). Keep the last category in a global variable, and print only when the new one is different. That's edge detection again, this time on a category instead of a button.
:::

:::solution
```arduino
const int LIGHT_PIN = A0;
const unsigned long CHECK_MS = 250;

const char* NAMES[] = {"dark", "dim", "bright"};
int lastCategory = -1;          // -1 means "nothing printed yet"
unsigned long lastCheck = 0;

int categoryOf(int reading) {
  if (reading > 772) return 0;  // darker than about 20 lux
  if (reading < 250) return 2;  // brighter than about 500 lux
  return 1;
}

void setup() {
  Serial.begin(9600);
  Serial.println("Light monitor");
}

void loop() {
  if (millis() - lastCheck >= CHECK_MS) {
    lastCheck = millis();
    int category = categoryOf(analogRead(LIGHT_PIN));
    if (category != lastCategory) {
      Serial.println(NAMES[category]);
      lastCategory = category;
    }
  }
}
```

At Wokwi's default 500 lux the reading sits right on 250, so the first line may be `dim` or `bright`. Starting `lastCategory` at -1 guarantees the first check always prints something.
:::

### Challenge: Calibrate at startup

Hard-coded thresholds break when the sensor, the room, or the soil changes. Write a sketch that spends its first 5 seconds recording the lowest and highest readings on A0 while you sweep the sensor through its range (in Wokwi, use a potentiometer standing in for a soil probe, and turn it end to end). After that, print each reading as a percentage from 0 to 100 of the calibrated range, twice a second.

```text
Calibrating for 5 seconds: sweep the sensor now
Calibrated: min=40 max=980
0%
37%
100%
```

:::hint
Start `low` at 1023 and `high` at 0, so the first real reading replaces both. Inside a `while (millis() < 5000)` loop in `setup()`, update them. Afterwards, `map(reading, low, high, 0, 100)` gives the percentage, and `constrain(…, 0, 100)` stops readings outside the calibrated range from producing 110% or −5%.
:::

:::solution
```arduino
const int SENSOR = A0;
int low = 1023;
int high = 0;
unsigned long lastPrint = 0;

void setup() {
  Serial.begin(9600);
  Serial.println("Calibrating for 5 seconds: sweep the sensor now");
  while (millis() < 5000) {
    int reading = analogRead(SENSOR);
    if (reading < low) low = reading;
    if (reading > high) high = reading;
  }
  if (high <= low) high = low + 1;   // avoid dividing by zero in map()
  Serial.print("Calibrated: min=");
  Serial.print(low);
  Serial.print(" max=");
  Serial.println(high);
}

void loop() {
  if (millis() - lastPrint >= 500) {
    lastPrint = millis();
    int percent = map(analogRead(SENSOR), low, high, 0, 100);
    percent = constrain(percent, 0, 100);
    Serial.print(percent);
    Serial.println("%");
  }
}
```

The `high <= low` guard matters: if nobody sweeps the sensor, `low` and `high` end up equal, and `map` would divide by zero. Real projects often save calibration values so they survive a restart, but recalibrating at power-on is a good start.
:::
