:::objectives
- Turn one signed speed number into the IN1, IN2, and ENA signals an H-bridge driver needs.
- Map a knob to forward, stop, and reverse, with a dead band around the middle.
- Ramp speed changes so the motor never slams from full forward to full reverse.
- Add a latching stop button and a servo needle that shows the speed.
:::

Real robot teams don't test motor code on the robot first. They build a bench: a knob for the command, lights for the driver signals, and a big red button. That's what you'll make here, in Wokwi, and the sketch you end with is the motor layer of the robot you'll build later.

## What we're building

```mermaid caption="The test bench. Everything to the right of the Arduino is what a real L298N would receive."
flowchart LR
    K["Knob on A0"] --> U["Arduino Uno"]
    S["STOP button on pin 2"] --> U
    U -- "pin 5 PWM" --> E["ENA LED: brightness = speed"]
    U -- "pin 7" --> I1["IN1 LED"]
    U -- "pin 8" --> I2["IN2 LED"]
    U -- "pin 9" --> G["Servo needle: 0 to 180 degrees"]
```

Turn the knob right of center and the IN1 LED lights while ENA glows brighter the further you turn. Left of center lights IN2 instead. The servo needle sits at 90° when stopped and swings toward 180° for full forward or 0° for full reverse. Press STOP and everything goes dark until you return the knob to the middle.

## Step 2: One function that owns the driver pins

Everything the rest of the program says about the motor goes through `setMotor()`. Replace the sketch with this test, which runs a fixed pattern you can check by eye:

```arduino
const int ENA = 5;   // PWM: speed
const int IN1 = 7;   // direction
const int IN2 = 8;   // direction

void setMotor(int speed) {
  speed = constrain(speed, -255, 255);
  if (speed > 0) {
    digitalWrite(IN1, HIGH);
    digitalWrite(IN2, LOW);
  } else if (speed < 0) {
    digitalWrite(IN1, LOW);
    digitalWrite(IN2, HIGH);
  } else {
    digitalWrite(IN1, LOW);
    digitalWrite(IN2, LOW);
  }
  analogWrite(ENA, abs(speed));
}

void setup() {
  pinMode(ENA, OUTPUT);
  pinMode(IN1, OUTPUT);
  pinMode(IN2, OUTPUT);
}

void loop() {
  setMotor(255);    // full forward
  delay(1000);
  setMotor(80);     // slow forward
  delay(1000);
  setMotor(0);      // stop
  delay(1000);
  setMotor(-160);   // reverse
  delay(1000);
}
```

Press the green play button. You should see this repeating:

```text
IN1 on,  IN2 off, ENA bright      (full forward)
IN1 on,  IN2 off, ENA dim         (slow forward)
all off                            (stop)
IN1 off, IN2 on,  ENA medium       (reverse)
```

If ENA looks almost as bright at 80 as at 255, that's expected: Wokwi's LED model brightens short pulses the way your eye does with a real LED. The direction LEDs are the important check.

## Step 3: Read the knob, with a dead band

A potentiometer reads 0 to 1023. We want the middle to mean "stop", so subtract 512 to get a number centered on zero, then ignore small values. Without that dead band, a knob that's *almost* centered would creep the robot forward.

```arduino
const int KNOB = A0;
const int DEAD_BAND = 40;   // knob counts around the middle that mean "stop"

int knobToSpeed(int raw) {
  int centered = raw - 512;            // -512 .. 511
  if (abs(centered) < DEAD_BAND) {
    return 0;
  }
  return map(centered, -512, 511, -255, 255);
}
```

Put `Serial.begin(115200);` in `setup()` and print `knobToSpeed(analogRead(KNOB))` in `loop()` to check it. Turning the knob fully one way should print about −255, the other way 255, and the middle 0.

## Step 4: Ramp instead of jumping

If you snap the knob from full forward to full reverse, the code above tells the motor to reverse instantly. On a real robot that's a current spike, a jerk that can flip the chassis, and stress on the gears. The fix is a **ramp**: each pass through `loop()`, move the actual speed at most `MAX_STEP` toward the target.

```arduino
const int MAX_STEP = 5;   // largest speed change per loop pass

int rampToward(int current, int target) {
  if (target > current + MAX_STEP) return current + MAX_STEP;
  if (target < current - MAX_STEP) return current - MAX_STEP;
  return target;
}
```

With a loop that runs every 20 ms, 0 to 255 takes about 51 steps, roughly one second. Here's the same logic run in Python so you can see the effect before you trust it:

```python run alt="Step chart: the target jumps from 0 to 255 and then to minus 255, while the ramped speed climbs in a straight line, then slides down through zero to minus 255" caption="The ramp turns sudden knob changes into smooth speed changes"
import matplotlib.pyplot as plt

MAX_STEP = 5
LOOP_MS = 20

def ramp_toward(current, target):
    if target > current + MAX_STEP:
        return current + MAX_STEP
    if target < current - MAX_STEP:
        return current - MAX_STEP
    return target

targets = [0] * 10 + [255] * 80 + [-255] * 120   # what the knob asks for, one per loop pass
speed = 0
speeds = []
for target in targets:
    speed = ramp_toward(speed, target)
    speeds.append(speed)

times = [i * LOOP_MS / 1000 for i in range(len(targets))]
reversal_start = targets.index(-255)
zero_cross = next(i for i in range(reversal_start, len(speeds)) if speeds[i] <= 0)
print("Reaches full forward after", (speeds.index(255) - 10) * LOOP_MS, "ms")
print("Passes through zero", (zero_cross - reversal_start) * LOOP_MS, "ms after the knob reverses")

plt.step(times, targets, where="post", color="#adb5bd", label="knob target")
plt.plot(times, speeds, color="#7892ee", label="speed sent to driver")
plt.axhline(0, color="black", linewidth=0.6)
plt.xlabel("time (s)")
plt.ylabel("speed (-255 to 255)")
plt.legend()
```

The reversal takes about two seconds and crosses zero halfway, so the motor slows, stops, and then reverses. Change `MAX_STEP` to 15 and run it again: the robot gets snappier and the spikes get bigger. Picking that number is a trade-off you'll tune on a real chassis.

## Step 5: A servo needle that shows the speed

A gauge makes the invisible number visible. `map()` turns −255..255 into 0..180, so stopped is 90°.

```arduino
#include <Servo.h>

Servo gauge;

// in setup():
gauge.attach(9);

// in loop(), after setMotor(currentSpeed):
gauge.write(map(currentSpeed, -255, 255, 0, 180));
```

## Step 6: A stop button that stays stopped

A stop button that only works while you hold it is a trap: let go and the robot leaps back to whatever the knob says. Ours **latches**. Pressing STOP sets a flag, and the flag clears only when the knob is back in the dead band, so the motor can never restart at speed by surprise. The button uses `INPUT_PULLUP`, so pressed reads `LOW`.

```arduino
bool stopped = true;        // start stopped: no driving until the knob is centered once

// in loop():
if (digitalRead(STOP_BUTTON) == LOW) {
  stopped = true;
}
if (stopped && target == 0) {
  stopped = false;          // re-arm only with the knob centered
}
```

The flag starts `true`, so a robot switched on with the knob already turned stays still. Notice too that the stop *skips the ramp*. Ramps protect the hardware during normal driving; an emergency stop should act now.

## The finished sketch

```arduino
#include <Servo.h>

// Motor driver inputs. In Wokwi they light LEDs; on a robot they go to an L298N.
const int ENA = 5;           // PWM speed (keeps PWM even with the Servo library)
const int IN1 = 7;
const int IN2 = 8;
const int KNOB = A0;
const int STOP_BUTTON = 2;
const int GAUGE_PIN = 9;

const int DEAD_BAND = 40;    // knob counts around the middle that mean "stop"
const int MAX_STEP = 5;      // largest speed change per loop pass

Servo gauge;
int currentSpeed = 0;        // -255..255, what the driver is being told now
bool stopped = true;         // true at power-up and after STOP, until the knob is centered

void setMotor(int speed) {
  speed = constrain(speed, -255, 255);
  if (speed > 0) {
    digitalWrite(IN1, HIGH);
    digitalWrite(IN2, LOW);
  } else if (speed < 0) {
    digitalWrite(IN1, LOW);
    digitalWrite(IN2, HIGH);
  } else {
    digitalWrite(IN1, LOW);
    digitalWrite(IN2, LOW);
  }
  analogWrite(ENA, abs(speed));
}

int knobToSpeed(int raw) {
  int centered = raw - 512;
  if (abs(centered) < DEAD_BAND) {
    return 0;
  }
  return map(centered, -512, 511, -255, 255);
}

int rampToward(int current, int target) {
  if (target > current + MAX_STEP) return current + MAX_STEP;
  if (target < current - MAX_STEP) return current - MAX_STEP;
  return target;
}

void setup() {
  pinMode(ENA, OUTPUT);
  pinMode(IN1, OUTPUT);
  pinMode(IN2, OUTPUT);
  pinMode(STOP_BUTTON, INPUT_PULLUP);
  gauge.attach(GAUGE_PIN);
  setMotor(0);               // known-safe state before anything else
  Serial.begin(115200);
  Serial.println("target,speed,stopped");
}

void loop() {
  int target = knobToSpeed(analogRead(KNOB));

  if (digitalRead(STOP_BUTTON) == LOW) {
    stopped = true;
  }
  if (stopped && target == 0) {
    stopped = false;
  }

  if (stopped) {
    currentSpeed = 0;        // emergency stop skips the ramp
  } else {
    currentSpeed = rampToward(currentSpeed, target);
  }

  setMotor(currentSpeed);
  gauge.write(map(currentSpeed, -255, 255, 0, 180));

  Serial.print(target);
  Serial.print(',');
  Serial.print(currentSpeed);
  Serial.print(',');
  Serial.println(stopped);
  delay(20);
}
```

Run it and turn the knob fully right. Lines like these scroll past as the speed climbs toward the target:

```text
target,speed,stopped
0,0,0
255,5,0
255,10,0
255,15,0
...
255,255,0
```

Now press STOP mid-ramp: speed drops to 0 on the very next line, and stays there while the knob is still turned.

## Taking it to a real robot

The sketch doesn't change. The wiring does:

| Arduino | L298N | Notes |
| --- | --- | --- |
| Pin 5 | ENA | Remove the ENA jumper first |
| Pin 7 | IN1 | |
| Pin 8 | IN2 | |
| GND | GND | Shared with the battery's negative |
| (nothing) | Motor supply terminal (often labeled 12V) | Battery pack positive (4 × AA works for TT motors) |
| (nothing) | OUT1, OUT2 | The motor's two wires |

Before the first power-up, put the robot on a box with its wheels off the table. A bug that says "full speed" is harmless when the wheels spin in the air.

:::quiz
Q: Why does the stop button skip `rampToward()` and set the speed to 0 directly?
- [ ] Ramping only works for positive speeds
  The ramp handles negative speeds fine; the chart shows it sliding to −255.
- [x] An emergency stop has to act immediately; the ramp exists to protect hardware during normal changes
  At `MAX_STEP = 5`, ramping down from 255 would take another second of driving after you hit STOP.
- [ ] `setMotor()` can't receive 0 from the ramp
  It can; 0 is a normal speed for `setMotor()`.

Q: Someone moves ENA to pin 10 to tidy the wiring. What breaks?
- [ ] Nothing; pin 10 supports PWM on an Uno
  It does normally, but not while the `Servo` library is in use.
- [x] Speed control, because the Servo library disables PWM on pins 9 and 10
  The direction LEDs still work, but `analogWrite()` on pin 10 no longer produces the right duty cycle.
- [ ] The servo, because it needs pin 10 to be free
  The servo only needs its own signal pin, 9 here.

Q: What would happen without the `stopped && target == 0` re-arm rule, if the flag simply cleared when you released the button?
- [x] The motor would ramp back up to the knob's speed as soon as you let go
  The knob is still turned, so the target is still high. Latching until the knob is centered prevents the surprise restart.
- [ ] The motor would stay stopped forever
  That happens if the flag never clears at all.
- [ ] Nothing different, because the ramp prevents restarting
  The ramp slows the restart down but doesn't prevent it.
:::

:::takeaways
- Keep all driver-pin logic in one function (`setMotor`) so the rest of the program speaks in signed speeds.
- A dead band stops a nearly centered control from creeping.
- A ramp limits how fast speed changes; it's gentler on gears, batteries, and chassis.
- Emergency stops bypass the ramp and latch until the controls are back at zero.
- Put the robot's wheels in the air for the first test of any new motor code.
:::

## Ideas to extend it

- Add a second motor (ENB on pin 6, IN3 and IN4 on pins 4 and 3) and a second knob, making a two-wheel "tank" control.
- Make the ramp asymmetric: speed up gently, slow down faster.
- Replace `delay(20)` with a `millis()` timer (the next module shows how) so the loop can do other work between ramp steps.
