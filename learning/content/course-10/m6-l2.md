:::objectives
- Turn a written spec into a state diagram, then into an `enum` and `switch`.
- Run three independent `millis()` timers in one `loop()`: sensor pings, door motion, and a warning light.
- Move a servo smoothly with a proportional rule instead of jumping.
- Test every transition by playing "the world" with Wokwi's distance slider.
:::

Supermarket doors look simple until you list what they must never do: close on a person, stay shut while someone waits, or open and close so fast they look broken. That list is a state machine, and the door is an excellent rehearsal for a robot. Same sensor, same servo, same timers, but the stakes are easy to see.

## What we're building

Here is the spec, then the diagram it turns into:

- When someone comes within 60 cm, the door opens to 90°.
- It stays open while anyone is there, and for 3 seconds after they leave.
- If someone appears while it's closing, it reopens. **Always.**
- A red light flashes whenever the door moves.

```mermaid caption="The door controller. CLOSING to OPENING is the safety rule."
stateDiagram-v2
    [*] --> CLOSED
    CLOSED --> OPENING: person within 60 cm
    OPENING --> OPEN: door reaches 90 degrees
    OPEN --> CLOSING: 3 s with nobody there
    CLOSING --> OPENING: person appears
    CLOSING --> CLOSED: door reaches 0 degrees
```

Notice what *isn't* there: no arrow from OPENING straight to CLOSING. A person leaving halfway doesn't reverse an opening door; it finishes opening and waits. Missing arrows are design decisions too.

## Step 2: Ping the sensor on a timer

An HC-SR04 needs a 10 µs pulse on TRIG, then holds ECHO high for as long as the sound took to return. Sound covers about 0.0343 cm per microsecond and makes a round trip, hence the divide by 2.

```arduino
const int TRIG = 10;
const int ECHO = 11;
const unsigned long SENSOR_MS = 60;   // leave about 60 ms between pings

long distanceCm = 999;
unsigned long lastPing = 0;

long readDistanceCm() {
  digitalWrite(TRIG, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG, HIGH);
  delayMicroseconds(10);
  digitalWrite(TRIG, LOW);
  unsigned long duration = pulseIn(ECHO, HIGH, 30000UL);  // give up after 30 ms
  if (duration == 0) return 999;                          // no echo: nothing in range
  return duration * 0.0343 / 2;
}

void setup() {
  pinMode(TRIG, OUTPUT);
  pinMode(ECHO, INPUT);
  Serial.begin(115200);
}

void loop() {
  unsigned long now = millis();
  if (now - lastPing >= SENSOR_MS) {
    lastPing = now;
    distanceCm = readDistanceCm();
    Serial.println(distanceCm);
  }
}
```

Run it and drag the slider; the printed number should follow within a centimeter. Two choices here matter later. The `30000UL` timeout caps how long `pulseIn()` can wait; without it, a missing echo stalls the whole program for its default of one second. And a timeout returns 999 ("nothing there"), not 0, because 0 cm would mean "someone is pressed against the sensor".

## Step 3: Move the door proportionally

`door.write(90)` would snap the door open in one jerk. Instead, every 40 ms we close a fixed fraction of the remaining gap between where the door is and where it should be:

```arduino
const float KP = 0.1;   // fraction of the remaining gap closed per update

void moveDoor() {
  int error = doorTarget - doorAngle;
  int step = error * KP;
  if (step == 0 && error != 0) {
    step = (error > 0) ? 1 : -1;   // always finish the last degree
  }
  doorAngle += step;
  door.write(doorAngle);
}
```

That's the proportional rule from the notes: big error, big step; small error, small step. Here the "measurement" is our own `doorAngle` variable, not a sensor, so it can't oscillate the way the line follower did; the servo's built-in feedback loop handles the real shaft. Preview the motion before wiring it in:

```python run alt="Door angle over time for three gains: 0.05 reaches 90 degrees in about 2.3 seconds, 0.1 in about 1.4 seconds, 0.5 in about a third of a second; all three rise fast at first and slow down near the end" caption="Each update closes a fraction of the remaining gap, so the door slows as it arrives"
import matplotlib.pyplot as plt

MOVE_MS = 40

def open_door(kp):
    angle, angles = 0, [0]
    while angle != 90:
        error = 90 - angle
        step = int(error * kp)
        if step == 0:
            step = 1
        angle += step
        angles.append(angle)
    return angles

for kp, color in [(0.05, "#adb5bd"), (0.1, "#7892ee"), (0.5, "#e8590c")]:
    angles = open_door(kp)
    seconds = (len(angles) - 1) * MOVE_MS / 1000
    print(f"KP = {kp}: fully open after {seconds:.2f} s")
    plt.plot([i * MOVE_MS / 1000 for i in range(len(angles))], angles, color=color, label=f"KP = {kp}")
plt.xlabel("time (s)")
plt.ylabel("door angle (degrees)")
plt.legend()
```

`KP = 0.5` slams open in a third of a second; `0.05` dawdles. We'll use 0.1.

## Step 4: The state machine

Now the diagram becomes code. Each `case` sets where the door should be and checks only its own outgoing arrows. `enterState()` logs every transition, which turns the Serial Monitor into a record of exactly what the controller decided and why:

```arduino
enum DoorState { CLOSED, OPENING, OPEN, CLOSING };
DoorState state = CLOSED;
unsigned long stateStart = 0;

void enterState(DoorState next) {
  Serial.print(millis());
  Serial.print(" ms: ");
  Serial.print(stateName(state));
  Serial.print(" -> ");
  Serial.println(stateName(next));
  state = next;
  stateStart = millis();
}
```

The OPEN state has one subtle line. While someone is still there, it keeps pushing `stateStart` forward, so the 3-second countdown only begins once the doorway is empty:

```arduino
case OPEN:
  doorTarget = 90;
  if (someone) stateStart = now;            // restart the countdown
  if (now - stateStart >= HOLD_OPEN_MS) enterState(CLOSING);
  break;
```

## Step 5: The safety reversal and the warning light

In CLOSING, the person check comes **first**, before the "fully closed" check. If both were true on the same pass, safety wins:

```arduino
case CLOSING:
  doorTarget = 0;
  if (someone) enterState(OPENING);          // never close on a person
  else if (doorAngle == 0) enterState(CLOSED);
  break;
```

The light is a third independent timer: toggle every 150 ms while the door moves, off otherwise.

## The finished sketch

```arduino
#include <Servo.h>

const int TRIG = 10;
const int ECHO = 11;
const int DOOR_PIN = 9;
const int WARNING_LED = 12;

const long PERSON_CM = 60;
const unsigned long HOLD_OPEN_MS = 3000;
const unsigned long SENSOR_MS = 60;
const unsigned long MOVE_MS = 40;
const unsigned long BLINK_MS = 150;
const float KP = 0.1;

enum DoorState { CLOSED, OPENING, OPEN, CLOSING };
DoorState state = CLOSED;
unsigned long stateStart = 0;

Servo door;
int doorAngle = 0;
int doorTarget = 0;
long distanceCm = 999;
unsigned long lastPing = 0;
unsigned long lastMove = 0;
unsigned long lastBlink = 0;

const char* stateName(DoorState s) {
  switch (s) {
    case CLOSED:  return "CLOSED";
    case OPENING: return "OPENING";
    case OPEN:    return "OPEN";
    case CLOSING: return "CLOSING";
  }
  return "?";
}

void enterState(DoorState next) {
  Serial.print(millis());
  Serial.print(" ms: ");
  Serial.print(stateName(state));
  Serial.print(" -> ");
  Serial.print(stateName(next));
  Serial.print("  (distance ");
  Serial.print(distanceCm);
  Serial.println(" cm)");
  state = next;
  stateStart = millis();
}

long readDistanceCm() {
  digitalWrite(TRIG, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG, HIGH);
  delayMicroseconds(10);
  digitalWrite(TRIG, LOW);
  unsigned long duration = pulseIn(ECHO, HIGH, 30000UL);
  if (duration == 0) return 999;
  return duration * 0.0343 / 2;
}

void moveDoor() {
  int error = doorTarget - doorAngle;
  int step = error * KP;
  if (step == 0 && error != 0) {
    step = (error > 0) ? 1 : -1;
  }
  doorAngle += step;
  door.write(doorAngle);
}

void setup() {
  pinMode(TRIG, OUTPUT);
  pinMode(ECHO, INPUT);
  pinMode(WARNING_LED, OUTPUT);
  door.attach(DOOR_PIN);
  door.write(doorAngle);
  Serial.begin(115200);
  Serial.println("Door ready: CLOSED");
}

void loop() {
  unsigned long now = millis();

  if (now - lastPing >= SENSOR_MS) {        // timer 1: sensor
    lastPing = now;
    distanceCm = readDistanceCm();
  }
  bool someone = distanceCm < PERSON_CM;

  switch (state) {
    case CLOSED:
      doorTarget = 0;
      if (someone) enterState(OPENING);
      break;
    case OPENING:
      doorTarget = 90;
      if (doorAngle == 90) enterState(OPEN);
      break;
    case OPEN:
      doorTarget = 90;
      if (someone) stateStart = now;
      if (now - stateStart >= HOLD_OPEN_MS) enterState(CLOSING);
      break;
    case CLOSING:
      doorTarget = 0;
      if (someone) enterState(OPENING);
      else if (doorAngle == 0) enterState(CLOSED);
      break;
  }

  if (now - lastMove >= MOVE_MS) {          // timer 2: door motion
    lastMove = now;
    moveDoor();
  }

  bool moving = (state == OPENING || state == CLOSING);
  if (!moving) {
    digitalWrite(WARNING_LED, LOW);
  } else if (now - lastBlink >= BLINK_MS) { // timer 3: warning light
    lastBlink = now;
    digitalWrite(WARNING_LED, !digitalRead(WARNING_LED));
  }
}
```

## Step 6: Test every arrow

A state machine is tested by making each transition happen on purpose. Run these with the slider and check the log:

| Test | What you do | What the log should show |
| --- | --- | --- |
| Approach | Slide from 200 to 30 cm | CLOSED -> OPENING, then OPENING -> OPEN |
| Linger | Stay at 30 cm for 10 s | No new lines; the door stays open |
| Leave | Slide to 200 cm | About 3 s later, OPEN -> CLOSING, then CLOSING -> CLOSED |
| Safety | Slide to 200, and while it's closing, back to 40 | CLOSING -> OPENING |
| Brief visit | Slide to 30, then to 200 before it's fully open | OPENING finishes, then OPEN, then CLOSING after 3 s |

A run through the first three tests prints something like this (your times will differ):

```text
Door ready: CLOSED
4210 ms: CLOSED -> OPENING  (distance 29 cm)
5640 ms: OPENING -> OPEN  (distance 29 cm)
17980 ms: OPEN -> CLOSING  (distance 199 cm)
19400 ms: CLOSING -> CLOSED  (distance 199 cm)
```

The slider said 30 and the log says 29, because converting to `long` drops the fraction. It doesn't matter for a door; module 7 shows when it does. If the safety test fails, look at the CLOSING case first.

:::quiz
Q: Why does the OPEN state set `stateStart = now` while someone is present, instead of just checking the timer?
- [ ] To make the door open wider
  `stateStart` only affects timing; the angle comes from `doorTarget`.
- [x] So the 3-second countdown starts when the last person leaves, not when the door opened
  Pushing the start time forward keeps resetting the countdown while anyone is in the doorway.
- [ ] Because `millis()` stops while the door is open
  `millis()` never stops; it counts from power-up regardless of state.

Q: Someone deletes `if (someone) enterState(OPENING);` from the CLOSING case. A person steps into the doorway while the door is closing. What happens?
- [ ] The door stops where it is
  Nothing tells it to stop; `doorTarget` is still 0 in CLOSING.
- [x] The door keeps closing on the person, and only reopens after it has fully shut
  Without that arrow, CLOSING can only lead to CLOSED. The CLOSED state then sees the person and opens again, too late.
- [ ] The door reopens immediately, because CLOSED handles people
  CLOSED does handle people, but the door has to finish closing before it reaches CLOSED.

Q: `readDistanceCm()` returns 999 when `pulseIn()` times out. What would happen if it returned 0 instead?
- [ ] Nothing, because the door ignores 0
  The check is `distanceCm < 60`, and 0 is less than 60.
- [x] Every missed echo would look like a person right at the sensor, so the door would open for no one
  A timeout means no echo came back. Treating it as "very far" keeps the door shut.
- [ ] The Arduino would freeze for a second
  The 30 ms timeout prevents long waits whatever value is returned.
:::

:::takeaways
- Write the spec as sentences, draw the state diagram, then code one `case` per state that checks only its own outgoing arrows.
- Several `millis()` timers can share one `loop()` because none of them waits.
- Give `pulseIn()` a timeout, and map "no echo" to a safe value.
- A proportional step (`error * KP`) gives smooth motion that slows as it arrives.
- Put safety checks first, and test every transition deliberately.
:::

## Ideas to extend it

- Add a "hold open" pushbutton: while held, the door stays OPEN no matter what the timer says.
- Add a FAULT state: if the sensor returns 999 for 2 seconds straight, open the door and flash the light fast until it recovers.
- Swap the servo for the motor test bench from the last module: the door becomes a robot that backs away when you approach.
