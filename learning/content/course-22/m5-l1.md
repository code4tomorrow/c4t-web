Your new classifier scores 0.87 on a 150-sample test set. The published baseline scored 0.83 on a test set of the same size. Before you write "our method improves accuracy by 4 points," run the cell below. It imagines a single model whose true accuracy on the whole population is exactly 0.85, then scores it on 10,000 different 150-sample test sets. Guess first: how often does that one model land at 0.87 or above?

```python run alt="Histogram of 10,000 test-set accuracies for one model with true accuracy 0.85. The bars span roughly 0.76 to 0.93, and dashed lines at 0.83 and 0.87 both sit well inside the bulk." caption="One model, 10,000 possible test sets"
import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(7)
true_acc = 0.85      # the model's accuracy on everything it could ever see
n_test = 150         # rows in one test set

observed = rng.binomial(n_test, true_acc, size=10_000) / n_test
lo, hi = np.percentile(observed, [2.5, 97.5])
print(f"middle 95% of test-set accuracies: {lo:.3f} to {hi:.3f}")
print(f"test sets scoring 0.87 or higher: {(observed >= 0.87).mean():.1%}")
print(f"test sets scoring 0.83 or lower:  {(observed <= 0.83).mean():.1%}")

plt.figure(figsize=(7, 2.8))
plt.hist(observed, bins=np.arange(0.74, 0.96, 1 / 150), color="#4c72b0", edgecolor="white")
plt.axvline(0.83, color="C3", ls="--", label="baseline reported 0.83")
plt.axvline(0.87, color="C2", ls="--", label="new model reported 0.87")
plt.xlabel("accuracy on a 150-row test set")
plt.ylabel("test sets")
plt.legend(loc="upper left")
```

A quarter of the test sets give 0.87 or more, and another quarter give 0.83 or less, from a model that never changed. A 4-point gap on 150 rows is not yet a finding; it might be the luck of which rows landed in each test set. This module is about measuring that luck.

## Where the wobble comes from: the standard error

Think of the test set as a poll. You can't test every possible patient, cell, or galaxy, so you test 150 and report the share the model got right. A different 150 would give a slightly different share.

Let's make that precise. If each test row is an independent draw and the model is right with probability *p*, the number correct is binomial, and the **standard error** (the standard deviation of the observed accuracy across possible test sets) is

SE = √( p(1 − p) / n ).

The cell checks the formula against simulation for several test-set sizes:

```python run
for n in [50, 150, 500, 2000]:
    sims = rng.binomial(n, true_acc, size=10_000) / n
    formula = np.sqrt(true_acc * (1 - true_acc) / n)
    print(f"n = {n:>4}: simulated spread {sims.std():.4f}, formula {formula:.4f}")
```

The formula matches simulation to the third decimal, so you can get an SE from a single test set by plugging in your observed accuracy for *p*. Notice it shrinks with √n, not n: going from 150 to 600 rows only halves it. A rough 95% range is the estimate ± 2 SE, so 0.85 on 150 rows means "somewhere around 0.79 to 0.91."

## SD, SE, and a confidence interval are three different error bars

Many papers draw a whisker on a bar and never say what it is. The three common choices answer different questions:

| Error bar | Formula | Answers |
| --- | --- | --- |
| SD (standard deviation) | spread of the individual measurements | How variable are the things I measured? |
| SE (standard error of the mean) | SD / √n | How much would my mean move if I repeated the study? |
| 95% CI | mean ± t × SE | What range of true means is consistent with my data? |

Here are seedling root-growth rates (mm per day) measured on 5, 20, and 80 plants from the same simulated population:

```python run
from scipy import stats

rng = np.random.default_rng(3)
for n in [5, 20, 80]:
    growth = rng.normal(4.2, 1.1, size=n)
    mean = growth.mean()
    sd = growth.std(ddof=1)
    se = sd / np.sqrt(n)
    t_crit = stats.t.ppf(0.975, df=n - 1)
    print(f"n = {n:>2}: mean {mean:.2f}  SD {sd:.2f}  SE {se:.2f}  "
          f"95% CI {mean - t_crit * se:.2f} to {mean + t_crit * se:.2f}")
```

The SD doesn't shrink as you measure more plants; it just homes in on the true 1.1 (five plants give a noisy 1.84), because it describes the plants. The SE and CI keep shrinking, because they describe your knowledge of the mean. `ddof=1` divides by n − 1, the usual sample SD, and `stats.t.ppf(0.975, df=n-1)` is the 95% multiplier for a small sample: 2.78 for n = 5, near 1.96 for large n.

:::warning
**Unlabeled whiskers.** The same data drawn with SE bars looks about four times more precise than with SD bars when n = 16. If a figure or table says "0.91 ± 0.02" without naming the quantity, you can't interpret it. Write it out every time: "mean ± SD across 5 folds" or "95% bootstrap CI."
:::

## The bootstrap: let your sample stand in for the population

Those formulas only exist for simple statistics. What's the standard error of a median, an AUC, or the gap between two models? The **bootstrap** handles all of them with one idea: you can't draw new samples from the population, so draw them from your sample. Pick n rows *with replacement* (some appear twice, some not at all), recompute the statistic, and repeat thousands of times. The spread of those values estimates the spread across real repeated studies.

Step through three resamples of a five-value sample and watch `resample` fill up with repeats:

:::trace Watch the bootstrap draw with replacement
```python
import random
random.seed(4)
sample = [12, 15, 9, 20, 14]
boot_means = []
for b in range(3):
    resample = []
    for i in range(len(sample)):
        resample.append(random.choice(sample))
    boot_means.append(sum(resample) / len(resample))
print(boot_means)
```
:::

Now a realistic case: hours until 25 seeds germinate. Germination times are skewed (most seeds sprout together, a few lag far behind), so the median is the natural summary and no simple SE formula applies.

```python run alt="Histogram of 5,000 bootstrap medians of germination time. The distribution is lumpy and skewed to the right, with dashed lines marking the 2.5th and 97.5th percentiles around 25 and 40 hours." caption="5,000 bootstrap medians; the dashed lines are the 95% percentile interval"
rng = np.random.default_rng(11)
hours = np.round(rng.lognormal(mean=3.4, sigma=0.5, size=25), 1)
print("sample median:", np.median(hours))

boot_medians = np.empty(5000)
for b in range(5000):
    resample = rng.choice(hours, size=hours.size, replace=True)
    boot_medians[b] = np.median(resample)

lo, hi = np.percentile(boot_medians, [2.5, 97.5])
print(f"bootstrap SE {boot_medians.std(ddof=1):.2f}, 95% percentile CI {lo:.1f} to {hi:.1f}")

plt.figure(figsize=(7, 2.8))
plt.hist(boot_medians, bins=40, color="#4c72b0", edgecolor="white")
for edge in (lo, hi):
    plt.axvline(edge, color="C3", ls="--")
plt.xlabel("median germination time in a bootstrap resample (hours)")
plt.ylabel("resamples")
```

The **percentile interval** is just the middle 95% of the bootstrap values. It's lopsided (about 4 hours below the median, 11 above), which is the right answer for skewed data and something a symmetric ± formula can't give you. The lumpy histogram is normal for a median: it can only take values that are in the data or halfway between two of them.

SciPy packages the same procedure. Note that `data` is a *tuple* of samples, even when there's only one:

```python run
from scipy.stats import bootstrap

pct = bootstrap((hours,), np.median, n_resamples=5000, method="percentile",
                rng=np.random.default_rng(0))
bca = bootstrap((hours,), np.median, n_resamples=5000, method="BCa",
                rng=np.random.default_rng(0))
print("percentile:", np.round(pct.confidence_interval, 1), "  SE", round(pct.standard_error, 2))
print("BCa:       ", np.round(bca.confidence_interval, 1))
```

The default method, **BCa** (bias-corrected and accelerated), shifts the percentile cut-offs to correct for bias and skew in the bootstrap distribution. Here it agrees with the percentile interval; with skewed means or small samples it often won't, and BCa is usually the better-calibrated one. The `rng=` keyword is for SciPy 1.15 and newer; older versions call it `random_state=`.

## Confidence interval for the line, prediction interval for the next point

Regression adds a second question that people constantly mix up. A chemist builds a calibration curve: absorbance of 6 standard concentrations, each prepared three times. Two questions can be asked at 5 mg/L:

- Where is the **average** absorbance at 5 mg/L? That's a **confidence interval** for the fitted line.
- Where will **the next single sample** at 5 mg/L read? That's a **prediction interval**, and it must also include the scatter of individual measurements around the line.

statsmodels computes both from one fitted OLS model:

```python run alt="Scatter of 18 calibration points rising linearly from 0 to 10 mg/L, with a fitted line, a narrow dark band for the 95% confidence interval of the line, and a much wider light band for the 95% prediction interval." caption="The narrow band is about the line; the wide band is about the next measurement"
import statsmodels.api as sm

rng = np.random.default_rng(5)
conc = np.repeat([0.0, 2, 4, 6, 8, 10], 3)          # mg/L, triplicates
absorb = 0.02 + 0.095 * conc + rng.normal(0, 0.03, size=conc.size)
fit = sm.OLS(absorb, sm.add_constant(conc)).fit()

grid = np.linspace(0, 10, 60)
bands = fit.get_prediction(sm.add_constant(grid)).summary_frame(alpha=0.05)

plt.figure(figsize=(7, 3.4))
plt.fill_between(grid, bands.obs_ci_lower, bands.obs_ci_upper, color="C0", alpha=0.15,
                 label="95% prediction interval")
plt.fill_between(grid, bands.mean_ci_lower, bands.mean_ci_upper, color="C0", alpha=0.45,
                 label="95% confidence interval")
plt.plot(grid, bands["mean"], color="C0")
plt.scatter(conc, absorb, color="k", s=14, zorder=3)
plt.xlabel("concentration (mg/L)")
plt.ylabel("absorbance")
plt.legend(loc="upper left")
```

Now test what each band promises. The cell draws 10,000 new single readings at 5 mg/L from the true process and counts how many land inside each band:

```python run
at5 = fit.get_prediction(np.array([[1.0, 5.0]])).summary_frame(alpha=0.05).iloc[0]
new = 0.02 + 0.095 * 5 + rng.normal(0, 0.03, size=10_000)
print(f"95% CI for the mean: {at5.mean_ci_lower:.3f} to {at5.mean_ci_upper:.3f}")
print(f"95% PI for one read: {at5.obs_ci_lower:.3f} to {at5.obs_ci_upper:.3f}")
print(f"new readings inside the CI: {((new > at5.mean_ci_lower) & (new < at5.mean_ci_upper)).mean():.1%}")
print(f"new readings inside the PI: {((new > at5.obs_ci_lower) & (new < at5.obs_ci_upper)).mean():.1%}")
```

The confidence interval catches only about 40% of new readings because it was never meant to: it's a statement about the mean. The prediction interval catches almost all of them (95% is the average over many repeated calibrations, so one calibration can land a little above or below). If your model will be used on *individual* cases, the prediction interval is the honest error bar.

:::warning
**Bootstrapping rows that aren't independent.** If 600 rows come from 30 patients, resampling rows pretends you have 600 independent people, and the interval comes out far too narrow. Resample patients, keeping each patient's rows together. You'll build this cluster bootstrap in the practice lesson.
:::

:::quiz
Q: A paper reports "accuracy 0.91 ± 0.02" and nothing else. What can you conclude?
- [ ] The true accuracy is between 0.89 and 0.93 with 95% probability
  That reading assumes the ± is a 95% CI half-width, and the paper didn't say so.
- [x] Not much until you know whether ± is an SD, an SE, or a CI half-width
  Those three differ by large factors, so the same "± 0.02" can mean very different precision.
- [ ] The test set had about 200 rows
  You'd need to know what the 0.02 measures before you could back out a sample size.

Q: You grow a test set from 150 rows to 600 rows. What happens to the standard error of accuracy?
- [ ] It drops to a quarter
  SE scales with 1/√n, and √4 = 2.
- [x] It roughly halves
  Four times the rows divides the SE by √4 = 2.
- [ ] It stays the same, because the model didn't change
  The model is the same, but your estimate of its accuracy gets more precise with more rows.

Q: A lab will use your calibration curve to read single unknown samples. Which interval should go in the report next to each reading?
- [ ] The confidence interval of the fitted line
  That covers the average response at that concentration, not one new measurement.
- [x] The prediction interval
  A single new reading has the line's uncertainty plus the measurement scatter, and only the prediction interval includes both.
:::

:::takeaways
- A test-set score is a sample statistic with SE ≈ √(p(1−p)/n); 150 rows give roughly ±6 points at 95%.
- SD describes the measurements, SE describes the mean, a CI gives a plausible range for the truth. Label which one you drew.
- The bootstrap resamples your data with replacement to get the uncertainty of any statistic; `scipy.stats.bootstrap` uses BCa by default. Resample the independent unit, not the row.
- Use a confidence interval for a mean or a fitted line, and a prediction interval for the next individual observation.
:::
