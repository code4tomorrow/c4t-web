:::objectives
- Score a dummy model, a one-feature rule, a linear model, and two ensembles on the same held-out-batch split.
- Separate variation from held-out batches and variation from seeds.
- Write a run record with the configuration, data hash, library versions, model parameters, and results.
- Rebuild the experiment from its configuration alone and prove the record matches.
- Pin the environment and run an automatic reproducibility checklist.
:::

A protein engineering lab measures the melting temperature (Tm) of enzyme variants: the temperature at which half the protein unfolds. Higher Tm means a more heat-stable enzyme. Each assay batch runs 60 variants, and the lab wants a model that predicts Tm for the *next* batch from five sequence descriptors, so they can skip variants unlikely to be stable.

Here's the finished result, a ladder of models scored on assay batches they never saw, plus a record that lets anyone regenerate every number:

```text
rung                          MAE (deg C)   sd across batches
1 mean (dummy)                3.50          0.40
2 hydrophobicity only         2.33          0.26
3 ridge (all descriptors)     1.88          0.34
4 random forest               2.10          0.38
4 gradient boosting           1.94          0.38
run record: results/runs/<run id>.json   rerun matches: True   checklist: 7/7 PASS
```

## Step 1: Fix the configuration, then make and fingerprint the data

Everything that could change a result goes in one dictionary, written before any modeling. The data here is simulated from the config's seed so the lesson runs anywhere; in a real project, `make_data` would read the lab's file from `data/raw` instead.

```python run title="config.py"
import hashlib
import json
from importlib.metadata import version
from pathlib import Path

import numpy as np
import pandas as pd

CONFIG = {
    "seed": 7,
    "n_variants": 240,
    "n_batches": 4,
    "target": "tm_c",
    "features": ["hydrophobicity", "proline_frac", "disulfides", "net_charge", "length"],
    "one_feature_rule": "hydrophobicity",
    "split": "leave one assay batch out",
    "model_seeds": [0, 1, 2],
}
PROJECT = Path("enzyme-tm-study")
for folder in ["data/raw", "results/runs"]:
    (PROJECT / folder).mkdir(parents=True, exist_ok=True)

def make_data(config):
    rng = np.random.default_rng(config["seed"])
    n, k = config["n_variants"], config["n_batches"]
    data = pd.DataFrame({
        "variant": [f"V{i:03d}" for i in range(1, n + 1)],
        "batch": np.repeat([f"B{b + 1}" for b in range(k)], n // k),
        "hydrophobicity": rng.normal(0, 1, n).round(3),
        "proline_frac": rng.uniform(0.02, 0.12, n).round(4),
        "disulfides": rng.poisson(1.5, n),
        "net_charge": rng.normal(0, 5, n).round().astype(int),
        "length": rng.normal(300, 40, n).round().astype(int),
    })
    batch_offset = dict(zip(data["batch"].unique(), rng.normal(0, 0.8, k)))   # assay calibration drift
    h = data["hydrophobicity"]
    data["tm_c"] = (55 + 3.0 * h + 0.5 * np.maximum(h, 0) ** 2 + 40 * data["proline_frac"]
                    + 1.5 * data["disulfides"] - 0.25 * data["net_charge"].abs() + 0.01 * (data["length"] - 300)
                    + data["batch"].map(batch_offset) + rng.normal(0, 1.5, n)).round(2)
    return data

def sha256_of(path):
    return hashlib.sha256(Path(path).read_bytes()).hexdigest()

enzymes = make_data(CONFIG)
data_file = PROJECT / "data" / "raw" / "enzymes.csv"
enzymes.to_csv(data_file, index=False)
data_hash = sha256_of(data_file)
print(enzymes.head(3).to_string(index=False))
print(f"{len(enzymes)} variants in {enzymes['batch'].nunique()} batches, sha256 {data_hash[:12]}...")
```

The split is part of the config because it's part of the claim. "Leave one assay batch out" means every score answers the lab's real question: how well does the model do on a batch it wasn't trained on?

## Step 2: Climb the first three rungs

One scoring function serves every rung, which guarantees they all see the same folds and the same metric. Mean absolute error (MAE) is in degrees Celsius, a unit the lab can reason about.

```python run title="rungs_1_to_3.py"
from sklearn.dummy import DummyRegressor
from sklearn.linear_model import LinearRegression, RidgeCV
from sklearn.model_selection import LeaveOneGroupOut, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

def fold_maes(model, columns, data):
    return -cross_val_score(model, data[columns], data[CONFIG["target"]], groups=data["batch"],
                            cv=LeaveOneGroupOut(), scoring="neg_mean_absolute_error")

simple_rungs = {
    "1 mean (dummy)": (DummyRegressor(), CONFIG["features"]),
    "2 hydrophobicity only": (LinearRegression(), [CONFIG["one_feature_rule"]]),
    "3 ridge (all descriptors)": (make_pipeline(StandardScaler(), RidgeCV(alphas=np.logspace(-3, 3, 13))),
                                  CONFIG["features"]),
}
results = {}
for name, (model, columns) in simple_rungs.items():
    maes = fold_maes(model, columns, enzymes)
    results[name] = {"mae": round(maes.mean(), 4), "sd_batches": round(maes.std(), 4), "sd_seeds": 0.0}
    print(f"{name:<28} MAE {maes.mean():.2f}   per batch {np.round(maes, 2)}")
```

Guessing the training mean misses by 3.5 °C on average. Hydrophobicity alone, a predictor a protein chemist would reach for first, cuts that by a third. Ridge on all five descriptors gets to 1.88. Look at the per-batch numbers too: the same model's error moves by most of a degree depending on which batch is held out, because each batch carries its own calibration offset.

## Step 3: Add the complex rung, with seeds

Random forests and gradient boosting use randomness (bootstrap samples, row subsampling), so each gets run with three seeds. Leave-one-batch-out has no shuffling, so the folds stay fixed and only the models' own randomness changes.

```python run title="rung_4.py"
from sklearn.ensemble import GradientBoostingRegressor, RandomForestRegressor

def complex_rungs(seed):
    return {
        "4 random forest": RandomForestRegressor(n_estimators=50, min_samples_leaf=3, random_state=seed),
        "4 gradient boosting": GradientBoostingRegressor(n_estimators=150, learning_rate=0.05, max_depth=2,
                                                         subsample=0.8, random_state=seed),
    }

for name in complex_rungs(0):
    per_seed = np.array([fold_maes(complex_rungs(s)[name], CONFIG["features"], enzymes)
                         for s in CONFIG["model_seeds"]])            # rows: seeds, columns: batches
    results[name] = {"mae": round(per_seed.mean(), 4),
                     "sd_batches": round(per_seed.mean(axis=0).std(), 4),
                     "sd_seeds": round(per_seed.mean(axis=1).std(), 4)}
    print(f"{name:<22} MAE {per_seed.mean():.2f}   sd across batches {results[name]['sd_batches']:.2f}"
          f"   sd across seeds {results[name]['sd_seeds']:.3f}")
```

Neither ensemble beats ridge. Gradient boosting comes within about 0.06 °C, a gap far smaller than the 0.38 °C spread across batches, so the honest summary is "ridge and boosting are indistinguishable here, and ridge is simpler". The seed spread is tiny next to the batch spread. That's worth knowing: in this problem, *which batch you test on* matters far more than *which seed you use*, so more batches would tighten the comparison more than more seeds would.

## Step 5: Write the run record

The record holds everything needed to recognize and regenerate these numbers. `get_params()` captures each model's full configuration, defaults included, and keeping only the plain values makes it JSON-friendly.

```python run title="record.py"
PACKAGES = ["numpy", "pandas", "scikit-learn"]

def plain_params(model):
    return {k: v for k, v in sorted(model.get_params().items()) if isinstance(v, (int, float, str, bool, type(None)))}

def build_record(config, data_hash, results):
    models = {name: plain_params(model) for name, (model, _) in simple_rungs.items()}
    models.update({name: plain_params(model) for name, model in complex_rungs(0).items()})
    body = {"config": config, "data_sha256": data_hash,
            "environment": {name: version(name) for name in PACKAGES},
            "models": models, "results": results}
    run_id = hashlib.sha256(json.dumps(body, sort_keys=True).encode()).hexdigest()[:10]
    return {"run_id": run_id, **body}

record = build_record(CONFIG, data_hash, results)
record_file = PROJECT / "results" / "runs" / f"{record['run_id']}.json"
record_file.write_text(json.dumps(record, indent=2, sort_keys=True))
print("wrote", record_file)
print(json.dumps(record["models"]["4 gradient boosting"], indent=None)[:200], "...")
```

The run ID is a hash of the record's contents, so two runs with any difference in config, data, versions, or results get different IDs. A run ID like that also makes a good name for figures produced from the run.

## Step 6: The whole experiment in one call

This is the finished program. `run_experiment` starts from nothing but the configuration: it regenerates the data, rewrites and fingerprints the file, scores every rung, and builds the record. If it matches the saved record exactly, the experiment is reproducible on this machine.

```python run title="run_experiment.py"
def run_experiment(config):
    data = make_data(config)
    data.to_csv(data_file, index=False)
    scores = {}
    for name, (model, columns) in simple_rungs.items():
        maes = fold_maes(model, columns, data)
        scores[name] = {"mae": round(maes.mean(), 4), "sd_batches": round(maes.std(), 4), "sd_seeds": 0.0}
    for name in complex_rungs(0):
        per_seed = np.array([fold_maes(complex_rungs(s)[name], config["features"], data)
                             for s in config["model_seeds"]])
        scores[name] = {"mae": round(per_seed.mean(), 4), "sd_batches": round(per_seed.mean(axis=0).std(), 4),
                        "sd_seeds": round(per_seed.mean(axis=1).std(), 4)}
    return build_record(config, sha256_of(data_file), scores)

saved = json.loads(record_file.read_text())
rerun = run_experiment(CONFIG)
print("rerun matches saved record:", rerun == saved)
print("run id:", rerun["run_id"])
```

If the comparison ever prints `False`, compare the two dictionaries key by key; the first key that differs (data hash, environment, a model parameter, or a score) tells you where to look.

## Step 7: Pin the environment and run the checklist

The last step writes `requirements.txt` and runs a checklist against the project folder. Each check is a question a reviewer would ask, written as code so it can't be skipped.

```python run title="checklist.py"
(PROJECT / "requirements.txt").write_text("".join(f"{p}=={version(p)}\n" for p in PACKAGES))

def checklist(record_path):
    rec = json.loads(Path(record_path).read_text())
    lines = (PROJECT / "requirements.txt").read_text().split()
    rungs = " ".join(rec["results"])
    return {
        "seed recorded": "seed" in rec["config"],
        "data file matches its hash": sha256_of(data_file) == rec["data_sha256"],
        "every requirement pinned with ==": all("==" in line for line in lines),
        "environment matches record": all(version(p) == v for p, v in rec["environment"].items()),
        "dummy, one-feature, and linear rungs present": all(r in rungs for r in ["dummy", "only", "ridge"]),
        "split stated in config": bool(rec["config"].get("split")),
        "spread reported for every rung": all("sd_batches" in r for r in rec["results"].values()),
    }

checks = checklist(record_file)
for item, ok in checks.items():
    print(f"{'PASS' if ok else 'FAIL'}  {item}")
print(f"{sum(checks.values())}/{len(checks)} checks passed")
```

:::quiz
Q: Why does every rung use the same `fold_maes` function?
- [x] So every model sees exactly the same held-out batches and metric, making the comparison fair
  Different splits or metrics for different rungs is one of the commonest ways a baseline gets shortchanged.
- [ ] Because scikit-learn requires one scoring function per notebook
  There's no such rule; it's a design choice for fairness.
- [ ] To make the code run faster
  Speed is the same. The benefit is that the comparison can't drift.

Q: Gradient boosting scored 1.94 °C and ridge 1.88 °C, with about 0.38 °C spread across batches. What should the report say?
- [ ] Ridge is significantly better than gradient boosting
  A 0.06 °C gap against 0.38 °C of batch-to-batch spread can't support that.
- [ ] Gradient boosting is better because it's more flexible
  It scored slightly worse, and flexibility isn't evidence.
- [x] The two are indistinguishable on four batches, so the simpler ridge model is the reasonable choice
  When a complex model doesn't clearly beat a linear one, the linear one wins on simplicity and interpretability.

Q: Why is the run ID a hash of the record's contents rather than a counter like `run-002`?
- [ ] Hashes are shorter
  `run-002` is shorter. The point is what the ID guarantees.
- [x] Any change to config, data, environment, or results changes the ID, so two different runs can never share a name
  A counter can be reused or reset; a content hash identifies exactly what was run.
- [ ] Counters can't be stored in JSON
  They can; they just don't tie the name to the contents.
:::

:::takeaways
- Put everything that can change a result, including the split and seeds, in one config written before modeling.
- Score every rung with one function on the same held-out groups, and report the spread across groups and across seeds separately.
- A complex model earns its place only with a gap larger than the spread; otherwise report the simpler model.
- Save a run record with config, data hash, versions, full model parameters, and results, and name it by a hash of its contents.
- Prove reproducibility by rebuilding from the config alone, and turn your standards into a checklist that runs as code.
:::
