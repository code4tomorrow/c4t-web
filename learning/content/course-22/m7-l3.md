## Warm-up: what kind of check is it?

Label each with reproduction, robustness check, replication, or generalisation (in the Turing Way sense).

1. You rerun a paper's notebook on its released data and get the same table.
2. You use the paper's data but switch from 5-fold CV to leave-one-site-out and from R to Python.
3. You apply the paper's exact pipeline to a dataset collected two years later at a different hospital.
4. A different team, with different data *and* a different method, reaches the same conclusion.

:::solution
1. Reproduction: same data, same analysis.
2. Robustness check: same data, different (reasonable) analysis choices.
3. Replication: different data, same analysis.
4. Generalisation: different data and different analysis, same answer. This is the strongest of the four and the rarest.
:::

### Exercise 1: Is the gap bigger than chance, at two sizes?

A paper reports 87.0% accuracy on 230 held-out patients. Your reimplementation scores 83.5% on a fresh 230-patient split from the same source. Is the gap consistent with sampling error? Then answer again assuming both test sets had 2,300 patients and the same accuracies.

At n = 230 the gap's interval should cross zero; at n = 2,300 it shouldn't.

:::hint
Convert each accuracy to a count of correct patients, then use `proportion_confint(..., method="wilson")` for each and `confint_proportions_2indep(mine, n, theirs, n, method="newcomb")` for the gap.
:::

:::solution
```python run
import numpy as np
import pandas as pd
from statsmodels.stats.proportion import proportion_confint, confint_proportions_2indep

for n in [230, 2300]:
    paper, mine = round(0.870 * n), round(0.835 * n)
    gap_low, gap_high = confint_proportions_2indep(mine, n, paper, n, method="newcomb")
    print(f"n = {n}: paper CI {np.round(proportion_confint(paper, n, method='wilson'), 3)}, "
          f"mine CI {np.round(proportion_confint(mine, n, method='wilson'), 3)}, "
          f"gap CI [{gap_low:+.3f}, {gap_high:+.3f}]")
```

The same 3.5-point gap is "consistent" with 230 patients and "a real difference" with 2,300. Small test sets make almost any reproduction look successful, which is why the report should give the interval's width, not just the verdict.
:::

### Exercise 2: Percentages that can't exist

A test-set accuracy computed on *n* cases must equal *k*/*n* for some whole number *k*. A paper reports these results. Which are impossible at one decimal place?

| Reported | Test cases |
| --- | --- |
| 93.8% | 97 |
| 94.0% | 97 |
| 71.4% | 35 |
| 88.2% | 51 |
| 65.0% | 43 |

This is the idea behind the [GRIM test](https://en.wikipedia.org/wiki/GRIM_test) (Brown and Heathers, 2016), which found impossible means in a large share of the psychology papers it could check.

:::hint
For each row, loop over *k* = 0 … *n*, round 100*k*/*n* to one decimal, and see whether any match the reported value.
:::

:::solution
```python run
def matching_counts(reported_pct, n, decimals=1):
    return [k for k in range(n + 1) if round(100 * k / n, decimals) == reported_pct]

for reported, n in [(93.8, 97), (94.0, 97), (71.4, 35), (88.2, 51), (65.0, 43)]:
    counts = matching_counts(reported, n)
    print(f"{reported:5.1f}% of {n:3d}: {'possible, k = ' + str(counts) if counts else 'IMPOSSIBLE'}")
```

94.0% of 97 falls between 91/97 (93.8%) and 92/97 (94.8%), and 65.0% of 43 falls between 28/43 (65.1%) and 27/43 (62.8%). An impossible value isn't proof of anything bad (it may be a typo, a different *n* after exclusions, or a different metric), but it's a concrete question to ask the authors and a line in your discrepancy log.
:::

### Exercise 3: Rewrite a vague methods paragraph

Rewrite this so a stranger could rerun it. Use the lake-bloom study from Module 5's build as the facts.

```text
We compared several machine learning models for predicting algal blooms using cross-validation.
Data were preprocessed appropriately. The random forest performed best (82% accuracy).
```

:::hint
Name: the data (how many lakes, how sampled, outcome definition), every preprocessing step and where it was fit, the models and their settings, the splitter, repeats and seeds, the metric and what ± means, the test set, and the comparison's interval.
:::

:::solution
```text
Data. 480 lakes, one summer water sample each (simulated survey; generator and seed in the
repository). Outcome: bloom = cyanobacteria above the alert level (34% of lakes).
Split. 120 lakes (25%, stratified, random_state=0) were locked as a test set before any modeling.
Models. Majority-class baseline; logistic regression on log-transformed, standardized features;
random forest (scikit-learn 1.8, 50 trees, min_samples_leaf=3, random_state=0). All
preprocessing ran inside scikit-learn pipelines, refit on each training fold.
Evaluation. 5-fold stratified CV repeated 5 times (RepeatedStratifiedKFold, random_state=1) on
the 360 development lakes, identical folds for all models. We report mean accuracy and compare
models by paired fold differences with the Nadeau-Bengio corrected 95% t-interval. The locked
test set was scored once; intervals are 95% BCa bootstrap (5,000 resamples), paired for differences.
Result. Random forest 0.822 vs logistic regression 0.795 in CV (difference +2.7 points, 95% CI
-1.0 to +6.4); test set 0.825 vs 0.792 (paired 95% CI -3.3 to +10.0).
```

"82% accuracy" became a number with a design, an interval, and a comparison. "Performed best" became a difference whose interval includes zero, which is the actual finding.
:::

### Exercise 4: Redraw a misleading figure

This figure reports a new pipeline's 5-fold CV results. Redraw it so a reader can judge the comparison.

```python run alt="Bar chart of mean accuracy for three pipelines on a y-axis from 0.80 to 0.86. The third bar looks roughly twice as tall as the first. There are no error bars." caption="The original figure"
import matplotlib.pyplot as plt

folds = {"baseline": [0.80, 0.84, 0.79, 0.86, 0.82],
         "pipeline A": [0.81, 0.85, 0.80, 0.86, 0.84],
         "pipeline B": [0.83, 0.87, 0.80, 0.88, 0.85]}
means = {name: np.mean(v) for name, v in folds.items()}
plt.figure(figsize=(5, 3))
plt.bar(list(means), list(means.values()), color=["grey", "C0", "C3"])
plt.ylim(0.80, 0.86)
plt.ylabel("accuracy")
```

:::hint
Plot every fold as a point (a fold appears in all three columns, so you can connect them with faint lines), add the mean ± SD, and label what the bars mean. Use an axis range that shows the fold spread.
:::

:::solution
```python run alt="Dot plot with the five fold scores of each pipeline as grey points joined by faint lines across pipelines, plus a black mean with SD error bars. The folds range from about 0.79 to 0.88 and overlap heavily, and every line rises only slightly from baseline to pipeline B." caption="Same data: every fold, paired across pipelines, with mean ± SD"
names = list(folds)
scores = np.array([folds[n] for n in names])          # shape: (pipelines, folds)
plt.figure(figsize=(5.5, 3.2))
for fold in range(scores.shape[1]):
    plt.plot(range(3), scores[:, fold], color="grey", alpha=0.4, marker="o", ms=4)
plt.errorbar(range(3), scores.mean(axis=1), yerr=scores.std(axis=1, ddof=1),
             fmt="s", color="k", capsize=5, label="mean ± SD over 5 folds")
plt.xticks(range(3), names)
plt.ylim(0.75, 0.90)
plt.ylabel("fold accuracy (5-fold CV)")
plt.legend(loc="lower right", fontsize=8)
```

The redraw shows what the bars hid: fold-to-fold spread (about 0.03) is larger than the gap between pipelines, but within each fold pipeline B is slightly ahead. That paired pattern is the real argument for B, and it calls for the paired, corrected interval from Module 5, not a taller bar.
:::

### Exercise 5: Audit a paper with REFORMS

Read this description and list the problems, grouped by REFORMS section (study design; computational reproducibility; data quality; data preprocessing; modeling; data leakage; metrics and uncertainty; generalizability and limitations).

```text
We trained a gradient boosting model to predict 30-day hospital readmission from electronic
health records. Admissions from 2015-2022 at our hospital (n = 41,200) were split randomly 80/20.
Missing values were imputed with the median and the 50 most predictive features were selected.
Hyperparameters were tuned to maximize test-set AUC. Our model achieved AUC 0.91, outperforming
prior work (0.78). Code available on request.
```

:::hint
Ask, for each step: was it fit on training data only, and would the model have this information at prediction time? Then ask what the numbers are being compared to.
:::

:::solution
| REFORMS section | Problem | Fix |
| --- | --- | --- |
| Study design | The claim's population and use are undefined, and "outperforming prior work" compares numbers from different datasets. | State who the model is for; rerun the prior method on the same data. |
| Computational reproducibility | "Code available on request," no versions or seeds. | Public repository, pinned environment, seeds. |
| Data quality | No inclusion criteria; "readmission" undefined (this hospital only?). | Describe the cohort, the label, and its source. |
| Data preprocessing | Unclear whether imputation and feature selection used all data. | Fit both inside the training pipeline. |
| Modeling | Hyperparameters tuned on the test set. | Tune with CV on training data; touch the test set once. |
| Data leakage | Random split of *admissions* puts the same patients in both sets; a random split across 2015–2022 lets the model train on the future. | Group by patient; train on earlier years, test on later ones. |
| Metrics and uncertainty | One AUC from one split, no interval, no calibration. | Bootstrap CI, calibration plot, repeated or temporal validation. |
| Generalizability and limitations | One hospital, no external validation, no limitations stated. | Test at another site, or state that it's untested. |

Tuning on the test set and splitting admissions instead of patients could each inflate the AUC by a lot. The 0.91 is uninterpretable until both are fixed.
:::

### Exercise 6: Is a reproduced ranking robust?

In the build, QDA (1 LOO error) and LDA (2 errors) both reproduced exactly on the wine data. Check whether "QDA beats LDA" survives a robustness check: 10-fold stratified CV repeated 10 times, paired fold differences, and the corrected interval from Module 5.

You should find a difference under one point with an interval that includes zero.

:::hint
Use one `RepeatedStratifiedKFold` object for both models. For 10-fold CV, n_val/n_train = 1/9.
:::

:::solution
```python run
from scipy import stats
from sklearn.datasets import load_wine
from sklearn.discriminant_analysis import LinearDiscriminantAnalysis, QuadraticDiscriminantAnalysis
from sklearn.model_selection import RepeatedStratifiedKFold, cross_val_score

X_wine, y_wine = load_wine(return_X_y=True)
cv = RepeatedStratifiedKFold(n_splits=10, n_repeats=10, random_state=0)
qda = cross_val_score(QuadraticDiscriminantAnalysis(), X_wine, y_wine, cv=cv)
lda = cross_val_score(LinearDiscriminantAnalysis(), X_wine, y_wine, cv=cv)

diff = qda - lda
k = len(diff)
se = diff.std(ddof=1) * np.sqrt(1 / k + 1 / 9)
half = stats.t.ppf(0.975, k - 1) * se
print(f"QDA {qda.mean():.4f}, LDA {lda.mean():.4f}")
print(f"QDA - LDA = {diff.mean():+.4f}, corrected 95% CI [{diff.mean() - half:+.4f}, {diff.mean() + half:+.4f}]")
print(f"QDA ahead in {(diff > 0).sum()} folds, tied in {(diff == 0).sum()}, behind in {(diff < 0).sum()}")
```

Most folds are ties, because both classifiers are nearly perfect on this data. The ranking from 1992 reproduces numerically, but it doesn't show that QDA is the better method here. A reproduction report can say both things.
:::

### Challenge: Diff two pipelines to find the leak

A paper says: "Missing values were imputed with feature means, and a standardized logistic regression was evaluated with stratified 5-fold CV. Accuracy: 0.84." Their released code is `paper_pipeline` below. Your reimplementation from the text is `my_pipeline`. Run both, find the line that explains the gap, and check whether the plain reading of "imputed with feature means" (one mean per column computed on all data, outside CV) is also leaky, and by how much.

```python run
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import StratifiedKFold
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(10)
X_raw = rng.normal(size=(300, 8))
labels = pd.Series((rng.random(300) < 1 / (1 + np.exp(-(1.0 * X_raw[:, 0] - 0.8 * X_raw[:, 1])))).astype(int))
X_raw[rng.random((300, 8)) < 0.4] = np.nan          # 40% of values missing at random
survey = pd.DataFrame(X_raw, columns=[f"m{i}" for i in range(8)])
cv5 = StratifiedKFold(5, shuffle=True, random_state=0)

def paper_pipeline(df, y):
    filled = df.copy()
    for cls in [0, 1]:
        filled[y == cls] = filled[y == cls].fillna(filled[y == cls].mean())
    return cross_val_score(make_pipeline(StandardScaler(), LogisticRegression()), filled, y, cv=cv5).mean()

def my_pipeline(df, y):
    model = make_pipeline(SimpleImputer(strategy="mean"), StandardScaler(), LogisticRegression())
    return cross_val_score(model, df, y, cv=cv5).mean()
```

:::hint
Look at what `paper_pipeline` groups by before computing the fill value. What would it need to know about a new patient to impute that patient's missing values the same way?
:::

:::solution
```python run
global_fill = survey.fillna(survey.mean())
plain = cross_val_score(make_pipeline(StandardScaler(), LogisticRegression()), global_fill, labels, cv=cv5).mean()
print(f"paper's code (fill by class mean):          {paper_pipeline(survey, labels):.3f}")
print(f"fill with overall means, outside CV:        {plain:.3f}")
print(f"reimplementation (fill inside each fold):   {my_pipeline(survey, labels):.3f}")
```

The paper's code fills each missing value with the mean *of that row's class*. A missing value therefore becomes a coded hint about the label, and with 40% of values missing there are many hints. At prediction time you don't know the class, so this can't be done, and the 0.84 is mostly leakage. Filling with overall means outside CV is a much smaller problem here, within a point or two of the in-fold version, but it's still the wrong order and costs nothing to fix. The report should say: "not reproduced; the released code imputes using class labels; corrected accuracy 0.65," which mirrors what happened in the civil-war reproductions.
:::
