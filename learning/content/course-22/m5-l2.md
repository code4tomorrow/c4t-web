:::objectives
- Score several models on identical repeated cross-validation folds and summarize the spread, not just the mean.
- Compute a paired difference between two models and explain why the naive interval for it is too narrow.
- Bootstrap a locked test set for each model's accuracy and for the paired difference.
- Draw a comparison figure with labeled intervals and write a result sentence a reviewer can check.
:::

A state environmental agency samples 480 lakes once each summer and wants an early warning for harmful algal blooms. Your colleague trained a random forest and says it "beats logistic regression." By the end of this build you'll have the figure and sentence that either support that claim or say how far the data can actually go. Here's the plan:

```mermaid caption="Two independent looks at the same comparison, both reported with intervals"
flowchart LR
    A[480 lake samples] --> B[360 development]
    A --> T[("120 locked test")]
    B --> C["5x5 repeated CV, same folds for every model"]
    C --> D["Paired fold differences, corrected CI"]
    B --> F[Fit each model once on all 360]
    T --> G["Per-lake correct / wrong"]
    F --> G
    G --> H["Bootstrap CIs, paired difference"]
    D --> R[Figure and result sentence]
    H --> R
```

The data are simulated, so we know the truth: blooms switch on when water passes about 23 °C and the lake stratifies, and phosphorus matters more in warm lakes. A random forest can learn that threshold; a linear logistic model can only approximate it. The forest *should* be somewhat better. The question is whether 480 lakes are enough to show it.

## Step 1: Simulate the lake survey

Each row is one lake, sampled once, so rows are independent. (Module 6 deals with data where they aren't.)

```python run title="lakes.py"
import numpy as np
import pandas as pd

def make_lakes(n, seed):
    """One summer water sample per lake; bloom = 1 if cyanobacteria pass the alert level."""
    rng = np.random.default_rng(seed)
    df = pd.DataFrame({
        "temp_c": rng.normal(22, 4, n),
        "phosphorus_ugL": rng.lognormal(np.log(40), 0.6, n),
        "nitrate_mgL": rng.lognormal(np.log(0.8), 0.5, n),
        "turbidity_ntu": rng.lognormal(np.log(6), 0.5, n),
        "ph": rng.normal(8.0, 0.4, n),
        "wind_ms": rng.gamma(2.0, 2.0, n),
    })
    warm = (df.temp_c > 23).astype(float)            # the lake stratifies above ~23 °C
    p = np.log(df.phosphorus_ugL / 40)
    logit = -2.4 + 3.4 * warm + 1.0 * p + 1.6 * warm * p - 0.4 * (df.wind_ms - 4)
    df["bloom"] = (rng.random(n) < 1 / (1 + np.exp(-logit))).astype(int)
    return df

lakes = make_lakes(480, seed=3)
print(lakes.head().round(2).to_string())
print(f"\n{len(lakes)} lakes, {lakes.bloom.mean():.1%} with a bloom")
```

A third of lakes bloom, so a model that always says "no bloom" already scores about 0.66. That's the number every other model has to beat, and it belongs in the final figure.

## Step 2: Lock away a test set before anything else

```python run
from sklearn.model_selection import train_test_split

X = lakes.drop(columns="bloom")
y = lakes["bloom"]
X_dev, X_test, y_dev, y_test = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=0)
print(f"development: {len(X_dev)} lakes   locked test set: {len(X_test)} lakes")
```

All model choices happen on the 360 development lakes. The 120 test lakes are scored once, at the end, so they give an estimate nobody tuned toward.

## Step 3: Score every model on the same 25 folds

`RepeatedStratifiedKFold(n_splits=5, n_repeats=5)` runs 5-fold cross-validation five times, reshuffling between repeats, which gives 25 scores per model. Because `cv` is one object with a fixed `random_state`, every model sees exactly the same 25 train/validation splits. That pairing is what makes Step 4 possible.

```python run
from sklearn.dummy import DummyClassifier
from sklearn.ensemble import RandomForestClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import RepeatedStratifiedKFold, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import FunctionTransformer, StandardScaler

models = {
    "majority class": DummyClassifier(strategy="most_frequent"),
    "logistic regression": make_pipeline(FunctionTransformer(np.log), StandardScaler(),
                                         LogisticRegression()),
    "random forest": RandomForestClassifier(n_estimators=50, min_samples_leaf=3, random_state=0),
}
cv = RepeatedStratifiedKFold(n_splits=5, n_repeats=5, random_state=1)
cv_scores = {name: cross_val_score(model, X_dev, y_dev, cv=cv) for name, model in models.items()}

summary = pd.DataFrame({
    name: {"mean": s.mean(), "SD": s.std(ddof=1), "worst fold": s.min(), "best fold": s.max()}
    for name, s in cv_scores.items()}).T
print(summary.round(3).to_string())
```

The log transform tames the right-skewed chemistry columns and is harmless for the rest, since every column is positive. Now read the table across, not down. Logistic regression's folds range from 0.71 to 0.92: one lucky fold would have made it look better than the forest's average. The forest's mean is 2.7 points higher, but its worst fold and logistic regression's best fold overlap heavily. You can't decide from means.

## Step 4: Compare on paired folds, and correct the interval

Since both models were scored on the same folds, subtract fold by fold. Pairing cancels the "this fold was easy" effect that hits both models together.

```python run
from scipy import stats

diff = cv_scores["random forest"] - cv_scores["logistic regression"]
k = len(diff)
n_val = len(X_dev) / 5
n_train = len(X_dev) - n_val
t_crit = stats.t.ppf(0.975, df=k - 1)

naive_se = diff.std(ddof=1) / np.sqrt(k)
corrected_se = diff.std(ddof=1) * np.sqrt(1 / k + n_val / n_train)
naive_ci = diff.mean() + np.array([-1, 1]) * t_crit * naive_se
corrected_ci = diff.mean() + np.array([-1, 1]) * t_crit * corrected_se

print(f"random forest minus logistic regression, mean over {k} folds: {diff.mean():+.3f}")
print(f"naive 95% CI:     {naive_ci[0]:+.3f} to {naive_ci[1]:+.3f}")
print(f"corrected 95% CI: {corrected_ci[0]:+.3f} to {corrected_ci[1]:+.3f}")
print(f"forest won {np.sum(diff > 0)} folds, tied {np.sum(diff == 0)}, lost {np.sum(diff < 0)}")
```

The naive interval treats the 25 differences as 25 independent experiments and excludes zero. They aren't independent: any two folds share most of their training lakes, and across repeats the same lakes are validated again and again. The differences rise and fall together, so 25 of them carry far less information than 25 separate studies would.

**Nadeau and Bengio's correction** inflates the variance to account for that overlap: replace 1/k with 1/k + n_val/n_train. With 5-fold CV, n_val/n_train = 0.25, which here is more than six times larger than 1/k = 0.04, so the interval widens about 2.7×. Now it runs from −1.0 to +6.4 points. The forest winning 18 of 25 folds sounds decisive, but it's the same overlap problem in a friendlier costume.

:::note
The correction is a heuristic, not an exact result. In Nadeau and Bengio's simulations it kept false alarms near the promised 5%, while the naive t-test declared differences that weren't there far more often.
:::

## Step 5: Bootstrap the locked test set

Fit each model once on all 360 development lakes and record, for every test lake, whether it was classified correctly. A vector of 1s and 0s is all the bootstrap needs.

```python run
from scipy.stats import bootstrap

correct, test_ci = {}, {}
for name, model in models.items():
    model.fit(X_dev, y_dev)
    correct[name] = (model.predict(X_test) == y_test).to_numpy().astype(float)
    res = bootstrap((correct[name],), np.mean, n_resamples=5000, rng=np.random.default_rng(0))
    test_ci[name] = res.confidence_interval
    print(f"{name:20s} test accuracy {correct[name].mean():.3f}  "
          f"95% CI {res.confidence_interval.low:.3f} to {res.confidence_interval.high:.3f}")

row_diff = correct["random forest"] - correct["logistic regression"]
paired = bootstrap((row_diff,), np.mean, n_resamples=5000, rng=np.random.default_rng(0))
test_diff_ci = paired.confidence_interval
print(f"\nlakes where the two models disagree: {int(np.sum(row_diff != 0))} of {len(row_diff)}")
print(f"paired difference on the test set: {row_diff.mean():+.3f}, "
      f"95% CI {test_diff_ci.low:+.3f} to {test_diff_ci.high:+.3f}")
```

Look at the third-to-last line. The models agree on 102 of the 120 lakes, so the whole comparison rests on 18 lakes. That's why the paired difference has a wide interval even though each accuracy looks precise to within a few points. `row_diff` is +1 where only the forest was right, −1 where only logistic regression was, and 0 elsewhere; bootstrapping its mean resamples lakes, keeping each lake's two predictions together. That's a **paired bootstrap**, and it's narrower than comparing two separate intervals would be.

## Step 6: Draw the comparison figure

The left panel shows what each model achieves; the right panel shows the quantity the claim is actually about, the difference, with a reference line at zero.

```python run alt="Two-panel forest plot. Left: test accuracy with 95% bootstrap intervals for majority class near 0.67, logistic regression near 0.79, and random forest near 0.83, with hollow diamonds for the cross-validation means. Right: three intervals for random forest minus logistic regression; the naive CV interval sits entirely right of zero, while the corrected CV interval and the paired test-set interval both cross zero." caption="Each model clearly beats the baseline; the forest-vs-logistic gap is not yet resolved"
import matplotlib.pyplot as plt

fig, (left, right) = plt.subplots(1, 2, figsize=(10, 3.2), gridspec_kw={"width_ratios": [1.2, 1]})
names = list(models)
for i, name in enumerate(names):
    acc, ci = correct[name].mean(), test_ci[name]
    left.errorbar(acc, i, xerr=[[acc - ci.low], [ci.high - acc]], fmt="o", color="C0",
                  capsize=4, label="test set, 95% bootstrap CI" if i == 0 else None)
    left.plot(cv_scores[name].mean(), i, "D", mfc="none", color="C1",
              label="mean of 25 CV folds" if i == 0 else None)
left.set_yticks(range(len(names)), names)
left.set_xlabel("accuracy")
left.legend(loc="lower right", fontsize=8)

rows = [("CV, naive CI", diff.mean(), naive_ci),
        ("CV, corrected CI", diff.mean(), corrected_ci),
        ("test set, paired bootstrap", row_diff.mean(), (test_diff_ci.low, test_diff_ci.high))]
for i, (label, est, (lo, hi)) in enumerate(rows):
    right.errorbar(est, i, xerr=[[est - lo], [hi - est]], fmt="o", color="C2", capsize=4)
right.axvline(0, color="grey", ls="--")
right.set_yticks(range(len(rows)), [r[0] for r in rows])
right.set_xlabel("random forest minus logistic regression")
fig.tight_layout()
```

The intervals in the legend and axis labels say exactly what they are. The x-axis on the left isn't forced to start at zero: this is a dot plot, and dots are read by position, so a zoomed axis is fine. (Bars are read by length, which is why truncated bar charts mislead; Module 7 returns to this.)

## Step 7: Write the sentence that goes in the paper

```python run
print(f"Random forest vs logistic regression: {diff.mean():+.1%} accuracy "
      f"(95% CI {corrected_ci[0]:+.1%} to {corrected_ci[1]:+.1%}; corrected resampled t over "
      f"5x5-fold CV on {len(X_dev)} lakes). On a locked test set of {len(X_test)} lakes: "
      f"{row_diff.mean():+.1%} (paired bootstrap 95% CI {test_diff_ci.low:+.1%} to {test_diff_ci.high:+.1%}).")
```

Both analyses point the same direction, and both intervals include zero. The defensible claim: "Both models beat the majority baseline by 13 to 16 points; the forest may be a few points better than logistic regression, but 480 lakes can't distinguish a gain of 6 points from a small loss." That's a real result. It tells the agency the comparison is worth repeating with more lakes, and it stops anyone from building policy on a 2.7-point gap.

## The finished script

Here is the whole build as one file you can run top to bottom in a fresh Colab runtime:

```python title="compare_models.py"
import numpy as np
import pandas as pd
from scipy import stats
from scipy.stats import bootstrap
from sklearn.dummy import DummyClassifier
from sklearn.ensemble import RandomForestClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import RepeatedStratifiedKFold, cross_val_score, train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import FunctionTransformer, StandardScaler


def make_lakes(n, seed):
    rng = np.random.default_rng(seed)
    df = pd.DataFrame({
        "temp_c": rng.normal(22, 4, n),
        "phosphorus_ugL": rng.lognormal(np.log(40), 0.6, n),
        "nitrate_mgL": rng.lognormal(np.log(0.8), 0.5, n),
        "turbidity_ntu": rng.lognormal(np.log(6), 0.5, n),
        "ph": rng.normal(8.0, 0.4, n),
        "wind_ms": rng.gamma(2.0, 2.0, n),
    })
    warm = (df.temp_c > 23).astype(float)
    p = np.log(df.phosphorus_ugL / 40)
    logit = -2.4 + 3.4 * warm + 1.0 * p + 1.6 * warm * p - 0.4 * (df.wind_ms - 4)
    df["bloom"] = (rng.random(n) < 1 / (1 + np.exp(-logit))).astype(int)
    return df


def corrected_ci(diff, n_train, n_val, level=0.95):
    """Nadeau-Bengio corrected t interval for the mean of paired CV differences."""
    k = len(diff)
    se = diff.std(ddof=1) * np.sqrt(1 / k + n_val / n_train)
    t_crit = stats.t.ppf(0.5 + level / 2, df=k - 1)
    return diff.mean() - t_crit * se, diff.mean() + t_crit * se


def test_set_ci(correct, seed=0):
    res = bootstrap((correct,), np.mean, n_resamples=5000, rng=np.random.default_rng(seed))
    return res.confidence_interval.low, res.confidence_interval.high


lakes = make_lakes(480, seed=3)
X, y = lakes.drop(columns="bloom"), lakes["bloom"]
X_dev, X_test, y_dev, y_test = train_test_split(X, y, test_size=0.25, stratify=y, random_state=0)

models = {
    "majority class": DummyClassifier(strategy="most_frequent"),
    "logistic regression": make_pipeline(FunctionTransformer(np.log), StandardScaler(),
                                         LogisticRegression()),
    "random forest": RandomForestClassifier(n_estimators=50, min_samples_leaf=3, random_state=0),
}
cv = RepeatedStratifiedKFold(n_splits=5, n_repeats=5, random_state=1)
cv_scores = {name: cross_val_score(m, X_dev, y_dev, cv=cv) for name, m in models.items()}

correct = {}
for name, model in models.items():
    model.fit(X_dev, y_dev)
    correct[name] = (model.predict(X_test) == y_test).to_numpy().astype(float)
    lo, hi = test_set_ci(correct[name])
    print(f"{name:20s} CV {cv_scores[name].mean():.3f}   test {correct[name].mean():.3f} [{lo:.3f}, {hi:.3f}]")

diff = cv_scores["random forest"] - cv_scores["logistic regression"]
n_val = len(X_dev) / 5
lo, hi = corrected_ci(diff, n_train=len(X_dev) - n_val, n_val=n_val)
print(f"RF - LR, CV:   {diff.mean():+.3f} [{lo:+.3f}, {hi:+.3f}]  (corrected)")
row_diff = correct["random forest"] - correct["logistic regression"]
lo, hi = test_set_ci(row_diff)
print(f"RF - LR, test: {row_diff.mean():+.3f} [{lo:+.3f}, {hi:+.3f}]  (paired bootstrap)")
```

:::quiz
Q: Why does the build pass the same `cv` object to `cross_val_score` for every model?
- [x] So each model is scored on identical splits, which lets you subtract fold by fold
  Paired differences cancel the "easy fold" or "hard fold" effect that hits both models at once.
- [ ] Because `cross_val_score` can't create its own folds
  It can (`cv=5`), but then the folds for each model wouldn't be guaranteed to match.
- [ ] To make cross-validation run faster
  Sharing the splitter doesn't change the number of fits.

Q: The forest won 18 of 25 folds. Why isn't that strong support on its own?
- [ ] 18 out of 25 is below the 95% threshold
  Win counts don't have a 95% threshold; the issue is what the 25 folds are.
- [x] The folds overlap heavily in their training data, so the 25 results are far from independent
  That's the same reason the naive interval is too narrow: correlated results get counted as if they were separate experiments.
- [ ] Two folds were ties, which invalidates the comparison
  Ties are normal with small validation folds and don't invalidate anything.

Q: On the test set the models disagree on only 18 of 120 lakes. What does that imply for the difference in accuracy?
- [ ] Its interval should be about as wide as each model's own interval
  Pairing makes it narrower than naively combining two intervals, but it's still driven by only the disagreements.
- [x] Its uncertainty is governed by those 18 lakes, so it stays wide even though 120 lakes were tested
  The 102 lakes where both models agree add nothing to the difference.
:::

:::takeaways
- Score every model on one shared, repeated CV splitter and report the spread of fold scores alongside the mean.
- Compare models with paired differences. Correct their interval for fold overlap (1/k + n_val/n_train); the naive version is too narrow.
- Bootstrap the locked test set from a per-row correct/wrong vector, and bootstrap the paired difference, not two separate accuracies.
- Put the difference, with its interval and a zero line, in the figure. That's the quantity the claim is about.
- "We can't tell yet, and here's the range" is a reportable result.
:::

## Extend it

- Change `make_lakes(480, ...)` to 2,000 lakes. Does the corrected interval for the gap move off zero? Roughly how many lakes would the agency need?
- Swap accuracy for `scoring="roc_auc"` in Step 3 and `sklearn.metrics.roc_auc_score` with `paired=True` bootstrapping of `(y_test, scores)` in Step 5.
- Turn the comparison into a one-sided question ("is the forest better?") and compute a corrected p-value with `stats.t.sf`.

## Further reading

- [scikit-learn: Statistical comparison of models using grid search](https://scikit-learn.org/stable/auto_examples/model_selection/plot_grid_search_stats.html): implements the corrected t-test step by step and adds a Bayesian alternative for "how likely is model A better?"
- [Nadeau & Bengio, "Inference for the Generalization Error" (Machine Learning, 2003)](https://link.springer.com/article/10.1023/A:1024068626366): the paper behind the 1/k + n_val/n_train correction.
- [Bouthillier et al., "Accounting for Variance in Machine Learning Benchmarks" (2021)](https://arxiv.org/abs/2103.03098): measures how much data splits, seeds, and hyperparameter choices move benchmark results, and what that means for claiming one method beats another.
