A team records a phone's accelerometer while 30 people hold it still, 16 recordings per person. Half the people have a movement disorder. The team trains a 5-nearest-neighbor classifier and checks it with 5-fold cross-validation. Then a reviewer asks for one change: keep all of each person's recordings in the same fold. Same model, same data, same metric. Guess how much the score moves.

```python run
import numpy as np
import pandas as pd
from sklearn.model_selection import KFold, GroupKFold, cross_val_score
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

def make_tremor(seed=0, n_people=30, per_person=16):
    rng = np.random.default_rng(seed)
    person = np.repeat(np.arange(n_people), per_person)
    condition = (np.arange(n_people) < n_people // 2).astype(int)
    # most patients were recruited at clinic A, most controls at clinic B
    clinic = np.where(rng.random(n_people) < np.where(condition == 1, 0.75, 0.25), "A", "B")
    signature = rng.normal(0, 1.0, (n_people, 5))          # every person moves a bit differently
    effect = np.array([0.7, 0.4, -0.3, 0.3, 0.0])         # what the condition actually changes
    feats = signature[person] + np.outer(condition[person], effect) + rng.normal(0, 0.5, (person.size, 5))
    df = pd.DataFrame(feats, columns=["tremor_power", "tremor_harmonic", "gait_speed", "stride_var", "grip_rate"])
    df["noise_floor"] = (clinic[person] == "A") * 1.0 + rng.normal(0, 0.3, person.size)  # clinic A's phones are noisier
    df["person"], df["clinic"], df["condition"] = person, clinic[person], condition[person]
    return df

df = make_tremor()
X = df.drop(columns=["person", "clinic", "condition"])
y, person = df["condition"], df["person"]
knn = make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=5))

leaky = cross_val_score(knn, X, y, cv=KFold(5, shuffle=True, random_state=0))
honest = cross_val_score(knn, X, y, cv=GroupKFold(5), groups=person)
print(f"KFold (recordings shuffled):   {leaky.mean():.3f}")
print(f"GroupKFold (people kept whole): {honest.mean():.3f}")
```

From 0.88 to 0.61. Only the question changed. KFold asked "can you label a new recording of someone you've already met?" GroupKFold asked "can you label a new person?" Only the second matches how the model would be used.

## Group leakage: the model learned *who*, not *what*

Each person has a movement signature that shows up in every one of their recordings, and it's larger than the condition's effect on any single feature. With shuffled folds, a test recording's nearest neighbors are almost always other recordings of the same person, whose label is right there in the training set. The classifier is doing person identification and getting diagnosis for free.

That's **leakage**: information unavailable at prediction time gets into training and inflates the score. Whenever rows come in groups (patients, mice, plots, lab batches, sessions), split on the group.

```mermaid caption="Choose the splitter from how the data were collected, not from habit"
flowchart TD
    Q{How do rows relate?} -->|independent samples| A[StratifiedKFold]
    Q -->|several rows per patient, site, batch| B["GroupKFold / StratifiedGroupKFold"]
    Q -->|ordered in time| C["TimeSeriesSplit (train on past, test on future)"]
    Q -->|close in space| D["GroupKFold on spatial blocks"]
```

This failure is not hypothetical. Zech and colleagues (PLOS Medicine, 2018) trained pneumonia detectors on chest X-rays from several hospital systems and found the networks could identify which hospital system an X-ray came from for more than 99.9% of images. Because pneumonia was 34% of one hospital's images and about 1% of another's, sorting by hospital alone gave an AUC of 0.86. A model can score well by learning the source of the data.

## Time and space leak the same way

A river sensor logs daily water temperature and dissolved oxygen for two years. Oxygen depends on temperature, plus a slow drift that carries over from day to day. A tempting feature is simply the day number. Compare shuffled 5-fold CV with forward-chaining splits that always train on the past and test on the next three months:

```python run
from sklearn.ensemble import RandomForestRegressor
from sklearn.model_selection import TimeSeriesSplit

rng = np.random.default_rng(12)
days = np.arange(730)
temp = 14 + 8 * np.sin(2 * np.pi * (days - 110) / 365) + rng.normal(0, 1.0, 730)
drift = np.zeros(730)
for t in range(1, 730):
    drift[t] = 0.97 * drift[t - 1] + rng.normal(0, 0.15)   # yesterday's drift carries into today
oxygen = 12.5 - 0.22 * temp + drift + rng.normal(0, 0.2, 730)
river = pd.DataFrame({"day": days, "water_temp": temp})

forest = RandomForestRegressor(n_estimators=100, min_samples_leaf=2, random_state=0)
splitters = {"shuffled KFold": KFold(5, shuffle=True, random_state=0),
             "TimeSeriesSplit": TimeSeriesSplit(n_splits=4, test_size=91)}
for name, cv in splitters.items():
    for cols in (["water_temp"], ["water_temp", "day"]):
        mae = -cross_val_score(forest, river[cols], oxygen, cv=cv, scoring="neg_mean_absolute_error").mean()
        print(f"{name:16s} features {str(cols):25s} MAE {mae:.2f} mg/L")
```

Shuffled CV says adding the day number cuts the error in half. Forward-chaining says it does nothing. With shuffled folds, every test day sits between training days from the day before and the day after, so the forest just reads off its neighbors' drift. When you actually forecast, tomorrow has no neighbors in the training set. `test_size=91` keeps every training window at least a year long so each fold sees a full season.

Space works the same way. Soil samples a few meters apart are more alike than samples a kilometer apart, so random folds let a model interpolate between neighbors and overstate how well it maps new ground. Cut the map into blocks and use the block as the group; you'll build this in the practice lesson.

## Ablations: take components away one at a time

An **ablation study** removes one part of a system (a feature block, a preprocessing step, a model component), re-runs the *same* evaluation, and records how much the score drops. It answers "what is this result made of?" Use the honest, grouped splitter, and repeat it over several split seeds so each number comes with a spread.

```python run alt="Horizontal bar chart of grouped cross-validation accuracy with error bars for six feature sets. Device noise floor only scores highest at about 0.70, the full model about 0.67, and removing the device feature drops to about 0.61." caption="The phone's noise floor alone beats the full model"
import matplotlib.pyplot as plt
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import StratifiedGroupKFold

def grouped_scores(cols, seeds=range(5)):
    """Mean accuracy of grouped 5-fold CV, once per split seed."""
    model = make_pipeline(StandardScaler(), LogisticRegression())
    return np.array([
        cross_val_score(model, X[cols], y, groups=person,
                        cv=StratifiedGroupKFold(5, shuffle=True, random_state=s)).mean()
        for s in seeds])

blocks = {"tremor": ["tremor_power", "tremor_harmonic"], "gait": ["gait_speed", "stride_var"],
          "grip": ["grip_rate"], "device": ["noise_floor"]}
every = list(X.columns)
variants = {"full model": every}
variants.update({f"without {b}": [c for c in every if c not in cols] for b, cols in blocks.items()})
variants["device only"] = ["noise_floor"]

ablation = pd.DataFrame({name: grouped_scores(cols) for name, cols in variants.items()}).T
table = pd.DataFrame({"mean": ablation.mean(axis=1), "SD over seeds": ablation.std(axis=1, ddof=1)})
table["change vs full"] = table["mean"] - table.loc["full model", "mean"]
print(table.round(3).to_string())

plt.figure(figsize=(7, 3))
plt.barh(table.index, table["mean"], xerr=table["SD over seeds"], color="#4c72b0", capsize=3)
plt.axvline(0.5, color="grey", ls="--", label="chance")
plt.xlim(0.4, 0.75)
plt.xlabel("grouped CV accuracy (mean ± SD over 5 split seeds)")
plt.gca().invert_yaxis()
plt.legend(loc="lower right")
```

Read it row by row. Removing the tremor block costs about 2 points, removing the device feature costs 6, and the noise floor *on its own* scores best of all. That feature measures the phone, and the phone tells you the clinic, and the clinic tells you who was recruited where. The ablation didn't find the biology; it found the recruitment pattern. The next check would be **leave-one-clinic-out** validation, where that shortcut can't help.

Removing gait slightly *improves* the score and removing grip changes almost nothing, but both are within about one seed-to-seed SD of the full model, so neither is a finding.

## Sensitivity: would another reasonable choice change the conclusion?

A **sensitivity analysis** reruns the study under choices you could reasonably have made differently: seeds, hyperparameters, preprocessing, thresholds. If the headline flips, the headline was about the choice. Here is the neighbor count *k* swept under both splitters:

```python run alt="Line chart of accuracy against number of neighbors for two splitters. KFold stays near 0.88 to 0.90 for small k and falls after k = 15. GroupKFold starts near 0.59 at k = 1 and rises slowly to about 0.67 at k = 41." caption="Leaky CV and honest CV recommend opposite settings"
ks = [1, 3, 5, 9, 15, 25, 41]
curves = {"KFold": [], "GroupKFold": []}
for k in ks:
    model = make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=k))
    curves["KFold"].append(cross_val_score(model, X, y, cv=KFold(5, shuffle=True, random_state=0)).mean())
    curves["GroupKFold"].append(cross_val_score(model, X, y, cv=GroupKFold(5), groups=person).mean())

plt.figure(figsize=(7, 3))
for name, vals in curves.items():
    plt.plot(ks, vals, "o-", label=name)
plt.xscale("log")
plt.xticks(ks, ks)
plt.xlabel("n_neighbors (k)")
plt.ylabel("mean CV accuracy")
plt.legend()
```

Leakage doesn't just inflate the number; it changes which model you'd pick. KFold favors small *k* (find the same person), GroupKFold favors large *k* (average over many people). Seeds are a sensitivity check too: the ablation's "SD over seeds" column, about 0.02 to 0.03, is the noise floor of this evaluation. A claimed improvement smaller than that needs more data before it means anything, and reporting only your best seed is a quiet way of reporting noise.

## Forking paths: try 30 analyses and one will look good

Every choice you make while looking at results (which features, which model, which outlier rule) is a fork. Take enough forks and you'll find a path that looks good by chance. To see how strong the effect is, build a dataset where the labels are pure noise, try 30 random four-feature subsets, and keep the best:

```python run
from sklearn.model_selection import StratifiedKFold

rng = np.random.default_rng(5)
X_noise, y_noise = rng.normal(size=(120, 40)), rng.integers(0, 2, 120)
X_fresh, y_fresh = rng.normal(size=(120, 40)), rng.integers(0, 2, 120)
cv = StratifiedKFold(5, shuffle=True, random_state=0)

subsets = [rng.choice(40, 4, replace=False) for _ in range(30)]
scores = np.array([cross_val_score(LogisticRegression(), X_noise[:, s], y_noise, cv=cv).mean()
                   for s in subsets])
best = subsets[scores.argmax()]
print(f"median of 30 analyses: {np.median(scores):.3f}   best: {scores.max():.3f}")
fresh = LogisticRegression().fit(X_noise[:, best], y_noise).score(X_fresh[:, best], y_fresh)
print(f"best subset on fresh data: {fresh:.3f}")
```

The best analysis reaches 0.65 on labels that contain no information, and falls back to chance on new data. Cross-validation was done correctly every time; the leak is in the *selection*. A famous demonstration is the [fMRI study that found "significant" brain activity in a dead salmon](http://prefrontal.org/files/posters/Bennett-Salmon-2009.pdf), because thousands of voxels were tested without correction. Three defenses work: decide the comparisons before you look (and write them down), correct for the number of tests (Holm or Benjamini–Hochberg), and confirm the final choice on a test set that played no part in the search.

:::warning
**Preprocessing on the full dataset.** Scaling, imputing, selecting features, or oversampling *before* splitting lets test rows shape the training pipeline. Put every data-dependent step inside a `Pipeline` so `cross_val_score` refits it on each training fold. Feature selection is the worst offender: on pure noise it can push a CV score from 50% to over 90%.
:::

:::quiz
Q: A dataset has 400 skin-lesion photos from 80 patients, 5 photos each. Shuffled KFold gives 0.93; GroupKFold by patient gives 0.78. Which number belongs in the paper?
- [ ] 0.93, because it uses more varied training data
  Its test photos have siblings from the same patient in training, which won't be true for new patients.
- [x] 0.78, because the model will be used on patients it has never seen
  The splitter has to mirror deployment; here that means whole patients held out.
- [ ] The average, 0.855
  Averaging an inflated estimate with an honest one is still inflated.

Q: In the ablation, the noise-floor feature alone beat the full model. What's the best next step?
- [ ] Drop the other features and publish the one-feature model
  That feature encodes which clinic recorded someone, which won't predict the condition anywhere else.
- [x] Evaluate with leave-one-clinic-out splits and look for how the feature relates to recruitment
  If the score collapses when clinics are held out, the feature is a shortcut, not a symptom.
- [ ] Add more trees to the model
  Model capacity isn't the problem; what the feature measures is.

Q: You tried 30 feature sets and report the best CV score, 0.65. Which change fixes the optimism?
- [ ] Use 10 folds instead of 5
  The problem is choosing the maximum of 30 noisy scores, which more folds don't remove.
- [x] Score the chosen feature set once on data that played no part in choosing it
  A held-out test set (or nested CV) gives an estimate that the selection couldn't tune toward.
- [ ] Report the median of the 30 instead
  That's less inflated, but it no longer describes the model you're actually claiming.

Q: Shuffled KFold says a "day number" feature halves forecasting error; TimeSeriesSplit says it doesn't help. Why the difference?
- [x] Shuffled folds put training days on both sides of each test day, so the model interpolates
  In real forecasting there's no tomorrow in the training set, so the trick disappears.
- [ ] TimeSeriesSplit uses less training data, so every model looks worse
  The temperature-only model scores about the same under both splitters; only the day feature changes.
:::

:::takeaways
- Leakage means information unavailable at prediction time reaches training. Split on the unit you'll predict for: groups with `GroupKFold`, time with `TimeSeriesSplit`, space with blocks.
- Leaky CV inflates scores *and* picks different hyperparameters, so fixing it can change your whole conclusion.
- An ablation removes one component at a time under the same honest evaluation; a feature that works suspiciously well alone is a shortcut to investigate.
- Rerun across seeds and reasonable settings. A gain smaller than the seed-to-seed spread isn't a finding.
- Searching many analyses and reporting the best one is selection leakage; pre-specify, correct, and confirm on untouched data.
:::
