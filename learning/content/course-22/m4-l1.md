In 2018, a paper in *Nature* trained a deep neural network to predict where aftershocks would occur after large earthquakes. With 13,451 parameters, it reached an AUC of 0.85, far above the 0.58 of Coulomb stress change, the standard physics-based predictor. A year later, Arnaud Mignan and Marco Broccardo showed that a logistic regression with **two** free parameters reached the same 0.85, and a logistic regression on distance and mainshock slip reached 0.86 ([Mignan & Broccardo, 2019](https://arxiv.org/abs/1904.01983)).

The original paper did compare against a baseline, the one physicists use. What it skipped was the simplest statistical model on the same inputs. That missing rung would have shown that the network's complexity bought nothing, and that the interesting result was in the inputs, not the architecture.

## The baseline ladder

Each rung of the ladder answers a different question, and a result only means something relative to the rung below it.

```mermaid caption="Each rung is a model the next one has to beat on the same split"
flowchart TB
    A["Rung 1: ignore the inputs (majority class, mean)"] --> B["Rung 2: one feature or a domain rule"]
    B --> C["Rung 3: linear or logistic model on all features"]
    C --> D["Rung 4: forest, boosting, or neural network"]
```

Rung 1 tells you what score is free. Rung 2 tells you how much one obvious variable explains, the number a domain expert would compute on a napkin. Rung 3 tells you how far a simple combination of features gets you. Rung 4 is only interesting by its margin over rung 3, and only if that margin survives a change of seed.

## Rung 1: models that ignore the inputs

A dummy model predicts without looking at the features. scikit-learn has two: `DummyClassifier` (strategies include `"most_frequent"`, which always predicts the majority class, and `"stratified"`, which guesses at random in proportion to the class rates) and `DummyRegressor` (default `"mean"`). They score what you'd get for free, and they're the quickest check that a metric is behaving.

This dataset has 8% positives, like many screening problems.

```python run title="dummy.py"
import numpy as np
import pandas as pd
from sklearn.datasets import make_classification
from sklearn.dummy import DummyClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import StratifiedKFold, cross_validate
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X, y = make_classification(n_samples=1000, n_features=10, n_informative=3,
                           weights=[0.92], flip_y=0.02, random_state=0)
print(f"positive rate: {y.mean():.3f}")

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
candidates = {"always majority": DummyClassifier(strategy="most_frequent"),
              "random by class rate": DummyClassifier(strategy="stratified", random_state=0),
              "logistic regression": make_pipeline(StandardScaler(), LogisticRegression())}
for name, model in candidates.items():
    scores = cross_validate(model, X, y, cv=cv, scoring=["accuracy", "balanced_accuracy", "roc_auc"])
    print(f"{name:<21} accuracy {scores['test_accuracy'].mean():.3f}   "
          f"balanced {scores['test_balanced_accuracy'].mean():.3f}   AUC {scores['test_roc_auc'].mean():.3f}")
```

The model that never predicts a positive scores 92% accuracy, and logistic regression beats it by only 2 points. On balanced accuracy and AUC, the dummies sit at 0.5 and the real model's advantage becomes visible. That's the dummy's second job: if your chosen metric gives a do-nothing model a high score, choose a different metric before comparing anything else.

## Rungs 2 to 4 on a real dataset

The diabetes dataset in scikit-learn has 442 patients, 10 baseline measurements, and a measure of disease progression one year later. Here are all four rungs, scored with the same 5-fold split. For rung 2, the one-feature rule uses body mass index, the measurement a clinician would reach for first.

```python run title="ladder.py"
from sklearn.datasets import load_diabetes
from sklearn.dummy import DummyRegressor
from sklearn.ensemble import RandomForestRegressor
from sklearn.linear_model import LinearRegression, RidgeCV
from sklearn.model_selection import KFold, cross_val_score
from sklearn.neural_network import MLPRegressor

diabetes = load_diabetes(as_frame=True)
X_all, y_all = diabetes.data, diabetes.target

def ladder(seed):
    return {
        "1 mean (dummy)": (DummyRegressor(), ["bmi"]),
        "2 BMI only": (LinearRegression(), ["bmi"]),
        "3 linear (ridge)": (make_pipeline(StandardScaler(), RidgeCV(alphas=np.logspace(-2, 3, 20))), list(X_all)),
        "4 random forest": (RandomForestRegressor(n_estimators=50, min_samples_leaf=5, random_state=seed), list(X_all)),
        "4 neural network": (make_pipeline(StandardScaler(), MLPRegressor(hidden_layer_sizes=(64, 64), max_iter=2000,
                                                                          early_stopping=True, random_state=seed)), list(X_all)),
    }

split = KFold(n_splits=5, shuffle=True, random_state=0)
rows = []
for name, (model, columns) in ladder(seed=0).items():
    r2 = cross_val_score(model, X_all[columns], y_all, cv=split, scoring="r2").mean()
    rows.append({"seed": 0, "model": name, "r2": r2})
    print(f"{name:<18} R^2 = {r2:.3f}")
```

The dummy scores about zero, which is what R² is designed to do for a model that predicts the mean. BMI alone gets a third of the way to perfect. Ridge regression on all ten measurements reaches about 0.49, and neither the forest nor the neural network beats it. With 442 patients and a mostly additive relationship, the extra flexibility mostly fits noise. That's not a law (on large datasets with strong interactions, complex models do win), but you only find out which situation you're in by running rung 3.

## One run is one draw: compare gaps with the seed spread

Each score above came from one shuffle of the data into folds and one random initialization of each model. Change the seed and every number moves. Before claiming one model beats another, measure how far scores move when nothing but the seed changes. This cell adds seeds 1 to 4 to the seed-0 scores above.

```python run alt="Dot plot of cross-validated R squared for five models across five seeds; ridge regression sits highest with very little spread, the random forest slightly lower, and the neural network spread widely from about 0.30 to 0.45" caption="Five seeds per model: the neural network's spread is wider than its gap to the forest"
import matplotlib.pyplot as plt

for seed in range(1, 5):
    split = KFold(n_splits=5, shuffle=True, random_state=seed)
    for name, (model, columns) in ladder(seed).items():
        r2 = cross_val_score(model, X_all[columns], y_all, cv=split, scoring="r2").mean()
        rows.append({"seed": seed, "model": name, "r2": r2})
by_seed = pd.DataFrame(rows)
print(by_seed.groupby("model")["r2"].agg(["mean", "std", "min", "max"]).round(3))

fig, ax = plt.subplots(figsize=(6.5, 3.4))
for position, (name, group) in enumerate(by_seed.groupby("model")):
    ax.scatter(group["r2"], np.full(len(group), position), s=30, color="#3b5bdb", alpha=0.7)
ax.set_yticks(range(by_seed["model"].nunique()), sorted(by_seed["model"].unique()))
ax.invert_yaxis()
ax.set_xlabel("cross-validated R^2 (one dot per seed)")
ax.spines[["top", "right"]].set_visible(False)
```

Ridge barely moves, because its only randomness is the fold split. The neural network moves the most, because each seed also changes its starting weights and its early-stopping validation set. The gap between the forest and the network is smaller than the network's own spread, so "the forest beats the network" isn't supported, while "ridge beats both" holds on every seed. Report the mean and the spread over seeds, never the best seed.

:::warning
**Three ways papers stack the deck against the baseline.** Tuning the complex model's hyperparameters for days while running the baseline with defaults. Scoring the two on different splits, or the baseline on a published number from another paper's data. Running the new model with ten seeds and reporting the best one. Each can manufacture a gap that isn't there. Give every rung the same split, the same tuning budget, and the same number of seeds.
:::

## A seed isn't enough: what a rerun needs

Seeds fix randomness inside one environment. A rerun months later, or by someone else, also needs:

- **The code version.** A git commit hash, or at minimum a dated copy of the exact notebook.
- **The environment.** `requirements.txt` with `==` pins, written when the result was produced, like Module 1 set up.
- **The data version.** The SHA-256 of each input file, so a silently edited file is caught.
- **The full configuration.** Every hyperparameter, including the defaults you didn't touch, since defaults change between library versions. `model.get_params()` prints them all.
- **Hardware notes.** Multithreaded and GPU code can give slightly different results on different machines. Record the machine, and treat differences in the third decimal as expected rather than alarming.

Published checklists turn this into a list to tick before you submit. The [ML Reproducibility Checklist](https://www.cs.mcgill.ca/~jpineau/ReproducibilityChecklist.pdf) used at NeurIPS covers models, data, code, and results, and the [REFORMS checklist](https://reforms.cs.princeton.edu/) from Kapoor, Narayanan, and colleagues is written specifically for ML-based science. The next lesson builds both the baseline ladder and a run record that covers every item above.

:::quiz
Q: A classifier for a rare condition (5% positive) reports 95.4% accuracy. What's the first thing to compute?
- [x] The majority-class baseline, which scores 95% without looking at any input
  The model beats doing nothing by 0.4 points. Balanced accuracy or recall will show whether it learned anything.
- [ ] A deeper model's accuracy, to see if it does even better
  Climbing the ladder starts at the bottom rung; you don't yet know the first model is useful.
- [ ] The training accuracy
  That tells you about fit, not whether the test score beats a trivial guess.

Q: On the diabetes data, ridge regression scored about 0.49 and the random forest about 0.44. What does that suggest?
- [ ] Random forests are bad models
  They're often excellent. On this small, mostly additive dataset their flexibility fits noise.
- [x] With 442 patients and a largely linear relationship, the extra flexibility doesn't pay off, so the linear model is the result to beat
  The ladder's job is to show where added complexity starts helping. Here it doesn't.
- [ ] The forest needs more trees
  More trees reduce variance a little but don't change the underlying bias-variance trade-off much.

Q: Over five seeds, model A scores 0.71 ± 0.04 and model B scores 0.73 ± 0.05. What can you claim?
- [ ] B is better, since 0.73 > 0.71
  The gap is smaller than either model's seed-to-seed spread.
- [x] The data don't separate them; the gap is within the variation from seeds alone
  A real difference should be larger than what reshuffling the data produces.
- [ ] A is better, since it varies less
  Lower variance is nice, but it isn't a higher score.

Q: A colleague reruns your notebook with your seed and gets slightly different numbers. Which record would tell you most quickly why?
- [ ] The notebook's file name
  The name doesn't change when the contents, data, or libraries do.
- [ ] The number of cells
  Same code can still read different data or run on different library versions.
- [x] The saved data hash and library versions from your run, compared with theirs
  A mismatched hash means different data; mismatched versions point to changed defaults or algorithms.
:::

:::takeaways
- A model's score means something only relative to the rung below: dummy, one-feature rule, linear model, complex model, all on the same split.
- Dummy models show what score is free and expose metrics that reward doing nothing.
- Fit a linear model before a deep one; complex models have to earn their place by a margin.
- Compare gaps between models with the spread across seeds, and report mean and spread, not the best seed.
- A rerun needs the code version, pinned environment, data hashes, full configuration, and hardware notes, not just a seed.
:::
