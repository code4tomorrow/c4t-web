## Warm-up

scikit-learn's breast cancer dataset has 357 benign and 212 malignant tumors. Before running anything, work out what `DummyClassifier(strategy="most_frequent")` scores on accuracy and on balanced accuracy. Then check:

```python run title="warmup.py"
import hashlib
import json
from importlib.metadata import version

import numpy as np
import pandas as pd
from sklearn.datasets import load_breast_cancer
from sklearn.dummy import DummyClassifier
from sklearn.model_selection import StratifiedKFold, cross_validate

cancer = load_breast_cancer(as_frame=True)
X, y = cancer.data, cancer.target
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
scores = cross_validate(DummyClassifier(strategy="most_frequent"), X, y, cv=cv,
                        scoring=["accuracy", "balanced_accuracy"])
print(f"accuracy {scores['test_accuracy'].mean():.3f}, balanced {scores['test_balanced_accuracy'].mean():.3f}")
```

(357 / 569 is 0.627. Balanced accuracy averages the recall of each class, 1.0 for benign and 0.0 for malignant, so it's 0.5 for any model that always predicts one class.)

### Exercise 1: The classification ladder

On the same 5-fold split, score four rungs with accuracy and balanced accuracy: the dummy, logistic regression on `worst radius` alone, logistic regression on all 30 features (scaled), and a random forest with 100 trees. Which rung would you report as the model to beat?

```text
dummy           accuracy 0.627   balanced 0.500
worst radius    accuracy 0.916   balanced 0.899
logistic (all)  accuracy 0.979   balanced 0.975
random forest   accuracy 0.965   balanced 0.959
```

:::hint
Keep each rung as a `(model, columns)` pair in a dictionary, like the build-along, and use `make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))` for the logistic rungs.
:::

:::solution
```python run
from sklearn.ensemble import RandomForestClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

def logistic():
    return make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))

rungs = {"dummy": (DummyClassifier(), list(X)),
         "worst radius": (logistic(), ["worst radius"]),
         "logistic (all)": (logistic(), list(X)),
         "random forest": (RandomForestClassifier(n_estimators=100, random_state=0), list(X))}
for name, (model, columns) in rungs.items():
    r = cross_validate(model, X[columns], y, cv=cv, scoring=["accuracy", "balanced_accuracy"])
    print(f"{name:<15} accuracy {r['test_accuracy'].mean():.3f}   balanced {r['test_balanced_accuracy'].mean():.3f}")
```

One measurement, the radius of the largest cell nuclei, already scores 0.92. The full logistic regression is the model to beat: it's the best rung, and the forest doesn't beat it. A paper proposing a deep network for this dataset would need to clear 0.975 balanced accuracy, not the dummy's 0.5.
:::

### Exercise 2: Is a one-point gain real?

On the wine dataset (178 wines, three cultivars), a colleague says extra-randomized trees beat a random forest. Score both with 30 trees on 5-fold stratified CV for seeds 0 to 9, changing both the split and the model seed each time. Print each model's mean and standard deviation, the mean paired difference, and how many seeds favor extra trees.

:::hint
Use the same `StratifiedKFold(5, shuffle=True, random_state=seed)` for both models inside each loop iteration, so their scores are paired by seed. `ExtraTreesClassifier` lives in `sklearn.ensemble`.
:::

:::solution
```python run
from sklearn.datasets import load_wine
from sklearn.ensemble import ExtraTreesClassifier
from sklearn.model_selection import cross_val_score

X_wine, y_wine = load_wine(return_X_y=True)
forest, extra = [], []
for seed in range(10):
    split = StratifiedKFold(n_splits=5, shuffle=True, random_state=seed)
    forest.append(cross_val_score(RandomForestClassifier(n_estimators=30, random_state=seed), X_wine, y_wine, cv=split).mean())
    extra.append(cross_val_score(ExtraTreesClassifier(n_estimators=30, random_state=seed), X_wine, y_wine, cv=split).mean())
forest, extra = np.array(forest), np.array(extra)
diff = extra - forest
print(f"random forest {forest.mean():.3f} +/- {forest.std(ddof=1):.3f}")
print(f"extra trees   {extra.mean():.3f} +/- {extra.std(ddof=1):.3f}")
print(f"paired difference {diff.mean():+.4f}; extra trees ahead on {np.sum(diff > 0)} of 10 seeds, tied on {np.sum(diff == 0)}")
```

Extra trees come out ahead on most seeds, by under a point on average. That's a consistent but tiny edge: on 178 wines, one more correct prediction is worth 0.56 points, so the whole gap is about one bottle. A fair report says "extra trees were slightly and fairly consistently better (+0.7 points, ahead on 8 of 10 seeds)", which is very different from "extra trees outperform random forests".
:::

### Exercise 3: Which value changed?

Two copies of a field log are supposed to be identical. Compare their SHA-256 hashes, and if they differ, find exactly which cell changed.

```python run title="two_versions.py"
log_v1 = pd.DataFrame({"plot": ["P1", "P2", "P3", "P4"], "rain_mm": [12.0, 8.5, 15.2, 9.9],
                       "yield_t": [6.1, 5.4, 6.8, 5.7]})
log_v2 = log_v1.copy()
log_v2.loc[2, "yield_t"] = 6.3                      # someone "fixed" a value by hand
log_v1.to_csv("field_log_v1.csv", index=False)
log_v2.to_csv("field_log_v2.csv", index=False)
```

:::hint
Hash each file's bytes with `hashlib.sha256(Path(...).read_bytes()).hexdigest()`. For the cell, read both CSVs back and call `first.compare(second)`, which shows only the cells that differ.
:::

:::solution
```python run
from pathlib import Path

def sha256_of(path):
    return hashlib.sha256(Path(path).read_bytes()).hexdigest()

h1, h2 = sha256_of("field_log_v1.csv"), sha256_of("field_log_v2.csv")
print("v1", h1[:12], " v2", h2[:12], " identical:", h1 == h2)
if h1 != h2:
    print(pd.read_csv("field_log_v1.csv").compare(pd.read_csv("field_log_v2.csv"), result_names=("v1", "v2")))
```

The hashes tell you *that* something changed in a fraction of a second, even for gigabyte files. `compare` tells you *what*: row 2's yield went from 6.8 to 6.3. Tools like DVC apply the same idea to whole data folders, storing a hash for every file alongside your git history.
:::

:::video kLKBcPonMYw
DVC's hands-on introduction to versioning data. What to watch for: data files are tracked by their hashes in small text files that git versions, the same fingerprinting idea as Exercise 3, scaled up to whole datasets.
:::

### Exercise 4: Report environment drift

A run record from last year says the result came from `numpy 1.26.4`, `pandas 2.1.4`, `scikit-learn 1.4.2`, and `scipy 1.11.4`. Print which packages differ from the current environment, then print the pinned `requirements.txt` lines that would rebuild last year's environment.

:::hint
`importlib.metadata.version(name)` gives the installed version. The pinned lines come straight from the recorded dictionary, not from the current environment.
:::

:::solution
```python run
recorded = {"numpy": "1.26.4", "pandas": "2.1.4", "scikit-learn": "1.4.2", "scipy": "1.11.4"}
for name, then in recorded.items():
    now = version(name)
    status = "same" if now == then else f"changed: {then} -> {now}"
    print(f"{name:<13} {status}")
print("\nrequirements.txt to rebuild the recorded environment:")
print("".join(f"{name}=={then}\n" for name, then in recorded.items()))
```

If last year's numbers don't reproduce today, this report is the first place to look. A major-version change (NumPy 1 to 2, for example) can change defaults and random streams, so the fix is to rebuild the old environment from the pinned list, reproduce the old number, and only then upgrade and record what changed.
:::

### Exercise 5: Audit a run record

Write `audit_record(record)` that returns a list of problems: no seed in the config, no data hash, any requirement without `==`, a result without a spread, or fewer than two rungs. Test it on the record below, which has five problems.

```python run title="weak_record.py"
weak_record = {
    "config": {"split": "random 80/20"},
    "requirements": ["numpy==2.1.3", "scikit-learn", "pandas>=2.0"],
    "results": {"gradient boosting": {"auc": 0.91}},
}
```

:::hint
Use `record.get("config", {})` so a missing key doesn't crash the audit. A result has a spread if its dictionary has any key starting with `"sd"`.
:::

:::solution
```python run
def audit_record(record):
    problems = []
    if "seed" not in record.get("config", {}):
        problems.append("no seed in config")
    if not record.get("data_sha256"):
        problems.append("no data hash")
    unpinned = [line for line in record.get("requirements", []) if "==" not in line]
    if unpinned:
        problems.append(f"unpinned requirements: {unpinned}")
    results = record.get("results", {})
    if any(not any(key.startswith("sd") for key in values) for values in results.values()):
        problems.append("a result has no spread")
    if len(results) < 2:
        problems.append("fewer than two rungs: no baseline to compare with")
    return problems

for problem in audit_record(weak_record):
    print("-", problem)
```

The single result fails two checks at once, the spread check and the rungs check. The most serious problem is the last one: a gradient boosting AUC of 0.91 with no baseline can't be judged at all.
:::

### Exercise 6: Hunt down hidden randomness

This function returns a different score every time it's called. Find all three sources of randomness, then write `stable_score(data, seed)` that returns the same score on every call with the same seed.

```python run title="unstable.py"
data = cancer.frame

def unstable_score(data):
    sample = data.sample(frac=0.8)
    model = RandomForestClassifier(n_estimators=30)
    split = StratifiedKFold(n_splits=5, shuffle=True)
    return cross_val_score(model, sample.drop(columns="target"), sample["target"], cv=split).mean()

print(", ".join(f"{unstable_score(data):.4f}" for _ in range(3)))
```

:::hint
Look for anything that shuffles or samples: a pandas method, a model, and a splitter. Each takes a `random_state` argument.
:::

:::solution
```python run
def stable_score(data, seed):
    sample = data.sample(frac=0.8, random_state=seed)
    model = RandomForestClassifier(n_estimators=30, random_state=seed)
    split = StratifiedKFold(n_splits=5, shuffle=True, random_state=seed)
    return cross_val_score(model, sample.drop(columns="target"), sample["target"], cv=split).mean()

print(", ".join(f"{stable_score(data, seed=0):.4f}" for _ in range(3)))
print("other seeds:", ", ".join(f"{stable_score(data, seed=s):.4f}" for s in (1, 2)))
```

`data.sample`, `RandomForestClassifier`, and the shuffling `StratifiedKFold` each drew from an unseeded generator. Seeding all three from one `seed` argument makes the function a pure function of its inputs, and the "other seeds" line keeps you honest about how much the score moves anyway.
:::

### Challenge: Reproduce a number from a vague methods section

A report says: "We fit ridge regression to the scikit-learn diabetes data, holding out 25% of patients as a test set, and obtained a test R² of 0.527." It doesn't give the split's random seed or the ridge penalty. Search `random_state` from 0 to 19 and `alpha` in 0.01, 0.1, and 1.0 for combinations within 0.002 of 0.527. Then report the full range of test R² across your search.

:::hint
Loop over both, call `train_test_split(X, y, test_size=0.25, random_state=rs)`, fit `Ridge(alpha=a)`, and store `(rs, a, score)` rows in a DataFrame you can filter.
:::

:::solution
```python run
from sklearn.datasets import load_diabetes
from sklearn.linear_model import Ridge
from sklearn.model_selection import train_test_split

X_d, y_d = load_diabetes(return_X_y=True)
rows = []
for rs in range(20):
    X_tr, X_te, y_tr, y_te = train_test_split(X_d, y_d, test_size=0.25, random_state=rs)
    for alpha in [0.01, 0.1, 1.0]:
        rows.append({"random_state": rs, "alpha": alpha, "r2": Ridge(alpha=alpha).fit(X_tr, y_tr).score(X_te, y_te)})
search = pd.DataFrame(rows)
matches = search[(search["r2"] - 0.527).abs() <= 0.002]
print(matches.round(3).to_string(index=False))
print(f"\ntest R^2 across all {len(search)} settings: {search['r2'].min():.3f} to {search['r2'].max():.3f}")
```

Several different settings reproduce the reported number, so you can "reproduce" it without knowing what the authors actually ran. Worse, the same model and data give a test R² anywhere from about 0.35 to 0.60 depending only on which patients land in the test set. One train/test split is a single draw from that range. A methods section needs the seed and every hyperparameter, and a result needs cross-validation or repeated splits to show where in the range it falls.
:::
