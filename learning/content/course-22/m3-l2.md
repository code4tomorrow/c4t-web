A plant pathology lab hands you a pilot dataset. Three greenhouses each measured seedlings with their own handheld spectrometer: reflectance in four bands, three leaves per plant, plus a hand-held chlorophyll (SPAD) reading. Each plant was later scored for powdery mildew. The lab wants a detector that works in any greenhouse, and asks whether this data is good enough to build one.

By the end of this lesson you'll have an audit report and a plan for better data:

```text
units: 180 plants (540 leaf readings), 3 per plant
prevalence by site: G1 0.47, G2 0.10, G3 0.17
missing: spad 42% at G2 only
site predictable from spectra: 0.94 (chance 0.33)
random forest AUC: random leaves 0.94, new greenhouse 0.80
follow-up: 3 greenhouses x 48 plants, half inoculated, half mock, reference panel every session
```

## Step 1: Load the pilot and record its provenance

The simulation below stands in for the lab's file. Each greenhouse has a different infection rate and its spectrometer reads each band slightly high or low, the two flaws a real multi-site dataset tends to have.

```python run title="pilot.py"
import json
from pathlib import Path

import numpy as np
import pandas as pd

rng = np.random.default_rng(11)
BANDS = ["green", "red", "red_edge", "nir"]
BASE = np.array([0.12, 0.07, 0.30, 0.46])
INFECTION = np.array([-0.008, 0.010, -0.012, -0.020])            # what mildew does to reflectance
SITES = {"G1": (0.45, [0.0, 0.0, 0.0, 0.0]),                     # infection rate, spectrometer offset
         "G2": (0.10, [0.015, 0.025, -0.01, 0.04]),
         "G3": (0.25, [-0.01, -0.02, 0.02, -0.03])}

rows = []
for site, (rate, offset) in SITES.items():
    for number in range(1, 61):
        infected = rng.random() < rate
        plant_signature = rng.normal(0, 0.012, 4)                 # shared by all leaves of one plant
        for leaf in range(1, 4):
            values = BASE + INFECTION * infected + np.array(offset) + plant_signature + rng.normal(0, 0.005, 4)
            rows.append({"plant": f"{site}-{number:02d}", "site": site, "leaf": leaf,
                         **dict(zip(BANDS, values.round(4))), "infected": int(infected)})
pilot = pd.DataFrame(rows)
pilot["spad"] = (42 - 6 * pilot["infected"] + rng.normal(0, 3, len(pilot))).round(1)
pilot.loc[(pilot["site"] == "G2") & (rng.random(len(pilot)) < 0.4), "spad"] = np.nan
print(pilot.head(3).to_string(index=False))
```

Now write down what you know about where this data came from, and mark what you don't. The unknowns become your questions for the lab.

"Natural, not inoculated" is the entry to keep an eye on. It means the greenhouses chose their own infection rates, which is how prevalence ended up tied to site.

## Step 2: Count the independent units

The file has 540 rows, but the experimental unit is the plant: three leaves from one plant share its genetics, its pot, and its infection status.

```python run title="units.py"
summary = pilot.groupby("site").agg(plants=("plant", "nunique"), readings=("plant", "size"),
                                    prevalence=("infected", "mean"))
print(summary.round(2))
print("readings per plant:", pilot.groupby("plant").size().unique())
```

Prevalence ranges from 47% at G1 to 10% at G2. Any feature that identifies the greenhouse now carries information about infection, whether or not it has anything to do with the plant.

## Step 3: Map the missing values

```python run title="missing.py"
print(pilot.groupby("site")[BANDS + ["spad"]].apply(lambda d: d.isna().mean()).round(2))
```

The spectra are complete. SPAD is missing for 42% of G2 readings and nowhere else, so it's missing at random *given site*. If you used SPAD as a feature, "SPAD is missing" would itself become a G2 detector, and G2 is the low-infection site. The audit decision: leave SPAD out of the detector, keep it for a separate check of the labels, and log the reason.

## Step 4: Look for a site fingerprint

Plot one band by site and infection status before running any model.

```python run alt="Strip chart of near-infrared reflectance for healthy and infected plants in three greenhouses; infected plants read lower within each greenhouse, but G2's readings are shifted up and G3's down, so the greenhouse shift is as large as the infection effect" caption="Near-infrared reflectance per plant: the greenhouse shift is as large as the mildew effect"
import matplotlib.pyplot as plt

plants = pilot.groupby(["plant", "site", "infected"], as_index=False)[BANDS].mean()
fig, ax = plt.subplots(figsize=(6.5, 3.8))
for status, offset, marker, label in [(0, -0.12, "o", "healthy"), (1, 0.12, "^", "infected")]:
    for position, site in enumerate(SITES):
        values = plants.query("site == @site and infected == @status")["nir"]
        ax.scatter(np.full(len(values), position + offset) + rng.uniform(-0.05, 0.05, len(values)),
                   values, marker=marker, s=18, alpha=0.8, color=["#7892ee", "#e0803a"][status],
                   label=label if position == 0 else None)
ax.set_xticks(range(3), list(SITES))
ax.set_ylabel("near-infrared reflectance")
ax.legend(frameon=False)
```

Within every greenhouse, infected plants read lower. Across greenhouses, G2's spectrometer reads high and G3's reads low by about as much. Two numbers make that concrete: how well the spectra identify the greenhouse, and how well the greenhouse alone predicts infection.

```python run title="fingerprint.py"
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import roc_auc_score
from sklearn.model_selection import StratifiedKFold, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

site_model = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
site_cv = StratifiedKFold(5, shuffle=True, random_state=0)
site_acc = cross_val_score(site_model, pilot[BANDS], pilot["site"], cv=site_cv).mean()
site_only_auc = roc_auc_score(pilot["infected"], pilot.groupby("site")["infected"].transform("mean"))
print(f"greenhouse predicted from spectra: {site_acc:.2f} accuracy (chance 0.33)")
print(f"infection predicted from greenhouse alone: AUC {site_only_auc:.2f}")
```

The spectra identify the greenhouse 94% of the time, and the greenhouse alone predicts infection with an AUC of about 0.72. A model has every incentive to learn the instrument.

## Step 5: Does the score survive a new greenhouse?

The lab wants a detector for *any* greenhouse, so the honest test holds out a whole greenhouse. Compare that with the usual random split of leaf readings.

```python run title="shortcut_test.py"
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import KFold, LeaveOneGroupOut

models = {"logistic regression": make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000)),
          "random forest": RandomForestClassifier(n_estimators=100, random_state=0)}
schemes = {"random leaves": (KFold(5, shuffle=True, random_state=0), None),
           "new greenhouse": (LeaveOneGroupOut(), pilot["site"])}

for model_name, model in models.items():
    for scheme_name, (cv, groups) in schemes.items():
        auc = cross_val_score(model, pilot[BANDS], pilot["infected"], cv=cv, groups=groups, scoring="roc_auc")
        print(f"{model_name:<20} {scheme_name:<15} AUC {auc.mean():.3f}  (folds {np.round(auc, 2)})")
```

The random forest looks excellent on random leaves (0.94) and falls to about 0.80 on a greenhouse it hasn't seen, because it learned the greenhouse-specific readings. The logistic regression holds up much better here: it can only combine bands linearly, and the infection signal is a difference between bands that survives the offsets. That's one pilot, so don't generalize "linear always wins"; the point is that the random split hid a large drop for one model and not the other, and only the grouped split told you which.

## Step 6: Design the follow-up experiment

No analysis can remove the link between site and prevalence in this pilot, because the greenhouses chose their own infection rates. The fix is new data from a design where site can't predict infection:

- **Randomize** within each greenhouse, by code with a recorded seed, which seedlings are inoculated with mildew spores.
- **Block** by greenhouse: exactly half the plants in every greenhouse are inoculated, so prevalence is 50% everywhere.
- **Controls**: mock-inoculated plants (sprayed with water) are the negative control; inoculated plants are a positive control that shows the detector can see real infection. A white reference panel measured at the start of every session records each spectrometer's offset.
- **Blind** the person scoring mildew to the treatment.

```python run title="layout.py"
DESIGN_SEED = 101
PER_GREENHOUSE = 48
design_rng = np.random.default_rng(DESIGN_SEED)

layout = []
for site in SITES:
    arms = design_rng.permutation(["inoculated", "mock"] * (PER_GREENHOUSE // 2))
    for position, arm in enumerate(arms, start=1):
        layout.append({"greenhouse": site, "position": position, "arm": arm})
layout = pd.DataFrame(layout)
layout.to_csv(project / "follow_up_layout.csv", index=False)

print(pd.crosstab(layout["greenhouse"], layout["arm"]))
print(layout.head(6).to_string(index=False))
```

The crosstab is the proof of balance: 24 and 24 in every greenhouse. The seed means the lab can regenerate this exact layout, and the CSV is what goes to the greenhouse staff.

## Step 7: Size it with a power analysis

Is 48 per greenhouse (72 per arm overall) enough? Take the pilot's within-greenhouse effect on near-infrared reflectance as a starting point, then plan for an effect half that size, because pilot estimates are noisy and inoculated infections may differ from natural ones.

```python run title="power.py"
from statsmodels.stats.power import TTestIndPower

plants["nir_within"] = plants["nir"] - plants.groupby("site")["nir"].transform("mean")
sick = plants.query("infected == 1")["nir_within"]
healthy = plants.query("infected == 0")["nir_within"]
pooled_sd = np.sqrt(((len(sick) - 1) * sick.var() + (len(healthy) - 1) * healthy.var())
                    / (len(sick) + len(healthy) - 2))
d_pilot = (healthy.mean() - sick.mean()) / pooled_sd

analysis = TTestIndPower()
for label, d in [("pilot", d_pilot), ("half the pilot", d_pilot / 2)]:
    n = analysis.solve_power(effect_size=d, alpha=0.05, power=0.9)
    print(f"{label:<15} d = {d:.2f}: {np.ceil(n):.0f} plants per arm for 90% power")
```

Even planning for half the pilot effect, about 47 plants per arm gives 90% power, and the design has 72. The spare capacity matters for a different reason: the real goal is a detector tested on a held-out greenhouse, which uses only a third of the plants as a test set.

```python run alt="Power curves rising with plants per arm for the pilot effect size and for half of it; the pilot curve reaches 0.9 near 13 plants per arm, the half-size curve near 47" caption="Power against plants per arm, with the 90% target marked"
sizes = np.arange(4, 81, 2)
fig, ax = plt.subplots(figsize=(6.5, 3.6))
for label, d, style in [("pilot effect", d_pilot, "-"), ("half the pilot effect", d_pilot / 2, "--")]:
    ax.plot(sizes, analysis.power(effect_size=d, nobs1=sizes, alpha=0.05), style, linewidth=2, label=label)
ax.axhline(0.9, color="#888888", linewidth=1)
ax.axvline(72, color="#888888", linewidth=1, linestyle=":")
ax.text(73, 0.3, "planned: 72 per arm", fontsize=8)
ax.set_xlabel("plants per arm")
ax.set_ylabel("power")
ax.legend(frameon=False, loc="lower right")
```

## The finished audit

Here's the audit as one reusable function. Point it at any table with a unit column, a batch column, and a label.

```python run title="audit.py"
def audit(data, unit, batch, label, features):
    report = {"units": data[unit].nunique(), "rows": len(data),
              "prevalence": data.groupby(batch)[label].mean().round(2).to_dict()}
    missing = data.groupby(batch)[data.columns.drop([unit, batch])].apply(lambda d: d.isna().mean())
    report["missing"] = {col: missing[col].round(2).to_dict() for col in missing if missing[col].any()}
    clf = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
    report["batch_predictable"] = round(cross_val_score(
        clf, data[features], data[batch], cv=StratifiedKFold(5, shuffle=True, random_state=0)).mean(), 2)
    report["batch_only_auc"] = round(roc_auc_score(data[label], data.groupby(batch)[label].transform("mean")), 2)
    return report

for key, value in audit(pilot, unit="plant", batch="site", label="infected", features=BANDS).items():
    print(f"{key:<18} {value}")
```

:::quiz
Q: Why did the audit count plants instead of using all 540 leaf readings as the sample size?
- [x] Leaves from one plant share its genetics, pot, and infection status, so they aren't independent
  Treating 540 correlated readings as 540 samples overstates the evidence and lets the same plant land in both training and test sets.
- [ ] To make the analysis run faster
  Speed has nothing to do with it; it's about what counts as an independent observation.
- [ ] Because three leaves per plant is too few
  The number of leaves is fine. They just add precision to each plant, not new plants.

Q: The random forest scored 0.94 on random leaves and 0.80 on a held-out greenhouse. Which number goes in the report?
- [ ] 0.94, because it uses more training data per fold
  It's inflated by greenhouse fingerprints the model will never see in a new greenhouse.
- [x] 0.80, because the claim is about greenhouses the model hasn't seen, and that's what the grouped split tests
  The evaluation must match the claim. Report both if you like, but the headline is the held-out greenhouse.
- [ ] The average, 0.87
  Averaging a valid and an invalid estimate doesn't produce a valid one.

Q: Why does the follow-up inoculate exactly half the plants in each greenhouse instead of randomizing across all 144 plants at once?
- [ ] It needs fewer plants
  The total is the same; what changes is how treatments are spread across greenhouses.
- [x] Blocking guarantees 50% prevalence everywhere, so greenhouse can't predict infection and its offset can be estimated
  A fully random draw could, by chance, put more inoculated plants in one greenhouse; blocking rules that out.
- [ ] Greenhouse staff prefer even numbers
  The reason is statistical: balance within each block.
:::

:::takeaways
- Write a provenance record before modeling, and turn its unknowns into questions for whoever collected the data.
- Count independent units and prevalence per site; a site with a different base rate makes the site itself a predictor.
- Map missingness by site; a column missing at one site can become a site detector.
- Test whether features predict the batch, and evaluate on held-out groups that match your claim.
- Fix confounded data with a new design: randomize within blocks, include positive and negative controls and a reference standard, blind the scorer, and size it with a power analysis that assumes a smaller effect than the pilot.
:::

## Extend it
