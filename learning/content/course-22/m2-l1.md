"Can machine learning help farmers use less fertilizer?" sounds like a research question. Try to test it and it falls apart. Which farmers? Help compared with what, a soil test or guessing? Measured how, and how much less counts as success? Any result at all can be read as a yes, which means the question can't be wrong, which means it can't be tested.

Here's a version that can fail: *"For wheat plots in one region's 2025 season, does a model using drone images of leaf color predict nitrogen deficiency at week 6 with recall of at least 0.80, compared with 0.65 for the standard handheld chlorophyll meter, on plots from farms the model never saw?"* It's longer and less exciting, and it's the only one of the two you could put in a lab notebook and check in September.

## The five parts of a testable question

Medical researchers use a checklist called PICO (population, intervention, comparison, outcome) to pin questions down. For ML research it helps to add a fifth part: a success threshold written *before* you see results.

```mermaid caption="From a hunch to a question that can come out wrong"
flowchart LR
    H["Hunch: ML could help with X"] --> P["Population: which samples?"]
    P --> I["Inputs: which data does the model see?"]
    I --> C["Comparison: beats what baseline?"]
    C --> O["Outcome: which metric, on which test set?"]
    O --> T["Threshold: what result counts as yes?"]
```

The comparison is the part students skip most, and it's the part reviewers check first. "Our model gets 0.91 AUC" means nothing until you know what a soil test, an existing model, or a one-line rule would get on the same plots. The threshold matters because it stops you from deciding what counts as good after you've seen the number you got.

## Prediction and explanation are different questions

Some questions ask *what will happen*: will this plot be deficient, will this patient be readmitted? Others ask *what would happen if we changed something*: does more fertilizer raise yield, and by how much? The first kind is prediction; the second is explanation, or causal inference. A model can be excellent at one and useless for the other.

This simulation makes the difference concrete. Each of 400 field plots has a soil nitrogen level, a fertilizer amount, a leaf greenness reading, and a yield. The rules are built in, so we know the truth: fertilizer raises yield by 0.02 t/ha per kg, greenness has no effect on yield at all (it's a symptom of nitrogen, not a cause of yield), and, as on real farms, farmers put more fertilizer on poorer soil.

```python run title="plots.py"
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
n = 400
soil_n = rng.normal(50, 10, n)                                              # mg/kg
fertilizer = np.clip(120 - 1.2 * (soil_n - 50) + rng.normal(0, 15, n), 0, None)   # poorer soil gets more
greenness = 20 + 0.4 * (soil_n + 0.25 * fertilizer) + rng.normal(0, 1.5, n)      # a symptom of nitrogen
yield_t = 2 + 0.06 * soil_n + 0.02 * fertilizer + rng.normal(0, 0.4, n)          # greenness isn't in here

plots = pd.DataFrame({"soil_n": soil_n, "fertilizer_kg": fertilizer,
                      "greenness": greenness, "yield_t": yield_t}).round(2)
print(plots.describe().loc[["mean", "std"]].round(2))
```

First, the prediction question: can greenness alone predict yield on plots the model hasn't seen?

```python run title="predict.py"
from sklearn.linear_model import LinearRegression
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(
    plots[["greenness"]], plots["yield_t"], test_size=0.3, random_state=0)
model = LinearRegression().fit(X_train, y_train)
print(f"held-out R^2 from greenness alone: {model.score(X_test, y_test):.2f}")
```

Greenness explains about half the variation in yield on held-out plots. As a predictor it's genuinely useful. As a lever it's worthless: painting the leaves green wouldn't add a gram of wheat, because greenness and yield are both downstream of nitrogen.

Now the explanation question: what does fertilizer do to yield?

```python run title="explain.py"
import statsmodels.formula.api as smf

for formula in ["yield_t ~ fertilizer_kg", "yield_t ~ fertilizer_kg + soil_n"]:
    fit = smf.ols(formula, data=plots).fit()
    low, high = fit.conf_int().loc["fertilizer_kg"]
    print(f"{formula:<34} effect = {fit.params['fertilizer_kg']:.4f}  (95% CI {low:.4f} to {high:.4f})")
```

The naive regression says fertilizer does nothing, with a confidence interval tightly around zero. That's confidently wrong. Poorer soils get more fertilizer, so the fertilizer's benefit is cancelled out by the soil's deficit in the raw comparison. Soil nitrogen is a **confounder**: it affects both the treatment and the outcome. Adjusting for it recovers the true 0.02. In real data you rarely know every confounder, which is why the strongest way to answer an explanation question is a randomized experiment, the topic of Module 3.

:::warning
**The classic mistake: reading feature importance as cause.** A model's most important feature is the one that helps it *predict*, which may be a symptom, a proxy, or a measurement artifact. "The model relies on greenness" is a statement about the model. "Greenness affects yield" is a claim about the world, and the model can't support it.
:::

## Read a paper like a referee

When you read an ML paper in your field, go past the abstract and answer five questions. Write the answers in a table; you'll build one in the next lesson.

1.  **Claim.** What exactly is claimed, about which population, and is it a prediction claim or a causal one?
2.  **Data.** Where did the data come from? How many independent units (patients, farms, sites), not just rows or images? How was the test set kept apart, by random rows or by new sites and later dates?
3.  **Baselines.** What does the model beat? A majority-class guess, the existing method, and a simple linear model on the same features are the minimum.
4.  **Metrics.** Does the metric match the use? Was it chosen before the results?
5.  **Effect size and uncertainty.** How big is the improvement, and how sure can we be? A paper that reports a single number without an interval leaves you to compute one.

These questions aren't academic. When Sayash Kapoor and Arvind Narayanan re-examined political science papers claiming that complex models (random forests, AdaBoost) predicted civil war onset far better than logistic regression, they found the advantage came from data leakage; once it was fixed, the complex models did no substantively better. Their [running list of reviews](https://reproducible.cs.princeton.edu/) documenting ML errors in science, when this course was written, covered 41 reviews in 30 fields that together found problems in 648 papers.

Question 5 is one you can often answer yourself with one line of code. Suppose a paper reports 92% accuracy on a test set of 50 images, and another reports 92% on 1,000.

```python run title="interval.py"
from statsmodels.stats.proportion import proportion_confint

for correct, total in [(46, 50), (920, 1000)]:
    low, high = proportion_confint(correct, total, alpha=0.05, method="wilson")
    print(f"{correct}/{total} correct = {correct / total:.0%}   95% CI {low:.1%} to {high:.1%}")
```

Same headline number, very different evidence. With 50 test images, the true accuracy could plausibly be anywhere from about 81% to 97%, so a claimed improvement from 89% to 92% is well inside the noise. The Wilson interval is a standard choice for proportions and behaves better than the textbook "plus or minus 1.96 standard errors" when the accuracy is near 100% or the test set is small.

## Find the papers that matter

Start broad, then narrow. Three free search engines cover most of what you'll need:

- **[Google Scholar](https://scholar.google.com/)** covers every field. Put exact phrases in quotes, use the `author:` operator, and use the year filter in the left sidebar. **Cited by** shows newer papers that cite a result (often including critiques), and **All versions** frequently leads to a free PDF.
- **[PubMed](https://pubmed.ncbi.nlm.nih.gov/)** indexes biomedical and life-science journals. Boolean operators must be uppercase, and field tags restrict where words appear: `[tiab]` for title or abstract, `[dp]` for publication date.
- **[arXiv](https://arxiv.org/)** holds preprints in ML, physics, math, and quantitative biology. Papers are moderated but not peer reviewed, so the five questions above matter even more.

```text
Google Scholar:  "nitrogen deficiency" "deep learning" wheat leaf images
PubMed:          (machine learning[tiab] OR deep learning[tiab]) AND pneumonia[tiab] AND radiograph*[tiab] AND 2019:2025[dp]
arXiv (search):  nitrogen stress classification UAV imagery
```

Once you find one good paper, follow its references backward and its **Cited by** list forward. Two or three rounds of that usually surface the key papers in a niche faster than more keyword searches would.

:::quiz
Q: Which question is testable as written?
- [ ] Can AI improve crop management?
  No population, comparison, metric, or threshold, so no result could show it's false.
- [ ] Is our new model accurate?
  "Accurate" compared with what, on which data, by which metric?
- [x] On held-out farms, does the image model reach recall of at least 0.80 for week-6 nitrogen deficiency, versus 0.65 for the chlorophyll meter?
  It names the population (held-out farms), comparison, metric, and a threshold fixed in advance, so it can come out no.

Q: In the simulation, `yield_t ~ fertilizer_kg` gave an effect near zero with a narrow interval. Why was it wrong?
- [ ] The sample was too small
  400 plots is plenty; the interval was narrow. The problem is bias, not noise.
- [x] Soil nitrogen drives both fertilizer use and yield, so the naive comparison mixes the fertilizer's effect with the soil's
  Soil nitrogen is a confounder. Adjusting for it, or randomizing fertilizer, recovers the real effect.
- [ ] Linear regression can't estimate effects
  The same method gave the right answer once the confounder was included.

Q: A paper reports 95% accuracy on 40 test samples and no interval. What's your first move?
- [x] Compute an interval for 38/40: it runs from roughly 83% to 99%, so treat small claimed gains with suspicion
  A Wilson interval on 40 samples is wide; differences of a few points can be noise.
- [ ] Accept it, because 95% is high
  High accuracy on a tiny test set is weak evidence, and you also need the baseline.
- [ ] Reject the paper outright
  A small test set is a limitation to weigh, not proof the result is wrong.

Q: A model's top feature for predicting hospital readmission is "number of medications". What can you conclude?
- [ ] Reducing medications will reduce readmissions
  That's a causal claim. Sicker patients take more medications and are readmitted more; the feature is likely a proxy for illness.
- [x] The feature helps prediction, which says nothing yet about what causes readmission
  Predictive importance describes the model. Causal claims need a design that handles confounders.
- [ ] The model is leaking information
  Possibly, but importance alone doesn't show leakage; it shows reliance.
:::

:::takeaways
- A testable question names a population, the model's inputs, a comparison, an outcome metric with its test set, and a threshold fixed before the results.
- Prediction asks what will happen; explanation asks what would change if you intervened. A good predictor can be a useless lever.
- A confounder affects both treatment and outcome, and can make a real effect vanish or a fake one appear.
- Read papers for claim, data, baselines, metrics, and effect size with uncertainty; compute the interval yourself when a paper omits it.
- Search Scholar, PubMed, and arXiv with exact phrases and field filters, then follow references backward and citations forward.
:::
