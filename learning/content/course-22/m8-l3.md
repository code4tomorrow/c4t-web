A careful reviewer spends the first five minutes with your study doing three things: restarting the notebook and running every cell, finding the one sentence that states the verdict, and looking hard at the main figure. If the notebook fails, the verdict is vague, or the figure exaggerates, they stop trusting everything else. This lesson makes sure all three survive.

## Test the notebook the way a reviewer would

Most notebook bugs that change results come from three places: rows from one group leaking across a split, randomness that isn't pinned, and controls nobody looked at. Write a check for each and put them in a final "tests" section.

```python run
import numpy as np
import sklearn
import scipy
from sklearn.model_selection import GroupKFold, KFold

def check_groups_disjoint(splitter, X, y, groups):
    """Fail if any group (patient, farm, site) lands in both train and test of a fold."""
    for i, (train, test) in enumerate(splitter.split(X, y, groups)):
        shared = set(groups[train]) & set(groups[test])
        assert not shared, f"fold {i}: {len(shared)} groups appear in both train and test"
    return "ok"

def check_deterministic(run, *args):
    """Fail if the same call with the same seeds gives different results."""
    first, second = run(*args), run(*args)
    assert np.allclose(first, second), "results change between identical runs"
    return "ok"

groups = np.repeat(np.arange(20), 5)                 # 20 patients, 5 rows each
X_demo, y_demo = np.zeros((100, 1)), np.zeros(100)
for name, splitter in [("KFold", KFold(5, shuffle=True, random_state=0)), ("GroupKFold", GroupKFold(5))]:
    try:
        print(f"{name:10s} group check: {check_groups_disjoint(splitter, X_demo, y_demo, groups)}")
    except AssertionError as err:
        print(f"{name:10s} group check FAILED: {err}")

noisy = lambda seed: np.random.default_rng(seed).normal(size=3)
print("determinism check:", check_deterministic(noisy, 42))
print(f"environment: numpy {np.__version__}, scipy {scipy.__version__}, scikit-learn {sklearn.__version__}")
```

The KFold failure is the point: this helper catches the leak from Module 6 the moment someone swaps a splitter. Call `check_deterministic` on your primary analysis function, and assert that your shuffled-label or negative control sits near chance, as in the previous lesson. Print the library versions at the end so the report can quote them.

Then do the reviewer's run yourself. In Colab: **Runtime › Restart session and run all**. Better still, open the notebook from a fresh copy of your repository in a new browser profile or on a friend's account, so nothing on your Drive or in memory can quietly help it. Fix whatever breaks, and repeat until a clean run finishes with every test passing.

## Lint your figures

You can check the most common figure problems the same way you check code. This function inspects a matplotlib axis and lists what a reviewer would object to:

```python run alt="Two panels with the same three accuracies. Left: unlabeled bars on a y-axis from 0.90 to 0.935 with no intervals. Right: dots with 95% Wilson intervals on a labeled y-axis from 0.85 to 0.97, titled with the test-set size." caption="Left fails the lint; right passes"
import matplotlib.pyplot as plt
from matplotlib.container import BarContainer, ErrorbarContainer
from statsmodels.stats.proportion import proportion_confint

def lint_axes(ax):
    problems = []
    if not ax.get_ylabel():
        problems.append("y-axis has no label")
    bars = [c for c in ax.containers if isinstance(c, BarContainer)]
    if bars and ax.get_ylim()[0] > 0:
        problems.append("bars on an axis that doesn't start at zero")
    has_interval = (any(isinstance(c, ErrorbarContainer) for c in ax.containers)
                    or any(c.errorbar is not None for c in bars) or len(ax.collections) > 0)
    if not has_interval:
        problems.append("no error bars or intervals")
    if not ax.get_title():
        problems.append("no title or note saying what n is and what the intervals are")
    return problems

names, correct, n = ["baseline", "method A", "method B"], np.array([365, 367, 372]), 400
acc = correct / n
ci = np.array([proportion_confint(c, n, method="wilson") for c in correct])

fig, (before, after) = plt.subplots(1, 2, figsize=(9, 3))
before.bar(names, acc)
before.set_ylim(0.90, 0.935)
after.errorbar(names, acc, yerr=[acc - ci[:, 0], ci[:, 1] - acc], fmt="o", capsize=4, color="k")
after.set_ylim(0.85, 0.97)
after.set_ylabel("test accuracy")
after.set_title(f"95% Wilson intervals, n = {n}")
fig.tight_layout()

for label, ax in [("before", before), ("after", after)]:
    print(f"{label}: {lint_axes(ax) or 'no problems found'}")
```

A lint pass doesn't make a figure good, but it catches the mistakes that make a figure misleading. Run it on every figure in the report. Then do the human checks it can't: units on every axis, colors that still differ in grayscale and for color-blind readers, compared conditions on one shared axis, and a caption that states the takeaway in words.

## Structure the report around the verdict

A reproduction report is easier to read than a methods paper because it has one question. Put the answer first.

| Section | What it contains |
| --- | --- |
| Abstract (150 words) | The claim, what you did, the verdict with numbers and intervals, the main discrepancy. |
| 1. The claim and its context | What the paper found, why it matters, where exactly the number appears. |
| 2. Plan | The pre-registered rule, primary analysis, ambiguities, and declared variants, dated. |
| 3. Data and provenance | Source, version, checks against documentation, anything that couldn't be matched. |
| 4. Methods | Checkable detail: splitter, groups, seeds, preprocessing location, library versions. |
| 5. Results | Baseline, controls, the primary result with intervals, the claimed-vs-reproduced figure. |
| 6. Sensitivity, ablation, and error analysis | Every declared variant, reported whether it helped or not. |
| 7. Discrepancy log | Every difference from the paper and what you did about it. |
| 8. Limitations | Specific threats and their likely direction. |
| 9. Reproducibility statement | Repository link, how to run, environment, and the filled REFORMS checklist. |

The abstract's verdict sentence is the most important line you'll write. Compare "We attempted to reproduce the results and found some differences" with "Two of three accuracies reproduced exactly; the third was one wine lower (95.5% vs 96.1%, 95% CI 91.4% to 97.7%), consistent within sampling error." The second can be checked, quoted, and cited.

## Present it in five minutes

Five minutes is enough for one claim and one figure. A workable plan:

1. **The claim** (30 seconds). Quote it and say why someone would care if it were wrong.
2. **What you did** (45 seconds). Data, method, and the rule you set before running.
3. **The figure** (60 seconds). Claimed vs reproduced, with intervals. Point at what the reader should see.
4. **What differed** (60 seconds). The biggest discrepancy, what you tested, and what you found.
5. **What it means** (45 seconds). The verdict and the most important limitation.
6. **One takeaway** (30 seconds). The sentence you want people to remember, plus the repository link.

Rehearse with a timer, out loud, at least twice. Cut slides until you finish with 20 seconds to spare.

## Rubric

| Criterion | Points | Excellent | Needs work |
| --- | --- | --- | --- |
| Claim and plan | 15 | Specific quoted claim; dated plan with match rule, ambiguities, and declared variants written before the primary run | Vague target, or rule chosen after seeing results |
| Data provenance | 10 | Checks against documentation as assertions; unresolvable differences stated | Data loaded without any checks |
| Primary reproduction, baseline, controls | 20 | Faithful primary analysis; baseline plus a negative (shuffled or null) control, and a positive control where possible | No baseline or controls; primary analysis swapped for a better-matching variant |
| Uncertainty | 15 | Intervals on every reported number and on the claimed-vs-reproduced comparison; resolution discussed | Single numbers without intervals |
| Sensitivity, ablation, leakage, errors | 15 | All declared variants reported; leakage risks checked; errors examined, not just counted | Variants selectively reported or missing |
| Reproducible notebook | 10 | Clean restart-and-run-all; tests pass; versions recorded; public repository | Fails on a fresh run or depends on local files |
| Report and figures | 10 | Verdict sentence with numbers; checkable methods; specific limitations; figures pass lint; REFORMS attached | Missing sections or misleading figures |
| Talk | 5 | Five minutes, one figure, clear verdict and limitation | Over time or no clear verdict |

A study that doesn't reproduce its target can earn full marks. The rubric rewards how well you tested the claim, not whether the paper turned out to be right.

## Reflect

Write a short paragraph on each before you submit. They make good material for the report's limitations section and for your own next project.

- Which decision in your plan would you change if you started over, and why didn't you see it at the start?
- Where did the paper's description leave you guessing? Write the sentence the authors *should* have included.
- If your result matched, what's the strongest remaining reason it might still be wrong? If it didn't, what's the most likely explanation you couldn't test?
- Which check from Modules 5 to 7 caught the most problems in your own work?

## Share it and keep going

- **Put it online with a citation.** Push the notebook, `requirements.txt`, report, and checklist to a public GitHub repository. GitHub's guide to [referencing and citing content](https://docs.github.com/en/repositories/archiving-a-github-repository/referencing-and-citing-content) shows how to archive a release on Zenodo and get a DOI so others can cite it.
- **Submit it.** [ReScience C](https://rescience.github.io/) is a peer-reviewed open-access journal for replications of computational research. The [ML Reproducibility Challenge](https://reproml.org/) is an annual event that publishes reproductions of recent machine-learning papers.
- **Tell the authors.** A short, polite email with your report is useful to them whether you matched or not, and an exact reproduction is good news worth sharing.
- **Read further.** [*The Turing Way*](https://book.the-turing-way.org/reproducible-research/overview/overview-definitions) covers reproducible research practices well beyond ML, and the [REFORMS guidelines](https://reforms.cs.princeton.edu/) explain the reasoning behind every checklist item.

:::takeaways
- Write tests for group separation, determinism, and controls, then restart and run all from a clean copy until everything passes.
- Lint every figure for labels, zero-based bars, and intervals, then check what code can't: units, color, captions.
- Lead the report and the talk with a checkable verdict sentence, then show the one figure that supports it.
- The rubric rewards how carefully you tested the claim; a well-documented failure to reproduce is a full-credit result.
:::
