## Warm-up: what pose is the board in?

Match each set of readings to a pose: **flat with the screen up**, **flat with the screen down**, or **falling**.

```text
(a) x = 0,    y = 0,    z = -1023
(b) x = 0,    y = 0,    z = 1023
(c) strength = 40
```

:::solution
(a) is flat with the screen up: all of gravity is along z, pointing down through the back. (b) is flat with the screen down: same size, opposite sign, because the board is upside down. (c) is falling. In free fall everything drops together, so the accelerometer feels almost no force; that's how the **free fall** gesture works.
:::

### Exercise 1: Shake dice with real faces

Shaking the board rolls a number from 1 to 6, draws it as dice dots (the faces from the last practice lesson), and plays a short sound.

:::hint
Start from your dice-faces solution and swap **on button A pressed** for **on shake** in **Input**. Put the sound **in background** so the face appears at once.
:::

:::solution
```makecode
input.onGesture(Gesture.Shake, function () {
    let roll = randint(1, 6)
    music.play(music.tonePlayable(784, music.beat(BeatFraction.Sixteenth)), music.PlaybackMode.InBackground)
    basic.clearScreen()
    if (roll == 1 || roll == 3 || roll == 5) {
        led.plot(2, 2)
    }
    if (roll >= 2) {
        led.plot(0, 0)
        led.plot(4, 4)
    }
    if (roll >= 4) {
        led.plot(4, 0)
        led.plot(0, 4)
    }
    if (roll == 6) {
        led.plot(0, 2)
        led.plot(4, 2)
    }
})
```

Only the event changed: the drawing code doesn't care *why* it was asked to roll. Click **SHAKE** in the simulator a few times and check that you see all six faces eventually.
:::

### Exercise 2: A night light that doesn't flicker

Light the whole screen when the room gets dark and switch it off when it's bright again. Use a margin so it doesn't flicker at dusk: on below 35, off above 45.

:::hint
You need a variable `lit` that remembers whether the light is on, because between 35 and 45 the answer is "keep doing what you were doing". Remember that the very first light reading is 0, so wait a moment before the first check.
:::

:::solution
```makecode
let lit = false
basic.pause(500)
basic.forever(function () {
    let light = input.lightLevel()
    if (!lit && light < 35) {
        lit = true
        led.setBrightness(255)
        basic.showLeds(`
            # # # # #
            # # # # #
            # # # # #
            # # # # #
            # # # # #
            `)
    } else if (lit && light > 45) {
        lit = false
        basic.clearScreen()
    }
})
```

Between 35 and 45 neither branch runs, so the light stays as it was. The half-second pause in **on start** skips past the switch-on reading of 0, which would otherwise light the screen for an instant every time the board starts. Drag the simulator's light control slowly through 35 to 45 in both directions to test the margin.
:::

### Exercise 3: A thermometer with a heat warning

A shows the temperature in °C, B shows it in °F, rounded to a whole number. If the temperature reaches 30 °C, play a warning sound once. Don't warn again until it has dropped below 28 °C.

```text
A  ->  22
B  ->  72
(slider to 31)  ->  warning sound, once
```

:::hint
°F = °C × 1.8 + 32. **round** is in **Math**. The "warn once" rule is the night-light margin again, with a variable `warned`.
:::

:::solution
```makecode
let warned = false
input.onButtonPressed(Button.A, function () {
    basic.showNumber(input.temperature())
})
input.onButtonPressed(Button.B, function () {
    basic.showNumber(Math.round(input.temperature() * 1.8 + 32))
})
basic.forever(function () {
    let temp = input.temperature()
    if (!warned && temp >= 30) {
        warned = true
        music.play(music.builtInPlayableMelody(Melodies.PowerDown), music.PlaybackMode.InBackground)
    } else if (warned && temp < 28) {
        warned = false
    }
    basic.pause(1000)
})
```

Temperature changes slowly, so checking once a second is plenty. Without `warned`, the alarm would replay every second for as long as the room stayed hot.
:::

### Exercise 4: A spirit level

Show a single dot that rolls toward the low side of the board, like the bubble's opposite in a spirit level. Flat, the dot sits in the center. Tilted fully right, it's on the right edge; tilted toward you, it slides to the bottom.

:::hint
x and y run from about -1023 to 1023 when you tilt. Adding 1023 gives 0 to 2046, and dividing by 512 and rounding gives 0 to 4. Shaking can push readings past 1023, so keep the result between 0 and 4 with **min** and **max** from **Math**. If the dot runs uphill on your board, put a minus sign in front of that reading.
:::

:::solution
```makecode
basic.forever(function () {
    let col = Math.round((input.acceleration(Dimension.X) + 1023) / 512)
    let row = Math.round((input.acceleration(Dimension.Y) + 1023) / 512)
    col = Math.min(Math.max(col, 0), 4)
    row = Math.min(Math.max(row, 0), 4)
    basic.clearScreen()
    led.plot(col, row)
    basic.pause(50)
})
```

Flat, x is 0, so `(0 + 1023) / 512` is just under 2 and rounds to 2: the center column. At x = 1023 it rounds to 4. `Math.max(col, 0)` lifts anything below 0 up to 0, and `Math.min(..., 4)` caps anything above 4. In the simulator, move your pointer around the board and watch the dot follow.
:::

### Exercise 5: A clap counter (V2)

Count claps. Each loud sound adds one and shows the total; A+B resets it. Then make it beep on every clap and find out what goes wrong.

:::hint
**on loud sound** and **set loud sound threshold** are in **Input**. Try a threshold around 150 and adjust. For the beep: where does the speaker's sound go?
:::

:::solution
```makecode
let claps = 0
input.setSoundThreshold(SoundThreshold.Loud, 150)
input.onSound(DetectedSound.Loud, function () {
    claps += 1
    basic.showNumber(claps)
})
input.onButtonPressed(Button.AB, function () {
    claps = 0
    basic.showNumber(claps)
})
```

Add a beep inside the sound handler and, on a real board, the count may start climbing by itself: the microphone hears the board's own speaker, which counts as another loud sound, which beeps again. Fix it by keeping the beep quiet with **set volume** in **Music**, or by not beeping at all. Talking loudly near the board can also add claps, so tune the threshold in a quiet room.
:::

### Exercise 6: An eight-point compass

Show the direction the top edge faces as one of eight labels: N, NE, E, SE, S, SW, W, NW.

:::hint
Each label covers 45 degrees. `Math.round(heading / 45) % 8` turns a heading into a number from 0 to 7. An array from **Arrays** (under **Advanced**) can hold the eight labels in order, and **get value at** picks one by its index.
:::

:::solution
```makecode
let names = ["N", "NE", "E", "SE", "S", "SW", "W", "NW"]
basic.forever(function () {
    let index = Math.round(input.compassHeading() / 45) % 8
    basic.showString(names[index])
})
```

A heading of 100 gives `100 / 45`, about 2.2, which rounds to 2: "E". A heading of 350 rounds to 8, and `% 8` wraps it to 0: "N". The array replaces a chain of seven `else if` blocks, and putting the labels in the same order as the arrows makes the index do all the work.
:::

### Challenge: A steady light meter

`led.plotBarGraph(input.lightLevel(), 255)` jitters even when the room isn't changing. Smooth it: keep a variable `smooth` and, on every pass, move it one fifth of the way toward the new reading. Show `smooth` as the bar graph. Then turn a lamp on and off and describe the trade-off.

```python run alt="Model light readings over 6 seconds. The raw line jitters by about 20 either side of 60 for 3 seconds, then jumps to jitter around 180. The smoothed line is much steadier, but takes about half a second to climb from 60 to 180 after the jump." caption="Raw versus smoothed light readings (model data). Smoothing removes the jitter but reacts more slowly when the light really changes."
import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(5)
t = np.arange(0, 6, 0.05)
raw = np.where(t < 3, 60, 180) + rng.normal(0, 12, t.size)
smooth = np.zeros_like(raw)
smooth[0] = raw[0]
for i in range(1, raw.size):
    smooth[i] = smooth[i - 1] + (raw[i] - smooth[i - 1]) / 5

plt.figure(figsize=(7, 3.2))
plt.plot(t, raw, color="#9aa5b1", linewidth=1, label="raw reading")
plt.plot(t, smooth, color="#d1495b", linewidth=2, label="smoothed")
plt.xlabel("time (s)")
plt.ylabel("light level")
plt.legend(loc="upper left")
plt.grid(alpha=0.3)
plt.tight_layout()
```

:::hint
"Move one fifth of the way" is `smooth = smooth + (light - smooth) / 5`. Start `smooth` at a first real reading, not at 0, or the bar will creep up from nothing every time the board starts.
:::

:::solution
```makecode
basic.pause(500)
let smooth = input.lightLevel()
basic.forever(function () {
    smooth = smooth + (input.lightLevel() - smooth) / 5
    led.plotBarGraph(smooth, 255)
    basic.pause(50)
})
```

Each pass closes a fifth of the gap between `smooth` and the newest reading, so a single odd reading only nudges the bar. The cost is lag: after a real change, the bar takes several passes to catch up, as the chart shows. Divide by 2 for a quicker but jumpier bar, or by 10 for a steadier but slower one. Choosing that number is a design decision, and the right answer depends on whether your invention cares more about speed or steadiness.
:::
