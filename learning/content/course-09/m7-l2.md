:::objectives
- Write one program that can play several roles, chosen with a button at start-up.
- Send labelled readings from numbered stations to a hub over radio.
- Stream readings to the computer with `serial.writeValue` and log them with the data logger.
- Detect a silent network with a timeout, and analyse the hub's log in Python.
:::

Here's the network you're building. Every board gets the same program. Press A at start-up and a board becomes a **station**: it measures the temperature every five seconds and broadcasts it with its station number. Press B and it becomes the **hub**: it listens, streams every reading to the computer, writes it to the data log, and shows a cross if nothing has arrived for 15 seconds.

```mermaid caption="Three stations report to one hub, which feeds the computer"
flowchart LR
    S1["Station 1 (window)"] -- "s1 = 24" --> H["Hub"]
    S2["Station 2 (door)"] -- "s2 = 17" --> H
    S3["Station 3 (desk)"] -- "s3 = 22" --> H
    H -- "serial: s1:24" --> PC["Computer: Show data chart"]
    H -- "log row" --> LOG["MY_DATA log"]
```

Why one program for every role? In a classroom you flash the same file to 30 boards, which is far easier than keeping track of three different programs. In the MakeCode simulator you have no choice anyway: both simulated boards always run the same code.

## Step 1: Pick a role at start-up

The board starts with no role and shows `?`. The first press decides. On a station, later presses of A pick the station number, from 1 to 9 and round again.

```makecode
let role = "NONE"
let station = 0
radio.setGroup(23)
basic.showString("?")
input.onButtonPressed(Button.A, function () {
    if (role == "NONE") {
        role = "STATION"
        station = 1
    } else if (role == "STATION") {
        station = station % 9 + 1
    }
    if (role == "STATION") {
        basic.showNumber(station)
    }
})
input.onButtonPressed(Button.B, function () {
    if (role == "NONE") {
        role = "HUB"
        basic.showIcon(IconNames.House)
    }
})
```

This is a state machine with three states (`NONE`, `STATION`, `HUB`) and no way back, which is what you want: a hub that turned into a station mid-experiment would ruin the log. Press A on the top simulated board and B on the bottom one. The top board shows `1`, the bottom one a house.

## Step 2: Stations broadcast a labelled reading

Each station sends its temperature every five seconds with a label like `s1` or `s2`. The label is short (well under the 8-character limit) and carries the station number, so the hub knows who sent what.

```makecode
loops.everyInterval(5000, function () {
    if (role == "STATION") {
        radio.sendValue("s" + station, input.temperature())
        led.toggle(4, 0)
    }
})
```

`led.toggle(4, 0)` flips the top-right LED on each send, a small heartbeat that tells you the station is alive without hiding its number.

## Step 3: The hub streams readings to the computer

`serial.writeValue(name, value)` sends a line like `s1:21` over the USB cable. MakeCode's **Show data** view reads those lines and draws a live chart, with one line per name.

```makecode
let lastHeard = 0
radio.onReceivedValue(function (name, value) {
    if (role == "HUB" && name.charAt(0) == "s") {
        lastHeard = control.millis()
        serial.writeValue(name, value)
        led.toggle(2, 2)
    }
})
```

Two checks guard the handler. `role == "HUB"` stops stations from reacting to each other's messages, since they hear them too. `name.charAt(0) == "s"` ignores any other value messages that might share the group.

Run it: make the top board station 1 and the bottom board the hub. After a few seconds, **Show data** appears under the simulator. Click it and you'll see an `s1` line. Drag the station's thermometer up and the line climbs five seconds later.

```text
s1:21
s1:21
s1:27
```

:::note
With a real micro:bit as the hub, the same chart works once MakeCode is paired with the board over USB (WebUSB, in Chrome or Edge). The data view then lists the micro:bit as its source instead of the simulator.
:::

## Step 4: The hub writes every reading to the log

The live chart vanishes when you close the editor. The data logger keeps the readings on the hub itself, ready to download as a CSV later. Set the columns when the board becomes the hub, not at start-up, because stations might be older V1 boards, which stop with error 927 if they touch the log:

```makecode
input.onButtonPressed(Button.B, function () {
    if (role == "NONE") {
        role = "HUB"
        lastHeard = control.millis()
        datalogger.includeTimestamp(FlashLogTimeStampFormat.Seconds)
        datalogger.setColumnTitles("station", "temperature")
        basic.showIcon(IconNames.House)
    }
})
```

Then add one line to the hub's receive handler, after `serial.writeValue`:

```makecode
datalogger.log(datalogger.createCV("station", name), datalogger.createCV("temperature", value))
```

Each row now holds the time, the station label, and the reading. Storing the label in its own column (instead of one column per station) means the table never needs to change shape when a tenth station joins.

## Step 5: Warn when the network goes quiet

A hub that shows a happy house while every station's battery has died is lying to you. The hub already records `lastHeard`; a `forever` loop compares it with the clock. A `quiet` flag makes sure the screen only changes when the situation changes, so the loop isn't redrawing the house fifty times a second.

```makecode
let quiet = false
basic.forever(function () {
    if (role == "HUB") {
        let quietNow = control.millis() - lastHeard > 15000
        if (quietNow && !quiet) {
            quiet = true
            basic.showIcon(IconNames.No)
        } else if (!quietNow && quiet) {
            quiet = false
            basic.showIcon(IconNames.House)
        }
    }
})
```

That's a two-state machine (listening, quiet) driven by time, the same pattern as the countdown timer.

## Step 6: Test the network

| Do this | You should see |
| --- | --- |
| A on top board, B on bottom board | Top shows `1`; bottom shows a house |
| Wait 10 seconds | Top's corner LED blinks; hub's centre LED flickers; **Show data** appears |
| Drag the station's thermometer | The `s1` line in Show data moves within 5 s |
| Press A twice more on the station | It shows `3`, and a new `s3` line starts in the chart |
| Restart, make the bottom board the hub, never choose a station role | After 15 s the hub shows a cross |

## The finished program

```makecode title="sensor-network"
let role = "NONE"
let station = 0
let lastHeard = 0
let quiet = false
radio.setGroup(23)
basic.showString("?")
input.onButtonPressed(Button.A, function () {
    if (role == "NONE") {
        role = "STATION"
        station = 1
    } else if (role == "STATION") {
        station = station % 9 + 1
    }
    if (role == "STATION") {
        basic.showNumber(station)
    }
})
input.onButtonPressed(Button.B, function () {
    if (role == "NONE") {
        role = "HUB"
        lastHeard = control.millis()
        datalogger.includeTimestamp(FlashLogTimeStampFormat.Seconds)
        datalogger.setColumnTitles("station", "temperature")
        basic.showIcon(IconNames.House)
    }
})
loops.everyInterval(5000, function () {
    if (role == "STATION") {
        radio.sendValue("s" + station, input.temperature())
        led.toggle(4, 0)
    }
})
radio.onReceivedValue(function (name, value) {
    if (role == "HUB" && name.charAt(0) == "s") {
        lastHeard = control.millis()
        serial.writeValue(name, value)
        datalogger.log(datalogger.createCV("station", name), datalogger.createCV("temperature", value))
        led.toggle(2, 2)
    }
})
basic.forever(function () {
    if (role == "HUB") {
        let quietNow = control.millis() - lastHeard > 15000
        if (quietNow && !quiet) {
            quiet = true
            basic.showIcon(IconNames.No)
        } else if (!quietNow && quiet) {
            quiet = false
            basic.showIcon(IconNames.House)
        }
    }
})
```

Because the station is a column, the first job is to split the rows into one list per station. A dictionary keyed by the label does it in a few lines:

```python run title="by_station.py"
import csv

stations = {}
with open("hub_log.csv") as f:
    for row in csv.DictReader(f):
        name = row["station"]
        if name not in stations:
            stations[name] = {"time": [], "temp": []}
        stations[name]["time"].append(float(row["Time (seconds)"]))
        stations[name]["temp"].append(int(row["temperature"]))

for name in sorted(stations):
    temps = stations[name]["temp"]
    print(name, "readings:", len(temps), "min:", min(temps), "max:", max(temps))
```

The window station ranged five degrees, the door station dipped and recovered, and the desk barely moved. Put them on one chart to see *when*:

```python run alt="Line chart of temperature for three stations over 1200 seconds: the window station climbs from 20 to 25 after 600 s, the door station dips from 19 to 16 around 840 s and recovers, and the desk station stays near 21 to 22" caption="Three stations, one time axis"
import matplotlib.pyplot as plt

labels = {"s1": "s1 window", "s2": "s2 door", "s3": "s3 desk"}
plt.figure(figsize=(7, 4))
for name in sorted(stations):
    plt.plot(stations[name]["time"], stations[name]["temp"], marker="o", label=labels[name])
plt.xlabel("time (seconds)")
plt.ylabel("temperature (°C)")
plt.title("Classroom sensor network")
plt.legend()
```

Now the pattern is plain. The window warms steadily from about 600 seconds, which fits the sun moving onto the sill. The door drops three degrees around 720 to 840 seconds and recovers, which looks like a door opened to a cold corridor. The desk, in the middle of the room, hardly notices either. No single board could have told you that the room isn't one temperature; three boards and one hub could.

:::quiz
Q: Why does the board choose its role with a button press instead of using two separate programs?
- [ ] MakeCode can't download two different programs
  It can; you'd just have to keep track of which board got which.
- [x] One program can be flashed to every board, and the simulator runs the same program on both boards anyway
  Choosing the role at run time keeps a whole class on one file and makes the simulator test realistic.
- [ ] Radio only works if every board runs identical code
  Radio only needs a shared group and matching message kinds.

Q: Stations send `sendValue("s" + station, ...)`. What would go wrong if every station sent `sendValue("temp", ...)` instead?
- [x] The hub couldn't tell which station each reading came from
  Every message would look the same, so the window, door, and desk readings would blur into one column of numbers.
- [ ] The hub would receive nothing
  The messages would still arrive; they'd just carry no identity.
- [ ] The labels would be cut to 8 characters
  `temp` has 4 characters, so it fits.

Q: The hub shows a cross. What do you know for sure?
- [ ] Every station's battery is dead
  That's one explanation, but not the only one.
- [x] The hub hasn't received a station reading for more than 15 seconds
  The cross reports a fact about the hub. The cause (range, batteries, wrong group, no stations chosen) is yours to investigate.
- [ ] The data log is full
  A full log is reported by the data logger, not by this timeout.
:::

:::takeaways
- One program with a role chosen at start-up scales from two simulated boards to a whole classroom.
- Put the sender's identity in the label (`s1`, `s2`) so the hub can tell readings apart.
- `serial.writeValue` gives a live chart in **Show data**; the data logger keeps a CSV on the hub for later.
- A timeout on "last heard" turns silence into a visible warning.
- Store the station as a column, then group by it in Python to compare stations on one time axis.
:::

## Ideas to extend it

- Send light level too, as `l1`, `l2`…, and log it in a third column.
- Have the hub reply `radio.sendValue("ok", station)` so each station can show a tick when its reading arrives, like the mood messenger's receipt.
- Track `lastHeard` per station in an array, so the hub can say *which* station went quiet.
- Add a threshold alarm: the hub beeps if any station reads above 28 °C.
