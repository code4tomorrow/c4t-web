## Warm-up: read a log by eye

```text
Time (seconds),sound,light
0,12,80
10,14,82
20,96,81
30,15,80
```

How often was this logged, what happened at 20 seconds, and how do you know it wasn't someone switching on a light?

:::solution
Every 10 seconds (the time goes up by 10 each row). At 20 seconds the sound level jumped from about 14 to 96 for a single reading, so something loud and short happened, like a door slamming. The light column didn't change, so it wasn't a lamp.
:::

### Exercise 1: Traffic survey logger

Make a counter for a traffic survey outside school. Pressing A logs a car and B logs a bike. Each press writes one row with a `vehicle` column, and the board shows a quick icon so the counter knows the press registered.

```text
Time (seconds),vehicle
4,car
9,car
11,bike
```

:::hint
Set the timestamp and the column title once at the start. In each button handler, `datalogger.log(datalogger.createCV("vehicle", "car"))`. A column value can be text as well as a number.
:::

:::solution
```makecode
datalogger.includeTimestamp(FlashLogTimeStampFormat.Seconds)
datalogger.setColumnTitles("vehicle")
input.onButtonPressed(Button.A, function () {
    datalogger.log(datalogger.createCV("vehicle", "car"))
    basic.showIcon(IconNames.Square)
    basic.clearScreen()
})
input.onButtonPressed(Button.B, function () {
    datalogger.log(datalogger.createCV("vehicle", "bike"))
    basic.showIcon(IconNames.Diamond)
    basic.clearScreen()
})
```

This log isn't taken on a timer; each row is an *event*. The timestamps are what let you count vehicles per minute later (Exercise 6).
:::

### Exercise 2: Pick a sensible interval

How many rows does each plan produce? Write a function `rows(duration_s, interval_s)` that counts the first reading at time zero, then use it for all three.

1.  Fridge door test: every 1 second for 5 minutes.
2.  Plant shelf: every 10 minutes for 1 week.
3.  Bike ride: every 0.1 seconds for 20 minutes.

:::hint
Readings happen at 0, interval, 2 × interval, and so on, up to the duration. That's duration ÷ interval readings, plus one for time zero. Use `round(duration / interval)` rather than `//`: `0.1` can't be stored exactly in binary, and `1200 // 0.1` gives `11999.0`.
:::

:::solution
```python run title="rows.py"
def rows(duration_s, interval_s):
    return round(duration_s / interval_s) + 1

print("fridge:", rows(5 * 60, 1))
print("plant: ", rows(7 * 24 * 60 * 60, 10 * 60))
print("bike:  ", rows(20 * 60, 0.1))
```

The plant shelf needs only about a thousand rows for a whole week, but the bike ride generates over ten thousand in 20 minutes. Fast logging fills the log quickly, so only log fast when the thing you're measuring changes fast.
:::

### Exercise 3: How loud was lunch?

A sound logger ran in the cafeteria, one reading every 5 seconds. Print the number of readings, the average, the loudest reading, and how many readings were above 100.

```text
readings: 12
average: 81.8
loudest: 142
above 100: 3
```

:::hint
Read with `csv.DictReader(io.StringIO(log))` so you can keep the log in a string. Convert each `sound` value with `int` before doing maths.
:::

:::solution
```python run title="lunch.py"
import csv
import io

log = """Time (seconds),sound
0,64
5,70
10,72
15,118
20,66
25,71
30,142
35,75
40,69
45,104
50,62
55,69
"""
sound = [int(row["sound"]) for row in csv.DictReader(io.StringIO(log))]
print("readings:", len(sound))
print("average:", round(sum(sound) / len(sound), 1))
print("loudest:", max(sound))
print("above 100:", len([s for s in sound if s > 100]))
```

`io.StringIO` makes a string behave like an open file, which is handy for testing before you have a real download.
:::

### Exercise 4: Clean a messy log

This temperature log has two problems that real logs often have: one reading is blank, and the header appears a second time in the middle because the board was reset during logging. Skip anything that isn't a number, then print how many good readings remain and their average.

```text
good readings: 7
average: 21.6
```

:::hint
Use the plain `csv.reader` so the repeated header comes through as an ordinary row. A value is usable if `value.strip().lstrip("-").isdigit()` is true.
:::

:::solution
```python run title="clean.py"
import csv
import io

log = """Time (seconds),temperature
0,21
30,21
60,
90,22
Time (seconds),temperature
0,22
30,22
60,21
90,22
"""
good = []
for row in csv.reader(io.StringIO(log)):
    value = row[1].strip()
    if value.lstrip("-").isdigit():
        good.append(int(value))
print("good readings:", len(good))
print("average:", round(sum(good) / len(good), 1))
```

The check throws away the header rows (`temperature` isn't a number) and the blank. Notice the times restart at 0 after the reset: if you needed real times, you'd have to stitch the two sections together using your own notes.
:::

### Exercise 5: Which corner is warmer?

Two stations logged to a hub. Plot both on one chart with a legend, then print each station's average. Which corner is warmer, and from what time?

:::hint
Group rows into a dictionary keyed by station, like the build-along. Call `plt.plot` once per station with `label=` and finish with `plt.legend()`.
:::

:::solution
```python run title="corners.py" alt="Line chart of two stations over 600 seconds: the north corner stays at 19 to 20 degrees while the south corner rises from 20 to 24 after 240 seconds" caption="South corner warms from about 240 s"
import csv
import io
import matplotlib.pyplot as plt

log = """Time (seconds),station,temperature
0,north,19
1,south,20
120,north,19
121,south,20
240,north,20
241,south,21
360,north,19
361,south,22
480,north,20
481,south,23
600,north,20
601,south,24
"""
data = {}
for row in csv.DictReader(io.StringIO(log)):
    name = row["station"]
    data.setdefault(name, ([], []))
    data[name][0].append(float(row["Time (seconds)"]))
    data[name][1].append(int(row["temperature"]))

for name, (times, temps) in data.items():
    plt.plot(times, temps, marker="o", label=name)
    print(name, "average:", round(sum(temps) / len(temps), 1))
plt.xlabel("time (seconds)")
plt.ylabel("temperature (°C)")
plt.legend()
```

The south corner averages warmer, but the chart tells the better story: the corners stay within a degree of each other until about 240 seconds, then the south one climbs. An average alone would hide when the difference started.
:::

### Exercise 6: Cars and bikes per minute

Using a traffic survey log like Exercise 1's, count cars and bikes in each minute and draw a grouped bar chart.

:::hint
The minute for a row is `int(time // 60)`. Keep two lists of counts, one per vehicle, with one slot per minute.
:::

:::solution
```python run title="traffic.py" alt="Grouped bar chart of vehicles per minute over three minutes: cars 3, 1, 4 and bikes 1, 2, 0" caption="Traffic outside school, per minute"
import csv
import io
import matplotlib.pyplot as plt

log = """Time (seconds),vehicle
4,car
9,car
11,bike
40,car
71,bike
88,car
102,bike
125,car
131,car
150,car
171,car
"""
cars = [0, 0, 0]
bikes = [0, 0, 0]
for row in csv.DictReader(io.StringIO(log)):
    minute = int(float(row["Time (seconds)"]) // 60)
    if row["vehicle"] == "car":
        cars[minute] += 1
    else:
        bikes[minute] += 1

minutes = [0, 1, 2]
plt.bar([m - 0.2 for m in minutes], cars, width=0.4, label="cars")
plt.bar([m + 0.2 for m in minutes], bikes, width=0.4, label="bikes")
plt.xticks(minutes, ["0-1 min", "1-2 min", "2-3 min"])
plt.ylabel("count")
plt.legend()
print("cars:", cars, "bikes:", bikes)
```

Shifting the bars by 0.2 either side of each minute puts cars and bikes next to each other instead of on top of each other.
:::

## The trick for the challenge: count a step once, even if it wobbles

A footstep shows up in an acceleration log as a spike well above the resting value of about 1000. Real spikes wobble: the reading can shoot up, dip a little, and shoot up again within the same step. A counter that adds one every time the reading crosses a line will count that wobble twice. The fix is two lines instead of one: count a step when the reading rises above a high line, and only get ready for the next step once it falls below a lower line.

```mermaid caption="Two thresholds: count on the way up past 1500, re-arm only below 1100"
stateDiagram-v2
    [*] --> Ready
    Ready --> Stepping: reading above 1500, count one step
    Stepping --> Ready: reading below 1100
```

A dip to 1200 in the middle of a step doesn't reach 1100, so the counter stays in `Stepping` and doesn't count again.

### Challenge: A step counter that ignores bounces

The list below is acceleration strength logged 10 times a second during a short walk. Count steps two ways: the naive way (add one every time the reading goes from 1500 or less to above 1500) and the two-threshold way from the diagram. Print both counts.

:::hint
For the two-threshold count, keep a variable `ready = True`. When `ready` and the reading is above 1500, count and set `ready = False`. When the reading is below 1100, set `ready = True`.
:::

:::solution
```python run title="steps.py"
strength = [1010, 1030, 1500, 1720, 1350, 1040, 980, 1020, 1580, 1690,
            1210, 990, 1000, 1610, 1180, 1530, 1700, 1060, 1010, 1550,
            1650, 1300, 1000, 990, 1020]

naive = 0
for i in range(1, len(strength)):
    if strength[i - 1] <= 1500 and strength[i] > 1500:
        naive += 1

steps = 0
ready = True
for reading in strength:
    if ready and reading > 1500:
        steps += 1
        ready = False
    elif reading < 1100:
        ready = True

print("naive count:", naive)
print("two-threshold count:", steps)
```

The naive counter sees the dip to 1180 in the third step and counts that step twice. The two-threshold counter stays in `Stepping` until the reading truly settles, so it finds the four steps that were really taken. The same idea, called hysteresis, keeps thermostats from clicking on and off every second.
:::
