:::objectives
- Choose the right send and receive pair for a message.
- Track messages with variables, labels, and timers.
- Find radio bugs that produce no error message.
- Translate a small MakeCode radio program into MicroPython.
:::

Every exercise runs in the MakeCode simulator, which shows a second board as soon as you use a radio block. Both boards run the same program, so each exercise is one program that can play either part. Set a group in on start for every exercise; the solutions use 5.

## Warm-up: predict before you press

This program is on both boards. You press A on the top board three times, then B on the bottom board once. What does each board show at the end?

```makecode
let count = 0
radio.setGroup(5)
input.onButtonPressed(Button.A, function () {
    radio.sendNumber(1)
})
input.onButtonPressed(Button.B, function () {
    basic.showNumber(count)
})
radio.onReceivedNumber(function (receivedNumber) {
    count += receivedNumber
})
```

:::solution
The bottom board shows `3`; the top board shows nothing. Each A press sends a 1 that only the *other* board receives (a board never hears its own broadcast), so the bottom board's `count` climbs to 3 while the top board's stays at 0. B on the bottom board shows its own count.
:::

### Exercise 1: Remote doorbell

Pressing A on either board rings the other: it shows a bell-ish icon (use `IconNames.QuarterNote`), plays a tone, and clears the screen after a second.

```text
Top board:    (press A)
Bottom board: music note icon, a beep, then blank
```

:::hint
You need one send (`sendString` is fine) and its matching receive block. Do the showing, beeping, and clearing in the receiver.
:::

:::solution
```makecode
radio.setGroup(5)
input.onButtonPressed(Button.A, function () {
    radio.sendString("DING")
})
radio.onReceivedString(function (receivedString) {
    if (receivedString == "DING") {
        basic.showIcon(IconNames.QuarterNote)
        music.playTone(659, 300)
        basic.pause(1000)
        basic.clearScreen()
    }
})
```

Checking for `"DING"` costs one line now and saves you later, when you add a second kind of string message.
:::

### Exercise 2: Who's been knocking?

The bottom board keeps a count of how many knocks it has received and shows the count after each one. Shaking a board sends a knock. Pressing B resets that board's count to 0.

```text
Shake top board twice -> bottom board shows 1, then 2
Press B on bottom     -> bottom board shows 0
```

:::hint
Use `input.onGesture(Gesture.Shake, ...)` to send. In the simulator, a **SHAKE** button appears on each board once your code uses a gesture.
:::

:::solution
```makecode
let knocks = 0
radio.setGroup(5)
input.onGesture(Gesture.Shake, function () {
    radio.sendNumber(1)
})
radio.onReceivedNumber(function (receivedNumber) {
    knocks += 1
    basic.showNumber(knocks)
})
input.onButtonPressed(Button.B, function () {
    knocks = 0
    basic.showNumber(knocks)
})
```
:::

### Exercise 3: Remote weather station

Every two seconds, each board broadcasts its temperature and light level as labelled values. The receiving board remembers the latest of each. Pressing A shows the remote temperature; pressing B shows the remote light level.

```text
Drag top board's thermometer to 30, then press A on bottom -> 30
```

:::hint
`loops.everyInterval(2000, function () { ... })` runs code on a timer. In the receive block, store `value` in a different variable depending on `name`.
:::

:::solution
```makecode
let remoteTemp = 0
let remoteLight = 0
radio.setGroup(5)
loops.everyInterval(2000, function () {
    radio.sendValue("temp", input.temperature())
    radio.sendValue("light", input.lightLevel())
})
radio.onReceivedValue(function (name, value) {
    if (name == "temp") {
        remoteTemp = value
    } else if (name == "light") {
        remoteLight = value
    }
})
input.onButtonPressed(Button.A, function () {
    basic.showNumber(remoteTemp)
})
input.onButtonPressed(Button.B, function () {
    basic.showNumber(remoteLight)
})
```

The receiver stores readings and the buttons show them. Splitting "collect" from "show" is a pattern you'll keep using.
:::

### Exercise 4: Three silent bugs

A student flashed the sender program onto one real micro:bit and the receiver program onto another. Nothing ever appears on the receiver, and neither board shows an error. Find all three bugs.

```makecode title="sender"
radio.setGroup(12)
input.onButtonPressed(Button.A, function () {
    radio.sendValue("brightness", input.lightLevel())
})
```

```makecode title="receiver"
radio.setGroup(21)
radio.onReceivedNumber(function (receivedNumber) {
    basic.showNumber(receivedNumber)
})
```

:::hint
Check the group, the kind of message, and the label length. Any one of them is enough to keep the receiver dark.
:::

:::solution
1. The groups are 12 and 21. Make them the same.
2. The sender sends a **value** but the receiver only listens for **numbers**. Use `onReceivedValue`.
3. `"brightness"` has 10 characters and would arrive as `brightne`. Use a short label.

```makecode title="receiver (fixed)"
radio.setGroup(12)
radio.onReceivedValue(function (name, value) {
    if (name == "light") {
        basic.showNumber(value)
    }
})
```

The sender's line becomes `radio.sendValue("light", input.lightLevel())`, with the group still 12.
:::

### Exercise 5: Translate the doorbell to MicroPython

Rewrite your Exercise 1 doorbell for python.microbit.org. Test it in that editor's simulator by pressing A (the **Radio** panel shows what your board sent) and by typing `DING` into the panel's message box (your board should ring).

:::hint
You need a `while True` loop that checks `button_a.was_pressed()` and calls `radio.receive()` on every pass. The note picture is `Image.MUSIC_QUAVER`, and `music.pitch(659, 300)` plays the tone after `import music`.
:::

:::solution
Run this in the Python editor, not desktop Python, where `from microbit import *` raises an import error.

```python title="doorbell.py"
from microbit import *
import radio
import music

radio.config(group=5)
radio.on()

while True:
    if button_a.was_pressed():
        radio.send("DING")
    message = radio.receive()
    if message == "DING":
        display.show(Image.MUSIC_QUAVER)
        music.pitch(659, 300)
        sleep(1000)
        display.clear()
    sleep(20)
```

The two event blocks became two `if` checks inside one loop. `radio.receive()` returns `None` when nothing is waiting, and `None == "DING"` is simply false, so no extra check is needed.
:::

### Exercise 6: Hot and cold finder

One board is a hidden beacon and the other is a finder. Press A to make a board the beacon: it sends a number every 200 ms. The other board plots a bar graph of the signal strength, so the bars rise as you walk toward the beacon. (The simulator can't model distance, so you need real boards to play; the code still runs there.)

:::hint
Signal strength runs from about -128 to about -28. Adding 128 turns that into 0 to 100, which `led.plotBarGraph(level, 100)` can draw. A variable `beacon` decides whether the forever loop sends.
:::

:::solution
```makecode
let beacon = false
radio.setGroup(5)
input.onButtonPressed(Button.A, function () {
    beacon = true
    basic.showIcon(IconNames.Diamond)
})
basic.forever(function () {
    if (beacon) {
        radio.sendNumber(0)
        basic.pause(200)
    }
})
radio.onReceivedNumber(function (receivedNumber) {
    let level = radio.receivedPacket(RadioPacketProperty.SignalStrength) + 128
    led.plotBarGraph(level, 100)
})
```

Walls, bodies, and even which way the board faces change the reading, so expect the bars to jitter. Moving slowly and watching the trend works better than trusting one reading.
:::

### Challenge: Rock, paper, scissors over radio

Shake to pick a random throw (0 rock, 1 paper, 2 scissors), show it, and send it. When a board knows both its own throw and its opponent's, it shows a tick for a win, a cross for a loss, or `=` for a draw. Press B to play again.

:::hint
Keep two variables, `mine` and `theirs`, both starting at -1 for "not chosen yet". After any shake or any received throw, call one function that does nothing unless both are 0 or more. With throws as 0, 1, 2, you win exactly when `(mine - theirs + 3) % 3 == 1`.
:::

:::solution
```makecode
let mine = -1
let theirs = -1
radio.setGroup(5)
function judge() {
    if (mine < 0 || theirs < 0) {
        return
    }
    basic.pause(1000)
    if (mine == theirs) {
        basic.showString("=")
    } else if ((mine - theirs + 3) % 3 == 1) {
        basic.showIcon(IconNames.Yes)
    } else {
        basic.showIcon(IconNames.No)
    }
}
input.onGesture(Gesture.Shake, function () {
    if (mine >= 0) {
        return
    }
    mine = randint(0, 2)
    basic.showNumber(mine)
    radio.sendValue("rps", mine)
    judge()
})
radio.onReceivedValue(function (name, value) {
    if (name == "rps") {
        theirs = value
        judge()
    }
})
input.onButtonPressed(Button.B, function () {
    mine = -1
    theirs = -1
    basic.clearScreen()
})
```

The `return` at the top of the shake handler stops a second shake from changing your throw after you've already sent it.
