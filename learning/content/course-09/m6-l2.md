---

:::objectives
- Turn a state diagram into a working MakeCode program, one state at a time.
- Count down with a saved end time instead of `basic.pause`.
- Pause and resume a timer without losing time.
- Test every transition in the simulator with a checklist.
:::

You're building a timer for things like brushing your teeth or a study sprint. Button A adds five seconds. Button B starts it, pauses it, and resumes it. When the time runs out it flashes and beeps until you press a button. Shaking it cancels whatever it's doing. Here's the whole design before any code:

```mermaid caption="The timer's four states and every event that moves between them"
stateDiagram-v2
    [*] --> Setting
    Setting --> Setting: A adds 5 s
    Setting --> Running: B (if time > 0)
    Running --> Paused: B
    Paused --> Running: B
    Running --> Ringing: time is up
    Ringing --> Setting: A or B
    Running --> Setting: shake
    Paused --> Setting: shake
```

Every arrow becomes a few lines of code. Every state becomes one branch of the `forever` loop that draws the screen. Work in the JavaScript view at makecode.microbit.org and run the simulator after each step.

## Step 1: A state variable and a loop that draws it

Start with the variables and the `Setting` state only. `total` is how many seconds the timer is set to.

```makecode
let state = "SETTING"
let total = 0
basic.forever(function () {
    if (state == "SETTING") {
        basic.showNumber(total)
    }
})
```

The simulator shows `0`. Nothing else happens yet, which is right: no handler can change anything.

## Step 2: Add time with button A

A handler checks the state before acting. In `Setting`, A adds five seconds, capped at 60 so a stray press can't set ten minutes by accident.

```makecode
input.onButtonPressed(Button.A, function () {
    if (state == "SETTING") {
        total = Math.min(total + 5, 60)
    }
})
```

Press A three times quickly. The display might still be scrolling the old number, but when it catches up it shows `15`. The handler counted every press; only the drawing lagged. That's the event-driven split from the Notes lesson doing its job.

## Step 3: Start with B and count down

When B starts the timer, the code doesn't count seconds one by one. It works out *when* the timer should end, in board time, and stores it:

```makecode
let endTime = 0
input.onButtonPressed(Button.B, function () {
    if (state == "SETTING" && total > 0) {
        endTime = control.millis() + total * 1000
        state = "RUNNING"
    }
})
```

Then the drawing loop gets a `Running` branch that compares the end time with the clock on every pass:

```makecode
basic.forever(function () {
    if (state == "SETTING") {
        basic.showNumber(total)
    } else if (state == "RUNNING") {
        let left = Math.ceil((endTime - control.millis()) / 1000)
        if (left > 9) {
            led.plotBarGraph(left, total)
        } else {
            basic.showNumber(left)
        }
    }
})
```

Set 15 seconds and press B. The bar graph shrinks for the first few seconds, then single digits count down from 9. Single digits fit on the 5×5 screen without scrolling, which is why the code switches to numbers only near the end. `Math.ceil` rounds up, so 2.3 seconds left shows as `3`, the way a real timer does.

:::note
The `total > 0` check stops B from starting a timer set to zero. Every arrow in the diagram with a condition in brackets becomes an `&&` in code.
:::

## Step 4: Ring when time is up

"Time is up" isn't a button, so no handler catches it. The `forever` loop notices it while drawing the `Running` state and makes the transition itself. Add the check before the drawing, and a `Ringing` branch that flashes and beeps:

```makecode
basic.forever(function () {
    if (state == "SETTING") {
        basic.showNumber(total)
    } else if (state == "RUNNING") {
        let left = Math.ceil((endTime - control.millis()) / 1000)
        if (left <= 0) {
            state = "RINGING"
        } else if (left > 9) {
            led.plotBarGraph(left, total)
        } else {
            basic.showNumber(left)
        }
    } else if (state == "RINGING") {
        basic.showIcon(IconNames.Target)
        music.playTone(988, 200)
        basic.clearScreen()
        basic.pause(200)
    }
})
```

Each pass of the `Ringing` branch is one flash and one beep. The short pause here is fine, because ringing is the one time the loop has nothing else to watch. Now let A and B stop the alarm by adding a `Ringing` branch to each handler:

```makecode
input.onButtonPressed(Button.A, function () {
    if (state == "SETTING") {
        total = Math.min(total + 5, 60)
    } else if (state == "RINGING") {
        state = "SETTING"
    }
})
```

Do the same in B's handler with `else if (state == "RINGING")`. Set five seconds, start it, and let it ring. A press brings you back to `Setting` with the same total, ready to go again.

## Step 5: Pause and resume without losing time

Pausing is where the end-time idea pays off. When you pause, save how many milliseconds were left. When you resume, set a new end time that far into the future:

```makecode
let remaining = 0
input.onButtonPressed(Button.B, function () {
    if (state == "SETTING" && total > 0) {
        endTime = control.millis() + total * 1000
        state = "RUNNING"
    } else if (state == "RUNNING") {
        remaining = endTime - control.millis()
        state = "PAUSED"
    } else if (state == "PAUSED") {
        endTime = control.millis() + remaining
        state = "RUNNING"
    } else if (state == "RINGING") {
        state = "SETTING"
    }
})
```

Here's that arithmetic on its own, with made-up clock readings. Step through and watch `remaining` survive a 22-second pause.

:::trace Pausing a 20-second timer for 22 seconds
```python
now = 0
end_time = now + 20000
now = 8000
remaining = end_time - now
now = 30000
end_time = now + remaining
left = (end_time - now) // 1000
print("seconds left after resuming:", left)
```
:::

Eight seconds had passed, so twelve were left, and twelve are still left after the break. Without saving `remaining`, resuming would use the old `endTime`, which is already in the past, and the timer would ring the instant you resumed.

Give `Paused` something to show in the drawing loop, a classic pause symbol:

```makecode
basic.forever(function () {
    if (state == "PAUSED") {
        basic.showLeds(`
            . # . # .
            . # . # .
            . # . # .
            . # . # .
            . # . # .
            `)
    }
})
```

In the finished program this becomes one more `else if` branch in the main loop rather than a second `forever`.

## Step 6: Shake to cancel

One handler, no conditions needed: from any state, shaking returns to `Setting`. In the simulator, a **SHAKE** button appears on the board once your code uses a gesture.

```makecode
input.onGesture(Gesture.Shake, function () {
    state = "SETTING"
})
```

## The finished program

```makecode title="countdown-timer"
let state = "SETTING"
let total = 0
let endTime = 0
let remaining = 0
input.onButtonPressed(Button.A, function () {
    if (state == "SETTING") {
        total = Math.min(total + 5, 60)
    } else if (state == "RINGING") {
        state = "SETTING"
    }
})
input.onButtonPressed(Button.B, function () {
    if (state == "SETTING" && total > 0) {
        endTime = control.millis() + total * 1000
        state = "RUNNING"
    } else if (state == "RUNNING") {
        remaining = endTime - control.millis()
        state = "PAUSED"
    } else if (state == "PAUSED") {
        endTime = control.millis() + remaining
        state = "RUNNING"
    } else if (state == "RINGING") {
        state = "SETTING"
    }
})
input.onGesture(Gesture.Shake, function () {
    state = "SETTING"
})
basic.forever(function () {
    if (state == "SETTING") {
        basic.showNumber(total)
    } else if (state == "RUNNING") {
        let left = Math.ceil((endTime - control.millis()) / 1000)
        if (left <= 0) {
            state = "RINGING"
        } else if (left > 9) {
            led.plotBarGraph(left, total)
        } else {
            basic.showNumber(left)
        }
    } else if (state == "PAUSED") {
        basic.showLeds(`
            . # . # .
            . # . # .
            . # . # .
            . # . # .
            . # . # .
            `)
    } else if (state == "RINGING") {
        basic.showIcon(IconNames.Target)
        music.playTone(988, 200)
        basic.clearScreen()
        basic.pause(200)
    }
})
```

Now test every arrow in the diagram, not just the happy path. Tick each row off in the simulator:

| Do this | You should see |
| --- | --- |
| Press B with the total at 0 | Still `0`; nothing starts |
| A three times, then B | Bars shrink, then 9 down to 1 |
| B while running, wait 10 s, B again | Pause bars, then the countdown continues from where it stopped |
| Let it reach zero | Flashing target and beeps |
| A or B while ringing | Back to the total you set |
| SHAKE while running or paused | Back to the total you set |
| A while running | Nothing changes (no arrow for it) |

:::quiz
Q: Why does the timer store `endTime` instead of looping `basic.pause(1000)` and subtracting one each time?
- [ ] `basic.pause` doesn't work inside `forever`
  It works; the trouble is what it costs.
- [x] The loop never blocks, so it can redraw, notice a pause, and stop the moment the state changes
  Comparing the clock with a saved end time takes no waiting at all, and pausing becomes simple arithmetic.
- [ ] `control.millis()` is more accurate than the LEDs
  Accuracy isn't the point; staying responsive is.

Q: You remove the line `remaining = endTime - control.millis()` from the pause branch. What happens when you resume?
- [ ] The timer resumes normally
  `remaining` would still be 0 from the start, so resuming can't work normally.
- [x] It rings almost immediately, because the new end time is "now + 0"
  With `remaining` stuck at 0, `endTime` becomes the current time and `left` drops to 0 on the next pass.
- [ ] It starts over from the full total
  Nothing in the resume branch reads `total`.

Q: Where does the `Running` to `Ringing` transition happen, and why there?
- [ ] In button A's handler, because A stops the alarm
  A stops the alarm *after* it rings; something else has to start it.
- [x] In the `forever` loop, because "time is up" isn't an input event, so the code that already watches the clock makes the move
  Not every transition comes from a button. Time-based ones belong wherever the clock is checked.
- [ ] In the shake handler
  Shake only cancels; it never starts the alarm.
:::

:::takeaways
- Draw the state diagram first; each arrow becomes one `if`/`else if` branch in a handler, and each state becomes a branch of the drawing loop.
- Count down with a saved end time and `control.millis()`, never a chain of pauses.
- To pause a timer, save what's left; to resume, set a new end time that far ahead.
- Time-based transitions happen in the loop that watches the clock.
- Test every arrow, including the "nothing should happen" ones.
:::

## Ideas to extend it

- Make A add 5 seconds, but touch the logo (V2's `input.onLogoEvent(TouchButtonEvent.Pressed, ...)`) to add a whole minute.
- Send `radio.sendString("DONE")` when the timer rings, so a second board across the room alerts you too.
- Add a "snooze" arrow from `Ringing`: B sets a new end time 10 seconds ahead instead of going back to `Setting`.
- Replace the scrolling total in `Setting` with a bar graph so the display never lags.
