## The starter skeleton

Start every network project like this: all the variables from your plan, the radio group, and the role picker, with empty spots for each milestone. Paste it into the JavaScript view of a new MakeCode project.

```makecode title="voting-starter"
let role = "NONE"
let state = "WAITING"
let myId = randint(1, 30000)
let myVote = ""
let tries = 0
let retryAt = 0
let votesA = 0
let votesB = 0
let voted: number[] = []
let poll = 0
let shown = ""
radio.setGroup(31)
basic.showString("?")
function draw() {
    // M1: one screen per role and state
}
input.onButtonPressed(Button.A, function () {
    if (role == "NONE") {
        role = "VOTER"
    }
    // M2 and M3: teacher opens a poll, voter votes A
})
input.onButtonPressed(Button.B, function () {
    if (role == "NONE") {
        role = "TEACHER"
        state = "CLOSED"
    }
    // M2 and M3: teacher closes the poll, voter votes B
})
basic.forever(function () {
    let view = role + state + voted.length
    if (view != shown) {
        shown = view
        draw()
    }
    // M4: resend or give up
})
```

Two things here are worth a look. `myId = randint(1, 30000)` gives each voter a random id when it starts, so the teacher can tell voters apart without names; two voters picking the same number is possible but rare in a class. And the `forever` loop builds a `view` string from everything the screen depends on, then calls `draw()` only when that string changes. The screen updates the moment the state changes, and the loop never wastes time redrawing an unchanged picture.

## Milestone 1: Roles and screens

Fill in `draw()` with one picture per role and state. Choosing pictures now makes every later test easier, because you can read a board's state off its face.

```makecode
function draw() {
    if (role == "TEACHER") {
        if (state == "OPEN") {
            basic.showNumber(voted.length)
        } else if (votesA > votesB) {
            basic.showString("A")
        } else if (votesB > votesA) {
            basic.showString("B")
        } else {
            basic.showString("=")
        }
    } else if (role == "VOTER") {
        if (state == "WAITING") {
            basic.showIcon(IconNames.Asleep)
        } else if (state == "VOTING") {
            basic.showIcon(IconNames.Target)
        } else if (state == "SENT") {
            basic.showArrow(ArrowNames.North)
        } else if (state == "DONE") {
            basic.showIcon(IconNames.Yes)
        } else if (state == "FAILED") {
            basic.showIcon(IconNames.No)
        }
    }
}
```

**Test M1.** Press A on the top board: a sleeping face (a voter, waiting). Press B on the bottom board: `=` (a teacher with no results yet). Both boards answered the role picker, and each shows its state. Done.

## Milestone 2: Open and close the poll

The teacher's A and B now open and close polls. Opening resets the tallies and the list of ids that have voted. Voters listen for the two strings.

```makecode
input.onButtonPressed(Button.A, function () {
    if (role == "NONE") {
        role = "VOTER"
    } else if (role == "TEACHER" && state == "CLOSED") {
        votesA = 0
        votesB = 0
        voted = []
        state = "OPEN"
        radio.sendString("OPEN")
    }
})
radio.onReceivedString(function (receivedString) {
    if (role == "VOTER") {
        if (receivedString == "OPEN") {
            state = "VOTING"
        } else if (receivedString == "CLOSED") {
            state = "WAITING"
        }
    }
})
```

Closing goes in the teacher's B branch: `else if (role == "TEACHER" && state == "OPEN") { state = "CLOSED"; radio.sendString("CLOSED") }`. Notice that `CLOSED` sends a voter to `Waiting` from *any* state, which answers the planning lesson's question about a vote still being resent when the poll ends.

**Test M2.** Teacher presses A: the teacher shows `0` and the voter's face changes to a target. Teacher presses B: the teacher shows `=`, the voter goes back to sleep.

## Milestone 3: Votes and the tally

A voter's A or B sends a vote whose value is its id. Both buttons do the same thing with a different letter, so they share a function:

```makecode
function sendVote() {
    radio.sendValue(myVote, myId)
    tries += 1
    retryAt = control.millis() + 1000 + randint(0, 500)
}
function castVote(choice: string) {
    if (state == "VOTING" || state == "FAILED") {
        myVote = choice
        tries = 0
        state = "SENT"
        sendVote()
    }
}
```

In the voter branches of the button handlers, call `castVote("A")` and `castVote("B")`. The teacher counts a vote only the first time it sees an id:

```makecode
radio.onReceivedValue(function (name, value) {
    if (role == "TEACHER" && state == "OPEN" && (name == "A" || name == "B")) {
        if (voted.indexOf(value) < 0) {
            voted.push(value)
            if (name == "A") {
                votesA += 1
            } else {
                votesB += 1
            }
        }
    }
})
```

`voted.indexOf(value) < 0` means "this id isn't in the list yet". That one check is the difference between a fair vote and one where a stuck button or a resend counts twice.

**Test M3.** Open a poll, press B on the voter, close the poll. The teacher shows `B`. Open a new poll and press A on the voter three times in a row: the teacher's count stays at `1`, because the voter left `Voting` after the first press.

## Milestone 4: Receipts and retries

Without a receipt, the voter's arrow stays up forever and nobody knows whether the vote counted. The teacher now acknowledges every vote it hears (even repeats, since a repeat means the voter missed the first `ack`), and the voter waits for an `ack` carrying its own id. Add the `ack` line at the end of the teacher's branch, and a voter branch:

```makecode
radio.onReceivedValue(function (name, value) {
    if (role == "TEACHER" && state == "OPEN" && (name == "A" || name == "B")) {
        if (voted.indexOf(value) < 0) {
            voted.push(value)
            if (name == "A") {
                votesA += 1
            } else {
                votesB += 1
            }
        }
        radio.sendValue("ack", value)
    } else if (role == "VOTER" && state == "SENT" && name == "ack" && value == myId) {
        state = "DONE"
    }
})
```

The `forever` loop handles the timeout. If no receipt has come by `retryAt`, resend, up to three tries in total:

```makecode
basic.forever(function () {
    if (role == "VOTER" && state == "SENT" && control.millis() >= retryAt) {
        if (tries < 3) {
            sendVote()
        } else {
            state = "FAILED"
        }
    }
    let view = role + state + voted.length
    if (view != shown) {
        shown = view
        draw()
    }
})
```

Why the `randint(0, 500)` in `retryAt`? Imagine 25 voters whose votes collided in the air at the same instant. If they all retried after exactly one second, they'd collide again. A random extra wait spreads the retries out so most get through on the second try.

**Test M4.** A vote now shows an arrow, then a tick. To test the failure path, put `//` in front of `radio.sendValue("ack", value)` and vote again: the arrow stays up for a few seconds while the voter retries, then turns into a cross. Press A or B on the cross to try again. Remove the `//` when you're done, and check that the tally still says 1 after all those retries.

## Milestone 5: Results out

When the teacher closes a poll, it streams the result over serial and writes one row to the data log, with the column names from the plan. Set the log up when the board becomes the teacher, so voter boards never touch the log:

```makecode
input.onButtonPressed(Button.B, function () {
    if (role == "NONE") {
        role = "TEACHER"
        state = "CLOSED"
        datalogger.includeTimestamp(FlashLogTimeStampFormat.Seconds)
        datalogger.setColumnTitles("poll", "A", "B", "voters")
    } else if (role == "VOTER") {
        castVote("B")
    } else if (role == "TEACHER" && state == "OPEN") {
        state = "CLOSED"
        radio.sendString("CLOSED")
        poll += 1
        serial.writeValue("A", votesA)
        serial.writeValue("B", votesB)
        datalogger.log(datalogger.createCV("poll", poll), datalogger.createCV("A", votesA), datalogger.createCV("B", votesB), datalogger.createCV("voters", voted.length))
    }
})
```

**Test M5.** Run two polls in the simulator, then click **Show data**: you'll see the `A` and `B` values from each poll. On a real V2 teacher board, MY_DATA has one row per poll.

## Chart a week of polls

Here's what the teacher's log might hold after a week of one poll a day on "Should we have music during practice time? A = yes, B = no". The first cell saves the CSV; the second charts it.

```python run title="save_polls.py"
polls = """Time (seconds),poll,A,B,voters
95,1,9,14,23
2510,2,11,13,24
4980,3,15,10,25
7420,4,17,9,26
9910,5,19,7,26
"""
with open("polls.csv", "w") as f:
    f.write(polls)
print("saved polls.csv")
```

```python run alt="Stacked bar chart of five polls: yes votes grow from 9 to 19 while no votes shrink from 14 to 7, and total voters rise from 23 to 26" caption="Votes per poll"
import csv
import matplotlib.pyplot as plt

with open("polls.csv") as f:
    rows = list(csv.DictReader(f))
numbers = [int(r["poll"]) for r in rows]
yes = [int(r["A"]) for r in rows]
no = [int(r["B"]) for r in rows]

plt.bar(numbers, yes, label="A: yes", color="#4a90d9")
plt.bar(numbers, no, bottom=yes, label="B: no", color="#d98c4a")
plt.xlabel("poll")
plt.ylabel("votes")
plt.xticks(numbers)
plt.legend()
for r in rows:
    print("poll", r["poll"], "turnout", r["voters"], "yes share",
          round(100 * int(r["A"]) / int(r["voters"])), "%")
```

The class swung from 39% yes to 73% yes over the week, and turnout crept up too. Because the log has a `voters` column, you can check the numbers: A plus B always equals voters, so no vote was counted twice or lost after it was acknowledged.

## Mapping the milestones onto other projects

| Milestone | Relay race timer | Climate network | Sound monitor |
| --- | --- | --- | --- |
| M1 Roles and screens | start gate, finish gate | station number, hub | zone number, display |
| M2 First message | `GO` from start to finish | one reading reaches the hub | one level reaches the display |
| M3 Core job | finish gate times the run with its own clock | hub tracks every station | display shows the loudest zone, averaged |
| M4 Failure feedback | finish gate replies; start gate shows a cross if no reply | per-station "last heard" | zone goes grey if silent |
| M5 Data out | lap times to the log | readings to the log | levels per zone to the log |

:::quiz
Q: The teacher sends an `ack` even when it has already counted that id. Why?
- [ ] To count the vote a second time
  The `indexOf` check makes sure it isn't counted again.
- [x] A repeat means the voter never got the first `ack`, so the teacher must answer again or the voter will end up showing a cross
  Acknowledging repeats is safe because counting is guarded separately by the list of ids.
- [ ] Because `radio.sendValue` must always be answered
  The radio never requires an answer; this is a rule of your protocol.

Q: You remove `randint(0, 500)` from `retryAt`, so every retry happens exactly one second later. When does that matter?
- [ ] Never, because messages can't collide
  Two boards sending at the same instant can garble each other's packets.
- [x] With many voters: votes that collided once would all retry at the same moment and collide again
  The random extra wait spreads the retries out, which is why many networks use a random back-off.
- [ ] Only in the simulator
  The simulator rarely loses packets at all; collisions are a real-hardware, many-board problem.

Q: Why does the `forever` loop compare `view` with `shown` before calling `draw()`?
- [x] So the screen is redrawn only when something it depends on changes, keeping the loop fast enough to check retry times
  `showIcon` and `showNumber` take time to display. Redrawing an unchanged picture every pass would slow the timeout checks.
- [ ] Because `draw()` can only be called once
  It's an ordinary function and can be called any number of times.
- [ ] To stop voters from voting twice
  The voter's state and the teacher's id list handle that.
:::

:::takeaways
- Start from a skeleton that already holds the plan: variables, group, roles, and empty milestone spots.
- Test each milestone before starting the next, including the "nothing should happen" cases.
- A unique id per sender lets the receiver ignore repeats and address receipts.
- Receipts, a timeout, and a few retries with a random wait turn lost messages into visible, recoverable failures.
- Log one row per meaningful event, with columns you can cross-check later.
:::

## Ideas to extend it

- Three or four options: use the logo touch (`input.onLogoEvent`) or A+B as extra choices, and add columns to the log.
- Let the teacher see turnout live: plot `voted.length` against the class size as a bar graph while the poll is open.
- Anonymous results screen: a third role that only hears `CLOSED` and the teacher's results message, for projecting on the board.
