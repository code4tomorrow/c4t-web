Lay a micro:bit flat on a desk, where it isn't moving at all, and ask its accelerometer how much force it feels. You'd expect zero. The answer is about 1023, pointing straight down through the board.

That's gravity. An accelerometer can't tell "sitting still on Earth" from "speeding upward at one g in a rocket", so it reports gravity as a steady pull. That pull is how the board knows which way is up.

## The accelerometer measures force on three axes

Readings come in **milli-g** (mg), thousandths of the pull of Earth's gravity, so about 1000 means "one g". The board measures along three directions at once:

- **x**: left and right, across the screen.
- **y**: forward and back, between the logo end and the pin end.
- **z**: up and down, straight through the board.

Flat on a desk with the screen facing up, the board reads x = 0, y = 0, and z = -1023. Tilt it and gravity shifts from z into x or y. **Input › acceleration (mg)** reads one axis, or **strength**, which combines all three into a single size of force.

```makecode
basic.forever(function () {
    serial.writeValue("x", input.acceleration(Dimension.X))
    serial.writeValue("y", input.acceleration(Dimension.Y))
    serial.writeValue("z", input.acceleration(Dimension.Z))
    basic.pause(100)
})
```

**serial write value** (in **Serial**, under **Advanced**) sends a labelled number to the computer ten times a second. Run it, click the **Show data** button that appears under the simulator, and move your pointer over the board to tilt it. You'll get a chart like this:

```python run alt="Three lines of model accelerometer readings over 6 seconds. From 0 to 2 seconds x and y sit near 0 and z near minus 1023. From 2 to 4 seconds the board is tilted right: x rises to about 720 and z moves up to about minus 720. From 4 to 5 seconds all three swing quickly between roughly minus 1500 and plus 1400 during a shake. From 5 seconds on the readings return to flat." caption="Model readings shaped like a real recording: flat, tilted right, shaken, then flat again. Real data looks like this, with a little jitter everywhere."
import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(7)
t = np.arange(0, 6, 0.02)  # 50 readings per second
x = np.zeros_like(t)
y = np.zeros_like(t)
z = np.full_like(t, -1023.0)
tilt = (t >= 2) & (t < 4)
x[tilt], z[tilt] = 720, -720
shake = (t >= 4) & (t < 5)
x[shake] = 1400 * np.sin(2 * np.pi * 6 * t[shake])
y[shake] = 600 * np.sin(2 * np.pi * 6 * t[shake] + 1)
z[shake] = -1023 + 500 * np.sin(2 * np.pi * 6 * t[shake] + 2)
for axis in (x, y, z):
    axis += rng.normal(0, 25, t.size)

plt.figure(figsize=(7, 3.4))
plt.plot(t, x, label="x", color="#d1495b")
plt.plot(t, y, label="y", color="#00798c")
plt.plot(t, z, label="z", color="#e09f3e")
for start, label in [(0.05, "flat"), (2.05, "tilted right"), (4.05, "shaken"), (5.05, "flat")]:
    plt.text(start, 1550, label, fontsize=9)
plt.ylim(-1700, 1750)
plt.xlabel("time (s)")
plt.ylabel("acceleration (mg)")
plt.legend(loc="lower left", ncol=3)
plt.grid(alpha=0.3)
plt.tight_layout()
```

Flat, gravity sits entirely in z. Tilted 45 degrees to the right, it splits between x and z, about 720 each, because the total pull is still about 1023. Shaken, all three swing far past one g as your hand adds force on top of gravity. And every line is fuzzy: even a board at rest never reports exactly the same number twice.

## Gestures: the board recognizes common movements for you

Deciding "was that a shake?" from raw numbers is real work, so the micro:bit does it for you. **Input › on shake** is an event with a dropdown of gestures: **shake**, **logo up**, **logo down**, **screen up**, **screen down**, **tilt left**, **tilt right**, **free fall**, and high-force jolts of **3g**, **6g**, and **8g**.

The shake gesture fires when the readings swing strongly back and forth several times in quick succession, which is exactly the shaken section of the chart. That makes dice almost a one-liner:

```makecode
input.onGesture(Gesture.Shake, function () {
    basic.showNumber(randint(1, 6))
})
```

When a program uses shake, the simulator adds a **SHAKE** button to the board. Swap **show number** for the dice faces from the last practice lesson and you have real dice. For the tilt gestures, move your pointer to one side of the simulator board.

Gestures, like buttons, come as an event and as a check. **is screen down gesture** (`input.isGesture(Gesture.ScreenDown)`) answers whether the board is face down *right now*, which suits "while" behavior, such as blanking the screen while the board lies face down.

## The compass: which way the top edge points

**Input › compass heading (°)** gives a number from 0 to 359: the direction the board's top edge (the logo end) is pointing, measured clockwise from magnetic north. So 0 is north, 90 east, 180 south, and 270 west. Hold the board flat, screen up, with the top edge pointing where you want to measure.

```makecode
basic.forever(function () {
    let heading = input.compassHeading()
    if (heading < 45 || heading >= 315) {
        basic.showString("N")
    } else if (heading < 135) {
        basic.showString("E")
    } else if (heading < 225) {
        basic.showString("S")
    } else {
        basic.showString("W")
    }
})
```

North needs two ranges, `heading < 45` and `heading >= 315`, because the scale wraps around: 350 degrees and 10 degrees are both nearly north. In the simulator a compass needle appears around the board; drag it around the logo to change the heading.

On a real board the compass must be **calibrated** first, because every board and room has slightly different magnetic surroundings. The first time a program reads the compass, the screen scrolls **TILT TO FILL SCREEN**. Tilt the board slowly in every direction until all 25 LEDs are lit; a smiley means you're done. The calibration lasts until you download a new program, and **calibrate compass** (`input.calibrateCompass()`) redoes it on purpose.

## Light and temperature: slow, steady measurements

**light level** reads from 0 (dark) to 255 (bright), using the LED screen itself as the sensor. The very first reading in a program is always 0 while the sensor switches on, so a program that reacts to darkness should ignore its first reading or wait a moment.

**temperature (°C)** reads the temperature of the processor chip, which is usually close to the air around it. A board that's been busy, or held in a warm hand, reads a degree or two high. Compare it with a real thermometer once and you can correct for the difference in code.

```makecode
basic.forever(function () {
    led.plotBarGraph(input.lightLevel(), 255)
})
```

**plot bar graph** (in **LED**) turns a number into a bar: here, the brighter the room, the more LEDs light. In the simulator, drag the light-level control that appears on the board; temperature gets a thermometer slider in the same way.

## The microphone (V2 only): loudness, not words

The V2's microphone sits behind the small hole on the front, with an LED beside it that lights while it listens. **sound level** reads loudness from 0 (quiet) to 255 (loud). It can't record or recognize words, only how loud things are. There's also an event, **on loud sound** (`input.onSound(DetectedSound.Loud, ...)`), and **set loud sound threshold** to choose what counts as loud.

```makecode
input.onSound(DetectedSound.Loud, function () {
    basic.showIcon(IconNames.Surprised)
    basic.pause(500)
    basic.clearScreen()
})
```

Clap near a V2 and a surprised face appears. The simulator switches to a V2 board and shows a sound-level slider so you can "clap" by dragging it.

## Noisy readings need a margin

Every sensor jitters. A night light that switches on below 40 flickers when the room sits around 40, because readings of 38, 41, 39, 42 cross the line again and again. The fix is a **margin**: switch on below 35, but off only above 45, and in between keep doing whatever you were doing. The build-along uses the same idea to make a step counter count each step exactly once.

:::warning
**The compass jumps around or points the wrong way.** It hasn't been calibrated since the last download, or it's near metal or a magnet: laptops, phones, speakers, steel table frames. Recalibrate away from them, then hold the board flat. In the simulator the compass is always perfect, so this only shows up on real hardware.
:::

:::warning
**927 on the screen as soon as the program starts.** The program uses **sound level** or **on loud sound** and the board is a V1, which has no microphone. Use a V2, or test that part in the simulator.
:::

:::quiz
Q: A micro:bit lies flat and perfectly still, screen up. What does `input.acceleration(Dimension.Z)` read?
- [ ] 0, because nothing is moving
  The accelerometer always feels gravity, even at rest.
- [x] About -1023
  Gravity pulls straight down through the board, about one g along z.
- [ ] About 1023 on all three axes
  Flat, all of gravity is on z; x and y read near 0.

Q: You want the screen to go blank *while* the board lies face down and come back when it's turned over. Which fits best?
- [ ] **on screen down** to clear the screen
  An event runs once when it happens; nothing would bring the picture back.
- [x] A forever loop that checks **is screen down gesture**
  "While" is about what's true right now, so a check inside forever suits it.
- [ ] **on shake** to clear the screen
  Shaking has nothing to do with which way the board faces.

Q: The compass reads 300. Which way is the top edge pointing, using the four-direction program above?
- [ ] North
  North starts at 315 in that program; 300 is just short of it.
- [x] West
  300 is at least 225 and less than 315, so the program shows W.
- [ ] East
  East is around 90, on the other side of the circle.

Q: A night light turns on when `input.lightLevel() < 40` and off otherwise. At dusk it flickers rapidly. What's the best fix?
- [ ] Check the light level less often
  Slower checks just make it flicker slowly.
- [ ] Change 40 to 30
  The flicker moves to a different light level but doesn't go away.
- [x] Turn on below 35 and off only above 45
  The gap between the two values absorbs the jitter, so small wobbles don't switch it.
:::

:::takeaways
- The accelerometer reports force in milli-g on x, y, and z; at rest it reads gravity, about 1023 in total.
- Gesture events (shake, tilt, screen down, free fall) do the pattern-spotting for you; **is ... gesture** checks the current pose.
- Compass headings run from 0 to 359 clockwise from north, need calibration on a real board, and suffer near metal.
- Light reads 0 to 255 (first reading 0), temperature reads the chip in °C, and the V2 microphone reads loudness 0 to 255.
- Use two thresholds with a gap between them so jittery readings don't flip a decision back and forth.
:::
