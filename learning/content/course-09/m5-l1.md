Thirty students in one room press button A at the same moment. Every micro:bit in the room flashes a heart, including the ones that were supposed to stay dark. Nobody wrote a bug in the usual sense. They all left their radios on the same default group, so every board heard every other board.

That scene holds the core idea: messages go to everyone listening, and a group number you pick decides who is listening.

## A radio message is a shout, not a phone call

A phone call connects two people. A micro:bit radio message is more like shouting across a playground: anyone close enough who is paying attention hears it. The board's 2.4 GHz radio (the band Wi-Fi and Bluetooth use) broadcasts each message as one short packet. Three facts follow:

- **No address.** You can't send to "Maya's badge". Every board in range and in your group gets the packet.
- **No receipt.** The sender never learns whether anyone heard. If you need to know, the receiver has to send a reply, which you'll build in the next lesson.
- **Short range, short packets.** Think "same room or the next one", carrying a number, a short text, or a label plus a number.

## Groups keep your conversation private

`radio.setGroup(id)` tunes your board to a group from 0 to 255. If you never call it, the board uses group 0, which is why the classroom above went wrong. Put `setGroup` in **on start** so it runs before any message goes out, and agree on the number with your partner.

```makecode
radio.setGroup(42)
input.onButtonPressed(Button.A, function () {
    radio.sendString("HI")
})
radio.onReceivedString(function (receivedString) {
    basic.showString(receivedString)
})
```

Paste this into the JavaScript view at makecode.microbit.org. As soon as a radio block is in the project, the simulator draws a **second micro:bit** under the first. Press A on the top board and the bottom board scrolls `HI`.

```text
Top board:    (you press A)
Bottom board: H ... I   (scrolls across the LEDs)
```

Both simulated boards run the same program, so they always share a group. MakeCode's reference notes that `setGroup` only takes effect on real hardware, which is where groups matter: real badge pairs on groups 42 and 43 can sit side by side without hearing each other.

:::note
A group is a filter, not a lock. Anyone who sets their board to 42 hears your messages. Never send anything over micro:bit radio that you'd mind the whole room reading.
:::

Here is the filtering rule as a tiny Python model: each board compares the packet's group with its own, then keeps or drops the message.

:::trace Which boards keep the message?
```python
boards = {"Ana": 1, "Ben": 1, "Cat": 2}
sender_group = 1
message = "HI"
for name in boards:
    if boards[name] == sender_group:
        print(name, "shows", message)
    else:
        print(name, "ignores it")
```
:::

## Three kinds of message, three matching receivers

MakeCode can send three kinds of packet. Each one has its own receive block, and a board only reacts if it has the receive block that matches what was sent.

| Send block | Receive block | What it carries | Size limit |
| --- | --- | --- | --- |
| `radio.sendNumber(n)` | `radio.onReceivedNumber` | one number | none worth worrying about |
| `radio.sendString(s)` | `radio.onReceivedString` | text | 19 characters |
| `radio.sendValue(name, n)` | `radio.onReceivedValue` | a label and a number | label up to 8 characters |

`sendValue` is the one you'll use most for sensors, because the label says what the number means. A board that sends both temperature and light can label each reading, and the receiver sorts them out:

```makecode
radio.setGroup(42)
basic.forever(function () {
    radio.sendValue("temp", input.temperature())
    radio.sendValue("light", input.lightLevel())
    basic.pause(2000)
})
radio.onReceivedValue(function (name, value) {
    if (name == "temp") {
        basic.showNumber(value)
    } else if (name == "light") {
        led.plotBarGraph(value, 255)
    }
})
```

Drag the top board's temperature slider in the simulator and the bottom board's number follows. The `if` on `name` is the line that matters: without it, light readings would be shown as temperatures.

## One receive block per kind, with the decisions inside

A project can have only one `onReceivedString` block (and one each for numbers and values). To react to several different strings, make the decisions inside that one block:

```makecode
radio.onReceivedString(function (receivedString) {
    if (receivedString == "HI") {
        basic.showIcon(IconNames.Happy)
    } else if (receivedString == "BYE") {
        basic.showIcon(IconNames.Asleep)
    } else {
        basic.showString(receivedString)
    }
})
```

Inside a receive block, `radio.receivedPacket(RadioPacketProperty.SignalStrength)` tells you how strong the signal was: about -128 when barely heard, up to about -28 on a V2 board right beside you.

## The same program in Blocks, JavaScript, and MicroPython

**Blocks and JavaScript are two views of one MakeCode project.** The switch at the top of the editor flips between them and translates your code both ways, so a Blocks badge and a JavaScript badge download the same program and talk perfectly. (The switch also offers a Python view; that's still the same MakeCode project, spelled in Python.)

**MicroPython is a different system.** At python.microbit.org you write real Python and the micro:bit runs a small Python interpreter. Here's the `HI` program in MicroPython. It runs on a micro:bit or in that editor's simulator; desktop Python stops at line 1 with an import error, because the `microbit` module only exists on the device.

```python title="main.py"
from microbit import *
import radio

radio.config(group=42)
radio.on()

while True:
    if button_a.was_pressed():
        radio.send("HI")
    message = radio.receive()
    if message:
        display.scroll(message)
    sleep(20)
```

Five differences stand out:

1.  **Events versus a loop.** MakeCode uses event blocks ("when A is pressed…"). MicroPython has no radio event, so the program loops and *checks*: was A pressed since last time? Is a message waiting?
2.  **Asking for messages.** `radio.receive()` takes the next message from a small waiting line (three by default) or returns `None`. Stop calling it and new messages are dropped.
3.  **Setting the group.** `radio.config(group=42)` instead of `radio.setGroup(42)`.
4.  **Only text.** MicroPython's `radio.send` takes a string. To send a number, send `str(n)` and turn it back with `int(message)` on the other side.
5.  **Indentation instead of braces.** The lines inside `if` and `while` are indented; there are no `{ }`.

One difference is invisible: MakeCode wraps each message in its own packet format, which MicroPython's `radio.receive()` doesn't understand. A MakeCode badge and a MicroPython badge won't read each other's messages without extra work, so keep all the boards in a project on one system.

## Mistakes that make radio go silent

:::warning
**Groups don't match.** One board calls `radio.setGroup(12)`, the other `radio.setGroup(21)`, and messages vanish with no error. Fix: show the group on start with `basic.showNumber(12)` so you can compare boards at a glance.
:::

:::warning
**Sender and receiver use different kinds.** The sender calls `radio.sendString("5")` but the receiver only has `onReceivedNumber`. A string packet never triggers a number block. Fix: pick one kind and use the matching pair.
:::

:::warning
**Text cut short.** `radio.sendString("Meet at the gym after lunch")` arrives as `Meet at the gym aft`, because strings stop at 19 characters. `sendValue` labels stop at 8, so `"temperature"` arrives as `temperat` and never matches a check for the full word. Fix: short labels like `"temp"`.
:::

:::quiz
Q: Board A is on group 5 and sends `radio.sendString("GO")`. Board B is on group 5 and board C never calls `setGroup`. Both have an `onReceivedString` block. What happens?
- [ ] Both B and C show GO
  C is on the default group 0, so it drops packets from group 5.
- [x] Only B shows GO
  B shares group 5 with A. C sits on group 0 and never sees the packet.
- [ ] Neither shows GO, because A didn't name a receiver
  Radio messages have no receiver address; everyone in the group gets them.

Q: The sender runs `radio.sendValue("brightness", 60)` and the receiver checks `if (name == "brightness")`. What does the receiver do?
- [ ] Shows 60 as expected
  It would if the label fit, but `brightness` has 10 characters and labels stop at 8.
- [x] Nothing visible: the label arrives as `brightne`, so the `if` is false
  The packet does arrive and the receive block runs, but the shortened name never equals `"brightness"`.
- [ ] Crashes with an error
  MakeCode never crashes over a long label; it shortens it without telling you.

Q: Why does the MicroPython version call `radio.receive()` on every pass of the loop?
- [ ] To turn the radio on
  `radio.on()` does that, once, before the loop.
- [x] MicroPython has no radio event, so the program must check its waiting line for new messages
  Messages wait in a small queue until your code takes them out with `radio.receive()`.
- [ ] To send a reply to the other board
  Receiving never sends anything; only `radio.send` does.

Q: One badge is coded in MakeCode Blocks and the other in MakeCode JavaScript, both on group 7. Can they talk?
- [x] Yes, because Blocks and JavaScript produce the same program
  They're two views of one project, so the downloaded code and its packet format are identical.
- [ ] No, they need the same editor view
  The view only changes how you see the code, not what runs on the board.
- [ ] Only if both use `sendString`
  Any matching send and receive pair works, whichever view you wrote it in.
:::

:::takeaways
- A radio message is a broadcast: every board in range on the same group hears it, and the sender gets no receipt.
- `radio.setGroup` (0–255) goes in on start; boards that skip it share group 0 with everyone else.
- Match the pairs: `sendNumber`/`onReceivedNumber`, `sendString`/`onReceivedString`, `sendValue`/`onReceivedValue`. Strings stop at 19 characters, value labels at 8.
- Use one receive block per kind and decide inside it with `if`.
- Blocks and JavaScript are one MakeCode program; MicroPython loops and checks instead of using events, and its radio messages aren't compatible with MakeCode's.
:::
