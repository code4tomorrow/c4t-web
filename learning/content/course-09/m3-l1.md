Type `led.plot(5, 2)` into a program and run it. Nothing lights up. There's no error message and no crash; the board simply ignores you. The screen has five columns, but they're numbered 0 to 4, so column 5 doesn't exist.

That one fact, counting from zero, explains most of the bugs people hit when they start drawing on the micro:bit. Once you have the coordinate system straight, the screen becomes a tiny game display you control one LED at a time.

## Every LED has an address

Each of the 25 LEDs has an address made of two numbers. **x** is the column, counting from the left edge. **y** is the row, counting from the top. Both run from 0 to 4, so the top-left LED is (0, 0) and the center is (2, 2).

```python run alt="A 5 by 5 grid of LED circles, each labelled with its (x,y) coordinates. (0,0) is top left, (4,0) top right, (0,4) bottom left, and (2,2) the center. The LEDs at (0,0), (4,0), and (2,2) are lit red." caption="The 25 LED addresses. The red LEDs are the ones lit by the program below."
import matplotlib.pyplot as plt

lit = {(0, 0), (4, 0), (2, 2)}
fig, ax = plt.subplots(figsize=(4.6, 4.6))
for y in range(5):
    for x in range(5):
        color = "#e23b3b" if (x, y) in lit else "#cfcfcf"
        ax.add_patch(plt.Circle((x, y), 0.27, color=color))
        ax.text(x, y + 0.42, f"({x},{y})", ha="center", va="center", fontsize=8)
ax.set_xlim(-0.6, 4.6)
ax.set_ylim(4.8, -0.6)
ax.set_aspect("equal")
ax.set_xticks(range(5))
ax.set_yticks(range(5))
ax.xaxis.tick_top()
ax.xaxis.set_label_position("top")
ax.set_xlabel("x: column, counted from the left")
ax.set_ylabel("y: row, counted from the top")
for side in ax.spines.values():
    side.set_visible(False)
```

Notice that y grows *downward*, the opposite of a math graph. Hold the board with the buttons on the left and right, the way it sits in the simulator, and (0, 0) is the top-left corner.

## Turn single LEDs on and off

```makecode
led.plot(0, 0)
led.plot(4, 0)
led.plot(2, 2)
basic.pause(1000)
led.toggle(2, 2)
```

These blocks live in the **LED** category. **plot x y** turns one LED on; **unplot x y** turns it off; **toggle x y** flips it. After the pause, the center LED goes dark because it was on and toggle flipped it. There's also **point x y**, a check that answers true if that LED is currently on. Under **LED › more**, **plot x y brightness** sets one LED to any brightness from 0 to 255.

:::

## Show blocks repaint the whole screen

The screen keeps a picture of all 25 LEDs in memory. **plot** and **unplot** change single dots in that picture. Every **show** block (show icon, show leds, show string, show number) replaces the entire picture at once. So order matters:

```makecode
basic.showString("d")
led.plot(0, 0)
```

This shows the letter "d" *and* lights the top-left corner. Swap the two lines and the corner vanishes, because show string repaints all 25 LEDs and wipes your plot.

There's a second difference. Show blocks wait for the screen if it's busy and then hold their picture for a while. **plot** never waits and never holds: it changes the LED instantly. That makes plot the right tool for things that move, like a player in a game, and show blocks the right tool for whole pictures and messages. If you plot while a scroll is running, the next frame of the scroll paints over your dot.

For a picture you design yourself, use **show leds** from **Basic** and click the squares. In JavaScript it's a grid of `#` (on) and `.` (off):

```makecode
basic.showLeds(`
    . # . # .
    . # . # .
    . . . . .
    # . . . #
    . # # # .
    `)
```

## Variables remember where things are

A **variable** is a named box that holds a value your program can change later. To move a dot, you need to remember where it is. Make one in **Variables › Make a Variable...**, then use **set** to give it a value and **change ... by** to adjust it.

```makecode
let x = 2
led.plot(x, 2)
input.onButtonPressed(Button.A, function () {
    led.unplot(x, 2)
    x += -1
    if (x < 0) {
        x = 0
    }
    led.plot(x, 2)
})
input.onButtonPressed(Button.B, function () {
    led.unplot(x, 2)
    x += 1
    if (x > 4) {
        x = 4
    }
    led.plot(x, 2)
})
```

Each handler follows the same four moves: erase the dot where it is, change `x`, keep `x` on the screen, draw the dot where it is now. The two `if` blocks are a **clamp**: they stop `x` at the edges. Step through what happens to `x` when you press B three times and then A twice:

:::trace Watch the clamp keep `x` between 0 and 4
```python
x = 2
presses = ["B", "B", "B", "A", "A"]
for press in presses:
    if press == "A":
        x = x - 1
    else:
        x = x + 1
    if x < 0:
        x = 0
    if x > 4:
        x = 4
    print(press, "-> dot at x =", x)
```
:::

The third B tries to make `x` equal 5, and the clamp pulls it back to 4. Without the clamp, `x` would become 5, `led.plot(5, 2)` would do nothing, and the dot would seem to vanish off the edge.

## Random numbers keep things unpredictable

**pick random 0 to 4** (in **Math**) gives a whole number from 0 to 4, and both ends are included. Games need it, or every round plays out identically.

```makecode
basic.forever(function () {
    led.toggle(randint(0, 4), randint(0, 4))
    basic.pause(100)
})
```

Ten times a second this flips a random LED, which makes a twinkling screen. Change the range to `randint(1, 6)` and you have a dice roll, which you'll draw properly in the practice lesson.

## Two more inputs: the logo and the pins

The V2's gold **logo** is a touch sensor. **on logo pressed** in **Input** has a dropdown with four choices: *pressed* (touch and let go), *touched* (the moment your finger arrives), *released* (the moment it leaves), and *long pressed*. There's also **logo is pressed**, a check you can use in forever, just like button is pressed.

The three large gold pads on the edge, labelled **0**, **1**, and **2**, work as touch inputs too. Hold the **GND** pad with one hand and touch pin 0 with the other, and **on pin P0 pressed** runs. In the simulator, just click the pad.

```makecode
let score = 0
input.onLogoEvent(TouchButtonEvent.Pressed, function () {
    score += 1
    basic.showNumber(score)
})
input.onPinPressed(TouchPin.P0, function () {
    score = 0
    basic.showNumber(score)
})
```

Single digits show without scrolling, which is why scores from 0 to 9 are easy to read in a game. From 10 upward, **show number** has to scroll.

:::warning
**A variable that never gets past 1.** If you write `let score = 0` *inside* a handler, a fresh `score` starting at zero is made on every press, so it always shows 1. Create the variable once, outside every handler (in blocks, put **set score to 0** in **on start**), and only *change* it inside.
:::

:::warning
**Swapped coordinates.** `led.plot(4, 1)` is column 4, row 1: near the top right. If your drawing comes out flipped along the diagonal, you've given (row, column) instead of (x, y). The column always comes first.
:::

:::takeaways
- x is the column from the left and y is the row from the top; both run from 0 to 4.
- plot, unplot, and toggle change one LED instantly; show blocks repaint the whole screen and hold.
- Plotting outside 0 to 4 does nothing, so clamp positions at the edges.
- Create variables once, outside handlers, and change them inside.
- The logo and the pins 0, 1, and 2 are extra touch inputs with their own events.
:::
