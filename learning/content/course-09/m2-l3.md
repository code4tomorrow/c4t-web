summary: Solve six short micro:bit problems that combine button events, button checks, icons, sound, and timing, then build a secret-knock lock as a challenge.

:::objectives
- Predict how long a sequence of show blocks and pauses really takes.
- Pick between an event and a check for each button task.
- Use a variable that a handler sets and a forever loop acts on.
- Plan a multi-step input sequence as a set of states.
:::

Every exercise runs in the simulator. Build it, predict what will happen, then run it. If the result surprises you, work out why before opening the solution; the surprise is where the learning is.

## Warm-up: how long is one pass?

```makecode
basic.forever(function () {
    basic.showIcon(IconNames.Happy)
    basic.showIcon(IconNames.Sad)
    basic.pause(400)
})
```

How long does one pass take, and which face is on screen longer?

:::solution
One pass takes 1.6 seconds: 600 ms for the happy face, 600 ms for the sad face, plus the 400 ms pause. The sad face is on screen for 1 second, because it stays visible through the pause, while the happy face gets only 0.6 seconds.
:::

### Exercise 1: A heartbeat at exactly 60 beats per minute

Make a heart that beats once per second: the big heart for half a second, then the small heart for half a second.

```text
big heart (0.5 s), small heart (0.5 s), big heart (0.5 s), ...
```

:::hint
In blocks, **show icon** always holds for 600 ms, which is too long. In JavaScript, `basic.showIcon` takes an optional second number: how many milliseconds to hold.
:::

:::solution
```makecode
basic.forever(function () {
    basic.showIcon(IconNames.Heart, 500)
    basic.showIcon(IconNames.SmallHeart, 500)
})
```

The second argument replaces the 600 ms default, so each picture holds for 500 ms and a full beat takes one second. The **show icon** block has no slot for that number, so do this one in the JavaScript view. For an all-blocks version, draw each heart with **show leds**, which holds for 400 ms, and add **pause (ms) 100** after each.
:::

### Exercise 2: Arrows that point at the button

Pressing A shows an arrow pointing at the A button; pressing B shows one pointing at B. Either arrow disappears by itself after 2 seconds. Pressing both together shows a small diamond.

```text
press A  ->  left arrow, blank after 2 s
press B  ->  right arrow, blank after 2 s
press A+B -> small diamond
```

:::hint
**show arrow** is in **Basic**. A is on the left of the board, so its arrow points west. A handler can pause and then clear the screen.
:::

:::solution
```makecode
input.onButtonPressed(Button.A, function () {
    basic.showArrow(ArrowNames.West)
    basic.pause(2000)
    basic.clearScreen()
})
input.onButtonPressed(Button.B, function () {
    basic.showArrow(ArrowNames.East)
    basic.pause(2000)
    basic.clearScreen()
})
input.onButtonPressed(Button.AB, function () {
    basic.showIcon(IconNames.SmallDiamond)
})
```

Each handler runs on its own, so pausing inside one doesn't freeze the others. Try pressing A, then quickly B: the right arrow replaces the left one, and the first handler's **clear screen** may blank it early. That's two handlers sharing one screen, the same problem the badge solved with modes.
:::

### Exercise 3: A two-level torch

While A is held, light every LED at full brightness. While B is held, light them dim. When neither is held, the screen is dark.

:::hint
"While held" means you're checking what's true right now, so this belongs in **forever** with **button A is pressed** and **button B is pressed** from **Input**. **set brightness** is in **LED › more**.
:::

:::solution
```makecode
basic.forever(function () {
    if (input.buttonIsPressed(Button.A)) {
        led.setBrightness(255)
        basic.showLeds(`
            # # # # #
            # # # # #
            # # # # #
            # # # # #
            # # # # #
            `)
    } else if (input.buttonIsPressed(Button.B)) {
        led.setBrightness(30)
        basic.showLeds(`
            # # # # #
            # # # # #
            # # # # #
            # # # # #
            # # # # #
            `)
    } else {
        basic.clearScreen()
    }
})
```

Events would be the wrong tool here: **on button pressed** runs only after you let go. You may notice the torch stays on for a moment after release. That's **show leds** holding its picture for 400 ms before the loop can check again.
:::

### Exercise 4: A tap counter that never goes negative

A adds one and shows the count. B subtracts one and shows the count, but never goes below zero. A+B resets to zero.

```text
A, A, A, B   ->  1, 2, 3, 2
B, B, B, B   ->  1, 0, 0, 0
A+B          ->  0
```

:::hint
Make a variable `count` in **Variables**. Before subtracting, use an **if** to check that `count` is bigger than 0.
:::

:::solution
```makecode
let count = 0
input.onButtonPressed(Button.A, function () {
    count += 1
    basic.showNumber(count)
})
input.onButtonPressed(Button.B, function () {
    if (count > 0) {
        count += -1
    }
    basic.showNumber(count)
})
input.onButtonPressed(Button.AB, function () {
    count = 0
    basic.showNumber(count)
})
```

`let count = 0` sits outside every handler, so all three share the same variable and it keeps its value between presses. If you put `let count = 0` *inside* the A handler, every press would start again from zero and the count would always show 1.
:::

### Exercise 5: A doorbell that chimes

Pressing A shows a house and plays a two-note "ding-dong" (a high note, then a lower one), then clears the screen.

:::hint
Use **play tone** from **Music** twice with **until done**, so the second note waits for the first. 659 Hz is a high E and 523 Hz is a C.
:::

:::solution
```makecode
input.onButtonPressed(Button.A, function () {
    basic.showIcon(IconNames.House)
    music.play(music.tonePlayable(659, music.beat(BeatFraction.Half)), music.PlaybackMode.UntilDone)
    music.play(music.tonePlayable(523, music.beat(BeatFraction.Whole)), music.PlaybackMode.UntilDone)
    basic.clearScreen()
})
```

With **in background**, both notes would start almost together and the chime would sound like one note. Now press A twice quickly: the second ring waits until the first finishes, because a second press of the same button queues behind the running handler.
:::

### Exercise 6: A crosswalk signal

The screen shows an X (don't walk). When someone presses B, wait 2 seconds, show a walking figure for 2 seconds, count down 5, 4, 3, 2, 1, then go back to the X. Pressing B again during the walk shouldn't add another walk afterward.

:::hint
Long sequences belong in **forever**, not in the handler. Let B set a variable `requested` to true; let forever check it, run the walk sequence, and set it back to false at the end.
:::

:::solution
```makecode
let requested = false
basic.forever(function () {
    if (requested) {
        basic.pause(2000)
        basic.showIcon(IconNames.StickFigure)
        basic.pause(2000)
        for (let index = 0; index <= 4; index++) {
            basic.showNumber(5 - index)
            basic.pause(250)
        }
        requested = false
    } else {
        basic.showIcon(IconNames.No)
    }
})
input.onButtonPressed(Button.B, function () {
    requested = true
})
```

The handler just raises a flag and finishes instantly, so presses are never delayed. A press during the walk sets `requested` to true when it's already true, and the reset at the end clears it, so it's ignored. The countdown uses **for index from 0 to 4** from **Loops**; `5 - index` turns 0 to 4 into 5 down to 1. A single digit holds for about three quarters of a second, so with the pause each number lasts about a second.
:::

### Challenge: A secret-knock lock

Make a lock that opens only after the sequence **A, A, B**. When it opens, show a tick and play a sound, then lock again. Any wrong press sends you back to the start, and shows an X for a moment.

Plan it as states before you write code. Each state answers one question: how much of the secret have I seen so far?

```mermaid caption="The lock's states; each press either moves forward or resets"
stateDiagram-v2
    state "nothing yet" as S0
    state "seen A" as S1
    state "seen A A" as S2
    state "open" as Open
    [*] --> S0
    S0 --> S1: A
    S1 --> S2: A
    S2 --> Open: B
    S0 --> S0: B
    S1 --> S0: B
    S2 --> S2: A
    Open --> S0: after the tick
```

:::hint
One number variable, `step`, can hold the state: 0, 1, or 2. Each handler looks at `step` and decides where to go. Look closely at the arrow from "seen A A" on another A: why does it stay put instead of resetting?
:::

:::solution
```makecode
let step = 0
input.onButtonPressed(Button.A, function () {
    if (step < 2) {
        step += 1
    }
})
input.onButtonPressed(Button.B, function () {
    if (step == 2) {
        basic.showIcon(IconNames.Yes)
        music.play(music.builtInPlayableMelody(Melodies.PowerUp), music.PlaybackMode.UntilDone)
        basic.clearScreen()
    } else {
        basic.showIcon(IconNames.No)
        basic.pause(500)
        basic.clearScreen()
    }
    step = 0
})
```

The A handler never resets: if you've pressed A, A, A, the last two presses are still A, A, so you're one B away from opening. B is the only press that can be "wrong", and it always sends you back to 0. Test it with A A B (opens), A B (X), and A A A B (opens).
:::
