:::objectives
- Count parameters, bytes, and MACs for a small audio CNN without help from a framework.
- Find peak activation memory with the pair rule, and see where the rule breaks.
- Measure latency correctly with `time.perf_counter`.
- Sweep a design choice (input resolution) and find the largest value that fits every limit.
:::

The build-along used motion data, where the firmware outweighed the model. These exercises move to audio and images, where the model starts to fight for memory. Every solution is plain Python or NumPy, so each one runs on its own.

## Warm-up

Answer these in your head or on paper, then check:

1.  How many parameters does a dense layer from 64 inputs to 10 outputs have?
2.  How many bytes is that in float32?
3.  How many parameters does a 5×5 convolution from 3 channels to 8 channels have?

:::solution
1.  64 × 10 weights + 10 biases = **650**.
2.  650 × 4 bytes = **2,600 bytes**, about 2.5 KB.
3.  5 × 5 × 3 × 8 weights + 8 biases = **608**. The image size doesn't matter.
:::

### Exercise 1: Count a keyword spotter's parameters

A keyword spotter turns one second of audio into a 49 × 40 grid of filterbank energies (49 time frames, 40 frequency bands) and treats it like a one-channel image. The model:

| Layer | Details |
| --- | --- |
| Conv2d | 3×3, 1 → 8 channels, padding keeps 49×40 |
| MaxPool | 2×2, halves height and width (rounding down) |
| Conv2d | 3×3, 8 → 16 channels, padding keeps the size |
| MaxPool | 2×2 |
| Dense | flatten, then 3 outputs ("yes", "no", background) |

Write a short program that walks these layers, tracks the shape, and prints the total parameters and the int8 and float32 sizes in KB.

```text
total parameters: 7,011
int8: 6.8 KB   float32: 27.4 KB
```

:::hint
Keep three variables, `h`, `w`, and `c`, and update them as you go. A pool layer changes `h` and `w` with `//2`. The dense layer's input count is `h * w * c` at that point.
:::

:::solution
```python run
h, w, c = 49, 40, 1
params = 0

params += 3 * 3 * 1 * 8 + 8;   c = 8           # conv 1
h, w = h // 2, w // 2                           # pool: 24 x 20
params += 3 * 3 * 8 * 16 + 16; c = 16          # conv 2
h, w = h // 2, w // 2                           # pool: 12 x 10
params += (h * w * c) * 3 + 3                   # dense from 1,920 values to 3

print(f"total parameters: {params:,}")
print(f"int8: {params / 1024:.1f} KB   float32: {params * 4 / 1024:.1f} KB")
```

The dense layer has 5,763 of the 7,011 parameters, because it connects all 1,920 flattened values to each output. That's typical: in small CNNs the last dense layer often holds most of the weights.
:::

### Exercise 2: Find its peak activation memory

Using the same model, list the size of every tensor (input, then each layer's output) and apply the pair rule: peak = the largest input-plus-output of any layer. Report it for int8 and float32.

```text
tensor sizes: [1960, 15680, 3840, 7680, 1920, 3]
peak: 19,520 values = 19.1 KB int8, 76.2 KB float32
```

:::hint
The first convolution's output is 49 × 40 × 8. Then use `zip(sizes, sizes[1:])` to walk through neighboring pairs.
:::

:::solution
```python run
sizes = [49 * 40 * 1]          # input
sizes.append(49 * 40 * 8)      # conv 1
sizes.append(24 * 20 * 8)      # pool
sizes.append(24 * 20 * 16)     # conv 2
sizes.append(12 * 10 * 16)     # pool
sizes.append(3)                # dense

peak = max(a + b for a, b in zip(sizes, sizes[1:]))
print("tensor sizes:", sizes)
print(f"peak: {peak:,} values = {peak / 1024:.1f} KB int8, {peak * 4 / 1024:.1f} KB float32")
```

The peak is the first pooling layer, reading 15,680 values and writing 3,840. Even in float32 this model fits easily in 256 KB, which is one reason keyword spotting was one of the first TinyML successes.
:::

### Exercise 3: Will it keep up?

The device classifies a 1-second window every 250 ms. Turning audio into the 49 × 40 grid takes 35 ms on the board. Count the MACs for each layer (convolution: `h_out × w_out × k × k × c_in × c_out`; dense: `n_in × n_out`), then estimate total latency at 64 MHz for 1 and 2 cycles per MAC. Does it fit in half the hop (125 ms)?

```text
MACs per layer: [141120, 552960, 5760]  total 699,840
latency: 46 to 57 ms including DSP -> fits
```

:::hint
Pool layers do comparisons, not MACs, so leave them out. The second convolution runs on the pooled 24 × 20 grid.
:::

:::solution
```python run
macs = [
    49 * 40 * 3 * 3 * 1 * 8,     # conv 1 on the full grid
    24 * 20 * 3 * 3 * 8 * 16,    # conv 2 on the pooled grid
    1920 * 3,                    # dense
]
total = sum(macs)
DSP_MS, CLOCK = 35, 64_000_000
fast = total * 1 / CLOCK * 1000 + DSP_MS
slow = total * 2 / CLOCK * 1000 + DSP_MS
print(f"MACs per layer: {macs}  total {total:,}")
print(f"latency: {fast:.0f} to {slow:.0f} ms including DSP ->", "fits" if slow <= 125 else "too slow")
```

The model itself takes only 11 to 22 ms; the DSP is the bigger cost. For audio, always budget the feature extraction too. Edge Impulse reports DSP and classification time separately for this reason.
:::

### Exercise 4: Fix the timing harness

A teammate timed a tiny NumPy network like this and reported "0.03 ms" in the team chat. Run it a few times and you'll see the number jump around.

```python
import time
import numpy as np

rng = np.random.default_rng(0)
W1, W2 = rng.standard_normal((375, 32)), rng.standard_normal((32, 4))

def predict(x):
    return np.maximum(x @ W1, 0) @ W2

x = rng.standard_normal(375)
start = time.time()
predict(x)
print("inference took", (time.time() - start) * 1000, "ms")
```

Rewrite it so it uses `time.perf_counter()`, does 50 warm-up calls, times 2,000 calls, and prints the first call, the median, and the 99th percentile in microseconds.

:::hint
Store each duration in a list. Sort the list, then index at `int(0.99 * len(times))` for the 99th percentile. `statistics.median` gives the median.
:::

:::solution
```python run
import time
import statistics
import numpy as np

rng = np.random.default_rng(0)
W1, W2 = rng.standard_normal((375, 32)), rng.standard_normal((32, 4))

def predict(x):
    return np.maximum(x @ W1, 0) @ W2

x = rng.standard_normal(375)
times = []
for i in range(50 + 2000):
    start = time.perf_counter()
    predict(x)
    times.append((time.perf_counter() - start) * 1e6)

first, timed = times[0], sorted(times[50:])
print(f"first call: {first:.1f} us")
print(f"median:     {statistics.median(timed):.1f} us")
print(f"99th pct:   {timed[int(0.99 * len(timed))]:.1f} us")
```

The median is stable from run to run; the single `time.time()` reading wasn't. The 99th percentile shows the occasional slow call, which on a real device is the one that misses a deadline. Your numbers will differ from the ones shown here, and none of them say much about a 64 MHz chip.
:::

### Exercise 5: Find the largest camera image that fits

A wildlife camera uses this CNN on a square grayscale image of side `r`:

-   Conv 3×3, 1 → 16, same size, then 2×2 max-pool
-   Conv 3×3, 16 → 32, same size, then 2×2 max-pool
-   Conv 3×3, 32 → 32, same size, then global average and a 2-way dense layer

After the firmware, sensor buffers, and Bluetooth, **120 KB** of RAM is left for activations, and one photo may take up to **1,000 ms** (2 cycles per MAC, 64 MHz). Try `r` in 64, 80, 96, 112, 128, and 160. Plot int8 peak activation and latency against `r`, with the limits as dashed lines, and print the largest `r` that meets both.

:::hint
Write a function `costs(r)` that returns `(peak_kb, latency_ms)`. The tensors are: `r*r`, `16*r*r`, `16*(r//2)**2`, `32*(r//2)**2`, `32*(r//4)**2`, `32*(r//4)**2`. The MACs come from the three convolutions only.
:::

:::solution
```python run alt="Two line charts against image side length from 64 to 160 pixels. Peak activation memory rises from 80 KB to 500 KB and crosses the 120 KB limit between 64 and 80. Latency rises from about 240 ms to 1,500 ms and crosses the 1,000 ms limit between 128 and 160." caption="RAM runs out long before time does"
import matplotlib.pyplot as plt

def costs(r):
    h2, h4 = r // 2, r // 4
    sizes = [r * r, 16 * r * r, 16 * h2 * h2, 32 * h2 * h2, 32 * h4 * h4, 32 * h4 * h4]
    peak_kb = max(a + b for a, b in zip(sizes, sizes[1:])) / 1024
    macs = r * r * 9 * 1 * 16 + h2 * h2 * 9 * 16 * 32 + h4 * h4 * 9 * 32 * 32
    return peak_kb, macs * 2 / 64e6 * 1000

sides = [64, 80, 96, 112, 128, 160]
results = [costs(r) for r in sides]
for r, (kb, ms) in zip(sides, results):
    ok = kb <= 120 and ms <= 1000
    print(f"r={r:3}  peak {kb:6.1f} KB  latency {ms:6.0f} ms  {'fits' if ok else ''}")
print("largest side that fits:", max(r for r, (kb, ms) in zip(sides, results) if kb <= 120 and ms <= 1000))

fig, (a1, a2) = plt.subplots(1, 2, figsize=(9, 3.4))
a1.plot(sides, [kb for kb, _ in results], marker="o", color="#2a78d6")
a1.axhline(120, color="#333", linestyle="--")
a1.set_xlabel("Image side (pixels)"); a1.set_ylabel("Peak activations (KB, int8)")
a2.plot(sides, [ms for _, ms in results], marker="o", color="#eb6834")
a2.axhline(1000, color="#333", linestyle="--")
a2.set_xlabel("Image side (pixels)"); a2.set_ylabel("Latency estimate (ms)")
plt.tight_layout()
```

Memory grows with `r²`, and so does time, but the RAM limit is much tighter: only 64×64 fits, while time would allow up to 128×128. The first pool layer, holding the full-resolution 16-channel map and its pooled copy, sets the peak. A stride-2 first convolution would let 96×96 fit, as in the notes.
:::

### Exercise 6: When the pair rule underestimates

The pair rule assumes each tensor is used once, by the next layer. A **skip connection** breaks that: an early tensor is kept so it can be added back later. In this block, `t1` is needed again at the Add step.

```mermaid caption="A residual block: t1 must stay in RAM until the Add step"
flowchart LR
    t0["t0 input, 9 KB"] --> A[Conv A]
    A --> t1["t1, 36 KB"]
    t1 --> B[Conv B] --> t2["t2, 36 KB"]
    t2 --> C[Conv C] --> t3["t3, 36 KB"]
    t3 --> ADD[Add]
    t1 -- skip --> ADD
    ADD --> t4["t4, 36 KB"] --> P[Pool] --> t5["t5, 9 KB"]
```

Each tensor is created at one step and last read at a later step. A tensor is in RAM at step `s` if it was created at or before `s` and is still needed at or after `s`. Write `peak_live(tensors)` that returns the largest total at any step, and compare it with the pair rule.

```text
step 1: 45 KB  ['t0', 't1']
step 2: 72 KB  ['t1', 't2']
step 3: 108 KB  ['t1', 't2', 't3']
step 4: 108 KB  ['t1', 't3', 't4']
step 5: 45 KB  ['t4', 't5']
true peak 108 KB vs pair rule 72 KB
```

:::hint
Store each tensor as `(name, size_kb, created_step, last_used_step)`. The input is created at step 0, and the final output is last used at the last step. For each step from 1 to 5, add up the sizes of tensors that are alive.
:::

:::solution
```python run
tensors = [
    ("t0", 9, 0, 1),     # input, read by Conv A at step 1
    ("t1", 36, 1, 4),    # made by Conv A, read by Conv B (2) AND by Add (4)
    ("t2", 36, 2, 3),
    ("t3", 36, 3, 4),
    ("t4", 36, 4, 5),
    ("t5", 9, 5, 5),     # final output
]

def peak_live(tensors, steps=5):
    peak = 0
    for s in range(1, steps + 1):
        alive = [(n, kb) for n, kb, made, last in tensors if made <= s <= last]
        total = sum(kb for _, kb in alive)
        print(f"step {s}: {total} KB  {[n for n, _ in alive]}")
        peak = max(peak, total)
    return peak

chain = [kb for _, kb, _, _ in tensors]
pair_rule = max(a + b for a, b in zip(chain, chain[1:]))
print(f"true peak {peak_live(tensors)} KB vs pair rule {pair_rule} KB")
```

Holding `t1` across three layers adds 36 KB to the peak, half again what the pair rule predicts. That's why MobileNet-style models with skip connections need careful memory planning on microcontrollers, and why Edge Impulse and TensorFlow Lite Micro compute the arena from the real graph instead of a rule of thumb.
:::

### Challenge: Fit a person detector

Design a CNN for 96×96 grayscale images that answers "person or no person" within these limits on the nRF52840:

-   int8 weights at most **250 KB**
-   int8 peak activations at most **100 KB**
-   at most **800 ms** per image (2 cycles per MAC at 64 MHz)
-   at least **four** convolution layers, so it has a chance of being accurate

Write the model in PyTorch, measure it with the `profile()` function from the build-along (adapted for `Conv2d`), and write three sentences explaining which choice saved the most RAM and which saved the most time. There's no single right answer; compare yours with a classmate's.

:::hint
