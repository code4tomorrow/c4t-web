:::objectives
- Compute per-class recall, precision, and balanced accuracy from a confusion matrix.
- Decide whether a board passes a parity check against Studio, including near-ties.
- Find which input features drifted between lab and field, and connect them to a physical cause.
- Show what a sample-rate mistake does to a frequency feature.
- Estimate how many field-test blocks you need for a given precision.
:::

These exercises use small arrays you can check by hand, so you can focus on the reasoning. Every solution runs on its own.

## Warm-up

A person detector was tested on 200 camera frames. It found 45 of the 50 frames with a person and raised 10 false alarms on the 150 empty frames. Work out accuracy, recall for "person", and precision for "person".

:::solution
-   True positives 45, false negatives 5, false positives 10, true negatives 140.
-   Accuracy = (45 + 140) / 200 = **92.5%**.
-   Recall = 45 / 50 = **90%**: of the real people, how many it found.
-   Precision = 45 / (45 + 10) = **81.8%**: of its "person" alerts, how many were right.
:::

### Exercise 1: Which keyword needs more data?

Here is a keyword spotter's confusion matrix from a field test (rows are the truth, columns the prediction):

```text
             yes   no   unknown  silence
yes           88    4      7        1
no             9   71     18        2
unknown        3    6     86        5
silence        0    0      2       98
```

Write a program that prints recall and precision for each class and the overall accuracy. Then answer: which class should you collect more training data for, and what should those recordings sound like?

```text
yes      recall 88.0%  precision 88.0%
no       recall 71.0%  precision 87.7%
unknown  recall 86.0%  precision 76.1%
silence  recall 98.0%  precision 92.5%
accuracy 85.8%
```

:::hint
Recall divides the diagonal by the **row** total; precision divides it by the **column** total. With NumPy, `cm[i, :].sum()` is row `i` and `cm[:, i].sum()` is column `i`.
:::

:::solution
```python run
import numpy as np

labels = ["yes", "no", "unknown", "silence"]
cm = np.array([
    [88,  4,  7,  1],
    [ 9, 71, 18,  2],
    [ 3,  6, 86,  5],
    [ 0,  0,  2, 98],
])
for i, name in enumerate(labels):
    recall = cm[i, i] / cm[i, :].sum()
    precision = cm[i, i] / cm[:, i].sum()
    print(f"{name:8} recall {recall:5.1%}  precision {precision:5.1%}")
print(f"accuracy {np.trace(cm) / cm.sum():.1%}")
```

"no" has the worst recall, and 18 of its 29 misses went to "unknown". The model doesn't recognize many real "no"s as the keyword. Collect more "no" recordings from the voices, distances, and rooms where the field test happened. The low precision of "unknown" is the same problem seen from the other side: it's absorbing those missed "no"s.
:::

### Exercise 2: The 96.5% fall detector

A fall detector was tested on 1,000 windows: 950 normal activity and 50 real falls. It caught 20 falls and raised 5 false alarms. Compute accuracy, fall recall, and **balanced accuracy** (the average of the recall of each class). Then compute the accuracy of a "model" that always says "no fall".

:::hint
Normal-class recall is the true negatives divided by 950. Balanced accuracy for two classes is `(recall_fall + recall_normal) / 2`.
:::

:::solution
```python run
falls, normal = 50, 950
caught, false_alarms = 20, 5

tp, fn = caught, falls - caught
fp, tn = false_alarms, normal - false_alarms

accuracy = (tp + tn) / (falls + normal)
recall_fall = tp / falls
recall_normal = tn / normal
balanced = (recall_fall + recall_normal) / 2
always_no = normal / (falls + normal)

print(f"accuracy          {accuracy:.1%}")
print(f"fall recall       {recall_fall:.1%}")
print(f"balanced accuracy {balanced:.1%}")
print(f"always 'no fall'  {always_no:.1%} accuracy")
```

The detector misses 60% of falls and still scores 96.5%, barely above the 95% you'd get by never detecting anything. When one class is rare, report its recall and the balanced accuracy, never accuracy alone.
:::

### Exercise 3: Does the board agree with Studio?

You ran the `static_buffer` example on five test samples. Here are the scores Studio showed (float32) and the scores the board printed (int8 model), for classes idle, snake, updown, and wave:

```python
studio = [[0.02, 0.01, 0.03, 0.94], [0.91, 0.05, 0.02, 0.02], [0.10, 0.62, 0.25, 0.03],
          [0.05, 0.48, 0.44, 0.03], [0.01, 0.01, 0.97, 0.01]]
board  = [[0.02, 0.02, 0.03, 0.93], [0.90, 0.06, 0.02, 0.02], [0.11, 0.60, 0.26, 0.03],
          [0.05, 0.45, 0.47, 0.03], [0.01, 0.02, 0.96, 0.01]]
```

Write a check that passes if every score is within 0.05 of Studio's, and the top label matches whenever Studio's top score beats its second by at least 0.10. Print a line per sample.

:::hint
For each sample, `max(abs(a - b) for a, b in zip(s, b))` gives the largest difference. Sort Studio's scores to find the margin between first and second place.
:::

:::solution
```python run
studio = [[0.02, 0.01, 0.03, 0.94], [0.91, 0.05, 0.02, 0.02], [0.10, 0.62, 0.25, 0.03],
          [0.05, 0.48, 0.44, 0.03], [0.01, 0.01, 0.97, 0.01]]
board  = [[0.02, 0.02, 0.03, 0.93], [0.90, 0.06, 0.02, 0.02], [0.11, 0.60, 0.26, 0.03],
          [0.05, 0.45, 0.47, 0.03], [0.01, 0.02, 0.96, 0.01]]
labels = ["idle", "snake", "updown", "wave"]

all_ok = True
for i, (s, b) in enumerate(zip(studio, board), start=1):
    diff = max(abs(x - y) for x, y in zip(s, b))
    top_s, top_b = labels[s.index(max(s))], labels[b.index(max(b))]
    first, second = sorted(s, reverse=True)[:2]
    must_match = first - second >= 0.10
    ok = diff <= 0.05 and (top_s == top_b or not must_match)
    all_ok = all_ok and ok
    note = "" if top_s == top_b else f"  (top label flipped, Studio margin only {first - second:.2f})"
    print(f"sample {i}: max diff {diff:.2f}, Studio {top_s}, board {top_b} -> {'ok' if ok else 'FAIL'}{note}")
print("parity check:", "PASS" if all_ok else "FAIL")
```

Sample 4 flips from snake to updown, but Studio itself only preferred snake by 0.04. Rounding to int8 can tip a near-tie either way, so that's expected. A flip on a sample with a large margin, or any difference above about 0.05, would point to a build problem.
:::

### Exercise 4: Which feature drifted?

The gesture model uses nine features: the mean, motion strength (RMS), and dominant frequency on each axis. The next cell makes 200 lab windows and 200 field windows of features. For each feature, compute the **standardized shift**: `(field mean − lab mean) / lab standard deviation`. Plot the shifts as bars, mark ±1 with dashed lines, and print the features beyond it. What physical change explains them?

:::hint
`lab.mean(axis=0)` and `lab.std(axis=0)` give one value per feature column. A shift of 1 means the field average moved by one lab standard deviation.
:::

:::solution
```python run alt="Bar chart of standardized shift for nine features. The x-axis mean shifts by about +9 and the z-axis mean by about -7. All other features stay within plus or minus 1." caption="Only the gravity features moved"
import numpy as np
import matplotlib.pyplot as plt

names = ["x mean", "x rms", "x freq", "y mean", "y rms", "y freq", "z mean", "z rms", "z freq"]
lab_mu = np.array([0.0, 2.0, 1.8, 0.0, 1.5, 1.8, 9.8, 2.0, 1.8])
lab_sd = np.array([0.8, 1.0, 0.5, 0.8, 1.0, 0.5, 0.3, 1.0, 0.5])
rng = np.random.default_rng(5)
lab = rng.normal(lab_mu, lab_sd, (200, 9))
field_mu = lab_mu.copy()
field_mu[0] += 9.81 * np.sin(np.radians(40))          # gravity leaks onto x
field_mu[6] = 9.81 * np.cos(np.radians(40))           # and less of it stays on z
field = rng.normal(field_mu, lab_sd, (200, 9))

shift = (field.mean(axis=0) - lab.mean(axis=0)) / lab.std(axis=0)
for n, s in zip(names, shift):
    if abs(s) > 1:
        print(f"{n:7} shifted by {s:+.1f} lab standard deviations")

plt.figure(figsize=(7.5, 3.4))
plt.bar(names, shift, color=["#d64545" if abs(s) > 1 else "#2a78d6" for s in shift])
plt.axhline(1, color="#333", linestyle="--", linewidth=1)
plt.axhline(-1, color="#333", linestyle="--", linewidth=1)
plt.ylabel("Field shift (lab std devs)")
plt.xticks(rotation=30)
plt.tight_layout()
```

Gravity moved from z toward x, which is exactly what tilting the board by about 40 degrees does. You can find this without labels: comparing feature averages needs only the raw field data. That makes it a cheap early warning to run on any new deployment before anyone has labeled anything.
:::

### Exercise 5: The sample-rate bug

A teammate "simplified" the sketch by deleting the wait in the sampling loop. The board now fills its 125-sample buffer at about 125 Hz instead of 62.5 Hz, but the DSP block still assumes 62.5 Hz. A tester waves at 2 Hz. Generate both versions of the window and print the dominant frequency the model's features would report.

```text
sampled at 62.5 Hz: model sees 2.0 Hz
sampled at 125 Hz: model sees 1.0 Hz
```

:::hint
Build the time axis from the real sample rate: `t = np.arange(125) / real_hz`. Compute the frequency axis from the rate the model assumes: `np.fft.rfftfreq(125, 1 / 62.5)`.
:::

:::solution
```python run
import numpy as np

N, ASSUMED_HZ, WAVE_HZ = 125, 62.5, 2.0
freqs = np.fft.rfftfreq(N, 1 / ASSUMED_HZ)

for real_hz in [62.5, 125]:
    t = np.arange(N) / real_hz
    signal = np.sin(2 * np.pi * WAVE_HZ * t)
    seen = freqs[np.abs(np.fft.rfft(signal)).argmax()]
    print(f"sampled at {real_hz:g} Hz: model sees {seen} Hz")
```

Sampling twice as fast squeezes 2 seconds of the model's expectations into 1 second of real motion, so every movement looks half as fast. No error appears anywhere. This is why the Edge Impulse examples wait `EI_CLASSIFIER_INTERVAL_MS` between samples, and why your bench test should check the time between log lines.
:::

### Exercise 6: How many blocks do you need?

Each field block has its own accuracy, because people and places differ. Simulate field tests where each block's accuracy is drawn from `rng.beta(8.5, 1.5)` (average 85%) and each block has 10 windows. For 8, 16, 24, 32, 48, 64, and 128 blocks, run 2,000 simulated tests, and print the range that holds the middle 95% of measured accuracies. What's the smallest number of blocks that pins accuracy within about ±5 points (a range 10 points wide or less)?

:::hint
For one simulated test of `n` blocks: `p = rng.beta(8.5, 1.5, n)`, then `right = rng.binomial(10, p)`, and the measured accuracy is `right.sum() / (10 * n)`. Repeat 2,000 times and take `np.percentile(results, [2.5, 97.5])`.
:::

:::solution
```python run alt="Line chart of the width of the 95% range of measured accuracy against the number of field blocks. Width falls from about 21 points at 8 blocks to about 6 points at 128 blocks, crossing 10 points between 32 and 48 blocks." caption="Precision improves with the square root of the number of blocks"
import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(3)
sizes = [8, 16, 24, 32, 48, 64, 128]
widths = []
for n in sizes:
    results = []
    for _ in range(2000):
        p = rng.beta(8.5, 1.5, n)          # each block's own accuracy
        right = rng.binomial(10, p)        # 10 windows per block
        results.append(right.sum() / (10 * n))
    lo, hi = np.percentile(results, [2.5, 97.5])
    widths.append((hi - lo) * 100)
    print(f"{n:4} blocks: {lo:.1%} to {hi:.1%}  (width {widths[-1]:.1f} points)")
print("smallest that meets +/-5:", next(n for n, w in zip(sizes, widths) if w <= 10))

plt.figure(figsize=(6.5, 3.4))
plt.plot(sizes, widths, marker="o", color="#2a78d6")
plt.axhline(10, color="#333", linestyle="--")
plt.xlabel("Field blocks")
plt.ylabel("Width of 95% range (points)")
plt.tight_layout()
```

Going from 8 to 32 blocks halves the uncertainty, and halving it again takes about 128. That's the square-root rule: four times the data for twice the precision. Plan field tests in blocks across many people and places, because adding windows inside the same block barely helps.
:::

### Challenge: Write the field-test plan for a wildlife camera

A camera trap classifies photos as **animal** or **empty** and only stores animal photos. Write a one-page field-test plan as a Markdown table plus a few sentences. Include:

-   the conditions you'll vary (at least time of day, weather, distance, and two camera mounting heights), and how many blocks per condition;
-   what the device logs for every photo, so you can score it later without guessing;
-   your pass targets, written before the test, for animal recall, empty-photo precision, and battery drain per day;
-   one feature-shift check you'll run on unlabeled photos to spot drift early (for example, average brightness by hour).

:::hint
Start from the gesture plan: truth logged on the device, transition windows dropped, results split by condition, bootstrap over blocks. For a camera, a "block" might be one night at one location. Exercise 6 tells you roughly how many you need.
:::
