## Cell 2: fake an accelerometer

An accelerometer reports acceleration along three axes, x, y, and z, usually in units of **g** (1 g is the pull of gravity). A board lying flat reads about 1 g on z and about 0 on x and y. Shake it and x and y swing back and forth.

Real sensors are coming. For now NumPy can produce a convincing fake: 3 seconds resting, then 3 seconds of shaking at 4 times per second, sampled 50 times per second, with a little random noise on every reading.

```python run title="cell 2" alt="Line chart of x, y, and z acceleration over 6 seconds. All three lines are flat for the first 3 seconds, then x and y oscillate strongly while z stays near 1 g." caption="Six seconds of synthetic accelerometer data"
import matplotlib.pyplot as plt

rate = 50                        # samples per second
t = np.arange(0, 6, 1 / rate)    # 300 time stamps
rng = np.random.default_rng(seed=1)

still = t < 3
x = np.where(still, 0.0, 1.5 * np.sin(2 * np.pi * 4 * t)) + rng.normal(0, 0.05, t.size)
y = np.where(still, 0.0, 0.8 * np.sin(2 * np.pi * 4 * t + 1)) + rng.normal(0, 0.05, t.size)
z = 1.0 + rng.normal(0, 0.05, t.size)

plt.figure(figsize=(8, 3))
for axis, name in ((x, "x"), (y, "y"), (z, "z")):
    plt.plot(t, axis, label=name, linewidth=1)
plt.axvline(3, color="gray", linestyle="--")
plt.xlabel("time (s)")
plt.ylabel("acceleration (g)")
plt.legend(loc="upper left")
plt.title("Resting, then shaking")
```

`np.where(still, 0.0, ...)` picks 0 for the resting half and the sine wave for the shaking half. The `seed=1` makes the "random" noise identical every time you run the cell, which means your chart matches this one exactly.

## Cell 3: find a feature that separates the two halves

A model doesn't look at a chart. It needs a few numbers that summarize a stretch of signal. Those numbers are called **features**. Two simple ones:

- **Mean**: the average value.
- **RMS** (root mean square): square every value, average the squares, take the square root. It measures how *big* the signal is, whichever direction it points.

Before running the next cell, guess: which feature will look different for resting and shaking?

```python run title="cell 3"
def rms(values):
    return np.sqrt(np.mean(values ** 2))

resting, shaking = x[:150], x[150:]
print(f"resting: mean {resting.mean():+.3f} g   RMS {rms(resting):.3f} g")
print(f"shaking: mean {shaking.mean():+.3f} g   RMS {rms(shaking):.3f} g")
```

The means are both near zero. A sine wave spends as long below zero as above it, so its average cancels out. RMS squares the values first, so negative swings count as much as positive ones, and the shaking half comes out more than twenty times larger. Picking features that capture the thing you care about is half of TinyML, and Module 3 is built around it.

## Cell 4: train a tiny shake detector

Now make 40 short windows of 2 seconds each, half resting and half shaking at a random strength and speed, and train a decision tree that is allowed only **one** question.

```python run title="cell 4"
from sklearn.tree import DecisionTreeClassifier

def fake_window(shaking):
    tt = np.arange(100) / rate                 # 100 samples = 2 seconds
    strength = rng.uniform(0.8, 2.0) if shaking else 0.0
    speed = rng.uniform(3, 6)                  # shakes per second
    return strength * np.sin(2 * np.pi * speed * tt) + rng.normal(0, 0.05, 100)

labels = np.array([0, 1] * 20)                 # 0 = resting, 1 = shaking
features = np.array([[rms(fake_window(s))] for s in labels])
model = DecisionTreeClassifier(max_depth=1).fit(features, labels)

new_windows = np.array([[rms(fake_window(False))], [rms(fake_window(True))]])
print("predictions for a resting and a shaking window:", model.predict(new_windows))
print("rule the tree learned: shaking if RMS >", round(model.tree_.threshold[0], 3), "g")
```

The model is a single threshold: if the RMS is above a number somewhere between the resting and shaking values, call it shaking. That's a real model, trained from labeled data, and it predicts both new windows correctly. It's also small enough to be written in one line of C on a microcontroller.

## Cell 5: weigh the model

A microcontroller has two kinds of memory that matter: **flash**, where the program and model are stored, and **RAM**, the working memory used while it runs. The Nano 33 BLE Sense has 1 MB of flash and 256 KB of RAM. How big is the model we just trained?

```python run title="cell 5"
import pickle

size = len(pickle.dumps(model))
print(f"pickled model: {size} bytes")
print(f"that is {size / (1024 * 1024):.3%} of 1 MB of flash")
```

`pickle.dumps` turns the Python object into bytes, so its length is a rough size. It overstates the true cost, because pickle also stores Python class names and bookkeeping that a chip would never need. On a microcontroller this model is one float and a comparison, about 4 bytes. Later modules measure models with tens of thousands of weights, where the size really does decide whether the model fits.

## Now record a real sample in Edge Impulse

Synthetic data is great for learning because you control everything. Real data is messier, so look at some now.

1. In your Edge Impulse project, open **Data acquisition**. Your phone (connected in the last lesson) should be listed as a device.
2. Under **Record new data**, set the label to `shake`, choose the **accelerometer** sensor, and set the sample length to `10000` ms (10 seconds).
3. Click **Start sampling**, pick up your phone, and shake it gently from side to side until the recording ends.
4. Click the new sample in the list. You'll see three lines, one per axis, just like the chart in cell 2.

Compare your real sample to the synthetic one. The real z axis probably isn't flat at 1 g, because you didn't hold the phone level. The shake isn't a perfect sine wave, and its strength drifts as your arm gets tired. Those differences are why the course mixes synthetic data, where you can see the idea clearly, with real data, where you find out whether the idea survives.
