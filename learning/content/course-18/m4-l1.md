Your keyword model scores 94% on your laptop. It's 420 KB of float32 weights. The board you want to use has 1 MB of flash and 256 KB of RAM, which sounds like plenty, until you remember that the firmware, the audio buffers, and the feature code all need room too. The model has to get smaller, and it has to stay accurate.

There are two levers, and this lesson covers both. Shrink the **input**: one second of audio is 16,000 numbers, but a good feature representation needs about 1,300. Then shrink the **weights**: store each one in 1 byte instead of 4.

## One second of audio is 16,000 numbers

Microphones for speech usually sample at **16 kHz**: 16,000 readings per second, enough to capture frequencies up to 8 kHz, where most of the information in speech lives. Here's a synthetic "word", a tone that glides upward from 400 Hz to 900 Hz with a harmonic above it, buried in a little background hiss.

```python run title="a fake word"
import numpy as np
import matplotlib.pyplot as plt

SR = 16_000                                  # samples per second
rng = np.random.default_rng(5)

def word(start=0.3, length=0.4, f0=400, f1=900):
    """A tone gliding from f0 to f1 Hz, with a harmonic at twice the pitch."""
    clip = np.zeros(SR)
    n = int(length * SR)
    pitch = np.linspace(f0, f1, n)
    phase = 2 * np.pi * np.cumsum(pitch) / SR
    envelope = np.sin(np.pi * np.arange(n) / n) ** 2      # fade in and out
    s = int(start * SR)
    clip[s:s + n] = envelope * (np.sin(phase) + 0.4 * np.sin(2 * phase))
    return clip

audio = 0.5 * word() + 0.05 * rng.normal(size=SR)
print("one second of audio:", audio.shape, audio.dtype)
```

Plotted as a waveform, this is a dense scribble. The individual samples say almost nothing on their own; what matters is which **frequencies** are present and how they change over time. That's what a spectrogram shows.

## Frames and the FFT: a spectrogram

The trick is the windowing you learned in Module 3, at a much smaller scale. Cut the second into short **frames** of 25 ms (400 samples), starting a new one every 10 ms (160 samples). Over 25 ms, the pitch barely changes, so an FFT of one frame gives a clean snapshot of the frequencies at that moment. Stack the snapshots side by side and you have a **spectrogram**: time across, frequency up, brightness for energy.

```python run title="spectrogram"
FRAME, HOP, NFFT = 400, 160, 512             # 25 ms frames, 10 ms apart

def power_spectrogram(x):
    window = np.hanning(FRAME)               # taper each frame's edges
    starts = range(0, len(x) - FRAME + 1, HOP)
    frames = np.stack([x[s:s + FRAME] * window for s in starts])
    return np.abs(np.fft.rfft(frames, n=NFFT)) ** 2

S = power_spectrogram(audio)
print("frames x frequency bins:", S.shape)
print("bin spacing:", SR / NFFT, "Hz")
```

98 frames of 257 frequency bins each. The `np.hanning` window fades each frame in and out, so the sudden cut at the frame edges doesn't smear energy across every frequency. Apple describes the same structure for "Hey Siri": the audio becomes a sequence of frames, each describing the spectrum of about 0.01 seconds.

## The mel scale: spend detail where ears do

The 257 bins are spaced evenly, 31.25 Hz apart. Human hearing isn't even. You easily hear the difference between 200 Hz and 300 Hz, but 7,200 Hz and 7,300 Hz sound almost the same. The **mel scale** stretches low frequencies and squashes high ones to match:

mel = 2595 × log₁₀(1 + *f* ÷ 700)

A **mel filterbank** is a set of overlapping triangles, evenly spaced in mel, each adding up the energy in its range of bins. Narrow triangles at the bottom keep detail where speech needs it; wide ones at the top save numbers where it doesn't. Taking the log of each filter's energy gives a **log-mel spectrogram**, which Edge Impulse's **MFE** block produces.

```python run title="mel filterbank"
def hz_to_mel(f):
    return 2595 * np.log10(1 + f / 700)

def mel_to_hz(m):
    return 700 * (10 ** (m / 2595) - 1)

def mel_filterbank(n_filters=40):
    edges_hz = mel_to_hz(np.linspace(0, hz_to_mel(SR / 2), n_filters + 2))
    bin_hz = np.fft.rfftfreq(NFFT, d=1 / SR)          # frequency of every FFT bin
    bank = np.zeros((n_filters, len(bin_hz)))
    for i in range(n_filters):
        left, center, right = edges_hz[i:i + 3]
        rising = (bin_hz - left) / (center - left)
        falling = (right - bin_hz) / (right - center)
        bank[i] = np.clip(np.minimum(rising, falling), 0, None)   # a triangle
    return bank

bank = mel_filterbank()
logmel = np.log(S @ bank.T + 1e-10)
print("log-mel:", logmel.shape)
print("first filter centers (Hz):", mel_to_hz(np.linspace(0, hz_to_mel(8000), 42))[1:5].round())
print("last filter centers (Hz): ", mel_to_hz(np.linspace(0, hz_to_mel(8000), 42))[-5:-1].round())
```

Near 0 Hz the filters are about 50 Hz apart; near 8 kHz they're about 500 Hz apart. The `1e-10` keeps `np.log` from hitting zero in silent frames.

## MFCCs: compress the shape of the spectrum

Neighboring mel filters are strongly correlated: if one is loud, the next probably is too. A **discrete cosine transform** (DCT) across the 40 filters re-expresses each frame as a sum of smooth "shapes", from broad to fine. Keeping only the first 13 coefficients keeps the overall shape of the spectrum and drops fine ripples. These are **MFCCs**, Mel-Frequency Cepstral Coefficients. Edge Impulse's documentation for its MFCC block notes that 13 coefficients are usually retained.

```python run title="MFCC" alt="Three heat maps of the same one-second clip. Left, the spectrogram: two thin bright lines rising between 0.3 and 0.7 seconds, near 400 to 900 Hz and twice that. Middle, the log-mel spectrogram: the same two lines, thicker and higher up the image because low frequencies are stretched. Right, 13 MFCCs: horizontal bands that change while the word is present." caption="The same second of audio as a spectrogram, a log-mel spectrogram, and MFCCs"
from scipy.fft import dct

mfcc = dct(logmel, type=2, axis=1, norm="ortho")[:, :13]
print("MFCC:", mfcc.shape, "=", mfcc.size, "numbers instead of", SR)

fig, axes = plt.subplots(1, 3, figsize=(10, 3))
panels = [(np.log(S.T + 1e-10), "spectrogram", 8000, "Hz"),
          (logmel.T, "log-mel (40 filters)", 40, "filter"),
          (mfcc.T, "MFCC (13)", 13, "coefficient")]
for ax, (image, title, top, unit) in zip(axes, panels):
    ax.imshow(image, origin="lower", aspect="auto", extent=[0, 1, 0, top])
    ax.set_title(title)
    ax.set_xlabel("s")
    ax.set_ylabel(unit)
fig.tight_layout()
```

1,274 numbers instead of 16,000, a 12× cut, and the word is still clearly visible in all three. MFCCs are the classic choice for **speech**. For non-speech sounds (a dog bark, a machine fault, glass breaking), Edge Impulse recommends its MFE or spectrogram blocks, which keep more detail that speech-tuned MFCCs throw away.

## How keyword spotting uses these features

A keyword spotter, the model behind "Hey Siri" or "OK Google", runs on a 1-second window of MFCCs that slides along the audio stream several times a second. Edge Impulse's keyword-spotting tutorial trains three classes: **your keyword**, **unknown** (other words), and **noise** (background sound), with similar amounts of each. The extra classes matter: a model that only knows "keyword" will call every sound a keyword, because it must pick one of its classes.

Because the window slides, one spoken word appears in several consecutive windows. Real systems average or vote over those predictions before they trigger, which cuts false alarms from a single odd window.

## Quantization: 256 levels instead of 4 billion

Now the weights. A float32 can represent about 4 billion different values. Most models don't need that precision; the weights of a layer usually sit in a narrow range like −1 to +1. **Quantization** maps that range onto the 256 levels of an int8 (−128 to 127), like replacing a fine ruler with a coarse one.

Two numbers define the mapping:

- **scale**: how much real value one integer step is worth, (max − min) ÷ 255;
- **zero point**: the integer that represents real 0.0, chosen so that min maps to −128.

quantize: *q* = clip(round(*x* ÷ scale) + zero point, −128, 127)
restore: *x̂* = (*q* − zero point) × scale

Step through four weights to see each line do its job:

:::trace Quantize four weights to int8 and restore them
```python
weights = [-0.62, 0.05, 0.31, 0.90]
lo, hi = min(weights), max(weights)
scale = (hi - lo) / 255
zero_point = round(-128 - lo / scale)
q = []
for w in weights:
    level = round(w / scale) + zero_point
    level = max(-128, min(127, level))
    q.append(level)
restored = [(level - zero_point) * scale for level in q]
print(q)
print([round(r, 3) for r in restored])
```
:::

The smallest weight lands on −128 and the largest on 127, as designed. Each restored value is within half a step of the original. Now do it for 2,000 weights:

```python run title="int8 by hand"
def quant_params(lo, hi):
    scale = (hi - lo) / 255
    zero_point = int(round(-128 - lo / scale))
    return scale, zero_point

def quantize(x, scale, zero_point):
    return np.clip(np.round(x / scale) + zero_point, -128, 127).astype(np.int8)

def dequantize(q, scale, zero_point):
    return (q.astype(np.float32) - zero_point) * scale

w = rng.normal(0, 0.3, 2000).astype(np.float32)
scale, zp = quant_params(w.min(), w.max())
q = quantize(w, scale, zp)
restored = dequantize(q, scale, zp)

print(f"range [{w.min():.3f}, {w.max():.3f}]   scale {scale:.5f}   zero point {zp}")
print(f"largest error {np.abs(w - restored).max():.5f}   half a step {scale / 2:.5f}")
print(f"memory: {w.nbytes} bytes as float32 -> {q.nbytes} bytes as int8")
```

The largest error equals half a step, exactly as rounding promises, and the memory drops by 4×. The zero point isn't 0 because this range isn't centered: it runs further below zero than above.

## Does the model still work?

Rounding every weight by up to half a step sounds risky. Try it on a trained classifier: quantize its weights, restore them, and compare the predictions.

```python run title="accuracy before and after"
from sklearn.datasets import make_classification
from sklearn.linear_model import LogisticRegression

X, y = make_classification(n_samples=1500, n_features=20, n_informative=8, random_state=0)
clf = LogisticRegression(max_iter=1000).fit(X[:1000], y[:1000])
weights, bias = clf.coef_.ravel(), clf.intercept_[0]

s, z = quant_params(weights.min(), weights.max())
weights_int8 = dequantize(quantize(weights, s, z), s, z)

float_pred = (X[1000:] @ weights + bias > 0).astype(int)
int8_pred = (X[1000:] @ weights_int8 + bias > 0).astype(int)
print(f"float32 accuracy {(float_pred == y[1000:]).mean():.1%}")
print(f"int8 accuracy    {(int8_pred == y[1000:]).mean():.1%}")
print(f"same prediction on {(float_pred == int8_pred).mean():.1%} of test examples")
```

Every prediction is unchanged. A prediction only flips when an example sits so close to the decision boundary that half-step nudges in the weights push it across, and that's rare. Deep networks round thousands of weights per layer and usually lose a little accuracy, though often very little, which is why int8 is the default for microcontrollers. ## Mistakes that break audio models and int8 models

:::warning
**One outlier ruins the scale.** The scale is set by the minimum and maximum, so a single extreme weight stretches the ruler for everyone:

```python run title="an outlier"
with_outlier = w.copy()
with_outlier[0] = 8.0                              # one weight far from the rest
s2, z2 = quant_params(with_outlier.min(), with_outlier.max())
err = np.abs(with_outlier - dequantize(quantize(with_outlier, s2, z2), s2, z2))
print(f"scale {s2:.4f} (was {scale:.4f})   mean error {err.mean():.5f}")
print("distinct int8 levels used:", np.unique(quantize(with_outlier, s2, z2)).size, "of 256")
```

Most weights now share a few dozen levels. Real quantizers clip the range to ignore rare extremes, or give each output channel its own scale (per-channel quantization).
:::

:::warning
**Training features that don't match the device's features.** If training clips were recorded at 44.1 kHz and the board samples at 16 kHz, or the frame length differs by a few milliseconds, every MFCC shifts and accuracy collapses with no error message. Resample training audio to the device's rate and use the exact same feature settings on both. Edge Impulse avoids this by compiling the same processing block into the device code.
:::

:::warning
**Calibrating with the wrong data.** In full int8 models, the inputs and intermediate values (activations) are quantized too, and their ranges come from a **calibration** set. Calibrate on audio that looks like real use, including quiet rooms and loud ones, or loud inputs will be clipped at 127.
:::

:::quiz
Q: One second of 16 kHz audio is cut into 400-sample frames with a 160-sample hop. How many frames are there?
- [ ] 100
  That would be 16,000 ÷ 160, which ignores that each frame needs 400 samples to fit.
- [x] 98
  ⌊(16,000 − 400) ÷ 160⌋ + 1 = 97 + 1 = 98, the same window formula as Module 3.
- [ ] 40
  40 is the number of mel filters, which counts frequency bands, not frames.

Q: Why are mel filters narrow at low frequencies and wide at high ones?
- [x] Hearing separates nearby low pitches much better than nearby high pitches, so detail is spent where it matters for sound
  The mel scale follows perceived pitch, so equal mel steps are small in Hz at the bottom and large at the top.
- [ ] High frequencies carry more energy, so they need fewer filters
  Speech actually has more energy at low frequencies; the spacing follows perception, not energy.
- [ ] The FFT has fewer bins at high frequencies
  FFT bins are evenly spaced, 31.25 Hz apart here, at every frequency.

Q: Weights range from −0.5 to 1.0. What scale and zero point map them to int8?
- [ ] scale 1.5 ÷ 256, zero point 0
  The range has 256 levels but 255 steps between them, and the zero point must shift −0.5 down to −128.
- [x] scale 1.5 ÷ 255 ≈ 0.00588, zero point round(−128 + 0.5 ÷ 0.00588) = −43
  −0.5 ÷ 0.00588 ≈ −85, so −0.5 lands at −85 − 43 = −128 and 1.0 at 170 − 43 = 127.
- [ ] scale 1.0 ÷ 127, zero point 0
  That's symmetric quantization sized for ±1.0, which wastes the levels below −0.5.

Q: You quantize a model and accuracy drops from 94% to 61%. What should you check first?
- [ ] Whether int8 is too coarse for any neural network
  Most models lose little at int8; a drop this large points to a specific bug.
- [x] Whether a few extreme values set a huge range, or the input calibration data doesn't match real inputs
  Outliers stretch the scale and wrong calibration clips real inputs; both cause large drops.
- [ ] Whether the model was trained for enough epochs
  Training length affects the float model too, and that one scored 94%.
:::

:::takeaways
- Raw audio is 16,000 numbers a second; 25 ms frames, an FFT, mel filters, a log, and a DCT turn one second into about 1,300 MFCC values.
- A spectrogram shows frequencies over time; log-mel energies (MFE) suit general sounds; MFCCs compress them further for speech.
- Keyword spotters need keyword, unknown, and noise classes, and they slide a 1-second window along the stream.
- int8 quantization stores each number in 1 byte using a scale and zero point; each restored value is within half a step of the original.
- Check accuracy after quantizing, watch for outliers that stretch the range, and calibrate on realistic inputs.
:::
