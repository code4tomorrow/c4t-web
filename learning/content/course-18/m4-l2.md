:::objectives
- Generate a labeled audio dataset with keyword, unknown, and noise classes.
- Convert every clip to a 13 × 98 MFCC array with your own NumPy feature code.
- Train a small 1D convolutional network in PyTorch and count its bytes.
- Quantize each weight tensor to int8 with a scale and zero point, load it back, and compare accuracy.
- Quantize the inputs with a calibrated range, then push to fewer bits and chart accuracy against size.

Here's the plan: a model that listens to one second of sound and decides whether it heard the keyword **up**, the keyword **down**, some **unknown** other word, or just **noise**. Then you'll make it four times smaller without retraining, and measure exactly what that costs.

The keywords are synthetic: **up** is a tone that glides upward, **down** glides downward. That makes the data free to generate and easy to check by eye. Edge Impulse's own tutorial does the same job with recorded speech, and Step 8 maps every step onto it. Name your notebook `m4-l2-keyword-int8.ipynb`.

## Step 1: Generate the clips

Every clip gets realistic messiness: a random start time, length, pitch, and loudness, plus background hiss and mains hum at 50 or 60 Hz. The **unknown** class matters as much as the keywords. Without it, the model would learn "any tone is a keyword", because it must always pick one of its classes. Here, unknown sounds are flat tones and tones that step or bend, so the model has to learn the *direction* of the glide, not just "something happened".

```python run title="step 1: clips"
import numpy as np
import matplotlib.pyplot as plt
from scipy.fft import dct

SR = 16_000
CLASSES = ["up", "down", "unknown", "noise"]
rng = np.random.default_rng(0)

def tone(f_start, f_end, length):
    n = int(length * SR)
    pitch = np.linspace(f_start, f_end, n)
    phase = 2 * np.pi * np.cumsum(pitch) / SR
    fade = np.sin(np.pi * np.arange(n) / n) ** 2
    return fade * (np.sin(phase) + 0.4 * np.sin(2 * phase) + 0.2 * np.sin(3 * phase))

def background():
    t = np.arange(SR) / SR
    hum = rng.choice([50, 60]) * rng.integers(1, 4)            # mains hum and its harmonics
    return rng.uniform(0.01, 0.08) * rng.normal(size=SR) + rng.uniform(0, 0.05) * np.sin(2 * np.pi * hum * t)

def make_clip(label):
    audio = background()
    if label == "noise":
        return audio
    length, low, rise = rng.uniform(0.25, 0.55), rng.uniform(250, 600), rng.uniform(1.4, 2.2)
    if label == "up":
        sound = tone(low, low * rise, length)
    elif label == "down":
        sound = tone(low * rise, low, length)
    else:                                                      # other "words"
        kind, half = rng.integers(3), length / 2
        if kind == 0:
            sound = tone(low, low, length)                     # flat
        elif kind == 1:
            sound = np.concatenate([tone(low * rise, low * rise, half), tone(low, low, half)])
        else:
            sound = np.concatenate([tone(low, low * rise, half), tone(low * rise, low, half)])
    start = rng.integers(0, SR - len(sound))
    audio[start:start + len(sound)] += rng.uniform(0.2, 0.8) * sound
    return audio

labels = np.array([c for c in CLASSES for _ in range(150)])
clips = np.array([make_clip(label) for label in labels])
print("clips:", clips.shape)
```

600 clips × 16,000 samples. That's 9.6 million numbers of raw audio, which is exactly why the next step exists.

## Step 2: Turn every clip into MFCCs

This is the feature pipeline from the Notes, with one speed-up: instead of looping over frames, `FRAME_INDEX` is a 98 × 400 grid of sample positions, so `audio[FRAME_INDEX]` pulls out all 98 frames in one NumPy operation. The result is transposed to **13 × 98** (coefficients × time), the shape PyTorch's 1D convolution expects: channels first, then time.

```python run title="step 2: MFCCs" alt="Four heat maps of 13 MFCC coefficients over one second, one per class. Up, down, and unknown each show a band of change lasting a few tenths of a second at a different time; noise shows no distinct event." caption="One clip of each class as MFCCs"
FRAME, HOP, NFFT = 400, 160, 512                      # 25 ms frames, 10 ms apart

def hz_to_mel(f):
    return 2595 * np.log10(1 + f / 700)

def mel_to_hz(m):
    return 700 * (10 ** (m / 2595) - 1)

def mel_filterbank(n_filters=40):
    edges_hz = mel_to_hz(np.linspace(0, hz_to_mel(SR / 2), n_filters + 2))
    bin_hz = np.fft.rfftfreq(NFFT, d=1 / SR)
    bank = np.zeros((n_filters, len(bin_hz)))
    for i in range(n_filters):
        left, center, right = edges_hz[i:i + 3]
        bank[i] = np.clip(np.minimum((bin_hz - left) / (center - left),
                                     (right - bin_hz) / (right - center)), 0, None)
    return bank

BANK = mel_filterbank()
FRAME_INDEX = np.arange(0, SR - FRAME + 1, HOP)[:, None] + np.arange(FRAME)
HANN = np.hanning(FRAME)

def mfcc(audio, n_coeffs=13):
    frames = audio[FRAME_INDEX] * HANN
    power = np.abs(np.fft.rfft(frames, n=NFFT)) ** 2
    logmel = np.log(power @ BANK.T + 1e-10)
    return dct(logmel, type=2, axis=1, norm="ortho")[:, :n_coeffs].T      # (13, 98)

features = np.array([mfcc(c) for c in clips]).astype(np.float32)
print("features:", features.shape)

fig, axes = plt.subplots(1, 4, figsize=(10, 2.6), sharey=True)
for ax, label in zip(axes, CLASSES):
    ax.imshow(features[labels == label][0], origin="lower", aspect="auto", extent=[0, 1, 0, 13])
    ax.set_title(label)
    ax.set_xlabel("s")
axes[0].set_ylabel("MFCC")
fig.tight_layout()
```

Each clip shrank from 16,000 numbers to 1,274. The event shows up wherever it happened in the second, which is why the model in Step 4 must not care *where* in time the pattern sits.

## Step 3: Split and normalize

These clips are independent (each was generated separately), so a random split is fair here. With real recordings you'd split by **speaker**, for the same reason you split by recording in Module 3.

Each MFCC coefficient has its own typical range, so standardize them, one mean and one standard deviation **per coefficient**. That's 26 numbers the device must also store and apply before running the model.

```python run title="step 3: split"
y = np.array([CLASSES.index(label) for label in labels])
order = rng.permutation(len(y))
train_idx, test_idx = order[:450], order[450:]

mean = features[train_idx].mean(axis=(0, 2), keepdims=True)    # shape (1, 13, 1)
std = features[train_idx].std(axis=(0, 2), keepdims=True)
X_train = (features[train_idx] - mean) / std
X_test = (features[test_idx] - mean) / std
y_train, y_test = y[train_idx], y[test_idx]
print("train", X_train.shape, " test", X_test.shape, " test clips per class", np.bincount(y_test))
```

## Step 4: Train a small 1D CNN

A **1D convolution** slides a small filter along the time axis, looking at 5 frames (50 ms) at a time, so it finds a glide wherever it occurs. `AdaptiveMaxPool1d(1)` then keeps each filter's strongest response across the whole second, which makes the output independent of *when* the word was said. Edge Impulse's default network for audio is also built from 1D convolutions over the MFCCs, for the same reason.

```python run title="step 4: train"
import torch
from torch import nn

torch.manual_seed(1)
model = nn.Sequential(
    nn.Conv1d(13, 16, kernel_size=5, padding=2), nn.ReLU(), nn.MaxPool1d(2),
    nn.Conv1d(16, 32, kernel_size=5, padding=2), nn.ReLU(), nn.AdaptiveMaxPool1d(1),
    nn.Flatten(), nn.Linear(32, 4),
)
optimizer = torch.optim.Adam(model.parameters(), lr=3e-3)
loss_fn = nn.CrossEntropyLoss()
inputs, targets = torch.tensor(X_train), torch.tensor(y_train)

for epoch in range(15):
    perm = torch.randperm(len(inputs))
    for i in range(0, len(perm), 32):
        batch = perm[i:i + 32]
        optimizer.zero_grad()
        loss = loss_fn(model(inputs[batch]), targets[batch])
        loss.backward()
        optimizer.step()

def accuracy(net, x):
    with torch.no_grad():
        return (net(torch.tensor(x)).argmax(dim=1).numpy() == y_test).mean()

n_weights = sum(p.numel() for name, p in model.named_parameters() if name.endswith("weight"))
n_biases = sum(p.numel() for name, p in model.named_parameters() if name.endswith("bias"))
float_bytes = (n_weights + n_biases) * 4
print(f"float32 accuracy {accuracy(model, X_test):.1%}")
print(f"{n_weights:,} weights + {n_biases} biases = {float_bytes:,} bytes as float32")
```

3,780 parameters, about 15 KB. Your accuracy may differ by an example or two in Colab, since PyTorch's random numbers can vary between machines. This model would already fit on the Nano 33 BLE Sense; the point of the next steps is to see what quantization does to a model you can inspect completely.

## Step 5: Quantize the weights to int8 by hand

For each weight tensor: find its range, compute a scale and zero point, round to int8, then **dequantize** and put the result back into a copy of the model. Running the copy shows exactly what the int8 numbers can still do. This is called **fake quantization**, and it's how quantization is usually evaluated before deployment.

```python run title="step 5: int8 weights"
import copy

def quant_params(lo, hi):
    scale = (hi - lo) / 255
    return scale, int(round(-128 - lo / scale))

def quantize(x, scale, zero_point):
    return np.clip(np.round(x / scale) + zero_point, -128, 127).astype(np.int8)

def dequantize(q, scale, zero_point):
    return (q.astype(np.float32) - zero_point) * scale

int8_model = copy.deepcopy(model)
stored = {}
with torch.no_grad():
    for name, p in int8_model.named_parameters():
        if name.endswith("weight"):
            w = p.numpy().copy()
            s, z = quant_params(w.min(), w.max())
            q = quantize(w, s, z)
            stored[name] = (q, s, z)
            p.copy_(torch.from_numpy(dequantize(q, s, z)))
            err = np.abs(w - dequantize(q, s, z)).max()
            print(f"{name:<10}{str(tuple(w.shape)):<13} scale {s:.5f}  zero point {z:>3}  max error {err:.5f}")

int8_bytes = n_weights + n_biases * 4 + len(stored) * 8      # int8 weights, float32 biases, scale + zero point
print(f"int8 accuracy {accuracy(int8_model, X_test):.1%}   size {int8_bytes:,} bytes (was {float_bytes:,})")
```

Each tensor gets its own scale, so a layer with small weights isn't forced onto the coarse ruler of a layer with big ones. Biases stay in higher precision here; they're only 52 numbers, and real int8 runtimes keep them as 32-bit integers for the same reason. The model is now 3.8 times smaller, and accuracy moves by at most an example.

:::warning
Notice `.copy()` in `w = p.numpy().copy()`. `p.numpy()` doesn't copy anything: it gives a NumPy view of the *same memory* as the PyTorch tensor. Without `.copy()`, `p.copy_(...)` overwrites `w` too, and the "max error" line compares the dequantized weights with themselves and prints 0.00000 for every layer. A check that can't fail isn't a check.
:::

## Step 6: Quantize the inputs too

On a microcontroller running a fully int8 model, the **inputs** are int8 as well, so the MFCCs have to be squeezed into 256 levels. Their range comes from **calibration**: measure it on training data, then apply the same scale and zero point to every input the device will ever see.

```python run title="step 6: int8 inputs"
in_scale, in_zero = quant_params(X_train.min(), X_train.max())
X_test_int8 = dequantize(quantize(X_test, in_scale, in_zero), in_scale, in_zero)
print(f"input scale {in_scale:.4f}, zero point {in_zero}")
print(f"int8 weights + int8 inputs accuracy {accuracy(int8_model, X_test_int8):.1%}")
```

If a real input falls outside the calibrated range, `np.clip` pins it at −128 or 127. That's why calibration data should include the loudest and quietest situations the device will meet.

## Step 7: How low can the bits go?

int8 isn't the only choice. Some hardware supports 4-bit weights, and fewer bits mean less memory. Generalize the quantizer to any bit width and sweep.

```python run title="step 7: bits sweep" alt="Line chart of test accuracy against model size in kilobytes. Points are labeled float32 at about 14.8 KB, then 8, 6, 4, 3, and 2 bits at smaller sizes. Accuracy holds near the float32 value down to 8 and 6 bits, then falls step by step at 4, 3, and 2 bits." caption="Accuracy against size as the weights lose bits"
def quantize_bits(x, bits):
    levels = 2 ** bits
    qmin, qmax = -(levels // 2), levels // 2 - 1
    scale = (x.max() - x.min()) / (levels - 1)
    zero_point = round(qmin - x.min() / scale)
    q = np.clip(np.round(x / scale) + zero_point, qmin, qmax)
    return ((q - zero_point) * scale).astype(np.float32)

points = [("float32", float_bytes / 1024, accuracy(model, X_test))]
for bits in (8, 6, 4, 3, 2):
    net = copy.deepcopy(model)
    with torch.no_grad():
        for name, p in net.named_parameters():
            if name.endswith("weight"):
                p.copy_(torch.from_numpy(quantize_bits(p.numpy(), bits)))
    kb = (n_weights * bits / 8 + n_biases * 4) / 1024
    points.append((f"{bits}-bit", kb, accuracy(net, X_test)))

for label, kb, acc in points:
    print(f"{label:>8}: {kb:5.1f} KB   accuracy {acc:.1%}")

plt.figure(figsize=(7, 3.2))
plt.plot([p[1] for p in points], [p[2] * 100 for p in points], "o-")
for label, kb, acc in points:
    plt.annotate(label, (kb, acc * 100), textcoords="offset points", xytext=(4, 6), fontsize=8)
plt.xlabel("model size (KB)")
plt.ylabel("test accuracy (%)")
plt.title("Fewer bits, smaller model")
```

The curve has the shape you'll see on real models: nearly flat from float32 down through 8 and 6 bits (one test clip of difference), then a slide as the ruler gets too coarse to tell weights apart. This task is easy, so even 2 bits survives better than most real models would; a harder task usually loses more at each step. int8 sits in the sweet spot, which is why it's the standard for microcontrollers.

## The finished program

Steps 1 to 6 in one cell, without the charts or the sweep. It prints the float32 and int8 results.

```python run title="keyword_int8.py"
import copy
import numpy as np
import torch
from torch import nn
from scipy.fft import dct

SR, FRAME, HOP, NFFT = 16_000, 400, 160, 512
CLASSES = ["up", "down", "unknown", "noise"]
rng = np.random.default_rng(0)

def tone(f0, f1, length):
    n = int(length * SR)
    phase = 2 * np.pi * np.cumsum(np.linspace(f0, f1, n)) / SR
    return np.sin(np.pi * np.arange(n) / n) ** 2 * (np.sin(phase) + 0.4 * np.sin(2 * phase) + 0.2 * np.sin(3 * phase))

def make_clip(label):
    t = np.arange(SR) / SR
    hum = rng.choice([50, 60]) * rng.integers(1, 4)
    audio = rng.uniform(0.01, 0.08) * rng.normal(size=SR) + rng.uniform(0, 0.05) * np.sin(2 * np.pi * hum * t)
    if label == "noise":
        return audio
    length, low, rise = rng.uniform(0.25, 0.55), rng.uniform(250, 600), rng.uniform(1.4, 2.2)
    if label == "up":
        sound = tone(low, low * rise, length)
    elif label == "down":
        sound = tone(low * rise, low, length)
    else:
        kind, half = rng.integers(3), length / 2
        if kind == 0:
            sound = tone(low, low, length)
        elif kind == 1:
            sound = np.concatenate([tone(low * rise, low * rise, half), tone(low, low, half)])
        else:
            sound = np.concatenate([tone(low, low * rise, half), tone(low * rise, low, half)])
    start = rng.integers(0, SR - len(sound))
    audio[start:start + len(sound)] += rng.uniform(0.2, 0.8) * sound
    return audio

def mel_filterbank(n_filters=40):
    to_mel = lambda f: 2595 * np.log10(1 + f / 700)
    to_hz = lambda m: 700 * (10 ** (m / 2595) - 1)
    edges = to_hz(np.linspace(0, to_mel(SR / 2), n_filters + 2))
    bins = np.fft.rfftfreq(NFFT, d=1 / SR)
    return np.array([np.clip(np.minimum((bins - l) / (c - l), (r - bins) / (r - c)), 0, None)
                     for l, c, r in zip(edges, edges[1:], edges[2:])])

BANK, HANN = mel_filterbank(), np.hanning(FRAME)
FRAME_INDEX = np.arange(0, SR - FRAME + 1, HOP)[:, None] + np.arange(FRAME)

def mfcc(audio):
    power = np.abs(np.fft.rfft(audio[FRAME_INDEX] * HANN, n=NFFT)) ** 2
    return dct(np.log(power @ BANK.T + 1e-10), type=2, axis=1, norm="ortho")[:, :13].T

def quant_params(lo, hi):
    scale = (hi - lo) / 255
    return scale, int(round(-128 - lo / scale))

def quantize(x, scale, zero_point):
    return np.clip(np.round(x / scale) + zero_point, -128, 127).astype(np.int8)

def dequantize(q, scale, zero_point):
    return (q.astype(np.float32) - zero_point) * scale

labels = np.array([c for c in CLASSES for _ in range(150)])
features = np.array([mfcc(make_clip(label)) for label in labels]).astype(np.float32)
y = np.array([CLASSES.index(label) for label in labels])
order = rng.permutation(len(y))
train_idx, test_idx = order[:450], order[450:]
mean = features[train_idx].mean(axis=(0, 2), keepdims=True)
std = features[train_idx].std(axis=(0, 2), keepdims=True)
X_train, X_test = (features[train_idx] - mean) / std, (features[test_idx] - mean) / std
y_train, y_test = y[train_idx], y[test_idx]

torch.manual_seed(1)
model = nn.Sequential(
    nn.Conv1d(13, 16, kernel_size=5, padding=2), nn.ReLU(), nn.MaxPool1d(2),
    nn.Conv1d(16, 32, kernel_size=5, padding=2), nn.ReLU(), nn.AdaptiveMaxPool1d(1),
    nn.Flatten(), nn.Linear(32, 4))
optimizer = torch.optim.Adam(model.parameters(), lr=3e-3)
inputs, targets = torch.tensor(X_train), torch.tensor(y_train)
for epoch in range(15):
    perm = torch.randperm(len(inputs))
    for i in range(0, len(perm), 32):
        batch = perm[i:i + 32]
        optimizer.zero_grad()
        nn.functional.cross_entropy(model(inputs[batch]), targets[batch]).backward()
        optimizer.step()

def accuracy(net, x):
    with torch.no_grad():
        return (net(torch.tensor(x)).argmax(dim=1).numpy() == y_test).mean()

int8_model = copy.deepcopy(model)
with torch.no_grad():
    for name, p in int8_model.named_parameters():
        if name.endswith("weight"):
            w = p.numpy().copy()
            s, z = quant_params(w.min(), w.max())
            p.copy_(torch.from_numpy(dequantize(quantize(w, s, z), s, z)))
in_s, in_z = quant_params(X_train.min(), X_train.max())
X_test_int8 = dequantize(quantize(X_test, in_s, in_z), in_s, in_z)

print(f"float32:                  {accuracy(model, X_test):.1%}")
print(f"int8 weights:             {accuracy(int8_model, X_test):.1%}")
print(f"int8 weights and inputs:  {accuracy(int8_model, X_test_int8):.1%}")
```

:::quiz
Q: Why does the dataset include an **unknown** class of flat and bent tones, not just up, down, and noise?
- [x] Without it, any tone would be called up or down, because the model must always choose one of its classes
  The unknown class teaches the model that "a tone happened" isn't enough; it has to be the right glide.
- [ ] To make the classes the same size
  The classes are balanced at 150 each either way; unknown is there for what it teaches.
- [ ] Because Edge Impulse requires exactly four classes
  Edge Impulse accepts any number of classes; its tutorial uses keyword, unknown, and noise for the same reason this build does.

Q: Why does Step 5 give each weight tensor its own scale and zero point instead of one for the whole model?
- [ ] PyTorch can't store one scale for several tensors
  It's a design choice, not a library limit.
- [x] Layers have different weight ranges, and one shared range would give the small-weight layers far fewer usable levels
  Per-tensor ranges fit the ruler to each layer, so a layer with small weights still uses all 256 levels.
- [ ] It makes the model smaller
  Each extra scale and zero point adds 8 bytes, so it's slightly larger; it's done for accuracy.

Q: In Step 6, the calibration range comes from the training inputs. What happens on the device if a clip is much louder than anything in training?
- [ ] The device recalibrates automatically
  The scale and zero point are fixed constants in the deployed model.
- [x] Some MFCC values exceed the calibrated range and get clipped to 127 (or −128), which can change the prediction
  `np.clip` (and the int8 type itself) can't represent values beyond the range, so they're flattened.
- [ ] Nothing, because MFCCs are always between −1 and 1
  The standardized MFCCs here range well beyond ±1; their range depends on the audio.
:::

:::takeaways
- A keyword spotter needs keyword, **unknown**, and **noise** classes, or every sound becomes a keyword.
- MFCCs shrink each second from 16,000 numbers to 1,274, and a 1D CNN with global max pooling finds the pattern wherever it occurs in the window.
- Fake quantization (quantize, dequantize, put back, evaluate) measures what an int8 model can do before you deploy it.
- Give each tensor its own scale and zero point, keep biases at higher precision, and calibrate input ranges on realistic data.
- int8 cut this model by about 3.8× with almost no accuracy change; below 4 bits accuracy starts to slide.
:::

## Ideas to extend it

- Replace the CNN with a plain `nn.Linear(1274, 64)` network on the flattened MFCCs. Compare its parameter count and accuracy with the CNN's, and think about why position in time hurts it.
- Quantize each **output channel** of the conv layers with its own scale (per-channel quantization) and see whether 3-bit accuracy improves.
- Add a fifth class, a "click" made of a very short burst of noise, and check whether the model still separates all classes.
