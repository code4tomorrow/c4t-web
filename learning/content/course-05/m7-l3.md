:::objectives
- Prove a refactor kept behavior identical by comparing old and new code over many inputs.
- Apply named constants, extract function, introduce parameter object, and replace conditional with polymorphism.
- Repair a subclass that breaks its parent's promises.
- Make code that depends on randomness testable by passing the dependency in.
:::

Every exercise here starts from code that works. Your job is to change its shape without changing its behavior, so each solution ends with a check that old and new agree. Keep the original as `old_...` in the same file while you work; that's your characterization test for free.

## Warm-up: name the smells

Before reading on, list every smell you can find in this function.

```python run title="warmup.py"
def summary(u):
    if u["t"] == "free":
        s = f"{u['n']} ({u['e']}): 1 project"
    elif u["t"] == "pro":
        s = f"{u['n']} ({u['e']}): 10 projects"
    elif u["t"] == "team":
        s = f"{u['n']} ({u['e']}): 10 projects x {u['seats']} seats"
    return s

print(summary({"n": "Ana", "e": "ana@example.com", "t": "pro"}))
```

Cryptic names (`u`, `s`, `"t"`); primitive obsession, since a user is a dict of one-letter keys; a type switch on `u["t"]`; duplicated formatting of name and email in every branch; magic numbers (1, 10); and a latent crash, because an unknown plan leaves `s` unassigned and raises `UnboundLocalError`.

### Exercise 1: Name the numbers, extract the repetition

```python title="phone_bill.py"
def bill(minutes, texts, gb):
    cost = 15
    if minutes > 300:
        cost += (minutes - 300) * 0.05
    if texts > 500:
        cost += (texts - 500) * 0.02
    if gb > 5:
        cost += (gb - 5) * 3
    if cost > 60:
        cost = 60
    return round(cost, 2)


for usage in [(250, 100, 2), (400, 600, 7), (2000, 3000, 30)]:
    print(usage, bill(*usage))
```

Replace every number with a named constant, and extract one `overage(used, included, rate)` function that replaces the three look-alike `if` blocks. Then prove nothing changed: compare the old and new `bill` on every combination of a few thousand inputs.

:::hint
`itertools.product(range(0, 1000, 50), range(0, 1200, 100), range(12))` gives you every combination of three ranges. `all(old_bill(*u) == bill(*u) for u in ...)` checks them in one line.
:::

:::solution
```python run title="phone_bill.py"
from itertools import product

BASE_PRICE = 15.00
MONTHLY_CAP = 60.00
INCLUDED_MINUTES, PER_MINUTE = 300, 0.05
INCLUDED_TEXTS, PER_TEXT = 500, 0.02
INCLUDED_GB, PER_GB = 5, 3.00


def overage(used: float, included: float, rate: float) -> float:
    return max(0, used - included) * rate


def bill(minutes: int, texts: int, gb: int) -> float:
    cost = (
        BASE_PRICE
        + overage(minutes, INCLUDED_MINUTES, PER_MINUTE)
        + overage(texts, INCLUDED_TEXTS, PER_TEXT)
        + overage(gb, INCLUDED_GB, PER_GB)
    )
    return round(min(cost, MONTHLY_CAP), 2)


def old_bill(minutes, texts, gb):
    cost = 15
    if minutes > 300:
        cost += (minutes - 300) * 0.05
    if texts > 500:
        cost += (texts - 500) * 0.02
    if gb > 5:
        cost += (gb - 5) * 3
    if cost > 60:
        cost = 60
    return round(cost, 2)


grid = list(product(range(0, 1000, 50), range(0, 1200, 100), range(12)))
print(len(grid), "inputs compared, all equal:", all(old_bill(*u) == bill(*u) for u in grid))
```

`overage` encodes the one rule the three blocks shared ("only what's over the allowance costs extra"), and the constants put every number the phone company might change in one place. Comparing thousands of inputs catches mistakes a handful of hand-picked tests would miss.
:::

### Exercise 2: Introduce a parameter object

Six loose values travel together through `clashes`. Introduce a frozen dataclass `Slot(day, start, end)` with an `overlaps` method and a `__str__`, and a `Booking(room, slot)`. Moving the clash test onto `Slot` also fixes a feature-envy smell: the function only ever used a slot's data.

```python title="rooms.py"
def clashes(day_a, start_a, end_a, day_b, start_b, end_b):
    return day_a == day_b and start_a < end_b and start_b < end_a


def describe(room, day, start, end):
    return f"{room}: {day} {start}:00-{end}:00"


bookings = [("Lab", "Mon", 9, 11), ("Lab", "Mon", 10, 12), ("Gym", "Tue", 14, 16)]
for i, (room_a, *slot_a) in enumerate(bookings):
    for room_b, *slot_b in bookings[i + 1:]:
        if room_a == room_b and clashes(*slot_a, *slot_b):
            print("Clash:", describe(room_a, *slot_a), "and", describe(room_b, *slot_b))
```

Expected output, unchanged: `Clash: Lab: Mon 9:00-11:00 and Lab: Mon 10:00-12:00`

:::hint
Give `Booking` a method `clashes_with(other)` that checks the room and then delegates to `self.slot.overlaps(other.slot)`.
:::

:::solution
```python run title="rooms.py"
from dataclasses import dataclass


@dataclass(frozen=True)
class Slot:
    day: str
    start: int
    end: int

    def overlaps(self, other: "Slot") -> bool:
        return self.day == other.day and self.start < other.end and other.start < self.end

    def __str__(self) -> str:
        return f"{self.day} {self.start}:00-{self.end}:00"


@dataclass(frozen=True)
class Booking:
    room: str
    slot: Slot

    def clashes_with(self, other: "Booking") -> bool:
        return self.room == other.room and self.slot.overlaps(other.slot)

    def __str__(self) -> str:
        return f"{self.room}: {self.slot}"


bookings = [Booking("Lab", Slot("Mon", 9, 11)), Booking("Lab", Slot("Mon", 10, 12)), Booking("Gym", Slot("Tue", 14, 16))]
for i, a in enumerate(bookings):
    for b in bookings[i + 1:]:
        if a.clashes_with(b):
            print("Clash:", a, "and", b)
```

The loop no longer unpacks tuples with `*slot_a`, and nobody can pass a start and end in the wrong order without it being obvious, because they're named fields.
:::

### Exercise 3: Replace the format switch with classes

```python title="export.py"
import json


def export(rows, fmt):
    if fmt == "csv":
        lines = [",".join(rows[0].keys())]
        for row in rows:
            lines.append(",".join(str(v) for v in row.values()))
        return "\n".join(lines)
    elif fmt == "json":
        return json.dumps(rows)
    elif fmt == "markdown":
        header = "| " + " | ".join(rows[0].keys()) + " |"
        rule = "|" + "---|" * len(rows[0])
        body = ["| " + " | ".join(str(v) for v in row.values()) + " |" for row in rows]
        return "\n".join([header, rule] + body)
    else:
        raise ValueError(f"unknown format {fmt!r}")


rows = [{"name": "Ana", "score": 93}, {"name": "Ben", "score": 71}]
for fmt in ["csv", "json", "markdown"]:
    print(export(rows, fmt), end="\n\n")
```

Write one class per format, each with `export(rows) -> str`, and a dict `EXPORTERS` mapping names to instances. Keep `export(rows, fmt)` as a thin wrapper (it must still raise `ValueError` for an unknown format). Then add tab-separated output by writing a single new class.

:::hint
The wrapper becomes a dictionary lookup inside `try`/`except KeyError`, re-raising as `ValueError ... from None` so callers see the same error type as before.
:::

:::solution
```python run title="export.py"
import json


class CsvExporter:
    separator = ","

    def export(self, rows: list[dict]) -> str:
        lines = [self.separator.join(rows[0].keys())]
        lines += [self.separator.join(str(v) for v in row.values()) for row in rows]
        return "\n".join(lines)


class TsvExporter(CsvExporter):
    separator = "\t"


class JsonExporter:
    def export(self, rows: list[dict]) -> str:
        return json.dumps(rows)


class MarkdownExporter:
    def export(self, rows: list[dict]) -> str:
        header = "| " + " | ".join(rows[0].keys()) + " |"
        rule = "|" + "---|" * len(rows[0])
        body = ["| " + " | ".join(str(v) for v in row.values()) + " |" for row in rows]
        return "\n".join([header, rule] + body)


EXPORTERS = {"csv": CsvExporter(), "tsv": TsvExporter(), "json": JsonExporter(), "markdown": MarkdownExporter()}


def export(rows: list[dict], fmt: str) -> str:
    try:
        exporter = EXPORTERS[fmt]
    except KeyError:
        raise ValueError(f"unknown format {fmt!r}") from None
    return exporter.export(rows)


rows = [{"name": "Ana", "score": 93}, {"name": "Ben", "score": 71}]
for fmt in ["csv", "json", "markdown", "tsv"]:
    print(export(rows, fmt), end="\n\n")
try:
    export(rows, "pdf")
except ValueError as err:
    print("ValueError:", err)
```

`TsvExporter` inherits everything from `CsvExporter` and changes one class attribute. That's inheritance used well: a TSV file really is a CSV file with a different separator, so every promise the parent makes still holds. `from None` hides the internal `KeyError` from the traceback, because it's an implementation detail.
:::

### Exercise 4: The square that broke the rectangle

`stretch` was written for rectangles and assumes that setting the width leaves the height alone. Run it with a `Square`:

```python run raises title="shapes.py"
class Rectangle:
    def __init__(self, width: float, height: float) -> None:
        self.width = width
        self.height = height

    def set_width(self, width: float) -> None:
        self.width = width

    def set_height(self, height: float) -> None:
        self.height = height

    def area(self) -> float:
        return self.width * self.height


class Square(Rectangle):
    def __init__(self, side: float) -> None:
        super().__init__(side, side)

    def set_width(self, width: float) -> None:
        self.width = self.height = width

    def set_height(self, height: float) -> None:
        self.width = self.height = height


def stretch(rect: Rectangle) -> None:
    rect.set_width(10)
    rect.set_height(2)
    assert rect.area() == 20, f"expected 20, got {rect.area()}"


stretch(Rectangle(3, 4))
print("rectangle ok")
stretch(Square(5))
```

Restructure the classes so this can't happen: a shared `Shape` ABC with `area()`, and `Rectangle` and `Square` as separate, immutable (frozen dataclass) implementations. `stretch` should return a new `Rectangle` instead of mutating one.

:::hint
A square can't keep the promise "changing width doesn't change height", so it shouldn't inherit it. The only promise the two really share is "I have an area".
:::

:::solution
```python run title="shapes.py"
from abc import ABC, abstractmethod
from dataclasses import dataclass


class Shape(ABC):
    @abstractmethod
    def area(self) -> float: ...


@dataclass(frozen=True)
class Rectangle(Shape):
    width: float
    height: float

    def area(self) -> float:
        return self.width * self.height


@dataclass(frozen=True)
class Square(Shape):
    side: float

    def area(self) -> float:
        return self.side**2


def stretch(rect: Rectangle) -> Rectangle:
    return Rectangle(10, 2)


def total_area(shapes: list[Shape]) -> float:
    return sum(shape.area() for shape in shapes)


print(stretch(Rectangle(3, 4)).area())
print(total_area([Rectangle(3, 4), Square(5)]))
```

Code that needs "any shape" takes `Shape` and only calls `area()`, which both keep. Code that needs width and height takes `Rectangle`, and a `Square` can't be passed in by accident. Immutability removes the setters, which were the promise `Square` couldn't keep.
:::

### Exercise 5: Inject the randomness

A 5% chance of a dragon egg is nearly impossible to test when the function calls `random.random()` itself:

```python title="loot.py"
import random


def open_chest() -> str:
    roll = random.random()
    if roll < 0.05:
        return "dragon egg"
    if roll < 0.30:
        return "gold"
    return "rusty spoon"


print(open_chest())
```

Change it to `open_chest(rng)`, where `rng` is anything with a `.random()` method. The game passes `random.Random()`; tests pass a `FakeRng` that returns chosen numbers. Write `unittest` tests for all three outcomes and for both boundaries (exactly `0.05` and exactly `0.30`).

:::hint
`FakeRng` needs only `__init__(self, value)` and `random(self)`. Test boundaries deliberately; that's where `<` versus `<=` bugs hide.
:::

:::solution
```python run title="test_loot.py"
import random
import sys
import unittest

EGG_BELOW = 0.05   # rolls under this: 5% chance of an egg
GOLD_BELOW = 0.30  # rolls from 0.05 up to this: 25% chance of gold


def open_chest(rng) -> str:
    roll = rng.random()
    if roll < EGG_BELOW:
        return "dragon egg"
    if roll < GOLD_BELOW:
        return "gold"
    return "rusty spoon"


class FakeRng:
    def __init__(self, value: float) -> None:
        self.value = value

    def random(self) -> float:
        return self.value


class TestChest(unittest.TestCase):
    def test_low_roll_is_an_egg(self):
        self.assertEqual(open_chest(FakeRng(0.01)), "dragon egg")

    def test_exactly_egg_chance_is_gold(self):
        self.assertEqual(open_chest(FakeRng(0.05)), "gold")

    def test_exactly_thirty_percent_is_a_spoon(self):
        self.assertEqual(open_chest(FakeRng(0.30)), "rusty spoon")

    def test_high_roll_is_a_spoon(self):
        self.assertEqual(open_chest(FakeRng(0.99)), "rusty spoon")


suite = unittest.defaultTestLoader.loadTestsFromTestCase(TestChest)
unittest.TextTestRunner(stream=sys.stdout, verbosity=2).run(suite)

seeded = random.Random(7)
print([open_chest(seeded) for _ in range(5)])
```

The real game stays random, a seeded `random.Random(7)` gives the same sequence on every run (handy for reproducing a player's bug report), and the tests are exact. This is dependency inversion again: `open_chest` depends on "something with `random()`", not on the `random` module.
:::

### Exercise 6: Pin down code you don't understand

Nobody remembers why member codes are computed this way, but codes are printed on cards that are already in people's wallets, so the output must never change.

```python title="codes.py"
def code_for(n):
    s = "".join(c for c in n.upper() if c.isalpha())
    if len(s) < 3:
        s = s + "X" * (3 - len(s))
    t = 0
    for i, c in enumerate(s):
        t = t + (ord(c) - 64) * (i + 1)
    return s[:3] + "-" + str(t % 97).zfill(2)
```

First, run it on at least six varied names (short, punctuated, mixed case, a single letter) and save the results as a dict of expected codes. That dict *is* your characterization test. Then rewrite the function with readable helpers and prove every expected code still matches.

:::hint
You don't need to understand *why* the formula exists to preserve it. Translate it piece by piece: letters only, pad to three, a weighted sum of letter positions, two-digit remainder.
:::

:::solution
```python run title="codes.py"
def old_code_for(n):
    s = "".join(c for c in n.upper() if c.isalpha())
    if len(s) < 3:
        s = s + "X" * (3 - len(s))
    t = 0
    for i, c in enumerate(s):
        t = t + (ord(c) - 64) * (i + 1)
    return s[:3] + "-" + str(t % 97).zfill(2)


names = ["Ana", "Al", "o'Neil", "BEN TAYLOR", "q", "Mary-Jo"]
expected = {name: old_code_for(name) for name in names}
print(expected)


def letters_only(name: str) -> str:
    return "".join(ch for ch in name.upper() if ch.isalpha())


def checksum(letters: str) -> int:
    """Each letter's alphabet position (A=1), weighted by where it appears."""
    return sum((ord(ch) - ord("A") + 1) * place for place, ch in enumerate(letters, start=1)) % 97


def code_for(name: str) -> str:
    letters = letters_only(name).ljust(3, "X")
    return f"{letters[:3]}-{checksum(letters):02d}"


print(all(code_for(name) == code for name, code in expected.items()))
```

The pinned dict caught every subtle detail you might have "tidied" by accident, such as the checksum using *all* the letters rather than just the first three. `str.ljust(3, "X")` pads only when the string is shorter, exactly like the original `if`.
:::

### Challenge: Turn a command switch into command classes

This handler for a tiny text adventure has an `if`/`elif` branch per command, and it'll keep growing. Refactor it into a `Command` ABC with a `names` tuple and `run(args, state) -> str`, one class per command, and a `Registry` that maps every name (including the `"i"` shortcut) to its command. `handle` should become a lookup. Prove the replies are identical for the script below, then add a `Drop` command without editing the registry.

```python title="adventure.py"
EXITS = {"hall": {"north": "library"}, "library": {"south": "hall"}}


def handle(line, state):
    words = line.lower().split()
    if not words:
        return "Say something."
    if words[0] == "look":
        return f"You are in the {state['room']}."
    elif words[0] == "go" and len(words) == 2:
        if words[1] in EXITS[state["room"]]:
            state["room"] = EXITS[state["room"]][words[1]]
            return f"You walk {words[1]} to the {state['room']}."
        return "You can't go that way."
    elif words[0] == "take" and len(words) == 2:
        state["bag"].append(words[1])
        return f"Taken: {words[1]}."
    elif words[0] in ("inventory", "i"):
        return "You carry: " + (", ".join(state["bag"]) or "nothing")
    else:
        return "I don't understand that."


script = ["look", "look around", "go west", "go north", "take", "take map", "i", "dance", ""]
state = {"room": "hall", "bag": []}
for line in script:
    print(f"> {line}\n{handle(line, state)}")
```

Read the original closely: `look` and `inventory` ignore any extra words, but `go` and `take` only match with exactly one word after them; otherwise they fall through to "I don't understand that." Give each command an `arity`, with `None` meaning "any number of words", so the registry can preserve that quirk.
:::

:::solution
```python run title="adventure.py"
from abc import ABC, abstractmethod

EXITS = {"hall": {"north": "library"}, "library": {"south": "hall"}}


class Command(ABC):
    names: tuple[str, ...] = ()
    arity: int | None = None  # None: accept any number of words

    @abstractmethod
    def run(self, args: list[str], state: dict) -> str: ...


class Look(Command):
    names = ("look",)

    def run(self, args, state):
        return f"You are in the {state['room']}."


class Go(Command):
    names, arity = ("go",), 1

    def run(self, args, state):
        direction = args[0]
        if direction not in EXITS[state["room"]]:
            return "You can't go that way."
        state["room"] = EXITS[state["room"]][direction]
        return f"You walk {direction} to the {state['room']}."


class Take(Command):
    names, arity = ("take",), 1

    def run(self, args, state):
        state["bag"].append(args[0])
        return f"Taken: {args[0]}."


class Inventory(Command):
    names = ("inventory", "i")

    def run(self, args, state):
        return "You carry: " + (", ".join(state["bag"]) or "nothing")


class Drop(Command):
    names, arity = ("drop",), 1

    def run(self, args, state):
        if args[0] not in state["bag"]:
            return f"You don't have a {args[0]}."
        state["bag"].remove(args[0])
        return f"Dropped: {args[0]}."


class Registry:
    def __init__(self, commands: list[Command]) -> None:
        self._by_name = {name: command for command in commands for name in command.names}

    def handle(self, line: str, state: dict) -> str:
        words = line.lower().split()
        if not words:
            return "Say something."
        command = self._by_name.get(words[0])
        args = words[1:]
        if command is None or (command.arity is not None and len(args) != command.arity):
            return "I don't understand that."
        return command.run(args, state)


def old_handle(line, state):
    words = line.lower().split()
    if not words:
        return "Say something."
    if words[0] == "look":
        return f"You are in the {state['room']}."
    elif words[0] == "go" and len(words) == 2:
        if words[1] in EXITS[state["room"]]:
            state["room"] = EXITS[state["room"]][words[1]]
            return f"You walk {words[1]} to the {state['room']}."
        return "You can't go that way."
    elif words[0] == "take" and len(words) == 2:
        state["bag"].append(words[1])
        return f"Taken: {words[1]}."
    elif words[0] in ("inventory", "i"):
        return "You carry: " + (", ".join(state["bag"]) or "nothing")
    else:
        return "I don't understand that."


script = ["look", "look around", "go west", "go north", "take", "take map", "i", "dance", ""]
registry = Registry([Look(), Go(), Take(), Inventory(), Drop()])
old_state, new_state = {"room": "hall", "bag": []}, {"room": "hall", "bag": []}
old_replies = [old_handle(line, old_state) for line in script]
new_replies = [registry.handle(line, new_state) for line in script]
print("identical:", old_replies == new_replies and old_state == new_state)
for line in ["drop map", "drop map", "i"]:
    print(f"> {line}\n{registry.handle(line, new_state)}")
```

The comparison checks the final game state as well as every reply, since a command could print the right text and still update the wrong thing. Preserving the arity quirk exactly is the refactor; making `look` strict about extra words would be a separate, deliberate change with its own test. This command structure is also the backbone of the capstone's adventure engine.
:::
