## Warm-up: plain class or dataclass?

Predict the three lines this prints.

```python title="warmup.py"
from dataclasses import dataclass


class PlainBook:
    def __init__(self, title):
        self.title = title


@dataclass
class DataBook:
    title: str


print(PlainBook("Dune") == PlainBook("Dune"))
print(DataBook("Dune") == DataBook("Dune"))
print(DataBook("Dune"))
```

:::solution Check your prediction
```python run title="warmup.py"
from dataclasses import dataclass


class PlainBook:
    def __init__(self, title):
        self.title = title


@dataclass
class DataBook:
    title: str


print(PlainBook("Dune") == PlainBook("Dune"))
print(DataBook("Dune") == DataBook("Dune"))
print(DataBook("Dune"))
```

A plain class compares by identity, so two separate objects are never equal. The dataclass generated an `__eq__` that compares fields, and a `__repr__` that shows them.
:::

### Exercise 1: A thermostat that guards its target

Write `Thermostat(room, target)`. `target` is a property whose setter refuses anything outside 10 to 30 degrees with a `ValueError`. Add a read-only property `mode` that returns `"heating"` when the room is colder than the target and `"idle"` otherwise. Remember the constructor should go through the setter too.

```text
target 21, room 18 -> heating
target 18, room 18 -> idle
Refused: target must be between 10 and 30, got 45
```

:::hint
In `__init__`, write `self.target = target` (no underscore) so the setter runs. `mode` needs only a getter; it computes its answer every time from `self.room` and `self._target`.
:::

:::solution
```python run title="thermostat.py"
class Thermostat:
    def __init__(self, room, target):
        self.room = room
        self.target = target  # goes through the setter

    @property
    def target(self):
        return self._target

    @target.setter
    def target(self, value):
        if not 10 <= value <= 30:
            raise ValueError(f"target must be between 10 and 30, got {value}")
        self._target = value

    @property
    def mode(self):
        return "heating" if self.room < self._target else "idle"


t = Thermostat(room=18, target=21)
print(f"target {t.target}, room {t.room} -> {t.mode}")
t.target = 18
print(f"target {t.target}, room {t.room} -> {t.mode}")
try:
    t.target = 45
except ValueError as err:
    print("Refused:", err)
```

`mode` is never stored, so it can never be out of date. A computed property is the right tool for any value that follows from other state.
:::

### Exercise 2: Fix the inventory record

This dataclass fails before a single object is created. Fix the error, then add a `__post_init__` method (dataclasses call it right after their generated `__init__`) that raises `ValueError` if `quantity` is negative.

```python run raises title="item.py"
from dataclasses import dataclass


@dataclass
class InventoryItem:
    name: str
    quantity: int = 0
    tags: list[str] = []


print(InventoryItem("pencil", 40))
```

```text
InventoryItem(name='pencil', quantity=40, tags=[])
InventoryItem(name='eraser', quantity=5, tags=['art'])
Refused: quantity can't be negative, got -3
```

:::hint
The error message names the fix: `field(default_factory=list)`. `__post_init__(self)` takes no other arguments; read `self.quantity` inside it.
:::

:::solution
```python run title="item.py"
from dataclasses import dataclass, field


@dataclass
class InventoryItem:
    name: str
    quantity: int = 0
    tags: list[str] = field(default_factory=list)

    def __post_init__(self):
        if self.quantity < 0:
            raise ValueError(f"quantity can't be negative, got {self.quantity}")


print(InventoryItem("pencil", 40))
eraser = InventoryItem("eraser", 5)
eraser.tags.append("art")
print(eraser)
try:
    InventoryItem("glue", -3)
except ValueError as err:
    print("Refused:", err)
```

`__post_init__` is where a dataclass checks its rules. Note it only runs at creation; for rules that must hold after every change, use a property instead, as in Exercise 1.
:::

### Exercise 3: Sort the shelf

A library shelves books by author, then title. Write a `Book` dataclass with `order=True` so `sorted()` works with no `key`. It also has a `copies` count, which should *not* affect sorting or equality.

```text
Herbert: Children of Dune
Herbert: Dune
Sachar: Holes
True
```

The last line is `Book("Herbert", "Dune", copies=3) == Book("Herbert", "Dune", copies=1)`.

:::hint
With `order=True`, fields are compared in the order they are declared, so declare `author` before `title`. `field(default=1, compare=False)` leaves a field out of both `==` and `<`.
:::

:::solution
```python run title="shelf.py"
from dataclasses import dataclass, field


@dataclass(order=True)
class Book:
    author: str
    title: str
    copies: int = field(default=1, compare=False)


shelf = [Book("Sachar", "Holes"), Book("Herbert", "Dune", 3), Book("Herbert", "Children of Dune")]
for book in sorted(shelf):
    print(f"{book.author}: {book.title}")
print(Book("Herbert", "Dune", copies=3) == Book("Herbert", "Dune", copies=1))
```

The field order is the sort order. Moving `title` above `author` would quietly change how every shelf sorts, so a comment saying so is worth adding in real code.
:::

### Exercise 4: A Money value object

Prices stored as floats drift (`0.1 + 0.2` isn't `0.3`). Write a frozen dataclass `Money` that stores whole **cents**. Add `__add__` so two `Money` values add up (returning `NotImplemented` for anything else), and `__str__` so it prints as dollars.

```text
$4.50 + $0.75 = $5.25
Basket total: $7.74
True
Refused: unsupported operand type(s) for +: 'Money' and 'int'
```

:::hint
`__add__(self, other)` should return `Money(self.cents + other.cents)`. For the dollars string, `divmod(self.cents, 100)` gives dollars and remaining cents; format the cents with `:02d`. To total a list with `sum`, give it a starting value: `sum(prices, Money(0))`.
:::

:::solution
```python run title="money.py"
from dataclasses import dataclass


@dataclass(frozen=True)
class Money:
    cents: int

    def __add__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        return Money(self.cents + other.cents)

    def __str__(self):
        dollars, cents = divmod(self.cents, 100)
        return f"${dollars}.{cents:02d}"


a, b = Money(450), Money(75)
print(f"{a} + {b} = {a + b}")
basket = [Money(199), Money(450), Money(125)]
print("Basket total:", sum(basket, Money(0)))
print(a + b == Money(525))
try:
    a + 5
except TypeError as err:
    print("Refused:", err)
```

Returning `NotImplemented` (rather than raising yourself) tells Python "I don't know how to add this", and Python produces the standard `TypeError`. Because `Money` is frozen, `a + b` makes a new value and never changes `a`.
:::

### Exercise 5: A library that works with len, in, and for

Write a `Library` that keeps books in a private dict keyed by ISBN. `add(isbn, title)` refuses a duplicate ISBN with `ValueError`. Implement `__len__`, `__contains__` (so `isbn in library` works), and `__iter__` that yields titles in alphabetical order.

```text
3 True False
['Dune', 'Holes', 'Wonder']
Refused: 978-0441013593 is already in the library
```

:::hint
`__iter__` can simply `return iter(sorted(self._books.values()))` if the dict maps ISBN to title.
:::

:::solution
```python run title="library.py"
class Library:
    def __init__(self):
        self._books = {}

    def add(self, isbn, title):
        if isbn in self._books:
            raise ValueError(f"{isbn} is already in the library")
        self._books[isbn] = title

    def __len__(self):
        return len(self._books)

    def __contains__(self, isbn):
        return isbn in self._books

    def __iter__(self):
        return iter(sorted(self._books.values()))


lib = Library()
lib.add("978-0441013593", "Dune")
lib.add("978-0440414803", "Holes")
lib.add("978-0375869020", "Wonder")
print(len(lib), "978-0440414803" in lib, "000" in lib)
print(list(lib))
try:
    lib.add("978-0441013593", "Dune (again)")
except ValueError as err:
    print("Refused:", err)
```

Callers never see the dict, so you could later switch to a database without changing any code that uses `len`, `in`, or `for`.
:::

### Exercise 6: Let the type hints find the bug

This lookup works for the first ISBN and crashes on the second. Run it, then explain from the type hints why the crash was predictable, and fix the caller so a missing book prints `not found`.

```python run raises title="lookup.py"
from dataclasses import dataclass


@dataclass(frozen=True)
class Book:
    isbn: str
    title: str


def find_by_isbn(books: dict[str, Book], isbn: str) -> Book | None:
    return books.get(isbn)


catalog = {"978-0441013593": Book("978-0441013593", "Dune")}
print(find_by_isbn(catalog, "978-0441013593").title.upper())
print(find_by_isbn(catalog, "000").title.upper())
```

:::hint
Read the return hint out loud: "a `Book` or `None`". Every caller has to handle both. A type checker says the same thing; here is mypy's report on this file:

```text
lookup.py:15: error: Item "None" of "Book | None" has no attribute "title"  [union-attr]
lookup.py:16: error: Item "None" of "Book | None" has no attribute "title"  [union-attr]
Found 2 errors in 1 file (checked 1 source file)
```
:::

:::solution
```python run title="lookup.py"
from dataclasses import dataclass


@dataclass(frozen=True)
class Book:
    isbn: str
    title: str


def find_by_isbn(books: dict[str, Book], isbn: str) -> Book | None:
    return books.get(isbn)


catalog = {"978-0441013593": Book("978-0441013593", "Dune")}
for isbn in ["978-0441013593", "000"]:
    book = find_by_isbn(catalog, isbn)
    if book is None:
        print(isbn, "not found")
    else:
        print(book.title.upper())
```

The hint `-> Book | None` was a promise that some calls return `None`. The checker flagged *both* lines, even the one that happened to work, because nothing in the code guaranteed it would. After the `if book is None` check, the checker knows `book` is a `Book` in the `else` branch and stops complaining.
:::

### Challenge: A tested inventory for the school shop

Build an inventory with two classes. `Product` is a frozen dataclass with `sku`, `name`, and `price_cents`. `Inventory` keeps products and stock counts in private dicts and offers:

- `add_product(product)`, refusing a duplicate SKU;
- `receive(sku, qty)` and `ship(sku, qty)`, which refuse unknown SKUs, non-positive quantities, and shipping more than is in stock;
- a read-only way to ask `quantity(sku)`;
- `low_stock(threshold)`, returning products at or below the threshold, sorted by name;
- `total_value()` in cents;
- `__len__` (number of products) and `__contains__` (by SKU).

Write pytest tests for at least: receiving and shipping, refusing to oversell (and nothing changing), the low-stock report's order, total value, and that a `Product` can't be modified.

```mermaid caption="The inventory challenge: a value object inside a guarded collection"
classDiagram
    class Product {
        <<frozen dataclass>>
        +sku: str
        +name: str
        +price_cents: int
    }
    class Inventory {
        -_products: dict
        -_stock: dict
        +add_product(product)
        +receive(sku, qty)
        +ship(sku, qty)
        +quantity(sku) int
        +low_stock(threshold) list
        +total_value() int
        +__len__() int
        +__contains__(sku) bool
    }
    Inventory o-- Product : stocks
```

:::hint
A private `_require(sku)` helper that raises for unknown SKUs keeps `receive`, `ship`, and `quantity` short. Do every check in `ship` before you subtract anything.
:::

:::solution
```python run title="inventory.py"
from dataclasses import FrozenInstanceError, dataclass

import pytest


@dataclass(frozen=True)
class Product:
    sku: str
    name: str
    price_cents: int


class Inventory:
    def __init__(self) -> None:
        self._products: dict[str, Product] = {}
        self._stock: dict[str, int] = {}

    def add_product(self, product: Product) -> None:
        if product.sku in self._products:
            raise ValueError(f"{product.sku} is already stocked")
        self._products[product.sku] = product
        self._stock[product.sku] = 0

    def _require(self, sku: str) -> None:
        if sku not in self._products:
            raise ValueError(f"unknown product {sku}")

    def receive(self, sku: str, qty: int) -> None:
        self._require(sku)
        if qty <= 0:
            raise ValueError("quantity must be positive")
        self._stock[sku] += qty

    def ship(self, sku: str, qty: int) -> None:
        self._require(sku)
        if qty <= 0:
            raise ValueError("quantity must be positive")
        if qty > self._stock[sku]:
            raise ValueError(f"only {self._stock[sku]} of {sku} in stock")
        self._stock[sku] -= qty

    def quantity(self, sku: str) -> int:
        self._require(sku)
        return self._stock[sku]

    def low_stock(self, threshold: int) -> list[Product]:
        low = [p for sku, p in self._products.items() if self._stock[sku] <= threshold]
        return sorted(low, key=lambda p: p.name)

    def total_value(self) -> int:
        return sum(p.price_cents * self._stock[sku] for sku, p in self._products.items())

    def __len__(self) -> int:
        return len(self._products)

    def __contains__(self, sku: object) -> bool:
        return sku in self._products


def make_shop() -> Inventory:
    shop = Inventory()
    shop.add_product(Product("PEN", "Pen", 120))
    shop.add_product(Product("NB", "Notebook", 350))
    shop.add_product(Product("ER", "Eraser", 80))
    shop.receive("PEN", 50)
    shop.receive("NB", 4)
    shop.receive("ER", 2)
    return shop


def test_receive_and_ship_change_the_count():
    shop = make_shop()
    shop.ship("PEN", 20)
    assert shop.quantity("PEN") == 30


def test_overselling_is_refused_and_nothing_changes():
    shop = make_shop()
    with pytest.raises(ValueError):
        shop.ship("NB", 5)
    assert shop.quantity("NB") == 4


def test_unknown_sku_is_refused():
    with pytest.raises(ValueError):
        make_shop().receive("GLUE", 3)


def test_low_stock_is_sorted_by_name():
    names = [p.name for p in make_shop().low_stock(5)]
    assert names == ["Eraser", "Notebook"]


def test_total_value_in_cents():
    assert make_shop().total_value() == 50 * 120 + 4 * 350 + 2 * 80


def test_collection_dunders():
    shop = make_shop()
    assert len(shop) == 3 and "PEN" in shop and "GLUE" not in shop


def test_products_are_frozen():
    with pytest.raises(FrozenInstanceError):
        Product("PEN", "Pen", 120).price_cents = 1


for name, test in list(globals().items()):
    if name.startswith("test_") and callable(test):
        test()
        print("passed:", name)
```

`Inventory` stores stock separately from `Product` on purpose: a product's price and name are facts about the product, while the count is a fact about this shop, and it changes constantly. Keeping the changing part in the guarded class and the fixed part in a frozen value is the same split as `Account` and `Transaction`.
:::
