:::objectives
- Write characterization tests that pin down existing behavior, including a bug.
- Refactor in small steps: extract function, named constants, extract class, replace conditional with polymorphism.
- Keep an old entry point working as a thin wrapper while the inside is rebuilt.
- Fix a bug as a separate, test-first change after the refactor is finished.
:::

The school store's checkout code was written in a hurry before the first spirit week, and it shows. Every new discount was squeezed into one function, the stock rules exist in two places, and the last two changes each broke something that used to work. The treasurer now wants a new "big order" discount. Nobody wants to touch the function.

You'll rebuild it from the inside while keeping its output identical, then add the new discount by writing one small class. Here is where it ends up:


## Step 1: Read the legacy code

This is `store.py` as it is today. Run it once and read the receipt.

```python run title="store.py (before)"
PRICES = {"pencil": 0.50, "notebook": 3.00, "hoodie": 25.00, "lanyard": 2.00}
STOCK = {"pencil": 100, "notebook": 20, "hoodie": 2, "lanyard": 0}


def can_buy(sku, qty):
    return sku in STOCK and STOCK[sku] >= qty


def checkout(order):
    for sku, qty in order["items"]:
        if sku not in STOCK:
            return "ERROR: unknown item " + sku
        if STOCK[sku] < qty:
            return "ERROR: only " + str(STOCK[sku]) + " " + sku + " left"
    total = 0
    lines = []
    for sku, qty in order["items"]:
        cost = PRICES[sku] * qty
        total += cost
        label = f"{qty} x {sku}"
        lines.append(f"{label:<16}{cost:>8.2f}")
    if order["customer"] == "staff":
        discount = total * 0.2
    elif order["customer"] == "student" and total >= 20:
        discount = total * 0.1
    else:
        discount = 0
    if order.get("club") == "robotics":
        discount = max(discount, 5)
    total -= discount
    for sku, qty in order["items"]:
        STOCK[sku] -= qty
    lines.append(f"{'discount':<16}{discount:>8.2f}")
    lines.append(f"{'TOTAL':<16}{total:>8.2f}")
    return "\n".join(lines)


print(checkout({"customer": "student", "items": [("hoodie", 1), ("pencil", 4)]}))
```

Count the smells: a long function doing five jobs (validate, price, discount, update stock, format), magic numbers (`0.2`, `0.1`, `20`, `5`), a type switch on `order["customer"]`, the stock rule duplicated in `can_buy`, and a global `STOCK` dict that everything mutates.

## Step 2: Pin the behavior before changing anything

Characterization tests describe what the code does *now*. They compare whole receipts, character for character, because any difference counts as a change. `setUp` resets the global stock before each test, which is itself a sign of the global-state smell: the tests have to clean up after the code.

```python run title="test_store.py"
import sys
import unittest

START_STOCK = {"pencil": 100, "notebook": 20, "hoodie": 2, "lanyard": 0}


class PinCheckout(unittest.TestCase):
    """What checkout() does today. Change these only on purpose."""

    def setUp(self):
        STOCK.clear()
        STOCK.update(START_STOCK)

    def test_student_over_20_gets_10_percent(self):
        receipt = checkout({"customer": "student", "items": [("hoodie", 1), ("pencil", 4)]})
        self.assertEqual(receipt, "1 x hoodie         25.00\n4 x pencil          2.00\n"
                                  "discount            2.70\nTOTAL              24.30")

    def test_staff_gets_20_percent(self):
        receipt = checkout({"customer": "staff", "items": [("notebook", 5)]})
        self.assertTrue(receipt.endswith("TOTAL              12.00"))

    def test_robotics_member_gets_at_least_5_off(self):
        receipt = checkout({"customer": "student", "club": "robotics", "items": [("notebook", 3)]})
        self.assertTrue(receipt.endswith("discount            5.00\nTOTAL               4.00"))

    def test_sale_reduces_stock_and_can_buy_agrees(self):
        checkout({"customer": "guest", "items": [("hoodie", 2)]})
        self.assertEqual(STOCK["hoodie"], 0)
        self.assertFalse(can_buy("hoodie", 1))

    def test_errors_are_returned_as_text(self):
        self.assertEqual(checkout({"customer": "guest", "items": [("lanyard", 1)]}), "ERROR: only 0 lanyard left")
        self.assertEqual(checkout({"customer": "guest", "items": [("mug", 1)]}), "ERROR: unknown item mug")

    def test_tiny_robotics_order_goes_negative(self):
        # BUG, pinned on purpose: fixed after the refactor, in Step 7.
        receipt = checkout({"customer": "guest", "club": "robotics", "items": [("pencil", 1)]})
        self.assertTrue(receipt.endswith("TOTAL              -4.50"))


def run_tests(*cases: type[unittest.TestCase]) -> None:
    suite = unittest.TestSuite()
    for case in cases:
        suite.addTests(unittest.defaultTestLoader.loadTestsFromTestCase(case))
    unittest.TextTestRunner(stream=sys.stdout, verbosity=2).run(suite)


run_tests(PinCheckout)
```

Six green tests, and one of them pins a bug: a robotics member buying a 50-cent pencil gets $5 off and the store owes *them* $4.50. Writing the tests found it. It's tempting to fix it right now. Don't: if you fix it mid-refactor and a test goes red later, you won't know which change caused it. Pin it, note it, keep going.

## Step 3: Extract functions and name the numbers

The first refactor is mechanical: pull each job into a function and give every number a name. `checkout` becomes a short list of steps.

```python run title="store.py"
STAFF_RATE = 0.20
STUDENT_RATE = 0.10
STUDENT_MINIMUM = 20.00
ROBOTICS_MINIMUM_OFF = 5.00


def stock_problem(items):
    for sku, qty in items:
        if not can_buy(sku, qty):
            if sku not in STOCK:
                return "ERROR: unknown item " + sku
            return "ERROR: only " + str(STOCK[sku]) + " " + sku + " left"
    return None


def subtotal(items):
    return sum(PRICES[sku] * qty for sku, qty in items)


def discount_for(order, total):
    if order["customer"] == "staff":
        discount = total * STAFF_RATE
    elif order["customer"] == "student" and total >= STUDENT_MINIMUM:
        discount = total * STUDENT_RATE
    else:
        discount = 0
    if order.get("club") == "robotics":
        discount = max(discount, ROBOTICS_MINIMUM_OFF)
    return discount


def receipt(items, discount, total):
    lines = []
    for sku, qty in items:
        label = f"{qty} x {sku}"
        lines.append(f"{label:<16}{PRICES[sku] * qty:>8.2f}")
    lines.append(f"{'discount':<16}{discount:>8.2f}")
    lines.append(f"{'TOTAL':<16}{total:>8.2f}")
    return "\n".join(lines)


def checkout(order):
    problem = stock_problem(order["items"])
    if problem:
        return problem
    total = subtotal(order["items"])
    discount = discount_for(order, total)
    for sku, qty in order["items"]:
        STOCK[sku] -= qty
    return receipt(order["items"], discount, total - discount)


run_tests(PinCheckout)
```

Still six green. `stock_problem` now reuses `can_buy`, so the stock rule exists in one place. Each function can be read, tested, and changed on its own.

## Step 4: Extract an Inventory class with real exceptions

Stock is state with rules attached, which is exactly what a class is for. `Inventory` owns the dict and raises the custom exceptions from Module 5 instead of returning strings. The old `checkout` and `can_buy` stay as thin wrappers, so their callers (and the pinned tests) never notice.

```python run title="store.py"
class StoreError(Exception):
    """Base class for checkout problems."""


class UnknownItem(StoreError):
    def __init__(self, sku: str) -> None:
        super().__init__(f"unknown item {sku}")
        self.sku = sku


class OutOfStock(StoreError):
    def __init__(self, sku: str, left: int) -> None:
        super().__init__(f"only {left} {sku} left")
        self.sku = sku
        self.left = left


class Inventory:
    def __init__(self, stock: dict[str, int]) -> None:
        self._stock = stock

    def check(self, sku: str, qty: int) -> None:
        if sku not in self._stock:
            raise UnknownItem(sku)
        if self._stock[sku] < qty:
            raise OutOfStock(sku, self._stock[sku])

    def take(self, items: list[tuple[str, int]]) -> None:
        for sku, qty in items:
            self.check(sku, qty)
        for sku, qty in items:
            self._stock[sku] -= qty


def can_buy(sku, qty):
    try:
        Inventory(STOCK).check(sku, qty)
    except StoreError:
        return False
    return True


def checkout(order):
    try:
        Inventory(STOCK).take(order["items"])
    except StoreError as err:
        return f"ERROR: {err}"
    total = subtotal(order["items"])
    discount = discount_for(order, total)
    return receipt(order["items"], discount, total - discount)


run_tests(PinCheckout)
```

`take` checks every item before changing any stock, so a failed order leaves the inventory untouched, the same as before. The messages are identical because the exception classes build the same text the old string concatenation did. `stock_problem` is no longer used; delete it.

## Step 5: Replace the discount conditional with rule classes

The `if`/`elif` in `discount_for` is the part that keeps breaking. Each discount becomes a class with one method, `amount`, and the customer's two loose values become a small dataclass (the data-clump fix). Since staff and student discounts never both apply, and the club rule was "at least $5", the total discount is simply the largest amount any rule offers.

```python run title="store.py"
from abc import ABC, abstractmethod
from dataclasses import dataclass


@dataclass(frozen=True)
class Customer:
    kind: str  # "student", "staff", or "guest"
    club: str | None = None


class DiscountRule(ABC):
    @abstractmethod
    def amount(self, customer: Customer, subtotal: float) -> float:
        """Dollars off this rule offers; 0 if it doesn't apply."""


class StaffDiscount(DiscountRule):
    def amount(self, customer: Customer, subtotal: float) -> float:
        return subtotal * STAFF_RATE if customer.kind == "staff" else 0.0


class StudentDiscount(DiscountRule):
    def amount(self, customer: Customer, subtotal: float) -> float:
        if customer.kind == "student" and subtotal >= STUDENT_MINIMUM:
            return subtotal * STUDENT_RATE
        return 0.0


class ClubDiscount(DiscountRule):
    def __init__(self, club: str, minimum_off: float) -> None:
        self.club = club
        self.minimum_off = minimum_off

    def amount(self, customer: Customer, subtotal: float) -> float:
        return self.minimum_off if customer.club == self.club else 0.0


RULES: list[DiscountRule] = [StaffDiscount(), StudentDiscount(), ClubDiscount("robotics", ROBOTICS_MINIMUM_OFF)]


def discount_for(order, total):
    customer = Customer(order["customer"], order.get("club"))
    return max(rule.amount(customer, total) for rule in RULES)


run_tests(PinCheckout)
```

Green again, bug and all. The negative total survived because this step preserved behavior exactly, which is the point.

## Step 6: An injectable Checkout, and the new discount

Last structural step. `Checkout` receives its inventory, prices, and rules instead of reaching for globals, so new code (and tests) can build one with any stock and any rules. The legacy `checkout()` becomes a short adapter.

```python run title="store.py"
class Checkout:
    def __init__(self, inventory: Inventory, prices: dict[str, float], rules: list[DiscountRule]) -> None:
        self.inventory = inventory
        self.prices = prices
        self.rules = rules

    def run(self, customer: Customer, items: list[tuple[str, int]]) -> str:
        self.inventory.take(items)
        total = sum(self.prices[sku] * qty for sku, qty in items)
        discount = max((rule.amount(customer, total) for rule in self.rules), default=0.0)
        return receipt(items, discount, total - discount)


def checkout(order):
    """Old entry point, kept so existing callers keep working."""
    store = Checkout(Inventory(STOCK), PRICES, RULES)
    try:
        return store.run(Customer(order["customer"], order.get("club")), order["items"])
    except StoreError as err:
        return f"ERROR: {err}"


run_tests(PinCheckout)
```

Now the treasurer's request. A big-order discount is one new class; nothing that already works gets edited. And because `Checkout` takes its dependencies, this demo uses its own inventory and never touches the global `STOCK`:

```python run title="big_order.py"
class BigOrderDiscount(DiscountRule):
    def __init__(self, threshold: float, off: float) -> None:
        self.threshold = threshold
        self.off = off

    def amount(self, customer: Customer, subtotal: float) -> float:
        return self.off if subtotal >= self.threshold else 0.0


shop = Checkout(Inventory({"hoodie": 5, "pencil": 50}), PRICES, RULES + [BigOrderDiscount(50.00, 6.00)])
print(shop.run(Customer("guest"), [("hoodie", 2), ("pencil", 2)]))
print()
print(shop.run(Customer("staff"), [("hoodie", 2)]))
```

The guest's $51 order gets the $6 big-order discount. The staff member's $50 order qualifies too, but 20% ($10) is bigger, so the staff rule wins. "Best single discount" is now one line in `Checkout.run`, so if the store ever decides discounts should stack, that one line is the only place to change.

## Step 7: Fix the bug, as its own change

With the refactor finished and green, fix the negative total. Test first, and notice what the refactor bought you: the club rule is now a small class you can test directly, without building a whole order.

```python run title="test_discounts.py"
class TestClubDiscount(unittest.TestCase):
    def setUp(self):
        self.rule = ClubDiscount("robotics", 5.00)

    def test_never_more_than_the_subtotal(self):
        self.assertEqual(self.rule.amount(Customer("guest", "robotics"), 0.50), 0.50)

    def test_members_of_other_clubs_get_nothing(self):
        self.assertEqual(self.rule.amount(Customer("guest", "chess"), 30.00), 0.0)


run_tests(TestClubDiscount)
```

Red, for the right reason: `5.0 != 0.5`. The fix is one expression, in the one place the rule lives:

```diff
-        return self.minimum_off if customer.club == self.club else 0.0
+        return min(self.minimum_off, subtotal) if customer.club == self.club else 0.0
```

The two new tests pass, and exactly one old test fails: `test_tiny_robotics_order_goes_negative`, the one that pinned the bug. That failure is the good kind. ## The finished store.py

Here is the whole module after all seven steps, with the big-order rule added to the defaults, followed by one last run of every test (minus the deleted one).

```python run title="store.py (after)"
from abc import ABC, abstractmethod
from dataclasses import dataclass

PRICES = {"pencil": 0.50, "notebook": 3.00, "hoodie": 25.00, "lanyard": 2.00}
STOCK = {"pencil": 100, "notebook": 20, "hoodie": 2, "lanyard": 0}
STAFF_RATE = 0.20
STUDENT_RATE = 0.10
STUDENT_MINIMUM = 20.00
ROBOTICS_MINIMUM_OFF = 5.00


class StoreError(Exception):
    """Base class for checkout problems."""


class UnknownItem(StoreError):
    def __init__(self, sku: str) -> None:
        super().__init__(f"unknown item {sku}")
        self.sku = sku


class OutOfStock(StoreError):
    def __init__(self, sku: str, left: int) -> None:
        super().__init__(f"only {left} {sku} left")
        self.sku = sku
        self.left = left


class Inventory:

            self.check(sku, qty)
        for sku, qty in items:
            self._stock[sku] -= qty

```

The last two lines are for this page only: `del` removes the pinned-bug test from the class, just as you deleted it from the file. Every remaining receipt test passes against the finished module, so for every order the tests cover, it prints exactly what the legacy code printed.

:::warning
**Big-bang rewrites.** It's tempting to delete the legacy function and write `Checkout` from scratch. Then nothing tells you whether the new code matches the old receipts, and edge cases (like `take` checking every item before changing any stock) quietly disappear. Each step above was small enough to undo in seconds, and the pinned tests ran after every one.
:::

:::quiz
Q: Why did Step 2 pin the negative-total bug instead of fixing it immediately?
- [ ] Because characterization tests can't express correct behavior
  They can; Step 7 changes the test to do exactly that.
- [x] So the refactor and the bug fix are separate changes, each checked by green tests
  Mixing them makes a red test ambiguous: was it the refactor or the fix?
- [ ] Because the bug might be a feature
  It isn't; but even real bugs get fixed as their own step.

Q: Why does the legacy `checkout(order)` function still exist at the end?
- [x] Other code and the pinned tests call it, so it stays as a thin adapter over `Checkout`
  Keeping the old entry point lets you refactor the inside without breaking any caller.
- [ ] Python needs a plain function to call a class
  Callers can create and use `Checkout` directly; the adapter is for old callers.
- [ ] It's faster than `Checkout.run`
  It does slightly more work, since it builds a `Checkout` on each call.

Q: The store decides discounts should stack: staff get 20% *and* the big-order $6. How many places change?
- [ ] Every rule class
  The rules each report their own amount; they don't decide how amounts combine.
- [x] One line in `Checkout.run`: `max(...)` becomes `sum(...)`
  How amounts combine is the checkout's job, and it lives in exactly one expression.
- [ ] `Customer` and `Inventory`
  Neither knows anything about discounts.
:::

:::takeaways
- Pin current behavior with characterization tests before refactoring, and compare whole outputs.
- Refactor in steps small enough to undo: extract function, name constants, extract class, replace conditional with polymorphism, inject dependencies.
- Keep old entry points as thin adapters so callers don't break while the inside changes.
- Polymorphic rule classes turn "add a discount" into "add a class", leaving tested code alone.
- Fix bugs after the refactor, test first, in the one place the rule now lives.
:::

## Ideas to extend it

- Make `receipt` a method of a `Receipt` class and add a `to_csv()` alongside it, with tests for both.
- Add a `Prices` class that raises `UnknownItem` for a missing SKU, and remove the separate `PRICES` dict from `Checkout`.
- Split `store.py` into a package (`store/errors.py`, `store/inventory.py`, `store/discounts.py`, `store/checkout.py`) using the import direction rule from Module 5.
