Take two sentences: "deposit cash at the bank" and "the river bank flooded." The word embeddings you used in Module 2 give `bank` exactly one vector, the same in both. That vector has to sit halfway between money and water, which is right for neither sentence.

A transformer fixes this in one move. Before `bank` is passed on, it looks at the other words in its sentence and mixes some of their information into its own vector. Next to `cash`, it drifts toward money. Next to `river`, it drifts toward water. That mixing step is **attention**, and by the end of this page you'll have computed it with your own hands.

## Queries, keys, and values: a soft lookup

Here's the intuition. Every token does three jobs at once:

-   It sends out a **query**: "here's what I'm looking for."
-   It advertises a **key**: "here's what I contain, if you're looking."
-   It carries a **value**: "here's what I'll hand over if you pick me."

Each query is compared with every key. Close matches earn big scores, the scores become weights that add up to 1, and the token's new vector is the weighted blend of everyone's values. Think of a library search that hands you a blend of the books whose labels matched, mostly the best match.

Now precisely. Stack the tokens' vectors as rows of a matrix `X` (n tokens × d numbers). Three learned matrices turn it into `Q = X·W_q`, `K = X·W_k`, `V = X·W_v`. Then:

```text
Attention(Q, K, V) = softmax( Q·Kᵀ / √d ) · V
```

`Q·Kᵀ` is an n × n table of scores: row *i*, column *j* says how well token *i*'s query matches token *j*'s key. The softmax runs along each row, so every row of weights sums to 1.

Let's see it in code. I hand-built 4-number embeddings whose columns mean *money*, *water*, *action*, and *filler word*, so you can read the results. A trained model learns its `W` matrices; here they're identity matrices, so the query, key, and value of each token are just its embedding.

```python run
import numpy as np
np.set_printoptions(precision=2, suppress=True)

# columns: money, water, action, filler
vocab = {
    "deposit": [2.5, 0.0, 2.0, 0.0],
    "cash":    [3.0, 0.0, 0.0, 0.0],
    "at":      [0.0, 0.0, 0.0, 2.0],
    "the":     [0.0, 0.0, 0.0, 2.0],
    "river":   [0.0, 3.0, 0.0, 0.0],
    "bank":    [1.5, 1.5, 0.0, 0.0],
    "flooded": [0.0, 2.5, 2.0, 0.0],
}

def softmax(scores):
    exp = np.exp(scores - scores.max(axis=-1, keepdims=True))
    return exp / exp.sum(axis=-1, keepdims=True)

tokens = "the river bank flooded".split()
X = np.array([vocab[t] for t in tokens])
W_q = W_k = W_v = np.eye(4)
Q, K, V = X @ W_q, X @ W_k, X @ W_v

d = Q.shape[1]
scores = Q @ K.T / np.sqrt(d)
weights = softmax(scores)
output = weights @ V

i = tokens.index("bank")
print("scores for bank :", scores[i])
print("weights for bank:", weights[i], " sum =", weights[i].sum())
print("bank before:", X[i])
print("bank after :", output[i])
```

Look at the weights row. `bank` splits most of its attention between itself and `river` (0.36 each), gives a quarter to `flooded`, which has some water in it, and almost nothing to `the`. Its output vector went in as 1.5 money and 1.5 water and came out as 0.54 money and 2.23 water: the sentence pulled it toward the river meaning.

Before you run the next cell, predict: in "deposit cash at the bank", will `bank` end up higher in money or in water?

```python run
def attention(Q, K, V):
    weights = softmax(Q @ K.T / np.sqrt(Q.shape[1]))
    return weights @ V, weights

for sentence in ["deposit cash at the bank", "the river bank flooded"]:
    toks = sentence.split()
    Xs = np.array([vocab[t] for t in toks])
    out, _ = attention(Xs, Xs, Xs)
    money, water = out[toks.index("bank")][:2]
    print(f"{sentence:28s} bank -> money {money:.2f}, water {water:.2f}")
```

Same input vector for `bank`, two different outputs. A real model does this with hundreds of dimensions, dozens of layers, and many attention **heads** per layer, each with its own learned `W` matrices.

## Reading an attention heatmap

The `weights` matrix is easier to read as a picture. Each row is one token's query, and the colors across it show where its attention goes.

```python run alt="A 4 by 4 heatmap of attention weights for the sentence 'the river bank flooded'. Rows are queries and columns are keys. The diagonal is darkest. 'river', 'bank', and 'flooded' share their weight among themselves and give almost none to 'the', while 'the' keeps 0.71 on itself." caption="Rows are queries, columns are keys; every row sums to 1"
import matplotlib.pyplot as plt

fig, ax = plt.subplots(figsize=(4.6, 3.8))
im = ax.imshow(weights, cmap="Blues", vmin=0, vmax=1)
ax.set_xticks(range(len(tokens)), tokens)
ax.set_yticks(range(len(tokens)), tokens)
ax.set_xlabel("key (looked at)")
ax.set_ylabel("query (looking)")
for r in range(len(tokens)):
    for c in range(len(tokens)):
        ax.text(c, r, f"{weights[r, c]:.2f}", ha="center", va="center", fontsize=9)
fig.colorbar(im, ax=ax, shrink=0.8)

```

The three content words form a block in the lower right: they share the water dimension, so their queries and keys match, and the column for `the` is nearly white below the first row. `the` matches nothing but itself, keeps 0.71 of its weight, and spreads the rest evenly. Heatmaps from trained models are messier, but you read them the same way.

## Why divide by √d

Leave out the `/ np.sqrt(d)` and the code still runs; the trouble shows up in wide models. A dot product of two d-dimensional vectors with random unit-sized entries has a spread of about √d, so at d = 512 raw scores swing by ±20. Softmax of numbers that far apart is nearly one-hot, and training gets tiny gradients for every other token.

```python run
rng = np.random.default_rng(0)
print("   d   spread of raw scores   top weight, raw   top weight, scaled")
for d_test in [4, 64, 512]:
    q = rng.standard_normal((1000, d_test))
    k = rng.standard_normal((1000, 8, d_test))
    raw = np.einsum("nd,nkd->nk", q, k)        # 1000 queries x 8 keys each
    top_raw = softmax(raw).max(axis=-1).mean()
    top_scaled = softmax(raw / np.sqrt(d_test)).max(axis=-1).mean()
    print(f"{d_test:4d}   {raw.std():12.1f}          {top_raw:10.2f}        {top_scaled:10.2f}")
```

With 8 keys, a fair spread would give the top key around 0.3. Unscaled, the top key's share climbs to 0.95 as d grows. Scaled, it stays near 0.36 for every size. Dividing by √d keeps the softmax in a range where learning works, whatever the model's width.

## Masking: a GPT-style model can't read ahead

A model that writes one token at a time is trained to predict each next token. If position 3 could attend to position 4, it would just copy the answer. So decoder models like GPT apply a **causal mask**: before the softmax, every score where the key comes after the query becomes −∞. Since e^(−∞) = 0, those weights are exactly zero and the rest still sum to 1.

Step through one row. Token 1 (the second token) is allowed to see tokens 0 and 1, but not token 2:

:::trace Watch one masked row of attention weights form
```python
import math

position = 1
scores = [1.0, 2.0, 3.0]
masked = []
for j, s in enumerate(scores):
    if j > position:
        masked.append(-math.inf)
    else:
        masked.append(s)
exps = [math.exp(s) for s in masked]
total = sum(exps)
weights = [round(e / total, 3) for e in exps]
print(weights)
```
:::

Notice that the 3.0 was the largest score, and it ends up with weight 0. In NumPy, the whole matrix gets masked at once with `np.triu`:

```python run
n = len(tokens)
future = np.triu(np.ones((n, n), dtype=bool), k=1)   # True above the diagonal
causal_scores = np.where(future, -np.inf, Q @ K.T / np.sqrt(d))
print(softmax(causal_scores))
```

The first row is `[1, 0, 0, 0]`: the first token can only look at itself, and each later row spreads over one more token. BERT-style encoders skip this mask, so they read whole sentences well but don't generate text left to right.

## Attention can't see word order on its own

Shuffle the rows of `X` and attention shuffles its output rows the same way, but each token's output vector doesn't change. To attention, "dog bites man" and "man bites dog" are the same bag of tokens.

```python run
rng = np.random.default_rng(1)
emb = {w: rng.standard_normal(4) for w in ["dog", "bites", "man"]}

def encode(sentence, positions=False):
    words = sentence.split()
    Xw = np.array([emb[w] for w in words])
    if positions:
        pos = np.arange(len(words))[:, None]
        dims = np.arange(4)[None, :]
        angle = pos / 10000 ** (2 * (dims // 2) / 4)
        Xw = Xw + np.where(dims % 2 == 0, np.sin(angle), np.cos(angle))
    out, _ = attention(Xw, Xw, Xw)
    return out[words.index("dog")]

print("no positions:  ", np.allclose(encode("dog bites man"), encode("man bites dog")))
print("with positions:", np.allclose(encode("dog bites man", True), encode("man bites dog", True)))
```

Without positions, `dog` gets the identical vector whether it's biting or bitten. Adding a position signal breaks the tie. The original transformer added the sine and cosine waves used here, GPT-2 learned one vector per position, and many current models (Llama among them) rotate queries and keys by a position-dependent angle, called RoPE.

## A context window is a budget, and it's measured in tokens

Every query is scored against every key, so n tokens produce n × n scores, in every head of every layer.

```python run
for n in [512, 8_000, 128_000, 1_000_000]:
    print(f"{n:>9,} tokens -> {n * n:>17,} scores per head, per layer")
```

That square growth is one reason every model has a **context window**, a maximum number of tokens per call. The window holds everything: instructions, chat history, pasted documents, your question, and the answer the model writes. Tokens aren't words, either. For English prose, a rule of thumb many providers quote is about 4 characters per token; code, numbers, and many other languages need more.

What happens at the limit depends on the tool. Many APIs reject an over-long request with an error, which is easy to notice. Hugging Face tokenizers called with `truncation=True` quietly cut tokens off the end. Chat apps often drop the oldest messages, so the definitions you pasted first are the first to go.

Even when everything fits, position matters: in the 2023 "Lost in the Middle" study, models used a fact best when it sat near the start or end of a long context. Next lesson you'll build a planner that decides what goes into the window instead of letting truncation decide.

:::warning
**Softmax over the wrong axis.** Normalizing with `axis=0` makes each *column* sum to 1 instead of each query's row. The code runs, the shapes are right, and the output is wrong. Check that `weights.sum(axis=1)` is all ones.

**Masking after the softmax.** Zeroing future weights after the softmax leaves rows that sum to less than 1, and the earlier weights were already shaped by the future scores. Mask the *scores* with −∞, then take the softmax.
:::

:::quiz
Q: A query's scores against three keys are `[2.0, 2.0, 2.0]`. What are its attention weights?
- [ ] `[1, 1, 1]`
  Softmax weights always sum to 1, so three equal weights can't each be 1.
- [x] `[0.33, 0.33, 0.33]`
  Equal scores give equal weights, and they must sum to 1.
- [ ] `[0, 0, 1]`
  A one-hot result needs one score far above the others; these are tied.

Q: You remove `/ np.sqrt(d)` from a model with d = 1024. What happens to the attention weights?
- [ ] Nothing, because the softmax normalizes the scores anyway
  Softmax makes the weights sum to 1 but doesn't undo a large spread.
- [x] They become nearly one-hot, with most rows putting almost all weight on one key
  Raw scores have a spread near √1024 = 32, so the softmax saturates.
- [ ] They become uniform across all keys
  Near-uniform weights come from scores close together, the opposite of what removing the scale does.

Q: In a causal (GPT-style) model, which keys can token 4 (counting from 0) attend to?
- [ ] Every token in the context
  That's an encoder like BERT, with no mask.
- [x] Tokens 0 through 4
  The mask hides keys after the query's own position; the token can see itself and everything before it.
- [ ] Only token 3
  Attention isn't limited to the previous token; it blends all visible tokens.

Q: A chatbot that keeps the latest messages and drops old ones starts ignoring rules you gave at the start. What's the most likely cause?
- [ ] The rules were too short to attend to
  Short text attends fine; length isn't the issue.
- [x] The earliest messages were dropped once the conversation passed the context window
  Chat tools often drop the oldest turns to stay under the limit, and your rules were the oldest turn.
- [ ] Attention can only look backward one message
  Attention covers every token inside the window, however many messages that spans.
:::

:::takeaways
- `softmax(QKᵀ/√d)V` rebuilds each token as a blend of other tokens' values; each row of weights belongs to one query and sums to 1.
- Dividing by √d keeps wide models from saturating the softmax.
- A causal mask sets future scores to −∞ before the softmax, so a generating model can't peek ahead.
- Attention alone ignores order; positional encodings put "where" into the vectors.
- A context window caps input and output tokens together, and over-long text is often cut without warning.
:::
