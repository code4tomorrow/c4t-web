:::objectives
- Write gold-standard entity labels as character spans, and score any extractor against them with span-level precision, recall, and F1.
- Build a regex extractor for dates, money, and emails that reports the same span format as the model.
- Merge rule and model entities so that each source covers what it's good at, without overlaps.
- Read a model's per-token probabilities to understand one of its mistakes.
- Pull attention weights out of a transformer and plot them as heatmaps.
:::

Here is what you'll build, running on a sentence it has never seen:

```text
EMAIL  'lena.vogel@example.com'     rule
DATE   '2 May'                      rule
MONEY  '€300'                       rule
LOC    'Berlin'                     model
PER    'Kofi Mensah'                model
```

Three entities come from regular expressions, two from the transformer, and the last column says which. Before writing it, you'll measure each half on hand-labelled text, so the claim "the combination is better" comes with numbers.

## Step 1: Hand-label a small gold standard

Evaluation needs correct answers. Four short documents, with every entity written as `(document, start, end, label)`. Typing character offsets by hand invites off-by-one errors, so a helper finds them with `str.index`:

```python run
import re

docs = [
    "Dr. Amara Okafor will speak at the Lagos Tech Summit on 12 March 2026. Tickets cost $25; email amara.okafor@example.org with questions.",
    "On 3 April, Diego Ramírez signed a two-year contract with Nordic Wind Energy in Oslo worth €1.2 million.",
    "Priya Nair from Bengaluru joined Greenleaf Robotics on May 5, 2025, and moved to Toronto in June.",
    "Email support@riverbank.example by 30 June 2026 to claim the $40 refund from Riverbank Books.",
]

def span(doc_id, text, label):
    start = docs[doc_id].index(text)
    return (doc_id, start, start + len(text), label)

gold = {
    span(0, "Amara Okafor", "PER"), span(0, "Lagos Tech Summit", "MISC"), span(0, "12 March 2026", "DATE"),
    span(0, "$25", "MONEY"), span(0, "amara.okafor@example.org", "EMAIL"),
    span(1, "3 April", "DATE"), span(1, "Diego Ramírez", "PER"), span(1, "Nordic Wind Energy", "ORG"),
    span(1, "Oslo", "LOC"), span(1, "€1.2 million", "MONEY"),
    span(2, "Priya Nair", "PER"), span(2, "Bengaluru", "LOC"), span(2, "Greenleaf Robotics", "ORG"),
    span(2, "May 5, 2025", "DATE"), span(2, "Toronto", "LOC"), span(2, "June", "DATE"),
    span(3, "support@riverbank.example", "EMAIL"), span(3, "30 June 2026", "DATE"),
    span(3, "$40", "MONEY"), span(3, "Riverbank Books", "ORG"),
}
print(len(gold), "gold entities:", sorted({label for *_, label in gold}))
```

Labelling forces decisions. *Lagos Tech Summit* is an event, so it's MISC, and the whole three words form the entity. *Dr.* is a title, not part of the name. Write these rules down when you label real data; two people labelling the same text disagree more often than you'd expect.

## Step 2: Score with exact span matching

A predicted entity counts as correct only if its document, start, end, and label all match a gold entity. With predictions and gold as sets of tuples, the matches are just their intersection:

```python run
def score(predicted, gold):
    correct = len(predicted & gold)
    precision = correct / len(predicted) if predicted else 0.0
    recall = correct / len(gold) if gold else 0.0
    f1 = 2 * precision * recall / (precision + recall) if correct else 0.0
    return f"{correct:2} correct   precision {precision:.2f}   recall {recall:.2f}   F1 {f1:.2f}"

print("empty extractor:", score(set(), gold))
```

Exact matching is strict on purpose. An extractor that finds *Okafor* instead of *Amara Okafor* gets no credit, because a redaction tool built on it would leave the first name visible.

## Step 3: The rule-based half

Three patterns, each producing spans in the same format. Order matters inside the DATE pattern: the longest forms come first, and a bare month name comes last so *June* on its own is still caught.

```python run
MONTH = r"(?:January|February|March|April|May|June|July|August|September|October|November|December)"
RULES = [
    ("EMAIL", r"[\w.+-]+@[\w-]+(?:\.[\w-]+)+"),
    ("MONEY", r"[$€£]\d+(?:[.,]\d+)*(?: (?:thousand|million|billion))?"),
    ("DATE", rf"\b\d{{1,2}} {MONTH}(?: \d{{4}})?\b|\b{MONTH} \d{{1,2}}(?:, \d{{4}})?|\b{MONTH}\b"),
]

def rule_entities(doc_id, text):
    return {
        (doc_id, m.start(), m.end(), label)
        for label, pattern in RULES
        for m in re.finditer(pattern, text)
    }

rule_pred = set().union(*(rule_entities(i, doc) for i, doc in enumerate(docs)))
print("rules:", score(rule_pred, gold))
```

Precision 1.00, recall 0.50: everything the rules find is right, and they find exactly the half of the gold set that has a regular shape. The bare-month alternative is the risky one. It would also tag *May* in "May I ask a question?", so on real text you'd want it only after words like *in* or *by*.

## Step 4: The model half

Run this in Colab. It repeats the four documents so it works in a fresh session, and prints the model's entities as tuples you can copy:

```python
from transformers import pipeline

docs = [
    "Dr. Amara Okafor will speak at the Lagos Tech Summit on 12 March 2026. Tickets cost $25; email amara.okafor@example.org with questions.",
    "On 3 April, Diego Ramírez signed a two-year contract with Nordic Wind Energy in Oslo worth €1.2 million.",
    "Priya Nair from Bengaluru joined Greenleaf Robotics on May 5, 2025, and moved to Toronto in June.",
    "Email support@riverbank.example by 30 June 2026 to claim the $40 refund from Riverbank Books.",
]
ner = pipeline("token-classification", model="dslim/distilbert-NER", aggregation_strategy="first")
for doc_id, doc in enumerate(docs):
    for e in ner(doc):
        print(f"({doc_id}, {e['start']}, {e['end']}, {e['entity_group']!r}, {e['score']:.3f}),  # {doc[e['start']:e['end']]}")
```

The model's one real failure is *Lagos Tech Summit*: it split the event into a location and a shorter MISC, so the gold span and both predicted spans all count as errors. ## Step 5: Merge the two halves

The two halves cover different labels, so they mostly don't collide. When they do (say, the model tags *riverbank* inside an email address as an organization), the rule wins, because its patterns are more precise. The merge keeps every rule span, then adds each model span that doesn't overlap one:

```python run
def overlaps(a, b):
    return a[0] == b[0] and a[1] < b[2] and b[1] < a[2]

def merge(rule_spans, model_spans):
    merged = set(rule_spans)
    for m in sorted(model_spans):
        if not any(overlaps(m, r) for r in rule_spans):
            merged.add(m)
    return merged

combined = merge(rule_pred, model_pred)
print("combined:", score(combined, gold))
for label in ["PER", "ORG", "LOC", "MISC", "DATE", "MONEY", "EMAIL"]:
    p = {x for x in combined if x[3] == label}
    g = {x for x in gold if x[3] == label}
    print(f"   {label:6} {len(p & g)} of {len(g)} found, {len(p - g)} wrong")
```

Two spans overlap when each one starts before the other ends; that one-line test covers every case, including one span inside another. The per-label breakdown shows where the remaining errors live: all in MISC and LOC, both from the summit.

## Step 6: Look inside a wrong answer

The Notes lesson ended with a mistake: *Washington signed the treaty in Washington* gets LOC twice. Ask the model for its two best labels on every token (Colab):

```python
import torch
from transformers import AutoTokenizer, AutoModelForTokenClassification

name = "dslim/distilbert-NER"
tokenizer = AutoTokenizer.from_pretrained(name)
model = AutoModelForTokenClassification.from_pretrained(name, attn_implementation="eager")
model.eval()

text = "Washington signed the treaty in Washington."
inputs = tokenizer(text, return_tensors="pt")
tokens = tokenizer.convert_ids_to_tokens(inputs["input_ids"][0])
with torch.no_grad():
    outputs = model(**inputs, output_attentions=True)

probs = outputs.logits.softmax(dim=-1)[0]
for token, p in zip(tokens, probs):
    top = p.topk(2)
    print(f"{token:11}", "   ".join(f"{model.config.id2label[i.item()]:6} {v.item():.3f}" for v, i in zip(top.values, top.indices)))
```

```text
[CLS]       O      0.497   B-LOC  0.132
Washington  B-LOC  0.968   B-PER  0.025
signed      O      1.000   I-ORG  0.000
the         O      1.000   B-MISC 0.000
treaty      O      1.000   I-ORG  0.000
in          O      1.000   B-LOC  0.000
Washington  B-LOC  0.999   O      0.000
.           O      1.000   B-LOC  0.000
[SEP]       O      0.980   B-LOC  0.007
```

PER was the model's second choice for the first *Washington*, at 0.025. It wasn't torn between the two; it was nearly certain and wrong. A plausible reason is the training data: in news text, *Washington* at the start of a sentence usually means the US government or the city, so *signed* wasn't enough evidence to override that. That's a guess about the data, not something the probabilities prove.

Two details in the code matter. `attn_implementation="eager"` loads the plain attention code, which can return its weights; the faster default implementation may not. `output_attentions=True` asks for them.

The left head does one simple job: almost every token puts nearly all its weight on the token just before it (*the* looks at *signed*, *Washington* looks at *in*). Heads like this let information flow from left to right through the sentence. The right panel looks nothing like a reading of the sentence: in the last layer, every token sends between a quarter and three quarters of its attention to `[SEP]`. Researchers have found this pattern in BERT-style models and read it as a "no-op": a head with nothing useful to collect parks its weight on a token that changes little.

That's the caution to carry into Module 5. Attention weights show where information *could* flow, not *why* the model chose a label. The first *Washington* gives most of its last-layer attention to `[SEP]`, which tells you almost nothing about the mistake.

## The finished extractor

The whole thing as one Colab cell, ready to reuse. It repeats the rules so it runs on its own.

```python title="extract_entities.py"
import re

from transformers import pipeline

MONTH = r"(?:January|February|March|April|May|June|July|August|September|October|November|December)"
RULES = [
    ("EMAIL", r"[\w.+-]+@[\w-]+(?:\.[\w-]+)+"),
    ("MONEY", r"[$€£]\d+(?:[.,]\d+)*(?: (?:thousand|million|billion))?"),
    ("DATE", rf"\b\d{{1,2}} {MONTH}(?: \d{{4}})?\b|\b{MONTH} \d{{1,2}}(?:, \d{{4}})?|\b{MONTH}\b"),
]
ner = pipeline("token-classification", model="dslim/distilbert-NER", aggregation_strategy="first")


def extract_entities(text, min_score=0.5):
    found = []
    for label, pattern in RULES:
        for m in re.finditer(pattern, text):
            found.append({"label": label, "start": m.start(), "end": m.end(), "source": "rule"})
    for e in ner(text):
        overlaps = any(e["start"] < f["end"] and f["start"] < e["end"] for f in found)
        if e["score"] >= min_score and not overlaps:
            found.append({"label": e["entity_group"], "start": e["start"], "end": e["end"], "source": "model"})
    for f in found:
        f["text"] = text[f["start"]:f["end"]]
    return sorted(found, key=lambda f: f["start"])


for entity in extract_entities("Write to lena.vogel@example.com before 2 May about the €300 Berlin workshop with Kofi Mensah."):
    print(f"{entity['label']:6} {entity['text']!r:28} {entity['source']}")
```

```text
EMAIL  'lena.vogel@example.com'     rule
DATE   '2 May'                      rule
MONEY  '€300'                       rule
LOC    'Berlin'                     model
PER    'Kofi Mensah'                model
```

`min_score` drops model entities below a confidence threshold. At 0.7, the summit's MISC fragment (0.659) would have been dropped, which helps precision on this data; choose the value by scoring a labelled set, as in Step 5.

:::quiz
Q: The model predicts *Okafor* (PER) where the gold span is *Amara Okafor* (PER). How does exact span matching score it?
- [ ] Half correct, because one of two words matches
  Exact matching has no partial credit.
- [x] One false positive and one missed gold entity
  The predicted span doesn't equal the gold span, so it lowers both precision and recall.
- [ ] Correct, because the label matches
  Start and end must match too.

Q: Why does the merge give rule spans priority over overlapping model spans?
- [ ] The model is always wrong when they overlap
  Not always, but the rules' patterns are precise for the shapes they target.
- [x] On this data the rules had precision 1.00 for their labels, and an overlap usually means the model tagged part of an email, price, or date
  Priority goes to the source you've measured to be more precise for that kind of span.
- [ ] Python sets can't hold overlapping tuples
  Sets hold any distinct tuples; overlap is about character ranges, which the set knows nothing about.

Q: The last layer's attention for the first *Washington* puts 0.70 on `[SEP]`. What can you conclude about its LOC label?
- [ ] `[SEP]` caused the wrong label
  High attention to a separator token is a common pattern that carries little information.
- [x] Not much: attention shows where information could flow, not why the model chose a label
  Explaining a prediction needs other tools, such as testing how the output changes when you edit the input.
- [ ] The model ignored the word *signed*
  Earlier layers and other heads could still have carried information from *signed*.
:::

:::takeaways
- Gold labels as `(doc, start, end, label)` tuples make evaluation a set intersection. Exact matching gives no partial credit, which is what tasks like redaction need.
- Rules and models fail differently: here, rules had perfect precision on half the labels and the model covered the other half. Measure each before combining.
- Merge by priority: keep the more precise source's spans, and add the other's only where they don't overlap.
- `logits.softmax(-1)` with `topk` shows how sure the model was and what it nearly chose.
- With `attn_implementation="eager"` and `output_attentions=True`, attention comes back as one `(batch, heads, tokens, tokens)` tensor per layer, with rows that sum to 1.
- Some heads have clear jobs, like attending to the previous token; many weights pile onto `[SEP]`. Attention is not an explanation.
:::

## Ideas to extend it

- Write four more documents in your own style, label them, and score the combined extractor on them. Does recall hold up on text you wrote?
- Make the bare-month rule require *in*, *by*, *on*, or *until* before the month, and check that recall on the gold set stays the same.
- Loop over all 12 heads of layer 1 and find any others with a simple pattern, such as attending to the *next* token.
