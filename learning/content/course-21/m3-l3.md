## Warm-up: cosine similarity in your head

Predict the cosine similarity of `a = [2, 1, 0]` and `b = [1, 1, 1]` before running this. (The dot product is 3; the lengths are √5 and √3.)

```python run
import numpy as np

a, b = np.array([2, 1, 0]), np.array([1, 1, 1])
print(round(a @ b / (np.linalg.norm(a) * np.linalg.norm(b)), 3))
```

3 / √15 ≈ 0.775. Doubling `a` to `[4, 2, 0]` leaves it unchanged.

### Exercise 1: Find near-duplicate tickets

Customers often send the same complaint twice. Duplicates inflate your counts, and if one copy lands in training and the other in testing, they make a model look smarter than it is. Find every pair in this inbox with TF-IDF cosine similarity of at least 0.5.

```python
inbox = [
    "My parcel never arrived",
    "I was charged twice for my order",
    "my parcel never arrived!!",
    "The app crashes when I open it",
    "Charged twice for one order, please refund",
    "Where is my parcel? It never arrived.",
    "App crashes on open",
    "How do I change my email address?",
]
```

```text
1.00  'My parcel never arrived'  ~  'my parcel never arrived!!'
0.64  'My parcel never arrived'  ~  'Where is my parcel? It never arrived.'
...
```

:::hint
`cosine_similarity(X)` with a single matrix returns every pair at once, as a square matrix. Loop over `itertools.combinations(range(len(inbox)), 2)` so each pair appears once and nothing is compared with itself.
:::

:::solution
```python run
from itertools import combinations

from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

inbox = [
    "My parcel never arrived",
    "I was charged twice for my order",
    "my parcel never arrived!!",
    "The app crashes when I open it",
    "Charged twice for one order, please refund",
    "Where is my parcel? It never arrived.",
    "App crashes on open",
    "How do I change my email address?",
]
sims = cosine_similarity(TfidfVectorizer().fit_transform(inbox))
for i, j in combinations(range(len(inbox)), 2):
    if sims[i, j] >= 0.5:
        print(f"{sims[i, j]:.2f}  {inbox[i]!r}  ~  {inbox[j]!r}")
```

The first pair scores exactly 1.00: lowercasing and dropping punctuation made them identical. The threshold is a judgement call. At 0.5 the three parcel tickets group together, which is right; lower it to 0.3 and unrelated tickets that share *my* start to pair up.
:::

### Exercise 2: Precision, recall, and F1 by hand

A classifier produced this confusion matrix on 30 tickets (rows are true labels, columns are predictions, in the order billing, shipping, technical):

```text
[[8 2 0]
 [1 6 3]
 [0 1 9]]
```

Compute precision, recall, and F1 for each class with NumPy, then check your numbers with `classification_report`.

:::hint
Precision divides the diagonal by the **column** sums; recall divides it by the **row** sums. F1 = 2PR / (P + R). To check with scikit-learn, rebuild `y_true` and `y_pred` lists: cell `[i, j]` of the matrix means that many tickets with true class *i* and prediction *j*.
:::

:::solution
```python run
import numpy as np
from sklearn.metrics import classification_report

classes = ["billing", "shipping", "technical"]
cm = np.array([[8, 2, 0], [1, 6, 3], [0, 1, 9]])

precision = cm.diagonal() / cm.sum(axis=0)
recall = cm.diagonal() / cm.sum(axis=1)
f1 = 2 * precision * recall / (precision + recall)
for name, p, r, f in zip(classes, precision, recall, f1):
    print(f"{name:9} precision {p:.3f}  recall {r:.3f}  f1 {f:.3f}")

y_true = [classes[i] for i in range(3) for j in range(3) for _ in range(cm[i, j])]
y_pred = [classes[j] for i in range(3) for j in range(3) for _ in range(cm[i, j])]
print(classification_report(y_true, y_pred, digits=3))
```

Shipping is the weak class on both measures: 3 shipping tickets were called technical (hurting recall), and 2 billing tickets were called shipping (hurting precision). Technical has the opposite profile: it finds 9 of its 10 tickets, but a quarter of what it labels technical isn't.
:::

### Exercise 3: The 90% model that finds nothing

In a test set of 20 tickets, 18 are billing and 2 are shipping. Compare a "model" that always says billing with a real one that gets 2 billing tickets wrong (calls them shipping) and finds 1 of the 2 shipping tickets. Report accuracy and macro F1 for both.

```text
always billing   accuracy 0.90  macro F1 0.47
real model       accuracy 0.85  macro F1 0.66
```

:::hint
Build the lists directly: `y_true = ["billing"] * 18 + ["shipping"] * 2`. Use `accuracy_score` and `f1_score(..., average="macro", zero_division=0)`.
:::

:::solution
```python run
from sklearn.metrics import accuracy_score, f1_score

y_true = ["billing"] * 18 + ["shipping"] * 2
always_billing = ["billing"] * 20
real_model = ["billing"] * 16 + ["shipping"] * 2 + ["shipping", "billing"]

for name, y_pred in [("always billing", always_billing), ("real model", real_model)]:
    acc = accuracy_score(y_true, y_pred)
    macro = f1_score(y_true, y_pred, average="macro", zero_division=0)
    print(f"{name:16} accuracy {acc:.2f}  macro F1 {macro:.2f}")
```

Accuracy prefers the useless model. Macro F1 averages the F1 of each class equally, so the shipping class's F1 of 0 drags the always-billing model down to 0.47. When the small class is the one you care about (fraud, an outage, a safety complaint), report per-class recall and macro F1, never accuracy alone.
:::

### Exercise 4: How much does a cross-validation score wobble?

Using the setup tickets and the pipeline `TfidfVectorizer(stop_words="english")` + `LogisticRegression(C=10)`, run 4-fold stratified cross-validation five times with `random_state` 0 to 4. Print each run's fold scores and mean.

:::hint
Only the `random_state` of `StratifiedKFold(n_splits=4, shuffle=True, random_state=seed)` changes between runs; the model is the same each time.
:::

:::solution
```python run
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import StratifiedKFold, cross_val_score
from sklearn.pipeline import make_pipeline

model = make_pipeline(TfidfVectorizer(stop_words="english"), LogisticRegression(C=10))
for seed in range(5):
    folds = StratifiedKFold(n_splits=4, shuffle=True, random_state=seed)
    scores = cross_val_score(model, texts, labels, cv=folds)
    print(f"shuffle {seed}: folds {scores.round(2)}  mean {scores.mean():.2f}")
```

A single 8-ticket fold can report anything from 25% to 75% for the same model. Even the averages over four folds range from 0.44 to 0.56 depending only on the shuffle. With data this small, a difference of a few points between two models is noise; report the spread, and don't trust a single split.
:::

### Exercise 5: Make similarity survive typos

Three customers type in a hurry. Match each query to the closest of three known tickets, first with word TF-IDF, then with `TfidfVectorizer(analyzer="char_wb", ngram_range=(3, 5))`, and compare the scores.

```python
known = ["I cannot log in with my new password", "my package is three days late", "the app closes as soon as I open it"]
queries = ["cant login, pasword rejected", "packge is late", "app keeps closing"]
```

:::hint
Fit each vectorizer on `known`, then compare `vec.transform(queries)` with `vec.transform(known)`. `char_wb` makes character n-grams only inside word boundaries, padding each word with spaces.
:::

:::solution
```python run
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

known = ["I cannot log in with my new password", "my package is three days late", "the app closes as soon as I open it"]
queries = ["cant login, pasword rejected", "packge is late", "app keeps closing"]

for name, vec in [("words", TfidfVectorizer()), ("char 3-5", TfidfVectorizer(analyzer="char_wb", ngram_range=(3, 5)))]:
    vec.fit(known)
    sims = cosine_similarity(vec.transform(queries), vec.transform(known))
    print(name)
    for query, row in zip(queries, sims):
        best = row.argmax()
        print(f"   {query!r:32} -> {known[best]!r} ({row[best]:.2f})")
```

With words, the login query shares nothing with any ticket (*cant*, *login*, and *pasword* are all new tokens), so its score is 0.00 and the "match" is arbitrary. Character n-grams like `pas`, `wor`, and `ord` survive the typo, and *closing* shares `clos` with *closes*. This is the same idea as subword tokens: pieces of words generalize where whole words can't.
:::

### Exercise 6: Chart coverage against accuracy

Get an honest probability for every setup ticket with `cross_val_predict(..., method="predict_proba")` (each ticket is scored by a model that never saw it). Then, for thresholds from 0.25 to 0.70 in steps of 0.05, compute **coverage** (share of tickets with top probability at or above the threshold) and **accuracy** on those tickets. Plot both against the threshold.

:::hint
`cross_val_predict` returns one row of probabilities per ticket, with columns in sorted label order, so `np.array(sorted(set(labels)))[probs.argmax(axis=1)]` gives the predicted labels.
:::

:::solution
```python run alt="Line chart against confidence threshold from 0.25 to 0.70. Coverage starts at 100 percent and falls in steps to about 16 percent. Accuracy on the covered tickets starts near 50 percent and rises unevenly to 100 percent at the highest thresholds." caption="Raising the threshold hands fewer tickets to the model, and it gets more of them right"
import matplotlib.pyplot as plt
import numpy as np
from sklearn.model_selection import cross_val_predict

folds = StratifiedKFold(n_splits=4, shuffle=True, random_state=0)
probs = cross_val_predict(model, texts, labels, cv=folds, method="predict_proba")
classes = np.array(sorted(set(labels)))
guesses = classes[probs.argmax(axis=1)]
confidence = probs.max(axis=1)
truth = np.array(labels)

thresholds = np.arange(0.25, 0.71, 0.05)
coverage, accuracy = [], []
for t in thresholds:
    sure = confidence >= t
    coverage.append(sure.mean())
    accuracy.append((guesses[sure] == truth[sure]).mean())

fig, ax = plt.subplots(figsize=(7, 4))
ax.plot(thresholds, coverage, marker="o", linewidth=2, color="#2a78d6", label="coverage")
ax.plot(thresholds, accuracy, marker="s", linewidth=2, color="#eb6834", label="accuracy on covered tickets")
ax.set_xlabel("confidence threshold")
ax.set_ylabel("share of tickets")
ax.set_ylim(0, 1.05)
ax.grid(alpha=0.3)
ax.legend()
print(f"overall accuracy: {(guesses == truth).mean():.2f}")
```

Just above 0.25 the lines cross: by 0.3 the model handles about 60% of tickets and gets about 70% of those right, against 50% when it handles everything. The accuracy line is jagged and even dips around 0.45, because at high thresholds it's measured on a handful of tickets. With 32 examples this chart is a sketch; the method is what you'd reuse on a real inbox.
:::

### Challenge: A nearest-neighbour classifier from scratch

Similarity can label text directly: give a new ticket the most common label among its *k* most similar training tickets. Write `knn_predict(train_texts, train_labels, test_texts, k=3)` using a TF-IDF vectorizer (with English stop words) fitted on the training texts and `cosine_similarity`. Evaluate it with the same 4 folds as Exercise 6 (`folds.split(texts, labels)` gives the index arrays), and compare with `KNeighborsClassifier(n_neighbors=3, metric="cosine")` and logistic regression in pipelines.

:::hint
For each row of the similarity matrix, `row.argsort()[::-1][:k]` gives the *k* nearest training tickets. `Counter(...).most_common(1)[0][0]` picks the winning label. Turn `texts` and `labels` into NumPy arrays so you can index them with the fold's index arrays.
:::

:::solution
```python run
from collections import Counter

import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity
from sklearn.neighbors import KNeighborsClassifier

def knn_predict(train_texts, train_labels, test_texts, k=3):
    vec = TfidfVectorizer(stop_words="english").fit(train_texts)
    sims = cosine_similarity(vec.transform(test_texts), vec.transform(train_texts))
    predictions = []
    for row in sims:
        nearest = row.argsort()[::-1][:k]
        votes = Counter(train_labels[i] for i in nearest)
        predictions.append(votes.most_common(1)[0][0])
    return predictions

X, y = np.array(texts), np.array(labels)
mine = []
for train_idx, test_idx in folds.split(X, y):
    predicted = knn_predict(list(X[train_idx]), list(y[train_idx]), list(X[test_idx]))
    mine.append(np.mean(np.array(predicted) == y[test_idx]))
print("my 3-NN            ", np.round(mine, 2), f"mean {np.mean(mine):.2f}")

for name, clf in [("KNeighborsClassifier", KNeighborsClassifier(n_neighbors=3, metric="cosine")),
                  ("logistic regression ", LogisticRegression(C=10))]:
    scores = cross_val_score(make_pipeline(TfidfVectorizer(stop_words="english"), clf), texts, labels, cv=folds)
    print(name, scores.round(2), f"mean {scores.mean():.2f}")
```

Your version and scikit-learn's disagree on some folds, mostly because of ties. When the three neighbours have three different labels, `Counter.most_common` keeps the first one it counted (the nearest), while scikit-learn picks the label that comes first alphabetically. With short tickets, many similarities are exactly 0, which creates more ties. None of the three models is clearly best on 32 tickets; Exercise 4 showed that differences this small are within the noise.
:::
