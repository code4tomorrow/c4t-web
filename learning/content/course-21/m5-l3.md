## Warm-up: predict three softmaxes

Before running anything, guess: what is `softmax([1, 2, 3])`? Will `softmax([2, 4, 6])` be flatter or sharper? And what about `softmax([101, 102, 103])`?

```python run
import numpy as np

def softmax(x):
    e = np.exp(x - np.max(x))
    return e / e.sum()

for scores in ([1, 2, 3], [2, 4, 6], [101, 102, 103]):
    print(scores, "->", softmax(np.array(scores, dtype=float)).round(3))
```

Doubling the scores sharpens the weights, because softmax cares about the gaps between scores. Adding 100 to every score changes nothing at all: only differences matter. That second fact is what makes Exercise 1 work.

### Exercise 1: A softmax that doesn't overflow

The textbook formula, `exp(x) / sum(exp(x))`, breaks on large scores. Run this and look at the result:

```python run
import numpy as np

scores = np.array([1000.0, 1001.0, 1002.0])
naive = np.exp(scores) / np.exp(scores).sum()
print(naive)
```

`np.exp(1000)` is larger than the biggest float, so it becomes `inf`, and `inf / inf` is `nan`. Write `stable_softmax(x)` that works on a 2-D array of scores, one row per query, and returns rows that each sum to 1. Test it on `[[1000, 1001, 1002], [1, 2, 3]]`.

```text
[[0.09  0.245 0.665]
 [0.09  0.245 0.665]]
row sums: [1. 1.]
```

:::hint
The warm-up showed that subtracting the same number from every score in a row leaves the softmax unchanged. Which number would make the biggest exponent exactly `exp(0) = 1`? Use `keepdims=True` so the subtraction lines up row by row.
:::

:::solution
```python run
import numpy as np

def stable_softmax(x):
    shifted = x - x.max(axis=-1, keepdims=True)
    e = np.exp(shifted)
    return e / e.sum(axis=-1, keepdims=True)

scores = np.array([[1000.0, 1001.0, 1002.0], [1.0, 2.0, 3.0]])
weights = stable_softmax(scores)
print(weights.round(3))
print("row sums:", weights.sum(axis=1))
```

After subtracting each row's maximum, the largest exponent is `exp(0) = 1` and the rest are smaller, so nothing overflows. Both rows give the same weights because they have the same gaps. Every deep learning library's softmax does this shift internally.
:::

### Exercise 2: Who attends to whom?

Here are queries and keys for the sentence "she fed her cat", with d = 2. Compute the attention weights `softmax(QKᵀ/√d)` and, for each token, print the token it attends to most and that weight.

```python
import numpy as np

tokens = ["she", "fed", "her", "cat"]
Q = np.array([[1.0, 0.0], [0.0, 2.0], [2.0, 0.5], [0.5, 1.5]])
K = np.array([[2.0, 0.0], [0.0, 1.0], [1.5, 0.0], [0.0, 2.0]])
```

```text
 she -> she (0.46)
 fed -> cat (0.73)
 her -> she (0.59)
 cat -> cat (0.56)
```

:::hint
`Q @ K.T` gives a 4 × 4 score table. Divide by `np.sqrt(2)`, softmax each row, then use `.argmax()` on each row to find the column with the biggest weight.
:::

:::solution
```python run
import numpy as np

def softmax(x):
    e = np.exp(x - x.max(axis=-1, keepdims=True))
    return e / e.sum(axis=-1, keepdims=True)

tokens = ["she", "fed", "her", "cat"]
Q = np.array([[1.0, 0.0], [0.0, 2.0], [2.0, 0.5], [0.5, 1.5]])
K = np.array([[2.0, 0.0], [0.0, 1.0], [1.5, 0.0], [0.0, 2.0]])

weights = softmax(Q @ K.T / np.sqrt(Q.shape[1]))
for i, token in enumerate(tokens):
    j = weights[i].argmax()
    print(f"{token:>4} -> {tokens[j]} ({weights[i, j]:.2f})")
```

I chose these vectors so the pattern reads like grammar: `her` looks back at `she`, and the verb `fed` looks at its object `cat`. In a trained model, heads that track pronouns or verb objects like this do turn up, though most heads are far harder to name.
:::

### Exercise 3: Build and test a causal mask

For n = 5 tokens with random scores (`np.random.default_rng(0).standard_normal((5, 5))`), apply a causal mask and softmax. Then check three things in code: every row sums to 1, every weight above the diagonal is exactly 0, and the count of visible (query, key) pairs is 15 of 25.

```text
[[1.   0.   0.   0.   0.  ]
 [0.28 0.72 0.   0.   0.  ]
 ...
rows sum to 1: True
future weights all zero: True
visible pairs: 15 of 25
```

:::hint
`np.triu(np.ones((n, n), dtype=bool), k=1)` is `True` exactly where the key is in the future. Put `-np.inf` there with `np.where` *before* the softmax. For the visible count, n(n + 1)/2 is the formula to check against.
:::

:::solution
```python run
import numpy as np

def softmax(x):
    e = np.exp(x - x.max(axis=-1, keepdims=True))
    return e / e.sum(axis=-1, keepdims=True)

n = 5
scores = np.random.default_rng(0).standard_normal((n, n))
future = np.triu(np.ones((n, n), dtype=bool), k=1)
weights = softmax(np.where(future, -np.inf, scores))

print(weights.round(2))
print("rows sum to 1:", np.allclose(weights.sum(axis=1), 1))
print("future weights all zero:", bool((weights[future] == 0).all()))
print("visible pairs:", int((~future).sum()), "of", n * n)
```

`weights[future]` picks out every entry above the diagonal using the same boolean mask, so one line checks all ten of them. A generating model needs only the lower triangle, about half the scores, but the cost still grows with n².
:::

### Exercise 4: Two heads instead of one

Real layers run several attention heads side by side, each on its own slice of the vectors. With `rng = np.random.default_rng(42)`, make `X` of shape (4, 6) and three (6, 6) weight matrices. Compute `Q, K, V`, split their 6 columns into 2 heads of 3, run attention in each head (scale by √3), print token 0's weights in each head, and concatenate the head outputs back to shape (4, 6).

```text
head 0 weights for token 0: [0.   0.01 0.15 0.84]
head 1 weights for token 0: [0.71 0.   0.01 0.27]
output shape: (4, 6)
```

:::hint
Head *h* uses columns `h * 3` to `h * 3 + 3`. Slice `Q[:, cols]`, `K[:, cols]`, and `V[:, cols]` with the same `cols`, and join the results with `np.concatenate(outputs, axis=1)`. Make the matrices in the order X, W_q, W_k, W_v so your random numbers match.
:::

:::solution
```python run
import numpy as np

def softmax(x):
    e = np.exp(x - x.max(axis=-1, keepdims=True))
    return e / e.sum(axis=-1, keepdims=True)

rng = np.random.default_rng(42)
n, d_model, heads = 4, 6, 2
d_head = d_model // heads
X = rng.standard_normal((n, d_model))
W_q, W_k, W_v = (rng.standard_normal((d_model, d_model)) for _ in range(3))
Q, K, V = X @ W_q, X @ W_k, X @ W_v

outputs = []
for h in range(heads):
    cols = slice(h * d_head, (h + 1) * d_head)
    w = softmax(Q[:, cols] @ K[:, cols].T / np.sqrt(d_head))
    print(f"head {h} weights for token 0:", w[0].round(2))
    outputs.append(w @ V[:, cols])
print("output shape:", np.concatenate(outputs, axis=1).shape)
```

Same token, two very different patterns: head 0 sends token 0's attention to token 3, while head 1 keeps most of it on token 0 itself. That's why models use many heads: each can track a different relationship at the same cost as one wide head. Real layers then multiply the concatenated output by one more learned matrix.
:::

### Exercise 5: Budget a long chat

A chat model has a 4,096-token window. The system prompt costs 350 tokens, and you reserve 800 for the reply. Message 0 contains the user's rules for the whole conversation, so it is pinned. The other messages must be kept as a contiguous run of the most recent ones: walk backward from the newest and stop at the first message that doesn't fit.

```python
messages = [420, 610, 95, 880, 1200, 540, 130, 700, 60]   # token counts, oldest first
```

```text
kept messages: [0, 5, 6, 7, 8]
dropped: [1, 2, 3, 4]
prompt 2200 + reserve 800 = 3000 of 4096
```

:::hint
Start the budget at 4096 − 350 − 800 − 420. Loop `for i in range(len(messages) - 1, 0, -1)`, and `break` (not `continue`) when a message is too big, so you never keep message 3 while skipping message 4.
:::

:::solution
```python run
WINDOW, SYSTEM_TOKENS, RESERVE = 4096, 350, 800
messages = [420, 610, 95, 880, 1200, 540, 130, 700, 60]

budget = WINDOW - SYSTEM_TOKENS - RESERVE - messages[0]
recent = []
for i in range(len(messages) - 1, 0, -1):
    if messages[i] > budget:
        break
    budget -= messages[i]
    recent.append(i)
kept = [0] + sorted(recent)
used = SYSTEM_TOKENS + sum(messages[i] for i in kept)

print("kept messages:", kept)
print("dropped:", [i for i in range(len(messages)) if i not in kept])
print(f"prompt {used} + reserve {RESERVE} = {used + RESERVE} of {WINDOW}")
```

Message 4, at 1,200 tokens, is the one that doesn't fit, so it and everything older (except the pinned rules) is dropped. Using `continue` would sneak message 3 back in and leave a gap the model can't see, which makes the conversation read as if a turn never happened. About 1,100 tokens go unused; a fancier planner could summarize messages 1 to 4 into that space.
:::

### Exercise 6: Keep key chunks out of the middle

Long-context studies found that models use information at the start and end of the context better than information in the middle. Given chunks already ranked best-first, write `edges_first(ranked)` that places the best chunk first, the second-best last, the third second, the fourth second-to-last, and so on, so the weakest chunks end up in the middle.

```text
['A', 'C', 'E', 'F', 'D', 'B']
['A', 'C', 'E', 'G', 'F', 'D', 'B']
```

:::hint
Every other chunk, starting with the best, goes on the front in order: `ranked[0::2]`. The rest go on the back, reversed so the second-best ends up last.
:::

:::solution
```python run
def edges_first(ranked):
    front = ranked[0::2]
    back = ranked[1::2][::-1]
    return front + back

print(edges_first(list("ABCDEF")))
print(edges_first(list("ABCDEFG")))
```

With six chunks, the best two (A and B) sit at the very edges and the weakest (F and E) meet in the middle. This is a cheap fix to try, and you should measure it on your own questions: newer models are better at long contexts, and the effect varies by model.
:::

### Challenge: Positional encodings that know distance

Implement the sinusoidal encoding from the original transformer: for position `pos` and dimension `i`, use `sin(pos / 10000^(2⌊i/2⌋/d))` on even `i` and `cos` of the same angle on odd `i`. Build the matrix for 50 positions and d = 16, draw it as a heatmap, and then show that the dot product `PE[p] · PE[p + k]` depends only on the offset `k`, not on the starting position `p`. Print it for `p` in 0, 10, 25 and `k` in 0, 1, 5, 20.

:::hint
Broadcasting does the work: `pos = np.arange(50)[:, None]` and `i = np.arange(16)[None, :]` give a 50 × 16 grid of angles. For the dot products, `PE[p] @ PE[p + k]` is one number per (p, k) pair.
:::

:::solution
```python run alt="Left: a 50 by 16 heatmap of sinusoidal positional encodings, with fast stripes in the low dimensions and slow waves in the high ones. Right: the dot product between two position vectors plotted against their offset; lines for three starting positions lie exactly on top of each other, falling from 8 at offset 0." caption="Each dimension is a wave of a different speed; similarity depends only on distance"
import numpy as np
import matplotlib.pyplot as plt

def positional_encoding(n_positions, d):
    pos = np.arange(n_positions)[:, None]
    i = np.arange(d)[None, :]
    angle = pos / 10000 ** (2 * (i // 2) / d)
    return np.where(i % 2 == 0, np.sin(angle), np.cos(angle))

PE = positional_encoding(50, 16)
for p in [0, 10, 25]:
    print(f"p={p:2d}:", [round(float(PE[p] @ PE[p + k]), 2) for k in [0, 1, 5, 20]])

fig, (left, right) = plt.subplots(1, 2, figsize=(9, 3.2))
left.imshow(PE, aspect="auto", cmap="RdBu")
left.set_xlabel("dimension")
left.set_ylabel("position")
for p in [0, 10, 25]:
    right.plot(range(21), [PE[p] @ PE[p + k] for k in range(21)], label=f"start {p}")
right.set_xlabel("offset k")
right.set_ylabel("PE[p] · PE[p+k]")
right.legend()
fig.tight_layout()
```

The three rows of numbers are identical. Each sine and cosine pair contributes `sin(a·p)sin(a·(p+k)) + cos(a·p)cos(a·(p+k)) = cos(a·k)`, and `p` cancels out. So two tokens five apart have the same positional similarity anywhere in the sentence, which helps a model learn patterns like "the word two to the left" once instead of separately for every position.
:::
