Here is a sentence and what a 65-million-parameter model said about it. You'll run this exact model in the next lesson:

```text
Maya Patel flew from Toronto to Nairobi to meet engineers at Safaricom.

PER   0.999  'Maya Patel'
LOC   0.998  'Toronto'
LOC   0.998  'Nairobi'
ORG   0.998  'Safaricom'
```

By Module 4 you'll be able to explain every number in that output: how the sentence became 17 tokens, how each token got a vector, and how the vectors became the labels PER, LOC, and ORG. First you need a place to run it. That place is Google Colab, and setting it up takes about ten minutes.

## What you need, and what you don't

- **A Google account.** A personal account is the safe choice. Some school accounts have Colab switched off by an administrator, and you'll see an access page instead of a notebook.
- **A browser** on any computer, Chromebooks included.
- **No GPU and no installs.** Colab runs Python on a Google virtual machine. transformers, PyTorch, scikit-learn, NumPy, and matplotlib are already installed there.
- **A Hugging Face account is optional.** Every model in this course is public, so you can download them without signing in. The last section explains when an account helps.

This course has two kinds of code. Cells that run on the page (the ones with output underneath) use only scikit-learn, NumPy, and matplotlib on small texts typed into the cell, and the output you see came from actually running them. Cells that download a model from the Hugging Face Hub are marked as Colab cells; run those in your notebook, where the download happens on Google's machine.

## Create your course notebook

1.  Go to [colab.research.google.com](https://colab.research.google.com/) and sign in at the top right.
2.  Choose **File › New notebook in Drive**.
3.  Click the name `Untitled0.ipynb` at the top left and rename it, for example `nlp-m1-setup.ipynb`.
4.  Click into the empty code cell, type `print("hello")`, and press **Shift+Enter**.

The first run takes a few seconds while Colab connects you to a machine, called a *runtime*. Once it's connected, small RAM and Disk bars appear at the top right and the output shows under the cell. In Google Drive, the notebook is now in a folder named **Colab Notebooks**.

:::tabs

## Check that every library is there and new enough

Paste this into a new cell and run it. It reads each package's installed version without importing it, so it's quick, and it flags anything missing or too old for this course.

```python run title="check_versions.py"
import sys
from importlib.metadata import version, PackageNotFoundError

needed = {
    "transformers": (4, 40),
    "torch": (2, 0),
    "scikit-learn": (1, 3),
    "numpy": (1, 24),
    "matplotlib": (3, 5),
}

print(f"{'python':13} {sys.version.split()[0]}")
problems = 0
for package, minimum in needed.items():
    try:
        found = version(package)
    except PackageNotFoundError:
        print(f"{package:13} MISSING")
        problems += 1
        continue
    major, minor = (int(part) for part in found.split(".")[:2])
    ok = (major, minor) >= minimum
    problems += not ok
    print(f"{package:13} {found:10} {'ok' if ok else 'too old'}")

print("Ready for the course" if problems == 0 else f"{problems} package(s) need attention")
```

That output is from the machine that built this page. Your Colab will show its own version numbers, probably different ones, and that's fine as long as every line says `ok`. Notice the comparison uses tuples of integers: `(4, 57) >= (4, 40)` is true, but comparing the strings `"4.100"` and `"4.40"` would give the wrong answer, because text compares character by character.

## Install or upgrade a library, then restart

If a line says `MISSING`, or a later import stops with an error saying no module has that name, install it in a new cell:

```python
%pip install -q transformers
```

To upgrade a package that's too old, add `-U`:

```python
%pip install -q -U transformers
```

Then choose **Runtime › Restart session** and run the version cell again. People skip the restart and then wonder why nothing changed. Python had already loaded the old package into memory, and new files on disk don't replace a module that's already imported. A restart starts a fresh Python process that imports the new copy.

:::note
Installs last only as long as the runtime. When Colab gives you a new machine (after you disconnect, after a long idle stretch, or the next day), the preinstalled versions are back. If you needed an install, keep that `%pip` cell at the top of the notebook.
:::

## Choose CPU or GPU

Every notebook in this course runs on Colab's free CPU runtime. A GPU only makes the transformer cells faster, and on short sentences you'll barely notice. When you do want one:

1.  Choose **Runtime › Change runtime type**.
2.  Under **Hardware accelerator**, pick **T4 GPU** (the free option), then **Save**.
3.  Run this check:

```python
import torch

print("GPU available:", torch.cuda.is_available())
if torch.cuda.is_available():
    print("Device:", torch.cuda.get_device_name(0))
```

On a T4 runtime it prints:

```text
GPU available: True
Device: Tesla T4
```

Changing the runtime type gives you a different machine, so all your variables are gone afterwards. Run your setup cells again. Free GPU time has a usage limit that Google doesn't publish and that changes over time; when you hit it, Colab says it can't connect to a GPU backend and offers a CPU runtime instead. Take it: nothing in this course needs the GPU.

## Optional: a Hugging Face account and token

The [Hugging Face Hub](https://huggingface.co/models) hosts the models you'll download. Public models need no account. An account helps in two cases: models whose owners require you to accept terms before downloading (these are called *gated* models), and heavy use, where signed-in downloads get higher rate limits.

If you make one:

1.  Sign up at [huggingface.co/join](https://huggingface.co/join), then open **Settings › Access Tokens** and create a token with **Read** permission.
2.  In Colab, click the key icon in the left sidebar to open **Secrets**, choose **Add new secret**, name it `HF_TOKEN`, paste the token as its value, and switch on **Notebook access**.
3.  Restart the session. The Hugging Face libraries find a secret named `HF_TOKEN` on their own, so your code never contains the token.

Without a token, your first download prints a warning that begins `The secret HF_TOKEN does not exist in your Colab secrets` and ends by saying authentication is still optional for public models. That warning is harmless. The download carries on.

:::warning
Never paste a token into a code cell. Notebooks are easy to share, and anyone with the notebook could use the token as you. If you ever do, delete it on the Access Tokens page and create a new one.
:::

## Problems people hit on day one

- **"You do not have access" or a blank page when opening Colab.** Your school account has Colab disabled. Sign in with a personal Google account.
- **The version cell still shows the old number after `%pip install -U`.** You didn't restart. Choose **Runtime › Restart session**, then run the cell again.
- **"Cannot connect to GPU backend".** You've used up the free GPU allowance for now. Continue on CPU, or try again later.
- **The `HF_TOKEN` warning on the first download.** Harmless for public models. Add the secret if you want it gone.

:::quiz
Q: You run `%pip install -U transformers`, it finishes without errors, and the version check still prints the old version. What do you do?
- [ ] Run the install cell a second time
  The new files are already on disk. Installing again changes nothing while the old copy is loaded in memory.
- [x] Choose Runtime › Restart session and run the check again
  Python keeps using the module it already imported until the process restarts.
- [ ] Switch to a GPU runtime
  The runtime type has nothing to do with which package version is loaded.

Q: Where should a Hugging Face token live in a Colab notebook?
- [ ] In the first code cell, as `token = "hf_..."`
  Anyone you share the notebook with could read it and use your account.
- [x] In Colab's Secrets panel, named `HF_TOKEN`
  The libraries read it from there, and it never appears in the notebook's code or output.
- [ ] Nowhere: tokens are required for every download, so you can't use the Hub without one
  Public models download without any token; it's needed only for gated models or higher rate limits.

Q: You change the runtime type from CPU to T4 GPU halfway through a notebook. What happens to the variables you'd created?
- [ ] They're copied to the new machine
  Colab doesn't move Python state between machines.
- [x] They're gone, so you rerun the earlier cells
  A new runtime type means a new virtual machine with a fresh Python process.
:::

:::takeaways
- Colab runs your notebook on a Google machine with the NLP libraries preinstalled; notebooks save to **Colab Notebooks** in your Drive.
- Check versions at the top of a notebook. After `%pip install -U`, restart the session or the old version stays loaded.
- The free CPU runtime is enough for this course. A T4 GPU is optional, limited, and comes with a fresh machine.
- A Hugging Face token is optional. If you have one, keep it in Colab Secrets as `HF_TOKEN`, never in a cell.
:::
