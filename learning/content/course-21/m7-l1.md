In 2023, a federal judge in New York fined two lawyers $5,000. Their court filing cited earlier cases, with names, quotes, and citations, that did not exist; ChatGPT had produced them, and nobody checked. The fake cases read exactly like real legal writing. That's the whole problem: a fluent wrong answer and a fluent right answer look the same.

Your Module 6 prototype answered three demo questions perfectly. That is three questions. Here are the checks that turn "it looked good" into a number you can defend, and the options for when the number is too low.

## What a hallucination is, and why models produce one

A **hallucination** is output that sounds confident but isn't supported by the sources the model was given or by the facts. In a grounded system it comes in three main shapes:

-   **Contradiction**: the source says 14 days; the answer says 21.
-   **Unsupported addition**: the answer repeats the source correctly, then adds a rule that appears nowhere.
-   **Fabrication**: a citation, quote, case, or URL that doesn't exist.

Why? A language model is trained to produce likely next tokens, and "likely" isn't "true." A 2025 paper by OpenAI researchers adds a second reason: training and most benchmarks score a confident guess above "I don't know," like a test with no penalty for wrong answers. Retrieval puts the facts in front of the model, which reduces hallucination without removing it.

## Grounding checks you can run without another model

Plain code can catch some failures by comparing the answer with the source it cites. Two checks go a long way:

1.  **Numbers**: every number in the answer should appear in the cited source.
2.  **Support**: most of the answer's content words should appear in the source. We'll use the same light stemming as the Module 6 retriever.

```python run
import re
from collections import Counter

from sklearn.feature_extraction.text import ENGLISH_STOP_WORDS

def terms(text):
    out = []
    for word in re.findall(r"[a-z0-9]+", text.lower()):
        if word in ENGLISH_STOP_WORDS:
            continue
        for suffix in ("ing", "ed", "s"):
            if word.endswith(suffix) and len(word) - len(suffix) >= 3:
                word = word[: -len(suffix)]
                break
        out.append(word)
    return out

def numbers(text):
    return set(re.findall(r"\d+(?:\.\d+)?", text))

def grounding_report(answer, source, min_support=0.75):
    words, source_words = terms(answer), set(terms(source))
    support = sum(w in source_words for w in words) / max(len(words), 1)
    flags = []
    invented = numbers(answer) - numbers(source)
    if invented:
        flags.append(f"numbers not in source: {sorted(invented)}")
    if support < min_support:
        flags.append(f"low support, unmatched {[w for w in words if w not in source_words]}")
    return support, flags

SOURCE = ("Laptops and tablets are loaned for 14 days. A loan can be renewed twice online "
          "if no one is waiting for that model.")
ANSWERS = {
    "faithful": "Laptops are loaned for 14 days and can be renewed twice online.",
    "changed number": "Laptops are loaned for 21 days and can be renewed twice online.",
    "added claim": "Laptops are loaned for 14 days, and late fees are waived for seniors.",
    "negated": "Laptops cannot be renewed online.",
}
for name, answer in ANSWERS.items():
    support, flags = grounding_report(answer, SOURCE)
    print(f"{name:15s} support {support:.2f}  {'; '.join(flags) or 'passes'}")
```

The number check catches the 21. The support check catches the invented senior discount, and its list of unmatched words points straight at the made-up clause. Now look at the last line. "Laptops cannot be renewed online" says the opposite of the source and **passes both checks**: every content word is in the source, and "cannot" is a stop word.

Word-matching checks are cheap and catch a lot, but meaning isn't word overlap. Stronger checks use a natural language inference (NLI) model that predicts whether a source *entails* a sentence, or a second LLM acting as a judge. Both are models that make mistakes, so you measure them too, on examples where you know the answer.

## An evaluation set beats a demo

An **evaluation set** is a list of questions with the right answer and its source written down. Build it before you tune anything, and include on purpose:

-   ordinary questions, phrased the way real users would ask them;
-   tricky ones: numbers, negations, two facts in different sections;
-   **unanswerable** questions (a fifth to a third of the set), where the right output is "the documents don't say."

The SQuAD reading benchmark popularized two scores for short answers. **Exact match** (EM) is 1 if the answer equals the gold answer after normalizing (lowercase, no punctuation, no *a*, *an*, *the*), else 0. **Token F1** gives partial credit for overlapping words. Predict these five scores first:

```python run
import string

def normalize(text):
    text = "".join(ch for ch in text.lower() if ch not in string.punctuation)
    text = re.sub(r"\b(a|an|the)\b", " ", text)
    return " ".join(text.split())

def exact_match(prediction, gold):
    return float(normalize(prediction) == normalize(gold))

def token_f1(prediction, gold):
    pred, ref = normalize(prediction).split(), normalize(gold).split()
    common = sum((Counter(pred) & Counter(ref)).values())
    if common == 0:
        return 0.0
    precision, recall = common / len(pred), common / len(ref)
    return 2 * precision * recall / (precision + recall)

gold = "14 days"
for prediction in ["14 days", "14 Days.", "Fourteen days", "They are loaned for 14 days.", "21 days"]:
    print(f"{prediction:30s} EM {exact_match(prediction, gold):.0f}   F1 {token_f1(prediction, gold):.2f}")
```

Three predictions get the same F1 of 0.50, and only two of them are right. "21 days" would send a student back a week late, and F1 can't tell it from "Fourteen days." So a real evaluation adds number checks, tracks abstention separately, and has a person read a sample.

Size matters too: on 20 questions, "85% vs 80%" is one question. Grow the set as you find new failures.

## Prompting, retrieval, or fine-tuning?

When the scores are too low, there are three levers, and they fix different problems.

| Approach | What changes | Good for | Costs and limits |
| --- | --- | --- | --- |
| **Prompting** | Only the input | Format, tone, rules, a few examples | Uses context tokens on every call; can't add knowledge the model lacks |
| **RAG** | The input, filled with retrieved text | Facts that change or are private; answers that need citations | Only as good as retrieval; more moving parts |
| **Full fine-tuning** | Every weight in the model | A specialized task with thousands of good examples | Expensive; a full copy per task; can forget general skills; facts baked in go stale |
| **LoRA (adapters)** | A small add-on to some weights | The same uses as fine-tuning, on one consumer GPU | Still needs good training data; a weak fit for facts that change often |

A rule of thumb: prompt first, add retrieval when the problem is *knowledge*, and fine-tune when it's *behavior* prompting can't reach, like a strict house style, a narrow labeling task, or a small model that must act like a big one. They combine: many systems fine-tune for their citation format and use RAG for the facts.

## LoRA: fine-tune by learning a small correction

Fine-tuning changes a weight matrix `W` to `W + ΔW`. The insight behind **LoRA** (Low-Rank Adaptation) is that the useful change for one task can be written as the product of two thin matrices: `ΔW = B·A`, where `B` is d × r, `A` is r × k, and the **rank** r is tiny, like 8. The original `W` stays frozen. Only `A` and `B` are trained.

```python run
import numpy as np

d = k = 4096
full = d * k
print(f"full update of one {d}x{k} matrix: {full:,} numbers")
for r in [4, 8, 16, 64]:
    lora = r * (d + k)
    print(f"  LoRA rank {r:2d}: {lora:>9,} numbers ({lora / full:.2%})")

rng = np.random.default_rng(0)
W = rng.standard_normal((6, 6))
r, alpha = 2, 4
A = rng.standard_normal((r, 6)) * 0.01
B = np.zeros((6, r))                       # B starts at zero...
W_effective = W + (alpha / r) * (B @ A)
print("\nmodel unchanged before training:", np.allclose(W_effective, W))
```

Rank 8 trains under 0.4% of that matrix. `B` starts at zero, so the adapted model begins exactly like the original and moves only as far as the data pushes it; `lora_alpha` sets the `alpha / r` scale. For GPT-3, the LoRA paper reports about 10,000 times fewer trainable parameters while matching full fine-tuning on the tasks tested.

Hugging Face's `peft` library adds adapters in a few lines. To stay offline, this cell builds a small, randomly initialized Llama-style model; the code is the same for a real checkpoint loaded with `from_pretrained`.

```python run
from peft import LoraConfig, get_peft_model
from transformers import LlamaConfig, LlamaForCausalLM

config = LlamaConfig(vocab_size=8000, hidden_size=512, intermediate_size=1376,
                     num_hidden_layers=4, num_attention_heads=8, num_key_value_heads=8)
model = LlamaForCausalLM(config)          # random weights, nothing downloaded

lora = LoraConfig(r=8, lora_alpha=16, lora_dropout=0.05,
                  target_modules=["q_proj", "v_proj"], task_type="CAUSAL_LM")
peft_model = get_peft_model(model, lora)
peft_model.print_trainable_parameters()

for name, param in peft_model.named_parameters():
    if "layers.0.self_attn.q_proj" in name:
        print(f"{name.split('q_proj.')[1]:28s} {tuple(param.shape)}  trainable={param.requires_grad}")
```

Check the count by hand: 4 layers × 2 target matrices (`q_proj` and `v_proj`) × 8 × (512 + 512) = 65,536. The base weight is frozen (`trainable=False`); the A and B matrices are the only things an optimizer would touch. For a real 7B model, a trained adapter like this saves as a file of a few dozen megabytes at most, so one base model can carry many adapters. A variant called **QLoRA** also stores the frozen base in 4-bit precision, which lets a 7B model be fine-tuned on a single 16 GB GPU like the T4 in free Colab.

:::quiz
Q: The source says "Study rooms seat up to six people." The answer says "Study rooms seat up to six people and include a whiteboard." Which kind of hallucination is this?
- [ ] Contradiction
  Nothing in the answer conflicts with the source; six people is right.
- [x] Unsupported addition
  The whiteboard appears nowhere in the source; the answer added it.
- [ ] Fabricated citation
  No source is invented here; a claim is.

Q: Gold answer "5 dollars per day". Prediction "5 dollars per week". What is the token F1?
- [ ] 0.0
  Three of the four words match, so F1 gives partial credit.
- [ ] 1.0
  "week" and "day" differ, so it isn't a perfect match.
- [x] 0.75
  Precision and recall are both 3/4, so F1 = 0.75 for an answer that's wrong by a factor of seven.

Q: A city's recycling rules change every few months, and the chatbot keeps giving last year's answer. What should you try first?
- [ ] Fine-tune the model on the new rules
  Baked-in facts go stale again with the next change, and you'd retrain every time.
- [x] Retrieve from the current rules document at question time
  RAG keeps facts outside the model, so updating the document updates the answers.
- [ ] Raise the temperature
  Temperature changes randomness, not knowledge.

Q: A model layer has a 1024 × 1024 weight matrix. How many trainable numbers does a rank-4 LoRA adapter add to it?
- [ ] 4,096
  That's r × d, only one of the two matrices.
- [x] 8,192
  A is 4 × 1024 and B is 1024 × 4, so r × (d + k) = 4 × 2048.
- [ ] 1,048,576
  That's the full matrix, which LoRA keeps frozen.
:::

:::takeaways
- Hallucinations come as contradictions, unsupported additions, and fabrications; retrieval reduces them but doesn't remove them.
- Cheap grounding checks (numbers in the source, word-level support) catch many failures and miss negations and paraphrases.
- An eval set with gold answers, gold sources, and unanswerable questions is the only fair way to compare versions.
- Exact match is strict, token F1 is lenient, and neither notices a wrong number; add targeted checks and read samples.
- Prompt for behavior, retrieve for knowledge, fine-tune (often with LoRA) for behavior prompting can't reach.
:::
