:::objectives
- Split labelled text into training and test sets that keep the class balance.
- Train a TF-IDF and logistic regression pipeline, then diagnose its errors from its weights and its mistakes.
- Compare two versions of a model with cross-validation on the training set, not with the test set.
- Plot a confusion matrix and turn it into precision and recall.
- Retrieve the most similar past tickets with nearest-neighbour search.
- Route tickets automatically only when the model is confident, and measure what that costs in coverage.
:::

The finished tool takes a new ticket and returns a decision like this:

```text
'Where is my refund? It has been two weeks.'
  -> billing (top guess billing, confidence 0.72)
  similar past tickets:
     0.49 [billing] Can I get a refund for the jacket I returned last week?
     0.41 [billing] I was charged twice for order 4471, please refund one of the payments.
```

It labels the ticket, shows how sure it is, and pulls up similar solved cases for whoever handles it. When it isn't sure, it says so and hands the ticket to a person. You'll build it in eight steps, and the first version won't be good. Finding out *why* is most of the lesson.

Make a notebook called `nlp-m3-l2-triage.ipynb`.

## Step 2: Hold out a test set first

Before anything else touches the data, set aside a quarter of it. `stratify=labels` keeps the four classes in the same proportions on both sides, so the test set gets 3 or 4 tickets from each team instead of, by bad luck, none from one.

```python run
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(
    texts, labels, test_size=0.25, stratify=labels, random_state=0
)
print(len(X_train), "training,", len(X_test), "test:", Counter(y_test))
```

From here until Step 6, the test set stays untouched. Every decision about the model is made with training data only.

## Step 3: A first model, and its mistakes

The default choices from the Notes lesson: TF-IDF features into logistic regression, wrapped in a pipeline.

```python run
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline

baseline = make_pipeline(TfidfVectorizer(), LogisticRegression())
baseline.fit(X_train, y_train)

words = baseline[0].get_feature_names_out()
for k, label in enumerate(baseline[-1].classes_):
    top = baseline[-1].coef_[k].argsort()[::-1][:6]
    print(f"{label:10}", [words[i] for i in top])
```

Look at what the model learned. Next to sensible words like *refund* and *delivery* sit *my*, *how*, *was*, *for*, *is*, *the*, and *on*. With only 45 training tickets, the accident that more account tickets happen to say *my* and *how* looks like a real pattern. Those words carry no information about the team, and they're crowding out the words that do.

## Step 4: Fix it, and prove the fix with cross-validation

Two changes. `stop_words="english"` removes common function words before counting. `C=10` weakens logistic regression's regularization (its default penalty for large weights), letting the remaining words get larger weights; with so few examples per word, the default pulls them too close to zero.

Is the new version better? Don't ask the test set; once you choose models by their test score, it stops being an honest estimate. Ask **cross-validation** instead: split the training set into 5 folds, train on 4, score on the 5th, and rotate.

```python run
from sklearn.model_selection import StratifiedKFold, cross_val_score

improved = make_pipeline(TfidfVectorizer(stop_words="english"), LogisticRegression(C=10))

folds = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
for name, model in [("baseline", baseline), ("improved", improved)]:
    scores = cross_val_score(model, X_train, y_train, cv=folds)
    print(f"{name:9} fold accuracies {scores.round(2)}  mean {scores.mean():.2f}")
```

The mean rises by about 20 points. The individual folds bounce around a lot, because each one has only 9 tickets, so a single fold could be fooled; the mean over five is steadier, and the improved model wins or ties on every fold. Because `cross_val_score` refits the whole pipeline each time, the vectorizer never sees the held-out fold either.

## Step 5: Look at the confusion matrix

Now, once, score the chosen model on the test set:

```python run alt="Confusion matrix heatmap for 15 test tickets. The diagonal holds 2 billing, 3 shipping, 3 technical, and 2 account correct. Off the diagonal: one billing ticket predicted as account, one billing as shipping, one technical as shipping, and two account tickets predicted as shipping." caption="Confusion matrix on the 15 held-out tickets: rows are true teams, columns are predictions"
import matplotlib.pyplot as plt
from sklearn.metrics import ConfusionMatrixDisplay, classification_report

improved.fit(X_train, y_train)
predicted = improved.predict(X_test)

teams = ["billing", "shipping", "technical", "account"]
ConfusionMatrixDisplay.from_predictions(y_test, predicted, labels=teams, cmap="Blues", colorbar=False)
plt.title("Improved model on the test set")
print(classification_report(y_test, predicted, labels=teams, zero_division=0))
```

Read the shipping column: shipping's recall is perfect (all 3 shipping tickets were found), but 4 tickets from other teams were also sent there, so its precision is only 3 out of 7, or 0.43. Shipping has become the model's default guess when it's unsure. Let's see which tickets those are:

```python run
for text, truth, guess in zip(X_test, y_test, predicted):
    if truth != guess:
        print(f"{truth:9} -> {guess:9} {text}")
```

Each mistake has a reason you can name. *refunds* is a different token from *refund*, which the model learned, so the PayPal ticket has almost no billing evidence (the subword idea from Module 2 would help). *bank account* contains *account*, the strongest account word. And "unsubscribe me from your marketing emails" uses words that appear in no training ticket at all. The fix for all three is more and more varied training data; no setting will invent the missing evidence.

## Step 6: Similar-case search

An agent handling a ticket wants to see how similar tickets were solved. The pipeline's vectorizer already turns text into TF-IDF vectors, so reuse it and index the training tickets with `NearestNeighbors`:

```python run
from sklearn.neighbors import NearestNeighbors

vectorizer = improved[0]
index = NearestNeighbors(n_neighbors=3, metric="cosine").fit(vectorizer.transform(X_train))

def similar_tickets(text):
    distances, rows = index.kneighbors(vectorizer.transform([text]))
    return [(round(1 - d, 2), y_train[r], X_train[r]) for d, r in zip(distances[0], rows[0])]

for score, label, past in similar_tickets("Where is my refund? It has been two weeks."):
    print(score, f"[{label}]", past)
```

With `metric="cosine"`, `kneighbors` returns cosine *distance*, which is 1 minus cosine similarity, so the code converts it back. The vectorizer drops stop words, so only *refund* (and *weeks*, which no ticket contains) can match. That's why the third result scores 0.00: no other ticket shares a word, and it's an arbitrary pick. A real tool would hide matches below a minimum similarity.

## Step 7: Only act when the model is confident

The model's top probability says how sure it is. Route a ticket automatically only when that probability clears a threshold, and send the rest to a person:

```python run
import numpy as np

probs = improved.predict_proba(X_test)
confidence = probs.max(axis=1)
guesses = improved.classes_[probs.argmax(axis=1)]
truth = np.array(y_test)

for threshold in [0.0, 0.4, 0.5]:
    sure = confidence >= threshold
    accuracy = (guesses[sure] == truth[sure]).mean()
    print(f"threshold {threshold:.1f}: routes {sure.sum():2} of {len(truth)} tickets automatically, {accuracy:.0%} of those correct")
```

At 0.5, the model handles fewer than half the tickets, but gets every one of those right. That's the trade-off you get to choose: *coverage* (how much work the model takes off people) against *accuracy on what it handles*. With 15 test tickets, these numbers are rough; with a real inbox you'd pick the threshold from a few hundred labelled tickets.

## Step 8: The finished triage function

```python run title="triage.py"
def triage(text, threshold=0.5):
    probs = improved.predict_proba([text])[0]
    best = probs.argmax()
    label, confidence = improved.classes_[best], probs[best]
    decision = label if confidence >= threshold else "human review"
    print(repr(text))
    print(f"  -> {decision} (top guess {label}, confidence {confidence:.2f})")
    print("  similar past tickets:")
    for score, past_label, past in similar_tickets(text):
        print(f"     {score:.2f} [{past_label}] {past}")

triage("Where is my refund? It has been two weeks.")
triage("The app shows an error when I try to reset my password.")
```

The second ticket only just clears the bar at 0.55, and its closest past case is an account ticket. It really is both: a technical fault in an account feature. Raise `threshold` to 0.6 and it goes to a person, with the password-reset ticket at the top of the similar cases, which is the most useful thing the tool can do for it.

:::quiz
Q: Why was the test set split off in Step 2, before choosing between the baseline and improved models?
- [ ] `train_test_split` must be the first call in any notebook
  The order is about what information each decision uses, not a library rule.
- [x] So the final test score is an honest estimate; model choices were made with cross-validation on the training set
  If you pick the model that scores best on the test set, that score is no longer unbiased.
- [ ] Cross-validation would crash with the test tickets included
  It would run fine. It would just let test tickets influence your choice.

Q: The shipping column of the confusion matrix has 3 correct and 4 wrong predictions. What does that mean?
- [ ] Shipping recall is 3/7
  Recall is about the shipping *row*: all 3 real shipping tickets were found, so recall is 1.0.
- [x] Shipping precision is 3/7: more than half of the tickets sent to shipping belonged elsewhere
  Precision reads down the predicted column.
- [ ] The model is biased against shipping
  It's the reverse: shipping is its fallback guess.

Q: You raise the confidence threshold from 0.4 to 0.5. What happens?
- [x] Fewer tickets are routed automatically, and those that are tend to be right more often
  A higher bar trades coverage for accuracy on the tickets the model keeps.
- [ ] The model retrains with stricter settings
  The threshold is applied after prediction; the model doesn't change.
- [ ] Accuracy on the whole test set goes up
  Overall accuracy is the same; the threshold only changes which tickets go to people.
:::

:::takeaways
- Split off the test set first and stratify it. Make every modelling decision with cross-validation on the training set, then score on the test set once.
- A model's top-weighted words are a fast diagnostic. Function words near the top mean the model is learning accidents; stop words and more data help.
- The confusion matrix shows *which* mistakes happen: recall reads along a row, precision down a column.
- The pipeline's fitted vectorizer can power nearest-neighbour search too; with `metric="cosine"`, similarity = 1 − distance.
- Acting only on confident predictions trades coverage for accuracy, and you choose the threshold.
:::

## Ideas to extend it

- Add a fifth team, *returns*, with 15 tickets of its own, and see which existing team it gets confused with.
- Try `TfidfVectorizer(analyzer="char_wb", ngram_range=(3, 5))` so *refund* and *refunds* share pieces, and compare it with cross-validation.
- Write 20 new tickets in your own words, label them, and use them as a second test set. Scores usually drop on text written by someone else, which tells you how much the model relies on one writer's phrasing.
