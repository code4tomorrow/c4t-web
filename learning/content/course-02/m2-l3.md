:::objectives
- Predict a sprite's position after a mix of `go to`, `change`, and `set` blocks.
- Measure how Scratch's edge fence treats big and small sprites.
- Choose directions and rotation styles for a walking character.
- Control layers, stop runaway scripts, and react to backdrop changes.
- Read one sprite's position from another sprite's script.
:::

Each exercise starts from a new project unless it says otherwise. Try it on your own first, open the hint if you stall for more than a few minutes, and only then check the solution.

## Warm-up: where does it end?

Without building it, work out the final x and y:

```scratch
go to x: (30) y: (-40)
change x by (-100)
set y to (90)
change y by (-30)
```

:::solution
**(−70, 60).** Step by step: (30, −40), then x becomes 30 − 100 = −70, then y is *set* to 90 (the −40 is thrown away), then 90 − 30 = 60. Build it and check the sprite pane to confirm.
:::

### Exercise 1: Say where you are

Make the cat say its own coordinates for two seconds whenever it's clicked. Drag it somewhere and click it:

```text
-70, 60
```

:::hint
`join` in Operators glues two pieces of text together. You need to glue three pieces: the x position, a comma and space, and the y position. Put one `join` inside another.
:::

:::solution
```scratch
when this sprite clicked
say (join (x position) (join [, ] (y position))) for (2) seconds
```

The inner `join` makes `, 60`, and the outer one puts the x in front. If you see long decimals after dragging, wrap each position in `round` from Operators: `(round (x position))`. Keep this script around; clicking a sprite to ask where it is beats squinting at the sprite pane.
:::

### Exercise 2: How far past the edge can a sprite go?

Run this with the cat at its normal size, then again after `set size to (20) %`. Write down what it says each time.

```scratch
when green flag clicked
go to x: (400) y: (0)
say (x position)
```

Before running it, predict: will it say 400, 240, or something else?

:::hint
Look at how much of the cat is still showing at the right edge. Scratch keeps a small strip of every sprite on the stage, measured from the sprite's *edge*, not its center.
:::

:::solution
It says neither 400 nor 240. The full-size cat stops at a number noticeably bigger than 240, and the small cat stops much closer to 240.

Scratch doesn't fence the costume center; it fences the picture. It lets the sprite slide off until only a thin strip, at most about 15 pixels, is left on the stage. A wide sprite's center is far from its edge, so its center can sit well past 240. A tiny sprite's center is close to its edge, so it stops nearly at 240.

This matters for games. A check like `if <(x position) > (240)>` might never be true for a small sprite, so use a limit a little inside the edge, like 230.
:::

### Exercise 3: Face the way you walk

Make the cat walk with the arrow keys. Left and right should turn it to face that way and step 10. Up and down should move it 10 without turning it. It must never end up upside down.

```text
right arrow:  faces right, x goes up by 10
left arrow:   faces left (mirrored, upright), x goes down by 10
up / down:    y changes by 10, still facing the same way
```

:::hint
`move (10) steps` moves in whatever direction the sprite is facing. Which rotation style mirrors a sprite instead of spinning it?
:::

:::solution
```scratch
when green flag clicked
set rotation style [left-right v]
point in direction (90)
go to x: (0) y: (0)

when [right arrow v] key pressed
point in direction (90)
move (10) steps

when [left arrow v] key pressed
point in direction (-90)
move (10) steps

when [up arrow v] key pressed
change y by (10)

when [down arrow v] key pressed
change y by (-10)
```

Left and right use `point in direction` plus `move`, so the cat turns and walks. Up and down use `change y by` because `move` would send the cat in the direction it's facing, which is sideways. The **left-right** rotation style mirrors the costume when the direction is negative instead of rotating it upside down.
:::

:::video 7ATo0fW5qaU
The Scratch Team shows why a sprite's direction and the way its costume is drawn have to agree. Watch what happens when a costume is drawn facing up instead of right.
:::

### Exercise 4: Put everyone in the right layer

Add the **Sun**, **Cloud**, and **Dove** sprites, and drag them so they overlap. When the green flag is clicked, the order from back to front must always be: Sun, then Cloud, then Dove, no matter how you dragged them before. Then the Dove glides from (−200, 60) to (200, 60) over 4 seconds, passing in front of the cloud.

:::hint
You only need two layer blocks in total, in two different sprites. With three sprites, if you know which one is at the very back and which is at the very front, where does that leave the third?
:::

:::solution
Sun:

```scratch
when green flag clicked
go to x: (60) y: (90)
go to [back v] layer
```

Dove:

```scratch
when green flag clicked
go to [front v] layer
go to x: (-200) y: (60)
glide (4) secs to x: (200) y: (60)
```

The Cloud needs no layer block. The Sun is forced to the back and the Dove to the front, so the Cloud has to be in the middle. This is more reliable than giving all three sprites layer blocks, because green flag scripts in different sprites start at the same moment and you can't count on which one runs first.
:::

### Exercise 5: Stop the legs when the walk ends

Add the **Avery Walking** sprite and give it these two scripts:

```scratch
when green flag clicked
go to x: (-180) y: (-60)
glide (4) secs to x: (180) y: (-60)

when green flag clicked
forever
next costume
wait (0.15) seconds
end
```

Avery walks across nicely, then keeps marching on the spot after she arrives. Fix it so her legs stop when the glide ends and she shows her first costume.

:::hint
The glide script knows when the walk is over, because the block after `glide` only runs once the glide has finished. Which block can end the *other* script from there?
:::

:::solution
```scratch
when green flag clicked
go to x: (-180) y: (-60)
glide (4) secs to x: (180) y: (-60)
stop [other scripts in sprite v]
switch costume to (avery walking-a v)
```

`glide` makes its script wait, so the `stop` block runs exactly when she arrives. It ends the animation loop, and `switch costume to` puts her in a standing pose. Leave the forever script as it is; it still starts on every green flag.
:::

### Exercise 6: Switch scenes with backdrop events

Give the Stage two backdrops, **Arctic** and **Beach Malibu**. Pressing 1 shows the Arctic and pressing 2 shows the beach. Add **Penguin 2**, which reacts to each scene on its own:

```text
Arctic:  penguin jumps to (-100, -80) and says "Home sweet home!"
Beach:   penguin glides to (150, -120) and says "Way too hot!"
```

The scripts that press the keys must not mention the penguin at all.

:::hint
The Stage handles the keys with `switch backdrop to`. The penguin listens with a hat block from Events that fires when the backdrop changes.
:::

:::solution
Stage:

```scratch
when [1 v] key pressed
switch backdrop to (Arctic v)

when [2 v] key pressed
switch backdrop to (Beach Malibu v)
```

Penguin 2:

```scratch
when backdrop switches to [Arctic v]
go to x: (-100) y: (-80)
say [Home sweet home!] for (2) seconds

when backdrop switches to [Beach Malibu v]
glide (1) secs to x: (150) y: (-120)
say [Way too hot!] for (2) seconds
```

The Stage changes the scene and the penguin decides for itself what that means. Add a third sprite that reacts to the same backdrops and you won't touch the Stage's scripts at all. Keeping the "what happened" separate from the "who cares" is the core idea of event-driven programs.
:::

### Challenge: A mirror twin

Make a second cat that always stands at the mirror image of the first one across the vertical center line, as if the y-axis were a mirror. Steer the first cat with your arrow-key scripts from Exercise 3. When the first cat is at (120, 60), the twin is at (−120, 60). When the first cat faces right, the twin faces left.

Move over this practice stage to see the rule: the orange dot follows your mouse, and the blue dot is its twin.

```html preview height="420" title="mirror.html"
<!doctype html>
<style>
  body { margin: 0; font: 15px system-ui, sans-serif; background: #ffffff; color: #222222; }
  svg { display: block; width: 100%; max-width: 480px; margin: 8px auto; border: 2px solid #855cd6; border-radius: 6px; touch-action: none; background: #ffffff; }
  p { text-align: center; margin: 4px; font: bold 16px ui-monospace, monospace; }
</style>
<svg id="stage" viewBox="0 0 480 360">
  <line x1="240" y1="0" x2="240" y2="360" stroke="#855cd6" stroke-width="2" stroke-dasharray="6 4" />
  <line x1="0" y1="180" x2="480" y2="180" stroke="#dddddd" stroke-width="1" />
  <circle id="me" r="7" fill="#ff8c1a" cx="360" cy="120" />
  <circle id="twin" r="7" fill="#4c97ff" cx="120" cy="120" />
</svg>
<p id="read">cat (120, 60)   twin (-120, 60)</p>
<script>
  const svg = document.getElementById("stage");
  svg.addEventListener("pointermove", (e) => {
    const r = svg.getBoundingClientRect();
    const x = Math.round(((e.clientX - r.left) / r.width) * 480 - 240);
    const y = Math.round(180 - ((e.clientY - r.top) / r.height) * 360);
    document.getElementById("me").setAttribute("cx", x + 240);
    document.getElementById("me").setAttribute("cy", 180 - y);
    document.getElementById("twin").setAttribute("cx", 240 - x);
    document.getElementById("twin").setAttribute("cy", 180 - y);
    document.getElementById("read").textContent = "cat (" + x + ", " + y + ")   twin (" + -x + ", " + y + ")";
  });
</script>
```

:::hint
In Sensing, `([x position v] of (Sprite1 v))` reads another sprite's x. The twin's x is that number with its sign flipped, which you can get by subtracting it from 0. Directions mirror the same way: 90 becomes −90.
:::

:::solution
Duplicate the cat, delete the copy's arrow-key scripts, and give the twin (Sprite2) this script:

```scratch
when green flag clicked
set rotation style [left-right v]
forever
go to x: ((0) - ([x position v] of (Sprite1 v))) y: ([y position v] of (Sprite1 v))
point in direction ((0) - ([direction v] of (Sprite1 v)))
end
```

Every frame, the twin copies the first cat's y and the opposite of its x and direction. There's no `-x` block in Scratch, so `0 − x` does the flipping. For an extra twist, add a third cat that mirrors across the horizontal line instead: same x, opposite y.
:::
