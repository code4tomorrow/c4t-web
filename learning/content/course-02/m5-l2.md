:::objectives
- Paint a level as one sprite and use it for every floor, wall, and ceiling check.
- Combine gravity, landing, and walls with the move, check, undo pattern.
- Allow jumping only when the player is standing on something.
- Respawn the player after a fall and end the game when it reaches the goal.
:::

You're building a small platformer called Crystal Climb. A square hero named Pip starts on the left, jumps up three platforms, clears a short wall and a pit, and grabs a crystal at the top right. Here's the level on the Scratch stage grid, with each character standing for 10 steps across and 30 steps up:

```text
  y = 180 +------------------------------------------------+
          |                                                |
          |                                                |
          |                                                |
          |                                           *    |  * Crystal
          |                                    ########### |  C: top at y = 60
          |                                                |
          |                     ##########                 |  B: top at y = 0
          |                                                |
          |       ########                        ##       |  A: top at y = -60
          |    P                                  ##       |  P: Pip starts; ## is a short wall
          |####################      ######################|  ground: top at y = -120
          |                      pit                       |
 y = -180 +------------------------------------------------+
       x = -240                                     x = 240
```

When you finish, Pip will walk smoothly, fall faster and faster, land on any platform, stop at walls, bump into ceilings, and reappear at the start after falling into the pit. Every one of those behaviors comes from one sprite, `Level`, and one pattern: move, check, undo.

## Step 1: Paint the level and the hero

Start a new project at [scratch.mit.edu](https://scratch.mit.edu) and delete the cat.

1. Hover over **Choose a Sprite** and click the paintbrush (**Paint**). Name the sprite `Level`.
2. With the **Rectangle** tool and a filled color, draw the ground, the three platforms, and the wall from the map. Make every piece at least 20 steps thick. Use one color for all of them.
3. Paint a second sprite, a filled square a little taller than a platform is thick. Name it `Pip`. Add eyes if you like, but keep the outline a plain square so it never snags on corners.
4. From the sprite library, add **Crystal** and drag it onto the top-right platform. Set its size to about 50.

The paint canvas is the same size as the stage, so give the level a script that parks it in the middle, where what you painted lines up with where it appears:

```scratch
when green flag clicked
go to x: (0) y: (0)
go to [back v] layer
```

Click the green flag. Nothing moves yet, but the level should sit exactly where you drew it.

## Step 2: Walk left and right

Select Pip. Make two variables with **For this sprite only** selected: `y speed` and `on ground`. Then start Pip's main script:

```scratch
when green flag clicked
go to x: (-200) y: (-90)
forever
  if <key (right arrow v) pressed?> then
    change x by (4)
  end
  if <key (left arrow v) pressed?> then
    change x by (-4)
  end
end
```

Run it. Pip glides left and right, floating in the air and passing through the wall like a ghost. Both problems are next.

## Step 3: Add gravity

Inside the forever loop, after the arrow keys, add the falling code from the Notes. Also set `y speed` to 0 right after the `go to` at the top, so every game starts from rest.

```scratch
change [y speed v] by (-1)
change y by (y speed)
```

Run it. Pip falls straight through the ground and ends up wedged against the bottom of the stage. Scratch's fencing is the only thing stopping it, and fencing isn't a floor.

## Step 4: Land on the level

After `change y by (y speed)`, check for the level and undo the fall if Pip went into it:

```scratch
if <touching (Level v)?> then
  change y by ((0) - (y speed))
  set [y speed v] to (0)
end
```

`(0) - (y speed)` is the opposite of the move Pip just made. If it fell 9 steps, this moves it up 9.

Run it. Pip drops and stops on the ground. Watch closely after a long fall: Pip stops a few steps *above* the ground, then settles the rest of the way over the next few frames. The undo puts Pip back where it was before the last move, which can leave a small gap. It's barely visible, and Module 6 has a pixel-perfect fix using a custom block.

## Step 5: Jump, but only from the ground

Try the obvious version first. Add this at the end of the loop:

```scratch
if <key (up arrow v) pressed?> then
  set [y speed v] to (13)
end
```

Run it and hold the up arrow. Pip flies off the top of the stage, because every frame of holding up resets the speed to 13, even mid-air. The game needs to remember whether Pip is standing on something.

Remove that `if` and rebuild the landing part so it records that fact:

```scratch
change y by (y speed)
set [on ground v] to (0)
if <touching (Level v)?> then
  change y by ((0) - (y speed))
  if <(y speed) < (0)> then
    set [on ground v] to (1)
  end
  set [y speed v] to (0)
end
if <<key (up arrow v) pressed?> and <(on ground) = (1)>> then
  set [y speed v] to (13)
end
```

`on ground` is reset to 0 every frame and only becomes 1 if Pip was moving *down* when it hit the level. Standing still counts, because gravity tugs Pip 1 step into the floor every frame and the undo lifts it back out.

Run it. One press of up gives one jump, about 78 steps high. Holding up just jumps again each time Pip lands.

## Step 6: Solid walls and ceilings

Walk Pip into the short wall. It passes right through, because only the vertical move is checked. Give each arrow key its own undo:

```scratch
if <key (right arrow v) pressed?> then
  change x by (4)
  if <touching (Level v)?> then
    change x by (-4)
  end
end
if <key (left arrow v) pressed?> then
  change x by (-4)
  if <touching (Level v)?> then
    change x by (4)
  end
end
```

Now jump while standing under platform B. Pip's head hits the bottom of the platform and it falls back down. You didn't write any ceiling code: the landing check from Step 5 already undoes the move and stops the speed. The `y speed < 0` test is what keeps a head bump from counting as standing, so Pip can't jump again from the underside of a platform.

## Step 7: Pits, edges, and a speed limit

Three last rules go at the end of the loop. They cap the falling speed so Pip can't tunnel through a platform, keep Pip on the stage left to right, and send Pip home after a fall into the pit.

```scratch
if <(y speed) < (-12)> then
  set [y speed v] to (-12)
end
if <(x position) > (225)> then
  set x to (225)
end
if <(x position) < (-225)> then
  set x to (-225)
end
if <(y position) < (-160)> then
  go to x: (-200) y: (-90)
  set [y speed v] to (0)
end
```

The speed cap belongs just before `change y by (y speed)` in the finished script, so the limit applies to the move that's about to happen. Drop Pip into the pit to check that it reappears at the start, standing still.

## Step 8: Reach the crystal

The crystal decides when the game is won. It waits until Pip touches it, then tells everyone:

```scratch
when green flag clicked
show
wait until <touching (Pip v)?>
broadcast (crystal found v)
hide
```

Pip listens and freezes in place:

```scratch
when I receive [crystal found v]
stop [other scripts in sprite v]
say [I made it!] for (2) seconds
```

`stop [other scripts in sprite v]` ends Pip's forever loop but leaves this script running, so Pip can still talk.

## The finished scripts

Here is Pip's whole main script with every step in place. The Level and Crystal scripts are exactly as above.

```scratch
when green flag clicked
go to x: (-200) y: (-90)
set [y speed v] to (0)
set [on ground v] to (0)
forever
  if <key (right arrow v) pressed?> then
    change x by (4)
    if <touching (Level v)?> then
      change x by (-4)
    end
  end
  if <key (left arrow v) pressed?> then
    change x by (-4)
    if <touching (Level v)?> then
      change x by (4)
    end
  end
  change [y speed v] by (-1)
  if <(y speed) < (-12)> then
    set [y speed v] to (-12)
  end
  change y by (y speed)
  set [on ground v] to (0)
  if <touching (Level v)?> then
    change y by ((0) - (y speed))
    if <(y speed) < (0)> then
      set [on ground v] to (1)
    end
    set [y speed v] to (0)
  end
  if <<key (up arrow v) pressed?> and <(on ground) = (1)>> then
    set [y speed v] to (13)
  end
  if <(x position) > (225)> then
    set x to (225)
  end
  if <(x position) < (-225)> then
    set x to (-225)
  end
  if <(y position) < (-160)> then
    go to x: (-200) y: (-90)
    set [y speed v] to (0)
  end
end

when I receive [crystal found v]
stop [other scripts in sprite v]
say [I made it!] for (2) seconds
```

If a jump you painted turns out to be impossible, move the platform, not the code. The jump is about 78 steps high and carries Pip about 100 steps sideways, so keep each platform within about 60 steps up and 60 steps across from the one before.

:::quiz
Q: Why does the script only set `on ground` to 1 when `y speed` is less than 0?
- [ ] So Pip falls faster
  The check doesn't change any speed; it only decides whether a jump is allowed.
- [x] So bumping a ceiling doesn't count as standing on something
  A head bump also touches the level. Without the test, Pip could jump again from the underside of a platform.
- [ ] Because `y speed` is always negative
  It's positive while Pip rises, which is exactly the case the test filters out.

Q: You remove the `y speed < -12` cap and make a very high drop onto a 10-step-thick platform. What can happen?
- [x] Pip passes straight through the platform
  At high speed Pip can jump from above the platform to below it in one frame, so `touching` is never true.
- [ ] Pip lands harder and bounces
  Nothing in the script makes a bounce; the undo just stops the fall.
- [ ] Scratch shows an error
  Scratch never complains; the collision silently gets missed.

Q: When Pip falls into the pit, the script runs `go to x: (-200) y: (-90)`. What goes wrong if you forget `set [y speed v] to (0)` after it?
- [ ] Nothing, the speed resets by itself
  Variables keep their values until a script changes them.
- [x] Pip reappears already falling at full speed
  `y speed` is still about −12, so the first frame after respawning moves Pip 12 steps down.
- [ ] Pip can no longer jump
  Jumping depends on `on ground`, which still works after landing.
:::

:::takeaways
- Painting every solid thing into one `Level` sprite means one `touching (Level v)?` check covers floors, walls, and ceilings.
- Undo each axis separately: x right after the arrow keys, y right after gravity.
- A flag variable like `on ground`, reset every frame, is how a game remembers what happened this frame.
- Speed caps, clamps, and resets are small rules that stop whole families of bugs.
:::

## Ideas to extend it

- **Coyote time.** Let Pip jump for a few frames after walking off a ledge. Count frames since Pip was last on the ground and allow a jump if the count is under 4.
- **Short hops.** If the player lets go of up while `y speed` is still above 4, set it to 4. Tapping gives a small hop and holding gives a full jump.
- **Lava.** Paint a red strip into a separate `Lava` sprite and send Pip home when it touches it.
- **A second level.** Paint a new costume for `Level` and switch to it when the crystal is found. Module 7 turns this into a proper level system.
