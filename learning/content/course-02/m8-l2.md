---
title: Build your game in milestones, starting from a skeleton
summary: Start from a skeleton that already runs title, levels, and endings, then add the player, goals, clones, difficulty, and feedback one tested milestone at a time, using a three-level Crystal Climb as the worked example.
---

:::objectives
- Start from a skeleton whose states and messages work before any gameplay exists.
- Build in six milestones, each one playable and tested before the next.
- Load levels with `load level` and `begin play`, and clear old clones safely.
- Keep a saved version after every milestone.
:::

The safest way to build a game is to keep it playable the whole time. Each milestone below ends with a game that runs from the title screen to an ending, even if early versions are mostly rectangles. If you run out of time, you hand in the last milestone that worked, not a half-finished pile of scripts.

The worked example is **Crystal Climb: Three Caves**, the platformer from Module 5 grown into a full game. If you chose a different idea, follow the same milestones and use the table at the end to translate each part.

:::tip
Save a version at the end of every milestone, with the milestone number in the project title ("Three Caves m3"). If you're signed in, **File › Save as a copy** does this; offline, use **File › Save to your computer**. When a change breaks everything, going back costs one click.
:::

## Milestone 1: The skeleton

Before any jumping, make the game *flow*. You need two backdrops (`Title`, with the game name and controls written on it, and `Cave`), and these variables and lists, all **For all sprites**:

- Variables: `state`, `level`, `lives`, `level name`.
- Lists: `level names`, `start x`, `start y`, `crystal x`, `crystal y`, `bat count`, `bat speed`.

This is the whole Stage. It runs the title, loops through the levels, and picks an ending:

```scratch
when green flag clicked
set up game
switch backdrop to (Title v)
set [state v] to [title]
wait until <key (space v) pressed?>
switch backdrop to (Cave v)
repeat until <<(lives) < (1)> or <(level) > (length of [level names v])>>
  set [level name v] to (item (level) of [level names v])
  broadcast (load level v) and wait
  set [state v] to [playing]
  broadcast (begin play v)
  wait until <<(state) = [level done]> or <(lives) < (1)>>
  if <(state) = [level done]> then
    change [level v] by (1)
  end
end
set [state v] to [over]
if <(lives) > (0)> then
  broadcast (you win v) and wait
else
  broadcast (game over v) and wait
end
stop [all v]

define set up game
set [level v] to (1)
set [lives v] to (5)
delete all of [level names v]
delete all of [start x v]
delete all of [start y v]
delete all of [crystal x v]
delete all of [crystal y v]
delete all of [bat count v]
delete all of [bat speed v]
add level [The Cellar] start (-200) (-90) crystal (190) (90) bats (1) speed (2)
add level [The Mines] start (-210) (120) crystal (200) (-110) bats (2) speed (3)
add level [The Summit] start (0) (-120) crystal (0) (150) bats (4) speed (3)

define add level (name) start (sx) (sy) crystal (cx) (cy) bats (count) speed (bat speed)
add (name) to [level names v]
add (sx) to [start x v]
add (sy) to [start y v]
add (cx) to [crystal x v]
add (cy) to [crystal y v]
add (count) to [bat count v]
add (bat speed) to [bat speed v]

when [n v] key pressed
if <(state) = [playing]> then
  set [state v] to [level done]
end
```

The `n` key is a test shortcut that finishes the current level instantly. With it you can check the whole flow now, and later jump straight to level 3 without replaying levels 1 and 2. (Delete it, or keep it as a secret, before you share.)

**Done when:** the green flag shows the title, space starts the game, the `level name` monitor reads The Cellar, pressing `n` moves to The Mines and then The Summit, and a third `n` ends the game (silently for now, since nothing answers `you win` yet). Right-click the `level name` monitor and choose **large readout** so it looks like part of the game.

## Milestone 2: The player and one level

Bring in `Level` and `Pip` from Crystal Climb. If you're signed in, drag them across with the **Backpack** at the bottom of the editor; offline, right-click each sprite and choose **export**, then use **Upload Sprite** in the new project. Paint `Level` costume 1 as The Cellar. The Level sprite needs one new script:

```scratch
when I receive [load level v]
switch costume to (level)
```

Pip's movement moves from the green flag to `begin play`, and placing Pip moves to `load level`. A `respawn` custom block keeps both in step:

```scratch
when I receive [load level v]
stop [other scripts in sprite v]
respawn

define respawn
go to x: (item (level) of [start x v]) y: (item (level) of [start y v])
set [y speed v] to (0)

when I receive [begin play v]
forever
  if <key (right arrow v) pressed?> then
    change x by (4)
    if <touching (Level v)?> then
      change x by (-4)
    end
  end
  if <key (left arrow v) pressed?> then
    change x by (-4)
    if <touching (Level v)?> then
      change x by (4)
    end
  end
  change [y speed v] by (-1)
  if <(y speed) < (-12)> then
    set [y speed v] to (-12)
  end
  change y by (y speed)
  set [on ground v] to (0)
  if <touching (Level v)?> then
    fix vertical
    if <(y speed) < (0)> then
      set [on ground v] to (1)
    end
    set [y speed v] to (0)
  end
  if <<key (up arrow v) pressed?> and <(on ground) = (1)>> then
    set [y speed v] to (13)
    start sound (Jump v)
  end
  if <(x position) > (225)> then
    set x to (225)
  end
  if <(x position) < (-225)> then
    set x to (-225)
  end
  if <<(y position) < (-160)> or <touching (Bat v)?>> then
    change [lives v] by (-1)
    start sound (Bonk v)
    respawn
  end
end

define fix vertical
repeat until <not <touching (Level v)?>>
  if <(y speed) > (0)> then
    change y by (-1)
  else
    change y by (1)
  end
end
```

`fix vertical` is the Module 6 Practice block; tick **Run without screen refresh** for it, and leave `respawn` unticked (it has nothing to hurry). Add the **Jump** and **Bonk** sounds from the sound library first. `touching (Bat v)?` is always false until Milestone 4 adds bats, so it's safe to include now.

**Done when:** Pip walks, jumps, and lands cleanly on The Cellar, falling into a pit costs a life and returns Pip to the start, and losing all 5 lives ends the game.

## Milestone 3: Goals and three levels

The Crystal ends each level. It moves into place during `load level` and starts watching during `begin play`:

```scratch
when I receive [load level v]
go to x: (item (level) of [crystal x v]) y: (item (level) of [crystal y v])
show

when I receive [begin play v]
wait until <touching (Pip v)?>
start sound (collect v)
set [state v] to [level done]
hide
```

Setting `state` is all the Crystal does. The Stage's `wait until` notices, and the next pass of its loop loads the next level. Now paint Level costumes 2 and 3, and adjust the start and crystal numbers in `set up game` to fit your layouts.

**Done when:** you can play all three levels in order without the `n` key, every level starts with Pip standing in open air, and the crystal is reachable on each one.

## Milestone 4: Bats, clones, and a custom block

Add the library sprite **Bat** at size 40. The original hides and spawns; the clones fly.

```scratch
when green flag clicked
hide

when I receive [load level v]
delete this clone

when I receive [begin play v]
repeat (item (level) of [bat count v])
  spawn bat
end

define spawn bat
go to x: (pick random (-200) to (200)) y: (pick random (-60) to (150))
repeat until <(distance to (Pip v)) > (150)>
  go to x: (pick random (-200) to (200)) y: (pick random (-60) to (150))
end
set [speed v] to (item (level) of [bat speed v])
create clone of (myself v)

when I start as a clone
show
set rotation style [left-right v]
point in direction (pick random (-180) to (180))
forever
  move (speed) steps
  if on edge, bounce
end

when I start as a clone
forever
  next costume
  wait (0.1) seconds
end
```

Make `speed` **For this sprite only**. Three decisions are worth noticing:

- `delete this clone` on `load level` clears last level's bats. The original ignores that block, so it survives to spawn again.
- Bats spawn on `begin play`, not `load level`, because by then Pip is already at its start point and `distance to (Pip v)` measures the right spot.
- `spawn bat` keeps trying random spots until it finds one at least 150 steps from Pip, so no bat appears on top of the player. Tick **Run without screen refresh** for it so the search finishes in one frame.

**Done when:** each level has the right number of bats (1, 2, then 4), they flap and bounce around, touching one costs a life, and no bat from an earlier level is ever left behind.

## Milestone 5: Difficulty that rises and adapts

The rising part is already in your lists: more bats on later levels. Check the curve by playing it. If The Summit is a wall, lower its `bat count` or `bat speed` in `set up game`, not in the bat scripts.

For the adaptive part, use the helping hand from Module 7's Practice. Paint Level costumes 4 to 6 as copies of 1 to 3, each with one extra platform that makes the hardest jump easier, away from the start point. Make a `falls here` variable, set it to 0 in Pip's `load level` script, and add this inside Pip's life-loss `if`, after `change [lives v] by (-1)`:

```scratch
change [falls here v] by (1)
if <(falls here) = (3)> then
  broadcast (assist v)
end
```

The Level sprite answers:

```scratch
when I receive [assist v]
switch costume to ((level) + (3))
```

**Done when:** three falls on any level makes the helper platform appear, and moving to the next level removes it.

## Milestone 6: Feedback, instructions, and endings

The game works; now make it talk. Pip announces the endings:

```scratch
when I receive [you win v]
stop [other scripts in sprite v]
say [I reached the summit!] for (3) seconds

when I receive [game over v]
stop [other scripts in sprite v]
say (join [Out of lives on ] (level name)) for (3) seconds
```

Then work through this list: controls written on the Title backdrop, the `lives` and `level name` monitors placed where they don't cover platforms, a sound for every action (jump, bonk, collect), and the crystal's two costumes animating so it catches the eye.

**Done when:** a friend who has never seen the game can start it, understand the goal, and reach an ending without you saying a word. You'll test exactly that in the next lesson.

## Translating the skeleton to your game

| Skeleton part | Ghost Patrol: Siege | Lantern Dive | Spell Duel |
| --- | --- | --- | --- |
| `level` | wave number | cave depth | opponent number |
| `Level` costume | backdrop per wave | cave walls per depth | opponent's arena |
| Crystal sets `level done` | Stage sees `ghosts left` reach 0 | `pearls left` reaches 0 | opponent's power reaches 0 |
| Bat clones | ghost clones | pearl and jellyfish clones | spell particle clones |
| Lists per level | wave size, spawn gap | pearls, air time, jellyfish | question range, opponent power |
| Adaptive part | ghost speed bonus | extra air after a failed dive | question range adapts |

:::quiz
Q: Why do the bats spawn on `begin play` instead of `load level`?
- [ ] `create clone` doesn't work inside `load level`
  Clones can be made from any script.
- [x] Pip has already moved to its start point, so `distance to (Pip v)` checks the right place
  During `load level`, Pip might still be standing where the last level ended.
- [ ] So the bats appear before the level costume changes
  It's the opposite: by `begin play`, the costume has already changed.

Q: What does the `n` key script let you do?
- [x] Test level transitions and later levels without replaying the whole game
  Finishing a level instantly makes the flow testable from Milestone 1.
- [ ] Skip the title screen
  It only works while `state` is `playing`.
- [ ] Give the player an extra life
  It sets `state`; it doesn't touch `lives`.
:::

:::takeaways
- Build the flow first: title, levels, endings. Then fill in the gameplay.
- Every milestone ends playable, tested, and saved as its own version.
- `load level` gets everything into place; `begin play` starts things moving.
- `delete this clone` at the top of a `load level` receiver clears old clones and leaves the original alone.
- Tune difficulty in the level data, not inside the scripts.
:::
