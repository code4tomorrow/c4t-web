summary: Fix a clone pile-up between levels, build a story that handles any answer, design a curve with rests, write a quiz that adapts, give Crystal Climb three levels, and code a rival that rubber-bands.
---

:::objectives
- Clear out old clones when a new level loads.
- Branch a story on the player's answer and handle answers you didn't expect.
- Read a difficulty curve from a list and write one with rests.
- Adapt difficulty from a streak, with limits.
- Load levels from lists using `broadcast and wait`.
:::

Exercises 1, 2, 4, and 6 start from new projects. Exercise 3 uses Ghost Patrol, and Exercise 5 and the challenge use Crystal Climb.

## Warm-up: draw the states

Crystal Climb is getting three levels in Exercise 5. On paper, draw its states as boxes and its messages as arrows: title, playing a level, level complete, and won. What message sends the game from "level complete" back to "playing"?

:::solution
Title → Playing (space pressed) → LevelComplete (crystal found) → Playing (load level, then begin play) → … → Won (crystal found on level 3). The arrow back to Playing is really two messages in a row: `load level` with `and wait`, then `begin play`. Drawing it first tells you both broadcasts you'll need.
:::

### Exercise 1: Too many bats on level 2

A friend's platformer spawns bats with this script. The list `bat count` holds 2, 3, 4 (one item per level). Level 1 has 2 bats, as planned. **Before you build it**, predict how many bats are flying on level 2. Then fix it so level 2 has exactly 3.

```scratch
when I receive [load level v]
repeat (item (level) of [bat count v])
  go to x: (pick random (-200) to (200)) y: (pick random (0) to (150))
  create clone of (myself v)
end

when I start as a clone
show
forever
  move (3) steps
  if on edge, bounce
end
```

```text
Level 1: 2 bats
Level 2: 3 bats   (not 11)
```

:::hint
On level 2, which sprites hear `load level`? The hidden original does, and so does every clone left over from level 1. What does each of them do with the message?
:::

:::solution
Level 2 has **11 bats**. The original and the two old clones all run the script, and each makes 3 copies of itself: 3 × 3 = 9 new bats, plus the 2 old ones still flying.

```scratch
when I receive [load level v]
delete this clone
repeat (item (level) of [bat count v])
  go to x: (pick random (-200) to (200)) y: (pick random (0) to (150))
  create clone of (myself v)
end
```

Every old clone hits `delete this clone` and disappears before it can spawn anything. In the original sprite that block does nothing, so the original moves on to the loop and makes exactly 3.
:::

### Exercise 2: Two doors, any answer

Write a tiny story. A narrator says "You wake in a dark hall. Two doors stand ahead." and then asks the player to type `left` or `right`. Left switches to one backdrop and says a line about a crypt; right switches to another and says a line about a tower. If the player types anything else, such as `lfet` or `the middle one`, ask again.

```text
Narrator: Type left or right.     (you type: up)
Narrator: Type left or right.     (you type: LEFT)
Narrator: The left door creaks open onto a crypt...
```

:::hint
Save the answer in a variable and use `repeat until` with an `or` of the two good answers. Scratch's `=` ignores capital letters, so `LEFT` already counts as `left`.
:::

:::solution
```scratch
when green flag clicked
say [You wake in a dark hall. Two doors stand ahead.] for (3) seconds
set [choice v] to []
repeat until <<(choice) = [left]> or <(choice) = [right]>>
  ask [Type left or right.] and wait
  set [choice v] to (answer)
end
if <(choice) = [left]> then
  broadcast (crypt v)
else
  broadcast (tower v)
end

when I receive [crypt v]
switch backdrop to (Castle 2 v)
say [The left door creaks open onto a crypt...] for (3) seconds

when I receive [tower v]
switch backdrop to (Castle 4 v)
say [The right door opens onto a spiral stair, climbing into a tower...] for (3) seconds
```

Without the loop, an `if`/`else` sends every typo through the `else` door, so "lfet" would take the player to the tower. The loop makes sure the `if` only ever sees a real choice. Use any two backdrops you like.
:::

### Exercise 3: Read a curve, then write one

Here are three `wave size` lists for an 8-wave game. Which one is flat, which is a steady ramp, and which ramps with rests?

```text
A: 4, 5, 6, 7, 8, 9, 10, 11
B: 6, 6, 6, 6, 6, 6, 6, 6
C: 4, 6, 8, 5, 8, 10, 7, 12
```

Then write 8 `add wave` lines for Ghost Patrol's `set up game` block with rests at waves 4 and 7 and the hardest wave last. Remember that `spawn gap` matters too: a rest can be fewer ghosts, a longer gap, or both.

:::hint
A rest is a wave that's easier than the one before it. Look for the places where the numbers go *down*.
:::

:::solution
A is the steady ramp, B is flat, and C ramps with rests (it dips at waves 4 and 7). One possible 8-wave design:

```scratch
add wave (5) ghosts every (1.8) seconds :: custom
add wave (7) ghosts every (1.5) seconds :: custom
add wave (9) ghosts every (1.3) seconds :: custom
add wave (6) ghosts every (1.6) seconds :: custom
add wave (10) ghosts every (1.2) seconds :: custom
add wave (12) ghosts every (1.0) seconds :: custom
add wave (9) ghosts every (1.3) seconds :: custom
add wave (15) ghosts every (0.8) seconds :: custom
```

Each rest is still harder than the start of the previous climb (wave 4 is harder than wave 1, and wave 7 is harder than wave 4), so the game keeps moving forward. Because the Stage's wave loop uses `length of [wave size v]`, it plays all 8 waves without any other change.
:::

### Exercise 4: A quiz that adapts

Make a 10-question addition quiz. Each question adds two random numbers from 1 to `top`, where `top` starts at 10. Two right answers in a row raise `top` by 5 (up to 50). A wrong answer lowers it by 5 (down to 5) and resets the streak. At the end, say the score out of 10.

```text
What is 4 + 7?     (you type 11)  ->  Correct!
What is 9 + 2?     (11)           ->  Correct!   (top is now 15)
What is 13 + 8?    (20)           ->  Not quite. It was 21.   (top is back to 10)
...
You got 8 out of 10.
```

:::hint
You need `top`, `streak`, `score`, and two variables `a` and `b` for the numbers. Build the question with nested `join` blocks. Clamp `top` after every question, not just when it changes.
:::

:::solution
```scratch
when green flag clicked
set [top v] to (10)
set [streak v] to (0)
set [score v] to (0)
repeat (10)
  set [a v] to (pick random (1) to (top))
  set [b v] to (pick random (1) to (top))
  ask (join [What is ] (join (a) (join [ + ] (join (b) [?])))) and wait
  if <(answer) = ((a) + (b))> then
    change [score v] by (1)
    change [streak v] by (1)
    say [Correct!] for (1) seconds
    if <(streak) = (2)> then
      set [streak v] to (0)
      change [top v] by (5)
    end
  else
    say (join [Not quite. It was ] ((a) + (b))) for (2) seconds
    set [streak v] to (0)
    change [top v] by (-5)
  end
  if <(top) > (50)> then
    set [top v] to (50)
  end
  if <(top) < (5)> then
    set [top v] to (5)
  end
end
say (join [You got ] (join (score) [ out of 10.])) for (3) seconds
```

This is the same measure, step, clamp recipe as `adapt difficulty`, applied every question instead of every wave. Questions are short enough that adapting this often still feels fair.
:::

### Exercise 5: Three levels for Crystal Climb

Paint two more costumes for the `Level` sprite (costumes 2 and 3) with different platform layouts. Store each level's start point and crystal position in four lists, `start x`, `start y`, `crystal x`, and `crystal y`, one item per level. Reaching the crystal on levels 1 and 2 loads the next level; reaching it on level 3 wins. Falling into a pit sends Pip back to *this* level's start.

:::hint
Use two messages, as in the Notes. `load level` (sent with **and wait**) switches the costume, moves the crystal, and places Pip. `begin play` starts Pip's movement loop and the crystal's `wait until`. The diagram below shows the order.
:::

:::solution
**Stage** (fill the lists with your own numbers):

```scratch
when green flag clicked
set [level v] to (1)
delete all of [start x v]
delete all of [start y v]
delete all of [crystal x v]
delete all of [crystal y v]
add level start (-200) (-90) crystal (190) (90)
add level start (-210) (120) crystal (200) (-110)
add level start (0) (-120) crystal (0) (150)
broadcast (load level v) and wait
broadcast (begin play v)

define add level start (sx) (sy) crystal (cx) (cy)
add (sx) to [start x v]
add (sy) to [start y v]
add (cx) to [crystal x v]
add (cy) to [crystal y v]

when I receive [crystal found v]
if <(level) < (length of [start x v])> then
  change [level v] by (1)
  broadcast (load level v) and wait
  broadcast (begin play v)
else
  broadcast (you win v)
end
```

**Level**: `when I receive [load level v]` → `switch costume to (level)`.

**Crystal**: replace its old green flag script with these two.

```scratch
when I receive [load level v]
go to x: (item (level) of [crystal x v]) y: (item (level) of [crystal y v])
show

when I receive [begin play v]
wait until <touching (Pip v)?>
broadcast (crystal found v)
hide
```

**Pip**: change the main script's hat from `when green flag clicked` to `when I receive [begin play v]`, delete the opening `go to`, and replace the old `crystal found` script with these:

```scratch
when I receive [load level v]
stop [other scripts in sprite v]
go to x: (item (level) of [start x v]) y: (item (level) of [start y v])
set [y speed v] to (0)

when I receive [you win v]
stop [other scripts in sprite v]
say [I made it to the top!] for (2) seconds
```

`stop [other scripts in sprite v]` ends the old movement loop, so Pip stands still while the level changes, and `begin play` starts the loop fresh. Inside the main loop, the pit respawn uses the same two `item` blocks instead of (−200, −90).
:::

### Exercise 6: A rival who rubber-bands

Make a two-sprite race, like the Module 3 race but with the computer as your opponent. The player's sprite moves 6 steps right each time you press the right arrow. A rival sprite moves on its own, and its speed depends on the gap: `2 + (player x − rival x) / 40`, kept between 1 and 5. When it's far behind it speeds up, and when it's far ahead it eases off. The first to pass x = 200 wins.

```text
Rival 120 steps behind  ->  speed 5 (capped)
Level with the player   ->  speed 2
Rival 120 steps ahead   ->  speed 1 (floored)
```

:::hint
Read the player's position from the rival's script with the sensing block `([x position v] of (Player v))`. Calculate the speed, clamp it, then move.
:::

:::solution
```scratch
when green flag clicked
go to x: (-200) y: (-60)
repeat until <(x position) > (200)>
  set [rival speed v] to ((2) + ((([x position v] of (Player v)) - (x position)) / (40)))
  if <(rival speed) < (1)> then
    set [rival speed v] to (1)
  end
  if <(rival speed) > (5)> then
    set [rival speed v] to (5)
  end
  change x by (rival speed)
end
say [I win!]
stop [all v]
```

The player's sprite needs its own finish check:

```scratch
when green flag clicked
go to x: (-200) y: (0)

when [right arrow v] key pressed
change x by (6)
if <(x position) > (200)> then
  say [I win!]
  stop [all v]
end
```

The race stays close whatever the player's skill, which is the point of rubber-banding. Racing games use it to keep the pack together. Push the cap too high, though, and good players feel cheated when a rival they lapped catches up out of nowhere.
:::

### Challenge: a helping hand after three falls

In Crystal Climb, count falls on the current level. After 3 falls on the same level, give the player an extra platform that makes the hardest jump easier, and have Pip say "Here's a hand." Moving to the next level resets the count and removes the help.

:::hint
Paint costumes 4, 5, and 6 as copies of levels 1, 2, and 3 with one extra platform each. Then the assisted version of a level is just `switch costume to ((level) + (3))`. Reset the count in `load level`. Put each helper platform away from the start point so it never appears on top of Pip.
:::

:::solution
In Pip's pit respawn, add one line and a check:

```scratch
change [falls here v] by (1)
if <(falls here) = (3)> then
  broadcast (assist v)
  say [Here's a hand.] for (2) seconds
end
```

Add `set [falls here v] to (0)` to Pip's `load level` script. Then in the Level sprite:

```scratch
when I receive [assist v]
switch costume to ((level) + (3))
```

`load level` already switches back to `(level)`, so the help disappears on the next level. Testing tip: show the `falls here` monitor and fall in on purpose three times to see the switch happen. Note that `say … for (2) seconds` pauses Pip's loop for two seconds; use `say` without a time and clear it later if that bothers you.
:::
