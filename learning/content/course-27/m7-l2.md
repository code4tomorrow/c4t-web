:::objectives
- Save and reload text with SharedPreferences so it survives the app being closed.
- Use Logcat messages to narrow down where a bug is hiding.
- Confirm a theory with a breakpoint and the Variables pane.
- Auto-save in `onPause` so even unsaved drafts aren't lost.
- Build a debug APK and install it on a phone.
:::

Everyone has typed a reminder into an app, closed it, and come back to nothing. Today's app fixes that: one note that's still there after you swipe the app away or restart the phone. Along the way you'll type in a bug on purpose (the kind people really make every week), catch it with Logcat and the debugger, and finish with an APK you can send to a friend.

Here's the finished screen, and what happens to the note across a full close and reopen:

```text
+--------------------------------+
| Buy milk                       |
| Text Sam about Saturday        |
|                                |
|                                |
| Saved 2 times                  |
| [   SAVE    ]  [   CLEAR   ]   |
+--------------------------------+
```

## Step 1: Project and strings

Create an **Empty Views Activity** project named **Quick Note**, package `com.example.quicknote`, Java, API 24. Then replace `res/values/strings.xml`:

```xml
<resources>
    <string name="app_name">Quick Note</string>
    <string name="note_hint">Write something to remember</string>
    <string name="save">Save</string>
    <string name="clear">Clear</string>
</resources>
```

The note box uses `layout_height="0dp"` with `layout_weight="1"`, so it stretches to fill whatever space the status line and buttons leave. `gravity="top|start"` puts the cursor in the top corner of that big box instead of halfway down. `textMultiLine` lets Enter start a new line, and `textCapSentences` capitalizes the first letter of each sentence on the keyboard.

## Step 3: A first version, with a bug in it

Type this `MainActivity.java` exactly, bug included. Don't hunt for the bug yet; the point is to find it the way you'd find a real one.

```java
package com.example.quicknote;

import android.content.SharedPreferences;
import android.os.Bundle;
import android.util.Log;
import android.widget.Button;
import android.widget.EditText;
import android.widget.TextView;

import androidx.activity.EdgeToEdge;
import androidx.appcompat.app.AppCompatActivity;
import androidx.core.graphics.Insets;
import androidx.core.view.ViewCompat;
import androidx.core.view.WindowInsetsCompat;

public class MainActivity extends AppCompatActivity {

    private static final String TAG = "QuickNote";

    private SharedPreferences prefs;
    private EditText noteInput;
    private TextView statusText;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        EdgeToEdge.enable(this);
        setContentView(R.layout.activity_main);
        ViewCompat.setOnApplyWindowInsetsListener(findViewById(R.id.main), (v, insets) -> {
            Insets systemBars = insets.getInsets(WindowInsetsCompat.Type.systemBars());
            v.setPadding(systemBars.left, systemBars.top, systemBars.right, systemBars.bottom);
            return insets;
        });

        prefs = getSharedPreferences("quick_note", MODE_PRIVATE);
        noteInput = findViewById(R.id.note_input);
        statusText = findViewById(R.id.status_text);

        String saved = prefs.getString("notes", "");
        noteInput.setText(saved);
        Log.d(TAG, "Loaded note with " + saved.length() + " characters");

        Button saveButton = findViewById(R.id.save_button);
        saveButton.setOnClickListener(v -> saveNote());
    }

    private void saveNote() {
        String text = noteInput.getText().toString();
        prefs.edit().putString("note", text).apply();
        Log.d(TAG, "Saved note with " + text.length() + " characters");
        statusText.setText("Saved");
    }
}
```

Run it, type `Buy milk`, and tap **Save**. The status line says "Saved." Now swipe the app away from recent apps and open it again. The note is gone. The app promised it saved, and it lied.

## Step 4: Narrow it down with Logcat

Your first job isn't to fix anything; it's to find out *which half* is broken. Is the note never saved, or is it saved and never loaded? The log lines you added answer that.

Open **Logcat** and type `tag:QuickNote` in the search bar. After the run above you'll see three lines like these (the date, time, and process numbers will differ):

```text
2026-11-15 16:02:11.481  8123-8123  QuickNote  com.example.quicknote  D  Loaded note with 0 characters
2026-11-15 16:02:19.902  8123-8123  QuickNote  com.example.quicknote  D  Saved note with 8 characters
2026-11-15 16:02:31.077  8311-8311  QuickNote  com.example.quicknote  D  Loaded note with 0 characters
```

Read them like a detective. Saving happens, and 8 characters is exactly `Buy milk`. Loading happens too, but loading finds nothing. Notice the process number changed from 8123 to 8311: the app really was closed and started fresh. So the bug is somewhere between the save and the load.

## Step 5: Confirm it with a breakpoint

1.  Click the gutter next to the line `String saved = prefs.getString("notes", "");` so a red dot appears.
2.  Click **Debug 'app'** (the bug icon) instead of Run.
3.  The app freezes on that line before it runs. Press **Step Over** (F8) once.
4.  In the **Variables** pane, `saved` is `""`.

So `getString` really returns nothing. Now put the two lines side by side: `getString("notes", ...)` and `putString("note", ...)`. One extra letter. You're reading a key that was never written, and SharedPreferences doesn't complain about that; it just hands back your default.

:::video ln5hc-zprEM
What to watch for: setting breakpoints, stepping, and reading the Variables pane. The video's code is Kotlin, but the debugger buttons and windows are exactly the same for Java.
:::

## Step 6: Fix it for good

You could just delete the `s`. But the same typo can happen again with any key, so fix the cause: type each key **once**, as a constant, and use the constant everywhere. Here's the finished `MainActivity.java`, which also counts saves, wires up the Clear button, and auto-saves whenever you leave the screen:

```java
package com.example.quicknote;

import android.content.SharedPreferences;
import android.os.Bundle;
import android.util.Log;
import android.widget.Button;
import android.widget.EditText;
import android.widget.TextView;

import androidx.activity.EdgeToEdge;
import androidx.appcompat.app.AppCompatActivity;
import androidx.core.graphics.Insets;
import androidx.core.view.ViewCompat;
import androidx.core.view.WindowInsetsCompat;

public class MainActivity extends AppCompatActivity {

    private static final String TAG = "QuickNote";
    private static final String PREFS_NAME = "quick_note";
    private static final String KEY_NOTE = "note";
    private static final String KEY_SAVE_COUNT = "save_count";

    private SharedPreferences prefs;
    private EditText noteInput;
    private TextView statusText;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        EdgeToEdge.enable(this);
        setContentView(R.layout.activity_main);
        ViewCompat.setOnApplyWindowInsetsListener(findViewById(R.id.main), (v, insets) -> {
            Insets systemBars = insets.getInsets(WindowInsetsCompat.Type.systemBars());
            v.setPadding(systemBars.left, systemBars.top, systemBars.right, systemBars.bottom);
            return insets;
        });

        prefs = getSharedPreferences(PREFS_NAME, MODE_PRIVATE);
        noteInput = findViewById(R.id.note_input);
        statusText = findViewById(R.id.status_text);

        String saved = prefs.getString(KEY_NOTE, "");
        noteInput.setText(saved);
        showSaveCount();
        Log.d(TAG, "Loaded note with " + saved.length() + " characters");

        Button saveButton = findViewById(R.id.save_button);
        saveButton.setOnClickListener(v -> saveNote());

        Button clearButton = findViewById(R.id.clear_button);
        clearButton.setOnClickListener(v -> {
            noteInput.setText("");
            prefs.edit().remove(KEY_NOTE).apply();
            Log.d(TAG, "Cleared note");
        });
    }

    @Override
    protected void onPause() {
        super.onPause();
        prefs.edit().putString(KEY_NOTE, noteInput.getText().toString()).apply();
        Log.d(TAG, "Auto-saved in onPause");
    }

    private void saveNote() {
        String text = noteInput.getText().toString();
        int count = prefs.getInt(KEY_SAVE_COUNT, 0) + 1;
        prefs.edit()
                .putString(KEY_NOTE, text)
                .putInt(KEY_SAVE_COUNT, count)
                .apply();
        Log.d(TAG, "Saved note with " + text.length() + " characters (save #" + count + ")");
        showSaveCount();
    }

    private void showSaveCount() {
        int count = prefs.getInt(KEY_SAVE_COUNT, 0);
        statusText.setText("Saved " + count + " times");
    }
}
```

Two things changed besides the constants. `saveNote()` reads the old count, adds one, and writes the note and the count in a **single** `edit()` chain, so they're saved together. And `onPause` saves the text every time the screen loses focus, including when you press Home or swipe to recent apps, so a note you forgot to save still survives.

Remove the breakpoint (click the red dot), run normally, type `Buy milk`, tap **Save**, swipe the app away, and reopen it. The note is back. The newest Logcat lines, trimmed to the message, read:

```text
Saved note with 8 characters (save #1)
Auto-saved in onPause
Loaded note with 8 characters
```

The status line says `Saved 1 times`. That grammar is wrong, and fixing it is the first exercise in this week's practice.

:::tip
`onPause` also runs on rotation, and an `EditText` with an id keeps its own text across rotation anyway, so the note survives turning the phone too. Try it: type something without saving, rotate, then swipe away and reopen.
:::

## Step 7: Build an APK

1.  Choose **Build > Generate App Bundles or APKs > Generate APKs**. On older Android Studio versions it's **Build > Build Bundle(s) / APK(s) > Build APK(s)**.
2.  Wait for the popup saying the APK was generated, and click **locate**.
3.  `app-debug.apk` is in `app/build/outputs/apk/debug/`.

Send that file to an Android phone, tap it, and allow installs from that source when Android asks. The Quick Note icon shows up in the app drawer like any other app. Your note won't be on it: each install has its own private storage, so the phone starts with an empty note.

This is a **debug** APK, signed with Android Studio's automatic debug key. That's fine for friends and testing. A store-ready release needs your own keystore, which this week's practice walks through.

:::quiz
Q: Logcat shows `Saved note with 8 characters` followed later by `Loaded note with 0 characters`. What does that tell you?
- [ ] The note was never saved
  The save line ran, with the right length. Saving isn't the broken half.
- [x] Saving and loading both run, so the problem is in how the two connect, such as the key
  That's exactly what the breakpoint then confirmed: two different keys.
- [ ] SharedPreferences doesn't work on the emulator
  It works the same on emulators and phones.

Q: Why replace the string keys with `KEY_NOTE` and the other constants instead of just deleting the extra `s`?
- [ ] Constants make SharedPreferences save faster
  Speed is the same either way.
- [x] Each key is typed once, so a mismatch between save and load can't happen again
  A misspelled constant name is a compile error, while a misspelled string is silently a different key.
- [ ] Android requires keys to be constants
  Any string works as a key; constants are a safety habit.

Q: You type a note, don't tap Save, and press Home. Later Android closes the app to free memory. Is the note still there when you reopen it?
- [x] Yes, because `onPause` saved it when you pressed Home
  `onPause` runs whenever the screen loses focus, before Android ever gets a chance to close the app.
- [ ] No, because you never tapped Save
  The auto-save in `onPause` covers exactly this case.
- [ ] Only if the phone was rotated first
  Rotation has nothing to do with it.
:::

:::takeaways
- Log both sides of a save-and-load so Logcat can tell you which half is broken.
- A breakpoint plus the Variables pane turns a guess into a confirmed cause.
- SharedPreferences returns the default for a missing key, silently, so keep keys in constants.
- Write related values in one `edit()` chain, and auto-save in `onPause` so drafts survive.
- A debug APK installs on any Android phone, with its own separate storage.
:::
