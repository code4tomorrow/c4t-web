Along the way you'll touch the manifest's label, three resource files, and the layout: the same tour as the notes, but with your hands on the keyboard.

## Step 1: Create the project

Start a new **Empty Views Activity** project (**File > New > New Project**) with these settings:

-   **Name:** `Week1Hello`
-   **Language:** Java
-   **Minimum SDK:** API 24
-   **Build configuration language:** Kotlin DSL (build.gradle.kts)

Wait for the Gradle sync to finish, then press **Run** once before changing anything. If the unchanged template runs, any problem later is something you typed, which makes it much easier to find.

## Step 2: Rename the app and write your text

The name under the icon comes from the manifest's `android:label="@string/app_name"`, so the place to change it is `app > res > values > strings.xml`. While it's open, add the two lines of text for the screen:

```xml
<resources>
    <string name="app_name">Hello C4T</string>
    <string name="greeting">Hi, I\'m Maya!</string>
    <string name="subtitle">This is my first Android app.</string>
</resources>
```

Use your own name. Look closely at `I\'m`: an apostrophe inside an Android string has to be escaped with a backslash. Leave the backslash out and Android Studio flags the line as an error.

## Step 3: Pick your colors

Open `res > values > colors.xml`. Keep the template's two colors and add yours. Colors are written `#AARRGGBB` (alpha, then red, green, blue), where `FF` alpha means fully opaque:

```xml
<?xml version="1.0" encoding="utf-8"?>
<resources>
    <color name="black">#FF000000</color>
    <color name="white">#FFFFFFFF</color>
    <color name="c4t_navy">#FF1B2A49</color>
    <color name="c4t_gold">#FFF5B700</color>
</resources>
```

Android Studio draws a little color square in the left margin beside each line. Click one to pick a color visually instead of typing hex.

:::tip
Resource names may only contain lowercase letters, digits, and underscores. `c4t_navy` works; `C4T-Navy` won't compile.
:::

## Step 4: Use them in the layout

Open `res > layout > activity_main.xml` in **Split** mode. Three changes:

1.  Give the root `ConstraintLayout` a background color.
2.  Point the existing `TextView` at your greeting, give it an ID, and make it big and gold.
3.  Add a second `TextView` underneath for the subtitle.

Replace the whole file with this:

```xml
<?xml version="1.0" encoding="utf-8"?>
<androidx.constraintlayout.widget.ConstraintLayout xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:app="http://schemas.android.com/apk/res-auto"
    xmlns:tools="http://schemas.android.com/tools"
    android:id="@+id/main"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:background="@color/c4t_navy"
    tools:context=".MainActivity">

    <TextView
        android:id="@+id/greetingText"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="@string/greeting"
        android:textColor="@color/c4t_gold"
        android:textSize="32sp"
        android:textStyle="bold"
        app:layout_constraintBottom_toBottomOf="parent"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintTop_toTopOf="parent" />

    <TextView
        android:id="@+id/subtitleText"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_marginTop="12dp"
        android:text="@string/subtitle"
        android:textColor="@color/white"
        android:textSize="18sp"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintTop_toBottomOf="@id/greetingText" />

</androidx.constraintlayout.widget.ConstraintLayout>
```

Watch the preview as you paste: the screen turns navy and both lines appear. Here's what each change does.

-   `android:background="@color/c4t_navy"` paints the whole screen. The `@color/` prefix means "look this name up in `colors.xml`."
-   `android:text="@string/greeting"` replaces the hardcoded `"Hello World!"`. Keeping text in `strings.xml` is how real apps get translated: add a second `strings.xml` for another language and the layout never changes.
-   `sp` (scale-independent pixels) is the unit for text, because it grows when someone picks a larger font in their phone's settings. `dp` is for everything else, like the 12dp gap.
-   The subtitle is pinned to the parent's left and right edges, which centers it, and its top hangs from the bottom of `greetingText`. The reference `@id/greetingText` has no `+` because that ID already exists.

```mermaid caption="Every @ reference in the layout is looked up in a resource file when the app runs"
flowchart LR
    L["activity_main.xml"] -->|"@string/greeting"| S["strings.xml"]
    L -->|"@color/c4t_gold"| C["colors.xml"]
    S --> T["Hi, I'm Maya!"]
    C --> T
    M["AndroidManifest.xml"] -->|"@string/app_name"| S
    S --> N["Hello C4T under the icon"]
```

:::warning
Keep `android:id="@+id/main"` on the root layout. `MainActivity.java` calls `findViewById(R.id.main)` to add the system-bar padding, so if that ID disappears, the build fails with `error: cannot find symbol` pointing at `R.id.main`.
:::

## Step 5: Leave MainActivity.java alone (and know why)

Open `MainActivity.java` and you'll find nothing to change. It already calls `setContentView(R.layout.activity_main)`, so it shows whatever that layout describes. That split is the whole point of Android's View system: what the screen looks like lives in XML, and what it does lives in Java. In Week 4 you'll write Java that changes these views while the app runs, which is why both text views now have IDs.

## Step 6: Run it

Choose your emulator or phone and click **Run**. You should see:

-   A navy screen.
-   **Hi, I'm Maya!** (with your name) in large, bold gold text in the middle.
-   **This is my first Android app.** in white just below it.

Press the home button and open the app drawer: your app is now called **Hello C4T**. If the old name lingers, uninstall the app (long-press the icon, then **Uninstall** or **App info > Uninstall**) and run again; some launchers cache labels.

## Step 7: Compare the preview with the device

Switch the layout editor to **Design** and hold it up against the real screen. They should match. If the preview looks wrong but the device is right, click the refresh arrow above the preview; it sometimes lags behind your typing.

## If something goes wrong

| What you see | Likely cause |
|---|---|
| `error: resource string/greting (aka com.example.week1hello:string/greting) not found.` | A typo between the name in `strings.xml` and the `@string/` reference |
| A red error on a string containing an apostrophe | `I'm` written without the backslash in `strings.xml` |
| The subtitle sits at the very top of the screen | The second `TextView` is missing `app:layout_constraintTop_toBottomOf` |
| The old screen still appears | The build failed; open the **Build** window and read the first error |

:::quiz
Q: Why does the layout say `android:text="@string/greeting"` instead of `android:text="Hi, I'm Maya!"`?
- [ ] Hardcoded text won't compile
  It compiles fine; Android Studio just shows a yellow warning.
- [x] Text in `strings.xml` can be translated or changed in one place without editing layouts
  A `values-es/strings.xml` with the same names would give you a Spanish app, layouts untouched.
- [ ] `@string/` text loads faster
  Speed isn't the reason; organization and translation are.

Q: The greeting uses `32sp`, and the gap below it uses `12dp`. What would change if the greeting used `32dp` instead?
- [x] The greeting would ignore the user's font-size setting
  `sp` follows the phone's text-size preference; `dp` doesn't, which hurts people who need bigger text.
- [ ] The text would be twice as big
  `dp` and `sp` are the same size at the default font setting.
- [ ] The build would fail
  `dp` is a valid unit; Android Studio only warns about it for text.

Q: You delete `android:id="@+id/main"` from the root layout to tidy up. What happens on the next build?
- [ ] Nothing; IDs are optional
  Many IDs are optional, but this one is used by Java code.
- [x] The build fails because `MainActivity.java` refers to `R.id.main`
  The inset code calls `findViewById(R.id.main)`, and that symbol no longer exists.
- [ ] The app runs, but the background turns white
  The background comes from `android:background`, not from the ID.
:::

:::takeaways
- The name under the icon is `app_name` in `strings.xml`, reached through the manifest's `android:label`.
- `@string/name` and `@color/name` look values up in resource files, so one edit changes every screen that uses them.
- Use `sp` for text sizes and `dp` for everything else.
- `MainActivity` shows whatever its layout describes, so design changes don't need Java changes.
- Keep `@+id/main` on the root layout of every Empty Views Activity project.
:::

## Ideas to make it more yours

-   Add a third line with your favorite app or game, using a new string and `android:textStyle="italic"`.
-   Change `c4t_gold` to a color you like and watch both the preview and the device update.
-   Move the greeting a third of the way down the screen by adding `app:layout_constraintVertical_bias="0.3"` to it.
