summary: Arrange screens with LinearLayout and ConstraintLayout, use TextView, Button, ImageView, and EditText, and keep text, colors, and sizes in resource files.

Before a single line of Java runs, a user judges your app by its screen: whether the text lines up, whether the buttons are easy to hit, whether it still looks right on a small phone and a big tablet. Android's View system describes those screens in XML, and the decisions you make there (which container, which units, which resources) determine whether a screen bends gracefully or falls apart.

## Views and ViewGroups

Every element on screen is a **View**. Containers that position other views are **ViewGroups**, and they nest to form a tree. Every view must say how big it is with two required attributes:

-   `wrap_content`: just big enough for its content.
-   `match_parent`: as big as its parent allows.
-   A fixed size such as `48dp`.

Forget either `android:layout_width` or `android:layout_height` and Android Studio underlines the tag in red; run it anyway and the app crashes as soon as that screen loads.

## Units: dp and sp

Screens have wildly different pixel densities, so Android avoids raw pixels.

-   **dp** (density-independent pixels) is about the same physical size on every phone. Use it for widths, heights, margins, and padding. A comfortable touch target is at least 48dp tall.
-   **sp** (scale-independent pixels) is dp that also follows the user's font-size setting. Use it only for text sizes.

## LinearLayout: one direction at a time

A `LinearLayout` stacks its children in a single row or column, set by `android:orientation`. It's the simplest container and perfect for forms and lists of buttons:

```xml
<?xml version="1.0" encoding="utf-8"?>
<LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools"
    android:id="@+id/main"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical"
    tools:context=".MainActivity">

    <TextView
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_margin="@dimen/space_medium"
        android:text="@string/signup_title"
        android:textSize="@dimen/text_title" />

    <EditText
        android:id="@+id/nameInput"
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:layout_marginStart="@dimen/space_medium"
        android:layout_marginEnd="@dimen/space_medium"
        android:autofillHints="name"
        android:hint="@string/name_hint"
        android:inputType="textPersonName" />

    <LinearLayout
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:layout_margin="@dimen/space_medium"
        android:orientation="horizontal">

        <Button
            android:id="@+id/cancelButton"
            android:layout_width="0dp"
            android:layout_height="wrap_content"
            android:layout_weight="1"
            android:text="@string/cancel" />

        <Button
            android:id="@+id/joinButton"
            android:layout_width="0dp"
            android:layout_height="wrap_content"
            android:layout_marginStart="@dimen/space_small"
            android:layout_weight="1"
            android:text="@string/join" />
    </LinearLayout>

</LinearLayout>
```

The two buttons use `layout_weight`. Setting the width to `0dp` and both weights to `1` tells the row to split its leftover space evenly, so each button gets half. Weights of 2 and 1 would give a two-thirds/one-third split.

Two attributes with nearly identical names do different jobs. `android:gravity` positions a view's **content** inside it (text inside a button). `android:layout_gravity` asks the **parent** to position the view itself. Likewise, **padding** is space inside a view's border and **margin** is space outside it.

The root `LinearLayout` keeps `android:id="@+id/main"` so the template's `MainActivity` still compiles.

:::warning
Don't put `android:padding` on the root layout in an Empty Views Activity project. The template's inset code in `MainActivity` calls `setPadding()` on that view at runtime, which replaces your padding with the system-bar sizes. Use margins on the children, or pad an inner layout instead.
:::

## ConstraintLayout: position by relationships

Nesting rows inside columns inside rows gets messy fast. `ConstraintLayout`, the template's default root, lets you place every view in one flat layer by connecting its edges to the parent or to other views:

```xml
<?xml version="1.0" encoding="utf-8"?>
<androidx.constraintlayout.widget.ConstraintLayout xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:app="http://schemas.android.com/apk/res-auto"
    xmlns:tools="http://schemas.android.com/tools"
    android:id="@+id/main"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    tools:context=".MainActivity">

    <ImageView
        android:id="@+id/photo"
        android:layout_width="64dp"
        android:layout_height="64dp"
        android:layout_marginStart="@dimen/space_medium"
        android:layout_marginTop="@dimen/space_medium"
        android:contentDescription="@string/photo_description"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintTop_toTopOf="parent"
        app:srcCompat="@mipmap/ic_launcher_round" />

    <TextView
        android:id="@+id/profileName"
        android:layout_width="0dp"
        android:layout_height="wrap_content"
        android:layout_marginStart="@dimen/space_small"
        android:layout_marginEnd="@dimen/space_medium"
        android:text="@string/profile_name"
        android:textSize="@dimen/text_title"
        android:textStyle="bold"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintStart_toEndOf="@id/photo"
        app:layout_constraintTop_toTopOf="@id/photo" />

    <TextView
        android:id="@+id/profileBio"
        android:layout_width="0dp"
        android:layout_height="wrap_content"
        android:text="@string/profile_bio"
        app:layout_constraintEnd_toEndOf="@id/profileName"
        app:layout_constraintStart_toStartOf="@id/profileName"
        app:layout_constraintTop_toBottomOf="@id/profileName" />

    <Button
        android:id="@+id/followButton"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_marginEnd="@dimen/space_medium"
        android:layout_marginBottom="@dimen/space_medium"
        android:text="@string/follow"
        app:layout_constraintBottom_toBottomOf="parent"
        app:layout_constraintEnd_toEndOf="parent" />

</androidx.constraintlayout.widget.ConstraintLayout>
```

Read constraint attributes as sentences: `app:layout_constraintStart_toEndOf="@id/photo"` means "my start edge sits against the photo's end edge." The rules that matter most:

-   Each view needs at least one **horizontal** and one **vertical** constraint. Without them, Android Studio warns "This view is not constrained," and the view jumps to the top-left corner when the app runs.
-   A width of `0dp` means **match constraints**: stretch to fill the space between the start and end constraints. That's how the name text fills the gap beside the photo and wraps long names instead of running off screen.
-   Constrain both sides and the view centers between them. `app:layout_constraintHorizontal_bias="0.3"` slides it 30% of the way instead of 50%.
-   `start` and `end` (rather than `left` and `right`) flip automatically for right-to-left languages like Arabic.

In the Design view you can drag the small circles on a view's edges to create constraints, but always check the XML afterwards; it's easier to spot a missing constraint in text.

## The four everyday views

**TextView** shows text. Useful attributes: `android:text`, `android:textSize`, `android:textColor`, `android:textStyle` (`bold`, `italic`), `android:gravity`, and `android:maxLines` with `android:ellipsize="end"` to cut long text with "...". Use `tools:text` for placeholder text that appears only in the preview.

**Button** is a tappable view with text. In a Material 3 project, a plain `<Button>` tag is automatically turned into a Material button with rounded corners and the theme's primary color. Change its color with `app:backgroundTint`; `android:background` won't work on it. Tapping does nothing until you connect Java code, which is next week's job.

**ImageView** displays a picture. Prefer `app:srcCompat` over `android:src` because it supports vector images on every API level. Always set `android:contentDescription`, which screen readers announce for blind users (use `@null` for purely decorative images). `android:scaleType` decides how an image fits: `fitCenter` shows all of it, `centerCrop` fills the box and trims edges. To add an image, copy a `.png` or `.jpg` into `res/drawable` (lowercase name, no spaces or dashes), or create an icon with **right-click res > New > Vector Asset**.

**EditText** is a text box. `android:hint` shows grey placeholder text. `android:inputType` controls the keyboard: `textEmailAddress` adds an @ key, `number` shows a number pad, and `textPassword` hides what you type. `android:autofillHints` (like `name`, `emailAddress`, or `password`) lets the phone's autofill help; for fields like notes that should never be autofilled, set `android:importantForAutofill="no"` instead.

## Resources: one place for text, colors, and sizes

The layouts above never hardcode a value. Each `@string/`, `@color/`, or `@dimen/` reference points into `res/values`. These are the resource files the examples need. `strings.xml`:

```xml
<resources>
    <string name="app_name">Week3Layouts</string>
    <string name="signup_title">Join the club</string>
    <string name="name_hint">Your name</string>
    <string name="cancel">Cancel</string>
    <string name="join">Join</string>
    <string name="photo_description">Profile photo</string>
    <string name="profile_name">Maya Patel</string>
    <string name="profile_bio">Learning Android one screen at a time.</string>
    <string name="follow">Follow</string>
</resources>
```

The template has no dimensions file, so create one: right-click `res/values`, choose **New > Values Resource File**, and name it `dimens`:

```xml
<?xml version="1.0" encoding="utf-8"?>
<resources>
    <dimen name="space_small">8dp</dimen>
    <dimen name="space_medium">16dp</dimen>
    <dimen name="text_title">22sp</dimen>
</resources>
```

Colors work the same way in `colors.xml`, as you saw in Week 1. Why bother with resources?

-   **Consistency:** change `space_medium` once and every screen updates.
-   **Translation:** a `values-es/strings.xml` file with the same names gives you a Spanish app with no layout changes.
-   **Variants:** `values-night` colors for dark mode, or bigger `dimens` for tablets, are picked automatically.

:::tip
Android Studio highlights hardcoded text in yellow. Put the cursor on it, press Alt + Enter (Option + Return on macOS), and choose **Extract string resource**. It creates the entry in `strings.xml` and rewrites the attribute for you.
:::
