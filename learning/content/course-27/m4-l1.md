- Choose `dp` or `sp` for a size, and know why raw pixels are avoided.

Your profile screen looks perfect on the Pixel emulator. Then a classmate runs it on a small phone and the email address runs off the right edge, and on a tablet everything huddles in the top-left corner. Nothing is wrong with the Java; the layout just described *positions* when it should have described *relationships*. This week is about writing layouts that bend instead of break.

## Every screen is a tree of views

Everything you can see is a **View**: a piece of text, a button, an image. Containers that arrange other views are **ViewGroups**, and they nest, so every screen is a tree. Here's the sign-up screen from the next section, drawn as its tree:

```mermaid caption="The sign-up layout as a tree: two containers, four views"
flowchart TD
    R["LinearLayout, vertical (id main)"] --> T["TextView: Join the club"]
    R --> E["EditText: Your name"]
    R --> H["LinearLayout, horizontal"]
    H --> C["Button: Cancel"]
    H --> J["Button: Join"]
```

Android measures the tree from the top down: each parent tells its children how much room there is, and each child answers with how big it wants to be. A child says that with two required attributes, `android:layout_width` and `android:layout_height`, each set to one of:

-   `wrap_content`: just big enough for what's inside.
-   `match_parent`: as big as the parent allows.
-   A fixed size such as `48dp`.

Leave one out and Android Studio underlines the tag in red. Run it anyway and the app crashes when that screen loads, with `You must supply a layout_width attribute`.

## dp and sp: sizes that mean the same on every phone

Android screens range from about 160 pixels per inch to well over 400. Size a button in pixels and it's a fingertip on one phone and a grain of rice on another. So Android measures in two units of its own:

-   **dp** (density-independent pixels) is roughly the same physical size on every screen. Use it for widths, heights, margins, and padding. A comfortable touch target is at least **48dp** tall.
-   **sp** (scale-independent pixels) is dp that also follows the user's font-size setting. Use it **only** for text sizes.

## LinearLayout: one row or one column

A `LinearLayout` lines its children up in a single column or row, set by `android:orientation`. It's the simplest container there is, and perfect for forms and rows of buttons:

```xml
<?xml version="1.0" encoding="utf-8"?>
<LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools"
    android:id="@+id/main"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical"
    tools:context=".MainActivity">

    <TextView
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_margin="@dimen/space_medium"
        android:text="@string/signup_title"
        android:textSize="@dimen/text_title" />

    <EditText
        android:id="@+id/nameInput"
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:layout_marginStart="@dimen/space_medium"
        android:layout_marginEnd="@dimen/space_medium"
        android:autofillHints="name"
        android:hint="@string/name_hint"
        android:inputType="textPersonName" />

    <LinearLayout
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:layout_margin="@dimen/space_medium"
        android:orientation="horizontal">

        <Button
            android:id="@+id/cancelButton"
            android:layout_width="0dp"
            android:layout_height="wrap_content"
            android:layout_weight="1"
            android:text="@string/cancel" />

        <Button
            android:id="@+id/joinButton"
            android:layout_width="0dp"
            android:layout_height="wrap_content"
            android:layout_marginStart="@dimen/space_small"
            android:layout_weight="1"
            android:text="@string/join" />
    </LinearLayout>

</LinearLayout>
```

The two buttons use **weights**. A width of `0dp` plus a `layout_weight` tells the row, "ignore my natural size and give me a share of the space." Weights of 1 and 1 split the row in half. Weights of 1 and 2 give Join two of three shares. Drag the slider to see the split change (this is a browser imitation, but the arithmetic is the same):

```html preview height="190" title="layout_weight imitation"
<p>Join's weight: <input id="w" type="range" min="1" max="3" value="1"> <b id="v">1</b></p>
<div class="row">
  <button>Cancel<br><small>weight 1</small></button>
  <button id="join">Join<br><small id="jw">weight 1</small></button>
</div>
<p id="share">Cancel gets 1/2 of the row; Join gets 1/2.</p>
<script>
  const slider = document.getElementById("w");
  slider.oninput = () => {
    const n = Number(slider.value);
    document.getElementById("join").style.flex = n;
    document.getElementById("v").textContent = n;
    document.getElementById("jw").textContent = "weight " + n;
    document.getElementById("share").textContent = "Cancel gets 1/" + (n + 1) + " of the row; Join gets " + n + "/" + (n + 1) + ".";
  };
</script>
<style>
  body { font: 15px system-ui, sans-serif; margin: 12px; }
  .row { display: flex; gap: 8px; }
  button { flex: 1; padding: 10px; border: 0; border-radius: 20px; background: #6750a4; color: #fff; font: inherit; }
  small { opacity: 0.8; }
</style>
```

Two pairs of attributes trip everyone up at first:

-   `android:gravity` positions a view's **content** inside it, like text inside a button. `android:layout_gravity` asks the **parent** to position the view itself.
-   **Padding** is space inside a view's border; **margin** is space outside it.

The root `LinearLayout` keeps `android:id="@+id/main"` so the template's `MainActivity` still compiles.

:::warning
Don't put `android:padding` on the root layout in an Empty Views Activity project. The template's inset code in `MainActivity` calls `setPadding()` on that view while the app runs, which replaces your padding with the system-bar sizes. Use margins on the children, or pad an inner layout instead.
:::

## ConstraintLayout: place views by their relationships

Nesting rows inside columns inside rows gets messy fast. `ConstraintLayout`, the template's default root, keeps every view in one flat layer and places each one by tying its edges to the parent or to other views:

```xml
<?xml version="1.0" encoding="utf-8"?>
<androidx.constraintlayout.widget.ConstraintLayout xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:app="http://schemas.android.com/apk/res-auto"
    xmlns:tools="http://schemas.android.com/tools"
    android:id="@+id/main"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    tools:context=".MainActivity">

    <ImageView
        android:id="@+id/photo"
        android:layout_width="64dp"
        android:layout_height="64dp"
        android:layout_marginStart="@dimen/space_medium"
        android:layout_marginTop="@dimen/space_medium"
        android:contentDescription="@string/photo_description"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintTop_toTopOf="parent"
        app:srcCompat="@mipmap/ic_launcher_round" />

    <TextView
        android:id="@+id/profileName"
        android:layout_width="0dp"
        android:layout_height="wrap_content"
        android:layout_marginStart="@dimen/space_small"
        android:layout_marginEnd="@dimen/space_medium"
        android:text="@string/profile_name"
        android:textSize="@dimen/text_title"
        android:textStyle="bold"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintStart_toEndOf="@id/photo"
        app:layout_constraintTop_toTopOf="@id/photo" />

    <TextView
        android:id="@+id/profileBio"
        android:layout_width="0dp"
        android:layout_height="wrap_content"
        android:text="@string/profile_bio"
        app:layout_constraintEnd_toEndOf="@id/profileName"
        app:layout_constraintStart_toStartOf="@id/profileName"
        app:layout_constraintTop_toBottomOf="@id/profileName" />

    <Button
        android:id="@+id/followButton"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_marginEnd="@dimen/space_medium"
        android:layout_marginBottom="@dimen/space_medium"
        android:text="@string/follow"
        app:layout_constraintBottom_toBottomOf="parent"
        app:layout_constraintEnd_toEndOf="parent" />

</androidx.constraintlayout.widget.ConstraintLayout>
```

Read each constraint as a sentence. `app:layout_constraintStart_toEndOf="@id/photo"` says "my start edge sits against the photo's end edge." Drawn out, the four views hang off each other like this:

```mermaid caption="Each arrow is one constraint: which edge is tied to what"
flowchart LR
    P[parent] -->|"start + top"| I[photo]
    I -->|"name's start to photo's end"| N[profileName]
    P -->|end| N
    N -->|"bio's top to name's bottom"| B[profileBio]
    P -->|"end + bottom"| F[followButton]
```

The rules that matter most:

-   Every view needs at least one **horizontal** and one **vertical** constraint. Without them Android Studio warns `This view is not constrained`, and on the phone the view jumps to the top-left corner.
-   A width of `0dp` means **match constraints**: stretch to fill the space between the start and end constraints. That's how the name fills the gap beside the photo and wraps a long name instead of running off the screen, which is the fix for the phone in this lesson's first paragraph.
-   Constrain both sides and the view centers between them. `app:layout_constraintHorizontal_bias="0.3"` slides it 30% of the way across instead of 50%.
-   Use `start` and `end` rather than `left` and `right`. They flip automatically for right-to-left languages like Arabic and Hebrew.

In Design view you can drag the small circles on a view's edges to make constraints, but always check the XML afterwards; a missing constraint is far easier to spot in text.

## The four everyday views

**TextView** shows text. Useful attributes: `android:text`, `android:textSize`, `android:textColor`, `android:textStyle` (`bold`, `italic`), `android:gravity`, and `android:maxLines` with `android:ellipsize="end"` to cut long text off with "...". Use `tools:text` for placeholder text that only appears in the preview.

**Button** is a tappable view with text. In a Material 3 project, a plain `<Button>` tag is automatically turned into a Material button with rounded corners and the theme's main color. Change its color with `app:backgroundTint`; `android:background` won't work on it. Tapping does nothing until Java listens for it, which is next week.

**ImageView** displays a picture. Prefer `app:srcCompat` over `android:src`, because it supports vector images on every Android version. Always set `android:contentDescription`, which screen readers announce for blind users (use `@null` for purely decorative images). `android:scaleType` decides how the image fits its box: `fitCenter` shows all of it, and `centerCrop` fills the box and trims the edges. To add an image, copy a `.png` or `.jpg` into `res/drawable` (lowercase name, no spaces or dashes), or make an icon with **right-click res > New > Vector Asset**.

**EditText** is a text box. `android:hint` shows grey placeholder text. `android:inputType` picks the keyboard: `textEmailAddress` adds an @ key, `number` shows a number pad, `phone` shows a dial pad, and `textPassword` hides what you type. `android:autofillHints` (like `name`, `emailAddress`, or `password`) lets the phone's autofill help; for a field that should never be autofilled, such as a note, set `android:importantForAutofill="no"` instead.

## Resources: one place for text, colors, and sizes

Neither layout above hardcodes a value. Each `@string/`, `@color/`, and `@dimen/` points into `res/values`. Here are the strings they need, in `strings.xml`:

```xml
<resources>
    <string name="app_name">Week3Layouts</string>
    <string name="signup_title">Join the club</string>
    <string name="name_hint">Your name</string>
    <string name="cancel">Cancel</string>
    <string name="join">Join</string>
    <string name="photo_description">Profile photo</string>
    <string name="profile_name">Maya Patel</string>
    <string name="profile_bio">Learning Android one screen at a time.</string>
    <string name="follow">Follow</string>
</resources>
```

The template has no dimensions file, so make one: right-click `res/values`, choose **New > Values Resource File**, and name it `dimens`:

```xml
<?xml version="1.0" encoding="utf-8"?>
<resources>
    <dimen name="space_small">8dp</dimen>
    <dimen name="space_medium">16dp</dimen>
    <dimen name="text_title">22sp</dimen>
</resources>
```

Colors work the same way in `colors.xml`, as you saw in Week 1. Why go to the trouble?

-   **Consistency:** change `space_medium` once and every screen that uses it updates.
-   **Translation:** a `values-es/strings.xml` file with the same names gives you a Spanish app with no layout changes.
-   **Variants:** `values-night` colors for dark mode, or bigger `dimens` for tablets, are picked automatically by the phone.

:::tip
Android Studio highlights hardcoded text in yellow. Put the cursor on it, press Alt + Enter (Option + Return on macOS), and choose **Extract string resource**. It writes the entry in `strings.xml` and rewrites the attribute for you.
:::

:::quiz
Q: A row has two buttons, both with `layout_width="0dp"`. One has `layout_weight="2"` and the other `layout_weight="1"`. How is the row split?
- [ ] Half and half
  That's what equal weights do.
- [x] Two thirds and one third
  There are three shares in total, and the first button takes two of them.
- [ ] The first button gets 2dp more
  Weights are shares of the leftover space, not sizes in dp.

Q: In a `ConstraintLayout`, a button has `app:layout_constraintTop_toBottomOf="@id/title"` and no other constraints. Where does it appear on the phone?
- [ ] Centered under the title
  Centering needs both a start and an end constraint.
- [x] Under the title, but stuck against the left edge
  It has a vertical constraint but no horizontal one, so it falls back to x = 0.
- [ ] Exactly where you dragged it in the Design view
  Dragged positions are `tools:` attributes, which only exist in the preview.

Q: You want the word "Join" centered inside a wide button. Which attribute goes on the button?
- [x] `android:gravity="center"`
  `gravity` positions the content inside the view.
- [ ] `android:layout_gravity="center"`
  That asks the parent to move the whole button, not its text.
- [ ] `android:padding="center"`
  Padding takes a size like `8dp`, not a position.

Q: Which `inputType` should a text box for a phone number use?
- [ ] `text`
  That shows a full keyboard, which slows people down.
- [ ] `number`
  A number pad works, but it has no `+` or other dialing symbols.
- [x] `phone`
  It opens a dial pad with the symbols phone numbers need.
:::

:::takeaways
- A screen is a tree of views inside ViewGroups, and every view needs `layout_width` and `layout_height`.
- Use `dp` for sizes and spacing, `sp` only for text, and make touch targets at least 48dp tall.
- `LinearLayout` stacks in one direction; `0dp` plus `layout_weight` splits the space by shares.
- In `ConstraintLayout`, every view needs a horizontal and a vertical constraint, and `0dp` stretches between them.
- Pull text, colors, and sizes from `res/values` so one edit updates every screen, and translation and dark mode come for free.
:::
