title: "Practice: find, change, and fix project files"
summary: Six exercises that have you find answers in the project files, rename and version the app, add a footer, test on an old Android version, and repair a broken layout, plus a dark-mode challenge.
---

:::objectives
- Find the file and line behind any visible part of the app.
- Change the app's name, version, and layout through the right files.
- Read Android Studio's error messages and use them to fix broken XML.
- Make the app switch colors in dark mode using a resource qualifier.
:::

All of these use the `Week1Hello` project from the code-along. Try each one before opening the hint, and open the hint before the solution. If you're stuck for more than ten minutes, read the solution, close it, and redo the exercise from memory; that second attempt is where it sticks.

## Warm-up: guess the file

Without opening anything, say which file you'd edit for each change. Then check by opening it.

1.  The app should be called **Pocket C4T** on the home screen.
2.  The greeting should be red.
3.  The app should refuse to install on anything older than Android 8.0.

(Answers: `strings.xml`, `colors.xml` or the layout, and `build.gradle.kts (Module :app)`.)

### Exercise 1: Find it in the project

Find the file and the exact line that answers each question, without searching the web:

1.  What text appears under the app's icon?
2.  Which Activity opens when the icon is tapped?
3.  What's the oldest Android version this app installs on?
4.  Which file says where the ConstraintLayout library comes from, and what's its group name?

:::hint
Questions 1 and 2 both start in the same file, the one that describes the app to Android. For question 4, the app's build file only has a short `libs.` name; follow it to the version catalog.
:::

:::solution
1.  `AndroidManifest.xml` has `android:label="@string/app_name"`, and `res/values/strings.xml` defines `app_name` (for example, `Hello C4T`).
2.  `AndroidManifest.xml`: the `<activity android:name=".MainActivity">` tag, the one containing the `MAIN` action and `LAUNCHER` category.
3.  `build.gradle.kts (Module :app)` has `minSdk = 24`, which is Android 7.0 (Nougat).
4.  `gradle/libs.versions.toml`, in the `[libraries]` section:

```toml
constraintlayout = { group = "androidx.constraintlayout", name = "constraintlayout", version.ref = "constraintlayout" }
```

The group is `androidx.constraintlayout`. The app's build file uses it with `implementation(libs.constraintlayout)`.
:::

### Exercise 2: A name with an apostrophe

Change the name under the icon to **Maya's First App** (with your name). The apostrophe is the catch.

:::hint
Strings in `strings.xml` treat a bare apostrophe as an error. What character goes in front of it?
:::

:::solution
In `strings.xml`:

```xml
    <string name="app_name">Maya\'s First App</string>
```

Without the backslash, Android Studio marks the line as an error. After you run, the new label appears in the app drawer; if the launcher still shows the old one, uninstall the app and run again.
:::

### Exercise 3: Ship version 1.1

Change the app's version to **1.1** so it's ready for a second release. Run it, then find the new version number on the device itself.

:::hint
Two values in `defaultConfig` need to change, and one of them must be a bigger whole number than before. After editing a Gradle file, there's a yellow bar to click.
:::

:::solution
In `build.gradle.kts (Module :app)`, inside `defaultConfig`, raise both values, then click **Sync Now**:

```kotlin
        versionCode = 2
        versionName = "1.1"
```

`versionName` is what people see. `versionCode` has to be larger than the previous release's, or an update won't install over the old version. Run the app, then on the device open **Settings > Apps**, pick the app, and scroll to the bottom of its info page, where the version is listed as 1.1.
:::

### Exercise 4: Add a footer

Add a small white line, **Code 4 Tomorrow, Fall 2026**, centered at the bottom of the screen with 24dp of space below it. Use a string resource, not hardcoded text.

:::hint
A view hugs the bottom when its bottom edge is constrained to the parent's bottom. Centering it horizontally takes two more constraints. Which margin creates the gap?
:::

:::solution
Add the string to `strings.xml`:

```xml
    <string name="footer">Code 4 Tomorrow, Fall 2026</string>
```

Then add this inside the `ConstraintLayout` in `activity_main.xml`, after the subtitle:

```xml
    <TextView
        android:id="@+id/footerText"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_marginBottom="24dp"
        android:text="@string/footer"
        android:textColor="@color/white"
        android:textSize="14sp"
        app:layout_constraintBottom_toBottomOf="parent"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintStart_toStartOf="parent" />
```

The bottom constraint holds it at the bottom, and the start and end constraints center it. The margin only works because there's a bottom constraint for it to push against; a margin on an unconstrained side does nothing.
:::

### Exercise 5: Run on an old Android version

Your app claims to support API 24. Prove it: create a second virtual device with an old system image and run the app on it next to your usual device. If your computer is short on memory, use your phone plus one emulator instead.

:::hint
The system image step in Device Manager filters what it shows. Look for a way to see older API levels. The device dropdown next to Run can target more than one device at once.
:::

:::solution
1.  In **Device Manager**, click **+ > Create Virtual Device**, pick any phone, and on the system image step choose the oldest API level offered for your computer, ideally **API 24**. You may need to change the image filters to see older versions. Download it and click **Finish**.
2.  Start both devices.
3.  In the device dropdown, choose **Select Multiple Devices**, tick both, and click **Run**. Android Studio installs and launches the app on each.

The layout and colors match on both. The status and navigation bars look different because each Android version draws them its own way. If an image were older than your `minSdk`, the install would fail with a message about the device's API level being too low.
:::

### Exercise 6: Fix the broken layout

A classmate's `TextView` won't build, and one line has a quieter problem as well. Find all three issues:

```xml
    <TextView
        android:id="@+id/greetingText"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="@string/greetings"
        android:textSize="32dp"
        android:textColor="@color/c4t_gold"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintTop_toTopOf="parent"
        app:layout_constraintBottom_toBottomOf="parent" >
```

:::hint
Look at the very last character, then compare each `@string/` name with what's in `strings.xml`. The third problem builds fine but Android Studio paints it yellow; it's about units.
:::

:::solution
1.  **The tag is never closed.** It ends with `>` instead of `/>`, so the XML parser thinks everything after it is inside the `TextView`. End the last line with `/>`.
2.  **`@string/greetings` doesn't exist.** The string is named `greeting`. The build fails with `error: resource string/greetings (aka com.example.week1hello:string/greetings) not found.`
3.  **`32dp` should be `32sp`.** This one builds, with a yellow warning. In `dp`, the text ignores the user's font-size setting, which hurts people who need bigger text.

Fixed version:

```xml
    <TextView
        android:id="@+id/greetingText"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="@string/greeting"
        android:textSize="32sp"
        android:textColor="@color/c4t_gold"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintTop_toTopOf="parent"
        app:layout_constraintBottom_toBottomOf="parent" />
```
:::

### Challenge: Dark-mode colors

A phone in dark mode should get a darker, softer version of your colors. Make the app use near-black `#FF121212` for the background and a paler gold `#FFFFD54F` for the greeting when the device is in dark mode, **without changing the layout file at all**.

Android chooses between resource folders using **qualifiers**, suffixes on the folder name. Here's how it picks a color:

```mermaid caption="When the layout asks for @color/c4t_navy, Android checks the most specific folder first"
flowchart TD
    A["Layout asks for @color/c4t_navy"] --> B{Is dark mode on?}
    B -->|yes| C{"Does values-night define c4t_navy?"}
    C -->|yes| D["Use the values-night color"]
    C -->|no| E["Use the values color"]
    B -->|no| E
```

:::hint
You need a second `colors.xml` in a folder whose name ends in `-night`, defining the **same names** with new values. Android Studio's **New > Android Resource File** dialog can add the qualifier for you.
:::

:::solution
1.  Right-click `res` and choose **New > Android Resource File**.
2.  File name: `colors`. Resource type: **Values**. In the qualifiers list, add **Night Mode** and set it to **Night**. The directory name becomes `values-night`.
3.  Put the overrides in it, reusing the same names:

```xml
<?xml version="1.0" encoding="utf-8"?>
<resources>
    <color name="c4t_navy">#FF121212</color>
    <color name="c4t_gold">#FFFFD54F</color>
</resources>
```

Run the app, then turn on **Dark theme** in the device's display settings (the emulator's quick settings panel also has a **Dark theme** tile). The colors switch with no change to `activity_main.xml`, because the layout only refers to names, and Android decides which file each name comes from. `white` isn't overridden, so it falls back to the default `values` folder.
:::
