summary: Six exercises that have you find answers in the project files, change the version and layout, run on more than one device, and fix a broken layout.
---

These exercises all use the `Week1Hello` project from the code-along. Try each one before you open the solution. If you get stuck for more than ten minutes, peek, then close the solution and do it again from memory.

### Exercise 1: Find it in the project

Without searching the web, find the file and the exact line that answers each question:

1.  What text appears under the app's icon on the home screen?
2.  Which Activity opens when the icon is tapped?
3.  What's the oldest Android version this app can be installed on?
4.  Which file says where the ConstraintLayout library comes from, and what is its group name?

:::solution
1.  `AndroidManifest.xml` has `android:label="@string/app_name"`, and `res/values/strings.xml` defines `app_name` (for example, `Hello C4T`).
2.  `AndroidManifest.xml`: the `<activity android:name=".MainActivity">` tag that contains the `MAIN` action and `LAUNCHER` category.
3.  `build.gradle.kts (Module :app)` has `minSdk = 24`, which is Android 7.0 (Nougat).
4.  `gradle/libs.versions.toml`, in the `[libraries]` section:

```toml
constraintlayout = { group = "androidx.constraintlayout", name = "constraintlayout", version.ref = "constraintlayout" }
```

The group is `androidx.constraintlayout`. The app module uses it with `implementation(libs.constraintlayout)`.
:::

### Exercise 2: Ship version 1.1

Change the app's version to **1.1** so it's ready for a second release, run it, and confirm the new version on the device.

:::solution
In `build.gradle.kts (Module :app)`, inside `defaultConfig`, raise both values, then click **Sync Now**:

```kotlin
        versionCode = 2
        versionName = "1.1"
```

`versionName` is what people see; `versionCode` must be a larger whole number than the previous release, or an update won't install over the old version. Run the app, then on the device open **Settings > Apps > Hello C4T** (on some phones, **App info**). The version is listed near the bottom of that page as 1.1.
:::

### Exercise 3: Add a footer

Add a small white line of text, **Code 4 Tomorrow, Fall 2026**, centered at the bottom of the screen with 24dp of space below it. Use a string resource, not hardcoded text.

:::solution
Add the string to `strings.xml`:

```xml
    <string name="footer">Code 4 Tomorrow, Fall 2026</string>
```

Then add this inside the `ConstraintLayout` in `activity_main.xml`, after the subtitle:

```xml
    <TextView
        android:id="@+id/footerText"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_marginBottom="24dp"
        android:text="@string/footer"
        android:textColor="@color/white"
        android:textSize="14sp"
        app:layout_constraintBottom_toBottomOf="parent"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintStart_toStartOf="parent" />
```

Constraining only the bottom edge, plus both sides, holds it at the bottom and centers it horizontally. The margin only works because there is a bottom constraint for it to push against.
:::

### Exercise 4: Run on an old Android version

Your app claims to support API 24. Prove it: create a second virtual device that runs API 24 and run the app on it, alongside your usual device. (If your computer is short on memory, run on your phone and one emulator instead.)

:::solution
1.  In **Device Manager**, click **+ > Create Virtual Device**, pick any phone, and on the system image step choose an **API 24** image. You may need to clear a filter or open another tab of images to find it. Download it and click **Finish**.
2.  Start both devices.
3.  In the device dropdown, choose **Select Multiple Devices...**, tick both, and click **Run**. Android Studio installs and launches the app on each.

The layout and colors should match on both. The system bars at the top and bottom look different, because each Android version draws them its own way. If the app refused to install on API 24, you'd see an error mentioning the device's API level being lower than the app's `minSdk`.
:::

### Exercise 5: Fix the broken layout

A classmate's `TextView` won't build, and one of its lines has a quieter problem too. Find all three issues:

```xml
    <TextView
        android:id="@+id/greetingText"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="@string/greetings"
        android:textSize="32dp"
        android:textColor="@color/c4t_gold"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintTop_toTopOf="parent"
        app:layout_constraintBottom_toBottomOf="parent" >
```

:::solution
1.  **The tag is never closed.** It ends with `>` instead of `/>`, so the XML parser thinks the rest of the file is inside the `TextView`. Change the last line to end with `/>`.
2.  **`@string/greetings` doesn't exist.** The string is named `greeting`. The build fails with `error: resource string/greetings (aka com.example.week1hello:string/greetings) not found.`
3.  **`32dp` should be `32sp`.** This one builds, but Android Studio shows a yellow warning. With `dp`, the text ignores the user's font-size setting, which hurts people who need bigger text.

Fixed version:

```xml
    <TextView
        android:id="@+id/greetingText"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="@string/greeting"
        android:textSize="32sp"
        android:textColor="@color/c4t_gold"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintTop_toTopOf="parent"
        app:layout_constraintBottom_toBottomOf="parent" />
```
:::

### Exercise 6: A name with an apostrophe

Change the app's name under the icon to **Maya's First App** (use your name). Watch out: this name contains an apostrophe.

:::solution
In `strings.xml`:

```xml
    <string name="app_name">Maya\'s First App</string>
```

Without the backslash, Android Studio reports an error on the line. After running, the new label appears in the app drawer. If the launcher still shows the old name, uninstall the app and run it again.
:::

## Stretch challenge: a dark-mode color scheme

Phones in dark mode should get a darker, softer version of your colors. Make the app use near-black `#FF121212` for the background and a paler gold `#FFFFD54F` for the greeting when the device is in dark mode, without changing the layout file at all.

:::solution
Android picks resources from folders with **qualifiers**. A `values-night` folder overrides `values` when dark mode is on.

1.  Right-click `res` and choose **New > Android Resource File**.
2.  File name: `colors`. Resource type: **Values**. In the qualifiers list, add **Night Mode** and set it to **Night**. The directory name becomes `values-night`.
3.  Put the overrides in it, reusing the same names:

```xml
<?xml version="1.0" encoding="utf-8"?>
<resources>
    <color name="c4t_navy">#FF121212</color>
    <color name="c4t_gold">#FFFFD54F</color>
</resources>
```

Run the app, then turn on **Settings > Display > Dark theme** on the device (on an emulator, the quick settings panel has a **Dark theme** tile too). The colors switch without any change to `activity_main.xml`, because the layout only refers to names, and Android chooses which file each name comes from.
:::
