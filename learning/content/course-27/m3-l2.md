Most apps boil down to a list of things, each with a little data and a few rules about it. A to-do app has tasks, a music app has songs, a fitness app has workouts. Today you'll write the plain-Java core of one of these: a habit tracker that records which days you did each habit and prints a weekly report. No Android yet. The point is to get comfortable designing a class and using it, because that's the shape of the code behind an Android screen, and in Week 5 you'll put a list just like this one on a phone.

Here's the design. One `Habit` class holds a habit's data and rules; the `HabitTracker` program creates several and prints the report:

Work in one file named `HabitTracker.java`. After each step, compile and run it with `javac HabitTracker.java` and `java HabitTracker`. Every step below shows the **whole file so far**, with `// new` marking the lines that step adds, and its real output underneath.

## Step 1: A class to hold one habit

A habit has a name, a weekly goal (how many days you want to do it), and a record of the seven days. A `boolean` array fits that record: `daysDone[0]` is Monday, `daysDone[6]` is Sunday, and every slot starts out `false`.

```java run title="HabitTracker.java"
class Habit {
    private String name;
    private int goalPerWeek;
    private boolean[] daysDone = new boolean[7];

    Habit(String name, int goalPerWeek) {
        this.name = name;
        this.goalPerWeek = goalPerWeek;
    }

    @Override
    public String toString() {
        return name + " (goal: " + goalPerWeek + " days)";
    }
}

public class HabitTracker {
    public static void main(String[] args) {
        Habit reading = new Habit("Read 20 minutes", 5);
        System.out.println(reading);
    }
}
```

Two classes share one file. Only `HabitTracker` is `public`, and the file has to be named after it. That's fine for a small program; in an Android project, each class gets its own file.

## Step 2: Record days, safely

Marking a day done means setting one slot to `true`. But what if a bug, or a user, asks for day 9? Here's what an array does with a slot that doesn't exist:

```java run raises title="NoGuard.java"
public class NoGuard {
    public static void main(String[] args) {
        boolean[] daysDone = new boolean[7];
        daysDone[1] = true;
        daysDone[9] = true;
        System.out.println("Marked!");
    }
}
```

`ArrayIndexOutOfBoundsException: Index 9 out of bounds for length 7`, and "Marked!" never prints. In an app, that's a crash. So `markDone` checks the day before touching the array. Add three methods to `Habit` and a test in `main` that makes two mistakes on purpose, marking Tuesday twice and asking for day 9:

```java run title="HabitTracker.java"
class Habit {
    private String name;
    private int goalPerWeek;
    private boolean[] daysDone = new boolean[7];

    Habit(String name, int goalPerWeek) {
        this.name = name;
        this.goalPerWeek = goalPerWeek;
    }

    void markDone(int day) {                                  // new
        if (day < 0 || day >= daysDone.length) {
            System.out.println("Day " + day + " is not a valid day (use 0-6).");
            return;
        }
        daysDone[day] = true;
    }

    int countDone() {                                         // new
        int count = 0;
        for (boolean done : daysDone) {
            if (done) {
                count++;
            }
        }
        return count;
    }

    boolean metGoal() {                                       // new
        return countDone() >= goalPerWeek;
    }

    @Override
    public String toString() {
        return name + " (goal: " + goalPerWeek + " days)";
    }
}

public class HabitTracker {
    public static void main(String[] args) {
        Habit reading = new Habit("Read 20 minutes", 5);
        reading.markDone(0);
        reading.markDone(1);
        reading.markDone(1);                                  // new: Tuesday twice
        reading.markDone(9);                                  // new: not a real day
        System.out.println(reading + ": " + reading.countDone() + " done, goal met? " + reading.metGoal());
    }
}
```

Look at what the class protects you from. Marking Tuesday twice still counts once, because the slot is simply `true` either way. Day 9 gets a polite message instead of a crash, because the guard returns early. And since `daysDone` is `private`, no other code can skip that check by writing into the array directly; the only way in is through `markDone`.

`metGoal()` reuses `countDone()` instead of repeating the counting loop. Small methods that build on each other are easier to test, and a bug fixed in one place is fixed everywhere.

## Step 3: Show the week at a glance

Numbers are fine, but a picture reads faster. Add a list of day names at the top of `Habit`, and two methods that loop over the week:

```java run title="HabitTracker.java"
class Habit {
    private static final String[] DAY_NAMES = {"Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"}; // new

    private String name;
    private int goalPerWeek;
    private boolean[] daysDone = new boolean[7];

    Habit(String name, int goalPerWeek) {
        this.name = name;
        this.goalPerWeek = goalPerWeek;
    }

    void markDone(int day) {
        if (day < 0 || day >= daysDone.length) {
            System.out.println("Day " + day + " is not a valid day (use 0-6).");
            return;
        }
        daysDone[day] = true;
    }

    int countDone() {
        int count = 0;
        for (boolean done : daysDone) {
            if (done) {
                count++;
            }
        }
        return count;
    }

    boolean metGoal() {
        return countDone() >= goalPerWeek;
    }

    String weekBar() {                                        // new
        StringBuilder bar = new StringBuilder();
        for (int i = 0; i < daysDone.length; i++) {
            bar.append(daysDone[i] ? "#" : "-");
        }
        return "[" + bar + "]";
    }

    String missedDays() {                                     // new
        String missed = "";
        for (int i = 0; i < daysDone.length; i++) {
            if (!daysDone[i]) {
                missed += DAY_NAMES[i] + " ";
            }
        }
        return missed.trim();
    }

    @Override
    public String toString() {
        return name + " (goal: " + goalPerWeek + " days)";
    }
}

public class HabitTracker {
    public static void main(String[] args) {
        Habit reading = new Habit("Read 20 minutes", 5);
        reading.markDone(0);
        reading.markDone(1);
        reading.markDone(3);
        System.out.println(reading.weekBar() + " " + reading);
        System.out.println("Missed: " + reading.missedDays());
    }
}
```

Three new pieces of Java:

-   `static final` on `DAY_NAMES`: `static` means one shared copy for every habit (they all use the same day names), and `final` means it can't be swapped for a different array.
-   `condition ? a : b` is the **ternary operator**, a one-line if/else that picks a value. `daysDone[i] ? "#" : "-"` gives `#` for a done day and `-` otherwise.
-   `StringBuilder` builds text piece by piece. For seven characters, `+=` would work just as well, but you'll meet `StringBuilder` all over real Java code.

Both loops count with `i` instead of using for-each, because they need the **position** (which day) and not just the value.

## Step 4: Track several habits with an ArrayList

An array has a fixed size, but people add and remove habits. An `ArrayList` grows as you add to it. Put `import java.util.ArrayList;` at the very top of the file and replace `main`. Here's the finished program:

```java run title="HabitTracker.java"
import java.util.ArrayList;                                   // new

class Habit {
    private static final String[] DAY_NAMES = {"Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"};

    private String name;
    private int goalPerWeek;
    private boolean[] daysDone = new boolean[7];

    Habit(String name, int goalPerWeek) {
        this.name = name;
        this.goalPerWeek = goalPerWeek;
    }

    void markDone(int day) {
        if (day < 0 || day >= daysDone.length) {
            System.out.println("Day " + day + " is not a valid day (use 0-6).");
            return;
        }
        daysDone[day] = true;
    }

    int countDone() {
        int count = 0;
        for (boolean done : daysDone) {
            if (done) {
                count++;
            }
        }
        return count;
    }

    boolean metGoal() {
        return countDone() >= goalPerWeek;
    }

    String weekBar() {
        StringBuilder bar = new StringBuilder();
        for (int i = 0; i < daysDone.length; i++) {
            bar.append(daysDone[i] ? "#" : "-");
        }
        return "[" + bar + "]";
    }

    String missedDays() {
        String missed = "";
        for (int i = 0; i < daysDone.length; i++) {
            if (!daysDone[i]) {
                missed += DAY_NAMES[i] + " ";
            }
        }
        return missed.trim();
    }

    @Override
    public String toString() {
        return name + " (goal: " + goalPerWeek + " days)";
    }
}

public class HabitTracker {
    public static void main(String[] args) {
        ArrayList<Habit> habits = new ArrayList<>();          // new from here down
        habits.add(new Habit("Read 20 minutes", 5));
        habits.add(new Habit("Practice Java", 3));
        habits.add(new Habit("Walk outside", 4));

        int[] readingDays = {0, 1, 2, 3, 5};
        for (int day : readingDays) {
            habits.get(0).markDone(day);
        }
        habits.get(1).markDone(1);
        habits.get(1).markDone(4);
        int[] walkingDays = {0, 2, 4, 6};
        for (int day : walkingDays) {
            habits.get(2).markDone(day);
        }

        System.out.println("Weekly habit report");
        System.out.println("-------------------");
        int goalsMet = 0;
        Habit best = habits.get(0);
        for (Habit habit : habits) {
            String status = habit.metGoal() ? "goal met" : "keep going";
            System.out.println(habit.weekBar() + " " + habit + ": " + status);
            if (habit.metGoal()) {
                goalsMet++;
            } else {
                System.out.println("    missed: " + habit.missedDays());
            }
            if (habit.countDone() > best.countDone()) {
                best = habit;
            }
        }
        System.out.println();
        System.out.println("Goals met: " + goalsMet + " of " + habits.size());
        System.out.println("Most consistent: " + best);
    }
}
```

What to notice in the new `main`:

-   `ArrayList<Habit>` holds only `Habit` objects; the compiler rejects anything else. The empty `<>` on the right lets Java fill in the type.
-   `ArrayList` uses methods where arrays use brackets: `add()` to put something in, `get(0)` instead of `[0]`, and `size()` instead of `.length`.
-   The "find the best" loop is a pattern worth memorizing: assume the first item is best, then replace it whenever you meet a better one. Because the test is `>` and not `>=`, a tie keeps the habit that came first.

:::warning
An `ArrayList` can't hold basic types like `int` directly. Write `ArrayList<Integer>`, not `ArrayList<int>`, which fails with `unexpected type`. Java converts between `int` and `Integer` for you when you add and get values.
:::

## How this connects to Android

In Week 5 you'll show a scrolling list on a phone, and the code behind it has this exact shape: a model class like `Habit`, an `ArrayList` of those objects, and a loop-like piece of code that turns each object into a row on screen.

:::quiz
Q: Why is `daysDone` declared `private`?
- [ ] So the array uses less memory
  `private` changes who can see a field, not how big it is.
- [x] So every change has to go through `markDone`, which checks the day first
  Code outside the class can't write `daysDone[9] = true` and skip the guard.
- [ ] Because arrays must always be private in Java
  Arrays can be public; it's a design choice, and here a good one.

Q: After `markDone(1)` runs twice and `markDone(9)` once, what does `countDone()` return if nothing else was marked?
- [x] `1`
  Tuesday's slot is just `true` twice, and day 9 is rejected by the guard.
- [ ] `2`
  Marking a day again doesn't add a second check mark; the slot is a `boolean`, not a counter.
- [ ] `3`
  Day 9 never reaches the array.

Q: Why does `main` keep the habits in an `ArrayList<Habit>` instead of a `Habit[]` array?
- [ ] Arrays can't hold objects
  Arrays can hold objects; `Habit[]` would compile.
- [x] An `ArrayList` can grow and shrink as the user adds or deletes habits
  An array's size is fixed when it's created.
- [ ] `ArrayList` sorts its items automatically
  It keeps them in the order you added them.
:::

:::takeaways
- Keep a class's data `private` and change it only through methods that check their inputs.
- Build small methods on top of each other, like `metGoal()` using `countDone()`.
- Loop with an index when you need positions, and with for-each when you only need values.
- `ArrayList` grows as you `add()`, and uses `get(i)` and `size()` instead of `[i]` and `.length`.
- To find the best item, start with the first one and replace it whenever a later one beats it.
:::

## Ideas to extend it

-   Add `void unmark(int day)` with the same guard as `markDone`.
-   Add `int percentDone()` that returns how much of the goal is complete, capped at 100. Watch out for integer division.
-   Add `int longestStreak()` that finds the most consecutive days done in a row.
-   Let `main` remove a habit with `habits.remove(1)` and print the report again.
