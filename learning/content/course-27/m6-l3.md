All of these build on the Planet Facts app from the code-along, so open that project first. Solutions show only the code that changes. If you get stuck, reread the four pieces of a RecyclerView in the notes: most bugs here come from one of them.

### Exercise 1: A count header

Add a `TextView` above the list that says `8 planets`. Get the number from the list itself, not by typing 8.

Hint: a `FrameLayout` stacks children on top of each other. Switch the root to a vertical `LinearLayout` and give the RecyclerView `layout_height="0dp"` with `layout_weight="1"` so it fills the leftover space.

:::solution
`activity_main.xml`:

```xml
<?xml version="1.0" encoding="utf-8"?>
<LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools"
    android:id="@+id/main"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical"
    tools:context=".MainActivity">

    <TextView
        android:id="@+id/count_header"
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:padding="16dp"
        android:textSize="16sp" />

    <androidx.recyclerview.widget.RecyclerView
        android:id="@+id/planet_list"
        android:layout_width="match_parent"
        android:layout_height="0dp"
        android:layout_weight="1" />

</LinearLayout>
```

In `onCreate`:

```java
List<Planet> planets = makePlanets();
TextView countHeader = findViewById(R.id.count_header);
countHeader.setText(planets.size() + " planets");
planetList.setAdapter(new PlanetAdapter(planets, this::openDetail));
```

The top of the screen now reads:

```text
8 planets
```
:::

### Exercise 2: Highlight Earth (and meet a recycling bug)

Make Earth's name green. First try it **only** with an `if` and no `else`, then rotate to landscape (so fewer rows fit) and scroll up and down a few times. What goes wrong? Fix it.

:::solution
Add two colors to `res/values/colors.xml`:

```xml
<color name="planet_home">#FF2E7D32</color>
<color name="planet_normal">#FF212121</color>
```

The buggy version:

```java
if (planet.getName().equals("Earth")) {
    holder.nameText.setTextColor(ContextCompat.getColor(holder.itemView.getContext(), R.color.planet_home));
}
```

After scrolling, other planets turn green too. The row view that showed Earth gets **recycled** for, say, Neptune, and nothing ever set its color back. The rule: if `onBindViewHolder` changes something for some items, it must set it for every item.

```java
int color = planet.getName().equals("Earth") ? R.color.planet_home : R.color.planet_normal;
holder.nameText.setTextColor(ContextCompat.getColor(holder.itemView.getContext(), color));
```

Import `androidx.core.content.ContextCompat`. If your phone is in dark mode, `#FF212121` is hard to read on the dark background; add a lighter `planet_normal` in `res/values-night/colors.xml` and Android picks it automatically.
:::

### Exercise 3: Long-press for a quick fact

A normal tap still opens the detail screen. A long press on a row should show the fact in a Toast instead.

:::solution
In `onBindViewHolder`:

```java
holder.itemView.setOnLongClickListener(v -> {
    Toast.makeText(v.getContext(), planet.getFact(), Toast.LENGTH_LONG).show();
    return true;
});
```

Returning `true` says "I handled this," so the long press doesn't also count as a normal click. The adapter isn't an Activity, so it borrows a `Context` from the view with `v.getContext()`. Import `android.widget.Toast`.
:::

### Exercise 4: Add a planet at runtime

Add a Button below the list labeled "Add Pluto". Tapping it adds `new Planet("Pluto", 9, "A dwarf planet since 2006.")`, updates the header, scrolls to the new row, and then disables the button so Pluto can't be added twice.

:::solution
Keep the list and adapter in fields so the click listener can reach them:

```java
private List<Planet> planets;
private PlanetAdapter adapter;
```

In `onCreate` (after finding `planetList` and `countHeader`, and adding a Button with id `add_button` to the layout):

```java
planets = makePlanets();
adapter = new PlanetAdapter(planets, this::openDetail);
planetList.setAdapter(adapter);
countHeader.setText(planets.size() + " planets");

Button addButton = findViewById(R.id.add_button);
addButton.setOnClickListener(v -> {
    planets.add(new Planet("Pluto", 9, "A dwarf planet since 2006."));
    int newPosition = planets.size() - 1;
    adapter.notifyItemInserted(newPosition);
    planetList.scrollToPosition(newPosition);
    countHeader.setText(planets.size() + " planets");
    addButton.setEnabled(false);
});
```

`planetList` must be effectively final to use inside the lambda; it is, as long as you don't assign it twice. The header now reads `9 planets`. Without `notifyItemInserted`, the list wouldn't show Pluto until something else forced a redraw.
:::

### Exercise 5: Share a fact

On the detail screen, add a "Share" button that opens Android's share sheet with text like `Mars: Home to Olympus Mons, the tallest volcano in the solar system.`

This uses an **implicit** Intent: instead of naming an Activity, you describe an action and let Android offer every app that can handle it.

:::solution
In `DetailActivity.onCreate`, after reading the extras and adding a Button with id `share_button` to the layout:

```java
final String shareText = name + ": " + fact;
Button shareButton = findViewById(R.id.share_button);
shareButton.setOnClickListener(v -> {
    Intent send = new Intent(Intent.ACTION_SEND);
    send.setType("text/plain");
    send.putExtra(Intent.EXTRA_TEXT, shareText);
    startActivity(Intent.createChooser(send, "Share this fact"));
});
```

`name` and `fact` were reassigned by the `null` checks, so they aren't effectively final; copying them into `shareText` fixes the "variable used in lambda should be final" error. No manifest change is needed, since you're asking *other* apps to do the work.
:::

## Stretch challenge: delete with a long press

Replace the long-press Toast from Exercise 3 with a delete: long-pressing a row removes that planet from the list with an animation and updates the header.

Hints: the adapter needs a second callback, and the `position` parameter of `onBindViewHolder` can be stale by the time the user long-presses. Ask the holder for its current position instead.

:::solution
In `PlanetAdapter`, add a second interface and field:

```java
public interface OnPlanetLongClickListener {
    void onPlanetLongClick(int position);
}

private final OnPlanetLongClickListener longListener;

public PlanetAdapter(List<Planet> planets, OnPlanetClickListener listener,
                     OnPlanetLongClickListener longListener) {
    this.planets = planets;
    this.listener = listener;
    this.longListener = longListener;
}
```

In `onBindViewHolder`:

```java
holder.itemView.setOnLongClickListener(v -> {
    int current = holder.getBindingAdapterPosition();
    if (current != RecyclerView.NO_POSITION) {
        longListener.onPlanetLongClick(current);
    }
    return true;
});
```

In `MainActivity`:

```java
adapter = new PlanetAdapter(planets, this::openDetail, position -> {
    Planet removed = planets.remove(position);
    adapter.notifyItemRemoved(position);
    countHeader.setText(planets.size() + " planets");
    Toast.makeText(this, "Removed " + removed.getName(), Toast.LENGTH_SHORT).show();
});
```

Make `countHeader` a field too, since the lambda now runs long after `onCreate`. Why `getBindingAdapterPosition()`? After you delete Mercury, every row below it moves up one, but rows that didn't need rebinding still remember their old `position`. Asking the holder gives the real, current position. (It needs RecyclerView 1.2.0 or newer, which is why you added the dependency yourself.)
:::
