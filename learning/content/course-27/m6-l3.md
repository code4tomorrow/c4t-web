title: "Practice: grids, recycling bugs, live updates, and sharing a fact"
summary: Extend the Planet Facts app with a count header, a grid, recycling-safe highlights, runtime additions, and a share button, then delete rows with a long press as a challenge.
---

:::objectives
- Change how a RecyclerView looks and behaves without rewriting the adapter.
- Find and fix the classic recycling bug in `onBindViewHolder`.
- Update a list at runtime and tell the adapter exactly what changed.
- Hand work to other apps with an implicit Intent.
:::

Every exercise builds on the Planet Facts app from the code-along, so open that project first. Solutions show only the code that changes. When you're stuck, go back to the four pieces of a RecyclerView (row layout, ViewHolder, Adapter, LayoutManager): almost every bug here lives in exactly one of them, and naming which one is half the fix.

**Warm-up.** In `PlanetAdapter`, temporarily make `getItemCount()` return `3`. Before you run it, predict what the list shows. (Only Mercury, Venus, and Earth: RecyclerView never asks for a position past the count, so the other five planets are never bound.) Put it back to `planets.size()`.

### Exercise 1: A count header

Add a `TextView` above the list that reads:

```text
8 planets
```

Get the number from the list itself, not by typing 8, so it stays right when planets are added later.

:::hint
A `FrameLayout` stacks children on top of each other, so the header would sit over the first row. Switch the root to a vertical `LinearLayout`, and give the RecyclerView `layout_height="0dp"` with `layout_weight="1"` so it fills whatever space the header leaves.
:::

:::solution
`activity_main.xml`:

```xml
<?xml version="1.0" encoding="utf-8"?>
<LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools"
    android:id="@+id/main"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical"
    tools:context=".MainActivity">

    <TextView
        android:id="@+id/count_header"
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:padding="16dp"
        android:textSize="16sp" />

    <androidx.recyclerview.widget.RecyclerView
        android:id="@+id/planet_list"
        android:layout_width="match_parent"
        android:layout_height="0dp"
        android:layout_weight="1" />

</LinearLayout>
```

In `onCreate`, keep the list in a variable so you can both count it and hand it to the adapter:

```java
List<Planet> planets = makePlanets();
TextView countHeader = findViewById(R.id.count_header);
countHeader.setText(planets.size() + " planets");
planetList.setAdapter(new PlanetAdapter(planets, this::openDetail));
```

Import `android.widget.TextView`.
:::

### Exercise 2: Two columns

Show the planets in a grid, two per row, without touching the adapter or the row layout. On a phone held upright you should see Mercury and Venus side by side at the top, then Earth and Mars.

:::hint
Only one of the four pieces decides where rows go, and it's not the adapter.
:::

:::solution
Swap the LayoutManager in `onCreate`:

```java
planetList.setLayoutManager(new GridLayoutManager(this, 2));
```

Import `androidx.recyclerview.widget.GridLayoutManager`. That's the whole change. The adapter still makes and fills rows; it never knew or cared where they were placed. That separation is why RecyclerView splits the work into four pieces. Switch back to `LinearLayoutManager` before the next exercise, or keep the grid if you like it.
:::

### Exercise 3: Highlight Earth (and meet a recycling bug)

Make Earth's name green. First write it with an `if` and **no** `else`. Then rotate to landscape (so fewer rows fit and more get recycled) and scroll up and down several times. What goes wrong? Fix it.

:::hint
A row view that once showed Earth gets reused for another planet. Ask yourself: when that happens, which line of code sets its color back?
:::

:::solution
Add two colors to `res/values/colors.xml`:

```xml
<color name="planet_home">#FF2E7D32</color>
<color name="planet_normal">#FF212121</color>
```

The buggy version:

```java
if (planet.getName().equals("Earth")) {
    holder.nameText.setTextColor(ContextCompat.getColor(holder.itemView.getContext(), R.color.planet_home));
}
```

After some scrolling, other planets turn green too. The row view that showed Earth is **recycled** for, say, Neptune, and no line of code ever sets its color back. The rule that prevents this whole family of bugs: if `onBindViewHolder` changes something for some items, it must set it for **every** item.

```java
int color = planet.getName().equals("Earth") ? R.color.planet_home : R.color.planet_normal;
holder.nameText.setTextColor(ContextCompat.getColor(holder.itemView.getContext(), color));
```

Import `androidx.core.content.ContextCompat`. In dark mode, `#FF212121` is hard to read on a dark background; add a lighter `planet_normal` to `res/values-night/colors.xml` and Android picks it automatically.
:::

### Exercise 4: Long-press for a quick fact

A normal tap should still open the detail screen. A long press on a row should show that planet's fact in a Toast instead, without opening anything.

:::hint
Views have a `setOnLongClickListener` that works much like `setOnClickListener`, except the lambda must return a `boolean`. The adapter isn't an Activity, so borrow a `Context` from the view.
:::

:::solution
In `onBindViewHolder`:

```java
holder.itemView.setOnLongClickListener(v -> {
    Toast.makeText(v.getContext(), planet.getFact(), Toast.LENGTH_LONG).show();
    return true;
});
```

Returning `true` means "I handled this," so the long press doesn't also count as a normal click. `v.getContext()` gives you the Activity the row lives in, which is all `Toast.makeText` needs. Import `android.widget.Toast`.
:::

### Exercise 5: Add a planet at runtime

Add a Button below the list labeled **Add Pluto**. Tapping it adds `new Planet("Pluto", 9, "A dwarf planet since 2006.")`, scrolls to the new row, updates the header, and disables the button so Pluto can't be added twice. Afterwards the header reads:

```text
9 planets
```

:::hint
The click listener needs to reach the list and the adapter long after `onCreate` finishes, so promote them to fields. Adding to the list isn't enough on its own: the adapter has to hear which position is new.
:::

:::solution
Fields at the top of `MainActivity`:

```java
private List<Planet> planets;
private PlanetAdapter adapter;
```

In `onCreate`, after finding `planetList` and `countHeader` (and adding a Button with id `add_button` below the RecyclerView in the layout):

```java
planets = makePlanets();
adapter = new PlanetAdapter(planets, this::openDetail);
planetList.setAdapter(adapter);
countHeader.setText(planets.size() + " planets");

Button addButton = findViewById(R.id.add_button);
addButton.setOnClickListener(v -> {
    planets.add(new Planet("Pluto", 9, "A dwarf planet since 2006."));
    int newPosition = planets.size() - 1;
    adapter.notifyItemInserted(newPosition);
    planetList.scrollToPosition(newPosition);
    countHeader.setText(planets.size() + " planets");
    v.setEnabled(false);
});
```

`v` is the view that was clicked, the button itself, so `v.setEnabled(false)` greys it out. Without `notifyItemInserted`, Pluto would be in the list but not on screen until something forced a redraw. Rotate after adding Pluto and it disappears, because `onCreate` rebuilds the list from `makePlanets()`. Keeping it would take a Bundle (last week) or saved storage (next week).
:::

### Exercise 6: Share a fact

On the detail screen, add a **Share** button that opens Android's share sheet with text like:

```text
Mars: Home to Olympus Mons, the tallest volcano in the solar system.
```

This needs an **implicit** Intent. Instead of naming an Activity, you describe an action ("send some text") and Android offers every app on the phone that can do it.

:::hint
The action is `Intent.ACTION_SEND`, the type is `"text/plain"`, and the text goes in the extra `Intent.EXTRA_TEXT`. Wrap the Intent in `Intent.createChooser(...)` to get the share sheet. If Java complains a variable "should be final or effectively final," look at what happened to `name` and `fact` earlier in `onCreate`.
:::

:::solution
In `DetailActivity.onCreate`, after reading the extras and adding a Button with id `share_button` to the layout:

```java
final String shareText = name + ": " + fact;
Button shareButton = findViewById(R.id.share_button);
shareButton.setOnClickListener(v -> {
    Intent send = new Intent(Intent.ACTION_SEND);
    send.setType("text/plain");
    send.putExtra(Intent.EXTRA_TEXT, shareText);
    startActivity(Intent.createChooser(send, "Share this fact"));
});
```

`name` and `fact` were reassigned by the `null` checks, so they aren't effectively final, and a lambda can't use them. Copying them into a new `shareText` variable that's never reassigned fixes it. No manifest change is needed, because you're asking *other* apps to do the work. On the emulator the share sheet may offer only a few apps, like Messages or Gmail; a real phone shows many more.
:::

### Challenge: delete with a long press

Replace the long-press Toast from Exercise 4 with a delete: long-pressing a row removes that planet with an animation and updates the header. Delete Mercury, then long-press Venus. Venus must be the one that disappears.

:::hint
The adapter needs a second callback that reports a position, and `MainActivity` does the removing. Watch out: the `position` parameter of `onBindViewHolder` is the position when the row was **bound**, which may be out of date by the time someone long-presses. The holder can tell you its current position.
:::

:::solution
In `PlanetAdapter`, add a second interface, a field, and a third constructor parameter:

```java
public interface OnPlanetLongClickListener {
    void onPlanetLongClick(int position);
}

private final OnPlanetLongClickListener longListener;

public PlanetAdapter(List<Planet> planets, OnPlanetClickListener listener,
                     OnPlanetLongClickListener longListener) {
    this.planets = planets;
    this.listener = listener;
    this.longListener = longListener;
}
```

In `onBindViewHolder`, replace the Toast long-press:

```java
holder.itemView.setOnLongClickListener(v -> {
    int current = holder.getBindingAdapterPosition();
    if (current != RecyclerView.NO_POSITION) {
        longListener.onPlanetLongClick(current);
    }
    return true;
});
```

In `MainActivity`, make `countHeader` a field too, since this code now runs long after `onCreate`:

```java
adapter = new PlanetAdapter(planets, this::openDetail, position -> {
    Planet removed = planets.remove(position);
    adapter.notifyItemRemoved(position);
    countHeader.setText(planets.size() + " planets");
    Toast.makeText(this, "Removed " + removed.getName(), Toast.LENGTH_SHORT).show();
});
```

Why `getBindingAdapterPosition()`? After Mercury is deleted, every row below slides up one place, but `notifyItemRemoved` doesn't rebind rows that didn't change. The Venus row still remembers `position = 1` from when it was bound, even though Venus is now at 0. Using that stale number would delete Earth. Asking the holder gives the real, current position. (This method arrived in RecyclerView 1.2.0, one more reason you added version 1.4.0 yourself instead of relying on the older copy Material brings along.)
:::
