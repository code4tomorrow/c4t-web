title: "Code-along: Planet Facts, a list that opens a detail screen"
summary: Build a two-screen app where tapping a planet in a scrolling RecyclerView opens a detail screen that receives the planet's data through Intent extras.
---

:::objectives
- Write a model class to hold one list item's data.
- Build an adapter that reports taps through a small interface instead of opening screens itself.
- Create a second Activity and send it three values with Intent extras.
- Use constants for extra keys so the two screens can't disagree.
:::

Eight planets, one list, one detail page. It's small enough to finish in one class, and it uses every piece of the list-to-detail pattern you'll reuse in your capstone: a model class, an adapter with a click callback, a second Activity, and Intent extras. Here are the two screens you'll have at the end:

```text
List screen                      Detail screen (after tapping Mars)
+----------------------------+   +------------------------------------+
| Mercury                    |   | Mars                               |
| Planet #1 from the Sun     |   | Planet #4 from the Sun             |
| Venus                      |   |                                    |
| Planet #2 from the Sun     |   | Home to Olympus Mons, the tallest  |
| ...                        |   | volcano in the solar system.       |
| Neptune                    |   |                                    |
| Planet #8 from the Sun     |   | [ BACK TO LIST ]                   |
+----------------------------+   +------------------------------------+
```

The interesting part is the trip a tap takes. The row is inside the adapter, but the screen change belongs to `MainActivity`, so the tap gets passed along like this:

```mermaid caption="The path of one tap, from the Mars row to the detail screen"
sequenceDiagram
    actor User
    participant Row as Mars row (adapter)
    participant Main as MainActivity
    participant Android
    participant Detail as DetailActivity
    User->>Row: taps the row
    Row->>Main: listener.onPlanetClick(mars)
    Main->>Main: openDetail(mars) builds an Intent with 3 extras
    Main->>Android: startActivity(intent)
    Android->>Detail: onCreate
    Detail->>Detail: reads name, order, and fact from the extras
```

## Step 1: Project setup

Create a new **Empty Views Activity** project named **Planet Facts**, package `com.example.planetfacts`, Java, minimum SDK API 24.

Open `gradle/libs.versions.toml`. Under the `[versions]` header that's already there, add `recyclerview = "1.4.0"`. Under the existing `[libraries]` header, add the library line:

```toml
[versions]
recyclerview = "1.4.0"

[libraries]
recyclerview = { group = "androidx.recyclerview", name = "recyclerview", version.ref = "recyclerview" }
```

Then in `app/build.gradle.kts`, inside `dependencies { }`, add `implementation(libs.recyclerview)` and click **Sync Now**. Run the empty app once. If it launches, the library is in and you have a clean starting point.

## Step 2: The model class

A **model class** holds the data for one item. It knows nothing about screens or Android; it's just Java. Right-click the `com.example.planetfacts` package, choose **New > Java Class**, and name it `Planet`:

```java
package com.example.planetfacts;

public class Planet {
    private final String name;
    private final int order;
    private final String fact;

    public Planet(String name, int order, String fact) {
        this.name = name;
        this.order = order;
        this.fact = fact;
    }

    public String getName() {
        return name;
    }

    public int getOrder() {
        return order;
    }

    public String getFact() {
        return fact;
    }
}
```

The fields are `final` because a planet's data doesn't change after you create it. Because this is plain Java, you can check it right here before Android is involved. This test program carries its own copy of `Planet` at the bottom (without the `package` line) so it runs on its own. Before running, predict the position number printed next to Earth.

```java run title="PlanetCheck.java"
import java.util.ArrayList;
import java.util.List;

public class PlanetCheck {
    public static void main(String[] args) {
        List<Planet> planets = new ArrayList<>();
        planets.add(new Planet("Mercury", 1, "The closest planet to the Sun."));
        planets.add(new Planet("Venus", 2, "The hottest planet, thanks to its thick clouds."));
        planets.add(new Planet("Earth", 3, "The only planet known to have life."));
        for (int i = 0; i < planets.size(); i++) {
            Planet p = planets.get(i);
            System.out.println("position " + i + ": " + p.getName() + " (#" + p.getOrder() + " from the Sun)");
        }
        System.out.println("getItemCount() would return " + planets.size());
    }
}

class Planet {
    private final String name;
    private final int order;
    private final String fact;

    Planet(String name, int order, String fact) {
        this.name = name;
        this.order = order;
        this.fact = fact;
    }

    String getName() { return name; }
    int getOrder() { return order; }
    String getFact() { return fact; }
}
```

Earth is at position 2 but is planet #3. List positions start at 0 and planet order starts at 1. Mixing them up is the classic off-by-one bug in list apps, which is exactly why the order is stored as its own field instead of being worked out from the position.

## Step 3: The row layout

```xml
    android:orientation="vertical"

    <TextView
        android:id="@+id/planet_name"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:textSize="20sp"
        android:textStyle="bold" />

    <TextView
        android:id="@+id/planet_order"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content" />

</LinearLayout>
```

`?attr/selectableItemBackground` borrows the theme's ripple effect, so a row flashes when tapped. Without some feedback like that, users can't tell a row is clickable.

## Step 4: The adapter, with a click callback

Who should open the detail screen? Not the adapter. Its job is turning planets into rows, and if it also started Activities, you couldn't reuse it on a screen that does something else on tap. Think of a waiter: they take your order to the kitchen, but they don't cook it.

So the adapter defines a tiny **interface**, a promise of one method, and calls it when a row is tapped. Whoever creates the adapter decides what that method does. Create `PlanetAdapter.java`:

```java
package com.example.planetfacts;

import android.view.LayoutInflater;
import android.view.View;
import android.view.ViewGroup;
import android.widget.TextView;

import androidx.annotation.NonNull;
import androidx.recyclerview.widget.RecyclerView;

import java.util.List;

public class PlanetAdapter extends RecyclerView.Adapter<PlanetAdapter.PlanetViewHolder> {

    public interface OnPlanetClickListener {
        void onPlanetClick(Planet planet);
    }

    private final List<Planet> planets;
    private final OnPlanetClickListener listener;

    public PlanetAdapter(List<Planet> planets, OnPlanetClickListener listener) {
        this.planets = planets;
        this.listener = listener;
    }

    @NonNull
    @Override
    public PlanetViewHolder onCreateViewHolder(@NonNull ViewGroup parent, int viewType) {
        View row = LayoutInflater.from(parent.getContext())
                .inflate(R.layout.item_planet, parent, false);
        return new PlanetViewHolder(row);
    }

    @Override
    public void onBindViewHolder(@NonNull PlanetViewHolder holder, int position) {
        Planet planet = planets.get(position);
        holder.nameText.setText(planet.getName());
        holder.orderText.setText("Planet #" + planet.getOrder() + " from the Sun");
        holder.itemView.setOnClickListener(v -> listener.onPlanetClick(planet));
    }

    @Override
    public int getItemCount() {
        return planets.size();
    }

    public static class PlanetViewHolder extends RecyclerView.ViewHolder {
        final TextView nameText;
        final TextView orderText;

        public PlanetViewHolder(@NonNull View itemView) {
            super(itemView);
            nameText = itemView.findViewById(R.id.planet_name);
            orderText = itemView.findViewById(R.id.planet_order);
        }
    }
}
```

Two details in `onBindViewHolder` are worth a second look. `holder.itemView` is the whole row, so the click listener covers the entire row, not just the bold name. And the listener is set again every time a row is bound. That's on purpose: a recycled row that used to show Venus must now report Mars when tapped, so it needs a fresh listener for its new planet.

What to watch for: the interface inside the adapter and how the Activity supplies the code that runs on a tap. It's the same idea as Step 4. The recording is older, so its imports use `android.support` names where you have `androidx`.
:::

## Step 5: The detail screen

Choose **File > New > Activity > Empty Views Activity**, name it `DetailActivity`, and keep Java selected. Android Studio declares it in `AndroidManifest.xml` for you. Open the manifest and check that this is inside `<application>`:

Replace `DetailActivity.java`:

```java
package com.example.planetfacts;

import android.content.Intent;
import android.os.Bundle;
import android.widget.Button;
import android.widget.TextView;

import androidx.activity.EdgeToEdge;
import androidx.appcompat.app.AppCompatActivity;
import androidx.core.graphics.Insets;
import androidx.core.view.ViewCompat;
import androidx.core.view.WindowInsetsCompat;

public class DetailActivity extends AppCompatActivity {

    public static final String EXTRA_NAME = "com.example.planetfacts.NAME";
    public static final String EXTRA_ORDER = "com.example.planetfacts.ORDER";
    public static final String EXTRA_FACT = "com.example.planetfacts.FACT";

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        EdgeToEdge.enable(this);
        setContentView(R.layout.activity_detail);
        ViewCompat.setOnApplyWindowInsetsListener(findViewById(R.id.main), (v, insets) -> {
            Insets systemBars = insets.getInsets(WindowInsetsCompat.Type.systemBars());
            v.setPadding(systemBars.left, systemBars.top, systemBars.right, systemBars.bottom);
            return insets;
        });

        Intent intent = getIntent();
        String name = intent.getStringExtra(EXTRA_NAME);
        int order = intent.getIntExtra(EXTRA_ORDER, 0);
        String fact = intent.getStringExtra(EXTRA_FACT);

        if (name == null) {
            name = "Unknown planet";
        }
        if (fact == null) {
            fact = "";
        }

        TextView nameText = findViewById(R.id.detail_name);
        TextView orderText = findViewById(R.id.detail_order);
        TextView factText = findViewById(R.id.detail_fact);
        nameText.setText(name);
        orderText.setText("Planet #" + order + " from the Sun");
        factText.setText(fact);

        Button backButton = findViewById(R.id.back_button);
        backButton.setOnClickListener(v -> finish());
    }
}
```

The three `EXTRA_` constants are the contract between the two screens. They live in `DetailActivity` because it's the screen that needs them; any screen that wants to open it uses `DetailActivity.EXTRA_NAME` and can't misspell the key. Prefixing keys with your package name keeps them from clashing with keys from libraries.

## Step 6: The list screen

Replace `activity_main.xml`. A `FrameLayout` is enough here, since the list is the only thing on the screen:

```xml
<?xml version="1.0" encoding="utf-8"?>
<FrameLayout xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools"
    android:id="@+id/main"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    tools:context=".MainActivity">

    <androidx.recyclerview.widget.RecyclerView
        android:id="@+id/planet_list"
        android:layout_width="match_parent"
        android:layout_height="match_parent" />

</FrameLayout>
```

Replace `MainActivity.java`:

```java
package com.example.planetfacts;

import android.content.Intent;
import android.os.Bundle;

import androidx.activity.EdgeToEdge;
import androidx.appcompat.app.AppCompatActivity;
import androidx.core.graphics.Insets;
import androidx.core.view.ViewCompat;
import androidx.core.view.WindowInsetsCompat;
import androidx.recyclerview.widget.LinearLayoutManager;
import androidx.recyclerview.widget.RecyclerView;

import java.util.ArrayList;
import java.util.List;

public class MainActivity extends AppCompatActivity {

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        EdgeToEdge.enable(this);
        setContentView(R.layout.activity_main);
        ViewCompat.setOnApplyWindowInsetsListener(findViewById(R.id.main), (v, insets) -> {
            Insets systemBars = insets.getInsets(WindowInsetsCompat.Type.systemBars());
            v.setPadding(systemBars.left, systemBars.top, systemBars.right, systemBars.bottom);
            return insets;
        });

        RecyclerView planetList = findViewById(R.id.planet_list);
        planetList.setLayoutManager(new LinearLayoutManager(this));
        planetList.setAdapter(new PlanetAdapter(makePlanets(), this::openDetail));
    }

    private void openDetail(Planet planet) {
        Intent intent = new Intent(this, DetailActivity.class);
        intent.putExtra(DetailActivity.EXTRA_NAME, planet.getName());
        intent.putExtra(DetailActivity.EXTRA_ORDER, planet.getOrder());
        intent.putExtra(DetailActivity.EXTRA_FACT, planet.getFact());
        startActivity(intent);
    }

    private List<Planet> makePlanets() {
        List<Planet> planets = new ArrayList<>();
        planets.add(new Planet("Mercury", 1, "The closest planet to the Sun."));
        planets.add(new Planet("Venus", 2, "The hottest planet, thanks to its thick clouds."));
        planets.add(new Planet("Earth", 3, "The only planet known to have life."));
        planets.add(new Planet("Mars", 4, "Home to Olympus Mons, the tallest volcano in the solar system."));
        planets.add(new Planet("Jupiter", 5, "The largest planet in the solar system."));
        planets.add(new Planet("Saturn", 6, "The least dense planet; on average it is less dense than water."));
        planets.add(new Planet("Uranus", 7, "It spins tipped over on its side."));
        planets.add(new Planet("Neptune", 8, "It has the fastest winds of any planet."));
        return planets;
    }
}
```

`this::openDetail` is a **method reference**, shorthand for the lambda `planet -> openDetail(planet)`. Java accepts it as an `OnPlanetClickListener` because `openDetail` has the same shape as `onPlanetClick`: it takes one `Planet` and returns nothing.

## Step 7: Run it

The first screen shows all eight planets with their order underneath. On a small phone you'll need to scroll to reach Neptune. Tap **Mars** and the detail screen shows its name, `Planet #4 from the Sun`, and the Olympus Mons fact. Tap **Back to list** or use the system Back gesture, and the list is exactly where you left it, because `MainActivity` was stopped underneath, not destroyed.

Now try the failure on purpose. In `openDetail`, change `DetailActivity.EXTRA_NAME` to the literal string `"name"` and run again. Tap any planet: the detail screen says "Unknown planet," with no error anywhere. That silent failure is what the constants protect you from. Change it back.

:::warning
If tapping a row crashes with `ActivityNotFoundException`, the `<activity>` entry is missing from the manifest. If the detail screen says "Unknown planet," the key in `putExtra` doesn't match the one in `getStringExtra`; using the `EXTRA_` constants on both sides prevents that.
:::

:::quiz
Q: Why does `PlanetAdapter` call `listener.onPlanetClick(planet)` instead of starting `DetailActivity` itself?
- [x] Opening screens is the Activity's job; the interface lets whoever creates the adapter decide what a tap does
  The same adapter could then be reused on a screen where a tap does something else entirely.
- [ ] An adapter isn't allowed to call `startActivity`
  It could, with a `Context` borrowed from a view. It's a design choice, not a rule.
- [ ] Interfaces make the list scroll faster
  Scrolling speed comes from recycling rows, not from how taps are reported.

Q: Why is the click listener set inside `onBindViewHolder` instead of once in the ViewHolder's constructor?
- [ ] Listeners stop working after a few seconds
  They don't expire.
- [x] Rows are recycled, so a row that showed Venus may now show Mars and must report the right planet
  Binding sets everything for the current item, and that includes what a tap reports.
- [ ] `holder.itemView` doesn't exist in the constructor
  It does; it's passed into the constructor. The issue is which planet the row holds right now.

Q: The sender uses `putExtra(DetailActivity.EXTRA_ORDER, planet.getOrder())`. What does `getIntExtra(EXTRA_ORDER, 0)` return if you forget that line?
- [ ] It crashes with a `NullPointerException`
  An `int` can't be `null`, so the method returns the default instead.
- [x] `0`, the default, so the screen says "Planet #0 from the Sun"
  Which is a good reason to choose defaults you'd notice in testing.
- [ ] A random number
  Missing extras always give back the default you passed.
:::

:::takeaways
- A model class holds one item's data and can be tested as plain Java.
- The adapter turns items into rows; it reports taps through an interface and lets the Activity decide what happens.
- Set everything in `onBindViewHolder`, including click listeners, because rows get reused.
- Extra keys are constants on the receiving Activity, shared by both screens.
- The list screen is stopped, not destroyed, while the detail screen is open, so Back returns to the same scroll position.
:::

## Ideas to extend it

-   Add an `ImageView` to each row with a planet picture from `res/drawable`, stored as an `int` drawable id in `Planet`.
-   Add a distance-from-the-Sun field and show it on the detail screen.
