Every Android app you write in this class is Java underneath the XML. Java is stricter than Python or JavaScript: each variable has a fixed type, every statement ends in a semicolon, and the compiler refuses to build code it can't make sense of. That strictness is annoying for a week and then becomes a gift, because the compiler catches mistakes before your app ever reaches a phone.

The programs here are plain Java with a `main()` method, so you can run them from a terminal without Android Studio. Save each one in a file named after its class (`Variables.java` for `public class Variables`), then:

```bash
javac Variables.java
java Variables
```

## Variables and data types

A Java variable is declared with its type, and that type never changes:

```java
public class Variables {
    public static void main(String[] args) {
        int lives = 3;
        double price = 4.99;
        boolean isMuted = false;
        char grade = 'A';
        long downloads = 3_000_000_000L;
        String player = "Maya";
        final int MAX_LIVES = 5;

        System.out.println(player + " has " + lives + " of " + MAX_LIVES + " lives.");
        System.out.println("Price: " + price + ", muted: " + isMuted + ", grade: " + grade);
        System.out.println("Downloads: " + downloads);

        System.out.println(7 / 2);
        System.out.println(7 / 2.0);
        System.out.println((double) 7 / 2);
        System.out.println((int) 9.99);
        System.out.println(7 % 2);
    }
}
```

```text
Maya has 3 of 5 lives.
Price: 4.99, muted: false, grade: A
Downloads: 3000000000
3
3.5
3.5
9
1
```

The types you'll use constantly:

| Type | Holds | Example |
|---|---|---|
| `int` | whole numbers up to about 2.1 billion | `int lives = 3;` |
| `long` | bigger whole numbers (note the `L`) | `long ms = 3_000_000_000L;` |
| `double` | decimals | `double price = 4.99;` |
| `boolean` | `true` or `false` | `boolean isMuted = false;` |
| `char` | one character, in single quotes | `char grade = 'A';` |
| `String` | text, in double quotes | `String player = "Maya";` |

`final` makes a variable a constant: assign it once and the compiler blocks any later change.

The output shows the classic trap: `7 / 2` is `3`, not `3.5`. When both sides are `int`, Java does **integer division** and throws away the remainder. Make either side a `double` (with `2.0` or a cast like `(double) 7`) to get the decimal answer. Casting the other way, `(int) 9.99`, chops off the decimal rather than rounding. The `%` operator gives the remainder.

## Strings

`String` is a class, not a basic type, so strings come with methods you call using a dot:

```java
public class Strings {
    public static void main(String[] args) {
        String greeting = "  Hello, Android!  ";
        String clean = greeting.trim();
        System.out.println(clean.length());
        System.out.println(clean.toUpperCase());
        System.out.println(clean.substring(7, 14));
        System.out.println(clean.contains("Droid"));
        System.out.println(clean.indexOf(','));

        String typed = new String("yes");
        System.out.println(typed == "yes");
        System.out.println(typed.equals("yes"));
        System.out.println("YES".equalsIgnoreCase(typed));

        int score = Integer.parseInt("42");
        System.out.println(score + 8);
        System.out.println("4" + 2);
        System.out.println(String.format("%s scored %d points (%.1f%%)", "Maya", score, 87.456));
    }
}
```

```text
15
HELLO, ANDROID!
Android
false
5
false
true
true
50
42
Maya scored 42 points (87.5%)
```

-   Strings are **immutable**. `trim()` and `toUpperCase()` return new strings; the original stays the same.
-   `substring(7, 14)` includes index 7 and stops before 14. Indexes start at 0.
-   `contains("Droid")` is `false` because comparisons are case-sensitive.
-   `Integer.parseInt()` turns text into a number. You'll need it in Android, because everything a user types into a text box arrives as a `String`.
-   `"4" + 2` is `"42"`: once a `String` is involved, `+` means "join".

:::warning
Compare strings with `.equals()`, never `==`. The `==` operator checks whether two variables point to the very same object in memory, not whether the text matches. It sometimes appears to work, which makes the bug harder to spot when it doesn't.
:::

## Methods, conditions, and loops

A **method** is a named block of code that can take parameters and return a value. Its declaration lists the return type first (`String`, `double`, or `void` for nothing):

```java
public class Control {
    static String letterGrade(int percent) {
        if (percent >= 90) {
            return "A";
        } else if (percent >= 80) {
            return "B";
        } else if (percent >= 70) {
            return "C";
        } else {
            return "Needs work";
        }
    }

    static double average(int[] scores) {
        int total = 0;
        for (int s : scores) {
            total += s;
        }
        return (double) total / scores.length;
    }

    static String dayType(int day) {
        switch (day) {
            case 6:
            case 7:
                return "weekend";
            default:
                return "school day";
        }
    }

    public static void main(String[] args) {
        int[] scores = {95, 82, 71, 64};

        for (int i = 0; i < scores.length; i++) {
            System.out.println("Quiz " + (i + 1) + ": " + scores[i] + " -> " + letterGrade(scores[i]));
        }
        System.out.println("Average: " + average(scores));

        boolean passedAll = true;
        for (int s : scores) {
            if (s < 70) {
                passedAll = false;
                break;
            }
        }
        System.out.println("Passed every quiz? " + passedAll);

        int countdown = 3;
        while (countdown > 0) {
            System.out.print(countdown + "... ");
            countdown--;
        }
        System.out.println("Liftoff!");

        System.out.println("Day 6 is a " + dayType(6));
        System.out.println("Day 2 is a " + dayType(2));
    }
}
```

```text
Quiz 1: 95 -> A
Quiz 2: 82 -> B
Quiz 3: 71 -> C
Quiz 4: 64 -> Needs work
Average: 78.0
Passed every quiz? false
3... 2... 1... Liftoff!
Day 6 is a weekend
Day 2 is a school day
```

-   Conditions go in parentheses and use `&&` (and), `||` (or), and `!` (not).
-   The counting `for` loop has three parts: start, keep-going test, and step. The **for-each** loop (`for (int s : scores)`) is simpler when you just need each item.
-   `break` leaves a loop early. `while` repeats as long as its condition is true.
-   In `switch`, a `case` without `break` or `return` "falls through" to the next one, which is how 6 and 7 share a result.
-   Arrays have a fixed size; `scores.length` (no parentheses) tells you how many items there are.

These methods are `static` because `main` calls them directly without creating an object first. Methods in your Android classes usually aren't static, for reasons the next section makes clear.

## Classes and objects

A **class** is a blueprint; an **object** is one thing built from it. Each `Pet` object below has its own name and hunger level:

```java
class Pet {
    private String name;
    private String species;
    private int hunger;

    Pet(String name, String species) {
        this.name = name;
        this.species = species;
        this.hunger = 5;
    }

    void feed() {
        if (hunger > 0) {
            hunger--;
        }
    }

    void play() {
        hunger += 2;
    }

    boolean isHungry() {
        return hunger >= 5;
    }

    String getName() {
        return name;
    }

    @Override
    public String toString() {
        return name + " the " + species + " (hunger " + hunger + ")";
    }
}

public class Pets {
    public static void main(String[] args) {
        Pet rex = new Pet("Rex", "dog");
        Pet miso = new Pet("Miso", "cat");

        rex.feed();
        rex.feed();
        miso.play();

        System.out.println(rex);
        System.out.println(miso);
        System.out.println(rex.getName() + " hungry? " + rex.isHungry());
        System.out.println(miso.getName() + " hungry? " + miso.isHungry());

        Pet sameDog = rex;
        sameDog.play();
        System.out.println(rex);
    }
}
```

```text
Rex the dog (hunger 3)
Miso the cat (hunger 7)
Rex hungry? false
Miso hungry? true
Rex the dog (hunger 5)
```

-   **Fields** (`name`, `species`, `hunger`) store each object's data. Marking them `private` means only the class's own methods can change them, so hunger can never go below zero by accident.
-   The **constructor** has the class's name and no return type. `new Pet("Rex", "dog")` calls it. `this.name` means "this object's field," as opposed to the parameter with the same name.
-   **Getters** like `getName()` let other code read private data safely.
-   `toString()` controls what prints when you pass an object to `println`.
-   The last two lines show that object variables hold **references**. `sameDog` and `rex` are two names for one dog, so playing with `sameDog` changes `rex`.

## Inheritance: how MainActivity works

`public class MainActivity extends AppCompatActivity` uses **inheritance**: your class gets everything `AppCompatActivity` already does and replaces only the parts you write. Here is the same pattern in miniature:

```java
class Screen {
    void onCreate() {
        System.out.println("Screen: setting up the window");
    }
}

class HomeScreen extends Screen {
    @Override
    void onCreate() {
        super.onCreate();
        System.out.println("HomeScreen: showing the home layout");
    }
}

public class Screens {
    public static void main(String[] args) {
        Screen screen = new HomeScreen();
        screen.onCreate();
    }
}
```

```text
Screen: setting up the window
HomeScreen: showing the home layout
```

`@Override` asks the compiler to confirm you're really replacing a parent method; misspell the name and it reports an error instead of silently creating a new method. `super.onCreate()` runs the parent's version first, which is exactly why Android's `onCreate` starts with `super.onCreate(savedInstanceState)`.

:::tip
New Android projects compile Java at the Java 11 language level. Stick to features like the ones on this page and avoid newer syntax such as `record` classes or `switch` expressions with `->` arrows in your app code; those can fail to compile in an Android project even though your terminal's JDK accepts them.
:::
