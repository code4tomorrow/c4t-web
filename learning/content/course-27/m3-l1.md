Here's a tip calculator with a bug. Read it, guess the tip on a $40 bill, then look at what it actually prints:

```java run title="TipBug.java"
public class TipBug {
    public static void main(String[] args) {
        double bill = 40.00;
        double tip = 15 / 100 * bill;
        System.out.println("Tip: $" + tip);
    }
}
```

Zero dollars. No error, no warning, just a wrong answer. By the end of the second section you'll know which two numbers caused it.

Every Android app in this class is Java underneath the XML, and Java is strict: every variable has a fixed type, every statement ends in a semicolon, and the compiler refuses code it can't make sense of. That's annoying for about a week. Then it starts saving you, because it catches mistakes before your app ever reaches a phone.

Each program on this page runs right here, with its real output underneath. To run one yourself, save it in a file named after its class (`TipBug.java` for `public class TipBug`), then type `javac TipBug.java` and `java TipBug`.

## Every variable has a type, and it never changes

You declare a Java variable with its type, and from then on it can only hold that kind of value:

```java run title="Variables.java"
public class Variables {
    public static void main(String[] args) {
        int lives = 3;
        double price = 4.99;
        boolean isMuted = false;
        char grade = 'A';
        long downloads = 3_000_000_000L;
        String player = "Maya";
        final int MAX_LIVES = 5;

        System.out.println(player + " has " + lives + " of " + MAX_LIVES + " lives.");
        System.out.println("Price: " + price + ", muted: " + isMuted + ", grade: " + grade);
        System.out.println("Downloads: " + downloads);
    }
}
```

| Type | Holds | Example |
|---|---|---|
| `int` | whole numbers up to about 2.1 billion | `int lives = 3;` |
| `long` | bigger whole numbers (note the `L`) | `long ms = 3_000_000_000L;` |
| `double` | decimals | `double price = 4.99;` |
| `boolean` | `true` or `false` | `boolean isMuted = false;` |
| `char` | one character, in single quotes | `char grade = 'A';` |
| `String` | text, in double quotes | `String player = "Maya";` |

`final` turns a variable into a constant: assign it once, and the compiler blocks any later change. The underscores in `3_000_000_000L` are just for your eyes; Java ignores them.

## Why 15 / 100 is zero

When **both** sides of `/` are `int`, Java does **integer division**: it divides and throws away everything after the decimal point. `15 / 100` is 0.15, which becomes `0`, and `0 * 40.0` is `0.0`. That's the tip bug.

Predict all five lines before you read the output:

```java run title="Division.java"
public class Division {
    public static void main(String[] args) {
        System.out.println(7 / 2);
        System.out.println(7 / 2.0);
        System.out.println((double) 7 / 2);
        System.out.println((int) 9.99);
        System.out.println(7 % 2);
    }
}
```

Make either side a `double` and you get the decimal answer, either by writing `2.0` or with a **cast** like `(double) 7`. Casting the other way, `(int) 9.99`, chops off the decimal rather than rounding, so it gives `9`. The `%` operator gives the remainder, handy for "is this number even?" checks. The tip fix is `15.0 / 100 * bill`, or better, `bill * 0.15`.

## Strings are objects with methods

`String` is a class, not a basic type, so every string comes with methods you call with a dot:

```java run title="Strings.java"
public class Strings {
    public static void main(String[] args) {
        String greeting = "  Hello, Android!  ";
        String clean = greeting.trim();
        System.out.println(clean.length());
        System.out.println(clean.toUpperCase());
        System.out.println(clean.substring(7, 14));
        System.out.println(clean.contains("Droid"));

        String typed = new String("yes");
        System.out.println(typed == "yes");
        System.out.println(typed.equals("yes"));
        System.out.println("YES".equalsIgnoreCase(typed));

        System.out.println("4" + 2);
        System.out.println("Score: " + 3 + 4);
        System.out.println(String.format("%s scored %.1f%%", "Maya", 87.456));
    }
}
```

-   Strings are **immutable**: `trim()` and `toUpperCase()` hand back new strings and leave the original alone.
-   `substring(7, 14)` starts at index 7 and stops **before** 14. Indexes start at 0.
-   `contains("Droid")` is `false` because comparisons care about capital letters.
-   Once a `String` is involved, `+` means "join", working left to right. That's why `"Score: " + 3 + 4` gives `Score: 34`, not `Score: 7`.
-   `String.format` fills in `%s` (a string), `%d` (a whole number), and `%.1f` (a decimal to 1 place); `%%` prints a percent sign.

:::warning
Compare strings with `.equals()`, never `==`. The `==` operator asks whether two variables point at the **same object** in memory, not whether the text matches. It sometimes appears to work, because Java reuses identical string literals, which makes the bug harder to catch when user input arrives and it suddenly doesn't.
:::

## Turning typed text into numbers

Everything a user types into an Android text box arrives as a `String`, even digits. `Integer.parseInt()` and `Double.parseDouble()` convert text to numbers, and they crash on anything that isn't a clean number:

```java run raises title="ParseCrash.java"
public class ParseCrash {
    public static void main(String[] args) {
        String typed = "12 apples";
        int count = Integer.parseInt(typed);
        System.out.println(count + 1);
    }
}
```

Read the first line of that error: `NumberFormatException: For input string: "12 apples"`. In an app, that exception closes the app in front of the user. The fix is to **catch** it with `try` and `catch` and fall back to something sensible:

```java run title="SafeParse.java"
public class SafeParse {
    static int parseOrZero(String text) {
        try {
            return Integer.parseInt(text.trim());
        } catch (NumberFormatException e) {
            return 0;
        }
    }

    public static void main(String[] args) {
        System.out.println(parseOrZero("42"));
        System.out.println(parseOrZero(" 7 "));
        System.out.println(parseOrZero("seven"));
        System.out.println(parseOrZero(""));
    }
}
```

If anything inside `try` throws a `NumberFormatException`, Java jumps straight to `catch`. You'll use this same pattern in Week 4 when you read a number from a text box.

## Methods, decisions, and loops

A **method** is a named block of code that takes parameters and can return a value. Its declaration lists the return type first: `String`, `double`, or `void` for nothing.

```java run title="Control.java"
public class Control {
    static String letterGrade(int percent) {
        if (percent >= 90) {
            return "A";
        } else if (percent >= 80) {
            return "B";
        } else if (percent >= 70) {
            return "C";
        } else {
            return "Needs work";
        }
    }

    static double average(int[] scores) {
        int total = 0;
        for (int s : scores) {
            total += s;
        }
        return (double) total / scores.length;
    }

    public static void main(String[] args) {
        int[] scores = {95, 82, 71, 64};

        for (int i = 0; i < scores.length; i++) {
            System.out.println("Quiz " + (i + 1) + ": " + scores[i] + " -> " + letterGrade(scores[i]));
        }
        System.out.println("Average: " + average(scores));

        int countdown = 3;
        while (countdown > 0) {
            System.out.print(countdown + "... ");
            countdown--;
        }
        System.out.println("Liftoff!");
    }
}
```

-   Conditions go in parentheses and combine with `&&` (and), `||` (or), and `!` (not).
-   The counting `for` loop has three parts: start, keep-going test, and step. The **for-each** loop, `for (int s : scores)`, is simpler when you only need each value.
-   `while` repeats as long as its condition stays true.
-   Arrays have a fixed size, and `scores.length` (no parentheses) tells you how many items there are.
-   `(double) total / scores.length` casts before dividing, which is the integer-division fix from earlier.

These methods are `static` because `main` calls them directly without making an object first. Methods in your Android classes usually aren't, for reasons the next section makes clear.

## Classes: blueprints for your own types

A **class** is a blueprint; an **object** is one thing built from it. Each `Pet` below has its own name and hunger:

```java run title="Pets.java"
class Pet {
    private String name;
    private int hunger;

    Pet(String name) {
        this.name = name;
        this.hunger = 5;
    }

    void feed() {
        if (hunger > 0) {
            hunger--;
        }
    }

    void play() {
        hunger += 2;
    }

    boolean isHungry() {
        return hunger >= 5;
    }

    @Override
    public String toString() {
        return name + " (hunger " + hunger + ")";
    }
}

public class Pets {
    public static void main(String[] args) {
        Pet rex = new Pet("Rex");
        Pet miso = new Pet("Miso");

        rex.feed();
        rex.feed();
        miso.play();
        System.out.println(rex + " hungry? " + rex.isHungry());
        System.out.println(miso + " hungry? " + miso.isHungry());

        Pet sameDog = rex;
        sameDog.play();
        System.out.println(rex);
    }
}
```

-   **Fields** (`name`, `hunger`) hold each object's data. `private` means only the class's own methods can touch them, so hunger can never go below zero by accident.
-   The **constructor** has the class's name and no return type, and `new Pet("Rex")` calls it. `this.name` means "this object's field", as opposed to the parameter with the same name.
-   `toString()` decides what prints when you pass an object to `println`.
-   The last three lines show that object variables hold **references**. `sameDog` and `rex` are two names for one dog, so playing with `sameDog` changes `rex`.

## extends: how MainActivity works

`public class MainActivity extends AppCompatActivity` uses **inheritance**: your class gets everything `AppCompatActivity` already does and replaces only the methods you write. Here's the same shape in miniature:

```java run title="Screens.java"
class Screen {
    void onCreate() {
        System.out.println("Screen: setting up the window");
    }
}

class HomeScreen extends Screen {
    @Override
    void onCreate() {
        super.onCreate();
        System.out.println("HomeScreen: showing the home layout");
    }
}

public class Screens {
    public static void main(String[] args) {
        Screen screen = new HomeScreen();
        screen.onCreate();
    }
}
```

```mermaid caption="Your MainActivity inherits hundreds of methods and overrides one"
classDiagram
    class AppCompatActivity {
        #onCreate(Bundle)
        +setContentView(int)
        +findViewById(int)
    }
    class MainActivity {
        #onCreate(Bundle)
    }
    AppCompatActivity <|-- MainActivity
    class Screen {
        +onCreate()
    }
    class HomeScreen {
        +onCreate()
    }
    Screen <|-- HomeScreen
```

`super.onCreate()` runs the parent's version first, which is why Android's `onCreate` begins with `super.onCreate(savedInstanceState)`. `@Override` asks the compiler to confirm you're really replacing a parent method. Misspell it as `onCreat` and you get `method does not override or implement a method from a supertype` instead of a new method that Android never calls.

## Lambdas: handing Android code to run later

A `Button` can't know what *your* app wants to happen when it's tapped. So Android defines an **interface**, a promise that an object has a certain method, and you hand the button an object that keeps the promise. A **lambda** like `v -> { ... }` is the short way to write that object. The template already uses one: `(v, insets) -> { ... }` is the code Android runs when it learns the system bars' sizes.

This plain-Java version fakes a button so you can watch the idea work:

```java run title="Clicks.java"
interface OnClickListener {
    void onClick(String buttonName);
}

class FakeButton {
    private final String name;
    private OnClickListener listener;

    FakeButton(String name) {
        this.name = name;
    }

    void setOnClickListener(OnClickListener listener) {
        this.listener = listener;
    }

    void tap() {
        if (listener != null) {
            listener.onClick(name);
        }
    }
}

public class Clicks {
    static int count = 0;

    public static void main(String[] args) {
        FakeButton plus = new FakeButton("plus");
        plus.setOnClickListener(name -> {
            count++;
            System.out.println(name + " tapped, count is now " + count);
        });
        System.out.println("Listener set. Nothing has run yet.");
        plus.tap();
        plus.tap();
    }
}
```

Setting the listener runs nothing. The lambda's body only runs when `tap()` calls `onClick`, and it runs again on every tap. In a real app, Android plays the part of `tap()`:

```mermaid caption="A tap in Week 4: Android finds the button, and the button calls the code you gave it"
sequenceDiagram
    participant U as User
    participant A as Android
    participant B as Button
    participant L as Your lambda
    U->>A: Taps the screen
    A->>B: Finds the view under the finger
    B->>L: onClick(v)
    L->>L: count++, then update a TextView
```

Notice `count` is a field (`static int count`), not a local variable inside `main`. Java won't let a lambda change a local variable from the method around it; try it and the compiler stops you with `local variables referenced from a lambda expression must be final or effectively final`. In an Activity, the fix is the same: make the counter a field of the class.

Q: What does this print? `double avg = (90 + 85) / 2; System.out.println(avg);`
- [ ] `87.5`
  That needs decimal division, but `175 / 2` is two `int`s.
- [x] `87.0`
  Integer division gives `87` first; storing it in a `double` just adds `.0`.
- [ ] `87`
  A `double` always prints with a decimal point.

Q: A user types `yes` into a box, and your code gets it as `String answer`. Which check is reliable?
- [ ] `answer == "yes"`
  `==` compares object identity, so text typed at runtime usually fails it.
- [x] `answer.equals("yes")`
  `.equals()` compares the characters themselves.
- [ ] `answer = "yes"`
  A single `=` assigns; it doesn't compare.

Q: What does `System.out.println("Score: " + 3 + 4);` print?
- [ ] `Score: 7`
  The additions happen left to right, and the left side is already a `String`.
- [x] `Score: 34`
  `"Score: " + 3` is `"Score: 3"`, then `+ 4` joins another character.
- [ ] A compile error
  Joining strings and numbers with `+` is allowed.

Q: You type `protected void onCreat(Bundle savedInstanceState)` under `@Override` in `MainActivity`. What happens?
- [ ] The app runs, but the screen is blank
  That's what would happen without `@Override`: a new method Android never calls.
- [x] The build fails: the method doesn't override anything
  `@Override` makes the compiler check the name against the parent class, and catches the typo.
- [ ] Android renames it to `onCreate` for you
  Nothing renames your methods.
:::

:::takeaways
- Every Java variable has one type for its whole life; `int / int` throws the decimals away.
- Compare strings with `.equals()`, and join them with `+`, which works left to right.
- `Integer.parseInt` crashes on bad text, so wrap it in `try`/`catch` whenever the text came from a user.
- A class bundles private fields with the methods allowed to change them; `new` builds an object from it.
- `extends` and `@Override` are how `MainActivity` customizes `AppCompatActivity`, and `super.onCreate()` runs the parent's setup first.
- A lambda is a piece of code you hand over now and that runs later, which is how buttons call your code.
:::
