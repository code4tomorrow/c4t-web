---
title: "Practice: counters, greetings, a converter, and the lifecycle detective"
summary: Work through six exercises that connect views to code, validate typed input, and keep app state alive across rotation, then rebuild a counter on a ViewModel.
---

:::objectives
- Wire buttons, text fields, and TextViews together without looking at the notes.
- Catch empty and non-numeric input before it can crash the app.
- Keep a value through rotation with a Bundle, and predict lifecycle calls before checking Logcat.
- Move state into a `ViewModel` as a stretch.
:::

Each exercise starts from a fresh **Empty Views Activity** project (Java, API 24) unless it says to build on the last one. Leave the template's `EdgeToEdge` and window-insets code alone at the top of `onCreate` and add yours after it. Solutions show only the parts you add or change. Give each one a real attempt first; the hint is there for when you're stuck, not for before you start.

**Warm-up (2 minutes).** The template's "Hello World!" `TextView` has no id. Give it `android:id="@+id/hello_text"`, find it in `onCreate`, and change its text to your name with `setText`. If that works on the first run, your wiring is solid and you're ready.

### Exercise 1: Tap counter

Make a screen with a large `TextView` showing `0` and a Button labeled **Tap**. Each tap adds one. After three taps, the screen shows:

```text
3
```

:::hint
Keep the count in an `int` field. `setText` wants text, not an `int`, and there's a one-call way to turn one into the other.
:::

:::solution
In `activity_main.xml`, inside a vertical `LinearLayout` with `android:id="@+id/main"`:

```xml
<TextView
    android:id="@+id/count_text"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="0"
    android:textSize="48sp" />

<Button
    android:id="@+id/tap_button"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Tap" />
```

In `MainActivity.java`:

```java
private int count = 0;
private TextView countText;

// at the end of onCreate:
countText = findViewById(R.id.count_text);
Button tapButton = findViewById(R.id.tap_button);
tapButton.setOnClickListener(v -> {
    count++;
    countText.setText(String.valueOf(count));
});
```

`String.valueOf` is the important part. `countText.setText(count)` also compiles, because `TextView` has a `setText(int)` method, but that method expects a **string resource id**. Android looks for a string with id 1, finds none, and crashes with `Resources$NotFoundException`.
:::

### Exercise 2: Reset with a Toast

Add a **Reset** button to Exercise 1. It sets the count back to 0 and shows a Toast saying how high you got. Tap 7 times, then Reset, and you should see:

```text
Toast: Reset from 7
Screen: 0
```

:::hint
Order matters inside the listener. Think about what `count` holds at the moment the Toast message is built.
:::

:::solution
Add a second Button with `android:id="@+id/reset_button"` to the layout, then:

```java
Button resetButton = findViewById(R.id.reset_button);
resetButton.setOnClickListener(v -> {
    Toast.makeText(this, "Reset from " + count, Toast.LENGTH_SHORT).show();
    count = 0;
    countText.setText(String.valueOf(count));
});
```

Build the Toast message **before** resetting, or it always says "Reset from 0". Import `android.widget.Toast`.
:::

### Exercise 3: A greeting that won't take blanks

Make an `EditText` for a name, a **Say hi** button, and a `TextView`. Typing `  Ana ` (with spaces) and tapping shows:

```text
Hi, Ana!
```

If the box is empty, or holds only spaces, show an error on the field instead and leave the TextView alone.

:::hint
Get the text, turn it into a `String`, and clean the edges before checking whether anything is left. `String` has a method for each step.
:::

:::solution
```java
EditText nameInput = findViewById(R.id.name_input);
TextView greetingText = findViewById(R.id.greeting_text);
Button hiButton = findViewById(R.id.hi_button);

hiButton.setOnClickListener(v -> {
    String name = nameInput.getText().toString().trim();
    if (name.isEmpty()) {
        nameInput.setError("Please type your name");
    } else {
        greetingText.setText("Hi, " + name + "!");
    }
});
```

`trim()` is doing two jobs: it removes the spaces around `Ana`, and it turns `"   "` into `""` so the empty check catches it.
:::

### Exercise 4: Temperature converter

Build a Celsius-to-Fahrenheit converter: one `EditText`, one button, one result `TextView`. Use `android:inputType="numberSigned|numberDecimal"` so negative temperatures can be typed. Bad input must show a message, never crash. Write and test the logic in plain Java first. For `-40` the screen should show:

```text
-40.0 °C = -40.0 °F
```

:::hint
The formula is `F = C × 9 / 5 + 32`. Put the parse and the formula in one `try` block, and have the `catch` return a friendly message instead of a number.
:::

:::solution
The logic as plain Java, with test inputs including two bad ones:

```java run title="Converter.java"
import java.util.Locale;

public class Converter {

    static String convert(String text) {
        try {
            double celsius = Double.parseDouble(text.trim());
            double fahrenheit = celsius * 9 / 5 + 32;
            return String.format(Locale.US, "%.1f °C = %.1f °F", celsius, fahrenheit);
        } catch (NumberFormatException e) {
            return "Please enter a number";
        }
    }

    public static void main(String[] args) {
        System.out.println(convert("100"));
        System.out.println(convert("-40"));
        System.out.println(convert("21.5"));
        System.out.println(convert(""));
        System.out.println(convert("warm"));
    }
}
```

In the app, copy `convert` into `MainActivity` as a `private` method (drop `static` and `main`) and call it from the listener:

```java
convertButton.setOnClickListener(v ->
        resultText.setText(convert(celsiusInput.getText().toString())));
```

`-40` is the one temperature where both scales agree, which makes it a handy test value.
:::

### Exercise 5: Make the counter survive rotation

Go back to your counter from Exercises 1 and 2. Tap it up to 5, rotate, and watch it drop to 0. Fix it so the screen still shows `5` after any number of rotations.

:::hint
You need two pieces: one method that Android calls just before the old Activity is destroyed, and code in `onCreate` that reads the value back. Then the screen has to be told about it.
:::

:::solution
```java
private static final String KEY_COUNT = "count";

@Override
protected void onSaveInstanceState(@NonNull Bundle outState) {
    super.onSaveInstanceState(outState);
    outState.putInt(KEY_COUNT, count);
}
```

In `onCreate`, after finding `countText`:

```java
if (savedInstanceState != null) {
    count = savedInstanceState.getInt(KEY_COUNT, 0);
}
countText.setText(String.valueOf(count));
```

Import `androidx.annotation.NonNull`. The last line is the one people forget: restoring `count` fixes the variable, but the TextView was rebuilt from XML and still says `0` until you set it.
:::

### Exercise 6: Lifecycle detective

Override all six lifecycle methods (`onCreate`, `onStart`, `onResume`, `onPause`, `onStop`, `onDestroy`) and log each one with `Log.d("Lifecycle", "...")`. Before running, **write down** what you expect Logcat to show for each of these actions. Then do them and compare:

1.  Launch the app.
2.  Press Home.
3.  Reopen the app from recent apps.
4.  Rotate the phone.

:::hint
Pressing Home hides the Activity but doesn't throw it away. Rotation does throw it away. One of those two leads to `onDestroy`, and one of them doesn't.
:::

:::solution
Every override follows this shape, with `super` called inside:

```java
@Override
protected void onPause() {
    super.onPause();
    Log.d("Lifecycle", "onPause");
}
```

With Logcat filtered to `tag:Lifecycle`, the four actions produce:

```text
onCreate      <- 1. launch
onStart
onResume
onPause       <- 2. Home
onStop
onStart       <- 3. back from recents
onResume
onPause       <- 4. rotate
onStop
onDestroy
onCreate
onStart
onResume
```

Pressing Home stops the Activity but never destroys it, so coming back skips `onCreate` and your fields are still there. Rotation runs the full teardown and rebuild, which is why Exercise 5 needed a Bundle. Android also calls `onRestart` just before the `onStart` in step 3; override it too if you want to see it.
:::

### Challenge: a counter on a ViewModel

Rebuild the counter so the number lives in a `ViewModel` instead of a field plus a Bundle. Rotating must keep the count, with no `onSaveInstanceState` anywhere.

:::hint
Create a class that extends `androidx.lifecycle.ViewModel` and holds the count with a getter and an `increment()` method. In `onCreate`, ask `new ViewModelProvider(this)` for it instead of calling `new` yourself.
:::

:::solution
`CounterViewModel.java`, in the same package as `MainActivity`:

```java
package com.example.counter;

import androidx.lifecycle.ViewModel;

public class CounterViewModel extends ViewModel {
    private int count = 0;

    public int getCount() {
        return count;
    }

    public void increment() {
        count++;
    }
}
```

In `MainActivity.onCreate`:

```java
CounterViewModel model = new ViewModelProvider(this).get(CounterViewModel.class);
TextView countText = findViewById(R.id.count_text);
countText.setText(String.valueOf(model.getCount()));

Button tapButton = findViewById(R.id.tap_button);
tapButton.setOnClickListener(v -> {
    model.increment();
    countText.setText(String.valueOf(model.getCount()));
});
```

Import `androidx.lifecycle.ViewModelProvider`, and change `com.example.counter` to your package name. After a rotation, `ViewModelProvider` hands the new Activity the **same** `CounterViewModel` object, so the count is still there. If you wrote `new CounterViewModel()` yourself, you'd get a fresh object with 0 every time.

Want to see where a ViewModel falls short? Turn on **Don't keep activities** in Developer options, tap to 5, press Home, and come back. The ViewModel's count is gone, while Exercise 5's Bundle version would still show 5.
:::
