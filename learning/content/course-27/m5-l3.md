summary: Work through six exercises that connect views to code, validate typed input, and keep app state alive across rotation and lifecycle changes.
---

Each exercise starts from a fresh **Empty Views Activity** project (Java, API 24) unless it says to build on the previous one. Keep the template's `EdgeToEdge` and window-insets code in `onCreate` and add your code after it. Solutions show only the parts you change. Try each one yourself before you peek.

### Exercise 1: Tap counter

Make a screen with a big `TextView` showing `0` and a Button labeled "Tap". Each tap adds one to the number.

Hint: `setText` needs text, so convert with `String.valueOf(count)`.

:::solution
In `activity_main.xml` (inside a vertical `LinearLayout` with `android:id="@+id/main"`):

```xml
<TextView
    android:id="@+id/count_text"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="0"
    android:textSize="48sp" />

<Button
    android:id="@+id/tap_button"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Tap" />
```

In `MainActivity.java`:

```java
private int count = 0;
private TextView countText;

// at the end of onCreate:
countText = findViewById(R.id.count_text);
Button tapButton = findViewById(R.id.tap_button);
tapButton.setOnClickListener(v -> {
    count++;
    countText.setText(String.valueOf(count));
});
```

After three taps the screen shows:

```text
3
```

Passing `count` directly to `setText` compiles, because there is a `setText(int)` method, but it treats the int as a **string resource id** and crashes with `Resources$NotFoundException`. That's why `String.valueOf` matters.
:::

### Exercise 2: Reset with a Toast

Add a "Reset" button to Exercise 1. It sets the count back to 0 and shows a Toast that says how high you got, for example "Reset from 7".

:::solution
Add a second Button with `android:id="@+id/reset_button"` to the layout, then:

```java
Button resetButton = findViewById(R.id.reset_button);
resetButton.setOnClickListener(v -> {
    Toast.makeText(this, "Reset from " + count, Toast.LENGTH_SHORT).show();
    count = 0;
    countText.setText(String.valueOf(count));
});
```

Build the Toast message **before** resetting, or it will always say "Reset from 0". Import `android.widget.Toast`.
:::

### Exercise 3: Polite greeting

Make an `EditText` for a name, a "Say hi" button, and a `TextView`. Tapping the button shows `Hi, Ana!`. If the field is empty (or only spaces), show an error on the field instead.

:::solution
```java
EditText nameInput = findViewById(R.id.name_input);
TextView greetingText = findViewById(R.id.greeting_text);
Button hiButton = findViewById(R.id.hi_button);

hiButton.setOnClickListener(v -> {
    String name = nameInput.getText().toString().trim();
    if (name.isEmpty()) {
        nameInput.setError("Please type your name");
    } else {
        greetingText.setText("Hi, " + name + "!");
    }
});
```

Typing `  Ana ` and tapping shows:

```text
Hi, Ana!
```

The `trim()` call is what removes the extra spaces and makes "   " count as empty.
:::

### Exercise 4: Temperature converter

Build a Celsius-to-Fahrenheit converter: one `EditText` (`inputType="numberSigned|numberDecimal"` so negative numbers work), one button, one result `TextView`. Bad input must not crash the app. Write and test the logic as plain Java first.

:::solution
Plain Java version, tested with `javac` and `java`:

```java
import java.util.Locale;

public class Converter {

    static String convert(String text) {
        try {
            double celsius = Double.parseDouble(text.trim());
            double fahrenheit = celsius * 9 / 5 + 32;
            return String.format(Locale.US, "%.1f °C = %.1f °F", celsius, fahrenheit);
        } catch (NumberFormatException e) {
            return "Please enter a number";
        }
    }

    public static void main(String[] args) {
        System.out.println(convert("100"));
        System.out.println(convert("-40"));
        System.out.println(convert("21.5"));
        System.out.println(convert(""));
    }
}
```

```text
100.0 °C = 212.0 °F
-40.0 °C = -40.0 °F
21.5 °C = 70.7 °F
Please enter a number
```

In the app, copy `convert` into `MainActivity` as a `private` method and call it from the click listener:

```java
convertButton.setOnClickListener(v ->
        resultText.setText(convert(celsiusInput.getText().toString())));
```
:::

### Exercise 5: Make the counter survive rotation

Go back to your counter from Exercises 1 and 2. Tap it up to 5, rotate the phone, and watch it reset to 0. Fix it.

:::solution
```java
private static final String KEY_COUNT = "count";

@Override
protected void onSaveInstanceState(@NonNull Bundle outState) {
    super.onSaveInstanceState(outState);
    outState.putInt(KEY_COUNT, count);
}
```

In `onCreate`, after finding `countText`:

```java
if (savedInstanceState != null) {
    count = savedInstanceState.getInt(KEY_COUNT, 0);
}
countText.setText(String.valueOf(count));
```

Import `androidx.annotation.NonNull`. The last line matters: restoring `count` isn't enough; the screen also has to show it.
:::

### Exercise 6: Lifecycle detective

Override all six lifecycle methods (`onCreate`, `onStart`, `onResume`, `onPause`, `onStop`, `onDestroy`) and log each with `Log.d("Lifecycle", "...")`. Before you run it, **write down** what you expect Logcat to show for each action, then check:

1.  Launch the app.
2.  Press Home.
3.  Reopen the app from recent apps.

:::solution
Each override looks like this (always call `super` first):

```java
@Override
protected void onPause() {
    super.onPause();
    Log.d("Lifecycle", "onPause");
}
```

Filtering Logcat with `tag:Lifecycle` shows:

```text
onCreate
onStart
onResume
onPause
onStop
onStart
onResume
```

The first three lines are the launch, the next two are pressing Home, and the last two are coming back. Notice that pressing Home does **not** call `onDestroy` and coming back does **not** call `onCreate`: the Activity was only stopped, so your fields are still there. (Android also calls `onRestart` just before that second `onStart`; override it too if you want to see it.)
:::

## Stretch challenge: a ViewModel counter

Rebuild the counter so the number lives in a `ViewModel` instead of a field plus a Bundle. Rotating should keep the count with no `onSaveInstanceState` at all.

:::solution
`CounterViewModel.java` (same package as `MainActivity`):

```java
package com.example.counter;

import androidx.lifecycle.ViewModel;

public class CounterViewModel extends ViewModel {
    private int count = 0;

    public int getCount() {
        return count;
    }

    public void increment() {
        count++;
    }
}
```

In `MainActivity.onCreate`:

```java
CounterViewModel model = new ViewModelProvider(this).get(CounterViewModel.class);
TextView countText = findViewById(R.id.count_text);
countText.setText(String.valueOf(model.getCount()));

Button tapButton = findViewById(R.id.tap_button);
tapButton.setOnClickListener(v -> {
    model.increment();
    countText.setText(String.valueOf(model.getCount()));
});
```

Import `androidx.lifecycle.ViewModelProvider`. After a rotation, `ViewModelProvider` hands back the **same** `CounterViewModel` object, so the count is still there. Replace `com.example.counter` with your own package name.
:::
