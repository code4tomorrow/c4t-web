### Exercise 1: Temperature report

Store these Celsius readings in a `double` array: `18.5, 31.0, 24.2, 35.6, 9.0`. For each one, print the Fahrenheit value to one decimal place (F = C × 9 / 5 + 32). Add `(hot)` after readings above 30 C and `(cold)` after readings below 10 C.

```text
18.5 C = 65.3 F
31.0 C = 87.8 F (hot)
24.2 C = 75.6 F
35.6 C = 96.1 F (hot)
9.0 C = 48.2 F (cold)
```

:::hint
Loop over the array with for-each. Build a `label` string that starts empty and becomes `" (hot)"` or `" (cold)"` with `if`/`else if`. `String.format("%.1f", value)` gives one decimal place.
:::

:::solution
```java run title="Temps.java"
public class Temps {
    public static void main(String[] args) {
        double[] celsius = {18.5, 31.0, 24.2, 35.6, 9.0};
        for (double c : celsius) {
            double f = c * 9 / 5 + 32;
            String label = "";
            if (c > 30) {
                label = " (hot)";
            } else if (c < 10) {
                label = " (cold)";
            }
            System.out.println(String.format("%.1f C = %.1f F%s", c, f, label));
        }
    }
}
```

Because `c` is a `double`, `c * 9 / 5` stays a decimal all the way through. If `c` were an `int`, the division by 5 would throw away the fraction.
:::

### Exercise 2: Username rules

Write `static boolean isValidUsername(String name)` that returns `true` only when the name is 3 to 15 characters long, has no spaces, and starts with a letter. Test it on `maya_codes`, `jo`, `4tomorrow`, `big bird`, `android_developer_01`, and `Sam2026`.

```text
maya_codes -> OK
jo -> rejected
4tomorrow -> rejected
big bird -> rejected
android_developer_01 -> rejected
Sam2026 -> OK
```

:::hint
Check one rule at a time and `return false` the moment a rule fails. `name.charAt(0)` gives the first character, and `Character.isLetter(...)` tests it.
:::

:::solution
```java run title="Usernames.java"
public class Usernames {
    static boolean isValidUsername(String name) {
        if (name.length() < 3 || name.length() > 15) {
            return false;
        }
        if (name.contains(" ")) {
            return false;
        }
        return Character.isLetter(name.charAt(0));
    }

    public static void main(String[] args) {
        String[] tests = {"maya_codes", "jo", "4tomorrow", "big bird", "android_developer_01", "Sam2026"};
        for (String t : tests) {
            System.out.println(t + " -> " + (isValidUsername(t) ? "OK" : "rejected"));
        }
    }
}
```

Returning early keeps each rule on its own short line, and the length check comes first so `charAt(0)` never runs on an empty string. You'll run the same kind of check on text typed into an Android sign-up screen.
:::

### Exercise 3: Battery drain

A phone starts at 100% and loses 7% each hour. Use a `while` loop to find how many hours pass before the battery drops below 20%. Then use nested `for` loops to draw a bar of `|` characters, one per 10%, for the levels 100, 75, 50, 25, and 0.

```text
Low battery warning after 12 hours (16% left).
100% ||||||||||
 75% |||||||
 50% |||||
 25% ||
  0%
```

:::hint
You don't know the number of hours in advance, which is the sign to use `while (battery >= 20)`. For the bars, the outer loop counts down by 25, and the inner loop runs `level / 10` times. `%3d` pads a number to three characters.
:::

:::solution
```java run title="Battery.java"
public class Battery {
    public static void main(String[] args) {
        int battery = 100;
        int hours = 0;
        while (battery >= 20) {
            battery -= 7;
            hours++;
        }
        System.out.println("Low battery warning after " + hours + " hours (" + battery + "% left).");

        for (int level = 100; level >= 0; level -= 25) {
            String bar = "";
            for (int i = 0; i < level / 10; i++) {
                bar += "|";
            }
            System.out.println(String.format("%3d%% %s", level, bar).stripTrailing());
        }
    }
}
```

Integer division does useful work here: `75 / 10` is `7`, so 75% gets seven bars. `%%` prints a literal percent sign, and `stripTrailing()` removes the space left after `0%` when its bar is empty.
:::

### Exercise 4: Read an age safely

In Week 4 you'll read numbers from a text box, where people type anything. Write `static int parseAge(String text)` that trims the text, converts it to an `int`, and returns `-1` if the text isn't a number **or** the age is outside 0 to 120. Test it on `"15"`, `" 42 "`, `"fifteen"`, `"-3"`, `"200"`, and `""`.

```text
"15" -> 15
" 42 " -> 42
"fifteen" -> -1
"-3" -> -1
"200" -> -1
"" -> -1
```

:::hint
Put `Integer.parseInt(text.trim())` inside `try`, and `return -1` in a `catch (NumberFormatException e)`. The range check goes after a successful parse, still inside `try`.
:::

:::solution
```java run title="Ages.java"
public class Ages {
    static int parseAge(String text) {
        try {
            int age = Integer.parseInt(text.trim());
            if (age < 0 || age > 120) {
                return -1;
            }
            return age;
        } catch (NumberFormatException e) {
            return -1;
        }
    }

    public static void main(String[] args) {
        String[] inputs = {"15", " 42 ", "fifteen", "-3", "200", ""};
        for (String text : inputs) {
            System.out.println("\"" + text + "\" -> " + parseAge(text));
        }
    }
}
```

`"fifteen"` and `""` both throw `NumberFormatException`, so they land in `catch`. `"-3"` parses fine, which is why the range check is needed too. `\"` puts a quote mark inside a string.
:::

### Exercise 5: Playlist classes

Create a `Song` class (title and length in seconds, both private, with getters) and a `Playlist` class that holds an `ArrayList<Song>`. `Playlist` needs `add(Song)`, `totalSeconds()`, `longest()`, a `static` helper `formatTime(int seconds)` that returns text like `3:05`, and `print()`. Build a "Study Mix" with three songs: Lo-fi Morning (185 s), Rainy Window (242 s), and Focus Mode (207 s).

```text
Study Mix (3 songs, 10:34)
  1. Lo-fi Morning 3:05
  2. Rainy Window 4:02
  3. Focus Mode 3:27
Longest: Rainy Window
```

:::hint
`formatTime` is two integer operations: `seconds / 60` for minutes and `seconds % 60` for seconds. `%02d` pads the seconds to two digits. `longest()` uses the "assume the first is best" loop from the habit tracker.
:::

:::solution
```java run title="PlaylistApp.java"
import java.util.ArrayList;

class Song {
    private String title;
    private int seconds;

    Song(String title, int seconds) {
        this.title = title;
        this.seconds = seconds;
    }

    String getTitle() {
        return title;
    }

    int getSeconds() {
        return seconds;
    }
}

class Playlist {
    private String name;
    private ArrayList<Song> songs = new ArrayList<>();

    Playlist(String name) {
        this.name = name;
    }

    void add(Song song) {
        songs.add(song);
    }

    int totalSeconds() {
        int total = 0;
        for (Song s : songs) {
            total += s.getSeconds();
        }
        return total;
    }

    Song longest() {
        Song best = songs.get(0);
        for (Song s : songs) {
            if (s.getSeconds() > best.getSeconds()) {
                best = s;
            }
        }
        return best;
    }

    static String formatTime(int seconds) {
        return String.format("%d:%02d", seconds / 60, seconds % 60);
    }

    void print() {
        System.out.println(name + " (" + songs.size() + " songs, " + formatTime(totalSeconds()) + ")");
        for (int i = 0; i < songs.size(); i++) {
            Song s = songs.get(i);
            System.out.println("  " + (i + 1) + ". " + s.getTitle() + " " + formatTime(s.getSeconds()));
        }
        System.out.println("Longest: " + longest().getTitle());
    }
}

public class PlaylistApp {
    public static void main(String[] args) {
        Playlist study = new Playlist("Study Mix");
        study.add(new Song("Lo-fi Morning", 185));
        study.add(new Song("Rainy Window", 242));
        study.add(new Song("Focus Mode", 207));
        study.print();
    }
}
```

`formatTime` is `static` because it doesn't use any playlist's data; it only converts a number. One weakness: `longest()` crashes on an empty playlist, so a real app would check `songs.isEmpty()` first.
:::

### Exercise 6: A button that calls you back

Fake the way an Android button works. Write an interface `OnTapListener` with one method, `void onTap(int tapNumber)`, and a class `TapButton` with `setOnTapListener(OnTapListener listener)` and `tap()`. Each `tap()` counts the tap and calls the listener with the count, but if no listener has been set yet, `tap()` does nothing at all (no count, no crash).

In `main`, tap once **before** setting a listener, then set one with a lambda that prints `Tap n`, adding `: combo!` on every third tap, and tap five more times:

```text
Tap 1
Tap 2
Tap 3: combo!
Tap 4
Tap 5
```

:::hint
Store the listener in a private field that starts as `null`. At the top of `tap()`, `if (listener == null) { return; }`. The lambda takes one parameter, `n -> { ... }`, and `n % 3 == 0` spots every third tap.
:::

:::solution
```java run title="Taps.java"
interface OnTapListener {
    void onTap(int tapNumber);
}

class TapButton {
    private OnTapListener listener;
    private int taps = 0;

    void setOnTapListener(OnTapListener listener) {
        this.listener = listener;
    }

    void tap() {
        if (listener == null) {
            return;
        }
        taps++;
        listener.onTap(taps);
    }
}

public class Taps {
    public static void main(String[] args) {
        TapButton button = new TapButton();
        button.tap();

        button.setOnTapListener(n -> {
            if (n % 3 == 0) {
                System.out.println("Tap " + n + ": combo!");
            } else {
                System.out.println("Tap " + n);
            }
        });
        for (int i = 0; i < 5; i++) {
            button.tap();
        }
    }
}
```

The first `tap()` returns early, so nothing prints and the count stays at 0. Without the `null` check, it would crash with a `NullPointerException`, which is also what happens in Android if you call a method on a view that `findViewById` couldn't find. The lambda's code is stored, not run, until `tap()` calls `onTap`.
:::

### Challenge: Savings accounts

Write an `Account` class with an owner, a balance, a `withdraw(double amount)` method that returns `false` (and changes nothing) for amounts that are zero, negative, or more than the balance, and a `toString()` like `Maya: $30.00`.

Then write `SavingsAccount extends Account` with an interest rate, an `addInterest()` method, and a limit of two successful withdrawals. Override `withdraw` and `toString`, and use `super` in both. Put both classes in `Bank.java`, above a `public class Bank` whose `main` runs these lines:

```java
        Account checking = new Account("Maya", 50);
        SavingsAccount savings = new SavingsAccount("Maya", 200, 0.05);

        System.out.println(checking.withdraw(80));
        System.out.println(checking.withdraw(20));
        savings.addInterest();
        System.out.println(savings.withdraw(10));
        System.out.println(savings.withdraw(10));
        System.out.println(savings.withdraw(10));
        System.out.println(checking);
        System.out.println(savings);
```

It should print:

```text
false
true
true
true
false
Maya: $30.00
Maya: $190.00 (savings, 0 withdrawals left)
```

:::video Qb_NUn0TSAU
Coding with John covers both uses of `super` you need here: calling the parent's constructor with `super(...)`, and calling the parent's version of an overridden method with `super.method()`.
:::

:::hint
The subclass constructor must start with `super(owner, balance)`. Make `balance` `protected` so `addInterest()` can change it. In the overridden `withdraw`, check the withdrawal limit first, then let `super.withdraw(amount)` do the balance checks, and only count the withdrawal if it returned `true`.
:::

:::solution
```java run title="Bank.java"
class Account {
    private String owner;
    protected double balance;

    Account(String owner, double balance) {
        this.owner = owner;
        this.balance = balance;
    }

    boolean withdraw(double amount) {
        if (amount <= 0 || amount > balance) {
            return false;
        }
        balance -= amount;
        return true;
    }

    @Override
    public String toString() {
        return String.format("%s: $%.2f", owner, balance);
    }
}

class SavingsAccount extends Account {
    private double rate;
    private int withdrawalsLeft = 2;

    SavingsAccount(String owner, double balance, double rate) {
        super(owner, balance);
        this.rate = rate;
    }

    void addInterest() {
        balance += balance * rate;
    }

    @Override
    boolean withdraw(double amount) {
        if (withdrawalsLeft == 0) {
            return false;
        }
        boolean ok = super.withdraw(amount);
        if (ok) {
            withdrawalsLeft--;
        }
        return ok;
    }

    @Override
    public String toString() {
        return super.toString() + " (savings, " + withdrawalsLeft + " withdrawals left)";
    }
}

public class Bank {
    public static void main(String[] args) {
        Account checking = new Account("Maya", 50);
        SavingsAccount savings = new SavingsAccount("Maya", 200, 0.05);

        System.out.println(checking.withdraw(80));
        System.out.println(checking.withdraw(20));
        savings.addInterest();
        System.out.println(savings.withdraw(10));
        System.out.println(savings.withdraw(10));
        System.out.println(savings.withdraw(10));
        System.out.println(checking);
        System.out.println(savings);
    }
}
```

`super(owner, balance)` has to be the first line of the subclass constructor. `balance` is `protected` so the subclass can add interest, while `owner` stays `private`. The overridden `withdraw` adds one new rule and hands everything else to `super.withdraw`, so the balance checks live in one place. That's the same relationship your `MainActivity` has with `AppCompatActivity`: add what's new, and let the parent do the rest.
:::
