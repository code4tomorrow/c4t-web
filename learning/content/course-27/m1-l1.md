On the first day of an Android class, someone always opens Android Studio for the first time and watches a progress bar labeled "Downloading components" for the next 30 minutes. The installer is around 1 GB, and the setup wizard then pulls several more gigabytes: the Android SDK, build tools, and a full Android system image for the emulator.

Do all of it at home, on good Wi-Fi, before Week 1. Then class time goes to building apps.

## What you're installing

Android Studio is Google's free tool for making Android apps. It's really four tools in one window:

-   **The editor**, where you write Java and design screens in XML.
-   **The Android SDK**, the libraries and build tools every app is compiled against.
-   **Gradle**, the build system that turns your code into an installable app file (an APK).
-   **The emulator**, a virtual Android phone that runs in a window on your computer.

The emulator is the hungry one. Android Studio alone is comfortable on 8 GB of RAM; running a virtual phone next to it is where 16 GB starts to matter.

## Check your computer first

These are Google's published minimums:

| | Windows | macOS | Linux |
|---|---|---|---|
| OS | 64-bit Windows 10 or newer | macOS 12 or newer | 64-bit distro with GNOME, KDE, or Unity; glibc 2.31+ |
| RAM | 8 GB for Studio; 16 GB to also run the emulator | same | same |
| Free disk | 8 GB; 16 GB with the emulator (an SSD helps a lot) | same | same |
| CPU | 64-bit Intel or AMD from about 2017 on, with virtualization (VT-x or AMD-V) enabled | Apple M-series, or 6th-gen Intel Core or newer | same as Windows |
| Screen | 1280 x 800 | same | same |

Windows and Linux PCs with ARM processors (some thin laptops, such as Snapdragon models) aren't supported yet. On a Chromebook, Android Studio runs inside ChromeOS's Linux environment, and it can only send apps to a real phone plugged in over USB, not to an emulator.

Here's how to find your numbers:

-   **Windows:** press Ctrl + Shift + Esc to open Task Manager, click **Performance**, then **Memory** for RAM. Click **CPU** and look for **Virtualization: Enabled**.
-   **macOS:** Apple menu > **About This Mac**. It shows the chip (Apple M1, M2, and so on, or Intel) and the memory.
-   **Linux:** run these in a terminal.

```bash
free -h
grep -c -E 'vmx|svm' /proc/cpuinfo
```

Read the `total` column of the `Mem:` row for RAM. The second command counts CPU cores that support hardware virtualization: any number above `0` is good news, and `0` means it's missing or switched off in your BIOS.

Only 8 GB of RAM? You can still take this class. A real Android phone over USB costs your computer almost nothing, while an emulator can take 2 to 4 GB of RAM on its own. Any phone from the last several years works.

## Download and install

Download from the official page at developer.android.com/studio (linked at the bottom). Accept the license, then pick the file for your system.

:::tabs
@tab Windows
1.  Download the **Windows** `.exe` installer.
2.  Double-click it. On the components screen, leave **Android Virtual Device** ticked; that's the emulator.
3.  Accept the default install folder, click through to **Finish**, and let it launch Android Studio.

If Windows asks whether to allow the app to make changes, click **Yes**.
@tab macOS
1.  Check **About This Mac** first. Download **Mac with Apple chip** for M1 and newer, or **Mac with Intel chip** for Intel Macs. The wrong one either won't open or runs painfully slowly.
2.  Open the `.dmg` and drag **Android Studio** into **Applications**.
3.  Open it from Applications. When macOS warns that it was downloaded from the internet, click **Open**.

Google is phasing out support for Intel Macs, so on an older Intel Mac expect the emulator to be slow and lean on a real phone instead.
@tab Linux
Download the `.tar.gz`, unpack it into `/opt`, and start it from the `bin` folder (adjust the file name to match your download):

```bash
cd ~/Downloads
sudo tar -xzf android-studio-*-linux.tar.gz -C /opt
/opt/android-studio/bin/studio
```

On 64-bit Ubuntu, Google also asks for a few 32-bit libraries:

```bash
sudo apt-get install libc6:i386 libncurses5:i386 libstdc++6:i386 lib32z1 libbz2-1.0:i386
```

Once Android Studio is open, choose **Tools > Create Desktop Entry** so it appears in your app menu.
@tab Chromebook
1.  Turn on Linux: open **Settings**, search for **Linux development environment**, and click **Set up**. Give it at least 15 GB of disk if it asks.
2.  Download the **ChromeOS** `.deb` file.
3.  In the **Files** app, move the `.deb` from **Downloads** into **Linux files**.
4.  Open the **Terminal** app and install it (the exact file name will differ):

```bash
sudo apt install ./android-studio-*-cros.deb
```

5.  Launch **Android Studio** from the Launcher, or run `/opt/android-studio/bin/studio` in the terminal.

Remember that on ChromeOS you'll run apps on a phone plugged in over USB, so have one and a data cable ready.
:::

## Run the setup wizard

The first launch opens a setup wizard. These choices work for this class:

1.  **Import settings:** choose not to import (unless you've used Android Studio before).
2.  **Install type:** **Standard**. It picks the SDK, the emulator, and a recent Android version for you.
3.  **Theme:** your choice.
4.  **License agreements:** this is where people get stuck. The left side lists several licenses; click **each one** and select **Accept**. The **Finish** button stays grey until every license is accepted.
5.  Click **Finish** and wait. On slow Wi-Fi the downloads can take 20 minutes or more.

You know it worked when you land on the **Welcome to Android Studio** window, with **New Project**, **Open**, and **More Actions**.

The wizard puts the SDK in one of these folders. Make a note of yours, because several fixes later in the course need it:

| OS | Default SDK location |
|---|---|
| Windows | `C:\Users\<you>\AppData\Local\Android\Sdk` |
| macOS | `~/Library/Android/sdk` |
| Linux and Chromebook | `~/Android/Sdk` |

## When the install goes wrong

These are the four problems that actually come up, and their fixes.

**The wizard's Finish button won't light up.** A license is still unaccepted. Click every license name in the left list, one at a time, and select **Accept** for each.

**Strange build errors that mention your SDK folder.** Some build tools break on paths with spaces or non-English letters, such as a Windows user name like `Zoë Kim`. Create a simple folder like `C:\Android\Sdk` and choose it as the SDK location in the wizard. If you already installed, change it in **Settings > Languages & Frameworks > Android SDK**.

**The download stalls or fails halfway.** School and library networks sometimes block the SDK servers. Try home Wi-Fi or a phone hotspot, then restart Android Studio; the wizard picks up the missing parts.

**The emulator complains about hardware acceleration.** Virtualization is off in your computer's firmware. The next two lessons cover the fix, and a phone over USB sidesteps the problem entirely.

## One more tool for Week 2: a JDK

Android Studio carries its own Java for building apps. In Week 2, though, you'll run small plain-Java programs from a terminal, and that needs a separate **JDK** (Java Development Kit).

Install **Eclipse Temurin** from adoptium.net, version 21 or newer (the LTS version the site offers by default is fine). On Windows, the installer has an option called **Set JAVA_HOME variable**; switch it on, and leave **Add to PATH** on. Then open a **new** terminal and check:

```bash
java -version
javac -version
```

Both should print a version number of 21 or higher. If you get `command not found` or `'java' is not recognized`, close the terminal and open a fresh one, since terminals only read the PATH when they start. If that doesn't help on Windows, rerun the installer and make sure both options are on.
