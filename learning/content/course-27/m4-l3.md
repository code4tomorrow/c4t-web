---
title: "Practice: build layouts and fix broken ones"
summary: Six layout exercises on resources, weights, constraints and bias, keyboards and autofill, image scaling, and views that only look right in the preview, plus a challenge that translates your business card into Spanish.
---

:::objectives
- Move hardcoded values into string, color, and dimension resources.
- Split a row by weights and place views with constraints and bias.
- Pick the right `inputType`, `autofillHints`, and `scaleType` for a job.
- Diagnose a view that looks right in Design view but jumps on the phone.
- Translate an app with a locale-qualified `strings.xml`.
:::

Do these in a scratch project (an Empty Views Activity named `Week3Practice` works well) or in your business-card project. Each solution is XML you paste into `activity_main.xml` or the resource file it names. Keep the editor in **Split** view so every change shows up in the preview as you type.

Unless an exercise says otherwise, put views inside the template's root `ConstraintLayout` and keep its `android:id="@+id/main"`.

## Warm-up: name the attribute

Answer from memory, then check against the notes.

1.  Which attribute centers the text **inside** a button?
2.  Which width makes a view stretch between its start and end constraints?
3.  Which unit belongs on `android:textSize`?

(Answers: `android:gravity`, `0dp`, and `sp`.)

### Exercise 1: Move everything into resources

This `TextView` works, but every value is hardcoded. Move the text, the color, and both sizes into `strings.xml`, `colors.xml`, and `dimens.xml`, then update the view to use them.

```xml
    <TextView
        android:id="@+id/welcomeText"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_marginTop="20dp"
        android:text="Welcome back!"
        android:textColor="#FF0B6E4F"
        android:textSize="26sp"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintTop_toTopOf="parent" />
```

:::hint
Four values, three files: one `<string>`, one `<color>`, and two `<dimen>` entries. Then swap each value in the view for `@string/...`, `@color/...`, or `@dimen/...`. Alt + Enter on the text can do the string for you.
:::

:::solution
Add one entry to each resource file, inside its `<resources>` tag:

```xml
    <string name="welcome_back">Welcome back!</string>
```

```xml
    <color name="brand">#FF0B6E4F</color>
```

```xml
    <dimen name="space_top">20dp</dimen>
    <dimen name="text_headline">26sp</dimen>
```

Then the view becomes:

```xml
    <TextView
        android:id="@+id/welcomeText"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_marginTop="@dimen/space_top"
        android:text="@string/welcome_back"
        android:textColor="@color/brand"
        android:textSize="@dimen/text_headline"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintTop_toTopOf="parent" />
```

The yellow hardcoded-text warning disappears. **Extract string resource** handles strings automatically; colors and dimensions you move by hand.
:::

### Exercise 2: A row of equal buttons

Make a horizontal row of three buttons, **Easy**, **Medium**, and **Hard**, that always split the screen width into three equal parts with 8dp gaps between them. Then change it so **Medium** is twice as wide as each of the others.

:::hint
A horizontal `LinearLayout` inside the root does the splitting. Every button needs `layout_width="0dp"` and a `layout_weight`. Margins on the middle button create both gaps.
:::

:::solution
Place this inside the root `ConstraintLayout`:

```xml
    <LinearLayout
        android:id="@+id/levelRow"
        android:layout_width="0dp"
        android:layout_height="wrap_content"
        android:layout_marginStart="16dp"
        android:layout_marginTop="16dp"
        android:layout_marginEnd="16dp"
        android:orientation="horizontal"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintTop_toTopOf="parent">

        <Button
            android:id="@+id/easyButton"
            android:layout_width="0dp"
            android:layout_height="wrap_content"
            android:layout_weight="1"
            android:text="@string/easy" />

        <Button
            android:id="@+id/mediumButton"
            android:layout_width="0dp"
            android:layout_height="wrap_content"
            android:layout_marginStart="8dp"
            android:layout_marginEnd="8dp"
            android:layout_weight="1"
            android:text="@string/medium" />

        <Button
            android:id="@+id/hardButton"
            android:layout_width="0dp"
            android:layout_height="wrap_content"
            android:layout_weight="1"
            android:text="@string/hard" />
    </LinearLayout>
```

Add `easy`, `medium`, and `hard` to `strings.xml`. For the second part, change the middle button's `android:layout_weight` to `2`: the row is now four shares, and Medium takes two. Widths must be `0dp` for weights to divide the space exactly. With `wrap_content`, the weights only share out whatever's left after each button takes its natural width, so "Medium" would end up a little wider than intended.
:::

### Exercise 3: Corners and bias

Using only constraints, put a small **v1.0** label in the bottom-right corner, 16dp from both edges. Then add a headline that's centered horizontally but sits 30% of the way down the screen instead of in the middle.

:::hint
A corner needs just two constraints. The headline needs all four, which centers it both ways; one more attribute shifts it vertically. A bias of 0.5 is the middle.
:::

:::solution
```xml
    <TextView
        android:id="@+id/versionText"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_marginEnd="16dp"
        android:layout_marginBottom="16dp"
        android:text="@string/version_label"
        app:layout_constraintBottom_toBottomOf="parent"
        app:layout_constraintEnd_toEndOf="parent" />

    <TextView
        android:id="@+id/headlineText"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="@string/headline"
        android:textSize="28sp"
        app:layout_constraintBottom_toBottomOf="parent"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintTop_toTopOf="parent"
        app:layout_constraintVertical_bias="0.3" />
```

The version label hugs a corner, so bottom and end are enough. The headline is pulled equally from all four sides, which centers it, and `layout_constraintVertical_bias="0.3"` slides it from the default 0.5 up to 0.3. A bias of 0 pins it to the top; 1 pins it to the bottom.
:::

### Exercise 4: A login form with the right keyboards

Build a login screen with an email field, a password field, and a full-width **Log in** button, stacked vertically. The email field should bring up a keyboard with an @ key, the password should be hidden as you type, and both should work with the phone's autofill. Use a `LinearLayout` as the root this time.

:::hint
Two attributes per field do the work: `inputType` picks the keyboard and masking, and `autofillHints` tells autofill what goes there. Remember where padding is safe in an Empty Views Activity project.
:::

:::solution
```xml
<?xml version="1.0" encoding="utf-8"?>
<LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools"
    android:id="@+id/main"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical"
    tools:context=".MainActivity">

    <LinearLayout
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:orientation="vertical"
        android:padding="24dp">

        <EditText
            android:id="@+id/emailInput"
            android:layout_width="match_parent"
            android:layout_height="wrap_content"
            android:autofillHints="emailAddress"
            android:hint="@string/email_hint"
            android:inputType="textEmailAddress" />

        <EditText
            android:id="@+id/passwordInput"
            android:layout_width="match_parent"
            android:layout_height="wrap_content"
            android:layout_marginTop="8dp"
            android:autofillHints="password"
            android:hint="@string/password_hint"
            android:inputType="textPassword" />

        <Button
            android:id="@+id/loginButton"
            android:layout_width="match_parent"
            android:layout_height="wrap_content"
            android:layout_marginTop="16dp"
            android:text="@string/log_in" />
    </LinearLayout>

</LinearLayout>
```

The padding sits on the inner `LinearLayout`, because the template's `MainActivity` overwrites the root's padding with the system-bar sizes. No `app:` namespace is needed, since nothing here uses a library attribute. Run it and tap each field to see the two different keyboards.
:::

### Exercise 5: A banner photo

Copy any landscape photo into `res/drawable` and name it `banner.jpg` (lowercase letters, digits, and underscores only). Show it across the full width of the screen at the top, 160dp tall, filling the area without stretching or squashing the picture. Then try `fitCenter` and `fitXY`, and describe the difference.

:::hint
Full width in a `ConstraintLayout` is `0dp` with start and end constraints. The attribute that decides how a picture fits its box is `android:scaleType`, and the value you want fills the box and trims what spills over.
:::

:::solution
```xml
    <ImageView
        android:id="@+id/bannerImage"
        android:layout_width="0dp"
        android:layout_height="160dp"
        android:contentDescription="@string/banner_description"
        android:scaleType="centerCrop"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintTop_toTopOf="parent"
        app:srcCompat="@drawable/banner" />
```

The reference is `@drawable/banner`, without `.jpg`.

-   `centerCrop` scales the photo until it covers the whole box, then trims the overflow. No empty space, no distortion.
-   `fitCenter` shrinks the photo until all of it fits, which leaves empty bands at the sides or the top and bottom.
-   `fitXY` stretches it to the box's exact shape, which squashes faces and turns circles into ovals. You'll rarely want it for photos.
:::

### Exercise 6: Why is everything in the corner?

A classmate's preview looks fine in Design view, but on the phone both views pile up in the top-left corner, on top of each other. Android Studio shows a red error on each. Explain why, then fix it so the title is centered near the top and the button sits under it.

```xml
    <TextView
        android:id="@+id/titleText"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="@string/headline"
        tools:layout_editor_absoluteX="120dp"
        tools:layout_editor_absoluteY="80dp" />

    <Button
        android:id="@+id/startButton"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="@string/start"
        tools:layout_editor_absoluteX="150dp"
        tools:layout_editor_absoluteY="140dp" />
```

:::video XamMbnzI5vE
An Android Developers episode on building a layout by drawing constraints in the Design view. It's from an older Android Studio, but watch the moment a view gets its first constraint handle connected: that's the step your classmate skipped when they dragged views around.
:::

:::hint
Look at the namespace on the position attributes. What happens to `tools:` attributes when the app is built?
:::

:::solution
The error reads: `This view is not constrained. It only has designtime positions, so it will jump to (0,0) at runtime unless you add the constraints`. The `tools:layout_editor_absoluteX/Y` attributes appear when you drag views in Design view without connecting their edges. Like every `tools:` attribute, they only affect the preview and are thrown away in the real app.

Remove them and add real constraints:

```xml
    <TextView
        android:id="@+id/titleText"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_marginTop="80dp"
        android:text="@string/headline"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintTop_toTopOf="parent" />

    <Button
        android:id="@+id/startButton"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_marginTop="16dp"
        android:text="@string/start"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintTop_toBottomOf="@id/titleText" />
```

Each view now has a horizontal pair (start and end, which centers it) and a vertical constraint, so the phone puts it exactly where the preview does.
:::

### Challenge: A Spanish business card

Make your Week 3 business card appear in Spanish when the phone's language is Spanish, without touching the layout. The name and email should stay the same in every language.

```mermaid caption="How Android picks a string when the phone is set to Spanish"
flowchart TD
    A["Layout asks for @string/save_contact"] --> B{"Does values-es define it?"}
    B -->|yes| C["Guardar contacto"]
    B -->|no| D["Fall back to values: Save contact"]
```

:::hint
You need a second `strings.xml` in a folder named for the language, created with the **Locale** qualifier. It should define only the strings that change. Strings that must never be translated can say so with an attribute in the default file.
:::

:::solution
First, mark the strings that should never be translated. In `res/values/strings.xml`, add `translatable="false"`:

```xml
    <string name="card_name" translatable="false">Maya Patel</string>
    <string name="card_email" translatable="false">maya@example.com</string>
```

Next, make the Spanish file: right-click `res`, choose **New > Android Resource File**, enter the file name `strings`, set **Resource type** to **Values**, add the **Locale** qualifier, and pick **es: Spanish**. That creates `res/values-es/strings.xml`. Fill it in:

```xml
<?xml version="1.0" encoding="utf-8"?>
<resources>
    <string name="app_name">Tarjeta de presentación</string>
    <string name="card_title">Desarrolladora de Android en formación</string>
    <string name="card_location">San José, California</string>
    <string name="avatar_description">Foto de perfil de Maya Patel</string>
    <string name="note_hint">Añade una nota sobre este contacto</string>
    <string name="save_contact">Guardar contacto</string>
</resources>
```

On the device, open **Settings > System > Languages** (the exact path varies a little by phone), add **Español**, and drag it to the top. Run the app: every translated string switches, while the name and email come from the default `values` folder, because Android falls back to it for anything a language folder doesn't define. To see both languages side by side, open `strings.xml` and click **Open editor** in the banner at the top to launch the **Translations Editor**.
:::
