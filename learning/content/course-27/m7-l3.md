These exercises mix new apps with the Quick Note app from the code-along. Plain Java parts can be compiled and run with `javac` and `java` so you can check your logic before moving it into Android Studio. Debugging exercises are about the *process*, so write down what you see at each step, not just the fix.

### Exercise 1: Welcome back

Make an app with an `EditText`, a "Save name" button, and a `TextView`. The first time it opens, the TextView says `Hello, stranger!`. After you save `Ana` and reopen the app (swipe it away first), it says `Welcome back, Ana!`.

:::solution
```java
private static final String PREFS_NAME = "profile";
private static final String KEY_NAME = "name";

// in onCreate, after the template code:
SharedPreferences prefs = getSharedPreferences(PREFS_NAME, MODE_PRIVATE);
EditText nameInput = findViewById(R.id.name_input);
TextView welcomeText = findViewById(R.id.welcome_text);
Button saveButton = findViewById(R.id.save_button);

String savedName = prefs.getString(KEY_NAME, "");
if (savedName.isEmpty()) {
    welcomeText.setText("Hello, stranger!");
} else {
    welcomeText.setText("Welcome back, " + savedName + "!");
}

saveButton.setOnClickListener(v -> {
    String name = nameInput.getText().toString().trim();
    if (name.isEmpty()) {
        nameInput.setError("Type a name");
        return;
    }
    prefs.edit().putString(KEY_NAME, name).apply();
    Toast.makeText(this, "Saved!", Toast.LENGTH_SHORT).show();
});
```

After saving `Ana` and reopening:

```text
Welcome back, Ana!
```

Imports: `android.content.SharedPreferences`, `android.widget.Toast`, plus the usual widgets.
:::

### Exercise 2: "Saved 1 times"

The Quick Note status line says `Saved 1 times`. Write a method `label(int count)` that returns `Not saved yet` for 0, `Saved 1 time` for 1, and `Saved N times` otherwise. Test it in plain Java, then use it in `showSaveCount()`.

:::solution
```java
public class SaveLabel {

    static String label(int count) {
        if (count == 0) {
            return "Not saved yet";
        } else if (count == 1) {
            return "Saved 1 time";
        } else {
            return "Saved " + count + " times";
        }
    }

    public static void main(String[] args) {
        System.out.println(label(0));
        System.out.println(label(1));
        System.out.println(label(5));
    }
}
```

```text
Not saved yet
Saved 1 time
Saved 5 times
```

In `MainActivity`, paste `label` as a `private` method and change `showSaveCount()` to `statusText.setText(label(prefs.getInt(KEY_SAVE_COUNT, 0)));`. (Android also has *plurals* resources for this, which matter once you translate your app.)
:::

### Exercise 3: Read the crash

A student's age app crashes when they tap **Check** with an empty box. Logcat shows:

```text
FATAL EXCEPTION: main
Process: com.example.agecheck, PID: 9412
java.lang.NumberFormatException: For input string: ""
	at java.lang.Integer.parseInt(Integer.java:627)
	at java.lang.Integer.parseInt(Integer.java:650)
	at com.example.agecheck.MainActivity.checkAge(MainActivity.java:47)
	at com.example.agecheck.MainActivity.lambda$onCreate$0(MainActivity.java:38)
	at android.view.View.performClick(View.java:7659)
```

Answer three questions: What went wrong? On which line of *their* code? How would you fix it?

:::solution
1.  **What:** `NumberFormatException: For input string: ""`. `Integer.parseInt` was given an empty string, which isn't a number.
2.  **Where:** the first line from their own package, `MainActivity.checkAge(MainActivity.java:47)`. The line below it, `lambda$onCreate$0 ... :38`, is the click listener in `onCreate` that called `checkAge`. The `java.lang.Integer` and `android.view.View` lines are library code; skip them.
3.  **Fix:** catch the exception and show an error instead of crashing:

```java
private void checkAge() {
    String text = ageInput.getText().toString().trim();
    int age;
    try {
        age = Integer.parseInt(text);
    } catch (NumberFormatException e) {
        ageInput.setError("Enter your age as a number");
        return;
    }
    resultText.setText(age >= 16 ? "You can apply!" : "Not yet, but soon.");
}
```

The exact framework line numbers (`627`, `7659`) depend on the Android version, which is another reason to look for your own package name.
:::

### Exercise 4: Step through a wrong answer

This method should average three quiz scores, but it prints the wrong value and never crashes:

```java
public class ScoreAverage {

    static double average(int[] scores) {
        int sum = 0;
        for (int i = 1; i < scores.length; i++) {
            sum += scores[i];
        }
        return (double) sum / scores.length;
    }

    public static void main(String[] args) {
        int[] scores = {90, 80, 70};
        System.out.println("Average: " + average(scores));
    }
}
```

```text
Average: 50.0
```

Paste `average` into an Android app (call it from a button and show the result). Put a breakpoint on `sum += scores[i];`, debug, and watch `i` and `sum` in the Variables pane each time you press Resume. Find the bug.

:::solution
At the first stop, `i` is already `1` and `sum` is `0`. The values you see are `i = 1, sum = 0`, then `i = 2, sum = 80`, and the loop ends with `sum = 150`. The score at index 0 (`90`) is never added: `150 / 3 = 50`. Arrays start at 0, so the loop must too:

```java
for (int i = 0; i < scores.length; i++) {
    sum += scores[i];
}
```

```text
Average: 80.0
```

Logcat alone wouldn't have shown this, because nothing crashed. Watching the variables change is what revealed that one value was skipped.
:::

### Exercise 5: A setting that sticks

Add a `CheckBox` labeled "Auto-save when I leave" to Quick Note. Its checked state should be saved the moment it changes, and `onPause` should only auto-save when it's checked.

:::solution
Layout:

```xml
<CheckBox
    android:id="@+id/autosave_check"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Auto-save when I leave" />
```

Java (add `private static final String KEY_AUTOSAVE = "autosave";` and a field `private CheckBox autosaveCheck;`):

```java
autosaveCheck = findViewById(R.id.autosave_check);
autosaveCheck.setChecked(prefs.getBoolean(KEY_AUTOSAVE, true));
autosaveCheck.setOnCheckedChangeListener((buttonView, isChecked) ->
        prefs.edit().putBoolean(KEY_AUTOSAVE, isChecked).apply());
```

```java
@Override
protected void onPause() {
    super.onPause();
    if (autosaveCheck.isChecked()) {
        prefs.edit().putString(KEY_NOTE, noteInput.getText().toString()).apply();
        Log.d(TAG, "Auto-saved in onPause");
    }
}
```

Import `android.widget.CheckBox`. Calling `setChecked` **before** attaching the listener avoids an extra, pointless save at startup.
:::

### Exercise 6: A signed release APK

Produce a release APK of Quick Note signed with your own key, install it on a phone, and write down where your keystore lives.

:::solution
1.  **Build > Generate Signed Bundle / APK**, choose **APK**, click **Next**.
2.  Under **Key store path**, click **Create new...**. Save it *outside* your project folder, for example in a `keys` folder in your Documents, as `quicknote.jks`.
3.  Fill in a keystore password, a key alias (like `upload`), a key password, and at least your name under **Certificate**. Click **OK**, then **Next**.
4.  Pick the **release** build variant and click **Create**.
5.  When the popup appears, click **locate**. The file is `app/release/app-release.apk`.

If the phone already has the *debug* version installed, uninstall it first: the two are signed with different keys, so Android won't let one update the other. Keeping the keystore outside the project means you won't accidentally upload it to GitHub.
:::

## Stretch challenge: save a whole list

SharedPreferences only stores simple values, but a to-do list is a `List<String>`. Write `encode(List<String>)` that turns it into one `String`, and `decode(String)` that turns it back, then use them to save and load a list. Assume items never contain a newline.

:::solution
```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class TodoCodec {

    static String encode(List<String> items) {
        return String.join("\n", items);
    }

    static List<String> decode(String saved) {
        List<String> items = new ArrayList<>();
        if (saved == null || saved.isEmpty()) {
            return items;
        }
        items.addAll(Arrays.asList(saved.split("\n")));
        return items;
    }

    public static void main(String[] args) {
        List<String> todos = new ArrayList<>();
        todos.add("Study for quiz");
        todos.add("Call grandma");
        todos.add("Practice piano");

        String saved = encode(todos);
        System.out.println("Saved string has " + saved.length() + " characters");

        List<String> loaded = decode(saved);
        System.out.println("Loaded " + loaded.size() + " items: " + loaded);
        System.out.println("Empty save loads " + decode("").size() + " items");
    }
}
```

```text
Saved string has 42 characters
Loaded 3 items: [Study for quiz, Call grandma, Practice piano]
Empty save loads 0 items
```

In the app: `prefs.edit().putString("todos", encode(todos)).apply();` to save and `decode(prefs.getString("todos", ""))` to load. The empty-string check matters: `"".split("\n")` returns one empty item, not zero, so without it a fresh install would show a blank row. There's also `putStringSet`, but a `Set` forgets the order of your list.
:::
