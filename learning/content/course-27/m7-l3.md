summary: Save names, counts, and settings with SharedPreferences, read a real crash trace, step through a logic bug, produce a signed release APK, and save a whole list as a challenge.

:::objectives
- Save and reload text, numbers, and true-or-false settings with SharedPreferences.
- Read a stack trace and name the exact line in your own code that failed.
- Use breakpoints to find a bug that gives a wrong answer without crashing.
- Create a keystore and build a signed release APK.
- Store a whole list in SharedPreferences by turning it into one string.
:::

These exercises mix new apps with the Quick Note app from the code-along. Anything marked as plain Java runs right on this page, so you can check your logic before moving it into Android Studio. The debugging exercises are about the *process*: write down what you see at each step, not only the fix.

**Warm-up.** On a brand-new install, nothing has been saved yet. Predict what each of these returns, then check against the answers in brackets: `prefs.getString("name", "")` [an empty string], `prefs.getInt("high_score", 0)` [0], `prefs.getBoolean("sound_on", true)` [true]. On a first launch, the default is always the answer.

### Exercise 1: "Saved 1 times"

The Quick Note status line says `Saved 1 times`. Write a method `label(int count)` that returns these three answers, test it in plain Java, then use it in `showSaveCount()`:

```text
Not saved yet
Saved 1 time
Saved 5 times
```

:::hint
Three cases means an `if`, an `else if`, and an `else`. Check the special cases (0 and 1) before the general one.
:::

:::solution
```java run title="SaveLabel.java"
public class SaveLabel {

    static String label(int count) {
        if (count == 0) {
            return "Not saved yet";
        } else if (count == 1) {
            return "Saved 1 time";
        } else {
            return "Saved " + count + " times";
        }
    }

    public static void main(String[] args) {
        System.out.println(label(0));
        System.out.println(label(1));
        System.out.println(label(5));
    }
}
```

In `MainActivity`, paste `label` in as a `private` method (without `static`) and change `showSaveCount()` to `statusText.setText(label(prefs.getInt(KEY_SAVE_COUNT, 0)));`. Android also has **plurals** resources in XML for exactly this problem; they matter once you translate an app, because other languages have different rules for "1 time" versus "2 times."
:::

### Exercise 2: Welcome back

Make an app with an `EditText`, a **Save name** button, and a `TextView`. The first time it opens, the TextView says `Hello, stranger!`. After you save `Ana`, swipe the app away, and reopen it, it says:

```text
Welcome back, Ana!
```

:::hint
Read the saved name in `onCreate` with an empty-string default, and pick the greeting based on whether it's empty. Saving happens in the button's listener. Don't forget the last call in the save chain.
:::

:::solution
```java
private static final String PREFS_NAME = "profile";
private static final String KEY_NAME = "name";

// in onCreate, after the template code:
SharedPreferences prefs = getSharedPreferences(PREFS_NAME, MODE_PRIVATE);
EditText nameInput = findViewById(R.id.name_input);
TextView welcomeText = findViewById(R.id.welcome_text);
Button saveButton = findViewById(R.id.save_button);

String savedName = prefs.getString(KEY_NAME, "");
if (savedName.isEmpty()) {
    welcomeText.setText("Hello, stranger!");
} else {
    welcomeText.setText("Welcome back, " + savedName + "!");
}

saveButton.setOnClickListener(v -> {
    String name = nameInput.getText().toString().trim();
    if (name.isEmpty()) {
        nameInput.setError("Type a name");
        return;
    }
    prefs.edit().putString(KEY_NAME, name).apply();
    Toast.makeText(this, "Saved!", Toast.LENGTH_SHORT).show();
});
```

You'll need imports for `SharedPreferences`, `Toast`, and the three widgets. The greeting only changes on the *next* launch, because it's chosen in `onCreate`. For an instant update, also call `welcomeText.setText(...)` inside the listener.
:::

### Exercise 3: Read the crash

A classmate's age app crashes when they tap **Check** with the box empty. Logcat shows:

```text
FATAL EXCEPTION: main
Process: com.example.agecheck, PID: 9412
java.lang.NumberFormatException: For input string: ""
	at java.lang.Integer.parseInt(Integer.java:627)
	at java.lang.Integer.parseInt(Integer.java:650)
	at com.example.agecheck.MainActivity.checkAge(MainActivity.java:47)
	at com.example.agecheck.MainActivity.lambda$onCreate$0(MainActivity.java:38)
	at android.view.View.performClick(View.java:7659)
```

Answer three questions: What went wrong? On which line of *their* code? How would you fix it?

:::hint
The exception's name and message are on the third line. For the location, skip every line that starts with `java.` or `android.` and look for the first one with their package name.
:::

:::solution
1.  **What:** `NumberFormatException: For input string: ""`. `Integer.parseInt` was handed an empty string, which isn't a number.
2.  **Where:** the first line from their own package, `MainActivity.checkAge(MainActivity.java:47)`. The next line, `lambda$onCreate$0 ... :38`, is the click listener in `onCreate` that called `checkAge`. The `java.lang.Integer` and `android.view.View` lines are library code.
3.  **Fix:** catch the exception and show an error instead of crashing:

```java
private void checkAge() {
    String text = ageInput.getText().toString().trim();
    int age;
    try {
        age = Integer.parseInt(text);
    } catch (NumberFormatException e) {
        ageInput.setError("Enter your age as a number");
        return;
    }
    resultText.setText(age >= 16 ? "You can apply!" : "Not yet, but soon.");
}
```

The framework line numbers (`627`, `7659`) change with the Android version, which is one more reason to look for your own package name instead.
:::

### Exercise 4: Step through a wrong answer

This program should average three quiz scores. Run it: it prints the wrong value, and nothing crashes.

```java run title="ScoreAverage.java"
public class ScoreAverage {

    static double average(int[] scores) {
        int sum = 0;
        for (int i = 1; i < scores.length; i++) {
            sum += scores[i];
        }
        return (double) sum / scores.length;
    }

    public static void main(String[] args) {
        int[] scores = {90, 80, 70};
        System.out.println("Average: " + average(scores));
    }
}
```

The right answer is `80.0`. Paste `average` into an Android app (call it from a button and show the result in a TextView). Put a breakpoint on `sum += scores[i];`, start with **Debug 'app'**, and write down `i` and `sum` from the Variables pane each time it stops. Then find the bug.

:::hint
Look at the value of `i` the very first time the breakpoint stops. Which index of the array is that, and which score lives at index 0?
:::

:::solution
At the first stop, `i` is already `1` and `sum` is `0`. At the second stop, `i = 2` and `sum = 80`. Then the loop ends with `sum = 150`. The score at index 0 (`90`) is never added, so the method divides `150 / 3` and gets `50`. Arrays start at 0, so the loop must too:

```java run title="ScoreAverageFixed.java"
public class ScoreAverageFixed {

    static double average(int[] scores) {
        int sum = 0;
        for (int i = 0; i < scores.length; i++) {
            sum += scores[i];
        }
        return (double) sum / scores.length;
    }

    public static void main(String[] args) {
        int[] scores = {90, 80, 70};
        System.out.println("Average: " + average(scores));
    }
}
```

Logcat alone wouldn't have caught this, because nothing crashed and no error was printed. Watching the variables change is what showed that one value was skipped.
:::

### Exercise 5: A setting that sticks

Add a `CheckBox` labeled "Auto-save when I leave" to Quick Note. Its checked state must be saved the moment it changes, so it's still ticked (or unticked) next launch, and `onPause` should only auto-save the note when it's ticked.

:::hint
A `CheckBox` has `setChecked`, `isChecked`, and `setOnCheckedChangeListener`. Load the saved value with `getBoolean` before you attach the listener.
:::

:::solution
In the layout, above the buttons:

```xml
<CheckBox
    android:id="@+id/autosave_check"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Auto-save when I leave" />
```

Add `private static final String KEY_AUTOSAVE = "autosave";` and a field `private CheckBox autosaveCheck;`, then in `onCreate`:

```java
autosaveCheck = findViewById(R.id.autosave_check);
autosaveCheck.setChecked(prefs.getBoolean(KEY_AUTOSAVE, true));
autosaveCheck.setOnCheckedChangeListener((buttonView, isChecked) ->
        prefs.edit().putBoolean(KEY_AUTOSAVE, isChecked).apply());
```

And change `onPause`:

```java
@Override
protected void onPause() {
    super.onPause();
    if (autosaveCheck.isChecked()) {
        prefs.edit().putString(KEY_NOTE, noteInput.getText().toString()).apply();
        Log.d(TAG, "Auto-saved in onPause");
    }
}
```

Import `android.widget.CheckBox`. Calling `setChecked` **before** attaching the listener avoids a pointless save at every startup, since the listener would fire for that first `setChecked` too.
:::

### Exercise 6: A signed release APK

Produce a release APK of Quick Note signed with your own key, install it on a phone, and write down where your keystore lives. This walkthrough shows the wizard you'll use:

:::video yoHDdnnofeE
What to watch for: the **Create new** keystore form and the build variant step where you pick **release**. Your version of Android Studio may label the menu item slightly differently.
:::

:::hint
The wizard is under the **Build** menu, with "Signed" in its name. Save the keystore somewhere outside the project folder, so it can't end up on GitHub by accident.
:::

:::solution
1.  Choose **Build > Generate Signed App Bundle or APK** (older versions: **Generate Signed Bundle / APK**), select **APK**, and click **Next**.
2.  Under **Key store path**, click **Create new**. Choose a location *outside* your project folder, such as a `keys` folder in Documents, and name the file `quicknote.jks`.
3.  Fill in a keystore password, a key **Alias** (like `upload`), a key password (Android's docs suggest using the same one as the keystore), and at least your name under **Certificate**. Leave **Validity (years)** at 25 or more. Click **OK**, then **Next**.
4.  Pick the **release** build variant and click **Create**.
5.  When the popup appears, click **locate**. The file is `app/release/app-release.apk`.

If the phone already has the *debug* version, uninstall it first. The two are signed with different keys, so Android refuses to let one replace the other; the phone says the app wasn't installed because it conflicts with an existing package, and `adb` reports `INSTALL_FAILED_UPDATE_INCOMPATIBLE`. Newer Android Studio versions may also show a developer verification status for your package name in the wizard; that matters for publishing to the public, not for this exercise.
:::

### Challenge: save a whole list

SharedPreferences only stores simple values, but a to-do list is a `List<String>`. Write `encode(List<String>)`, which turns the list into one `String`, and `decode(String)`, which turns it back. Then use them to save and load a list in an app. You may assume no item contains a newline. Your test should print:

```text
Saved string has 42 characters
Loaded 3 items: [Study for quiz, Call grandma, Practice piano]
Empty save loads 0 items
```

:::hint
`String.join("\n", items)` glues a list together with newlines between items, and `split("\n")` cuts it apart again. Test the empty string separately: what does `"".split("\n")` give you?
:::

:::solution
```java run title="TodoCodec.java"
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class TodoCodec {

    static String encode(List<String> items) {
        return String.join("\n", items);
    }

    static List<String> decode(String saved) {
        List<String> items = new ArrayList<>();
        if (saved == null || saved.isEmpty()) {
            return items;
        }
        items.addAll(Arrays.asList(saved.split("\n")));
        return items;
    }

    public static void main(String[] args) {
        List<String> todos = new ArrayList<>();
        todos.add("Study for quiz");
        todos.add("Call grandma");
        todos.add("Practice piano");

        String saved = encode(todos);
        System.out.println("Saved string has " + saved.length() + " characters");

        List<String> loaded = decode(saved);
        System.out.println("Loaded " + loaded.size() + " items: " + loaded);
        System.out.println("Empty save loads " + decode("").size() + " items");
        System.out.println("Without the check, \"\".split gives " + "".split("\n").length + " item");
    }
}
```

The last line shows why the empty-string check exists: `"".split("\n")` returns one empty item, not zero, so without the check a fresh install would show one blank to-do. In the app, save with `prefs.edit().putString("todos", encode(todos)).apply();` and load with `decode(prefs.getString("todos", ""))`. SharedPreferences also has `putStringSet`, but a `Set` doesn't keep your list's order and drops duplicates.
:::
