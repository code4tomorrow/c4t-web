---
title: "Practice: app state, errors, and modules"
summary: Six exercises and a challenge on keeping state in one place, deriving values, writing update functions that refuse bad input, loading settings defensively, splitting code into modules, and showing error states with a retry.
---

:::objectives
- Move state out of the page and into an object that `render()` draws from.
- Derive totals instead of storing them, and keep money in whole cents.
- Write update functions that return new state and throw clear errors for bad input.
- Load saved data defensively, split code into modules, and give async work a proper error state.
:::

The Node exercises test pure logic, which is where state bugs are easiest to find. The browser ones are previews you can click, or files to run with Live Server.

## Warm-up: spot the problem

:::quiz
Q: A to-do app keeps a `todos` array and a separate `count` variable, adding 1 in the add handler and subtracting 1 in the delete handler. What's the risk?
- [ ] None, as long as both handlers are correct
  Today, maybe. The day someone adds "clear completed" and forgets `count`, the number on screen is wrong.
- [x] `count` can drift away from the real number of to-dos; it should be `todos.length`, worked out when needed
  A value you can calculate from other state shouldn't be stored. Then it can never disagree.
- [ ] Arrays can't be counted reliably, so the variable is needed
  `todos.length` is always exact.

Q: What is `name` after `const name = data.profile?.name ?? "Guest";` if `data` is `{ profile: { name: "" } }`?
- [x] `""`, an empty string
  `??` only steps in for `null` or `undefined`. An empty string is a real value, so it's kept.
- [ ] `"Guest"`
  That's what `||` would give, since `""` is falsy.
- [ ] `undefined`
  `profile` exists, so `?.` carries on and reads `name`.
:::

### Exercise 1: Stop keeping the count in the page

This counter "works", but the page itself is the state: every handler reads the number back out of the text. Now the counter needs to show whether the count is even or odd, and the best count reached so far. Rewrite it with a `state` object and a `render()` function, then add both.

```html preview height="130" title="counter-before.html"
<p>Count: <span id="count">0</span></p>
<button id="add">+1</button>
<button id="double">Double</button>
<button id="reset">Reset</button>
<script>
  const countEl = document.querySelector("#count");
  document.querySelector("#add").addEventListener("click", () => {
    countEl.textContent = Number(countEl.textContent) + 1;
  });
  document.querySelector("#double").addEventListener("click", () => {
    countEl.textContent = countEl.textContent * 2;
  });
  document.querySelector("#reset").addEventListener("click", () => {
    countEl.textContent = "0";
  });
</script>
<style>
  body { font-family: system-ui, sans-serif; margin: 12px; font-size: 18px; }
  button { font-size: 16px; padding: 6px 14px; }
</style>
```

:::hint
Try the quick way first: put "(even)" inside the same `span` and watch `Number(countEl.textContent)` turn into `NaN`. That's why the page shouldn't be the state. Is "even or odd" a fact you store, or something you work out? What about "best so far"?
:::

:::solution
```html preview height="150" title="counter-after.html"
<p>Count: <strong id="count"></strong> (<span id="parity"></span>) · Best: <span id="best"></span></p>
<button id="add">+1</button>
<button id="double">Double</button>
<button id="reset">Reset</button>
<script>
  const state = { count: 0, best: 0 };

  function render() {
    document.querySelector("#count").textContent = state.count;
    document.querySelector("#parity").textContent = state.count % 2 === 0 ? "even" : "odd";
    document.querySelector("#best").textContent = state.best;
  }

  function setCount(value) {
    state.count = value;
    state.best = Math.max(state.best, value);
    render();
  }

  document.querySelector("#add").addEventListener("click", () => setCount(state.count + 1));
  document.querySelector("#double").addEventListener("click", () => setCount(state.count * 2));
  document.querySelector("#reset").addEventListener("click", () => setCount(0));

  render();
</script>
<style>
  body { font-family: system-ui, sans-serif; margin: 12px; font-size: 18px; }
  button { font-size: 16px; padding: 6px 14px; }
</style>
```

"Even or odd" is derived from `count` every time `render()` runs, so it's never stored. "Best" has to be stored, because once the count drops you can't work out what it used to be. All three buttons go through `setCount`, so `best` can't be forgotten by one of them.
:::

### Exercise 2: Work out the cart totals

Write `cartSummary(items)` for a shop cart. Each item has a `priceCents` and a `qty`. Return the number of items, the subtotal, an 8% tax rounded to the nearest cent, and the total, all in **cents**. An empty cart should give zeros, not `NaN`. Then print it as money.

```text
3 items: $13.47 + $1.08 tax = $14.55
{ count: 0, subtotal: 0, tax: 0, total: 0 }
```

:::hint
Loop once, adding `item.qty` to a count and `item.priceCents * item.qty` to a subtotal. Round the tax with `Math.round`. Keep everything in whole cents until the last moment, then divide by 100 and use `toFixed(2)` only to display it.
:::

:::solution
```javascript run title="cart.js"
const TAX_RATE = 0.08;

function cartSummary(items) {
  let count = 0;
  let subtotal = 0;
  for (const item of items) {
    count = count + item.qty;
    subtotal = subtotal + item.priceCents * item.qty;
  }
  const tax = Math.round(subtotal * TAX_RATE);
  return { count, subtotal, tax, total: subtotal + tax };
}

const money = (cents) => `$${(cents / 100).toFixed(2)}`;

const cart = [
  { name: "Notebook", priceCents: 399, qty: 2 },
  { name: "Pens (10 pack)", priceCents: 549, qty: 1 },
];

const s = cartSummary(cart);
console.log(`${s.count} items: ${money(s.subtotal)} + ${money(s.tax)} tax = ${money(s.total)}`);
console.log(cartSummary([]));
```

Only `items` is state. Count, subtotal, tax, and total are all derived, so changing a quantity can't leave a stale total on screen. An empty cart works with no special case, because the loop just never runs.
:::

### Exercise 3: Update functions that say no

Write `addTask(state, text)` and `toggleTask(state, id)` for a to-do list whose state is `{ tasks: [], nextId: 1 }`. Both return a **new** state and leave the old one untouched. `addTask` trims the text and throws an error for empty text or a duplicate (ignoring capital letters). `toggleTask` throws if there's no task with that id.

```text
[
  { id: 1, text: 'Read chapter 4', done: true },
  { id: 2, text: 'Math worksheet', done: false }
]
old state unchanged: false
Refused: A task needs some text.
Refused: "math WORKSHEET" is already on the list.
Refused: No task with id 9.
```

:::hint
`array.some((t) => …)` is `true` if any item passes the test, which is perfect for the duplicate and "does this id exist" checks. For a new array with one item changed, use `map` and return `{ ...t, done: !t.done }` for the matching task and `t` for the rest. Spread (`[...state.tasks, task]`) adds to a copy instead of pushing onto the original.
:::

:::solution
```javascript run title="tasks.js"
function createState() {
  return { tasks: [], nextId: 1 };
}

function addTask(state, text) {
  const clean = text.trim();
  if (clean === "") throw new Error("A task needs some text.");
  const duplicate = state.tasks.some((t) => t.text.toLowerCase() === clean.toLowerCase());
  if (duplicate) throw new Error(`"${clean}" is already on the list.`);
  const task = { id: state.nextId, text: clean, done: false };
  return { tasks: [...state.tasks, task], nextId: state.nextId + 1 };
}

function toggleTask(state, id) {
  if (!state.tasks.some((t) => t.id === id)) throw new Error(`No task with id ${id}.`);
  return { ...state, tasks: state.tasks.map((t) => (t.id === id ? { ...t, done: !t.done } : t)) };
}

let state = createState();
state = addTask(state, "  Read chapter 4 ");
state = addTask(state, "Math worksheet");
const before = state;
state = toggleTask(state, 1);
console.log(state.tasks);
console.log("old state unchanged:", before.tasks[0].done);

const attempts = [
  () => addTask(state, "   "),
  () => addTask(state, "math WORKSHEET"),
  () => toggleTask(state, 9),
];
for (const attempt of attempts) {
  try {
    attempt();
  } catch (error) {
    console.log("Refused:", error.message);
  }
}
```

The `nextId` counter means ids are never reused, even after tasks are deleted. The error messages are written for people, so the form's submit handler can put `error.message` straight into a status line.
:::

### Exercise 4: Load settings you can't trust

Saved settings are `{ volume, theme, nickname }` with defaults `50`, `"light"`, and `"Player"`. Write `loadSettings(text)` that takes the saved JSON text and always returns a complete, valid settings object. `volume` must be a number from 0 to 100, `theme` must be `"light"` or `"dark"`, and `nickname` must be a non-empty string (trimmed). Anything else falls back to its default, one field at a time.

```text
null -> { volume: 50, theme: 'light', nickname: 'Player' }
"{oops" -> { volume: 50, theme: 'light', nickname: 'Player' }
"{\"volume\":0,\"theme\":\"purple\"}" -> { volume: 0, theme: 'light', nickname: 'Player' }
"{\"volume\":\"loud\",\"nickname\":\" Sam \"}" -> { volume: 50, theme: 'light', nickname: 'Sam' }
```

:::hint
Parse inside `try`, and return the defaults if it throws or gives something that isn't an object (`JSON.parse("null")` is `null`). Then check each field on its own with `typeof` or `Number.isFinite`. A volume of `0` must survive, which rules out `saved.volume || 50`.
:::

:::solution
```javascript run title="settings.js"
const DEFAULTS = { volume: 50, theme: "light", nickname: "Player" };

function loadSettings(text) {
  let saved;
  try {
    saved = JSON.parse(text);
  } catch {
    return { ...DEFAULTS };
  }
  if (typeof saved !== "object" || saved === null) return { ...DEFAULTS };

  const volumeOk = Number.isFinite(saved.volume) && saved.volume >= 0 && saved.volume <= 100;
  const themeOk = saved.theme === "light" || saved.theme === "dark";
  const nicknameOk = typeof saved.nickname === "string" && saved.nickname.trim() !== "";

  return {
    volume: volumeOk ? saved.volume : DEFAULTS.volume,
    theme: themeOk ? saved.theme : DEFAULTS.theme,
    nickname: nicknameOk ? saved.nickname.trim() : DEFAULTS.nickname,
  };
}

const samples = [null, "{oops", '{"volume":0,"theme":"purple"}', '{"volume":"loud","nickname":" Sam "}'];
for (const text of samples) {
  console.log(JSON.stringify(text), "->", loadSettings(text));
}
```

Checking each field separately means one bad value (a purple theme) doesn't throw away the good ones (a volume of 0). In the browser, call it as `loadSettings(localStorage.getItem("settings"))`, inside the same `try` you'd use for any storage access.
:::

### Exercise 5: Split a file into modules

Split this one-file shop page into `cart.js` (the logic, with no page code) and `main.js` (everything that touches the page). Then answer three questions: what happens if you forget `export` on `cartTotal`, if you write `from "./cart"` without `.js`, and if you double-click `index.html` instead of using Live Server?

```javascript title="script.js"
let cart = [];

function addItem(cart, name, priceCents) {
  return [...cart, { name, priceCents }];
}

function cartTotal(cart) {
  let total = 0;
  for (const item of cart) total = total + item.priceCents;
  return total;
}

function formatMoney(cents) {
  return `$${(cents / 100).toFixed(2)}`;
}

const list = document.querySelector("#list");
const totalEl = document.querySelector("#total");

function render() {
  const items = cart.map((item) => {
    const li = document.createElement("li");
    li.textContent = `${item.name}: ${formatMoney(item.priceCents)}`;
    return li;
  });
  list.replaceChildren(...items);
  totalEl.textContent = formatMoney(cartTotal(cart));
}

document.querySelector("#add-apple").addEventListener("click", () => {
  cart = addItem(cart, "Apple", 75);
  render();
});

render();
```

:::hint
Ask of each function: does it use `document`? If not, it belongs in `cart.js` and gets `export`. The `cart` variable is state, so it lives in `main.js` with the code that changes it. Don't forget to change the script tag.
:::

:::solution
```javascript title="cart.js"
export function addItem(cart, name, priceCents) {
  return [...cart, { name, priceCents }];
}

export function cartTotal(cart) {
  let total = 0;
  for (const item of cart) total = total + item.priceCents;
  return total;
}

export function formatMoney(cents) {
  return `$${(cents / 100).toFixed(2)}`;
}
```

```javascript title="main.js"
import { addItem, cartTotal, formatMoney } from "./cart.js";

let cart = [];
const list = document.querySelector("#list");
const totalEl = document.querySelector("#total");

function render() {
  const items = cart.map((item) => {
    const li = document.createElement("li");
    li.textContent = `${item.name}: ${formatMoney(item.priceCents)}`;
    return li;
  });
  list.replaceChildren(...items);
  totalEl.textContent = formatMoney(cartTotal(cart));
}

document.querySelector("#add-apple").addEventListener("click", () => {
  cart = addItem(cart, "Apple", 75);
  render();
});

render();
```

```html title="index.html"
<script type="module" src="main.js"></script>
```

The three mistakes:

1. **No `export` on `cartTotal`:** `SyntaxError: The requested module './cart.js' does not provide an export named 'cartTotal'`, and none of `main.js` runs, not even the lines before the problem.
2. **`"./cart"` without `.js`:** the browser asks Live Server for a file literally called `cart`, gets a 404, and the Console shows a red `404 (Not Found)` error for that address. The Network panel shows the failed request too.
3. **Double-clicking the file:** the page opens from `file://`, and the Console reports that the script was "blocked by CORS policy". Modules need a server.
:::

### Exercise 6: Loading, error, and "Try again"

Build a page that loads a class list from a (fake) server. Track the request with a `status` field in state: `"idle"`, `"loading"`, `"error"`, or `"ready"`. Show a Load button when idle, "Loading…" while loading, the error with a **Try again** button on failure, and the list when ready. The fake server fails the first time and works the second, so you can see every state.

```mermaid caption="Every request moves through these states, and render() draws one screen per state"
stateDiagram-v2
    [*] --> idle
    idle --> loading: Load
    loading --> ready: data arrives
    loading --> error: request fails
    error --> loading: Try again
    ready --> loading: Reload
```

:::hint
Write a `load()` function that sets `status = "loading"` and renders, awaits the fake server inside `try`, and sets `"ready"` with the data or `"error"` with the message in `catch`, rendering again at the end. `render()` is a set of `if` branches, one per status. Use one click listener on the container with `data-action`, as in the quiz game.
:::

:::solution
```html preview height="210" title="class-list.html"
<div id="app"></div>
<script>
  // A fake server that fails on the first call and works after that.
  let calls = 0;
  function fetchClassList() {
    calls = calls + 1;
    return new Promise((resolve, reject) => {
      setTimeout(() => {
        if (calls === 1) reject(new Error("The server timed out"));
        else resolve(["Ada", "Grace", "Katherine", "Mark"]);
      }, 1000);
    });
  }

  const app = document.querySelector("#app");
  let state = { status: "idle", students: [], error: "" };

  async function load() {
    state = { ...state, status: "loading", error: "" };
    render();
    try {
      const students = await fetchClassList();
      state = { ...state, status: "ready", students };
    } catch (error) {
      state = { ...state, status: "error", error: error.message };
    }
    render();
  }

  function button(label, action) {
    const b = document.createElement("button");
    b.textContent = label;
    b.dataset.action = action;
    return b;
  }

  function render() {
    const p = document.createElement("p");
    if (state.status === "idle") {
      p.textContent = "The class list hasn't been loaded yet.";
      app.replaceChildren(p, button("Load class list", "load"));
    } else if (state.status === "loading") {
      p.textContent = "Loading…";
      app.replaceChildren(p);
    } else if (state.status === "error") {
      p.textContent = `Couldn't load the list: ${state.error}.`;
      p.className = "error";
      app.replaceChildren(p, button("Try again", "load"));
    } else {
      const list = document.createElement("ul");
      for (const name of state.students) {
        const li = document.createElement("li");
        li.textContent = name;
        list.append(li);
      }
      p.textContent = `${state.students.length} students`;
      app.replaceChildren(p, list, button("Reload", "load"));
    }
    app.querySelector("button")?.focus();
  }

  app.addEventListener("click", (event) => {
    if (event.target.closest("[data-action='load']")) load();
  });

  render();
</script>
<style>
  body { font-family: system-ui, sans-serif; margin: 12px; }
  button { font-size: 16px; padding: 6px 14px; }
  .error { color: #b3261e; font-weight: 600; }
</style>
```

Because `status` is a single field, the page can't be "loading" and "showing an error" at the same time, a mix that happens easily when you track `isLoading` and `hasError` as separate booleans. The diagram above is the whole design: every arrow is a line in `load()`, and every circle is a branch in `render()`.
:::

### Challenge: an Undo button

Add Undo to the to-do functions from Exercise 3. Keep a `history` array of earlier states; every successful update pushes the old state first, and `undo()` pops the most recent one back. Keep at most 20 entries. Then answer: why is this easy *because* `addTask` and `toggleTask` return new objects instead of changing the old one?

:::hint
Write `apply(update)`, which runs `update(state)` inside `try`, and only if it succeeds pushes the old state onto `history` and replaces `state`. `history.slice(-20)` keeps the last 20. If an update throws, nothing should be pushed.
:::

:::solution
```javascript run title="undo.js"
function addTask(state, text) {
  const clean = text.trim();
  if (clean === "") throw new Error("A task needs some text.");
  return { tasks: [...state.tasks, { id: state.nextId, text: clean, done: false }], nextId: state.nextId + 1 };
}

let state = { tasks: [], nextId: 1 };
let history = [];

function apply(update) {
  try {
    const next = update(state);
    history = [...history, state].slice(-20);
    state = next;
  } catch (error) {
    console.log("Refused:", error.message);
  }
}

function undo() {
  if (history.length === 0) {
    console.log("Nothing to undo");
    return;
  }
  state = history[history.length - 1];
  history = history.slice(0, -1);
}

const names = () => state.tasks.map((t) => t.text).join(", ") || "(empty)";

apply((s) => addTask(s, "Read"));
apply((s) => addTask(s, "Write"));
apply((s) => addTask(s, "   "));
console.log("now:", names());
undo();
console.log("after undo:", names());
undo();
undo();
console.log("after two more:", names());
```

Each old state is a separate object that nothing else changes, so keeping a reference to it is a perfect snapshot. If the update functions changed `state.tasks` in place, every entry in `history` would point at the same array and Undo would bring back the current list. The refused update didn't create a history entry, so Undo never steps back to a state that didn't change.
:::
