:::objectives
- Pick the right event for a job and read what you need from the event object.
- React to typing with `input` and to keys with `keydown`.
- Write a validation function that returns a helpful message, and test it with plain values.
- Handle a list of buttons with one delegated listener and `data-` attributes.
- Turn a click-only widget into a form that works with the Enter key.
:::

Exercises 1–3, 5, and 6 change a page: build each in a project folder with Live Server, then compare with the solution's live preview. Exercise 4 is plain JavaScript. The challenge submits a form, so it can only run in your own project. For the keyboard exercise, click inside a preview first so it receives your key presses.

## Warm-up: which event?

Name the event you'd listen for in each case, and the element you'd attach it to:

1.  A "characters left" counter under a comment box.
2.  A newsletter form that should work with the Enter key.
3.  A dropdown menu where picking a size updates the price.
4.  Pressing **Escape** closes a pop-up anywhere on the page.
5.  Twenty "Add to cart" buttons in a product grid that's redrawn whenever the filter changes.

:::solution
1.  `input` on the textarea: it fires after every change, including pastes.
2.  `submit` on the form, with `event.preventDefault()`: it catches both the button and Enter.
3.  `change` on the `select`: it fires once a choice is made.
4.  `keydown` on `document`, checking `event.key === "Escape"`: the key press can happen while focus is anywhere.
5.  One `click` listener on the grid's container, using `event.target.closest("button")`: the buttons are replaced on every redraw, but the container isn't.
:::

### Exercise 1: A theme switch

Make a button that switches a page between light and dark. Each click toggles a `dark` class on the `body`, changes the button's text between **Dark mode** and **Light mode**, and sets `aria-pressed` to `"true"` or `"false"`.

:::hint
`classList.toggle("dark")` returns `true` if it just added the class and `false` if it removed it. Store that in a variable and use it for both the text and `aria-pressed`. Remember that `setAttribute` needs a string: `String(isDark)`.
:::

:::solution
```html preview height="170" title="theme-switch.html"
<button id="theme" type="button" aria-pressed="false">Dark mode</button>
<p>Some text so you can see the change.</p>

<script>
  const themeButton = document.querySelector("#theme");

  themeButton.addEventListener("click", () => {
    const isDark = document.body.classList.toggle("dark");
    themeButton.textContent = isDark ? "Light mode" : "Dark mode";
    themeButton.setAttribute("aria-pressed", String(isDark));
  });
</script>
<style>
  body { font-family: system-ui, sans-serif; padding: 12px; transition: background 0.2s; }
  body.dark { background: #1e1e1e; color: #eee; }
  button { padding: 6px 14px; }
</style>
```

`isDark ? "Light mode" : "Dark mode"` is the **conditional operator**: a compact `if`/`else` that produces a value. It reads "if `isDark`, then this, otherwise that." An `if`/`else` that sets `textContent` in each branch works just as well.
:::

### Exercise 2: Keyboard shortcuts for a search box

Pressing **/** anywhere on the page should jump into the search box, like it does on many big websites. Pressing **Escape** while in the box should clear it and leave the box. Typing **/** inside the box must still type a slash.

:::hint
Listen for `keydown` on `document`. `document.activeElement` is the element that currently has focus. For **/**, only act when focus is *not* already in the box, and call `event.preventDefault()` so the slash isn't typed into it. For **Escape**, set the value to `""` and call `search.blur()`.
:::

:::solution
```html preview height="190" title="shortcuts.html"
<p>Click here first, then press <kbd>/</kbd> to search and <kbd>Esc</kbd> to leave.</p>
<label for="search">Search</label>
<input id="search" type="search" placeholder="Press / to search">
<p id="hint"></p>

<script>
  const search = document.querySelector("#search");

  document.addEventListener("keydown", (event) => {
    const inBox = document.activeElement === search;
    if (event.key === "/" && !inBox) {
      event.preventDefault();
      search.focus();
    } else if (event.key === "Escape" && inBox) {
      search.value = "";
      search.blur();
    }
  });
</script>
<style>
  body { font-family: system-ui, sans-serif; padding: 0 12px; }
  kbd { border: 1px solid #999; border-radius: 3px; padding: 0 4px; }
  input { font-size: 1rem; padding: 4px; }
</style>
```

`preventDefault` on a `keydown` stops the key's normal effect, which here would be typing a slash into the box that just got focus. Checking `inBox` first is what keeps the slash typeable when you're already searching.
:::

### Exercise 3: A live password checklist

Under a password box, show three rules: **at least 8 characters**, **contains a number**, and **contains a capital letter**. On every keystroke, each rule should say `Done:` or `Not yet:` in front of it and turn green when met. Store the rules as an array of objects, each with a `label` and a `test` function, and draw the list from that array.

:::hint
A property can hold a function: `{ label: "contains a number", test: (pw) => … }`. To check for a capital letter, loop over the characters and compare each with `char >= "A" && char <= "Z"`. Use `some`: `[...pw].some((char) => char >= "0" && char <= "9")` turns the string into an array of characters and asks whether any one passes.
:::

:::solution
```html preview height="220" title="password-checklist.html"
<label for="pw">New password</label>
<input id="pw" type="password" aria-describedby="rules">
<ul id="rules"></ul>

<script>
  const rules = [
    { label: "at least 8 characters", test: (pw) => pw.length >= 8 },
    { label: "contains a number", test: (pw) => [...pw].some((char) => char >= "0" && char <= "9") },
    { label: "contains a capital letter", test: (pw) => [...pw].some((char) => char >= "A" && char <= "Z") },
  ];

  const pwInput = document.querySelector("#pw");
  const ruleList = document.querySelector("#rules");

  function renderRules() {
    ruleList.replaceChildren();
    rules.forEach((rule) => {
      const met = rule.test(pwInput.value);
      const li = document.createElement("li");
      li.textContent = `${met ? "Done" : "Not yet"}: ${rule.label}`;
      li.classList.toggle("met", met);
      ruleList.append(li);
    });
  }

  pwInput.addEventListener("input", renderRules);
  renderRules();
</script>
<style>
  body { font-family: system-ui, sans-serif; padding: 0 12px; }
  input { font-size: 1rem; padding: 4px; }
  li { color: #555; }
  li.met { color: #1b5e20; font-weight: bold; }
</style>
```

Adding a fourth rule is one new line in the array; nothing else changes. That's the payoff of keeping rules as data. The words `Done` and `Not yet` matter as much as the color: they carry the meaning for anyone who can't see green.
:::

### Exercise 4: Validate an age

Write `ageProblem(text)` for a club open to ages 13 to 18. It takes the raw text from an input and returns a message, or `""` if the age is fine:

```javascript
console.log(JSON.stringify(ageProblem("")));
console.log(JSON.stringify(ageProblem("fifteen")));
console.log(JSON.stringify(ageProblem("14.5")));
console.log(JSON.stringify(ageProblem("12")));
console.log(JSON.stringify(ageProblem("19")));
console.log(JSON.stringify(ageProblem(" 16 ")));
```

```text
"Enter your age."
"Enter your age as a whole number, like 15."
"Enter your age as a whole number, like 15."
"You need to be 13 or older to join."
"This club is for students up to 18."
""
```

`JSON.stringify` in the tests just wraps each result in quotes, so an empty string is visible as `""`.

:::hint
Trim first, then check for empty. `Number("fifteen")` is `NaN`, and `Number.isInteger(value)` is `false` for both `NaN` and `14.5`, so one check handles both. Only then compare with 13 and 18.
:::

:::solution
```javascript run
function ageProblem(text) {
  const trimmed = text.trim();
  if (trimmed === "") {
    return "Enter your age.";
  }
  const age = Number(trimmed);
  if (!Number.isInteger(age)) {
    return "Enter your age as a whole number, like 15.";
  }
  if (age < 13) {
    return "You need to be 13 or older to join.";
  }
  if (age > 18) {
    return "This club is for students up to 18.";
  }
  return "";
}

console.log(JSON.stringify(ageProblem("")));
console.log(JSON.stringify(ageProblem("fifteen")));
console.log(JSON.stringify(ageProblem("14.5")));
console.log(JSON.stringify(ageProblem("12")));
console.log(JSON.stringify(ageProblem("19")));
console.log(JSON.stringify(ageProblem(" 16 ")));
```

Each `if` returns as soon as it finds a problem, so the checks run from most basic to most specific, and the age comparisons never see `NaN`. These separate `if` statements do the same job as an `else if` chain, because `return` stops the function.
:::

### Exercise 5: A chore list with one listener

Draw a list of chores from an array. Each chore has a **Done** button and a **Delete** button. Use a single click listener on the `ul`. Give every button a `data-action` (`"done"` or `"delete"`) and a `data-id`, and use them to decide what to change in the array before redrawing.

:::hint
In the listener: `const button = event.target.closest("button")`, return early if it's `null`, then read `button.dataset.action` and `Number(button.dataset.id)`. For **Done**, find the chore with `chores.find((chore) => chore.id === id)` and flip its `done`. For **Delete**, `filter` it out.
:::

:::solution
```html preview height="250" title="chores.html"
<ul id="chores"></ul>

<script>
  let chores = [
    { id: 1, text: "Feed the cat", done: false },
    { id: 2, text: "Take out recycling", done: true },
    { id: 3, text: "Empty the dishwasher", done: false },
  ];
  const list = document.querySelector("#chores");

  function makeButton(label, action, chore) {
    const button = document.createElement("button");
    button.type = "button";
    button.textContent = label;
    button.dataset.action = action;
    button.dataset.id = chore.id;
    button.setAttribute("aria-label", `${label}: ${chore.text}`);
    return button;
  }

  function render() {
    list.replaceChildren();
    chores.forEach((chore) => {
      const li = document.createElement("li");
      const text = document.createElement("span");
      text.textContent = chore.text;
      li.classList.toggle("done", chore.done);
      li.append(text, makeButton(chore.done ? "Undo" : "Done", "done", chore), makeButton("Delete", "delete", chore));
      list.append(li);
    });
  }

  list.addEventListener("click", (event) => {
    const button = event.target.closest("button");
    if (!button) {
      return;
    }
    const id = Number(button.dataset.id);
    if (button.dataset.action === "done") {
      const chore = chores.find((item) => item.id === id);
      chore.done = !chore.done;
    } else if (button.dataset.action === "delete") {
      chores = chores.filter((item) => item.id !== id);
    }
    render();
  });

  render();
</script>
<style>
  body { font-family: system-ui, sans-serif; padding: 0 12px; }
  ul { padding: 0; }
  li { list-style: none; display: flex; gap: 8px; align-items: center; padding: 6px 0; border-bottom: 1px solid #ddd; }
  li span { flex: 1; }
  li.done span { color: #888; text-decoration: line-through; }
</style>
```

`find` returns the first item that passes the test (or `undefined` if none does), which is exactly what you want when ids are unique. A `data-action` attribute lets one listener tell many kinds of button apart. Redrawing here does move keyboard focus off the button, which is fine for a short list; the to-do build showed how to avoid it when it matters.
:::

### Exercise 6: Search as you type

Show a list of eight school clubs and a search box above it. As the user types, show only clubs whose names contain the search text, ignoring capital letters. When nothing matches, show `No clubs match "chess".` (with whatever was typed) instead of an empty list. Show the number of matches, too.

```javascript
const clubs = ["Robotics", "Debate", "Chess", "Art", "Coding", "Drama", "Robotics Juniors", "Science Olympiad"];
```

:::hint
Use the `input` event. Lowercase both sides before comparing: `club.toLowerCase().includes(query.toLowerCase())`. Then reuse the render pattern from Module 3: clear the list, draw the matches, and check `length` for the empty message.
:::

:::solution
```html preview height="330" title="club-search.html"
<label for="q">Find a club</label>
<input id="q" type="search" aria-describedby="count">
<p id="count" aria-live="polite"></p>
<ul id="results"></ul>

<script>
  const clubs = ["Robotics", "Debate", "Chess", "Art", "Coding", "Drama", "Robotics Juniors", "Science Olympiad"];
  const queryBox = document.querySelector("#q");
  const count = document.querySelector("#count");
  const results = document.querySelector("#results");

  function render() {
    const query = queryBox.value.trim().toLowerCase();
    const matches = clubs.filter((club) => club.toLowerCase().includes(query));

    results.replaceChildren();
    if (matches.length === 0) {
      count.textContent = `No clubs match "${queryBox.value.trim()}".`;
      return;
    }
    count.textContent = `${matches.length} of ${clubs.length} clubs`;
    matches.forEach((club) => {
      const li = document.createElement("li");
      li.textContent = club;
      results.append(li);
    });
  }

  queryBox.addEventListener("input", render);
  render();
</script>
<style>
  body { font-family: system-ui, sans-serif; padding: 0 12px; }
  input { font-size: 1rem; padding: 4px; }
</style>
```

An empty search box gives the query `""`, and every string includes the empty string, so the full list shows when the page loads. `aria-live="polite"` on the count means screen reader users hear "3 of 8 clubs" as they type, without the reader interrupting itself on every keystroke. Notice the message uses `textContent`, so typing HTML into the box just displays it as text.
:::

### Challenge: Turn the to-do list into a real form

The to-do list from Module 3 only adds a task when you click **Add**. Upgrade it:

1.  Wrap the input and button in a `form`, so **Enter** adds a task. Handle `submit` and call `preventDefault`.
2.  Reject an empty task, and a task that's already on the list (ignoring capital letters), with a message under the input. Link the message with `aria-describedby`, set `aria-invalid`, and clear both when a task is added.
3.  Replace the per-checkbox listeners with **one** `change` listener on the `ul`, and add a **Delete** button to each task, handled by **one** `click` listener on the `ul`.

Since it submits a form, build and test this in your own project with Live Server.

:::video cOoP8-NPLSo
Kyle from Web Dev Simplified explains event delegation from scratch. Watch for how he checks what was clicked before acting, which is the job `closest` and `data-` attributes do in step 3.
:::

:::hint
Give each task an `id` so the delegated listeners can find it: store `nextId` and increase it after each add. Put `data-id` on both the checkbox and the Delete button. In the `change` listener, `event.target` is the checkbox, so `event.target.checked` is its new state. For the duplicate check, `todos.some((todo) => todo.text.toLowerCase() === text.toLowerCase())` is `true` if any task matches.
:::

:::solution
```html title="03-todo-list/index.html (the body)"
<h1>To-do</h1>
<form id="add-form" novalidate>
    <label for="new-task">New task</label>
    <input id="new-task" type="text" maxlength="60" aria-describedby="task-error">
    <button type="submit">Add</button>
    <p id="task-error" class="error"></p>
</form>
<ul id="list"></ul>
<p id="summary"></p>
<button id="clear" type="button">Clear completed</button>
```

```javascript title="03-todo-list/script.js"
let todos = [
  { id: 1, text: "Finish math worksheet", done: true },
  { id: 2, text: "Practice guitar for 20 minutes", done: false },
];
let nextId = 3;

const form = document.querySelector("#add-form");
const input = document.querySelector("#new-task");
const error = document.querySelector("#task-error");
const list = document.querySelector("#list");
const summary = document.querySelector("#summary");

function renderSummary() {
  const left = todos.filter((todo) => !todo.done).length;
  if (todos.length === 0) {
    summary.textContent = "Nothing on the list. Add a task above.";
  } else if (left === 0) {
    summary.textContent = "All done!";
  } else {
    summary.textContent = `${left} of ${todos.length} left`;
  }
}

function render() {
  list.replaceChildren();
  todos.forEach((todo) => {
    const item = document.createElement("li");
    const label = document.createElement("label");
    const checkbox = document.createElement("input");
    checkbox.type = "checkbox";
    checkbox.checked = todo.done;
    checkbox.dataset.id = todo.id;

    const remove = document.createElement("button");
    remove.type = "button";
    remove.textContent = "Delete";
    remove.dataset.id = todo.id;
    remove.setAttribute("aria-label", `Delete ${todo.text}`);

    label.append(checkbox, ` ${todo.text}`);
    item.append(label, " ", remove);
    item.classList.toggle("done", todo.done);
    list.append(item);
  });
  renderSummary();
}

function showError(message) {
  error.textContent = message;
  if (message === "") {
    input.removeAttribute("aria-invalid");
  } else {
    input.setAttribute("aria-invalid", "true");
  }
}

form.addEventListener("submit", (event) => {
  event.preventDefault();
  const text = input.value.trim();
  if (text === "") {
    showError("Type a task first.");
    input.focus();
    return;
  }
  if (todos.some((todo) => todo.text.toLowerCase() === text.toLowerCase())) {
    showError(`"${text}" is already on the list.`);
    input.focus();
    return;
  }
  showError("");
  todos.push({ id: nextId, text: text, done: false });
  nextId = nextId + 1;
  input.value = "";
  input.focus();
  render();
});

list.addEventListener("change", (event) => {
  const id = Number(event.target.dataset.id);
  const todo = todos.find((item) => item.id === id);
  todo.done = event.target.checked;
  event.target.closest("li").classList.toggle("done", todo.done);
  renderSummary();
});

list.addEventListener("click", (event) => {
  const button = event.target.closest("button");
  if (!button) {
    return;
  }
  const id = Number(button.dataset.id);
  todos = todos.filter((todo) => todo.id !== id);
  render();
});

document.querySelector("#clear").addEventListener("click", () => {
  todos = todos.filter((todo) => !todo.done);
  render();
});

render();
```

The `change` listener updates one item in place instead of calling `render`, for the same reason as in the original build: redrawing would destroy the checkbox the user is focused on. The submit listener's two early `return`s mean a task is only added once it passes every check. Because focus returns to the input after each add, someone can type a task, press **Enter**, and type the next without touching the mouse. Test exactly that, then try adding `finish MATH worksheet` to see the duplicate message.
