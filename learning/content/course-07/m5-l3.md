:::objectives
- Write countdowns that stop themselves with `clearInterval`.
- Restart a `setTimeout` correctly with `clearTimeout`.
- Save and restore settings, lists, and drafts with `localStorage` and JSON, including the first-visit and damaged-data cases.
- Find and fix the classic timer bugs: double starts, drift, and timers that never stop.
:::

Make a new folder for each browser exercise with an `index.html` (and a `script.js` if you like), and open it with Live Server. The Node exercises run as they are; you can also paste them into the DevTools Console. Try each one properly before you open the solution.

## Warm-up: predict, then check

:::quiz
Q: What order do the letters print in? `setTimeout(() => console.log("A"), 200); setTimeout(() => console.log("B"), 100); console.log("C");`
- [ ] A B C
  That's the order in the file, but neither timer callback can run before the script finishes.
- [ ] C A B
  `C` is right to go first, but the 100 ms timer fires before the 200 ms one.
- [x] C B A
  `C` runs immediately. Then the shorter timer (`B`, 100 ms) fires, then `A` at 200 ms.

Q: After `localStorage.setItem("darkMode", false)`, does `if (localStorage.getItem("darkMode")) { … }` run its body?
- [x] Yes
  The value was stored as the string `"false"`. Any non-empty string is truthy, so the `if` runs. Compare with the string instead: `=== "true"`.
- [ ] No
  It would be skipped for the real `false`, but `localStorage` handed back the text `"false"`.
:::

### Exercise 1: Liftoff

Write a Node program that prints `5`, `4`, `3`, `2`, `1` (one every 200 ms) and then `Liftoff!`, and then stops. Use `setInterval` and `clearInterval`, not five `setTimeout` calls.

```text
5
4
3
2
1
Liftoff!
```

:::hint
Keep a `count` variable outside the interval. Each tick, either print and subtract, or print `Liftoff!` and clear the interval. Save the id that `setInterval` returns, or you can't stop it.
:::

:::solution
```javascript run title="liftoff.js"
let count = 5;

const id = setInterval(() => {
  if (count > 0) {
    console.log(count);
    count = count - 1;
  } else {
    console.log("Liftoff!");
    clearInterval(id);
  }
}, 200);
```

The interval checks `count` before printing, so the sixth tick prints `Liftoff!` and stops the interval. Without `clearInterval(id)`, it would print `Liftoff!` forever.
:::

### Exercise 2: A message that hides itself

Make a **Save** button. Clicking it shows the text "Saved!" for 2 seconds, then hides it. If someone clicks again while the message is showing, the 2 seconds start over, so the message never disappears early.

:::hint
Click once, wait 1.5 seconds, click again. A plain `setTimeout` per click lets the *first* timer hide the message only half a second after the second click. Keep the timeout id in a variable and call `clearTimeout` on it before setting a new one.
:::

:::solution
```html preview height="140" title="toast.html"
<button id="save">Save</button>
<p id="toast" hidden>Saved!</p>
<script>
  const toast = document.querySelector("#toast");
  let hideId = null;

  document.querySelector("#save").addEventListener("click", () => {
    toast.hidden = false;
    clearTimeout(hideId); // cancel the old countdown, if any
    hideId = setTimeout(() => {
      toast.hidden = true;
    }, 2000);
  });
</script>
<style>
  body { font-family: system-ui, sans-serif; margin: 12px; }
  button { font-size: 16px; padding: 8px 18px; }
  #toast { display: inline-block; background: #e2f4e8; color: #14341f; padding: 6px 12px; border-radius: 6px; }
  #toast[hidden] { display: none; }
</style>
```

`clearTimeout(null)` does nothing, so the first click is safe. Every later click cancels the pending hide and schedules a fresh one, so the message stays up for 2 seconds after the *last* click.
:::

### Exercise 3: Remember dark mode

The theme switch from Module 4 forgets your choice every time the page reloads. Build a "Dark mode" checkbox that switches the page to a dark theme and is still ticked after a refresh.

:::hint
Store the string `"dark"` or `"light"`, not a boolean (remember the warm-up). On load, read the value, set `checkbox.checked`, and apply the class. Put your storage calls in `try`/`catch` so the page still works when storage is blocked.
:::

:::solution
```html preview height="150" title="theme.html"
<label><input type="checkbox" id="dark" /> Dark mode</label>
<p>Your notes go here.</p>
<script>
  const box = document.querySelector("#dark");

  function applyTheme(theme) {
    document.body.classList.toggle("dark", theme === "dark");
    box.checked = theme === "dark";
  }

  let saved = "light";
  try {
    saved = localStorage.getItem("theme") ?? "light";
  } catch {
    // Storage is blocked (as in this preview); use the default.
  }
  applyTheme(saved);

  box.addEventListener("change", () => {
    const theme = box.checked ? "dark" : "light";
    applyTheme(theme);
    try {
      localStorage.setItem("theme", theme);
    } catch {}
  });
</script>
<style>
  body { font-family: system-ui, sans-serif; margin: 0; padding: 12px; background: #fff; color: #222; }
  body.dark { background: #1d2230; color: #eef; }
</style>
```

`?? "light"` handles the first visit, when `getItem` returns `null`. `classList.toggle("dark", condition)` adds the class when the condition is true and removes it when false, so one line covers both themes. In this preview the choice resets when you leave; on Live Server it survives a refresh.
:::

### Exercise 4: Save a whole list

Write two functions. `saveList(key, items)` stores an array. `loadList(key)` returns the array, or an empty array `[]` if nothing is saved, the text is damaged, or the saved value isn't an array. Test them with the stand-in storage below (Node has no `localStorage`).

```text
first visit: []
after saving: [ 'read ch. 4', 'math p. 31' ]
damaged: []
not a list: []
```

:::hint
`JSON.parse` goes inside `try`. After parsing, `Array.isArray(value)` tells you whether you really got a list. `JSON.parse('{"a":1}')` parses fine but gives an object, which would crash any code that calls `.map` on it.
:::

:::solution
```javascript run title="lists.js"
const storage = {
  data: {},
  setItem(key, value) { this.data[key] = String(value); },
  getItem(key) { return key in this.data ? this.data[key] : null; },
};

function saveList(key, items) {
  storage.setItem(key, JSON.stringify(items));
}

function loadList(key) {
  try {
    const value = JSON.parse(storage.getItem(key));
    return Array.isArray(value) ? value : [];
  } catch {
    return [];
  }
}

console.log("first visit:", loadList("homework"));

saveList("homework", ["read ch. 4", "math p. 31"]);
console.log("after saving:", loadList("homework"));

storage.data.homework = "[read ch. 4";
console.log("damaged:", loadList("homework"));

storage.data.homework = '{"task":"read"}';
console.log("not a list:", loadList("homework"));
```

On the first visit `JSON.parse(null)` returns `null`, which isn't an array, so you get `[]`. In the browser, replace `storage` with `localStorage` and the functions work unchanged.
:::

### Exercise 5: Fix the stopwatch

This stopwatch has three bugs. Click **Start** twice, try **Reset** while it runs, and leave it in a background tab for a minute. Find all three, then rewrite it so it can't double-start, Reset really stops it, and the time is measured with `Date.now()` instead of counted ticks.

```html preview height="150" title="stopwatch-buggy.html"
<p id="time">0.0</p>
<button id="start">Start</button>
<button id="stop">Stop</button>
<button id="reset">Reset</button>
<script>
  let tenths = 0;
  let id = null;
  const timeEl = document.querySelector("#time");

  document.querySelector("#start").addEventListener("click", () => {
    id = setInterval(() => {
      tenths = tenths + 1;
      timeEl.textContent = (tenths / 10).toFixed(1);
    }, 100);
  });
  document.querySelector("#stop").addEventListener("click", () => {
    clearInterval(id);
  });
  document.querySelector("#reset").addEventListener("click", () => {
    tenths = 0;
    timeEl.textContent = "0.0";
  });
</script>
<style>
  body { font-family: system-ui, sans-serif; margin: 12px; }
  #time { font-size: 40px; margin: 0 0 8px; font-variant-numeric: tabular-nums; }
  button { font-size: 15px; padding: 6px 14px; }
</style>
```

:::hint
The three bugs: Start has no guard; Reset never calls `clearInterval`; and `tenths + 1` assumes every tick is exactly on time. For the third, keep two numbers: `elapsedBefore` (time from earlier runs) and `startedAt` (when the current run began). The time shown is `elapsedBefore + (Date.now() - startedAt)`.
:::

:::solution
```html preview height="150" title="stopwatch-fixed.html"
<p id="time">0.0</p>
<button id="start">Start</button>
<button id="stop">Stop</button>
<button id="reset">Reset</button>
<script>
  const timeEl = document.querySelector("#time");
  let id = null;
  let startedAt = 0;      // Date.now() when the current run began
  let elapsedBefore = 0;  // ms from earlier runs

  function elapsed() {
    return id === null ? elapsedBefore : elapsedBefore + (Date.now() - startedAt);
  }
  function show() {
    timeEl.textContent = (elapsed() / 1000).toFixed(1);
  }

  document.querySelector("#start").addEventListener("click", () => {
    if (id !== null) return;            // bug 1: no double starts
    startedAt = Date.now();
    id = setInterval(show, 100);
  });
  document.querySelector("#stop").addEventListener("click", () => {
    if (id === null) return;
    elapsedBefore = elapsed();          // bank the time so far
    clearInterval(id);
    id = null;
    show();
  });
  document.querySelector("#reset").addEventListener("click", () => {
    clearInterval(id);                  // bug 2: actually stop it
    id = null;
    elapsedBefore = 0;
    show();
  });
</script>
<style>
  body { font-family: system-ui, sans-serif; margin: 12px; }
  #time { font-size: 40px; margin: 0 0 8px; font-variant-numeric: tabular-nums; }
  button { font-size: 15px; padding: 6px 14px; }
</style>
```

Bug 3 is fixed by `elapsed()`: the interval only redraws, and the clock supplies the time. Stop "banks" the time into `elapsedBefore` *before* setting `id = null`, because `elapsed()` uses `id` to decide whether the stopwatch is running.
:::

### Exercise 6: Autosave a draft

Make a `textarea` that saves its text to `localStorage` **1 second after the person stops typing**, not on every key press. Show "Saving…" while waiting and "Saved" once it's stored, and restore the draft when the page loads.

:::hint
On every `input` event, cancel the previous timeout and start a new 1-second one. Only the last timeout survives, so it fires once, after a second with no typing. This pattern is called **debouncing**. The diagram below shows the timeline.
:::

```mermaid caption="Debouncing: each key press cancels the waiting save and starts a new one"
sequenceDiagram
    participant You as You typing
    participant T as Save timer
    participant S as localStorage
    You->>T: "h" (start 1 s wait)
    You->>T: "i" (cancel, start again)
    You->>T: "!" (cancel, start again)
    Note over T: 1 second with no typing
    T->>S: save "hi!"
```

:::solution
```javascript title="script.js"
const box = document.querySelector("#draft");
const statusEl = document.querySelector("#status");
let saveId = null;

try {
  box.value = localStorage.getItem("draft") ?? "";
} catch {}

box.addEventListener("input", () => {
  statusEl.textContent = "Saving…";
  clearTimeout(saveId);
  saveId = setTimeout(() => {
    try {
      localStorage.setItem("draft", box.value);
      statusEl.textContent = "Saved";
    } catch {
      statusEl.textContent = "Couldn't save on this device";
    }
  }, 1000);
});
```

The draft is plain text, so it needs no JSON. To convince yourself that only one save happens, here is the same debounce in Node, with key presses simulated 100 ms apart:

```javascript run title="debounce-test.js"
let saveId = null;
let saves = 0;

function onInput(text) {
  clearTimeout(saveId);
  saveId = setTimeout(() => {
    saves = saves + 1;
    console.log(`save #${saves}: "${text}"`);
  }, 1000);
}

["h", "hi", "hi!"].forEach((text, i) => {
  setTimeout(() => onInput(text), i * 100);
});
```

Three key presses, one save, with the final text. Without `clearTimeout` you'd see three saves.
:::

### Challenge: a practice streak

Build a page with an **I practiced today** button and a line that says "Current streak: 4 days". Save the dates as an array of strings like `"2026-11-15"`. Pressing the button twice on one day must not count twice. The streak counts consecutive days ending today, or ending yesterday if you haven't practised yet today (so the streak doesn't drop to 0 at midnight). It must survive a refresh.

:::hint
Write two pure functions you can test in Node first: `dateKey(date)` turns a `Date` into `"YYYY-MM-DD"` (use `getFullYear`, `getMonth() + 1`, `getDate`, and `padStart`), and `currentStreak(days, today)` walks backwards one day at a time while the day is in the list. `date.setDate(date.getDate() - 1)` steps back a day and handles month boundaries for you. Put the days in a `Set` to check them quickly and to ignore repeats.
:::

:::solution
The logic, tested with fixed dates that cross from October into November:

```javascript run title="streak.js"
function dateKey(date) {
  const y = date.getFullYear();
  const m = String(date.getMonth() + 1).padStart(2, "0");
  const d = String(date.getDate()).padStart(2, "0");
  return `${y}-${m}-${d}`;
}

function currentStreak(days, today) {
  const done = new Set(days);
  const cursor = new Date(today.getFullYear(), today.getMonth(), today.getDate());
  if (!done.has(dateKey(cursor))) cursor.setDate(cursor.getDate() - 1);
  let streak = 0;
  while (done.has(dateKey(cursor))) {
    streak = streak + 1;
    cursor.setDate(cursor.getDate() - 1);
  }
  return streak;
}

const days = ["2026-10-30", "2026-10-31", "2026-11-01", "2026-11-02"];
console.log(currentStreak(days, new Date(2026, 10, 2))); // practised today
console.log(currentStreak(days, new Date(2026, 10, 3))); // not yet today
console.log(currentStreak(days, new Date(2026, 10, 5))); // missed two days
```

In the page, load the array with your `loadList` from Exercise 4. The button adds `dateKey(new Date())` only if it isn't already in the list, saves, and re-renders `currentStreak(days, new Date())`. Months in `new Date(2026, 10, 2)` count from 0, so `10` is November, a classic source of off-by-one bugs.
:::
