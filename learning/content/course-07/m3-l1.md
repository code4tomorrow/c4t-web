A school supply store has a button labelled **In stock only**. Its code filters the product list perfectly: the Console shows exactly the three products that are in stock. Yet all five product cards stay on the page, sold-out backpack included. The data changed, and the page didn't.

That gap is the whole subject of this module. JavaScript never updates the page on its own. Your code has to decide what should be shown (with conditions and loops) and then tell the page to show it (with the DOM). By the end of these notes you'll fix that store.

## Comparisons answer "true or false"

A comparison takes two values and gives back a boolean. These are the ones you'll use:

| Operator | Means | Example that's `true` |
|---|---|---|
| `===` | is exactly equal to | `3 === 3` |
| `!==` | is not exactly equal to | `"a" !== "b"` |
| `<` `>` `<=` `>=` | less than, greater than, or equal | `4.5 < 5` |
| `&&` | both sides are true | `inStock && price < 5` |
| `\|\|` | at least one side is true | `isAdmin \|\| isOwner` |
| `!` | flips true and false | `!soldOut` |

JavaScript also has a double-equals, `==`, which converts the values to the same type before comparing. That sounds helpful until you see the results:

```javascript run title="equality.js"
console.log("5" === 5);
console.log("5" == 5);
console.log(0 == "");
console.log(0 == "0");
console.log("" == "0");
```

`0` equals `""`, and `0` equals `"0"`, but `""` doesn't equal `"0"`. Nobody can keep those conversion rules in their head, so use `===` and `!==` everywhere. If you need to compare a string from an input with a number, convert it yourself first, as in Module 2.

## `if`, `else if`, and `else` choose a path

An `if` statement runs a block of code only when its condition is true. Add `else if` for more cases and `else` for "everything else":

```javascript run title="shipping.js"
function shippingMessage(cartTotal) {
  if (cartTotal >= 35) {
    return "Free shipping!";
  } else if (cartTotal >= 25) {
    return `Add $${(35 - cartTotal).toFixed(2)} more for free shipping.`;
  } else {
    return "Shipping is $4.99.";
  }
}

console.log(shippingMessage(40));
console.log(shippingMessage(30));
console.log(shippingMessage(12));
console.log(shippingMessage(35));
```

JavaScript checks the conditions from top to bottom and runs only the **first** block whose condition is true. Order matters: if the `>= 25` check came first, a $40 cart would match it and be told to spend more. The last call checks the boundary on purpose. Testing values that sit exactly on a cutoff catches most `<` versus `<=` mistakes.

:::warning
`if (total = 0)` is a bug that doesn't crash. A single `=` *assigns* 0 to `total`, and since 0 counts as false, the block never runs, and your total has just been wiped. Comparisons need `===`.
:::

:::note
An `if` accepts any value, not only booleans. `false`, `0`, `""` (empty string), `null`, `undefined`, and `NaN` count as false; everything else counts as true. So `if (name)` means "if name isn't empty." Writing `if (name !== "")` says the same thing more plainly.
:::

## Loops repeat work for every item

A `for` loop has three parts in its parentheses: where to start, the condition to keep going, and what to do after each pass. A `for...of` loop is simpler when you only need each item, not its position:

```javascript run title="loops.js"
const prices = [4.5, 7, 5.25, 32, 3];

for (let i = 0; i < prices.length; i++) {
  console.log(`Item ${i + 1}: $${prices[i]}`);
}

let total = 0;
for (const price of prices) {
  total = total + price;
}
console.log(`Total: $${total.toFixed(2)}`);
```

The condition is `i < prices.length`, not `<=`. With five prices the indexes are 0 to 4, so `<=` would run a sixth pass and read `prices[5]`, which is `undefined`. `i++` is shorthand for `i = i + 1`.

## `forEach`, `map`, and `filter` say what you mean

Most loops over arrays do one of three jobs, and arrays have a method for each. You pass the method a function, and it calls that function once per item:

```javascript run title="methods.js"
const products = [
  { name: "Notebook", price: 4.5, inStock: true },
  { name: "Gel pens", price: 7, inStock: false },
  { name: "Highlighters", price: 5.25, inStock: true },
  { name: "Backpack", price: 32, inStock: false },
  { name: "Sticky notes", price: 3, inStock: true },
];

products.forEach((product) => console.log(product.name));

const labels = products.map((product) => `${product.name} ($${product.price})`);
console.log(labels);

const available = products.filter((product) => product.inStock);
console.log(available.length);

const cheapAndAvailable = products.filter((product) => product.inStock && product.price < 5);
console.log(cheapAndAvailable.map((product) => product.name));
```

-   **`forEach`** does something with each item and gives back nothing. Use it for actions, like logging or adding an element to the page.
-   **`map`** builds a new array of the same length, where each item is whatever your function returned.
-   **`filter`** builds a new array containing only the items for which your function returned `true`.

None of them change the original array, which is why `products` still has five items after all that filtering. The last line chains them: filter first, then map the survivors to names.

:::warning
`prices.map((price) => { price * 1.08 })` gives `[ undefined, undefined, undefined ]`. With braces, the arrow function needs `return`. Either write `(price) => price * 1.08` or `(price) => { return price * 1.08; }`.
:::

## Find elements and change what they show

When the browser loads your HTML, it builds a tree of objects, one per element, called the **DOM** (Document Object Model). JavaScript changes the page by changing those objects. `document` is the root of the tree, and these are the tools you'll use most:

-   `document.querySelector("css selector")` returns the **first** matching element, or `null` if nothing matches.
-   `document.querySelectorAll("css selector")` returns **all** matches, as a list you can loop over with `forEach`.
-   `element.textContent` reads or replaces the text inside an element.
-   `element.classList.add("name")`, `.remove("name")`, and `.toggle("name")` change the element's classes, so your CSS decides how it looks.

Try both buttons:

```html preview height="250" title="dom-basics.html"
<h2 id="title">Reading list</h2>
<ul>
  <li class="book">Holes</li>
  <li class="book">Dune</li>
  <li class="book">Wonder</li>
</ul>
<button id="rename" type="button">Update the heading</button>
<button id="mark" type="button">Toggle highlight on every book</button>

<script>
  const title = document.querySelector("#title");
  const books = document.querySelectorAll(".book");

  document.querySelector("#rename").addEventListener("click", () => {
    title.textContent = `Reading list (${books.length} books)`;
  });

  document.querySelector("#mark").addEventListener("click", () => {
    books.forEach((book) => book.classList.toggle("highlight"));
  });
</script>
<style>
  body { font-family: system-ui, sans-serif; padding: 0 16px; }
  .highlight { background: #fff3b0; font-weight: bold; }
  button { padding: 6px 10px; margin-right: 6px; }
</style>
```

`toggle` adds the class if it's missing and removes it if it's there, so the second button switches the highlight on and off. Changing classes, rather than setting colors directly from JavaScript, keeps all of your styling in CSS where it belongs.

## Build elements from data

To add something new to the page, you make an element with `document.createElement("li")`, fill it in, and attach it to an element already on the page with `append`. Put that inside a loop, and you can draw a whole list from an array.

Here's the store with its bug fixed. Every button calls one function, `render`, and hands it the list to show:

```html preview height="330" title="store.html"
<div>
  <button id="all" type="button">All</button>
  <button id="in-stock" type="button">In stock</button>
  <button id="cheap" type="button">Under $5</button>
</div>
<p id="summary"></p>
<ul id="cards"></ul>

<script>
  const products = [
    { name: "Notebook", price: 4.5, inStock: true },
    { name: "Gel pens", price: 7, inStock: false },
    { name: "Highlighters", price: 5.25, inStock: true },
    { name: "Backpack", price: 32, inStock: false },
    { name: "Sticky notes", price: 3, inStock: true },
  ];

  const cards = document.querySelector("#cards");
  const summary = document.querySelector("#summary");

  function render(list) {
    cards.replaceChildren();
    list.forEach((product) => {
      const card = document.createElement("li");
      card.textContent = `${product.name}: $${product.price.toFixed(2)}`;
      card.classList.add("card");
      if (!product.inStock) {
        card.classList.add("sold-out");
      }
      cards.append(card);
    });
    summary.textContent = `Showing ${list.length} of ${products.length} products`;
  }

  document.querySelector("#all").addEventListener("click", () => render(products));
  document.querySelector("#in-stock").addEventListener("click", () => {
    render(products.filter((product) => product.inStock));
  });
  document.querySelector("#cheap").addEventListener("click", () => {
    render(products.filter((product) => product.price < 5));
  });

  render(products);
</script>
<style>
  body { font-family: system-ui, sans-serif; padding: 0 16px; }
  button { padding: 6px 10px; margin-right: 6px; }
  #cards { padding: 0; }
  .card { list-style: none; border: 1px solid #ccc; border-radius: 6px; padding: 8px 12px; margin: 6px 0; }
  .sold-out { color: #888; text-decoration: line-through; }
</style>
```

The original bug was a filter whose result went to `console.log` and nowhere else. The fix is a pattern you'll use in every app from here on:

```mermaid caption="The render pattern: the page is always drawn from the data"
flowchart LR
    A[Array of data] --> B["filter: which items to show"]
    B --> C["render: clear the list"]
    C --> D["forEach item: createElement, fill it in, append"]
    D --> E[Page matches the data]
    F[User clicks a button] --> B
```

Three details in `render` are worth copying:

-   `cards.replaceChildren()` with nothing in the parentheses removes everything inside the list first. Without it, each click would add five more cards below the old ones.
-   The `if` inside the loop decides per product whether to add the `sold-out` class. `card.classList.toggle("sold-out", !product.inStock)` does the same in one line: with a second argument, `toggle` adds the class when it's true and removes it when it's false.
-   `render(products)` at the bottom draws the page once when it loads, before anyone clicks.

:::warning
You'll see tutorials build elements with `card.innerHTML = …`. `innerHTML` treats the text as HTML, so if any of it came from a user, they can inject markup and scripts into your page. Someone could name a product `<img src=x onerror="alert('hacked')">` and that code would run. `textContent` always shows text as text, so use it for anything that contains data.
:::

:::quiz
Q: A text input holds `"16"`. What does `input.value === 16` give?
- [ ] `true`, because both are 16
  They look the same, but one is a string and one is a number.
- [x] `false`, because `===` compares type as well as value
  Convert first: `Number(input.value) === 16` is `true`.
- [ ] An error, because you can't compare a string with a number
  The comparison is allowed; it's just never true.

Q: What does `[1, 2, 3].map((n) => { n * 2 })` return?
- [ ] `[2, 4, 6]`
  That's the result without braces, or with `return n * 2` inside them.
- [x] `[undefined, undefined, undefined]`
  The braces make a block, and a block without `return` gives back `undefined` for every item.
- [ ] `[1, 2, 3]`
  `map` never returns the original items unless your function returns them.

Q: A page has five elements with `class="card"`. What does `document.querySelector(".card")` give you?
- [x] The first card
  `querySelector` always stops at the first match.
- [ ] All five cards
  That's `querySelectorAll`.
- [ ] `null`
  `null` means nothing matched, but five elements do.

Q: Users can type a nickname that your page then displays. Which line shows it safely?
- [ ] `badge.innerHTML = nickname;`
  `innerHTML` would run any HTML or script hidden in the nickname.
- [x] `badge.textContent = nickname;`
  `textContent` displays exactly the characters typed, and never treats them as code.
- [ ] `badge.classList.add(nickname);`
  That adds a CSS class named after the nickname; nothing visible changes.
:::

:::takeaways
- Use `===` and `!==`. `==` converts types by rules that surprise everyone.
- `if` / `else if` / `else` runs the first block whose condition is true, so order your checks from most to least specific.
- `forEach` performs an action per item, `map` transforms every item, and `filter` keeps the items that pass a test. None change the original array.
- `querySelector` finds an element, `textContent` and `classList` change it, and `createElement` plus `append` add new ones.
- Draw the page from the data with a `render` function that clears and rebuilds, and call it whenever the data or the filter changes.
:::
